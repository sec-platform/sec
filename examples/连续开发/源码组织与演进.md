## 同一中立源的语义与证据接缝

本节沿同一个中立作者任务检查声明、目标、契约与证明的接合。程序及失败输入都是设计范本，不是新产品实现或已经执行的测试。

### 商余不是目标或求解器的默认

```gift
export fn quotient(a: Int, b: Int) -> Int
  require b != 0
  ensure result * b + a % b == a
= a / b;
```

输入(-5,2)应得到-2，并使用余数-1满足关系；(5,-2)应得到-2，余数1；(-5,-2)应得到2，余数-1。除数0在checked入口是前提违例，不是返回0。这里都是依据合同手工推导的期望，没有运行后端。一个把所有输入都返回0的实现并不满足该合同；一个直接用SMT欧几里得div的证明编码也不能代替Gift编码。正确适配见[验证翻译](../../docs/运行/验收/方法与独立证据.md#契约到求解器的语义保持)。

### 新状态规则不需要官方工单封装

```gift
export type State = Open() | Closed(Text);
export type Event = Close(Text) | Reopen();
export type Failure = InvalidReason() | AlreadyClosed() | AlreadyOpen();

export fn step(state: State, event: Event) -> Result<State, Failure>
= match event {
    case Close(reason) =>
      if reason == "" then Err(InvalidReason())
      else match state {
        case Open() => Ok(Closed(reason));
        case Closed(_) => Err(AlreadyClosed());
      };
    case Reopen() => match state {
      case Open() => Err(AlreadyOpen());
      case Closed(_) => Ok(Open());
    };
  };
```

Result、Ok和Err来自冻结的基础画像，State/Event/Failure是本模块自定义。构造器在其预期类型可唯一确定时简写；有歧义则使用类型限定。此例仅决定纯状态转移：不读取当前账号、不写数据库、不发送通知。真实权限、版本冲突、持久提交与出站事件由明确端口和宿主层组合，不能因为函数返回Ok就声称工单已修改。

只需增加一个普通失败变体或调整前置规则时，开发者修改本模块，不增加关键词。状态带Text使实例集合不再是有限枚举；一般表示保存状态域与转换关系，模型检查可选有范围的抽象，不强制列出全部可能原因字符串。

### 编辑器的不可变值、可变对象与外部端口

另一个作者自己定义的领域是编辑器。`Document={content:Text, revision:Int}`是不可变值，`replaceAll(current, expectedRevision, nextContent)`要求`current.revision>=0`且`expectedRevision>=0`。版本不等时正常返回`Err(StaleRevision())`；相等时正常返回`Ok({content:nextContent, revision:expectedRevision+1})`。这里的失败是Result数据，不是契约错误；负版本才违反本例前提。原源后置只要求成功版本严格增大，实际主体进一步给出精确加一。

独立的调用性质观察完整四槽`(before, expectedRevision, nextContent, outcome)`，而不是只观察返回文档：`Ok(after)`时检查`after.revision==before.revision+1`，`Err(_)`时性质为true。性质不声称所有调用成功，也不抹去输入与正常Err。将该性质绑定到`replaceAll`、选择所有有效输入并组合成编辑合同，是设计中的要求声明；`gift/author`静态构造器、求值器、库和目标仍需要真实供给，声明本身没有实现或证明编辑器。仅import history、host、remote也不使它们成为输出根。

`history.newest(snapshots)`的实际定义是空列表返回`None()`，非空返回`Some(head)`；它没有寻找最大revision，也没有排序。若应用要让head代表最新，必须另有列表排序合同。`revisionIncreased(old,next)`仅比较`next.revision>old.revision`，不能替代上面的精确加一性质或证明快照已经保存。

可选对象画像另定义`RevisionView.value()`与`RevisionCounter`：构造`start>=0`，私有可变`current=start`；`value()`只读且返回当前值，`advance()`具有对象Read/Write效果、把current加一并返回新值，原后置为`result>=1`。它与不可变Document不是同一存储对象；纯读表示不修改对象，读取仍明确带`obj.Read`。受权调用advance才可修改，不能从有此方法推出任意调用方可写或并发计数已安全。

Host与Remote各自有完整的纯转移表，携带的session为Int、reason为Text，不额外捏造非负或非空前提：

| 定义与事件 | 允许的原状态 | 正常Result |
|---|---|---|
| Host `Start()` | `Stopped()` | `Ok(Starting())` |
| Host `Ready(session)` | `Starting()` | `Ok(Running(session))` |
| Host 上述两事件的其他状态 | 其他 | `Err(IllegalTransition())` |
| Host `Crash(reason)` | 任意 | `Ok(Crashed(reason))` |
| Host `Stop()` | 任意 | `Ok(Stopped())` |
| Remote `Dial()` | `Offline()` | `Ok(Connecting())` |
| Remote `Connected(sessionId)` | `Connecting()` | `Ok(Online(sessionId))` |
| Remote 上述两事件的其他状态 | 其他 | `Err(InvalidLinkTransition())` |
| Remote `Lost(reason)` | 任意 | `Ok(Failed(reason))` |
| Remote `Close()` | 任意 | `Ok(Offline())` |

Host状态域为Stopped/Starting/Running(Int)/Crashed(Text)，Remote为Offline/Connecting/Online(Int)/Failed(Text)。这两张表只计算值，没有创建进程、建立网络、监测退出或关闭连接；实际进程与网络责任必须由相应宿主承担。

文件宿主端口则明确声明外部作用：`readText:(Text)->Result<Text,FileError> !{host.fs.read}`，`writeText:(Text,Text)->Result<Unit,FileError> !{host.fs.write}`；`FileError=NotFound()|AccessDenied()|IoFailure(Text)`。这些效果符号必须由真实锁定的定义/画像提供，调用还须满足实际读写权限与宿主绑定。端口声明不会读取文件；Document的成功替换也不等于writeText成功或磁盘持久化。

### 同一模块的高阶契约与嵌套分支

在前面quotient定义旁可以直接增加普通函数，不用新增工具或官方能力包：

```gift
fn callAt(f: (Int, Int) -> Int !{}, a: Int, b: Int) -> Int !{}
= f(a, b);

export fn viaFunction(a: Int, b: Int) -> Int
= callAt(quotient, a, b);

export type Choice = A(Bool) | B();
export fn classify(choice: Choice) -> Int
= match choice {
    case A(true) => 1;
    case A(false) => 2;
    case B() => 0;
  };

export let planeThree: Text = "\u{30000}";
```

此处quotient使用前面的非零除数契约。`viaFunction(5, 0)`在checked目标中仍是quotient的前置违例，不因其经函数参数传递就进入裸除法。普通箭头没有承诺任意实参都正常返回；检查callAt本身也不能使用仅属于quotient的后置条件来证明所有f。`!{}`不等于没有契约失败或总会终止。

AI删除`case A(false)`时，A/B两个顶层名字依然都在，但新的候选缺少A(false)；应取得嵌套缺失模式诊断。旧候选和旧覆盖记录不能给它背书；之后明确加回该分支，或改成保持要求的通配分支，仍从作者源修改。

planeThree含一个合法Unicode标量，逻辑长度是一。TS的UTF-16存储可能使用两个码元，证明后端又未必能用其原生String字母表表示该值；均由对应映射保持，而不是改变此源常量。源检查在没有目标后端时仍可成立；证明方法缺项只影响采用该方法的声明，不能把这段Text从中立语言删掉。

调用c1的源检查、TS/第二目标生成及各自检查仍走下节同一组引用。不执行上述程序；这些预期由当前合同逐步推出，未来实际读取器、后端与验证适配需分别检验。

### 同一个AI任务的连续操作

先propose中立源得到c1；没有后端时可以check(types)检查c1的源语义。选择TS生成a1，选择Java生成a2，两者都绑定c1但目标和表示不同。运行案例必须明确a1或a2，不能从缓存里挑“唯一/最后生成”的文件。修改除法前提得到c2后，a1/a2继续作为历史结果存在，不自动获得c2身份。

propose的diff比较作者源；preview的diff必须用compareTo明确给出可比较的父目标产物。缺少、不可读或不相容的父产物不从缓存任取；返回相应诊断，需要完整代码时由请求方改为code，不偷偷生成旧目标来凑diff。write-output始终携带当前所选artifactRef、目标前像与请求身份，不能把尚无后端的源类型通过当作已经存在的程序。

若后置条件本身除零、只得到假设性证明、运行后出现契约违例或外部操作完成未知，结果保留对应状态。AI不用手算这些身份与摘要；服务返回真实引用。全部步骤按用户目的启用，设计任务到源码设计与取舍完成即止，不执行这些工具流程。

## 从纯状态函数到高层工程闭环

本章保留原有纯函数和领域反例；完整的工单作者源只在[事务应用与交付作者规格](../../docs/领域/状态关系与流/事务与交付.md#完整的作者例关闭工单)维护，不再次复制第二份状态规则。

同一需求的连续观察是：作者定义非空原因、当前版本和合法状态；编译器选择具备共同提交能力的目标；应用成功后状态、审计、事件与逻辑结果共同成立；通知未成功时仅交付状态未完成。新一次图片条件修改从decision或相应事实绑定发生；外部复核则新增Pending、请求事件、受信回调和取消/超时竞争，不重写不相关业务。

这一例的价值是检查不同语义责任的接缝，不宣称它是唯一最佳框架或全部业务。全新原生实现也可采用同样成熟事务/Outbox库作为公平基线。需要共享额度的第二对象检验跨行不变量：各自行CAS不会自动保护总额。订阅移除与旧消息晚到检验生命周期：删除源文件不是删除已经发生的业务责任。

后续实证需要在同一源的两个版本上比较：首次输入与生成成本，后续变更定位、检查、迁移和回退成本；小函数可以作为计算入口，但不能代替完整作用验证。本次仅给出设计与书面反例，没有写程序或执行这些情景。

### 一般算法的完整定义与递归边界

以下融合旧书面作者材料中的独立算法；统一使用现行Int含义，不恢复旧实验Schema或据其后缀签发生产合法性。它们是有限设计案例与手工推导，没有实际解释映像、MethodBinding、Target或运行成绩。已有quotient例保留全Int域的向零商余；这里的非负Division是另一个明确更窄的合同，不能反向收窄quotient。

`Division`为名义结果类型，字段表达商q与余r；`isDivision(n,d,result)`要求`n=q*d+r`、`q>=0`、`0<=r<d`。合同`quotRem(n,d)`前提为`n>=0,d>0`，实现候选`quotRemExact`用精确Int的向零`/`和`%`构造同一个Division，消费者只导入公开合同。在该域令`q=floor(n/d)`，有`q*d<=n<(q+1)*d`，故`r=n-q*d`满足全部条件。若另有q′、r′，则`(q-q′)*d=r′-r`；右侧绝对值小于d，只能q=q′、r=r′。这证明数学关系的存在与唯一性，尚未证明任何后端实现忠实。

扩大域必须同时处理反例。负n而仍保留`q>=0,0<=r<d,d>0`时根本无解；改为允许负商但保持非负余数时，向零实现对`n=-1,d=2`得到`q=0,r=-1`，不再合格。负d与原条件`0<=r<d`也不相容，不能只删掉`d>0`便声称同一方法适用。需要明确另一个余数约定与方法资格，不能偷偷缩小原函数来掩盖失败。

若实际所选作者合同允许负d，却仍要求q/r非负且r<d，须报告原合同冲突；上面的非负域证明和目标BigInt `/`都不能代签原Gift107整个函数。只有准确合同本来就限定该域，或经有权作者明确采用新域且同时核错误分类、契约检查与公开接口后，收窄实现才可能合格。源手册的非负TS示意是这种条件演示，不是可直接复制进Emitter的固定除法模板。

`interleave(a,b)`是用户新定义的递归：a空返回b；a非空而b空返回a；两者非空则取各自head，输出`[a.head,b.head,..interleave(a.tail,b.tail)]`。每个输入内部顺序、重复出现次数和较长列表剩尾均保留，`[1,3]`与`[2]`得到`[1,2,3]`。这是实际算法定义，不是要求内核预置interleave行业模板；其他模块可以通过公开定义复用而不复制主体。

泛型`identity<T>(x)=x`不约束T为数值。`compose(f,g)`构造闭包时不调用f/g；调用所构造函数时先求`g(x)`，再把其正常结果传给f。latent调用不能提前执行，g的Fault或发散也不能被跳过。

`partitionBy<T>(items,predicate)`在空列表返回两个空列表；非空时先对head调用谓词一次，保存keep，再递归tail，最后将head加到keep指定的一侧。有限列表且每个被访问谓词调用正常终止时，以长度归纳可得：每个原位置恰进入一侧，两侧各自保留原相对次序，重复值不丢、不新增元素。T不需Eq/Hash。纯谓词仍可能Fault或发散，观察顺序必须保持；不能先递归tail、重复求谓词或用集合去重。列表tail反复复制的资源代价也不能由正确性归纳消除，本例不签性能上界。

`spanWhile<T>`则取最长true前缀及原后缀：空输入得到`([],[])`且不调用谓词；head为false立即返回`([],原列表)`；head为true才递归tail并把head加回前缀。`[1,2,0,3]`配`x>0`得到`([1,2],[0,3])`，调用轨迹仅`[1,2,0]`。全true时每个元素调用一次、后缀为空；首次false之后的Fault/发散不被访问，不能影响已决定结果。被访问调用的失败/发散仍继承；T也不需Eq/Hash。filter或partition会继续访问并重新分组，不是可替换实现，预先map全列表也可能引入本不会发生的错误；纯不自动证明总定义、终止或足够栈界。跨模块消费者应导入这一定义，不能只因引用完整就称生产检查通过。

编译职责也可以是作者普通算法：递归类型`TypeExpr=Var(identity)|Base(...)|Arrow(left,right)|App(...,arguments)`，`occurs(v,t)`在Var比较身份，Base返回false，Arrow依序短路检查两侧，App调用`occursIn`检查实参列表；`occursIn`在空列表返回false，否则先检查head，未命中再检查tail。有限类型树/列表的每次递归沿子结构下降，因此调用图`occurs→occursIn→occurs`有环不等于不终止。它可在绑定v到T前拒绝`v=Arrow(v,...)`之类循环替换，只是统一检查的一部分，不是完整统一器或已自举编译器。新增TypeExpr构造器须重新检查穷尽，不能由default=false吞掉；真实自举还需C0实际解释并降低这些定义，原生文件透传不能代替。

`SumTo(n)`另展示partial递归：基底`n==0`返回0，否则`n+SumTo(n-1)`。非负n按递减到零可得三角和，n<0则持续减一而不抵达基底；没有非负前提的原定义不能被宣称对所有Int终止，也不能悄悄把负n改为0。结构输入中明确的partial标记须与这个行为一同保留。

### 有型有限业务与原生供给的具体差异

下列旧实验`.intent`是已保存的有限书面参考，原请求共同为TypeScript ESM、volatile存储及ESM模块；不是现行生产作者协议。本节用Int写出精确整数含义，并保留原SafeInt有限参考实现的输入/输出范围、溢出和零除拒绝边界；不据名称宣称支持任意精度后端。长度128、256、32、64等全是各例局部上界，不能提升为公共全局常量。

| 局部类型 | 具体字段与列表域 |
|---|---|
| CartLine | `sku:Text[1..64]`，`price:Int[0..100000]`，`quantity:Int[0..100]`，`active:Bool`；lines至多128项 |
| Reading | `value:Int[-10000..10000]`，`trusted:Bool`，`source:Text[1..20]`；readings至多128项 |
| Posting | `change:Int[-10000..10000]`，`accepted:Bool`，`memo:Text[1..40]`；postings至多256项 |

购物计算的全部规则为：`Subtotal(lines)=sum(price*quantity)`，不隐加active过滤；`EligibleCount=count(active)`；`AllShippable=all(active)`（原文件名为`Shippable`）；`ActiveSKUs=map(filter(active),sku)`，保持被选出现的原顺序与重复；`FinalPrice=max(0,Subtotal-discount)+(express?30:0)`。discount是有限参考整数域内的参数，原源没有另加非负前提；express费在减折扣及零下界之后加上。不能从EligibleCount存在推断Subtotal只收活跃项。

传感器规则另有独立含义：`TrustedCount=count(trusted)`；`AnyCritical(threshold)=any(trusted && value>=threshold)`；`NetValue=sum(trusted?value:0)`；`Alert=AnyCritical || TrustedCount==0`。因此没有可信读数也告警，不能把它简化成“有临界读数才告警”；空输入的数量/净值为0、AnyCritical为false、Alert为true。

账本EndBalance从opening开始，ApprovedTotal从0开始，均按原顺序只将accepted项的change加入累计；`AnyRejected=any(!accepted)`，完整版另有`ApprovedMemo=map(filter(accepted),memo)`。scalar版没有ApprovedMemo，其余三函数相同，不能把两版当两个不同账本协议。其完整归约机制和opening=100的独立见证只在[受界归约见证](../../docs/运行/验收/方法与独立证据.md#bounded-fold-witness)维护；本节补充上述Posting字段域与函数区别，不另建归约规范。

卫生例固定inline选择，列表xs局部上界32：`Subtotal(xs)=sum(xs,lambda safeAdd:safeAdd)`；`Reuse(computeSubtotal,xs)=Subtotal(xs)+computeSubtotal`；`Min(Math,safeMin)=min(Math,safeMin)`；`FoldCollision(xs)=fold(xs,0,lambda safeAdd,safeMin:safeAdd+safeMin)`；`Plus(safeAdd,Math)=safeAdd+Math`。safeAdd、safeMin、Math、computeSubtotal在这些位置是真实作者参数/绑定，不是内部helper或宿主全局。发射必须保持词法身份与卫生别名，不能靠保留这些拼写禁止作者使用，也不能把参数错接到生成helper。

另一例绑定`ClampValue=demo.math/ClampSafeInt@1`与`TagCanonical=demo.text/NormalizeAsciiTag@1`。两者是不同原生供给：局部库记录实际源摘要、export及TS标量签名，通用绑定器捕获源并生成有型wrapper，目标编译器核对可赋值签名；provider源不在参考Python编译器中执行。已保存的实际TypeScript主体给出完整的有限行为：

- `clampSafeInt(value:number,min:number,max:number):number`先要求三个参数均通过`Number.isSafeInteger`，否则抛`RangeError('safe integer input required')`；再要求`min<=max`，否则抛`RangeError('min exceeds max')`；正常返回`Math.min(max,Math.max(min,value))`。这是有界安全整数原生方法，不能将其number签名扩大成任意Int资格，也不能省略边界参数而等同于`PositiveClamp(a)=max(0,a)`。
- `normalizeAsciiTag(input:string):string`先核运行值是string且匹配`^[A-Za-z][A-Za-z0-9_-]{0,63}$`，即长度1至64、首字符为ASCII字母、后续仅ASCII字母/数字/下划线/连字符；否则抛`TypeError('ASCII tag [1..64] expected')`；正常返回`input.toLowerCase()`。它不接受任意Unicode标签，不等同于Tagged的拼接，也没有声明recordID身份或URI等价规则。

另存的`normalizeUri(uri:string):string`主体仅返回uri，原注释明确为作者自有原生供给的identity demo；它不能当作真实URI规范化，也不能替代上述ASCII标签函数。这里保留原生异常与普通返回的区别，未把原生throw伪装成Result中的Err。原生绑定仍保持`REFERENCE_ONLY_UNVERIFIED_MEANING`：源主体、可赋值签名和函数名字均不能单独签发语义资格，仍需独立语义定义及主体、观察、错误、效果、frame、环境、资源和证据对应。实际读取源并不构成本次已调用成功或运行验证。

记录/策略例也保留具体作者结构：`Task`以id为键，`id:Text[1..64]`、`title:Text[1..120]`、`done:Bool`、`stage:Enum[todo,doing,done,cancelled]`。TaskFlow初态todo，仅有`todo+start→doing`、`todo+cancel→cancelled`、`doing+complete→done`、`doing+cancel→cancelled`四条转换，`TaskActions`将Task.stage接到该flow。done字段没有被另立为stage的自动派生不变量；其余转换不能猜成允许。后续明确增加`done+reopen→doing`才是新的作者变化。

### 轨迹一：只设计并修改线性锐化

初态：作者候选C1包含Grid合同、sharpen和已选线性核；gain为1，边界Clamp，输入元素已要求处于0—255，目标尚未执行。任务要求只把gain改为2并解释影响，不写入目标工程。

1. 入口固定本次目的为设计，取得C1与相交合同；模型无需读取数据库、订阅和部署规范。
2. propose在C1的精确基础形成C2；gain和受影响内容修订变化，无关模块原字节与身份保持。没有把用户要求改写成“换成GPU”。
3. 工具根据已选线性结构重算访问关系与数值区间：halo仍为左右1；gain仍落在已接受范围；输出形状与Clamp保持。已有代码布局不必因这次参数改变重选。
4. 返回设计差异、更新的推导依据和受影响目标计划。若任务同时要求源码预览，才进入后端，形成绑定C2的新产物；本任务到文档/候选交付即结束。
5. 书面小域期望由[线性计算合同](../../docs/领域/计算基础/计算结构与算法.md#线性邻域计算的正向作者合同与实现)计算：源[10,20,30]由gain=1的[0,20,40]变为gain=2的[0,20,50]。该期望用于核对参数变化，仍是合同推导而非运行结果。

分支：请求gain=5且仍固定旧前置时，返回相交要求冲突，保留草稿；要允许5须显式改变输入合同并重算范围。权重库缺失时仍保留作者设计，生成返回库绑定缺项。已选择的TS后端不支持所需Int表示时保留语义，不改为有损Number。

### 轨迹二：把已经生成的两份文件应用到工作区

初态：C2已有经过所需检查的产物A2，工作区基准为B1，明确写集为p、q。操作身份O、目标根、前像Bp/Bq和后像Ap/Aq在准入前固定；无关文件u不在写集，保持不变。

1. apply先核对A2属于C2及当前实际检查要求，取得读取/写入许可和对应资源；已有相同O时按当前披露权读取其结果。
2. 新操作按目标协议保存意图，取得冲突域协调后复查B1和当前规则/围栏。匹配才准入；不匹配返回冲突，无目标写入。
3. p已写为Ap之后进程失联，q仍为Bq。新进程读取原意图并观察当前状态，不重新编译C2，也不创建新O。
4. q未改变且许可成立时，只应用q并读回全部写集，结算为完成。若q被人工改为Xq，则保持Ap/Xq，返回需要恢复和具体冲突；不覆盖Xq。
5. 有权选择反向恢复时，只在当前比较成立的范围恢复B；若B包含历史人工内容，重新判断它与某个旧生成代际是否一致，不能直接贴回旧标签。u全程不变。

执行结束与完成分开：写入响应丢失可通过原O读回；已经发生的写入不会因取消消失；未完成交付留在操作结果中，不能作为“新候选仍然存在所以成功”。完整分支由[恢复表](../../docs/运行/持久化提交与恢复.md#依真实前后像选择恢复动作)决定。
