# 跨语言能力连续开发

> 设计情景；不是已编译、部署或实测工程。

本页验证跨语言能力如何进入真实“创作→生成→检查→再次修改”链，不把单项语言比较留成静态清单。作者仍维护唯一 Definition、参数、关系及真实 require/prefer；编译器选择与运行授权分别绑定。

## 场景一：异构序列化器

作者固定字段顺序、wire format、错误与版本合同；反射只读取获准成员，参数包展开具体字段，特化选择整数、文本和用户类型的已绑定方法，布局检查字节序/范围，错误走原失败协议。Rust/TS 都可以输出普通函数。

私有字段无权访问时只阻断该字段路线；增加字段必须使“全部字段”集合依赖失效；第三个字段生成失败不能发布前两个字段组成的半个 serializer；wire format 改变必须按兼容合同处理旧读写者，不能把新字段默认为旧协议理解。

## 场景二：固定地址异步资源

作者要求指定区域、稳定地址、跨挂起持有外部句柄且必须异步关闭。先在最终 slot 完成部分初始化与失败清理，地址固定后才公开 self/reference；帧保存真实借用、线程/TLS 与资源 owner。注册回调后，正常完成和取消都必须停止新回调、注销/join，再由仍存在的 owner 完成异步 close。

若调用者取消但 close pending，资源不能被标成 Closed；若还要求无堆，而唯一可用适配强制堆帧，则返回具体资源冲突，不偷偷放宽。旧回调、对象和析构代码仍在时，不能卸载旧模块。

## 场景三：共享复合计数状态

作者要求 (count,generation) 一致 CAS、跨线程、lock-free、精确 C ABI 和固定布局。实现选择必须联合核原子宽度、对齐、表示、memory order、回收和导出 ABI。真正宽原子满足全部条件才可绑定；只有 mutex 模拟时不能满足 lock-free。TS 普通对象路线可被局部拒绝，同时其他独立纯计算仍可生成 TS。

## 开发工具操作

query 读取当前作者定义、能力范围和目标；propose/preview 在同一 candidate/base 上形成修改与生成结果；check 分别检查语义、目标、ABI/并发或运行；apply 只保存作者源或已绑定产物。实际运行继续使用原 operation/ref 和执行准入，不由“生成成功”取得运行权。

第二次修改从真实作者源开始：新增字段重算序列化器集合依赖；改变区域或关闭协议先处理活动旧对象；计数位宽扩大后重新核原子供给与 ABI。受管产物只有存在准确来源映射才回源；没有映射时保留独立目标草稿，下一次生成不能覆盖用户未知修改。

## 失败继续

语义错误、缺供给、歧义、工具故障、权限不足和预算耗尽保持不同；一个目标失败不清空其他独立根。外部运行/构建响应丢失时沿原 operation readback/recover，不换 requestId 盲重放。已取得的有限设计、独立子结果和旧完整产物继续保留其真实范围。
