# 完整范本：按用途选择

产品作者从本次真实要求与作者源出发，沿[需求含义](../docs/作者/需求含义与实现责任.md)、[结构化源码](../docs/作者/结构化源码.md)和相交[开放定义与组合](../docs/作者/组合/抽象与开放定义.md)确定合同，再按用途选择下列有限范本。[结构化工作台](结构化工作台/README.md)及其[Studio JSON](结构化工作台/model/studio.json)用于本地可扩展工作台设计，没有生成可运行工作台的声明。

| 范本类型 | 入口 | 用途与边界 |
|---|---|---|
| 当前结构作者 | [工作台说明](结构化工作台/说明.md) · [后继完整源](结构化工作台/后继示例/studio.reconfirm.json) | 标签、Block、管脚、共享主体、组合与产品差异 |
| 连续开发 | [全工程连续开发](连续开发/全工程连续开发.md) · [组合结构与任务轨迹](连续开发/组合结构与任务轨迹.md) · [局部实现替换](连续开发/局部实现替换与成品接合.md) | 从一次需求到相交编辑、检查、产物、运行与再修改 |
| 实现校准 | [内存编辑器计算范本](实现校准/内存编辑器计算范本.md) · [TS往返](实现校准/简洁计算与TS往返.md) | 可选计算主体、具体行为、来源和生成校准，不是产品作者必须逐项手写 |
| 原生维护 | [Code-OSS搜索替换](原生维护/Code-OSS搜索替换.md) | 固定现有工程的专项校准，不代表完整IDE已导入 |
| 领域组合 | [状态关系流与数值](领域组合/状态关系流与数值.md) · [领域应用与算法](领域组合/领域应用与算法.md) | 对独立领域的具体含义作对照，不合并所有语义 |
| 信息全周期 | [从修改到退役](连续开发/工程信息全生命周期.md) | 信息机制的实际数据、状态和失败路径 |

其余全文可由[源码组织与演进](连续开发/源码组织与演进.md)、[成熟供给与计算工具](实现校准/成熟供给与计算工具.md)、[合同历史与范围](合同历史与范围.md)进入。[可选文本意图方案](../alternatives/文本意图/README.md)另行存放，不与当前源混读。

[一项关系的多种成品](成品形态/README.md)给出共同规范化行为、库/CLI/工作器/HTTP处理器/插件/交互面板及共同发行的完整结构JSON和后继。它检验成品边界，不取代结构化工作台或要求所有项目同时生成这些形式。

[开发成品](开发成品/README.md)给出原16个家族的36个实际结构作者入口、复用定义、目标类型及完整接受合同；[Studio交互](../docs/作者/成品/工作台交互与共同状态.md)不是小面板示意。
