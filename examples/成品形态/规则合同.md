# 区间关系与多成品交付合同

本篇拥有本例的精确行为及六种消费边界。它是设计合同，不是已发布的包或已运行软件。`contracts/spec.json`是本篇有限字段、类型和名义值的派生目录；`model/`才是直接作者源。文档锁固定的是设计材料，不伪造目标编译器和宿主实现。

## 1. 类型与引用范围

命名空间为`example/spec/normalization`。Transform是被约束的纯区间变换主体，Delivery是本次要求交付的成品主体，两者不同。两个Transform主体同型不表示同一个函数实例；多个Delivery显式引用同一Transform表示共享其行为，不强制在运行时共用一个服务。

Adjacency是名义值类型，恰含MergeTouching与KeepTouching。Form是另一名义类型，恰含Library、Command、Worker、HttpHandler、Plugin、Panel；Form值是本例明确的交付合同选择，不是SEC全局产品枚举。相同字符串不能替代名义值。局部SubjectKind仅在本份准确已绑定目录的声明范围解析，不与另一个包的同名Transform混用。

所有定义引用依原`DefinitionRef`解析。当前目录内引用的subjectKinds必须唯一解析到本目录实际`req:subject`；跨目录需要公开类型映射，不能从另一包偷取同名类型。名义值类型引用其已声明成员；来源说明不授权执行或安装。

## 2. Canonical：不是一段隐藏的实现步骤

Rule名为Canonical，强度require。字段只有：`on`（本域Transform，必需）与`adjacency`（Adjacency，必需）。定义输入是有限、不可变序列`Interval={lo:Int,hi:Int}`，Int为精确数学整数；输入顺序和重数保留，函数不能修改输入。输入结构解码错误在公开边界处理，与合法类型中lo>hi的业务错误分开。

**正常结果。** 每项是半开区间[lo,hi)。按原位置检查，最早出现lo>hi的项返回`Reversed(index)`，不返回部分成功；lo==hi的项忽略。其余非空项参与下面明确的等价类，返回每类的最小lo和最大hi，并按lo升序输出。空输入返回空序列。

- MergeTouching：两个项有正长度交集或端点相接时相连；取此关系的传递闭包之连通分量。输出是覆盖相同、互不重叠且不再相接的最大区间。
- KeepTouching：只在两个项有**正长度交集**时相连，即`max(loA,loB) < min(hiA,hiB)`；仍取传递闭包。只是相接但没有任何桥接重叠路径的项分别保留。返回分量的包络而不是任意等覆盖切分。

因此[0,1),[1,2)在KeepTouching下仍为两段；再加入[0,2)则三项在严格重叠图中连通，输出一段。只写“同覆盖、升序、不合并相接”不足以排除任意切分，本定义用原输入的严格重叠分量消除了这项歧义。重复相同非空区间属于同一分量；集合去重不得改变最早错误位置。成功结果不依赖输入排序；重新对成功结果规范化得到相同结果。

**效果与进展。** 无外部I/O、输入修改、可观察全局状态、随机或时钟依赖。在合法输入与资源允许时完成；资源耗尽、取消和内部故障不伪装成Reversed或空序列。不存在固定的最大整数位数或输入条数的语义截断；部署可以声明预算，并在超预算时准确拒绝，不将其算作算法成功。

**实现方法基线。** 先按原次序取得/检查区间，再对非空项按lo、hi的精确整数序排序。保持当前分量包络；MergeTouching用`next.lo <= current.hi`合并，KeepTouching用`<`合并；不满足则发到私有结果并开启下一分量。完成后一次交付结果。前缀不变量是：已完成分量不与后续区间相连，当前包络恰为当前连通分量；排序保证再出现的区间不能越过已结束的间隙。比较次数O(n log n)，整数比较/存储成本另计，不把任意精度操作当无条件O(1)。可使用保持合同的成熟实现，不要求全部转写为SEC函数。

## 3. Emit：同一行为，六个真实公共边界

Rule名为Emit，强度require。恰含`on:Delivery`、`operation:Transform`、`form:Form`，均必需。它要求交付引用的Canonical变换及指定消费边界；不通过字段说明自证已有实现。相同Delivery要求两个不相容且未组合定义的form时报告冲突；六份独立成品必须有六个不同Delivery主体。一个宿主能够支持多个形式，不使其自动成为同一个成品。

生产目标由真实目标画像选择。当前先给TS/JavaScript源目标的具体边界，不指定第二语言、不假装所有TS宿主都支持相同I/O。静态作者文件里的Adjacency不是每次运行输入，任何适配不能暗加一个改变算法语义的运行选项。改变此规则应形成新作者选择、绑定与产物。

### 3.1 Library

公开纯调用`normalize`，输入精确整数区间列表，返回完整规范化结果或Reversed。在合格TS边界可以采用下面的**预期目标签名**；这些不是本包已经生成的源：

```ts
export type Interval = Readonly<{ lo: bigint; hi: bigint }>;
export type NormalizeResult =
  | { readonly ok: true; readonly value: readonly Interval[] }
  | { readonly ok: false; readonly error: { readonly code: "Reversed"; readonly index: bigint } };
export declare function normalize(items: readonly Interval[]): NormalizeResult;
```

`declare`只是这里展示接口；请求可运行库的产物必须同时含实际函数主体或允许且已绑定的实现依赖。精确业务index是Int；在物理数组上受资源限制并不把公共协议缩为隐含32位。内部异常/资源中断沿实际目标故障协议，不能吞为ok:false业务错误。类型化调用方按契约传入合法值；不可信外部对象须经边界解码，不能触发getter或代理而仍称纯值输入。

不要求main、启动服务、日志、配置读取或SEC客户端。若现有实现已给出相同公开API，可以直接重导出；需要稳定名字/表示转换时才保留薄适配。包可包含源、类型和所需许可/依赖；无现实需要不生成空目录或重复接口层。

### 3.2 Command

一次进程消费stdin直到EOF，完整内容是一个UTF-8 JSON数组，每项**恰有lo、hi两字段且值为规范十进制字符串**。允许JSON规定的外部空白，不允许BOM、重复键、未知字段、尾随第二个值、`-0`、前导零、加号、小数或指数。十进制约束作用于JSON转义解码后的字符串内容，因此"\u0031"解码为"1"时可以接受；输出重新使用规范数字字符。代理字符、非标量文本和其他非十进制内容不接受。字符串由精确整数解码，不能先转Number。空输入字节不是空数组。结构/编码先完整通过，才检查最早Reversed；不能将未完成解码当作已经取得完整业务输入。超读取预算是资源结果，不伪称语法或区间成功。

成功时stdout只写结果数组，字段序lo后hi、最小JSON分隔、UTF-8无BOM、末尾一个LF，退出0。类型或编码不合法，以及Reversed均退出2，stdout为空，stderr给一个有界错误对象（code、必要index/path），不复制完整输入。启动、I/O和资源故障退出1；取消由支持该行为的宿主映射为取消结果及约定非零退出，不伪造所有平台都有同一POSIX信号。

先完成解码和正常计算，再开始输出；输出途中短写只续已确认的后缀，不能报完整。因为结果可能超过内存，允许私有临时结果/宿主缓冲，但其读取、清理和失败须由所选目标真实承担；纯行为不因此变成有外部可见临时文件的合同。CLI只取得stdin/stdout/stderr及必要进程能力，不因格式处理加载整个工作台或通用任务服务。

### 3.3 Worker

目标是一份可被合格宿主加载的消息工作器，不是带服务器的应用。会话内请求恰为`{id:Text,items:WireIntervals}`，id非空；正常结算响应为`{id:Text,ok:true,value:WireIntervals}`或`{id:Text,ok:false,error:{code,...}}`。协议拒绝使用可区分形态`{protocolError:{code:Text,id?:Text}}`，不得伪装成原活动请求的结算。WireIntervals与Command的整数值格式相同，但消息已是结构值；不能把结构值重复当JSON文本解码。

每次输入在接受时固定，独立请求的成功响应可乱序，接收者按id绑定。已有活动id再次出现用protocolError/DuplicateActive拒绝，不覆盖原请求、不完成原等待槽；原请求仍可以随后产生自己的正常结算。请求格式非法且无法取得合法id时用protocolError/InvalidRequest；不给未接受的请求制造运行结果。id不是跨会话幂等键。重新加载后不继承旧会话响应资格。数据量/队列超预算拒绝相交请求，不静默丢弃；关闭先停止新准入，再排空或准确终结本实例任务。运行资源被强制终止时保持未完成，不为每个请求制造已返回的结果。纯计算无外部副作用，但重复业务结果的交付仍须由客户端接纳规则处理。

### 3.4 HttpHandler

公开一个由宿主调用的处理入口，不隐含监听端口、TLS证书、数据库或守护进程。精确路由为`POST /normalize`，Content-Type为application/json及UTF-8；body和成功响应采用Command的线格式。符合请求返回200；非法结构和Reversed为400。先判断路径：其他路径404；匹配路径的其他方法405并声明允许POST；再核媒体和请求预算，未支持媒体415、超过明确宿主请求预算413。存在多项无效条件时按该检查次序返回，不执行变换。内部故障返回不泄密的5xx，实际断连可能没有响应，不能总宣称状态码已送达。

公共部署边界另由真实选择给出认证、网络暴露、限流、并发和日志策略；声明Handler完整不意味可以匿名上线。请求体取消不终止其他请求；提交响应前保留请求身份和预算；纯规范化可以重新计算，但发送结果和外部计费/审计不能因此被推定恰好一次。业务模块不读取环境变量或运行账户，所需宿主能力经原适配注入。

### 3.5 Plugin

公开本例的宿主插件合同`normalization.plugin/1`（设计合同，不声称现实平台已经接受）。目标TS设计边界明确为下面的工厂和句柄；Interval与NormalizeResult沿Library的相同值合同：

```ts
export interface PluginHandle {
  readonly interfaceVersion: "normalization.plugin/1";
  normalize(items: readonly Interval[]): Promise<NormalizeResult>;
  close(): Promise<void>;
}
export declare function createPlugin(): PluginHandle;
```

这仍是预期接口，不是已经生成的实现。宿主取得提供的接口再显式注册到自己的命令系统，不由导入模块执行全局注册。内部可以串行或使用工作器，但公共异步合同固定，不随实现选择偷偷改成同步返回。正常业务Reversed沿NormalizeResult；已关闭后调用返回以`{code:"PluginClosed"}`拒绝的Promise；资源和内部故障走已声明的目标故障结果，不能混为业务Reversed。

插件只处理宿主显式提供的区间值；无需文件、网络、完整工作区或任意服务定位器。正常挂接不创建第二份算法和长期数据库。每个调用接受时取得合法不可变输入快照，后续调用方修改不得影响它。close先禁止新调用；已接受调用继续结算或在真正取消时以准确取消故障拒绝，只有它们和本实例资源已结算才完成关闭Promise。并发/重复close复用同一关闭意图，不二次释放；终结不能取得时Promise保留未完成或准确失败，不能只撤下入口就报告关闭。接口版本不合格则拒绝加载，不用相同显示名称混接。生产宿主API不同时，需要合格适配并满足其原生命周期，不能把本合同标签当作真实编辑器插件格式。

### 3.6 Panel

这是完整的有限交互产品要求，不是把纯函数类型自动画成表单。面板有输入文本编辑区、规范化按钮、只读结果区和状态/错误区域；输入/输出有独立文本标签，按钮可用键盘到达和激活，状态不只靠颜色传达。两栏放不下各自可读最小宽度时纵向排列；实际样式、字体和主题资产来自明确固定的合格供给，定制品牌是独立作者资产，不交给编译时随机选择。

初态输入为空且无结果；输入完整性不足时保留原草稿。点击规范化捕获本次输入文本与请求代，显示运行状态；得到结果先核当前输入代，旧结果不覆盖新输入。输入变更会让已有结果显示为旧输入结果或明确失效，不假装对应当前文本。失败保留输入与可辨认旧结果，不能清空为“成功的空数组”。正常结果按Command格式显示。重置只清本面板输入/结果，不清浏览器其他页面或宿主文档。

面板的交互责任不能由函数纯度代签。具体目标须在其已声明输入预算下用合格的有界工作片、工作器或其他方法保持输入与取消可接纳；没有相应能力时缩小并明确可接受的预算，或报告此目标不合格，不把无限主线程计算称为可交互。该规定不虚构统一毫秒阈值，也不要求每个小输入都启动额外进程。

不默认新增文件上传、剪贴板、远端请求、账号、拖拽或工作区保存。需要这些功能时新增准确I/O与权限条件。页面卸载停止新请求并按真实宿主处理已接受工作；代码生成、页面装载、实际可交互分别验证。此面板的状态/视图方法必须生成真实事件和渲染，不以截图代替。

## 4. 硬条件、参数与公开边界

Canonical的adjacency是算法结果语义；Emit.form是消费协议选择。缺参数只有在复合定义提供合法default时使用；两者与实现“prefer fast”不同。输出根的exposes仅暴露准确逻辑主体，方法沿Emit.operation取得同一行为，不从名字相似寻找另一实现。

`behavior.Normalize`默认MergeTouching，保留value参数供调用者显式选择KeepTouching。默认升级不覆盖已固定实参；父级独立硬要求不因省略而被删除。六种消费形态的线编码完全一致只说明适配可以复用，不使它们的启动、错误、环境或关闭合同相同。

## 5. 方法、目标成员与失败结果

N0捕获本域定义与作者源；N1解析默认、共享主体和公开边界；N2形成一份Canonical义务及各Emit义务；N3选定合格纯变换方法及所需TS目标表示；N4按被请求的形式取得I/O、消息、HTTP、插件或渲染方法；N5分别生成实际成员并检查公开符号、编码、效果、生命周期和依赖；N6封存独立根或共同发行。缺任何一项时保留对应义务，不产生TODO主体或伪成功空模块。

| 形式 | 预期最小目标成员 | 成为完整该形态的额外条件 |
|---|---|---|
| Library | `normalize.ts`，必要公开类型；包消费时的实际出口/许可 | 有实际实现或允许且取得的运行依赖，不只有declare |
| Command | 共同算法、`command.ts`、必要目标构建与入口信息 | stdio/退出/短写与取消合同成立；没有无关服务 |
| Worker | 共同算法、`worker.ts`及宿主装载所需成员 | 消息编码、队列、会话、结果接纳与终结成立 |
| HttpHandler | 共同算法、`handler.ts`及真实宿主接口适配 | 作为handler完整；独立服务还需明确运行环境，不自动公网部署 |
| Plugin | 共同算法、`plugin.ts`和该真实宿主需要的描述 | 精确接口和卸载/在途责任；不能只交一个类型标签 |
| Panel | 共同算法或工作器、真实视图/事件、样式/消息/入口 | 实际输入、焦点、错误/旧结果与卸载行为均有实现 |

表中路径是本例允许的普通默认布局，不是作者必须抄写的6套目录；公开路径已被消费者使用时必须按实际要求保持。同一共同发行可以共享一份纯实现，但需要不同加载模块时可以合格复制不可变代码，不共享无授权可变状态。某根因宿主缺失而失败，不使其他独立根的准确内容消失；共同发行仍不完整。

## 6. 连续变化与必须保留的反例

把Normalize的默认由MergeTouching改成KeepTouching：未固定的使用点采用新解释，显式MergeTouching仍不变；所有实际消费的新根重核结果关系和真实生成输入。只将库增加CLI输出：共同Canonical主体不变，新增stdio与进程义务；不能反而往库里加入进程启动。只升级HTTP适配：保留纯算法来源，但认证、请求限制与错误合同不得丢失。

两个同型Transform分别要求不同Adjacency可以同时合法；同一Transform同时固定两个不同Adjacency才冲突。一个Library和一个Command引用同一Transform是允许的，不将返回值和stdout混为同一个输出管脚。没有硬时限要求不能宣传截止保证；也不能仅因有纯函数就默认把大计算放在UI主线程阻塞输入。

这里的参考算法推导和接口合同不是实际运行证据。范本不交付已生成TS或宿主运行包；目前缺生产语义执行器、方法实现与准确目标配置。可以完成作者规格与有限静态检查，不能报告六种产品已可用。
