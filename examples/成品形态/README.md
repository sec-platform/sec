# 一项关系的多种成品

本例给出可直接读取的结构作者源，不要求先写普通算法或新的文本语言。它覆盖一份精确区间行为、六个独立消费形式和一个共同发行，完整合同在[规则合同](规则合同.md)。它是设计源码，尚无生产SEC解释器、目标方法和宿主的运行结果。

## 先打开真正维护的文件

| 文件 | 作者决定 | 不需要同步手写 |
|---|---|---|
| [behavior.json](model/behavior.json) | 规范化关系与可见Adjacency默认 | 排序、扫描、队列、JSON编码实现 |
| [library.json](model/library.json) | 作为同步计算库消费 | main、任务服务器、数据库 |
| [command.json](model/command.json) | 按已定义stdio协议一次运行 | 相同算法的另一份主体 |
| [worker.json](model/worker.json) | 消息工作器边界 | 后端HTTP或自带运行容器 |
| [httphandler.json](model/httphandler.json) | 请求处理器边界 | 公网监听、证书与默认认证策略 |
| [plugin.json](model/plugin.json) | 受宿主加载、关闭的能力 | 扩展商店、全局服务定位器 |
| [panel.json](model/panel.json) | 有真实输入、状态、结果和事件的界面 | 工作台完整环境与文件系统 |
| [family.json](model/family.json) | 一份共享行为及六份明确交付 | 把同一算法复制六次，或共用一个错误的可变实例 |

只交付一个库时使用Library根，不把其余五个形式加进产物。Family根显式要求共同交付；某宿主缺失时可保留独立合格成果，但Family本身尚未完整。默认工程不自动执行任何根，`targets`为空准确表示尚未取得目标画像，不能编造profileRef和安装成绩。

## 源码为什么是有限的，而不是把实现藏在空名字里

`Normalize`是普通复合需求定义，公开subject参数on和值参数adjacency；默认是准确名义值MergeTouching。Canonical和Emit的全部输入、数学关系、错误、作用、资源、目标接口和方法在同一[合同](规则合同.md)中明确；其有限字段目录在contracts/spec.json派生。源码引用真实设计，但目录中的implementation仍为unbound，不自证已可运行。

六个调用源通过省略默认只写实际差异，实例化器在定义自己的固定环境取得该值，源不被写回成展开树。硬约束不能被默认覆盖。`exposes`标出本定义公开的逻辑主体；模块exports选择复合定义；目标的normalize函数、进程或handler由相应合同解释，不从JSON对象的第一项猜。

## 三次需求变化

**只增加交付形式。** 原Library不变，新增Command源或选择Family中的相应成员。Canonical的行为与定义不动，生成新增stdio/进程边界和必要成员；如果两个输出打成一个包，共同配置由原目标组合器汇合，不由两个适配器互相覆盖。

**改变未固定的默认。** [完整behavior.keep.json](后继示例/behavior.keep.json)是behavior的完整后继，默认变为KeepTouching。按明确采用关系替换原behavior后，省略参数的六个消费根继承新值。[完整library.pinned.json](后继示例/library.pinned.json)则显式固定MergeTouching；它在该次默认升级中保持旧行为。后继文件不在sourceScopes和modules中，不能与原模块作为两份当前权威同时加载。

**保持行为，替换实现。** 可把合格排序扫描换成另一满足相同输入、结果、失败与资源合同的方法。需求源不改，实际供给绑定与产物输入变化；若新实现要求缩小整数范围、隐含网络或新的宿主，就不属于保持式替换。旧运行实例仍绑定旧制品。

改变默认并不是更改既有实例的运行参数；本例面板没有运行时切换Adjacency的控件。确需该控件时，需把策略变成明确的运行输入并重新定义相交接口与状态，不能复用构建参数名就宣称已支持。

## 大工程怎样沿同一形态展开

结构文件按共变和可见边界分模块；共享定义进入复用库时，消费者只引用其公开合同。目录并不强制每个定义一个文件：本例展开多个根是为了直接查看差异，小工程可将几个定义放在同一模块。

更大的产品可以把不同域的纯关系、状态机、接口、资产和生成器组合起来。公开需求参数不自动等于运行函数参数；外传相同主体保留共享关系；私有实例各自保持身份。多个目标各自绑定真实表示、依赖和宿主；普通重建不重新让AI解释旧需求，也不把本设计库的整个摘要放进用户工程缓存键。

图形化客户端不是前提。一次已知修改可直接更新JSON字段或提交原工具的精确差异；阅读时可只展开当前公开边界。规范仍保存完整含义，不因模型上下文只读一小段而减少。

## 输出与退出

预期目标类型、每种形态的最小成员和方法算法全部在[合同第3与第5节](规则合同.md#3-emit同一行为六个真实公共边界)。当前包不包含生成的运行源码、工作器、插件或界面，也没有运行它们。仅取得接口说明不能宣称软件已实现。

调用端可以请求规格包、可构建源或完整应用等不同终点。完整规格包允许实现unbound；运行库则必须有真实实现；独立应用还须闭合必要宿主进口。缺项应指向具体根、边界、前提与消费者，不要求作者重写全部算法，也不总括成“以后是插件”。

日常维护源为model与本合同；contracts在sourceScopes中明确为derived，只按规则正文派生，不接受另一条独立写入路径。锁是实际设计资料绑定。其resolutionInputs摘要取规范JSON编码（UTF-8、对象键排序、无额外空白）的{project,requests}：project为当前清单，requests按模块ID排序，分别保留moduleId/dialects/imports；不包含源主体、时间或未取得的运行工具。没有历史地址表、旧版本谱系或运行日志需要作为本例的产品前置。
