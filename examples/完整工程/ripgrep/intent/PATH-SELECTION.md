# 路径选择的产品决定

本页以固定 P `4c2362d359d9913c7a5e391ccd79cb4da22bc89b` 为对照保存路径选择合同：哪些路径能够成为结果、规则冲突怎样决定、公开来源与错误怎样保留，以及回调和增量查询的可观察区别。名称拒绝条件以本修订的唯一政策条款为准。产品作者修改这些独立行为；阶段拆分、内部中间值和实际遍历实现由系统承担。此前的 `path-selection.module.json` 将 AfterOverride、StartWalkEntry 等阶段函数暴露为作者输入，现已被 Project 的 semantic 范围排除，原文件只作本地未采用草稿保全，不随案例设计检查点交付，也不是继续开发的顶层入口。

公开 `ignore::Match<T>` 的 `None`、`Ignore(T)`、`Whitelist(T)` 保留无匹配、忽略、允许及其实际载荷；原公开查询、`inner`、`map`、`invert`、clone/debug 等合同随 API 保留（`crates/ignore/src/lib.rs:416` 起）。草稿的 `RuleMatch` 没有因此取得该公开类型的身份。接合时保持真实原始对象与借用关系：override 的匹配或 unmatched、ignore 文件 glob 的来源路径和原始/实际 glob、类型匹配或 unmatched，以及 hidden 来源各自不同，不压成无来源的布尔值或字符串。这些生产者和其公共 API 仍需真实定义。下表中的匹配属于同一候选路径和对应目录/配置，来自实际匹配器；类型合法不能证明来源、目录、配置或规则已经正确生产。

| 公开能力或条件 | 必须保持的行为 | 上游 P 来源 |
| --- | --- | --- |
| 显式 override 的优先与来源 | override 的 Ignore 或 Whitelist 都立即成为结果；仅 None 继续查询 ignore 文件。正向 override 存在时，不匹配的非目录可能产生带 unmatched 来源的 Ignore。 | `crates/ignore/src/dir.rs:500–534`、`overrides.rs:82–110` |
| ignore 文件类别的优先 | 每类的实际结果按 custom ignore、`.ignore`、`.gitignore`、`.git/info/exclude`、global gitignore、显式 ignore 的次序选择第一个非 None；类别优先级高于跨类别的目录远近。 | `dir.rs:548–685`、`lib.rs:484–486` |
| 类型选择与已有白名单的关系 | ignore 文件的 Ignore 直接结束；Whitelist 继续参与类型匹配。类型 Ignore 覆盖早先 whitelist，类型 Whitelist 也成为最终 whitelist 的来源，类型 None 才保留早先 whitelist。 | `dir.rs:527–545`、`types.rs:253–305` |
| 隐藏规则的适用范围 | 只有以上结果是 None 且 hidden 检测启用时，才取得实际 hidden 检测结果；是 hidden 则 Ignore，否则仍 None。Whitelist 不再进入 hidden 检测。`Ignore::matched` 本身不执行 hidden 检测；目录项和增量查询分别在外围调用。 | `dir.rs:485–497`、`incremental.rs:389–407`、`pathutil.rs:19–98` |
| 明确根与 stdout 排除 | 明确根在条目筛选中绕过 ignore/stdout/size/filter；非根的 Ignore 被跳过，None 和 Whitelist 继续 stdout 同一文件判断。真实 stdout 比较错误作为错误返回，不能改成跳过或不匹配。 | `walk.rs:1149–1170`、`1889–1918`、`2085–2098` |
| 串行遍历的尺寸与回调合同 | 只有非目录且配置了大小上限才检查大小；大于上限跳过，等于上限或 metadata 不可取得均不因大小跳过。串行实现一旦进入该大小分支就返回，不再调用 filter；未进入大小分支才调用已配置 filter。 | `walk.rs:1171–1183`、`2063–2083` |
| 并行遍历的尺寸与回调合同 | 并行的非根条目先检查大小，再调用已配置 filter，即使已经超限也会调用；两者任一要求跳过则不提交该条目。其 effect 和调用次数不能改成串行短路。 | `walk.rs:1919–1937` |

实际来源载荷的拥有、借用、清理及其他隐含效果沿其真实类型保持；有限纯值核验不能证明清理、失败或目标行为等价。类别内生产者仍需保持真实优先级：从当前目录向父目录找该类别第一个非 None；同目录指定多个 custom 文件名时后指定者优先；显式添加的 ignore 文件从后向前选第一个非 None；单个 gitignore 集合按最后匹配且符合仅目录条件的 glob 胜出。是否读取父目录、是否要求 Git、Git 仓库边界及全局配置影响哪些结果可以产生；启用 `require_git` 时 Git 类规则受原仓库存在和边界逻辑约束，关闭该要求时不能错误保留同一边界。原规则读取允许部分成功并带错误，不能为计算赢家丢弃错误或禁用仍有效的规则。原路径的 `./`、相对根及逐目录转换由真实路径与匹配器定义承接，不能以字符串前缀替代。

合同保留实际查询的条件与相交作用：override 一旦非 None 就不取后续 ignore/type；ignore 的 Ignore 不取 type；hidden 只在最终规则 None 且检测启用时取得。检查确认隐藏、检查未确认隐藏和根本没有执行检查是不同情况，不能靠同一个布尔值抹去作用差异。实现组织可以改变，但不能预先执行所有匹配器后只选择一个返回值。

## 名称政策：一个作者发生点

以下规定本修订的名称含义。它是路径合同的一部分，不要求作者声明私有 `FileName` 函数、阶段对象或运行版本选择器。[真实修改补丁](../changes/tail-dot-name.patch)记录从 P 到 Q 的一条拒绝条件变化，仅在 P 前像相符时应用；修改说明与消费者审查见[再次修改](../changes/README.md)。

Unix 路径的原始字节为空，或最后一个字节为 `.` 时，没有名称。

其余情况的名称是最后一个 `/` 之后的原始字节；没有 `/` 时是整个输入。非空路径以 `/` 结尾时，名称是空字节串：`/`、`a/`、`a/./` 都有空名称，不回取之前的分量。“无名称”与“空名称”保持区别。名称保留非 UTF-8 字节，不做 Unicode 正规化、大小写折叠或路径规范化；Unix 的反斜杠不是分隔符。该字节关系可以接纳含 NUL 的纯值，但不因此保证 OS 能创建、打开或遍历对应路径。

非 Unix 平台沿所选工具链 `Path::file_name` 的原合同；不把上述 Unix 规则施加到其他平台。Windows 的隐藏判断先按原调用路径取得文件属性，确认 HIDDEN 时为隐藏，否则继续名称判断；metadata 失败也继续名称判断。目录项是否复用已取元数据、跟随链接时是否实际 stat，保持原调用路径与状态条件，不能统一增加或省去一次读取。

`Types::matched` 仅对非目录且类型 glob 集合非空的输入消费该名称。有名称时交原类型匹配；无名称且有正向类型选择时得到带 unmatched 来源的 Ignore，否则为 None。hidden 的名称判断仅在实际进入该检查时使用：有名称且其原始编码字节以 `.` 开始则为隐藏，无名称或空名称均不由名称确认隐藏。先前 whitelist 和本页的查询条件继续适用，名称政策本身不承诺某个文件最终被搜索或排除。

这份政策来自固定 P 的 `crates/ignore/src/pathutil.rs:19–91,142–170` 与 `types.rs:263–301`；其 Q 修订按固定 P→Q 差异核对。源中的平台范围与独立接受条件必须随候选保留。本文已给出可审查的准确行为，Project 的 design 捕获仍不等于机器解释、API 绑定或生成已经成立。

## 遍历和增量查询的共同保持

stdout 排除消费其实际配置和真实文件身份比较，失败携带原错误；尺寸条件区分未配置上限/目录、不超限/无法取得 metadata，以及取得长度严格大于上限。已配置 predicate 必须按上表真实调用，不能以“未配置”掩盖没有执行的回调；它属于公开 `WalkBuilder::filter_entry` 的消费者合同。临时结果、日志所需的匹配来源和真实错误仍由其实际所有者保持；最终保留/跳过某条目，不抹去已经发生的回调、IO 或失败。这里不要求一组对应这些区别的作者中间枚举或运行台账。

根绕过只适用于上述条目检查，不保证根一定被输出或目录一定被递归：minimum/maximum depth、读取/元数据错误、符号链接、同文件系统、visitor 的 Continue/Skip/Quit、顺序和并行调度仍由各自真实消费者负责。`-` 是特殊 stdin 根，`./-` 是路径；相关根解析仍须实际定义和接合。目录被跳过时，其后代不可因更深的白名单重新被遍历。

公开 `IncrementalIgnore::matched` 不等于单纯复用 Walk 的 filter：它只接受相对该 matcher 根的路径，stdin matcher 始终返回 None。空根路径未产生规则匹配，但深度检查先执行：如果调用者将它当文件且低于最小深度，会得到 Ignore；目录还可能带不在深度范围或不可下探的标记。它按深度区分文件/目录、读取必要父目录并缓存已忽略目录，已忽略祖先使后代忽略。它不运行自定义目录项 predicate 或 stdout 判断；仅在配置了最大大小、路径有效、对象非目录且规则结果不是 Ignore 时尝试 metadata。已忽略的路径不会因大小判断被 stat；若取得的大小超限则返回 Ignore，metadata 失败被收集且保留原匹配。`matched` 在有错误时尝试发 debug 日志，`matched_with_errors` 返回部分错误；它还区分不在深度范围和不再下探的标记。已加载目录的 ignore 文件后续修改不可见，需新 matcher。完整增量状态、生产者及公开接口仍须实际定义和接合，不能由一组纯函数代签。来源：`walk.rs:654–700`、`incremental.rs:175–407,1159–1168`。

原阶段模块没有活动产品导入或输出根，现已退出 Project 的 semantic 选取，原字节与已有局部核验保留为未采用草稿。本页继续承接公开行为与来源，不能因草稿退役删除独立义务。原子规则匹配、平台路径与 bytes、大小/文件身份、错误来源、输入收集、匹配结果的真实来源、读取/并发/缓存行为、运行输出和 P→Q 的消费者变更仍未闭合。局部有限值检查或结构校验只证明绑定的值与结构，不代签生产 Reader、Type/Effect、Target、运行或全工程等价。
