# 参数来源、配置与同次有效决定

本设计源拥有固定 P `4c2362d359d9913c7a5e391ccd79cb4da22bc89b` 的参数来源、配置优先及相交诊断；Q 的这部分没有变化。它与[命令选项](CLI-OPTIONS.md)共同约束[同一次 rg 调用](COMMAND.md)。作者维护哪些输入形成有效决定、哪些失败与已发生作用必须保留；解析器、阶段函数、中间记录、容器串接和局部对象清理由系统组织。

下文的首次/二次解析和配置读取表示真实行为之间的关系，不要求作者提供一组调度函数或向产品传入阶段结果。`A₁`、`A₂`、`C` 是有型输入关系中的逻辑变量，不是新增源码字段、可调用定义或持久对象。它们按[同次绑定](#同次解析与产品投影的绑定)连接命令选项的 104 项产品投影；这份关系签名仍需准确类型引用、固定方法和目标消费者接合，不能代替已经完成的机器绑定。

## 输入关系与选择条件

`A₁` 为首次 `args_os().skip(1)` 的有序原生 OS 参数；只有下述非空配置分支才在配置诊断之后再次取得 `A₂`。`C` 为本次成功读取配置形成的完整有序参数。令 `D(A)` 表示[命令选项](CLI-OPTIONS.md)规定的、从产品默认值开始对完整参数 A 取得的有效决定；解析未成功时不存在可交付的 `D(A)`，更不能用部分状态代替它。D 不是一个已存在的 Gift 函数或“同上游一致”的实现引用。

| 同次调用的条件 | 必须保持的结果和发生关系 |
| --- | --- |
| logger 初始化失败 | 在第一次参数解析之前返回 `failed to initialize logger: {err}` 所形成的错误；不读取配置。 |
| 首次参数解析失败 | 传播该次实际错误；不按部分参数修改消息/日志等级，不读取配置，也不因前面出现 help/version 而忽略错误。 |
| 首次完整成功 | 先按 `D(A₁)` 设置消息和日志资格，再检查其最终信息模式和配置选择。 |
| 首次成功且有信息模式 | 交付短/长帮助、短/长版本或 PCRE2 版本中实际选中的模式；优先于 `--no-config`，不读取配置。 |
| 首次成功、无信息模式且禁止配置 | 先发“不读取配置”的 debug；该诊断正常返回后，以 `D(A₁)` 继续。 |
| 首次成功、无信息模式且允许配置 | 观察 `RIPGREP_CONFIG_PATH`；按下表读取与诊断。未设置、空路径、读取失败或成功得到空 C，均不再次取得 argv，以 `D(A₁)` 继续。 |
| 成功得到非空 C，且对应诊断正常返回 | 此后取得 A₂；新的完整输入为 C 在前、A₂ 在后，保持各自次序和重复。由同一选项合同及相同默认值重新取得 `D(C ⧺ A₂)`，不在 `D(A₁)` 上继续更新。 |
| 第二次解析失败 | 传播该次实际错误；保持首次已设置的消息和日志资格，不采用第二次的部分参数。 |
| 第二次完整成功 | 按 `D(C ⧺ A₂)` 重新设置消息和日志资格，再以该完整决定继续；不再次执行信息模式短路或配置选择。 |

串接的准确值关系为：长度等于 `len(C)+len(A₂)`；前 `len(C)` 个出现逐项来自 C，其余逐项来自 A₂。空序列、重复项和元素原生表示均保留；不排序、去重、转码或按名称覆盖。下层可以直接消费两个输入段，或采用合格容器/迭代实现；产品不要求递归 `Concat`、中间列表或两个阶段参数的物理移动。两次 argv 取得不能仅因通常内容相同就合并；实际取得时点和允许省略的依据仍须保持。

第二次成功结果中的信息模式不被本阶段清空或处理。P 的后续 `HiArgs::from_low_args` 断言它必须为 None；配置中的 help/version 因而可能导致实际 assertion Fault，而不是普通帮助或退出 2。`--no-config` 出现在配置内也不取消已经发生的配置读取。panic/abort 的目标行为由实际工具链和 profile 决定，不由本合同虚构为普通 Err。

所有旗标决定均由 CLI-OPTIONS 唯一拥有。配置前置不意味着所有旗标都是 last-wins；上下文优先、追加、累计等仍按各自合同解释。未成功解析的输入、Fault、资源失败及尚未完成，不被一个正常决定值吸收。

## 同次解析与产品投影的绑定

本节把上述选择接到 CLI-OPTIONS 的 `Accepted(r,A,E)` 与 `Decides(r,E,q)`，不定义新的流程程序。κ 是同一次 rg 调用的语义发生，r₁/r₂ 分别是其中实际发生的首次/二次解析；没有进入第二次解析的分支就不存在可读取的 r₂ 端点。所有语义类型均消费同一目标、原生导入及专业定义的固定环境，不允许两次解析使用不同词表、整数宽度或编码解释。

| 有型端点或关系 | 准确来源、成立条件及消费者 |
| --- | --- |
| `A₁ : Seq<OsString>`、`A₂ : Seq<OsString>` | 来自各自实际 `args_os().skip(1)` 取得；输入接纳视图保留每个值和次序。A₂ 仅在非空 C 的配置诊断正常返回后可用，不能把 A₁ 的值或发生身份冒充 A₂。 |
| `C : Seq<OsString>`、行错误序列 | 固定 P 的 `config::parse` 成功返回类型为 `(Vec<OsString>, Vec<anyhow::Error>)`，两项来自同一次完整读取。C 取其参数值投影，错误按原序报告；失败时没有成功元组，不能从先前读到的前缀构造 C。 |
| `A(r₁)=A₁`；`A(r₂)=C ⧺ A₂` | 第二个等式只在上述分支成立，串接按本页长度/逐项关系解释。两次各自从同一默认决定开始；不是在 q₁ 上应用 C，也不是让配置覆盖 CLI 的最终字段。 |
| `Accepted(rᵢ,A(rᵢ),Eᵢ) ∧ Decides(rᵢ,Eᵢ,qᵢ)` | 只在对应解析全部正常接纳成功时取得。qᵢ 的每个投影均由 CLI-OPTIONS 的类型、默认和逐项关系确定；任何投影不得来自另一次解析、另一调用或未接纳的输入。 |
| `qᵢ.messagesAllowed`、`qᵢ.ignoreMessagesAllowed`、`qᵢ.log` | 首次成功后设置消息/日志资格；第二次成功后才再次设置。配置读取、行错误及其 debug 消费 q₁；第二次解析失败也不提前采用 q₂。ignore 消息实际还要求 messagesAllowed。 |
| `q₁.information : Option<Information>`、`q₁.configAllowed : Bool` | 先按 information 选择信息出口，只有 None 才消费配置门控；二者均来自完整 q₁。不能从原始 argv 搜到 help/no-config 就跳过其他值的接纳。 |
| 继续命令的产品投影 `q` | 无信息出口且不发生重解析时，对每个产品投影 p 有 `q.p=q₁.p`；实际重解析成功时对所有 p 有 `q.p=q₂.p`。这是整份语义的选择，不把部分旧值与部分新值拼合，也不要求运行时搬运一个总记录。 |

固定 P 的 `Parser::parse` 实际接收原生参数迭代与 `&mut LowArgs`，返回 `anyhow::Result<()>`，**没有返回 q**。成功后的 q 是由同次输入、接纳和产品合同确定的语义投影；参考实现的对应关系要在实际成功后的状态及消费者上检查，不能伪造一个 return(q) 观察。失败时内部 LowArgs 可以已部分改变，但本产品没有采用这些部分决定的出口。LowArgs 的私有字段和布局不因此进入作者合同；另一个合格实现也不必产生它。

正常继续还保持以下区别：首次信息出口只消费 q₁ 中的信息选择；配置中的信息项属于 q₂，第二次成功不再走该出口。因此 q₂.information 为 Some 时仍到达后续高层断言，按真实 Fault 合同处理。信息、普通成功、参数 Err、配置捕获错误和诊断直接退出属于不同可用域，不能只把它们投影为一个退出整数。

这些端点与关系交给原[观察绑定](../../../../docs/编译/内核/领域方法与整体根.md#meaning-observation-binding)的发生、可用性和共同主体检查。类型同为 anyhow::Error 不足以连接两次失败；关系成立也不自动取得一次 IO/进程退出的完成回执。缺准确引用或固定方法时保留相应 Need，不凭本节记号合成接口、运行日志或一个无条件成功的 Rule。

## 消息资格与配置观察

普通消息资格为同次 q.messagesAllowed，ignore 消息资格为 q.ignoreMessagesAllowed；ignore 消息实际显示还要求普通消息启用。这两个投影分别对应参考实现的 `!noMessages`、`!noIgnoreMessages`。q.log 的 Warn/Debug/Trace 分别对应 P 的 None/Some(Debug)/Some(Trace)。第一次设置发生在信息模式、配置门控和读取之前；第二次设置仅在非空配置后的完整解析成功时发生。名字相同的配置项不创造独立控制状态。

以下配置观察发生在相同调用、环境取得和路径上。它们不是作者必须定义的 `ConfigRead`/`ConfigDecision` 运行变体，所选实现可以融合内部处理，但不能丢掉外界可区分的分支。

| 实际配置观察 | 实际诊断和继续条件 |
| --- | --- |
| 环境变量未设置 | 先发未设置环境变量的 debug；随后外层发无额外参数的 debug，以首次决定继续。 |
| 环境变量设置为空 | 不读文件；外层发无额外参数的 debug，以首次决定继续。 |
| 非空路径，打开或读取失败 | 按首次消息设置报告 `rg: failed to read the file specified in RIPGREP_CONFIG_PATH: {error}`，随后外层发无额外参数的 debug，以首次决定继续。该次部分参数和部分行错误不作为成功读取结果报告。 |
| 读取成功 | 按首次消息设置依序报告所有行转换错误，形式为 `rg: path:line: error`；随后发带路径和参数的 debug。C 为空时，外层再发无额外参数的 debug；否则进入上述再次取得 argv 与解析的分支。 |

配置文件按 bstr 1.13.0 的 `BufReadExt::for_byte_line_with_terminator`、`ByteSlice::trim` 与 `ByteSlice::to_os_str` 合同解释：逐行裁去 Unicode White_Space 两端；空行及裁后首字节为 `#` 的行不产参数；其他整行各产一个参数，不做 shell 分词。Unix 保留非法 UTF-8 字节；非 Unix 转换失败记录该行错误并继续。行号从 1 起，包含空行和注释行。只有完整读取成功才报告收集的行错误并采用 C；实际 IO 失败不能当作一个可跳过的行转换错误。

配置失败与逐行转换错误使用 `message!`，不是 `err_message!`，不会仅因这些消息而设置命令退出决定所用的 `errorRecorded`。`--no-messages` 可以抑制这些消息，debug/trace 依日志等级另行控制。所有启用的消息及日志仍可能在 `eprintln_locked!` 写入失败时直接退出；必须在实际失败位置接合 [RequestedExit](cli-exit.module.json) 的相应决定，不能先返回阶段结果，再回 main 以相同退出码替代。已经产生的输出前缀不回滚；尚未完成的诊断不被当作成功回执。

## 真实类型与发生点

下表固定实际输入及错误来源，供[原观察绑定算法](../../../../docs/编译/内核/领域方法与整体根.md#meaning-observation-binding)形成有型关系。它不要求作者维护私有 `LowArgs` 的副本、`LowState<Rest>`、阶段请求载荷或额外的错误类型参数。

| 内容 | 固定 P 的真实来源 | 保持条件 |
| --- | --- | --- |
| 原生参数 | `std::ffi::OsString`；命令行来自 `std::env::ArgsOs` 的元素，配置来自成功转换后的整行 | 保留顺序、重复和平台原生值；不能统一替换为 Unicode Text，两次实际 argv 取得不自动合并。 |
| 配置路径 | 非空环境值经 `std::path::PathBuf::from(OsString)` 形成；读取按 `AsRef<Path>` 借用 | 失败、成功、行诊断均关联同一次路径；合法借用不拥有底层路径或使其寿命独立，路径值也不证明文件已存在。 |
| 打开/读取错误 | `config::parse` 返回的 `anyhow::Error` | 打开失败由路径显示值和原 IO 错误格式化构造，读取失败沿 `?` 转换；不能恢复已失去的打开错误链，也不能给读取错误重复加路径。 |
| 行转换错误 | `anyhow::anyhow!("{line_number}: {err}")` 的结果 | 原 bstr 错误已格式化，不再是 `bstr::Utf8Error`；保留真实行号和发生顺序，不以成功参数下标代替。 |
| 参数解析错误 | 两次 `Parser::parse` 各自返回的 `anyhow::Error` | 取对应发生点的实际错误；不与配置/行错误或另一次解析的同型错误互换。 |
| 有效选项 | 本次完整成功解析所确定的产品决定 | 由 CLI-OPTIONS 定义全部值域、默认和关系；后续消费者投影所需决定，不需要一个供本组阶段函数转交的 Rest 容器。 |

配置成功的参数、行错误和路径来自同一次完整读取；失败保留实际错误。P 的 `config::args` 最终把多种失败和空结果都折成空序列，因此不能从其返回的 `Vec<OsString>` 反推出环境、读取和诊断全历史。解释应在真实可用观察上建立关系，不要求实现暴露新运行对象或为逻辑变量写日志。

配置行到 OsString 的转换不拒绝行内 NUL，不能把操作系统命令行通常不可含 NUL 的边界套到配置参数或库的纯值输入。Path/OsString 是合法值不证明可以作为 OS 文件名打开；实际打开、启动等操作在各自边界报告错误。CLI 的取值/附着值平台差异由 CLI-OPTIONS 拥有，不从字符串展示反推原生字节。

真实原生类型和操作沿[既有直接绑定](../../../../docs/编译/内核/原生与跨语言编译.md#直接供给不生成第二份应用算法)取得：由选定 Rust 前端、准确工具链/sysroot、目标和依赖内容派生 ImportedModuleView/SignatureView，保留定义来源、泛型/借用及实际效果；普通应用源不手写 std 接口或转发函数。P 的 Cargo.lock 固定 bstr 1.13.0、anyhow 1.0.104；标准库另由实际工具链固定，`rust-version = 1.96` 只是下界。旧 selector 的 callable/predicate 槽不能导出这些类型，不能用旧 `role:type` 或虚构 moduleId 填空。

## 下层责任、来源与未闭合边界

- 读取器、文件句柄、真实 IO 及失败清理继续由其资源合同承担；私有 Parser 身份、首次 LowArgs 的存储或 PathBuf 局部释放时点不因此成为产品作者决定。不同内部组织仍须保持规定的诊断、首错、输入次序、作用和适用资源要求；不声称 OOM、分配或故障等价，也不强制相同私有分配轨迹。
- 固定来源为 `crates/core/flags/parse.rs:64–127`、`config.rs:16–52,63–107`；`parse.rs:48–53` 与 `hiargs.rs:108–116` 给出后续转换及 special 断言；`messages.rs:33–99`、`logger.rs:31–66` 拥有消息写失败和直接退出的事实。
- 真实原生导入与锁、配置/argv/消息操作的有型观察、CLI 固定解释、完整产品根和目标保持仍未闭合；生产 Reader、类型/效果/借用检查、Rust 生成及实际 Gift 运行未执行。撤去阶段草稿消除了不必要的源码责任，没有把这些缺口变成已完成。
