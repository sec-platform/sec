# 从产品决定修改同一份作者源

可编辑发生点是 [PATH-SELECTION 的名称政策](../intent/PATH-SELECTION.md#path-name-policy)。此修改示例以固定 P 政策为前像；[tail-dot-name.patch](tail-dot-name.patch)给出 Q 的完整编辑差额。补丁路径相对于本 ripgrep 设计目录。应用前须核源前像，变更后仍是同一路径、同一条款及原有引用；不创建 P/Q 运行开关，也不将两份政策同时放入活动 Project。

作者要改变的产品区别是：真实名称可以以点结尾，完整分量 `.` 和 `..` 继续没有名称。该差额只改变一条拒绝条件。共同的字节值域、空输入、空名称、平台边界以及下游规则不随之重写。系统可将这项已接受差额形成准确候选、绑定解释、重算相交消费者与失效证据；普通构建消费已固定内容，不重新猜本段文字。

## 改变了哪些结果

以下判断针对名称政策的实际输入，不把路径字符串有意义混成文件已经存在。P 为 `4c2362d359d9913c7a5e391ccd79cb4da22bc89b`，Q 为其直接子提交 `7155f6408d370e699795dc75e954635abfaf08a6`。原生对照与独立字节见证见[已有审查](../EQUIVALENCE.md#4-pq允许差额及消费者闭包)；该审查的混合原型运行资格不转授给本作者候选。

| 输入区别 | P 与 Q 的关系 | 后续含义 |
| --- | --- | --- |
| `.foo.`、`a/.foo.`、`a/...` | P 无名称；Q 保留 `.foo.` 或 `...` | 在实际进入 hidden 名称检查时，Q 可认定隐藏 |
| `visible.`、`a/visible.` | P 无名称；Q 保留 `visible.` | Q 可参加原类型 glob 匹配；名称本身不属于隐藏 |
| 空输入、`.`、`..`、`a/.`、`a/..` | 两版均无名称 | 不因这次修正新增名称 |
| `/`、`a/`、`a/./` | 两版均有空名称 | 不等同无名称；类型集合仍按原空名称输入处理 |
| 含非 UTF-8、反斜杠或 NUL 的原始字节 | 保留原字节值域；仅拒绝条件有差额 | 不加入解码或 OS 文件存在保证；OS 作用的原错误继续保留 |
| 非 Unix 路径与 Windows hidden 属性 | 本次政策修订无差额 | 仍由原工具链与实际属性取得路径解释，不能用 Unix 向量认证 |

## 系统必须承接的真实消费者

下表属于系统的影响与等价审查，不是作者需重复填写的接线。每个结果只在真实到达条件下消费同一政策；不能先运行全部检查，再用最后结果掩盖多出的作用。

| 消费者 | 进入条件、改变和必须保留的内容 | 固定 P 的定位 |
| --- | --- | --- |
| `Types::matched` | 非目录且类型 glob 集合非空才取得名称。Q 新增的名称按已有类型集合及选择次序决定 Whitelist/Ignore/None；保留匹配来源或 unmatched 来源。 | `crates/ignore/src/types.rs:263–301` |
| `Ignore` 与 Walk 的 hidden 检查 | override、ignore 文件和类型关系先按原条件产生结果；仅结果 None 且 hidden 启用才按名称/平台属性判断。先前 whitelist 不因新名称被推翻。显式根的绕过、串并行回调、错误及递归剪枝沿原路径合同。 | `dir.rs:485–543`、`pathutil.rs:19–91`；[完整路径合同](../intent/PATH-SELECTION.md) |
| `IncrementalIgnore` 的祖先目录 | 按相对根、深度、调用者可选的 normalize 及实际目录访问条件处理；祖先匹配 None 且 hidden 启用时，尾点隐藏目录可成为已忽略缓存，后代随之被忽略。不能沿用旧代 Allowed 缓存证明新政策已生效。 | `incremental.rs:330–387` |
| `IncrementalIgnore` 的当前路径 | 同一根下先取得实际 ignore/type 结果，再在 None 且 hidden 启用时取得 hidden 结果；保持部分错误、深度标记、缓存寿命与原 metadata 条件。这条路径不经 Walk 的目录项 hidden 函数。 | `incremental.rs:393–410` 及本页引用的原合同 |
| Files 与 Search | 消费改变后的实际候选集合；Files 的选中结果与 Search 的内容匹配分别保留原模式含义。显式根条目、stdin、未进入该政策的输入不因名称修订而被强制重新筛选；显式目录根的后代仍按原规则筛选，可能受修订影响。 | [一次调用合同](../intent/COMMAND.md#模式结果与退出决定的接合)、固定 P `crates/core/main.rs`、`haystack.rs`、`search.rs` |
| 输出、统计、错误与退出 | 由同次真实搜索/列举结果继续决定，不能直接把“隐藏”映射成退出码。允许因实际候选集合变化产生相应的输出、选中、错误和统计差额；格式、quiet、BrokenPipe 与同次终结关系保持。 | [正常行为](../intent/COMMAND.md#正常行为不能被简化掉的区别)、[失败与终结](../intent/COMMAND.md#失败位置部分结果与终结) |

政策修订产生新作者候选，旧候选上的解释/目标/证据仅在相交输入和保持条件仍成立时复用。现有运行实例和 IncrementalIgnore 缓存仍归原代；本次没有规定热替换，也不把清空全部缓存作为普通作者编辑的实现步骤。未来运行采用必须选择新实例或履行已有升级合同。

## 当前资格

已经存在的是准确的 P 产品政策、Q 编辑补丁及上述源到消费者的设计审查。它们由 Project 的 `design` 范围引用，尚不是已经取得固定机器解释和 Rust Target 的完整语义作者工程。

下一接合要由当前调用和公开库的真实主体承接名称观察、规则结果及其来源，按整体候选选用既有 Definition/Meaning/Requirement 的实际解释路径，形成可固定消费的内容；不预定所有内容都须经 Rule 的 `validateMeaning`。只有 source 引用、公开 API 名称、补丁可应用或字节向量正确，都不能签发这一资格。本例没有伪填 methodRef，没有新建 FileName Goal，也没有手写目标 Rust；生产 Reader、目标生成、Unix 文件系统与全工程 Native/Gift 比较仍未执行。
