# 连续修改与反例

> 设计候选；与既有规范共用作者身份、语义与执行责任。生产实现与正式采用分别取证。

<a id="first-layer-development-examples"></a>
## 仅修改第一层的连续开发范本与反例

本节是[第一层作者合同](../../docs/作者/第一层语言.md#first-layer-author-language)的具体设计范本。需求、数学定义、候选关系与预期结果是设计内容，不是产品执行记录；随包给出的模块与引用具有真实源码，未提供的生产Reader、Method、Target与运行实现不因这些源存在而被宣称已具备。

<a id="first-layer-interval-example"></a>
### 范本一：没有业务目录项，也不需要作者提供排序算法

开发者的输入可以是：

> 做一个离线区间整理工具。输入有限个整数半开区间；空区间忽略；倒置区间明确报错；重叠或首尾相接的区间合并。结果升序、没有冗余区间、覆盖范围完全相同，不修改原输入。交付一个可调用的TypeScript库和一个CLI。整数按数学整数解释，不允许浮点舍入。具体算法、内部结构和构建配置由系统决定。

这里独立信息已经足以规定常规行为。系统不追问“用哪一种排序、建几个模块、IR用什么节点”，但必须识别CLI的实际编码、公共错误与结果交付要求。它在委派内给出固定选择：CLI逐次读取一份JSON区间序列，端点使用规范十进制字符串，输出同一编码；库采用可保持数学整数的实际目标表示。选择有公开兼容影响，须作为这次候选的明确部分固定，不能每次生成临时改用Number或另一编码。

**准确关系，不是一个空洞函数名。** `IntervalSequence`是有限有序整数对序列。对于合法输入，所有端点满足a≤b；a=b为空区间。本例的覆盖精确定义为整数点集{x∈ℤ｜a≤x<b}的并集；“连续段”指相邻整数没有空缺的段，不使用离散拓扑的连通分量。目标成功结果由这个并集确定，每个输出区间非空，按起点严格升序，且相邻输出满足前一区间右端严格小于后一区间左端。输出覆盖与输入覆盖相等。它等于输入并集的各最大连续区间，因此不会任意切割一个连续覆盖区域。输入重复和原始排列不改变这个成功结果。

活动源使用随包`CanonicalTouch(input,outcome)`与`NormalizeApi`，不再要求一个未物化的ExecutionTrace角色或CanonicalConnectedUnionBehavior名称。结果及业务错误由关系定义；原输入无写入、合法有限输入的正常进展及资源边界分别由接口、所选实现和保证方法承接，不能靠调用者自述执行轨迹证明。倒置端点在定义的入口检查中产生定位到原输入项的失败，不先交换端点后假装用户给了不同输入；输入词法损失和宿主解码错误也不被归为成功空数组。

当前Goal的关系域包含已准确解码的IntervalSequence及Outcome：端点合法时给出规范结果，存在倒置端点时给出原输入中第一个非法位置的Reversed结果。非法JSON、成员类型错误或整数词法损失仍在解码边界拒绝，不能与正常业务Outcome混同。该数学关系不自证任意物理设备能处理任意长度输入。真实目标声明适用的输入/资源及操作条件；已接受范围内须提供正常成功路径，资源不足须有真实依据并准确返回失败，不能把全部有效输入都改成拒绝来满足总函数包装。输入类型/值合同、业务拒绝、运行资源失败与编译器自身资源失败分别处理。

独立手算例：

```text
输入：[[7,9), [1,3), [3,5), [8,10), [4,4)]
输出：[[1,5), [7,10)]
```

空输入的正确输出是空序列；这是合法空域，不是“没有取得输入”。倒置的[9,7)必须失败；大于2^53的端点不能先经浮点转换再补成字符串。这些例子只校准相应区别，不代替关系整体的证明或完整目标符合性。

**系统形成的内容。** 从这份要求形成有准确类型和解释的`module:interval-spec`及其关系定义，按[结构源例](../../docs/作者/紧凑结构与同源编辑.md#first-layer-source-and-editing)产生一个引用它的Goal。系统继续建立Library与CLI消费根，让二者消费同一被接受行为；CLI的输入解码、输出编码、退出行为、帮助和所需配置属于CLI的真实贡献，不能只输出调用库的空壳。区间类型、关系、解释及接口的机器定义已经随包提供；实际方法取得、目标Library/CLI代码与运行检查仍属未完成的实现和证据，不能由这些定义代签。

系统可以选择排序扫描、树或其他合格方法；本文不将某一种算法偷偷变成需求。若选择排序扫描，必须证明或检查其只变换自有工作表示、保持数学整数、正确处理空/重复/相接区间，并将真实实现固定进原Binding。无真实方法时形成系统的实现缺口，而不是要求开发者另交一份算法程序。

**第二次修改仍只动意图。** 用户改为：“只合并确有交集的区间；仅首尾相接的不合并；其他要求保持。”

这个修改不能仅把相邻结果约束中的`<`改为`≤`。那只允许保留相接区间，却仍允许把它们合并，未表达“不得合并”。新的准确关系应以非空输入区间为结点，以正长度交集为边，按其连通分量分别取最小左端与最大右端，再按起点排列；跨分量不能合并。由此同一例子的结果变为：

```text
[[1,3), [3,5), [7,10)]
```

系统修订原关系定义和相交接受关系，重新取得方法资格并更新两个目标根及检查。原模块/对象身份可保持，解释修订必须变化；旧实现恰好在几个样本上仍正确不能作为复用依据。开发者不改排序扫描代码、不重填IR、不编辑两份产物，也不需要知道这个差异在目标实现中对应哪个比较运算符。

第三次若只请求“这次处理另一组区间”，它是运行输入变化，不修改上述作者定义。若只请求“库保留，CLI不再交付”，根选择和真实已发布CLI的退役责任分别处理；不根据取消本次输出选择直接删除旧成员。

### 范本二：状态、交互和真实作用不靠手工设计事务实现

开发者提出：

> 做离线文件整理应用。扫描所选目录，在预览中按内容一致分组；内容相同才视为重复。默认只显示，不改原文件。用户明确选择整理方案并确认后，才能移动选择的文件；不得覆盖已有文件。预览后文件变化要指出并重新确认。中断后能够说明哪些已完成、哪些未完成、哪些结果未知。交付桌面交互和CLI，两者遵守同一规则。

这些都是第一层需求，不要求作者指定数据库表、锁文件、journal字段或文件系统系统调用。系统必须形成并保持以下相交含义：

| 作者要求 | 系统必须实际形成的设计与结果 |
|---|---|
| 内容相同才算重复 | 准确输入观察与所声明的内容等价方法；哈希可以作候选筛选，不以未限定的摘要碰撞假设替代“字节相同”硬要求 |
| 默认只显示 | 查询/预览路径没有移动效果；目标程序可能有移动能力不授权本次开发工具移动用户文件 |
| 明确方案与确认 | 确认绑定准确对象、选择、版本及后果；旧确认不覆盖新文件或变更后的目的地 |
| 不覆盖 | 用真实目标提供的无覆盖保证；缺少所需原子能力时报告限制或选择合格较小操作，不以“先检查不存在”冒充竞争安全 |
| 预览后变化 | 对实际读取与选择基础重核；新内容、替换对象和旧路径身份不能混同；变化后的确认有新基础 |
| 中断可继续 | 原操作身份、每项尝试和读回；未知不能直接重做，同名目的地也不证明本次移动已经发生 |
| 桌面和CLI同义 | 共用接受关系和执行合同，但分别闭合交互、可访问性、参数、消息、错误和退出行为；不能只验一边 |

第二次只改第一层：“对副本目录执行整理，源目录始终不变。”系统必须重算共享对象、实际复制/移动语义、容量、来源及恢复责任，不能只替换路径字符串。若副本目录与源目录真实重叠，必须指出相交条件；不同名字不证明物理隔离。

再增加“如果空间不足，可删除已确认重复项”是一项新的不可逆风险与授权差异，不是普通性能优化。系统须保持原“仅移动”限制直到有权接受新行为；应用未来拥有删除功能也不授权编译期间删除现实文件。

这条完整设计轨迹可在没有GUI运行环境时仍交付准确源与成品计划，但不能报告桌面程序已经运行。真实宿主保证、部署及恢复证据分别取得；它们的缺项不反过来要求开发者承担下层实施。

### 跨领域使用同一第一层，而非复用同一运行模型

游戏中的实体身份、帧次序与网络裁决，仿真中的状态/时间步长/误差，服务中的协议/状态/失败，学习系统中的数据/目标/评价，均可在原有类型、关系、模态和组合中承接；各自准确定义和方法不同。新的业务定义不要求应用作者改编译器核心，也不能由一个“支持游戏/AI/仿真”的标签证明实现能力。若相交公共构造确实丢失了独立区别，由系统在原owner扩展和迁移，保留已有合法路径。

### 范本三：完整本地引用的布尔关系，不再以空名字代替定义

开发者说：“一个项目只有同时被选中且可用时才保留；其他情况不保留。这里只计算决定，不执行删除、移动或通知。”这是一项有限纯业务关系，不涉及任何真实权限推断。

系统固定三个Bool角色selected、available、keep：前两个是该调用输入，第三个是该调用的结果；方向由本例所选消费合同固定，不凭参数名猜测。正确关系为keep ⇔ (selected ∧ available)。所有四种输入均合法，每一种恰有一个合法结果；不能用总返回false满足“不错误保留”而漏掉selected=available=true的正常成功要求。

系统形成一个`gift.author-module/2`模块，局部定义关系如下。完整JSON位于[有限关系样本](closed-boolean/README.md)的 `design/choice.module.json`，其字段沿已读取的准确Schema，而不是自行缩写：

| 定义 | 当前Kind及内容 | 谁维护 |
|---|---|---|
| Bool | `core:type`，`body.type={tag:"scalar",name:"bool"}` | 由系统形成的固定类型别名，不是新业务对象或Grant |
| RelationBody | `core:function`，参数selected/available/keep，返回Bool，effects=[]；if仅有condition/then/otherwise | 该关系的准确纯解释，系统根据第一层变更同步修改 |
| KeepRelation | `domain:meaning`，category=relation，三个one角色、Bool结果、interpretationRef=local:RelationBody | 一份真正有解释的公开关系，不复制第二份判定规则 |
| KeepGoal | `intent:goal`，三个local:Bool角色，achieve条款调用local:KeepRelation并完整绑定 | 表示对该关系的承诺；不隐含任何现实作用 |

RelationBody是“检查给定三元组是否满足”的解释函数，不是“取得keep”的生成实现。它用以下等价分情况定义：selected=false时接受且仅接受keep=false；selected=true、available=false时同样只接受keep=false；selected=true、available=true时只接受keep=true。完整JSON使用literal、var和if，不导入任何未知std或Native实现。纯解释函数无递归、每条路径有限且不需要外部观察；这些是此有限结构的数学性质，不是某个生产解释器已经运行的证据。

Goal公式在这个完整Bool域上的评价，可以将确定的关系值提升为相应支持/反证位；输入为现实“未知”、观察冲突或缺来源时，不属于本例完整Bool值域，不能先填false再评价。无论Goal在设计上满足与否，都不自签真实运行或动作许可。

第二次开发者改为：“被选中或者可用，只要至少一个成立就保留。”系统保留模块、定义、角色和条款身份，改变原关系的解释修订，使keep ⇔ (selected ∨ available)。只需改变RelationBody的被接受含义及其实际依赖的资格，Goal不另建第二套承诺。具体输出差额如下，来自四个完整输入的数学推导，不是产品执行记录：

| selected | available | 第一次AND应得keep | 第二次OR应得keep | 原结果可否不变复用 |
|---|---|---|---|---|
| false | false | false | false | 本输入值相同，但全域旧资格不能整体沿用 |
| false | true | false | true | 不可 |
| true | false | false | true | 不可 |
| true | true | true | true | 同第一行，值相同不代表关系修订相同 |

设计包中的second-change.patch针对同一作者文件，修改后的完整源不作为第二个活动文件并列放入sourceScopes。该源项目只扫描design/*.module.json，不扫描补丁、说明和交付元数据。所有local引用都能从本模块找到声明；这只关闭样本内的引用缺口，Reader、专业解释接纳、Method、Target和完整产品消费根仍需各自实际支持。

该样本不是第一层应当让作者手填的代码长度。用户输入的是上面两条规则；由系统形成谓词解释和物理JSON，是系统代劳的设计结果。自然语言原话作为来源，不与此固定准确关系组成两个竞争可写程序。用户主动选择编辑准确JSON仍然合法，届时相交类型与解释资格照常重核。

### 范本四：存在满足关系，却不存在要求的在线策略

要求是：“在t0输出一个Bool，在t1环境才给一个任意Bool，输出必须等于后来给的输入；不允许修正旧输出，也不允许在t0观察该输入。”t0<t1，环境可独立选择两个值。

离线公式∀x∈Bool，∃y∈Bool，y=x成立。但合法策略在t0能看到的历史对x=false和x=true完全相同，所以两种环境下必须作相同的确定输出。若输出false，未来true会违反；若输出true，未来false会违反。随机选择也不能保证所有允许情况都正确。因而这个准确观察/时序合同下没有满足全部环境的策略。这是本例的有限反证，不是调用一个全域不可判定结论停止工作。

系统应保留原请求并返回准确冲突：未来输入任意、决定早于可观察输入、旧输出不可改、必须完全相等，四项无法共同成立。仅换一个更强模型或目标语言不改变这个约束。实际可继续的不同任务是延后输出、提前取得输入、允许后续修正，或改为某种有准确概率/误差界的预测；它们各改变原接受条件，不能自动算作同一任务的实现优化。

相反，“t1收到输入后输出同值”有直接正常路径，系统无需先完成一般策略合成器；“构建时选定对全部输入都返回同值的固定函数”也可实现，因为策略是恒定的函数identity，而非事先固定一个Bool。第一层不应把值选择、函数选择和未来运行选择混成一个exists。

<a id="first-layer-joint-witness-example"></a>
### 范本五：局部可行不能拼成共同可行

两个组件都使用同一受约束结果y。要求A是y=0，要求B是y=1，各自存在满足实现；合取要求则没有同一个y。系统必须保留共享身份并返回这个冲突，不复制成y_A与y_B来让两个检查分别通过。若用户原本要求的就是两个独立结果，则两个角色应有不同身份，正常可以完成；错误合并身份与漏掉共享身份同样有害。

资源场景给出更接近工程的版本：任务A与B各连续运行40个时间单位，各在运行期间持续占用60个容量单位；共享容量为100，二者都必须在共同开始后的50个时间单位内完成。以上是本例明确假设，不是实际产品测量。

串行需要80，违反期限；任何满足各自期限的开始时刻都在[0,10]，两个长度40的运行区间至少重叠30，重叠占用120>100，所以在这些固定方法下不存在合法调度。调度器不能把全程峰值取max(60,60)=60；若允许另一种真实等义方法把两者占用降至各50，则并发40时间单位是合格候选，但还需该方法的实际资格。增加容量、放宽期限、改输入范围都属于新的要求/环境选择，不是已实现的修复。

这里的结论仅为“固定方法与固定资源下无可行调度”，不是“该业务在任何算法上都不可能”。源码诊断必须指向容量、期限、真实共同资源和方法合同，而不是只报两个节点编译失败。

<a id="first-layer-observation-strength-example"></a>
### 范本六：相同结果样本不意味着相同保证

要求两个Bool各自公平且相互独立。合格联合分布让00、01、10、11各占1/4。若实现只抽一个公平位再复制为两个结果，两个边际仍各为1/2，却只产生00和11各1/2，违反独立性。固定样本分别检查两个输出，或以“少一次随机调用”做优化，均不足以支持原保证。第一层必须保留联合观察，编译器在目标随机源、共享、并行和重放中保持它。

另一个例子是“输入调用后数值没变”和“调用完全不写输入”。先改写再恢复可以满足前者但不满足后者，也可能产生可观察中间状态、触发器或竞争；两者不能由同一个快照相等测试代签。若作者只要求最终值保持，不应反向强加更强无写入，系统可在权限/共享和其他要求允许时采用合格实现。

同样的区别存在于结果排序与稳定排序、最多一次返回与最多一次外部作用、源字节相同与解释相同、预览确认与真实执行许可。其共同准则是按独立观察核变化，不是将所有名称做同义归一。

<a id="first-layer-editor-counterexamples"></a>
### 范本七：短视图和多人修改不能吞掉隐藏条件

源同时规定“只在本机处理”和“至多保留结果7天”。一个只显示保留期的视图将7改成30时，正确动作是修改该发生点的期限并按原授权检查；网络禁止仍保留。错误写回器若从短视图重建整个对象，就会删除网络限制。视图写后读到30并不能证明其余内容保持，所以验收必须比较原源余部和实际失效范围。

若本次主体没有修改保留期限的权力，知道旧值或能够看见源也不产生写资格。若另一个有权用户同时把期限固定为3天，新旧文字互不覆盖的某种拼接仍可能破坏共同要求；需要按准确B/L/U和接受关系给出重基或冲突，不以最后保存获胜。

未展示的秘密或私有约束可由可信服务在完整源上检查保持，不能原样回传到无权客户端来“解释为什么失败”。若没有这样的服务能力，停止相交修改而保全草稿；不为了保证自动化而泄露隐藏内容。

### 范本八：第一层变化不等于现实历史被改写

用户删除一个尚未采用的CLI输出根，系统可以停止该根生成并释放独属临时候选；共享Library和其他根保持。用户删除一个已经发布、仍有外部调用者的CLI根，则同时产生兼容、数据、依赖和旧成员退役判断，不自动删除磁盘上一切同名文件。只有请求并有权实施退役时才执行其真实动作。

同理，把“保存结果”改成“不再保存”可以改变后续行为，不能证明既有存储副本已经删除；把一项策略从OR改回AND不会追溯取消旧代已经发起的操作。编译器必须代劳新的影响、迁移和恢复分析，而不是把责任推给开发者手工编辑日志；现实保证取决于实际提供者与准确权限，不能从新的JSON推断旧效果已回滚。

## 区间范本的机器关系、第二次修改与实际消费

本包`examples/第一层作者/interval/`含实际项目、短Goal、完整解释库、派生/2对照与后继patch。活动sourceScopes只包含design和library，derived仅为只读对照，changes仅为演示差额，不会将同moduleId同时当作多个作者文件。解释库有24个定义，其中18个是纯解释辅助函数；所有local及导入引用均有实际定义。它使用准确候选已规定的std:IntCompare/IntEq/IntAdd/SeqUncons/BoolNot，不捏造Array.sort或库中的隐藏Union原语。源中total仍需相应消费者核证明，不能由该标签自证。

### 关系域和错误的完整定义

输入是任意有限序列的数学整数半开区间`{lo,hi}`，重复与次序保留到解释。lo=hi为空、忽略覆盖；lo>hi为非法。正常结果是`Outcome.Ok(IntervalSequence)`；非法输入唯一结果为`Outcome.Reversed({index})`，index是原输入从0开始的第一个倒置位置。类型/codec错误、资源失败、取消和未结作用不塞进这个业务错误构造，仍走原边界；不能将一个无法读取的整数当普通倒置。

输入的顺序只影响哪一个非法位置最先报告，不能通过先排序让错误位置漂移。空输入正常返回空结果。整数按原Int精确十进制解释，不经IEEE双精度；极大的整数不因某个目标暂缺实现而在源里改值。

对全合法输入，`CanonicalTouch`要求：输出每段非空，按lo升序且前段hi严格小于后段lo；每个非空输入完整归入某个输出；输入和输出覆盖完全相等。这唯一确定相接也合并的最大连续覆盖。

`CanonicalOverlap`把相邻段条件改为前hi≤后lo，并额外要求每个输出内的输入属于一个**正长度重叠连通分量**。最后这个条件不能删：对[1,3)、[3,5)，旧输出[1,5)即使满足覆盖和放宽的输出排序，也必须被拒绝。若加入[2,4)形成真实桥，则两种模式均输出[1,5)。单个[1,5)也不能被拆成[1,3)、[3,5)，因为原输入必须完整属于一个输出。

### 解释不是调用另一套未提供的算法

FirstBad递归检查原输入位置。Canonical检查输出正常形状和边界。AllFit防止跨输出拆分一个输入。Covered在准确整数点计算所属；CoverageEqual在两边所有端点检查覆盖一致。有限半开区间的覆盖只在端点改变；相邻不同端点间不再有变化、最外两边均无覆盖，因此这些点的检查就等价于整个整数域的覆盖相等，不能用任意少量采样替代这项端点论证。

严格重叠使用CutsConnected：对某输出内每个非空输入的起点c，若它严格位于输出内部，则必须有同一输出内另一个输入满足lo<c<hi。按照起点升序看，若某个新分量开始，最早起点没有区间严格跨过它；若每个内部起点都被跨过，归纳地每段加入同一重叠连通分量。CoverageEqual和AllFit同时保证没有虚构外延、遗漏或拆分。该论证不依赖输入原顺序，也不把刚好相接当作正长度重叠。

解释函数只沿有限序列tail递归，内层扫描完成后外层tail下降，没有增加输入或按数值大小枚举所有整数。各函数的自然数度量是本次递归的剩余序列长度，组合调用图除这些自递归外无循环；因此在数学模型下终止。物理内存、整数运算费用、调用栈与目标实现仍须实际资格；数学终止不承诺统一有限机器在固定期限下处理任意大的输入。

### 具体作者修改

第一层Goal只引用`intervals:CanonicalTouch`；第二次改为`intervals:CanonicalOverlap`，保留模块、Normalize、角色和canonical_result条款id。后继patch只有这一引用行变化，完整解释库不变；消费者按定义/解释新绑定失效，不能把旧检查沿用为新规则满足。修改是新要求，不伪装成格式化或默认升级。

应用模块同时给出真实`core:interface NormalizeApi`，input引用同一IntervalSequence，output引用同一Outcome，errors=Never，effects=[]。这把输入方向、返回类型和“不准出现state-write等已声明效果”的约束写进准确源，而不是让开发者提交一份自报ExecutionTrace；该接口由系统从第一层需求形成，后继只改合并关系时保持不动。接口声明仍不自证真实实现遵守空效果；候选实现的效果/别名/原生边界须取得实际资格，且不能将其运行Fault/资源/取消伪装成Never或正常结果。若某调用载体按原合同返回Result<Outcome,Never>，该载体的外层与业务Outcome仍有明确层次；TS纯函数直接返回Outcome的适配只在原错误和非正常通道完整保持时采用，不擅自剥除有错误可能的Result层。

普通应用作者无需维护这18个函数；它们是系统形成并可复用的关系解释，仍随包交付给专业维护者核查，不隐藏其信息成本。它们用于判断候选结果，不直接提供高效Normalize实现，也不要求每次运行都重放全部规范检查。CoverageEqual用有限端点扫描，严格连通的直接检查可能需要多层扫描；合格方法可以用独立证明或对应符合性证据复用关系保持，不能把本解释器的复杂度伪装成最优生产算法。实现供给可以用排序扫描：忽略已检查的空段，按lo/hi固定顺序排序，累积当前hi；touch使用next.lo≤hi，overlap使用next.lo<hi，取max hi并在不连通时输出当前段。排序、准确整数比较、原输入不变与错误映射由实际Target/Method负责；不以这个设计算法冒充已运行生成器。

### Library和CLI的完整消费合同

| 消费面 | 必需接合 | 不能省掉的边界 |
|---|---|---|
| Library | `normalize(input) -> Outcome`，输入是声明的精确区间序列，输出符合选中Meaning | NormalizeApi明确input/output/错误/效果；Goal的input/outcome与调用值的映射仍由实际Method绑定，不从变量名字猜方向 |
| CLI | 一次请求读取一个JSON区间数组，端点使用规范十进制字符串；正常stdout给出同编码结果数组 | 空、倒置、非法词元、额外输入、编码、资源与取消分开。stderr诊断与退出类别不污染机器stdout；不接受被JS舍入的大数 |
| 纯性与进展 | Library不写调用者输入；CLI只执行获准的读输入/写输出，不暗改文件或联网 | 解释谓词的effects=[]不是业务实现的证明；作用前实际验证、无任何实现一律返回Err不合格 |
| 完整成员 | Library源码/公开声明/依赖，CLI入口/codec/错误/帮助/运行配置、必要来源与对应检查 | 空函数、只有类型、只写两份目录不算完整两个根 |
| 连续修改 | 两根消费同一个选中Meaning，更新相交实现与证据，保留不相交结果 | 只更新Library而CLI仍使用旧“相接”规则不能算共同交付成功 |

这一具体产品的TS Library正常签名为`normalize(input: readonly {readonly lo: bigint; readonly hi: bigint}[]): Outcome`；Outcome分别为带结果数组的Ok和带精确零基index的Reversed。bigint只是所选TS实现表示，不反向成为公共数学整数定义；只写readonly类型不能证明实际函数不修改输入。运行Fault、资源不足和取消沿相应真实通道，不包装成Reversed。

CLI的唯一正常输入编码是UTF-8的一个JSON数组，成员恰为`{"lo":"规范有符号十进制整数","hi":"规范有符号十进制整数"}`。不允许重复键、额外字段、数字Token代替字符串、非规范前导零、额外第二个JSON值或截断输入；空白按JSON规则，数值符号与Int字面量相同。正常stdout是同形结果数组和一个LF。`--help`是独立无业务作用请求；不提供能暗改已编译Meaning的合并模式开关。

作为这个**生成工具的局部设计**，受控正常退出取0；命令/编码/结构输入错误取2；Reversed取3并在stderr给出`code=REVERSED_INTERVAL`及原输入index；受控运行Fault或资源不足取4并保留其准确code；已确认的协作取消取5。非成功stdout不输出伪造数组，stderr使用一个有界JSON终结记录，包含code和安全message、实际需要的index，不暴露源路径或秘密。宿主强杀、崩溃或根本没有终结记录，不伪造上述控制出口。这里没有改写Gift自身的CLI总协议或宣称这些退出已实测；目标适配须明确区分真实进程退出和请求结算。

源码草稿/保存、定义和字节完整性、CLI读取与作用以及完整成品都是不同消费者。目标成员、准入、所求检查和上述接口全部具备后才可将Library与CLI共同交付标成完成；此阶段不借两份rootId或profile字符串代签其存在。

这里已给接口、编码、算法和失败路径的设计，不捏造尚未存在的profileRef、Grant、绑定锁或生成TS成员。因此示例project故意不声明一个假Target。关系源缺口已补；生产Reader、Method绑定、完整两根的Target适配与真实运行仍是明确下一层实现/符合性缺额，不再称整个关系未设计。

### 本次独立数学核对与其边界

选择端点集合{-1,0,1,2}，穷举长度0至3的1111个合法输入序列、长度0至3的259个非空区间候选序列，对两种规则共比较575498次关系判定。独立参照直接建立输入区间相交图并求连通分量及外包端点，不复用CutsConnected判定；每个输入/模式恰有一个被接受输出，且与图参照相同。另算空、重复、倒置、跨界、桥接、负数、10^50端点等见证。结果是有限数学定义核对，不是Gift源执行、编译器测试或所有输入的运行验证；一般性依据为前述端点与分量论证。上述次数属于原离线交付的独立数学核验范围；本正文保留准确计算口径和一般依据，不将制作回执作为产品运行证据。

## 新的交叉反例与正常出口

**证据洗白。** A缺观察、B同时有支持和反证，material iff投影为T；接受者必须检查真正的推导和共同前提。相反，P有独立合格支持时any(P,Q)不因无关Q未知就失败。公开Bool结果相等、FDE汇总、合格证明和HostGrant是不同事实。

**短源放大。** 连续30层iff只有61个源节点，却能由朴素复制形成超过64亿展开节点；用有作用域的纯项共享保持结构线性，不共用独立IO或Claim发生点，也不让查看展开页面一次物化全部树。

**数据/代码误读。** 一个constant或扩展payload含`{"all":[1,2],"core:type":"text"}`，仍按数据codec保存；只有Formula/Definition位置才识别语法。未知载荷不代表已支持，合法字段也不导致运行安装脚本。

**名字捕获。** 调用者传入引用其局部x的表达式，模板内部也声明x；正确展开按binder身份保持外部引用，不能用字符串替换后绑定到模板x。两个组件Use即使有同样内容也不变成一个共享资源实例。

**求值顺序丢失。** record类型的字段集可无序，但两个字段的IO初始化必须使用Expr的有序字段列表。把两者统一成短字典会改变副作用顺序；精确原形正常可表达，不必新造第二语言。

**公开字符域。** 输入数据键`客户编号`不能因内部Identifier是ASCII就被改成另一个wire键；精确格式映射或原有Text/Map分别承担真实用途。映射缺项明确报告，不让原始字节保全代签类型化可编辑支持。

**位置混用。** `A😀中B`的B不是所有编码下同一个offset。过期版本上的“第4个字符”不得应用到新的第4个字节；用同一源修订的宿主坐标转换与前像检查，范围失效后重算。

**部分作用重试。** 一个混合工作区编辑已重命名文件，而后续资源操作失败；状态不能回写“什么都没发生”。恢复读取原/新URI和内容，保留已成结果，不盲重放重命名、不覆盖用户随后编辑。若有单纯文本原子应用资格可复用它，但不升级为磁盘、远端、Git索引的全局事务。

### 准确数据及业务规则

State含poolId、epoch、capacity和有序Entries。Entry含key、quantity和Phase=Held|Committed|Released；key和quantity为正数学整数。poolId为正整数、epoch与capacity非负。Entry的key在同域内唯一，quantity在其生命周期保持。源里的整数是准确业务域内标识/数量，不能冒充现实全局身份、授权或实际库存。

占用U是Held与Committed项的quantity之和；Released为0。合法状态满足U<=capacity。没有独立可写的free/used缓存，free由capacity−U推导；生产实现可以有合格派生索引，但更新和恢复必须保持同一关系。Entry顺序是本有限参照的稳定创建序，实际存储可采用map/索引并投影相同顺序，不要求目标数据库物理按列表存放。

Request含目标poolId、epoch及命令：Reserve(key,quantity)、Commit(key)、Release(key)。Outcome有Created、Observed、Committed、Released（携带准确Entry），以及Invalid、Conflict、Unavailable、Missing、NotHeld、StaleDomain（unit载荷）。这些是本库的业务变体，不修改语言核心的kind或全局错误协议。

| 前置与命令 | 唯一正常结果 | 后状态 |
|---|---|---|
| 请求pool/epoch不匹配 | StaleDomain | 不变，不跨域查找同名key |
| key非正，或Reserve的quantity非正 | Invalid | 不变 |
| Reserve已有key且quantity相同 | Observed(已有Entry) | 不变；若已Released仍返回Released状态，不重新激活 |
| Reserve已有key但quantity不同 | Conflict | 不变，不覆盖数量 |
| Reserve新key，U+quantity+headroom<=capacity | Created(该新Held项) | 仅追加该项 |
| Reserve新key且不满足该容量条件 | Unavailable | 不变，不伪造一个成功预留 |
| Commit/Release的key不存在 | Missing | 不变 |
| Commit一个Held项 | Committed(该项) | 只将其Phase改为Committed，占用不变 |
| Release一个Held项 | Released(该项) | 只将其Phase改为Released，占用减少对应数量 |
| 重复Commit已Committed项，或重复Release已Released项 | Observed(该项) | 不变 |
| Commit已Released项，或Release已Committed项 | NotHeld | 不变；需要新预留或明确补偿，不暗自复活/退款 |

非法State不是任何业务请求正常处理的前提，关系返回false；真实状态损坏应由原故障/恢复入口处理，不能转成Invalid并宣称状态健康。数据语法错误、宿主资源耗尽、取消、未知外部作用及无权调用也不伪装成本表的业务结果；实际API需要保留这些独立通道。

### 关系源码为什么足够准确而不强迫实现照抄

ValidEntries核唯一key和正quantity；Occupied求实际占用；SameEntries保持未变成员；AppendHeld只允许末尾增加一条准确Held项；CommitHeld/ReleaseHeld只允许目标key的阶段变换、其余项逐项保持；MatchesKey保证答复不能携带其他对象或错误数量。Step先核前后状态与目标域，再进入命令规则。每个Outcome分支都穷尽匹配，不使用字符串模糊比较或未给定义的MatchAny业务函数。

所有本地递归都沿有限Entries的tail下降；除这些自递归外，实际调用图无环。故在数学有限值域中终止。真实大整数、状态尺寸、栈/内存、现场读取与目标执行仍需实际资格，`termination:total`不是已执行证明。高效生产方法可采用索引、事务或权利分配；本规范可能反复扫描列表，不能把规范检查器成本宣传成最优产品算法。

两点论证可直接核查。第一，容量不变量由归纳保持：新预留只有U+q+h<=C且h>=0时增加q；确认不改变U；释放减少正q；其他分支不变。第二，给定合法State、准确Request及非负h，各规则的条件互斥且覆盖，答复和参照后状态唯一；原请求范围内可接受的合法新Reserve不能被一律拒绝。但这仍是**一步语义**，不是程序已经保证每个请求最终被处理；真实队列、公平、持久化、权限与外部恢复另消费已有合同。

### 同一第一层的第二次业务修改

NoOversell固定headroom=0；KeepOneFree固定headroom=1。第二次要求“新预留以后至少留一单位余量”只改应用的Meaning引用，完整库、条款id及角色保持。真实差额是新成功Reserve的准入条件，不是把已有Held或Committed项删除。容量2已全部预留时，新规则照样保留这两项并拒绝新的准入；明确要求释放旧承诺才进入独立有权迁移任务。

`changes/keep-one-free.patch`修改实际design文件，after副本仅供比较。新规则和旧规则有相同签名，不意味着旧证据或旧在途操作可以换义；实际绑定与政策生效范围仍须更新。没有在project中放虚构的Target、数据库URI、Grant或回执来伪装完整产品。

### 正常轨迹、并发与回收反例

容量3，从空状态Reserve(1,2)后Commit(1)，再Release(1)得到NotHeld，容量不会凭空恢复。再次Reserve(1,2)返回Observed(Committed)；新增Reserve(2,1)才占用最后一单位。不同pool/epoch的相同key被StaleDomain挡在原域之外。

已释放预留仍保留其key；删除这条记录后，同key的重放会被当成新申请。这正说明数据回收需要窗口、未结责任和原发行域拒旧，而不只是“该行当前占用0”。本库保留完整有限历史，实际无界服务的压缩/退役责任不能由这个有限数学模型代签。

在容量1的两个副本上分别新建不同key的1单位预留，局部均有效，合并却越界。源含义不允许后端以最后写者获胜任意丢掉某个已成功业务。协调或预分权利的正确路线、可用性代价和恢复见原编译承接节；不把同一个方法强塞给所有可安全合并的其他数据。

### 同构使用与不适用范围

此库可以作为同种可替代资源的预留机制被复用，而非内核新增“订单”或“票务”枚举。真实票务还须选座/日期/转移权，支付还须币种、结算和撤回，设备还有实占用/停止、数据访问许可还有规范和撤销；只有这些差额具备才可声明相应完整业务。本例没有自动补入外部法律、市场、物理或行业规则。确认占用永久计入本有限域，补货、销毁、退款、到期和跨pool转移需要明确新增操作/生效语义，不用改旧capacity或复用Released假装完成。

## 其他独立业务反例及其对应正常路径

**群体偏好。** 三人排序形成多数环，系统保留冲突比较关系而非宣称不存在可行方案；已接受的轮转/抽签/优先策略仍可正常选择。不能把某人的源码写权限自动变成代表全体的接受权。

**因果目标。** X=U,Y=X与X=U,Y=U观测相同、干预不同；预测模型不能代签改变X的效果。给定有依据的结构模型和可识别范围后，专业方法正常处理，不因所有现实未知而废弃已有观测结论。

**间歇可执行。** 一个请求无限次具备条件，却每次被另一请求抢走，弱公平仍可能成立。实现若承诺该请求最终服务，要有匹配调度/环境前提；有限期限还需实际容量界，不从eventually推导毫秒上界。

**迟到回执。** 原政策下已接受的动作在新政策生效后才查回。必须记录它在原解释下的真实状态，并分别判断当前可披露/可继续权限；不能重判成过去从未接受或用新ID重做。

**主观评价。** 指定评议者接受某版本可以完成该接受义务，却不证明全人群、所有未来场景都偏好它。探索三种可区分且满足硬条件的候选也是独立可完成结果，不强造唯一最优分数。

## 开放观察的实际关系源：至少、至多与恰好不是同一个计数按钮

开发者可以提出：“根据已经合格取得的范围，判断数量是否至少达到给定阈值；不足以判定时明确返回未定，不能把没取到的记录当不存在。”这一请求的成果是准确分类，不是立即触发业务动作。本包`examples/第一层作者/observation-bounds/`提供实际模块、公开API、完整解释函数、数学向量、/2只读对照和第二次修改补丁。

应用的两个角色是CountQuery与Evaluation，不让开发者传现实授权或自述证据。CountQuery含range及threshold；range含lower与upper。CountRange属于纯数学输入，是否足以代表某个现实查询由原实际适配与Assurance决定。第一次调用可用lower=3、upper=Unbounded、threshold=3，AtLeast应给AllSatisfy；同一输入下Exactly只能给Undetermined。

  "moduleId": "module:count-inquiry",
  "imports": {"counts": {"workspace": "module:count-envelope"}},
  "definitions": {
    "ClassifyCount": {
      "intent:goal": {
        "roles": {"query": "counts:CountQuery", "evaluation": "counts:Evaluation"},
        "clauses": {
          "answer": {
            "achieve": {"counts:AtLeast": {"query": "query", "evaluation": "evaluation"}}
          }
        }
      }
    },
    "CountApi": {
      "core:interface": {
        "operations": [{
          "name": "evaluate",
          "input": {"tag": "nominal", "ref": "counts:CountQuery"},
          "output": {"tag": "nominal", "ref": "counts:Evaluation"},

### 完整关系与合法成功出口

这份应用同时给出准确Goal和接口签名，不按它们同处一个模块就假定已有调用绑定。交付一个实际evaluate端点时，原组合/UseBinding须明确：调用输入映射到query，正常返回映射到evaluation，选择的关系由ClassifyCount的同一条款固定，选定方法承担全部输入的唯一输出及公开效果/错误合同。这个对应由系统从已接受任务形成，不新增作者必填binding字段。本示例未声明假Target，也没有冒称这份绑定已由生产编译器取得。

正常实现不需要枚举现实世界或启动万能求解器：先核lower、threshold及有限upper的数值前提；非法时返回InvalidInput；合法时按表比较至多两个边界，返回唯一Evaluation。相应关系主体仅检查候选Evaluation是否正确；它与产生答案的实现是不同消费者。四个变体穷尽且各分支互斥给出有限确定构造，精确整数比较的字长成本仍真实计入，不声称任意大整数均固定机器时间。

库内四个类型定义UpperBound/CountRange/CountQuery/Evaluation，三个Int比较辅助、四个Evaluation辨别函数、ValidQuery及三个关系主体组成实际机器解释；AtLeast、AtMost、Exactly均提供完整domain:meaning并使用同一CountQuery与Evaluation名义引用。公开入口含UpperBound和CountRange，避免只导出外层结构却无法在准确公开合同中构造其成员。所有辅助无递归、有限match/if，仅复用已有std:IntCompare；没有私设一个查询真实世界的原语。

| lower | upper | threshold | AtLeast | AtMost | Exactly |
|---:|---|---:|---|---|---|
| 3 | 无有限界 | 3 | AllSatisfy | Undetermined | Undetermined |
| 3 | 3 | 3 | AllSatisfy | AllSatisfy | AllSatisfy |
| 0 | 无有限界 | 0 | AllSatisfy | Undetermined | Undetermined |
| 0 | 0 | 0 | AllSatisfy | AllSatisfy | AllSatisfy |
| 4 | 无有限界 | 3 | AllSatisfy | AllViolate | AllViolate |
| 0 | 2 | 3 | AllViolate | AllSatisfy | AllViolate |
| 2 | 5 | 3 | Undetermined | Undetermined | Undetermined |
| 2 | 1 | 3 | InvalidInput | InvalidInput | InvalidInput |

对有效区间，三个关系分别唯一接受表中应有的Evaluation；对负阈值、负下界或倒置有限范围，唯一接受InvalidInput。某个Goal准确实现“分类查询”时可正常返回Undetermined；只有下游独立请求确实要让实际N≥k成立时，才继续其真实实现/取得/作用责任。不得把“正确报告未定”当那条独立要求的完成。

API的effects=[]只声明此纯查询不读取现场或执行动作；输入现实范围由适配取得。errors=Never不抹去解码、宿主故障、资源与取消的真实边界，业务数值域问题已由Evaluation表达。当前没有生产Reader、Method、目标产物或运行服务，因此project不加入虚构Target。完整关系既可供成熟分析方法采用，也允许编译器选择直接比较的轻量实现，不要求每次运行调用一个规范解释器。

### 第二次修改及正常细化

用户改为“判断恰好等于阈值，而不是至少达到”。`changes/exact-count.patch`仅将同一条款中的counts:AtLeast改为counts:Exactly，模块、角色、公开接口和库不变。lower=3且upper未知的正常结果从AllSatisfy变Undetermined；lower=4且upper未知从AllSatisfy变AllViolate。这个差额是业务含义变化，不是类型兼容即可自动采用的实现优化。

同一规则下取得新的完整快照，使[3,∞)细化成[3,3]，Exactly可以由Undetermined变AllSatisfy而无需改源码。反过来，一条所谓独立记录被发现是重复投递，范围从旧[3,3]更正为[2,2]，原Exactly(3)结论失效；这不是合法非空子域细化，不能凭“增量只加信息”强留旧结论。若已触发动作，交原恢复而非通过改结果假装没发生。

### 有限数学核对与一般依据

对0≤L≤U≤8、0≤k≤10的三种关系，逐个枚举[L,U]内整数并与条件表比较，共1485次；无有限上界的固定阈值谓词按其真假分段选择有限见证，核297项，不伪称枚举∞；另核15项非法输入和5040项非空子区间细化。数学一般依据是区间端点与单个阈值的次序，源文件没有被解释执行。后继来源是否可信、范围是否足以覆盖现实、具体目标是否正确和作用是否获准仍是独立问题。

### 接合反例，不将更多数据等同更强结论

**负存在性。** 扫描当前页没发现取消事件，不能据此自动执行不可逆交付；完整的固定日志域或对该对象准确的否定索引可给充分依据。若请求只要求显示“目前未观察到”，该弱结论可正常返回。

**迟到及修订。** 窗口已按估计水位产生100，随后得到同窗−100的更正，新的和可能为0；不能既宣称实时、不可修改、完整且允许任意迟到，又不给真实最终化前提。可修订显示、业务明确结算截止或具有严格封闭能力的源是不同正常路线。

**跨源合并。** 两个源都报告三个对象，却是同三个对象的镜像，唯一计数为3不是6。若它们分别是无去重的六次事件出现，则多重集计数6可以成立；系统不能从“记录”这个词猜语义。

**值域有洞。** 真实候选数{0,2}被安全包络成[0,2]，Exactly(1)未定属于该摘要精度不足，不是所有专业方法无法反证；精细方法可返回AllViolate，引用它实际的候选域。

**同名接口。** 保留CountApi类型不变而将AtLeast改Exactly，对同一个输入改变正确结果；不能凭ABI/Schema相同称公开行为未变。与此独立，新增输出成员还可能破坏旧strict decoder；可兼容的开放画像需要真实证据。
