# 同一作者源码：共享资料与两个独立视图

这是[第一层作者构造](../../docs/作者/第一层语言.md#intent-author-construction)的完整工程设计见证。交付对象是一个可供其他TypeScript工程使用的内存资料库：一个工作区拥有一份资料，主视图和预览视图共享它，各自保有独立阈值。这里写出该工程的全部新增产品含义、组合、边界、目标要求和连续修改；通用值域、调用、模块和资源含义继承语言原合同。它不是完整GUI或持久服务，不虚构已有业务库，也不将本设计稿冒称可由当前Reader执行的文件。

## 从空工程到可接受源码

开发者首次输入可以只有：

> 做一个资料库，资料是带评分的文本。一个工作区内主视图和预览共享资料，但筛选阈值分别调；默认都显示至少5分。给其他TypeScript工程使用。更新资料不能留下半份新数据，关闭之后不能再用。

系统形成下面的同源候选。评分范围、非法输入处理、容量、对外名字和并发调用合同不能从这段话唯一推出；它们应从项目上下文继承、在有效委派内形成明确决定，或只询问剩余重要区别。下面假定这些决定已被接受。作者只维护接受后的源；短句、图和展开视图不是要手工同步的三份文件。

`结构/关系/组件/模块`标识定义体的既有种类，`状态/入口/连接`使用其原合同；资料仓、视图等名字属于这个项目。文中的自然语言定义体明确给出数学域、前后关系和失败结果，不是靠名称调用未提供的能力。此工程所有新定义在下文给出，无未解释的搜索/筛选实现引用。

```text
定义「条目」：结构
  评分：整数，0 ≤ 评分 ≤ 9
  文本：有限Unicode标量序列

定义「资料」：值域
  条目的有限有序序列，允许相同条目重复出现

定义「按阈值保留」(输入：资料, 阈值：0..9整数, 输出：资料)：关系
  输出 = [ 条目 | 条目 来自 输入，where 条目.评分 ≥ 阈值 ]

定义「容量合格」(输入：资料)：关系
  长度(输入) ≤ 10000
  求和 [ Unicode标量长度(条目.文本) | 条目 来自 输入 ] ≤ 100000

定义「资料仓」(初始资料：资料)：组件
  状态：当前资料，属于本实例；创建时取初始资料的值
  创建要求：容量合格(初始资料)
  输出端「快照」：只读借用本次调用开始时的当前资料
  入口「替换」(新资料)：完成或输入无效或容量超限
    合法且容量合格：返回完成，当前资料成为新资料的值
    输入无效或容量超限：返回相应错误，当前资料保持
    对外一次调用只观察到替换前或完整替换后，不出现半份资料

定义「阈值视图」(初始阈值：0..9整数)：组件
  接受端「来源」：每次读取时借用一份资料快照，借用只持续该次调用
  状态：当前阈值，属于本实例；创建时等于初始阈值
  入口「读取」()：资料
    按阈值保留(本次来源快照, 本次当前阈值, 本次返回值)
    不改变资料与阈值，不在返回后保留来源借用
  入口「设阈值」(新值)：完成或输入无效
    0..9整数：当前阈值成为新值，返回完成
    否则：返回输入无效，当前阈值保持

定义「工作区」(初始资料：资料)：复合组件
  成员「资料」 = 采用「资料仓」(初始资料 = 初始资料)
  成员「主视图」 = 采用「阈值视图」(初始阈值 = 5)
  成员「预览」 = 采用「阈值视图」(初始阈值 = 5)
  连接 资料.快照 → 主视图.来源
  连接 资料.快照 → 预览.来源
  入口「替换资料」 = 委托 资料.替换
  入口「读主视图」 = 委托 主视图.读取
  入口「读预览」 = 委托 预览.读取
  入口「设主阈值」 = 委托 主视图.设阈值
  入口「设预览阈值」 = 委托 预览.设阈值
  入口「关闭」：完成
    本工作区从开放成为关闭；重复关闭仍返回完成
    释放本工作区对资料、视图状态与缓存的持有；已返回的值仍有效
  要求：下文的调用、失败、所有权与隔离合同

定义「资料库」：作者模块
  包含上述定义；公开定义「工作区」供其他作者模块采用
  产物入口：创建工作区及工作区的六个入口，按下文目标合同
  要求：下文的交付合同
  实现：私有算法、表示和源布局交由系统；公共入口形状固定
```

`按阈值保留`的同源数学展开是：对输入序列a，令I为所有满足`a[i].评分 ≥ 阈值`的合法位置i按递增排列所得的序列；输出长度等于I的长度，输出第j项等于`a[I[j]]`。这是同一个关系的精确解释，修改该关系后一起更新，不另维护第二个可写body，也不要求作者写循环、容器操作或方法阶段。空输入输出为空；内容相同的两个合格出现保留两次。资料是值，外部调用者修改自己的输入或返回数组不能改变仓内资料；实现可采用复制、不可变表示或其他满足合同的办法。

成员关系表达创建工作区时的三个组件位置。两个阈值视图共用一个定义却有不同状态；两个来源端连接同一个资料仓，不能各复制一个会独立更新的仓。`快照`端提供调用内的稳定只读借用，多读者可以共享；它不是可消耗流或转移唯一所有权的端口。连接不决定执行先后，不把两次读取合并成一次调用，也不产生后台定时刷新。

序列推导已接[普通模块与可组合结构源码](序列派生/README.md)：筛选和条目数分别消费Collect与Length；数值求和消费SumInt或FoldLeft，不要求作者展开遍历代码。若业务确实观察位置，Enumerate同时给该次序列的index/value，不生成基础语言中不存在的任意索引操作。Unicode标量长度另由该说明中的普通Text→Int定义及有限方法设计承担；这份方法设计未安装为可调用供给，完整容量的生产绑定/运行仍未执行，不能把结构源码和数学定义误报为已生成可运行工程。公共输入先完整验证，再判断容量，避免用前缀容量超限掩盖后续InvalidInput。

### 调用、失败、所有权与隔离

这些是上面复合组件的完整合同，和源稿的其他部分属于同一有效源码。首次展开可以分段展示，作者不需重复在每个成员上手写同一规则。

| 对象或边界 | 准确产品决定 |
| --- | --- |
| 创建 | 对目标输入先检查结构和数值域，再检查容量。失败只返回错误，不发布部分工作区；成功返回新的开放实例，各视图按其采用处绑定的初始阈值初始化。空资料合法。不同工作区互不共享可变资料、阈值或关闭状态。 |
| 调用历史 | 本工程是同步、单调用线程使用的库；同一实例的调用不重叠、不重入。跨线程共享或重入调用不属于此版本承诺，源不可因此声称线程安全。所有入口在其同步调用边界完成，无隐含异步队列。 |
| 委托与关闭 | 开放状态下，替换、两个读取和两个设阈值这五个转发入口每次恰好委托对应成员一次，参数、结果和失败保持。关闭由工作区自身完成开放到关闭的状态转换及持有关系结算，不委托虚构成员；重复关闭不重复结算，仍成功。关闭状态下，其他五个入口一律返回Closed且不读取成员。 |
| 输入检查 | 无效包含错误形状、缺字段、额外字段、非整数评分/阈值、超出0..9、非字符串、含未配对代理项的文本。目标数组输入必须是连续数组，条目是仅含score/text的数据记录；访问器、代理等可执行对象不在该值传递接口域内，不承诺无效果读取任意JS对象。 |
| 错误优先与帧 | 已关闭优先于输入检查；开放时输入无效优先于容量超限。无效或超限不修改任何工作区状态；设阈值只改该视图；读取不改状态；替换只改资料，不重置阈值。错误分类不泄漏私有成员或生成路径。 |
| 寿命 | 资料和视图由工作区拥有，外部只持有公共工作区句柄及返回的值。关闭后工作区解除其持有关系；已返回值由调用者持有，仍然有效。解除引用不承诺宿主垃圾收集立即释放物理内存。 |
| 预算 | 容量以条目数和Unicode标量数计量，重复出现分别计数；这不是进程字节上限或耗时保证。若产品增加峰值内存/时延要求，必须另定义计量边界并验证共同实现，不能把这些逻辑计数冒充测量结果。 |

宿主进程终止或分配失败不保证能正常返回业务错误，本版无持久恢复或进程存活承诺。这里的“错误时状态保持”针对表中明确的输入/容量/关闭结果；不以目标不可兑现的任意故障全包保证充当完整性。若以后需要持久性、并发、权限或故障恢复，应把新增区别写进同一工程合同，不能由库名称推定已具备。

### 公共入口、类型与生成源码

本例确实要交付供TypeScript调用的库，因此运行接口必须准确；这不是每个Gift项目都要维护的类型目录。目标入口采用以下值形状，`Result<T>`只表示本表可内联的联合形状，不要求导出名为Result的类型：

```text
条目目标值：{ score: number, text: string }
Result<T>：{ ok: true, value: T }
        或 { ok: false, error: "InvalidInput" | "CapacityExceeded" | "Closed" }
create(initialRows) → Result<工作区句柄>
句柄.replace(rows) → Result<null>
句柄.readMain() → Result<条目数组>
句柄.readPreview() → Result<条目数组>
句柄.setMainThreshold(value) → Result<null>
句柄.setPreviewThreshold(value) → Result<null>
句柄.close() → { ok: true, value: null }
```

每个入口仅返回其实际可能的分支：create不返回Closed；readMain/readPreview仅有成功或Closed；设阈值没有容量错误；replace有三类错误。参数的静态类型是相应条目数组或数值，运行时仍检查数据合同；目标number不扩大评分域。文本采用标量域而非任意UTF-16码元串。句柄是经成功create取得的实例；伪造句柄、修改私有存储和未声明的反射行为不属于公共能力。

对作者模块公开`工作区`，使其他Gift作者可以采用定义；运行库只导出`create`值入口和它所需的可达结构签名。实现类型可内联或保持私有，不额外导出资料仓、阈值视图或一套DTO。这里没有外部规则需要指称内部逻辑主体，因此**不设置暴露主体出口**；未来若有真实消费者，沿原Subject合同增加，不通过公开TS类型伪造此能力。

```text
产物「资料库包」
  目标：TypeScript库，ECMAScript模块；包名 shared-views，版本0.1.0
  包根运行入口：dist/index.js；类型入口：dist/index.d.ts
  包根仅具名导出create，无默认导出；公共句柄方法名按上表
  完整成员：src/index.ts及实际需要的私有源码、包清单、构建配置、说明
  要求：从清单中固定的依赖和构建配置可重建声明的运行及类型产物
  要求：私有源码不得导入网络、文件系统或环境变量读取能力
  实现：私有文件名、函数分解与筛选算法交由系统
```

这里的成员集合是生成责任，不是假装文件已经生成。形成目标候选时，系统必须给出实际文件、固定工具依赖和构建命令；缺少实现时返回准确缺项，不能交付只有声明或空方法的“源码工程”。包版本及接口决定属于工程源，构建锁和派生声明由其原owner承担，不要求作者另维护一份目标普通程序。后续若在生成预览里改内部循环，必须把意图转成适当的实现控制或回源修改；生成区直接编辑不能成为无声的第二状态源。非受管外部文件则按其所有者合同保全。

## 组合后怎样核对含义

这些是设计期可手工推演的判别向量，不是已执行的运行测试。用`[(5,"甲"),(9,"乙"),(5,"甲"),(2,"丙")]`创建一个工作区：

| 动作或反例 | 该源码唯一要求的结果 |
| --- | --- |
| 分别读主视图和预览 | 都返回`[(5,"甲"),(9,"乙"),(5,"甲")]`，两个甲保留；读不改数据。 |
| 仅设预览阈值为8，再读取两处 | 主视图仍有三个条目，预览仅乙。两个采用处的配置相同从未意味着状态同一。 |
| 替换为`[(8,"丁"),(4,"戊")]`再读取 | 两处都只返回丁；预览阈值仍8，主阈值仍5。若主仍返回甲乙，则错误地复制了资料仓。 |
| 设预览阈值为10；或替换超过容量 | 返回相应错误，原资料及两个阈值保持；不能先写一部分再报错。 |
| 输入恰在容量上限/超过一个单位 | 前者可以成功，后者返回CapacityExceeded；空资料可以成功。 |
| 修改调用者保留的输入数组或读取结果 | 不影响仓内值及后续读取。共享的是工作区内部来源，不是可变JS数组别名。 |
| 关闭后读、替换或设阈值；再次关闭 | 前三者Closed，重复关闭成功；之前得到的条目数组仍可使用。 |

所有向量绑定同一次调用和同一实例历史。只证明筛选关系的纯函数例，不能代签共享、帧和关闭责任；只通过TypeScript类型检查也不能证明这些关系。

## 再次修改仍只改同一作者源

下面是从上面0.1.0源出发的四个**各自独立的修改候选**，不是要求作者同时维护四份活动工程。比较视图展示准确前后和影响；接受哪一个才产生相应后继修订，其他候选无运行作用。

### A：只改新建时预览的默认值

```diff
-  成员「预览」 = 采用「阈值视图」(初始阈值 = 5)
+  成员「预览」 = 采用「阈值视图」(初始阈值 = 8)
```

只有新建工作区的预览初值变化，共享定义、主视图、资料连接、运行时setPreviewThreshold含义保持。已创建实例不会被编辑器偷偷重置。对外默认行为改变，发布候选应同时显式更新包版本（本例为0.2.0）与相关说明，不能继续声称完全等价于0.1.0。第一组判别向量在新实例的预览结果变为仅乙；主视图仍三个。

### B：改共享的筛选政策

将`按阈值保留`的`评分 ≥ 阈值`改为`评分 > 阈值`，所有采用该关系的读取都受影响。这是产品含义修改，不是“优化算法”。阈值5时评分5的两个甲都不再输出；两个视图都必须按新关系解释。系统列出共享定义的实际采用处并更新派生结果；作者不用遍历生成文件搜索运算符。发布同样形成显式新版本。若需求只是预览采用严格大于，应建立局部关系或参数化该独立政策，不改共同定义来冒充局部变化。

上述序列推导沿[值与派生集合](../../docs/作者/第一层语言.md#intent-value-expressions)解释：条目绑定本次输入的出现，按位置递增，每个合格出现恰产出一次，重复文本也分别计入容量。筛选与容量已有普通定义和候选codec的准确结构；运行输入、状态与返回继续按下面的同次操作映射接合。设计期展开和结构校验均不表示生产Reader已经支持。

若后续把评分改成可选值，当前比较项失去对所有新输入的定义性。开发者必须明确本次需要的区别，例如“无评分时排除”或“无评分时按指定分值比较”；已由上下文固定时直接继承。它们会产生不同结果，不能由系统暗选。未改变类型时，缺评分仍走原InvalidInput，不能在筛选中按false吞掉；观察尚未知也不等于可选值的缺席。

### C：抽取可复用组合而保持现有行为

```text
定义「双视图」(主初值：0..9整数, 预览初值：0..9整数)：复合组件
  接受端「来源」：沿阈值视图.来源的同一只读借用合同
  成员「主视图」 = 采用「阈值视图」(初始阈值 = 主初值)
  成员「预览」 = 采用「阈值视图」(初始阈值 = 预览初值)
  连接 来源 → 主视图.来源
  连接 来源 → 预览.来源
  入口 读主视图/读预览/设主阈值/设预览阈值：分别委托原成员对应入口

工作区中的变更：
  用成员「视图对」 = 采用「双视图」(主初值 = 5, 预览初值 = 5)
    替代原主视图和预览的直接包含位置
  连接 资料.快照 → 视图对.来源
  四个视图入口改为委托视图对的对应入口；替换、关闭和拥有责任保持
```

抽取保持两个原采用的身份、状态位置与来源绑定；新复合边界不额外创建资料仓，不增加运行调用次数，也不新增对外导出。原复合角色参数提升时先给所有已有使用保留5，不能只改声明漏掉使用点。若工具无法保持身份或发现捕获改变，必须给出准确差异，不能只凭输出文本同名宣布等义。这里不需要产品热迁移；运行采用仍是独立事项。局部把`预览`改名为`副视图`同理应保持身份及全部准确引用，public readPreview的名字不会顺带更改。

### D：只约束目标源码形态，再撤去约束

```text
实现：固定「按阈值保留」的目标定义位置 = src/filter.ts
      该定义保持私有，只由实际读取实现引用；其他私有布局交由系统
```

这是一项有实际目标成员和依赖消费者的实现控制。它不导出filter，不改变筛选政策，不让作者维护第二份TS函数。路径冲突、目标不支持或违反依赖限制时报告具体冲突；不能默默把固定变成偏好。撤去这条固定后布局自由恢复，公共入口、隔离、寿命和读取关系全部保留。其他算法选择也只有在其语义及资源影响准确时才能固定，不能凭一个未定义的“高性能”名字形成保证。

## 同一工程如何形成准确结构

本节将上文已接受内容接到[组件与操作合同](../../docs/作者/组合/定义与接口.md#structured-component-and-call-contract)，不产生第二份可独立修改的产品要求。准确结构采用`projectId=example:shared-views`、`moduleId=module:shared-views`；中文名与局部DefinitionId对应为资料仓/Store、阈值视图/ThresholdView、工作区/Workspace、双视图/TwinViews、按阈值保留/KeepByThreshold、容量合格/CapacityValid。它们是本设计的选定身份，不是已安装库或按文本匹配生成符号的规则。下面给出形成、角色接合与语义的完整设计映射；完整可独立链接的工程模块和目标供给尚未物化，不能把局部结构片段交给Reader冒称整项目。

其中资料与政策关系已经物化为[共享资料关系模块](共享资料工程/policy.module.json)及[说明与证明](共享资料工程/README.md)，实际身份为`module:shared-views-policy`。上文KeepByThreshold、CapacityValid及相关资料关系统一采用该模块的定义；后续根模块以workspace import取得它们，不再复制另一份本地政策。当前`example:shared-views-policy`清单只捕获这条源链，不能冒充本节尚未物化的`example:shared-views`完整工程。Text标量计数也已具备真实原生声明与准确profile来源；函数实现、绑定资格和目标运行仍未执行。

| 作者决定 | 准确形成及唯一消费者 |
| --- | --- |
| 资料仓属于此工作区 | Workspace.composition.components的`instance:store,componentRef:local:Store`；其constructorArguments.initialRows取父构造的initialRows值，不是静态literal或context |
| 两个独立阈值 | main、preview两个ComponentUse，各引用local:ThresholdView，argumentBindings.initialThreshold为有型静态5；各自state.threshold，身份不能合并 |
| 共享资料 | store的snapshot提供端分别连到main/preview的source接受端；两个View引用同一个供应发生，实例并没有复制 |
| 工作区开放/关闭 | Workspace.state.closed:Bool，initial=false；公开api提供端引用六操作WorkspaceApi，六项operationContracts分别附着本工作区操作 |
| 输入成为有型资料 | Store.constructor接受本目标被动值，成功合同将其与state.rows关联；state.rows有Rows类型，省略initial，完整值由同一个成功见证确定 |
| 模板初值进入状态 | ThresholdView.state.threshold.initial为已绑定initialThreshold值；其普通构造参数为空，不能在每次read时重取模板值覆盖状态 |
| 作者出口和目标入口 | 模块exports.Workspace指向该定义；目标ts的outputRoots选择`{rootId:"package",moduleId:"module:shared-views",export:"Workspace"}`；目标合同将构造映射为create、六操作映射为句柄方法 |
| 实现位置 | 独立ControlFile的definition scope、target ts及root package选择；关系、目标产生函数与文件成员各有自己的身份 |

Store的providedPorts为snapshot→Snapshot接口、replace→Replace接口；ThresholdView为read→Read、set→Set，requiredPorts.source→Snapshot；Workspace为api→WorkspaceApi，无外部requiredPorts。Read接口内操作名为read，Set为set；端口发生名与操作名分别解析。状态型、接口I/O/E和上文要求共同限定行为；未列出的专业成员没有被默认为已提供。

**输入域必须包含会被判为无效的输入。**这里的`TargetPassiveValue`是本TypeScript目标边界的名义值域，保留原始binary64分类、UTF-16码元、数据属性、数组孔洞及共享/循环对象图；包含null/undefined、布尔、数值、bigint、symbol、字符串和有限普通数组/数据记录图。可执行对象、Proxy、accessor以及读取会触发任意代码的宿主对象不在此接口承诺域，不能宣称运行器可安全识别所有Proxy。它不是语言新增Any，也不能经JSON序列化丢掉NaN、孔洞或孤立代理项。公开静态TS签名仍使用相应数组/number，运行边界检查覆盖本例承诺的无效被动值。

`ValidRows(raw)`精确要求raw为连续数组，每个条目只含score/text两个数据字段；score为0..9整数，text不含未配对代理项。额外symbol字段、孔洞、循环条目等不满足这项形状；合法空数组满足。`DecodeRows(raw,rows)`只在ValidRows成立时有唯一的值序列rows，保留顺序、重复和Unicode标量，不保留可变宿主别名。`ValidThreshold(raw,t)`在raw为0..9整数时唯一给t。它们是该名义边界的普通关系，必须由准确目标profile解释与证明；未安装profile时保持供给缺口，不把关系名当可执行能力。

成功初始化使用`DecodeRows(raw,rowsAfter) ∧ CapacityValid(rowsAfter)`，所有after cell属于同一次成功构造。无效分支没有rowsAfter；容量错误可准确写为`存在rows：DecodeRows(raw,rows) ∧ 非CapacityValid(rows)`，其rows是逻辑见证值，不是失败实例的状态。完整有效输入的成功或错误分类及同步进展共同约束实现；不能只写后置条件后永远拒绝。实现可先检查再构造，作者不因此维护阶段函数。父构造失败不发布工作区，但已经暂时成功构造的子实例仍须依原拥有合同清理。

### 同次调用的前后关系与固定解释

令S为本次receiver的抽象工作区观察：`Open(D,m,p,H)`或`Closed`。D为资料值，m/p为两个阈值，H为本工作区的持有关系；Closed没有可再读取的子状态。S是原observation:contract在本例的有型观察值，不是新的可写总状态库。before/after必须来自本次c及同一w；调用历史观察另保留实际child调用、访问与持有结算，不能只比较最终S猜“没读取/没释放”。

| 操作与输入条件 | 正常Result与准确后态 | 成员调用和帧 |
| --- | --- | --- |
| create，raw无效 | Err InvalidInput，无已发布receiver | 不把不存在的after state绑定到角色；临时资源仍须结算 |
| create，有效且超容量 | Err CapacityExceeded，无已发布receiver | 容量判断不能遮蔽后续元素无效 |
| create，有效且容量合格 | Ok新w；Open(Decode(raw),本次main初值,本次preview初值,H) | 新实例与其他create隔离；全部成员同一次成功形成 |
| readMain/readPreview，Open | Ok按对应阈值筛选D；S保持 | 对对应View恰一次，View对同一Store本次快照恰一次；借用在返回前结束 |
| replace，Open且raw无效／有效超容量 | Err InvalidInput／CapacityExceeded；S保持 | 两分支也必须委托Store.replace恰一次，不能由Workspace提前拒绝 |
| replace，Open且有效容量合格 | Ok Unit；Open(Decode(raw),m,p,H) | 恰一次；资料原子替换，两个阈值保持 |
| setMain/setPreview，Open且raw无效 | Err InvalidInput；S保持 | 对对应View.set恰一次 |
| setMain/setPreview，Open且有效t | Ok Unit；只把对应m/p改为t | 恰一次；资料、另一阈值与持有保持 |
| 上述五操作，Closed | Err Closed；仍Closed | 零成员调用，零成员读取，不先做raw校验；不能阻止调用者在入方法前求值实参 |
| close，Open | Ok Unit；Closed | Workspace自身解除相交持有一次，已返回值有效 |
| close，Closed | Ok Unit；Closed | 不重复释放，不读取已退役子状态 |

各普通接口的input是唯一逻辑值：无参数方法使用Unit，replace/set使用本profile被动值。output只放成功载荷，errors只列本操作业务错误：create无Closed，read仅Closed，set为InvalidInput/Closed，replace三类，close为Never。目标正常值按上文ok/value/error编码；宿主throw、取消和未知完成不当业务Err。没有暗加物理秒数期限。

例如Store成功构造的一条准确角色接合为：

```json
{"ref":"local:StoreCreated","callBinding":{"at":"success","roles":{
  "raw":{"source":"parameter","name":"initialRows"},
  "rows":{"source":"state","when":"after","cell":"rows"}
}}}
```

StoreCreated表示上面的同一DecodeRows及CapacityValid关系，不是新的阶段函数。类似地，View.read的成功要求把本次来源观察及本次threshold前态与output相连；Workspace每个操作的成功/错误要求以自身closed前态和准确观察相连。守卫和业务错误都属于操作合同，透明连接不能代替。观察Use须明确产出类型、对象、同次入口/完成及释放后的可用域；未取得资格时报告缺口，不能从字符串useId造快照。当前仅结构用例可机查，这些观察消费者与语义资格尚未实现。

### 抽取后仍为同一组实例与调用

TwinViews只需要四个具名providedPorts：mainRead/previewRead分别引用Read，mainSet/previewSet分别引用Set；requiredPorts.source引用Snapshot。其composition包含原main/preview两个View，静态参数分别转传父mainInitial/previewInitial；source向内扇出，四个子provided端分别连接对应boundary provided端。它不增加自己的四个操作合同、关闭状态或资料仓。

这四条provided转发只有唯一、有限、无环、完整接口兼容时透明。Workspace仍持有六个真实操作，Open分支产生一次真实child dispatch，沿TwinViews的别名不再新造第二次业务发生；Closed分支没有dispatch。目标若新增内部栈帧，其资源、错误和调试区别仍需所选目标保持合同判断，不能因“透明”一词免责。

抽取C的显式源身份对应是`Workspace/main → Workspace/pair/main`、`Workspace/preview → Workspace/pair/preview`，Store与Workspace.closed保持，pair是新边界。路径后像本身不证明身份延续；编辑对应必须绑定共同前像、原发生、端口和拥有关系。Workspace释放经新拥有树到达旧叶一次，不能同时保留旧直接边和新间接边造成双重结算。

在这些侧条件下可给出**任意有限合法调用历史**的保持论证，而非只测几个返回值。令ρ把新状态的pair/main、pair/preview映回原main、preview，并在拥有树中收缩无独立状态/作用的pair边界；资料和closed恒等，Closed不读取已释放子状态。构造成功时两个初值、同一资料及独立发生对应，失败时两边均不发布receiver并保持各自临时结算义务。假设第n次调用前ρ成立：上表穷尽本公开操作和正常业务输入分支；read选择同一D与阈值，replace只替换同一D，set只改同一叶，Closed五入口无dispatch，close收缩对应的拥有边且仅结算一次。透明路由把同一child调用及来源借用一一对应，故结果、允许状态变化、访问、重复结算禁止和返回值寿命均保持，ρ在第n+1次后仍成立。反方向展开同一边界给出对应步骤，因而两边在所声明观察上有双向对应。由历史长度归纳，命题对任意有限合法历史成立；A/B改变政策，不适用这个等义结论。

论证的前提包括各叶及Workspace本身满足上表、无重叠重入、正常进展与有限无环转发。它不证明这些实现已经存在或运行，也不证明任意目标物化的pair对象零成本；物理内存、时限、宿主异常和被新profile观察的栈帧仍须另核。若边界缓存快照、合并两阈值、吞掉错误、重复dispatch或保留旧清理边，分别破坏read、set、error、调用次数或close的归纳步，是具体反例而非“以后可能有问题”的泛泛列表。

## 从首次源码连续修改到撤去控制

上面的A—D仍是独立候选。现在明确选定一条**新的连续修订链**R0→R1→R2→R3→R4→R5；这些编号只是例子的前后位置，不是仓库任务身份或已发布版本。每次候选消费前一次真实源/控制/身份对应，产品版本在实际接受相交公开变化时明确更新。

| 边 | 同一源的准确差额 | 必须保留的内容 |
| --- | --- | --- |
| R0→R1，A | preview初始5改8 | main仍5；已创建实例不被重置；共享关系仍≥ |
| R1→R2，B | KeepByThreshold的≥改为> | 主/预览初值5/8继续保持；所有真实关系消费者重新取得资格 |
| R2→R3，C | 抽取TwinViews并传mainInitial=5、previewInitial=8；连接同一Store | 不复制独立C候选的旧5/5；保留严格>、原两个状态与公共六操作 |
| R3→R4，D固定 | 增加下面唯一Control逻辑键 | 不改变5/8、严格>、状态、公开面或源关系身份 |
| R4→R5，D撤去 | 删除该记录，本链明确保留records为空的原ControlFile | 不撤销A/B/C；重新计算剩余布局贡献，合法结果仍可能留在src/filter.ts |

```json
{
  "schema":"gift.control-file/1", "projectId":"example:shared-views",
  "fileId":"engineering-controls", "records":[{
    "scopeRef":{"kind":"definition","moduleId":"module:shared-views","definitionId":"KeepByThreshold"},
    "target":"ts", "controlRef":"generation.definition-file", "mode":"require",
    "value":{"placements":[{"rootId":"package","path":"src/filter.ts"}]}
  }]
}
```

此记录准确消费[definition-file描述符](../../docs/作者/组合/稀疏控制与目标限定.md#definition-file-control)的修订1；真实锁选择描述符和目标profile，不向作者记录添加虚构revision字段。源关系先关联合格的`输入、阈值→输出`构造性实现，再关联该目标中实际产生输出的私有callable anchor，最后落到文件。只把Bool检查器或同名helper放进filter.ts不能满足要求。若需要从内联实现物化anchor，仍须证明正常调用、捕获、错误和资源保持；缺合格构造方向或不能合法合并特化时返回准确Need/不支持，不造假wrapper。

单独文件可能需要内部ESM export/import；包根仍只公开create。文件控制还须接实际build、declaration与成员所有权，不能把src位置直接当dist产物保证。reset后为`records:[]`，不持久化`mode:"reset"`。源关系Definition身份与派生函数身份不同；改作者定义名须同一编辑事务更新准确引用和Control selector，新建同名定义不会继承旧控制。

这条链的判别向量：评分[5,8,9,5]在R1主结果为[5,8,9,5]、预览为[8,9]；R2主为[8,9]、预览为[9]；R3—R5保持R2结果、重复、共享及独立阈值。只比较这组输出不足以证明C，还必须保留上表的发生、访问、寿命与拥有映射。M0—M7沿原[整体修改合同](../../docs/作者/组合/结构编辑与身份保持.md#whole-change-materialization)形成一个源/控制联合候选，不默合并旧草稿，也不把形成候选当生成、发布或运行采用。

自举改名使用同样的区分：原源为input中的不可变值，声明d是其中的真实发生，后源为success output中的候选；它不是after state，也不自动写文件。Conflict没有可读取的后源。保持引用绑定须沿同一源身份对应；无须为“自举”另造一套修改语言。

本轮推导借鉴[Reynolds的局部状态推理](https://www.cs.cmu.edu/~jcr/seplogic.pdf)来区分可修改部分、保持部分及拥有前提；并按[Lamport的精化映射说明](https://lamport.azurewebsites.net/pubs/simple.pdf)明确旧/新状态与观察的对应。这里是将方法应用于本例的设计论证，论文不替Gift证明；透明边界的调用/寿命条件和C的映射仍须本工程逐项核对。没有把所有资源简化成单个堆，也没有凭内部停顿相等抹去终止或真实时间义务。
