# 纯结果关系的目标源码设计

这是[通用第一层完整使用设计](../通用语言完整设计.md)的目标输出设计。代码围栏给出可实施算法与公开表示，不是已由Gift生成或已发布的实现；应用作者仍维护program.module.json中的关系。它与状态例共同检验同一语言的落实边界。

## 准确输出

本例TypeScript目标将源Int表示为bigint，有限序列表示为只读数组，具名变体表示为tag/value。Reversed.index为数学整数；数组的本机索引只用于实际可容纳的数组，返回前转bigint。接口接收准确解码、已形成的被动值；无隐式Number端点转换、用户getter或可变外部别名。物理输入大小和资源失败由目标的操作外层保持，不借资源不足取消正常成功域。

```ts
type Interval = Readonly<{ lo: bigint; hi: bigint }>;
type IntervalOutcome =
  | Readonly<{ tag: "Ok"; value: readonly Interval[] }>
  | Readonly<{ tag: "Reversed"; value: Readonly<{ index: bigint }> }>;

export function normalize(input: readonly Interval[]): IntervalOutcome {
  // 错误位置属于原输入，不能排序后再检查。
  for (let i = 0; i < input.length; i++) {
    if (input[i].lo > input[i].hi) {
      return { tag: "Reversed", value: { index: BigInt(i) } };
    }
  }
  const sorted: { lo: bigint; hi: bigint }[] = [];
  for (const item of input) {
    if (item.lo < item.hi) sorted.push({ lo: item.lo, hi: item.hi });
  }
  sorted.sort((a, b) =>
    a.lo < b.lo ? -1 : a.lo > b.lo ? 1 :
    a.hi < b.hi ? -1 : a.hi > b.hi ? 1 : 0);
  const result: { lo: bigint; hi: bigint }[] = [];
  for (const item of sorted) {
    const last = result[result.length - 1];
    if (last !== undefined && item.lo <= last.hi) {
      if (item.hi > last.hi) last.hi = item.hi;
    } else {
      result.push({ lo: item.lo, hi: item.hi });
    }
  }
  return { tag: "Ok", value: result };
}
```

`callBinding`将原关系input/outcome映到本函数同次调用的参数/返回值。P4选取排序扫描构造，P5选择上述表示，P6检查以下保持依据：第一遍保留最早倒置位置；过滤只去掉空区间；排序不改变覆盖；每次合并保留并集，已输出前缀互不相接且有序；扫描完成时每个非空输入属于唯一输出，输出没有额外覆盖。有限数组上的每遍扫描终止，排序按有限序列排序合同终止。这里是算法保持论证，不是形式证明或所有平台运行证据。

CanonicalOverlap的第二版只将合并判定改为`item.lo < last.hi`，但取得方法资格仍核整个关系：相接输入必须保持两段，每个原非空区间不得跨多个输出，输出覆盖与原覆盖相等。不能只放宽输出间隔约束而继续接受旧合并结果。[实际关系库](../interval/library/interval-spec.module.json)分别拥有这两份准确关系。没有新的运行时touch开关，两个版本各自固定原要求。

公开组合的构造设计如下，省略的import只定位前两项真实生成成员，不提供业务实现：

```ts
export function createTools() {
  const ledger = createLedger();
  return {
    intervals: { normalize },
    reservations: { apply: ledger.apply },
    reservationRetry: { apply: ledger.apply },

```

状态页的createLedger提供箭头闭包apply，所以取出后不丢this。每次工厂调用产生不同内存资源实例；同一返回对象上的两个预留端点共享一个。poolId/epoch值相同不把两个工厂调用合并成现实同一pool；本例身份域包含产品实例。不能将这份单进程内存Profile用作持久库存或支付实现。

本Profile的product根只输出一个公开工厂符号；默认名createProduct，当前显式Control选择createTools。package的exports只暴露index入口，内部normalize/createLedger导出用于源码成员间引用，不构成额外包出口。类型关系必须准确，但不默认增加具名类型的公开出口：内部类型别名与生成声明由目标维护，调用方可据返回结构推导。若作者另要求导出某个SDK类型名，才新增相应公开合同和控制。本例因此不生成一个无独立消费者的公开IntervalApi接口。

本Profile没有CLI根或网络协议，也没有执行外部交易；已有[连续范本](../连续修改与反例.md)的Library/CLI交付义务原样保留，不能由本例library成功代签。字节流适配若被选择，必须沿其精确十进制编码、重复键拒绝、stdout/stderr、退出与取消规则取得独立资格，不能直接JSON.stringify(bigint)。
