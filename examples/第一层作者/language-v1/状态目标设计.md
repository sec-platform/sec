# 同一预留关系的单 owner 状态目标设计

本页是可据以实施的 TypeScript 目标设计，代码只存在于 Markdown 围栏，不是已经运行的服务或生产 Provider。它消费[真实预留定义](../reservations/library/reservation.module.json)的 State、Request、Outcome、Step、NoOversell 和 KeepOneFree，复用[业务执行接合](../../../docs/开发/第一层编译承接.md#business-invariant-effect-lowering)，不增加业务库、Goal、持久日志或通用事务机制。

本例选定单进程、单 JavaScript agent、单 owner、同步调用、非持久内存状态。`module:language-v1-ledger` 的 Ledger 只构造一个 owner；Product 的 `reservations.apply` 与 `reservationRetry.apply` 共享同一个 apply 闭包，本轮没有 CLI 根。Pool 的 `capacityLiteral=1 reservation-slot` 是本例模型配置，不是对物理库存、现实权限或已取得资源的观察。初态准确为 `poolId=1n, epoch=0n, capacity=1n, entries=[]`。

## 准确类型与纯变化构造

`tag/value` 是本例目标变体布局；unit 分支没有 value。源 Int 使用 bigint，不经过 Number。接口边界在进入此方法前已用准确 codec 解码类型、字段、变体及整数；原生 getter、Proxy、回调和任意 `as State` 对象不是中立值。下列深复制隔离合法普通值的可变别名，不自称可以把任意主动 JavaScript 对象变成受信输入。

```ts
export type Phase = "Held" | "Committed" | "Released";
export type Entry = Readonly<{
  key: bigint;
  quantity: bigint;
  phase: Phase;
}>;
export type State = Readonly<{
  poolId: bigint;
  epoch: bigint;
  capacity: bigint;
  entries: readonly Entry[];
}>;
export type Command =
  | Readonly<{
      tag: "Reserve";
      value: Readonly<{ key: bigint; quantity: bigint }>;
    }>
  | Readonly<{ tag: "Commit"; value: Readonly<{ key: bigint }> }>
  | Readonly<{ tag: "Release"; value: Readonly<{ key: bigint }> }>;
export type Request = Readonly<{
  poolId: bigint;
  epoch: bigint;
  command: Command;
}>;
type EntryOutcomeTag = "Created" | "Observed" | "Committed" | "Released";
type UnitOutcomeTag =
  | "Invalid" | "Conflict" | "Unavailable"
  | "Missing" | "NotHeld" | "StaleDomain";
export type Outcome =
  | Readonly<{ tag: EntryOutcomeTag; value: Entry }>
  | Readonly<{ tag: UnitOutcomeTag }>;
export type StepResult = Readonly<{ outcome: Outcome; after: State }>;

export class TargetFault extends Error {
  constructor(readonly code: "INVALID_STATE" | "INVALID_HEADROOM") {
    super(code);
    this.name = "TargetFault";
  }
}

export function occupied(entries: readonly Entry[]): bigint {
  let total = 0n;
  for (const entry of entries) {
    if (entry.phase !== "Released") total += entry.quantity;
  }
  return total;
}

export function validState(state: State): boolean {
  if (state.poolId <= 0n || state.epoch < 0n || state.capacity < 0n) return false;
  const keys = new Set<bigint>();
  for (const entry of state.entries) {
    if (entry.key <= 0n || entry.quantity <= 0n || keys.has(entry.key)) return false;
    keys.add(entry.key);
  }
  return occupied(state.entries) <= state.capacity;
}

export function step(before: State, request: Request, headroom: bigint): StepResult {
  if (!validState(before)) throw new TargetFault("INVALID_STATE");
  if (headroom < 0n) throw new TargetFault("INVALID_HEADROOM");

  const unchanged = (tag: UnitOutcomeTag): StepResult => ({
    outcome: { tag }, after: before,
  });
  const observed = (entry: Entry): StepResult => ({
    outcome: { tag: "Observed", value: entry }, after: before,
  });

  // Step 的域判断先于命令参数判断。
  if (request.poolId !== before.poolId || request.epoch !== before.epoch) {
    return unchanged("StaleDomain");
  }
  const command = request.command;
  const key = command.value.key;
  if (command.tag === "Reserve") {
    const quantity = command.value.quantity;
    if (key <= 0n || quantity <= 0n) return unchanged("Invalid");
    const existing = before.entries.find(entry => entry.key === key);
    if (existing !== undefined) {
      return existing.quantity === quantity ? observed(existing) : unchanged("Conflict");
    }
    if (occupied(before.entries) + quantity + headroom > before.capacity) {
      return unchanged("Unavailable");
    }
    const created: Entry = { key, quantity, phase: "Held" };
    return {
      outcome: { tag: "Created", value: created },
      after: {
        poolId: before.poolId, epoch: before.epoch, capacity: before.capacity,
        entries: [...before.entries, created],
      },
    };
  }
  if (key <= 0n) return unchanged("Invalid");
  const existing = before.entries.find(entry => entry.key === key);
  if (existing === undefined) return unchanged("Missing");
  if (existing.phase !== "Held") {
    const repeated =
      (command.tag === "Commit" && existing.phase === "Committed") ||
      (command.tag === "Release" && existing.phase === "Released");
    return repeated ? observed(existing) : unchanged("NotHeld");
  }
  const updated: Entry = {
    key: existing.key, quantity: existing.quantity,
    phase: command.tag === "Commit" ? "Committed" : "Released",
  };
  return {
    outcome: {
      tag: command.tag === "Commit" ? "Committed" : "Released", value: updated,
    },
    after: {
      poolId: before.poolId, epoch: before.epoch, capacity: before.capacity,
      entries: before.entries.map(entry => entry.key === key ? updated : entry),
    },
  };
}
```

源 Step 是检查 `(before, request, outcome, after, headroom)` 的关系；目标 step 构造其唯一正常答复和后状态。非法 State 不属于关系的正常前提，不能以业务 Invalid 掩盖损坏；TargetFault 是独立目标故障通道。codec、宿主资源耗尽、取消或进程死亡同样不变成本库 Outcome。

## 单实例同步服务与必要隔离

下面是同一代码单元的续段。公开 ApplyApi.apply 直接返回 Outcome。before/after 是保持论证中的逻辑切面，默认不物化调用轨迹；没有相应独立审计需求时，不为每次调用复制和保存整份状态。私有状态只由本 owner 创建并保持不可变，合法的内部结构共享不产生外部写权。

```ts
function copyEntry(entry: Entry): Entry {
  return { key: entry.key, quantity: entry.quantity, phase: entry.phase };
}
function copyState(state: State): State {
  return {
    poolId: state.poolId, epoch: state.epoch, capacity: state.capacity,
    entries: state.entries.map(copyEntry),
  };
}
function copyRequest(input: Request): Request {
  const command = input.command;
  const copied: Command = command.tag === "Reserve"
    ? { tag: "Reserve", value: { key: command.value.key, quantity: command.value.quantity } }
    : command.tag === "Commit"
      ? { tag: "Commit", value: { key: command.value.key } }
      : { tag: "Release", value: { key: command.value.key } };
  return { poolId: input.poolId, epoch: input.epoch, command: copied };
}
function copyOutcome(outcome: Outcome): Outcome {
  return "value" in outcome
    ? { tag: outcome.tag, value: copyEntry(outcome.value) }
    : { tag: outcome.tag };
}
class ReservationOwner {
  #state: State;
  #headroom: 0n | 1n;

  constructor(initial: State, headroom: 0n | 1n = 0n) {
    const owned = copyState(initial);
    if (!validState(owned)) throw new TargetFault("INVALID_STATE");
    if (headroom !== 0n && headroom !== 1n) throw new TargetFault("INVALID_HEADROOM");
    this.#state = owned;
    this.#headroom = headroom;
  }

  apply(input: Request): Outcome {
    return this.#invoke(input);
  }

  // 由已接受的第二次源码/政策采用调用，不作为普通客户端业务命令。
  adoptKeepOneFree(): void {
    this.#headroom = 1n;
  }

  #invoke(input: Request): Outcome {
    const request = copyRequest(input);
    const before = this.#state;
    const headroom = this.#headroom;
    const result = step(before, request, headroom);
    // 先隔离返回值，再提交；不把内部 Entry 别名交给调用者。
    const returned = copyOutcome(result.outcome);
    this.#state = result.after;
    return returned;
  }
}

export function createLedger() {
  const owner = new ReservationOwner({
    poolId: 1n, epoch: 0n, capacity: 1n, entries: [],
  });
  const apply = (request: Request): Outcome => owner.apply(request);
  return {
    apply,
    // 仅供已接受源码/政策的内部采用，不接到产品 publicEndpoints。
    adoptKeepOneFree: (): void => owner.adoptKeepOneFree(),
  };
}
// 产品工厂只创建一次 ledger，并把同一 ledger.apply 接到
// reservations.apply 与 reservationRetry.apply；不能分别 createLedger 两次。
```

构造入口复制整个 State 及每个 Entry；输入复制 Request/Command/payload；返回 Outcome 中的 Entry 另作深复制。step 不修改私有前像，后像只包含内部已有的不可变条目或本次新建条目，所以内部可以共享未变成员而不必再次复制整个 State。调用方即使通过原生可变别名或类型断言修改初态、请求或返回数据，也不会改写已提交私有状态；readonly 只作静态使用提示。公开返回对象自身不是不可变审计凭证，不信任客户端改写后的自报副本。

该方法没有 await、外部 Provider 调用、用户回调或事件发射；单 JavaScript agent 中同步调用直到返回前不会被另一事件任务插入，因此不另加锁、重入状态或排队机制。中立值边界必须先排除主动宿主对象；不把复制期间可能触发任意 getter/Proxy 的原生对象当作这一无回调方法的输入。两个工作线程、两个进程或两个独立 owner 不属于此串行保证。

## callBinding、资源和观察的逻辑切面

本例 callBinding 的对应由同一 `#invoke` 内的源码位置与表达式确定，不要求新增运行时记录：

| callBinding 位置 | 同次调用的实际来源 |
| --- | --- |
| input | `const request = copyRequest(input)` 形成的准确 Request |
| before | `const before = this.#state` 取得的私有不可变前像 |
| after | `step(before, request, headroom)` 的 `result.after`，随后成为私有状态 |
| return | `result.outcome` 的隔离副本 `returned` |

这些对应绑定同一次调用，不能把甲调用的 before 与乙调用的 return/after 拼接。headroom 指明本次采用的关系参数；真正的 Meaning 与源码修订仍由原方法绑定取得，不由一个整数自签。独立审计确实要求运行时捕获时，才按原观察能力取得相应字段、修订、披露权限与成本；本例默认可以消去这些逻辑变量和证明投影，不分配永久 trace。

resourceParticipations 绑定这个 ledger 私有 owner 对应的 Pool。observationParticipations 的 PoolView 以该方法同次调用的相应 State 为观察基础，`ProjectCapturedState` 只是纯 identity 投影；`same-reservation-call-cut` 在本例就是同一同步调用的准入前像和提交后像，不是任意墙钟同刻或客户端截图。closed 仅表示这份有限 State 值的 entries 在该逻辑切面完整，不证明现实库存、全部历史或外部世界已完整观察。声明这一对应不强制把 State 再复制给客户端，也不创造新的资源实例。

线性化点是 `this.#state = result.after`。不变结果也在本次同步调用的相同串行顺序内作出；调用期间没有其他公开入口改变基础。returned 中的 Entry 与该准确后像或原状态的目标 Entry 相等而对象分离。返回复制在赋值前准备，普通复制失败不会在提交后被误报为无作用；宿主死亡或返回途中响应丢失仍可能发生在提交之后。

## 分支保持、失败和第二次修改

合法前像要求 poolId 正、epoch/capacity 非负、唯一正 key、正 quantity，且 Held/Committed 的占用和不超过 capacity。对于准确解码请求和非负 headroom，各正常分支互斥且覆盖：

| 分支 | 准确结果与保持 |
| --- | --- |
| 请求 pool/epoch 不符 | StaleDomain，先于 key/quantity 合法性检查；全 State 不变 |
| 同域 Reserve 的 key 或 quantity 非正 | Invalid，全 State 不变 |
| Reserve 已有 key 且 quantity 相同 | Observed 原 Entry；Held、Committed、Released 都不重新激活 |
| Reserve 已有 key 但 quantity 不同 | Conflict，不覆盖数量，不因容量足够而重建 |
| 新 key 且占用加 quantity 加 headroom 不超 capacity | Created；只追加一个 Held，已有顺序和全部成员保持 |
| 新 key 但容量条件不成立 | Unavailable，全 State 不变 |
| Commit/Release 的 key 非正或不存在 | 分别 Invalid/Missing，全 State 不变 |
| Commit(Held) | Committed；只改该 Entry.phase，占用不变 |
| Release(Held) | Released；只改该 Entry.phase，占用减少原正 quantity |
| Commit(Committed) 或 Release(Released) | Observed 原 Entry，全 State 不变 |
| Commit(Released) 或 Release(Committed) | NotHeld；不复活、不退款、不自动补偿 |

新建由容量准入保持不变量；Commit 保持占用；Release 减少占用；其余分支不变。所有成功答复携带准确目标 Entry，key/quantity 不变；poolId、epoch、capacity 及未选成员均保持。单次有限 State 通过有限遍历构造唯一结果，数学终止不承诺任意大状态在固定机器期限内成功。

本例的最小共享见证是：容量1空态，经 reservations.apply Reserve(1,1) 得 Created；随后 reservationRetry.apply Reserve(2,1) 得 Unavailable；reservationRetry.apply Commit(1) 得 Committed，再 reservations.apply Release(1) 得 NotHeld。若两端分别 new owner，第二项会错误 Created，因此这条轨迹能区分共享实例与同配置副本。

源码第二次将 NoOversell 改 KeepOneFree，对本实例的采用调用 `adoptKeepOneFree()`：只把后续调用采用的 headroom 从0改1，不重写旧 State。容量1中原 Held/Committed 条目保留；同 key 同 quantity 仍可 Observed，原 Held 仍可 Commit 或 Release。即使随后全部释放，新 key 的正 quantity 也因 `0 + quantity + 1 > 1` 得 Unavailable；这是容量1与新政策共同决定的正常结果，不是实现偷偷永拒。容量至少2且可用量满足该条件时仍有新 Reserve 成功路径。历史回执不能用新政策重新判成当时未发生；显式追溯迁移属于另一项独立要求。

TargetFault 与准确 codec 故障发生在本次状态提交前时，本次未提交；本页代码的正常业务拒绝不是 TargetFault。进程崩溃、强杀、内存耗尽或响应丢失没有可靠终结记录时，不能仅因客户端失败认定状态未改。仍活着的同实例可以再次观察成功业务状态：重发同 key 同 quantity 会 Observed。但 Request 没有 operationId，Unavailable 后重发可能因后来释放而成功；本方法没有持久失败回执、跨进程去重或崩溃恢复保证。进程死亡会失去本实例状态；重新启动空实例不能冒充原 epoch 的安全续接，真实重启/持久化必须另取合格方法及域退役协议。

## 替换为持久或事务方法的条件

只有确实需要跨进程、持久化、外部作用或多个写者时才激活相应能力。替换方法必须保持相同输入/Outcome/Step关系、顺序与目标帧，并把同一状态/政策基础上的判断、提交及承诺回执置于真实原子能力内；并发失败重新取前像判断，不返回尚未提交的成功。超时由原 operation 身份和读回处理；不以新请求 ID 重放未知作用。采用不重叠权利分配时也必须证明共享容量和转移期间不重复消费。

Method/Provider 的实际能力、源码绑定、资源身份、观察 cut、故障和进展资格均需相交证据；不能从数据库名称、capacityLiteral、effects 声明或本页 TS 围栏取得。该替换条件保留了成熟事务方法的采用路径，本页没有接入数据库、发布 Provider 或验证运行服务。
