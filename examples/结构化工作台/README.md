# 结构化工作台：先打开这几个文件

[studio.json](model/studio.json)是产品特有选择；[standard.json](model/standard.json)引用完整可复用工作台需求；[searching.json](model/searching.json)展示搜索/替换与共享主体；[完整后继](后继示例/studio.reconfirm.json)只改变预览过期政策。详细合同、展开与边界见[范本说明](说明.md)。

`model/`是十份作者JSON。`contracts/`是从准确规则正文派生的13份字段目录，不是另一份手写业务源。`sec.project.json`只定位工程及输出要求；`sec.lock.json`固定当前可取得的设计资料，不声称已有目标后端。`targets`为空仍不删除源内TS及三平台要求。

[结构编码](../../docs/作者/结构化源码.md) · [Block与管脚](../../docs/作者/组合/定义与接口.md) · [需求规则与供给](../../docs/作者/需求规则与供给合同.md) · [清单、模块与锁](../../docs/作者/工程源/清单模块与绑定锁.md)。

直接查看[工程清单](sec.project.json)与[设计资料锁](sec.lock.json)。

所选完整工作台的屏幕、文件与文档、搜索替换、语言诊断、执行/终端/调试/测试/VCS以及设置/扩展的正常操作、取消与退出，见[交互与共同状态](../../docs/作者/成品/工作台交互与共同状态.md)。原JSON与主体关系不变；没有真实方法的必需动作不能靠隐藏入口取得完整资格。
