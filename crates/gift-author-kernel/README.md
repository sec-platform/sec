# Gift author compiler

This Rust kernel implements the complete selected `design-converged` structural Reader, common name and lexical analysis, and library-level type formation, declaration headers, signature constraints and common body analysis. The repository's `author` CLI exposes the Reader and name analysis alongside a separate bounded `/2` author-to-TypeScript method. The original source bytes remain authoritative; expanded structures, semantic arenas, typed lowering plans, bindings, dependency graphs, project members and source maps are rebuildable outputs.

The `/2` method's semantic owner is the [finite ordered record profile](../../docs/领域/状态关系与流/关系查询与维护.md#有限有序记录的独立方法画像), with the existing [scalar and expression rules](../../docs/领域/计算基础/文法类型与求值.md). The method is `gift:finite-ordered-records/2`; it does not reuse the earlier I64 experiment's qualification.

## Build and use

Run from the repository root with its pinned Bun dependencies, Cargo and Rust installed:

```powershell
cargo build --locked --manifest-path crates/gift-author-kernel/Cargo.toml --target-dir .tmp/gift-author-kernel-target
bun run sec -- author --input crates/gift-author-kernel/fixtures/shared-views.module.json --kernel .tmp/gift-author-kernel-target/debug/gift-author-kernel.exe --json
```

On Unix the executable has no `.exe` suffix. `--kernel` is an explicitly selected local compiler executable, not an automatic installer or an untrusted-plugin sandbox. The host captures one workspace-relative source file, passes its exact bytes through bounded stdin, and checks the returned source revision. The Rust library itself does not read files, environment, Git, clocks or the network. The standalone executable has only stdin/stdout transport.

The JSON result contains `src/index.ts`, `src/main.ts`, `package.json` and `tsconfig.json`. It does not write these members into the workspace or execute the target. Materialize the members into a new destination through an authorized caller. The emitted package builds with TypeScript 6.0.3 and runs its `dist/main.js` with Node. Its public library uses `bigint`; the demonstration JSON observer renders integers as decimal strings, keeping negative and greater-than-I64 values exact.

## Supported semantics and failures

Use `author --read --input <file> --kernel <executable> --json` to read a complete `gift.author-module/design-converged` module or `gift.project/design-converged` project. The exact marker selects its Reader; a failure never retries another format. All complete Definition branches come from the existing [parameterized grammar](../../schema/author/first-layer/codec-parameters.json). Short forms consume the original [expansion equations](../../tools/documentation/author_codec_spec.py); complete `kind`, `tag`, `op` and control bodies keep their stopping boundaries. Project input uses its complete shape. A sequence comprehension needing an ordinary Collect binding returns `NeedsSurfaceBinding` until that binding is supplied by its qualified semantic context.

The result is `gift.author-read/1`, explicitly at the `structural` stage. It contains exact source and grammar revisions and a finite node graph with separate source/expanded roots. Children precede parents. Original values retain source JSON Pointers and half-open UTF-8 byte ranges; synthesized nodes retain their source occurrence. Numeric wire values are strings containing original number lexemes, so a JSON transport cannot round them. `iff` expansion shares each original operand without merging distinct same-valued occurrences. The Rust library retains the original bytes. This stage does not establish lexical binding, type/effect correctness, professional interpretation, Method availability, target generation or execution.

Cargo embeds only the manifest's exact resource closure. The runtime reconstructs and verifies its bounded graph and uses `jsonschema 0.60.2` with default HTTP/file resolution disabled and an explicit rejecting retriever. `serde_json` owns syntax and the shared source capture rejects duplicate decoded keys and non-scalar Unicode before map construction. The old `/2` method uses that same capture and retains its own semantic decoder.

The pinned Schema engine has a known upstream numeric-bound defect: a bound such as `9007199254740993` can miscompare an equal decimal token. Its use is qualified for the actual fixed Gift grammar, whose numeric bounds are safe integers. Before provider construction, every Schema node's bounds must be integer literals within `[-(2^53-1), 2^53-1]`; `multipleOf` is not qualified. New grammar outside this capability returns `GrammarCapabilityUnsupported`, without rounding or changing author values. The independent defect reproducer remains in the tests. Exact large-number const/enum/uniqueItems use the library's separate precise comparison path and have their own tests. Upgrading the engine requires requalifying these boundaries; the runtime does not accept arbitrary external Schemas.

Input is bounded to 4 MiB, 200,000 JSON nodes, 128 levels, 16 MiB of retained source-pointer bytes and 65,536 aggregate numeric lexical/exponent work units. Pointer bytes are charged before allocation; derived nodes share immutable origins. Expansion has its own depth, visit and derived-node budgets. Exceeding those budgets returns `ResourceLimit`, retaining the source; it does not declare the language construct invalid. Reader output allocation is charged before copying each unique node, conservatively allowing worst-case JSON escaping and container overhead within the 64 MiB transport limit. No performance or unbounded resource guarantee is claimed.

Use `author --names --input <file> --kernel <executable> --json` for the next, independent name-analysis stage. It registers every Definition in the captured design-converged module and locates references through their actual Schema-owned slots. It resolves local declarations and public export routes, preserving original locations and each expanded occurrence. SourceRef, historical DefinitionRef, original professional selectors and dialect consumer slots retain their distinct interpretation boundaries. JSON data, annotations, lexical variables and professional payload terms are not guessed into module references. `--read` and `--names` are mutually exclusive.

The result is `gift.author-names/2`, with `stage: names` and `identity_scope: capture-local`. Its `input_revision` binds ordered source/grammar revisions and the explicit in-memory import graph. The Rust `binding::analyze_sources` API accepts Reader-validated captures and import requests selecting existing source aliases and target capture slots; it validates the target's real moduleId. Captures with identical bytes remain distinct slots, while multiple aliases explicitly targeting one slot share the terminal declaration. Public alias cycles, missing local names, missing public exports, invalid namespaces and missing captures have separate results and read dependencies. The single-file CLI reports uncaptured imports as specific needs, without searching the filesystem.

The required `lexical` arena records source occurrences, parent-before-child scopes, local bindings and uses, return/break/continue targets, lexical capture relationships, problems and region-specific needs. Candidate Type/Expr/Exec and shared common expressions/patterns use the same identity and visibility rules. Initializers precede their new bindings; branches and try handlers retain separate environments; a lambda resets its loop boundary. Author keys cannot bypass visibility or shadowing. Static Value parameters participate in semantic and value lookup through one binder, with kind/phase checks after lookup. Omitted callback semantic parameters do not introduce author-visible names or keys, so source lookup continues through the actual declared scopes. Later signature analysis must introduce hygienic local semantic identities without rebinding those source references; an explicit local Region/Scope reference requires an explicit lambda parameter declaration. Known inner binders can resolve while a professional outer environment remains unavailable; uninterpreted payloads are not guessed into this arena.

Arena IDs are indices within the returned result, interpreted with its schema and input revision, not persistent handles across analyzer revisions. Original byte origins and expanded occurrence paths remain distinct, including shared source nodes used in multiple contexts. The host strictly checks `/2`, arena edges, parent order, control-target kinds and source ranges. Old `/1` analyzer output is rejected rather than supplemented with a fabricated empty arena. The existing `--read`, compilation and failure formats keep their separate contracts.

These are name-location and lexical conclusions in that exact capture. Declaration IDs do not claim stable editing lineage, nominal identity or a formal ModuleUse; a locked import retains its pending lock qualification. Types, effects, value evaluation, capture lifetimes, static initialization, professional interpretation, callable qualification and target behavior retain their independent checks. A lexical capture edge does not prove it can be copied, borrowed or retained. A found name is not a successfully typed program. Professional old strings retain their Profile resolution needs; extension payloads retain their exact interpretation boundary. No target artifacts are generated. Analysis is bounded to 128 captures and 32 MiB of captured bytes, with an 8-million-unit navigation/validation work budget and conservative 48 MiB allocation/output accounting; exhaustion is `ResourceLimit`, not invalid author syntax.

The Rust `header_seeds::collect(bytes)` and `collect_sources(sources, imports, root)` APIs continue from this same name analysis and selected Schema navigation. They return a `HeaderCollection` containing the names, a common `TypeArena`, declaration seeds and outstanding issues. Names-only callers retain their existing result and do not run type formation. This library stage has no separate CLI flag or serialized inference format.

Candidate Type and shared TypeTerm encodings enter one semantic representation. It retains scalar attributes, definition references and parameters, records and rows, variants and tuples, option/result, containers and equality contracts, function parameters/effects/captures, resources and asynchronous values, quantity/refinement/opaque types, existential binders, constructor applications and packs, rational types, wire variants and associated projections. Identically formed primitive domains can share a semantic node while retaining each original source occurrence. Omitted and explicit attributes retain their source distinctions; later semantic comparison applies the original defaults and qualification rules. Rust structural equality or different arena IDs do not establish semantic equivalence or incompatibility. Definition-reference and SubjectSchema positions preserve their restricted roles; an unresolved professional interpretation remains an obligation. These constructs compose user-defined types rather than registering a finite list of business concepts in the compiler.

Type nodes consume the declaration and local-binding identities already produced by name analysis. Their IDs belong to this analysis result and are separate from source occurrences or persistent definition identity. Declaration references remain finite references rather than recursively expanding nominal bodies. Static expression arguments and pack indices retain their actual source expressions and evaluation obligations; forming them does not evaluate those expressions. This continuation shares the original analysis work/allocation budget rather than opening a second allowance.

Header seeds are the immediate consumer of these types. They preserve every Definition, distinguish type aliases, direct nominal definitions and representation hiding, and retain function binders, parameters, contracts and actual bodies. Omitted result types request inference from the body; constants retain the actual initializer and an explicit expected type or an inference request. Omitted effects on a function declaration request body inference. This differs from the shared function-type syntax, whose omitted effects denote an empty upper bound under its existing contract; both retain their actual context. Professional and imported declarations retain their own interpretation needs rather than acquiring fabricated empty bodies.

`signature_resolution::resolve(bytes)` and `resolve_sources(sources, imports, root)` continue from those headers with the same retained navigation and analysis budget. They check the header type closure, including unused parameters, collect signatures before checking bodies and use actual bound declaration dependencies to wake waiting inference work. Explicit signatures permit recursive calls; a cycle that still needs inferred call signatures reports its annotation obligation. The result retains names, the common type arena, headers, signature states, dependencies, source-bound problems and needs, and a `bodies: BodyAnalysis` projection. This library continuation has no new author format or CLI mode.

The finite constraint machine works over that same arena. It distinguishes authored semantic binders from fresh derived identities, retains their provenance, checks kinds, rigid scope and occurs constraints, and restores speculative state after a probe without refunding its work. Transparent aliases and nominal declarations retain their different recursion and identity rules. Equality consumes the original record/function defaults and the [shared sequence mapping](../../docs/作者/组合/结构编辑与身份保持.md#类型项); it does not infer arbitrary scalar defaults or erase unresolved static arguments. Type equality, assignment compatibility and effect inclusion remain separate judgments.

The common body judge consumes the actual selected Expr, shared Expr, Pattern and Exec slots. It covers ordinary values and references, let/region/do, operators and branches, lambda/call, records/updates/fields, sequences and list tails, variants/matches and the ten Exec statements. It also visits the common children of conditional or professional constructs, retaining the missing interpretation instead of treating their payload as arbitrary code. Direct calls to explicit generic declarations get fresh Type instances; ordinary constants and local values keep one monomorphic instance, with an annotation need when it cannot be determined.

`BodyAnalysis` retains occurrence types, expected types, real local bindings, targeted control exits, call layouts, captures, pattern coverage and effect equations. A normal value, no normal successor and a pending result are distinct. Return values constrain their actual function or lambda result; break/continue retain their actual loop targets. All source still receives static checking, including unreachable expressions, while only reachable normal paths contribute to normal-flow joins. Named calls preserve source argument order separately from formal parameter positions. Pattern usefulness decomposes the actual type's constructors and keeps missing coverage, redundancy and unknown coverage distinct.

Signature inference and these body facts share one prepared session. Successful declaration summaries remain in the returned analysis; provisional facts and solver changes commit or roll back together, so a failed attempt cannot leave summaries pointing at discarded inference state. The derived tables reference the original immutable source and existing type and lexical identities. They do not create another source tree or grant persistent identity to local arena indices.

Effect equations preserve ordered and conditional activation, individual call occurrences, local reads/writes and the distinction between lambda creation and its latent body. A try equation keeps body and handler separate and retains its missing error-profile qualification. These are inputs for the existing [compile-value-service pipeline](../../docs/编译/内核/编译值服务.md), not a solved effect fixed point. Managed Raise interpretation, error families, resource cleanup, projection rights, capture safety, contracts, static initialization and callable qualification retain their actual obligations. Explicit semantic call arguments, non-Type inference, static-value substitution and broader assignment compatibility also remain incomplete. Type readiness and body facts do not establish target behavior. The older `/2` method below continues to use its own five-type model and qualified target behavior; its default CLI route has not yet migrated to this common pipeline, and Rust target emission remains open.

With neither flag, the existing `/2` compilation method supports:

- One closed `/2` module, explicit local exports, mathematical Int, Bool, Text, immutable closed records and ordered sequences. Int literals use the existing canonical decimal-string encoding.
- Pure, finite, acyclic internal first-order functions: literals, lexical variables, constant references, records, sequences, fields, calls, `if`, and exhaustive `Ordering` matches. The primitive binding supports mathematical `IntCompare`, `IntEq`, `IntAdd`, `IntSub`, `IntMul` and `BoolNot`.
- Predicate Meanings resolve to actual functions with matching named roles and result types. Names alone never supply an interpretation.
- `data:query` scan/filter consumes complete static record sequences and pure total unary predicates. It preserves order and duplicate occurrences; nested filters complete their source before evaluating the next predicate.
- Source revisions hash exact bytes. Semantic revisions hash the checked author structure. Definition dependencies and call occurrences retain source pointers; `affected_exports` computes the union of old/new dependency closures after edits. Compilation currently recomputes cleanly: there is no incremental-cache performance claim.
- The reader rejects duplicate JSON keys before maps can erase them. Source size and dependency depth have explicit implementation budgets. Resource refusal is separate from mathematical integer validity.

Imports, nominal types, finite-width numbers, mutable/optional/open records, arbitrary effects, recursion, contracts, Goal/Requirement, components, external data, Bag/Set and other queries return specific diagnostic codes. Callable exports return `NeedsTargetBridge` until a native input codec can establish immutable data and Unicode scalar Text; TypeScript's structural types alone admit accessors and lone surrogate code units. Internal functions and Meanings remain available to the static project. Unknown or unsupported obligations anywhere in the submitted module are not silently treated as dead code. The caller retains the unchanged input on failure.

The fixture's inherited view explicitly references `DefaultThreshold`; its fixed view contains the same integer literal. This demonstrates distinct evolution of a shared source and a fixed value. It does **not** implement absent-parameter default elaboration, component Use identity, arbitrary projection editing, general Method search, Rust target emission or the complete shared Workspace/state/resource example.

## Verification

```powershell
cargo test --locked --manifest-path crates/gift-author-kernel/Cargo.toml --target-dir .tmp/gift-author-kernel-target
bun crates/gift-author-kernel/tests/reader-check.ts .tmp/gift-author-kernel-target/debug/gift-author-kernel.exe
bun crates/gift-author-kernel/tests/target-check.ts .tmp/gift-author-kernel-target/debug/gift-author-kernel.exe
```

The Rust cases cover accepted structure, exact values, role/occurrence binding, dependency changes, rejected interpretations and source preservation. `target-check.ts` uses the repository-pinned TypeScript Compiler API to typecheck and emit each generated project, executes the emitted JavaScript under Node against independently written expected values, and invokes the actual repository CLI. It exercises the baseline, shared threshold change, shared `≥` to `>` change, empty input, large negative boundaries, equivalent declaration reordering and Unicode line separators. Source-map lines are checked against the target compiler's own parsed line positions. Each run prints the retained artifact/evidence directory under `.tmp`; it never overwrites an existing destination.

Common frontend changes are checked through their Rust analysis APIs and, where the transport changes, the native Reader/name CLI checks. Generating and running every target fixture is not required to establish name binding, type formation, signature constraints or body judgments. Formation, signature and body tests use real Reader inputs and independent semantic expectations: declaration-order changes, recursive signature dependencies, generic instantiation, nominal distinctions, normal versus outward exits, local scope and writes, call layouts, nested pattern coverage and failed-probe rollback. Their success does not establish complete professional/effect qualification or the Rust target.

`serde_json` owns JSON syntax and lossless numeric transport, `num-bigint` checks exact integer values, and `sha2` supplies content digests. The small Rust emitter operates only on checked typed nodes; JSON escaping and compiler-generated identifiers prevent author names/text from becoming target syntax. TypeScript's actual compiler remains the independent target syntax/type authority. No new general parser, integer arithmetic library or target-language checker is implemented here. The Cargo lock records exact dependency revisions; the licenses are inherited from their upstream packages (serde/serde_json, num-bigint and sha2 use MIT/Apache-2.0 alternatives).

The earlier research experiment described by PR #895 has not been recovered as source here. Its reported TS experiment and I64 bound are not counted as tests of this implementation. The 1,786 U / 568 D originals, general abstraction generation, full author editing, imported modules, component runtime and additional targets remain separate obligations with their original owners.
