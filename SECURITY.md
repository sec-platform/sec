# Security Policy

## Supported versions

SEC is currently an active development preview and has not declared a stable release line. Security fixes are applied to the current `main` branch. Older commits, branches, forks, and unreleased interfaces are not maintained as supported versions.

## Reporting a vulnerability

Please report a suspected vulnerability privately through the repository's **Security** tab by choosing **Report a vulnerability**. Do not open a public issue for an undisclosed vulnerability.

Include the affected revision, impacted component, prerequisites, reproduction steps or a proof of concept, expected impact, and any suggested mitigation. Remove credentials, personal data, and unrelated private material from the report.

The maintainer will make a best-effort initial assessment within seven days. Validation, remediation, disclosure timing, and any credit will be coordinated in the private advisory. Reports that concern only unsupported historical revisions, general hardening ideas without a concrete security impact, or third-party products may be redirected to the appropriate owner.

## Scope

Security reports should concern behavior implemented by this repository or a repository-owned release artifact. A design document describing a future capability is not proof that the capability exists. Vulnerabilities in dependencies should also be reported to their upstream maintainers when the issue is not caused by SEC's integration.
