# 有限语义设计载体

这里的JSON Schema保存有限设计画像的结构合同，不是已发布产品decoder、运行模块或权威事实签发器。作者定义的语义、名称/类型/角色解析、单位、名义细化、权限、目标方法与证据仍由相应唯一正文和真实消费者解释；结构PASS不证明这些义务成立。

| 载体 | 有限责任 | 必须在结构检查之外取得 |
|---|---|---|
| `intent-finite-model-1.schema.json` | 明确离线模型的对象与字段快照 | `typeRef`实际解析、字段的准确类型/单位/范围及模型解释；模型值不成为现实世界事实 |
| `semantic-pattern-1.schema.json` | 复用角色、含义导入、共同命题/Requirement引用、差异槽与观察边界 | 角色/命题局部唯一、真实导入绑定、Requirement本义、差异槽类型与相交资格 |
| `semantic-pattern-use-2.schema.json` | `one/optional/set/bag/sequence`的有型使用表示 | 绑定覆盖、名义细化、实际身份去重、准确重数、顺序及观察/证据资格 |

`semantic-pattern-1`的七种`variation.kind`是这个版本画像的结构支持域，不是所有开放Definition或领域差异的封闭全集。遇到该集合无法保存的合法区别，选择已有更开放的作者定义，或者版本化扩展schema/profile并完成正文、绑定、失败、迁移与消费者交接；不得丢弃差异、塞进`authorNotes`或为了通过旧schema降低原作者能力。纯谓词共同命题也不能吞掉时间、规范、权限、跨运行或外部效果，后者引用其独立Requirement。

`uniqueItems`只比较JSON表示，不签发对象同一性：同一对象带不同细化/证据字段仍可能重复，bag中的重复对象需按所选身份与精确正整数重数解释。空模型/集合是否合法由真实任务决定；某角色`optional:null`是准确可选缺席，不是未知观测的默认编码。跨版本迁移不得仅看键名相同就声称等义。

这三张载体与采用它们的作者设计同次闭合。其当前消费者只获得设计/静态结构能力；没有真实decoder和实现证据时不声明产品已加载、可运行或已经验证。
