# test-design

## 归属与不可越界的事实

- Claim 和验收方法的权威归[要求证据](../../../docs/运行/保证/要求证据与裁决.md#要求含义与验收方法不互相定义)；CasePlan/casesRef、测试发现、Q0—Q6、Test Value、REWRITE/consumer-zero 与执行归[测试发现与执行](../../../docs/开发/测试发现与执行.md#developer-test-selection)及其正式 owner。本 Skill 只指导证据与方法的选择，不创建第二份 inventory、评分、台账、审批状态或测试执行平台。
- 现行产品合同按已核实的采用来源读取，候选实现、测试及 selector 绑定本次 exact base/candidate；既有同版证据直接复用，不要求每次承接重读 main。PR、分支、历史审计、标题和旧 CI 不冒充新主干事实，静态候选不签发删除授权。
- **所有当前正式 SEC 产品能力保持不变。** 测试优化不能以撤销 Git Hooks、Provider、Runner、编译能力或恢复义务来制造可删测试；有独立正式授权且迁移、消费者与历史状态已经结算的产品退役属其他任务，本 Skill 无权发起。
- **测试设计不签发提交、推送或合并权限。** 按执行时有效的最新用户授权与原Effect准入决定交付终态；用户最新禁止合并、要求保留PR或撤回目标ref更新授权时，不得merge、squash、rebase-merge或启用auto-merge。已有明确目标ref授权且未撤回时，沿原集成合同完成收口，不因历史限制重复索取已取得的授权；PR可合并、CodeQL成功、作者权限及Skill本身均不能补足缺失授权。该边界不改变正式仓库门禁。
- 由主协调者在有界设计任务中读取；当前 hosted activation 只确认 Worker implement，不由注册信息推断 design role 已接通。`test-design-required` 交回主协调者；无 canonical Claim 或方法未归于测试时返回 requirement/assurance owner；纯选择/执行交 selector/runner，不扩张既有 Work Package 权限。

补充执行约束：固定候选提交与工作区差异，区分已采用产品合同、当前实现和历史证据；实现现状不能反向定义要求。安全与数据保全同属不得为删测试撤销的保证。角色与平台能力按实际核验，不凭 Skill 声明推断。仅修订本 Skill 的请求不授权继续改测试、生产代码、规范或新建 PR；账户 Skill 安装另按授权处理。

## 从目标保障形成最终集合

**测试数量、目录、语言、assert 数、覆盖率和旧测试存在都不是价值依据。** 先判断保障本身是否服务真实用户结果、已采用合同或实际风险，再判断承担它的集合。实现、导出、当前引用、旧断言与旧 KEEP 都不能单独创设保留义务；无有效义务及辅助价值者整类退役，无需造替代。有效义务保留充分的合格保障；每个额外成员须证明超出其余合格集合的贡献，未知不标已证必要。安全、恢复、兼容承诺不因暂未调用取消。 从用户要完成的结果、已接受产品合同与保证，独立确定本次范围内的有效验证义务 `O`。比较范围按同一有效保障及其 owner、消费者形成跨观察层的完整相关集合，不按文件或条数截断；先确定目标保留集合 `S`：保护什么结果，何种错误会造成实际后果，适用输入/主体/环境，以及所需观察层、selector/平台/频率与恢复终态。复用已有 Claim 和[测试导航](../../../tests/README.md)的观察层/职责域，不再从旧测试逐条修补后拼目标，也不新造分类矩阵。

按[主责能力族设计](../../../tests/README.md#主责能力族与跨族保障)组织比较：观察层与职责域正交，职责树只细化到稳定公开能力族，不按文件、批次或数量划族。每个已归属的源码测试身份只有一个主责族，跨族依赖、保障与承接可多对多；无法唯一归属和必要性未判定分别保未知，不从局部比较组推算全仓族数。物理布局、共置／模板／Python 入口不因此迁移。

映射渐进投影到既有身份与证据记录，缺映射不阻塞已有独立证据的清理，不要求小任务先建立全仓族树、逐条新增声明或第二注册表；主责归属不授予 `KEEP`；完整分类、阅读完成、有界 `KEEP`、范围内必要性结算与全局删尽分别报告。只有有效公开义务、消费者或保障差额改变才优化设计并重核相交项；固化规则不等于已经完成全仓映射，禁止为归类或少注册压缩资格和独立预算窗口。

消费者只能证明某物被使用，不能单凭调用关系证明它必要：调用者可能同样冗余。反过来，安全拒绝、灾难恢复或已接受但尚未激活的义务，不因暂时没有调用就消失。沿使用关系核查的是**删除或改变后会损害什么用户结果或保证**。内部实现差异只有能造成这种损害，或自身确属受承诺的信任边界，才进入 `O`。

先查合格现存测试承担 `S`，只迁移缺失的必要观察。共同充分证明可覆盖数十文件、数百或上千注册/输入实例，但须映射精确成员、前提、差额与最终承接者；数量不是配额或上限，标题、文件未变或抽样不能签发未核成员的结论。**比较集合与交付批分开：** 从相关集合中领取当前可完整承接、退役及按风险复核后发布的最大成熟多文件批，不等全领域审完，也不为凑删量拼无关对象；未知或需深查的成员只隔离相交依赖，不拖住其余成熟部分。

旧测试是发现输入、反例和迁移责任的线索，不是义务的来源。审查发现把偶然布局、措辞、引用身份或无后果的差异误纳入 `O` 时，应纠正分类，说明依据及仍保持的真实保证；无需为这些偶然约束寻找替代测试。不能为了减数撤销有效义务，不能因缺少运行环境就认定没有义务。真正未知的相交项保留未决，不把未读、未找到消费者或未运行当作无价值。

### 按语义选择断言精度

| 对象 | 必须保护的内容 | 不自动固定的细节 |
|---|---|---|
| 人读 CLI／展示 | 必要状态、阻塞、未知、风险及其归属准确；完整字段键值与列表成员不能被前后缀或子串冒充，同文本的不同字段不能互代；显示不得放大领域结论 | 整段英文文案、标点、行序、空白和末尾换行；只有独立的字节合同才逐字比较 |
| machine JSON／协议／持久产物 | 已承诺的字段、类型、值、错误、版本与完整性；strict schema 的额外字段拒绝也须保留 | 未承诺的序列化空白、对象键序、内部字段；canonical encoding、签名等确实消费字节时另按合同 |
| 身份、快照与容器 | 稳定领域身份、输入隔离、后续修改不污染、必须的顺序/重数及复用含义 | 插入对象与返回对象必须 `===`、数组必须换引用、私有 Map/类布局；只有别名/身份本身有后果或承诺时固定 |
| 结构与交互 | 已成立的 AST/import 信任边界、权限负面空间、Provider 参数/时序、安全拒绝与物理结算 | 私有函数位置、无承诺遍历顺序、注释、临时版本与实现路径 |

完整 JSON 相等、固定文本、结构断言或引用相等都不是天然好或坏；按其保护的义务确定精度。避免用同一个 formatter 生成 expected 自证语义，也不要为了消除自证就把当前全文硬编码成新的兼容合同。路由和展示可能有不同责任，先查已有 integration/E2E 是否已观察所需结果；机器输出正确不自动证明人读状态正确，显示正确也不证明审核、授权或业务决策正确。

### 需要核对的有效边界

- **语义与编译**：适用合同中的 Canonical IR、稳定身份/Revision、确定性 lowering、固定点、跨投影保持及非法输入拒绝，观察实际语义而非内部字段自证。
- **接口与产物**：Block/Registry、CLI/API/schema、兼容、安装、生成与用户入口到有效结果；精确字节依上表判定，不以“公开输出”自动冻结排版。
- **安全与治理**：权限、TCB/来源信任、路径/符号链接越界、凭证隔离、未授权修改、AI Runtime 授权及审查/合并门禁真假判别。
- **物理效果与恢复**：事务、journal、commit/rollback、幂等、并发、崩溃切点、清理及文件/进程/Git 状态读回。不同主体、平台、失效点或顺序会改变有效失败模型时保留对应观察，不能凭字段相似抵消；死 PID、TTL 到期或锁消失不证明旧作用已静止，后代进程、已派发写入及外部作用按相交责任结算。
- **工具链与执行资格**：正式构建、测试选择、完整性、证据复用和发布不得漏选、假绿或错误采用；分别核配置版本、工具自报版本及实际采用资格，候选能力不代签准入。工具框架自己的行为不自动成为 SEC 义务。
- **资源与非功能**：已接受的字节/并发/资源上限、兼容与平台边界按合同保护。性能或 SLO 结论须绑定工作负载、环境、基线和实际测量，错误码断言不能代签内存峰值、耗时或分配时序；单树/单操作预算不代签整个进程或并发总量，核计量对象、寿命与组合范围。

这些是审查方向，不是每个任务必须新增的一套测试类别；正常成功、必要拒绝及真实恢复分别按本次能力检查。

## 再判断测试实际证明什么

**测试样本、统计与测量链。** 当预期、发现或测试数据来自生成器、聚合器、过滤器、跨层 join、测试设施或历史报告时，先确认观测单位（源码注册、参数展开实例、源文件、实际执行、实体/资源及失败切点）、有资格进入的完整输入集合，以及过滤、缺失、重复、空集合、不同来源对齐和版本/时间窗口漂移。匹配或汇总的数量须有独立输入依据；同一个生产 helper 产生的 expected 与 actual 即使在多个文件重复，也只是一条共同依赖的证据，不能按断言数或重复投影计为独立正确性证明。只有稳定且确实由产品合同要求的质量条件才应形成长期硬断言。

**测试设施的证据责任。** 测试 fixture、testkit、发现器、mock seam、报告器和 cleanup 不是因自身存在就成为产品能力；但它们若会筛掉必要样本、引入假绿、污染跨用例状态、泄漏权限、错记终态或遗失失败/资源，就处在验证证据链上。评估其测试时以实际消费这些设施的受保障用例为起点，保留能独立判错的适配、故障注入、资源结算与运行资格观察；退役只锁定 Promise/对象引用、调用次数、日志排版等偶然实现的断言。不能因为一个测试针对测试设施就一律删除，也不能为了设施自测而重新实现一套 SEC 测试平台。

按下文风险分级读取足以决定本组结论的完整语义：实际注册与参数、相交 hook/helper/fixture、条件及实现；已取得且前提未变的内容直接复用，不为每项重读全链。确定有独立判错依据的义务子集 `P(t) ⊆ O`，即实际输入、动作、独立预期、失败见证、适用资格与清理。判错指能检出违反有效义务的实现，不是任意实现差异；没有字面 `expect()` 可能由 helper 抛错，有断言也可能毫无判错能力。

- 优先采用产品合同、真实外部读回、经独立语义核对的固定向量、可信参考或有独立依据的性质。预期不得仅从同一未受约束的生产 builder/catalog/formatter/selector 得到。管线相等可证明确有价值的接线关系，但不能自证被传递结果正确。原语可直接测试不证明正式入口已接通；接线缺口与原语保障分别保留，不能互相代签或抵消。
- fixture 必须建立所称前提：与观察层匹配的资源、正确身份/权限、输入域及故障位置；声称物理效果时使用真实资源。缺席、显式 null、非法值及读取失败按真实入口分别核对，不以可选/空值短路合并；无效输入不是噪声，当拒绝非法输入属于义务时须保留。过滤掉义务要求覆盖的困难/非法样本、零有效样本或准备失败直接 return 均不能产生该义务的合格证明。
- 昂贵原生 fixture 只复用效果前已完成写入的不可变输入基线；各用例拥有独立 Git index、refs、工作树、原生身份与结算窗口。复制源仓库前排除已注册 worktree、未结算子进程／租约及携带不可安全重绑定绝对路径的状态；复制后按用例重绑 remote 等物理路径，后续 Git Effect/故障切点/凭据单独产生。并行准备多物理写入者须先完整 join（含失败分支）再清理父根；setup、被测动作、cleanup 的并发／复合错误保留全部证据。不以运行内模板缓存冒称跨进程复用或静态 PASS。
- 验证两个读口相等时，须排除二者同时为空或同错；以独立 fixture 内容建立结果依据，只有确需的别名语义才加引用相等。Mock 响应自检、对象自比较、没有有效观察的空 fixture 与裸第三方工具成功不能证明 SEC 行为；合法空输入的边界观察与正式环境资格检查另论。
- 往返、确定性复算、变形与差分可证明各自有限性质，须说明适用前提及反例。Golden/snapshot 依据真实语义审查，不能从 actual 自动批准；修订断言不应仅为让失败消失。
- 运行资格与价值是两条证据轴。完整源码语义可在依据充分时判定等价、偶然约束、明确缺口及有界删改；不要求先跑测试才能作这些裁决，也不把缺少运行当成 `P(t)=∅`。静态判断不能产生运行 PASS；依赖真实宿主、时序或资源的未知仍须保留。

## 处置与联合迁移

最终保留集合 `S` 应承接本次范围内每项有效 `O` 所需的合格验证。保全对象是有效义务的输入等价类、独立失败模型、资格与恢复观察，不是所有旧断言、fixture 或字节。若义务尚无合格验证，应报告真实缺口，不通过降低目标或把未运行项算通过来消除。

**联合复核最终 `S` 的语义与执行资格。** 承接前对照[测试导航的资格来源](../../../tests/README.md#支持代码与执行资格)、实际 selector、预算及平台/skip 条件；同资格成员共享对照证据，核迁出族的精确成员在所需 fast/slow 频率、反馈时点上均有合格承接；语义更强或断言相同不够。fast 故障恢复并入 slow 生命周期会漏掉日常保障时，反转保留方向或迁移必要观察，不复制昂贵 fixture 补回频率。多个独立用例合为一个时，即使 timeout 数字未改，总预算包络也可能收窄；昂贵或原生多世界缺等价依据时，优先共享前置并保留原用例隔离与各自窗口，不追求注册减少。迁移或机械改写须逐注册绑定完整调用头、回调体、fixture 实参及 skip/窗口；匹配区不得跨入另一注册，特殊参数例单独核对。发表前对完整候选做可用解析/有界词法检查并明确其证明范围，发现语法或绑定异常先修复，不能发布伪计数。断言数、登记数不变或正则逆变成功均不自证原边界保持。还须核对 oracle／fixture 及选择资格的连续性；标题、数量或登记 tokens 相同不能单独证明语义承接。联合检查无循环替代；资格未明仅冻结相交项。

| 处置 | 判据与动作 |
|---|---|
| `KEEP` | 有独立判错能力，当前保留以承担有效义务；按注册或有界输入族定位删除后失去的保障及已比较替代集合的资格差额；同一充分理由可映射多个精确成员，不要求逐条重复论证。仅文件“已读”或共同分类不够，差额未知时用 `UNDECIDED`。不把有界判断冒称全仓唯一或全局最优证明。 |
| `MERGE/REPLACE` | 指名最终承接用例，说明所需输入/失败模型、资格、频率及恢复观察；先落实承接，满足适用 Q4 REWRITE/来源要求，再移除旧注册。 |
| `DELETE` | 已证实不承担有效验证义务且无有价值的资格/辅助责任，或这些有效责任全部已由最终 `S` 充分承接；满足原 owner 的适用 consumer-zero/supersession 前提。只删获准测试与独属 fixture，不删产品能力。 |
| `REWRITE` | 有效义务仍在，但 oracle、样本、执行资格、错误/恢复观察不足，或断言混入偶然约束；修正必要观察，去掉无依据限制，不机械保留旧形状。 |
| `UNDECIDED` | 相交义务、价值或承接仍缺决定性依据，暂留并指出具体未知。缺 Bun 本身不阻止有充分源码依据的裁决，也不把暂留说成已证明不可替代。 |

`NO_PROOF`、`SELF_ORACLE`、`REDUNDANT_PROOF`、`ACCIDENTAL_LOCK`、`FALSE_GREEN`、`EXCESS_BURDEN` 是问题描述，不是自动删除许可。假绿或自证若遮住有效义务，应重写或由现有合格测试承接；纯偶然锁不需要伪造替代者。必要保障承接与删除同批；真实缺陷在授权内最小闭合，但先判相交测试是否必要；不把删除任务无界扩成逐例修复。仍必要的同类准备与结算收归既有主责 fixture，删除重复模板，保持各例隔离、资格与预算；其他独立问题交原责任者，不挤占整族退役主线。风格整理与新能力不挤占清理。资源过重不能靠撤功能、另造测试平台或强迫另一运行时兼容来减负。

**新增先查能否合并或加强，修复同时退役旧项。** 用户已冻结新增时，新增测试文件、注册及展开义务默认禁止，例外须明确授权；不以改名、参数化或 INTRODUCE 自行绕过。沿[必要测试准入与单一资源主责](../../../docs/开发/测试发现与执行.md#必要测试准入与单一资源主责)执行，未接入真实门禁不得称自动强制。 先查相交 owner、已有索引和相关跨文件的 unit/integration/E2E、参数实例及间接断言；已有证据未失效时不重扫全仓。只有明确“有效义务缺口 → 新判错点 → 现有用例为何不能承接”才新增注册，优先合并或加强现有用例。修复或迁移同时移除已失效或被承接的旧测试、独属 fixture、helper、准备与导入，核共享消费者，不只追加新测试而遗留旧负担。不能按命名对称、代码行数或数量目标新增，也不为减少注册机械混合不同边界。有限枚举可表驱动；property/fuzz 须适合输入域与性质，核有效样本、种子和反例；无依赖授权不加框架。

## 方法、执行与成本

### 落地时先固定必要性，再动物理测试代码

按[测试方法](../../../docs/运行/验收/测试生成与形式方法.md#21-从保障到最小充分案例不能用测试越多越好代替设计)与[开发者发现/执行](../../../docs/开发/测试发现与执行.md#developer-test-selection)分别取规范与真实采用：业务要求/必要错误后果 → 当前实际消费者与源码/模板注册 → 独立 oracle/fixture/物理结果 → 同一资格的现存承接 → 最大成熟独立集合的修改/退役。物理布局仍以[测试导航](../../../tests/README.md#物理测试源码与运行边界)为准；不要为了把所有测试塞在一个目录而搬迁，不要新增另一个判定表或类型化 runner。

**反问每个准备保留的额外测试：** 它被删掉会失去哪个独立错误见证？如果唯一差异是毫秒等待、私有调用次数、getter/Map 引用、同一空 fixture 的再运行、框架自身内置语义或运行顺序的偶然输出，应先寻找已充分承担的原生同资格案例。若差异是取消后的后继副作用、精确截止、不同物理失败切点、后代进程/身份替换或恢复残留，就不能以“出了问题再修”代替防事故的验证。参数批/循环的静态调用合并不等于执行实例减少，slow 承接 fast 不等于同频率，删除一个入口模板不等于只删一个当前 Bun 用例。

**实际交付：** 有相交方法冲突才改原规范/Skill；在已授权写集直接完成语义族承接、删改和 helper 清理，不把规则修改设为普遍前置。只有支撑该退役所必需的弱 oracle 修复属于本批；计时改写、工具替换、形式证明/全量性能优化等无关扩展不得冲淡删测主任务。提交后回读 exact tree，分别报告文件/声明/动态实例/真实进程和预计负担变化，未运行一律 NOT_RUN。

### 时间、次数与成熟工具的最小充分性

先区分：**产品时间语义**（期限、租约、取消、重试）、**测试执行防卡死上限**（runner timeout）、**性能/容量测量**（真实负载、环境和基线）、**多次样本与复跑**（等价类、性质、flaky 诊断）。这些量不互相证明，更不能因为测试中有时间、循环、异步或内部调用就自动新增用例。

- **一般逻辑不测耗时。** 产品没有约定时钟读次数、getter 次数、Promise/Map 引用身份、具体微任务轮次或某个毫秒数时，不锁这些实现细节；先用最小输入与独立 oracle 测结果。用户修复一个问题，不意味着必须增加一个永久测试；若现有必要验证可区分该错误，直接复用。
- **有时间保证才测试截止时刻。** 固定未到、恰到、超时、时钟回退、取消竞态等能改变有效结果或安全作用的独立边界；优先 owner 已有的注入时钟／控制点和 deferred/barrier 建立因果次序，核效果与清理，杜绝用 `sleep(50)` 或 `elapsed >= 50` 猜测状态。不得以虚拟时钟证明真实进程树、文件或宿主原生终态。若必须模拟全局时间，优先已有 Bun 官方模拟时钟能力并在合格隔离环境恢复全局状态。
- **Runner timeout 是防卡死，不是业务性能 SLO。** 已有默认超时不逐测试复制；存在真实多阶段结算、租约、崩溃／恢复的独立预算时保留必要上限与平台资格。不靠把 timeout 加大、retry 直到绿、自动更新快照或跳过不稳定用例修复失败。
- **次数由失败模型及输入覆盖决定。** 代表值、上下界、缺省、空、非法、越界、第二次编辑等有穷等价类优先表驱动。高维不变量可用独立参考模型及可复现种子/缩小反例的性质测试；种子固定的千次循环不自动比数个代表反例更可信。20k/50k 深度、海量 DAG 和长时间测量只有在真实栈／容量／复杂度风险与合格运行资格下才保留最小有判错能力的压力规模，通常归慢/专用观察；未经 fast/slow 承接核验不能私自改运行频率。
- **基准测试与回归测试分账。** 只有已采用性能/资源预算且有工作负载、预热、环境、基线和独立测量时才做性能结论；单次业务正确不证明峰值/尾延迟，单次慢也不是明确性能退化。静态注册减少、assert 数减少与本地运行变快不是同一个数。
- **选择轮子而不建第二套平台。** Bun 内建 runner、Mock／隔离／模拟时钟、现有 TypeScript Compiler API/Source Program/Test Value、Knip 和 jscpd 先承接运行、发现、结构依赖与重复候选；它们不能独自判断测试对产品义务是否必要。多维随机性质或 AST 批改可分别只读评估 fast-check／ast-grep，突变有效性可在明确收益和授权后有界评估 Stryker；不因候选出现自动安装依赖、引入 Node 等效执行器、启动大量 mutation 测试或加入永久自制台账。

物理存放以[测试导航](../../../tests/README.md#物理测试源码与运行边界)为准；测试方法选择按“可发生的错误后果 × 独立判错力 × 运行及维护成本 × 执行资格”裁决，而不是预设测试层数、时间点或数量配额。修复不重测已证同一失败族的整个输入矩阵，但有不可逆副作用／安全绕过／持久状态损坏的独立故障切点必须可验证。

先固定用户范围、base/candidate、相交合同与唯一写者，再按决定性未知支付证据成本；不要求每项重走完整流程或证明全仓最小保留集。

遇到重复自制 parser、协议、调度或测试设施，按[轮子审查与复用](../repository-audit/SKILL.md#轮子审查与复用)同时比较仓内实现与可用成熟能力。复用上游能力不自动取消本仓适配、失败恢复和执行资格的独立验证；只读比较可与清理并行，发现库不授权安装、替换产品或新增测试平台。

| 证据层级 | 何时足够，何时升级 |
|---|---|
| 局部可决，整组删除 | 同一观察下保留断言严格蕴含被删断言；相同输入、owner、独立 oracle 和触发资格且无额外性质；或准备确无消费、资格责任及副作用。作者完整源审核实局部前提与最终保留项后即可成熟成组删，不强制非作者逐项独审、运行或全链追踪。只凭标题、文本、哈希或 AST 相似不够。 |
| 有界承接比较 | 局部不足时沿真实消费者比较相关文件，核输入等价类、失败模型、独立 oracle、触发频率与清理；先利用现有强观察，必要承接与旧项退役同批。读过或已分类不等于保留必要性已收敛。 |
| 深查并独立复核 | 跨入口/平台、权限、共享状态、并发恢复、物理结算或唯一保障存在可能改变结论的差异时，追到相交实现与正式 owner，由非作者复核删除反事实。具体未知只冻结依赖项，其他已证实可删组继续；不因删得慢而盲删。 |

**证据复用与有效并发。** 区分长期责任范围、路内处理批次、成熟发布批次：各路持有整个余量，当前小批或一次发布不缩减责任、不结束任务。汇报同时给出总范围、已结算、未结算、当前批及已发表净差额，并绑定版本/统计口径；旧基线、阅读量、当前批文件数和实际删量不得混用，未核实数字标未知。 同版合同、源码 blob、消费者及资格前提未变时只补变化闭包；hash 绑定证据，不替代初次语义判断。按域负责、按族执行、跨族去重；六路施工覆盖现有职责域，复核/统计/集成由负责人兼任，不占独立施工名额。大族按独立保障拆，小族按共同保障合批，不按文件数或条数切。交接归属后每文件/共享 fixture 仍只有一名写者，共享 HEAD/index 同步仍单写者，各路使用独立 worktree 或临时 index；共享承接先定最终保留者，不扩大授权。census 读不可变快照，发布只冻结本批精确路径与前后像，其他组继续。沿既有记录映射成员、例外和处置，不另造任务平台、永久台账或逐微改提交；报告绑定准确 tree，保留风险项独审和作用准入。

授权、语义范围和唯一写集明确即直接实现，不等 root 逐项内部批准；仅真实扩权、写集冲突或改变裁决的新证据升级。按上文风险分级成熟后滚动发布，只有深查项交非作者复核，不等整轮签收；禁止以几行删除反复交接报忙。每路长期持有整个已授权分组余量，族只是路内批次。单族完成、零差额或暂无成熟候选只结算本族，随即自行从未结算族领取下一组并报告精确写集，不等根逐项派单；跨域写集先交接，真实权限/依赖才阻塞。结束前核完整剩余范围：仅整个授权分组已结算或全部余量确受阻才可结束；不以全局最小性未知反复重审稳定组，也不以单族无候选注销未结算余量。异步交接核接收与当前执行，已结束者显式续启或改派；保留必要资格、风险项独审、发布准入及禁跑边界。各域自行检查、提交、推送并 exact 回读同一获准分支，不排专职集成队列。只在最新远端父提交应用 owned 差量，非强制快进并校验 expected head；竞争失败先查结果再重建本组，禁止旧树覆盖他人，不重做有效语义审。

- 选择最小充分观察层：纯算法用直接语义观察；跨 owner/存储/恢复用相应集成；实际 CLI、发布、Git/OS 权限保留相应原生证据义务。进程内 CLI 不冒称打包 E2E，Mock 不代替物理效果；定点故障注入/突变仅在争议确需且获准时使用，不追 mutation 分数。
- 区分无真实输入的私有 DTO 与有效故障注入：注入参数本身没有生产调用，不等于所触发的生产失败阶段不可达；若它独立检查已分配资源的失败回收及零回执／零作用，成功路径或分配前拒绝不能替代，须保留或由同阶段合格观察承接。
- 出现失败先分清产品、oracle、fixture、共享状态、宿主、依赖与权限；隔离相交 HOME/cwd/环境/Mock/时钟/随机数/Git 配置及资源，保留首次失败和获准的有界重试，不靠 sleep、扩 timeout、吞错、跳过或更新快照换绿。
- 成本按实际准备、依赖物化、运行、结算、CI 队列和定位比较；注册减少不自动证明运行更快，语义保持不自动保持频率，不造评分。执行由原 selector/runner 按缺口与失效证据选择；纯语义分析不跑测试、安装或追加兼容检查，用户另禁 typecheck 等也优先遵守，不为删改证明偷跑。正式采用所需未取得证据如实保留，不以静态裁决代签资格。

### 原生与发布硬边界

- 正式测试使用仓库声明的 Bun 版本、runner 与命令。**禁止把 `bun:test` 改为 `node:test`、制造 Node 等效 runner 或为“额外兼容性”运行未经要求的替代测试。** Node 作为产品既有被测外部能力时须有相应任务与 Claim。
- Bun/平台缺席、用户禁止执行或权限不足分别记录原因及 `NOT_RUN` / `NOT_VERIFIED`；只在获准范围做源码审计或静态检查，不把静态、CodeQL、历史 CI 或另一平台结果当成 Bun PASS。
- 有副作用的宿主/Git/工作区/Provider 测试只在获准隔离环境执行，结算文件、进程、凭证、锁与残留；测试许可不扩大为远端修改、用户配置变更或第三方写入。
- Hosted CI 只为冻结候选取得必要且不能由现有证据等价替代的证据，不用于探索、调试或逐步修改后反复试跑；复用同一对象的 fresh evidence，不重复 dispatch/rerun。出现确定失败先定位原因，不用重跑碰运气。
- 合并资格须绑定精确 PR head 的实际 CI、有效审查意见与 unresolved threads、base/head/merge-base 和真实 diff；资格不授权合并，仍遵守当前禁止合并的用户边界。

## 报告与收口

### 当前计数与逐项保留依据

用户需要随时核对数量时，复用正式测试发现／Source Program／Test Value 的同一事实来源与查询投影，不另造手写清单或把临时文本扫描器当正式执行发现器。每次展示绑定准确 source snapshot、发现范围与方法、环境／条件及新鲜性；工作区变化不能只凭 HEAD 未变复用旧数。没有匹配事实就明确缺失、过期或未知，不静默显示上次总数，不暗中触发未经允许的昂贵编译、模块加载或测试执行。

静态注册点、有限参数的潜在展开、展开未知族、runner 实际发现／执行／跳过数分列；Python 方法、类型级模块、间接 suite 及尚未物化的模板分别标明资格。静态登记须核实际 registrar 来源与别名、包装调用、条件／参数工厂及泛型，不能把文本中的 `test(` 当注册、把工厂调用当用例，或把一个包装入口代替全部真实调用点。不能静态确定的输入或条件保留未知；未知族数不等于未知实例数。禁止运行时不以“只发现”偷偷加载有作用的模块。

对声明 `KEEP`／已评估必要的每个当前 registration 或有界输入族，必须能定位到具体保留理由：有效义务及来源、可观察失败与独立 oracle、输入／fixture、真实消费者与资格、删除反事实，以及相交承接集合。其余项明确标注未评估、过期或缺证据及具体未知，不能以暂留代称必要。共同语义依据可一次覆盖整族，但须绑定精确成员和前提，逐成员可追溯其承接或独立差额；不要求重复书写共同证明。只有文件级审阅、文件 hash、标题匹配或状态继承，不能自动将所有条目标为必要。新补核须按实际时间记载，不倒推过去已逐条完成。

沿原责任与证据 owner 绑定 registration 内容、helper／fixture、规范及执行资格；这些前提变化后复核失效闭包，不凭旧 `KEEP` 继续宣称必要。区分已评估必要、未评估暂留、过期与缺证据；`retained-unassessed` 不签发必要性，解析成功或责任字段齐全也不证明理由真实。缺项／未知不得被“未分析为零”或文件覆盖抵消；发现误计、漏登或错误继承时同时纠正统计与完成口径。工具可检查绑定和缺项，语义判断仍按风险分级复核，不能保证任意未来绝无冗余。

报告本次实际审查范围、准确修订、处置依据、有效保证与残余未知；有删除/替代时指明承接及资格边界，有纠正 `O` 时说明为何原约束不成立。可直接放原案例、源码或 PR 审查，不要求另建文件或逐项表格。

涉及计数时分列实际整文件删除、静态测试声明增删、参数展开的动态实例、被测输入/调用、昂贵 fixture 建立次数、断言及行数；静态可推导的潜在实例与真实发现/执行实例另标，不能互充。说明已索引与已独立审查范围；循环内外移动一个 `test()` 不等于减少声明位置，helper 断言、Python 方法、类型级测试、模板与 Bun 注册不混计。修补弱断言不是删测，减少断言或调用不冒充减少测试声明/实例；纯 Skill 改动报告测试未变，不为凑数或无关全仓计数扩大任务。

运行结果严格区分 `PASS / FAIL / SKIP / NOT_RUN / INCONCLUSIVE / NOT_VERIFIED`，只有实际执行才报告其 runner、环境、精确对象和退出结果。语义审查、局部测试、受信 Gate、远端入库与 main 合并分别声明；保存源码不证明规则已加载或将来会正确执行。未审部分不计为已证明价值，暂留不冒称最优保留量。

收口前复核：是否从旧断言反推义务？仅有调用就认定必要？把独立风险误当相似输出？把两次同错或全部过滤当通过？把 fixture 失败或平台缺席当成功？用逐字文本、JSON 全等或引用相等锁住未承诺细节？迁移改变了 fast/slow 频率？用静态结论冒运行 PASS，或凭 CI 绿色擅自合并？结束或等待前执行[审计的完成检查](../repository-audit/SKILL.md#停止与恢复)，核当前范围余量及下一可推进组；阅读映射清零、单批/worker 完成不代签全轮结束，余量未知不当零。获准可推进的工作立即续接；不承诺未取得的“完美”或全局最优。
