# repository-audit

## 当前归属
系统边界从[总体架构](../../../docs/架构/总体设计.md)进入；同类消费者与新增入口的闭包归[约束强制](../../../docs/架构/约束强制与整体一致性.md#system-control-closure)，审计与作用准入的分工归[工程行为路由](../../../docs/开发/仓库维护/工作身份与续接.md#engineering-behavior-routing)。索引和路径分类用于发现，覆盖结论仍由实际读取与方法支撑；测试价值与删改判断交[测试设计](../test-design/SKILL.md)，本 Skill 不复制其裁决规则。测试清理以有效保障和整族退役为主线，新增冻结与单一 fixture 所有权沿[正式测试准入](../../../docs/开发/测试发现与执行.md#必要测试准入与单一资源主责)执行；发现重复缺陷时收敛责任入口，不以逐例补丁代替结构落实。完整分类、阅读完成和有界保留理由均不证明范围内必要性已全部结算或冗余已删尽。

## 触发
- 用户明确要求全仓审计，或对指定跨owner范围作完整分析；“全面优化某一对象”不自动扩大为整个仓库。
- 重大架构/合同演进前，或同类问题重复出现并怀疑共享抽象、状态所有权、验证架构或治理合同失效。
- active authority、实现、测试、CI、控制面、外部能力或仓库结构出现冲突、漂移或无法解释的空洞。

## 不触发
- frozen Task Envelope 内已证明为局部叶节点的普通实现、修复或重构。
- 只需建立 latest main/PR/Issue/CI/Review 最小事实快照；该行为由受信 control-plane resolver 确定性完成。

## 输入
- exact repository/base/head/tree、声明的审计范围及该范围完整path集合；全仓声明需要全部tracked paths。当前default、PR/Issue、CI/Review与active pointer只在相交结论需要时取得；不可用不伪造成当前事实。
- `.documentation/documents.json`、相交文档正文、模块/入口/公共合同、状态与写 owner、依赖/工具链、测试/CI/Gate、外部能力账本和历史边界。身份索引与当前运行控制事实分开核验。

## 前置门禁
- 固定可复核的输入身份。当前操作/发布资格消费受信control-plane snapshot；离线frozen source审计保留缺失live事实，不据此阻断不依赖它的源码判断，也不签发当前操作资格。
- 声明范围可读取；路径、submodule、生成输入或外部 authority 不可访问时记准确 unknown，只阻断依赖它的结论，不妨碍已具完整依据的其他组。

## 执行
1. 固定 immutable tree，从该 tree 与 raw blobs 对声明范围做一次 census；全仓模式覆盖全部 tracked paths，限定范围说明边界与外部消费者。分类为产品实现、验证、配置、活动权威、历史/Evidence、Agent投影或启发式运行面。已有同版分类直接复用，新修订只更新变化及失效闭包；搜索命中或目录抽样不代替全仓覆盖。checkout/index 不混入 exact-tree 报告，dirty 工作不因审计被清理；census 读取不可变快照，不以盘点为由冻结并发写入，新候选按变化闭包补齐。
2. 按结论所需建立相交对象、入口、接口、状态/写 owner、生命周期、依赖、数据/控制流、错误/恢复和发布关系；区分确定性合同与 Agent 判断。局部语义已足以决定的冗余，不先重建全系统链路；只有真实跨边界区别或未知才继续追踪。
3. 对齐相交 Goal、阶段 DAG、规范责任、代码、测试和实际产物；CI/Gate、PR/Issue/Review 等实时事实仅在依赖它们的结论需要时读取。冲突按当前规范与现实反证追到 canonical owner，不让身份索引签发权限，也不以代码存在反向覆盖目标设计。
4. 主动寻找第二 writer/loader/revision/pipeline、隐式状态、循环依赖、孤儿入口、重复规则、宽泛 catch-all、无消费者配置、过期当前事实、弱测试、错误成功声明和不可恢复路径；具体重复能力按下节核对复用候选，不只检查依赖包是否重复。
5. finding 绑定 exact path/line/symbol、机制、影响、决定性证据、适用范围及会反转结论的未知；区分事实、机制推导、现实推断和候选优化。同语义组可共享依据，但每项处置要能定位；只有结论需要时才深入构造反例，不给明显冗余强加全链证明或全局最小性证明。
6. 将 Agent 启发式缺口交给 `heuristic-governance`，跨 owner 架构缺口交给 `architecture-evolution`，产品实现交给受信 work selector/Work Package owner；全仓审计本身不扩张为无限修改包。
7. 复用原审计输出的path/line/behavior与deterministic-or-Skill路由，不建立第二套行为账本。unowned与unknown依真实消费者决定阻塞范围；生产blocking/diagnostic出口按原audit合同处理，不能由报告prose抹掉或扩大。
8. 输出按严重度、控制半径、不可逆风险、依赖顺序和修复收益排序的机器可读报告及有限候选闭包。

## 轮子审查与复用

- 从具体能力及真实消费者双轨查找：仓内重复自制实现，以及可承担该能力的既有 owner、已用依赖、官方标准库和成熟外部实现。先复用仓内已取得的证据，再定向查外部候选，不堆热门库清单或按文件少就替换。
- 用候选准确版本的官方文档/源码核语义、失败、资源、身份、并发与恢复边界，比较许可证、维护、体积、平台和迁移/退役成本。分别裁决可直接复用、保留有独立责任的薄适配、现有能力不可替代或待证，说明具体差额；同名 API、成功样例或功能列表不证明等价。
- 只读轮子审查与既有清理并行，未知只隔离相交替换。发现外部能力不授权新增依赖、安装、执行或扩大产品重构；实际采用仍消费原权限、owner 与完整迁移/验证闭包，遵守当前禁跑和 main 限制。结论回原源码/审计记录，不新建框架或永久选型台账。

## 风险覆盖与责任路由

全面审计只在声明范围核以下 A–L 风险；定向任务仅核相交项。这些是通用审计特征在 SEC 的路由，不建立第二份产品规范或逐测试登记。具体处置沿消费者、删除反事实及正式 owner 判断，共同证据可覆盖多项；在原结果区分 checked/finding、checked/no issue、checked/preserved、not applicable 与 unverified/unknown，不预填通过。分类存在不证明各项已检查，目录不声称穷尽未来问题。

## 审计工具的作用与证据边界

先复用已有工具结果，再按决定性缺口选工具；只读名称不保证无执行或外传。工具仅发现线索，不能签发权限、保障必要性或全仓完成。

| 工具 | 合格用途 | 必须保留的盲区 |
|---|---|---|
| jscpd | token/近似片段与重复准备候选；按实际版本核归一化范围 | 同文不同义、不同入口/平台/失败阶段不可直接互替；相似度不是等价证明 |
| ast-grep | 已知结构问题、调用/断言形态与整族候选 | 先 search，再独立判义；不自动 rewrite，未命中不证明穷尽 |
| Knip | 在有效入口内查可达文件、导出、依赖及孤儿辅助 | 测试本身常是入口；动态/外部入口、模板及其他语言遗漏会误报。排除测试的 production 模式不能裁决测试辅助退役 |
| Stryker | 获准局部变异与原测试观察，定位部分检测缺口 | 会执行测试及被测代码；执行与结果判定沿[测试设计](../test-design/SKILL.md#有界变异证据)，不能替代集合必要性判断 |

- **运行前固定边界：** 核工具版本、输入/输出范围、配置与规则来源、插件/加载钩子和实际启动链；JS/TS 配置、项目脚本、模块发现、安装脚本或自动下载均可能执行代码。禁跑时只用经核纯解析及静态配置路径，无法保证则冻结该工具，不冻结无依赖的静态裁决。安装、运行、联网模型/遥测、上传源码、仓库依赖修改分别取实际授权；不借 npx 隐式安装、自动 fix 或工具发现绕过限制。
- **绑定与复用：** 结果绑定相关源码内容、工具版本、配置、规则及有效入口范围；记录排除、解析失败、动态盲区和未覆盖语言/模板/间接注册。只重算内容或这些前提实际改变的闭包；入口变动沿可达性扩大，不因新提交号重复全扫。多个域复用同一结果，重叠命中不相加计数。
- **从线索回到义务：** 把命中关联到既有身份和实际 owner，比较可达输入、独立 oracle、失败阶段、平台/权限/恢复及最终集合贡献；共同依据充分才整族退役并删独属辅助，特有差额保留或待证。工具未命中的已声明范围仍需原审计覆盖，零告警、零候选、覆盖或变异分数不代签结算。

## 清理任务的交付节奏
- 先独立核保障是否服务真实用户结果、已采用合同或实际风险；实现、引用及旧 KEEP 不是单独保留依据，无有效义务及辅助价值者无需替代即可整类退役，真实未知不得标必要，安全/恢复/兼容承诺不因无调用撤销。再从有效目标推导充分保障与最终保留集合，复用[测试导航](../../../tests/README.md)的观察层/职责域和合格测试，再按共同义务整类替换。不要先把所有旧例逐条修好；必要承接修复同批；真实缺陷在授权内最小实际闭环，与无依赖清理并行，不扩平台或框架，标题润色等无用扩展不抢占清理。
- 比较范围取同一有效保障及其 owner/消费者在不同观察层的完整相关集合，不限文件或条数；共同充分证明可覆盖数十文件、数百或上千注册/输入，但精确成员及差额必须可追溯。交付批取其中当前能完整承接退役、按风险复核后发布的最大成熟多文件集合，不等全领域完成，不设数量配额或凑删量；需深查/未知仅隔离相交依赖。局部冗余由作者完整源审即成熟；仅边界敏感等风险项按测试设计独审。
- 目录只作发现索引；按域负责、按族执行、跨族去重；六路用于实际施工，复核/统计/集成兼任，不挤占施工名额。大族按独立保障拆、小族按共同保障合批，不按条数碎切。归属交接后每文件/共享 fixture 仍单 writer，跨组承接先定最终保留者；不扩权限或新造编排平台。census、审查/删改与成熟批集成并行，只冻结该批准确前后像和 owned paths。
- 区分长期责任范围、路内处理批次、成熟发布批次：各路持有整个余量，当前小批或一次发布不缩减责任、不结束任务。汇报同时给出总范围、已结算、未结算、当前批及已发表净差额，并绑定版本/统计口径；旧基线、阅读量、当前批文件数和实际删量不得混用，未核实数字标未知。交付成熟语义批，不以几行删除反复交接报忙，不凑无关高风险项。源码审查、测试执行和发布资格分别结算；用户禁跑优先，未运行如实保留。各域用隔离 index/worktree 自行检查、提交、非强制推送同一获准分支并 exact 回读，不排专职集成队列；从最新远端父提交只应用 owned 差量，expected-head 竞争失败先核结果再重建本组。共享 HEAD/index 同步单写者，不重做有效语义审。授权与写集明确即实现，不等 root 逐项批准；每路长期持有整个已授权分组余量，族只是路内批次。单族完成、零差额或暂无成熟候选只结算本族，随即自行从未结算族领取下一组并报告精确写集，不等根逐项派单；跨域写集先交接，真实权限/依赖才阻塞。结束前核完整剩余范围：仅整个授权分组已结算或全部余量确受阻才可结束；不以全局最小性未知反复重审稳定组，也不以单族无候选注销未结算余量。

## 完成证据
- exact输入tree、声明范围与path分类计数、相交authority/heuristic coverage、行为候选与模块/owner/入口覆盖、原报告中的finding/unknown及优化证据链；限定范围结果不得称全仓完成。
- `unclassified=0`、所有未覆盖/冲突均显式列出；“没有发现”必须同时说明检测机制和覆盖边界。
- 清理报告分别说明已索引、已语义审查和已交付的范围；测试整文件、静态声明、动态实例、输入/调用、昂贵 fixture 建立次数、断言、行数按测试设计分别计量，不拿修补/格式变化当删测。已有报告增量更新，不另建人工台账。
- 测试数量和逐项必要性依[当前计数与逐项保留依据](../test-design/SKILL.md#当前计数与逐项保留依据)核对；文件分类、共同组阅读或统计状态不能自动给所有注册签发保留结论。误计、间接注册遗漏及仅有文件级证据的项必须显式纠正／补核，不能以 `unclassified=0` 代称每个运行实例都已独立证明必要。

## 停止与恢复
- **重复重开暴露结算缺口：** 同一范围/前提未变，却在每次用户催促后立刻发现同类可退役成员，应重开该族的充分集合判断，不能把旧结算当已证事实。先定位共用的错误保留前提，按完整族成员一次裁决及合批处置，不再逐例补丁、反复结算或等待催促；发现仍有冗余不授权凑删量或撤销独立保障。记录本次实际重开的范围和原结论修正。
- **用正面范围证据结算：** 当前精确成员覆盖只证明没有漏项；须同时有覆盖整个责任范围的实际义务、最终合格保障集合与删除反事实判断，且交接、例外、纠错、未知和获准交付已结算。既有完整判断及连续有效证据可复用，不必在最终检查重审每个稳定成员或证明全局数学最小。只有候选清空、分组标题、文件覆盖或“未发现缺口”不能补出缺失判断；记录仍不足时定位具体未判组继续，不要求已结算组无限找反例。
- **结束或等待前的完成检查：** 按当前 source snapshot 与用户声明范围，在既有记录中核当前范围的已结算部分，将余量分为在途、可推进、受阻及待判定，明确下一可推进语义组；余量未核实就报 unknown，不报零。单批发布、worker 结束、报告交付或阅读映射中“未分析 = 0”均不证明全范围完成。有获准且可推进的组，立即自行处理或分派，不无条件等待或等用户催促；在途工作跟踪终态，待判定项继续获准补证；产品修复缺授权时，继续已获准的测试修补、静态补证与独立清理，不把一个产品缺口扩成全局停工。只有范围内义务及获准验证/发布/回读全部结算才可声明完成；用户暂停/取消或全部剩余工作确受阻时可暂停，但准确保留未完与恢复条件。
- 在既有记录保存准确版本、下一未完组与阻塞/恢复条件，恢复时先核副作用与证据有效性再续接。不得无依据泛扫扩范围、重复审稳定对象或增添台账制造持续；不承诺平台无限后台执行，不绕过授权。未再找到反例不证明开放范围已穷尽。
- 已满足用户约定完成条件时实际结算，并按原授权停止相应定时任务；提交只是检查点，不自动停止，也不让“继续”变成永不允许完成。仅等待用户必需决定时保留精确问题与独立可做项，不把重复读 HEAD/审批状态称为施工，不反复提问或擅自暂停。新的继续请求、新采用合同或具体反例，先核实际改变的范围/前提再重开相交组，不自动扩大产品删除权限或重扫稳定全仓。
- 仓库与账户 Skill 共同维护时，对齐适用义务而非字节同一：通用细则保留单一清晰归属，SEC 的 Claim、Source Program、selector、Bun 与 Effect 准入仍由本仓 owner 承担。声明已同步前核实际目标版本与引用内容；本地副本、旧保存结果或仅主文件可读，不代签当前在线完整内容。发现缺项回改原归属，不复制互相漂移的全包或将同步记录做成永久账本。
- 报告始终只证明其绑定的exact revision；需要评价新revision时由变化闭包决定哪些观察失效并补齐新census，保留可复用的固定对象证据。无关default前进不销毁旧报告，也不能将旧报告冒称新revision；根假设变化须重算相交模型。

## 禁止捷径
- 不以 `rg`、GitHub Search、单一代码图、README、PR body、历史报告或少量代表文件宣称全仓分析。
- 不把审计报告提升为产品/架构 authority，不把所有发现塞进一个巨型实现包。
- 不把确定性算法、类型字段和产品事实机械复制为 Skill；只抽取真实启发式行为。
- 不把dirty checkout、index或只含候选计数的摘要标记为exact-revision Evidence。
