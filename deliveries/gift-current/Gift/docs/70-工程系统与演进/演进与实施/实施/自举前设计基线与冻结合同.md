# 自举前设计基线与冻结合同

本页拥有**自举前的设计范围、设计冻结条件与跨责任装配边界**；语言意义、目标保持、权限、恢复和自举计算分别仍由其原规范拥有。本基线在 Gift106 源包上继续修订，属于设计采用，不是生产支持声明、真实自举记录或新增产品协议。`107` 是本次文档包序号，不是要求所有源码切换的语言版本。

## 终点必须是能继续创造的系统

Gift 的作者能力不是“选择系统已懂的业务”。作者可以定义新的名义类型、函数、谓词、关系、状态和协议，复用或创造实现；新业务定义不修改 Kernel。对新观察规律、外部效果或新的逻辑体系，系统提供有版本的语义扩展与资格接口，而不假装由名字自动获得含义。一个编译器自身、一个游戏规则、一个数据工具和一个尚未被标准库收录的算法，都使用相同身份、组合、控制和实现供应机制。

意图保留**结果与实现之间的自由度**。当已有合格方法满足公开合同，业务作者不必编写算法。没有现成方法时，既允许在 Gift 通用计算面定义新实现，也允许接入明确归属的原生供给；随后该实现可被其他意图复用。编译器可以请求取得方法，却不强迫所有作者每次选择语言、布局、线程、数据库和证明器。它也不得自行创造业务意义、权限或硬约束例外。

自举前的总设计不等于先实现所有未来领域。需要现在确定的是所有已知责任的合同、相互作用、失败出口与扩展准入；需要在自举运行前实际具备的是**编译器自身源码所消费的闭合能力集**。这两个集合不能互相冒充：用较小源码子集做自举不缩小语言设计；把领域目录写全也不代替一个可编译的自举源码闭包。

## 已采用的整体选择，不再留给实现者猜

正式作者可以始终保存严格 JSON：`gift.project.json` 管工程，唯一候选 `gift.author-module/2` 管新业务逻辑定义（旧 `/1` 仅历史只读），`gift.semantic-body/1` 管其有资格的中立计算主体，原 `gift.requirement-structure/1` 继续管有限需求组合。长 JSON 通过定义复用、局部编辑、默认值、结构投影、模块分离和按需展开解决，不因变长强制更换格式。可选 `.gift` 是同一已定义语义的另一个 SourceProfile，不能成为使用通用计算或语言自举的必要条件。一个区域只有一份有权编辑的作者源，原生实现仍保有自己的作者区域。

实现采用已有的单生产 Rust Kernel 方向，TS/Bun 保留工作台、交互、AI 候选组织和受权宿主作用；Rust/TS 目标源码是被编译的产品，不与控制面或 Kernel 混同。自举后部分 Kernel 的**作者源**可以迁为 Gift，生成 Rust 后仍由真实 Rust 工具链构建，不维护一份手写 Rust 与一份 Gift 的长期同义双源。未迁移原生模块有明确边界与真实比例，不靠透传全部 Rust 源码宣称语言自举。

不新增统一大 Runtime、第二套 Requirement 数据库、强制八层 IR、所有领域通用布尔、全局 `auto/manual` 开关或随意运行的插件。现有 G0—G7 是工程生命周期，Source/Meaning/Method/Target/Effect 是不同责任，两者不是重复目录。实际请求可以在相同进程中经过多个纯函数，无须每个责任都变成服务或持久文件。

## 四种“做好”分别成立

**设计已定**要求：有准确输入/输出、命名和引用、类型与意义、默认和拒绝条件、依赖与权限、状态变化、失败恢复、修改失效和可检验结果。内部可替换算法可留给 Method，但不能把公共语义、结果分类或所有权留空。

**实现可用**要求相应消费者真实读取这些合同，拒绝未知，而不是仅解析 JSON 或转发原生文件。**行为有保证**要求与主张相称的证明、参考语义、原生构建或现实观察，必须记录方法边界。**已完成自举**要求固定输入和真实阶段产物，并达到本包自举规范的覆盖、固定点与独立保证；这三者不因设计文件数量增长自动成立。

本次设计冻结只冻结**公开可观察合同与迁移责任**，不冻结内部数据结构、并行粒度、目录数、编译器代码语言永远不变或所有优化方法。之后发现反例时，按相交 owner 修改合同、影响闭包和迁移，而不是宣布旧程序一夜之间自动采用新义。

## 自举源码能力闭包如何准确取得

先选本次要由 Gift 实际实现的编译职责和输出根；收集这些根所有实际使用的 Definition、类型/效果、解释模块、Method、目标操作与本机库依赖。沿公开签名、函数主体、契约、默认、反射保留和生成器依赖求闭包。未选择的方法不是必需依赖；合法递归保留为强连通分量，不用“全部必须 DAG”误杀语言。

闭包中的每个语义操作必须有 C0 的实际消费者及保持该操作的选定 Target 供应；每个运行效果必须有受限宿主端口或明确原生边界。C0 不理解的新语法/类型规则不能用于产生“让 C0 理解自己”的第一份桥。先在旧能力集写桥、构建过渡编译器、检查旧样本，再采用新作者表达。若某项仍只能原生透传，登记为原生余部，不给它补一个恒真声明。

闭包的停止规则是没有未处理的**实际依赖边**，并完成所有相交方法/目标资格；不是查到没有 `TODO` 字样。数据相关的动态调用需要有限接口约束、显式保留或保守上界；不能靠运行过一次的调用图声称全面闭合。代码可以一般递归，依赖分析也必须有预算结果；预算不足不能被报告为成功闭包。

自举计算的优先交付面是：严格源解码与定位、模块/符号、类型/效果、契约实例化、实现解析、规范化/增量、目标生成、诊断和产物计划。源文件读取、外部编译器启动、输出发布、签名和凭证不因为“自举”就变为纯函数。前者由 Gift 定义真实计算，后者沿既有受权接口；可以复用成熟编译器、标准库和密码工具，不要求重新发明操作系统或机器码后端。

## 跨层不可缺少的接合

对每个自举根，先固定 AuthorRegion 的输入字节与 SourceProfile，再取得同一冻结来源下的解释身份和作用域，生成带 ReadSet 的类型化意义。可正常保存的草稿不等于可生成目标；完整候选也不必先成为正式作者提交才能预览。无缺项的意图经过硬条件筛选与确定性选择得到 MethodBinding；Target 只有在所有实际操作合法、依赖完整且剩余义务已按准入处理时才能发布完整候选源码。原生构建、结果采用与现场执行各有独立 Gate。

同一项修改可能只改变作者展示、改变公共含义、改变方法实现、改变环境资格或撤销当前授权。它们分别失效相交查询、证据、源码或执行权，不能用一个“版本更新”重建全世界，也不能仅变更源码哈希而继续保留旧证据。异常、取消、编译预算未尽、外部结果未知都保留本层原义，尤其禁止把未知作用当成安全重试。

这条链的每一步必须返回可定位、可继续的结果；缺 Meaning、缺实现、缺 Target、缺 Evidence 和缺 Authorization 是不同问题。返回失败不删除作者内容；可独立完成的根继续完成，带未决根的整个原请求仍不标完整成功。

## 开放性、易用性与质量的共同验收

验收不以函数、案例或行业数量为主。至少要求一个实现者使用已有语言构造引入此前未登记的语义定义，另一个产品作者只通过公开意图引用它，第三次修改约束时系统正确重选或拒绝方法。过程不得修改 Kernel 业务分派，不得复制原生实现正文给每个调用者，不得凭源注释中的自然语言猜目标程序。

意图输入的增量成本应由**新的独立决定**支配：沿已有定义默认继承的条件不重复写；用户没有委派的结果、错误、精度、隐私、时序与副作用不能省略。对任意新算法的实现成本不伪装为零，对已知能力的业务作者也不强迫承担实现者的整个证明和参数表。

“高质量源码”被拆成可观察保证：可构建/可运行、公共行为保持、目标惯用结构、准确类型和数值、依赖与生命周期、可定位错误、修改稳定、受管区域不覆盖、合格性能与安全。没有性能数据时不能将某生成模式叫最优；硬资源目标若无可信静态界或真实测量依据，返回缺证据。普通功能不因未要求最高保证就被迫使用形式证明，但严格主张不能由测试自动代签。

## 冻结门槛与剩余未知

设计冻结前检查：所选源码每种结构能定位到文法与意义；每个消费接口的默认/错误/预算明确；声明、生成、采用、执行不共用权威；所有真实调用有资源和取消责任；更新与旧版本并存不会制造同源多写；C0 到 C3 的构建、比较和恢复可独立执行；同一保证至少有不依赖同一错误路径的核验方案。对应细节分散在原责任规范，不复制成第二份总设计。

运行前仍需取得的私有或现场参数包括真实仓库源码位置/修订、可用 C0、工具链字节、宿主与目标平台、发行密钥/权限、实际资源预算与受支持外部 Provider。这些不能由文档杜撰。设计已规定这些值的类型、绑定和缺失时阻断行为；参数未知不等于接口未知，也不允许填假值后称自举可运行。

本页不声称已验证所有未想到的构造或未来领域。已知高级扩展由其公开合同与组合义务约束；新反例可重开受影响设计。实际实现、性能、跨目标保持、独立证明和现场恢复仍需各自真实证据，不能被本次设计包机械检查替代。

## 自举与通用业务意图的关键路径隔离

原 C0—C3 与 Rust Kernel 选择继续作为真实语言自举/迁移合同；**自举不应自动成为普通业务意图→现成软件的前置条件**。若 Gift111 计算子集被某个已选 Method 或真实自举源码消费，才按实际引用冻结其构造闭包。规划器的新领域表达能力按 Meaning/Method/Target 是否开放与实际资格评价，不能靠编译器自编译或函数表达式种类推断。两条工作并行但成果口径独立。
