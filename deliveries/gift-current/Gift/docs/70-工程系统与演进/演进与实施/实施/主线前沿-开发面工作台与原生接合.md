### 开发面 DEV0—DEV5：唯一实施接合与验收序列

本阶段先实现/核验[完整开发面](../../../80-开发者与接口/客户端/开发面与智能投影.md#developer-surface-contract)，不继续用另一个算法细节替代开发者动作。DEV编号只描述这一实施序列；它不与DEC、DP、DBG、DEP或其他协议共享阶段含义。当前文档任务不授权创建产品代码/测试工程或修改真实仓库。

| 阶段 | 可实际交付的完整用户任务 | 必须相交的拥有者、输入与退出条件 |
|---|---|---|
| **DEV0 Source capture** | 临时源、新工程、库/脚本、原生多根的打开、直接修改、草稿保存与恢复 | Runtime寿命、CLI分帧/退出、entry/workspace、`source/files/edits`与工作集捕获；真实格式/前像固定，临时引用不跨进程伪活，无后台安装 |
| **DEV1 Author feedback** | 查询说明、补全、局部值、格式化、重命名及有限抽取，形成同一多文件候选 | semantics/CST/原生服务、准确配置/语言/成员、诊断请求槽；附加编辑、非法草稿和动态未知不丢，旧空诊断不清新错 |
| **DEV2 Review & optional assist** | 语义组审查/部分选择、源类型与目标检查、真实案例选择/复跑；需要时启用authoring-assist、位置规范化和有限重构 | application/assurance、EditPlan、固定`casesRef/oracle`和覆盖；辅助不是DEV0/DEV3的语义前置，失败不靠删测试修绿，普通作者路线始终可用 |
| **DEV3 Generate & verify** | 多根生成/构建、ArtifactSet、未保存源物化、实际测试发现/CasePlan与精确检查 | compiler/execution和目标Provider；源/配置/资源/案例同代，至少两个请求输出根可独立结算；不偷测磁盘旧版 |
| **DEV4 Run, debug & re-edit** | 参数、CLI/服务、输入输出、有限调试、环境准备、运行后再次修改及必要写回 | 真实Runner/DebugDriver/Provider、来源与环境；新旧产物/运行/结果不串，运行资格与Profile分开，未支持公共分支准确拒绝 |
| **DEV5 Integrate, deliver & continue** | watch、多客户端/多AI、断线/交接、VCS/CI、部分采纳、包交付、迁出、回退和清理 | 原共享query/operation/保留/授权、工作树/index/merge、发行/许可；合并候选重新检查，真实在途不随客户端丢弃，迁出源码不被可选服务锁住 |

小型内存/串行实现可以先完成共同范围，不强制远端服务和GUI。成熟IDE、测试器、包管理器、VCS、调试器和运行库优先复用，差额落到[具体物理接合](../../实现与装配/能力接合与文件责任.md#developer-surface-physical)。不能以“调用Adapter”代替真实参数、源/结果绑定和失败处理；也不必重建Adapter背后的完整产品。

每个阶段以首次使用和第二次修改共同验证：编辑→相交消费者→结果→再改→恢复/退出。DEV2是条件增强，不阻塞DEV0、DEV1、DEV3已满足的普通开发；其他阶段只有硬依赖成立才形成顺序。典型任务至少含小片段、新自定义算法、成熟供给复用、两根工程、多文件接口变化、未保存测试、原生/生成回源、并行合并和交付；不只用成功小函数。Rust及其他非TS目标和更高级语义仍按各自U保留实现/验证边界，开发面排程不能擅自扩大其支持范围。

### 人类Workbench的实施切片：壳已选定，按authority成熟度递进

人类客户端不再重新选技术栈；一次实施任务只决定做到哪个已定切片。以下 HX 编号是实现切片定位，不是新的产品状态机，也不要求阻塞前面的headless主链：

| 切片 | 完整交付 | 必须先成立 | 验收出口 |
|---|---|---|---|
| **HX0 Client-neutral view contract** | DeveloperView与`DeveloperDecisionView`、Needs、Plan/Delta/Impact、Evidence、Operation摘要可以由CLI/测试直接消费；All Decisions的decisionRef/scope/owner/source/effective/actions及可选facet可分页取得 | 现有六工具/作者/Requirement/Control/native config/Operation合同 | 无`vscode`/DOM依赖；开发面符合性接缝保证Auto/Pin/Profile/native/runtime写回和同输入确定；大结果分页 |
| **HX1 Extension safe shell** | Code-OSS/VS Code Extension activation、Gift Activity Bar、Project/Needs/Operations只读视图、Inspector Summary；懒Runtime连接 | HX0；Workspace capture/read安全路径 | WB01—WB03、WB13—WB15；打开工程零写/零隐式执行 |
| **HX2 Review/edit bridge** | native editor/source mapping、Inspector可编辑owner、Plan/Review、candidate accept与`Apply to workspace` | EditPlan/semantic-change、前像/CAS/恢复 | WB04/WB06/WB12；CLI与Extension normalized Delta一致 |
| **HX3 Native developer integrations** | Problems、Testing、Run/Debug、Terminal/process、SCM的精确binding；不复制宿主真值 | 相交language/test/debug/VCS Providers | WB20及DEV案例；旧session/diagnostic不贴latest |
| **HX4 Assistant** | Gift自有可选Assistant view、context选择、Proposal卡、provider/disclosure/budget显示 | candidate/Plan已可完整承载AI建议 | WB17/WB18；无AI时产品仍可用，LLM无直接writer |
| **HX5 Read-only Graph** | Structure/State/Dependency/Impact/Evidence bounded graph、layout缓存、keyboard/list替代 | stable refs、query/Impact/Explain | WB08/WB09/WB19；删除layout无语义损失 |
| **HX6 Writable typed Graph** | 只开放已有typed Port的Connect/Disconnect proposal及Plan/Review | **[GraphMutationReadiness](../../../80-开发者与接口/客户端/工作台布局与交互.md#graph-mutation-readiness)**、typed Operation registry、transactional apply、deterministic lowering | WB09—WB12＋CLI同义；无edge-store真值 |
| **HX7 Gift Workbench distribution** | Code-OSS source build +同一Extension+固定Runtime+必要开源Provider，自己的品牌/update/extension-source策略 | HX1—HX3稳定；发行/license/SBOM/provenance | WB05；与普通VS Code Extension canonical结果一致 |
| **HX8 Remote/Web expansion** | remote/WSL/container colocated Runtime；Web只按真实Provider开放read/plan/effect | 真实remote transport/auth/disclosure/recovery | WB14/WB15；断线/stale/reconnect不误贴 |

HX4与HX5在HX2之后可以并行；HX6不能因为Graph好看越过[GraphMutationReadiness](../../../80-开发者与接口/客户端/工作台布局与交互.md#graph-mutation-readiness)；HX7不要求HX4/HX6；HX8按真实远程消费者激活。每个切片都必须保留headless CLI/SDK路径，不能让GUI成为唯一恢复工具。

#### 实现依赖与包闭包

Extension实现优先复用宿主API，不把Code-OSS源码作为Gift仓库的运行时源码依赖。Extension bundle只包含客户端adapter/presentation、必要Webview静态资源及兼容runtime launcher；Core Runtime仍可独立发行和运行。`vscode`、React、xyflow、elkjs等依赖不进入headless Runtime生产依赖闭包，防止CLI冷启动和服务器部署被UI供应链拖累。

图形依赖只在HX5开始增加，并在真实实现任务中锁版本、license、bundle/security扫描；HX0—HX4不能为了未来Graph提前安装。独立Code-OSS distribution在HX7才取得上游源码构建、品牌、更新、extension source、自动更新和平台签名责任；普通Extension实现不提前承担整套桌面发行。

#### 性能与完成门槛

UX性能不使用虚构固定毫秒SLA。实现时在真实基线记录Extension activation、首次Gift view、warm query、Plan打开、10k/100k对象bounded tree/graph、内存、bundle与Runtime启动；以宿主原生操作和CLI同等查询为对照。性能优化不能把unknown省略、预载全仓或把stale结果当current。只有有真实数据后才冻结发行预算。

### 原生接合的最小交付与逐能力增加

先贯通准确作者需求、现成TS/原生方法和一个真实消费根。采用复制值的同步小接口可先闭合；异步、设备、零拷贝与热卸载只在实际消费者需要时增加。对应具体实现分别由[GUARD0—GUARD8](../../../30-实现解析/有条件实现与公共行为保持.md)与[CALL0—CALL8](../../../50-执行运行与观测/跨实现调用与数据寿命.md)约束，不以新的语言前端或全功能缓冲平台为先决。

强资格必须能够在明确验证目的下取得：先形成可隔离检查的候选，再运行被允许的检查、评价实际证据和生产采用；不把需验证的实现直接标合格，也不让资格依赖形成永远无法启动的循环。静态结构检查、有限算例和真实适配/运行验证分别结算。
