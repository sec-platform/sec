# 发现、推导与覆盖判断

## 发现、推导与覆盖判断

### 目标到义务的自主发现主循环

本节拥有设计阶段的自主发现算法。它把已存在的目标、约束、反例与当前未决义务接成当前可执行的工作方式，不要求用户先指出哪个模块有问题。运行产品只在真正请求设计评审时消费相交规则；一个普通编译请求不加载全产品问题库。

当前采用**目标—义务关系图＋当前未决义务前沿＋按任务投影的工作前沿**。总表是供人和AI浏览、排序、过滤的视图，不是唯一能够表达关系的结构；没有新建在线管理平台、数据库或独立计划选择器。当前用Markdown条目、稳定锚点和准确引用即可维护。

#### DISC0 固定本次目的而不是跟着最近一个例子走

先读实际入口、用户持续约束、当前任务与父版问题。取得三项结果：当前必须交付什么；什么动作没有授权；哪组长期产品目标仍然成立。把每项来源标为用户要求、已接受产品目标、设计推导、外部观点或待确认事实。外部规范不是自动生效的本地要求，助手选了一个MVP也不因此删除长期目标。

对已明确的条件不重复追问。缺失条件先区分会影响幅度与会反转方案的变量；可安全建立基线时说明假设并继续设计，涉及授权与不可逆作用时保留真实边界。用户的目标、偏好和权限作为任务约束，其事实或因果判断仍需独立检验；技术提醒只产生比较义务，不自动成为采用决定。

当前已接受目标及约束由[产品要求](../../00-系统与原则/产品/产品要求与工作约束.md)与对应领域规范拥有；[当前前沿](../../90-治理与参考/状态/README.md)只是依真实 owner 与[实施闭包](../../90-治理与参考/状态/实施闭包.md)派生的工作入口，不是全部目标或全部设计问题的第二权威库。历史目标编号只能作溯源线索，不进入作者语言或每次开发请求，也不声称已逐字取得用户全历史。新要求无法归入既有目标时保留准确来源，在产品要求及相交规范中判断采用和派生关系，不强塞旧目标。

#### DISC1 从接受结果倒推必要义务

对每个实际目标，写一个合法成功情形，然后问：为了这个结果成立，作者、解释、实现、目标和采用分别需要什么事实与能力？逐层得到**必要结果和接口义务**，不要直接从“要快”跳成“必须分布式”，从“要自由”跳成“必须新增关键字”。

不能以标签重述作为第一性依据。对决定方案的约束，说明改变它为何会改变结果、可检验的作用链、适用范围、绕过与失效条件，及在多约束下是否真正控制结果。对相交链继续检查间接效应、反馈、时滞、阈值、累积、不可逆点和成本转移；证据显示约束或分类不成立时，返回本阶段重建，而不只补一个例外。

每条派生义务记录父目标、作用对象/范围、激活条件、可观察的完成结果和推导理由。其必要性来自：外部硬要求；父结果的逻辑前提；已选择的架构引入的义务；或明确选择的优化。后两类必须标明：换了架构可能移除该义务，优化也不自动成为全局必须。

例如“支持中立源生成TS与Java”导出各目标的数值、错误、模块和ABI保持；并不导出“所有高级语言今天都完整实现”。“支持不覆盖用户修改”导出前像、作者归属、冲突与可恢复写回；不自动导出一个分布式数据库。未选方案的后续实现不取并集，已产生的恢复责任却不能按未选优化删掉。

#### DISC2 用有类型的关系代替一棵纯树

| 关系 | 判定含义 | 对下一步的影响 |
|---|---|---|
| AND共同满足 | 父结果需要全部列出的子义务，并满足它们的接口组合 | 单个子项绿色不足以关闭父项 |
| OR合法替代 | 某一满足范围的方案足够 | 选定一条后只激活它的真实依赖；保留其他方案的适用范围与重开条件 |
| 条件激活 | 条件为真时才引入义务 | 未知条件保留待判定，不能自动当不适用；运行事实与设计选择分开 |
| 硬前置 | 开始指定动作前必须已满足 | 只阻断该动作与真正依赖它的后继 |
| 协同设计 | 两个接口要共同裁决，但无需等待对方软件已实现 | 可以作为一个设计单元，不伪造先后环 |
| 不可兼容 | 同一范围下两个选择不能共同满足 | 返回真实冲突与最强替代，不能平均或最后写入覆盖 |
| 产生/消费/验证 | 产物或声明有实际生产者、使用者和对应方法 | 孤立文件、无消费者机制和没有义务的检查进入必要性复审 |
| 失效/替代 | 前提变化使旧判断重开，或新决定明确取代旧决定 | 更新新图及旧消费者；不把旧问题悄悄删除 |

这些关系可以包含共同原因和多方不变量，所以根目标不是文件夹树，工作顺序也不是按行号排序。所选执行动作在解决真正循环后形成可调度图；整个知识和设计关系本来可以有反馈。

#### DISC3 追到可交付叶项，而不是一直拆到代码行

一个设计叶项要能够明确交付：负责规范、输入和前态、当前数据/算法/接口、正常结果、保持范围、失败分支、资源与进展、验证设计、替代与重开条件。已有规范已承担它时引用其具体位置，并写清当前调用方传入/返回及异常处理。

出现以下情况应继续拆分：同一条里混了可独立完成的决策；责任归属相反；激活条件不同；一个问题阻塞了另一个本可独立的结果；关闭条件无法判断。出现这些情况则合并：拆分只产生重复字段或重复审查，边界之间没有独立含义、消费者或失败路径。

叶项可以是一个算法、一个构造规则、一个适配合同或一次明确的设计决定。只设计任务不必拆成函数实现和产品测试文件；图中的叶项粒度也不等于作者源节点、线程、文件或服务粒度。

#### DISC4 从现有设计反向检查多余、遗漏和错误前提

对当前每一项机制反查其目标和义务：确无来源也无被接受的推导时，先列更小替代或删除候选，不以“行业最佳实践”直接保留。对每个目标反查它是否有完整的交付链，只有一个标题或一个类型名不能算完成。

再检查输入输出、失败、资源、版本和作用的连接：某个消费者依赖的保证有没有生产者；一个动作是否假定了没有声明的全局状态；两个分别合法的组件组合是否增加义务；只读任务是否被写回、签名或部署记录阻塞。

缺少路径是**追踪缺口**，不自动证明软件功能不存在；有路径也不证明含义正确。模型或静态工具只能发现候选，仍需阅读相交正文作语义裁决。NASA的要求管理同时要求双向追踪和检查派生要求是否真正完整满足父项，也明确处理无根据的额外需求。本包借用这组检查，不复制其全部组织审批流程。[依据](https://www.nasa.gov/reference/6-2-requirements-management/)。

#### DISC5 每个重要边界主动生成反例，不等用户提示

先保留合法成功路径，再依次改变该边界上最可能导致质变的条件：删除最后一个支持；将未知当空值；新增约束但原对象不变；相同结果换来源；改变阶段或责任；让旧响应迟到；两个任务争一份资源；恢复库和主库一起回退；把一个可选优化当全局前置；把一个局部完成当整组成功。

单一扰动揭示耦合后，再组合相关扰动，例如“取消＋远程失联”“规则升级＋旧缓存”“管脚改写＋外部原文变化”。不是盲目生成所有轴的笛卡尔积，也不把成对覆盖误称全部高阶组合证明。新反例揭示新对象或新约束时，回到A1/A2重建相交图。

必须同时尝试最强竞争方案：不用新增机制是否足够；直接成熟工具是否更小；保留原生资产是否更合适；中立作者的同等保证能否以更少决定表达。反证当前最强方案，而不是只收集能支持它的案例。

#### DISC6 两个独立入口轮换，减少目录和最近问题的锚定

一条入口从目标正向推导；另一条从一个具体使用过程、成熟系统机制或真实失败倒推当前合同。比如，从“线程池里所有父任务都在等子任务”倒查，就会发现仅有DAG和线程安全不足以保证进展。

还要从已有设计删除一整类设施，观察目标是否仍能完成。纯计算去掉数据库、设计请求去掉产品执行、结构编辑去掉人类GUI，都应各有合法路径。某领域不在本次实施，不等于在设计发现中禁止检查它对核心的约束。

这些是不同审查视角，不宣称同一模型换两个角色就取得了两个独立证据源。外部资料、独立方法与真实观测的共同原因另行保留。

#### DISC7 有缺口先保存，再立即能裁决的就裁决

问题按**真实责任分流，而非进入单一登记**：尚缺语义、算法、接口、跨 owner 交接或采用决定的，把来源、反例、影响范围、当前安全路线、待作决定、依赖和关闭条件写进相交[canonical owner](../../90-治理与参考/状态/README.md#全工程当前前沿)；设计已定但缺生产实现、接入或现场证据的，写入[实施闭包](../../90-治理与参考/状态/实施闭包.md)并引用规范。二者可以同时存在，但不得分别持有同一规则或同一完成状态。没有方案时仍保留可复核的最小反例和受阻操作，不用“尚未设计”替换实际不确定性。

在当前授权内能补的设计，不转交为“以后让agent分析”。当前任务不授权实现，所以实施前像、产品运行与外部账号事实仍保留具体取得路径，不伪造。这种区分不能成为回避纸面算法和接口设计的理由。

#### DISC8 按真实依赖和优先级推进，然后回扫消费者

使用[实施前沿与优先协议](实施/主线前沿-工作组织与成熟度准入.md#问题优先级与当前可推进前沿)选择当前工作，不按问题编号、出现先后、代码行数、最容易写或最后一条用户消息决定。

一个根前提改动，先修它的规范拥有者，再检查调用方、文法/模式、实例、目标、检查、迁移、理由和问题状态。几份文档分别看似正确仍可彼此矛盾。必要时把原来的依赖关系标为失效并回到A2，不能只在新段落写“以本章为准”。

结束前做一次逆向检查：每个关闭结论有范围和依据；每个原开放问题有当前去向；新条件激活的义务被纳入；未读取内容没有被写成已审；本次修改没有增加未经授权的执行或作者负担。

#### DISC9 交付的是当前闭包与开放前沿，不是绝对穷尽宣言

本次输出包括：已固定目标；已展开义务；实际读取与未读范围；修订与反例；尚开放且有具体下一步的前沿；当前优先顺序及其理由。对已有有限、固定、可枚举的范围，可以检查所有节点/边/分支；它不自动成为开放现实的全部问题。

默认停止条件不是“已写了很多”，而是当前授权和工具范围内，有依据的队列已被处置，重要攻击不再改变当前结论，或遇到明确的能力/权限/平台边界。尚未展开的邻域保持未审并指出怎样继续。没有新产出的重复搜索、同义拆分和无机制猜测不继续生成问题。

再次收到“继续”时，先读取本节、当前目标与就绪前沿，选择未解决的上游问题并主动扩展相交区域；不要求用户先给下一个关键词。没有跨会话常驻执行器时，该行为发生在实际任务中，不承诺离线后台一直工作。

### 从一个目标完整推导到具体工作

以“局部作者修改后生成仍合法且尽量稳定的源码”为例，目标不是一句`少改`：

| 派生义务 | 为什么需要 | 当前处置与已知问题 |
|---|---|---|
| 当前作者来源与精确基础 | 不知基于哪份内容就不能识别这次变化 | [AuthorSource / SourceProfile](../../10-作者与输入/作者源/可替换表示与适用范围-语言定位与作者基线.md#source-profile-selection)、候选前像与 SourceRevision |
| 本次真正改变的含义 | 参数、要求、实现选择和目标形态有不同后果 | Requirement / Control / Binding 的真实 owner 与语义差异 |
| 真实影响与共同约束 | 局部字段可能影响多个消费者 | 动态/负依赖、组合不变量与相交消费者 |
| 布局连续性输入 | 没有明确历史基础就只能规范重生 | 既有 SourceLayoutPlan / Artifact 基础与布局政策 |
| 并行的共享名字和输出拥有者 | 各模块分别选名或争写文件会制造不稳定 | [并行与远程编译](../../40-目标与制品/递归并行与远程编译.md)中的命名协调、输出 owner 与发布原子组 |
| 原生区、资源与其他文件保持 | 小源码修改不能覆盖人工文档或图标 | [原资产合同](../../10-作者与输入/作者源/工程源/资产与非源码.md) |
| 产物资格与真实写回 | 可生成不等于当前工作区前像仍相同 | Artifact 资格、SourceMap/CAS、工作区前像与真实 apply |
| 退路和采用收益 | 不可保持时应解释重组，整体成本也可能不划算 | 迁移退路、作者总负担、净收益 Evidence 与重开条件 |

其中选择`canonical`规范重生可以不依赖历史布局，但它不能满足明确的严格历史结构保持。选择只预览可以不依赖写回恢复，但它也不宣称已写文件。总表因此必须保留AND/OR和条件，而不是将上表每项变成所有任务的统一前置。

针对跨根并行生成的公共符号与布局竞争，当前采用的设计为：先固定全组公共符号与布局，按输出拥有者分派独立打印任务，冲突由协调者在实际发布前拒绝。这个义务不是用户先说了“命名竞争”才存在，而是从目标、并行方案和两个生产者的组合直接推出来的。

### 覆盖判定怎样避免自我认证

**目标覆盖**检查每个接受目标是否有承担它的义务和验收。

**边界覆盖**检查已选择组件之间的输入、输出、错误、版本、资源与作用是否接合。

**生命周期覆盖**检查该对象的产生、使用、变化、故障和退出；不适用项要有实际原因。

**扰动覆盖**记录实际分析过的删改、并发、失联、默认变化和恢复情形。

**实现/现场覆盖**只在实际取得对应证据时记录，不由文档覆盖代签。

当前分母来自固定版本中已声明的目标和边界。若后来发现遗漏目标，分母也要变；不能用100%完成旧表证明世界完整。存在新问题不表示所有旧设计无效，旧表全绿也不阻止继续发现。

### 完整语言体系的主动补位

从“作者能定义任意独特行为”推导语言、资源和工具义务，不只从最近收到的名词开始。语言新增或修改时使用[三十类能力裁决与LANG0—LANG5](../../20-语义与组合/作者语义/能力映射与表达边界.md#完整语言能力的当前裁决)，沿共享存储、绑定、控制、阶段、错误和输出检查组合。二元检查发现同一对象同时受第三条规则控制时继续追踪，不能因表格只预设两轴而截断。

当前明确的主动反例包括：var经闭包返回导致位置外逸；公开效果隐藏后内部两个调用被合并；let绑定的函数隐藏共享可变状态却被多态化；return已求值但close失败；close失败还留子任务使用父缓冲；目标finally/defer改变主错误；编译期函数读取未绑定环境。它们的处理归控制、语言、编译和验收规范，不在此重复算法。

每个反例先检验当前规格是否已解决：已解决则使用相应规则，不再创建同义U项；确有缺口则改拥有者和消费者。研究所用原始规范沿[来源协议](../../90-治理与参考/维护/设计依据与资料边界.md#研究结论的保存复用与失效协议)更新，不把提问者当成补齐资料的唯一触发器。

### 问题发现怎样收敛为一次可裁决的设计

研究先形成可裁决方案、最强反例和适用条件；采纳后的语义、算法与接口写回唯一领域 owner，无法裁决的设计缺口也留在该 owner，缺实现/接入/环境 Evidence 的义务留在[实施闭包](../../90-治理与参考/状态/实施闭包.md)。本节的[自主发现主循环](#目标到义务的自主发现主循环)是唯一发现算法，不再另立问题退出算法或由报告代替正文；实际消费者和失败后继必须随规范改动一起复核。

### 机制研究的输入范围输出与停止条件

研究服务于一个要作出的设计决定。当前不将“读取世界上所有语言的所有关键字”作为作者面或MVP实施前置；这类集合开放、版本变化且高度重复，无法从词表推导类型、效果、资源或成本。也不因不做全词表普查，就放弃对相交机制的深入比较。

#### 研究输入与已选机制表

每个研究问题先给：当前要求/使用场景、要决定的对象、当前候选机制、最强反例、需要保持的观察和允许的资源。优先查实际规范、工具实现及失败材料；同一语法词在不同语言中先归入机制问题，再比较语义，不按单词数量投票。

| 机制轴 | 必须回答的具体问题 | 当前设计方向 | 何时必须重开 |
|---|---|---|---|
| 作者与模块 | 原文、命名空间、导入、未完成草稿和多文件编辑怎样一致 | 直接中立文本、限定导入、单一作者、工具解析 | 必须手填第二模型、重命名丢身份或导入隐式执行 |
| 值与数值 | 整数域、浮点、文本、缺失和表示如何映射 | 明确公共值域；后端保存含义，特殊数值另画像 | 同名类型值域不等、悄悄溢出/规范化 |
| 类型与推断 | 哪些局部可推断，公开接口与泛型是否可检查 | 当前显式公开签名、局部推断、相交高级规则 | 普通表达要重复类型，或推断替换了业务要求 |
| 函数与效果 | 求值顺序、闭包捕获、错误和契约怎样保留 | 基础函数与效果分离，真实调用条件不丢 | 传递函数后检查消失、所谓纯优化改变失败 |
| 结构与高层表达 | 重复模式能否组合、自定义和局部具体化 | 库与显式领域构造使用同一基础 | 只能改模板开关、普通新算法要改核心 |
| 内存和资源 | 值、布局、别名、生命期及异步完成怎样关联 | 逻辑值不规定每步复制；保持条件后复用 | 取消就释放仍在用的内存、独占被误当原地合法 |
| 并发与时间 | 通信、顺序、等待、取消和期限是什么合同 | 具体域明确模型，不将所有状态做事务 | 数据竞争/死锁/实时被一个标签认证 |
| 编译与证明 | IR、优化、编码是否保持同一个对象和含义 | 多层表示按需派生，转换条件具体 | 证明器和后端对数值/文本解释不同 |
| 生态与目标 | 接口、包、初始化、ABI、调试与迁出怎样成立 | 用户产物目标采用TypeScript先行、Rust已纳入计划；Java暂缓，C/C++及其他语言按真实需求进入原生供给、互操作或另行目标决策 | 目标换了要重写公共语义、包装代替真正生成 |
| 工程控制 | 候选、绑定、权限和实际操作何时决定 | 按对象和时点分开，已绑定重建不重新猜 | 当前选项改写旧操作，保存被当部署 |
| 使用成本 | 冷/暖上下文、变更、诊断和退出的总工作 | 同库同保证完整任务比较 | 仅词数少却总任务更贵、删测试制造优势 |

这张表是研究者的输入分类，不是用户源文件，也不是每个任务都执行十一轮检索。某机制已由规范明确且当前反例不改变它，就保留选择；新证据改变其前提，再回到相交规则。

#### 一轮研究怎样交付

先从当前规范抽出可否证主张；确定备选实际在何处不同；读取原始机制；构造至少一个能区分方案的输入/轨迹；选择当前默认并说明最强替代；把正常路径、错误、资源、兼容与验收写回唯一规范。若关键环境事实缺失，选择有界可逆默认或写明特定阻断，不能把所有备选永久并列。

关键词研究服务于具体机制选择：Python 的软关键字只在特定上下文解释，Rust 的关键字按 edition 演进；关键词数量不能代替完整能力比较。MLIR Toy 先定义作者程序、数据与语义，再描述 AST；这一顺序可用于闭合作者路线，不要求 Gift 采用其张量结构。具体来源与适用边界见[资料目录](../../90-治理与参考/维护/设计依据与资料边界.md)。

研究对当前决策的停止条件是：已排除明显不合格者，当前默认具有明确机制与边界，最强已发现反例已处置，剩余不确定性不会改变当前相交接口或已有处理分支；未来新反例可以重开。它不是穷尽世界知识的证明，也不能以任意网页数、关键词数或一个月限期作为充分性依据。需要运行才能判断的内容转入明确实验设计；在只设计任务中不据此运行产品。

### 以源语言能力和全工程文件复核覆盖

针对“已有语言支持的能力”，审查同时取得关键词/符号入口和完整语义：声明、类型、运行、初始化、错误、资源、模块与工具链。选定语言的规范是索引，不只是抄一份词表；没有相应控制或转换的能力明确列缺项，不以图灵完备抹去。最强反例应包含同名不同义、异名可等价、运行反射阻止改写、初始化依赖和隐藏元数据。

相交实现按[能力映射](../../20-语义与组合/作者语义/README.md)分别验证默认自动选择、显式硬控制、可覆盖偏好与重置。普通新库不要求核心增关键词；普通新函数不被迫做“大功能意图”。保持语义、按指定形态生成和精确往返是不同目标，不能只验证其中一个。

全工程审查还要选一项不是代码的必需内容：资源、配置、构建脚本、数据或外部引用。检查它从读取、修改、生成、打包到退出是否保持字节、解释、权限和关联。未知格式能否保全；已解析格式是否有正确写回；闭包是否漏掉副产物或真实成员；删除是否抹掉已有责任。完整要求在[资产规范](../../10-作者与输入/作者源/工程源/资产与非源码.md)，不为每种文件再建设一套产品。

### 从本次发现到持续存在的已知问题

发现的每项独立结果必须有可追踪的责任落点，而不只是报告尾注。先核对所涉规范 owner：已有机制补入新的适用条件、反例和受影响消费者；确需新机制则在最小合格 owner 建立准确合同；仍无完整方案则保留反例、当前允许路径和待决差别。采用后的实现与现场证据缺口另接[实施闭包](../../90-治理与参考/状态/实施闭包.md)。优先级只决定当前安排，不删除低频但独立的反证。

完成一次设计变化后反查：原问题是否只改名；接受要求有没有被悄悄削弱；当前不处理是否误写为不适用；新方案是否给合法输入留下完成路径；同一源能否连续修改；别的领域是否被强加当前例子的前置。证据与结构检查都分别标范围。

问题数量只说明已记录的粒度，不能证明开放现实绝对穷尽。新增资料、目标、用户要求和实际反例继续回到对应上游设计；不因前沿已有条目就停止研究，也不把全宇宙未知都变成当前任务阻塞。
