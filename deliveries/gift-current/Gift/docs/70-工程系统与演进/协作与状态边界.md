# 跨主体协作与状态交接

<a id="统一架构与责任边界"></a>

这里唯一维护的是 **跨 owner 的交接正确性**，不是一个新服务、总状态表或第二次定义。成品实装由[实际模块及对象作用域](实现与装配/模块与运行实例-成品装配-实际对象作用域与入口闭合.md)拥有；一次请求的准备、补取、纯计算与返回由[开发任务主链](../80-开发者与接口/需求到交付主链.md)拥有；物理动作与结算由[执行/持久化](../50-执行运行与观测/README.md)拥有。下文仅讨论**分别有效的协议组合在一起何时仍有效**。

## 可组合性的输入：六个不同问题

一个联合结果需要回答以下问题，但不要求创建六种新持久化对象：

| 问题 | 有权判断的对象/角色 | 不能用来代签的材料 | 相交准入 |
|---|---|---|---|
| 这是谁提出的目标，允许 Gift 自主决定哪些细节？ | Accepted source、Requirement、委派和当前任务 scope | AI解释文本、被检索出来的规范 | 目标含义与作者权分别固定 |
| 这次实际读了哪些版本、环境和成员？ | AuthorSource/ProjectView、EngineImage、配置选择、来源前像 | `latest`、时间戳相同、单个内容哈希 | 独立依赖闭合且组合一致性可证明 |
| 哪些实现可合法满足相关义务？ | Realization 候选、Eligibility、Decision、Binding | 已安装/曾成功的 Provider、执行权限 | 每项硬条件与联合依赖满足 |
| 产生了什么目标成员，并对应哪项作者要求？ | Compiler、ArtifactSet、Target/ABI | 函数名、纯诊断、任一分支构建成功 | 必需根与公开消费入口闭合 |
| 对真实世界进行了哪些动作，有没有完成？ | Operation/Attempt、Grant、Provider 回执与读回 | ActionPlan、纯查询结果、操作超时 | 实际授权、前像、幂等域与恢复义务闭合 |
| 对哪些精确命题有何证据？ | Claim、Evidence、Verdict、Coverage | 自报成功、ZIP链接检查、时间相近的测试 | 对象/版本/环境/观察域相交且证据方法有资格 |

关系的详尽种类、身份、选择与修订约束见[关系与配置基线](信息与生命周期/对象关系与配置基线.md)；本篇不可新增 `UniversalTask`、全局 `success:Boolean`、无类型 `links[]` 或“全工程单一时钟”。

## 接缝合同：从生产者退出到消费者接纳

跨边不是把值传过去就完成。每次真正跨越权力或证据边界，消费者必须能够获得或重新验证：

1. **谁**：有来源的产生者/所有者、准确引用及其语义版本，而非显示名或绝对路径。
2. **基于什么**：读取的 basis、依赖封闭范围、环境/时间切面、是否联合一致、未知与不可见成员。
3. **承诺什么**：正常结果、合法变化范围、保持的外部状态、失败和进展义务；条件能力不得升格为全域能力。
4. **允许什么**：此时此用途的授权、资源配额、资格与否决规则；先前的绑定不授予后来的运行权限。
5. **实际发生什么**：纯值、候选、已经持久采纳的源、待执行计划、物理尝试或观察，分别记载，不能统一成 `done`。
6. **如何离开**：消费者拒绝、取消、时间戳/租约失效、重取、补偿、恢复及历史保留的责任；不可逆外部效果不会随 UI 关闭消失。

缺任一必需条件时，消费者保留准确受阻根与未决变量，不降低原要求，不把根外的无关工作一并阻塞。相交引用必须保持方向：`requires` 不是 `authorizes`，`realizes` 不是 `observes`，`generatedFrom` 不是 `verifiedBy`，`canceled` 不是 `reversed`。

**接管交接。（消费条件）：** 工作交接或会话恢复传递的是候选与未结算义务，不是旧会话长期有效的物理写凭证。 合同归属：[恢复后的权威代际、围栏与复写拒绝](../50-执行运行与观测/持久化与恢复/持久状态与存储协议.md#gift-fenced-writers)。

**跨owner错误。（消费条件）：** source诊断、resolver缺项、execution未知和assurance未证需要不同恢复处理，不允许由一个统一success字段互相代签。 合同归属：[失败返回的阶段、可继续性与非对称状态](../20-语义与组合/共同语义/规范元模型与结果语义.md#gift-failure-state-no-bool)。

### 联合 basis 不是若干局部最新值拼接

一个请求可能读源码版本 A7、目录元数据 M3、远程 Provider 描述 P5、权限策略 S9、目标画像 T2。是否可以联合使用这些读值，取决于它们共同约束有没有被固定、来源是否允许该一致性与相交有效性检验。每个局部 Provider 都声称读到了自己的 `current`，不构成跨源原子快照。若要求跨源同一因果视图，必须由真实协调/因果标记/版本向量/阻断条件取得；没有这种能力时，结果只声称各局部读取与它们的已知偏序，不虚构统一线性化时刻。

补取缺失输入时形成新的 `PreparedJob` 代际。旧任务已取得的结果可以在其依赖和权限仍合格时重用，但旧 `ActionPlan` 不能在新 basis 下原地更换操作对象，更不能隐式把旧授权提升为新授权。实际请求模型见[任务与结果](../80-开发者与接口/需求到交付主链.md#应用请求补取与实际修改的交接)。

### 多提供者原子性必须限制到真实边界

对独立目标成员，允许 `rootA: committed` 与 `rootB: blocked` 并存；应用可以返回分项成功加完整工程交付未闭合的状态，无需抹去 A 的真实提交记录。若对外承诺 A/B 原子共同生效，必须证明共同提交能力或使用已定义的协调/可观察切换协议。两个 Provider 分别写入成功既不是瞬时共同可见，也不是其他观察者看到同一版本的证据。

提交后通知丢失、进程死亡或远端超时时，先依据同一 Operation/Attempt 的幂等键、前像/围栏和 Provider 支持的查询能力查回。无法取得终局事实时保持 `unknown effect` 和安全后续责任；直接用新 Operation 再做一次会破坏不可重复动作。具体存储与读回协议在[事务恢复](../50-执行运行与观测/持久化与恢复/README.md)定义。

### 候选选择、制品封存和权限生效不是一个时点

实现选择基于有限候选闭包、硬资格、作者锁/策略、target 和真实依赖；候选变更应检查相交需求与依赖，不允许后端悄悄重新选择。编译产出只承诺目标成员满足已声明的产生前提；它不推出运行环境已具备权限、设备、数据或服务承诺。真实执行应在动作前再次获得当时有效的 Grant、资源与对象前像。权限撤销之后，已计算但未提交的缓存结果可以保留为不具使用资格的值，而不能拿旧资格操作；已对外泄露的数据即使撤权也不能由普通回滚收回。

## 主体切换与变化的可观察模型

**修改作者源**与**生成目标源码**、**发布制品**、**让旧运行退役**是四种不同的完成事件。相应 actor 只能通过本域已有提交协议推进自己的状态，跨 actor 的应用层结果是可重建投影。具体作者编辑/并发在[作者保存](../10-作者与输入/作者源/工程源/作者编辑保存与迁出.md)；目标成员在[生成与布局](../40-目标与制品/目标/README.md)；热更新、部署、订阅与旧运行在[运行生命周期](../50-执行运行与观测/运行生命周期/README.md)。

由此，一个变更可以有以下真实并存状态：设计满足但实现未提交；源码已修改但目标重新生成尚未完成；ArtifactSet 已完整但部署无权限；新服务已部署但旧实例仍在排空；外部效果已发生而请求响应尚未送达；请求结果已返回但所附 Evidence 已过期。任何一个状态的 `current` 只在它自己的命名域和选择上下文里有效，不能传播为所有人的 current。

### 完整请求与结果组合

请求的合法完成取决于**它实际索取的根**。例如 `design` 可以在不触发 build/run/deploy 时完成；`generate source` 可以在产生足够完整且无必需 importer 缺口时完成；`apply workspace edit` 要以已取得的提交/读回判定；`deploy and verify` 不得把构建通过当成部署及效果验证。产品运行与获益是否达成又必须绑定独立 Claim 和实际监测，不能倒灌改变请求最初的范围。

设本次响应请求了 `{design,source,apply}` 三根：design 与 source 合格、apply 已尝试但结算未知时，正确结果包含前两个根的实质交付和 apply 的未决作用；整体交付不能伪装全部成功或全部失败。对取消，也分别返回纯计算停止、未提交计划撤销、已在途但取消结果未知的物理动作，而不是一个跨域 canceled 标签。

## 一次跨修订反例：两个根、一个旧回调和不确定执行

初始：作者工程 revision `R10` 中，Root A 生成库接口，Root B 构建依赖它的应用；Workspace 已冻结文件集合 `W10`，Provider P 有 `p1` 与旧的 `p0` 连接。请求 Q1 选择候选实现 C1，产生 ArtifactSet `A10`。随后用户外部修改依赖锁和 A 的公开 API，工程变成 `R11`，Q1 的远程 build 回执丢失，旧客户端从 Q1 请求期缓存里取回旧编辑计划。

* 输入层：读取 `R10`、实际观察 `R11` 都必须作为有来源的事实并存，不把前者改成“错误来源”。不能把只依据 `R10` 的 Q1 写计划直接应用到 `R11`；按作者权和重基政策重新判断实际受影响的行、依赖锁及公开接口。
* 实现层：C1 在 `R10` 上的资格不能自动继承到 `R11`；若 B 依赖的 ABI 变了，重新计算联合选择及相交 Target，而非仅在 B 后端更换实现。完全不受影响的第三根仍可复用结果。
* 制品层：`A10` 不因 `R11` 出现而变成无效历史；它仍可用来复验 R10。但当次的 `A11` 必须明确包含相交重编成员和合法旧成员的组合，不得以文件同名冒充一个共同成员版本。
* 操作层：远端构建可能已运行。用 Q1 对应的 Operation/Attempt identity 查回；没有幂等/读回能力时不再执行同一不可重复外部操作，保存未知完成及后续责任。用户发起 Q2 属于新请求，不能用 Q1 旧回调覆盖 Q2 的客户端结果槽。
* 证据层：R10 下的静态证明可能仍对未变的局部语义成立；基于旧 ABI/Provider 的检查失效。未知完成既不是失败证据也不是成功证据；对发布给 R11 的声明必须绑定 R11 的联合成员和准确范围。

验收该场景至少拒绝：stale 写入覆盖新锁、选择路径双重改变、两个局部 root 拼装不兼容二进制、旧请求回调染新 UI、远端超时引发重复副作用、重算所有根造成不必要浪费、把旧测试的 PASS 当新环境的 PASS。这些反例分别由其[真正接缝验收 owner](../60-保证与证据/验收/接缝符合性.md)取得实施/实测资格。

## 失效和恢复由局部协议组合，不通过中央 status 修复

| 组合失效 | 允许保留的事实 | 禁止的捷径 | 谁继续处理 |
|---|---|---|---|
| 同一对象两个有权作者并行更改，联合约束冲突 | 各候选、基线与可交换变更 | 因物理写入不同路径便宣称互不冲突 | 作者保存协议、语义约束与合并裁决 |
| 远端 Provider 描述改变 | 原 binding 及旧任务使用的确切 descriptor | 用新 descriptor 解释已经执行的旧 attempt | 实现资格/执行准入与读取者 |
| ArtifactSet 缺必需成员 | 已闭合独立根 | 用空 stub、空测试或强制默认补齐 | 目标根贡献及完整装配 |
| Provider 响应丢失 | in-flight operation、已知尝试、最后可信观察 | 一律重试新 operation，或声称无作用 | 任务原操作/持久化/读回 |
| 证据来源撤销或发现共因错误 | 受影响 claim 的精确支持范围及独立剩余证据 | 一律清空全部事实或继续原样 PASS | Assurance 与相交消费者 |
| 撤权后的缓存与派生数据 | 缓存字节、来源 lineage、实际对外效果历史 | 缓存命中等同继续可使用；回滚等同追回泄露 | 数据/授权 owner 与保存/披露执行者 |
| 开放候选发现到预算终止 | 已找到合格者、已检查域和 frontier | 未找到即不可实现，局部最好即全局最优 | 搜索及作者政策；所需未闭合部分继续 |

这里没有“全系统已统一，因此以后只剩实现”的推论。联合约束真正涉及的接口或合理路径仍未定义时，明确写回对应 canonical owner；已定设计缺代码、集成、目标支持或现实证据时归[实施闭包](../90-治理与参考/状态/实施闭包.md)。不能创建第二套总账来替代这两条责任。
