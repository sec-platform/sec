# 11 让工程不仅能生成，还能受信地构建、检查、发布和恢复

## 1. 证据方法和真实支持范围必须分层

仅有 JSON Schema/类型检查/源码打印/目标编译/有限运行测试/形式证明中的一项，不能单独签发整个 Gift 的正确性。每个Claim必须绑定准确：对象与版本、输入域、环境/平台、观察集合、证据产生者、方法有效前提、失败与撤销条件。性能主张还需要可复现实测负载、并发度、设备/工具链版本及同场景比较基线，不能由代码看起来高效直接给出最优结论。

实现中的 `assurance::derive_obligations`从准确Requirement、实际选择、目标、Effect和资源派生待证条件；`assurance::assess`消费独立检查结果并返回所支持的Claim范围。真实检查器/求解器/TypeScript/rustc/Provider的执行由 Control 在对应授权与隔离下调度，不能让同一个方法生成器自己声称自己已被独立证明。

## 2. 独立 oracle 的具体组织

`conformance/`至少按 `reader/semantics/method/target/runtime/recovery/security/bootstrap` 分离输入与期望；每一个测试向量冻结版本、源码摘要、目标环境、输入与预期的可观察结果/错误或特定Need。**正向**验证合法构造可以完成；**负向**验证类型、权限、未绑定Meaning、未支持target、未获授权、未知结果和超预算不能被错误升级为成功。某模拟器的完整枚举可以证明该模拟输入域的性质，但不能因此签完整业务域。

建议三种相互区分的oracle：

- 源层独立解释器/经验证的小规模枚举：能比较标量函数在给定范围的值、错误和求值次序；不能验证任何现实Provider已真正执行。
- 原生工具链：目标TypeScript/Rust在固定虚拟/本地已授权输入上 typecheck/build/run，验证目标语言规则和部分实际行为；不能证明作者全体Requirement或安全保障。
- 外部观察与故障注入：本机文件、SQLite、网络/设备测试桩和有权生产适配器各自验证事务、恢复、迟到、撤销与readback；测试桩不代签真正服务。

当编译器与独立oracle由同一方法/规则生成时，不能在凭证里声称完全独立。有限测试无法证明无界输入恒成立；形式证明只有在精确模型、公理和受信核验器范围内支持强结论。

## 3. 威胁边界与最小权限的具体输入

攻击面按输入字节、源文件路径、JSON解析/原型对象、解释模块/原生依赖、Target构建脚本、Worker帧、FFI及Provider凭证、索引/缓存、用户通知与诊断分别建模。`SourceScope`控制哪些字节可读，`WriteGrant`控制哪些作者/目标区域可改，`ExecutionGrant`控制真实Effect，发行签名另归发行Authority；知道某文件SHA或方法URI不构成任何一种授权。

第三方语义模块默认作为数据/有资源预算的隔离计算加载，不能因为实现语言是Rust/TS或模块自报 `trusted` 就执行任意本地脚本。Toolchain、依赖、构建脚本的信任和权限分别审查：读一个npm包元信息不等于有权运行其安装脚本；读取模型结果不允许自动读取当前用户全部文件。固定依赖内容和lock后才允许复算构建；即使内容有签名，也只是来源/字节真实性的一部分，不等于无恶意或合语义。

## 4. build/release 的实际数据闭包

发行方案须产生：目标源码与依赖成员摘要、SourceSnapshot/MethodBinding/TargetProfile/toolchain准确选择、编译器及生成器版本、真实检查命令与退出/诊断、第三方许可来源、构建环境差异、受保护的签发权及恢复入口。构建流程可以在本地单次完成，不强制CI当调试循环；CI/独立runner只针对真正需要的可信发行与非回归义务执行。宿主采用本地runner时不能以省事自动转为云runner/Docker。

具体构建图：规范化的schema输入→双端生成绑定及结构向量→kernel/build→control/build→目标可选平台工具→独立check→合格ArtifactSet→只读签发准备→具权发布。任一环发生错误则相交产物不签发布成功，未受影响的独立root仍可保持自己的完成状态。所有产物目录默认与作者源分离，只有明确apply才向工作区写；后端不能在优化时隐式安装插件或更新project lock。

## 5. 故障、升级与污染后的真正恢复

输入/工具链升级不只是跑一次普通单测：需核机器协议读者/写者兼容、历史作者源可读/不能误写、旧方法曾签的Evidence是否仍适用、目标ABI、恢复器是否能读取旧DB、旧进程和新进程是否会共同争写head。结构扩展必须有明确协商，旧封闭消费者遇未知字段拒绝而不丢原字节。

若发现构建或Method供应被污染，先冻结受影响 artifact/Method/Claim 的后续发布，沿实际依赖图追溯已发产物与证据，使用可信来源和隔离构建重建，再根据不同版本与使用范围撤回或迁移；不只删缓存或重新跑同一个受污染生成器而宣布恢复。权限撤销传播到查询/diagnostics缓存的披露视图，已发生世界效果仍需要如实结算。

## 6. 实施者必须具备的验收证据

- 严格json重复键、超预算、非法schema拒绝且原字节可追溯。
- 两个不同模型解释修订产生不同语义身份或正确失效，而不是靠同名复用旧结果。
- TypeScript/rustc真实编译失败被定位到准确作者版本，不能被SourceMap指到错的文件。
- 生产设备/网络不可用时编译设计与真实效果的资格分开，返回准确Need。
- 长构建受资源上界/取消控制，异常退出保留未发布旧成果。
- 目标真正构建/行为观察的独立oracle与待测发射器不是同一个函数。
- 依赖包/许可证/签发的来源与撤销被追踪到准确版本，未授权发布不发生。
- 改变当前Method/Target/Grant后依赖的旧证据不再自动成为当前PASS。

## 证据记录、构建准入、撤销传播及测量程序

内部`EvidenceRecord`固定为`subjectRef/revision, claimRef/revision, inputDomain, assumptions, producerRef/revision, observerRef, environmentRef, artifactDigests, observation, limitations, validityDependencies`。观察的实际执行记录与对其解释的Verdict分开保存；Verdict引用准确记录和判定规则，不可原地把failed观察改pass。时间只有带来源/时钟域才用于有效性判断，不能把事件排序号当真实经过时长。

`assess`逐Claim执行：核主体/版本与观察域匹配；核产生者与方法真实来源、输入和环境；核假设有没有尚未解决或被撤销；根据该Claim的证据规则得Supported/Refuted/Unknown及其适用域。不同来源不是自动独立，同源码生成的两个oracle可能共享错误；独立性记录描述共享的生成器、规则、数据和工具，不只有一个布尔。若证据依赖图成环且无获准的循环证明规则，整体仍Unknown。

`BuildAdapter.prepare(ArtifactSet,ToolchainBinding,policy)`先算准确输入闭包及允许环境，生成argv数组、cwd和文件读写范围；受权execution启动进程，持续排空stdout/stderr、记录退出状态和截断，取消先停止接纳后请求终止，再确认进程组/Job实际结束与资源占用。build script和依赖加载可能执行代码，即使名为typecheck也必须采用真实隔离与权限。工具输出只可写入本次owned staging，构建产物不回写作者源。运行后的输出摘要与源映射使用实际最终字节。

发行准备是只读计算：固定源、工具、依赖、生成器、构建产物、证据与许可证来源的摘要，形成ReleaseCandidate。实际签名器只在当前发行授权和独立准入成立时签所选不可变材料；生成器不能修改自己的准入规则或取私钥。发布失败保留候选与旧可回退release，不把上传了一半的文件标成current。不同发布平台逐项确认，平台A的回执不能替平台B。

撤销从受影响来源、方法、工具或证据规则开始，沿精确依赖图标明“禁止新采用”“已有声明不再支持”“历史观察仍属实”“须恢复的已发生效果”四种不同结果。删除缓存只处理可重建投影，不能删除历史操作以假装风险消失。发现供应污染时用独立可信工具重建验证；重跑同一个污染工具不增加独立性。

性能验收计划在测量前固定工作负载族、规模、环境、冷/热定义、样本方式、统计方法和判定界限，记录所有失败样本。一个旧文档查询门禁偶发超限不能被新主机一次通过抹去，也不能由一次失败推整个产品确定缓慢。边界判断需同环境复现/分离噪声；没有足够数据保持该项未证实。本设计不编造毫秒目标、吞吐、硬实时界或“全局最佳”评分。

生产资格的来源为真实Reader、Target、运行和Provider；设计包校验只能证明这批设计文件、示例和局部模型的可检查属性。只读模型演练的记录必须标为MODEL_CHECK而不是PRODUCT_RUN；DDL在内存SQLite可执行只证明SQL形态与相应数据库约束，不证明适配器实现、更不证明掉电耐久。
