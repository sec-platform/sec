# 16 语义生成基底、编译器与实现供应：从零实现的最小充分设计

## 开发者抽象完备的可施工验收及最小反例集

开发面完备性要由原Owner分别签发，而不是以一张“关键字/家族数量已齐”总表签发。对每个公开支持的`SourceProfile × SemanticProfile × TargetProfile`组合，实施者至少取得以下证据：

1. **Source**：文本/JSON/原生源码能严格读取，导入、身份、公开导出与产品根闭包正确；未知kind、重复JSON键、非法字面量、未锁定Profile给出准确错误或Needs。
2. **Computation**：如果声称基础语言计算普适，提供形式化机器模拟的构造/保持证明或等价严格可查结果；如果只靠TS/Rust退路，标记是宿主实现覆盖而不是Gift内核普适。
3. **Domain**：任意新增领域Definition必须经版本化Typed Decoder、意义解释、观察边界、错误及效果合同；缺消费者时只允许未决草稿，不赋予业务资格。
4. **Intent/Composition**：对六模态、八Term、五种基数、时间/规范、四态证据及其真实交点检查已选择根的全部硬约束；全局共享资源不能只通过逐文件、逐目标或两两检查。
5. **Realization**：真实Method供应具有实施体及前置/后置/异常/帧/资源/进展/环境资格；区分`NO_SUPPLY`、`UNSAT`、`SEARCH_INCOMPLETE`、`NEEDS_MEANING`、`UNSUPPORTED_TARGET`；这些区分并非本条新建的公开枚举。
6. **Target**：每个选中根实际完成所有必要操作Lowering、依赖与构建闭包、ABI/运行依赖/作者归属，并由真实工具链和独立行为验证检查；不许以Stub、空复合、目录形状取得完成资格。
7. **Evolution**：增加新类型、删除产品根、改Method版本、更新外部政策及二次编辑时检查正负依赖和来源失效；至少做一次完整重编译与增量重编译的相同范围结果对比。
8. **Runtime/Assurance**：发生真实外部操作时检查独立Grant、OperationId、超时UNKNOWN、持久恢复/读回；仅纯源码任务不强制触发执行。证据明确范围/环境/主体/修订，文档工具和结构Schema通过不等于产品通过。

**必要反例**：同名谓词指向不同领域意义；未知Meaning仅有JSON结构；三个资源需求两两可行但全局超额；Goal禁止调用网络而外部Method依赖网络；外部操作超时后是否已结算未知；两段源码行为相同但作者归属不同；空Composite没有覆盖任何硬要求；目标AST仍有未降低操作；用户要求永久正确却没有可用观察者；新领域专业概念需要新增类型化扩展但仅由字符串表示。针对这些情况，检查器必须保留精确区分与拒绝/未决后继。

**工程关闭条件**：最小稳定抽象不按数量验收，而按“定义合法、意义可解释、组合可检查、可以由作者实现或被资格化供应实现、Target实际可完成、缺口明确拒绝”的链路验收。公开承诺限于实际完成的Profile组合。有限的构造性计算表达能力与无限的开放用户定义可以共存；不得把它外推为对所有未来行业、任意可观察目标和任意环境的自动合成保证。

## 本章只负责区分三种“完整”

1. **可表达性**：固定的核心构造、类型和组合规则，允许用户定义没有列在任何行业清单中的新函数、类型、算法、状态与合同；对通用计算构造，其含义以已绑定 `gift.semantic` 版本解释，不能通过业务名字补规则。普通新函数不要求修改 Kernel。
2. **实现供给**：用户只声明目标时，必须有具有真实实现体的已有方法、可保持的组合或限定合成的产物；不能从一个谓词名、函数签名、目录记录或声明 `verified` 推导出算法。一般的意图满足性/程序等价/终止/合成不存在同时完备、总能返回正确答案的通用判定程序。完整语言必须允许由作者/工具在受权范围内写出实现体作为退路。
3. **生产质量和现实行为**：即使生成源码确定、`tsc`/`rustc` 构建通过，公开合约、资源、异常、权限、世界读回与环境性能仍需要独立资格；不能从同型、相同文本或模板名称推出保持证明。

本章不另造公共 `Type/Requirement/Method` 的权威编码。语言形式意义分别位于基础语义、作者需求、方法与目标 owner；这里界定首批工程师具体应该实现的编译组件和资格边界，及 Gift111 的实际运行样本。

## 有限生成基底不是“所有语义标签全集”

实现者需要有限**基础操作的精确定义**：名称与作用域、变量/绑定、值与代数类型、名义身份、函数/调用与递归、条件与匹配、有限不可变集合、错误/正常结果、行为合同，及有类型的效果与资源边界。这些构造的组合产生不限数量的普通计算与业务程序。新业务概念可以是用户定义的类型、函数、规则、关系或库，不进入内核行业 `switch`。

`Int` 数学整数、`Bool` 的严格布尔、`List` 的顺序/重数、函数的求值和调用顺序、名义类型的身份是基础语义；`Money` 的法域、一个特定协议的保证、数据库事务的可见性、设备命令的真实作用均不是仅凭通用计算解释就自动获得的事实。通用计算可以计算这些领域模型，但模型与现实系统的合法性、适配、授权、可观察资格仍须新增明确合同或供应。

因此，“所有语义”分为：

- 已解释的有限基础构造及构造规则，**必须闭合**；
- 由这些构造表达的无界用户定义，**不应穷举**；
- 需要新的外部原语/观察权力的开放扩展，**通过固定 ABI、意义、Effect/Method/Target/Provider 准入**；
- 只声明可观察要求而省略算法的意图，**通过方法选择/合成与真实作者实现补给**，缺实现时保留 `NeedsImplementation`。

## 编译原理真正用在什么地方

| 可落地职责 | 核心理论及算法 | 需要程度 | Gift 工程实现位置与边界 |
|---|---|---|---|
| JSON 解码、作者定位与编辑 | 编码/树、增量编辑和源位置 | 必需；不需自研全新词法分析器 | READ0—READ6；严格重复键/字面量规则，缺 ByteSpan 不能签精确回源 |
| 模块身份、导入、词法绑定 | 符号表、作用域、SCC | 必需 | 先收集声明，再解析引用，允许合法函数互递归，拒绝非法初始化循环 |
| 通用计算的类型与效果 | 类型代数、双向类型检查、一阶统一、刚性泛型/实例化、occurs-check、区域与效果 | 必需；高级画像按需启用 | 精确诊断 + 不默许 Any；多次恢复/线性资源等确需扩展时不得伪装纯 |
| 规格与程序的连接 | Hoare-style pre/post、观察、帧、进展与合同细化 | 必需；声明与实现分离 | 类型正确不意味着实现符合要求；强保证需要独立证明或受控运行检查 |
| 意图实现选择 | 候选搜索、约束传播、能力前提、逻辑/SMT/合成（局部可判定域） | 必需有拒绝/人工实现路径；完备任意合成不可能 | 先硬资格再排序；无候选、未决、已证不可能是不同结果 |
| 中间意义与目标合法化 | 类型化表达式/操作、降低保持、合法性与反例 | 必需；不强制八份 IR | 留下未降低操作时不准发行完整目标；不能仅打印 AST 原样 |
| TS/Rust 目标生成 | 目标 AST、模块/ABI、构建闭包、原生工具链 | 必需 | 本编译器负责源级生成；原生 TS/Rust 编译器继续做更底层的优化和机器码生成 |
| 可维护源码/SourceMap | 原始发生位置、变换轨迹、目标成员归属 | 必需产品能力 | 不允许导出后失去所有权，也不能从同名/同路径推权限 |
| 大规模增量与自举 | 查询缓存、ReadSet/负依赖、版本、固定点、种子/复现 | 规模和自举前置范围必需 | 无需普通小工程强制启用分布式构建/全库证明；自举必须绑定真实源码消费者 |
| SSA、LLVM/JIT、寄存器分配、GC、任意最优合成 | 后端优化、运行时和不可判定问题 | **不是首个可工作的 Gift 作者→TS/Rust 的必需前提** | 能交由 `tsc`/`rustc`/LLVM/宿主处理的底层机制不重复开发；确需跨目标时再引入 |

“确定性”分别约束：相同冻结作者源的解释，方法目录/环境固定后的选择，完整源代码字节生成，及在明确条件下可复现的构建。**不意味着**存在唯一的合法算法、所有方法都正确、运行时不受并发/时钟/随机/外部世界影响，也不意味着相同算法是性能最优。

## 已落实的真实计算子集及调用接口

源路径：`fixtures/semantic-universe/Gift111/giftcore`，它是 **Python 离线参考消费者**，不是 GitHub 线上 Rust 编译器，也不是仅校验 JSON Schema 的旧 fixture。

```text
Program(paths, bindings)
  -> strict_load + module/import/export/definition index
  -> Program.check()                 # binding/type/contract/pattern checks
  -> emit_typescript(program, out)   # locked source modules → TS files + manifest
  -> tsc --strict / Node             # separate actual Target compile/run

Evaluator(program).call(moduleId, definitionId, *arguments)
  -> independent finite-fuel Python semantics oracle
```

本子集覆盖原始 Gift107、Gift110 六个模块与两个新增的未知领域模块。其 Method 绑定文件使用 `gift.reference-method-bindings/1` **仅为本参考消费者的显式输入**，不是将该临时输入提案升级为新的 Gift 产品持久协议。运行时会检查普通前置/后置，但同型方法不等于被证明满足无限输入/进展。输入纯数据且分支有限时可直接核算输出；未知现实效果严格拒绝，不能先执行后补 Grant。

对抗样本的含义：正常 `spanWhile([1,2,0,3], isPositive)` 产生前缀 `[1,2]`、余部 `[0,3]`、只调用前三项谓词；错误 Int 词法 `1e0`、未知引用、遗漏 ADT 分支、不受支持的 effect、缺实现/不合法方法、重复 JSON 键必须拒绝。`Signal` 是输入包中原先没有的类型；它能被同一编译内核解释而不用注册行业名字。这**只**支持当前已实现构造上的开放定义，不构成对所有领域的完全覆盖证明。

## 未完成的通用能力仍归原责任位置

本次实际不能声称完成：完整匿名/名义类型代数（Option/Result 等的构造与消解、参数化ADT、嵌套穷尽模式）、资源与效果系统、局部状态和任务、CST/回源字节及增量、联合 Constraint/Method 求解、强保证证明、跨平台 ABI、外部 Effect/Provider、完整 Rust/TS 双目标、性能调优，及 C0—C3 自举。运行示例使用 `List.slice`，部分递归算法有二次复制和原生调用栈问题；只有补齐合格目标实现或资源证明才可宣传性能优势。具体实测状态、负例和复现入口见 `fixtures/semantic-universe/Gift111/README.md` 和 `CAPABILITIES.json`。

不能把“已有文档描述”当成“运行实现”；相反也不能因部分高级功能没实现，就把基础通用计算已实现的这一纵切否认。下一次实施必须在原 `READ/COMP/Target/Runtime/Assurance` 责任处补消费者、资源边界和独立证据，而不是再列 100 个行业关键词。

## 机制依据（用于校准职责，不代替 Gift 实物）

- Rust Compiler Development Guide, [compiler overview](https://rustc-dev-guide.rust-lang.org/overview.html)：词法/语法、HIR/THIR/MIR、类型/借用、LLVM 后端的真实职责和区分。
- MLIR, [Dialect Conversion](https://mlir.llvm.org/docs/DialectConversion/)：完整合法化、部分转换与仅可转换分析是不同承诺；类型转换可能要求实际物化。
- Lean, [Elaboration and Compilation](https://lean-lang.org/doc/reference/latest/Elaboration-and-Compilation/)：前端便利性与可信类型核查分离；不能据此断言任意业务目标得到证明。

## 适用前提、限制与反例

以下按原版本保留相关定义、反例、判断和实测范围。版本名称仅表明形成来源；条款是否现行有效仍由本文件的当前合同、被引责任文件及实际消费者决定。

### Gift112 适用定位：为 Method 实现者提供语言工具

此章中词法、类型、递归、编译生成职责主要针对**已有实现无法满足时专业供应方创作新算法**。普通业务作者的默认路径现已改为[意图解释与合格供给](17-意图优先解释与现成方法装配.md)。不能将“通用计算核心图灵完备”推广为“一切业务意义已抽象”或“目标源码可由每个新谓词自动取得”。旧 Gift111 可运行参考子集保留，产品优先级已修订。
### 最小必需“编译原理”的准确对象

前端必须进行 JSON 解码、名称/身份绑定、类型/量纲、开放 Meaning 解释、Clause/作用域校验和源定位；核心优化是按可观察含义进行 Method 资格与联合约束求解；目标端需要声明式引擎适配、配置/胶水代码生成、构建和版本维护。**这已是编译/规划系统，不要求额外实现完整图灵完备计算语言。**若作者业务系统只需 SQL/规则/现成库，不应强迫其经 Gift111 函数表达式与 TypeScript AST。旧通用计算编译原理在被选专业方法和自举职责确有需求时保留；详见第18、21章。
