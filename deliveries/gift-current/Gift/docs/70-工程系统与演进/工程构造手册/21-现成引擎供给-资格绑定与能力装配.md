# 21 现成引擎供给：从准确意图到可替换 Method 的产品接口

> 本章给出生产实施接缝；Method 的公认合格性依然由[实现资格原责任](../../30-实现解析/实现选择/实现解析与候选资格.md)及[证据原责任](../../60-保证与证据/验收/意图覆盖与纵向符合性.md)拥有。这里列出的引擎不是 Gift 已安装、已授权或已测试的声称。

## 1. Method 供应不是“业务标题→模板”

意图层定义可接受行为，供给层回答**在什么条件下**哪个机制可以实现其中哪些义务。供应身份必须独立于人类可读名字。允许零、一或多项供应；没有则 `NeedsMethod`，无资格则 `NeedsQualification`，资源/权限/环境缺失分别保留，不退回默认最佳猜测。

建议的只读候选/受信资格接口：

```text
CapabilityOffer {
  offerId, revision, packageDigest, sourceAuthority,
  semantics: {inputMeaningRefs, outputClaims, applicabilityScope,
              assumptionRefs, preconditions, guarantees, frame, progress},
  execution: {implementationRef, engineKind, engineVersionRange,
              inputOutputABI, targetProfiles, resources, effectKinds,
              errorAndCancellation, stateLifetime, idempotencyScope},
  admission: {requiredGrants, environmentFacts, securitySandbox,
              qualificationRef, licensesAndDependencyFacts},
  selection: {hardConstraints, comparableCostModel?, preferences?},
  monitoring: {observableClaims, readbackMethod, retention, recovery}
}
```

`guarantees` 是需要资格证据支持的声明，不能由 `method.json` 自签正确。`implementationRef` 可以指向任意现成可用库，不要求总是代码生成。`applicabilityScope` 和 `frame` 限制方法可以读写哪些资源，以免虽然满足某个目标，却悄悄修改其它业务状态。要求真实外部 effect 的方法需通过有权宿主 Grant，不能把模型修改等同于执行。

## 2. 现成技术的功能分工与边界

| 业务语义用途 | 可采用的成熟机制 | Gift 需要实现的资格接合 | 不能由成熟工具代替的部分 |
|---|---|---|---|
| 决策表、规则依赖、确定性业务判断 | DMN 决策规则/FEEL、规则引擎 | typed input/object mapping、命中/冲突优先、缺值语义、version & source map | 外部事实是否真实、谁允许该决定、规则自身是否公正 |
| 政策允许/禁止、访问控制、条件策略 | OPA/Rego 或领域策略库 | principal/resource/action、三值/undefined 处理、可撤销 Policy 版本、宿主 Grant 联查 | Rego 决定不自动签发外部系统权限 |
| 关系读取、聚合、约束与事务更新 | SQL/成熟数据库引擎 | 集合/袋/NULL/隔离级别、快照、参数化、事务重试/冲突、准确写集 | 数据模型与法定主体意义、跨多个远程系统原子性 |
| 图与语义数据模式验证 | SHACL、schema/类型检查 | 语义图身份与 closed/open domain、shape version、验证报告的 Claim 范围 | SHACL 验证数据图不提供完成现实目标的执行器 |
| 长时段业务流程、审批、补偿、重试 | Temporal 等耐久工作流平台 | 事件/活动/定时器、历史重放、幂等操作、版本演进、取消、未知结果 | 业务批准事实、资金外部终局、无条件 exactly-once |
| 调度、匹配、选择/约束优化 | OR-Tools CP-SAT/MILP 等适用求解器 | 输入变量/约束/单位、最优性口径、结果证书与上界、超时退出 | 任意问题总能最优求解、模型与现实完全一致 |
| 状态机、UI 与交互组件 | 成熟组件库、状态库、Web/移动平台 API | 名义状态、交互事件、焦点/可访问性、Target 环境资格 | 仅有后端 JSON 就完成用户界面或体验 |
| 复杂自定义计算或缺供给的专用算法 | TS/Rust/其它原生库，必要时 Gift111 子集 | 参数/效果/ABI/前提/保证/测试/版本/安全读集 | 源码存在不证明其行为合格，通用计算不可替代领域意义 |

这张表是**优先查找成熟能力的路径**，不是固定 Runtime 依赖。普通纯函数/简单规则项目不应启动工作流、求解器、数据库或后台 Worker。目标不涉及某领域时，不加载该领域 Method 或外部凭证。

## 3. 接入成熟引擎时的核心编译算法

```text
resolve_offers(JointGraph goals, CatalogSnapshot offers, Context ctx):
  indexed := offers whose guaranteed observable claims/types overlap goals
  for each candidate, using its exact locked Meaning + method revision:
    reject lexical matches without witnessed semantic mapping
    resolve substitution of roles, object identities, units, clock and worldview
    collect extra premises: facts, grants, resource/time constraints, observers
    prove/check the method's claimed consequences within qualified scope
    check its frame and effects against *all* other accepted obligations
    check Target/package/runtime ABI and license/dependency admission
    record Needs for each undecidable/unsupported condition, do not guess
  solve joint hard conditions and resource budgets, compare qualified candidates
  return plan candidates with Evidence Needs + failure/repair instructions
```

**关键区别**：相同结果谓词可以被不同方法实现，而同名 API 可能产生完全不同的效果。方法选择必须基于可观察语义和明确的前提保证关系，而不是模板标题、代码名字或由 LLM 给出的相似度排序。语义引用来自精确 Definition，不意味着天然取得逻辑有效性证明：需要具体的 checker/受权声明和适用证据。

## 4. 具体 SQL 预留接口（施工级示例）

业务公共条件：已确认请求必须具有真实资源占用；同一时刻总 `reserved <= capacity`；重复请求不得再次增加占用。选用数据库方法时，接口必须包含精确的资源对象 ID、请求幂等键、事务隔离与持久结算状态。以下是**候选方法内部协议**，普通作者不填写：

```text
reserve(resourceId, requestId, expectedSnapshotRevision, grantContext):
  begin storage transaction in specified isolation
  verify authorization in trusted host, not from author JSON
  read exact request/reservation identity + resource capacity under safe isolation
  if prior operation id already settled: return the existing receipt
  if capacity full or request ineligible: settle a typed rejection (no reservation)
  atomically update occupancy and link request to reservation
  persist effect receipt and new state revision in same real DB boundary
  commit, then issue separately required notification as a new explicit effect
  on uncertain commit: query transaction/operation identity, NEVER issue new id
```

具体是 `UPDATE ... WHERE reserved < capacity RETURNING ...`、行锁、串行化事务还是单独容量账本，由真实 DB 版本/隔离级别及 Method 证据决定。此示例没有在 Gift113 参考消费者里执行，不能当已完成的事务代码。

## 5. 长流程与真实世界效果接合

- 工作流计划与具体业务事件属于不同身份；事件历史持久化和回放可让 Workflow 恢复，但不能消除不确定的外部效果，需要 activity idempotency/readback。没有真实工作流服务时用 `NeedsEnvironment`。
- 从确认/审批/资金的规范意义开始声明 `Obligation`，然后才绑定执行器。审批记录和实际裁决者应可追踪，`approved=true` 字段不得单独授予权限。
- 时间期限绑定真实时钟、公平性、依赖故障和用户声明的超时策略。`eventually` 不应在全体外部工作永远失败时被假证。
- 协议/SDK 后端的任何回调都必须区分输入、响应、现实已发生、读回与未决；补偿是新的受授权操作。

## 6. 性能与成本选择

硬条件先满足，软偏好再比较：准确、权限、接口/数据丢失与资源安全优先于吞吐优化。成本比较必须说明单位、负载、环境、缓存和遗漏的外部成本。规划器有预算与非最优状态，不能保证通用情况下高质量最优实现；构建源码、调度计划和执行服务的性能应独立衡量。无真实数据时保留 `NeedsMeasurement`，不制造性能阈值。

## 7. 实施模块和测试接口

生产 Rust Kernel 只维护 `MeaningBinding`, `ObligationGraph`, `RealizationOffer`, `SelectionReport`, `ArtifactPlan`, `Needs`；具体 SQL/Policy/Workflow/Optimizer 内部模型由各 adapter 维护，版本与 SourceMap 明确，不把任意引擎 AST 作为所有业务必需的永续持久 IR。TypeScript 控制层提供工具、客户端和宿主 adapter，严格划分编译期与运行期权限。

最低真实纵切需至少接入两个**不同技术机制**（例如一个规则判定与一个真实数据库事务），不能只把同一个模拟 `setField` 换两个领域名字。验证须含合法输入、缺库/坏版本、错单位、缺证据、超卖、重复消息、并发冲突、回滚/未知、方法撤销和二次编辑。真实构建/效果/授权的通过记录是这里缺失的生产证据，文档及模拟不能代签。

## 8. 已核对的外部机制材料与适用限度

- OMG DMN 1.5（官方规范索引）: https://www.omg.org/spec/DMN/1.5/ 。提供业务决策建模/规则结构，不是完整业务执行标准。
- OMG BPMN 2.0.2: https://www.omg.org/spec/BPMN/2.0.2 。过程/事件等建模不能替代有权真实世界结果。
- W3C SHACL Recommendation: https://www.w3.org/TR/shacl/ 。验证 RDF 数据图与 shape 条件，不是规划器或现实 effect 引擎。
- OPA Rego 官方语义: https://www.openpolicyagent.org/docs/policy-language 。基于结构化数据提供声明式策略判断，不签发外部系统 Grant。
- Temporal Event History: https://docs.temporal.io/encyclopedia/event-history 。耐久历史和 replay 支持恢复，但外部 activity 的真实副作用仍需准确处理。
- Google OR-Tools CP-SAT 模型: https://github.com/google/or-tools/blob/stable/ortools/sat/cp_model.proto 。能表示并求解其支持的约束域，不是全语义自动实现器。

以上材料支持**优先复用专用成熟引擎的机制选择**；不支持“Gift 已接入这些引擎、同领域实现已合格或任意意图一定可自动实现”的事实声称。每个实际采用需核兼容版本、许可证、目标构建与独立效果资格。
