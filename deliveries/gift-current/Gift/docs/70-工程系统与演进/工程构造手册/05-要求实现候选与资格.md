# 05 从公开要求到有资格的实现：联立约束、Method、选择与证据

## 1. 本层只做哪些实现决策

作者的公开定义和强制要求已固定后，编译器才有权决定内部算法、库、布局与合格目标方法。已有库可以满足要求但不代表一切自动合成；找不到候选、搜索耗尽、证明不可行、合同矛盾、现实效果没有授权是不同结果。目标生成器不重新选择实现；Assurance不因Method自报支持而自动给强保证。

首期方法目录可存于 EngineImage 中的只读映射：`Capability/DefinitionId + qualified Contract + TargetProfile → candidates`；目录本身有准确revision和来源。较高规模可加入查询索引，但索引是派生缓存，不能维护第二份可写业务规则。所有方法从本地固定包/锁及当前获准供应取得，不允许静态compile遇到缺项就自动下载网络库。

## 2. 要求含义与输入实例化

`RequirementInstance`需要作用主体、合法输入域、必须出现的正常结果、可接受错误、行为/时序/轨迹、帧与效果边界、资源及进展假设、证据强度与作者来源。要求的九维描述由公共Definition继承，大多数作者不必填全；展开后的局部实例应有能回源的来源引用，而不是为每次编译写一份永久冗余需求库。

已有 `req:composite` 的 `use/require/prefer/all/any/when/forEach/exists`只定义其**有限结构**：`all`合取，`any`选择整个合法分支而不是抽取部分条件；`when`先判定条件语义；`forEach/exists`只在其已定义有限范围上展开。若用户需要无界量化，必须由提供无界谓词Meaning、明确逻辑域和求解/证明合同的模块承担，不能把有限编码的一个Term改成暗含无限集合。

实例化过程：

```text
bindRequirements(candidate, selectedRoots)
  → resolve visible Definition and subject identity
  → elaborate explicit/locked defaults with origin
  → instantiate finite scoped Terms without capturing unrelated variables
  → collect joint guards/frame/safety/liveness/effects
  → normalize only where equivalence or weakening direction is justified
  → identify shared state/resources between requirements
  → produce Obligations + actual positive/negative Reads
```

这一步不能无条件将任意可描述的非干扰、安全、时序或概率目标压缩成布尔表达式，因为跨执行序列与现实环境观察有独立模型。证明/约束引擎只可检查其明示支持的子域。错误或未知Meaning必须保留原精确子需求，不允许“跳过未知所以剩余通过”。

## 3. 方法候选选择算法（可直接实现）

```text
resolve(uses, requirements, target, requestedExit, requestedClaims, controls, catalog, budget):
  obligations := classify by actual consumer phase under requestedExit/requestedClaims
  work := finite roots needing realization
  while work not empty and budget permits:
    use := deterministic dequeue(work)
    options := exact locked catalog entries matching use + authorized search scope
    record read of catalog epoch AND negative observation of absent candidates
    for method in options:
      verify method identity/revision, actual provider and claimed implementation entry
      check type/generic substitution, result/errors, allowed input domain
      check effects/frame, progression assumptions, resource and ABI bounds
      check target representation and all obligations required now for this exit
      preserve later toolchain/environment/Grant/evidence obligations with actual consumer
      if not eligible for this exit: record exact rejection reason, do not add as soft candidate
      else compose required dependencies, adapters, closures; enqueue missing uses
    if eligible none: choose correct Need (Meaning/Method/Target/Evidence/Authority)
    else evaluate whole feasible combinations respecting shared resources
  on exhaustion: BudgetIncomplete with frontier, not UNSAT
  for complete eligible combinations: rank only supported comparable soft preferences
  return selected RealizationBinding with qualified exit/scope, remaining obligations,
         method/target/evidence/source locks and reads
```

资格按[请求出口分层](../../30-实现解析/实现选择/实现解析与候选资格.md#method-qualification-by-requested-exit)：准确源码生成可以留下运行前绑定Provider实例、环境或Grant的义务，但必须有真实实现、所需内部成员、明确运行接口与拒绝未准入动作的消费者；不能将缺Method或未知Provider行为伪装成普通配置。生成方法自身需要工具/Effect时，其当前授权和环境仍是生成前提。每项未决按[归因与恢复合同](../../40-目标与制品/编译内核/诊断与追踪.md#need-provenance-and-resumption)保留原来源、受影响根、阻断出口与恢复入口；缺运行Grant不撤销合格源码，要求现在运行的请求也不因源码已生成而完成。

不要让同一个 `kind` 字符串在几种能力之间碰运气；同一能力两个提供者时精确比较需要的版本、公开合同、业务可观察区别。Method只在其公开输入域与目标构造上有资格；在无负边图适用的Dijkstra方法不能悄悄用于任意负权输入。业务硬约束永远先于性能软优化；不能通过改用户要求提升候选可行性。

组合不是简单逐件`PASS`后得到整体`PASS`：并行两个有限资源方法可能争同一个容量；互相调用的方法可能产生重入锁死；两个局部稳定控制器耦合后不一定稳定。跨Method组合必须暴露交互资源、共享状态、时序和假设，做整体资格判断或保留Need。存在多个Pareto不可比实现且用户未给额外偏好时可以给可解释选择/选项，不虚构全局最优评分。

## 4. 四条实现供应路径和可见的失败后继

1. `SourceBody`：作者自己使用通用计算结构写算法，类型检查和目标降低直接消费；这不是文本模板透传。
2. `ExternalExport`：真实原生库与受检函数/会话签名，经适配器说明Effects、ABI、资源寿命和目标导入依赖；只是调用已有实现，不算自动发明新算法。
3. `GenerationMethod`：按已固定规则参数化生成新目标结构，重新检查类型/效果和目标合法性；方法可变换表达式但不能绕过其原要求。
4. `SynthesisOrSearch`：仅在受限、明示语言/预算/求解完备前提的空间内寻找新程序。Candidate还需要检查/构建/行为或证明证据；无法在一般开放世界承诺都能合成。

没有合法方法时可以保存仍正确的Definition和Requirement，返回 `NeedsImplementation`，并明确可行下一动作（提供实现主体、绑定库、收紧有权决定的公开域、启用有资格合成域）。不能要求用户“随便填个函数”掩盖产品无实现。若两个要求逻辑上已矛盾，须交付可定位的冲突或不完备证明，而不是“试过所有库都不行”这一不支持的结论。

## 5. 结果代数与业务意图控制

设计时按以下不同出口保存足以审查的证据：`ImplementationBound`携真实绑定、前提、使用点和受资格范围；`NeedsMeaning`指未解释语义/相应定义；`NeedsMethod`指没有实现供给；`NeedsTarget`指所选生成后端无法完整降低；`NeedsEvidence`指所请求强保证还不能支持；`NeedsAuthority`指现实运行缺Grant；`Stopped/BudgetIncomplete`指有限资源耗尽；`Contradiction`必须有在相应逻辑子域的合法不满足证据。最终 wire 标签沿现行 `Result` 语义，不在这份施工说明里发布另一套枚举。

用户到底控制什么：公开结果和错误、合法输入域、安全/隐私/进展硬义、可观测状态、被允许的Effect与预算硬界必须来自作者/有效定义及其真实授权。用户委派后算法、内部索引、调度、缓存及目标布局可以由合格Method选择；用户仍能接管任何明确允许的实现控制而不重写整个业务含义。

## 6. 验证与负例设计

- 无方法且合同有效：设计保存成功、输出根`NeedsMethod`，不能生成 stub。
- 有合法SourceBody，零已登记业务名称：可选择并编译。
- 同名不同provider版本：锁和export不同，不能误绑。
- 输入放宽为负权图：旧方法资格被撤销，独立根不应全部失效。
- 新方法加入目录：过去记录“没有候选”的缓存必须失效。
- 求解预算耗尽：保留候选前沿，不能签不可行或最优。
- 局部各合格但共享资源不合格：整个组合拒绝或附需要改变的可观察条件，不能分别签两个局部PASS当整体PASS。
- 合成方法产生非法效果或未声明输入：二次检查拒绝，不相信方法生成工具自己的`ok`。
- 真实网络效果未授权：纯设计/生成可存在，执行必须拒绝，不因Method绑定成功而执行。

上述判定的逻辑定义继续由 `docs/30-实现解析/实现选择/实现解析与候选资格.md`、`设计空间搜索与求解.md`及 `docs/20-语义与组合/组合/跨软件需求合同.md`拥有；本页负责给工程师完整算法和中间产物。

## 联合实现搜索的工作状态、合格性推导和可复算出口

每个待实现使用点的键为`(DefinitionRef, use occurrence, type substitution, semantic controls, relevant target)`；不能只以函数名缓存一种实现。对于要求同一公共实现的接口组，先合并其一致性约束；允许逐使用点专门化时分别绑定，结果必须仍满足公开可观察含义。

搜索状态为`ChoiceState{bindings,pendingUses,logicalConstraints,resourceSummary,assumptions,proofNeeds,costBounds,reads,derivation}`，每个分支不可变或使用可完整撤销的日志。pendingUses优先选择已锁必选项，其次选择候选最少但枚举已完成的项，平手用稳定身份排序。该启发式只改变搜索次序，不改变合法性。候选方法产生新使用点时保留来源父边；重复键去重，递归供应进入SCC义务，不以“正在选择同名方法”自动视为完成。

资格分三层：结构/类型适配、公开行为保持、目标与被请求证据。令作者合法域为A、方法适用域为M，至少证明`A⇒M`，而不是`M⇒A`；在A和方法正常后置成立时须推出作者正常后置；方法可能错误必须落入作者允许错误且保持帧。方法的效果集合不能超过作者允许域。进展、非干扰、数值/概率与资源分别以其合格模块处理，不能一概压成布尔可达性。普通SourceBody经类型/效果检查可按普通构建强度生成；只有作者/发布Claim要求的强证据未满足时才阻断对应强声明，不强加所有函数的形式证明。

搜索展开一个方法后，立即核共享资源和已知矛盾，再进入后继状态。得到所有使用点均绑定的状态后还要核联合义务，不能只把局部PASS相乘。资源边界涉及峰值重叠时需显式执行图与同时存活区间；串行可取阶段峰值，并行可能需相加，未给依赖次序不随意选择更小者。优先级、锁顺序和进展假设也参与组合。控制器等没有简单合成定理的域调用精确join checker，缺它返回JoinNeed而不是全局已合格。

分支剪枝只使用可证明的不可行性，或在已定义可比目标下对全部未完成候选有效的下界。没有下界就不按主观估计剪掉候选。结果包含`selectionState=feasible/optimal-under-declared-space/incomplete`与搜索空间标识。用户要求“任一可行”时，遇合格完整分支可结束；要求最优却仍有未展开分支时不能把可行最优候选冒称已证最优。已锁方法现在失效则返回NeedRebind并保留原作者决定，不能在纯编译里自动更新锁。

约束不满足报告保留推导及原始需求位置。不可满足核心只有实际提取并验证最小性才称“最小”；普通解释性冲突集合不冒称最小。某checker返回unknown，其假设不能成为另一checker已证真的输入；循环证据依赖必须作为未完成整体处理。

有界合成的具体接入为`SynthesisDomain{grammar,inputDomain,observations,equivalenceRules,enumerationOrder,budget,checker}`。枚举器按声明成本层生成有限语法树，类型过滤后送独立checker；反例加入约束用于后继枚举。测试反例只能剪已被证明错误的程序；没有反例不等于全域正确。语法界外保持开放算法源/外部实现供应，不宣称一个枚举器可合成任意新意图。搜索前沿持久化只含版本化树/约束/已遍历范围，不保存宿主指针；重开须重核输入与checker版本。

一次可复算的组合反例：两个使用点各有Fast(峰值8单位)与Lean(3单位)，并行硬上限10时Fast+Fast不合格，Fast+Lean也超界，Lean+Lean可行；若目标允许串行，Fast+Fast可能满足内存但进展/时延需重核。不能不问作者并发含义就自动串行化“修好内存”。单位是该模型的显式参数，不是产品默认数值。
