# 06 COMP0—COMP7 的真正实现：完整目标源码、依赖、映射与第二次修改

## 1. 只有一条编译值服务

`compileFrozen(FrozenCompileInput)` 是纯编译入口；不复制出另一个“需求编译器”“TS编译器”的可写语义流。当前阶段沿原有 **COMP0—COMP7**，不是八个用户表单，不表示必须八次进程RPC。控制层负责输入捕获、源码保存和实际工具动作；Rust kernel可以在同一线程内跑多个stage，按需使用worker。接受新的AuthorSourceProfile后仍进入同一语义、RES、Target和Artifact组合关系。

调用结构：

```text
compile_frozen(input)
  COMP0 := freeze_sources_and_imported_views(input.snapshot, input.engine)
  COMP1 := collect_headers(COMP0)
  COMP2 := bind_names_requirements(COMP1)
  COMP3 := type_effect_contract_check(COMP2)
  for root in input.roots:
     if COMP3 has blocking Need for this root: keep diagnosis, continue independent roots
     COMP4 := resolve_uses_via_existing_RES(root, COMP3, fixed catalogs)
     COMP5 := lower_all_constructs(COMP4, target, profile)
     COMP6 := recheck_expanded_semantics(COMP5, sourceContracts)
     COMP7 := layout_artifact_set(COMP6, target, sourceMap)
     if no mandatory leftover nodes or missing members: publish immutable RootResult
     else return precise Needs/Stoppage and never publish an incomplete runnable root
```

只检查有关的声明和根，公共模块不必每次全部复制。方法动态展开后若新增调用/对象，回相交类型/效果与RES检查，不让后端临时解释新的业务含义。每步产出实际 ReadSet 和按源/目标的诊断。失败的一个root不应使完全独立root丢失可检查的正确输出，但同一个函数内部半截目标代码不能报告为完整Artifact。

## 2. 内部 `CheckedProgramView` 与 `TargetProgramPlan`

`CheckedProgramView`应能提供：固定DefinitionId→签名、绑定的Expr/Stmt和来源、类型、效果、前/后置契约、已选UseBinding、类型构造、资源及成员依赖。`TargetProgramPlan`描述实际项目根、语言版本/平台、公开成员、模块导入、私有helper、初始化关系、资源/声明、目标源码及最终BuildInputs和EditCorrespondence。它们是**只读阶段产物**，不要求业务作者手写，也不依赖一个统一的物理大IR文件长期保存。

每个目标方法为`lowerChecked(op, ctx) -> LoweringResult`，返回`code/fragment + newUses + dependencies + assumptions + trace obligations + source correspondences`；不能只返回一段无源身份字符串。多文件布局后输出ArtifactSet时先完成全部路径与导入合法性/稳定导出检查，才由外层打印器生成最终字节并重新计算位置。

## 3. TypeScript 后端的逐构造落实

基础映射（不得凭JS方便性静默改变）：数学 `Int→bigint`、`Bool→boolean`、Unicode标量Text需合法编码/迭代适配、`Unit→undefined`（仅结果确实不可观察时可省）、不可变结构→目标表示带必要边界检查、Option/Result→稳定变体标签。算术用精确BigInt与已有错误映射；`+x`对数学Int是恒等，**不能生成JS的一元 `+x`**，因为JS一元加将操作数转Number。整数字面量负号应使用目标一元节点或合法打印，不能将它强塞成纯非负literal。

求值次序通用辅助：

```text
lowerValue(expr,region) -> { beforeStatements, valueExpr, type, flow }
lowerTail(expr,region)  -> { statements, exits }
sequenceValues(children):
   evaluate each child once, in source order
   if a later child's before would execute before an earlier deferred value:
       materialize earlier deferred values into temporaries first
   allow target argument-order rearrangement only after values are evaluated
```

`if`与`&&/||`的右侧前置语句必须放在实际激活分支，不能提早执行；`match` subject求值一次，再按已检查覆盖处理分支；`let`初始化发生在新绑定建立前；lambda的主体不能在创建lambda时执行；函数/业务错误/资源结束三条出口不能全部变成TS `throw Error`。每个实际调用先计算callee，再按源实参次序求值，最后按formal slot重排临时量并调用一次。优化时必须保留可能Fault、非终止、资源和已被声明的执行次序。

例如输入一个已检查的 `safeQuotient(x:Int):Int = if x==0 then 0 else 10/x`，在合格TS profile下其核心输出可以是：

```ts
export function safeQuotient(x: bigint): bigint {
  return x === 0n ? 0n : 10n / x;
}
```

这里是**设计预期源码形态**，不是本包实际编译结果。`x`带强前置/后置时必须按契约入口生成边界检查及正常出口检查；不能为了示例简单删除作者硬义。若作者传入`x=0`希望执行`0`分支，不能把右侧`10n/x`提前计算。源Text和TS目标offset用UTF8 bytes↔UTF16 code units转换；CRLF、非BMP字符与源版本同时保存，目标打印后重新生成准确映射。

首批目标可使用纯Rust有限Emitter，或在固定 Method 下调用版本锁定的 TypeScript factory/printer Provider；不强迫Kernel本身以TS实现，也不能把可选Provider当成已资格化。每条路线必须显式支持的AST构造表、优先级/结合性/括号规则、Identifier与字符串转义、导入、完整VFS和检查器版本。遇到不支持构造报告NeedTarget，不能生成`undefined`/`panic`占位。

## 4. Rust Target 的独立工程设计

Rust作为目标语言需要独立 `TargetProfile`：edition/target triple、toolchain/标准库、Cargo依赖与feature、可用平台、整数表示（可能需要big-int库）、所有权/借用、panic和Result映射、异步运行时与FFI、crate根、公开函数与ABI及可重建SourceMap。Kernel自身以Rust编写不意味着生成器已能生成Rust。对于异步任务和借用跨边界，要实际取得Send/Sync与生命周期资格；不通过凭空添加`unsafe`满足原保证。`no_std`、裸机和实时不是普通Rust目标的隐含条件。

初次可只支持纯标量 + ADT + 函数签名 + 明确的闭包子集；不支持的高级构造返回准确TargetNeed。Rust生成产物的Cargo配置和目标SourceMap依完整ArtifactSet维护，不靠调用系统rustc后把用户手写文件算为生成。某个目标/平台失败不影响其它没有相交依赖的目标根。

## 5. 与原生库/工具链的实际接合

`ExternalExport`必须含相交发布的函数/会话ABI、效果、资源和初始化/关闭合同；检查原生依赖API确切版本与目标导出。可只读、正确绑定后直接生成 import+call，不把库算法重写到Gift；需要适配时生成真实有限适配并把成本/错误映射纳入Method资格。若原生API可能重入、异步结束、泄漏指针或跨卸载时继续回调，合格调用必须保留资源拥有/生命周期，不以类型声明`readonly`证明没有运行副作用。

检查外部TS工程应从冻结VFS启动相应版本的TS compiler host：`readFile/getSourceFile/fileExists/resolveModuleNames`都只能读capture输入和被允许的固定工具链lib/decl。仅覆盖`writeFile`仍可能从本机`node_modules`泄漏环境，不能称为闭合检查。build/check是否执行取决于请求及目标合同，不把源码成功打印提升为已构建、更不等于安全性已验证。

## 6. 成员布局、持久源与故障后继续修改

`layout`先收集每个根的公开入口、需要的helper/import、初始化与依赖，确定相同路径谁拥有、是否需显式组合；发生两根写同一独占源区域时拒绝，不能按文件名排序把后者覆盖。所有成员最终字节、摘要、依赖闭包、sourceMapping、构建环境一起成为ArtifactSet。`preview`返回精确已采用基础和目标比对；`apply`仍须CAS及实际当前权限。

第二轮修改：在原`module.json`中改变一个作者数值/要求，保留旧Candidate为历史候选，重新分析相交定义/Caller/Method/Target，再生成新ArtifactSet。对用户手改的generated区，按唯一owner方案拒绝、合法reverse edit或转为native；绝不把重新生成视为无损的默认覆盖。目标SourceMap与旧内容摘要必须失效，不因新代码“看着差不多”复用旧已过期的错误位置。

## 7. 验收输入与不可简化的负例

输入覆盖：Int BigInt及除零、具名参数重排和先错误后递归、短路分支、Option/Result、含非ASCII标识/文本、嵌套match、闭包捕获、递归、公开契约与外部导入。对于每个实际发布支持的目标组合，要求：作者源码解析→类型/效果和行为合同→真正源码打印→目标编译→运行观察（适用时）→第二次修改→再次构建，最后记录独立观察者而不是用Emitter自身报告“OK”。

不支持全功能时只对现有目标的准确`supports/doesNotSupport`矩阵作证明；不是要求实现者暂不做任何交付，亦不是允许把小演示称为完整生产编译器。

## 集合、闭包、递归、错误和完整输出的具体降低方案

完整目标不是给所有表达式套一层动态解释器。普通纯函数直接发射目标函数；只有该根实际需要的集合、精确数值、闭包/效果支持代码才进入ArtifactSet。默认无常驻Gift Runtime、无产品数据库、无中央业务switch。目标内部表示选择属于Method/Target责任，公开ABI变化则必须进入显式契约。

**List与结构值。**链式head/tail/cons频繁的不可变List，TS内部默认持久Nil/Cons节点，或经独立资格采用共享数组加offset视图；外部数组只在入口读取校验一次、按调用约定捕获或复制，输出在出口一次线性转换。不得在每次递归中`slice(1)`并用`[head,...rest]`重建尾部，把源中线性扫描悄悄变成二次复制。随机访问型Sequence可用数组，不能仅因底层同是集合就把List/Set/Bag的顺序和重数混同。一个有n个元素的链式扫描用每步常数个节点访问，总结构工作O(n)；元素运算及大整数位复杂度另外计入。

记录字段按类型决定布局，但初始化表达式必须先按源序求值再放入布局槽。名义类型在编译内部保留Definition身份，TS对外需要隔离误用时使用受控brand与构造函数；品牌不构成运行权限。Option/Result显式variant避免把Some(undefined)与None合并。公开外部结构不可仅靠TS `readonly`证明运行不可变；边界捕获、校验和借用约束需实际实施。相等和哈希只在已定义的Eq/Hash域生成，资源和函数默认没有按结构比较的资格。

**闭包。**先做free-variable analysis，产生`CapturePlan{binding,mode,region,type}`；只捕获真实自由变量，禁止把整个workspace/session放入闭包。TS可用词法闭包，但可重复调用只在捕获资源允许时成立；Rust按callMode选择静态闭包、`Fn/FnMut/FnOnce`及必要的显式环境结构。`move`不是“永远只能调用一次”的同义词；调用模式取决于主体如何使用捕获值。逃逸的借用闭包须满足调用者生命周期或改用有资格的拥有转换，不能靠`unsafe`隐藏未闭合借用。

**递归。**对自尾递归先建立形参与新实参的并行赋值临时量，再转`loop`；不能顺次覆盖参数导致后续新参数读取新值。互尾递归的SCC可降低为私有tag+参数槽状态机；若返回型/资源/异常路径不兼容，则保留普通函数或采用有资格的trampoline。非尾递归有深度硬界时使用显式帧栈或证明目标栈容量，不假定JavaScript/Rust无限栈。没有深度保证的普通函数仍可构建，但相应资源保证不能签发；异常/取消/清理必须在显式帧中保持。

**错误与契约。**用户Result错误、语言Fault、宿主工具崩溃分别映射。TS内部可以使用具私有标识的Fault对象加已选catch边界，Rust使用明确错误联合与Result；不把所有问题压为字符串Error，也不将未知宿主异常自动纳入合法业务错误。前置检查发生在外部效果之前，正常后置只在真实正常返回且result存在后检查。检查器本身的失败、超时和未知另外返回，不能签为需求为假。外部API需要原生异常时，由显式ABI适配映射，保留未识别异常。普通函数不强制携整套审计日志。

**打印器。**目标节点使用受限类型树，不拼未经转义的源码片段。名称表先固定所有公开导出与冲突，再为私有符号分配稳定名称；短摘要碰撞时按完整身份稳定消解，不能靠线程完成顺序加后缀。不可合法编码的公开名称经明确导出映射或拒绝，不能静默改API。字符串逐码元/标量按所选目标编码转义；标识符与字符串转义不是同一函数。保守打印可给所有复合表达式加括号；优化省括号必须按固定目标优先级、结合性和语法限制判断，例如指数运算左侧一元式和混用空值合并/逻辑运算，不能只比较一个优先数字。模板字符串、注释和路径中用户文本不未经转义插入代码。

**TargetPass工作表。**每个pass有`inputKind/outputKind/requiredAnalysis/preservedAnalysis/introducedUses`。按支配与控制区域放置临时量，所有introducedUses回RES资格；新增泛型实例进入去重队列。`verify_lowered`检查每个值定义/使用、控制流终结、返回类型、资源释放、未解决引用和必需操作。只有整个输出根闭包通过，才排布成员、打印最终字节、生成映射与BuildInputs。无需重复解释未改变的独立根。

SourceMap内部保存多对多关系：`target member+byte range→origin-set+transform-chain`，调试源优先精确的发生位置，生成helper可指向定义和调用者集合。打印后按最终字节构建UTF-8/UTF-16坐标；外部`.map`只能承载其中的投影，不能丢弃内部多来源再伪装唯一。错误回源跨版本失败时显示旧修订诊断，不贴新源。

TS独立检查器的所有读取入口统一落到冻结VFS，包括源码、lib、package.json、目录枚举、模块解析和大小写规则；默认CompilerHost会读取真实文件系统，不能只覆写writeFile就叫隔离。运行构建脚本是另一有权宿主步骤。ArtifactSet包含每个成员路径、角色、字节摘要、导入边、所需运行库与作者映射，退出Gift时可保留普通目标工程和必要支持库，不要求继续连接Gift服务。

外部机制校准及适用限界见[工程施工算法与宿主依据](../../../research/sources/工程施工算法与宿主依据.md)；本章的Gift接口和组合责任仍是当前工程设计。
