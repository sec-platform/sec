# 14 一次从空工程到真实目标，再到修改和恢复的完整纵向设计

## 1. 为什么只编出一个函数还不够

需要一个工程师按固定输入、文件、命令与预期结果执行的验收故事，同时区分**计划形态、预期输出、真实执行结果**。本章把 Gift107 已提供的真实结构模块作为合法源示例，避免复制一份伪合法schema：`fixtures/prebootstrap/Gift107/division.module.json`、`consumer.module.json`、`higher-order.module.json`、`compiler-types.module.json`。它们拥有实际类型、谓词、函数主体、泛型与递归；由于当前并没有产品Reader/Kernel，对它们的目标产物只给**预期可检查含义**，不得标成已由本版软件编译。

## 2. 仓库初始化和工程文件实例

工程布局（目标工程，不代表本设计ZIP自带这些实现）：

```text
app/
  gift.project.json           # 按当前发布的gift.project/1填写项目根与modules/targets
  design/
    division.module.json      # 从现有Gift107结构示例复制，唯一作者源
    consumer.module.json
    higher-order.module.json
    compiler-types.module.json
  gift.lock.json              # 在解释/方法/目标选择固定并已采用后才出现
  native/                     # 已存在原生项目文件，可为空
  target/                     # 由完整Target生成的受管产物（初始不存在）
```

初次没有真实Method时可以合法保存作者源，但不能把 `gift.lock.json`虚构成“所有依赖已确定”。使用原示例的确切moduleId/DefinitionId、dialect、expression字节；根据实际项目清单协议给定模块的相对路径及Target request，并由Reader拿到已锁定的`gift.semantic`解释版本。项目清单完整字段以 `docs/10-作者与输入/作者源/工程源/工程清单模块与绑定锁协议.md` 为准，不能将本章树状名称当成实际schema值。

## 3. 第一条编译请求的逐对象链

```text
CLI/tool request
  → WorkspaceCapture(ProjectView R0): actual source bytes + sourceProfile + lock + source scope
  → KernelSnapshot(epoch E1, frozen content): identity and import views
  → COMP0 strict structural parsing and provenance
  → COMP1 collect `Division`, `isDivision`, `quotRem` declaration headers
  → COMP2 bind cross-module `consumer` to `quotRem`; bind locals under lexical scopes
  → COMP3 check input Int, nominal Division, effect/error/require/ensure
  → RES exact method for body/external use and target qualification
  → COMP4–6 elaborate/lower/recheck; no raw TODO or missing required effect
  → COMP7 produce TS ArtifactSet; bytes plus SourceMap and build inputs
  → optional real TS TypeScript check/build in isolated VFS
  → preview result refers to Candidate R0 and precise method/target digests
```

预期行为：当`quotRem`在公开合同允许的输入域内有合法实现时，结果是值与Division字段满足`n = quotient*d + remainder`及其额外要求。**特别注意**：原`isDivision`的表达式中含`quotient >= 0`、`remainder >= 0`及`remainder < d`，当允许负数d时，它并不自动满足一般有符号欧几里得/向零除法；若要求覆盖负数而仍不修改公开语义，将产生实际合同冲突。不能偷偷用目标BigInt `/`代签原合约。此例同时用于检查“算法选择必须服从意义”。

示意性的单个TS生成成员（不是声称当前产品已生成）：

```ts
export type Division = Readonly<{quotient: bigint; remainder: bigint}>;
export function quotRem(n: bigint, d: bigint): Division {
  if (d <= 0n || n < 0n) throw new Error('precondition'); // 仅示意一个收窄且明确的输入合同
  const quotient = n / d;
  const remainder = n % d;
  return { quotient, remainder };
}
```

这个代码例子**不能直接作为原Gift107整个`quotRem`函数的合格实现**，除非实际所选作者合同确实限定输入且错误分类、合同检验和公开接口满足原定义。其用途是迫使实现者在目标代码旁展示输入域与意图来源，而不是把这一段复制进Emitter当固定除法模板。真正的输出需要从已绑定SourceBody或方法取得，且跨异常行为由正确Target映射。

## 4. 第二条新算法和跨模块使用

`higher-order.module.json`定义泛型、闭包与稳定`partitionBy`，`compiler-types.module.json`定义递归TypeExpr和`occurs`。这两个模块明确来自普通计算表达，而不是先写死“区间/账本”行业模块；在目标实际支持泛型实例与match递归前不允许声称它们构建通过。

第一轮可以仅交付分支清晰的标量子集，`partitionBy`因高级泛型目标能力未完成时应返回`NeedTargetCapability`；其它独立root仍可完整生成。若目标后续增加该能力，相关负依赖失效并重新求解，无需改变作者语义。对`occurs`，必须收齐递归函数头，再判断具体body和目标运行，不能因符号调用图有环就将合法语言表达错误拒绝。

## 5. 第二次修改与冲突演练

开发者在同一作者文件内将除法的公开输入域改变，或更换结果类型中的某字段。步骤：以R0执行`fork(R0, Delta)`得R1；类型/合约和Method资格重新计算；旧TS ArtifactSet只对应R0；新的同名目标文件在preview中显示受管区域精确Diff、SOURCE R1和未解决Need，不能依靠按文件名相同就直接覆盖。随后 `apply`重新读取current头与文件前像，R0尚当前且有写权时采用R1；若另一个编辑者先采用R2，返回冲突/重基Need，保留R1原有字节。没有采用就不能把当前仓库标R1。

系统不得为长JSON清理而整体重排不相干作者区域；若SourceProfile承诺原始字节保真，则局部替换旧span时必须保留周围内容与UTF-8位置。新目标的SourceMap重新以最终字节发布，旧R0错误位置可作为历史诊断，但不能贴到当前R1。

## 6. 再接一个实际Effect：范围外行为严格受阻

用户要求把新计算结果写入SQLite状态或外部服务。纯编译器可以在作者端形成带Effect的定义和可能的目标调用，实际操作调用必须先由宿主 `ExecutionGrant` 指定准确对象与内容、幂等身份、可写范围与恢复策略。本机SQLite能演示真实单库事务，但不能代签远程资金效果。请求派发后断连，必须留下OperationRef和UnknownOutcome并读回；不能把RequestId换新后再发送。用户没有启用真实Effect时，不得为了“初始化系统”就创建数据库或远程Provider。

## 7. 从成功路径延伸出的故障注入矩阵

| 注入点 | 注入的具体变化 | 期待状态/可继续操作 |
|---|---|---|
| 读入 | JSON重复键、错误UTF-8、未冻结dialect | 拒解释，源字节/位置可回读，不污染current |
| 名义类型 | 同字段不同Type身份 | 合格的名义检查拒绝隐式统一 |
| 合约 | 除法负输入被要求正常返回非负商余 | 返回合同冲突或合法输入域Need，不偷改算法 |
| Method目录 | 增加此前没有的合法供应 | 旧负依赖失效，已锁绑定不能静默改写 |
| Target | TS `Number`无法精确保存大Int | 返回目标不合格或使用BigInt/合格helper |
| 编译 | 递归调用图有环 | 合法声明先行；初始化环另判 |
| 目标工具 | 缺TS lib或工具版本变化 | 环境Need；不是源源码语法错误 |
| 目标成员 | 第二个root写同一受管路径 | 组合冲突，不能最终写覆盖 |
| 并发 | 旧worker对R0迟到结果 | 旧结果保留历史，不能更新R1current |
| 保存 | CAS前像变化或部分文件替换 | 冲突/恢复；不假称多文件原子提交 |
| 外部执行 | 已派发后超时断联 | UnknownOutcome + Reconcile，同OperationId |
| 租户权限 | 撤销已共享SourceScope | 不再披露派生私有视图，旧效果继续如实结算 |
| 安全 | 未合格外部语义插件请求执行宿主进程 | 无ExecutionGrant或隔离条件则拒绝执行 |
| 自举 | 新语言构造C0不支持 | 走旧语义bridge，不用新工具证明自己 |

## 8. 可用施工成果与还缺证据的判断

交付者至少同时提供：项目文件及准确作者字节、编译器/Method/Target完整构造声明、已生成的全部目标文件（若实际生成）、工具真实build/check结果（若请求）、两轮源修订与受管Diff、真实授权操作的journal/Receipt（若执行）、故障注入和独立oracle证据、可回退基线。只有架构图/代码范本/静态Schema通过时，状态仍是设计。若没有实际Provider，也不会因为本章定义了状态机而出现真实世界效果。不同根可以不同成熟度，整个系统Claim只能取相交要求真正支持的共同范围。

## 新增陌生泛型函数及跨阶段故障轨迹

本轮新增的作者例子位于`fixtures/prebootstrap/Gift110/span-prefix.module.json`及`span-consumer.module.json`。`spanWhile<T>`接收有限序列及作者提供的纯谓词，返回满足谓词的**最长前缀**和未经继续观察的后缀；第一次false后不再调用谓词。它与filter/partition不同：后面再次满足的元素也属于后缀。这样可以检验语言是否支持真正的新组合，而非把陌生函数名分派到既有筛选模板。消费者模块只导入公开定义，不复制主体。

函数本身用已有`s:function/gift.semantic-body/1`、泛型、递归、模式、let、if和record表达，没有新增业务kind。空序列返回两个空序列；非空先对head计算谓词，false则立即返回空前缀与原items，true才递归tail并把head接到前缀。predicate标纯仅排除其声明效果，不自行保证终止或不抛Fault；函数的实际求值继承它被调用部分的进展/异常，不应在false之后新增调用。每个已访问元素仅检查一次。

例如值序列`[1,2,0,3]`和“严格正数”谓词，结果为`prefix=[1,2], rest=[0,3]`，谓词调用轨迹恰为`[1,2,0]`。把它替为partition得到`[1,2,3]`即改变语义；先map谓词再分段即使结果相同，也会额外求值3，在谓词可能Fault或不终止时改变观察。例子不要求类型T有Eq或Hash，不应为了方法选择把这些能力强塞给作者。

首次请求的实际阶段值：R0原字节捕获→两个ModuleHeader解析到同一公开Definition→参数T保持刚性并在跨模块调用实例化→match覆盖空/cons两种结构且无多余默认→CheckedUnit记录latent predicate效果→直接使用作者主体生成BoundProgram→Target选择有限序列表示和调用帧→输出完整成员、源映射与独立构建输入。若其公开合同另要求大输入不依赖宿主调用栈，则Target将递归改为显式循环/帧；没有对应合法化方法时报告该Target缺项，不把普通递归设计称作已满足栈界。

源R1只将消费者导出显示名改动时，定义意义和主体可保持；导出API变化仍影响消费者。源R2改变“最长前缀”为“所有满足者”属于新合同，不可为了复用旧缓存假装等价。原生库是第一次false后仍读取尾部的实现时，应被轨迹/进展观察区别拒绝。新增更快方法使发现查询失效，但旧明确锁定方法不自动被替换。

| 故障轨迹 | 应保留的具体状态 | 允许的后继与独立观察 |
|---|---|---|
| 绑定成功，泛型统一中途失败 | 私有推导事务已回滚，原CheckedUnit未发布 | 另一候选重新实例化；不残留Int强迫T |
| 旧条件读取改变，旧分支已删除 | orderedReadTrace在条件处中止复用 | 重算新分支，不为了旧依赖触发本不应发生的错误 |
| 查询算完，发布前basis被更新 | 结果与ReadSet未进入当前索引 | 保存历史或丢弃；当前root重新请求 |
| Worker关闭snapshot时仍在发结果 | closing标志及响应pin | 结果编码/发送完释放，旧handle禁止新借用 |
| 准备文件操作后进程崩溃 | prepared含真实pre/post，meta头未前移 | 检查授权和前像后admit，或无效果aborted |
| admit已提交，替换第一个文件后崩溃 | active、direction、全部pre/post持久在库 | 逐路径三态读回，第三方像则recovery-required |
| 外部dispatch-intent已提交但无回执 | 无法单靠日志判是否真正送达 | 同OperationId读回/合格幂等；不得新身份盲重试 |
| SQLite COMMIT返回BUSY | 可能仍active，不可直接再次BEGIN | 有界重试原COMMIT或显式ROLLBACK，记录真实状态 |
| 目标代码完整但独立性质检查失败 | Artifact可检查、相应Claim Refuted | 不发行该强保证；源码仍可定位修复 |

本包只进行设计资产的结构/引用检查与有限模型演练，没有实现通用Gift前端或从这些JSON自动生成目标程序。目标消费者建成之后，还须直接运行同一模块的源/目标观察对照；不能用手写Python模型代签生成器。
