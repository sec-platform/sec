# 13 真正通用的能力接入：作者新语言、库、Method、Target、Provider 与36类领域

## 意图新领域的优先判断顺序

首先让领域作者以[开放 IntentSource](../../20-语义与组合/作者语义/通用意图语言-意图源与语义组合.md)声明目标、角色、观察及不变量，再判定现成 **Meaning/Rule/Query/Workflow/Method/Target/Provider** 哪些已可满足；缺实现时仍保留已接受业务意图。旧 D1 中“用普通 Gift 计算表达”仅是可选充分路径，不是新业务的强制首步。自定义新业务名不触发 Kernel 分派，也不能用 `meaningRef` 字符串自动声明可实施。

## 1. 什么都不预装，不等于什么都无法表达

语言自由来自普通Type/Function/ADT/Relation/State/Task/Effect/Requirement的**开放构造和组合**，而非预先枚举世界上全部业务。业务作者可以用现有语义描述任意新规则、关系及算法；只在实际需要新的不可归约原始意义/Effect或特定目标/环境能力时，才引入版本化SemanticModule、Method、Target Adapter或真实Provider。**普通自定义逻辑应做到零业务Kernel修改**；新的语义插件也不允许通过注册一个未解释的URI就宣布会生成代码。

领域扩展的交付单位是一个拥有真实Version/Digest的Definition或库包，可包含公开参数、数据类型、合法域、错误、输入/输出、状态/时序、框架保持、调用/效果/资源、可选Method和测试见证。核心不保存“医疗必须是什么结构”“游戏必须是什么状态”的中央枚举；领域政策和现实世界事实由真实拥有者输入。

## 2. 新能力从零接入的七个具体步骤

```text
D0 业务拥有者编写准确可观察意义：对象、身份、时间、状态、错误、效果和接受边界。
D1 判断是否已能用普通Gift计算/组合表达；若能，写普通AuthorModule/库，不注册新语言原语。
D2 若缺不可归约意义，发布真正SemanticModule：结构codec、类型/解释、组合与Assurance义务；锁revision+content。
D3 取得实现供给：SourceBody、受检ExternalExport、GenerationMethod或有界合成；描述目标适用域。
D4 对涉及平台/网络/设备/数据库的效果引入真实Target Adapter/Provider，固定ABI、权限与读回。
D5 运行正反例：普通无权作者可声明目标但不能借注册URI执行；已资格方法按明确域生成/检查/观察。
D6 升级/退出：保留旧意味、检查兼容、失效相交结果、迁移已使用的持久事实并保持恢复与撤权。
```

若D1已有表达能力但缺方法，正确结果为 `NeedsMethod`，不是“必须开发新的Kernel semantic kind”。只有系统的身份、权限、恢复或实际公共不变量不足时才有充分理由修改Kernel；一种业务问题很复杂不是充分理由。

## 3. SemanticModule与Method如何实施为真正的接口

SemanticModule 的发布包至少包括其语义身份与实现修订、可被解码的输入结构、受支持的类型与局部/跨域Meaning解释、所能检查的Requirement类别、所需的read-set领域、错误/Need、容量预算、与其它模块join的精确规则。Schema只提供结构门槛，不自动证明Meaning；纯插件提供`interpret/join/check`等现有职责时必须返回真实读集与未决条件。

Method供应声明其实现来源、MethodRef、目标/工具链和能力约束、真实算法与CallRule、效果/资源/异常/进展、适用证据和许可；Target Adapter只负责选定意义到具体目标表示的保持，不能重写用户业务硬要求；Provider只负责被实际Grant允许的现实作用，不能把自身在线健康固化到EngineImage以冒充当前授权。来自不可信包的代码只可在实际能隔离、能预算控制的宿主内运行；若当前宿主没有这类隔离，就允许把供应看作结构数据而暂不执行。

对两个新语义的结合例如流事件`eventTime`、库存`reserve`，需要说明共享事件身份、重复/重放、时间域、状态版本、可观察错误、实际Effect先后及总体保证；不是把两个module都`verified=true`便直接给跨域系统PASS。

## 4. 36类领域设计的具体实施投影

下表不是中央业务插件列表或Kernel固化注册表，而是已有 C01—C36 的**实现交付方法选择**。领域真正启用时，必须取得相应数据/算法/Provider/资格；未选业务域不成为自举前置。此处每一项说明需要创建的构件、算法或方法边界与失败处理，不以一个领域名顶替工程方案。

|---|---|---|---|
| C01 关系/SQL | bag/set、NULL、排序与隔离 | Relation Definition→参数绑定→查询计划→目标SQL、VFS/driver快照 | 空排序不保证分页稳定；SQL适配不匹配时NeedsTarget |
| C02 增量视图 | 增删/否定/递归模型 | 差分维护与分层/固定点、源日志和补算 | 删除及负环不能只累加，补算与全量对比 |
| C03 状态机 | 层级、history、正交区域/退出动作 | Event dispatcher、入口/退出、资源清理及持久checkpoint | 重入/历史状态非法需拒绝，取消后资源不能提前释放 |
| C04 乱序流 | event time/watermark/迟到与回撤 | 有身份Stream消息、window aggregate、重放状态与backpressure | watermark不是绝不迟到保证，更新/撤销需精确发布 |

| C28 人类审批 | 有权角色、责任和异议 | workflow state、signoff证据、任务追踪及复核 | 流程图不能代替真实人的批准 |

## 5. 横向组合接口：五个不可遗漏的接缝

**数据↔时间**：关系查询可能按快照时点，流按事件时间与处理时间，真实资金按结算时点。组合时必须有转换函数和可证来源，不能将三者统一为一个timestamp。**状态↔Effect**：内存状态更新与世界Effect可能不在同一原子域，必须按Operation/Provider恢复；把状态图画成事务不会自动让跨库更新原子。**资源↔并发**：多个独立Method共享CPU、内存、文件或设备时局部约束不足，需全局协调。**作者意义↔外部事实**：模型估算、传感器值、现实权利和外部同意有不同取得者，纯计算不能凭名称产生事实。**目标源码↔运行证据**：能在TS/Rust构建，只说明实际target条件符合，不代表原始业务与安全要求全部成立。

## 6. 从普通规则到新语义插件的反例

一个开发者定义从未见过的 Token 周期旋转与禁止邻接谓词，完全可用已有类型/函数/列表与约束表达：这是普通新库，不能要求Kernel升级。若作者要求真实射频设备按自定义协议在指定时间发射，算法仍可普通表达，但实际原语必须有合格Target、设备身份、真实Grant、时间/读回和失败恢复；没有它们时允许保存意图，但禁止冒充设备已执行。若提供新形式的跨运行非干扰语义，则SemanticModule必须解释什么是两条执行轨迹、允许什么观察、如何检查/证明、适用哪些假设和何时失败；只注册`noninterference`名字不够。

## 7. 领域供应生命周期与升级

发布包先经过结构/语义有效性检查，按准确revision和内容锁进入EngineImage；有资格的Target/Provider实例分别安装，运行前再核真实权限与健康。升级同一行业方法不能默默替换老合同；过去的结果只在准确证据条件还成立时保留。退出领域模块后保留必要历史解释、作者源及撤回/迁移路径，不能仅删插件再用generic fallback解释旧现实记录。其余不相交纯函数和领域根可以继续工作。

## 领域供应的函数边界、组合适配与运行闭包

所有领域共用既有Definition/Requirement/Method/Target/Provider身份，不新建与它们同义的领域数据库。实现者在装配时构造内部`DomainBindings{meaningImage, joins, methodCatalog, targetBindings, observers, effectProviders}`；不存在的部分不是空成功，而是只阻断实际需要它的根。普通库仅包含作者Definition和Method时无需插件进程；新原始语义才进入隔离解释适配。

`interpret(definition, substitutions, snapshot)`输出类型化意义与需要的观察域；`join(left,right,sharedBindings)`核共同主体、数值/时间单位、错误和帧能否兼容，返回联合义务或冲突见证；`qualify(method,obligations,target,environment)`只检查该域可判断的部分，保留其它域未决；`lower(binding,target)`产生具体目标结构与依赖；`observe(operation,provider)`记录真实状态。以上是内部调用分工，实际wire方法仍由已有协议映射，不能把每个函数名变成新公开接口。任何步骤都返回其实际ReadSet和失效条件。

**关系、流和状态三种适配。**关系域的中间计划节点携列身份与类型、nullable、bag/set、排序键及稳定tie规则、数据源快照。过滤/投影/聚合/连接分别传递重数和NULL语义；SQL lowerer只生成参数占位与参数序列，不拼用户值为SQL文本。分页游标绑定排序定义、唯一tie、快照和查询修订，过期不能当下一页正常继续。增量关系以带符号变化量或明示集合撤回传播；否定在有资格分层内先稳定被否定层，再重新判上层。窗口流保存去重ID、事件时间、watermark观察、分桶状态和已发结果修订；迟到回撤产生新的结果修订而不是修改已发出的历史消息。状态机先计算本次退出集合、过渡与进入集合，再按定义顺序运行退出/进入动作；外部动作经操作身份结算，不能重放一次event就重复扣款。

**数值、张量、微分和控制适配。**NumericPlan首先固定数值域、单位、形状、误差对象与目标环境。精确有理/区间和机器浮点的转换产生显式误差义务；shape/broadcast在索引生成前统一，动态shape保留运行检查。设备buffer携device/region/owner/last-use-fence，跨设备拷贝是具真实同步成本和寿命的动作，不把view当独立分配。AD变换在固定计算图和效果边界上生成前向值与线性化/反向拉回，tape由该调用拥有并在最后一次反向使用后释放；checkpoint重算仅允许对满足重放条件的区域。方程/优化解微分采用独立的隐式系统假设，不能把有限迭代程序的导数当同一个对象。控制器组合先把共享执行器、观测延迟和饱和映射到联立模型；局部稳定证明不替这个联立系统。

**概率、学习和因果适配。**随机算法的输入包含随机源合同而不只是整数seed；重现路径锁算法、分布、流拆分规则和并行使用次序。需要安全随机的效果从受权源获取，不得用可预测seed实现。训练数据变换、训练、评估和推断是不同依赖根，指标带数据划分、模型版本、域和测量方法；数据泄漏或来源撤销沿这些边传播。因果估计器要把估计对象、干预分配、混杂/干扰假设与观察窗口作为方法输入，不以预测准确率代替可识别性。偏差和不确定性不被编译器转换成确定业务事实。

**网络、身份、账本、库存与人类审批适配。**网络request的传输ID与业务OperationId分开，重连可换传输但不能改同一业务身份。认证适配只产生有来源且有时效的身份观察，授权策略另核动作与资源。账本原子过账在一个合格事务域核每币种合计及前像；跨域资金读回保存外部交易标识。库存预占、资金结算、发货是三个有状态参与者，允许何种补偿/时效由作者合同给定；网络成功不能代签到货。审批系统只生成待签任务和观察真实签发，超时、撤回、分歧有独立状态，不因图中有批准边就发货。定价版本与舍入绑定结算事实，不能在退款时自动用新价格重算旧收费。

**交互、媒体、图形、游戏与平台适配。**UI lowerer把组件状态、输入事件、焦点关系和资源版本变成DOM或原生组件树；每个事件处理绑定看到的状态修订，过期异步结果须按声明合并或丢弃，不能默认覆盖。无障碍适配以实际语义角色、标签、键盘路径及焦点退出建立观察，地区资源将时区/历法/排序分别锁定。媒体处理链明确时间基、采样/色彩空间和buffer回收点；播放速率、丢帧与转码不是等价转换。几何/渲染区分精确空间关系、可容许近似与可见画面；GPU命令完成前资源不得回收。游戏规则仍是作者程序，服务器权威、回放seed、时钟与网络容错则由协议合同决定。平台打包最终依赖目标SDK、权限、签名和更新机制，不由桌面build代签。

**硬实时、设备、工业、医疗与强保证适配。**驱动的命令接纳、实际运动和传感器读回分开；失联触发已设计安全策略，但无法观察的最终动作仍保持未知。硬实时必须记录任务释放、优先级、最坏时长依据、阻塞和抢占成本，方法可拒绝不满足预算的装配。工业工艺和医疗/公共安全的实际术语、风险与专业限制由有权领域主体提供；设计只给数据入口、验证与责任，不替其批准。形式证明验证精确模型和假设，安全论证还连接设备/环境观察及人工责任；任何一个局部PASS都不能提升为现实系统认证。

**远程、新语言、多组织与社会系统适配。**远程执行仅在明确许可后装配，输入最小化、秘密不随源码包外泄，重试先核旧尝试结果/计费身份；无权时不替换本地路径。新语言Target实现本语言的异常、内存、模块与构建输入，保留目标不支持的准确出口。跨组织join以各方独立签发和撤回范围合取，优先级不能由一个参与方单方面编造；不可同时满足时返回实际冲突并保留各方退出权。成本承担者和风险承担者不是默认同一对象。
