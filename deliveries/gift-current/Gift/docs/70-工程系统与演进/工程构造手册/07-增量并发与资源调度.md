# 07 从全量正确走向增量正确：QueryGraph、负依赖、SCC、预算与取消

## 1. 正确性基线与首期优化顺序

第一份 kernel 先提供完整的`compileFrozen`全量结果，形成同一固定源和Method/Target下的可比较语义 oracle。缓存、并行、持久QueryIndex只是后续性能实现；不能在没有全量参照前用缓存循环凑成功率。给每项优化定义影响域：哪些QueryKey可以重用，哪些负依赖必须重查，什么状态能够安全缓存、共享和取消。

实现者不能把“完全相同的JSON内容”作为所有场景全局同一身份；QueryKey须覆盖真正读到的解释版本、SourceOwner/visibility、Method/Target/ABI/toolchain、当前需要的环境与候选目录revision。跨租户的秘密和受控来源即使字节相同，其访问控制仍独立。当前Grant和Provider健康若影响本次执行资格，必须执行时重核，不能用编译缓存签发当前授权。

## 2. 四类依赖边而非只有“引用某个文件”

- `ValueRead(ref,version)`：实际读到一个定义、方法、文件或类型值；值变后对应查询失效。
- `ExistenceRead(scope,name/pattern,registryEpoch)`：曾确认某名称/候选不存在或目录枚举截止于某revision；后来新增方法会影响旧“未找到”结论。
- `SemanticRuleRead(languageRef,revision,digest)`：某节点由哪个解释器、规则、目标约束定义；规则升级即使源码字节不变也需重新解释。
- `EnvironmentRead(targetProfile,toolchain/ABI/config)`：实际发射/资格依赖的目标配置；不同Toolchain/OS/可用库不能互签。

ReadSet可优化成压缩集合，但所有可观察判断必须有真实依赖。切勿把`NegativeRead`投影成“某个文件路径没有被读取”，否则未来有新增candidate时不能正确重选Method。诊断位置依赖源revision，纯语义结果可依计算值不同程度复用，但旧位置不能贴到新源。

## 3. QueryKey、Entry和一次计算的生命周期

```rust
struct QueryKey { kind: QueryKind, input: Digest, semantic_image: Digest,
                  relevant_target: Option<Digest>, authority_scope: ScopeKey }
struct QueryEntry<T> { state: EntryState<T>, actual_reads: ReadSet,
                       assumptions: Vec<Assumption>, generation: u64 }
enum EntryState<T> { Computing, Complete(T), Incomplete(NeedOrBudget), Invalid(Diagnostics) }
```

这些是单内核内部实现设计，不是公开Schema。不可缓存的状态包括依赖当前不可重复实世界效果的结果、未捕获的工具输出、生命周期内不稳定的裸句柄。BudgetIncomplete可以按输入保存“资源不足”的诊断或已有有限前沿，但不能被下次更高预算请求命中为**语义无解**。查询重入和SCC合法递归分开；正确函数调用图允许环，而它的头/类型求解可使用SCC固定点或明示有限预算。

缓存发布必须是原子地提交 `value+actualReads+generation+status`，不能value已可见而依赖表尚未登记。任何源/规则/目标变更使查询失效时，要同时处理正向与反向依赖。基于旧版本迟到完成的worker不能发布到新head，但可在完全符合原basis和readset时形成历史可读结果。

## 4. 全量→增量算法

```text
snapshot_changed(old,new):
  delta := compare source revisions, semantic/rule image, target/method catalog, toolchain
  affected := queries whose actual positive OR negative dependencies intersect(delta)
  for each affected query: mark stale at its old generation
  schedule only roots consuming affected; retain independent roots
  for each recomputed entry:
    evaluate at frozen new basis
    track every value, absence, enumeration scope, semantics and target dependency
    if reading a stale entry, recompute or propagate specific Need
    publish only if basis and generation still match expected key
  compare root results and diagnostics with full recomputation in controlled evidence scope
```

不能单纯沿增加边传播变化；删除定义可能使`any`候选成为新最优，删除否定谓词可能使之前失败的关系成立。用于关系/固定点算法的半增量delta与一般编译QueryGraph的失效方式不同，需要各自的真实域和可证明单调前提。

## 5. SCC与查询固定点

类型/声明依赖的SCC允许互递归函数，若每轮更新在指定有限格上单调且可保证收敛，可执行工作表迭代并发布固定点；需要widening时记录它可能损失的保证和精度。未知或无限增长不能任意停止后报告类型正确。非单调关系、取反递归与不完备求解必须选择明确的分层/稳定模型或保留Needs。某个模块的顶层初始化依赖环不因函数头循环合法就自动通过。

例子：两个函数`f`和`g`互调不是自动拒绝。先收集两者声明签名，主体类型依赖可在同一SCC求解；其运行时可能无终止证明不意味着类型非法。相反，`const x = y+1; const y=x+1`有实际初始化环，若语言无合法惰性求值机制应拒绝。

## 6. 本地并行与共享singleflight

单个 query 的求值可以被多个请求等待；`QueryOwner`保留实际完成计算与其消费者计数，取消某个等待者只移除对应结果流/可见性，不能在其他等待者仍需它时杀掉底层工作。需要中止底层计算的条件：全部消费者撤销、无被授权后台必要，且计算本身能够安全协作取消。强制杀死不可取消native线程可能仍有资源/回调，不能马上释放映像或内存。

工作队列按有限并发数、总预算、每租户配额和真实内存/IO占用做准入；不让每层worker自己重置预算。长任务可以返回可重放的固定前沿或准确BudgetIncomplete，但不能因为一个低优先root拥塞而让已有高优先root不经准入占用无限资源。去重的是固定输入与计算身份，**不是**不同权限使用者的结果披露许可。

## 7. 性能计量必须实物化

记录三个独立指标群：前端冷/热解析与类型/效果、方法搜索与目标发射、工作区/工具/真实作用等待。指标的事件带fixed snapshot/target版本、输入规模、缓存命中条件、用户允许的采样信息；不能把编译CPU时间、TypeScript独立build耗时、Provider网络尾延迟合成一个没有场景定义的`compileMs`。必须按真实工作负载量化导入图节点/深度、泛型实例数、并发roots、负依赖规模、目标代码字节、峰值内存、p95/p99等。没有已测数据则保持Unknown。

对比方案：同源full vs incremental结果等价；single worker vs parallel相同可观察结果；冷/暖构建与换Method目录后的失效有不同采样；巨大JSON与非法深嵌输入必须有预算而非OOM。缓存策略可以在数据支持下选择arena重用/增量解析/index，但不得改变作者源覆盖或未完成结果的真实性。

## 8. 可执行故障注入条件

1. 完成编译之后新增一个更合格的方法，旧NoCandidate必须失效；已有锁若不允许自动重绑则返回明确版本不匹配/候选而非静默替换。
2. worker取消后回报迟到完成，旧epoch/旧base不得设置为current。
3. 同一源码不同目标Toolchain，不允许误共用目标诊断或artifact。
4. 两个root共享查询，取消其中一个不应使另一个缺结果。
5. SCC类型计算工作量超预算，保留未知，不发布当前类型完整成功。
6. 改了业务作者没有权限的文件，当前源捕获阶段应阻断或声明不可见，不允许从相同摘要缓存泄漏原先内容。
7. 低资源退化返回准确Needs或Stopped，不放松硬业务义务/权限以换“成功”。

## 增量复用、读序验证和发布事务的实际算法

固定输入上的QueryEntry分开`lookup key`与`actual dependencies`。查找键包含查询种类、显式参数、语言/方法/目标相关解释画像和可见域；不把整个工程文件摘要强塞进每个key导致一字改动全失效。真实依赖仍由执行追踪记录；不能为了命中更高而遗漏影响结果的输入。源位置诊断层与可复用意义层分开，使纯格式修改可以复用类型结果却重新生成位置。

每条已完成记录具有`valueFingerprint, changedAt, verifiedAt, orderedReadTrace, resultClass, producerRevision`。`changedAt`只在输出意义改变时前进，`verifiedAt`标明在本次输入图中重新确认的代际。读集可去重索引，**验证轨迹仍保存原消费顺序**：旧函数先读开关，再根据开关读A或B；开关改变时不能先验证旧A并把其错误当作新分支错误。

```text
get(q, frozen, context):
  find exact compatible entry or become unique producer
  if verifiedAt matches this frozen graph: return admitted result
  walk previous ordered reads:
    refresh dependency under the new frozen graph
    if dependency is changed/unknown/not visible: stop validation; recompute q
  if all observed inputs are equal under their declared equivalence:
    atomically mark verifiedAt and return requalified result
  else evaluate q with a private recorder and private result
  before publish, verify producer token, input basis, dependency revisions, disclosure scope
  under one publish lock, replace result+reads+reverse edges+fingerprint+version together
  wake waiters after lock release
```

immutable snapshot消除一次求值中输入被改写的问题，但不能消除缓存表中的并发发布。失去producer token的迟到生产者不能覆盖新entry；它可保留为其原basis的历史结果。发布锁只覆盖短元数据事务，禁止持锁调用插件、等待其他query或发送网络帧。验证失败不能半更新read-set；旧值及旧边作为一个一致记录撤下。

可缓存类型错误和NoMethod等负结论，但须记录导致它们成立的目录/存在性/解释依赖。Cancelled与BudgetIncomplete不是稳定的语义结论：仅可复用已封存的前沿，后继必须在同输入/规则/枚举空间上继续消耗新准入预算。旧“内存不足”不得挡住另一个合法更高预算请求。来源撤权可以限制返回而不修改历史数学结果；它必须重新校验披露，不用全局清缓存代替权限。

SCC分别处理：声明递归只需头先行；类型/效果单调有限域采用worklist；非单调查询遇相同key重入则形成显式循环义务，按其域算法处理。没有指定收敛规则的循环不能以“缓存Computing已存在”返回成功。等待图若形成跨线程死锁，调度器交回SCC责任或取消该计算，不让用户等到无期限。

缓存容量分`source pinned / semantic results / target byte buffers / protocol inflight / speculative frontier`五个真实池计账；同一共享内存物理上计一次，多个租户的保留和披露配额分别计。默认使用有权容量内的分层LRU，先丢可重算未pin结果，再回收不可见旧映射；live snapshot、待发响应、原生借用和恢复记录不可被LRU释放。结果大于可用缓存时可以不缓存而仍正确返回，不能把缓存失败当源错误。

singleflight按固定query及兼容预算条件共享。每个等待者拥有独立deadline、取消标志和披露scope；短等待者超时只解除自身。生产者预算由共享准入者掌握，不能因新等待者加入自动延长期限或重置消耗；确有追加预算时登记新准入。退出时先禁止新任务，协作取消无消费者任务，排空/封存仍受保护结果，最后释放arena。

性能数据记录各阶段CPU、墙钟、等待、分配峰值和输出量；不能用一个总耗时掩盖解析快而发射二次复制。实现验收同时比较值、Fault、公开次序、Needs与诊断来源，不能只比较成功返回值。有限模型不替代生产高并发测量。
