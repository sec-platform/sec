# 09 真正作用世界之前：Grant、Operation、事务、读回与恢复

## 1. 不给普通编译增加强制的数据库

`compileFrozen`是固定输入上的纯计算；短分析和目标preview可以没有任何持久工作状态。用户请求真实保存、发布、工具执行、远程网络或其它实际效果时，才由Control的 execution owner 准入、建立可恢复Operation、绑定实际Provider和前像。默认本机有状态画像使用 `.gift/state/control.sqlite` 及必要的内容库；具体表中已有 `meta/generations/operations/files/events` 五类责任，不另造竞争持久模型或把演示数据库当真实外部钱包。

**类型正确 ≠ 方法合格 ≠ 已授权 ≠ 操作执行 ≠ 外部系统确认 ≠ 业务效果满足。**这些状态分别产生可核验结果，不能由一条`Promise<boolean>`扁平化。

## 2. 五组持久事实的物理职责

以下是实施者的**逻辑SQL事务布局**，逻辑含义由 `docs/50-执行运行与观测/持久化与恢复/事务提交-任务合同与事务读回.md`拥有；本页下方“本地五表物理实现”给出首次具体DDL、事务程序与适配边界。原文的五类记录不是已存在的完整DDL，不能让施工者到原owner寻找不存在的SQL：

| 角色 | 必须可保存并读回的内容 | 不可混用的意义 |
|---|---|---|
| `meta` | schema版本、当前heads与必要全局epoch/fence | 不是业务资产真相；旧字段不可静默解释成新版本 |
| `generations` | 不可变目标代际与内容清单、作者/Method/Target基础 | desired是已采纳目标，不是已经实际应用 |
| `operations` | OperationRef、预期revision、动作意图、授权与恢复前像、活动阶段 | operation不等于requestId或某次Attempt |
| `files` | 受管文件的原字节摘要、前像/后像、owner、目标位置与应用观察 | 成功写调用不等于所有文件具有相同代际 |
| `events` | 时间序列中的接受、派发、观测、补偿、回滚和冲突来源 | 日志不是另一份可独立改写的当前头 |

`desired/observed/observedRevision/active/revision/fence/managed`需要在拥有者合同下解释：desired进了新代际，而observed尚未见到文件系统全部吻合，是合法恢复中间态。可重新获得的QueryCache、Catalog和UI展示索引不能反过来成为可写作者需求或现实效果账本。

## 3. 操作准入和外部派发的唯一允许路径

```text
prepare_operation(intent, sourceRevision, grant, desiredTarget):
  A0 read current real authority; check purpose, subject, lifetime, resource, provider caps
  A1 capture expected source/workspace/system preimage and actual effect domain
  A2 allocate unique persistent OperationRef before irreversible external dispatch
  A3 under the domain's atomic admission scope validate base/fence/owner/active conflict
  A4 commit operation intent, reserved resources and expected idempotency envelope
  A5 recheck dispatch authority/preimage; persist Attempt and dispatch-intent, then COMMIT
  A6 call selected provider with frozen op/attempt identity and prepared inputs
  A7 append exact receipt/observation or UnknownOutcome; reconcile under bounded budget
  A8 settle/compensate/retain Unknown; release only ended or explicitly transferred ownership
```

“准备”本身若会改变实际资源或请求远端预留，则已属于Operation，不允许以纯查询逃避journal。授权可以在派发前过期或撤销，必须重核其实际时间/范围和前像。Grant只来自真实权威；函数定义或模型声明的`granted:true`不能创造执行许可。

## 4. 一次本机文件发布的具体状态机

```text
CandidateReady → Admitted(intent+fence) → Staged(files)
             → Applying → ReadbackMatching → Settled
             ↘ ApplyFailure/ProcessCrash → RecoveryPending
RecoveryPending → ReadbackMatching/Compensating/Conflict/Unknown
```

文件发布须先锁定路径、受管区域和真实前像，再向受控临时位置写入并按文件系统提供的可靠持久化/切换协议提交。多文件原位替换**不自带原子性**：DB desired 可能已提交而磁盘在崩溃时只更新部分文件，恢复者须逐对象读回归类。存在外部并发写者、硬/软链接 TOCTOU 或不满足同步保证的文件系统时，只能采用已证明适用的弱声明或拒绝强原子承诺。

未结算操作的回滚沿原操作持久切换direction，并在成功后递增修订；已结算的操作要基于当前头创建新的逆变更。两者均不能让head倒退后覆盖较晚的合法作者工作。作者在新修改前人工采纳过的真实外部前像要保留；不能假设“上一个generated版本”必然是回滚目标。

## 5. 真实网络、金融或设备效果不同于保存文件

Provider 接入前须锁定 `effect type / actor / external idempotency capability / operation identity / revision/preimage / readback/query / timeout semantics / compensation kind / authority scope`。外发后 EOF/超时均保留 `UnknownOutcome`；协调和读回使用原 `OperationRef`，不得新建 UUID 当作未发生后的重试。重发需独立核实 Provider 的实际幂等作用域、有效期、前像和已取得回执，不能用 HTTP 状态反向推测现实结算。

金融跨库与资金效果：本机SQL单库commit只证明本库的原子修改，不证明外部银行过账；多服务采用具体Saga/outbox/补偿时，补偿是新的授权效果而不是“原事务自动反向执行”。设备执行：取消等待不代表设备停止；迟到的反馈、原有控制器可能继续运行，需要控制/急停与真实观测合同。权限撤销之后，已派发但未知结果仍要准确结算，不得通过忘记Operation抹掉风险。

## 6. 备份、迁移、恢复和损坏隔离

有状态系统启动时先检查schema版本、完整性、内容库可访问性、必要journal和fence是否连续；不能让新reader直接按自己的新字段解释旧DB。迁移在准确数据/工具链上预演，备份数据与日志满足恢复模型，失败后保持旧可读或隔离、进入显式恢复模式，不同时放任新旧writer写同一head。存储损坏不意味着必须删除所有数据重建cache；可重建索引与唯一持久真相要分层。

恢复器重读实际世界：先取得尚未settled的Operation，再按其真实provider/文件owner恢复读回。即使已过幂等窗口，也不能盲重试；宁可保持未知和人工处理Need。对能够确知没有派发的状态，可安全取消/回收，但必须保留证据支持“未派发”的边界。已结算的操作不能因为同一请求重放再次实际执行。

## 7. 故障演练的具体输入输出

- 入库前崩溃：没有被承认为admitted的不可逆操作，不留下半开Grant占用；若持久化不明确须核实际journal。
- Admitted后且尚无dispatch-intent时崩溃：完整可信journal与唯一派发路径可以支持“尚未派发”；再次派发仍重新准入。
- dispatch-intent提交后、Provider回执入库前崩溃：即使程序停在真正发送前，本地journal也无法区分已发未回，保持Unknown并消费原Operation的RetryBasis；不默认重发。
- 派发后返回前断线：状态Unknown，必须readback；若无法读回则不假定失败。
- 文件应用第2/3件崩溃：读回逐文件前像与后像，进行受权恢复或报告受阻；不称三文件原子。
- 原有writer未停止又出现新writer：fence和实际权限应阻止旧者覆盖；不支持fencing的Provider不得声明该强保证。
- 备份恢复后旧Grant已撤销：再次执行必须用当前权威，不复活旧权限。
- 外部补偿失败：保留原操作及补偿Attempt，不能把补偿请求已发送记为原交易消失。

这些样例验收的是明确的真实执行闭包，与本设计包的文档链接检查严格区分。

## 本地五表物理实现、事务程序和错误恢复

实际DDL位于[control-store-1.sql](设计资产/control-store-1.sql)。这是首次具体物理设计，不表示已在生产运行；只有显式创建的新空存储可以执行它，旧库先读format/DDL/索引/约束与根身份，禁止`IF NOT EXISTS`假装完成迁移。五类逻辑责任仍为meta、generations、operations、files、events。外部操作以`operations.kind=external`及其事件记录复用操作责任，不引入第二份同一操作账本；它不更新工作区desired/observed/active。

`meta`按root唯一保存头及受管清单；`generations`保存不可变胶囊及源/目标依据；`operations`保存精确意图、初始前像、方向、阶段、预算和已观察的授权背景；`files`保存每个路径的完整前后像和读取依赖；`events`保存按操作单调序号的尝试/观测。实际Grant仍从当前权威读取，authorization_observation不是永久凭证。大内容初版同库BLOB，在单事务内保住意图与恢复字节；以后迁外部内容库必须先持久blob再提交引用，不能把临时文件位置当已耐久内容。

Revision/fence按现行无符号64位语义保存为规范十进制TEXT，应用侧用精确整数计算增量，SQL只对规范字符串作相等CAS；DDL限制0至2^64−1且无前导零。物理CHECK还要求其真实存储类为TEXT、字节长度等于字符长度，以排除嵌入NUL后缀绕过length/GLOB边界；BLOB列显式核存储类，本地事件序号核integer而非只核非负。应用codec仍须在SQL类型亲和转换之前拒绝非规范输入。不能把超出有符号范围的修订存SQLite INTEGER或用`CAST(... AS INTEGER)+1`溢出。到最大值返回RevisionExhausted并进入显式换域迁移，不能回绕。events的event_seq是本地有符号有界序号，溢出也拒绝；它不是公共作者Revision。

连接工厂对每个连接显式启用foreign_keys并读回。数据库落在本地受信文件系统；选定WAL画像时读回journal_mode，写耐久目标要求相应synchronous设置与实际宿主证据。WAL不能自动提供网络文件系统或掉电耐久保证。一个writer执行短事务，长期读者可能阻止checkpoint并增大WAL；超过持久空间预算时停止新写、保留已入账责任，不能删WAL恢复“空间”。备份使用一致快照接口，不直接只复制正在运行的主db文件。

**prepare事务**：在事务外捕获有权输入并验证capsule/intent codec、摘要、路径冲突与载荷预算；`BEGIN IMMEDIATE`后检查根身份、同operationId是否已存在。若存在，解码并比对完整固定意图，相同则返回原记录，异意图拒绝。若不存在，插generation（已有同ID必须字节相同）、prepared operation、files和prepared event，然后COMMIT。此时不改desired、observed、revision或active，也不触碰目标文件。

**admit事务**：合作scope锁内重新读实际前像和当前授权；`BEGIN IMMEDIATE`内再次检查meta.revision=expected、active为空、prepared仍有效及完整保留空间。计算新revision/fence，保存prior_head，更新operation到admitted、写事件，并执行带旧revision和active条件的meta UPDATE；受影响行必须恰为1，否则回滚。局部索引同时禁止一个root存在两个admitted/applying/recovery-required的workspace操作。COMMIT成功以后才允许文件作用；锁住数据库不等于锁住外部文件系统。

**materialize程序**：离开SQL事务，保持实际合作scope锁，依稳定路径逐项执行。当前=后像时只读回，不重复写；当前=前像才写同目录受控temp、核字节与模式、请求同步、再次授权和核前像、replace/delete并同步目录；两者都不等则停止保留第三方字节。每项观察短事务入events和files.last_observation。只读依赖也必须重新确认。不能在SQLite写事务内调用网络/插件或等待设备。

**settle事务**：在合作锁内完成最终全部声明域读回，取得准确观察版本；事务内确认active仍为该op、fence与已准入值一致、方向未变，再更新observed、observedRevision、managed及operation终态，清active，写事件。任一比较失败为恢复冲突，不把过时读回签当前。数据库COMMIT报SQLITE_BUSY时事务可能仍活动，应按连接实际状态有限重试COMMIT或显式回滚；SQLITE_IOERR/FULL/中断须读取事务状态再决定。COMMIT响应不确定时重开后查询同op和head，不重做外部作用。

**外部派发程序**：external操作先把payload、真实Provider版本、幂等域/到期、实际作用主体、readback和补偿策略作为intent封存；资源预留在同一短writer事务中核当前未结算reservations，之后在每次真正dispatch之前写入带Attempt身份的dispatch-intent事件并提交。提交后与发送之间没有跨本地存储和Provider的自动原子性；该不确定窗口按第7节保留Unknown。恢复读取[原Operation的RetryBasis](../../50-执行运行与观测/持久化与恢复/事务提交-外部效果与幂等交付.md#attempt-finality-and-retry)，只有真实目标去重、旧尝试关闭且无效果，或原要求允许的受保护收敛才能再派发；其余继续读回/协调。confirmed与not-applied都需合格终局依据；超时不能推not-applied。资源取消和补偿各自需当前权限。

**方向与恢复**：未结算workspace操作可以在原op内持久设置rollback，按反向路径仅把本op后像恢复成真实前像；成功后revision递增，不能倒流。已settled操作建立新inverse op。人工前像恢复后只有确实等于历史generation才设置observed，否则observed为空且observedRevision为0。恢复不清除旧effects、未完成补偿或撤权事实。

DDL约束只能约束可表达的局部关系。业务codec、摘要匹配、归属、root.active对应workspace活动状态、文件模式合法性、跨事务状态变迁、全根可见性仍在适配器事务程序中核验。所有更新使用绑定参数，不把path、event kind或Provider返回文本拼入SQL。schema验证通过、内存数据库事务演练通过，都不能代替真实掉电/文件系统/远端恢复资格。

外部机制校准及适用限界见[工程施工算法与宿主依据](../../../research/sources/工程施工算法与宿主依据.md)；本章的Gift接口和组合责任仍是当前工程设计。
