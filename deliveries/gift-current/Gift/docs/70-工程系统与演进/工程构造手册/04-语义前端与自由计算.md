# 04 从任意新定义到类型化程序：前端具体实现算法

## 1. 基本目标：不是注册业务标签

当前新作者模块的 `core:type`、`core:function` 与其递归 Expr 由现行 `/2` Body 和计算 Owner 解释；内建语义不要求填写 `dialects`。旧 `/1` 中的 `s:type/s:function` 和原有Dialect映射，仅作为历史只读格式处理。`Division/Invoice/Map/UI/Graph` 等业务名不进入 Kernel 分支；新领域只要能由现有 TypeAlgebra、Value、Function、Effect、Requirement 构造，必须沿同一前端成功。真正新增的不可还原原语须由版本化 SemanticModule 取得解释资格，不能通过中央 `switch(kind)` 偷加行业例外。

首个真正编译消费者以 `fixtures/prebootstrap/Gift107` 的四个 JSON 模块为压力：类型 `Division`、有公开前置/后置的 `quotRem`、跨模块 `consumer`、泛型高阶函数与相互递归的 `TypeExpr.occurs`。同时保留 Gift106 十个结构Proposal未实际绑定Meaning的事实，不能因为外壳能解析就当作函数可运行。

## 2. 内部数据结构与不可变节点

前端第一层 `CstOrStructuredTree` 持有作者字节的真实出现位置；随后构建只读的 `ModuleRevision`：

```rust
struct DeclHeader {
    id: DefinitionId,
    public_name: String,
    kind: DefinitionKind,
    signature: SignatureCandidate,
    exports: ExportScope,
    source: OccurrenceId,
    dialect_revision: RevisionId,
}
struct FunctionBody {
    params: Vec<ParamDecl>,
    return_type: TypeExpr,
    effects: EffectRequirement,
    requires: Vec<ContractRef>,
    ensures: Vec<ContractRef>,
    expression: Option<ExprId>,
}
struct ExprRecord {
    tag: ExprTag,
    source: OccurrenceId,
    children: Vec<ExprId>,
    inferred: Option<TypeId>,
    effects: Option<EffectSet>,
}
```

内部`Option<ExprId>`区分“只有合同且委派实现”与“有实际主体”；没有主体的普通函数可保留有效公开合同但生成该使用点时需要Method/ExternalExport。结构体每个局部ID属于对应ModuleRevision；跨模块引用需携锁定模块ID/revision及定义ID。生成/变换节点不得覆盖旧节点上绑定的来源，须记录其解释和出现组。

## 3. 声明先行与可见性算法

```text
S0 严格解码所有相交模块/导入视图，确认dialect已锁定，生成只读ModuleRevision。
S1 第一遍只收 module identity、import/export、类型/函数头和显式签名，不检查主体内容。
S2 检查同模块重复ID、名义身份、导出重名、不可访问的私有定义、缺失import与版本不匹配。
S3 建立声明依赖图及 SCC；合法函数互递归允许，必须特殊拒绝有执行副作用的非法顶层初始化环。
S4 将每个主体的局部作用域按词法嵌套逐项建立：param→let后继→pattern分支→lambda闭包；不得跨分支借用同名绑定。
S5 绑定所有ref与类型引用至唯一确切定义/LocalId；无唯一引用或被遮蔽必须诊断具体位置，不根据显示名猜ID。
S6 后续双向类型及效果检查以已形成HeaderIndex为输入，并封存真正合格的CallableView。
```

`let x=init in body`中 `init`只能看到旧作用域；`body`能看到新的x。模式分支局部绑定只在本branch有效。普通递归调用可先看到函数头，但未经合法约束的多态递归不能靠无限次猜参数自动推断。导入图环不等于初始化环，更不等于运行时死锁；三者分别判定。

## 4. 类型代数与约束传播

基础值包括 Core Int/Bool/Text/Unit、List、Option、Result和名义 Record/Sum、函数/泛型及实际开启的其他画像。类型推断采用**有签名的局部双向检查**：`synth(expr, env) -> Type+Effects`和`check(expr, expected, env)`；不从未经声明的业务字符串推断类型或隐式统一不同名义类型。刚性泛型参数只能用合法实例化，避免`Any`吞掉未知类型；公开签名需要完整才可导出。

实现执行顺序：字面量按其tag进入类型域；引用查环境；call先检查callee为函数型，再按**作者实参求值顺序**检查实参，参数槽重排在求值后发生；if要求条件Bool并联合分支类型与潜在效果；let先检查初始化再将binding放入后继；match检查subject的真实ADT，分支按顺序检查覆盖/冗余/警戒并取得合并返回类型；lambda用预期函数型推动参数绑定、闭包效果行；递归/高阶函数保留独立推断条件。覆盖与不可达检查不能通过枚举无限整数域的所有值完成，不完备时返回准确判定范围。

`Int`使用数学整数语义，源 JSON值规范十进制字符串可超过JS安全整数范围。除法（向零截断/余数）和不等号必须按实际已选合同判定；不把 JS Number 的浮点溢出与舍入偷渡进前端。Bool严格布尔，不使用 truthiness。Text的Unicode标量语义与来源UTF8字节、IDE UTF16偏移、目标TS `string`三者分开表示。没有实现所要求的正确转换即为目标缺口，而不是类型推断时默许。

## 5. 效果、错误、异常和继续执行的判定

为每个已检查表达式产生 `type/effects/mayFault/progressAssumptions/actualReads`。`effects=[]` 不足以推出可能不终止或不会抛出计算错误；纯函数可递归不终止、整数可除零。短路和条件分支的右侧效果/错误只有在激活时发生，不能为优化方便提前执行；let初始化即使结果不用，只要可能错误/不终止也不能删除。

资源拥有按实际Region和唯一终结者分析：lambda捕获独占资源时不能无依据复制成可多次调用的高阶值；Effect Handler若允许多次恢复continuation，必须检查被捕获区域中是否含不可复制资源。FFI借用跨同步/异步边界时需要拥有者生命周期保证，不能将Rust借用地址序列化跨Worker。

合约检查分开 `requires/ensures/invariant`：前置限定合法调用域，不随方法偷缩；正常后置仅在正常返回执行，不能在抛异常时取未定义`result`；保持帧和世界效果独立；纯静态证明未知时不能用目标成功build替代证明。新 Method 产生的变换表达式必须再次经过类型/效果/保持检查，不相信方法自报`verified:true`。

## 6. 有主体、无主体与外部实现的三条具体代码路径

**有主体**：类型化`Expr`→受控Lowering；例如前述`occurs`的互递归在函数头先行后检查，后端依据实际target可用性选择普通递归或合法消除。**无主体**：产生 `CallableContract`；当该根真正引用时才要求 RES 选择满足它的已有方法或外部导出，缺方法时本根返回Need，不生成`throw new Error('TODO')`假实现。**原生绑定**：语义读取只消费真实public export、ABI、资源和Effect合同；不能读取外部库的“未检验源码推断”作为保证；无权读源码仍可通过合格接口调用但不可声明其内部性质。

从作者新语义到真实方法供给的公开API应包含 `resolve_definition/interpret/join/check/qualify/lower` 等已采用职责；每个Module解释结果附固定revision、实际读取、假设、缺项与预算。第三方不可信方法默认隔离，描述符不作为执行许可；具体隔离由真实平台资格决定，不能假设Rust插件天生安全。

## 7. 阶段工作结构和诊断修复链

`decodeModule` 不允许直接读取工作区、`checkModule` 不允许执行Provider；它们的输入显式传入已固定的SourceSnapshot和EngineImage。为错误保留source span、错误类别、expected/actual、引用链及能否只修改某一AuthorRegion的建议；诊断本身不是自动改写授权。

工程师应为下列输入给出不同实际输出：未声明变量、被遮蔽局部、失去import的公开定义、两个同名不同身份模块、正确互递归、非法顶层初始化环、不完整ADT模式、未绑定新语义Meaning、无实现体但允许保存的合同、运行时可能不终止但合法的函数、因为要求必须终止而不合格的实现。重命名只变公开显示，不自动改变名义身份；删除/增添约束要让原有递归分析失效后正确重算。

## 8. 源语言可扩展性的实物判定

验收开放性须采用一对独立正反例：在**同一 Kernel 构建**下，新增未预置的 `type TokenRule` 与 `function transform` 并使用现有构造，得到真实可调用 TS，期间 Kernel 零源修改；再新增确需外部原始世界 Effect 的定义，应允许保存、类型化和定位，但无 Method/Handler/Grant 时必须在效果执行处精确拒绝。这只证明选定构造的领域开放性，不证明任意现实作用可自动生成。

## 类型约束机、模式矩阵、效果与求值机的具体实现

TypeStore采用内部代数`Primitive | Rigid(binder,index,kind) | Infer(var,universe,kind) | Apply(constructor,args) | StructuralRecord(fields) | Nominal(definition,args) | Function(params,result,effectRow,callMode) | Resource(region,capability) | Extension(typeRef,payload)`。名义递归ADT保留Nominal引用，不展开为无限树；结构记录只对本Profile明确允许的结构记录使用字段对齐，不能借此把名义record变结构相等。`Extension`由已锁类型模块解释，不是任意不透明payload自动相等。

统一器按工作表处理`Eq(left,right,origin)`：先解已绑定代表元和允许展开的透明别名；相同代表元结束；Infer对结构先做kind、universe可见性与occurs检查，再记录替换；Rigid只能与同binder/index或合法外层实例一致；Nominal必须同定义身份且参数逐项统一；结构记录核字段集合再对齐；函数核参数槽与结果，并另发效果约束；其余构造不等则返回带两端来源的冲突。透明别名环是别名错误，名义递归不是occurs错误。`α = List<α>`拒绝，`Tree = Leaf(Int) | Branch(List<Tree>)`作为名义声明合法。

每次候选实例化创建fresh Infer变量；泛型定义内用Rigid检查，不能把一次调用的`T=Int`写回泛型定义。局部let无隐式多态。公开签名中未解变量不是Any。约束求解的副作用进入撤销日志：记录绑定、union父节点/秩、效果尾约束及新增义务；`probe`失败回滚全部，候选成功也只在最终被选择时commit。路径压缩若不能完整记录，probe内禁用压缩；这样避免尝试方法A污染方法B。别名/实例归约超预算返回Incomplete，不误报类型矛盾。Rust的推断快照机制可作为此类回溯实现的参照，不能把其当前内部结构直接变为Gift公开协议。

kind检查先于类型统一。启用高阶类型时Kind为`Type | Effect | Region | KindArrow`，Apply必须满足参数kind。关联类型归约以精确trait实例、type substitution、规则revision为键，用正在求解集合识别循环；只有显式共归纳且有合法证明规则的域允许循环成功，普通循环返回未完成。存在类型开包建立新universe，离开作用域前检查结果与捕获闭包不泄漏其刚性变量。高级画像没有实现时留准确能力Need，不悄悄擦成无类型值。

效果行内部为`{labels, tail?}`，label带类型化参数和资源域而非裸字符串。闭行包含判定直接比较；开放行包含把尚缺labels与尾约束入队，存在未解尾不能签纯。Handler只消去它实际处理的标签，并加上handler本体效果；多次恢复要求捕获环境可复制。局部状态不逃逸可以隐藏外部标签，但不可据此删除源顺序和可能Fault。资源检查在控制流边上传递`Uninitialized/Owned/Borrowed/Moved/Released`及region；分支汇合核每条可达路径的拥有责任，循环采用有限状态合流，悬挂借用或一条路径释放后另一条继续使用拒绝。

模式覆盖采用矩阵算法：按subject的类型选择构造器列，把每个候选构造器的字段展开为子列，通配符展开为对应数量的通配子模式；递归问新pattern能否覆盖旧行未覆盖的值。终止到零列时，旧矩阵含空行代表已覆盖；没有空行则构造见证。整数/字符串无限域不能枚举，按当前字面量/区间的端点分割等价类并保留“其它”类；List以Nil/Cons及尾模式处理。guard行不作为无条件覆盖行，除非独立证明它在该pattern域恒真；生成代码仍按源顺序求guard。OR-pattern各分支必须绑定相同局部集合且对应类型一致。预算不足返回覆盖判定未完成，不能自动插默认返回值。

语言求值的工程参照使用显式控制栈：状态`Eval(expr,env,k)`、`Return(value,k)`、`Raise(fault,k)`、`Suspend(effect,args,k)`。call帧先保存callee，再从左到右保存实参，全部求值后按参数槽排列；let保存旧env供initializer；if只进入选定分支；match保存一次subject并逐arm匹配；lambda只构造捕获环境。Fault沿清理帧退出，普通Result错误仍是值。此机器用于明确源意义和独立oracle接口，不要求目标代码带通用解释器。

自递归与互递归函数头先收集；终止证明是独立进展义务。前端检查完成后生成不可变类型/效果/合同表和未决义务；语义可保存、类型可分析、目标可生成、强保证可签发是不同门槛。该算法不要求所有纯程序先证明终止才能使用。

外部机制校准及适用限界见[工程施工算法与宿主依据](../../../research/sources/工程施工算法与宿主依据.md)；本章的Gift接口和组合责任仍是当前工程设计。
