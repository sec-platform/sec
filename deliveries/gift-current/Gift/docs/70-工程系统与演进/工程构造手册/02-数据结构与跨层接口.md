# 02 从源字节到目标产物：内部数据形态、身份及跨层签名

## 1. 实现顺序由数据依赖驱动

先建立 `contracts` 里的**不同的身份类型**，再开发读取器/编译器。一个 `string` 无法区分项目ID、模块定义ID、修订、内容OID、局部指针、目标产物、请求、操作与权限。首期实现应使用 Rust newtype 和 TS branded type；公共字节的稳定编码由已有 schema 与 codec 承担，不把 Rust `usize` 或进程内地址持久化。`SourceBlob` 可借由内容地址寻址，但 SourceRef 仍是有权源身份，两个租户使用相同 SHA-256 不意味着可共享私有派生信息。

内部身份类型的设计声明（不是新对外 wire 结构；完整联合与构造边界见本页“内部结果构造与阶段值的实际类型设计”）：

```rust
struct ProjectId(String);
struct SourceRef(String);          // 逻辑源拥有者
struct ModuleId(String);
struct DefinitionId(String);       // 定义身份，不以名称代替
struct RevisionId(String);         // 所属主体的真实修订
struct Digest { algorithm: DigestAlgorithm, bytes: Vec<u8> }
struct SnapshotHandle(u64);        // 仅当前workerEpoch有效
struct OccurrenceId { module: ModuleId, revision: RevisionId, local: u32 }
struct RootRef(String);
struct MethodRef(String);
struct TargetRef(String);
struct ArtifactRef(String);
struct OperationRef(String);       // 现实作用身份；绝不等于请求id
struct RequestId(String);         // 某连接代际内关联标识
```

`RevisionId` 只在其 owner 下解释；同一个 `42` 不能跨源相等。Digest必须包括实际算法标识与确定内容域；一个未指定内容域的`sha256`字符串不足以作为编译缓存的全面身份。当前原规范的 OID、sha256、BLAKE3及Git OID用途不同，不统一重新定义，也不用 display title/hash 冒充授权。

## 2. 十个逻辑模块的直接接口与消费路径

以下是首批实现者需要建立的**代码签名级设计**，准确方法含义消费 `docs/70-工程系统与演进/实现与装配/模块与运行实例-最终逻辑模块与公开接口.md` 的唯一职责；允许在一个文件中合并多个纯函数，不能因为方法多就建十个网络服务。

| owner | 入口（目标函数的逻辑签名） | 返回内容 | 具体调用者/不得执行 |
|---|---|---|---|
| workspace | `capture(inputs, policy) -> ProjectViewOrNeed` | 固定字节、源位置、可读权限、actualReads | application与kernel输入装配；不执行脚本 |
| workspace | `fork(base, edits) -> CandidateOrConflict` | immutable CandidateRef + Delta | application；不提交当前头 |
| semantics | `decode_module(blob, profile, budgets) -> ModuleOrDiagnostics` | 有来源的声明树、只读错误 | compiler；不选择目标实现 |
| semantics | `check(module_graph, imports, rules) -> CheckedViewOrNeed` | header/type/effect/Requirement/reads | compiler；不写工作区 |
| compiler | `compile_frozen(snapshot, roots, target, methods, budget) -> RootResults` | 完整 ArtifactSet/Needs/ReadSet/diagnostics | application；不直接执行产物 |
| compiler query | `impact(before,after,scope) -> ImpactResult` | 精确更新域和证据失效 | workspace/application；不过度失效独立根 |
| assurance | `derive_obligations(frozen,claims) -> ObligationSet` | 可验证条件、环境前提与缺项 | application、显式检查路径 |
| execution | `prepare(intent,grant,preimage)-> OperationOrDenied` | 可持久的 OperationRef，授权与前像 | 只有明确请求的application |
| execution | `attempt(op,provider)-> ReceiptOrUnknown` | 尝试/观察/未知及readback入口 | execution协调器；不由编译器调用 |
| application | `handle(tool_request,session)-> ToolResult` | 六工具之一的匹配结果和被请求动作 | entry；无二次语义解释 |
| entry | `decode_route_respond(wire) -> bounded_frames` | 精确协商的请求/进度/最终结果 | CLI/SDK/IDE；不直接调用Provider写动作 |
| bootstrap | `create_image(frozen_plugins, target_adapters)-> EngineImage` | 只读准确语义与Method目录 | control与kernel输入准备，不绑定当前用户Grant |

`application`可以先让 `workspace` 冻结候选，再用 `compiler` 纯计算、`assurance`拟定检查，并按用户许可委托 `execution` 实际执行。这里的API不产生第二个Requirement/Method/Target持久库；只有不同生命周期需要独立持久事实时保存相应稳定对象。

## 3. 五个必须在类型层分离的观察对象

1. `ProjectView`：工程ID、固定的项目/锁/源文件及缓冲快照、读权限，**不是用户当前写头**。
2. `Candidate`：从某基础生成的只读新修订，`base` 和作者Diff不可丢，不能用它对当前工作树直接LWW覆盖。
3. `EngineImage`：固定受信的语言/Method/Target解释画像与摘要；运行时剩余配额、Provider在线状态和当下Grant不放入image。
4. `PreparedJob`：按特定目的绑定Candidate、roots、target、sourceProfile、engineImage、预算及相交方法选择，禁止执行时偷偷改锁。
5. `Operation`：经过当前授权检查后的现实作用意图、持久前像、尝试与恢复状态。只有请求进入现实作用才建立它；纯编译没有这个身份。

Rust接口可以用带域参数的只读句柄：

```rust
struct FrozenCompileInput<'s> {
    snapshot: &'s SourceSnapshot,
    root_set: &'s [RootRef],
    engine: &'s EngineImage,
    target: &'s TargetRequest,
    budget: &'s CompileBudget,
}
struct RootResult {
    root: RootRef,
    basis: EvaluationKey,
    outcome: RootOutcome, // 单一带载荷联合；不存在 completion/artifact/needs 的任意组合
    diagnostics: Vec<Diagnostic>,
    reads: ReadSet,
}
```

`CompletionKind`由已采用的结果语义决定，不能借此草图新增对外枚举；实现中分开 `Ready`、`Rejected`、`NeedsInput/Method/Target/Evidence`、`Stopped`、`BudgetIncomplete`等已具有不同后继的状态。对 `Ready` 有完整 ArtifactSet 的根仍需区分源代码生成、独立 TypeScript build 成功、运行符合性、真实世界操作完成四个等级。

## 4. SourceSpan、依赖边与错误定位的表示

`SourceSpan`至少携：所属SourceRef、准确RevisionId、UTF-8 byte start/end、SourceProfile及可证明的坐标精度。行列是派生而不是唯一事实；字节范围始终是半开区间，不能跨版本照搬。跨`*.module.json`字段、扩展生成和打印目标的 `EditCorrespondence` 是关系，不是仅一个目标行号。某helper来自多段源时保存来源集；无细粒度映射时标记降级精度，不能用最近出现的同值字面量冒充唯一来源。

`ReadSet`收录的不只是实际读到的正依赖，还包括**缺失的名称、方法候选枚举范围、目录修订、否定条件、Target能力与运行身份**等；引擎升级或目录新增方法可能令过去“未找到实现”的结果失效。ReadSet不存作者源的同义副本，而存可重新核验的依赖坐标。

建议检查型式：

```text
QueryResult<T> = Complete(value:T, reads, assumptions)
               | Needs(needKinds, reads)
               | Stopped(reason,budgetConsumed,reads)
               | Invalid(diags,reads)
```

这是Rust结果设计的方便写法，**不是**新增一个公开 `QueryResult` wire 标签。已有公共结果状态及序列化以原owner为准，内部构造时必须保证同一分支确实携带合格的结果/读集/假设；失败状态不创建可签发Artifact。

## 5. 方法供给不应该被隐式字符串承载

`MethodDescriptor`需要准确方法引用、能力前提、目标支持、实现源、版本摘要、必要效果/资源/证据、ABI/工具链范围及查询时能观察的目录修订。`RealizationBinding`由 RES 产生且固定每个使用点与方法：

```text
realizationBindingRef ─┬─ SourceBody(bodyRef, ownerRevision)
                       ├─ ExternalExport(providerRef, exportRef, callRule, ABI)
                       └─ GenerationMethod(methodRef, capturedInputs)
```

若同一外部方法只保证无负权图的最短路，而用户的图允许负权，则它不是“分数较低的候选”，而是不可用。Target读到method不满足时返回选择层修复或Need，不能由目标打印器选另一算法。绑定锁的依赖身份、升迁和撤销由原binding-lock负责；上面只是具体消费安排。

## 6. 编译内部 arena 与跨语言传输边界

Rust局部 `DeclId/LocalId/ExprId` 应使用分开的newtype并附ModuleRevision上下文；允许在一次分析中使用紧凑数字索引，但禁止把裸索引写进持久锁、公开协议或跨worker世代复用。跨 Rust/TS 使用实际生成协议 DTO与不可变SourceContentRef，禁止向JSON编码裸指针或内存借用。大型源码内容按受限 `content.put`分块缓存，发布前以长度+摘要核同一内容；不能把未完成块集交给parser。

从工程建设角度，先用单线程只读图+私有builder降低错误面，再建立可复用纯值查询；将能力做快不能以共享可变AST、`static mut`全局最新候选或隐式读宿主路径实现。仅声明不可变不足以保护第三方Native可变对象，边界仍要执行实际验证/复制或合格受检视图。

## 7. 应写的测试与不可替代的实物

要求：不同SourceRef同摘要不会越权共享诊断；不同Revision使用旧span返回拒绝；缺方法在目录变化后失效；取消某等待者不使其他独立客户失败；一个根Need、另一个根Ready时各自结果准确；有Artifact但尚未build，状态不得显示“verified executable”。这些是实施者需要写出可运行用例的具体行为，设计包里的文字与有限 JSON Schema 检查不能替它们执行。

## 内部结果构造与阶段值的实际类型设计

`RootOutcome`采用不可混合的带载荷联合：`Generated{artifacts, qualification}`、`Blocked{needs, continuation}`、`Invalid{violations}`、`Stopped{reason, consumed, frontier}`。`qualification`是该生成物逐Claim的状态，不是一个`verified`布尔；Generated只证明本次目标生成边界。诊断可以包含警告，但必需输入未知、类型不合法、硬生成义务未满足的根不得进入Generated。历史生成物只放在单独的历史关联，不出现在失败分支的可发布载荷中。

生成方通过私有构造器 `seal_artifacts(plan, legality, member_closure, basis)`取得 `SealedArtifactSet`；普通模块不能new一个`Generated`绕过它。构造器检查全部成员存在且无独占路径冲突、全部必需节点已降低、导入闭包完整、字节与映射版本吻合。软件类型封装是防误用的工程措施，不替代不可信插件隔离和独立证据。

阶段值按真正不同的数据表达：

```text
SourceUnit { sourceRef, sourceRevision, profileRef, rawBytes, contentDigest, lineIndex }
ParsedUnit { sourceUnit, nodeArena, tokenSpans, decodedKeyIndex, structuralErrors }
HeaderIndex { moduleRevision, byDefinitionId, exports, imports, declaredSignatures }
BoundUnit { headers, exprArena, patternArena, scopes, resolvedUses, originArena }
CheckedUnit { boundUnit, typeStore, exprTypes, effectRows, contracts, pendingObligations }
BoundProgram { checkedUnits, useBindings, targetAssumptions, requiredOrigins, reads }
LoweredProgram { targetNodes, controlFlow, layoutConstraints, sourceRelations, obligations }
ArtifactSet { basis, roots, members, buildInputs, mappingRefs, qualificationRefs }
```

它们可以共享`Arc`和arena，不是要求八次深拷贝、八份文件或八个持久IR。`exprTypes`和`effectRows`属于一次检查结果的side tables，不在共享BoundUnit中原地填`Option`；并行检查同一节点不会覆盖彼此的类型上下文。可诊断但含Hole的CheckedUnit只是分析视图，`finalize_for_codegen`才形成能交给RES/Target的类型完整投影。原来的 `ExprRecord.inferred/effects`示意字段只允许在私有builder内使用，不进入共享已冻结节点。

持久Definition引用为 `(module identity, definition identity, selected revision)`，短期Occurrence引用为 `(module revision, occurrence index)`，arena索引另带具体arena所有权。`SnapshotHandle`由控制边界查表到`(workerEpoch, session, image, snapshot, slotGeneration)`；slot复用时递增generation，引用未释放不能复用。不能只靠Rust的`u64` newtype隔离不同Worker。

内存由三种根保护：SourceSnapshot拥有输入与位置；查询条目拥有独立可缓存的结果；响应流拥有待发送字节或pin。关闭snapshot先断新借用，再等旧借用；需要长期保留的响应先编码为自有字节或显式引用不可变内容。诊断里保留来源不等于永久pin整个工程，允许把精确span及必要片段拷出，过期源码未保留时显示“历史源不可取得”，不能贴到同名现源。

所有阶段返回`reads`和`assumptions`。失败也记录导致失败的真实读取；尚未访问的分支不能假造依赖。跨Worker只输送公开DTO、内容Ref和已校验结果，不传arena地址。序列化器逐类型使用唯一已锁codec；内部联合到外部结果的投影若缺合法wire分支，返回协议能力缺项，不新造标签或把Blocked改成成功。

诊断内部字段固定为 `code, severity, primaryOrigin, relatedOrigins, ruleRef, expected, actual, dependencyPath, recoveryActionKinds`。重复诊断按规则与来源发生位置去重，不按文本去重；错误排序固定规则优先与源码顺序。原生工具stderr只能是观察来源之一，不能直接成为可执行修复命令。
