# 保证证据与验收

<a id="source-cache-evidence-separation"></a>
## 作者事实、派生索引和 Evidence 的证明范围分开

AuthorSource/SemanticModel 记录接受的定义和要求；Projection/Index/Cache 只是访问或展示投影；Observation/Evidence 记录在特定主体、环境、时间、方法下实际取得的根据。索引命中、缓存摘要、JSON 导出及 Artifact 文件存在都不能签发运行/安全/性能 Claim，反过来一次测试或现场 Observation 也不能改写作者要求。

Assurance引用派生查询结果时必须保留其source revision、index generation和coverage，并最终落到可复核作者源或原始Evidence。索引不完整只能降低发现能力，不把未命中升级为反证。

## 完整证据裁决：事实、方法和支持强度不合并

每个 `Claim{subjectIdentity,revision,property,scope,environment,methodConstraints,threatModel,requiredConfidenceOrExactness}` 都对应独立 `ProofObligation`；证据必须能追溯 Source、Target、Provider、Policy 与环境修订、方法及参数、独立 Oracle、实际观察或形式推导、失败覆盖与残余未知。静态 Schema/字节检查仅证明对应静态性质，同一个生成器同时产出源码与期望测试不构成两个独立证明者。

`Verdict` 在支持范围内区分 `SATISFIED`、`VIOLATED`、`INDETERMINATE`、`NOT_APPLICABLE` 与 `NOT_EVALUATED`，并携带 `(validityBasis,coveredSubclaims,exceptions,dependencies,expiresOrInvalidationTriggers,methodFailures)`。`NOT_APPLICABLE` 仅在前置条件经证明为假时成立；方法没有运行、缺接口、预算耗尽、样本不足不能标为通过或不适用。作者要求不得由实际性能/现有能力反向自动降低，降低范围或改变风险接受属于独立有权决定。

证据组合依赖 Claim 的 AND/OR/conditional 结构：两个单独语言目标都可编译，不证明它们共享 ABI；一次端到端正常运行不证明崩溃恢复；多个绿灯若依赖相同错误假设并不增加独立性。证明链使用正/负依赖和版本化解释，证据失效只传到相交目标。新发标准或工具 bug 若可能使证据无效，应重判相交 Claim，不直接宣布历史当时记录不存在。

发布和安全例子：同一变更要求 `功能语义∧目标构建∧来源许可∧授权发布∧已知Effect结算` 时，其中任何一项 unknown 都阻止**完整发布** Claim，但允许仍合格的单项构建结果独立保留。验收提供错误注入、对抗 Oracle、故障恢复及陈旧证据组合，验证没有从局部 PASS 静默升级为总体 PASS。

<a id="gift95-cross-contract-22"></a>
## Rule谓词、Method资格、目标Artifact和Claim的独立证据

当 `req:rule` 的正常/失败/帧/进展被解析成ProofObligation后，每项义务都须绑定具体观察主体、输入域、源/方法/目标/环境修订、合格Oracle及前提。`normal.predicate`字段只是**一个有类型的待检查命题**，不是其真实性的证明；原生函数同名、类型检查或Schema通过只能获得相应较弱结论。

若failure/progress保持`unresolved`，完整Root的行为等价不可签发SATISFIED；允许保存完整设计、表达准确Need、让独立已闭合的子Claim各自得到有限结论。证据在其来源和版本改变后按依赖失效，过期PASS只作为历史事实，不覆盖新结果。

## 有限结构检查结果的派生凭据与独立事实

静态结构 `VALID` 只说明该字段图像符合当前提案且有限引用相容。`gift.qualification-envelope-proposal/1` 在 `fixtures/contract-closure/Gift95/schemas/qualification-envelope.proposal.schema.json` 展示如何绑定检查 `basis.files` 的确切输入字节及其 SHA-256，表达 `coverage.complete=false`、`NOT_READY_FOR_TARGET` 和逐项 Need。SHA-256 摘要不是签名或权限，不证明同一逻辑事实在不同语言、平台、时间、并发调度下行为等价。即使所有 Need 后续被补完，也必须由实际生产 Target/Runtime、独立证据与本篇 Claim/Verdict Owner 逐项授予资格，不能改写历史结构检查记录。

## 以实际观察强度陈述 TypeScript 源与 Rule 的保证

对 `replaceText` 的 Rule，可直接证实的最弱内容包括：给定实际源字节与编译器版本，导出了可调用的 TS 符号；它具有某个静态签名；通过若干具体输入的运行样本出现了 revision 增长。三类 Evidence 分别绑定 `toolchain/source/hash/options`、被检查符号/类型和具体执行输入/环境，不能被合并成“Rule 对所有输入成立”。`revisionIncreases` 的 TypeScript 返回类型是 `boolean` 不证明其纯净性，也不能证明改动前后别的文档与外部资源未受影响。

声称“所有合法输入至少 +minimumDelta”的强 Requirement，需要先固定合法输入域、值上界、Number 精度、异常/失败分支、别名观察、框架条件，再取得相应证明、全面有界穷举或足以支持限定范围的证据。样例中 `number` 到正整数的语义映射尚需检查；在接近精度/溢出边界时 `before.revision+1` 可失去严格增量。`frame`、`failure`、`progress` 未解决时，不能使包含它们的整体 Claim 获得 PASS。Runtime/多线程/远端时钟义务还需对其实际环境与调度公平性重新取证。

判定结果保存 `Claim(subject,property,scope,basis)`、`Evidence(method,observer,observations,coverage,toolRev,inputHash)`、`Verdict` 和被拒/未知的反例、作用域；静态结构通过、目标编译通过、样本运行通过分别是有价值但不等价的事实。规则/原生文件/Method/Target/Control或证据方法任一相交修订改变，先撤销受影响 Verdict，再选择可复用的独立证据或新检查，不自动保留旧 PASS。

### 边界反证会撤销对应性质，而不仅仅留下未知

对 `Document.revision` 使用原生 `number` 且未限定安全整数的 Claim，已能通过真实编译后的样本重现输入 `2^53`：`replaceText` 正常返回 `after.revision===before.revision`，同时 `revisionIncreases(before,after,1)===true`。据此应将“对所有允许的 `number` 输入 revision 数学增长≥1”判为此实现不成立，而不是仅列为尚待形式证明。正常范围的小样本通过仍有效；TypeScript 导出/签名合格也仍有效；受影响的是原先若外推成普遍正确性的结论。限制为安全整数且不溢出的域、改变表示或明确定义失败分支后，可以针对新的准确 Claim 再做证明/测试，不能修改既有失败 Evidence。

## 同一 Requirement 的失败反证与受限修复证据必须并存

保留 Gift96 原生 `number` 在 `2^53` 正常返回却无严格增长的 FAIL 证据，不能用 Gift97 新样本的成功覆盖或删除。另建基于 `Revision64` 这一确切域的 Claim：已检查 `before.revision∈[0,MAX64]`、`delta∈[1,MAX64]`、`before<=MAX64-delta`，调用纯 `advance` 后 `after.revision==before.revision+delta`，由整数代数推出 `after>before`；若超界，正常成功不发生而返回 `REVISION_EXHAUSTED`。对应的 TS bigint 实现、Node 观察与 4096 个确定性属性样本只支持该实现/工具版本/环境中的有限行为观察；若要签发产品级声明，仍需要源码到语义的等价证明或适合范围的独立验证。

强 Claim 的可核验 Evidence 至少分成数值域和 Codec 正确性、Native 正常/拒绝分支、序列化防重复字段和精度丢失、类型/ABI、存储成功事务/并发 CAS、Idempotency 持久性、未知结算恢复。前四项即使在本机得到实际结果，也不能替代后面三项。不得把“`tsc` 通过”“Node 测试通过”“Method 声明了 checkedInputDomain”“有 JSON Schema”合并命名为 Rule 全量 PASS。证据的精确主体需记录 Source Hash、文件清单、Toolchain Revision、Fixture Domain、输出及负例，并在任何相交变更时失效重查。
