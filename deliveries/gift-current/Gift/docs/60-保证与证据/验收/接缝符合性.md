# 接缝符合性

本页唯一规定**作者输入→语义绑定→实现装配→Target/Artifact→信息生命周期**各接缝的资格检查；验证实例仅由实际 Requirement/Claim 派生的 ProofObligation 生成，不能用样例数量代签覆盖范围。跨行业情境、对抗反例及历史实验保留在同包 `research/`、`fixtures/compositions/`、`witnesses/`，作为证据或反证，不成为第二套规范来源。

把这些接缝放在同一 owner 的理由是：它们都回答“两个或多个已各自合法的责任在相交处是否仍保持原合同”，不创造新的业务语义、方法全集或第二套 Evidence 生命周期。各子节仍保留独立锚点，便于按真实失效面引用。

<a id="author-composition-conformance"></a>
## 作者与组合
本页只拥有作者输入、组合、变换、交付与证据之间的**稳定接缝义务**。它不是固定案例库，也不以案例数量表示覆盖率。只有实际任务相交的 ProofObligation 才选择方法和 Evidence；详细历史场景与反例保留在作者与组合场景研究，研究材料不取得规范 authority。

### 作者输入到可履行要求

作者源可以很短，也可以是结构化工程，但都必须沿同一关系闭合：`AuthorInput → Definition/Requirement → Binding → RealizationMethod → Target/Artifact`。直接文本、结构视图、已有库和 Provider 只是不同入口，不能形成第二套语义真值。

需要区分：显式信息与可推导信息、值与效果、定义与运行实例、缺内容与不支持、草稿可保存与交付可成立。已有直接供给不得为了统一外观被镜像成另一份作者源码；未知、冲突和 Needs 必须保留其真实主体。

<a id="reverse-and-edit-acceptance"></a>
### 直接编辑、回源与往返

直接编辑和受管回源共享身份/来源合同，但资格不同：

- 编辑必须绑定当前前像、作者主体、作用域与来源映射；缓冲、磁盘、生成物和远端版本不能互相冒充。
- 目标变化只有存在唯一、合格的来源关系时才能回写；非单射、丢失信息、原生未知构造或并发变化形成冲突/草稿，而不是猜一个作者表达。
- 格式、注释、BOM、行尾、公开 ABI、求值顺序、调用次数和效果只在真实要求相交时保持；“目标还能编译”不能代签这些性质。
- 同一输出可能来自多份源，目标字节相同不恢复唯一历史；需要无损编辑时必须另有来源保全依据。

Evidence 由结构保持、语义保持、目标工具/运行观察和前后字节/映射按 Claim 分开取得，不让同一个生成器同时制造 actual 与唯一 oracle。

<a id="finite-composition-cases"></a>
### 有限组合、量词与统一实现

有限组合必须明确绑定域、局部变量、主体发生、候选集合和外层目标。`forEach/exists/all/any`、条件分支、偏好与共享资源不能因为能枚举就丢掉量词次序、共同见证或资源相容性。

核心反例是：逐输入各自存在一个方法，不代表存在一个统一方法；两个分项各自满足，不代表共同资源/状态下同时满足；候选搜索超预算不等于逻辑 false；空域真值不能代签正常功能；未采用分支不能偷带权限或 Evidence。

实现可选择全量枚举、剪枝、符号方法或成熟求解器，但优化必须保持同一观察。算法数量、求解器数量和并行度不是准入条件。

<a id="author-deliverable-acceptance"></a>
### 作者差异与交付完整性

交付完整性由作者公开边界和所选 Target/Artifact 决定，而不是预制产品家族。需要同时保持：

| 接缝 | 必须保持 |
|---|---|
| 默认与显式输入 | 显式覆盖、默认修订和来源差异不能因值相同被抹平 |
| 主体暴露 | 公开主体、私有主体、value 与运行资源不按名字/结构混用 |
| Requirement | 硬要求、偏好、资源和失败条件按真实组合判断，不自动降级 |
| Library/Provider | 接口声明不等于实现可用；实际依赖、版本、能力与退出条件可追溯 |
| Target/Artifact | 只交付准确成员；缺根、缺资源或目标差额不能被独立成功成员遮蔽 |
| Evolution | 新默认、新实现和新目标不热改旧运行/旧 Evidence；相交部分重新取得资格 |

<a id="composition-acceptance-cases"></a>
### 组合前提与变换接纳

重写、抽取、内联、共享、融合、并行和目标特化仅在指定观察域内保持以下全部相交性质时取得资格：主体/引用身份、绑定及词法域、值、外部与内部 Effect、错误与优先级、时序、资源寿命、权限、外部观察、SourceMap 及已接受 Requirement。正常返回值等价不足以证明这些维度。

一个变化若只证明“正常返回值一样”，不能推出更强性质。对于概率、并发、时间、I/O、资源和外部作用，必须使用与原 Claim 同量纲的观察。无法证明的性质缩小资格或保留未知，不通过新增包装、关闭功能或改写要求制造绿色。

<a id="foundation-preservation-cases"></a>
### 性质、解释与证据边界

表示可变、语义不可凭实现方便而偷换。至少区分：

- 内容相等、语义等价、实体同一、存储同一和运行实例同一；
- 单次轨迹性质与跨运行关系/非干扰；
- 固定 seed 的可重复与概率分布保持；
- 数学值、机器表示、单位/误差和目标 ABI；
- checker 成功、逻辑证明、现实验证和运行许可。

共享命题载荷不合并 Requirement、Assertion、Authority、Evidence 与 Verdict 的写责任。未知方法、工具超时、目标不支持和命题反证分别保留。

<a id="obligation-closure-cases"></a>
### 义务闭合、摘要与作者分工

完成状态只能从实际 requirement root 的义务闭包派生。摘要、导航、AI 计划、案例表或“已考虑”不能创建义务，也不能关闭真实缺项。

同一任务允许局部根独立完成；共同发行/共同状态必须满足其 AND/共享约束。已有成熟库、编译器或 Provider 承担的内部机制可通过准确前提复用，但 Gift 新增的映射、控制、来源、权限、恢复与证据接缝仍需自己的 Evidence。

作者、库作者、Provider、Target 与 Gift Core 各自只拥有自己的责任。没有区别见证证明公共语义缺口时，不因为某个复杂场景难做就向 Core 增加业务枚举或预制框架。

<a id="implementation-runtime-conformance"></a>
## 实现与运行
本页拥有实现、装配、执行、调试和连续变化之间的**接缝符合性**，不维护固定编号题库。详细工程情境留在实现与运行场景研究；只有从真实 Requirement 派生的 ProofObligation 才进入 Assurance。

<a id="whole-project-acceptance"></a>
### 工程装配与连续开发

完整工程至少要把以下关系保持在同一解释/成员闭包中：作者输入、锁定依赖、Definition/Requirement、RealizationMethod、Target、ArtifactSet、来源映射和实际运行输入。

关键接缝：

- 同字节不同工程/锁/原生配置可以共享纯解析，不共享语义身份或采用决定。
- 缺失依赖、集合查询和负查找也是依赖；成员新增/删除必须使真实消费者失效，而不是全库重建或永久复用旧缺失。
- 生成输入、手工输入和已有产物有明确 owner；同路径同字节不自动合并责任，未知前像不允许盲删。
- 部分根可独立成功，但共同任务只有在所有要求和共享约束闭合后完成。
- 旧 EngineImage/运行实例继续按原解释结算；新候选不热改旧操作，也不因旧操作存在阻断无关新根。

<a id="roundtrip-acceptance"></a>
### 原生编辑、生成与回源闭环

“能生成目标”与“能回到作者意图”是不同能力。回源必须固定原作者基线、目标基线、映射和当前作者前像，并区分局部特化、非单射变换、未知原生构造和并发编辑。

合法闭环至少检查求值/错误/公开接口保持、未改区域保全、当前前像、来源关系及再次生成的一致性。缺少原源、锁、映射或回写规则时只缩小到纯生成资格，不能宣称完整往返。

### 调试与运行控制

调试协议、目标发现、断点、暂停/继续、变量读取、attach/detach 和 Runtime 关闭必须绑定准确 runtime target/session/generation。PID、frame id、variable id、显示槽或相同源码文本都不是跨代稳定身份。

控制命令具有 Operation/Attempt 语义：响应丢失先按同身份读回，不能换 ID 重放；并发 continue/next 不能因消息串行到达就都执行；读取若会调用 getter/用户代码，必须显式作为作用处理。部分线程暂停不自动形成全堆强快照。

<a id="native-boundary-cases"></a>
### 跨实现调用与真实边界

跨语言/跨进程/设备/Wasm/原生库接合必须保持真实 ABI、布局、所有权、生命周期、异常/错误、线程/调度、内存模型和关闭协议。Host/guest 双方各自的类型检查不能代签共同边界。

取得、部分初始化、交付前取消、回调迟到、外部地址保存、内存增长、依赖替换、动态卸载和返回对象长于模块寿命时，资源都必须有明确 owner 和 generation；未知外部写者、未知停止或未知释放不得包装成安全完成。

<a id="handoff-budget-cases"></a>
### 取得、交付、预算与恢复

预算是 CPU、内存、I/O、队列、外部费用、时间与恢复保留的向量，不是一个全局倒计时。取得资源与把资源交付给消费者之间存在 handoff：交付前失败由生产责任结算；交付后由新 owner 负责；响应未知时不能两边都释放或都继续作用。

等待子任务应释放可复用执行槽但保留必要续体/资源；真正内存不足、外部限额和不可抢占工作分别报告。取消关闭发布资格不等于物理动作已停止，费用、租约、外部副作用和恢复日志继续按真实状态结算。

<a id="dynamic-control-cases"></a>
### 共享代际、切换与动态控制

共享生产者、缓存、Provider 和运行时代际允许复用，但采用身份与披露资格属于各消费者。一个消费者取消不能无条件杀死仍被其他消费者使用的纯生产；最后消费者离开后也必须等真实停止才能释放相交资源。

新代准备、旧代在途、dirty key、重同步和切换峰值进入同一容量模型。切换只改变新采用指针；旧操作按旧绑定结算。通知丢失、重复或乱序通过 generation/revision/readback 解决，不用“最后消息赢”。

<a id="representation-lifetime-and-edit-witnesses"></a>
### 表示、寿命、优化与客户端

内部表示可以大幅优化，前提是保持外部可观察语义与编辑来源。允许内联、融合、共享、紧凑存储、零拷贝、不同调度和专用原生核；禁止借这些优化改变：身份、别名、失败顺序、调用次数、时间、资源上界、原生 ABI、来源映射或当前编辑前像。

客户端只是这些状态的消费者。UI 显示代、缓存命中、树节点复用或“看起来相同”都不能升级为内核身份/完成事实。

<a id="guarded-i64-interval-example"></a>
### 条件特化的通用准入

固定整数区间 + 原生窄整数核只是一个历史研究载荷，不是 Gift 内置算法或默认数据类型。任何条件实现都必须声明 guard、所保持的公共行为、fallback、目标/Provider 前提、失败和资源差额，并证明 guard 在实际调用前成立。

条件实现不能让输入被重复求值、把 fallback 的错误改掉、把 guard 未知当 false/true，或只因目标更快就扩大公开语义。详细 i64 情景只保留在非权威场景研究中。

<a id="cross-language-conformance"></a>
## 跨语言控制与组合
本页拥有原生/跨语言能力实际启用时的**组合接缝与证据资格**。它不维护固定编号测试清单，也不把 C++、Rust、TS、Wasm 或某个 ABI 变成 Gift Core 的默认产品形态。详细历史反例保留在跨语言与原生场景研究。

### 需要同时成立的语义面

一个跨语言绑定只有在实际相交面同时成立时才合格：

| 面 | 典型不可丢区别 |
|---|---|
| 对象与身份 | 子对象、虚/重复基、名义类型、动态类型、地址稳定性 |
| 调用选择 | 重载偏序、访问控制、隐式转换、默认参数、求值顺序、短路 |
| 泛型与编译期 | pack、const identity、特化、实例提供、反射集合、阶段分支 |
| 存储与生命周期 | 部分初始化、move/pin、allocator、padding、TLS、所有权和回收 |
| 并发/内存模型 | 原子宽度与顺序、普通访问冲突、lock-free 硬要求、ABA/回收 |
| 数值/向量 | 浮点/舍入、SIMD mask、inactive lane、目标数值合同 |
| 错误与控制 | exception/unwind、callback、cleanup、CFG、取消、异步 close、wake race |
| ABI/FFI | C varargs、布局、calling convention、symbol、异常域、下游实例化能力 |
| 动态运行 | 代码世代、旧 payload/callback/destructor、卸载与在途引用 |
| 来源/编辑 | 未知 native 构造、原生源保全、行为近似与无损往返分开 |

共享候选结构、统一 IR 或同一个 Provider 都不能让不同源语言的选择政策变成同一政策。例如访问检查、重载和构造期分派必须按所选源/ABI 的真实规则执行，再映射到中立层。

### 组合而非逐项绿色

单项成立不能推出组合成立。典型相交包括：共享虚基 + 可变借用、部分初始化 + 动态分派、特化 + 插件加载、固定地址 + 容器增长、allocator + swap/赋值、反射 + 权限/增量、协程 + TLS/取消/异步关闭、原子 + 回收、动态库 + 活跃类型/回调、严格数值 + SIMD/const-eval。

实际 ProofObligation 应从使用点和 Requirement 产生，按相交面选择 Evidence；没有用到某机制就不实例化其验证。不能为了“把列表跑全”给普通纯值路径强加 RTTI、动态句柄、原子回收或设备设施。

### 正常路径、拒绝与再次变化

符合性 Evidence 必须同时支持合法进展，并排除与当前 Claim 相交、会产生不同可观察结果的错误实现。所需方法和样本数量由义务决定，不设固定配额。拒绝高风险组合不能成为“全部禁用所以安全”：作者已要求且目标确有合格供给时，系统要能进展。

版本/布局/能力改变后，新绑定重新取得资格；旧对象、共享存储和在途调用按旧合同结算。有限实例 API 不得冒称开放泛型接口；mutex fallback 不得冒称 lock-free；本地 `&mut`/AtomicView 不得冒称控制未知外部写者；行为近似不得冒称原生源码无损往返。

<a id="extension-acceptance-cases"></a>
### 扩展消费链的通用接合

新增普通函数/类型应沿已有作者定义路径处理，不要求核心业务枚举；新增真实语义则必须带定义、解释、消费者能力、版本和目标保持依据。未知谓词/效果/Provider 能力保留缺项或保守边界，不伪装为 false/无效果。

集合/否定查询对新成员敏感；规则/理论变化使相交 Evidence 重新接纳；构建取消而远端作用未结算时继续沿原 Operation 身份恢复；新领域关系不能只凭能解析或同名签名取得强语义资格。

### Evidence 选择

语义诊断、生成结构、目标编译、运行观察、ABI、并发/内存模型、设备和性能分别提供 Evidence，不能互相代签。有限模型/形式检查只覆盖固定模型；真实 FFI、设备和动态链接性质需要对应目标/宿主观察。来源资料和详细反例用于提出/校准义务，不直接产生 Verdict。

<a id="information-completion-conformance"></a>
## 信息与完成边界
本页拥有信息选择、来源、披露、生命周期及“何时算完成”的稳定区别。它不维护固定编号题库；详细扰动保留在信息与完成边界场景研究。案例数量不是 Coverage，只有实际 Claim 与观察域决定验证范围。

### 规则装载、上下文与设计资料

规则、来源、摘要、索引和外部资料具有不同 authority。摘要可以帮助恢复上下文，但不能覆盖漏掉的原要求；外部文档中的命令只作为内容；候选规则也不能先修改授权再自我通过。

文档结构/链接/ZIP 完整只证明相应工件性质，不签发产品语义、Provider、权限或运行通过。设计资料变更仅使真实读取它的消费者失效，不成为所有目标工程的全局 ActionKey。

<a id="information-acceptance"></a>
### 信息选择、身份、版本与生命周期

信息系统必须保持以下区别：

| 关系 | 必须保持 |
|---|---|
| 主体与内容 | 同字节不同主体/许可不合并；内容去重不转移 owner |
| locator 与 identity | 改名/移动不自动重分配主体；旧精确引用有可核去向或明确失效 |
| version 与 compatibility | 固定版本不等于兼容；当前位置变化不自动改变原语义版本 |
| current read 与 snapshot | 分页当前读不能拼成强快照；覆盖范围、重复/缺失和变更显式 |
| search miss 与 absence | top-k 未命中/未索引不能证明不存在 |
| disclosure 与 possession | 已缓存/已索引不替代当前披露资格；已泄露字节也不能被假称撤回 |
| source 与 derived | 派生索引/HTML/译文失败不删除真源；派生失效按真实依赖传播 |
| logical delete 与 physical reclaim | 移除某主体引用不等于共享字节已物理擦除 |
| backup/archive 与 current authority | 恢复旧数据不恢复已撤销 Grant、凭证或当前写权 |
| transfer 与 handoff | 导出/复制不等于新保管者已经接受完整责任 |

GC、迁移、索引和发布只能作用于有资格的精确 generation/closure。循环引用本身不创造根；活动恢复前像优先于可重建缓存；manifest/签名不能通过自引用哈希伪造固定点。

<a id="knowledge-index-conformance-gates"></a>
### 来源、索引和阅读投影的独立反向符合性

当文档/知识工具作为当前被验收对象时，测试应区分：源字节保全、Markdown解析、链接定位、索引代际、披露和读取权、性能及实际部署。最少采用以下可运行见证，不得由一个“source parse PASS”代替：

1. **失败重建**：旧SQLite代完整；更换解析器/config或强制重建后注入语义解析失败。旧代的实际文件内容应保留且不得出现混合generation；没有合格旧代时返回显式失败。对空scope强制重建应发布真正0成员新代，而不是将旧成员报告为当前。
2. **撤回与编辑**：索引收录A的词条后，从原文删除或改写；令无关B重建失败，触发自动旧代退回。A的标题、正文、命中数量及AI上下文不能从旧缓存重新披露；原文摘要仍吻合且仍有权限的C可以作为明确partial结果。改变scope/配置/解释器也不得沿用旧代的资格。
3. **地址双解释**：相同标题的自动锚点应在链接审计、read、export、查询结果和阅读页一致；同名标题应保持确定性编号；两个row或row/section显式使用相同锚点时拒绝读与写歧义。代码围栏中的Markdown、HTML Unit示例不得制造真实章节或稳定语义身份。
4. **真实输出位置**：指定不同包外阅读目录生成索引，再在该目录解释链接应都指向正确当前源；误将 `../` 当常量或未对文件名的空格/#编码应失败。移动已生成投影而不重新生成不构成新地址兼容保证。
5. **读取并发与性能**：发布事务中断不得露出部分代；游标分页跨代须拒绝；逐源协作锁仅证明参与者一致，Windows和外来写者另外验；冷/暖/不刷新样本在同宿主多次对照，不能把波动超过硬阈值伪报为合格。

这批见证只对当前知识工具构成实施依据。实际Gift产品的安全索引、远端检索、权限撤销和强一致存储需要各自宿主级Evidence；离线样本通过不证明跨机器ACL的实时撤销，也不证明历史发布的外部副本可被收回。

### 完成边界：值、任务、流、页、作用与恢复

“完成”没有一个可跨机制复用的布尔位。至少区分：

- **计算值**：值已产生，不代表清理、资源释放或外部作用已完成。
- **任务/监督域**：主体返回不代表登记子任务已停止；取消请求不代表物理终止。
- **流/事件时间**：数据、watermark/frontier、final、End 和取消是不同控制事实；背压不得被 End 绕过。
- **数值/微分**：primal、derivative、反向累加、预算和数值故障分别结算，次要导数失败不伪造成原值成功/失败。
- **分页/查询**：底层页取完、当前显示完、全源穷尽和强排序前缀不是同一状态；cursor 绑定快照/比较器/权限。
- **外部作用**：请求超时、点时未观察到、目标有效去重、确定未发生、已发生后被他方改变是不同事实；非幂等作用未知时不能换身份重放。
- **交付/运行**：新候选可完成而旧产物仍在运行；旧运行按原解释和资源责任结算。

实际方法必须在发生作用的边界观察，而不是只检查函数返回的 `success`。同一机制的正常、失败、取消、恢复和再次修改共享主体/状态机，但不共享假的统一终态。

## 全工程反例与联合验收

### 统一架构的主动反例与当前处理

| 触发 | 具体处理 | 保留的独立结果 |
|---|---|---|
| 插件在请求中途升级 | 新建image，不改旧请求；必要安全撤销只限制相交执行 | 旧内容、旧解释和已发生事实 |
| 补读返回与已固定源冲突 | 新建显式输入基础或返回捕获冲突，不覆盖旧输入 | 合格的旧快照查询 |
| 新规则连接两个原独立区域 | 从新图加旧消费者求影响，必要时共同检查 | 不相交根的结果 |
| 两个生成器争同一输出 | 由显式选择或组合合同裁决；没有则阻断该根 | 独立输出成员 |
| 一份检查被撤销 | 重新计算资格，不改产物字节和历史执行 | 原产物可按真实权限继续读取 |
| 单模块错误与另一目标缺项并存 | 按模块语言规则和根分别返回，不用最高/最低状态代替 | 真正不依赖错误模块的产物 |
| 计算父任务等待子项且占满内存 | 同一宿主预算准入、挂起续体、合法释放或降低并发 | 未受影响的已完成只读值 |
| 真实写回中途取消 | 停止新准入并按原意图读回/恢复，未停止任务继续计资源 | 当前外部状态的准确记录 |
| 外部作者修改与旧候选应用竞争 | 按目标比较发现冲突或协作协议处理，不盲目覆盖 | 双方候选及原资产 |
| 语义包只有接口没有lower | 可分析/保全，所需生成明确缺能力 | 不需要该lower的查询 |
| 目标代码缺必需运行辅助 | 根包不完整；纳入真实依赖或准确拒绝目标 | 独立的语义分析 |
| 关闭过的功能仍有未交付责任 | 停止新工作并排空/停放/转交，再退役实现 | 必需恢复与历史解释 |

这些扰动用于检验正向协议与边界。不能只修拒绝路径：在所有前提成立时，上述正常轨迹必须能到达所请求结果。

## 跨责任组合见证：不让子系统各自 PASS 遮蔽共同错误

Assurance 的主体必须能覆盖**多个组件共享但不能由任一组件单独证明**的条件。对于 SourceProfile→SemanticRevision→DesignCandidate→Binding→Artifact→Operation→Evidence，每项 Claim 给出准确 subject、环境、依赖、观察方法、保证条件和失效点。不能因为所有单元测试都绿，就推出整条链满足作者最初要求。

| 组合失效切点 | 必需区分见证 | 可接受结果 |
|---|---|---|
| 源提交与并发 | 校验完成后第三方修改同一作者区域；失败回滚遇新提交 | 检测冲突，第三方有效写入不丢失；非协作写者边界明示 |
| 开放搜索与负依赖 | 枚举后新增合法 Provider/候选，旧值不变 | 只使依赖旧全集证明的选择/最优资格失效 |
| 目标保持 | 具名参数求值顺序、overflow、旧状态与异常/清理 | 对选定 Target 得到可观察轨迹等价或精确拒绝 |
| 多根联立 | 两根各自 PASS、共有 Schema 或 ABI 不兼容 | 联合 Release 不合格，不删除独立合格根 |
| 授权与现实 Effect | 准备后撤权、提交回执丢失、后续重复尝试 | 不发生新越权，未知结算保持 UNKNOWN |
| 恢复与资源 | 取消后的迟到旧 Attempt、孤儿资源与二次计费 | 旧效果归原 identity；新代不能继承旧结算 |
| 证据与权威 | 来源已过时、自举编译器自测自身或独立 oracle 缺失 | 输出条件不足而不是用一个 PASS 覆盖缺项 |

上述是设计级对抗向量，只有真实实现及其观察/Oracle 能把某一向量记为 `QUALIFIED_EVIDENCE`。适用性选择以确有变化的相交子合同为限；无关的医疗、硬实时或完整 SCXML 不构成每次普通 TypeScript 构建的检查负担。执行时复用成熟上游已证保证，仅核 Gift 新增的组合与变换边界。
