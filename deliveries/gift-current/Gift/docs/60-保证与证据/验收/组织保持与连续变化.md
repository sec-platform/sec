# 组织保持与连续变化符合性

> 本页拥有“组织、布局、树形出现、连续变化与恢复接缝如何进入 Assurance”的公共符合性合同。它不维护固定案例库，也不要求把研究目录逐题执行。具体反例保存在组织与连续变化反例研究，仅用于发现区别；真实验证由准确 Claim 派生 ProofObligation，再选择适合的方法与 Evidence。

## 适用范围与判定单位

当一个变化跨越两个或更多 owner，且任一方的局部成功可能掩盖整体语义损坏时，创建相交的 ProofObligation。典型接缝包括：语义实体与多个视图出现、作者结构与物理布局、候选与当前采用、编辑与发布、发布与恢复、目标表示与共享合同、树形导航与权限披露、生态解析与最终制品。

判定单位不是文件数、目录深度、截图、测试数量或“某个页面能打开”，而是准确的 `Entity/Definition/Requirement/Binding/Artifact/Operation/Claim` 身份、revision、前像、消费者、作用域和可观察结果。若某项结论只能在特定 Target、Provider、宿主、配置或权限下成立，Evidence 必须绑定该环境，不能提升成全局支持声明。

本页只规定**什么差异必须保持、什么失败会反转结论、谁拥有最终规则**。方法数量由真实风险和可判定性决定；形式证明、静态检查、差分、故障注入、真实构建或运行证据按 Claim 选择，不设“一类至少一条测试”的配额。

## 身份、出现与组织接缝

同一语义实体可以在多个目录、树节点、目标表示、文档或查询结果中出现；出现身份不等于实体身份。符合性至少保持：

- 同一实体的多个 `ViewOccurrence/Use/Projection` 可以拥有不同父路线、展开状态和选择状态，但不得因此复制成多个可独立写的 authority；
- 同名、同结构或同字节对象不能仅凭名称/hash 自动合并；名义身份、owner 与 revision 仍由原合同决定；
- 一个物理成员可以承载多个语义主体，一个语义主体也可产生多个 Target/Artifact 表示，因此“一个实体一个文件”不是系统不变量；
- 树包含、语义引用、初始化、事务、能力隔离等关系各有自己的边类型，不能为了得到单一 DAG 把不同关系压成目录父子关系；
- 事务、隔离、共享资源和联合不变量由真实运行/存储/权限边界拥有，移动文件或创建目录不能替代这些合同。

相关规范由[多维工程组织与树形落位](../../70-工程系统与演进/信息与生命周期/多维组织与树形落位.md)及各语义 owner 持有。本页只验证跨 owner 接合没有改变它们。

## 布局、候选与负依赖接缝

布局器、解析器和候选选择不得把“当前看见的正输入”误当成完整世界。需要保留：

- `preserve` 模式可以把旧合法布局作为输入；`canonical` 模式只有在相同完整输入下才承诺相同结果，两者不能同时宣称“消费历史”又“与历史无关”；
- 名称查找、导入、成员集合等必须记录会反转结果的**负依赖**，例如“此名称当前不存在”；后续新增成员时相交分析需要失效；
- 目标/生态规则只扩展到真实共享接口和消费者闭包，不能把某 Target 的 ABI、布局或 feature 要求强推到不相交目标；
- 多根共享配置、共享 Provider、共享资源必须用同一真实配置见证联合可行性；分别在不同配置通过不能拼接成联合 PASS；
- 成本、风险、时间、内存、费用等不同单位不能直接相加成伪评分；未知量保持未知；
- 并行搜索、预算耗尽或宿主截止只允许报告已探索范围、已验证可行候选和最优性限制，不能把最早返回/最后发现候选提升为确定最优。

候选与当前采用的区别由[选择与当前效力](../../70-工程系统与演进/信息与生命周期/对象关系与配置基线.md#selection-and-current-validity)拥有；符合性 Evidence 不得因为候选通过就修改 current head。

## 编辑、发布、取消与恢复接缝

一旦产生真实作用，恢复责任高于“重新计算一个看起来等价的结果”。符合性必须能够区分：

- 纯规划候选、已授权待执行、部分作用已发生、结果未知、已读回 terminal 等不同阶段；
- 生成基线、用户工作树和新生成结果之间的三方关系；
- 源/目标在执行期间被合法并发修改时的前像失效；
- 大小写、symlink、硬链接、根外路径等宿主身份与字符串路径的差异；
- 新布局已采用但旧进程/旧回调/旧数据仍消费旧代的共存期；
- 写回映射不唯一时的待决状态，不能按文本最近位置猜 owner。

未知结果必须先按原 `Operation/Attempt` 身份读回；不能通过创建新候选、重新执行或删除 journal 掩盖旧作用。真实原子性只在底层 owner 能保证的域内成立，多文件/多服务流程必须准确报告部分完成和恢复边界。

## 文档、来源与交付接缝

文档重组、历史保全和派生导航只在各自范围内证明事情。符合性要求：

- 当前规范、历史版本、冻结范本、研究材料和派生索引拥有不同读取角色，历史字节不能因新规范出现而被重写成“当前实现”；
- 重写不得吞掉否定、量纲、条件、时间/版本、消费者、证据等级或未知状态；标题/链接都正常并不足以证明语义保真；
- 可重建索引可以退役，唯一迁移前像、provenance、恢复记录不能因位于 `_meta` 或缓存目录而被机械删除；
- ZIP/manifest/链接检查只证明对应工件属性，不能转签产品运行、Provider 能力、权限安全或业务正确性。

需要历史语义核对时，应比较准确前像与当前 owner，而不是用“文件数相同/更多”代替内容保持。

## 树形导航接缝义务

树形客户端必须把“主体”“出现”“查询覆盖”“显示状态”和“工程作用”分开。至少在相交 Claim 下证明以下区别没有丢失：

- 同一主体可以多次出现；不同 `Use/Occurrence` 不得按主体名或内容 hash 错误去重；
- 合法语义环只在当前祖先链形成引用叶，不得全局禁止环或无限递归；
- 未加载、完整空集合、Provider 失败、权限受限、分页未尽、全域未知是不同状态；
- 旧 cursor、旧配置、旧权限或旧 revision 的迟到结果不得接入新查询基础；
- 过滤时用于路径定位的祖先不自动成为命中，局部已加载无命中不等于全工程不存在；
- 全结果批操作必须冻结用途、基准和完整选择域，不能把“当前可见行”或未来对象偷偷并入；
- focus、展开、折叠、预览等 presentation 行为本身不取得保存、部署、Binding mutation 或其他工程效果权限；
- 重命名若有合法 identity mapping 可以延续出现；删除后重建同名对象不能继承旧身份、权限或书签；
- ACL/披露范围缩小时应清理相交缓存、计数、tooltip 与选择资格，同时保留不相交公开子树可用性。

具体失败构造见组织与连续变化反例研究；正式树协议由[树形导航与结构投影](../../80-开发者与接口/客户端/树形导航与结构投影.md)拥有。

## 生态、Target 与交付出口接缝

Provider/生态解析可能改变候选资格、feature、共享实例、许可、成本或目标能力，因此“解析前选择通过”不能直接变成 Artifact 资格。符合性需要绑定实际解析结果并验证：

- host 与 target、build 与 runtime、共享与独占实例、直接与传递能力等作用域不被合并；
- 相同 lock 不意味着相同 target/profile/features/rustflags/physical input，也不能自动复用二进制或性能 Evidence；
- Provider 超时、无权限、未缓存是 `Needs/UNKNOWN`，不是“该候选不存在”的全域 `UNSAT`；
- 新执行资格被撤销不抹掉历史选择与旧实例的恢复责任；
- 多 Provider 的本地版本向量只有在有额外证据时才能支持跨源一致快照 Claim；
- 生成源码、构建、安装、部署、采用、运行和退役分别需要自己的真实前提与 Evidence，前一阶段通过不能代签后一阶段。

Target 扩展本身服从[开放 TargetProfile 合同](../../40-目标与制品/目标/README.md#open-target-profile)，不能由本页引入中央产品族或 Target 枚举。

## ProofObligation 路由与关闭

当变化命中上述接缝时，Assurance 记录准确 Claim、主体、revision、环境和会反转结论的失败模式，再把 ProofObligation 路由到真正的 owner 与 VerificationMethod。没有真实 Claim 时，研究反例保持研究身份，不生成待跑队列。

可以关闭某项设计问题的条件不是“案例表全绿”，而是：公共合同已能区分合法/非法状态；相交 owner 的责任与恢复路径明确；当前 Claim 的 Evidence 足以支持其限定结论；竞争失败模式没有被未知输入掩盖。若新反例只暴露实现或接合错误，应修实现/接合；只有它证明现有公共合同无法表达一个会反转结果的区别，才重开 Core/Standard Semantics 设计。
