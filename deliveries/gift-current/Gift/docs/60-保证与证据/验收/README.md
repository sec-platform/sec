# 符合性、验证方法与区别见证

本目录保存**可复核的验证方法、跨责任接缝和少量高价值区别见证**。它不是文档单元测试目录，也不是“所有场景都要跑”的案例库。一个项目只物化与其实际 Claim、实现、Target、运行环境和风险相交的验证义务；没有真实实现或执行条件时保持“尚未取证”，不能用更多书面案例代替 Evidence。

产品/行业深度分析及 IDE、事务型应用等完整组合由同包[研究入口](../../../research/README.md)提供；它们是有用研究，不成为本层的业务规范或强制测试清单。能真正否证公共抽象的跨域差异才提炼到[跨域区别见证](跨域区别见证.md)。

这里的“符合性”表示如何判断某个准确合同是否被保持；“验证设计”表示要取得什么证据；二者都不代表已运行或通过。测试文件数量、案例编号数量和行业数量都不是覆盖率。

## 主要入口

- [方法与独立证据](方法与独立证据.md)：从 Claim/义务选择方法、独立性、故障注入、形式/运行证据与裁决边界。
- [验证计划与证据编排](验证计划与证据编排.md)：把实际 Claim 派生为需要执行或复用的 Evidence 动作，不复制 Claim/Evidence schema。
- [全域接合检查](全域接合检查.md)：只维护跨责任接合如何选择验证，不枚举行业测试全集。
- [跨域区别见证](跨域区别见证.md)：保存少量脱离行业名后仍改变合法性、运行、恢复或 Evidence 的反例。
- [作者与组合符合性](接缝符合性.md#author-composition-conformance)、[实现与运行符合性](接缝符合性.md#implementation-runtime-conformance)、[公共语义符合性](公共语义符合性.md)：验证公共合同在真实消费路径上的保持。
- [开发面符合性接缝](开发面符合性接缝.md)、[控制与演进区别见证](控制与演进区别见证.md)、[信息与完成边界符合性](接缝符合性.md#information-completion-conformance)：专门攻击 authority、阶段、Effect、恢复和信息边界偷换。
- [跨语言控制与组合符合性](接缝符合性.md#cross-language-conformance)：只在相应原生/跨语言能力实际启用时实例化。
- [组织保持与连续变化](组织保持与连续变化.md)、[会话集成与结果复用](会话集成与结果复用.md)：定义组织变更与集成操作的动态 ProofObligation 接缝；不维护固定案例题库。
- [经验验证与测试生成方法](经验验证与测试生成方法.md)、[覆盖与收益判据](覆盖与收益判据.md)：拥有自动生成/形式方法和 Coverage 的方法论，不要求每个项目采用全部方法。

[工程决策覆盖坐标](../../00-系统与原则/设计方法/工程决策覆盖坐标.md)、[需求发现坐标](../../00-系统与原则/设计方法/需求发现坐标.md)和[接合边界检查](../../00-系统与原则/设计方法/接合边界检查.md)属于设计发现方法，不属于验收套件。
