## 业务选择与规范完整性的独立验证范围

`Gift137`有限静态检查器只核验以下可从冻结来源确定的命题：新增字段符合候选Schema、分支目标/步骤类型/角色引用存在、两种证据处理表述互斥、优先级不重复、状态/事件名称有效、带义务的规则具有内容引用、组件端口方向正确，以及部分没有资格时必须返回Needs而非成功。它不执行Meaning、证明互斥、决定跨签发者规范层级，也不运行真正的Method或目标系统。

产品级保证至少须分别证明：①观察在指定域确实完整并能区分 `T/F/NEITHER/BOTH`；②多路线排他性或优先处理不会吞掉未知及冲突；③同状态/事件候选可明确执行且保持不变量与进展；④义务具有有权解释、实际触发与履行观测；⑤端口双方的操作、类型、错误、效果、资源及版本相容；⑥所选目标根中的共同资源、权限和义务全量联合；⑦生成的实际产品在指定环境下满足其可被独立观察的合同。每项Claim携带源修订、外部解释版本、时间域、对象范围与证据来源；任一条件失效须撤回对应Claim。

特别对抗案例：同一分支的 `NEITHER` 与 `BOTH` 必须得到不同的作者处置；有两个合格 T 的排他分支应被拒绝；两个相同优先值不能靠遍历顺序打破平局；已有 `obligationRef` 但没有Norm解释不得得到合格的履行资格；同Kind而不同签名的端口不得被自动接通。这些均是后续产品消费者的验收义务，不能由本轮静态样例的PASS代替。


<a id="gift135-static-contract-evidence-boundary"></a>

非计算作者源码的本地结构检查可签发的事实仅为：选定Profile的JSON形状合法、原文件/模块/引用/根在有限快照下可读取、互斥字段和可静态判定的名义规则未冲突。它不签发单位实际可信、状态/流程进展、Policy例外有效、Observer覆盖、Method实现、目标源码或真实效果。对任何仍有外部供应锁未读取的`conditionRef/MeasurementAuthority/PolicyAuthority`，必须保留`Needs`，不把无反证写成真或把参考测试通过转成D2–D7资格。验收以确切根集合、源修订、外部环境和证据范围为单位。

## 从结构到现实作用的资格等级与独立证据签发（Gift122）

<a id="scoped-proof-envelope-and-downgrade"></a>
### 资格不是全局勾选，而是有作用域且可撤回的证据关系

一条可签发的 `Claim` 至少固定：所断言的谓词、被检查主体与精确内容/修订、来源选择、输入/业务/行为量化范围、环境/工具链与外部假设、方法与实际检查者、证据及其独立性、取得时刻、覆盖/失效条件和未验证部分。D0–D7是**证据资格视图**而不是单值自动升级等级；D7独立性可以用来审查此前各类Claim，D6实际世界观察也不是所有只要源码交付的必选阶段。S7构建通过不能自动取得行为/性能/安全/法律/未来时域的资格。

实际裁决必须分别表达`SUPPORTED`、`REFUTED`、`CONTESTED`、`UNKNOWN/INCOMPLETE`及适用时的条件性结论，不能将证据不足写成通过/失败。必要证明前提变化时撤回相交Verdict，保留旧证据供历史重演并指出当前不可再沿用的范围。自动生成代码与同一个生成器同时生成的测试不能对重大业务行为自证全部正确；至少由独立输入、性质、模型、可信测量或异构消费者对应具体风险进行核验。文档包可运行测试只证明文档工具自己的Claim，不支持生产Rust编译器或世界Effect资格。

**验证基线的复用**：对既有可靠Method/目标工具链证据，只有当修订、环境、许可证、调用方式和前提均被有效继承时才能直接复用；否则明确新增义务，不必机械重跑全部相同测试。局部成功与缺口可并存，在验收报告中按根要求和覆盖前沿分别交付。


Schema 形状、局部解释、Method 自述、Target 构建、运行回执及独立业务证据是不同资格来源。Claim 必须固定主体、所证明属性、量化输入与负载、时空/环境、版本、签发者、方法、结果、失效条件及证据质量；`EvidenceRef` 或哈希不能替代实际检查。生成器和由其生成的测试可能同错，重大性质需独立 Oracle、异构输入或可信外部检查边界；证据不足返回 Needs，不越级签发。

产品资格需分别验证 `STRUCTURE`（格式）、`INTERPRETATION`（限定意义及证据）、`JOINT`（全体义务）、`METHOD`（实现精化）、`TARGET_SOURCE`（源及成员完整）、`TARGET_BUILD`（指定构建）、`BEHAVIOR`（声明输入域内行为）。这不是单个自增成功位：各 Claim 均记录主体、范围、方法和依据。`EFFECT/SETTLEMENT`、`PERFORMANCE`、`SAFETY`、`LEGAL` 按实际现场、负载、时间和法域另行签发，可能互不可比较；有未验证假设时只能作条件性结论，不授予 Grant 或效果完成。

任一 Claim 依赖的正/负读取、Meaning/Policy、Method、Target 工具链、检查方法、环境前提或证据本身改变或撤回时，按真实依赖失效并重检，不盲目重跑全部产品。已派发 Operation 的原身份、效果及结算路线独立保留，不以缓存失效触发重复执行。PASS 只覆盖实际验证的版本、输入和环境；ZIP完整、文档链接与知识工具校验不是生产编译器资格。

<a id="stable-full-semantic-assurance"></a>
## 采用设计：完整语义编译和真实效果的独立签发准则（R11）

设计稿、Schema、Model测试、可构建源码和实际满足业务要求是不同Claim，**不得**互相转换。验证面应逐层生成范围化可审核回执：

| 资格级别 | 需要实际证据 | 绝不支持的升级 |
|---|---|---|
| D0 `DocumentedShape` | 字段、版本、源/owner、Schema及明确未实现项 | 不能声称Production Reader |
| D1 `ParsedAndTyped` | 实际Reader读取混合模块、类型/角色/锁/格式拒绝 | 不推断领域Meaning正确 |
| D2 `SemanticallyInterpreted` | 对所选范围的Meaning/Fact/Time/Norm/Clause有真实解释及反例 | 不能从模型等价宣称现实真相 |
| D3 `JointQualified` | 多根硬义务、资源/效果/进展/许可组合有完整证据或明确作用域的证明 | 不能由独立计划相加获得 |
| D4 `MethodEligible` | 精确Method/Provider/Target前提、效果Frame、输入、进展及供应证据 | 不能声称源码已生成 |
| D5 `TargetProducedAndChecked` | 实际ArtifactSet成员、SourceMap、依赖/工具链、目标构建和相应行为检查 | 不等于已运行或世界效果发生 |
| D6 `RuntimeObserved` | 当前Grant、Operation/Attempt/结算/读回及恢复的合格证据 | 不等于所有未来输入已证明 |
| D7 `IndependentAssured` | 对明确量化域、版本、环境与可信基础完成独立Oracle/证明/观测核查 | 不得推广超出具体Claim/覆盖范围 |

此表是**证据门槛视图**，继续引用原 `Claim/Evidence/Verdict` owner，不写第二份持久成功状态Enum。每个级别单独签发且有主体、作用域、依赖、取得时间和证据质量；可以只有D5源码交付而没有D6真实执行，不能倒签D7。未经独立核验的现有`fixtures/`样例保持`reference-model-only`。

### 必须含的对抗验收

真实测试不依赖编译器用相同算法生成的预期值，至少包括：跨未见过的新领域Definition只改变名义/观察/政策而不新增Kernel行业分派；五种角色基数及空/缺席/重复/别名；同一谓词 `T/F/BOTH/NEITHER`、观察缺失与反证；条件义务、许可≠Grant、触发/豁免/违约、截止和无界进展；跨三约束的两两可行而整体无交的反例；资源容量/并发/重复消息；跨目标的数值、编码、错误和副作用顺序；生成工程首次构建、第二次源编辑和旧运行迁移；Method供应撤回、Source/Meaning/Fact目录变化及负依赖；真实Provider超时后晚到效果、撤权、不可补偿状态；未知/预算失败不输出虚假PASS。

不同证明有不同结论：*存在一个合格方案*不能证明全局最优；有限闭合模型无解不能证明开放域无解；全部静态安全条件满足不证明活性；应用代码可构建不证明外部支付清算；平均性能和单次测试不能证明硬实时。偏好比较必须有共同基线、量纲与测量假设；安全/资源/隐私/知识时效的负证据必须按其真实覆盖签发。所有未知继续有精确Need/责任/修复/再次检查入口。

## 从真实义务选择验证，而不是再建一张支持总表

本页拥有 Intent facet/作者配方到实际目标/运行/证据的符合性接合。它消费[64类发现坐标](../../00-系统与原则/设计方法/机制适用性与覆盖坐标.md)、[意图描述](../../20-语义与组合/作者语义/意图描述与作者投影.md)和[机制配方](../../20-语义与组合/组合/机制组合与作者配方.md)，不复制这些类型定义，不以64个标签构造封闭业务类型或默认运行64套测试。

每个实际采用的facet动作固定descriptor/模板/展开方法、参数域、真实作者对象/ModuleUse、原要求、Target/Provider与允许观察范围，派生相交Claim/ProofObligation。覆盖查询引用这些原对象、方法、输入、规范版本、环境、假设、结果和资格，不在旁边持久化一个 `intentSupported=true`。结构定义存在、目录可见、源可保存、静态可分析、Target可生成、实际运行、生产资格分别显示。

新验证材料可以包括由descriptor生成的基础vectors、独立作者给出的强反例和真实故障记录；期望从原规范、独立参考方法、数学/小域推导或成熟实现的准确合同取得，不让模板生成器同时担任唯一Oracle。已合格证据/证明直接复用；只有缺失、失效或实际要求新增观察时才执行新动作。零新动作不是自动PASS，也不是自动不适用。

<a id="intent-fixture-contract"></a>
## 可落实的样本合同

一份逻辑fixture至少绑定 `fixtureRef`、facet/action与其准确修订、输入基础/typed parameters/subject bindings、原义务、预期源变化和保持帧、期望Need/合法输出区别、所用独立Oracle/理由、目标与Provider差异条件、故障/重试/恢复/迁移条件和应取得的Evidence种类。可复用输入以内容引用共享，不能复制三份相互漂移的期望；计数、测试路径和状态不是规范authority。

原理能直接裁决的见证不必先实现Gift。例如同观测异干预模型可枚举，小残差反例可精确计算，有限资源双hold可按声明状态空间反证。实际读取器/运行器接线是否满足合同则需对应实现测试；不能把有限Python模型、模板静态扫描或链接通过当实际产品测试。

负例保持不相关字段合法，只改变要攻击的前提；必须检查产生正确层次的诊断/拒绝/未知及保留责任，任意JSON解析失败不能证明业务约束受检。正例用同一合同的合法对照，避免把拒绝所有输入的实现误判安全；不支持某目标时保留源/独立目标，不删除整体项目。

<a id="vertical-witnesses"></a>
## 十个纵向样本与逐次变化

这些是虚构通用资源和有独立差异的工程样本，不是可直接复制的行业成品。一个样本可以按目标实际需要停在源/静态层；声称完整可用时才必须取得所声称的author→compile→Target→run/readback→Evidence各层依据。每个样本同时做第二次局部修改，检查read-set、受影响产物与未变部分保持，不把第一次生成成功当增量闭合。

### 有状态记录、查询、权限与审计

正例声明带分区键的Record、严格类型/唯一约束、查询、访问政策及更正审计，经Persistence/API/UI配方生成普通源和目标贡献；拥有者读取自身记录并取得相应授权/审计证据。强反例只将搜索计数/缓存键的分区条件去掉：即使主表过滤正确，也应产生隔离义务失败，而不是回填所有人数据。

分别选择有资格的本地存储与服务端Provider时，按真实事务/查询/迁移能力比较，不把不同隔离级别标相同保证。注入提交响应丢失，保留原效果身份并协调；删除/缩短保留期作为第二次变更，保持未知提交和必要审计材料，不因源保存成功宣布数据已销毁。

### 耐久通用资源流程

正例是申请虚构资源→审核/等待→分配→通知，明确timer时钟、人工升级、activity、补偿与版本。短不需跨故障的对照用普通状态/async；耐久画像在重启后从真实历史继续，不重复已结算通知。

强反例在纯历史重放回调里直接发送通知，或给重试换效果key；应阻断相应方法资格。故障注入活动已完成但回执丢失，workflow history与Gift/产品Operation分别查询，不按流程图“回到上一格”重做。第二次修改审核步骤只影响新实例，旧等待继续原解释或显式迁移/移交。

### 稀缺资源预占与匹配

容量为1，两方并发请求hold；正例在真实串行/CAS/合格分区方案中最多确认一份，第二方获得排队/拒绝/其他允许结果。强反例用两次独立“先读余额再减”并都确认；局部计算正确不覆盖联合不变量。

比较真实事务与受约束离线策略，不能无条件CRDT保证唯一性。丢失确认先按原hold identity读回；过期回调必须绑定旧代，不释放续租/新hold。第二次改变公平/匹配政策保持已接受预占、计费与旧队列责任，业务公平不是Gift线程优先级。

### 带单位账本与外部对账

正例以明确币种/单位/精度的账户和entry表达借贷/守恒规则，只有合格posting形成账本结果；外部转移另有Receipt/Settlement。强反例把两个不同币种的数值直接配平，或凭本地事务成功将外部转账标已完成。

固定数据库/外部Provider保证范围，响应丢失沿原身份协调；部分补偿作为后继entry和新Effect，不擦旧历史。第二次修改规则有效期和显示舍入，不重算旧entry伪装当时已知，旧Evidence按原基础保留。

### Local-first多端对象

正例选允许并发添加的集合或已声明合并规则的对象，在有效离线委派内编辑、重连并保留来源/冲突。强反例把全局唯一预占、不允许重复消费的权利套入无条件合并，或离线无限续权限。

不同Provider的日志保留/压缩和冲突能力分别限定。重连发现历史被压缩时按固定切面重同步，草稿与旧在途操作保留；不可重建事件不能靠重扫补足。第二次增加开放字段/迁移codec，旧reader能保全原件不等于已理解新语义，不能无损宣称删除未知顺序。

### 检索与流分析

正例从有批界的事件/记录源接入，构建带ACL/freshness的索引和窗口统计，显示真正覆盖与检查点。强反例按源revision丢弃同批Y分片，或将空页/BOOKMARK解释为本地耐久处理完成。

TS/Rust目标及搜索/流Provider分别取得映射资格；比较排名/近似与精确查询时保持语义差异。重建中第二页失败不拼新快照；数据已应用但确认丢失时原批重传不重复。第二次改窗口/排序/权限，即使结果值相同也更新真实读集和相交Evidence。

### 产品UI、可访问性与地区化

正例在真实目标框架实现有标签/焦点/键盘/IME的表单与路由，使用准确locale输入codec和领域单位。强反例让旧异步验证覆盖新输入、虚拟列表位置换主体沿用旧确认，或把翻译回退当货币/权限切换。

Workbench投影可用不算生成产品UI通过。分别取得目标平台/辅助技术/输入方式的必要证据；断线提交未知保留原命令，关页不宣称取消完成。第二次改布局/语言/模板，保证草稿、焦点对象和原语义值不被隐藏重解释；图形写入不合格时文本合法路径继续。

### ML推理与模型更新

正例绑定数据/预处理/模型/输出解释和合格推理Provider，按相交评估/监测范围返回结果。强反例在评估数据上拟合预处理却仍沿用独立评估Claim，或更新权重不更新tokenizer/Feature绑定。

本地固定模型与不透明服务保留不同可复现/数据用途/费用范围；没有ML方法时源和需求可保留但实际推理为Need。训练/部署中断沿真实Operation结算，检查点只含权重时不能标完整恢复。第二次更新模型按允许变化域切换在途请求，回退模型不撤销已触发的业务效果。

### 仿真、测量与设备闭环

正例绑定仿真时间、求解器/误差、校准、控制律、设备能力/时序、安全约束与读回；先在明确模型内推演，再按Claim取得实际设备证据。强反例请求推进10而参与者成功8就发布共同10，或以两个局部稳定证书推联合稳定。

成熟模拟器/求解器/设备Provider的能力分别固定，纯模型与现实耦合不混同。试算步拒绝只能回滚私有数值状态，已发命令仍按原身份协调；超时不是已到安全状态。第二次改控制参数/校准/拓扑时沿实际依赖和共同故障路径更新资格，不全局清空未相交模型，也不复用失效安全证书。

### 跨组织交接与多权威结算

正例在两个组织各自的主体、数据范围、政策和Operation边界内完成有类型请求/证据移交；每方只声明自己确知的结果，交接包含责任人/自动受托方、期限、接受依据和未决项。强反例把一方Grant或PASS当双方的超级权限/整体验收。

不同提供者的事务/日志/时钟/签名范围分别保留，不能造全局原子提交。对方不可达时保留部分/未知，不通过隐藏缓存披露其数据；已交付部分不能因取消当前会话抹掉。第二次修改协议/责任方，旧未结算请求继续由原身份恢复或获准移交，不以新合同重解释旧回执。

<a id="mixed-domain-scale"></a>
## 联合规模、覆盖与完成判断

混合workspace将以上相交配方组合，测实际catalog懒加载、ModuleUse/negative-dependency、共享查询、供给候选集合、约束求解、目标贡献、缓存/检查点和退役资源。输入包括大量无关库与高基数相关条目：应验证无关模块不会进入每次上下文或导致全部失效，相关候选/权限/默认变化又不会因优化被漏掉。声明scope、基线、冷热条件、硬件、并发和资源包络，不设一个全球“百万行合格”阈值。

笛卡尔积数量不是必须执行的测试数，也不是覆盖率。按不同机制/证据/成立条件/失败/主体利益发现新的独立见证；实际相同闭包可复用，不同条件不得因标题相似删除。包含64坐标不证明所有未知业务已覆盖；某facet无实际方法/Evidence就保留其准确设计/缺项状态。

完成某个已支持意图的资格要求：可追到真实作者/Requirement；每项义务有合格满足依据或准确Need；Target产物有冻结输入/Binding/生成方法与所声明的工具结果；实际Effect有真实身份/尝试/范围/结算；Evidence有准确Claim/方法/对象/环境/覆盖；客户端不另写事实；TS/Rust边界不隐式I/O/双内核/每节点RPC；新业务通过合法库组合而非行业Kernel特判；实现、CI、性能、安全和故障事实与声明一致。未请求运行的设计/纯输出不被强行要求伪造Operation；尚未取得的产品证据不能由文档签发。

## 自举前设计的跨层区别见证与实际验收边界

本节定义后续产品核验的预期，不表示本包已执行这些产品实验。合格验收优先选择能击中独立错误路径的区别，而不是重复增加同类成功样例。已有 45 家族/135 侧面仍用于发现遗漏，不作为程序可定义种类的上限。

| 区别见证 | 必须取得的结果 | 不能代签的捷径 |
|---|---|---|
| 未登记的新普通函数/谓词 | 只增作者/库定义，不改 Kernel 业务分派；另一模块可按公开合同使用 | 新增一个特化 kind 或名字映射 |
| 合同有完整主体而缺 Method | 保留含义与精确 NeedsImplementation，不输出桩 | JSON 合法便认为能生成 |
| 合同声明有实现但故意返回错误正常值 | 合同/相应保证捕获差异；仅类型检查不签业务正确 | 正常函数可调用 |
| 合法输入上永不返回 | 没有进展要求时保留一般计算；有进展硬要求时不能通过安全空真 | 只比较已经返回的值 |
| 同名类型/导出跨模块不同身份 | 作用域、名义与锁按真实身份区分 | 只按显示名合并 |
| 增加更具体实例或删除规则 | 负依赖和非单调推导正确失效 | 只追踪旧读取文件 |
| 融合后回调/错误顺序变化 | 未满足等价前提时拒绝优化或保留原次序 | 最后整数相同 |
| 大整数、负商余、非 BMP 字符 | 与源域和定位单位一致，不能舍入/错位 | 小正整数/ASCII 通过 |
| 取消与晚到资源取得竞争 | 唯一接收/清理 owner，未停止不回收 | Promise 已拒绝 |
| 远端提交后回执丢失 | 完成未知并查回，不盲重试 | 超时即失败 |
| 原生构建仍在写而请求取消 | 停止/隔离实际进程后才释放 staging | 控制任务已结束 |
| 第二次修改且用户改过生成源 | 前像冲突保护，合法回源/接管，不静默覆盖 | 第一次生成成功 |
| 工具链/假设被撤销而源未改 | 相交目标/证据/执行资格失效 | 源哈希相同 |
| 源自管理与真正语言自举 | 精确列 Gift 计算职责与原生余部，C1 实际消费 Gift 主体 | 透传全部 Rust 后 Cargo 成功 |
| C2/C3 相同但共同解释错误 | 独立语义对照仍能否定错误 | 固定点就是正确 |
| 未知外部领域/硬实时目标 | 可保存定义；缺对应模型/Target/环境证据准确阻断强保证 | 关掉相关要求使请求变绿 |

测试生成器可以由 Schema 派生形状反例，但行为、效果、生命周期和独立 oracle 需要对应真实模型/实现。每项实际测试绑定源码/工具/环境、输入范围、预期来源和结果；未运行标未运行，有限枚举标其有限域，产品运行标真实消费者。更改同一 owner 后只重做相交检查，不全仓运行所有领域实验，也不拿 CI 当调试循环。

自举前设计 Gate 检查以上路径是否有确定合同；自举执行 Gate 要取得真实源闭包、阶段产物、差分/固定点和恢复记录。设计可用于开始实施，不自动允许清除旧源码/恢复链或宣称各目标已生产支持。

## 抽象、复用、组合、源码生成的独立验收设计（与现实取证分离）

### 1. 四种互不代签的覆盖

**表达覆盖**：未知领域新增名义类型、关系、事实来源、要求和差异政策，无 Kernel 行业分派或源码模板修改。**语义保持**：模式实例化、特化、复合过程中所有被业务区分的结果/错误/进展/状态/规范/权限保持。**实现覆盖**：有资格 Method/Target/Assembly 实际为选定输出根生成完整项目，消除所有未解释操作。**运行与现实符合性**：目标程序实际运行、应有的原子/恢复/幂等/外部观察成立。`JSON Schema pass` 只对应结构合法，不能为上述四者中的后面三者签发通过。

### 2. 开放领域正反例矩阵

| 反例/变体 | 必须保留的独立区别 | 能成立的最大声明 |
|---|---|---|
| 床位、座位、GPU 实例化公共容量模式 | 资格来源、独占/抢占、时段、原子占用、外部确认 | 相应子域共享模式表达和有限实现资格 |
| 同一个业务名 `paid` 映射授权/扣账/清算 | 身份、真实来源、时点与效力不同 | 明确区分不同 Meaning；不能自动替换 |
| 两个请求分别合格但共享容量为 1 | 联合硬约束与共享写集 | 局部可行、整体不可行（只在声明的完备域） |
| 取消订阅并履行通知 | 取消状态、已发生扣费和待完成义务不同 | 本地字段更新不能签现实停止扣款/通知完成 |
| 无界安全/最终进展 | 未来轨迹、公平调度与观察覆盖 | 有界测试无法证明无界性质 |
| 高并发、多资源、多方法候选 | 原子域、死锁、成本/资源共享、幂等/恢复 | 仅对明确定义的环境及方法组合签发 |
| 业务只需 CLI、另一业务要求无障碍 UI | 交付形式是公开要求，而不是实现默认 | 一种最小部署不能代表所有系统产品 |
| 法定义务、主观审美、物理设备 | 解释者、权威、测量及法律/物理条件 | 未取得外部证据时准确返回 Needs |
| 同一 Method 更换 Rust/TS Target | 整数、异常、字符串、ABI、资源、时间 | 逐 Target 实际符合性，不跨目标自动继承 |
| 内容相同、主体或授权不同 | 来源域、revision、租户、Grant 的区别 | 不能以内容摘要代替资源和权限身份 |

### 3. 分层证明义务和独立 Oracle

每个已接受公共 `Pattern` 的测试必须固定反例、选定观察、所有输入场景到角色的映射、共用/差异槽及版本；还要构造至少一个导致抽象过宽的反例。每个 `DefinitionUse` 的实例化应有类型与单位、身份、事实来源、观察范围和差异保持检查。每次 `compose` 应有资源/时间/权限冲突案例、未完成搜索与不可判定出口。每次 `realize` 应区分库复用、组合、合成、新代码，并具备可比目标生成结果。独立 Oracle 不能仅重用被测模块同一套逻辑判断而自证正确；可用独立解释器/真实引擎/数学模型/外部 Provider 读回，明确共享缺陷风险。

### 4. 性能、开发成本和无新增核心分派

采用相同领域任务、原生对照方案及明确的目标/工作负载比较：作者需要提供的**业务特有决定**、显式算法/配置、二次修改涉及的受管文件、生成目标可维护性、构建开销、运行延迟/内存、安全、缺失事实次数、维护任务工时与出错率。时间性能必须按精确硬件/版本/负载取得，不规定凭空阈值。新模式装配对已知任务快速不代表对未知领域开放；新的领域类型不修改 Kernel 也不代表必须自动找到合格 Method。未验证的效率主张继续作为目标，不写成已达成效果。

### 5. 资格报告的最小结构

每项结果至少记录 `{claimRef, subjectRef, subjectRevision, semanticSelection, modelOrWorld, environment, timeScope, methodOrOracle, evidenceRefs, outcome, uncoveredObligations, negativeExamples, counterexampleOrNeeds}`；若是模型证据则绑定模型定义、搜索预算/完备域和有限输入，而不是给现实世界当前值盖章。只有 Claim 对应的证据齐全才能发表相应强度的保证；`Unknown`、`Conflict`、`OutOfScope`、`Unimplemented` 不从结果中删除。

<a id="gift119-layer-status-acceptance"></a>
## 每层究竟设计到哪一步的判定与证据等级

对每个具体 `Construct/Definition/Use/Root` 单独保留 `CoverageRecord` 的六个正交字段：`meaning`（解释/来源）、`syntax`（合法编码）、`consumer`（实际检查/编译）、`method`（合格供给）、`artifact`（独立构建运行）、`world`（受权效果与合格读回）；任一字段缺失不能用别的字段的 PASS 填充。仅声明 `design-shape` 的 Schema 不意味着生产 Decoder，参考解释器的有限 `ModelPlanCandidate` 不意味着开放语义解释器，单库 SQLite 模型提交不意味着真正医院/支付已执行。时间/法规/物理/人工主张必须按自身实际观察条件和适用地域/有效期取证。

验收门槛依次：A 源和结构可严格读取；B 新定义能在受支持的 Meaning 模块解析/实例化；C 联合约束和方法覆盖有可复核证据；D 全部目标源码/依赖严格构建且有源映射；E 真实执行与事务/授权/恢复符合本次声明；F 各公开保证取得独立 Oracle。各门槛允许 `pass/fail/unknown/not-applicable`，并必须保留支持主张的原始范围与反例；同一产品可在不同能力上处于不同阶段，不以整体百分比隐藏差异。

重点反例：名称不同但语义相同；名称相同但有不同授权/时域；两个各自可行但共享容量只允许一个；`oblige` 中触发已发生而通知仍未发送；`permit` 已成立但真实 Grant 不存在；算法满足值结果但进展失败；真实 effect 已发送但结果未知；版本变更导致旧 Method/Evidence 不再匹配；局部 TS 构建通过而部署缺配置/依赖。逐项留下正确 Need 与恢复路径，不能只断言测试数量“很多”。

## 开放模式实例化的分级可观察证据

对 `semantic:pattern-use/2` 的验证分为互不代签的结果：(1) Schema 合法；(2) 被锁定 Definition/Meaning/对象/类型引用全部存在且无歧义；(3) 名义类型、身份、单位、基数与差异槽满足抽象精化；(4) 已有 Requirement 的义务、量词、条件、时域取得原拥有者的真实解释；(5) 联合方法符合并全部目标可发射；(6) 外部作用获得 Grant、结算/读回；(7) Claim 所需独立证据支持。**最多通过前三项不得报告后四项完成。**

必须保留的负例：集合角色被单对象绑定、set 的两个别名指向同一规范身份、bag 数量被 Number 截断、序列被排序、缺席 optional 被默认 false、nominal 类型仅凭同字段被强转、实际对象的单位/身份域不一致、差异选择缺失、仅有 `whenVariation` 未有条件 Requirement、模式/Meaning 锁篡改、模型观察冒充世界效果、缺真实 Method 却产生目标代码。测试中的 `TrustedRefinement` callback 仅代表测试宿主提供的受界合格判断器，不证明任何真实医院、设备或业务政策。验证声明必须给出实际被运行的 Consumer 与环境/版本，不能把离线 Reference Fixture 升级成生产合格。

### 通用意图语言的鉴别式纵向验收（规范与样本未混用）

仅由 45 个语义家族/135 个侧面建立目录，不足以证明任意新功能可以由开发者自由定义，更不足以证明自动合成和生产运行。验收必须逐次记录同一个新定义的 `SourceRef` → `DefinitionRef` → `Meaning` → `Requirement` → `Method/Target` → `Build/Run` → `Evidence`，并用**已有但未出现于生成算法中的独立反例**排除伪正确。一个新的行业标题与重命名模板不能算一种新的语义能力。

#### 十个互相独立的挑战方向

| 实际能力 | 作者独立控制 | 通用 Method 可承担 | 会击穿错误通用化的反例 |
|---|---|---|---|
| 整数区间规范化 | 半开区间、同覆盖、最少相接合并、升序 | 扫描排序、数据结构选择 | 端点相接/空区间/整数溢出与重复输入 |
| 任意有向图路径 | Node/Edge Identity、存在性、有效路径、无路径错误 | BFS/DFS 或已合格图算法 | 有环、同节点、无路、无限/未知规模 |
| 修订工作台 | 旧结果禁止发布、当前输出进展 | 调度、取消、只读快照与版本检查 | 一直不发布可以满足 safety 却违背活性 |
| 事件时间窗口 | 窗口、水位、迟到/回撤政策 | 组合窗口方法、状态存储 | 处理时间与事件时间混合、迟到后重复聚合 |
| 双边账本 | 币种、守恒、错误与审计、提交范围 | 存储/一致性/对账实现 | 两次写后补偿并非原子，跨服务不是 exactly-once |
| 带单位数值求解 | ODE 定义、单位、误差模型和容差 | 数值方法与误差估计 | 函数不满足正则性时不能无条件承诺误差 |
| 全新 token 变换 | 自定义邻接谓词与可行/无解区分 | 作者/实现方新编递归搜索、已有约束器 | 仅返回原序列不满足旋转/邻接，搜索预算未完不等于无解 |
| 新网络 Effect | 消息、重试/幂等/未知状态、授权 | Handler/Provider 资格 | 声明操作不创造真实权力，回包丢失不是失败未提交 |
| 高阶泛型组合 | 泛型 Type、稳定性、纯度和终止前提 | map/filter 和 Target 组合 | 闭包带效果或不终止时不能与纯函数重排 |
| 可访问性 UI | 文档模型、状态、焦点、区域化资源 | 渲染/事件/无障碍适配 | 只生成后端 API 不等于 UI 功能被实现 |

离线方案结构样本见 `fixtures/semantic-universe/Gift106/` 的 10 份作者模块和 6 份负例：它们证明**哪些字段被提议、各自为什么不同、当前锁/语义缺项如何暴露**，不证明已被 Gift105 的 parser、Kernel、Target 或现实执行方法接受。先对 Schema + 引用的确切规则执行结构校验，再以真正实现后的语义求解/目标代码/现场效果分别验收；此处不使用文件数量或范本 PASS 冒称真实能力。

#### 强制的可复核验收路径

- **开源性而非名字自由**：用随机且从未登记的用户命名空间，定义与复用新名义 Type/计算函数/谓词，不编辑 Kernel/Requirement 解析器；必须检查 Lexical Scope、Ref、类型、未知语义与冲突的负例。若只是把未知名字塞进万能 JSON，不算通过。
- **抽象成本**：作者提交仅公开保证、依赖与必要决策的项目，选用已锁定的语义供应；核对 Method 自动得出的算法/资源/布局不会静默成为新需求。缺实现时退化为清楚的 `Need`，而非空产物。
- **计算通用性**：为开放自定义 ADT 和任意递归定义生成至少一个有界样本的实际 Rust/TS 可执行源码；另验证非终止或资源耗尽不被当作一般终止性证明。
- **完整行为**：用独立 oracle 检查正常结果、错误、帧、进展、取消/外部效果；负例必须在其应失败的阶段失败，不允许全被模板接受。
- **目标维护**：作者第二次变化影响公开行为时只重新资格化相交 Binding；无关变更不重写不受管原生源码；目标构建错误能定位回作者定义。
- **现实和证据**：涉及真实 Payment/Network/Device 的样本只有在具体授权/Provider/回执/恢复已资格化时才可真实执行；其他样本明确返回未决或模拟。负面证明不由生成器自己的测试独占。

通过某一套具体 Target/Profile/数据域的纵向样本只授权该组合，不自动延伸到无限新定义、所有平台、业务法律事实或任意世界状态。

### 将通用性与实现供给的证据分别评价

最少区分 `Author Expressibility`（新领域意图能被定义）、`Meaning Qualification`（角色/观测/时间等有真实解释）、`Joint Realizability`（共享状态/资源/权利下存在合格计划）、`Artifact Qualification`（目标工程完整可构建）、`World Effect Qualification`（有权实际执行/读回）、`Maintenance Qualification`（第二次更改未污染原作者源）六类 Claim。某项通过不自动提升其它项。

Gift113 的十项联合参考测试只证明受界有限模型里的组合算法能拒绝共享容量超额并保留未决；它不证明持续时间、复杂环境、真正权限、生产内核、自动任意算法生成、法律有效性或真实高性能。独立核验应覆盖两单项可行但共同不合法、未知事实、截断、撤销/重试与原生源码维护；详见施工手册第23章。

在已有有限模型通过之外，[Gift114 本地工程](../../70-工程系统与演进/工程构造手册/25-意图到本地持久程序-可运行装配施工.md)新增独立 `tsc --strict` 构建、Node 运行、跨进程 SQLite 读回、两个共享意图原子提交、幂等 receipt、过期合同/前像拒绝、数据库触发器注入失败后的事务回滚。它可声明 **local-model-committed**，不能声明已满足真实行业意图、无限期安全、外部 Grant 或生产运行资格；Node22 `node:sqlite` 为实验接口。
