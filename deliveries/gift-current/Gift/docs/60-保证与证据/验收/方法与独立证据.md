## 高质量源码不是一个绿色布尔值：首个生成样本的证据分解（Gift 98）

对`作者短意图直接成为专业代码`必须分别报告：（1）SourceProfile准确读取与字段拒绝；（2）Definition使用、关系、合格方法和硬控制均满足；（3）完整TypeScript成员和稳定导出布局；（4）真实`tsc`严格构建；（5）正常/失败/边界行为的独立实际调用；（6）第二次作者修改的对应与非相交成员保持；（7）真实环境下的运行/安全/恢复/性能。前六项的有限受控测试即使通过，也不能替第七项发出生产资格。

Gift98含两组不同业务中立方法配置：记录＋状态机＋组合，及有界库存记录＋开发者自定义纯条件谓词。参考测试覆盖负面非法源、重复键、未知方法、非法目标或存储升级、类型和state不匹配、同一状态事件歧义、溢出拒绝、修订前像冲突、去重重放、字段/Unicode校验与资源限制。每条证据应绑定精确fixture版本、实际TypeScript/Node运行、输出与测试代码；按本次真实执行数量统计，不把4,096个取样当独立形式证明。原Gift97 Revision64另有独立无损范围反例；不能因为当前试验也使用bigint便继承整个持久事务资格。

源码的可维护性在目前仅通过**可观察结构**（模块职责分离、强类型、显式错误、稳定命名、共享算法、第二次修改局部差分）初步验证。人类维护性、生产代码审查、P95构建/运行时延、长期容量、目标生态兼容与恶意同进程行为尚无发布级实证。若作者要求`durable`但已绑定Method仅支持`volatile`，正确结论是**明确不满足**，不是为了让CI变绿删掉持久性或自动配置一份伪数据库。

当前新增运行回归覆盖：两种作者输入的等价源码、严格文本解析负例、Method源重定向拒绝、编译器/运行源字节身份、手工改动受管文件的覆盖拒绝、模拟多文件更新中断后的字节回滚、真实增量构建及新增状态事件的运行调用。可运行的`tests/run_all.sh`让这些有限行为脱离本会话复核；运行次数和确定性取样不能被提升为数学证明或完整安全资格。

## 参考编译器测试的分层含义与非垃圾判定

有限回归的保留资格由所阻止的具体缺陷决定：源语法/语义拒绝、类型和状态绑定、目标成员确定性、外部供给身份、第二次作者改动、源被修改时的保护、日志缺失时不误删恢复目录，以及目标构建、运行和发布读回，是不同的验证义务。状态/版本序列取样不能按断言次数升级为彼此独立场景或形式证明；`METHOD_SUPPLY_CHANGED`拒绝只说明未冒用源码身份，不保证供给行为正确。历史参考程序和原运行结果只在其准确制品内支持对应结论，本设计包没有重演这些结果。

实现/质量保证应把结论按`source acceptance → semantic checking → exact supply identity → generated target type-check → local runtime behavior → target/environment/effect qualification → independent claim/evidence`逐层绑定。一个新`BindCallable`供应者即使编译、运行几个样例成功，仍须标记`REFERENCE_ONLY_UNVERIFIED_MEANING`；当作者要求强保证、持久化或目标级副作用时，缺乏独立证据必须产生`Needs`，不能将结构型TS函数签名当作行为证明。文档链接和知识查询校验留在文档包门禁，不应放入每次Gift产品构建的强制重跑路径。删除历史测试前必须先确认相应风险被更可信测试或真实消费者覆盖；仅旧版样本名不同不证明它无价值。

验证复用按实际影响闭包进行：首次作者工程取得范围内完整的有限行为与结构证据；后续仅改变状态边、且记录模型和公共运行时未变时，可复用不受影响的证据，对目标构建及新增状态事件取得针对性证据。触及记录模型、安全校验器或共享Runtime时，必须扩大到相交行为。输入与目标完全一致的受管更新在前像校验后返回`UNCHANGED`，不制造无实质内容的备份事务。

## 通用 Fold/方法候选/受管快照的实际证据等级

测试必须按所阻止的错误组织，不按 assert 次数追求数量。应按实际实现选取的局部验证对象包括：复杂表达式类型与最大值树预算；有序 Fold 正常及数值溢出；受限候选 pin 与 `auto` 过滤；候选切换时作者语义摘要不变；局部源码更新只触及使用该方法的受管成员；非法数组空槽、扩展属性、访问器不进入生成计算；名称捕获的 TypeScript 编译验证；同一新业务对不同 Lowering 的正常/失败观测。这些义务来自[有限参考实验说明](../../../fixtures/contract-closure/Gift98/README.md)，实际实施时绑定当前消费者及准确输入；原脚本不在本包中，参考回归也不等于产品级独立Assurance。

对于宣称高性能、内存上界、证明纯度、持久事务、抗恶意 Proxy、发布兼容性或“全局最优”的 Claim，以上单机样本均不充分。运行时快照只有节点数量上界，不等于时间与字节硬上界；JS 输入 Proxy 仍可能在调用宿主描述符 API 时执行 trap。没有宿主隔离的未知效果不得升级为 `pure`。需要补充独立语义 Oracle、目标运行环境、负载分布与压力/故障证据，保持局部实际证据与生产要求未闭合的区别。

## 纯计划与真实单库提交的分层验收

[有限本地实验说明](../../../fixtures/semantic-universe/Gift104/README.md)保留纯计划和单库提交的比较场景；原测试代码及运行证据不随当前包提供。实际实施取得证据后，其证据层级必须分别陈述：① 作者语义解释与 TS 纯计划在给定样本输入上相同；② HMAC 在受控测试发行者/密钥范围内校验准确 scope；③ SQLite 单库内持久状态、容量和幂等 receipt 共同提交；④ 失败注入证明提交前回滚与提交后查回执。上述结果相加不等于真实支付/设备效果、组织授权、强网络隔离、独立安全证明或生产环境断电耐久。

任何生产级保证的补足，至少需要真实 Grant/Policy Provider 的 issuer、撤销/密钥保管、目标来源签名、授权与事务之间的 TOCTOU 处理、生产数据库和备份/故障域、长期并发/恢复、针对作用类型的外部 readback 及独立消费者测试。对无法验证的效果保留 `NOT_ATTEMPTED` / `NEEDS_*`，不能以通用 bool `pass` 替代不同的 Claim。
