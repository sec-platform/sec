# 跨域区别见证

本页只保存**会真实否证通用抽象的少量区别见证**。它不是行业测试套件、业务能力目录、标准库清单或支持矩阵，也不要求每次产品任务逐项执行。领域研究的职责是寻找反例；只有当一个反例脱离行业名称后仍对应不同的状态、时间、权限、恢复、数值或 Evidence 行为，才在这里留下一个可复查见证。具体游戏、仿真、制造、金融、医疗等研究材料归领域研究，不取得 Gift Core authority。

一个见证通过只说明现有公共机制能够保持该区别；失败则定位缺少的公共表达、组合或供给合同。它**不会**自动创建 Standard Semantic Module、Profile、Provider、Target 或行业 API。是否提升公共机制仍由[核心提升规则](../../70-工程系统与演进/演进与实施/作者定义组合与核心扩展.md#core-promotion-rule)裁决。

<a id="realtime-joint-distinction-witness"></a>
## 多时基、可回滚模型与现实作用必须分开

实时交互暴露一个跨领域联合反例：输入采样、模型推进、呈现、音频、网络接收和持久提交可以拥有不同时间轴、抖动和重采样规则；因此不能用一个全局 `realtime` 或 `tick` 布尔值替代时间映射。确定性重放只约束声明进入 canonical comparison 的状态、随机流、规则/协议 generation 与允许差异；只要求权威服务器加客户端预测时，correction/acknowledgement 合同并不等价于 bitwise equality。

模型 snapshot 可以回到旧切面并重算，但已尝试的外部 Effect 只能按自己的 operation/settlement 合同查回、去重、补偿或人工结算。局部 snapshot/interest filtering 只有覆盖全部相互作用历史时才足以回滚；缺闭包时必须扩大历史、重建依赖或明确接受近似。作者资产、派生产物、代码 revision、保存格式、运行实例和设备资源也是不同 generation；一个 generation 变化只能使真实相交消费者失效。

稳定权利/资格与当前可服务性同样分开。资源、region 或 Provider 健康可使能力 temporarily unavailable，但不能重写已成立的权利事实；恢复可服务性也必须重新取得当前资源资格。这里提升的是多时基、Effect settlement、generation-aware derivation 与 capability/authority 分离，不是游戏、ECS、rollback networking 或 live-service 本身。

**深度研究来源：**实时交互研究材料。

<a id="gift-unit-cb4e2f2ba3845fe987743dbb073fb7b7"></a>
## 测量、校准与实验解释不是一个数值

<a id="measurement-calibration-identifiability"></a>
### 测量值、估计值、误差来源与可识别性必须分开

测量至少绑定被测对象、方法/设备、单位与参考框架、量程、采样/时间、校准修订及缺失/饱和/异常状态。测量值不自动等于真值估计，设备标称精度也不自动覆盖安装、环境、处理算法和校准漂移。随机波动、系统偏差、参数不确定、模型不足、离散误差与观察缺口是不同不确定来源；只有方法和对象明确时才能给区间或概率声明。

参数估计还必须保持**可识别性**：若多个参数只通过同一组合量影响观察，优化器给出一组数值不证明它们分别被现实确定。校准、拟合、验证和实际用途数据的复用关系进入 Evidence 依赖；修改观测映射、校准或用途，即使代码字节不变，也会使相交 Claim 重新求资格。数字/现实映射中的观察状态、估计状态、预测状态与实际对象保持不同身份。

**深度研究来源：**实验测量研究。

<a id="experiment-selection-and-cumulative-effects"></a>
### 自适应实验选择与现实累计作用不能被“重跑”抹掉

研究问题、估计目标、总体/样本、干预或观察方式、比较基线、随机流、停止规则和测量方式共同限定一次实验解释。查看结果后改参数、子群或停止时点会改变推断条件；只展示最佳 run、删除负结果或把共同数据源当独立重复，会高估 Evidence。硬条件与软偏好也不能由一个无来源综合分互相抵消。

现实中的数据披露、费用、设备损耗、参与者负担等作用具有累计性；换实验 ID、恢复模型 snapshot 或重启会话不会撤销已发生的消耗。相应预算归真实主体和执行记录管理。这个见证要求 Evidence 选择过程和现实 Effect 都有自己的 provenance/settlement，而不是要求 Gift 内置科研、A/B、ML 或临床平台。

**深度研究来源：**实验选择与累计作用研究。

<a id="gift-unit-4ada298ae5525a77b0426751d51e2442"></a>
## 多模型耦合与现实控制不能由“能连起来”代替正确性

<a id="cosimulation-coupling"></a>
### 接口可连接不证明耦合、守恒或误差闭合

多个模型交换的可能是状态、流、势、累计量、事件或控制命令；单位、方向、参考框架和符号都必须跟具体接口一致。两个值都能编码为浮点数，不证明它们可直接相乘或相连。联合方法还要明确通信点、保持/插值、事件同步、代数依赖、收敛、拒步和回滚；存在代数环时，只有参与模型支持相应迭代和状态恢复，才能把它当固定点问题。

总误差不仅来自单个求解器容差，还可能来自通信、耦合延迟、插值、离散、参数和模型误差。并行调度、代理模型或保真度切换若改变这些假设，也必须触发相交资格重评。一个子模型成功不能把其他模型的旧中间态合成联合成功。

**深度研究来源：**联合模型研究。

<a id="real-control-response-boundary"></a>
### 模型监测与真实安全响应有不同证据边界

把模型接到现实作用前，必须区分可在模型内检查的假设、运行时可观察假设及无法及时观察的现实条件。若安全响应需要在危害前完成，检测、传输、调度和动作完成的真实上界必须与剩余安全裕度比较；平均延迟、模型预测或“告警已发送”不能代替这个界。保护动作本身、执行器故障、共同电源/网络故障和人工接管资格仍是独立前提。

探索、影子运行和离线仿真不取得真实设备权限。错过 deadline 后是否丢弃、保持、降级或进入安全控制，由该项目的真实执行合同决定；不能把所有设备行为统一成 `stop=true`。这要求通用系统保持监测、能力、授权、Effect 与 Evidence 的分离，不要求 Core 认识任何具体设备或控制律。

**深度研究来源：**现实控制研究。

<a id="gift-unit-2e8396129dab5b38aff85c5a861bf8c0"></a>
## 时间推进、检查点与模型完成不是一种运行状态

<a id="simulation-progress-and-checkpoints"></a>
### 进展方法决定什么才叫可恢复切面

连续积分、离散事件、约束求解、状态空间探索和同步更新拥有不同的进展/提交规则。检查点也不能只保存“当前可见变量”：具体方法可能还依赖求解器历史、随机流、事件日历、通信消息和内部缓冲。可恢复状态必须绑定模型/方法/格式修订；若某参与者不能回滚，就不能把整个联合计算声明成可任意回滚。

并行保守推进需要不会再出现更早事件的安全前沿；乐观推进需要可恢复状态、撤回/等价协议、全局提交前沿和足够历史。历史回收不能越过仍可能收到回溯影响的范围，未提交模型事件也不得触发真实 Effect。若只承诺统计一致性，则按分布与误差验收；不能把它冒充位级 replay。

**深度研究来源：**时间推进研究。

<a id="gift-unit-715d51ce19e859cfb9f586829fd0b69a"></a>
## 历史依赖、拓扑变化与梯度必须保持模型身份

<a id="history-contact-topology"></a>
### 当前状态不足以代表有记忆或不光滑系统

延迟/记忆模型的恢复可能需要历史区间、插值和近似策略，而不只是当前 `x(t)`。接触、碰撞、相变、断裂、移动网格等变化还会改变激活集合、自由度、几何或历史变量；重建数组不等于完成守恒量、材料历史和观察对应的迁移。模拟 snapshot 的恢复也不能撤销现实中的不可逆材料或设备历史。

自动微分程序导数、连续模型敏感度、离散化后梯度和替代光滑模型梯度可能不是同一个命题。切换点不可微、分支变化或近似模型只能按自己的定义给出分段、广义、估计或不支持结果。这个见证要求导数 Claim 绑定准确模型、离散、历史与方法，而不是要求 Core 预置接触/网格/材料算法。

**深度研究来源：**历史与拓扑研究。

<a id="physical-genealogy-and-life"></a>
## 设计对象、现实对象与寿命历史不是“latest”

现实工程中 as-designed、as-planned、as-built、as-installed、as-maintained 可以同时成立并指向不同配置事实；设计 revision 更新不自动把现场对象变成新设计。物料拆分、混合、加工、损耗、返工和回收还会产生多对多谱系，不能只用包含树。守恒只在明确边界和计量下成立，不能把未观察边界流塞进误差项后宣称闭合。

磨损、疲劳、腐蚀、热循环、校准和维修形成路径依赖。恢复软件 snapshot 不重置现实设备寿命；更换部件也不自动清除整机历史责任。图纸、模型、工艺候选和软件可以作为 Artifact，但制造、安装、检验和现场资格是后续现实 Operation/Evidence，不由“生成成功”代签。退役同样可能相交残余能量、危险材料、数据、密钥和资产责任。

**深度研究来源：**现实工程寿命研究。

## 使用与扩展规则

这些见证按**区别**而不是按行业计数。新增领域材料若只重复现有区别，链接已有见证即可；只有出现新的可观察状态、失败、恢复、权限、数值或 Evidence 关系时才增加一节。一个见证不要求建立对应测试文件或固定 case ID；真实产品声称某保证时，才由对应 Claim/Evidence owner 选择足以发现该类错误的检查。

领域研究可以继续扩展，但不得从“研究过某行业”推导“Gift 支持某行业”。反过来，某业务没有专门研究页也不意味着无法用 Gift 组织；真正资格由它所消费的通用合同、作者定义、Provider/Target 供给和实际 Evidence 决定。

[跨域纯计划解释器和示例](../../../fixtures/semantic-universe/Gift103/README.md)中的支付确认与设备安全两个完全不同的 Definition 复用同一语义解释/TypeScript发射：无观察时不允许把本地声明当已验证世界事实；模型中的政策允许不等于当前真实Grant；重复操作先查回、超时结果不得冒充未发生；状态拟议后像不等于外部效果已执行。正负差异检查只说明**固定有界模型**保持这些区别，不能认为真实支付/设备运行安全、跨进程原子提交或 Provider结算已通过测试。
