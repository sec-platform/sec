# 构建、交付、演进与跨域协作

## 构建、交付、演进与跨域协作

### 依赖获取、构建与工具链

**规范入口：**[宿主生态与技术约束](../../50-执行运行与观测/平台生态/README.md)

**需要识别的输入：**源、库、目标工具、构建脚本及环境

**适用性检查：**获取、安装、构建分权；固定可重建输入

**失败恢复检查：**离线缺依赖报获取请求；构建效果隔离

**验证方向：**干净环境、离线缓存、脚本越权与工具漂移

**不承担的责任：**不把包存在或能import当方法适用

**业务作者目的：**获取依赖、构建、测试、打包、缓存和工具链。

**作者投影与落实：**Build facet 由 TargetProgramPlan 产生工具需求，Provider 固定 exact tool/dependency inputs；不重造 npm/Cargo/clang。

**可区分的见证：**固定工具链和依赖闭包可按本次规则构建；锁文件存在不证明包脚本未执行。禁网时缺项如实返回，缓存重算不自动获下载权。

### 实现选择、降低与完整产物

**规范入口：**[生成规则与产物链接](../../40-目标与制品/编译内核/生成规则与产物链接.md)

**需要识别的输入：**UseBinding、目标、真实贡献与输出根

**适用性检查：**SourceBody/ExternalExport/GenerationMethod统一接纳

**失败恢复检查：**未闭合贡献不污染成功根；新依赖回到选择

**验证方向：**跨目标语义、符号、布局、初始化与完整成员

**不承担的责任：**不由printer临时改变方法或用户要求

**业务作者目的：**从意图选择实现、降低到目标、形成完整产物。

**作者投影与落实：**Intent facet 只声明 semantic/capability needs；RES/Binding 选择 Method，TargetPlan 只消费冻结 Binding，禁止 backend 重解释业务。

**可区分的见证：**Target只消费正式Binding；新增约束需回RES形成后继绑定，不能后端私换库。无实现返回Need，不发TODO/panic占位产物。

### 原生接口、ABI与异质目标

**规范入口：**[原生与跨语言编译](../../40-目标与制品/编译内核/原生与跨语言编译.md)

**需要识别的输入：**外部函数、布局、调用约定、异常与设备

**适用性检查：**桥接明确内存、地址、线程和生命周期条件

**失败恢复检查：**不支持ABI时隔离或拒绝，不伪造原生等价

**验证方向：**跨语言异常、分配器、结构体布局与目标平台

**不承担的责任：**不要求把每种目标语言变成核心实现语言

**业务作者目的：**调用 C/C++/Rust/系统 API、ABI、GPU、设备和异质运行时。

**作者投影与落实：**Native facet 声明 ABI/data/lifetime/error/threading/callback requirements；适配器从真实 headers/metadata 产生固定 contract，并做目标测试。

**可区分的见证：**ABI/布局/回调寿命吻合才调用；Rust kernel存在不证明Rust target或任意FFI可用。abort/不可展开边界不能伪装成捕获并清理完成。

### 协议、格式与标准符合性

**规范入口：**[扩展语义与适配合同](../../20-语义与组合/基础语义/扩展语义与适配合同.md)

**需要识别的输入：**标准版本、读写角色、扩展和能力协商

**适用性检查：**语法、语义、互操作与部署资格分开

**失败恢复检查：**未知字段依合同保全/拒绝/忽略，禁止安全降级

**验证方向：**版本矩阵、中间代理、黄金向量与模糊测试

**不承担的责任：**不以支持标准名推导完整行业支持

**业务作者目的：**遵守外部协议、文件格式、行业/技术标准。

**作者投影与落实：**Conformance facet 绑定 StandardRef revision/profile 与 method/evidence；兼容结果只覆盖实际版本/向量，不能从名称宣称完全符合。

**可区分的见证：**通过某profile向量只支持准确版本/范围；协议名字相同不能推完整符合。旧reader遇未知封闭分支拒绝，开放载荷保全另按合同。

### 封装、发布、装载与运行实例

**规范入口：**[发布运行与资源生命周期](../../50-执行运行与观测/运行生命周期/README.md)

**需要识别的输入：**制品、配置、目标、授权和当前状态

**适用性检查：**构建成功、发布、部署、采用和运行分别读回

**失败恢复检查：**失败发布不替换良好实例；保留已发生作用

**验证方向：**灰度、回滚、失联、并发发布与旧实例

**不承担的责任：**不让生成源码自动触发线上作用

**业务作者目的：**把产品封装、发布、加载、启动、关闭和升级。

**作者投影与落实：**Deployment facet 声明 package/runtime topology/config/secrets/health/upgrade/rollback；Execution 只对获准 Operation 实施并读回。

**可区分的见证：**制品上传成功不等于发布指针/运行健康已确认；分项readback分别观察。旧运行实例仍占资源时不能因新版本Ready就删除。

### 演进、迁移、兼容与退役

**规范入口：**[兼容迁移与退役](../../70-工程系统与演进/演进与实施/兼容迁移/README.md)

**需要识别的输入：**旧源、旧数据、旧写者、消费者和恢复责任

**适用性检查：**模式、语义、权限、状态和工具版本分别迁移

**失败恢复检查：**双写、旧消费者、半迁移要有协调和退出

**验证方向：**升级降级、长离线客户端、恢复与consumer-zero

**不承担的责任：**不认为源代码回滚即可数据回滚

**业务作者目的：**演进 schema/API/业务规则、迁移数据、兼容旧客户端和退役。

**作者投影与落实：**facet/library/Definition及目标/Provider按各自修订和实际消费者演进；解释/表达/运行数据的迁移分别判断。只在需要且授权时形成迁移Realization/Operation，不强制重写全部历史。

**可区分的见证：**新解释器发布不强改旧快照；真实迁移具前像和兼容依据才采用。停止新绑定不等于旧回调/恢复材料已可退役。

### 供应链、许可、来源与可分发性

**规范入口：**[模块封装与复用库](../../20-语义与组合/组合/模块封装与复用库.md)

**需要识别的输入：**直接/传递依赖、模板、运行库、资产和权利

**适用性检查：**逐成员确定实际来源与分发条件，不看顶层许可猜全部

**失败恢复检查：**未知许可阻断相交对外分发，不阻断合法内部设计

**验证方向：**SBOM/许可清单、替代依赖和私有材料泄露检查

**不承担的责任：**不把第三方成熟实现改称Gift自有商业秘密

**业务作者目的：**控制依赖来源、许可证、SBOM、签名、可分发性和供应链风险。

**作者投影与落实：**SupplyChain facet 生成 source/license/integrity/distribution requirements；构建 Provider 产 SBOM/provenance，Assurance 核实际制品。

**可区分的见证：**每成员来源/许可/摘要和分发要求相交核对；SBOM文件存在不证明内容全部真实。签名覆盖/撤销/保留范围随制品精确绑定。

### 产品配置、特征与条件装配

**规范入口：**[对象关系与配置基线](../../70-工程系统与演进/信息与生命周期/对象关系与配置基线.md)

**需要识别的输入：**选项、默认、画像、互斥和运行配置

**适用性检查：**默认有来源；配置关系联合验证；不覆盖硬要求

**失败恢复检查：**非法组合提供冲突原因；旧配置兼容可追踪

**验证方向：**组合边界、未知键、默认漂移与迁移

**不承担的责任：**不采用一个全局auto/guided/manual开关

**业务作者目的：**产品功能开关、版本变体、条件装配和客户/地区配置。

**作者投影与落实：**Feature facet 使用有 owner 的 typed Profile/Condition/Control；编译期和运行期开关分开，不能用 string map 覆盖领域约束。

**可区分的见证：**编译期特征改变产物；运行期开关仅在已允许变化域内生效。Profile不是隐藏来源优先级，缺省与显式reset分别解释。

### 运行适配与受控重配置

**规范入口：**[兼容迁移与退役](../../70-工程系统与演进/演进与实施/兼容迁移/README.md)

**需要识别的输入：**预先合格候选、监控条件、切换与状态转移

**适用性检查：**只在已授权语义包络内切换，并有防抖和回退

**失败恢复检查：**抖动、切换失败、状态不兼容时停止或保留旧路

**验证方向：**边界负载、反复切换、冷启动和恢复

**不承担的责任：**动态不等于每次下载最新版或随意热换

**业务作者目的：**运行中根据环境、资源、策略、能力变化受控重配置。

**作者投影与落实：**RuntimeAdaptation facet 声明允许变化域、触发、切换不变量、回滚/readback；未获准的 Provider 变化不自动生效。

**可区分的见证：**运行资源变化只能触发已获准策略；未选Provider出现不能自动热切。切换时保护旧状态/在途作用/回滚依据，不从一份新配置推完成。

### 跨组织、跨域与多权威协作

**规范入口：**[适用性与能力协商](../../70-工程系统与演进/演进与实施/适用性与能力协商.md)

**需要识别的输入：**独立域、契约、证明、数据驻留和争议

**适用性检查：**各域保留自己的权威、状态与责任

**失败恢复检查：**对方失联、政策冲突、撤回采用不能伪造全局一致

**验证方向：**跨域负测、退出、争议与部分履约

**不承担的责任：**不建立一个替所有组织裁决的超级真相库

**业务作者目的：**跨组织/跨域协作，多个 authority、数据域、执行域和责任边界共同完成业务。

**作者投影与落实：**Federation facet 明确 authority/domain/interface/data/effect/evidence/settlement boundary；不存在全局 super-authority，跨域结果保持各自 owner。

**可区分的见证：**各组织分别准入与结算自身范围；一方许可不能赋予全局超级权限。跨域超时/争议/数据不可见保留各方证据与责任，不强造全局事务。
