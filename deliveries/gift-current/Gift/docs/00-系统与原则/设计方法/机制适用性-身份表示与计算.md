# 身份、表示与基本计算

## 身份、表示与基本计算

### 主体身份与引用

**规范入口：**[对象关系与配置基线](../../70-工程系统与演进/信息与生命周期/对象关系与配置基线.md)

**需要识别的输入：**人、设备、定义、实例与外部标识映射

**适用性检查：**区分主体身份、内容摘要、修订和运行实例；同名不同物不合并

**失败恢复检查：**映射冲突进入待决，不按相似字符串静默合并

**验证方向：**别名、同名、重建、实例复用与跨租户负测

**不承担的责任：**不负责认定现实身份的真实性

**业务作者目的：**识别人、组织、设备、业务对象、定义与外部标识；决定何时是同一主体。

**作者投影与落实：**提供 Identity facet：主体角色、命名域、自然键/外部键、唯一性作用域、别名与证据映射成现有 Subject/Requirement；真实认证仍由 Provider。

**可区分的见证：**两个租户都使用外部键7但仍是不同主体；同一发行方的合格别名才可关联。撤销一条别名依据不删除原主体或另一条独立依据。

### 版本、快照与配置基线

**规范入口：**[兼容迁移与退役](../../70-工程系统与演进/演进与实施/兼容迁移/README.md)

**需要识别的输入：**作者源、依赖、数据、资产及部署配置

**适用性检查：**保存各自修订与兼容关系，冻结一次消费的准确内容

**失败恢复检查：**旧读者、新字段及部分升级分别迁移；不得用latest重解释

**验证方向：**往返、混合版本、旧实例仍存活及增量失效

**不承担的责任：**不把所有对象压进一个全局版本

**业务作者目的：**声明业务规则、数据、配置、模型、资产究竟按哪一版生效。

**作者投影与落实：**Version facet 只生成版本/兼容 Requirement 与项目/锁引用；所有消费固定准确 Revision，禁止 latest 偷换。

**可区分的见证：**旧请求固定规则R1，新请求可采用R2；禁止以latest重读旧请求。有效期政策变化与原内容revision分开，回放使用原时间语义。

### 声明、作用域与类型

**规范入口：**[共同语义关系](../../20-语义与组合/共同语义/README.md)

**需要识别的输入：**定义、名义类型、参数、公开边界

**适用性检查：**按定义环境解析，卫生代换；值域与效果进入调用资格

**失败恢复检查：**歧义、未解符号与不支持分开返回

**验证方向：**捕获、重载、递归类型、泛型与私有泄露

**不承担的责任：**不负责所有行业名词的核心枚举

**业务作者目的：**定义业务对象、字段、参数、作用域、接口与类型边界。

**作者投影与落实：**由 SemanticDialect/AuthorLibrary 暴露 authorShape；写回既有 Definition/Type/exports，不增加 UniversalBusinessType。

**可区分的见证：**两个模块同名类型不得无依据合并；同一声明的无关修订不凭文件路径制造新类型。泛型/私有边界与实际ModuleUse一起检查。

### 数值、量纲与单位

**规范入口：**[计算结构与算法](../../20-语义与组合/基础语义/计算基础/计算结构与算法.md)

**需要识别的输入：**整数、浮点、定点、精度、单位、坐标

**适用性检查：**溢出和舍入明确；量纲正确仍须解释语义类别

**失败恢复检查：**范围不足换合格编码或拒绝；不静默截断

**验证方向：**边界数值、仿射单位、货币时点、NaN与符号零

**不承担的责任：**不把相同数值类型当可互换物理量

**业务作者目的：**表达金额、数量、百分比、温度、时间、坐标等带单位数值。

**作者投影与落实：**Quantity facet 要求明确语义类型、单位/币种、精度、舍入、时点；货币和计量作为领域类型/Requirement，不并成 number。

**可区分的见证：**1美元与1米编码都为1仍不可相加；厘米到米只在给定量纲/比例中转换。仿射温度、币种/时点、舍入与溢出仍各有要求。

### 内存、所有权与资源寿命

**规范入口：**[控制流与存储寿命](../../20-语义与组合/基础语义/对象与控制/控制流与存储寿命.md)

**需要识别的输入：**借用、地址、缓冲、设备句柄、分配器

**适用性检查：**访问资格、别名、释放责任及地址稳定性可追踪

**失败恢复检查：**取消和跨语言异常仍执行合法清理；悬空使用拒绝

**验证方向：**泄漏、双释放、移动、重入与FFI压力测试

**不承担的责任：**不声称所有目标天然具有Rust所有权保证

**业务作者目的：**在原生/设备/高性能业务中约束缓冲、句柄、资源占用和释放。

**作者投影与落实：**仅在相交 native/device facet 暴露 borrow/ownership/lifetime requirement；lowering 绑定目标机制，失败保留未知/拒绝。

**可区分的见证：**借用缓冲尚被回调使用时不得释放；独立拥有的合格副本可脱离旧源寿命。取消等待不是设备/FFI访问结束。

### 一般计算与控制流

**规范入口：**[计算结构与算法](../../20-语义与组合/基础语义/计算基础/计算结构与算法.md)

**需要识别的输入：**函数、分支、循环、递归、闭包

**适用性检查：**保留一般程序表达能力；编译求值与目标执行分开

**失败恢复检查：**编译预算耗尽留下前沿，不把目标循环一律拒绝

**验证方向：**解释器差分、递归、错误传播与效果次序

**不承担的责任：**不凭高层要求自动发明缺失算法

**业务作者目的：**表达独特算法、分支、循环、递归、规则外的任意计算。

**作者投影与落实：**Compute facet 可直接引用准确已知供给；需要搜索时复用现有合格 Definition/Method 解析，独特算法进入 .gift 或原生源。编译器不从名字发明算法，不强制每次编译先做目录搜索。

**可区分的见证：**准确已有算法可直接引用；只有函数名而无实现时返回Need，不造空body。目标允许的递归不是编译期无限求值许可。

### 关系、图与拓扑

**规范入口：**[对象关系与配置基线](../../70-工程系统与演进/信息与生命周期/对象关系与配置基线.md)

**需要识别的输入：**实体关系、方向、基数、路径与图算法

**适用性检查：**边类型决定遍历、环语义和保持条件

**失败恢复检查：**未知边保留；循环按图种类处理

**验证方向：**有向无向、多重边、递归、共享约束反例

**不承担的责任：**不把状态图、调用图和构建图合成一种图

**业务作者目的：**定义实体关系、层级、网络、依赖、路径和图约束。

**作者投影与落实：**Relation facet 必须绑定边类型、方向、基数、主体、保持条件与查询；Graph UI 只是投影，不是统一图语义。

**可区分的见证：**两个不同方向/类型的边不可因端点相同合并；真正同一边重传可去重。删除一条关系后其余独立关系和索引依赖保留。

### 逻辑约束与规则求解

**规范入口：**[组合前提与进展闭合](../../30-实现解析/组合前提与进展闭合.md)

**需要识别的输入：**谓词、量词、硬约束、条件、软偏好

**适用性检查：**同主体约束联合求解，保留条件与量词作用域

**失败恢复检查：**不可满足、未知、不支持与搜索预算耗尽区分

**验证方向：**冲突核、反例、条件撤回与多候选检验

**不承担的责任：**不以综合分抵消安全或权限硬约束

**业务作者目的：**声明硬规则、资格条件、组合条件、偏好与冲突。

**作者投影与落实：**Rule facet 从领域 descriptor 生成 req:* 结构与 Require/Prefer；求解/冲突核走既有 Requirement/Assurance。

**可区分的见证：**同主体同时Require x>5与x<3应报冲突；改为x<8有可满足对照。偏好高分不能抵消硬约束冲突，预算停止不是不可满足证明。
