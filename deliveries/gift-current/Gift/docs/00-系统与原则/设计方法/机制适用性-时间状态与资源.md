# 时间、状态与资源

## 时间、状态与资源

### 时间域、时钟与历法

**规范入口：**[扩展语义与适配合同](../../20-语义与组合/基础语义/扩展语义与适配合同.md)

**需要识别的输入：**单调时钟、墙钟、逻辑时钟、仿真时钟

**适用性检查：**明确单位、精度、同步误差、时区与有效期间

**失败恢复检查：**时钟跳变、漂移和未知同步产生相应缺口

**验证方向：**回拨、闰日、夏令时、时钟失联与多速率

**不承担的责任：**不把时间戳相同当因果或同时发生

**业务作者目的：**表达时点、时区、日历、有效期、窗口、延迟和业务时间。

**作者投影与落实：**Time facet 在相交边界明确时钟域、时区/历法、容差、窗口与回放要求；能由固定类型/上下文合法推导的不重复填写。Target/Provider提供真实时钟能力，显示时刻不替代Instant。

**可区分的见证：**同一本地时刻处于fold的两个Instant必须区分；明确歧义选择后才映射。墙钟回拨不改变单调期限的含义，缺同步依据不能推同时发生。

### 状态、模式与迁移

**规范入口：**[共同语义关系](../../20-语义与组合/共同语义/README.md)

**需要识别的输入：**初态、状态变量、guard、transition、reset

**适用性检查：**区分观测、预测、期望和实际状态；保持不变量

**失败恢复检查：**非法迁移拒绝；未知完成不猜终态

**验证方向：**可达性、边界转换、初态一致性与恢复

**不承担的责任：**不强制所有计算改写为事务状态机

**业务作者目的：**定义订单/任务/设备/会话等生命周期、状态转移与迁移。

**作者投影与落实：**Lifecycle facet 生成状态、transition、guard、invariant、migration Requirement；运行实例与 Definition 修订分离。

**可区分的见证：**合法guard成立才迁移；观察值变化不自动证明请求的transition已执行。删除状态定义不删除旧运行实例的恢复责任。

### 事件、反应与消息语义

**规范入口：**[计算结构与算法](../../20-语义与组合/基础语义/计算基础/计算结构与算法.md)

**需要识别的输入：**事件身份、顺序、重复、窗口、订阅

**适用性检查：**声明至少一次等交付条件、去重寿命及处理效果

**失败恢复检查：**丢失、乱序、重放与毒消息各有处理

**验证方向：**重复投递、断连、取消、积压与重放窗口

**不承担的责任：**不凭消息队列保证端到端恰好一次效果

**业务作者目的：**发命令、记录事件、订阅变化、触发反应。

**作者投影与落实：**Messaging facet 明确 command/event/signal、delivery、identity、ordering、dedup、retention、replay；具体 broker 是 Provider。

**可区分的见证：**同revision修改X/Y的分片须完整消费；X到达后不能按revision丢Y。可合并通知不同于不可重建业务事件。

### 调度、并发与截止期

**规范入口：**[权限与资源管理](../../50-执行运行与观测/权限与资源/README.md)

**需要识别的输入：**任务、优先级、依赖、期限和执行预算

**适用性检查：**区分并行、并发、确定顺序、进展与公平性

**失败恢复检查：**过载限流或准入拒绝；期限失败执行明示策略

**验证方向：**争用、饥饿、优先级反转、尾延迟与WCET证据

**不承担的责任：**不以平均或p99耗时证明硬实时

**业务作者目的：**安排定时任务、并行工作、截止、优先级与公平性。

**作者投影与落实：**Scheduling facet 描述 trigger/deadline/concurrency/fairness/resource budget；lowering 可选 host timer、queue、workflow provider。

**可区分的见证：**两个业务触发同显示时间但不同出现身份不误合并；真实重传不重复作用。资源拒绝与错过触发分开，旧尝试未停不能靠重启补跑绕过。

### 容量、配额与资源分配

**规范入口：**[权限与资源管理](../../50-执行运行与观测/权限与资源/README.md)

**需要识别的输入：**CPU、内存、GPU、带宽、磁盘、能源

**适用性检查：**按真实可用量计入共享资源与峰值，不重复承诺

**失败恢复检查：**资源不足保留可行子根；回收不破坏在途责任

**验证方向：**耗尽、突发、嵌套配额、取消和邻居干扰

**不承担的责任：**不默认所有能力同时装载

**业务作者目的：**限制容量、速率、并发、配额、预算和资源使用。

**作者投影与落实：**Quota facet 区分 product quota 与 Gift execution budget；前者写业务 Requirement/状态，后者只由 Execution 准入。

**可区分的见证：**某租户剩余业务配额不等于Gift还有CPU预算；两项都合格才可执行。释放旧份额不能释放同名新预占。
