# 空间、仿真、测量与控制

## 空间、仿真、测量与控制

### 空间、几何与坐标

**规范入口：**具体几何类型与运算由作者定义/库/Provider 提供；公共数值、类型、身份和关系分别由现有通用 owner 保持，不建立 Gift Core 几何业务子系统。

**压力样本：**物理工程、制造与寿命用于检查坐标、几何、配置基线和现实对象是否被错误合并。

**需要识别的输入：**点线面、网格、坐标系、拓扑及尺度

**适用性检查：**变换方向、手性、容差和几何有效性明确

**失败恢复检查：**退化、非流形、坐标混用不能偷偷修形

**验证方向：**退化几何、尺度变化、拓扑与坐标往返

**不承担的责任：**不把视觉重合当几何或测量一致

**业务作者目的：**表达位置、形状、坐标系、空间关系与地理业务。

**作者投影与落实：**Geometry facet 由领域库提供 CRS/units/topology/operations authorShape；Core 只保共同类型/关系/数值，目标绑定成熟库。

**可区分的见证：**两个坐标值一样但CRS不同不能当同位置；准确变换及误差范围内才转换。未知几何操作保留原生/库边界，不补万能Core类型。

### 仿真时间推进与实验

**规范入口：**公共状态/事件/流由[状态、关系与流](../../20-语义与组合/基础语义/状态关系与流/README.md)拥有，恢复与现实作用由[执行与恢复](../../50-执行运行与观测/持久化与恢复/README.md)拥有；具体推进器属于业务/库/Provider。

**压力样本：**仿真时间推进与状态恢复用于检验多时钟、回滚与提交边界。

**需要识别的输入：**模型、求解方法、场景、输入和观察

**适用性检查：**状态、时钟、求解器与实验组织分责

**失败恢复检查：**失败步不混入成功轨迹；检查点绑定全部运行状态

**验证方向：**重放、事件边界、跨求解器及现实校准

**不承担的责任：**不提供一个拥有全部领域的万能Simulator

**业务作者目的：**运行离散/连续仿真、场景实验、时间推进。

**作者投影与落实：**Simulation facet 声明 model state、time step、solver、scenario、seed、observation、termination；runtime 可绑定成熟模拟器。

**可区分的见证：**请求推进t=10而参与者只成功至8时共同切面不能标10；全部合格至10才采用。私有模型回滚不撤销已发设备命令。

### 传感、计量与校准

**规范入口：**通用定量与误差由[定量合同与误差传播](../../20-语义与组合/基础语义/计算基础/定量合同与误差传播.md)拥有，真实设备读写由[平台生态与适配](../../50-执行运行与观测/平台生态/README.md)和 execution 拥有。

**压力样本：**测量、校准与实验检验观测、校准和 Evidence 的边界。

**需要识别的输入：**仪器、样本、时间、单位、精度与校准

**适用性检查：**原始测量、清洗、估计和人工输入分开

**失败恢复检查：**校准失效、饱和、遮挡和丢样显式

**验证方向：**已知输入、漂移、量程、时钟与不确定性传播

**不承担的责任：**不把传感器输出直接当世界真实状态

**业务作者目的：**采集传感数据、校准、处理测量误差和质量。

**作者投影与落实：**Measurement facet 声明 sensor/channel/unit/calibration/uncertainty/freshness/quality；真实设备读写受 Provider/Grant。

**可区分的见证：**传感器校准版本与单位匹配的观察可采用；缺校准不能填零误差。设备失联、过期数据、观测不到与确认不存在分开。

### 控制、执行器与安全状态

**规范入口：**现实命令、授权、资源、Attempt 与结算由[权限与资源](../../50-执行运行与观测/权限与资源/README.md)和[持久化与恢复](../../50-执行运行与观测/持久化与恢复/README.md)拥有；控制律/安全策略仍属于具体业务或设备合同。

**压力样本：**联合仿真与现实控制用于攻击模型回滚与不可逆现实作用的分界。

**需要识别的输入：**目标、反馈、控制律、执行器约束

**适用性检查：**命令、接受回执和实际动作分别观察

**失败恢复检查：**失联或超时进入系统定义的安全状态

**验证方向：**SIL/HIL、饱和、延迟、传感失效与急停

**不承担的责任：**不允许模型回滚直接撤销已发生物理动作

**业务作者目的：**控制设备/执行器、闭环控制、fail-safe 与安全状态。

**作者投影与落实：**Control facet 组合 state/stream/time/device/safety requirements；启动前验证 stop/override/fence/readback，普通软件权限不能代替物理安全。

**可区分的见证：**两个各自稳定控制器对同一执行量相加可能失稳；联合证书才覆盖组合。安全状态转换仍需真实时序、资源、停止/反馈能力。
