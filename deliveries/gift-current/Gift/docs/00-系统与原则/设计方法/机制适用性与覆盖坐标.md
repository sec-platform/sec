# 机制适用性与覆盖坐标

本页是**设计发现与复核坐标**，不是测试清单、作者必填问卷、运行时 schema 或产品支持矩阵。它把常见工程机制映射到真实规范 owner，帮助新任务发现相交责任、失败边界和可能缺口；只选择当前任务实际相交的条目，条目数量不构成覆盖率。

具体字段、状态、算法和资格由各规范入口拥有。公共机制可以完整复用，不以名字、行业、代码量或是否出现在本页判断它是不是 Gift 内置能力。若真实需求无法落到已有 owner，应产生区别见证并回到扩展协议，而不是向本页追加一个“其他”分类。

各专题中的“可区分的见证”均是**待验证的合同条件或反例对照**，不是已执行的Gift产品测试；只在对应facet、方法、Target与Claim被实际选中时形成验证义务，不能据此签发已支持的产品能力。

本页各机制下的业务目的、作者投影和区别见证是同一发现坐标的不同阅读面；不是新增64个必须安装的模块。机器发现遵循[意图描述](../../20-语义与组合/作者语义/意图描述与作者投影.md)，实际组合由[机制配方](../../20-语义与组合/组合/机制组合与作者配方.md)展开；每个“可选领域设计合同”只定义适用的语义，并不签发真实方法、Target或Provider资格；相应资格需要回实现/目标owner取得，研究来源仍留在research。一个项目只选择相交义务；[纵向符合性](../../60-保证与证据/验收/意图覆盖与纵向符合性.md)使用这些见证但不从数量计算全业务覆盖率。
