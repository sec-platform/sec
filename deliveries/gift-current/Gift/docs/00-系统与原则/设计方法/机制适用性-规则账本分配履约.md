# 规则、账本、分配与履约

## 规则、账本、分配与履约

### 政策、资格、计价与规则版本

**规范入口：**[适用性与能力协商](../../70-工程系统与演进/演进与实施/适用性与能力协商.md)

**需要识别的输入：**适用对象、条件、优先级、例外与批准

**适用性检查：**条件、地域、有效时间和裁决主体可解释

**失败恢复检查：**冲突规则、追溯变更与未知适用性显式

**验证方向：**边界日期、例外叠加、同主体规则冲突

**不承担的责任：**不把软件规则当法律意见或最终专业判断

**业务作者目的：**表达资格、规则、折扣/计价、政策版本、例外和批准。

**作者投影与落实：**Policy facet 组合 Rule/Condition/Version/Subject/Decision；价格只是可能输出，不在 Core 硬编码商业规则；解释和审计可追溯。

**可区分的见证：**R1产生的旧业务结果不能用R2回算冒充原事实；显式再评估须记录新基础。未经批准的例外不因规则求值成功生效。

### 数量、账本、价值与对账

**规范入口：**[持久化提交与恢复](../../50-执行运行与观测/持久化与恢复/README.md)

**需要识别的输入：**币种/单位、科目、分录、结算与外部回执

**适用性检查：**守恒、唯一记账、舍入和交易阶段明确

**失败恢复检查：**未知支付先对账；撤销记新事实而非删历史

**验证方向：**重复扣记、部分结算、币种混用与关账重开

**不承担的责任：**不把库存、现金和权益统称一个余额

**业务作者目的：**记账、余额、库存、价值转移、结算与对账。

**作者投影与落实：**Ledger facet 由领域库定义 account/entry/unit/posting/reconciliation/settlement invariants；事务、idempotency、external receipt 只是实现机制，不能取代会计语义。

**可区分的见证：**同单位借贷平衡是账本义务，外部转账仍须回执；二者不得互相代签。撤销/对账更正保留原entry及后继来源。

### 预占、配额、排队与匹配

**规范入口：**[持久化提交与恢复](../../50-执行运行与观测/持久化与恢复/README.md)

**需要识别的输入：**稀缺资源、请求、有效期和分配规则

**适用性检查：**容量、过期、公平性和确认状态可检查

**失败恢复检查：**超卖、过期确认、并发竞争有明确裁决

**验证方向：**极限容量、同时请求、释放失败与饥饿

**不承担的责任：**不暗中替作者选择商业优先策略

**业务作者目的：**预约、库存预占、排队、配额和双方/多方匹配。

**作者投影与落实：**Allocation facet 明确 scarce resource、hold/expiry、priority/fairness/matching policy、commit/release；选择 DB/queue/solver 实现但保持策略 author-owned。

**可区分的见证：**容量1的两个并发hold不能都被无依据确认；有真实串行/CAS对照才满足。旧hold过期回调不能释放已续代的新hold。

### 路由、履约、路径与交付

**规范入口：**[发布运行与资源生命周期](../../50-执行运行与观测/运行生命周期/README.md)

**需要识别的输入：**位置、网络、任务、可用资源与承诺

**适用性检查：**逻辑路径与物理可达性/时间成本分开

**失败恢复检查：**道路/节点变化、交接失败触发重规划

**验证方向：**不可达、时窗、容量、替代路径与现场确认

**不承担的责任：**不以地图路线证明现实可通行

**业务作者目的：**路径规划、订单/任务履约、配送、网络路由与承诺。

**作者投影与落实：**Fulfillment facet 组合 route constraint、resource availability、promise、milestone、exception、readback；地图/物流 API 是 Provider，不是事实 authority。

**可区分的见证：**规划存在路线不证明订单已送达；真实里程碑/异常/readback分别采用。部分履约不能以整体取消抹掉已交付数量。
