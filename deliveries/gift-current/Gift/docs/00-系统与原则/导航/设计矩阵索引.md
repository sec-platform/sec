# 因果角色与设计问题索引

本页是跨目录的阅读索引，保留L0—L6与ASMRVE的实际问题，不给每篇文档发行一个由文件夹推导的“层级身份”。[统一模型](../统一多层工程模型.md#七个因果角色及其不可混同的义务)拥有角色定义；[规范入口](../../README.md)唯一维护全量文件展开。阅读路径相交，不是必读顺序或产品执行流水线。

## 按ASMRVE检查某个责任，而不是检查每篇是否填了六格

| 设计问题 | 阅读方向 | 边界 |
|---|---|---|
| A 架构：为何存在、谁拥有、边界在哪里 | [设计综合与必要性](../设计方法/设计综合与必要性.md)、[总体架构](../总体架构.md)、[实现装配](../../70-工程系统与演进/实现与装配/README.md) | 一个文件不等于一个组件，新增抽象须有独立责任 |
| S 语义：什么含义与不变量必须保持 | [语义与组合](../../20-语义与组合/README.md)、相交Type/Requirement/Effect合同 | 不由当前工具或显示名称反推语义 |
| M 机制：怎样正常、失败、恢复与终止 | 先沿[方案入口](主题导航.md)选实际owner，再读其完整机制；相交时进入[编译机制](../../30-实现解析/内核/输入与阶段总览-编译责任-阶段与目标.md)或[执行恢复](../../50-执行运行与观测/持久化与恢复/README.md) | 纯计算不强造journal，存在恢复义务则不能省略 |
| R 落实：代码、配置、Provider怎样承载 | [实现与装配](../../70-工程系统与演进/实现与装配/README.md)、[目标与制品](../../40-目标与制品/README.md) | 布局与实现语言选择不证明物理能力已具备 |
| V 验证：主张、输入、方法和覆盖是什么 | [保证](../../60-保证与证据/保证/README.md)、[组织连续变化符合性](../../60-保证与证据/验收/组织保持与连续变化.md) | 书面案例不等于通过；一次通过不证明全域 |
| E 演进：升级、迁移、保全和退役怎样成立 | [演进与实施](../../70-工程系统与演进/演进与实施/README.md)、[保留恢复](../../70-工程系统与演进/信息与生命周期/存储保留与恢复.md)、[原决定](../../90-治理与参考/决策/README.md) | 不以新版本替换旧权限或抹掉在途责任 |

ASMRVE原完整定义仍在[统一模型](../统一多层工程模型.md#asmrve检查相交设计问题不定义对象地址)。本页只提供入口，不复制完整算法、状态条目或一份全库矩阵。扩展阅读路径需有真实问题和准确目标，不以目录/词频自动给未审查的交点打勾。

## 组织问题的三个不同对象

[文档实际归属](../../90-治理与参考/维护/文档架构.md#documentation-primary-placement)管本库的内容维护；[共同多维组织](../../70-工程系统与演进/信息与生命周期/多维组织与树形落位.md)管跨源码、包、文档的分组保持；[客户端树形呈现](../../80-开发者与接口/客户端/树形导航与结构投影.md)管节点出现与交互。三个入口彼此引用，不争写同一规则。
