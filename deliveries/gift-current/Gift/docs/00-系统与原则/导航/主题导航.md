# 全工程方案与责任入口

本文是当前设计方案的阅读地图，不拥有第二份字段、算法或状态定义。规范按真实责任聚合；这里把问题与已选路线接到准确正文。`L0—L6`、ASMRVE、任务、领域和历史只是读取视角，不是事实地址或必须走完的步骤。已知问题直接打开对应正文，不要求先通读本页。

本页的“当前选择”表示这份设计候选采用的方案；它不证明仓库main已采用、产品已实现或所有候选已比较完。[选择依据与重开](../设计方法/设计综合与必要性.md#design-choice-evidence-and-reopening)给出裁决标准；[当前前沿与实施闭包](../../90-治理与参考/状态/README.md)保留实现、证据和进一步设计的区别。

## 先找到实际方案，再展开细节

下表只保留路线差别与原拥有者；完整条件、参数、状态、失败、恢复和例子仍在链接正文。一个问题相交多个责任时需读这些责任之间的接口，而不是把整套文档同时作为每次编译输入。

| 工程问题 | 本候选选择与不采用的替代 | 精确设计入口与改变条件 |
|---|---|---|
| 整体架构是什么 | 一个工程中的准确身份、语义合同、责任交接与领域表示；不建万能对象表或统一全局事务 | [系统组成与交接](../总体架构.md#semantic-contract-responsibility-handoff)、[统一模型](../统一多层工程模型.md)；独立不变量/安全/恢复需求决定边界，不按层数决定 |
| 作者究竟写什么 | 新产品意图默认结构化模块；复用Definition/Profile和真实差异；原生算法保留，计算文本按明确区域选择 | [作者表示裁决](../../10-作者与输入/作者源/可替换表示与适用范围.md)、[结构意图](../../10-作者与输入/作者源/结构化源码.md)；不能因控件缺失逼作者抄低层实现 |
| 一个模块如何表达多领域 | 模块外壳统一身份/导入导出，各Definition body由实际dialect负责；不把所有Type/行为挤进Requirement字段 | [模块、dialect和绑定锁](../../10-作者与输入/作者源/工程源/工程清单模块与绑定锁协议.md#author-module-dialect-composition)；新独立语义才扩展，普通业务复用既有构造 |
| 变量、函数、对象及类型在哪里 | 计算主体保留精确绑定、求值、效果、控制与资源；领域公式/状态/查询能承担时不强降成手写循环 | [计算语义](../../20-语义与组合/基础语义/计算基础/通用计算与任务语义.md)、[文法与求值](../../20-语义与组合/基础语义/计算基础/文法类型与求值.md)；同名原生构造不自动等价 |
| 状态、关系、流、数值与仿真如何组合 | 各领域保留身份、时钟、重数、误差、进展及反馈；通过真实边界和联合义务接合 | [领域入口](../../20-语义与组合/README.md)、[组合前提](../../30-实现解析/组合前提与进展闭合.md)；存在几条图边不证明整组可实现 |
| 哪些细节由用户控制 | Meaning/Requirement、实现Control、运行输入及展示偏好各回唯一owner；Auto/Pin等降低到既有合同 | [完整决策面](../../20-语义与组合/作者语义/开发者决策模型与设定面.md)、[稀疏控制](../../20-语义与组合/组合/稀疏控制与目标限定.md)；隐藏不等于无语义，未定不取宿主偶然值 |
| 不调用LLM怎样生成代码 | 固定候选、解释与独立要求交确定性编译；查询、实例化、求解、降低、组合及检查由实际方法完成 | [无LLM责任链](../../70-工程系统与演进/演进与实施/实现语言与机制演进.md#intent-to-artifact-owner-chain)、[输入与阶段](../../30-实现解析/内核/输入与阶段总览-编译责任-阶段与目标.md)；独特新算法创作不冒充已存在的编译方法 |
| 内核为什么用Rust，TS还做什么 | Rust承接单一正式编译内核方向；TS/其他宿主适配成熟生态和产品接口，不维护第二语义核心 | [物理实现语言](../../70-工程系统与演进/演进与实施/实现语言与机制演进.md)、[绑定消费](../../70-工程系统与演进/实现与装配/源绑定与解释映像.md)；逐能力迁移须取得真实等价、性能及恢复依据 |
| 库与算法怎样动态选择 | 先资格、再比较；生态解析回传后重核共同依赖、feature、成本与剩余义务，直到冻结一致候选 | [解析反馈闭环](../../30-实现解析/实现选择/实现解析与候选资格.md#ecosystem-resolution-reconciliation)；不每次联网搜世界、不把解析成功当资格通过 |
| 优化怎样决定最佳方案 | 固定硬要求、比较域、成本单位和偏好；较小/已有方案参与比较，未知与不可比保留 | [搜索与合法剪枝](../../30-实现解析/实现选择/设计空间搜索与求解.md)、[设计裁决](../设计方法/设计综合与必要性.md#design-choice-evidence-and-reopening)；只有相应覆盖/界支持时称该域最优 |
| 多目标生成能共享什么 | 共享相同语义分析；Rust/TS各自固定目标方法、表示、依赖与制品；不让局部ABI要求污染全工程 | [成员与完整产物](../../40-目标与制品/目标/成员布局-完整装配与布局.md)、[Rust画像](../../40-目标与制品/目标/Rust目标画像与降低.md)；语义相同不等于同一构建或字节 |
| 原生构建输入怎么固定 | 原包管理器拥有解析语义；记录真实host/target、feature、profile和配置，锁不是完整构建输入 | [Cargo解析上下文](../../40-目标与制品/目标/Rust目标画像与降低.md#cargo-resolution-context)、[原生依赖取得](../../50-执行运行与观测/平台生态/依赖与生态解析.md)；真实作用按原权限执行 |
| 源码、文件、包如何组织 | 先选合法架构边界，再做成员、命名、布局；preserve/canonical/reorganize按本次目的选择 | [多维组织](../../70-工程系统与演进/信息与生命周期/多维组织与树形落位.md)、[结构稳定](../../40-目标与制品/目标/结构稳定与作者回源.md)；事务、隔离和发行边界不是目录名 |
| 只要源码能否不部署 | 可以；按请求分别闭合源码、构建输入、构建结果、发行或实际运行，不把应用一词当运行权限 | [按交付用途判定完整](../../40-目标与制品/目标/成员布局-完整装配与布局.md#delivery-purpose-completeness)、[开发主链](../../80-开发者与接口/需求到交付主链.md)；不能在失败后偷偷缩小原请求 |
| 增量、递归、并行如何正确 | 精确读集与负依赖、分型循环、共享生产者、挂起/取消与确定归并；正确相交重算始终允许 | [增量与性能](../../30-实现解析/增量与性能/README.md)、[递归并行远程](../../40-目标与制品/递归并行与远程编译.md)；无证据不声称最小重编译或物理上界 |
| 人/AI/编辑器是否另建模型 | 六工具接同一候选和真实owner；原生文本/CST及结构编辑共享语义，派生图无独立写权 | [工具协议](../../80-开发者与接口/工具协议/六工具与请求.md)、[编辑回写](../../40-目标与制品/表示/编辑与受管回源.md)；无法唯一回写时保留草稿，不猜写 |
| 保存、取消、崩溃怎样恢复 | 精确前后像、实际提交点、unknown读回与原恢复责任；纯计算不强制持久日志 | [持久化与恢复](../../50-执行运行与观测/持久化与恢复/README.md)；没有宿主原子能力就不承诺多文件瞬时原子 |
| 权限、秘密和远端边界在哪里 | 准入落在实际读取/执行/披露处，引用不授予权限；原Provider管秘密与资源 | [权限资源](../../50-执行运行与观测/权限与资源/README.md)、[信息接入](../../70-工程系统与演进/信息与生命周期/接入检索与派生.md)；先前许可不代签后续操作 |
| 哪一版算当前、旧版可否删除 | 配置选中、正式采用、当前资格、实际运行、历史证据与可删除性分开 | [选择与当前效力](../../70-工程系统与演进/信息与生命周期/对象关系与配置基线.md#selection-and-current-validity)、[保留与恢复](../../70-工程系统与演进/信息与生命周期/存储保留与恢复.md)；旧代仍有消费者就保留其责任 |
| 通过检查意味着什么 | Assurance针对准确Claim、输入、方法、环境和覆盖评价；静态证明不必先运行，运行成功也非全域证明 | [保证合同](../../60-保证与证据/保证/要求证据与裁决.md)、[组织连续变化符合性](../../60-保证与证据/验收/组织保持与连续变化.md)；设计案例、工具测试、产品测试分开 |
