# D01–D10 产品、作者与语义

## D01 产品中心是意图驱动的工程生成

当前实施选择为headless CLI/API先闭合作者到产物的路径；Code-OSS/VS Code Extension-first是人类主客户端方向，不构成核心编译链的前置条件。结构化作者源可直接表达已接受意图，复用定义承担已知含义，作者只补本次不可推导的差异；新增算法、类型和工程组合仍可在对应开放定义/Method中实现。生成新项目可不含原生手写业务文件，但已有原生工程继续保留自愿接入和受管维护路径。

作者操作依[INT0—INT8](../../20-语义与组合/组合/跨软件需求合同.md#意图进入同一作者源的完成与缺省算法)固定任务范围、读取已接受约束、推导可得值及处理委派，再将被采纳的真源交给确定性编译。自然语言解释或启发式生成只能形成可比较候选，不能未经采纳替代作者决定。IR、Binding、SourceMap和依赖图均由工具派生维护，不成为新的作者必填源。

**作者自由与实际职责。** 使用成熟定义时，短调用承载已写清的语义；定义不够时局部具体化或写新定义；需要新基本含义才修改相应扩展。多个实现满足同一合同可以自动选择，不构成意图不精确。尚未决定的行为、缺后端、当前授权不足和未取得运行结果分别处理。独立请求确实约束实现时保留其真实来源，不制造同义需求副本。

成熟语言结合现成库也可以得到同等简短的调用，应作为成本与能力基线。Gift必须通过跨要求组合、连续变更、目标保持、完整工程装配或错误回源提供可测增益，同时计入新前端、定义库、版本、调试和资格检查的维护成本。只有`tsc`通过不能证明这些收益；积累封闭模板也不能证明开放语义能力。提前实施全部未来语言、治理和GUI会把与首条核心编译链无关的成本变成前置，因此暂不采用。

**失败和重开。** 若新增普通算法要求改核心业务枚举、程序需要手修生成物、公开行为被无来源默认决定、模型每次重新搜索世界库或作者多维护一份相同事实，就修相交机制。完整冷暖任务和多轮维护收益见[生成收益](../../60-保证与证据/验收/覆盖与收益判据.md#必要性实验与生成收益验收)，未测不能宣称更快。不能以自然语言看起来短、输出行数、图节点或文档量认证成熟生态。

**任务和来源边界。** 只设计任务交付具体规格、取舍和未决，不自行实现或运行。新增协议的采用语义和取舍写入相应 canonical owner/决策理由；已定设计仍需实现、接入或证据的部分由[实施闭包](../状态/实施闭包.md)承接，实际采用以有权主体和精确版本为准。

## D02 中立语义与可替换作者表示

**落地规范**：[统一源码工程与多表示作者协议](../../10-作者与输入/作者源/工程源/统一源码工程与多表示作者协议.md)正式沿用本 D02 的原决定：不强制自研独立语言，结构化 JSON 可成为真实作者源；原生实现、Rust SDK 与 `.gift` 只是不同责任/可选前端。其确定性编译接合见[多表示输入与统一编译接合](../../70-工程系统与演进/实现与装配/多表示输入与统一编译接合.md)。第89版 `gift/author` 不曾取得强制默认地位，后续采用要核成本与真实可用性。

**实现选择：** 不把新的.gift文本语言列为产品前置或自编译种子。结构化意图直接绑定现成或新创作的原生实现；可选计算表示保留其语义但不要求重写已有算法。先TS或直接成熟原生供给均可，独立热点按同合同端到端成本升级。取舍是将语言生态与ABI适配作为真实责任，而非假装一套新语法能免除它们；相同成熟库下无意图收益的任务允许纯原生路径。详见[实现供给](../../30-实现解析/供给与替换.md)。

**当前决定。** 产品采用**意图/Block定义、类型化边界、准确组合、合格供给与同源精化**。新业务定义只写入唯一候选`gift.author-module/2`严格JSON作者合同，原`gift.author-module/1`仅为历史只读来源；每个非重叠**原生/计算**作者区域可以按其合格SourceProfile进入同一SemanticModel，不以前置`.gift`词法或将全部原生算法转写JSON为条件。结构业务JSON不会因为同时存在原生TS/Rust实现而产生双重业务真源；`.gift`文本仅保持已限定的计算画像。这个采用是设计者基于当前约束作出的决定，不冒称用户指定了每个字段、文件数量、GUI或统一后缀。

**设计裁决证据。（消费条件）：** 方案比较引用研究能解释为什么作出选择，但理由文本不能成为ImplementationBinding或运行资格的第二修改源。 合同归属：[研究事实、规范决定和新证据的冲突归属](../维护/知识记录与分域检索.md#gift-knowledge-evidence-owner)。

### 目标、方案和成本的比较口径

先固定共同要求：已有定义能简洁复用；独特算法在支持域内能正常创作；同一份已定义行为能够生成所需目标；目标特性可准确控制；文本、管脚和任务投影回到唯一作者源；源码、配置、资源与持续修改共同管理。任意原生程序的全部语义在任意目标上无损转换，不是这些有限承诺自动包含的结论。

四项多语言承诺分别评价：多语言客户端能够调用产品；不同平台实现遵守同一接口；同一份受支持算法能生成多个目标源码；任意旧程序及其平台专有观察都能互换。普通框架可以很好地实现前两项，却不能仅凭API相同取得第三项；统一二进制运行时也不自动产生指定语言的惯用源码。目标缺少硬件、权限或可表达观察时，不能通过忽略要求制造可移植。

比较完整替代路线时，所有路线都允许使用相同成熟库、生成器、宿主工具与已有上下文，并计入各自前端、适配、诊断、维护及目标成本。“在既有两前端旁增加第三条”的增量成本，只能支持不无理由新增入口，不能证明从原点选择独立语言必然优于替代。既有设计投入是迁移成本的事实，不是永久采用理由；缺少运行收益也不妨碍现在根据硬约束选择结构方案。

### 方案空间与明确处置

下表区分改变根架构的替代与可以局部复用的技术；不是全部必须实施的清单。框架、编译器、编辑器、运行时和存储并非同一比较轴，不能让一个候选仅凭名称同时取得所有能力。

| 方案族 | 真正省掉或提供什么 | 决定性代价、边界与当前处置 |
|---|---|---|
| 原生源码＋AI／语言服务 | 复用全部宿主开发方式，适合已有工程与独特单目标算法 | 仍需保证修改正确；不是相同算法跨目标保持的完整替代。作为可选原生路径保留，不成为中立缺项的必选出口 |
| 普通库、框架与注解 | 高层调用减少重复，可利用宿主类型、循环、类和调试 | 普通回调可能不透明，宿主行为不能自动中立；在单语言范围可独立最优，但不替换本产品的全部可移植目标 |
| 宏、引用、受检宿主子集或编译插件 | 复用熟悉语法并取得可分析代码，减少构造器样板 | 捕获域、绑定、阶段、作用、错误与源映射仍要定义；仅有AST不是中立语义。可作为真实替代前端，不同时建立无消费者的所有入口 |
| 分阶段程序与编译型库 | 已知参数在生成期处理，剩余计算生成普通程序；有条件消除框架运行成本 | 构造期不等于目标期；需要实际语义与终止预算。采用这种机制，复用既有定义与方法，不要求普通用户手写生成器 |
| Typed tagless-final／多解释代数 | 可借宿主类型检查某些DSL，并为同一表达式提供求值、分析和生成解释 | 类型保持不等于行为等价；编辑、持久源、身份和错误草稿仍须具体表示。允许用于内部方法，当前不把所有作者内容改为组合器树 |
| 现有多目标语言与编译器 | 直接复用语法、类型、部分标准库与多后端 | 目标集合、数值／错误差异、源码形态、内部API和维护要匹配。作为整段基础或后端的强替代供给；没有相交核对前不宣布Fable、Haxe已直接替换Gift |
| 可扩展语言工作台 | 复用语言片段、类型和编辑设施，并让高层定义逐段生成 | 工作台仍需实现领域语义，可能有IDE、模型格式与运行部署成本。采用其分责方法，不复制整套MPS或强加人类画布 |
| 完全自研独立通用语言 | 最大程度直接控制统一语义、诊断和目标策略 | 语言、工具链、标准库与生态维护最集中；不能仅因功能覆盖多而采用。现有有限语义有责任，自研范围不能无依据扩大为全部未来语言特性 |
| 图／表／投影与无代码模型 | 对连接、状态、规则和局部差异可更直接 | 这是作者表示，不提供缺失的含义；全图展开可更长。按区域使用已有结构与文本，不建设第二作者真相 |
| 模板、产品线和领域专用平台 | 在稳定领域内快速生成完整功能或变体 | 超出变化点会参数爆炸或分叉；作为有范围的定义库，必须允许在同一体系局部写新行为 |
| 约束、逻辑与求解式合成 | 在明确候选与逻辑域内从要求求实现或选择 | 不完整要求可能有多解，求解有模型／资源范围；不能代替全部一般程序。作为可选创作或解析方法，不是每次构建前置 |
| 示例／AI程序合成与修复 | 生成此前未写出的候选，减少手工草拟 | 样例不能穷尽任意行为；接受结果须保存并校验，不在普通重建时重新猜测。采用为创作机制，不作为唯一确定执行器 |
| 可执行语义与元编译框架 | 从规则复用解释、分析、验证等基础设施 | 规则仍要写对，生成质量与工具支持要核；可以减少自研解释器，不能用一份规则表证明漂亮多目标源码已经具备 |
| 统一VM、Wasm组件与多语言运行时 | 复用执行、隔离或互操作，减少每个宿主的重复实现 | 二进制兼容不是源码生成；运行依赖、跨边界拷贝与目标权利仍存在。按任务可选，不设为所有制品的必需运行层 |
| 网络服务或远端动作 | 集中实现，客户端多语言容易 | 数据披露、离线、延迟与完成未知改变合同；不是透明的语言中立替代。只在任务本来允许时使用 |
| 内容寻址程序库与双向编辑 | 降低命名漂移、定位与部分同步成本 | 不创造业务含义，也不提供任意生成代码的逆变换。复用已有身份／修订／映射，不新建程序数据库作为前置 |
| 等式饱和、自动调优与搜索 | 在合法候选空间中选实现，避免某些局部贪心 | 等式适用性、成本模型和预算先成立；不能发现未表达的要求或证明世界最优。作为实现选择的条件性方法 |

成熟例证的限定命题由[来源目录](../维护/设计依据与资料边界.md)拥有：MPS/mbeddr说明语言组合及多阶段生成并非必须从所有语法开始自研；LMS/Terra说明框架可在生成期消除而非永久留在运行时；Fable/Haxe说明现有多目标编译器是完整替代类别；WIT说明跨语言接口不等于行为语言。它们不被直接采用为新依赖，也没有取得Gift任务收益或符合性证据。

### 为什么选择编译型定义体系

在原目标不降低的条件下，普通运行框架不足以单独承担独特算法的共同语义与多目标生成；固定模板不足以承担开放定义；一个统一VM不能替代所需目标源码；纯自然语言执行不能提供固定重建。将这些不足全部补进任一方案后，会重新出现程序定义、解释、转换、版本与编辑责任。因此选择直接承认这些必要责任，并复用成熟供给，而不使用“不叫语言”隐去成本。

当前产品差异集中在已有需求复用、可分析的高层关系、局部精化、全资产与持续修改。普通循环、调用、对象、内存并非产品必须重新发明的卖点。已有`.gift`合同保持为当前有限实现规格；对它能合法降低或委派的部分优先使用成熟工具。要由现有完整编译器接管一段责任，先核其输入语义、输出类型、环境、诊断和可维护接口；不要求作者先改写两份源，不增加第三条无用途作者前端。

这不是独立语言已证明优于F#/Haxe等的裁决，也不是把产品改为某个宿主的附属库。当前架构选择已定，具体依赖只有取得相交资格才绑定；缺依据的整段替换继续作为真正的技术选型问题，而非已完成事实。有限语义的实现可以沿现有方案开展，不等待全世界工具比较结束。

**作者表面的简洁采用“渐进展开”，不是删掉控制维度。** 结构作者源只保存独特含义和必要选择；原生源码、配置和资产继续由真实owner维护；解析器对未固定的合法自由做选择。任何会改变行为、ABI、资源、持久化、构建或部署的区别，要么已有共同语义/Requirement，要么进入版本化稀疏控制，要么由原生owner逐字保留，要么明确保持Unknown/Unsupported；不存在“为了界面简单而忽略”的第五条路。客户端的简洁视图和完整有效配置只是同一事实的不同投影，不形成第二Property IR或万能配置数据库。

**开发设定面采用“统一投影、分散真实owner”，不采用万能Property/Config模型。** 用户确实需要一处看到并控制全部相交决定，但这些决定的语义层次不同：业务Meaning、Requirement、实现Control、原生配置、运行输入和Workbench偏好不能因为都能显示成`key=value`就合并。当前采用[完整开发设定面](../../20-语义与组合/作者语义/开发者决策模型与设定面.md#developer-decision-surface)：所有结果相关决定都可被查询、解释、搜索和下钻；编辑时回到唯一真实owner。这样既保留语言/工具级精确控制，也避免把整个工程重写成另一门配置语言。

**Profile只复用已定义含义，不隐藏控制。** Money、Timestamp、FIFO、durable-state等领域Profile及portable/offline/deterministic等政策Profile都只是版本化Definition/Requirement bundle；用户可从Profile开始，再只改差异，并随时展开其来源。Profile不取得实现选择权，Pin/Forbid/Auto等UX动作也不创造第二持久模式：Pin归一为精确hard requirement，Forbid只使用descriptor已定义的否定语义，Auto表示删除本层固定而继续委派。

**计算语言也不作为全部工程抽象的共同瓶颈。** 状态、关系、流、事务、资源、仿真等已有领域结构可以直接参与要求与实现选择；只有选定方法需要程序主体时才进入计算表示或原生代码。常见Queue/Map等名字可由普通Definition/领域组合或成熟供给封装，不能为了覆盖生态不断扩充核心作者kind；自定义Rust/TS保留为真正独特算法和原生专有含义的路径，不是高层设计缺口的默认补洞。

### 作者抽象的当前质量裁决

**选择对象同时包括作者成果与开发操作。** 产品作者保存准确意图、Block定义及必要组合/实参；工具在其上产生局部修改、检查、实现选择和产物。动作少不能替代作者抽象，源码短也不能替代实际维护范围。现有[操作协议](../../80-开发者与接口/需求到交付主链.md#intent-to-product)继续服务同一源，不改变该源的层次。

**原点比较。** 纯自然语言直接执行不能提供当前要求的固定重建；普通单宿主框架不足以单独承担支持域内的单源多目标源码；通用图／block能够保存关系但会给简单表达式增加定位和节点操作，类型化端口不能替不同领域的行为；强制完整文本虽然通用，却会让已覆盖任务重写无关内容。当前选择保留一份源及多种既有的精确动作，从任务事实确定最小合法动作；不是同时建设多套语言。

**为何采用直接语义入口而不是固定一种字节格式。** 当前候选`gift.author-module/2`和它保留的Definition语义应承担新业务的准确身份、组合与绑定，旧`/1`仍归历史读取；前端只需把选定SourceProfile可靠映射到同一SemanticModel，不必为了“统一”先实现或转换成另一门文本/JSON语法。严格JSON适合机器合同但有人工作量、重复键、引用和diff成本；文本/模型前端又有各自解析与往返成本。当前因此固定**一个区域一个可裁决的正式采纳协议与当前语义来源、多个可替换profile**，按真实作者负担、无损往返、诊断和实现成本选择，而不是并行增加多条真源。多个编辑者、离线副本或分区写者可以产生候选；是否能够合并成当前事实，由原 owner 的前像、权限和保持不变量裁决，而非由文件个数或最后写入者决胜。

**组合的准确地位。** 复合定义还能继续组合，是保留的机制；它既存在于普通函数和模块，也可以由管脚投影操作。SICP的组合闭包支持其可行性，不证明每个运算都应出现在全图画布。当前把Block作为封装和组合主结构，并不规定所有领域只有一种调度模型。没有合格实现的方框不是功能；把函数改称block不消除语言与库工作。内部模型也不能因为统一命名而丢失顺序、身份、借用、时基或错误。

**必要自研与无必要重复。** 必须定义含义，不等于必须自己实现其全部计算；必须有实际实现，不等于必须维护同义`.gift`主体。当前选择保持既有中立前端，但把成熟供给的直接绑定放在“重写一个缺失的Gift库”之前。通用检查、目标映射、真实差额及跨产物变更是Gift的相交责任；排序、容器、编解码、数值库、运行时和包解析在合格范围内交给成熟供给。新业务通常新增私有组合或参数，不新增核心Case；独特行为才需要真正的新算法。

**实际代价与替代。** 本方案仍支付中立前端、语义映射、必要库合同、诊断、源保全和目标适配成本。薄适配也可能引入复制、初始化、失败和依赖，不能被称为零成本；只有同名转发且无独立合同的层优先删除或改为绑定/别名。直接适配整组共同规则可以减少重复，但方法例外和跨目标缺口仍要说明。相同任务在成熟语言和同等库中更便宜时，该工程可以走原生路径，或替换相交编译供给；这不自动撤销全产品中立目标。当前没有总成本胜出的实测依据，不能把短投影、算法范本或更多图库当成替代。

**反转条件。** 当前动作对已知源仍需额外查询；高层修改隐含改变其余要求；源与图双写；新库迫使每次改词法；整个产品缺正常目标生成；更小的成熟供给在完整合同下成立。出现这些具体证据就重开相交选择。用户提醒研究block或SDK只提供比较对象，不计为支持采用的证据。

### 当前选择已经怎样改变成品

采用成熟供给不能只停在封装准入表。成品以作者ModuleRevision与ImportedModuleView共同链接；UseBinding在实际使用点与目标下区分源主体、外部调用和生成方法；无作者body的已合格根仍可生成；目标组合器汇合真实依赖和成员。原有Host桥接仅服务明确的port消费者，不再作为普通库调用默认。完整数据和算法分别由[物理实现](../../70-工程系统与演进/实现与装配/源绑定与解释映像.md#supply-physical-layout)和[编译主链](../../30-实现解析/内核/编译值服务.md#supply-aware-compile)拥有。

这增加的是原规则需要的内部联合和接口分支，不增加作者语言或永久供给平台。删除的强制工作是镜像算法、假body和无差额Host包装；保留的成本是准确调用、边界适配、目标依赖与真实资格。现有框架直接调用同一API也可以很短；本方案仍需在多目标、精确编辑和完整资产上取得增益，不能把标准库收益算成Gift独创。

### 一份源怎样同时简洁和开放

普通作者定义仍可以是声明、参数、主体与必要合同，也可以引用已有完整合同和实际供给，不强制补写主体。使用者调用它；确需新算法时在同一支持域写普通函数；同一AI可以承担两种角色。参数、公共要求、捕获与错误不要求再抄成意图树。一个函数没有专用编译规则时，正常编译其主体；有高层优化价值时，已授权的方法按确切定义身份与条件提供特化。完整处理由[可编译库路径](../../20-语义与组合/组合/模块封装-功能复用与作者责任.md#普通库与编译型定义的共同路径)拥有。

分阶段处理只把真正固定且可安全计算的部分提前；动态值留在目标程序。类、虚表、调度器与运行框架只有目标确需时保留，不将整个开发平台生成到每个工具。特化失败、超预算或方法缺失时，能满足原要求的普通主体继续可用；普通主体不满足硬实时、布局或内存要求时，不能以有结果为由偷偷回退。

文本和管脚是同一程序的操作面；结构编码不是每次请求的必填树。修改参数保留原定义；局部特殊化建立明确的私有定义和上游基础；全库语义改变更新真实消费者。目标代码的反向修改仍受准确映射限制，不能假设所有优化都有唯一逆。

### 已选控制与自造语法的真实取舍

这项计算表示的选择不宣称没有语言责任，但也不是所有产品必须采用新文本语言的计划。当前结构需求主面与可选`.gift`计算画像分别承担自己的精确含义；选择计算画像的任务用普通定义/实参创作、用局部差异修改、用类型化控制固定必要目标，见[实际控制协议](../../20-语义与组合/作者语义/作者信息完整性与控制入口.md#作者实际控制什么以及唯一修改入口)。需求没有现成定义时，由开发者或获准AI写足以决定行为的普通主体；不能只留下一个高层名称，再要求编译器猜算法。已有定义覆盖的任务不重写这些主体。

自造语法能够用直接的条件、调用、资源和领域构造消除某些宿主构造器噪声，统一词法与诊断，也能避开特定宿主对引用/宏的限制。它不会免掉语言的作用域、类型、效果、阶段、控制、资源和后端保持；也不会自动得到需求复用、所有目标实现或成熟生态。嵌入式前端能复用宿主工具，但受到实际捕获范围与解释接缝约束。比较时必须同时计入两边消掉的责任与新增责任，不能将“新语法更直接”扩大为“整体一定更简单”，也不能将“有自己的词法”本身当失败。

因此当前使用直接源，不增设逐运算s.call/s.choose前端，不把目标控制另写成属性语言，不为避免新语言而强迫所有需求进入普通运行框架。第一条基线仍是现有有限语义与直接TS目标；普通主体先正确编译，专用特化按有依据的收益增加。现有编译器若通过同一输入语义、输出、诊断与成本核对，可以替换相交供给；未选替代不是每次生成的前置搜索。

特殊需求从公开参数到组合再到私有源，是表达深度的变化，不是三份同义模型。一个调用的行为例外与保持含义的优化分开；共享类型和资源可能使其影响不只一处，必须诚实展示。源与元数据共同管理不同独立决定，不要求一份程序只有一个文件，也不容许相同属性存在两个竞争写源。

### 简洁作者形式的当前选择与代价

在已选择的计算画像内采用普通函数引用、被动lambda、有限返回/参数推导和确定导入别名，继续同一计算作者源，不把这些机制抬成产品结构主面的前置，也不新增通用DSL或嵌套作者SDK。理由是这些操作直接消除重复签名与转发样板，同时能复用现有TypeStore、函数值、CST、CallableIndex和目标降低；没有省掉独特行为，也没有改变保留原生源的路径。

代价是读取器真实新增省略规则、签名补全顺序和公开函数值根；它们必须一并落实，而非只改示例。递归、身份函数、模糊名义字段和不稳定捕获采用局部显式约束，不许用Any或任意全称泛化换表面短小。计算函数的默认实参、占位参数和新流水线语法不由这份有限合同提供；已有lambda/普通调用承担其已选功能，扩展需补求值、绑定和编辑责任。结构化需求参数已具有闭合`default`，与此不是同一个机制。

改语法必须同时保留唯一源：展开用于分析与阅读，不自动保存为更长的程序。成熟语言同样能提供函数值与推断，比较时允许它们使用这些能力；本选择只对消除已确认的重复作裁决，不由此宣称作者总成本已优于所有宿主方案。具体规则与反例归[简洁作者合同](../../20-语义与组合/基础语义/计算基础/紧凑表示与程序范式.md#compact-author-contract)。

### 需求的共同形状先于具体业务词与文本长度

当前进一步明确：作者抽象包含对象域、结果/结构/轨迹关系、保持帧、条件及真正的决定，不只是把函数签名写短或给业务换一个库名。既有Requirement与CompletionView承载这些相交内容；共同组合逻辑和领域叶语义分开，不新增作者语言或全世界需求原子目录。直接文件修改仍是正常方式，表/图/状态投影只有具体帮助时使用。

采用理由是同一套“映射并保持”“条件下只发布当前修订”“维护逆关系”能够跨软件复用，同时保留文件身份、命令义务和图基数等区别。更小的纯参数库足够时不强制加入完整约束树；普通编程和现成框架享有同样抽象，Gift的独立价值还须由可靠绑定、连续修改、相交编译与资产保持证明。仅增加通用节点名称不算这种价值。

不采用两种极端：为每个商业名字写一套核心机制；或把全部软件压成一个无语义的万能转换/状态图。检查方法与需求分开，防用当前方便验证的性质替换原要求；语义字段、变更规则、具体实现供给与全链消费者必须共同存在。完整合同见[跨软件意图](../../20-语义与组合/组合/跨软件需求合同.md#cross-software-intent-contract)。

### 成本、反例与重开条件

最低限度先筛硬要求，再比较有依据的开发投入、作者独立决定与持久内容、诊断修复、目标源码质量、冷暖构建、运行内存、依赖、长期迁移和退出。不把这些不同量纲相加成任意分数。包装层数量、关键字数、图节点数和首次短例不能代替完整任务比较。

必须攻击：相同库在成熟语言中已同样简短；一个微小特化迫使重写整个模型；普通函数需要先注册编译插件；泛型主体被执行成任意构建脚本；生成优化改变回调失败顺序；共享表示泄漏原生目标语义；新库升级使局部派生丢掉修改；内部可重复而目标源不稳定；一个目标缺特性导致全项目失去可移植资格。

现有多目标编译器若在承诺的值域、错误／效果、目标源码、编辑与完整成本上满足要求且更小，接管相应基底或整段后端；必须按该方案自己的成本比较，不计为额外第三前端惩罚。若真实需求只有单目标且没有独立中立生成收益，普通框架可成为该目标工程更好的实现，不将平台价值强加于它。若只有新原语才能保留接受的观察，允许有范围地增加语言责任。它们改变相交选型，不自动撤销全资产、AI优先或原任务。

**明确保留的底线。** 当前方案仍包含语言与编译器；不存在仅靠换名就消失的语义责任。能简化的是重复定义、机械结构、特化样板和后续同步。任意独特信息仍须表达或明确委派，不能承诺全部程序比使用同等库的成熟语言更短，也不能将未运行的设计判断包装成总成本最优证明。

### 当前语言深度与双向维护的取舍

对于已选择的原生维护与计算校准任务，先兑现TS原生文本/成组维护和受管目标回源；新产品主线仍先闭合结构化意图及供给接合。TypeScript与Rust已纳入通用目标计划：TS先形成首个完整闭环，Rust按真实消费者和目标差额逐项接入；Java暂缓，其他额外目标没有固定排位。C/C++及其他语言可作为按需原生供给；Rust也可以承担原生供给，但该角色与其已采用的目标角色分别裁决。已有调用、源维护、目标源码、二进制、ABI、设备或资源分别评估；没有新缺口时不为了说明“语言中立”自动增加第三个后端。

C能暴露原生ABI，不证明它必须是下一工作；Rust的所有权机制有价值，不证明其跨边界全部安全；某个动态语言也可能承载成熟原生数值实现。选型先筛任务和交付合同，再比较合格路线的完整成本，不按“更底层”排永久名次。条件范本保留的是接口知识，不是排程命令。

当前原生源码仍可直接维护；中立高层定义与实际已有供给不必有同义算法主体。源内容可以表达需求关系而不指定循环，普通程序保留独特行为的自由。例子使用低层语法不能据此把所有目标工程降成低层作者过程。

强逆向的当前价值包括读取现有工程、保持来源的修改回写，及无来源时提取有依据的行为/高层候选。源原文和心理意图可能不唯一，不构成取消后两项的理由。也不能以某个局部函数的等价恢复，承诺全部二进制的原始工程已重建。恢复算法和范围由[原生观察](../../80-开发者与接口/原生维护/原生来源与逆向边界.md#recovery-purpose)拥有。

### 有限逻辑组合为什么直接保存在结构源

当前选择在Requirement/AuthorModule语义中保存原All/Any/When/ForEach/Exists的精确有限逻辑结构，复用现有引用、主体和模块，不让产品作者先手写实现算法，也不发明另一套文本关键词；选择严格JSON SourceProfile时，该逻辑结构具有对应的精确JSON codec，但其他合格Profile无需先转成JSON。只有静态、有限且有准确类型的输入进入直接条件与量化；运行、无限集合和更广关系仍由领域语义承担。这样可直接描述产品变体、共同参数和有限候选，代价是读取器必须实现词法绑定、空域、分支类型和作用域检查，不能把JSON可解析当成全部支持。

全部展开成平铺叶项会丢掉共享约束和见证位置；全部展开成析取范式可能产生巨大中间状态；只保留高层标签又无法据以实现。因此采用保留公式与作用域的有限工作表，按需要扩展，允许保守相交重算。嵌套数量不是任意规定的固定禁令，实际资源预算限制工作并返回未完成，不改掉原需求。

偏好默认在共同范围内评价，有限any/exists内禁止直接或通过use隐藏prefer。另一种方案是给每个分支独立评分，但没有跨分支统一度量时，候选可通过删掉目标获胜；故不把这种行为当作默认。需要真正的条件目标时，允许已固定产品配置决定目标，或另行给出有共同口径的评价定义。未知高优先指标不通过比较次一级被偷偷忽略；稳定选定可行者仍然允许，但优越性声明另受证据约束。

该选择没有采用Alloy、SyGuS或SemGuS作为必装引擎；相关材料只校准量词、统一合成目标和证据边界，见[有限逻辑与合成依据](../../../research/sources/证明类型与编码.md#finite-logic-synthesis-sources)。若实际领域需要不能表达的主体值、动态成员或概率条件，重开其领域接口与方法，不以已有有限范本代签全能力。

### 作者成品与闭合默认的取舍

结构作者源承担独特行为和公共消费边界，不要求每个产品重写底层实现。显式default仅补闭合value参数，减少多处重复固定同一名义策略；它不同于运行函数默认、软优化偏好或隐式环境读取。保持全显式参数的旧写法合法。拒绝更强的相互依赖默认、subject默认和深合并，代价是某些关系仍需明确复合；收益是作用域、主体独立性和升级含义可直接核查。若频繁需要封装仅为计算默认，应重新比较有限依赖默认的真实成本，不直接开放任意执行。

exposes解决一个需求定义含多个同型主体时的公开边界问题。它不复制签名、不分配运行对象，也不为每个表达式建接口；目标仍消费实际合同。不开新字段而靠“取第一个subject”更短但不稳定；强制所有项目套一个Workbench根类型更整齐但改变产品。因此选择局部可选边界与画像准确映射并存。两项属于当前未发布结构编码的明确补全，不宣称所有旧读取器自动支持。

成品范本用同一关系检查不同消费条件，不用六个包装名遮住六组实现义务。全形态路由不等于所有领域都已完成，真实差额和未知继续按所属U保存。

### 作者成果与记录更新的取舍

真实复用使产品使用者只维护必要差异，而不是使整个软件凭空成为两行。新[作者结果](../../20-语义与组合/基础语义/计算基础/作者表示与实现分工.md)与完整源把高层调用、独特主体和准确宿主责任分开；成熟TS框架用同样供给也可同样简洁，不能以样例行数证明Gift净收益。

采用有限`with`不是为追求新语言特征：大型不可变记录的局部变化在原形式需要重复所有未改字段，字段增加容易遗漏。每类型setter和普通构造是保留的较小替代；当全部使用方只需一两个专有操作时并不强迫改为with。通用反射更新、任意深合并、镜像配置语言和编译期执行程序会增加更大含义/权限成本，当前不采用。新增构造的实际解析、类型和回源成本不能被“上下文词而非关键字”掩盖。

MVU式单实例工作台适合展示纯状态和外部命令分离，但不作为所有软件唯一架构。硬实时循环、编译器IR、数据库关系与动态对象保留各自模型和真实并发/资源合同。已有流程设计仍必要，只是它不能替代源码结构的成果，二者完成条件分开。

### 需求声明的定义角色与作者前端

原目标要求需求抽象，普通fn及开发工具不能代替产品最终源。需求声明作为既有Definition角色保留；本次结构形式直接编码其主体、参数、需求条款与关系。候选`design/use/prefer`的语义贡献分别对应定义、实例化、硬要求和偏好；这些贡献保留，新增词法不再被认定为当前必需路线。旧计算语法不删除，也不与结构源双写。

结构化记录并非必须猜schema：外壳、体种类和精确解释已绑定时，可以明确区分需求根、普通值和运行动作。先前以“记录只能靠任意schema猜”否定结构输入的论证不成立。独立文本语言能改善某些输入简洁度，但增加词法、诊断与编辑成本；高层函数适合确定计算组合，不能不加合同就代签需求集合、非运行主体与进展。当前选择严格结构模块直接进入已有RequirementTerm，保留其他形式的真实适用范围，不把用户历史提醒当成批准文本扩展。

若真实采用表明带强schema和静态阶段的既有前端可以保持同一含义与较低总体成本，可以替换前端；不撤销用户的需求作者主面，也不因此退回让每个产品重写普通程序。库方法与目标降低可以复用成熟设施；CUE、QML、Rosette和MLIR分别只提供约束组合、声明式表达、域内合成和多级合法化的机制参照，不证明本系统已实现。

## D03 需求与实现源分离

**选择与正向机制。** 需求规定接受的行为，设计给当前机制，源码定义具体程序，证据只支持实际对象。原任务与当前候选通过精确引用关联，可以来自同一作者文件，不重复保存函数体。编辑require/ensure、独立案例或要求源时，服务分类差异；实现编辑不自动移动要求接受关系。取得相应委派的目标变更可以一起采用，不强迫普通开发逐次人工批准。

候选自身的类型和编译保持，分别于原要求满足、实际部署和用户效果判断。[任务满足流程](../../60-保证与证据/保证/要求证据-要求主体与声明范围.md#原任务要求与候选合同的满足判定)从接受输入、结果、保持与环境逐项连接实现和方法。源不完整可以保存；生成所选根需要有实际主体或合格绑定。增加拒绝guard可以保护非法调用，但若拒绝原承诺合法的输入，就没有完成任务。

**必要区别。** 函数值通过高阶传递仍保留自身契约入口，普通函数类型不复制其全部行为；纯度不保证终止。前后条件的定义域和求值顺序要检查；互证需要合法推理规则，不因相互引用获得独立证明。后置失败不撤销既有作用。消解检查时把真实依据加入产物依赖，失效后重新判断采用资格。

**成本与更小替代。** 直接要求生成一个给定函数时，以该源为语义输入，不建立镜像需求文件或全域求解服务。有独立用户要求时保留其原来源，细节可由已有上下文推导。详细规范可以长，AI请求仍只写相关变化。保留运行检查可能更易实施；静态消解需要对应保持依据，不能单凭更短源码决定。

**反例与重开。** 收紧前置排除难输入、将后置改成恒真、删除独立验收、只验证新候选后反称原需求已满足，都要求回到接受关系和满足判定。真实任务有意改变时允许形成新要求，不为维护旧结果阻止演进。具体语言规则仍由[契约执行](../../20-语义与组合/基础语义/计算基础/文法类型与求值.md#行为契约的执行与证明责任)和[函数值合同](../../20-语义与组合/基础语义/计算基础/文法类型与求值.md#高阶调用中的契约不能丢失)拥有。

## D04 类型化能力端口

**选择。** 类型化端口用于有相应语义的连接分析和编辑；既有定义可经公开合同组合，产品作者直接复用Block而不展开实现。这个主结构不要求普通函数逐运算形成节点、不要求画布或每项需求先手工分块。私有算法可普通编译，满足条件时消除组合边界并保留来源；不新增运行实例或部署单元。

**正向机制。** [组合合同](../../20-语义与组合/组合/定义与接口.md#block-composition-contract)定义外部参数、结果、效果与保持，内部由原函数／区域或领域结构保存。调用、事件、流和资源按实际类型、激活、顺序、错误、寿命与基数解释。参数修改、一级展开、完整表达式抽取和内部值暴露使用[共同编辑](../../20-语义与组合/组合/结构编辑/编辑重构与确定回写.md#block-boundary-edit)，不另存一份可独立写入的展开图。

**实现与公开的边界。** 底层语义要由普通主体、成熟库或合格后端真正实现。调用者不必读取私有循环，但必须知道自己依赖的输入域、结果、失败和作用；摘要不够强时，工具按实际权限分析或保留缺口。复合外壳没有实现，不算功能完成。公开边界不把所有内部旋钮变成参数，新增可控制点要有消费者并保持未改使用点。需要下探的选择必须有真实owner和可达的定义、控制或受权源码修改路径；没有预置开关不构成能力上限。显式固定与自动委派可以在同一任务混合，使用[现有稀疏控制与实际施加合同](../../20-语义与组合/组合/稀疏控制与目标限定.md#mixed-explicit-and-delegated-control)，不另造全局决策系统。只有完整观察、失败与生命周期合同保持时才能透明替换，新增区别按相交接口演进。

**代价和更小替代。** 已知文本直接edits更省，现有函数已有适当边界时只折叠呈现，不再次包装。结构协议只传当前变化；普通局部值不领取全局端口身份。资源管脚仍遵守move/borrow、分配者、接受点和回调注销；零复制需要别名、旧值读取与生命周期条件，不满足时采用合格复制。GUI不是AI首期前置，也不能把管脚永久降为只读装饰。

**反例与重开。** if内除法外提、两次发送合成一次、一次采样被重复、流自动广播、两个同配置会话被合并、资源重复消费、旧回调修改新代、无限结构展开，均须改相应具体合同。数据边不是权限，折叠不是无依赖，合法递归不是必然死锁。数据库同名API但隔离或失败不同仍不兼容；普通纯任务不因此承担数据库前置。领域自动抽取尚无保持规则时保留明确范围，不用“都叫block”伪造跨域同义。

**依据。** 复合过程可按同类过程使用，支持递归封装；异质actor的内部执行机制需要明确边界，支持不能将全部图边解释为同一种调度。来源见资料章的SICP与Ptolemy条目。当前不复制Ptolemy运行时或director体系，成熟具体实现仍在合格范围复用。

## D05 公共数值与目标语义

**选择。** 数值、Text、容器和相等具有自己的值域、错误、顺序和观察合同；后端及逻辑求解器不能用同名类型替换。数学Int、定宽、定点和原生数值分别适用；公共Text是Unicode标量序列，不被某个String实现的字符表限制。

**机制与代价。** 源到目标、源到证明均采用明确编码：负商余需保持截断规则；完整Text用合格标量序列模型，只有证明了受限域才可用较窄String理论。相等不能只看哈希；有限值允许物理共享，但逻辑序列化预算要考虑展开大小。多目标可能引入运行库、适配和检查成本；单目标可选显式原生画像，不能暗中缩窄公共含义。

**替代与反例。** 直接采用宿主类型最省事，却会在大整数、NaN、负零、Unicode范围、错误哨兵及别名上改变行为。不可映射时可换证明方法、限制该目标或保全原生，不阻断所有设计。新增规则或目标改变观察域时重审对应绑定，不凭任意epsilon忽略差异。具体规范见[值域](../../20-语义与组合/基础语义/计算基础/通用计算与任务语义.md#值缺失与数值)、[逻辑编码](../../60-保证与证据/验收/方法与独立证据-独立性可信基础与求解.md#契约到求解器的语义保持)与[目标映射](../../40-目标与制品/目标/具体降低与目标输出.md#中立语义与目标表示的逐项映射)。

## D06 多入口共享语义而非同一文本文件

**选择。** 当前文本和结构是作者输入，表格与管脚是按需投影；一个区域只有一个实际写源。新增宿主前端需先按D02改变采用决定，不是当前并行必做项。当前基础体`gift.semantic-body/1`可直接进入共同分析，既不强制先打印`.gift`，也不把JSON格式当成天然完备的程序语义。

**机制。** [基础体与编辑规范](../../20-语义与组合/组合/结构编辑/README.md)定义局部键、绑定、类型、区域、草稿和三个精确操作；[区域迁移](../../10-作者与输入/作者源/工程源/作者编辑保存与迁出.md#作者方式切换是一次明确的迁移)保全原内容、未知和谱系，再转移唯一写权。文本CST回写比较真实绑定与增量，不只比较打印后类型。无操作原字节保留，结构产生的源码若没有原文补充只承诺规范输出。

**代价与边界。** 两种前端、节点和源补充需要真实适配。未知类型、原生语义、编译标注和错误节点有保全责任，支持一个基础函数体不意味着支持全部领域。缺适配时保留原源并允许已闭合局部继续，不强制转成原生，不用最后有效AST覆盖新草稿。没有真实身份映射的独立创建仅能比较相应含义，不取得共同作者谱系、权限或同字节布局。

**客户端与成本。** AI/脚本的首个 headless 闭环不增加 GUI 门槛；已选定的人类主客户端在实际启用时承担自己的交互与同义符合性验证，而不是重新定义业务语义。短ID可能增加查询往返，完整树又增加输入；按任务选择真实片段。画布坐标默认无程序作用，具有空间语义的领域另按其规则。上下文失效不换latest；图文各自保存一份或任意整文件重印，都是需要修正的竞争作者。D33仍为历史载体别名，D41负责公共模型与前端依赖方向。

## D07 混合工程表示

**裁决。** 混合工程是可支持的画像，不是每个工程的默认义务。中立全作者、既有原生作者和受控混合均使用同一身份、要求、依赖、变更与证据规则；具体入口不会自行扩大权限。原生作者、提供者内部实现、生成的原生源码、知识未知四者不能合成一个“原生区域”。

**机制。** 每个区域一份作者源，解析结构与展开树派生。中立源可以表达全部受支持的应用行为，依赖的普通库由提供者或后端维护；原生作者只在实际已有资产或用户选择下启用。观测类型/签名不重复填报，业务要求也不被当前实现自动覆盖。多目标保持按每个区域真实语义与绑定判断。

**替代和代价。** 强制全迁写会损害存量连续性；强制混合会让每个复杂需求都被推回原生；两份源双写会漂移。选择按责任使用，但对中立生成缺项明确是语义、目标、实现还是环境不足，不默认让作者另写宿主代码。

**反例。** 无原生文件就不能创建工程；系统使用数据库驱动便宣称应用非中立；中立文件自动获得保证；原生函数永远被当黑箱；接管生成物后仍宣称旧模型无损重建。出现任一项都应修相交规则，而不是强迫所有项目采用同一比例。

## D08 保全式导入

**采用方案。** 先在真实许可范围捕获字节与覆盖，再解释内容；原资产保持不变。源只读取一次的捕获内容供解析、摘要和生成共用，避免阶段间重新读取活动路径混成不同输入。

**具体处理。** [观察协议](../../80-开发者与接口/原生维护/语言前端与直接编辑.md#从输入范围取得可用快照的正向协议)定义层选择、固定版本、弱读取/强快照、阴性回答、编码和发布。未理解文件作为不透明资产保全；无读取权、失败、未完成和精确不存在分开。统计性“未见”不能作为创建或去重的强前提，目标提交仍重新比较。

**替代和代价。** 原构建执行可以取得更多行为，但它是获准后的实际作用，不是普通导入的隐式步骤。不可变树或宿主快照更强但有能力/存储成本；弱捕获适合较小保证，必须保留其范围。已有固定输入直接复用，不为所有片段引入全仓观察。

**验收与重开。** 合法读取产生可解析内容和真实覆盖；权限错误不能变absent；读后变化不改写旧输入；捕获树不是原工作区原子切面；所有后续写回仍核对前像。发现其中任一错误就修观察或消费者，而不是删除原资产。

## D09 渐进语义提升

**决定与机制。** 在已有代码上需要高层编辑或移植时，只提升有保持规则的构造；对业务意图的推断形成候选，不作为已证语义。原生区域按任务需要逐步提升，跳过某层时仍承担该层原有的约束，不要求所有输入经过完整IR阶梯。

**取舍与反例。** 保留原代码及类型化不透明边界是更小替代，但可编辑的公共含义也较少。同名函数不能据此认定同一责任，动态外部调用不能漏掉，未知区域不能被模板覆盖。需逐语言维护规则与兼容关系；收益不足以覆盖维护成本时停止该项提升，不停止其他已成立路径。支持的回写必须经过相应映射与保持检查。

## D10 本地身份与来源对应

**选择与机制。** 稳定实体身份、可变显示名/路径、内容修订、类型合同和物理对象分别使用。默认在固定分配域内创建实体ID，移动或重命名不自动换ID；旧对象删除重建、独立复制需要新身份或明确映射。Git分支/克隆同一作者谱系可以保留语义身份，但不复制运行权限和部署控制实例。

**取舍与反例。** 外部协议确以不可变地址定义身份时采用它的合同；内部临时AST无需全局ID。身份索引与歧义处理有成本，不能按名字合并同形对象，也不能因ID相同把不同单位、版本或资源实例的类型直连。路径仍影响导入/反射时跟踪真实依赖，稳定ID不是行为永远不变的证明。

**规范与重开。** 见[身份](../../10-作者与输入/作者源/工程源/身份断言与采纳.md)、[类型实例](../../20-语义与组合/基础语义/计算基础/通用计算与任务语义.md#类型与包实例的身份)与[副本分支](../../10-作者与输入/作者源/工程源/作者编辑保存与迁出.md#副本分支与权威重建)。ABA误合并、分支误发新ID、复制控制器恢复旧权或类型锁无法闭合时重算对应边界。

**文本续用的具体选择。** 通过精确base与编辑关系保持声明身份，只持久化必要的声明映射，不复制整棵AST。外部改写有歧义时保留内容和候选映射；相似算法不能自动签发旧身份。对应的局部诊断比“全部ID写进源码”更轻，比“完全不保存映射却承诺不丢身份”更诚实。

## 通用计算设计不是无用，而是不宜继续主导产品

前期语义计算、类型和源码生成资产的设计价值仍成立；Gift111 记录的有限计算机制可作为专业方法的研究候选；该历史实现不随本包提供，Gift112/113 的模型也未直接接入它，不能借旧测试宣布整体意图→源码产品已实现。项目价值在于可版本化业务意义、联合目标/权利/资源处理和合格现成供给的装配，而不是比普通语言包含更多计算关键词。

并不因此宣布“所有业务语义都能由有限固定标签枚举”；需要有限开放生成/组合规则加作者定义的、可解释可观察语义，允许领域新概念独立扩展。在已有成熟引擎的领域，重新实现等价功能的成本必须有真实收益论证；参考资产应完整保存、未使用功能不得写成产品完成率。
