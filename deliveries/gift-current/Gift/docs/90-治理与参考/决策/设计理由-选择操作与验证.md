# D49–D56 选择、操作与验证

## D49 资格过滤先于偏好且豁免有范围

**选择与机制。**本次要求、动作和声明的硬资格先于偏好。单项已满足、明确违反与仍需条件分开；组合检查实际输入域、共享资源、作用和环境。设计候选可以有开放假设，不能自动成为可运行绑定。一个适配新增了网络或精度损失，也要参加资格检查，不因名为内部实现取得豁免。

**有界自由。**已有政策可以决定低风险默认，不要求每次用户填写；真正非等价且未委派的行为仍需决定。固定排序只消除允许的表示差异，或执行已接受的取舍。豁免由实际有权主体在可豁免范围作出，绑定对象、时间、失效条件与到期；不能用成本分数抵消硬禁止。

**更小替代与代价。**显式绑定一个合格实现无需全局市场。全部未知剔除会阻止设计，未知一律接受会产生越权和错误保证。新证据或撤销重评当前资格，旧内容和历史锁保留；Pin遇硬冲突仍报告，回退不能重新引入已被排除的候选。

**反例和当前归属。**候选类型正确但值域不接合，计划资源存在但实际未取得，或廉价实现需要未许可披露，均在[组合算法](../../20-语义与组合/共同语义/边界摘要与跨域组合.md#组合边界摘要与义务闭合算法)和[执行准入](../../50-执行运行与观测/权限与资源/授权与执行准入.md#计划合格到真实准入的两次检查)分别处理。

## D50 成本向量和有范围的优化结论

**选择。**按当前任务、输入规模、主体、目标和时间范围比较完整路线，先保持硬要求，再用有依据的同量纲成本选择。源更短、工具调用更少、单个算子更快都不能独自证明整体收益。

**机制。**[联合选择](../../30-实现解析/实现选择/设计空间搜索与求解.md#带边界状态的联合搜索与合法剪枝)保留后续需要的布局、驻留、作用、寿命和未满足义务；[预算组合](../../30-实现解析/增量与性能/性能预算与复杂度.md#端到端预算的组合规则)分别处理时间、实际分配、误差和风险。关系场景另保留bag重数、排序键、NULL层次、快照与安全屏障，不能为下推更快而改变异常或披露。

**默认与代价。**既有合格绑定和简单完整计算优先，无多选就不搜索。只有需求与真实收益支持时维护索引或增量；多对多输出、长键、转换、传输、初始化、旧读者及状态迁移进入成本。估计决定搜索次序，可靠上下界才承担证明性剪枝。无测量时给可逆默认和观测办法，不填伪收益。

**反例与重开。**CPU上游2 ms加8 ms传输可能输给设备驻留3 ms；两侧重复使join输出倍增；SQL提前除法可能比完整顺序快却错误；旧top-k没有后继无法支持任意删除。任务、目标、真实消费者、硬约束或依据变化时重新裁决相交选择，保持原操作恢复意图，不因新候选出现就抖动切换。

**子域优化与完整产品。** [guarded方法](../../30-实现解析/有条件实现与公共行为保持.md)使窄原生核和通用实现共同满足原域；代价是守卫、分支、双方法成员与生命周期。g必须先于效果且不重求实参，错误/同步/隐私不变；小输入直接通用、同语言实现或复制同步接口仍是正常替代。没有完整成本依据不强行采用快速核。

择优过程本身改变证据解释，采用[探索/确认分离](../../60-保证与证据/验收/覆盖与收益判据.md#adaptive-confirmation)。现有固定样本和同负载比较不足以自动覆盖跨候选搜索；默认冻结候选后独立确认，有合法方法才复用留出或顺序停止。预算不足时保留可行但未证更优，避免为统计仪式阻止独立正常工作。

## D51 操作完成绑定提交点和实际读回

**决定与机制。**真实操作按所属提交点、成员读回、资源结算与残余判定完成；退出码、响应和文件存在只是对应观察。发布前核准入，发布后才取得本次提交与读回，不能把“已完成”作为启动前提。回执绑定操作、目标、成员和实际修订。

**恢复。**导出重试比较原意图保存的精确预期树；预先存在的目录不自动追认。持久重启根据可信操作记录和前后像判断。确认丢失时按合同读回，或在目标确有同键去重保证时安全重试；终态不重复业务写入。读回不一致保留未知，当前权威也不代表全知。返回阶段再出错记录为完成后错误，未完成保留实际残余。

**取舍与反例。**纯函数无需外部读回；成熟目标的原子回执和幂等机制可直接复用。HTTP成功却未提交、超时重发不可逆效果、恢复未结算却声称无作用，都是错误。全删除重写还会丢人工修改。状态查询、回执和恢复有成本，仅按真实作用启用；目标没有可用确认能力时保留完成未知，不擅自降低硬要求。

**领取与物理结束。** 子任务成功、组合采用该结果、结果拥有权移交、外部作用结算是不同完成点。all失败时未采用Own由原域收尾；一个共享等待者离开不能取消别人仍需的任务。立即回收可降低表面内存但可能导致悬空，全部永不回收又积累资源；采用登记、一次领取、有限排空及合法移交，而不是用GC或隐形detach替代。对应[物理接合](../../70-工程系统与演进/实现与装配/能力接合与文件责任.md#completion-physical-seams)是实现设计，不是代码已存在的声明。

## D52 统一应用操作而非统一所有界面

**位置辅助与端生命周期。** 保留普通源码直接编辑，只有需要准确位置、补全/导航或完整重构建议时协商authoring-assist/1。该分支复用原EditPlan/候选，没有另一类型系统或权限根；无它仍可使用原files/edits。CLI/SDK/已有编辑器在相同输入下共享语义，不强求相同交互次数。独立进程内存引用必须显露寿命；自动开启全局后台服务会违背小任务无负担，因此采用实际已有Runtime或内联/已保存内容。范围批次先同基准物化，宿主真实事务能力另外判断。

**正常路径。**source、files、edits、有限结构draft和已定位标量共用一个候选/语义更新责任。六工具协议不随业务库数量扩张，普通作者不手填全树；已有原文最简单就直接编辑，需要端点才查询。公共preview按请求产生真实代码或差异，只返回计划不能称生成完成。

**阶段与缺省。**v2裸source选择gift.semantic/1语言ID，其实际解释修订必须存在并固定；没有实现不猜TS或latest。完整批次可含错误草稿，只有根合格才生成。源检查、各目标生成、各实际检查和应用分维记录；source/base、candidateRef、artifactRef、布局基础和目标前像不能混用。compareTo只用于目标diff，save-source不部署，write-output必须选择实际产物。

**具体处理器。**[短ticket算法](../../80-开发者与接口/工具协议/候选修改与批量.md#短值处理器的内存接口与真实重试范围)把解析与输入占用原子接合，再在锁外核当前权限、读取原槽、解码值、降低set-input和执行CST/结构更新，最后发布可披露结果并释放。ticket并非权限；过期、回收、外部头更新分别处理，不从latest猜另一处相似值。

**重试的真实选择。**短分支没有changeId，不承诺memo回收后恢复同一候选身份；仅需等义纯候选时可依原base重算。确需严格响应丢失重放时，客户端在发送前使用完整协议并保存changeId。服务生成在已丢响应中的ID不能被当成客户端已有。真实外部作用继续使用自己的requestId、前像和结算，不以纯候选memo代替。

**成本与反例。**完整规范、首次合同、查询、请求、返回、失败和恢复都计入成本；不把暖短表达式同冷完整模块比较。小结果返回正文，大结果按需分页，权限隐藏不能通过诊断泄露。源码映射、临时句柄和字符串值均不签任意执行。发生输入不消费、短入口越权、非法模型冒充完整、保存变部署或后端忽略控制，修共同处理器而不是新增宽松旁路。人类主客户端已选Code-OSS / VS Code Extension-first并可按实施切片接入，但仍不是首期headless主链前置；其他客户端以后只适配同一合同。

**完整开发动作与薄客户端。** [开发面](../../80-开发者与接口/客户端/开发面与智能投影.md#developer-surface-contract)统一任务、候选与结果，不强迫所有动作走同一传输。普通文件/SDK/原生工具可提供完整操作；未注册的宿主安装/集成能力要准确显露，不用虚构mode掩盖。补全/格式化/修复返回既有编辑，测试选择生产原casesRef，正常参数生产原argumentsRef。收益是作者无需维护内部结构、已有生态仍可用；代价是各实际客户端必须对账能力，六个名字不能替代适配。

**有限进程交互的必要性。** build/run只说明怎么开始/结束，不表达运行期间连续输入、EOF、短写与响应丢失。采用可选gift.process-session/2的有限联合，仍在operation下；不将自由终端或任意shell命令作为统一协议。只需一次性运行时不启用。若未来必须在进程重启后保证输入消费，需要目标侧确认/游标等真实能力，不由本地requestId自动获得。

**选择的反例。** 统一大UI会把未需要的交互成本强加给AI/脚本；仅写六工具名又掩盖测试、环境、提交及输入的缺口。给每动作一个顶层工具随生态增长，纯自然语言命令又无法确定实际作用。当前选择准确任务路线、原请求归一和有限必要扩展；当真实客户端证实某条通路既不可实现又不能由成熟工具承担时，只重开相交协议，不推翻简洁作者和共同语义。

### Code-OSS客户端与Gift的无界面权威边界

**当前选择。** 人类主客户端采用VS Code / Code-OSS公开Extension API；需要独立品牌的Gift Workbench时，以Code-OSS源码发行版预装同一Extension和Gift Runtime，不重新实现一个Tauri/Monaco IDE。CLI、SDK、AI/Agent与Extension都消费相同query/propose/preview/check/apply/operation语义；客户端壳可以替换，Engineering authority不随UI迁移。

**为什么选择Code-OSS宿主。** Gift真正独有的是意图/Definition、Requirement、Control、Implementation Binding、Plan/Delta/Impact、Evidence与受控Operation。文件树、文本编辑、diff、多标签/分屏、命令面板、终端、调试、测试、SCM、keybinding、theme、无障碍与扩展生命周期不是Gift理论差异。Code-OSS已提供这些成熟Workbench能力和公开扩展点，复用它能把工程成本集中在独有语义而非重造IDE外围。

**为什么不以Tauri+Monaco为主线。** Monaco只承担编辑器核心，Tauri只承担桌面/WebView壳和系统桥；二者组合仍需Gift自己拥有Explorer、workspace、多editor布局、terminal emulator接合、debug/test/SCM UI、command/keybinding、accessibility、extension ecosystem与窗口恢复。该路线不是更“纯”，而是把大量非差异化产品责任永久转移给Gift。Tauri可以在未来Code-OSS真实总成本不合格时作为替代壳候选，但必须复用同一client contract。

**为什么不以浏览器为唯一主面。** Browser适合远端查询、Review、Explain和plan-only投影，但本地开发的文件系统、进程、终端、调试器、设备、工具链和秘密都有真实宿主能力与生命周期。把它们全部通过自建远程daemon映射到Web，会在没有需求时增加认证、传输、连接恢复和远端effect边界。浏览器因此保持条件客户端，而非默认本地开发入口。

**为什么不直接fork私有Workbench内部。** Code-OSS private API可以更容易插入深UI，却把Gift绑定到上游内部结构并扩大长期rebase/安全/发行成本。第一实现只使用公开Extension API、DAP/Testing/SCM等稳定能力；真正硬要求无法满足且已有消费者时，才允许独立distribution携带窄patch，并要求patch没有语义/权限authority、可被headless conformance覆盖且有退出方案。

**LSP/语言服务器的地位。** LSP或宿主Language Service继续作为语言分析Provider，可提供completion/definition/references/diagnostics；它不能承担Gift的Requirement、Binding、Impact、Verification、Operation或恢复authority。因此既不另造所有语言服务器，也不把“有LSP”当Gift开发面完成。

**图形库的地位。** 可写Graph只有[GraphMutationReadiness](../../80-开发者与接口/客户端/工作台布局与交互.md#graph-mutation-readiness)对相应 Operation kind 成立后才激活。React Flow / `@xyflow/react`和ELK/`elkjs`是当前参考显示/布局Provider：它们可以处理节点交互与布局，不能产生canonical node identity、Port compatibility、adapter选择或Operation成功。依赖可以在实现阶段替换而不改本设计；布局删除必须不损失Engineering semantics。

**许可与独立发行边界。** Code-OSS仓库源按其MIT许可使用；Microsoft的VS Code品牌发行物有自己的产品许可和专有差异，因此独立Gift发行以Code-OSS源码、Gift自己的品牌/更新/扩展来源策略为基础，不把Microsoft Marketplace或专有扩展变成产品必需依赖。普通用户也可以在自己的VS Code中安装Gift Extension；这两种客户端对同一工程必须产生等价normalized Plan/Delta/result。

**代价与重开条件。** Extension Host与Electron/Code-OSS壳有启动、内存、供应链、上游演进和宿主沙箱成本；Webview也有CSP、消息、主题和无障碍成本。这些全部计入真实测量。只有公开Extension API无法满足已接受硬要求、独立distribution无法合法/可靠提供所需能力，或完整任务测量证明更小宿主显著更合格时，才重开客户端壳；不能因为“Rust壳更轻”或“浏览器更现代”重新把UI技术偏好当产品目标。

## D53 中文规范源与未来多语言派生

**决定与机制。**当前中文规范是一份含义来源；有实际翻译需求时，按稳定单元、术语、保护跨度与源映射派生、复核和发布。代码与协议字面量受保护，源变化只使相关译文陈旧；缺译按已声明规则回退，译文澄清不能直接改源。

**取舍与反例。**标题、路径和排版不是语义身份，文本/图/表可以有不同呈现。手工维护多个规范源容易改掉否定、数值、例外和许可，旧译文不能覆盖新中文。当前不建立空翻译树；法域要求独立生效文本时明确其权威关系而非强作普通翻译。新增本地化需要术语和复核成本。

## D54 验证切片用于裁决架构而非替代成果

**开发面范围。** 采用现有Gift自身十职责、两输出根和两次完整源码/消费者变化，同时保留原新算法/成熟供给/原生/领域/回源范本。不能让CLI退出纯函数或Code-OSS搜索链代签整个开发面；也不因要证明完整就先造专用IDE。DF案例按真实用途/版本/目标复核，写出验收不是执行通过。

**选择。**完整产品是AI工程语义开发平台，当前优先普通业务意图、开放语义与非计算工程的有界设计。计算库或小函数只是一类条件载荷，不可替代模块组合、实际构建运行、观察定位、资源交付和再次修改。中间件与数据库暂缓，不要求另造事务应用来代签全产品完整性；计算已纳入统一语言，本阶段暂停新增计算研究与实现。

**当前路径。**先确定总体作者、数据、阶段、目标和运行责任，再由有真实需求的工程沿同一机制创建源、封装库、生成、构建、运行、诊断、保存及再次修改。对实际选中的解析控制、数据并行或反馈迭代任务反查共同架构；这三类是不同机制的检验，不构成同时开发三款产品的授权。内部第一个函数是小里程碑，不能结束成品设计。

**比较与更小替代。**正确全量和顺序目标先成立，成熟库与原生工具可直接用；增量、GPU和远程由真实要求或收益引入。没有调用方的示例库、把算法藏进未知Adapter、用更长JSON代替源，都不能证明价值。自身一个可隔离职责可尽早自用，但当前仓库前像、消费者和权限在真实实施时另取；HALO仍仅是历史线索。

**反例与重开。**新算法需要增加核心业务分支、改变私有布局就改所有调用者、生成物手工修补、运行只有check(cases)入口、普通任务必须读全表或携带数据库，均重开相交设计。新增真实效果或跨进程保证会激活条件能力，不用当前范围限制未来目标。Oracle来自独立要求、反例和真实消费，不能全由生成器自己决定。

**归属与历史。**[MVP主表](../../70-工程系统与演进/演进与实施/实施/仓库迁移与自托管.md#当前mvp范围与支持清单)拥有实际支持与先后，计算规范拥有完整程序，操作规范拥有启动与结果。设计不自动授权参考软件。

**当前全工程分工。** Code-OSS保留真实原生宿主的校准作用，不作为所有后续设计的唯一入口；Gift成品自身的多入口、多模块和连续修改检查共同架构。大型源码案例的规模不能替代生成、语言、资源或调试各自的接口与状态，局部链已完整也不能宣称整产品仅剩跑测试。

### 作者源码与开发流程的不同交付

保留有效编辑/运行/逆向机制；主验收面为完整产品意图源、被引定义的真实内容及从源到实现的责任。工作台标准定义完整展开交付，应用源只引用它并固定自己的差异；这不是用一个makeIDE名字遮住空白。多个公开角色不强制生成同数服务，产品目标界面也不要求Gift自己先做GUI。

成本从重复产品实现转移到可复用定义、方法和符合性维护，不能称成本消失。没有供给时由已有委派在实现侧解决；没有确定语义时不编造。图与更多流程不弥补源语义缺位；低层fn可表达一切计算也不证明意图抽象充分。

## D55 设计、生成、构建、写回、发布和效果单独证明

**决定与机制。**设计、生成、目标构建、写回、采纳、部署和实际效果分别绑定对象、依据与剩余义务。固定候选可以先于部署授权生成；前一阶段成功不自动触发下一阶段。小型操作可以合并执行，但仍保留实际失败原因和可依赖结果。

**取舍与反例。**单一完成百分比会把字段存在当认证服务、把有限测试当生产可用。成熟度不是proposed→verified→degraded→revoked→retired的单线：语义、实现资格、现场健康、撤销和生命周期不同，部署退役不会抹掉旧试验。未执行的AI、生产迁移、网络、通知和物理恢复也不继承原型成功。

**复核。**公开返回采用最小需要的正交状态；内部保留真实范围，承担必要记录与解释成本。类型、有限行为、导出字节及采用分别核对；阶段对象或保证改变时重审映射，不增加一个掩盖所有区别的成功枚举。

**调试的相交选择。** 构建运行合同不再被当作已拥有断点/暂停/单步。有限调试另行协商于原query/operation，精确区分会话结束、目标退出和命令未决；任意求值、热替换等不被偷偷纳入。代价是维护实际适配与暂停引用，收益是调用方能正常定位和继续开发，而不是只有事后错误文本。

## D56 能力与依赖图的边分型

**适用与选择。** 图为解析、影响、工作规划、调度或演进承担真实关系时，区分语义引用、AND义务、OR替代、条件激活、严格完成前置、协同设计、准入、证据、供给、反馈、冲突、兼容与排程。不为没有消费者的关系预建平台字段。

**正向机制。** 目标到义务、当前工作前沿、作者语义图、编译动作依赖与父子预算分别解释，再以现有引用接合。声明互引先收签名；领域分析按指定固定点；严格工作前置环检查错误分型或联合设计；动作等待跨线程登记并判环；父子树只管理提出者和资源，不能替代真实数据依赖。详细算法分别由[目标发现](../../70-工程系统与演进/演进与实施/工程挑战-发现推导与覆盖.md#目标到义务的自主发现主循环)和[编译调度](../../40-目标与制品/递归并行与远程编译.md)拥有。

**代价与替代。** 单一平铺待办表便于初始记录，却看不出替代和阻塞；一张万能DAG会误拒递归或漏掉资源死锁；无分型大图也会把可选远程、验证后置和实际硬前置全部并成必需。当前先用Markdown问题关系和进程内工作表，确有索引与远程需求才实现更复杂存储。图的规模不进入每次作者输入。

**反例与重开。** 存量导入只是候选来源却阻挡所有目标；把合法递归删掉以得到DAG；单侧未验证冲突禁用全部候选；所有worker持有执行槽等待子项；同一任务因OR供给而必须安装所有提供者。真实冲突仅限制相交组合，未知不能取得控制权。

**保持范围。** 零新增执行可由合格复用支持，不由空记录推出无义务。新候选不触发全部旧绑定重选；排程变化不改业务；只有新的实际关系无法由已定合同表达时，才扩展相交模型。当前依赖分类继续与[能力依赖](../../20-语义与组合/共同语义/对象必要性与能力依赖.md#能力依赖图与局部插入)一致。
