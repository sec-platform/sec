# 设计依据与资料边界

本篇规定供Gift设计、实现选型和边界判断使用的来源维护协议；完整来源命题在同包 research 记录层保存。来源支持到什么范围、Gift决定采用什么及实际实现了什么，分别记录；不把参考目录变成另一份语言或产品规范。

## 研究结论的保存复用与失效协议

研究维护单位是**原始资料中的具体命题及其被引用的工程使用点**。语言规范、编译器、CUE、数据库、网络协议和方法学遵循同一证据维护规则：在设计发生相交变更时重新核查，而不是只列 URL、按助手会话排列，或等用户点名后才复核。

### 记录的最小完整含义

每项来源命题保存原始出处、实际读取时间、版本/适用角色、支持范围、采用前提、禁止外推、消费方及维护位置。规范与算法的当前解释仍由其 canonical Owner 负责，研究条目不复制正文；多个转述若源于同一一次证据，视作同一来源链而非独立支持。

**记录日期不等于最后语义审查日期，更不等于当前安装版本。** 原记录缺日期就明确保留未记录；不能通过本次整理给所有旧材料补一个“已复核今天”。URL里的latest/master、活动文档和工作草案需在记录中保留该角色，不伪称固定发行。实际版本无公开证据时，只用它已支持的机制，不凭搜索摘要填版本。

“使用与维护位置”表示哪个规范使用该命题、比较或反例并承担相交复核，不等于该外部软件已采用。仅供备选比较的记录由D理由维护；产品实际调用或生成依赖由对应Adapter/Binding负责。源文件、普通函数和作者提示无需逐次携带这一目录。

### 每次变更执行的SRC0—SRC7

| 阶段 | 正常动作与形成的结果 | 不充分时怎样继续 |
|---|---|---|
| SRC0 提取实际变化 | 从要求、语义、接口、目标、运行假设和本次动作取得变化集；不是只取关键词 | 当前范围不明先从已取得要求恢复，不能要求用户重复提醒 |
| SRC1 取得相交命题 | 按来源记录的使用位置、机制主题及实际入链取来源；补查更小替代、失败与不兼容记录 | 没有来源不立即认为错误，也不假设成熟常识已验证；登记所缺命题 |
| SRC2 分清复用状态 | 比较原版本/前提/用途和当前需求，判断可复用、需重新判断适用、需外部复核、被反证或仅有线索 | 未读、不可访问、旧测试、活动版本和精确规范是不同状态 |
| SRC3 定向取得原始材料 | 对确有变化、实际采用或决定性不确定的内容读取相应章节；保留真实版本、范围及共同来源 | 访问失败只说明未取得；允许完成不依赖该事实的设计，不宣称当前能力已证实 |
| SRC4 重新裁决使用 | 先判命题是否仍成立，再判是否足以支持Gift当前用途；形成采用、拒绝、条件适用或具体未知 | 上游文档变化不自动改用户要求；同URL没有变化也不能免除用途变化的审查 |
| SRC5 同步消费者 | 改相交规范、例子、图、D理由和当前实施闭包；保留独立错误/边界；删除竞争的旧规则 | 不能只在来源条目末尾追加“新结论”，而保留调用方旧假设 |
| SRC6 做目录自检 | 检查本次新增/修改命题以及全目录的来源、日期缺口、归属和去向；合并真正重复 | 结构通过不证明所有命题正确；既存未知仍保留，不能新建空日期或虚假采用 |
| SRC7 交付准确范围 | 说明本次实际外部复核、继承范围、已定设计及真实残余；下一任务按同一规则启动 | 没有部署后台进程就不说全天监控；文档链接不等于客户端已经自动读取 |

本包直接以可读 Markdown AuthorSource 保存来源命题、读取范围、实际消费者与排除边界；SourceProfile 在解析时派生 KnowledgeIR、查询字段与索引，长篇理论继续按论证结构直接编辑。无需建立第二份记录数据库、全量爬虫、在线规则库或永久检索日志。自动化可以从同一作者源派生索引并检查结构，具体命题的适用与相反证据仍按实际方法裁决。该流程服务设计工作，不进入用户程序每个函数的运行路径。

### 不同信息怎样触发复核

| 来源或变化 | 默认处理 |
|---|---|
| 固定版规范、数学定义，前提和用途均未变 | 复用原命题与理由，不无故重读全文 |
| 固定规范相同，但新增回调、控制出口、目标、资源或安全假设 | 重新核适用性；用新的区分反例检查，必要时读取相交原文 |
| 活动API、发行支持、弃用、安全公告或实际工具选择 | 在实际采用或作当前事实声明前外部核验；不沿用旧“当前版本” |
| 安装、权限、设备、网络、性能和执行结果 | 由真实环境与方法取得；网上规范和模型判断不代签 |
| 来源移动、撤回、矛盾或只剩摘要 | 保留已取得的历史范围；重新定位原材料，降低无依据的新断言 |
| 技术备选未采用且没有相交用途变化 | 保留比较理由，不为防遗忘把它加入发行和实现队列 |
| 新的来源与旧来源同源 | 合并来源链与独立命题，不把转载和重复读取算作第二份验证 |

对语法和语言机制，修改一个构造要检查绑定、类型、效果、退出、清理、阶段和目标这些实际交点。对上游库，修改其调用也要检查输入域、配置、ABI、默认、错误及生命周期。未修改的稳定命题无需在每轮联网复核；“必须主动管全部资料”不等于每轮无理由重搜全部互联网。

已有[HTTP条件请求与弱ETag证据](../../../research/sources/表示编辑与协议.md#rfc9110-conditional-request-evidence)只能减少传输；不能单凭304、弱ETag或页面没变就认证字节身份、命题正确或用途适配。原始秘密与私有工程不为了核资料发送给公共服务。

## 来源记录的适用范围

来源记录承接已有资料，不表示所有页面已在同一时点重新核验。记录日期只说明材料范围；未记录日期的条目明确标识。活动页面中的版本或“当前”仅属于原记录，实际采用必须核对所需版本和环境。“排除项与适用限制”中，正向断言列出该来源不足以支持的结论，否定句保留其字面限制；不能反向解释成Gift应当满足的要求。

完整网页、逐轮检索过程、失败查询、旧仓库快照和打包统计不进入规范。精确来源和当前采用理由足以让后来工作按条件复用；特定实验、事故或迁移事实由其实际证据承担。

## 采用与复用的责任

平台原语由适配层消费；可替换机械能力用明确的提供者合同接入；只提供设计启发的机制不自动引入软件依赖；用户目标程序的库不自动成为 Gift 控制面的依赖。实际引入代码、模板或图表前，检查对应许可、通知和分发条件。来源目录本身不签发安装、实现、组合正确或工作区写入资格。

## 来源、研究与规范的可访问闭包

SRC0—SRC7不以“已被某个Claim引用”为资料保留前置。解释基础、备选机制、异常对象、失败记录、具体示例、负结果与有根据的待核线索，只要有独立内容价值，就在同包研究、组合样本或反例区保持完整可访问。精确命题已有原始证据时按原条件复用；只有线索时保留其不确定性，不得先删除再以“没有资料”为由要求实现取证。

一份原始资料可以有多个不同消费面。规范给出当前选择和生效边界；研究保留候选、论证与反例；来源给出原始定位、版本及实际读取范围。当前问题与资料双向链接，但不为每条未采用猜想创建强制Claim、执行任务或重复规范。两个研究段落只有在条件、参数、方向、来源强度及失败边界都等价时才是可合并重复；仅共用URL、名字或结论不够。

研究文字中的历史接口与当前接口冲突时，当前 owner 仍唯一生效；相交研究保留差异说明，不能在来源页偷偷延长旧协议。引用外部全文、代码或图时仍核分发权限；随包保存的是有独立价值的研究分析与准确定位，不表示已镜像全部上游源码、论文或历史制品。
