# 方案名称与实际控制的同步；抽象收束与实施准入的文档约束

## 方案名称与实际控制的同步

审查“是不是面向过程、关键词会否无界、源码是否更长”时分别核范式、语言词汇、库合同、实现负担和当前任务决定。既不能用“过程代码也很强”回避高层表达不足，也不能把过程抽象一概判为低级。正文中的实现基线、作者推荐路径和能力未覆盖状态必须分别说明；用一个新函数名替代长例子时，签名、定义性、次序、失败、算法与维护责任同时有唯一位置。普通库增加不增加词法，但仍是实际能力与成本；不拿关键词/工具数没变作为交付收益。

改变产品方案描述时，必须明确作者实际写什么、现有请求怎样调用、哪份文件/字段保存、哪个模块消费及真实结果如何判断；若作者面未变，就直接说明未变，不能用新的架构名暗示已减少源码或语言责任。自造语法、嵌入式框架和成熟编译器分别计算其消掉与新增的工作，不以“不叫语言”或“工具数没增”评价成本。

一个已有变体原来只说“存进extensions”而没有编码，仍属实现设计缺项。补具体编码时同步读取、保存、失效、reset和未知字段处理，并明确它是实际新增/闭合的合同，不冒称无成本。它不必新增文件、工具或语言语法。示例存在必须相容的目标、身份与基础，不能以占位引用省掉真正的字段规则。

同一例子的完整源码、参数变化和期望在一处维护；其他章节只补各自真实消费者与边界。合不能删除独特的权限、资源、错误、成本或资产责任；也不能继续复制同一份程序，靠每轮改一个名字制造新成果。

### 完整工程施工设计不等于新增规范断言

本库 `docs/` 是从零到能够建立产品的**全工程设计**，不是只发布要遵守的约束。稳定语义不变的前提下，若实施者仍须自行猜测模块文件、输入/输出和数据拥有者、调用次序、算法、状态/取消/恢复、Target产物及验收，属于**工程施工设计缺口**，可以直接完善准确施工设计和导航；这与“源码小重构无需修改规范”不矛盾。施工落实优先放入[工程构造手册](../../70-工程系统与演进/工程构造手册/README.md)的相关章节，并同原公共owner对照。

规范owner仍只维护它有权定义的公共意义、必要不变量和公开机器字段；施工文档维护实施接线、内部API、算法和失败演练。不得让同一规范字段在两处有竞争真值，也不得因一份施工设计存在就写“真实产品已运行”。当施工发现公共合同不够精确时再修原owner；仅写实施内部细节不强迫修改无变化的业务含义。

### 规范文档写入准入

文档不是实现的影子副本。任何源码、测试、构建、重构或运行修复在修改规范前，先判断是否有需要长期保存的工程含义变化，或现有文档存在独立的遗漏、错误、歧义、证据缺口及表达不足。实现行为未改变不证明文档正确完整；修正已存在的文档缺陷同样可以准入。没有上述差额时，正确动作是只改实现与相交测试，规范文档保持原字节；不能为了“同步”“留下记录”或让提交看起来完整而制造文档变化。

| 变化 | 规范文档动作 |
|---|---|
| 私有算法、内部函数、文件布局、重构、性能实现、错误修复，外部合同与设计不变 | **不改规范**；事实由源码与测试承担 |
| 测试数量、CI结果、commit/SHA、PR、临时运行状态、一次性能测量 | **不改规范**；进入对应证据、仓库或运行记录 |
| 已有规范早已要求的实现终于完成 | 默认**不改机制正文**；只在确有长期消费者的状态主责任 中更新“实现/验证状态”，不存在这种消费者就不新增状态文字 |
| 公共输入/输出、错误、时序、资源、权限、持久格式、兼容、部署前提或用户操作发生持久变化 | 修改唯一规范主责任，并同步真实消费者、理由与必要示例 |
| 新证据推翻原设计前提，导致采用方案、边界或保证改变 | 先重新裁决，再修改规范主责任 与相交理由/未决；不得先按当前实现改文档再倒逼设计 |
| 已有文档漏掉仍然成立的条件、反例、依据、操作、图解或恢复责任；实现未变 | 修正真实文档缺陷，保存独立信息与准确证据强度；不得借“少写文档”保留缺项 |
| 仅措辞、导航、拆分、链接或派生索引变化 | 不改变产品含义；只修改必要文档/派生物并保持身份、来源和入链一致 |

准入问题按此顺序回答：

```text
这次变化如果完全不写进文档，未来一个只拿到公开合同和当前源码的合格实现者
是否会因此缺少一项有独立理解/使用价值的条件、行为、边界、理由、依据、反例、兼容或重开条件，
或者继续受到原文错误、歧义、不完整图解/操作的误导？
  ├─ 否 → docs write set = ∅
  └─ 是 → 找唯一规范主责任 → 写最小稳定语义差额 → 同步真实消费者
```

“以后可能有用”“这次改了很多代码”“实现终于与设计一致”“AI怕下次忘记”“方便复盘”都不是规范写入理由。需要复盘的内容由Git历史、测试、Evidence或包外工作材料承担。反过来，公共合同真的改变时也不能用“代码已自解释”拒绝更新规范。

文档载体按真实责任分类，不按目录名赋权：[身份域合同](文档身份与重组协议.md#documentation-identity-domains)区分作者源、显式Contract Unit、包外reader/audit投影、查询/分析cache、包manifest与provenance。可重建派生物缺失、损坏或生产者/有效配置改变时可以重建；重建不能为了匹配旧投影而修改作者源。正文、工具、manifest 或配置的字节身份变化也不能代签规范采用变化。

<a id="complete-change-closure"></a>
### 完整变化的一次闭合

“一步到位”是对已取得的目标与已发现作用路径作完整设计和同次交付，不是边实现边随意发明相互冲突的中间合同。实现前明确本次不变量及真正限制结果的约束，找出权威输入、所有者、生产者、读者、调用与依赖、缓存/投影、正常状态、失败/恢复、并发、资源/权限、迁移与旧路径退出；比较直接复用成熟原语、减少载体或删除多余结构的可行方案，再确定一个有理由的目标结构。实现中发现反证则修正受影响的设计与整个消费闭包，不以原计划已写入为免责。

同一不变量的相关解析器、写者、检查器、包、阅读入口、示例和恢复路径必须相容；不能只修被点名的一个调用点，不能用新版本适配层掩盖仍活动的旧写者。若改变持久格式或身份域，先确定版本拒绝/迁移、前像、切换点和中断恢复，再发布。候选可以短步骤编辑、保存和验证；对共享正式入口的切换必须在本次要求的完整集合就绪后发生。局部已完成可准确报告，但不冒称整个闭包已结算。

该原则同时覆盖代码、设计、配置、文档和派生管线；不能把项目的局部实现当作世界全部事实，也不能要求每个纯函数建立一套管理平台。长期有价值的独立知识应归入现有责任；源数据量、工具缺项或确实未知有准确边界。安全的独立工作继续推进，不能把无限未知用作拖延已能决定方案的理由。外部写入需要实际权限；未经运行的保证不伪造为PASS。工具/平台确实阻塞时交付完整可用候选和准确剩余义务，不改变原目标，也不以删检查、扩权限或后台轮询制造完成。

### 从分析到实际设计交付

此要求不是可选的写作风格：收到“继续设计、全工程方案、实际落地”时，交付必须落实到现行规范，不得只在报告给出判断。一个具体问题的设计结果必须能够找回**真实输入→数据拥有者→接口与字段→算法及停止→合法结果和失败→消费者→开发者怎样操作→下一次修改**。规范已明确且无需改变的部分直接引用，不为填表复制整套规则。

判断采用方案以后，本次必须同步它**在规范层实际改变**的数据联合、公开调用、阶段责任、错误与资源、源/产物/资产、图和实施前置；纯实现变化先经过[规范写入准入](#documentation-write-admission)，不得因为函数名、文件或测试变化就机械扩写规范。只有“应该更统一”“优先复用”“加强逆向”而没有相应处理器、输入、输出与反例，不具备设计完成资格。给一个运行范本不能反过来要求实施者重新猜接口。

交付前按下表核改变范围，工作记录留包外，当前正文只保存工程知识：

| 检查点 | 应当实际得到什么 | 不能充当替代 |
|---|---|---|
| 决定 | 当前采用、未采用和触发重开的条件 | 正反两列后不作选择 |
| 实现设计 | 数据与写者、接口联合、状态/算法、进展及错误 | 新服务名、新抽象名、字段占位 |
| 开发闭环 | 完整请求、存放位置、产物、保存/运行分界和第二次修改 | 仅一个内部函数示例 |
| 消费者一致 | 上下游、目标、工具、图表和验收同步 | 只改首页或附录，以“最新说明”为准 |
| 收束 | 旧默认、重复路线和已完成待办改为当前状态 | 将无限历史进展追加到旧问题台账 |
| 真实性 | 文档检查、推导、实现、执行分别报告 | 链接数或未运行范本作为产品成绩 |

若本次确有证据、工具或权限限制不能完成某一相交块，交付已完成的具体设计并记录那份缺口；不能声称全块已闭合，也不能把其他有依据的接口决定全部延期。当前是设计任务，算法和验收设计可以完成，不因此获得产品编码、运行、安装或仓库写入许可。

技术提名只触发比较，不自动采用。选型比较要保持原任务、相同供给与完整成本；可行的组合不证明应成为所有任务的主面。已有规则在文档里并不保证执行者已落实，因此每次交付从实际变化倒查本节，而不是再增加一条“以后必须遵守”的同义原则。

## 决策收束与持续问题处理

每项当前方案要明确决定层：根目标、公共语义、作者前端、内部算法、目标策略或实际作用。对承担的范围写明一个当前采用方案、明确不采用项、实施输入和理由；比较本身不构成采用，用户提及候选也不签发采用。已具备设计依据的技术选择应当在本次作出，不能交给实现者重选或永久保留平行主线。没有新证据就沿已选方案推进。反例确实改变前提时重新裁决，不能为保留旧投入强迫用户适应。

收束的四项结果是：**相同责任只有一处规则；当前范围能形成连续交付；已决定部分从待决转为准确状态；旧摘要和重复前置在提交本次修改前从活动规范中移走。** 文本变短不是唯一目标，方法名不再增长也不是证明。新独立需求可以扩大规范，已知重复不能以穷尽为理由无限累积。

尚缺设计条件在对应 canonical owner 保持独立命题；已定设计的实现与证据缺项由[实施闭包](../状态/实施闭包.md)记录关闭条件，采用理由仍由 D 决策维护；“父项仍开放”不表示其所有设计从未解决。有限设计子项满足数据、接口、算法、例子与调用方后可以关闭该设计范围，具体实现、支持版本和效果继续公开。没有运行本来无需运行的文档冲突，不妨碍关闭该冲突；没有真实运行也不能关闭性能或物理操作声明。

当前前沿只投影真实 canonical owner 与[实施闭包](../状态/实施闭包.md)的关系，不再形成第二份“所有问题”的活动记录。准确后果、可实施方案与反例在机制正文保留，实施闭包只保存其完成条件及真实剩余；历史进展中的独立内容并入这些现行责任，逐轮“本次更新”不继续存入当前源。设计、实现、验证分别标明，设计可依据充分推导结项，不等待代码运行。合并保留独立失败、代价、前提与更小替代；已被当前正文吸收的历史解释留在原版本。未知、延期、未选、不适用、废弃和已结束各自有处理，旧效果不因删文档消失。

每轮继续任务从目标和实际就绪前沿自主选择，先找无主义务、无用途机制、接合冲突和新增条件，随后完成具体设计，再反查消费者。流程在当前授权目的处结束，不能把“设计→实现→发布”写成自动获权箭头。同级顺序依据当前阻塞、后果、不可逆点和解锁收益；工期、概率和数字分数无依据就不填写。

## 收束性编辑的执行方法

先固定父版及范围，列出本次相交的规则拥有者和消费者。对准备删并的段落逐项标记：独立规则、理由、反例、状态、历史、导航。纯导航合并，独立规则移到唯一拥有者；相反条文按根要求裁决；未解决义务保留可定位去向。禁止为了达到减量百分比删除信息，也禁止仅把几篇旧文首尾相接称为融合。

语言扩展不能只改关键词表：同步解析与结构体、作用域/类型、求值出口、效果、资源清理、目标、编辑和版本。要求“更通用”不等于加入全部语言词表，要求“更简洁”也不等于删除调用方真实需要的区分。声明语法增加几项，实际能力已定哪些、哪些仍是目标义务，分别报告。

项目树示例明确默认与可选：src/app/lib/model不签发语言或权限；输入、返回和生命周期字段省略只有既有来源能补齐时才允许。CUE等资料先核现存记录，缺采用或反转条件就补对应条目，不将同一命题反复改称首次发现。

改接口时同步例子和实际调用字段：差异基线要能传入，重试身份要在响应丢失前可持有，短入口不能引用根本没有的字段。源码、完整结构、任务投影与真实制品分层；不把隐藏长源码包装成已减少维护，不把另一种前端误称整个产品换方向。

改架构时先保持已接受目标、共同含义和真实外部观察，再改变私有机制。总架构不累计每轮所有算法，物理模块不复制领域字段表，实施附录不反向决定产品。重新排前沿时回查旧MVP表和末尾“下一步”，不能新页写延期、旧页仍强制该设施。

所有观察按准确层次报告：已读取的源码、实际改动的设计、静态核对、代码执行、现场效果分别有范围。当前静态检查可用成熟文档工具；不得为了证明设计而擅自实现并运行产品。相应任务允许后，成熟软件按其前提复用，只对新增映射与组合承担残余验证，普通结果不固定要求另一个AI重复审查。

## 抽象收束与实施准入的文档约束

给一个概念命名之前先写它属于语义合同、库入口、编码、执行方法、视图还是部署。不同角色可共用名字的词根，但不得共用无解释的启用、版本和完成状态；只有实际独立责任才建立模块或持久对象。语义分章可以详细，不能因此要求开发者逐项选择画像或创建同样数量的服务。

设计范围闭合时，将下一交付改成相应实现/符合性，不把尚未运行重新解释为接口未定。进入代码前检查所选公开含义、数据/接口、正常和失败算法、资源/结束及验收设计；迁移、部署、多租户、远程等仅在真实相交时进入。保留未来义务不意味着全部成为当前前置。每次修改原准入规则时，同时核相交的总体架构、实施闭包、首个真实消费者的交付路线与用户操作说明，不能仅追加一句“按需”。

说明`gift.object/1`时给含义、版本角色、实际字段位置、读写者和开发者动作；只说“不是什么”没有完成说明。详细对象语法用于维护具体能力，不据此把全部需求改写成类；已有封装承担含义时默认展示本次差异。抽象是否必要以独立含义、真实消费者和更小替代判断；不靠关键词、图数、包数或未决主题数评价。图应呈现一次固定环境、按需方法和准确阶段，不能把静态可解析画成必须装配所有运行依赖。
