# 按任务读取与独立知识保全

本章规定同一套完整设计如何按任务读取；不维护旧包统计、制作进度或第二份精简源码。完整规则分别由专业 Owner 持有，任务视图只帮助找到原文。

## 四种内容分别处理

1. 当前公共语义与失败/恢复合同留在 `docs/` 的唯一 Owner；摘要和施工导航不能取代它。
2. 施工设计给出模块、输入输出、算法、状态与恢复；当前实现/资格缺口由[实施闭包](../状态/实施闭包.md)投影，运行证据不写成设计完成率。
3. 研究、组合案例和反例保留独立机制、参数、负结果、比较及来源。`fixtures/` 当前提供 Markdown 研究说明，旧参考程序不随此包交付。
4. 索引、查询库、阅读页、制作报告只有在可以从准确源重建、没有独立取证或恢复用途时，才退出当前交付；未知材料不因体积、入度或相似度而删除。

删除或融合的语义判定由[内容保全](组织修改与来源保全.md)负责，定位和引用迁移由[身份与重组](文档身份与重组协议.md)负责。精确相同字节仅提供重复线索；独立工程输入、比较变量、历史复验及许可证可能仍需要同字节副本。

## 一份作者源，按任务定位

读取选择是原文件的路径、片段及准确修订，不是复制出去继续维护的工作集、第二项目清单或新 SourceProfile。已知位置可直接读；未知位置沿根入口、任务路线及专业链接展开。需要更多条件时扩展真实依赖和未履行 Need，不以返回条数证明读取闭合。

当前包没有查询/定位程序。外部工具若提供 `search/read/focus/inventory`，其能力分别受以下条件限制：

- 检索返回带 source revision 的现存 locator；命中是候选，零命中不是语义不存在。
- `focus` 只能选择读取范围，不复制作者源、不建新工程、不改变规范权威。
- 查询缓存位于包外；过期/损坏不能把旧字节伪装成当前合同，源扫描或受资格旧代回退须报告覆盖。
- 成员盘点应枚举实际文件、字节和角色，覆盖未进入全文检索的 Schema、JSON 与许可；盘点不证明逐句语义已审查。

`knowledge.toml` 将 `docs/` 声明为 canonical，将所列研究、反例及案例说明声明为 research。源码、Schema与许可可直接从各自目录读取；本文件不假定存在运行中的范围隔离。工具接入时按[分域协议](知识记录与分域检索.md)实现，不能只因读取配置就宣称完成。

## 正常读取顺序与扩大范围

- 普通业务设计：当前意图/Meaning、相交 Requirement、供给与 Target 合同，以及必要施工接口；无需预读计算实现全集。
- 新概念、联合资源冲突、持久执行、目标/编译错误：展开对应语义、解析、目标或执行 Owner，保留具体失败与反例。
- 新领域、强保证或设计发现：读取相交 `research/`、组合案例和 `witnesses/`，再把采纳的差额写回当前 Owner；未采用资料不因此失去独立价值。
- 版本迁移、旧消费者恢复或自举：按确切来源扩大输入与消费闭包，不将历史研究变成普通用户程序的运行依赖。

默认必读与必须保留是不同判断。某条资料只在异常、迁移或事故时有用，也可能应当完整保留；反过来，任务经常命中的摘要若无独立信息，也不能成为另一份权威正文。
