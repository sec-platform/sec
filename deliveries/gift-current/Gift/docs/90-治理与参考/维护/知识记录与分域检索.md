# 知识作者源、语义投影与分域检索

<a id="source-ir-query-contract"></a>
本章拥有 Gift 设计资料的 AuthorSource → KnowledgeIR → QueryIndex/Projection 合同。它规定文档工具采用 Gift 全系统 Source/IR/Projection/Cache 原则时的责任，不声称本包已实现或完成自举，也不创造平行产品架构。

## 一个事实只由一个作者源拥有

`docs/**` 的当前规范和 `research/**`、`fixtures/**`、`witnesses/**` 的研究资料都直接以各自 Markdown 作者源维护。根 `knowledge.toml` 只选择作者根的 `scope` 与 SourceProfile，不保存正文，不按文件逐项登记第二份知识目录。

SourceProfile 决定允许的 Markdown 子集、字段/表格解释、未知结构处理、编辑与往返条件；**文件后缀不签发语义 authority**。JSON、HTML、SQLite、搜索命中、reader 页面和 catalog 均只能是 codec、artifact、projection 或 cache，不能因为机器更容易消费就升级为作者本体。

长篇理论可以使用连续 Markdown 论证；领域场景、来源证据和反例可以用受约束的字段与表格。系统统一的是 Meaning / Identity / Ownership / Transformation / Evidence，不是强迫所有内容使用同一种字节语法。

## SourceRevision、SemanticRevision 与稳定身份

`SourceRevision` 绑定准确作者字节，用于 CAS 编辑、审计与冲突检测；`SemanticRevision` 绑定 SourceProfile 解释后的语义内容，可使纯排版变化不无条件击穿全部下游缓存。两者都不能替代实际对象身份。

稳定身份按需要晋升：跨 revision、迁移、权限、证据或外部引用真正需要长期身份的对象使用现有 Contract Unit / Semantic identity / 显式稳定 anchor；普通章节、表格行、查询命中只使用 revision-scoped handle 与 source span。路径、标题和行号只是 locator。旧 `kd/kr/src` blanket ID 已退出当前包，不保留活动 registry 或默认兼容 alias；若未来存在真实发布消费者，再由相应版本迁移合同明确承担兼容期与退役条件。

## KnowledgeIR 与 SourceMap 是派生语义，不是第二作者源

解析器从作者源得到 loss-aware KnowledgeIR：章节层级、字段、表格、链接、代码块及准确 SourceMap。KnowledgeIR 在内存或包外 cache 中存在；不得把整棵 CST/AST/IR 序列化回仓库，再要求作者维护解析器已能确定的 `parent/level/heading/segments/row-id` 等中间形状。

结构化编辑必须从语义操作通过 SourceMap 回到真实 AuthorSource。简单字段和结构表格中的明确 cell 可做最小 CAS patch，并在写入后重新解析同一 semantic locator 验证结果；复杂结构由对应 SourceProfile adapter 生成候选。前像 `SourceRevision` 漂移、字段/列不唯一或无法证明无损 round-trip 时拒绝相交修改并保持原字节，不能先改 IR 再猜回作者文本。

## 查询索引是可删除的运行 cache

查询从 KnowledgeIR 派生 QueryDocument，并编译到包外 QueryIndex。索引记录 source/config/parser/ranker revision 与 generation；新 generation 私有构建并在一次提交点发布，查询不能看到半旧半新状态。

默认查询范围是 canonical。`research` 必须显式选择；`all` 分组返回两个域。查询前先选 scope，再访问对应 source/index；没有命中不得扩大范围。结果必须携带覆盖和 generation：当索引已知缺源、落后或损坏时，零命中不能支持“没有这项信息”的判断。

若文档工具采用本地 SQLite，它只作为可替换 cache backend，不是产品的必选依赖或权威知识数据库。canonical 与 research 使用物理分离的 cache generation；默认 canonical freshness 检查不读取 research 正文字节，`all` 才显式查询两个 generation。日常 freshness 先以 size/mtime/ctime 识别变化候选，再只对候选执行 SHA-256 与重解析；严格审计/冷重建对全部作者源重算字节摘要。候选解析失败时不得发布半成品 generation：若存在上一份合格 generation，可准确标记 `PARTIAL_SOURCE_COVERAGE` 后提供旧结果；没有合格旧 generation 则失败。索引文件不进入正式 ZIP；缓存删除后可从 source 重建。cache-only query、freshness+query、单文件更新和 cold rebuild 有独立性能门禁，深审计不阻塞日常查询。

<a id="knowledge-index-qualification-and-redaction"></a>
### 索引失败后的旧代资格不是旧文本披露许可

正常重建以**一项完整 SQLite 事务**发布 `file_state`、`query_doc` 和 `generation`：先解析候选与固定读取范围，故障时回滚，不先删掉唯一已合格的上一代。即使当前 SourceProfile 选中集合变为空，强制重建仍须发布真实的空代际，不能因“无候选文件”返回 `CURRENT` 而保留旧命中。解析器/schema/ranker或配置摘要变化要求新代适配；旧代不能仅因表能打开就继续充当当前索引。

自动 `STALE_FALLBACK` 只解决“部分旧材料仍有定位价值”，不创设对过去可读内容的永久披露权。准入分两个步骤：①旧索引的 scope、配置解释、索引结构、解析器和排名器版本与当前资格相容；②对**每个将被披露的源**重新确认仍被当前 scope 选中、路径安全、可读且当前原文字节摘要等于旧索引记录。删除、改写、脱域、失去访问的源，一律不得展示其标题、路径、正文片段或由它得出的命中；已知其他源失败仍可返回逐源合格的子集，并标注整体 `PARTIAL_SOURCE_COVERAGE`。通过的只是“这些旧命中字节此刻仍对应可读取的原文”，不是已证明索引捕获了全体当前源。

采用协作式本地锁的工具，应在这些再验证期间持有 SourceProfile 共享门闩和对应作者源读锁；仅在参与者服从本地协作协议时约束竞争写入。网络文件系统、外来编辑器、恶意写者、跨租户授权撤销与缓存发布后的继续披露，都不由本地锁证明安全；具隐私隔离要求的宿主必须在**生成响应与每个继续披露边界**按现行权限复核。工具若提供显式不刷新选项（历史 CLI 名为 `--no-refresh`），其结果属于 `UNCHECKED` 历史缓存诊断，不能对外宣称“当前不存在”或“当前仍有权限”，严格策略下应禁用该通路或增加新的来源资格检查。

QueryCursor绑定已读索引代际、查询范围和解释版本，但不会把下一次请求授权为永久快照。相交代际变化必须拒绝旧cursor并重查；`all` 的 canonical/research 各有独立代际，普通顺序读取不等于跨域原子联合快照。任何范围未完成、候选检测可能遗漏或回退均不得支持负查询；要证明某范围的不存在，需该范围的当前完备枚举/检索及实际有权观察的条件同时成立。

## 研究、来源与规范的 authority 分开

<a id="knowledge-material-authority-qualification"></a>
### 知识材料进入规范和资格的唯一可审核路径

同一资料的不同角色按**能改变什么**区分：`docs` 当前Owner可以修订被采用的设计；`schema` 仅定义相应读取Profile能验证的结构；`fixtures` 提供已注明输入域内的参考结果；`witnesses` 给出反例或挑战；`research` 保存所引资料、竞争解释和未知；包外文档工具的机械PASS只证明其实际检查项；来源记录、许可和交付清单各保护其真实责任。字节保存在同一ZIP不会消除这些边界。一个带“必须”字样的研究段落不因此取得规范写权，反例尚未运行不能记录成失败测试。

采用链为 `SourceStatement(scope,time,method,quality) → CandidateDecision → OwnerAcceptedContractRevision → ConsumerReadSet → [Evidence/IndependentVerdict]`。研究可以引出设计修订，但**不能跳过Owner采纳或把材料补写成已发生事实**；同一来源的转载不算独立取证，旧版文档的观察时间不能因移入新ZIP而刷新。若研究与现规范冲突，应保留命题、真实主体、相互不一致的条件与Owner待决结论，不以“时间最新”裁决。证据撤回后受影响的Claim失效，旧来源本身为历史复现仍可保留。

只读Atlas/索引的能力限于文本坐标：它可以列出当前原文的表格、编号候选、来源位置、路径链接和推断出的待审清单；**不能**依据标题、表头或自然语言相似度擅自发布稳定 `gift-unit-*` 身份、正式语义关系或“全部设计无冲突”的Verdict。读取受检索范围/披露权约束；`research` 并不因为默认可用而获得 `canonical` 查询结果的优先权。


研究可以因为解释、候选、反例、领域覆盖或未来用途而长期保留，不要求先有当前 Claim consumer；但研究中的 `必须/不得/schema/状态机` 只描述该研究对象或候选，不能覆盖 canonical owner。研究被采纳时，把**采用的区别及成立条件**写回准确 canonical owner，研究保留推导、竞争方案和来源。

外部 Source URL 只是定位。URL 相同不等于命题相同；来源、读取范围、版本、支持/反驳、消费者和重核条件分别保存。未重新核验的历史来源不因为格式迁移刷新日期或证据强度。

<a id="gift-knowledge-evidence-owner"></a>
### 研究事实、规范决定和新证据的冲突归属

同一主题可以存在数个真实且相互冲突的外部资料版本；研究区负责保存其**原文命题、发布时间/规范版本、方法、适用范围、原始链接与证据缺口**，不直接拥有Gift内部Requirement或运行状态。是否改变现行规范由相应领域owner在明确设计决策与反例基础上采用；不能因为“最新版文档”或搜索排序较高就覆盖被冻结旧环境仍合法消费的事实。过期信息应标明时点与不能支持的新命题，而不是整段删除导致旧版迁移失去解释。

对同一原材料的转载不视作独立支持；模拟、fixtures、witness、真实事故和生产测量不得互相冒充。出现新反例时，应建立具体的受影响合同/假设、已有消费者和可检验的修正，而不是再复制一篇“系统总论”。若旧资料完全被新规范吸收而没有审计、兼容或独立反证用途，可退出active阅读面；若保留，必须能说明它为哪个不同主体提供何种无法由当前合同替代的知识。

## 分域阅读、AI 上下文与第三方工具

人、AI、CLI、Workbench 都先从任务确定 scope，再取得最小足够 source/semantic view。AI 默认获得相关 semantic task view 和必要 source span，不默认灌入全部研究或内部 QueryIndex row。需要反证、设计发现或来源核查时显式扩展 research。

当前包仅用 `knowledge.toml` 声明范围，没有随包查询器。接入的 embedding、IDE 插件、Agent 或文件搜索必须显式实现同一 scope 合同；只读到配置不证明消费者已隔离。文件目录本身不能神奇地替外部消费者实施权限和检索政策。

## Projection、Codec、Artifact 与 source package

阅读索引、HTML、JSON export、Combined Discovery、Unit catalog、文档/章节图都是可重建 Projection/Artifact；JSON/CBOR/Protobuf 等是 Codec；SQLite/FTS/embedding 是 Cache。它们的身份、生命周期和发布条件不得反向创建作者事实。

本 design source package 运输专业 Markdown、必要 Schema/JSON 设计示例、研究、`knowledge.toml` 与许可；制作工具、成员摘要及来源比较记录留在包外；不运输历史迁移账本、可删除的 `_generated`、reader mirror、查询数据库或分析 cache。零工具阅读直接使用 Markdown source 和人工维护 README；需要机器索引或审计视图时在包外按需生成。

## 失败、恢复与迁移

SourceProfile 配置变化是高扇出语义变化：先构建候选 KnowledgeIR/索引、比较差异，再原子切换；不能把 parser/profile 变化当普通 cache miss。索引失败保留旧合格 generation 或退回 source scan，并准确报告覆盖；它不修改 source。

跨平台发布拒绝大小写碰撞、Unicode 规范化碰撞、危险相对路径和逃逸链接。symlink、ZIP 路径、文件编码及 source hash 分别验证，不能只凭 CRC 或“本机能打开”证明交付安全。

当前研究与规范直接维护 Markdown AuthorSource；本包不以历史 records、旧迁移过程或某工具已完成迁移作为读取前提。旧 records、逐节点 ID 和迁移账本不属于 source package，也不得作为当前查询或编辑的隐藏兼容层；需要复原历史迁移过程时应使用对应旧制品，而不是把迁移账本永久携带到当前设计。

<a id="gift-local-knowledge-physical-schema-closure"></a>
## 物理索引与后续服务化的相交边界

索引升级、事务性 DDL、失败保旧库及 `IndexIncarnation` 的算法由[查询固定点与缓存](../../30-实现解析/增量与性能/查询固定点与缓存.md#gift-index-migration-and-query-incarnation)拥有；SQLite WAL 同步、断电及权威数据库迁移的差额由[持久状态与存储](../../50-执行运行与观测/持久化与恢复/持久状态与存储协议.md)拥有。本章消费这些条件，不重复发布物理布局。历史 `gift.query-index/7` 和 `gift.query-cursor/2` 仅在实际旧消费者仍使用它们时构成迁移输入，不是当前包发布的实现版本。

本地自包含游标的无密钥摘要只能检出意外损坏。若接入跨租户/联网服务，实际认证服务必须提供 MAC/票据、逐次 ACL、撤权代际、审计脱敏及相交泄露预算；不能从本地锁与本地摘要推得服务端安全。唯一资料不得套用可丢弃派生索引的退出规则。

性能资格按 `cold build / warm stat refresh / cache-only query / full strict audit` 分别取得，并固定宿主磁盘、缓存状态、并发/CPU负载及多轮观测。任何预设硬上限失败都独立保留为未达标；功能通过不关闭它，删安全检查或提高阈值也不是恢复资格。实际消费者采用新布局/游标版本前，另取得旧失败复现、恢复和制品读回证据。

## 工具采用时的符合性范围

声明采用本知识画像的工具，需要针对实际支持面取得可复核证据；未采用的编辑、查询或导出能力不制造空实现。检查责任按消费者划分：

- parser/SourceProfile：源字节与语义修订分离；非法 UTF-8、围栏/标题、重复 anchor、跨 canonical 的重复 `gift-unit-*`、空链接及表格预算分别拒绝或准确报未支持。
- SourceMap/editor：普通字段、明确 table cell、合成 row locator 的 query→read→edit→export 指向同一修订对象；旧 revision 拒绝，语义定位歧义不任取一项，最小 CAS 后重解析。
- 范围配置：root-profile 的 preview/CAS/overlap、canonical/research 物理分域、默认读取不越域以及 AI task context 的来源与覆盖可核；读取配置本身不构成隔离。
- index/cursor：clean/incremental 与 cache-disabled 等价，完整/部分 QueryCoverage、分页及 generation/incarnation 失效、重建失败保旧库、零源发布空集、删除/撤权后不披露均符合本章和索引 Owner。
- reader/audit/export：同源确定性、实际输出目录的链接、准确节选范围及损坏制品拒绝分别核对；投影不能新增规范或回写源。

这些证据绑定工具、输入、解释器/解析器、文件系统与实际平台。外部 Markdown parser 必须有明确支持版本；缺依赖报缺失，不自动安装。性能与功能分别取证，工具内部 PASS 不能签发来源语义正确、产品能力或现实权限。

### 历史研究进入现行规范的资格界限

研究采用边界为：`research/`、`fixtures/`、`witnesses/` 按来源及独立价值保留；现行语义修改只在准确的 canonical owner 中发生。新增的概念分层属于业务阅读视图，不是另一套知识分仓；工具的研究检索命中不能直接提升 Meaning、资格或现实证据。需要采用一条研究结论时，先固定来源、版本、成立条件、最强反例，再补对应 owner 的区别和可执行消费者/负例。文档管理与无二次工作集见[文档架构](文档架构.md#gift-semantic-integration-document-policy)。
