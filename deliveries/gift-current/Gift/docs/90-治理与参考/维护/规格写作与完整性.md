本篇规则也约束设计深化：具体语义只由一个领域章节定义，编译、界面、运行和迁移章节引用它并写自己的接合条件；不复制完整类型表或另造“最终协议”。发现根前提改变时同时检查规范句子、图、场景和理由，不以新段落解释旧相反流程。

写出设计反例时保存触发条件、被破坏的不变量、现行处理、替代与反转条件。它不是已运行的产品测试；具体设计默认可以现在裁决，真正的目标代码、实验与实际环境作用仍需相应任务授权。压缩只合并同义义务，不因例子或反证位于重复模板后面就一起删掉。

## 语义单元级的规范表述和无损收敛

<a id="unified-specification-change-gates"></a>
编辑单位是带适用域的独立可检验主张，可能小于一个段落，也可能跨表格、图和相邻解释。先固定原文及消费者，再判断它属于定义、消费条件、例子、理由、来源还是历史状态；不能按标题数、关键词或段落相似度决定删并。

| 判定所需内容 | 保持或修改规则 |
|---|---|
| 主体、对象、身份、类型、版本与适用域 | 对齐同一个合同及阶段资格；同名异义不得合并，不同写者对同义规则的竞争须消除 |
| 前提、量词、否定、法域、时点、顺序、默认、资源、预算与单位 | 每个会改变合法输入或结论的限定保留；兼容、迁移和失效单独核对 |
| 正常行为、拒绝、未知、异常、权限、结果、恢复与退出 | 写出合法输入怎样完成；不能以永远拒绝满足要求，也不以成功摘要删掉异常分支 |
| 理由、替代、反例、来源强度和未决 | 同义结论只有在这些条件也等价时才可合并；真实纠错保留更正依据，历史材料保持原时点 |
| 字段、输入输出、状态迁移、结构 Schema、接口、图、代码围栏与例子 | 分别核其实际角色及消费者，不让样例或同名字段反向定义另一阶段的合同 |
| 证据和能力陈述 | 已设计、结构合法、参考测试、生产实现及真实作用结算分别陈述；缺事实或权限时保持准确 Need |

术语核对尤其区分 `Claim/Requirement/Fact/Observation`、`State/Snapshot/Revision`、`Method/Binding/Target` 和 `Permit/Grant/Operation/Settlement`；不能全包机械替换。

比较成立后，将完整规则留在唯一 owner，其余位置只保留链接及各自输入、映射、失败和消费差异。若一个段落含两个不同义务，先拆清再融合；证据无法裁决的竞争主张保留具体未知，不选更长、更新或更严的一份。规范表格逐行判断，导航表只定位，研究表保留来源与时间，不能整表按格式降级。

一次专业改写的输出是实际旧主张到新 owner/句段的可恢复对应，以及纠错、保留和未决的依据。对未读文档不宣称已优化；实际没有缺陷的内容无需改动。结构审计只支持已检查的成员、链接、身份或格式，不能签发内容等价、全库完备或“已不可再优化”。过程对应与差异保存在包外，现行正文只保留长期有效知识。

## 跨文件规范保持与单一Owner的证据门禁

原文件权威仍由本目录各owner决定；新增机器Schema应指向它实际**消费**的Rule/Target/Method/作者语义条款，fixture不能用同名定义替换原正文。代码/样例提案若尚未采用，需声明正确的状态、Scope、消费者、拒绝路径和版本机制；不得给当前 `gift.*` 发布命名添一个未经锁定的隐含含义。

重组完整性需核原段落与各条件的去向：删除重复时必须证实完全同义且另一位置完整保留；校正旧错误应记录受影响的下游，不能为保存旧字节保留错误结论。每次变更只把真正采用的规则写入原owner，并通过本地链接、Contract Unit身份、全文读取和跨域失败样本检查。

## 跨文档契约防漂移：身份字面一致也需要实际消费者

Rule `semantics.profile` 与 Target `accepts` 不能通过近似名称、用户输入的别名或默认兼容处理；Method `targetRefs` 与 `project.targets[*].profileRef` 的 identity/revision，Required capabilities 与 Method requires，Rule 中的 Native 引用与真实符号选择，也必须在相同 SourceSnapshot 下逐一交叉校验。单文件 Schema 无法表达的这些关系要由原 owner 的组合消费者读取，跨 owner 正反例同时写入 conformance；升级/重命名更新实际使用点或保留显式版本化迁移，不只修正导航或复制定义。

文档事实唯一 Owner、结构 Schema、SourceProfile Adapter、生产消费者、离线见证彼此可追踪，但不能相互冒充。对每个新机器提案要披露 decoder 的严格性、作用域、主体权限、拒绝分支、能读到哪些原字节、实际谁消费、哪个验证仍未执行。交付包的独立内容签名、Markdown 导航、测试门禁、差异保全与补丁重放分开计算；性能不达门禁时持续报失败，不能用文档数量/清单大小作为成功代理。
