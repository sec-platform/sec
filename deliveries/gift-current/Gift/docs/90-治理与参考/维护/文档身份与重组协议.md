# 文档身份与内容重组协议

本篇定义源文档移动、拆分、合并、链接重写与 Contract Unit 关系迁移的**物理与身份保持算法**；自然语言准确性、主张去重和审校归[文档编写与维护](规格写作与完整性.md)。两者共享精确源与消费者，但不建立第二套问题台账或永久知识数据库。

## 稳定语义身份与当前物理定位

跨文件移动、拆分、合并或多种投影仍需长期引用的独立规范闭包，以正文中全局唯一的 `Contract Unit`/`gift-unit-*` 显式锚点标识；Markdown 路径和行号只定位本次容器。没有稳定引用需求的普通页面不强制发 Unit，也不新增竞争的 `document_id`。

```text
ContractUnitRef = gift-unit-*
ArtifactLocator = { artifact/revision, path, optional anchor, optional line }
```

一个文件可以承载零个、一个或多个 Contract Unit。整篇文档本身若确实需要稳定语义身份，就在其权威正文中声明一个页面级 `gift-unit-*`；无需跨版本稳定引用的普通页面和小节只使用当前 `path/anchor/line`。标题、路径、行号、内容摘要和文件排序都不能自动铸造 Unit，也不能在内容移动时替代已存在的 Unit 身份。

纯物理移动不改变 Unit；纯物理合并不把多个 Unit 压成一个；纯物理拆分也不自动生成新 Unit。只有规范责任本身真实合并、拆分或退役时，才修改 Unit 关系与消费者。产品合同、REQ/D、当前未决及实施闭包、Gift 产品实体及运行对象继续使用各自既有身份域；文档 Unit 不替代它们。

同一库内重名标题按所选 Markdown 规则解析；变更后更新所有受影响的当前链接，不通过旧址路由掩盖断链。外部已发布站点若有明确兼容合同，由该站点自己的发布机制承担；本 current-only 设计包不因假定的未知读者建立永久旧路径服务。

### 当前包怎样定位 Unit

当前正文的路径与显式锚点用于直接定位；需要核对交付成员和字节时，在包外从冻结源计算清单。Contract Unit locator、规范/研究导航树、联合发现和全文 catalog 都从当前作者源按需生成到包外；它们只定位 source 与 Unit，不签发规范采用、权限或产品完成状态。

按需生成的`UNIT_CATALOG.json`不得从标题、路径或hash生成身份；没有显式Unit的页面仍可由普通链接定位，但不因此得到跨版本耐久语义引用。新页面只有在存在真实的独立演进/跨容器稳定引用需求时才新增 Unit，避免把每个自然段永久对象化。

文档的性质与包的采用状态分别描述：规范、导航、理由、前沿、外部依据和维护规则可以同时属于一个未被 main 采用的本地候选。目录与 catalog 的用途提示只帮助查找，正式规范权仍由相应 canonical owner 与采用关系决定。

### 链接、阅读、查询和编辑共享的定位契约

普通标题的可见链接由当前 Markdown 阅读画像导出：处理可见 heading text、大小写折叠、标点过滤、空格处理和**同页重复标题的序号**；显式 `<a id=...>` 作为作者声明的另一地址，不吞掉默认 heading URL。链接审计、KnowledgeIR、直接read/export、表格定位和派生章节目录必须采用同一文法解释；一套生成`gift-工程...`、另一套生成`gift工程...`不构成可互操作的“同标题”。代码围栏及其结束长度、代码中的 `#` 与锚点、行内文本和正式HTML锚点必须按同一已声明的Markdown支持范围处理。解析/链接方法版本变化时，将查询缓存标为不兼容，而不是复用旧行号、旧标题地址或旧检索结果。

地址解析是“一个地址→一个现存目标”的部分函数：一个`path#anchor`同时匹配标题和表格行，或两行显式声明同一个锚点，read/export/edit 必须拒绝歧义，不能优先选首次命中。未显式稳定引用的 heading slug、行号和合成row locator都只是当前 revision 的定位能力，不保证更名、重排后仍指同一对象。明确要跨修订稳定的规范闭包才由作者源宣告`gift-unit-*`；代码块内的相同字符、搜索索引的hash ID、展示标题和导航文件名都不得创建 Unit。

包外 reader 的索引链接必须**相对于实际输出目录和当前作者源路径**生成并做URL转义；把输出目录硬编码为“源根目录的子目录/同级目录”会生成物理不存在的路径。读者投影若移位应重新生成；若需脱离原文件系统的可移植阅读版，则须独立选择并封装完整源/附件与入口，不可把相对链接凑成假离线自包含。投影生成前后的跨文件一致性只在捕获到的实际SourceSnapshot及宿主提供的隔离等级内承诺，普通逐文件读取不自动产生全库事务快照。

## 批次重组的正常流程 DOCORG0—DOCORG8

| 步骤 | 实际动作 | 保持与失败规则 |
|---|---|---|
| DOCORG0 固定源 | 记录准确父制品、成员、字节和工具读取范围 | 文件名不是版本证明；源缺失不能声称零损失 |
| DOCORG1 解析结构 | 围栏感知地取得标题、显式锚点、引用定义、图源、接口和完整段落 | fenced代码中的`#`不是章节；原文解析异常先保全/定位 |
| DOCORG2 选择责任 | 按独立用途与拥有者决定移动、拆分、合并或保留 | 不依“最重要”删枝；长而内聚的协议不为文件数拆碎 |
| DOCORG3 建立对应 | 每个原连续区间有唯一去向；真实纠错注明前后内容与原因 | 31个来源都指概述不能证明内容已承接；正文无去向阻止完整迁移 |
| DOCORG4 转换引用 | 按原文件位置解析相对链接，再按新位置重写；处理片段和引用式链接 | 不做全仓字符串替换污染代码/历史路径；外部URL不随本地目录改 |
| DOCORG5 迁入正文 | 移动完整定义、例子、反例与共同上下文；补最小引导 | 拆分所需引用定义可派生复用，不复制完整语义合同 |
| DOCORG6 修正设计 | 对已证实矛盾改唯一拥有者，同改字段、消费者、例子及相交未决/实施闭包 | 纠错与纯移动分开；不能以原字节保全保留错误规则 |
| DOCORG7 核对 | 全部原区间有去向；链接非空/可定位、锚点/围栏、全库 Contract Unit 身份唯一、相交反例；新包独立解压 | 结构检查不证明全语义；同一 Unit 不能因拆分同时在两个 canonical 作者位置声明；统计增长不弥补局部内容丢失 |
| DOCORG8 交付 | 核对准确当前成员与入口，新包可独立阅读和实施 | 不携带旧路径路由或强制附带迁移台账；原始输入不因制作新包自动删除 |

当前批处理只写隔离的新目录，不对用户原工作区实行破坏式移动。实际仓库实施时再取得真实前像、写集和权限，通过原资产变更协议应用；文档方案本身不授权远程推送。

## 三类核对不能互相代签

**字节和结构保全。** 全部来源成员/连续区间与目标对应；纯移动正文除链接定位变换外相等；变更区间有实际前后差异。JSON能解析、ZIP能解压、本地链接能定位，均只支持所执行检查。

**内容与设计。** 对实质变化说明触发、错误谓词、正常修复路径、失败和消费者，检验当前规则是否已覆盖。新提出的风险没有实测就不说已发生；已有覆盖不再叠加相同原则。所有旧文语义全面正确，不能从结构核对推出。

**产品与运行。** 本包没有运行Gift、实际ACL、Provider GC或业务测试。书面案例是未来验收输入，迁移脚本自身的测试只验证文档处理功能；不能把它们计入Gift能力通过率。

## 导航索引的生成和失效

机器内容树按实际作者文件按需生成：目录/文件表示当前**物理容器**，显式 `gift-unit-*` 作为语义节点；普通标题不会自动升级为 Unit。`任务路线`是少量人工维护的使用路线，页内章节由 Markdown outline 或包外 Section catalog 派生，不手写第二份章节数据库。

source package不运输任何可重建导航/locator。`内容索引.md`、`研究索引.md`、`UNIT_CATALOG.json`、`DOCUMENT_CATALOG.json`、`SECTION_CATALOG.json`和`DOCUMENT_GRAPH.json`都只在包外按需生成；不得保存独有规范、来源选择或采用事实。源变化先保存；派生失败不能回写或回退作者源。若某reader/audit制品声明投影完整，则必须从同一捕获源重建并独立复核。

### 当前链接与内容承接

本设计包不提供历轮文档旧地址到当前位置的查询协议。旧路径只在编辑者比较材料时提供线索，不是现行读者的输入，也不能代替旧内容的实际融合。移动时改完当前入链，拆分时把完整机制、必要定义及反例迁到准确拥有者；链接仍在但独立信息已丢失，属于失败交付。

当前规范引用另一规范时，必须直接指向当前目标和真实片段；索引、目录和示例同样更新。无唯一当前落点时应解决当前组织或保留具体未决，不能把读者导向多个旧版本自行选择。来源论文、标准或真实历史证据仍按其准确版本引用，不适用“旧文档路径全部去掉”的机械处理。

本包直接通过 Markdown 目录和链接阅读，不提供解析、索引、编辑、校验或打包命令。若另行取得文档工具，其检查应绑定准确源与方法范围：成员字节、SourceProfile、链接/锚点、结构及制品读回分别报告；缺依赖不能自动安装，更不能把未执行的方法记作通过。阅读/审计投影和查询索引只在包外按需生成。

## 当前工作材料与永久设计的不同保留

迁移前后字节、工具日志、ZIP统计和差异仅在确需时保留为工作记录，不进入现行规范。新的共同规则进入当前拥有者，新的独立反例进入相应机制 owner、其未决设计范围或确实改变取舍的 D 理由；已完成的移动过程不继续占用全工程前沿，也不默认追加一套必须长期维护的审计资料。

原始来源不可读、重复是否真同义无法判断时，说明对当前设计的具体影响；可取得材料的有效内容继续融合，不以缺完整历史为由停止。清理过程信息不能抹掉设计未决，也不能把未实现内容写成已验证能力。

## 作者源、派生投影与发行制品的身份域

本节拥有 current-only 设计包的生产/消费边界；通用的事实、规范与权威分离由[根原则](../../00-系统与原则/产品/原则总纲与归属.md)拥有，写入准入与完整变化闭合由[规格写作](规格写作与完整性-方案名称与实际控制的同步.md#documentation-write-admission)拥有。

| 对象 | 真实责任 | 失效与禁止事项 |
|---|---|---|
| 作者 Markdown / 根入口 | 当前设计、理由、状态、维护规则或明确登记的长篇理论作者源 | 路径和文件本身不是稳定语义身份；不同角色不因同为 Markdown 而同权 |
| 显式 `gift-unit-*` | 需要稳定引用的 Contract Unit 语义身份 | 只由作者源声明；生成器不得从标题/path/hash 铸造 |
| 分域索引与 `UNIT_CATALOG.json` | 从各角色唯一作者源确定性派生的包外 reader/audit 定位 | 可重建；不得拥有独有规范或采用事实 |
| 完整研究阅读页、联合发现与重型分析缓存 | 从唯一研究源或完整读取集合按需生成到包外 | 不属于主包成员；不得拥有独有规范、研究事实或采用状态 |
| full 分析 catalog/graph | 按需文档/章节/链接分析缓存 | canonical 不运输；删除或重建不改变规范语义 |
| 按需生成的包外成员清单、来源和范围记录 | 绑定实际路径、字节数、摘要及确需追溯的输入；本包不内置这些载体 | 只证明所记录的成员/字节/来源；不证明语义正确、main 采用或产品运行 |
| ZIP 及其 SHA-256 | 一次具体交付制品的准确字节身份 | 相同设计源不要求不同压缩器产生相同字节；要求字节可复现时另固定封装参数 |

### 文档制品的封装与核对条件

封装方法服务交付完整性，不成为产品组件或本包的必需程序。实际制作时固定准确成员集合与输入切面，排除可重建索引、reader/audit 投影和临时运行记录；规范、必要 Schema/示例、独立研究与许可各按其真实角色保留，未知材料不因目录名称自动删除。

若交付用途需要独立成员清单，每行绑定实际 `path + bytes + sha256`，并与制品摘要区分。清单记录放包外；采用其他发行格式而明确将 manifest 内置时，manifest 不自包含自身，最终 ZIP 摘要另绑定整个制品。清单只证明枚举与字节，不产生新的规范身份或采用权。

先检查所选源的结构/引用，再从隔离、冻结或其他能保证捕获期间不漂移的源封装。要求可复现时固定成员排序、时间戳、权限、编码标志和压缩参数；随后独立解压或逐成员读回，分别拒绝缺件、额外成员、摘要不符、危险路径和错误编码。普通逐文件重读不能冒充针对不合作写者的全库原子快照。

封装失败不回写作者源；派生清单和阅读投影可从同一源重建。清理只针对制作方法自己声明的可重建输出，不能扫描删除未知恢复资料。必要源、方法版本或权限不具备时，报告未核范围；成员/链接检查不签发产品能力、安全、性能、语义等价或 main 采用。

### 旧文档元数据体系的迁移边界

历史环境中的 `.documentation/**`、稳定 `document_id`、独立 source-manifest/requirements/figures registry 只作为对应历史实现或仓库迁移输入理解；current-only canonical 不再依赖它们，也不为兼容而保留活动 writer。仍有现实消费者时，先把其**独立语义责任**映射到当前 owner：稳定规范引用进入 `gift-unit-*`，物理成员完整性由实际交付的清单/摘要承担，导航/定位进入包外派生投影，真正产品实体继续由其产品身份域拥有；确认消费者归零后再退出旧 carrier。

若未来出现当前模型不能表达的新需求——例如一个必须跨独立仓库永久引用、又不能由 Contract Unit 承担的作者容器身份，或多个不可重建的权威文件需要同代原子可见——应根据真实消费者重新设计身份/存储协议，而不是恢复一套没有当前需求的旁路注册表。

### 外部依据及未采用内容

W3C的[PROV-Overview（2013-04-30工作组说明）](https://www.w3.org/TR/2013/NOTE-prov-overview-20130430/)提供entity/activity/agent及派生关系的区分；这里借用关系分责，不声称provenance证明内容真值，也不引入RDF服务。Reproducible Builds的[可复现定义](https://reproducible-builds.org/docs/definition/)将源、环境、构建指令及指定输出区分；这里据此分开源包和制品身份，不从相同源hash推断任意环境下HTML字节相同。

[SLSA 1.2 Build Provenance](https://slsa.dev/spec/v1.2/build-provenance)将构建定义、已解析依赖、运行详情和输出subject分开；这里采用这项关系，不宣称取得SLSA等级或完整attestation。SLSA通用provenance的忽略未知字段与空/null等同规则**不引入Gift的exact-JSON合同**。这些来源只支持对应机制，不认证本项目实现或完整性；来源版本、核查日期和采用边界由[构建分发与迁移依据](../../../research/sources/构建分发与迁移.md)维护。原生非阻塞锁分别依[Python fcntl](https://docs.python.org/3/library/fcntl.html)和[msvcrt](https://docs.python.org/3/library/msvcrt.html)接口；具体宿主仍需自己的运行证据，不能用Unix结果代签Windows。

## 组织变化的正文与交付保持

文档画像消费[共同组织保持](../../70-工程系统与演进/信息与生命周期/多维组织与树形落位.md#organization-preservation-laws)。路径迁移一一对应、标题全在、摘要一致分别证明其准确命题，不能提升为逐义务语义保持。需同时核条件、否定、数量/单位、角色、关系方向、算法、正常与失败/恢复、替代理由、证据范围和未决。保留原字节仅证明可追溯，不证明新正文已承接旧义务。

旧源码例/锁仍固定旧文档字节时，不为追逐最新目录默换解释。可用不可变版本子树保存其闭包，当前正文的链接应明确该对象角色；它不成为当前设计的竞争写源。修订或迁移示例时再按完整来源、字段、语义和符合性处理，不能只更新hash。

文件交付还须检查实际解码路径。ZIP中合法UTF-8名字若缺相应标志，标准解压可能产生乱码而CRC仍正确。输出工具必须写正确标志，并用默认解码重新读回成员与摘要；不要把只在特殊编码参数下可读的包称为正常交付。

资料用 `kd/kr/src` 的局部记录引用仅定位研究源、节点/行和外部地址，不与规范 `gift-unit-*` 竞争。当前布局、单一可编辑源和派生页冲突处理按[知识记录协议](知识记录与分域检索.md)执行；普通理论仍有准确 Markdown 作者源，资料格式变化不授予事实或采用资格。

## 整套文档的合同坐标与逐文件可检查覆盖

对全量设计包，逐文件审计清单属于**包外证据**；`docs/`每个现行规范文件有唯一当前路径、可解析标题/显式Unit与正确所属责任；`research/`、`fixtures/`、`witnesses/`作为独立输入或见证不会被机器索引提升为规范。跨文档语义索引可统计段落、标识、引用、重复和未决词，但这些统计不能证明已理解或闭合每项语义。

新增实质合同需向上进入当前主题索引，向下进入实际消费者/反例，并将能力/实施/证据状态各自显示；不得再向README逐版追加新的“最终版本”而使读者无法区分现行规范。文档版本的父包摘要、补丁及校验结果只保留在当前交付证据，不当做永久设计事实。
