# 客户端与并行会话

## 客户端适配不复制领域规则

首个headless实现闭环只有机器客户端，优先成组读取、明确基础、局部补丁、稳定诊断和续传。已选人类客户端及其他客户端接入时仍消费共同语义，可以使用不同交互，但不因编码或主体种类改变采纳、效果和并发含义。headless闭环不为尚未激活的界面预建专用流程。

机器操作归为**范围读取、候选修改、检验及真实作用**四种可组合阶段：读取限于当前可见域，修改绑定 base/前像，检查绑定被验证的 Candidate/Claim，只有实际作用要求现行 Grant 与稳定 Effect 身份。简单场景可在一个调用中融合，不要求四次网络往返或向用户暴露全字段信封。

批次的分组、临时身份和陈旧处理由[语义增量](候选修改与批量.md#语义增量临时身份与前提)至[联合候选](候选修改与批量.md#联合候选部分接受与真实作用)完整定义；所有客户端使用这一规则，不自行推断数组顺序、全部成功或隐式批准。

人类确认和 AI 处理的待决选择必须引用同一候选基础、身份及可见差异；是否可采纳由真实委派 Policy 与当前写权决定，不能按 Human/AI 类型自动授予或剥夺权限。提出候选、执行校验和独立裁决可按实际风险隔离，不硬编码“人类永远有最终签字权”。

**重连再协商。（消费条件）：** 客户端换端点、会话纪元或通道能力时不能把旧feature表当成当前授权与语义保证，编辑与观察请求各自核能力。 合同归属：[协议协商中的降级、未知字段与旧客户端保护](../../70-工程系统与演进/演进与实施/兼容迁移/生态协议与版本演进.md#gift-capability-downgrade)。

**多会话状态。（消费条件）：** 一个客户端断线重连后，旧订阅事件与新分页响应要按requestGeneration丢弃或标注旧basis；不能覆盖新候选结果。 合同归属：[离线客户端、分页视图与操作前像的同步](../客户端/工作台布局与交互.md#gift-client-view-consistency)。

**断开协议。（消费条件）：** 关闭传输只结束连接责任，不代表执行owner失效；在途Operation依本身状态完成或移交。 合同归属：[初始化半途失败、依赖倒序销毁与驻留回调](../../70-工程系统与演进/实现与装配/模块与运行实例-成品装配-实际对象作用域与入口闭合.md#gift-bootstrap-lifecycle)。

### 检查主体、差异基础与披露的确定性

无artifactRef的`check(methods=["types"])`可以在尚无后端时检查中立源的解析、绑定、类型与声明效果，不顺带生成或运行。提供artifactRef时，同名types方法检查该目标实际使用的工具与构建范围，并引用已有源检查；不能将二者合成一份无主体的PASS。cases必须有明确目标及独立casesRef；没有该候选/目标的产物就诊断，不能内部偷偷先生成并扩大执行范围。

`preview(return="diff")`指目标产物差异，必须以`compareTo`显式指定已有artifactRef；其他return模式禁止compareTo。服务核对它与候选基础的关联、实际输入、目标语言与映射范围，及当前读取权限；不依据缓存里“当前唯一”“最近”或猜测相似文件名选择。没有合法基础为`NO_ARTIFACT_BASE`，可另请求完整code。不同工具/布局版本可以作真实文本比较，但明确标示差异来源；比较本身不证明行为等价或允许直接应用。`propose(return="diff")`指作者源差异，绑定源base。两类diff直接标明subjectKind；不能把TS与Java文件做文本差分再称同一语义变化。实际值相同但上下文、资格或布局不同，仍保留其差别。

save-source只保存当前作者内容，不能因给了产物而写入生成结果；write-output只消费已绑定的实际产物，不在apply中重新选择后端或生成。sourceLanguage/target的变更产生新的解释或产物请求，不能在旧candidateRef上原地重解释。当前支持矩阵只是所需能力入口，不从模式完整或名称存在推导运行资格。

任何引用解析先校验作用域与当前披露权限；候选不匹配、不存在和无权访问可以按泄露策略统一返回，不先泄露另一个租户的产物身份。游标续同一查询；携带原查询字段只能完全一致，不允许悄悄改过滤、排序或快照。引用释放、撤销与内容不存在分别处理，不能从不可读推断产物没有生成。

以上为工具/2尚未发布草案的补充；实现时固定这些分支与错误。短preview仍可只有source，明确artifactRef由工具返回后自动用于后续请求，无需AI编造长哈希。

### 引用生命周期、执行占用与草稿保存

短context/candidate/artifact引用是定位柄，不是持久内容本身。开始一项读取或计算时，服务在同一解析准入中校验作用域、内容存在性和预算，并为实际使用的不可变内容建立有界占用；“刚检查过存在”与随后GC之间不能有未保护窗口。活动引用保护延续到该次工作结束，不能因为原查询游标先到期就删掉执行中的输入。长期未结算作用所需内容归恢复意图保护，不依赖模型会话TTL。

内容保护不锁住权限。披露、检查启动和真实写入仍按相应边界复查当前许可；撤权阻止后续返回/作用，但不使已发生的作用变成未执行，也不授权提前删除必要恢复资产。停止、崩溃和预算耗尽都有有限回收/转交机制，不能用“被pin”永久泄漏内存或对象；租约到期只回收已确认可回收的占用，不能猜测不受控执行器已停止。

含语法错误的设计草稿可以保全原字节和诊断，save-source按该任务的草稿保存合同处理，不先将它格式化成另一个程序。合格生成仍需对应语义闭合。保存到已有作者区继续需要前像和当前写入权，不能因为对象叫draft就绕过覆盖保护。源保存不表示采纳，也不让旧有效AST覆盖新但未完整的文本。

短默认请求不新增生命周期字段：服务管理引用及占用，调用者只在长期保留/跨会话迁出确有需要时选择相应保存目的。普通多文件可直接使用files；原结构增量继续处理身份移动和语义图变化，不因精简工具面恢复手写全IR。

## 远程、事件与重连

短查询可同步；长效果返回明确操作引用。HTTP成功、进程退出零和连接关闭不重定义工程终态。请求超时按[幂等合同](../../50-执行运行与观测/持久化与恢复/事务提交-外部效果与幂等交付.md#幂等授权与出站交付协议)处理，不用新身份盲重放。

### 分页查询的快照合同

第一页固定查询定义、过滤/排序/投影、解释版本、内容切面、可见范围和稳定并列排序键；续页游标是受保护的不透明引用，绑定这些条件与保留窗口。默认使用固定快照上的键集续页，不对持续变化的结果使用裸offset。多个相同排序值用稳定对象身份决胜，避免漏项或重复。

内容快照不是历史授权。每次返回按当前披露政策复查；权限相关版本改变、过滤改变或快照已回收时，使游标失效并重新取得合格快照，不把“剩余页为空”伪装成查询完整结束。可以采用重新授权后仍读原内容快照的专门协议，但需保持相同可见成员集合或明确返回变化，不能偷偷拼接。

跨数据源没有共同原子快照时，返回每源版本与观察切面；需要联立不变量的查询再做协调/重查。未完成、缺权、部分覆盖和确实空集合保持区别。客户端不能凭“已读最后一页”推导未获准观察的隐藏对象不存在。

### 快照与事件之间的无缺口接合

宿主在一个可解释切面固定快照和随后事件位置；支持相交历史读取的实现可取得修订R的完整快照并续接其后变化，或先建立有界事件缓冲再捕获对应快照。MVCC本身不证明还提供可续读变化流；adapter必须绑定准确Provider实例、流出生代、范围/过滤、解释及保留窗口，并把“切面之后”映射到原协议的包含/排除边界。原生游标不通用地加一、比较大小或转换成墙钟；确有同域整数顺序和后继规则时才使用它们。不能先读一个不带位置的列表，再从“现在”订阅，遗漏两步之间的修改。

排序域明确到工作区、对象或操作；不强迫所有系统拥有一个全球序号。一次源提交可以修改多个对象并共享revision；不能按裸revision或载荷相同删除其他真实出现。能证明同一完整批次重传时按批次去重；必须逐项接收时，使用原协议稳定的事件/出现身份和完整批界，不把网络分片编号当永久事件身份。接收与完整性沿[结果分片](#result-stream-completion)；所需前提、解释或完整批界不足时不先更新对外投影；自足的完整状态替换不额外要求取回其语义无需的旧值。缺口、逆序且无合法重排依据、历史压缩或换了投影权限时进入`resync-required`，按[检查点与重同步](#projection-checkpoint-resync)恢复。候选和未保存文本另外保留，重同步不覆盖作者修改。

控制器消费同一握手，但通知如何合并到正在处理的工作，由[调和排队交接](../../50-执行运行与观测/运行生命周期/运行实例-订阅部署与调和.md#reconcile-wakeup-handoff)拥有；它不重新定义本节游标，也不将被合并的通知当已执行命令。活动查询更换真实依赖时还要接上[订阅保护](../../30-实现解析/增量与性能/复用资格与失效案例.md#live-projection-dependency-handoff)，固定快照查询不承担无关的持续订阅。

用于当前状态同步的通知是状态的投影，不代表全部事件都可由最新状态重建。普通进度可合并或丢弃并标记不连续；终态、权限和恢复责任的摘要可以重新读回，但独立业务事件、命令、每次出现及所需审计历史仍由原Journal/消息源保全。值从A变B再变A时，新快照可恢复当前A，不能证明中间没发生B，也不能补签那两次交付。队列满不能在持有业务提交锁时无界等待慢客户端；无法重建且用途必需的内容须在原耐久介质保留、背压或停止相交接纳，不得普通丢弃。长期断线、保留窗口过期只撤销续传资格，不抹掉真实完成事实或自动获准重发作用。

游标及进度按可见投影生成，不公开全局事件计数、隐藏键或精确跨租户版本差。每次披露检查当前权限；过去已披露的数据无法靠换游标撤回。客户端断开是否取消由已接受政策决定，已发生作用仍须结算。

[etcd与Kubernetes的具体边界](../../../research/sources/构建分发与迁移.md#watch-boundary-source-details)区分带修订读取、续读起点、完整revision、可选传输分片、进度通知和历史过期。这里不把概述的原子保证扩大到未经适配的原始分片。协议可用轮询实现，不强制采用etcd、长连接或全局数据库；轮询可恢复相应当前状态，不自动补出轮询间全部业务事件。所选宿主必须实际提供本次用途要求的切面与保留条件。

### 投影检查点、进度确认与重同步发布

本节由entry适配与application的既有读回/投影拥有者共同实现，不新增公开工具、业务事件总线或统一持久服务。沿用[ReadBinding与ProviderPage](../../70-工程系统与演进/信息与生命周期/接入检索与派生.md#provider-page-composition)、ObservationCoverage和当前返回代；固定读取无需订阅，纯内存视图也不必写耐久日志。

| 内部交接 | 输入、结果与必要依据 |
|---|---|
| 捕获读取与续接边界 | 现有readInformation/源reader接收查询、所需一致性、当前读资格及预算，返回准确ReadBinding、同一切面的ProviderPage和adapter解释的续接边界；没有该能力就返回受限观察/缺项，不伪造cursor |
| 建立或恢复变化接收 | 输入原读取绑定、流代、准确起点及其包含/排除含义；返回已建立的订阅和覆盖，或历史失效、范围/资格变化、不支持、不可达。建立回执不是原基础已补齐，重复建立也不许可重放业务作用 |
| 接收完整变化/进度 | 每个消息绑定原订阅代和范围；区分完整语义批次、待装配片段、覆盖进度、失效及终止。原协议有可验证原子批界时直接复用，没有时先装配/校验，不用超时或短暂无消息猜批次结束 |
| 安装与确认消费 | 对原投影代和前置检查点作条件安装，完整内容/依赖/覆盖/应用位置共同生效；返回Installed、Superseded或所需检查点未能确认。旧检查点、原在途操作及未保存草稿不由失败分支改写 |
| 关闭接收 | 取消本消费者、停止新返回，待其缓冲/回调实际退出后释放对应占用；Provider订阅关闭与业务操作停止仍是独立结果 |

`ProjectionCheckpoint`是**派生投影的恢复值**，引用读取绑定/流代、投影方法与内容代、实际依赖和覆盖、最后完整应用边界、可恢复续接位置，及资格核对的适用条件。它不抄一份源事实、不签发Grant，也不是所有消息源都必须保存的新格式。多源无共同顺序时保存各源位置及真实耦合要求；无关来源可以独立推进，但声称共同不变量的视图不能把这些位置伪造成全局事务切面。

**接收、应用与耐久不是一个位置。** 网络已收到的最后cursor只描述接收；`BOOKMARK`或progress表示原协议承诺的前序交付范围，不表示应用队列已处理、磁盘已提交或权限仍有效。只有屏障之前的相交消息已全部完整应用，才允许将它作为应用检查点。需要崩溃恢复时，状态内容、实际依赖、去重所需信息和应用位置必须在同一真实本地提交边界安装，或先封存不可变投影清单，再条件切换其唯一目录指针；不能先写位置后写数据。无需耐久恢复的内存视图重启后重新捕获，不复用失去内容的持久cursor。若底层仅提供可重建检查点，可重放完整批次并以幂等投影或准确身份消除重复，不声明外部Effect恰好一次。

服务端的传输流控ack可以在接收后发出；会使唯一历史不可再取的消费ack必须等所需耐久状态/独立重建依据成立。确认丢失允许原消息重投而不重复应用；本地提交结果未知时先查原检查点，不凭异常推进或回退位置。单纯状态源具有合法全量重建能力时可选择断流后重建，不强制为每个进度写日志；不可重建的命令/事件仍沿其交付和幂等合同，不被本节降格。

**重同步的实际顺序如下。**

1. 立即将相交旧视图标为不再具备所要求的连续覆盖，关闭旧接收代的更新权；它的在途工作仍按原身份结算。旧值仅在当前许可和所接受的陈旧显示范围内继续展示，不得继续据它证明“最新”“不存在”或执行需要新前像的操作。
2. 在原预算内捕获新的ReadBinding与可续接边界，先确保历史保留或有界缓冲足以接合，再分页面构造**私有候选投影**。空页加More不是完成；丢页、过滤变化或切面丢失不能与另一新快照拼接。已经完整的独立分区可按自己范围交付，不冒充整个联合视图。
3. 按原方法补齐新边界之后的完整变化，安装新实际依赖的通知保护；值不变也要更新读集、成员/负依赖、解释和覆盖。新到达的dirty不能被结束回调清除。无限变化不要求“追到绝对现在”才允许返回固定切面；本次用途要求更新边界或持续性时，另取得对应屏障/保护，不能夸大已捕获保证。
4. 在该投影的短安装点核原返回代、对象/范围、所需一致性及当前披露资格，条件发布候选内容、依赖、完整覆盖和应用检查点。持久目录的应用位置与内容一起提交；没有跨端原子能力时仍准确保留源观察范围，不能由本地原子安装推出源端全局原子。安装成功后才退役被替换的旧保护。
5. 新捕获、接收、校验或安装失败，只清理该候选已确认无人使用的资源；原合法值、草稿、独立分区和恢复责任保留。位置压缩/缓冲溢出可以限速重试捕获，不能反复重连同一已失效cursor或刷新原deadline。无法在预算内取得连续覆盖时，返回有切面的较弱观察或相交缺项，不制造永久后台重扫任务。

**权限变化不是等重同步完成再生效。** 在已受控的披露/安装/作用边界识别撤销后，立即使相交旧投影失去该用途资格，停止新披露；需要保全的恢复资料转到其受限责任域，不物理抹掉历史或泄露隐藏对象计数。离线客户端或隔离端点无法观察即时撤销时，按原[执行准入](../../50-执行运行与观测/权限与资源/授权与执行准入.md)的授权有效期、受信新鲜度与真实拒旧能力判断；只在明确接受的有界离线权限内使用，不能一面失联一面保证即时撤销。过去已披露或导出的字节不在本地换cursor的可撤回保证内。

完整batch在revision R同时修改X和Y：收到X所在分片后断线，检查点仍应停在前一完整边界；重连重取R的完整批次或新快照，不能跳到R之后漏Y。对照是R完整应用并共同提交检查点、消费ack丢失：重投R只复用已安装状态。两例只约束投影交接，不把收到文件系统变化提示解释为确切业务编辑。

<a id="result-stream-completion"></a>
### 结果分片、完成屏障与取消后的结算

进度、结果分片和原操作的结算观察分别消费。一个`done`标记可能说明生产者已结束计算，也可能只是传输结束；只有协商合同说明其主体、范围与前序交付保证，接收者才能据此判定当前结果完整。不能把较快到达的结束回调当成缺失分片不存在的证明。本节补足上文快照/事件握手，不改变各领域的结果含义，也不另建全局流服务。

生产者按既有请求、结果或操作身份固定准确主体和结果范围；需要多路复用、重连或乱序时，entry适配绑定流的出生代及分片身份，不能只使用会复用的序号。传输中的身份可以来自原协议，不要求作者手填新的sessionId。完整性依据优先使用原协议可证明的有序交付和终结边界；协议不能提供时，才采用当前可见结果的封存成员/范围及完整性校验。仅有摘要不证明成员已收到，也不证明内容真实或有权披露。

| 责任 | 拥有者 | 输出或约束 |
|---|---|---|
| 结果是否在所求范围完成 | 原compiler/assurance/其他领域生产者 | 固定主体、覆盖、实际结果及尚未满足项；不由网络层改写 |
| 分片是否属于同一份结果并已收齐 | entry的协议适配与有界接收器 | 按协商的顺序、身份和结束规则装配；不改变领域语义 |
| 哪一代结果可以更新当前用途 | application与当前客户端返回槽 | 按[请求返回代](#request-result-routing)核输入与代际；批处理仍按原请求返回 |
| 作用是否成功、失败或仍需恢复 | execution及真实Provider | 原operationRef的结算；不依赖结果面板是否打开或分片是否保留 |

接收算法按以下顺序执行，纯本地原子返回可直接满足对应步骤，不新增网络往返：

1. **接纳本次流。** 固定请求代、结果主体、解释、可见范围和字节/成员/在途预算。未协商的字段与事件类型按原协议拒绝或明确不支持，不把未知必需含义忽略为成功。
2. **核对每份内容。** 先解码、校验边界及来源关联，再按实际分片身份接收。同一身份同一内容的重复可去重；同一身份出现不相容内容则停止将该流当成合格完整结果，保留冲突和独立已知事实。无依据的乱序不靠到达顺序猜测前像。
3. **有界保留与展示。** 完整的独立子结果可按其真实范围展示或交付；未完成聚合明确标partial。乱序缓冲和消费队列有界，超过预算按合同背压、终止交付或重同步，不在持有业务锁时等待慢客户端。不能为了保持内存上限丢掉语义分片后仍声称完整。
4. **验证完成屏障。** 只有当前结果的全部所求成员已按原协议收齐并通过相交完整性检查，才形成完整交付。结束标记先到而成员不足时，保留“生产者报告结束、当前交付不完整”两个事实；可在预算内续收，或从同一已封存结果的获准引用重新取得。不得以另一请求、另一可见范围或新运行的片段补齐旧结果。
5. **安装当前结果。** 完整交付仍需核当前返回槽、主体与披露资格；范围变化、撤权或请求被替代时不覆盖当前结果。旧内容只在仍被允许的保留用途下进入历史/缓存，不能因输入名字再次相同自动复活旧回调。安装时只替换该生产者和覆盖分区，不能清除其他工具或未覆盖根的结果。
6. **关闭本消费者。** 交付完成、截止或取消后释放本消费者的临时缓冲与占用。晚到分片不能重开已关闭的接收代；明确续传按保留合同建立新接收并绑定原封存结果。原作用的恢复资产仍归其操作拥有者，不能随流关闭删除，也不能靠永久保留所有输出代替恢复合同。

取消可以结束本调用者的等待，但不能把已收到的成功结算改成“从未执行”，也不能把未收到回执的作用判为取消成功。恢复查询沿原operationRef/requestId；重新读取同一封存结果不等于重新执行原作用。权限改变导致不能再展示细节时，返回不泄露隐藏主体的不足/受阻说明，不通过成员总数或摘要暴露原不可见内容。

### 同一接收合同在开发工具中的实际消费

| 消费者 | 可以接受的正向结果 | 必须挡住的反例 |
|---|---|---|
| 诊断与检查 | 完整分区的空诊断可以清除该生产者原分区；其余生产者保留 | 取消后收到空的部分批次，把所有错误清空 |
| 搜索、引用与影响查询 | 已收到命中可先显示；只有完整声明范围才报告确实无命中 | 只读一页、索引未就绪或预算截断却回答“不存在” |
| 测试发现与执行 | 发现范围完整且为空，与已选择测试全部通过分别表达 | 测试尚未发现、加载失败或全被过滤，就冒领测试通过 |
| 编译与产物成员 | 独立根完成可以单独返回；共同产物按其成员/配置条件闭合 | 最快根先结束，缺失资源和类型成员却发布完整产物 |
| 调试、Notebook与交互进程 | 控制回执、运行状态与输出交付分别呈现 | 收到输出结束就认定程序停止；旧执行输出混入新单元结果 |
| Agent与批量任务 | 文本说明与真实操作结果通过固定引用关联 | 模型文本结束、批次数组最后一项到达就认定全部作用已完成 |

有限正向轨迹：分片B先到、A后到、重复B、最后封存边界确认A/B构成所求范围；接收器去重并在当前返回代安装一次完整结果。对应反例是封存边界先到但A永久丢失，此时保留部分结果并查询同一封存对象或报告交付未完成，不盲重跑产生作用的任务。支持严格有序交付的通道无需实现乱序重排；小型一次性结果也无需额外分片摘要或持久记录。

## CLI 与 IDE 适配

首个 headless 闭环的 CLI 按机器调用提供版本化结构；已激活的人类显示与已选 Workbench 只投影相同任务结果，不成为独立业务入口。进度与结果分流；非交互调用不能弹窗等待或默认确认。输入文件、stdin、编码、大小、凭证与错误码有明确约束，参数中的路径不是无限读写许可。

IDE 必须参与未保存缓冲区、文档版本、选区映射、修改预览和冲突读回。语言服务器或编辑协议只提供能力之一，不是业务授权根。编辑器和后端使用相同前像，不能一边改缓冲区、一边直接改磁盘后仍宣称一致。

脚本与批处理保留同一目的边界；脚本能调用的底层接口也必须执行校验。传输适配的重试不能绕过效果幂等。定位 URL、路径和文件名可以变化，稳定对象身份及其权限仍由合同确定。

## 计算任务与未启用能力的接口语义

同一个`source/candidateRef/context/target`协议接收计算核、库、编译器与事务应用，不增算法专用工具。计算例的`sourceLanguage`仍是`gift.semantic/1`；其实际库和实现安排由冻结上下文/目标Binding提供。没有新设任意`fast`、`inplace`或`schedule`工具字段，也不要求AI填写内部循环计划。

`query(view="contract")`按相交对象返回不同合同：计算对象返回输入形状、边界、数值、顺序、内存/设备与当前缺项；事务对象才返回提交、授权和交付。它们都是现有合同投影，不新建两套权威。完整低层计划和未选能力的处置理由只在需要解释时展开，不能每次把全部平台模型返回。

无相交的未选项不显示为失败；当前必需但unsupported的输出继续明确报告；“forbidden”不能通过preview快捷路径或后端回退绕过。候选/目标仍按原规则绑定；保存一个纯计算源不会关闭另一份已部署事务应用或删除其恢复记录。

<a id="request-result-routing"></a>
## 多客户端、当前结果与准备态后继

### 请求身份不等于当前显示槽

同一工程可有两个AI任务、两个编辑器窗口和一个批量构建；不能使用进程级`currentCandidate`、`lastArtifact`或`lastOperation`协调它们。六工具的明确base/at/candidateRef/artifactRef继续是主体，客户端上下文只提供已固定的缺省输入，进入处理器后不再随着其他请求改变。

entry/application内部可以维护一个**返回槽**，其键为当前连接或本地调用者、具体用途与对象选择；槽内保存本次请求代及固定基础。它只用于回答“哪些结果可以更新这个当前展示”，不进入作者语言、锁文件或所有编译缓存，也不新增公开必填sessionId。无当前展示的批处理直接按请求返回结果，无需建立槽。

一次请求进入时固定`requestGeneration`；用途、候选、目标、比较基础或当前接受要求改变，建立新代。完成回调先核返回槽仍指本次代与输入，再披露并更新；旧结果可以保存为原主体的历史结果或合格缓存，但不能覆盖新代。即使选择经历C1→C2→C1，也不让第一次C1请求凭候选名相同自动更新第三次选择；合格结果可以被第三次请求明确复用，而非冒充它的回调。

`operationRef`指真实作用，独立于返回槽。用户切换页面或开始新候选后，原保存/运行已发生的事实仍须可查询和结算；不能因为结果不再“当前”就删除作用记录、隐藏失败或再启动一遍。任务接受关系改变，同样只影响新请求与资格判断，不重写旧操作意图。

### 固定输入、补取和恢复分别由谁执行

`application/prepare-job.ts`只取得本次原输入，`application/resolve-needs.ts`处理已有Needs，`compiler`只消费固定值。协调器的每次重入必须返回以下一种明确结果：

| 返回 | 内容与成立条件 | 后继 |
|---|---|---|
| `Prepared` | 原要求下，取得相容的新内容/观察/方法绑定，形成新的PreparedJob及真实读集 | 仅重算相交查询；旧完整结果按依赖可复用 |
| `Waiting` | 真实缺少外部决定、可恢复输入或允许稍后取得的能力，保留具体需要和有用结果 | 返回调用者，不持CPU槽/文件锁无限等待；新事实到来后显式继续 |
| `Conflict` | 新内容与原固定基础、作者前像或要求不相容 | 保全双方；要求明确新基础、合法重基或重新规划 |
| `Stopped` | 无权、明确不支持、预算结束、取消或工具故障等原类别 | 返回准确影响根与已完成部分；不自动降低原任务 |

它们是内部协调结果，公共响应仍使用原版本已定义的引用/诊断/分项状态；新增公开结果字段必须走版本能力协商，不能让客户端忽略必需含义。

### 补取去重、无进展和矛盾观察的处理算法

1. **归一需求。** 需求按固定basis、角色、实际解析域/精确内容、要求覆盖及选定工具输入识别。相同名称不同版本、不同根的查找或不同输出形状不能合并；多个消费者所需内容完全相同时可以共享取得。
2. **核已有事实。** 已取得found就核内容和范围；exact-absent只在原精确查找范围成立；denied/unavailable/failed不转为不存在。当前认证/披露影响是否可返回或继续，不能缓存一条拒绝后宣布全体用户永远无此库。
3. **选择取得方式。** 本地只读内容、缓存核验、获准外部取得与实际工具执行分别调用其已有端口。不在resolver里执行任意工作区脚本；缺工具安装不是普通读取的隐式后继。
4. **验证结果。** 新内容核真实身份、字节、编码、生产关系与覆盖；工具成功但输出缺少所需成员仍未满足。发现相同不可变内容标识对应不同字节，隔离该结果并保留冲突，不能覆盖内容库旧值。
5. **形成后继。** 同一作者候选补齐固定依赖时仅更新准备态；作者字节实际改变时形成新候选或报告前像变化。新增解释方法按原EngineImage协议准备新映像，不在旧调用中热改规则；原要求固定旧版本时不因新版本可用就升级。
6. **判断进展。** 新取得的内容、覆盖、已接受决定、方法或可用能力必须改变一个真实等待条件。重复相同需求且没有新事实时返回当前未完成原因，不再次调相同工具。复杂生成持续产生新输入仍受真实节点/空间/时间预算限制；“键每次不同”不是允许无限执行的理由。
7. **释放与返回。** 解除本消费者已不需要的占用。若别的获准消费者仍等待同一纯生产者，不由当前请求取消它；最后撤离与关闭接纳按[共享代际](../../40-目标与制品/递归并行与远程编译.md#shared-producer-generation)共同协调，新加入者不接到已经Closing的实例。其输入和资源仍等实际终止或责任移交再释放。

新观察与旧观察矛盾时，不在同一基础里同时留下“缺失”和“已存在”并任选有利者。需要的是新观测基础与重新解析，或明确识别观察能力不足。跨文件非原子捕获也不能通过补几个摘要伪装成原子快照。

### 传输失败、超时与部分结果的正向路径

纯查询的响应丢失，客户端可按原精确输入重读或复用有范围缓存；产生外部作用的请求按原requestId及去重合同查询，而非重放命令。没有持久重试窗口的实现不能声称跨崩溃恰好一次。请求要求完整组结果时，分项早到只能标进度或独立成果，不能先发全组success。

披露在返回前核当前范围；流式分片也必须遵守其当前披露与截断合同。断开连接不证明目标已停止，局部超时不删除完整候选。与本任务无关的其他连接不因一个坏输入被清空，真正共享资源故障则报告其实际影响，而不是永远假装请求互不影响。

该协议由[Runtime作用域](../../70-工程系统与演进/实现与装配/模块与运行实例-最终逻辑模块与公开接口.md#runtime-assembly-scopes)、原[调度取消](../../40-目标与制品/递归并行与远程编译.md)和[持久恢复](../../50-执行运行与观测/持久化与恢复/README.md)共同消费；不建立另一份请求数据库或重复权限引擎。

[gift.intent-authoring/1](意图发现与候选展开.md)沿本页会话能力/披露/返回代提供两种query视图和draft子类。重连后重新核实际可用能力、facet与源basis；旧目录游标和worker局部handle不能续授权或定位新对象。恢复已接受作者源与外部操作按原长期身份，纯发现失败不删除草稿或原Operation责任。

## 工具协议协商：请求效果、结果资格和未发布草案

公共工具名不是任何环境都已能执行该动作的承诺。客户端握手取得 `ToolProtocolIdentity{protocolRevision,serverImplementation,methodCapabilities,sourceProfiles,targetProfiles,hostEffects}`；每种方法还绑定所请求主体和场景，返回 `SUPPORTED / CONDITIONAL / UNSUPPORTED / UNKNOWN`，不拿“服务上线了”代替全部方法成熟。

内部请求上下文保存用途所需的 `taskRef/requestGeneration,subjectRef,basisRef,methodKind,scope,outputMode`；这些不是向六工具v2参数表自动追加的线字段，也不强制全部动作提交巨型Context；纯 `understand` 可无候选、无 Effect，`author/change` 要明确源前像与允许写集，`validate` 要精确选择源语义、目标产物或执行测试，`use/deliver` 则必须说明外部 Effect 的授权和恢复身份。检查源类型、目标构建与测试是三种不同检查语义，不是三个可直接混填的新参数分支。六工具基础形态仍为 `check(candidateRef, methods=[types])`，请求cases需同带artifactRef和casesRef；target-build等新方法只有另行协商相应扩展才可发送。源类型通过只说明所选修订，目标构建需固定Target及工具链，测试需封存的独立期望集合，三者不混成一个PASS。

返回 envelope 采用 `{status,subjectRef,basis,coverage,results?,diagnostics?,effectRef?,next?}` 的有条件公共视图；`status` 不覆盖内部业务状态。缺项必须用带准确字段和消费条件的 `UNSUPPORTED_CAPABILITY` 或 `NEEDS_BINDING`，拒绝而非隐式生成/联网/部署。中断或断线返回已有的 durable `operationRef`（若实际存在）；无 Effect 的读查询不能凭文本声称已创建 Operation。网络分片的完成屏障与真实动作已结算仍是两件事。

`tools/2` 中尚无真实实现、反向兼容/安全/性能消费者的分支保留为**未发布设计合同**；首次发行只公布通过对应 host conformance 的能力集合。Web/受限 IDE 没有 Node FS/进程能力时必须经合格 Runtime Adapter；页面 UI 自行模拟执行命令不能让 `use` 成为“已实际完成”。

<a id="gift-client-secure-cursor-and-epoch"></a>
## 重连游标、权限代际和不可控已披露内容

远程客户端接收 `Page/StreamCursor` 时，票据必须绑定 `principal/tenant/authorizationEpoch/queryDigest/sourceCut/generationAndIncarnation/ordering/expiry`，由受信服务签名或只保存不透明随机句柄。仅有未加密 SHA-256 校验和的自包含 JSON token 可检测意外损坏，但用户能自己重算，不能用于拒绝恶意跨租户或跳页访问；只在单用户离线工具且无授权 Claim 时允许该简化。服务器必须在每一页/分片向外披露前重检授权和当前来源资格；请求开始时验证一次不能保证长流中撤销后的安全。

订阅和重连保留原 `subscriptionId`、服务端快照/事件衔接水位、租户可见域和投影 generation；游标不存在、ACL 收缩或事件日志缺口时，返回 `RESYNC_REQUIRED` 并重新取得受权限约束的完整快照，不从旧进度跳接最新事件。授权扩大同样需要重新求视图与来源，不能自动补全过去没权限看过的历史。读者收到撤销前合法明文的风险按政策与受控设备清理处理，协议不虚构能够撤回第三方截图/副本。

并发结果有稳定 requestId 和所消费的 source/plan basis；UI 的当前选择改变不改旧结果身份。传输最后分片只能在该次实际输出序列闭合且准确coverage已交付后标记完成；它可以携带尚未结算的Effect或未完成证据。任务完成、目标完整降低和现实作用成功另核各自终结条件，不把未知效果无限延迟为无最终响应，也不把传输EOF当效果成功。背压/取消可终止当前客户端展示，但未结算的外部 operation 仍具有持久引用和恢复入口。

<a id="design-a06"></a>
## 六工具第二版的线协议与结算分离

六个操作名固定为 `query/propose/preview/check/apply/operation`，不增加第七个工具。协议版本协商先于任务执行：双方交换可接受的精确protocolRevision及Method/Source/Target/Host能力，选共同支持的版本；无交集时返回UnsupportedProtocol且无作用。源Profile版本、目标Profile版本与工具线协议版本分别锁定，不能用“工具兼容”推导源兼容。

既有 `gift.ai-tools/2` 参数表保持，不强制在工具参数外新增一层JSON-RPC或巨型信封。通道自身的请求关联ID与 `apply.params.requestId` 分开：后者继续承担已有作用请求的幂等关联，不能改名后丢失历史语义。服务端审计记录可包含 protocol/transportRequestId/tool/params，但它不是第七工具或新的作者必填载荷。重试同作用请求ID但规范payload不同返回Conflict；所有params由对应工具及实际协商扩展的严格schema联合拥有，不能允许任意params后声称已检查所有请求。纯query/preview/check默认无持久写入或原生运行；apply的save-source与write-output明确区分。

响应公共视图沿原 `status,subjectRef,basis,coverage`，协议版本/传输ID由已选择通道关联，可选 `results,diagnostics,effectRef,next`。status描述当前请求的结果，不替coverage、Claim或Effect结算：成功返回一个“目标不支持”的查询也是请求成功；生成成功但某根未降低不得显示整个目标已完成。复杂Basis由服务端派生，普通作者无需手填。尚无subject时使用明确的request subject，不能虚构artifact身份。

分片采用会话内单调 `sequence`、同一 `streamId` 和最后分片标记，缺序可以按保留窗口重发；窗口已丢则明确SnapshotRequired。游标必须绑定主体/租户、当前授权epoch、查询摘要、源cut、排序、进程incarnation和到期；用服务端随机不透明句柄或认证编码，裸hash不能防伪。敏感数据在发送每批前核披露权限，授权撤销不得继续泄漏已排队块。

传输终止、计算完成、源提交完成、外部Effect结算、证据完成是不同状态。最后分片可以交付指向原实际 Operation 的 `effectRef`，并在其可披露状态中保持 `UnknownOutcome` 后结束传输；引用不承载状态枚举，客户端以该操作引用通过 operation 读回；不能为了等待不可确定的现实效果永不发送最终响应，也不能因传输完成把效果改成成功。cancel首先撤销等待/后继调度；已派发效果沿原Operation结算。恢复不自动换身份、不重新授予current。旧端未协商的新字段不得静默丢弃后执行，显式降级只适用于能证明观察不变的纯读投影。

结构JSON的可达入口作显式兼容修复：旧files简明分支只默认新增`.gift`，不能同时宣称无base的任意JSON已可读。采用可协商 `gift.structured-files/1`，只为既有files分支增加 `fileProfiles`（path到已锁定SourceProfile引用的映射）和可选context；六选一不增加分支。每个非旧默认角色的新文件必须有实际profile；已存在文件profile不允许借此更换，改Profile走明确迁移；删除项不得带profile。带context的files只用于冻结来源/锁/解释，不同时携entry/source/draft。未协商服务拒绝新字段，仍支持原files。完整JSON新模块可以一次propose(files,fileProfiles,context?)创建候选，后续preview(candidateRef)，不必先转`.gift`或手造base。混合工程逐文件固定角色，不按首字符猜语言。

本设计的机器schema分为基础参数结构与协商后扩展union；未知draft.kind即使JSON结构正确也返回UNSUPPORTED_CAPABILITY。扩展schema必须从已锁定注册表编译入验证器，不接受裸对象绕过。公共响应中的status沿既有多维状态语义，其线编码必须由所协商结果Profile提供；shape检查通过不签业务成功。

结果视图另以可协商gift.tool-result-view/2固定wire结构，不强加给未协商旧端。status仅枚举completed/rejected/failed/incomplete；coverage含requested、complete和带reason的incomplete，完成与不完整集合不相交且属于requested。basis为实际可解析句柄，不要求调用者重建。results为reference/code/diff/summary/check的严格联合；code给language与path/content成员，diff标明author或artifact及baseRef，check给claimRef/verdict/evidenceRefs。不能内联的领域对象由reference{role,ref}返回；定位含sourceRef与可选JSON Pointer/字节范围。effectRef只指向真实已有操作；next只给六工具内建议，不授予执行权。这是独立结果投影的设计固定，不宣称现有服务已发布。

### 结果覆盖的闭合与状态映射

`gift.tool-result-view/2` 的 coverage 按本请求已固定的有限交付范围划分，不按全产品功能目录计数。`requested` 是该范围的互不重复标识；`complete` 与 `incomplete[].scope` 各自无重复、互不相交，二者的并集恰等于 requested。尚未执行、缺项、不可判断或取消的请求范围必须进入 incomplete 并给准确 reason，不能直接从 requested 删除。解析请求失败且尚不能形成领域范围时，可以用空集合并保留 request subject、原请求 basis 和拒绝诊断；空覆盖不证明任何领域能力。

`completed` 要求本次请求的覆盖全部完成；`incomplete` 要求至少一个不完整范围。`rejected` 表示请求未获准按其含义执行，`failed` 表示已开始处理但因具体故障没有满足请求；两者仍保留可披露的独立成果与不完整原因。读回一个失败或未知结算的 Operation 可以是已完成的 status 查询，因为所求是当前观察；请求完成不修改被查询操作的领域状态。反之，apply 请求要求提交与读回而结果仍未知时，必须为 incomplete，不能只因返回了 operationRef 就记 completed。派生客户端不得将四种请求状态与领域 Verdict/Settlement 一一强制互换。

结果生产者及 entry 适配共同核对上述集合关系，单份 JSON Schema 只检查结构、重复值及局部状态条件，不能比较任意数组间的集合等式。diagnostics 的位置按 sourceRef 固定的原始字节解释：字节区间为 `[startByte,endByte)`，端点成对、`0 ≤ startByte ≤ endByte ≤ 源字节数`；零长度表示插入点，编码由源 Profile 决定，不按客户端字符数换算。jsonPointer 使用合法 JSON Pointer 转义；同时提供指针与字节范围时必须定位同一版本中的同一对象，否则保留诊断但拒绝使用该定位自动编辑。

**验证与反例**：协议schema/envelope与流状态有限模型分开检查；乱序、重复final、同键不同载荷、授权epoch变化、传输结束但效果未知、旧端碰到新source版本均有对应拒绝。

**实际能力边界**：完整六工具生产handler、身份认证和持久operation store没有由本次设计生成。
