# 意图发现与候选展开协议

<a id="gift135-author-productivity-not-a-new-kind"></a>

## 非计算业务作者的三类工具责任不是新的 Definition

45家族/135侧面的`productivity.intent/editing/automation`不是三个丢失的业务原语，它们分属**发现候选、受管编辑、工具权限**：

| 开发者动作 | 确切输入/输出 | 不得隐式发生的事 |
|---|---|---|
| 意图发现 | 有权限的`SourceSnapshot`、Catalog/Facet、范围与预算 → `CandidateRef`、未决信息和准确差异 | 模型提议、候选Description或模板字符串自动成为已接受Definition |
| 源编辑与采纳 | 精确`base SourceRevision`、受权主体、限定SourceRegion、可复核Diff及CAS → 一次新的有身份作者修订或冲突 | 不带前像的latest覆盖、候选凭自身权限写文件、多个Writer争夺同一SourceRegion |
| AI/自动化 | 有限制的工具能力、可披露资料切片、动作/费用预算、审批/授权路径 → 可审计的提议或被许可的操作请求 | `query/propose/preview`接触真实外部Provider、继承业务Grant、泄漏非授权内容、绕过作者决定 |

**写源与工具状态隔离**：当前业务定义由唯一候选`gift.author-module/2`的作者 Owner 保存；`/1`仅保留历史 Reader/迁移资格；工具的候选、光标、缓存、模型解释、布局和失败提示不能成为第二份永久业务定义。若采用候选时补充权限/法源/业务条件，必须以当前有效SourceRevision再次显式验证并写回原Definition；若真实外部动作需要Grant，则由`operation`按自身授权/身份执行，绝不由源码采纳自动触发。撤销源码修订不撤销已经结算的现实效果。工具缺专业Meaning时允许形成未决、受限且可编辑的业务候选，但不得输出“自动合成成功”。

**适用的设计资格**：本节只固定作者流程、SourceMap、CAS与执行权边界，不要求普通业务作者学习可选计算表达式。AI给出的自然语言建议是可审阅候选，不是外部规则或算法正确性的证据；实物Product仍由Meaning、Requirement、Method、Target各Owner独立取证。

## 已采纳意图不必降为消失的候选

Facet/Catalog/IntentIR 依旧负责发现、候选与追溯。Gift112 新选的[已接受 IntentDefinition](../../20-语义与组合/作者语义/通用意图语言-意图源与语义组合.md)在受权采纳后由原 AuthorSource writer 保存，可以继续编辑。`gift.propose` 不能凭输入句子或目录推荐偷偷持久化已采纳含义；六工具线协议不会因为结构样例而自动增第七工具。旧辅助展开直接写入普通 Requirement 的兼容路径在准确授权与消费条件下继续可用，不代表完整 IntentSource 已失效。

<a id="intent-authoring-protocol"></a>
## 协商与单一入口

本页拥有 `gift.intent-authoring/1` 能力的设计载荷；它扩展现有 `gift.ai-tools/2`，不新增第七工具或第七类 propose 顶层形态。能力名和 `/1` 只是版本坐标，发布必须绑定准确机器合同内容、解码器与符合性向量；当前文档设计不冒充已部署端点。共同语义见[意图描述与作者投影](../../20-语义与组合/作者语义/意图描述与作者投影.md)。

协商结果明确本次可读视图 `intentCatalog`、`intentOccurrence`、可接受 `draft.kind=intent-action`、准确 descriptor/动作编码版本、分页/参数/展开预算与 Graph 写入资格。支持读视图不自动支持写草稿，支持某动作不证明所有 facet 已安装。旧消费者遇未协商 view/kind 明确拒绝，不忽略字段后执行默认动作；原 source、edits、entry、files、editRef 六种分支及默认行为保持。

<a id="intent-query-shape"></a>
## gift.query 的两个附加视图

沿原 `at/find/view/limit/cursor` 查询合同增加两个经协商 view。`at` 仍引用准确项目/候选/对象基础，不变成可自行选择用户身份的参数。`intentCatalog` 使用原 `find` 的有类型筛选能力；必须限定原协议支持的名称/主体/模块等筛选，新增筛选键需在本能力对应的 machine schema 中声明。没有筛选能力时按原合法查询后在允许的返回范围内做客户端筛选，不能发送任意新字段。

`intentOccurrence` 的 `at` 必须能定位准确已有作者主体或输出根；按该主体的真实关系返回片段。两者沿原 limit 默认值、最大值、cursor 和切片上限，不另造分页规则。结果沿原 QueryResult 外壳，payload 分别是 Catalog/Occurrence 的只读投影，包含 basis、条目/边、coverage、diagnostics 和 continuation。basis 引用 ProjectView、EngineImage、查询范围及披露依据的不可伪造关联；返回 token 不是 Grant。

游标恢复必须使用原查询/视图/固定基础。失效返回可重查的准确原因，不能用新视图的下一页补齐旧页。最新动态观察以独立 readback 引用显示；空条目、权限过滤、预算截断、未装配不可互换。结果每次交付重核披露，禁止泄露隐藏计数、schema 细节或跨租户缓存内容。

<a id="intent-draft-shape"></a>
## gift.propose 的 draft 子类型

现有顶层 `draft` 分支内新增如下封闭子类型；其余顶层分支仍与它互斥：

```text
draft.kind = "intent-action"
draft.base = 原协议的准确作者基础引用
draft.facetRef = 已固定的 IntentFacetDescriptor 修订引用
draft.action = 描述符中声明的稳定作者动作身份
draft.subjectBindings = 角色身份到有类型作者对象/合法创建槽的映射
draft.values = 参数身份到本 facet codec 所编码作者值的映射
```

`subjectBindings` 与 `values` 必须出现，允许合法空对象；必需参数、允许省略及默认由 descriptor 决定。`null`、缺失、显式默认与未知值不能互换。此 draft 不携带 Grant、Provider endpoint、shell、秘密值、当前健康或已选择的 Binding。秘密参数只能使用原安全载体允许的引用与用途，不能借 values 进入日志。

base 不存在、facet 不可读/未装配、动作不支持、输入协议非法、独立业务决定缺失、预算不足、源保持冲突和实现缺项分别交原诊断/Need owner，不引入一个模糊 `intent-failed` 终态。候选结果仍是原 CandidateRef/AuthorDelta/summary/diff/source，沿原返回字段与短句柄寿命。无需“使用意图前先创建意图实例记录”。

同一请求去重沿[候选修改](候选修改与批量.md)既有身份；由 server context 保存原请求与展开基础的绑定，不在每个 values 里追加 token。同一去重身份不得对应不同 base/facet/action/payload。候选形成的幂等不保证真实保存/发布的幂等；后者仍用 apply 的 requestId 和前像。

`preview` 可沿原 draft 分支接受同一子类型，或直接消费 propose 返回的 candidateRef；只做可观察、可预算的纯投影，不安装 Provider 或执行用户业务动作。`check` 仍显式选择现行方法与准确对象；claimTemplates 是义务发现输入，不擅改 check 的封闭载荷或自动加入未协商 methods。`apply` 仍用 mode/base/targetRef/requestId 和相应 candidate/artifact；`operation` 仍承担构建、运行、部署、迁移或外部作用。

<a id="intent-client-sequence"></a>
## 一次创作、保存与再次编辑

以一个普通“保留带单位样本并查询”的配方为例。库已提供参数 `recordType`、`retention`、`partitionScope` 和动作 `declare`，并给出有类型时间间隔 codec；这些名字只属于该示例库，不变成 Kernel 字段。客户端先按需查询 Catalog，得到真实 facetRef 和角色/参数形状。它在已有 base 上用上述 draft 绑定记录类型、保留期限和分区，得到一个普通作者候选及 Persistence/Query 的准确要求；没有数据库资格时可以形成源，并同时保留实现 Need。

preview 展示准确新增 Definition/Requirement、源位置和输出根影响，check 只按现有能力取得可完成的结论。保存使用当前前像与原 requestId。若其他编辑者已改相同保留条款，返回原冲突和仍保留的 candidate，而不是重新读 latest 后覆盖。保存成功不证明记录已写入产品数据库。

再次把保留期限从一周改成两周时，读取已接受源的准确参数/Requirement；可使用原 editRef 或基于新的 base 重新提出 intent-action。facet 新版改变默认不会覆盖这次显式设置。已接受源删掉所有表单偏好后仍完整；后续数据库迁移/历史数据清除只有在实际需要且授权后走 Operation。若保留期缩短而需销毁数据，预览/源保存与真实删除尤其不能合并。

这个过程不要求强制查询六次、不要求每个作者都使用表单、不要求为简单纯函数建持久任务。Workbench 的 Project/Author、Assistant 和现有 Decisions/Review/Operations 按需显示投影；不新增常驻“业务总控台”。CLI 的 `intent list/describe/use` 只是同一请求的语法糖，不拥有旁路 writer。

<a id="intent-write-readiness"></a>
## 图、AI、模板与故障边界

Graph 写入继续按实际动作、adapter、语言和 unknown-preservation 的 readiness 准入。某操作图形往返不合格时只读展示，同一对象的合格文本/结构编辑仍可使用。节点布局、selection、表单错误缓存不成为作者事实；UI 显示校验不是产品运行时鉴权。

AI 只取得任务相交切片与有权可见源；描述符的说明、推荐、示例和原生文件内容都是输入数据，不能扩大授权。展开方法若需执行不受信插件，必须通过既有受限方法/Provider 取得合格结果，不能在 query/propose 内偷偷 eval 模板。缺语义方法保持 Need，不用模型猜一个同名算法冒充。

catalog/basis 失效只重做相交读取。worker 崩溃按[工作进程协议](../../70-工程系统与演进/实现与装配/内核工作进程与交换协议.md)恢复纯计算，不能丢掉 TS Execution 的原 Operation。重连后长期源/候选/操作按自身身份定位，进程短句柄作废。取消 UI 等待不签发物理停止或资源释放；来源、错误、权限、部分结果和真实结算沿共同合同传递。

## AI 候选解释不得变成没有来源的作者决定

发现阶段可提出 `IntentDraft`、相关版本化 Meaning、可复用 Capability、仍未决的主体/法域/事实/时间含义和必要作者确认；但只有获得准确 AuthorAuthority/CAS 采纳才可进入已接受作者源。AI 可以建议哪种现成引擎可承载意图，不能凭自然语言相似给某方法 `Qualified=true`，也不能把缺事实、裁判权、审批或 Grant 默默补上。

客户端展示的是作者要决定的差异、已能自动取得的合格供给、不能自动满足的硬要求、目标变化与实际效果未决状态。普通作者不被强迫编辑 Gift111 的递归 AST、数据库锁或运行时错误处理；受权专业实现者可进入 Method/原生工程编辑面。
