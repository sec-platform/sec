# 编辑审查协作与大型视图

## 未保存缓冲、辅助编辑与接受变化

现有编辑器接入时，先把实际可见缓冲及其语言角色、版本、编码和根配置交给原文本工作集捕获。客户端本地撤销/选区不是作者语义；多个编辑器实例打开同一路径也不是同一文档实例。IME组合输入可作为本地未完成状态，不为每个中间键触发昂贵全工程检查；提交组后才发对应版本的工作项。增量同步丢段或基础不符时重取全量该文档，不猜着接增量。

本地输入立即保留；补全/格式化/快速修复产生候选或[准确编辑计划](../工具协议/作者辅助接口.md#authoring-assist-contract)，不是另一个可编辑业务模型。接纳建议时核实际基础与影响组；未相交的后续编辑可以按真实对应重基，不能只比较字符串仍相同。无合格重基则展示旧计划与新源差异，可继续手工编辑，不悄悄改latest。

补全包含主插入和必要import时一并形成后继候选；只收主插入可以成为普通错误草稿，不能标作完整可用补全。插入/替换模式、snippet占位和提交字符由客户端明确选择并在得到准确最终字节后捕获；不把snippet中的`${...}`交给语言解释器当新语法。未填占位的草稿继续合法保存。建议附带的外部command、包安装和生成器执行不在只读辅助中执行，另走实际准入。

客户端把候选应用到缓冲的动作，与写磁盘、更新索引及写输出分别处理。宿主只支持顺序应用且可能中途失败，就呈现实际已改范围；可尝试恢复但不宣称事务。必要的完整变化可先在私有候选中构造，只有宿主能兑现相应边界才进行强应用；否则保留候选/导出差异，不占用不可得能力。应用后的缓冲版本由宿主返回并重新捕获，不能提前给即将生成的版本编号。

直接写文件、AI成组编辑、CLI请求和可选编辑器接受，在相同基础、解释与变化下应得到相同语义候选。允许表示/注释保全结果有各方法声明的差别，但不能因为客户端不同改变要求或绕过检查。生成目标上的修改仍沿generated-edit；没有唯一逆映射时保留草稿和选择，不反向改全部模板实例。

## 审查、局部采纳、版本控制与多方协作

### Local History 与草稿恢复不是VCS

开发客户端可以提供类似IDE Local History的**本地恢复层**，但它不成为新的作者authority、Git替代品或长期发行历史。它只保存已实际观察/捕获过的workspace/buffer内容及其局部上下文，供崩溃、误删、远离最近commit的编辑和未提交实验恢复。

```text
WorkspaceHistoryRecord = exact {
  workspaceAndClientScope,
  capturedSubjectRefs,
  capturedWorkspaceOrBufferRevision,
  contentRefsAndDeletionState,
  captureReasonAndObservedAt,
  optionalLabel,
  retentionAndSensitivity,
  parentOrRelatedHistoryRefs
}
```

这里的revision只是被捕获对象的真实revision引用，不新增一个“历史revision”解释程序。History record不能被compiler/query当latest，也不自动进入共享索引、发布、review或Evidence。手工label只是给某个已捕获状态增加可导航标记，不改变内容身份、保留策略、权限或验证资格。

恢复整文件、目录或片段时，先取**历史状态H、当前工作区C、必要共同基础B**，形成普通新候选C′。当前内容自H以后已有变化时，不以“恢复”名义覆盖；能三方保全就形成合并候选，不能唯一保全则显示冲突。被删除文件的历史字节也只是恢复输入，选择恢复后才重新进入当前workspace candidate。

Local History允许保留语法错误、未保存中间态和外部编辑的已观察版本；这正是其恢复价值，但也意味着它们没有编译/测试/发布资格。历史记录可能因容量/TTL/明确清理而消失，未实际捕获的键盘状态不能承诺可恢复。若产品承诺某范围的崩溃恢复，就把相交history content登记为recovery asset并在承诺窗口内受保留根保护；其余仍可按本地缓存策略淘汰。

历史内容可能保存用户后来删除的secret、PII或受限源码，因此继承原读取限制、加密/本地目录保护和retention；“文件已删掉”不自动授权长期保留。跨租户/跨项目不能凭内容hash共用私有history。导出patch是新的披露动作，按当前权限处理。

### 实时副本收敛不是语义合并

多人实时编辑可以采用CRDT、OT或其他合格同步实现，但它们只拥有**协作buffer/结构副本的收敛与传输**，不能取得作者语义、候选采纳、权限或验证authority。客户端先把同步后的实际buffer revision捕获为workspace候选，再由既有解析、类型、关系、semantic-change、review与check处理。

```text
local editing events
→ collaboration replica state
→ captured buffer/workspace revision
→ semantic candidate
→ semantic conflict / verification
→ authorized adoption
```

文本/结构副本已收敛仍可能出现：类型错误、两处修改共同破坏不变量、同名实体身份冲突、删除与引用竞争、旧权限写入、一个确定性winner掩盖另一合法意图。CRDT内部operation id、actor id、heads或vector clock只在该协作Provider命名域中定位变化/因果，不自动成为Gift的Subject/Revision/Grant。需要跨会话稳定追踪时，通过映射绑定真实workspace/candidate revision，而不是复制provider内部ID做全平台身份。

### Presence、光标、选区和编辑意图

在线状态、光标、选区、正在输入、用户头像和临时锁提示属于短寿命 `PresenceObservation`/客户端view；默认不进入作者源、Git历史、工程revision或审计真相。断线/超时只使presence陈旧，不能据此判定用户已离开项目、放弃候选或释放业务写权。需要真正排他写入时仍取得现有Lease/Fencing/authoritative ownership，不能把“正在编辑”提示当锁。

undo/redo也分层：本地编辑器撤销可以生成新的buffer状态；CRDT撤销只在其操作域内产生新的协作变化；Git revert是版本历史操作；外部Effect补偿又是独立operation。四者都不能用一个“撤销”按钮的视觉概念互相替代。

### 冲突可以长期存在，但不能静默获胜

传输/VCS/CRDT能够保存一个未决冲突是合法状态。冲突需要携带真实基础、参与候选、相交读写集、已知关系与可继续动作；不强迫为了“仓库干净”立即选择任一侧。反过来，Provider因为实现需要选择一个可读winner，也不能让隐藏的loser从工程冲突中消失；只有对应语义问题已由有权规则裁决、验证并形成新候选时才算解决。

审查默认显示真实作者差异，另按需显示契约/要求变化、推导/生成变化、资产成员和实际作用计划。三个层次关联同一候选，不把生成差异反写成第二作者源。审查者可局部采纳实际独立修改；涉及定义与消费者、资源与引用、主插入与import的依赖组，拆开后重新形成候选并检查。可以保存未完草稿，不能沿用拆分前的检查通过。

工作树、未保存缓冲、Git索引、分支提交和合并候选分别捕获。运行测试的主体必须是声称接受的那一份：工作树C2通过不证明只暂存一半的S2通过；构建完成后hook或生成器改了文件，原结果仍绑定原输入，不能贴给新提交。查看stage/unstage属于读取/索引编辑，reset、clean、强制切分支和丢草稿是独立授权的破坏性操作，不能作为自动“修好冲突”的默认动作。

并行人/AI从各自base形成完整批次，短协调只发布引用；跨文件不同不证明语义独立，接口、公共配置、要求、锁和生成资源可能相交。真正不相交可合并并保留各方变化；相交而同值仍重新核读集；无法确定则返回冲突范围和可保留方案，不全仓最后写者获胜。形成合并候选后重新解析/类型/相交案例，不复用分支通过来证明组合通过。

独立worktree可以隔离某些文件与index，但配置、引用和外部缓存/工具状态不必隔离；不由目录不同推导完全独立。跨进程/远端协作仍用已有前像、围栏和操作恢复，离线缓存不签发新写权。Git/其他版本控制不是唯一要求，等价的准确内容与历史选择也可接入；不把本设计规范版本包当成已部署的协作服务。

### 文本优先的可用性与无障碍

帮助、诊断和差异必须能用纯文本完整理解；路径/范围可复制，关键状态不能只用颜色或图标表达。未来薄编辑器适配应支持键盘、焦点返回、可读标签、缩放/换行和屏幕阅读器，不要求先造自有控件库。选择显示文字与真实源码字节分别编码；中文消息不得改协议枚举，双向控制字和终端转义不静默执行。大文件采用分页和局部任务，不阻止立即输入；精确全工程引用查询仍报告真实覆盖而非以“快”代替完整。

性能准入以同任务冷/暖过程、首次有效反馈、最终结果、需要的输入量、失败/恢复成本及实用完成率衡量，未实测不设毫秒承诺。可用普通文本/脚本完成同一任务时，薄GUI不是支持条件。

### 国际化、Unicode、双向文本与机器协议分离

客户端本地化只改变**呈现文本**，不能改变机器协议、源码字节、路径身份、排序语义、错误码或领域值。Diagnostic至少保留稳定reason/code、结构化参数、source/span和producer revision；本地化message由这些值派生。日志/CLI JSON继续使用固定机器枚举，人类text模式才按locale渲染。

```text
LocalizedPresentation = derived {
  sourceStructuredValueRef,
  localeAndMessageCatalogRevision,
  formattedText,
  directionAndIsolationMetadata,
  accessibilityAnnotations
}
```

日期、时间、数字、小数分隔、单位和排序也分领域值与显示格式。`1,234`在某locale可能表示不同数值，不能把本地化字符串重新解析为程序参数；机器输入采用原有类型化编码。文件/符号搜索可以提供locale-aware或normalization-aware辅助匹配，但结果必须指向真实精确字节/标量序列，不把“看起来一样”合并成同一身份。

中立语言当前identifier仍服从其明确ASCII规则；其他原生语言若允许Unicode identifier，适配器绑定该语言实际Unicode/profile/normalization规则，不由客户端擅自NFC/NFKC。路径、JSON identity和外部协议也只按自己的合同比较；显示层不得为了“统一”改写底层字节。

对源码、diff、diagnostic、文件名和依赖名中的双向控制、不可见字符、confusable字符，客户端至少能安全隔离渲染方向并在可能误导编辑/审查时提供可见提示或诊断。提示不自动把合法非拉丁文本视为恶意；安全策略按实际语言允许集、脚本混用、不可见字符和受保护命名域判断。复制/粘贴和patch仍使用原字节，视觉顺序不作为range/offset。

IME composition、组合字素和emoji只影响交互分组/光标显示，不改变已有byte/UTF-16/scalar坐标合同。屏幕阅读器读取应给出逻辑文本和必要的不可见字符说明，不能只朗读视觉重排后的字符串。

<a id="scoped-review-and-policy-evidence"></a>
## 审查范围来自语义变化，批准不替代保持依据

实现、公开合同、授权关系、释放/迁移协议和证据接纳规则的变化可以要求不同审查能力。审查选择消费原 Delta 与 review 用途的影响闭包，返回实际责任及其来源；目录 owner 可作为组织映射，但不因文件搬移就自动改变语义责任，也不建立与原工程事实竞争的手填权限库。

候选作者独立性、审查主体可核验身份、所审输入、政策修订、未决意见和有效期各自检查。一个不同账号或模型名称不证明推理独立；一次没有发现问题不证明所有保持命题成立。具体项目可采用单人开发或多人生产等政策，但缺少实际审查人时不能伪造批准，缺少强保证也不能阻断无关设计和候选保存。

机检规则的计算机制与当前架构政策可分别演进；历史诊断名称、包数或文件行数不能代替实际执行分支和强制点的核查。变更必须有正常成功路径与拒绝反例，不能靠无差别拒绝或删除未知得到“全通过”。

## 编辑坐标与批量失败的实际语义

位置绑定文档身份、版本、编码单位、换行和映射。文本a😀bX中的b分别位于UTF-8字节列5、UTF-16码元列3、Unicode标量列2；把协议列3直接作为标量下标会命中X。宿主换成UTF-8字符串不改变已协商协议；视觉列、字节偏移和语义节点也不互换。换算正确仍须核原前像和新版本对应。

批量WorkspaceEdit不是统一事务承诺。abort停止后续而保留此前修改；transactional要求全部或不应用；textOnlyTransactional仅对纯文本批次提供事务；undo是实际支持的尽力撤销。applied=false可能伴随第一份文档已变化，不能接纳为NoWrite或盲重放整批。

适配器记录客户端声明与实际可验证的失败行为、每项前像/结果和剩余责任；文件创建、删除、重命名与文本修改的顺序按实际依赖保持。能力不足时使用更小合法批次、候选保存或准确部分结果，不用一次API响应制造跨资源原子性，也不扩大写入范围以方便恢复。

## 大型工程视图的覆盖、布局与扫描代际

事实捕获、语义分类、布局、渲染和交互编辑各自有消费者。按像素聚合可以限制可见几何与命中测试，不证明底层扫描、语义关系或完整影响分析也仅需屏幕规模的工作。不可见、不展开、权限拒绝和未扫描分别展示；未知大小不能作为0参与完整总量。

节点路径可以按祖先延迟拼接以减少重复存储，但位置不代替稳定语义身份。流式扫描的增量属于固定扫描代和成员解释；索引路径只有在该代的树和排序中才有效。扫描切换后旧增量不得覆盖新树；若调用者已用独立队列/私有实例隔离代际，可以由它承担而不在每个局部节点复制epoch。只看到局部apply没有代际字段，不能据此认定完整调用链有漏洞。

图上的聚合不签发缺失、可删除或权限结论。半开几何区间等布局规则只解决其命中边界；图编辑要回到准确源版本和编辑合同。注释称无UI依赖不替代实际进口和状态检查，渲染性能声明也须用相应负载与测量验证。

树的节点出现、局部加载、过滤祖先、批量选择、键盘与重连按[树形导航与结构投影](树形导航与结构投影.md)接合。本节继续拥有扫描、布局与渲染的覆盖边界，不把新的树形呈现状态当成工程对象状态。
