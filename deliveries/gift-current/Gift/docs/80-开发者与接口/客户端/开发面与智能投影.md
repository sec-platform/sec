# 开发面与智能投影


### 真实业务界面在产品中如何发生

业务UI按钮的`actionRef`必须指向业务领域动作Meaning，不能指向`effect:port`。组件的`activationRoutes`从具体UI节点、订阅流、服务端点、状态事件或定时源，连接到具体`workflowUseId`，再由流程内部的明确操作使用映射到Method/Effect。层级完整路径为 `UI操作→业务动作→实例局部触发→工作流输入→操作使用→有资格实现→结果/状态/UI反馈`。同一个源是否允许扇出到多Workflow需要可观察的业务仲裁和顺序/隔离；同源同目标的重复关系不构成两个独立合法动作。


### UI读写方向

`UiNode.dataBinding`是有类型只读或可编辑绑定，读取来源必须适用于渲染时点；可编辑输入必须另外关联业务`actionRef`以及组件局部激活路径，而不是对任意绑定结果原地赋值。可访问性、焦点管理、验证反馈、异步等待、错误和撤销是UI专业语义；由目标Renderer和合格方法承担，不被“界面节点在树里”所替代。UI输入校验与服务端安全性是两个边界，不能互相代签。


### 人类、AI和团队协作的地位

AI可提出新的Meaning候选、解释、代码/Method候选、重构与优化，但其自然语言输出不具有作者写入权限、外部访问权、法域权威和现实证据。所有修改必须经明确SourceScope和合格的原生/作者源编辑入口；AI不能把自己的中间会话写成第二份必须维护的产品规范。团队合并处理公开接口、作用域及Rev冲突；权限与质量判断不能被“某个Agent已经完成”替代。

工作台提供格式化JSON、可折叠模块导航、引用跳转、语义差异显示、组件/流程图的派生视图、可控Method方案选择、定位到原语义的报错和生成目标源码导航。视图不自动取得新AuthorOwner，外部Git仓库与本地SourceScope的写权必须明确；云端/本地执行、编译资源、可观察个人数据均由用户真实权限决定。


### 工作台应该实际降低的负担

工作台优先显示产品树、模块/定义/实例、已接受Goal、公开接口、精确参数、问题所在的源位置及Target生成关系；内部Hash、派生UseId和供应搜索状态可以按需展开，不作为初始必填信息。长JSON用多模块、引用补全、语义跳转、局部Patch与格式化解决；不把Markdown图、自然语言对话、自动生成的UI状态长期保存为另一份源。

同一模型在多个视图中编辑，必须持有作者修订/SourceScope，精确重放到合法拥有者；对数组顺序的变动使用稳定逻辑键而非过期数字下标。多个AI或人类协作者并行提出方案时，它们都只是候选；冲突合并和采纳属于SourceOwner，不靠最后写入者覆盖他人。

<a id="developer-surface-contract"></a>

## 完整开发面：工作对象、动作和结果，不是一套新界面

开发面涵盖人、AI、脚本及既有编辑器对同一工程的**观察、创作、修改、验证、操作与交付**，不限定为 GUI 或六个工具名。当前经原生文件/补丁、SDK/CLI 与现有工具接口承载；终端、网页和编辑器面板各自选择合适投影，不构成产品必须先开发新 GUI 的前置条件。

用户入口以**期望变化、作用对象或工程范围、不可推导的业务取舍**作为最小输入。版本、CST/IR、依赖、EditRef、Artifact 身份及运行台账由系统在取得资格后派生。对象已确定的请求直接进入对应操作，不强迫用户先展开能力目录、创建会话或重复申请读取资格。

<a id="six-client-surfaces"></a>
### 所有客户端共享六类开发任务，不共享同一布局

CLI、AI和Workbench都按`Understand / Author / Change / Verify / Operate / Deliver`六类任务解释用户意图；它们不要求相同菜单或调用序列，但同一对象、candidate、Operation和Evidence必须保持同义。

- **Understand**：query/search/navigate/inspect/explain/impact/provenance，零写入；
- **Author**：创建新的Meaning、Requirement、Profile、领域Definition或独特原生作者内容；
- **Change**：编辑/重构现有作者源，修改Control、target、dependency、native config和迁移选择；
- **Verify**：审查candidate、diagnostic/test/coverage/formal/measurement/Evidence；
- **Operate**：generate/build/run/debug/profile/interactive execution及运行输入；
- **Deliver**：save/apply、VCS integration、CI/package/release/publish/deploy/migrate/handoff。

`Needs` 是贯穿任务的未决结果，`Assistant` 属于通道，Graph/Text/Table 属于显示投影，Recovery 属于生命周期；它们均不构成独立第七任务。一次“改接口→核相交测试→提交”可跨多个面，但每一步仍按原 Candidate、Operation、Evidence 的独立拥有者和完成资格结算。

<a id="developer-effective-view"></a>
### 同一作者源的默认视图与完整下钻

最终开发UX首先显示作者正在改变的工程含义、公开边界和真实缺项，而不是把完整语言规格、全部控制描述符或每个目标配置键铺满屏幕。这里的“最终”指所有客户端应共享的**信息投影合同**，不是要求现在先实现专用GUI：AI、CLI、SDK、现有编辑器和未来Workbench均从同一作者修订、Binding、资产、诊断和Evidence取得事实。

普通视图按任务可以组织为：含义/接口与关系、Requirements、行为与状态、实现选择、目标与配置、生成对应、Evidence/历史；没有相交内容的组不显示。高级或“显示有效配置”视图必须能够展开[有效控制投影](../../20-语义与组合/组合/稀疏控制与目标限定.md#effective-control-projection)：Requested、Effective、Planned、Applied、Observed及每项来源、作用域和真实owner。分组名称是客户端阅读结构，不是新的持久Schema；同一事实不能因为同时出现在“Implementation”和“Generated”面板就获得两个写入口。

客户端修改先定位真实写入 owner：Requirement/Control、结构 Definition、原生源、原生配置或运行 Provider；纯观察只读。能唯一定位且满足权限、基础和 Profile 才构造 EditPlan/semantic-change；多 owner、未知资产或过期修订要求选择、冲突或只读处理。Auto 只委派已允许的剩余自由，不让客户端创造无来源默认；隐藏或展示底层字段均不转移作者写权。

AI自然语言同样只是创建或修改候选的交互入口。界面中的普通 `Candidate` 是有前像的工作区作者修改；[工程 `DesignCandidate`](../../30-实现解析/实现选择/设计空间搜索与求解.md#设计候选结构判定冻结与采纳) 是带提案修订和设计读取基础的方案，两者不是同一种保存对象。AI或GUI只显示和定位该方案；旧基础失效时提供差异、重评或舍弃入口，不能靠当前卡片仍显示“选中”就绕过采纳CAS。接受后的稳定事实必须写回上述真实owner；固定重建不再次调用AI猜数值位宽、数据库、库版本、目标配置或业务行为。无法从已接受语义/供给确定的内容保留Needs，而不是让模型或宿主习惯补齐。

<a id="developer-decision-view"></a>
### DeveloperDecisionView：所有客户端共享的设定投影

CLI、AI和Workbench需要看到同一组“用户能设什么”，但不把这些内容保存成新的统一配置。内部采用一个**派生view-model合同**；字段只引用现有owner和refs，可以按需分页/裁剪：

```text
DeveloperDecisionView = derived {
  subjectRef,
  decisionRef, decisionClass, semanticRevision, facetRefs?,
  authority { kind, ownerRef, revision? },
  sourceRepresentation { kind, ref?, revision? },
  settingScope? { graph: author | runtime | client, ref },
  targetRef?,
  externalApplicabilityRefs?,
  valueContract { shape, domain?, unit?, canonicalForm?, bounds? },
  declaredOrRequested?,
  effective?,
  contributors? [{
    producerRef, revision?,
    authority { kind, ownerRef }, decisionClass?, sourceRepresentation?,
    settingScopeRef?, propagatedFromRef?, targetRef?, mode?,
    derivationRef?, expansionRef?, applicabilityRef?
  }],
  allowedActions[],
  candidates? { qualified[], excluded[{ref, reason}] },
  planned? { bindingRef?, realizationSummary },
  applied? { sourceOrConfigRefs?, artifactRefs?, runtimeRefs? },
  observed? { observationRefs, freshness?, coverage? },
  assurance? { claimRefs, evidenceRefs, verdictRefs? },
  impactRef?,
  state: current | unknown | unsupported | conflict | stale | forbidden
}
```

`decisionRef`标识“哪一个已定义决策维度”，不是为每个局部变量生成全局Property ID；`decisionClass`只取A轴五类，`authority.kind`只取B轴六类，`settingScope.graph`只取D轴三张可继承设置图。Meaning可以引用Definition/Rule角色，Control引用descriptor；原生字段通过`sourceRepresentation`与authoritative native owner表达，不再造`Native-owned` decision class。

`facetRefs`是可选的检索/Explain投影，来自实际 SemanticModule、领域 Definition、机制 owner 或组织分类；没有 facet 的 Decision 仍必须被完整发现。客户端不得要求 Decision 先命中中央 family registry，也不得把 facet 当 writer、scope、merge、default、Binding 或兼容身份。真正决定“这是什么”的是 `decisionRef + semantic owner + value contract`；客户端分组可以变化而不改变工程语义。

`authority.ownerRef`才是写回/签发定位依据，客户端不能通过`decisionRef`或source path自己猜写文件。External authority或Evidence coverage等非D轴范围放`externalApplicabilityRefs/assurance`，不塞进`settingScope`。

`declaredOrRequested/effective/planned/applied/observed`只在该决定真正有相应C轴阶段时存在；Verification verdict放`assurance`而不是伪装成Observed值。Presentation preference通常没有planned/assurance，纯派生Binding通常没有可写declared。缺字段是阶段不适用，不是null语义。

`contributors`按[DecisionContribution正交合同](../../20-语义与组合/组合/稀疏控制与目标限定.md#decision-contribution-algebra)解释Declared/Effective为什么成立。Profile通过`expansionRef`保留bundle provenance，继承通过`propagatedFromRef`保留scope传播，严格推导使用`derivationRef`，External/Runtime/Client使用真实authority，native只描述`sourceRepresentation`；它们不再竞争一条扁平`role`枚举。顺序不表示优先级，冲突保留全部生产者和descriptor自己的冲突规则。选中实现放`planned.bindingRef`，不把Binding伪装成输入贡献。

客户端若只显示一个简短来源标签，也必须能展开全部contributors。值相同的多个hard来源不能因为UI去重就丢失独立失效/撤销关系；某来源失效后重新计算Effective，而不是删除整行Decision。

### 值编辑器由合同和动作共同生成，不只看“类型”

客户端选择控件时同时读取 value contract、semantic owner、allowed actions、scope、单位和相交 facet；只看JSON primitive会产生错误UX。

| 值合同/语义 | 默认编辑器 | 必须保持的细节 |
|---|---|---|
| Bool | tri-state/choice：Inherited(Auto) / Require true / Require false；若只是Meaning Bool则普通二值 | `false`与“未设置”分开；不把checkbox unchecked当reset |
| Enum / finite nominal | searchable select；Require与Prefer分开 | 显示稳定label但提交精确nominal/ref；未知值保全 |
| Exact integer / decimal / quantity | 文本数值输入 + unit + bounds提示 | 不经JS float round-trip；range/scale/rounding/overflow分别展示 |
| Duration/size/rate/percent等quantity | 数值+单位picker，内部canonical unit | unit转换必须精确/按定义舍入；显示单位不改Meaning |
| ProviderRef/AlgorithmRef/SymbolRef | qualified picker +候选资格/版本/来源 | 选择后固定精确ref；显示名相同不合并 |
| Allowed/forbidden set | multi-select/constraint builder | 空集、未设置、全部允许是三种不同情况 |
| Structured finite value | schema-driven form/table | 字段必需性、交叉约束、unknown字段和版本保留 |
| Text/regex/path/URI | 专用文本编辑器，仅在该descriptor明确语义时启用额外校验 | 不把任意Text当regex/path/shell；编码和case规则来自合同 |
| SecretRef | provider/key引用picker，只显示redacted metadata | 不读取/复制secret真实值进入Webview或作者源 |
| Native representation value | Go to authoritative native owner；有合格adapter时可提供字段级editor | adapter不能完整写回时只读，不造同义Gift字段，也不创造`Native-owned` decision class |
| Derived/Selected/Observed | read-only + Why/Change owner | 不能直接把派生值“保存”为显式值，除非用户执行Pin/Require形成新候选 |

编辑一个Decision从不直接改变当前行；先生成作者/Control/native/runtime候选，再重新计算Effective/Plan/Impact。表单校验通过只证明输入形状合法，不证明Requirements可满足或Provider可施加。

### Profile选择器与“高级设置”不是两套产品

Profile picker显示准确Definition/Requirement bundle、revision、来源、它会新增的Meaning/Requirement及当前显式差异；实现Control永远单列，不因Profile被选中而暗中Pin。用户可以`Use profile`、`Inspect expansion`、`Replace profile`、`Remove local use`；不能在看不到展开内容的情况下把Profile当神秘模板。

Advanced/Physical面板只是对同一 DeveloperDecisionView 扩大 owner/facet/physical filter。一个用户从Profile开始后可以只Pin某个storage provider、只固定一个字段的overflow或只在一个FFI occurrence指定ABI；系统不会因此把Profile展开复制成几百个本地记录。

### 作者真正维护的四类内容

| 对象 | 正常开发方式 | 系统提供而非作者重复维护的内容 |
|---|---|---|
| 新的中立行为或抽象 | 结构化意图、已有Definition/领域结构/库的引用、必要参数和独特行为；明确选择计算画像时才使用相应计算源；支持未写完草稿 | 从真实定义推导类型/效果、局部身份、依赖与生成对应；不展开回写成另一份作者程序 |
| 已有原生源 | 继续在TS等实际原文中编辑，保留注释、BOM、行尾、路径与原工具 | 可取得范围的符号、类型、调用与原生工具诊断；不强制生成.gift镜像 |
| 工程控制与非代码资产 | 原项目配置、依赖声明/锁、入口、资源、测试和独立说明；没有该信息则不建空文件 | 仅建立缺少且有消费者的稀疏控制；同一规则不在package、工程表和意图JSON中三写 |
| 生成/运行观察 | 默认看目标源、差异、栈和值；要改则定位真实作者，或保全受管目标编辑草稿 | 固定生成与运行来源；一对多和不可逆明确呈现。运行值、生成helper和推导签名不伪装成任意可写作者槽 |

`.gift`不是所有控制的同义配置语言。导入/模块、一般函数/类型、对象/状态/关系/流/数值的实际语法由各语言和领域拥有者定义；表格只规定它们如何进入共同开发过程。成熟供给够用时直接绑定；确有独特含义才定义新函数、类型或库；没有可验证供给不能仅写一个功能名冒充完整实现。

<a id="developer-action-family-mapping"></a>
### 动作族怎样落到六个开发任务面

当前动作目录由下表枚举；**条目数是目录派生统计，不是客户端或协议常量。** 它们是可组合的操作能力目录，不是开发面、公共API或关键词的基数。六个任务面的稳定中文/英文ID为：`Understand/理解`、`Author/表达`、`Change/改变`、`Verify/检查`、`Operate/使用`、`Deliver/交付`。

| 动作族编号 | 主归属 | 需要时的次归属/横切 |
|---:|---|---|
| 1 临时试写/空工程/已有工程打开 | Understand / Author | — |
| 2 克隆/多根/远程/恢复工作区 | Understand | Lifecycle/Recovery横切 |
| 3 定位/解释/搜索 | Understand | — |
| 4 创建一般程序/复用供给 | Author | Change（固定/替换实现时） |
| 5 补全/参数提示/查看推导 | Understand | 接受建议后Author/Change |
| 6 修改字段/组合/对象/状态/关系 | Change | Verify（保持性检查） |
| 7 移动/更名/改签名/抽取/内联 | Change | Verify |
| 8 格式化/整理导入/批量修复 | Change | Verify |
| 9 配置/环境变量/资源/秘密 | Change | Runtime输入属于Operate |
| 10 依赖添加/升级/移除/物化 | Change | Deliver（锁/发布输入正式化） |
| 11 浏览诊断/定位修复 | Verify | Change |
| 12 差异/部分选择/比较方案 | Verify | Change（采纳选择） |
| 13 源检查/案例/性质/覆盖/基准 | Verify | Operate（实际执行检查） |
| 14 生成/构建/导出 | Operate | Deliver（导出正式交付时） |
| 15 运行函数/CLI/服务 | Operate | — |
| 16 调试/性能定位 | Operate | Understand / Verify |
| 17 watch/再次构建/连续测试 | Operate | Verify |
| 18 保存/撤销/舍弃/清理 | Change | Deliver（持久保存/实际清理）与Lifecycle |
| 19 提交/分支/评审/合并/同步 | Deliver | Verify |
| 20 打包/发行/部署/迁移 | Deliver | Operate（真实部署/迁移Effect） |
| 21 AI委派/审查/交接/退出 | 不新增开发面 | Assistant/Delegation与Lifecycle横切六面 |

因此六面是**用户目的分类**，动作目录是**可调用/可组合的能力目录**。一个动作族可以跨面，一个面也包含多个动作族；二者不能互相替代。固定工具协议又是第三个维度——传输/调用入口——同样不能用工具数量推导开发面数量。动作目录和工具协议的当前成员由各自canonical合同派生，不把数量复制成客户端架构常量。

### 操作目录按任务展开，不按所有协议字段展开

下面各行都是应有的开发动作族。一个能力当前不可用时，仍能在明确请求时取得准确原因及合法替代；不显示虚假的可执行按钮，也不隐藏任务本身的缺口。没有请求相交能力就不把全目录塞进每次AI上下文。

| 动作族 | 作者最小输入 | 正常结果及真实通路 | 独立的不足/退出 |
|---|---|---|---|
| 临时试写/空工程/已有工程打开 | 一段源或真实路径；新工程必要目标 | 内存候选或获准工作区捕获；原context和projectView形成 | 未装编译后端不妨碍保全和源级检查；打开不执行项目脚本 |
| 克隆/多根/远程/恢复工作区 | 明确来源及范围，恢复时准确保存点 | 实际宿主连接/克隆后捕获；多根保持独立归属和解析域 | 下载、凭据、子模块/大文件取得是单独作用；不能读到的范围显露 |
| 定位/解释/搜索 | 名字、位置或问题；已知引用直读 | query的source/contract/origin/impact及原生语义查询 | 引用搜索与文本搜索分开；动态调用未知不叫零引用 |
| 创建一般程序/复用供给 | 完整源、局部表达式、真实调用/参数 | 直接编辑或propose形成同一候选；库查找按本次需要 | 类型未知只问最小注解；意图歧义不替用户改变要求 |
| 补全/参数提示/查看推导 | 当前内容与合法位置，已有签名/预期 | 有来源的候选项或说明；选定后变成普通编辑批次 | 不将模型生成的猜测显示为已存在符号；不执行用户函数探测类型 |
| 修改字段/组合/对象/状态/关系等 | 真实源差异或已有editRef与值 | 现有类型化作者/结构语义，统一候选 | 原本不支持的复杂语义保留原生/草稿及具体缺项，不伪造通用控件 |
| 移文件/更名/签名变更/抽取/内联 | 准确声明或范围及新要求 | 同一语义批次含引用、出口、资源与配置消费者 | 动态引用、外部公共API和资源捕获按真实保持范围处理 |
| 格式化/整理导入/批量修复 | 明确范围和合格方法 | 工具结果先成为源候选，显示副作用与完整差异 | 不以“格式化”重排有初始化效果的导入或清掉非法草稿 |
| 配置/环境变量/资源/秘密 | 改真实配置或安全输入引用 | 格式拥有者校验，输入与目标/运行绑定 | 秘密不写进日志/普通文本补全；检查存在不泄露内容 |
| 依赖添加/升级/移除/物化 | 所需能力/版本政策/明确变更 | 依赖计划、候选锁与消费者；物化另有获准实际操作 | 解析与安装分开；没有网络时只需网络的动作受阻 |
| 浏览诊断/定位修复 | 问题引用或选定范围 | 分生产者/主体/覆盖的诊断与可行修复 | 旧诊断、工具失败、未覆盖与当前错误分开 |
| 差异/部分选择/比较方案 | 候选、基础及保留哪些语义组 | 原preview或源差异、共同前提与冲突 | 半个不变量不能勾选通过；方案较优不等于已采用 |
| 源检查/案例/性质/覆盖/基准 | 明确方法与准确主体、范围 | check types/cases及已选原生测试/性能工具 | 测试发现可能执行代码；无案例/跳过/工具崩溃不叫全部通过 |
| 生成/构建/导出 | 已定候选和一个或多个输出根 | preview生成；compute-build实际构建；apply按需写出 | 各根单独结算，未选根不清理；生成不自动执行 |
| 运行函数/CLI/服务 | 真实入口及参数、环境选择 | 绑定参数并compute-run/eval；已有宿主提供活动会话 | 参数错误先定位输入；缺环境不改源；stdin/服务就绪不是退出码 |
| 调试/性能定位 | 准确运行、断点/观察用途 | 既有有限debug、profile与来源映射 | 无安全读取显示不可用；旧运行不映射为最新源；求值不偷进只读 |
| 监听/再次构建/连续测试 | 范围和自动动作策略 | 捕获最新有效输入，派发受限同类任务 | 默认不自动发布/提交/安装；旧任务完成只留原归属 |
| 保存/撤销/舍弃/清理 | 要处理的层和准确选择 | 源保存、草稿历史、生成协调、原操作查回 | 丢草稿、编辑器undo、Git revert与外部补偿不是一个撤销 |
| 提交/分支/评审/合并/同步 | 内容选择、目标ref与真正集成策略 | 原生VCS适配固定树/索引/历史/策略后操作 | 不擅自stage全部、stash、reset、force-push；远端成功与本地跟进分开 |
| 打包/发行/部署/迁移 | 发行选择及授权目标 | 已有产物、信息发布及真实Provider流程 | 不把save-source命名成publish；用户验收与技术检查分开 |
| AI委派/审查/交接/退出 | 目标、已取得源、必要范围/预算 | 同一候选分支和只读审查；精确引用交接 | 子任务结论不是根授权；关闭客户端不杀其他人使用的工作 |

### 一个统一的结果，不是一个万能success

内部`DeveloperView`是已有候选/产物/检查/操作的按需投影，不是新的持久权威。它由下列信息组成：本次请求与准确基础；已取得的source/contract/diagnostics/impact/origin/state；各受请求步骤的实际结果；仍需的最小决定或能力；当前合法下一动作。只有受请求且影响判断的未完成步骤才出现，不能在每次小编辑后刷几十项not-requested。

`NextAction`在内部含purpose、作用对象及基础、实际方法/消费者、必须输入的局部模式、效果范围、当前资格/阻塞理由和精确调用路径。客户端通常只显示自然语言动作、关键差异和缺项；完整结构按需取得。它不是可执行网页命令、授权票据或永不过期的能力。已知基础和动作可以直接构造原请求，不必先创建这个对象。

资格分成可准备、缺输入、方法不支持、当前禁止、基础过期、已有动作未决；不能把它们都翻译成“请重试”。权限类理由按当前可披露范围返回，不能通过被禁动作菜单泄露他人资源。行动前重新核实际前提。菜单上的建议或诊断的preferred标记不是必须采纳；涉及改变要求/期望或扩大作用，必须在任务现有授权内有明确选择，不因为发起者是AI而加确认，也不因为是人而免检。

### 读取、编辑和宿主动作的实际分工

source/contract/diagnostics/impact/origin/state仍是原query投影；补全和重构的语义提供者可通过现有编辑器/SDK请求位置和意图，再归一成原source/files/edits/edit-value/semantic-change。**本章没有添加`view:actions`、`propose(actionRef)`或`apply(mode:commit)`等未声明请求。** 远端只提供原六工具时，已可通过查询和真实源/批次完成同义开发；专用补全服务不可用时不假称有原生IDE能力。

克隆、依赖安装、Git集成和发行由真实宿主/原生工具或已注册Provider承担，使用下面的有限内部计划，不默认成为第七个公共工具，也不把任意shell字符串藏进compute-run。宿主尚无通路时返回所需能力和可执行原生路径设计，而非假造一个已有API。实现某远端客户端需要这些通路时，显式注册合格适配和精确协议后再公布；六个名字相同不证明所有客户端已支持全部能力。

### 同一开发过程在不同客户端中的表现

AI与脚本按真实源片段、必要诊断和最小差异操作；人可用现有编辑器文本、命令和终端。两者共享含义与前提，但输入节奏、展示、快捷键、访问权限和审批职责不必相同。面板若被采用，键盘可达、屏幕阅读语义、焦点恢复、非颜色状态和大内容渐进展开是该面板验收，不强制无GUI服务先做页面。命令行的机器结果与人类进度分别走实际输出通道；日志中的ANSI/终端控制和工具文本不作为可执行指令。

正常最短路径仍是“写源→看结果”，或“直接改已有文件→捕获→所需检查”；必须保持一个闭合小函数无需先启动服务器、调试器、数据库、Git仓库和完整工作台。大型工程增加的是准确范围、消费者和恢复责任，不把每个开发者变成内部状态管理员。

## 可视图、表单、结构面板与直接操作

类图、依赖图、状态机图、关系图、配置表单、属性面板和拖拽工作台都是**同一作者/语义事实的投影**。它们可以成为高效客户端，但不能为了可视编辑复制第二份可写模型。

```text
VisualWorkbenchProjection = derived {
  subjectSelectionAndRevision,
  projectionMethodAndRevision,
  semanticNodeAndRelationRefs,
  sourceAndEditMappings,
  visibilityFiltersAndCoverage,
  viewLayoutAndViewportState,
  editableActionDescriptors,
  staleAndConflictState
}
```

节点位置、缩放、折叠、颜色、网格、edge routing、自动layout和当前selection默认属于客户端view；可以保存为用户/团队展示偏好，但不进入程序语义摘要。**例外必须来自领域本身**：GUI坐标、CAD几何、工作流人工布局若被目标程序消费，则它们是该领域作者数据，不得以“图的布局”标签排除。

### 直接操作必须降低到同一候选

图上新增继承边、删除关系、拖线连接端口、修改属性、创建类/节点等，若存在唯一有资格的语义映射，就降低为已有 `semantic-change/EditPlan` 并生成正常workspace candidate；随后重新解析、类型/关系检查和review。图形客户端不能直接改自己的edge store后再异步“同步源码”。

一个视觉动作可能需要多个真实编辑，例如创建引用同时加入import、生成缺失声明、更新配置消费者；它们作为一个依赖组呈现。只有真实独立的子变化才允许局部采纳。映射到多个源位置、宏展开、generated-only节点、runtime observation或opaque外部对象时，默认只读或要求用户选择真实owner，不能按最近文本位置猜回写。

### stale view、过滤与“没看到”

Visual projection绑定精确subject revision。作者源变化后，旧图可以作为历史view继续查看，但拖拽/删除前必须重定位到当前source correspondence或基于旧revision形成分支candidate；不能把旧node id应用到latest。节点被filter/scope/collapse隐藏只说明当前view没显示，不能作为consumer-zero、删除安全或“没有引用”的证据。

布局算法重跑不使semantic candidate陈旧；semantic identity/relationship或projection method改变则相交view需重建。客户端可以缓存layout keyed by view/semantic refs，但缓存丢失只影响展示，不影响工程真相。

### 导出与可访问性

导出PNG/SVG/PDF/PlantUML/其他图格式是派生Artifact，绑定subject/projection revision和实际覆盖；不能导回一张图片后作为canonical source，除非所选外部格式本来就是该领域唯一作者源并经过显式接管。可视功能应有等价的文本/结构读取和键盘操作路径，节点/边有可读标签与关系说明；颜色、线型、空间位置不承担唯一工程含义。

## Developer Intelligence 是共同工程事实的投影

补全、导航、层级、诊断、重构、测试定位、调试定位和性能热点都需要项目级知识，但它们不形成第十一项逻辑责任，也不建立IDE专用语义库。**Developer Intelligence**只是 `workspace + semantics + compiler + information + assurance + execution` 的有界投影；每项结果继续携带真实主体、selection/revision、覆盖、来源和资格，客户端只改变交互和编码。 它不拥有持久缓存、索引代、symbol identity、诊断生命周期或变换身份；复用和失效继续由information/query/workspace及实际生产者承担。

| 开发智能 | 真正owner | 结果 |
|---|---|---|
| describe/hover、signature、type/effect | semantics | 说明、签名、推导来源 |
| definition/type-definition/implementation/references | semantics + information | 精确位置、关系种类、覆盖 |
| call/type/module hierarchy、impact | typed relations + query | 分页关系与未闭合范围 |
| completion、quick-fix、refactor、format | semantics + EditPlan/TransformationView | 建议或有基础的完整计划 |
| diagnostics、test/evidence navigation | compiler + assurance | 生产者、主体、方法、覆盖 |
| debug/profile/runtime navigation | execution + SourceMap/Observation | 运行到制品、目标、作者的可证明对应 |
| symbol/search/index | information | 固定切面的索引投影 |
| semantic tokens/highlights、outline/document symbols、folding/selection/linked ranges | parser + semantics + workspace | 与固定source revision绑定的结构/语义标注；只是显示投影 |
| inlay hints、inline values、code lens、moniker/document link | semantics + execution/assurance/information按项目 | 带生产者、revision和来源的派生注解；其中command/link不自动执行 |

同一路径可以同时存在未保存buffer、候选工作区、磁盘工作树、索引代、生成制品、依赖索引和历史revision。它们不是一个全局“最新覆盖栈”。查询明确或由客户端会话固定 `selectionRef` 与用途；“当前草稿的引用”“发行制品对应源码的引用”“已知依赖仓库的公开引用”是不同结果。索引落后时可旁路真源或返回较弱覆盖，不能把旧索引结果贴到新buffer。

LSP可以承载completion/navigation/diagnostics/workspace edit，SCIP类格式可以搬运代码索引，BSP类协议可以接build target与compile/test/run/debug；它们都只是投影。外部document version、symbol、build target、task/session id不自动成为Gift canonical identity。协议表达不了的evidence、authority、effect、unknown和跨表示对应必须保留在Gift结果中或显式记录投影损失。

## 嵌入语言与结构化搜索复用同一Developer Intelligence

当authoring-assist的position落在合格的[嵌入语言投影](../../40-目标与制品/表示/编辑与受管回源.md#embedded-language-roundtrip)中，原有 `describe/complete/signature/definition/references/implementations/actions` **不增加新kind**：应用层先固定host candidate和embedding rule，再把位置投影给相应语言Provider，最后把结果、coverage和可编辑范围映回host坐标。客户端可以显示“SQL / RegExp / GraphQL”等语言标签，但标签不创建另一文档身份。

### 搜索有四个不同层级

```text
text search       字节/文本出现
regex search      文本模式
structural query  语法/CST/AST形状
semantic query    绑定、类型、效果、关系及工程事实
```

四者不能相互冒充。结构模式匹配 `foo($X)` 只证明当前parser/strictness下有相应语法形状，不证明两个 `foo` 绑定同一symbol；semantic rename必须使用真实definition/reference relation。反过来，结构搜索仍有独立价值：迁移API调用形状、查找反模式、批量语法升级、模板/配置结构审查，不必把所有查询提升到全项目类型检查。

```text
StructuralQueryView = derived {
  sourceSelectionAndRevision,
  languageParserAndRuleRevision,
  queryPatternAndPatternLanguage,
  matchSemanticsOrStrictness,
  scopeAndCoverage,
  matchesWithHostRanges,
  metavariableBindings,
  unknownOrUnparsedRegions
}
```

它属于query/information投影，不拥有索引或作者状态。可使用Tree-sitter query、ast-grep、Semgrep或语言原生AST工具等成熟Provider；Provider结果先规范化成匹配事实，不能把工具的node id/metavariable id变成Gift稳定身份。

### Structural rewrite仍是候选变换

结构化工具给出的rewrite/fix首先是 `TransformationView` 的来源之一，然后降低成已有编辑候选。批量rewrite必须在**同一固定source selection**上产生全部原始匹配和前像；不能边改边重新搜索后把匹配集合偷换成另一含义。重叠匹配、一个rewrite产生/删除其他match、跨文件共同约束和生成代码区域分别处理。

应用前检查：匹配仍对应原revision；rewrite只触及声明范围；新文本能被host/embedded parser重新读取；需要语义保持的动作重新走类型/引用/合同验证。结构化工具的interactive“accept all”只是客户端选择，不能绕过当前workspace前像或写权限。可安全独立的matches可以分组采纳；共享不变量或相交write set必须共同检查。

## 不同工程的开发面接合，不能全部压成CLI运行

以下是当前应显式保留的工程入口差异，按组合需要启用；不是封闭工程分类，也不声明相关产品适配已实现。通用的源/配置/测试/运行/恢复通路相同，实际对象与效果不能合并。

| 工程形态 | 作者直接处理的东西与正常开发动作 | 必须另核的目标事实 |
|---|---|---|
| 库、SDK、小工具和命令行 | 公共入口、类型/错误、兼容调用、参数/流输入、打包和使用说明 | 库被消费者真实链接与CLI可启动不同；标准输入、退出、编码和依赖交付各有结果 |
| Web/前端/样式/媒体 | 组件/路由/模板/样式/资源同候选，生成bundle，启动开发服务器，在准确页面状态检查功能/布局/无障碍 | 服务器就绪不等于浏览器已加载新bundle；缓存、service worker、source map、热替换状态分别绑定。截图只是视觉证据，不能代替行为和键盘/屏幕阅读验证 |
| 后端、服务、任务与消息 | API/模式/配置、局部数据fixture、请求/事件、日志和追踪；在选定环境测试与调试 | 本地启动与真实数据库/消息/认证可用分开；不能用生产凭据跑测试，超时请求恢复遵守真实效果合同 |
| 移动/桌面与插件宿主 | 代码/界面资源、打包签名、模拟器/设备/宿主实例、调试附加与更新 | 应用标识、签名、安装对象、进程出生和真实已装制品；重新安装可能清数据，插件加载/配置读取可能执行代码 |
| 数据、数据库与迁移 | 模式/查询/索引、迁移脚本与数据样本、回填/校验/兼容窗口 | 源回退不等于数据回退；数据量、外部观察、读写竞争、保留和恢复按原事务/数据合同，不由文本diff保证 |
| 计算、GPU、ML与仿真 | 算法、数据/模型/参数、内存设备预算、训练/推理/评估与性能 | 代码、数据、权重、随机性及设备对应；采样数据/观察有权限，运行完成不等于精度/误差或可重现实验合格 |
| 编译器、生成器、构建与开发工具自身 | 工具源码与工具输入分开，固定引导种子/规则，生成/编译/比较和自用 | 新检查器不独自为自己签证；工具元程序执行是构建效果，不能变成query；宿主与目标工具不混同 |
| 嵌入式、设备和实时工程 | 硬件配置、镜像、接口与时序约束、设备部署/调试/恢复 | 实际设备身份、权限、刷写/断电风险、固件和物理状态；模拟通过不代表真设备保证 |
| 文档、规范、数据表和其他非源码 | 按真实格式编辑、关系/链接/引用重构、检查并按需生成派生物 | 格式通过不证明语义正确；图/HTML/译文不成第二真源，秘密/许可/大对象有独立存储及退出责任 |

每种画像最少需要准确作者范围、目标入口/参数、运行/测试/观察能力、结果对应和退出方式；复用这些角色，不为每个业务名称建新顶层模块或工具。需要的新目标字段由所属领域版本化解释，无法表达的语义不能用开放字典默默接收。界面可以有真实浏览器/设备预览，也可以先只用文件与脚本；未选可视客户端不意味着不设计目标软件的交互和资源行为。

## 树形视图的出现身份、拖动与实际编辑

客户端消费[多维组织与树形落位](../../70-工程系统与演进/信息与生命周期/多维组织与树形落位.md)，不从Explorer父子关系推断唯一业务归属。同一实体可以在多个视图中出现；每次出现解析到准确来源、配置、披露范围和可用动作。分页未加载不表示实体不存在，折叠/过滤不改变工程事实。

拖动须由当前view的真实动作合同解释：移动导航分组只改presentation；移动作者文件形成含导入/链接/配置消费者的候选；改变运行拓扑则是单独的领域设计与Operation，绝不能复用普通文件move取得部署权。客户端显示改变的是哪一种关系、真实owner、影响与前像，无法唯一降低时保留选择或只读。

开发者不需为了每次移动填写全图、ASMRVE或元模型坐标。必要信息从已有候选/配置取得，缺项只对相交动作返回；原有六工具与编辑/运行合同保持，不新增一个跨权限的万能tree-mutate接口。

<a id="developer-headless-cli-one-protocol"></a>
## CLI / SDK / AI / Workbench 的实施前共同开发合同

本节只规定**面向开发者的命令行适配、结果可用性与体验不变式**，不修改[公共六工具的`gift.ai-tools/2`字段联合](../工具协议/六工具与请求-工具边界-任务与作者输入.md#v2调用字段与控制动作)。以下`gift`命令是**本版确定的拟实现CLI呈现**，不是当前设计包已有可执行文件。CLI、SDK、IDE只编排同一个Application与ToolContract，不可拥有独立编译器或提交协议；CLI返回值不替代对应Owner的规范状态。

### 命令入口与真实路由（默认无外部作用）

| CLI入口（拟实现） | 命令自己的最低参数 | 唯一有权处理的已有协议/模块 | 开发者看见的默认结果 |
|---|---|---|---|
| `gift project inspect [--json]` | 可省略path，使用明确工作区上下文；多个根须指定根 | `bootstrap`确定宿主根/画像，`workspace`捕获前像，`gift.query(view=contract)`投影当前已准入对象 | 当前项目身份、语言/锁/目标/未决；不建空项目文件 |
| `gift query <ref> [--view source\|contract\|diagnostics\|impact\|origin\|state] [--json]` | `ref`是服务签发的合法对象Ref，不是任意磁盘路径 | `gift.query({at,view,limit,cursor})`，读取与分页由原owner负责 | 准确对象与覆盖、当前披露限制 |
| `gift propose --source <local-source-file> [--language <profile>] [--json]` | CLI受管地读取显式输入路径；未传语言沿已固定context/裸源v2规则 | `gift.propose`的**source联合**；本地读取得到固定内容和角色再传入 | candidateRef、可选诊断；不改源文件 |
| `gift propose --base <candidateRef> --edits <delta-file> [--json]` | base与实际有序edit集合；原文件编辑器也可直接提交捕获的delta | `gift.propose`的**base/edits联合** | 新候选、diff/冲突；旧候选不变 |
| `gift preview --candidate <ref> --target <targetKey> [--diff-from <artifactRef>] [--json]` | 当前准确candidate和目标；diff-from出现时使用`return=diff` | `gift.preview`；纯Target/Compiler，不执行目标工具 | 生成范围、artifactRef、代码/差异/诊断；可无项目存储 |
| `gift preview --source <file> --target <key> [--json]` | 显式源码；已固定的sourceLanguage/上下文 | `gift.preview`的source联合；禁止隐含先保存 | 源码结果，默认生成未检查 |
| `gift check --candidate <ref> [--artifact <ref>] [--types] [--cases <casesRef>] [--json]` | 指定真实候选；选cases时必须同时有artifactRef/casesRef | `gift.check`；涉及真实测试命令必须经Execution | 类型/案例的实际证据或未支持/失败；不调整测试期望 |
| `gift save --candidate <ref> --target-ref <ref> --base <ref> [--request-id <id>]` | 精确写集、前像、作用授权；requestId由CLI受信生成亦可显式传 | `gift.apply(mode=save-source)` | 真实提交/冲突/未知效果；不写输出、不git commit |
| `gift output write --candidate <ref> --artifact <ref> --target-ref <ref> --base <ref> [--request-id <id>]` | 经核的完整目标根与当前写出能力 | `gift.apply(mode=write-output)` | 真实写出及结果；不构建/运行/发布 |
| `gift operation status\|cancel\|resume\|rollback <operationRef>` | 已存在、当前可访问的operationRef | `gift.operation`基础status/cancel/resume/rollback | 真实当前状态及未结算事项；不把取消当回滚 |
| `gift build\|run\|debug ...`（条件） | 显式目标、artifact/环境/参数与权限 | 只在相应`compute-run`或`debug-session`协商能力真实存在时转换为被允许的operation；**基础v2不接收自造字段** | 未协商/缺Provider返回Unsupported，绝不偷偷调用shell |

本表具体flag是CLI自身的人机协议，可在实施前形成对应命令解析器唯一源、帮助文档和契约快照；`<...>`占位符不是编译器语法。命令一旦正式发布，要变更有兼容影响的flag、默认作用或退出码须走CLI版本政策，而不是只改此表。SDK可直接传已校验的公共对象/JSON，不要求重新经CLI的argv解析。任何入口都能处理`invalid`、`unsupported`、`needs-input`、`stale`、`partial`、`unknown-effect`与`success-with-bounded-evidence`的精确区别。

### 抽象命令不等于额外层：一对一意图与效果账本

`project inspect`读工作区，`propose`建立不可变Candidate，`preview`获得Artifact，`check`产生Evidence，`save/output write`向Execution移交有授权写作用，`operation`查看和控制已登记Effect；上述操作不按名称强迫每次依次执行。`gift preview --source ...`无需必须`project init`、`lock refresh`或提前启动持久恢复数据库，缺必要Profile时精确返回Needs。CLI自己的文件读取是受信Host输入采集，不能转由Rust worker拿任意路径打开；输入捕获后的摘要/Revision必须与Candidate绑定。

CLI输出格式默认文本，`--json`是结果的**同一类型投影**而非第二语义协议；JSON结果带确切subject、basis、stage、coverage、diagnostics与相交引用；人类文本允许折叠冗长依赖，但不能隐瞒未知或多根部分完成。stdout只放结果；机器模式的stdout为单个有版本Envelope或按协商协议的有序记录；诊断写stderr，不能将warning与协议数据混写。禁止对同一次命令打印多个相互冲突的成功状态。大结果分页；`--json`不隐含全部结果下载。

CLI 退出码统一消费[运行交互的请求退出合同](运行交互与工作台.md)：`0` 本次范围内正常结果，`1` 已取得可靠领域结果但明确完成目标未达，`2` 非法命令/协议且未派发，`3` 未取得可靠最终响应。Needs、Conflict、拒绝授权、不支持、检查不通过和未知结算保留为结构化领域状态，不另建一套 0—9 数字映射。纯 preview 完成仍可为 unchecked；启动请求取得可查回 Operation 可以退出0，明确等待完成却未结算应退出1。实现必须复用同一机器常量和帮助映射；这些设计不表示本包已有 CLI。

### 不同终端的等价性不是界面复制

- 终端：可仅凭`--source/--candidate/--target`完成短预览与二次改动；清楚区分纯工作与Effect动作；JSON适合CI但不会授权CI执行额外操作。
- SDK：使用签名的受限能力句柄、严格decoder、消歧的union字段；本地文件/秘密/Provider必须由Host显式供给。
- AI：只调用六工具并读取必要合同，模型内容以不可信作者候选处理；提示词不能自行改变角色、提交前像或执行许可。
- Workbench：命令、按钮、图/表单降低为同一Candidate与Operation；IDE崩溃恢复来自真实Operation/Workspace，不以webview内存为权威。
- Web/Remote：无本地worker时只提供真实合格的远端Runtime；单独网页和远端机器的身份、权限和源出境不可省略。Web连接断开只取消自身借用，不令外部作业成功/失败。

### 首发交互样例（各命令为拟实现的操作示意）

```sh
# 假定当前context已固定gift.semantic/1解释和真实TS目标，不写盘：
gift preview --source src/twice.gift --target typescript
# 输出中的candidateRef=C1、artifactRef=A1由系统签发，以下为符号占位
gift check --candidate C1 --artifact A1 --types
# 用编辑器拟定change.json（准确有序{path,old,new}），仍不修改源：
gift propose --base C1 --edits change.json
# 系统返回C2；对明确旧产物比较：
gift preview --candidate C2 --target typescript --diff-from A1
# 只有明确请求实际保存，取得当前workspaceRef W与前像 B：
gift save --candidate C2 --target-ref W --base B
```

与上面正例同样重要的失败终点：未知语言/未绑定目标→返回Needs而无文件；编译器unsupported→保留原候选；类型检查失败→仍可阅读差异但不标合格；前像改变→保留候选而不覆盖；Provider回执丢失→按原Operation核账而非用新请求盲重试。

<a id="design-only-headless-and-blueprint-query-compat"></a>
## 设计专用查询与六工具的无新增顶层入口兼容

基础 `gift.ai-tools/2` 的 `gift.query(view=contract/source/diagnostics/impact/origin/state)` 保持原字段与含义；`gift.propose`持有候选变更，`gift.preview`负责真实源码生成，`gift.check`按方法检查，`gift.apply`按前像保存源/写目标，`gift.operation`负责已登记或经协商的执行控制。不新增 `gift.plan()`、`gift.design()` 或 `preview(return=plan)`。完整蓝图读取统一采用[六工具 Owner 已选定的 `gift.blueprint-read/1` 扩展](../工具协议/六工具与请求-工具边界-任务与作者输入.md#gift-blueprint-read-extension)：能力协商且生产者实现合格后，才允许 `query(view=blueprint)`；未协商服务严格拒绝该 view。Target/Layout 仍由锁定的纯方法产生，既有 contract / origin / impact 只消费各自相交摘要，不能把缺少完整蓝图投影伪装成已支持。

CLI/headless、Code-OSS Extension、AI和未来自有客户端只能有相同的作者/Binding/Need/Basis/Effect含义。客户端按钮“工程蓝图”是一次只读计划显示，不触发 `gift.preview`，也不能为了在 UI 上看到树就先写出目标目录。人工修改图和表都必须产生准确 `gift.propose` 候选或导航回真实原生源；不能让独立 UI Model 变成影子可写 Graph。需要用户审阅的实现选择由原 `All Decisions` 暴露，但编译器固定作者源和已采纳选择后不再次调用 LLM 选择同一个功能。

若一次交互是内存纯函数，不需长期Operation；若处理的候选跨会话保存，就需要能续回的候选身份与精确前像；只有真实外部效果才需要Grant、Attempt、durable operation identity和settlement。`Designed / TargetPlanComplete / ImplementationReady` 是基于当前权威的可视结论，不改变 `gift.preview` 的 actual generated-unchecked 状态。所有未知、当前不可披露和未实施能力都保留为有限状态/Need，不从一个界面入口已注册推出产品可用。

## 从抽象开发面到真正连续的使用者体验

此篇拥有六类开发任务、DeveloperDecisionView与值编辑器；“第一次如何启动、如何选择本次做到设计还是源码、跨五视图怎样保留同一候选、什么时候显示完成/未知及如何从异常中返回”，由[开发者全旅程UX与交互验收](开发者全旅程UX与交互验收.md)拥有。该 UX 合同只拼接已有真实owner的投影，不新建一份可写配置或把六个公共工具直接作为人类主菜单。
