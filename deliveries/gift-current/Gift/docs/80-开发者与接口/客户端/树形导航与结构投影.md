# 树形导航与结构投影

本篇拥有Gift开发客户端如何把已有结构组织为可浏览的树：视角、节点出现、展开、分页、筛选、选择、定位、刷新、无障碍和导出。它细化[工作台布局](工作台布局与交互.md#final-workbench-layout)，不重新决定工程分解，不建立TreeManager、第二工程IR或永久节点数据库。架构分区和物理落位归[共同组织合同](../../70-工程系统与演进/信息与生命周期/多维组织与树形落位.md)，查询与续页归[客户端协议](../工具协议/客户端与并行会话.md#分页查询的快照合同)，本文只规定它们在树里的具体消费。

以下是可实施设计和验收条件，不是已实现的控件、Provider或性能证据。静态文档目录采用普通Markdown层级链接；复杂树控件只用于确有对象浏览、选择和局部刷新的客户端。不能为让文档“像树”而要求读者安装或启动Gift。

<a id="tree-view-purpose"></a>
## 先选择要看哪一种结构

Project主视图默认展示当前明确工作区中的产品根和作者结构，不把磁盘文件、生成物、在运行的实例和证据混为同一类子节点。只存在原生文件而尚未采用结构作者时，保留原生浏览入口及未采用状态，不捏造空Definition。原生文件浏览优先复用宿主Explorer；同一资产在Project中的语义入口只引用它。

| 视角 | 一级根与真实展开关系 | 可以解释什么 | 不可暗示什么 |
|---|---|---|---|
| 文件与资源 | 已授权工作区根，Provider实际目录成员或其固定清单 | 实际文件、编码、来源角色、源与生成区域 | 目录是模块、包、权限或事务边界 |
| 工程结构 | 选中ProductRoot、Module/Definition及其声明、use、公开边界 | 定义与实例、组合、共享引用、局部控制 | 一次use等于已经创建运行实例；每个表达式都有永久ID |
| 实现与目标 | 精确RootResult/Binding/Target；按已选方法、成员或生成对应展开 | 如何实现、生成到哪里、还有什么缺项 | Planned等于Applied；一个目标成功等于全部成功 |
| 操作与保证 | 明确Operation/Attempt或Claim/Evidence；分别使用其真实父子/支持关系 | 正在做什么、实际结果与哪份证据支持什么 | 可视父子就是因果全序；子检查通过能代签父Claim |
| 文档与设计信息 | 当前包根、责任目录、物理文档容器、显式Contract Unit及按需普通章节 | 正文在哪里、Unit归属及相交规范/理由/状态/依据 | 一个树节点必须对应一个文件；目录位置签发main采用；文字链接构成完整工程依赖图 |

视角是一个当前用途下的选择，不增加五个顶层公共工具。一个界面可以只显示其中一个；跨视角通过准确对象引用定位。过滤条件作为facet，不机械生成“语义类→authority→阶段→scope→target”的全量笛卡尔树；无匹配内容的分组不造空文件或空工程对象。

同组兄弟按明确依据划分：模块下可以是声明，声明下可以是公开成员与引用分组。固定导航分组与真实领域对象视觉上区分；分组名不能冒充Type、Block或新的owner。一个目录已有README时，目录行可直达该入口，不再把README作为与目录同义的重复行；该文件仍计入完整文件目录。文档视角进一步区分**container occurrence / Contract Unit occurrence / ordinary section occurrence**：container反映当前物理成员，显式Unit引用稳定语义闭包，普通section只提供当前标题定位。三者可以嵌套但身份域不同，文件合并不删除Unit节点，标题新增也不自动发行Unit。

<a id="tree-occurrence-identity"></a>
## 工程对象、关系与节点出现分别定位

一个Money定义可以在Orders与Payments两条引用路径下出现；这是一个对象的两个导航出现，不是两个Money定义。两个参数恰好相等的有状态use则可能是不同实例，不因标签或内容相同合并。当前树中每个出现只有一个父出现，工程的依赖或关系仍允许多父和合法环。

| 显示数据 | 从哪里取得 | 寿命及边界 |
|---|---|---|
| 主体及修订引用 | 原Entity/Definition/Use/Artifact/Operation/文档内容合同 | 真实工程或文件身份；不由树发行 |
| 出现定位 | 当前视角、父出现及真实关系/use/成员发生位置；合成分组另含该分组的本地稳定判别 | 只在所声明的视角/基础里唯一；不是跨系统永久身份 |
| 当前基础 | 查询快照、解释、必要Provider及可披露范围；多源时为声明的切面 | 每页和增量能检验同一基础，不把cursor当snapshot |
| 标签及补充描述 | 已获准显示名、角色、简短状态；必要时显示模块/目标/来源消歧 | 可改的展示信息；相同名字不证明相同对象 |
| 子项能力与取得状态 | 原关系能力、已捕获子项覆盖、页结果和本地请求状态 | 未请求、局部、完整为空、失败、陈旧分开 |
| 可用动作 | 原owner、接口能力、候选前像和当前许可允许的动作引用 | 菜单只是投影；执行时仍重验 |

不把显示标签、行号、数组下标、绝对磁盘路径或内容摘要单独当出现身份。只有当前有完整稳定关系时，才能从关系定位派生可重复的出现键；原接口没有稳定关系身份时，允许快照内临时键，刷新后重定位，不伪造长期对应。

当前请求的校验键包含准确基础；恢复展开/选择的位置提示只保存原主体与出现路线及其来源，不把整份新快照摘要纳入“永远不变”的UI id。换修订时先由原映射判断出现能否延续：同一合法重命名可保持，删除后重建不能；映射不唯一时显示候选或退到可确定祖先，不按名字命中第一个。恢复提示不携带写权，也不复活旧选区批准。

循环判断只沿**当前祖先链**检查同一种展开关系是否回到已有主体/关系上下文；发现回边显示可定位的引用叶，而不继续无界递归。不能用全局visited把第二条合法共享路径全部藏掉。关系允许不同角色的同主体重入时，按该关系的上下文判别；达到深度或工作预算只标“未展开”，不宣称循环或不存在。

<a id="tree-row-and-expansion"></a>
## 节点行、展开与大分支

一行优先显示展开控件、标签、语义角色和当前任务必要状态。详细revision、owner、来源、五阶段、证据、成本等在Inspector/详情按需展开；短标签不能删除消歧信息。当前选中目标、过滤及观察基础固定在视图上下文中，不在每行重复一大段合同。横向空间不足时允许换行或省略显示，但完整标签及来源可通过详情、键盘或复制取得。

未知子项是否存在时，保留“可查询子项”的入口；展开箭头表示可尝试取得，不签发非空。确知此关系无子项才按叶处理；只有某次传输失败不能将对象永久变为叶。UI取得状态不改变工程实体状态：一个未展开的已验证Artifact不会变成未验证，一个已渲染的节点也不会因此合格。

展开只取得当前节点下一层的必要摘要和有界页，不先递归计算所有后代。摘要能直接取得时不加载函数体、整文或二进制资源。重请求同一基础、父出现和查询条件时可共享无副作用的在途读取；一个视图取消只释放自己的订阅/保留，不终止仍被别的消费者使用的生产者。

“全部展开”是范围明确的可取消遍历，不是不可中断的全仓递归。显示实际展开数量、当前覆盖和剩余边界；到达预算停止，未展开部分保持原状态。高出度关系按稳定分页处理；需要全局排序却未取得足够下界时，结果只能称局部页，不伪称全局前若干名。

<a id="tree-page-contract"></a>
## 分页、覆盖和空结果

外部沿既有`query at/find/view/limit/cursor`及其已协商变体；本文没有新增顶层Tree RPC。内部树适配请求必须能够解析出：固定基础、视角、父出现、真实关系/成员范围、过滤与排序规则、所需摘要、当前披露上下文和原续页引用。字段已在固定上下文中时可引用，不要求每行重复传完整上下文。`limit`继续遵守原公开协议，不因视图需要一页就擅自突破它。

结果由原查询返回子项、实际覆盖、缺项/诊断和有后续时的cursor。树适配器核对结果的查询与基础后才安装；若某生态没有快照能力，保留它的逐页观察范围，并在需要完整联合结构时请求一致性能力或重新捕获。不能用一个cursor字符串把移动数据集拼成不可变世界。

| 取得情况 | 树上显示 | 后续合法动作 |
|---|---|---|
| 尚未请求 | 未加载，可展开 | 取得首个有界页 |
| 请求中 | 已有内容可保留并标正在刷新 | 取消本次观察；不清作者内容 |
| 成功但部分覆盖 | 当前子项＋“加载更多/剩余未取得”；数量注明已加载或下界 | 沿同查询cursor续页 |
| 范围完整且没有成员 | 明确“此关系在本次可见范围内为空” | 可折叠；并非全系统没有对象 |
| 范围完整且有成员 | 该范围完整；过滤后数与未过滤数分开 | 普通浏览/选择 |
| 失败或不支持 | 保留准确失败、可继续的已知范围 | 仅在具备安全重试条件时重试 |
| 基础、权限或cursor失效 | 旧内容陈旧或按披露要求移除，不能继续拼页 | 从新基础重取；不把剩余页当空 |
| 披露不允许 | 只给政策允许的通用说明 | 不显示隐藏名称、数量或存在性 |

“加载更多”、错误、预算边界是呈现辅助行，不进入实体数量、语义多选、拖动或导出成员集合。加载成功后用新页替换辅助行；它们可以接受“续页/重试”的客户端动作，但不能被当作可编辑Definition。

续页去重按同一快照中的**出现身份**，不是主体ID；两个不同引用出现必须都保留。同一页重传可以幂等显示，两个相同标签不能合并。父节点或filter改变后迟到结果只结算自己的读取，不覆盖新视图；必要时取消旧订阅，仍需核结果代际而不能仅靠取消回调保证无迟到。

原Provider组合排序、页前缀及不足下界由[跨Provider页组合](../../70-工程系统与演进/信息与生命周期/接入检索与派生.md#provider-page-composition)承担。层级分页不复制这一算法。

<a id="tree-order-filter-search"></a>
## 排序、筛选、搜索与定位

保留有语义的源顺序、参数顺序、结果重数和领域序列；不能为看起来整齐按字母改变含义。纯导航默认采用固定分组顺序及声明的标签排序，最终用可披露的稳定出现判别作并列顺序。locale排序是视图选择，其版本和规则进入该查询续页条件，不改变实体名称、作者顺序或工程hash。未知值不作为0参与排名。

筛选有两个明确模式。**当前已加载筛选**只检查已取得子项，不能给全库零命中结论；**范围搜索**交给原查询，报告实际覆盖。为了展示命中而保留的祖先标为“路径上下文”，不计作命中，也不表示祖先自身满足条件。祖先不可披露时不泄露其名称或层数；可以按Provider允许的方式给脱离树路径的结果。

搜索默认返回有界平铺命中，按需选择“在结构中定位”。不要先构造全树才搜索，也不要为恢复一条路径枚举全部兄弟。Provider能给合法祖先路径时直接使用；否则沿已知结构取得必要子项，无法定位则保留平铺结果与准确原因。内容索引覆盖、命中总量和当前可视树覆盖分别报告。

一个主体有多个合法出现时，优先保留用户发起定位时的视角/路径；已知唯一匹配可以直达，多处均合理则返回可辨上下文供选择。此处选择导航路线不是选择产品实现。当前过滤隐藏目标时，提供“临时显示该目标及祖先”或明确清除相关过滤的动作，退出后恢复原条件；不无声重写用户过滤器。

面包屑显示当前视角中的出现路线，不叫物理源码路径。需要物理位置时另显示真实resource/region；两者无可靠对应时不造路径。返回、前进及固定书签绑定原对象与上下文，必要时提示陈旧；不打开恰好占据旧路径的新文件并假装原书签仍有效。

<a id="tree-selection-and-actions"></a>
## 焦点、选中、活动对象与批量动作

焦点是键盘当前移动位置；选中集合是准备交给某种动作的对象；活动对象是当前编辑器/Inspector正在显示的对象。三者可以相同，也可以不同。普通方向键不得保存源码、切换Binding、启动任务或批准计划。单选树可按宿主惯例让焦点带动只读选中，但不能把随焦点变化作为有副作用动作的确认。

多选必须说明选的是节点出现、真实主体、当前可见文件还是某个查询集合。一个主体的两个出现可以同时高亮；执行“打开主体”可以按其动作合同去重，删除两个独立use、两条引用或两份运行实例不能按主体相同去重。多选形成批次前由原操作owner解释对象粒度、重复和相交依赖，不在UI凭标签归并。

“选择全部”不默认包含未来新成员。界面分别提供当前页/已加载集合和固定查询结果集合；后者在要求完整效果前须取得该范围的准确成员、覆盖与权限，不能边扫描边删除。若产品确需持续匹配未来成员，应使用原动态选择合同及单独操作，不伪装成一次普通勾选。

父节点的多选汇总只汇总实际选择域。部分后代未加载时明确“部分已选/范围未完整”，不能显示全选并批准隐藏成员。屏幕阅读的mixed仅描述混合选择，未知覆盖还需独立文本；未知不冒充checked=false。折叠不丢失明确选择，但批操作预览必须显示被隐藏的已选成员及准确数量/覆盖。权限撤销或删除导致的失效选择单列，不能静默剔除后宣称原批次全部完成。

| 用户动作 | 正常处理 | 不能混同 |
|---|---|---|
| 展开/折叠、排序、过滤、固定只读视图 | 更新Client presentation或取得查询 | 改作者结构、选择实现 |
| 单击/Enter打开 | 按已声明默认动作显示源码、合同、证据或操作详情 | 不可用动作靠双击偷偷执行 |
| 重命名 | 在真实owner形成候选，保持合法身份及公开消费者 | 仅改UI label后称源已改 |
| 拖动排序 | 若只改显示，写presentation；若源顺序有语义，走源编辑 | 表示重排和求值顺序变更 |
| 拖到另一父节点 | 先区分文件移动、use/关系重接、范围迁移或纯导航收藏；预览影响 | 直接把树parent改掉当工程移动成功 |
| 删除 | 明确删除引用、源对象、产物或运行实例；按各自恢复/前像协议 | 删除一行等于删除全实体、目录隔离等于权限 |

拖放只是提出typed proposal。跨Provider、卷、项目、版本或作者域没有合格迁移时保留候选并给出缺项，不能偷偷复制后删源。公开接口、相交硬要求、联合资源约束、未保存内容和在途操作继续进入原Plan/Review；树的唯一父约束不能替代这些条件。

<a id="tree-refresh-recovery"></a>
## 局部刷新、重连与跨次恢复

共享查询返回不可变的已披露页，UI在私有更新中安装相交子树与覆盖。部分刷新不要求重建全仓，也不能只改计数而保留来自另一基础的子项。适配器维护主体/关系到当前出现的反向定位，仅对已装载出现及可重建输入索引负责；不是全系统新关系库。

变化可确认时，针对改名、插入、删除、关系改接或摘要变化更新最小受影响范围。删除成员需要对应变更事实或完整新成员清单；没有在局部页看到旧项，不等于旧项已删。子项重排保留能证实的出现身份，更新页边界与焦点邻接。关系改变时同时失效旧父、新父和相关计数；缓存只在声明输入未变时复用。

事件缺口、历史压缩或多源失配走原`resync-required`。重连先核workspace/Provider/可见范围，再捕获新切面、恢复可证明的展开路径和选择；旧游标不在新快照上继续。原作者缓冲、TargetDraft和Operation恢复各自保留；关闭树、取消读取和重同步不取消真实运行、不回滚已发生效果。

当前焦点行消失时，先选本次可确定的可见邻项，再可见祖先，最后视图根；通知位置变化，不自动打开同名替代。恢复展开深度受当前预算限制，未恢复的路径作为可继续提示，不以自动“恢复全部展开”触发昂贵全仓工作。可跨会话的presentation只保存必要路线/过滤/排序与来源，不复制全部节点内容；敏感历史按原许可和保留策略处理。

权限收窄时，当前页面、搜索、tooltip、辅助技术文本、计数与本地缓存均消费撤销结果；不能只隐藏行而仍能复制隐藏名称。若协议不允许披露对象是否存在，统一呈现不可访问/不可解析，不通过子数、时序或错误文案主动给出隐藏存在性。是否需要更强侧信道隔离归真实安全合同，本文不凭UI代码宣称消除全部侧信道。

<a id="tree-host-and-accessibility"></a>
## 宿主适配、键盘与无障碍

当前人类客户端沿已选Code-OSS/VS Code Extension-first。TreeDataProvider的`getChildren`提供下一层，`getTreeItem`提供显示项；`onDidChangeTreeData`通知相交刷新。需要`TreeView.reveal`时实现当前出现的`getParent`；`TreeItem.id`采用可复原的出现定位，不能把同一主体在不同父下的出现都赋同一个id。API只提供树接合，不自带Gift的快照分页、权限、语义或联合操作保证；具体规则由本篇与原查询消费。原始API依据见[来源与适用边界](../../../research/sources/工作台与替代路线.md#tree-navigation-evidence)。

Provider分页与宿主`getChildren`返回数组之间由适配层承接：返回已取得的当前页和明确的续页辅助项；续页到达后刷新该父。不把辅助项当工程成员，不把未取得数据伪装成宿主None叶。需要不同表示的大表格可用已有表单/表格视图，不为每个树节点增加自由渲染容器。仅有虚拟滚动不能降低后端全量枚举成本，扫描与渲染预算分别成立。

原生树优先复用宿主键盘与辅助技术语义。自定义树才实施并验证对应tree/treeitem/group、层级、展开和选择语义；可见焦点与选择独立，非颜色反馈可读。垂直树中上下移动可见焦点，左右展开/回父，Home/End定位当前可导航首尾；类型前缀查找只读移动，Space按明确多选模式切换。Enter的默认动作必须可见且限定为打开/查看或显式声明的安全操作，发布/删除等效果仍由具名动作进入原准入。不得为了照搬某个键位覆盖宿主或辅助技术已定义的操作。

对动态未全部装载的树，层级与已知集合位置用真实信息提供；不知道总量时不冒用当前页长度作全体大小。具体未知数量编码、读屏行为、RTL键位和移动/触摸适配需在实际宿主组合中验证。键盘到达续页和错误说明，读取状态适度通知，不将每项后台刷新变为抢焦点播报。原国际化、双向字符隔离、精确复制与200%缩放要求继续适用。

静态文档导航使用嵌套链接和明确段落，不仿制应用树的键盘模型；这既保留可打印/可搜索的全文，也避免把普通目录误标成已实现交互的tree控件。HTML阅读物和真实客户端属于各自独立的派生/实施职责，不由本规范的Markdown目录代签。

## 文本导出、规模与退出

树的文本/Markdown导出至少保留视角、准确根与内容基础、排序/过滤、所列范围及未完成状态；每个实体出现能回到真实对象/文件引用，引用回边和省略边界有文字说明。展示缩进不是改变原结构；隐藏分支不能在导出后被叫作全工程完整树。全量导出另按读取覆盖取得成员，不只抓屏幕上可见行。

导出标题、文件名与说明按数据转义，不执行Markdown/终端控制、程序或任意命令链接。完整源文件仍是原件，导航标签转义不改原文件名或源码。向其他用户发送树也是披露行为，不能因它是“只有目录”跳过访问边界；未经允许不导出私有父路径或全量hash。

衡量实际规模时分别记录：Provider枚举/搜索工作、读取字节、解析/过滤排序成本、已驻留出现与页面、渲染量、首次有效反馈、完成覆盖、取消/重同步及释放。由原资源owner限制并发与内存；保留有实际消费者的查询/快照，不缓存每一种facet组合的全量树。没有实测不承诺特定万级规模或毫秒数字。

释放视图时注销监听、取消独占观察、释放自己的页/快照占用和无消费者缓存；仍被其他视图/真实操作保留的输入不释放。删除全部树缓存可以重建已存在的工程，但不能恢复未曾保全的作者草稿；恢复责任仍归原owner。

## 一个连续实例

固定工程C1中，Orders和Payments分别引用同一Money定义；Orders有两个参数相同但承担不同任务的use。工程结构树显示为：

```text
Shop 〔工程C1／结构视角〕
├─ Orders 〔模块〕
│  ├─ ReserveA 〔use：u-a〕
│  ├─ ReserveB 〔use：u-b；不是u-a副本去重〕
│  └─ Money 〔引用：同一公开定义M@r1〕
└─ Payments 〔模块〕
   └─ Money 〔引用：同一公开定义M@r1；另一导航出现〕
```

M@r1内部引用Orders形成合法模块声明环时，该路线显示“返回Orders”的引用叶；Payments下的Money仍显示，不能被全局visited吞掉。树的出现数、唯一主体数和运行实例数因此不是同一个计数。

用户搜索Money获得两个出现，选择Orders路线后查看M@r1。未请求修改时没有新作者源或Binding。展开Payments取得第一页并留续页提示；C2随后改变其成员，旧C1第二页迟到，只保留为旧观察而不接入C2。当前未加载部分不是零，点击“全部删除”也不能让已加载子项代替完整删除范围。

另一个用户重命名M但保留其声明身份，原映射能唯一延续时恢复两处出现。删除后重建同名Money而无映射，则提示新主体；旧书签不能自动取得新主体的写权。把ReserveA拖到Payments必须经过真实模块/引用/作用域迁移候选，不仅是改一行parent。预览发现共享资源约束不满足时保留原工程；树仍可继续浏览其他部分。

以上轨迹的正式接缝义务归[组织保持与连续变化](../../60-保证与证据/验收/组织保持与连续变化.md#tree-navigation-cases)。具体反例只作为研究输入，静态目录生成可在文档工具中核验；上述分页、权限、迁移与宿主行为只有真实实现和运行证据才能判定通过。
