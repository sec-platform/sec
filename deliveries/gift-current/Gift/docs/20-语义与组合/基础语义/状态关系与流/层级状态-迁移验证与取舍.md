# 迁移、验证与取舍

## 升级、迁移和旧事件

默认已有实例继续绑定原model与回调版本，新实例可以用新模型。把同一状态ID的含义改掉，不自动使旧激活成为新含义；物理表索引永远不是持久迁移身份。

需要迁移已有实例时，先固定稳定切面及目标模型，映射活跃状态、C、history与完成标志，再逐个处理活动/计时/内部通知的相关性。新配置必须满足新拓扑，旧事件与函数合同须有合法转换。只改显示名可保留逻辑身份；将atomic拆成compound需要选择新子态；deep记录指向被删叶必须映射或采取明确fallback。

旧活动仍在运行时，选择保留旧实例、等待停止后切换、经过已证明安全的接管、或有权隔离；不把新模型写入旧snapshot后继续接收所有旧回调。迁移失败维持旧稳定内容，可能阻断新的外部作用；它不扩大旧权限。

例：原inspected表示“格式合法”，新版表示“格式合法且签名核验”。原history中的inspected不能仅凭同名延续新完成结论。需要重新检查并得到新结果，或明确保留旧合同。这个要求变化不能被表索引迁移隐藏。

移除图或库源码只影响未来采用；现有实例、未结算事件和活动仍有责任，直到选择并完成停止、转移或保留旧解释。纯内存已结束实例可以直接释放，无须建立历史审计平台。

**语义消费校核：** **旧实例与迁移期间事件：** 状态模型新增字段或转移含义时，旧队列事件、保存快照和仍活动的旧实例可能同时存在。新解析器能读旧表示不自动证明原迁移无新作用；对于不可逆外部Effects，必须在消费端采用正确的新旧事件路由或阻断不兼容激活。 实现或验证此用例时分别消费[灰度发布中的读写兼容矩阵与不可逆分界](../../../70-工程系统与演进/演进与实施/兼容迁移/迁移切换与退役.md#gift-mixed-release-compatibility)、[老源解释升级与隐式新效果的采纳资格](../../../70-工程系统与演进/实现与装配/源绑定与解释映像.md#gift-source-interpretation-upgrade)的权威交接，当前机制只拥有本地行为含义。

## 对照例、失败切点与尚未实现范围

| 检查对象 | 具体输入/扰动 | 预期结果 |
|---|---|---|
| 父子优先 | 同一事件，子有真guard，父有默认转移 | 选中子；父不是第二次执行 |
| false与失败 | 子guard为false／除零／超预算 | false可寻找祖先；错误/未完成不能当false选祖先 |
| 正交完成 | 仅render进入final | work尚未完成；不得跳ready |
| 并行共享C | A把1加1，B再乘2 | C=4；擅自并发或调换可得3，不是合法同义优化 |
| 无目标与自转移 | stay("ping")／on("ping",当前ID) | 前者无exit/entry；后者重入且activation变化 |
| 正交内外转移 | 区域compound向自己的后代external/local | 按真实域决定是否重入外侧parallel；不能一律只改一个叶 |
| history | render完成后pause/resume | deep保留rendered；shallow重启work默认内部状态 |
| 完成再次出现 | 父activation保留，内部final退回工作态，再到final | 新completionEpoch，新Done；旧通知不得推动新轮次 |
| 临时状态输出 | 同宏步entry发显式输出后退出，同时声明activity | 显式输出计划保留，短暂activation的活动不启动 |
| 活动迟到 | 旧checking退出后新checking启动，旧结果返回 | 旧ledger结算，不能完成新checking |
| 逻辑完成与真实停止 | cancel已进入final，worker不响应 | 逻辑可完成，资源仍Pending，输入不能回收复用 |
| 无事件自循环 | always指回自身且guard恒真 | 预算中断/停放，不能返回Stable，也不能声称图无解 |
| 宏步失败 | 前一action已创建命令，后一action或activity输入构造错误 | 工作副本与未发命令弃置，旧快照保持 |
| 结果映射错误 | Provider已经完成，结果到事件的纯映射报错 | 保留实际结果，停放图输入；不能重做外部作用 |
| 提交切点 | 宏步完成、状态/命令提交后响应丢失 | 原输入身份读回，不重发不同身份的entry效果 |
| 名字和排序 | 改状态名但不改列表／改列表次序 | 前者不改变优先；后者明确语义变化 |
| 外部伪造 | 发送字符串done.state.work | 只作为普通外部事件；不能变成引擎Done |
| 迁移 | 同名完成态强化要求 | 旧完成依据不自动满足新要求 |

这些是可独立复算的设计预期。W3C基础规则、已有成熟引擎与其测试在相同前提下可以复用；Gift新增的纯反应、宏步提交、事件标签、激活/资源和迁移接缝需要自己的符合性，不重做全部上游测试，也不省掉新增边界。

本章定义有限作者库、模型/事件、逐步算法、历史/结束、驱动、计时、迁移和目标落位。仍未实现：该库和decoder、守卫/动作检查、目标适配与真实运行；仍缺后续完整设计：任意动态拓扑改写、多节点强实时、分布式全局同步、SCXML全部数据/I/O模型的跨语言保持。这些扩展子域的未定设计保留于[层级状态合同](层级状态与事件.md)的准确范围，缺代码/真实证据进入[实施闭包](../../../90-治理与参考/状态/实施闭包.md#impl-conditional-domains)；窗口、流与硬期限分别由[背压与事件时间](背压与事件时间.md)和[设备与实时交付](../../交付语义/设备与实时交付.md)拥有，不被本章两个计时字段自动关闭。

## 取舍与反转条件

当前选定“固定次序的层级图＋纯宏步反应＋按需外部driver”。更小替代是普通函数/扁平状态枚举，简单场景继续使用。更成熟直接替代是目标已有的状态机引擎，完全满足当前合同就优先复用；无必要不生成一套新的解释器。更强的事务工作流、同步数据流或实时模型只在实际要求下使用，不由本章替代。

代价是必须明确模型顺序、回调与状态生命周期，并处理纯反应与现实动作的接缝。收益是高层控制可以重复使用而不枚举组合状态，不必在每项导出任务重新写暂停、完成和过期回调骨架；收益仍需实际完整任务验证。

以下情况重开相交设计：作者任务要求与固定次序不相容；已接受源语义依赖直接可见微步效果；模型过大导致纯宏步暂存不可承受且任务允许分段可见；所选引擎不能满足共享语义或迁移；真正硬期限需要另一类可证明调度。重开具体责任与兼容条件，不重新制造一套候选、权限、内容库和全局成功状态。

## 动态拓扑、跨节点时间与 SCXML：四个分离的条件子合同

既有已选语义仍是**静态模型、单所有者、确定宏步、可复核的 event/guard/action 次序**。下面的子合同只在作者实际要求时激活；不能用“支持层级状态机”推导出动态在线改图、跨节点强实时或完整 SCXML 行为。

**在线改变状态图**：变更描述为 `TopologyTransition{fromModelDigest,toModelDigest,cutoverEpoch,stateMap,historyMap,activityPolicy,queuedEventPolicy}`。先在新图上检查状态映射单射要求（需要合并时显式选择合并政策）、活动父路径、迁移 guard、输出及历史状态合法性，随后冻结旧输入 epoch，在可恢复的稳定宏步边界安装新图。旧活动 token、超时事件与回调绑定旧 activationEpoch；新模型不得仅依同名状态吸收。无法证明安全迁移时允许旧/新两代并存、停止旧实例后重启或报告 `MIGRATION_REQUIRED`，不能在处理中直接覆盖状态表。

**跨节点分布**：作者明确选择 `LOCAL_SERIAL`、`CAUSALLY_ORDERED`、`PER_KEY_TOTAL_ORDER` 或 `COORDINATED_COMMIT` 等真实可用的一致性画像，声明参与者、成员变更、消息去重身份、隔离域、重放窗口与故障模型。网络分区出现时要在可用性与一致性之间遵循所选协议；没有可靠共识和可恢复日志的节点不能把各自本地稳定宏步拼成全局原子迁移。由执行/存储 owner 实现日志、围栏、超时与迟到回执；语义 owner 只定义允许的观察序列。

**时间与期限**：逻辑时钟、单调时钟、事件时间、真实墙钟和外部设备时钟是不同测量源；期限合同至少携带触发定义、时钟域、最大误差/漂移假设、调度预算、最坏情况计算/IO 条件与过期动作。无 WCET、可用资源保证、网络边界和设备验证时只能返回 `DEADLINE_UNPROVEN`，不能把某次快测“10ms”标成硬实时保证。设备危险态转换遵守合格的独立联锁/安全控制路径，不以普通用户态软件的状态图取代。

**SCXML 交换**：显式声明所支持的 W3C SCXML 语义子集、数据模型、脚本与 I/O processor、内部/外部事件入队及优先级、`<send>`/`<cancel>` 的效果归属，并维护 import/source map。逐语义差异矩阵判定 `SUPPORTED`、`ADAPTED_WITH_PROOF` 或 `UNSUPPORTED`；无法保持的动作不静默忽略。验证以原始标准解释器/合格 oracle 与 Gift 所选 target 对照事件轨迹，包括并行转移、历史、延迟事件、取消及故障，不能只对比最终叶状态。

以上四项分别选择、分别计费、分别提供 Evidence。一个本地有限状态任务只须满足第一段现行静态范围；任何可用目标的缺项都通过相交 Requirement 与 TargetCapability 差额精确反馈。

## 有条件启用的在线拓扑转换：迁移准备、切换和退役

只有当 `TopologyTransition` 指定的旧模型实例仍处于稳定宏步边界，并能固定 `(oldModelDigest,stateInstanceRevision,activationEpoch,pendingEvents,pendingTimers,activeActivities,externalAttemptRefs)`，才进入在线迁移准备。映射前先检测删除的叶/父路径、并行区域数改变、history深浅及作用域、计时器时钟域、事件数据升级与已执行 Effect 的旧资格。一个旧活动在新状态下是否复用必须由活动身份和生命周期映射证明，不能因为类名或路径相同继续消费回调。

准备产生 `MigrationDecision{newStateConfiguration,newHistoryMap,timerDisposition,eventDisposition,activityDisposition,unsettledEffectRefs,rollbackCut,requirementsToRecheck}`。可用处理策略为 `CONTINUE_OLD_EPOCH`、`QUIESCE_THEN_SWITCH`、`MIGRATE_AT_STABLE_CUT` 或 `REFUSE_ONLINE_MIGRATION`；每项策略明确谁承担旧队列、活动停止和外部资源结算，不能用一条布尔 `migrated` 表示迁移及现实效果全部完成。多个节点参与时，只有协调提交/fencing 与恢复日志保证不会同时接受两代写入，才声明跨节点联合切换；否则仅有局部状态机有效性。

切换先提交准确新模型与映射数据，再切换唯一可接受新输入的 owner/epoch；旧回调仍保留旧 Operation 结算，但不得自动影响新 activation。失败可在没有不可逆跨越时回到旧 owner；若新版本已向外提交不可补偿作用，走显式前滚/隔离，不借旧 snapshot 假装回滚世界。验收包含 activity 从旧 epoch 晚到、计时器同刻竞争、deep history 指向已删状态、正交区域扩容、持久消息重放和旧实体模型与新模型并存。
