# 数据源、权限、快照与分页

## 数据源、权限、快照与分页

**语义消费校核：** **联合快照与分页：** 单源分页游标只有该源真实声明的稳定性；不能把不同源的第一页各自标记current就证明全域原子切面。权限变动后，页内数据、下一页游标、总数与“缺失成员”都必须重新限制其披露和枚举覆盖。 实现或验证此用例时分别消费[跨源读取的观察切面、因果闭包与不可见参与者](../../../70-工程系统与演进/信息与生命周期/对象关系与配置基线.md#gift-joint-snapshot-closure)、[派生数据、索引和差分结果的披露资格](../../../50-执行运行与观测/权限与资源/工具秘密身份与披露.md#gift-confidential-derived)的权威交接，当前机制只拥有本地行为含义。

### 逻辑纯与真实读取分开

`RelationKernel`是已定义的纯数据变换。`SourceBinding`描述每个运行输入怎样取得：准确字段/类型与codec、真实来源和版本策略、可用能力、读取范围、相等与排序语义、输出完整性和生命周期。它不是每条源行的永久工程ID。

读取器处理路径或表，不向AI默认暴露完整原始数据。作者只改查询或源的明确控制；旧合格绑定可以复用。网络请求、文件扫描、数据库游标和向外发送分别是实际作用，不因结果最终是只读Bag就自动获准。

### 完整快照的具体规则

纯输入List已在当前函数调用中固定。文件源按实际捕获字节和成员建立输入；分块读取绑定内容版本。数据库单条语句是否提供所需一致性按实际引擎画像；多次语句/多页读取若要同一切面，采用合格快照事务或导出快照。Read Committed下每条语句各自一致，不能推出多条语句共享一个快照。

多个独立来源只取得各自固定版本时，结果明确绑定这个版本向量。原任务要求同一全局切面，则使用具备相应协调的提供者，或返回该一致性缺项；不能用相同墙钟标签证明强快照。快照仍存在也不维持永不过期的读取授权。

任一必需分片丢失时，不把实际取得行当成完整Bag。允许部分结果的另一个请求可以返回明确范围；当前完整关系根继续未完成。校验发现原生不合法值时，不通过过滤掉它们取得“成功”。

### 权限必须在用户回调之前成立

普通用户过滤条件不是访问控制。先取得当前执行主体可读的源域，再在其上执行作者谓词、比较器与聚合。一个会在秘密值上报错的回调，即使最终输出行被过滤，也可能泄露内容；因此谓词下推不能越过未经证明可穿越的安全屏障。

使用PostgreSQL RLS时核实际角色与owner/BYPASSRLS规则，不能以“表上配置过policy”代表当前连接一定受约束。输出聚合、缓存索引、存在性、错误文本和日志保留来源敏感性；count或groupBy不自动获得去标识授权。现在的设计提供信息流边界，不宣称完全消除时间/资源侧信道或多次合法聚合的推断；高保密场景继续使用相应隔离或专门隐私机制。

### 分页

只有明确的稳定顺序和源快照才能作为持续游标基础。游标绑定查询/参数、源版本向量、排序/codec、授权范围、位置及期限；它不包含长期凭证。多个完全相同行跨页时，位置可以带同键桶内已消费重数，不将相同行位置当新全局身份。

快照到期、排序规则升级或权限改变，返回需要重新同步；不能静默继续最新源。首次实现可以保留有限结果或使用既有目标游标，不要求先实现跨提供者永久分页。分页不是事件水位，后续持续更新采用下一节的代际协议。

## 联合读取、权限隔离与可验证游标的执行合同

`RelationReadRequest{principal,tenant,queryRef,params,sourceBindings,requiredConsistency,requiredCoverage,projection,sort,limit,deadline}` 必须区分 `READ_ONCE`、`REPEATABLE_SOURCE`、`CAUSALLY_CLOSED_CUT` 与 `ATOMIC_JOINT_SNAPSHOT` 的真实能力。读取返回 `ReadCoverage{selectedSourceSet,enumerationWatermarks,sourceRevisionVector,observationIntervals,excludedOrUnknownSources,consistencyKind}`；只有枚举域闭合、所需因果前驱在切面内且实际底层提供相应事务/版本保障时，才可签发强快照。跨独立 Provider 没有协调协议时，版本向量是可重放的**观察集合**，不是原子全局时刻；无法证明成员全集则全称结论为 `INDETERMINATE`，不是 `NONE`。

权限执行顺序：在源发现和任何回调执行前验证当前主体/租户及每个数据域；将原生可授权的查询推到安全边界之内；只在允许的行列视图上计算作者表达式。输出行、`count`、存在性、错误位置、耗时提示、自动完成、缓存命中与 AI 片段均属于披露表面。分页继续时必须**重新**核对授权 epoch 和真实源读取资格；冻结快照只冻结数据，不冻结授予权限。撤权后已有明文不能物理收回，应止住新披露并按保留政策清理受控副本。

`CursorBasis{sourceVector,enumerationScope,orderDefinition,queryDigest,limit,position,principalRef,tenantRef,authorizationEpoch,expiry,codecAndSchemaRevision}` 通过客户端不可伪造的签名/MAC 或服务端随机票据承载。游标不得含长期凭据，跨租户/查询/排序复用立即拒绝；对相等排序键用稳定次序加行内出现次序处理重复行，不能用 `OFFSET` 假定变化的动态数据集稳定。若后端只提供逐页弱一致，返回 `WEAK_PAGINATION` 且明确允许重漏，不能把它升级为强快照。服务断开、游标失效与授权撤销分别报告 `RESYNC_REQUIRED`、`STALE_SOURCE` 或 `ACCESS_REVOKED`，不得静默从新当前页接续旧页。

验收以两源互相引用但读到不同先后版本、同键重复行、分页间撤销权限、源消失、恶意修改游标和从计数泄露另一租户数据六种情形核对完整性/披露/失败状态。纯内存 List 查询无需网络身份票据，遵守真实授权边界即可；这个强游标合同只在跨请求持久分页被宣称时激活。
