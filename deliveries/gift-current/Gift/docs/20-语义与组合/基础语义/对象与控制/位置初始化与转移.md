# 位置初始化与转移

本页补充[控制流与存储寿命](控制流与存储寿命.md)中的相交能力；原章节继续拥有其已采用的有限语义。**当前选择：保留关键区分，缩小作者表面。** 所有权转移、原位初始化、地址稳定、复制和销毁不能混淆；不要求作者手动操纵每一种内部状态，move hook仅条件支持。

## 必须拆开的操作

| 操作 | 语义 |
|---|---|
| `take` | 转移所有权；源位置不再允许作为原值使用；不自动等于重定位或调用用户 hook |
| `clone_into` | 在新位置建立独立有效值，可执行用户定义复制行为及声明的失败／分配 |
| `transfer_construct` | 从仍然存在的源对象构造目标；源保留为合同定义的 moved-from 有效状态，之后仍需按规则析构 |
| `relocate` | 改变一个对象所占存储；需排除不允许的地址依赖与活跃借用，可有明确修复 protocol |
| `replace` | 用新值替换某个已有位置，负责旧值的资源释放 |
| `assign_from` | 更新现有对象内容，可复用资源，不一定改变对象身份 |
| `init_at` | 直接在最终指定位置开始初始化，不先构造另一份 T 再搬过来 |
| `destroy_at` | 在有效位置结束对象寿命；与释放底层存储是不同动作 |

C++ move constructor 的源对象仍然存活，与 Gift 默认 `take` 的消费语义不同；需要精确保留前者时使用 `transfer_construct`，不能靠同一个 move 关键字含糊带过。

## 位置状态与不变量

```text
Uninitialized
  -> Initializing(initialized_parts)
  -> Live
  -> MovedOut | Destroying
  -> Dead
```

初始化失败只逆序销毁 `initialized_parts`，再按实际存储 owner 释放；不能调用未初始化 T 的析构。重复 init、重复 drop、读未建立字段、把 Dead 当 Live 都必须被静态拒绝或在合法动态 API 中报告状态错误。

普通资源类型默认由结构推导移动性质。字节可重定位、显式用户转移、地址固定分别是不同性质。自定义底层声明无法由安全代码验证时，需要受限 unsafe 实现与清楚前提；不是随便写一个 `Relocatable` 标记就获得优化许可。

## Hook 与优化

用户复制、转移、赋值 hook 的效果是程序行为，编译器不能无依据删除、合并或改调用次数。没有可观察效果且有有效依据时可优化；要求 C++ 允许的特定 elision 行为，则由 compatibility profile 明确哪些事件可消失。

默认隐式 copy 仅限无用户可观察 hook 的结构复制。需要隐式自定义复制可以局部启用，但其分配、异常与资源成本必须进入表达式效果。显式 clone 永远不与 bitwise copy 混用。

赋值规定先求值新输入，再按操作合同处理旧对象。自赋值、别名源、分配器不匹配均有明确分支。强失败保证要求失败后源／目标不变；基本保证只要求恢复为声明的有效状态。只有具备准备—提交协议和必要回退资源时才能声明强保证，不能承诺回滚已发生的外部 I/O。

## 不可移动和目的地构造

`Pinned<T>`／固定位置属性限制的是被引用对象，拥有它的外层指针可以移动。建立内部自引用前就必须选定最终存储。初始化器取得 `PinnedSlot<T>` 的字段级写能力，在完整有效前不能形成伪造的 `&mut T`；完成后才公开合格 Pin／view。

返回固定对象采用 caller-provided destination 或稳定拥有句柄。严格要求栈中原位对象时，不能悄悄堆分配；目标 ABI 无法按该要求传递时返回缺项。`make() { return local; }` 不能凭“优化器应该会 NRVO”满足这条保证。

地址修复 hook 只能修复其合同所覆盖的引用。对象里更新 self-pointer 不能修复散落在其他线程、OS、设备或 C++ 库里的旧指针；存在这类外部观察时，应固定地址或要求显式注册／重定位协议。

Rust 的 Pin 是地址稳定协议，并不使所有对象自动不可移动，也不代替初始化正确性。[依据](../../../../research/sources/Rust与C++映射依据.md#research-r08) Rust lowering 必须使用真正的 field-wise 初始化及合格封装；TS lowering 可以提供逻辑身份固定，但不能把 GC 对象身份说成可供 C ABI 观察的稳定机器地址。

## 资源保证的域

受控 Gift 代码内可以要求确定性清理。导出到任意 Rust 代码后，安全 Rust 的遗忘／泄漏行为不等于非法内存访问；任意 JS 代码也可能丢失对象。因此“对象不会内存不安全”“最终一定 close”“不会泄漏”是三个不同保证。必须 close 的外部资源可使用运行域托管、线性 API 与显式结算；不能声称普通 Drop／GC 会证明所有外部消费者都正确结束资源。

## 再次修改与失效

存储位置、迁移政策或清理方法改变时，旧活动对象的借用、释放代码及未完成 close 继续由原拥有者处理；新对象采用新绑定。

- **自定义赋值 operator=**：保留替换与内容更新的差别；显式操作默认足够。与45合并计成本，不重复累计缺口。 硬边界示例：外部泛型算法必须以 = 调用你的自定义协议，且不能改为 trait 方法；[具体比较与出口](../../../../research/comparisons/Rust与C++能力比较.md#a17)。
<a id="cpp-gap-a43"></a>
- **自定义复制构造**：默认显式复制；保留复制成本/失败/副作用即可，不为覆盖C++而添加隐式copy hook。 硬边界示例：外部泛型接口依赖隐式copy事件或固定构造协议且不可改；[具体比较与出口](../../../../research/comparisons/Rust与C++能力比较.md#a43)。
<a id="cpp-gap-a44"></a>
- **自定义移动构造**：这是有条件的真控制差异；先偏移或原位设计，确需hook再定义显式迁移协议，不照搬所有特殊成员函数。 硬边界示例：对象需内联存储、可被普通容器迁移、迁移时自动修复内部指针，且不能改表示/间接存储；[具体比较与出口](../../../../research/comparisons/Rust与C++能力比较.md#a44)。
<a id="cpp-gap-a45"></a>
- **复制/移动赋值**：默认显式更新和所有权转移；保留allocator/失败保证；与17共用需求，不重复计数。 硬边界示例：必须与固定原生赋值语法/第三方generic接口配合，或必须保持源对象post-move状态；[具体比较与出口](../../../../research/comparisons/Rust与C++能力比较.md#a45)。

- **不可移动值的直接目的地构造**：保留原位初始化和地址稳定合同；不要把Pin单独称无损平替，也别把NRVO当强保证。 硬边界示例：必须原生按值工厂+不可移动类型+栈/内联存储，无新增间接层；C++同类型prvalue可满足特定情形；[具体比较与出口](../../../../research/comparisons/Rust与C++能力比较.md#a46)。
