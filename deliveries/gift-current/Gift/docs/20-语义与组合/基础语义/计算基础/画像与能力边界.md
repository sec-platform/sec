# 画像与能力边界

## 需求未决定实现时怎样工作

```gift
export fn estimate(value: Int) -> Int
  require value >= 0
  ensure 0 <= result && result <= value;
```

没有函数体的声明可以保存、导出设计或用于比较候选。这些条件没有唯一决定实现。下一步是补行为体或选取可检查的实现绑定；不是编译器任选一个返回值，也不要求先完成所有其他不相干定义。

仅含签名不具备的效果继续未知。纯度、输入域非空、终止和作者要求满足是不同判断。类型检查可以得到有限结构结论；生成所选输出时必须检查它的真实调用闭包。未使用的独立要求可以保留为设计，不能用一个未完成声明让全工程所有任务失败。

## 标准语义模块与基础语言的明确组合

基础语言只承担它已声明的词法、类型、表达式、函数、契约和诊断。状态、关系、流、数值等 Standard Semantic Module 在被明确选择时增加自己的结构和保持条件，但不能仅凭 import、文件后缀或陌生名称自动切换解释，更不能取得端口权限。组合版本固定在输入/锁中；同名语法、类型或扩展解释冲突直接诊断，不以加载顺序决定。

Standard Semantic Module 必须可以在不相交任务中完全缺席。只使用普通函数时不加载状态、流、AD 或数据库设施；只使用纯关系构造时不创建存储；选择一个模块也不会自动把其他模块串成“应用框架”。跨多个公共模块的完整应用组合由作者工程/库拥有。

事务型应用组合研究故意把持久对象、规则、变更、授权和提交后交付拼成完整形态，只用来检查这些公共边界能否组合；它不是 `gift.*` 作者画像，也不能作为基础语言 sourceLanguage。

## 普通工具和计算软件不以应用框架为前置

基础函数、模块、契约和效果可以构造完整计算程序，而不只是演示。网格、稀疏结构、求解和流的高层接口按真实库/画像绑定进入，目标实现可以使用受检的局部可变缓冲和并行，不要求作者把每个元素转换成工程实体。[计算结构与算法实现设计](计算结构与算法.md)提供现有文法下的完整网格例、有限库合同、算法与调度分离和连续变更。

该例没有增加保留词；`grid`是显式导入别名，`Grid/Shape2/Index2/Border`及五个调用由具体库合同定义，不是本包已发行的能力。把一个普通计算库加入当前作用域不激活任何完整应用框架。没有真实时间/浮点/资源画像支持时，不因写出一个名字就获得那些语义。

本章默认不可变是作者可观察的值模型，不是禁止所有目标使用可变内存的指令。计算域的依赖、内存与数值必须保留；任何完整应用组合研究都不是全部软件的骨架，发布口径按实际任务区分。

## 基础文法不是全部语言能力的控制上限

当前18个保留词、opaque修饰和已有产生式描述一个具体中立基础，不证明已覆盖所有源语言的能力，也不要求将各语言词表取并集。语义和意图在确定时可以是同一份作者内容；没有必要为了叫“意图”额外包装一个字段或关键词。

对不同语言的实际能力，按[语言能力映射与最小控制](../../作者语义/README.md)逐项说明公共含义、源/目标专有含义、作者入口、转换、保全和支持状态。类型、对象、异常、内存、并发、元编程、初始化和非源码属性均需要研究。不能因基础文法暂不含class就把目标class控制永久推给原生作者；也不能声称一个record已完整表示了对象继承和反射。

普通源先表达需要保持的行为与合同；编译器对已委派的具体实现自由作合法选择。源码中的Gift库导入选择复用定义，不必点名目标npm/Maven/系统库。精确目标结构或实现限制使用稀疏的类型化控制，并与作者源同一候选维护。控制draft的字段、解码、实际消费者与产物核对须同时满足；仅有可序列化对象不证明目标已执行控制。

原生源的关键词和语义按其真实语言保全；跨目标转换可以一对多、多对一，但保持所要求的观察。要求原文往返时还要保留具体语法、注释和未理解资产；仅生成等价行为不能冒称逐字还原。完整工程文件按资产合同管理，不要求都成为语言声明。

## 有限关系库与基础类型的接合

[关系查询](../状态关系与流/关系查询与维护.md)使用现有函数、块、记录、lambda和导入。`Bag<T>`与`Ordered<T>`是库抽象值，不是新增内置关键字。运行输入尚未赋值可以正常生成；纯关系构造也不触发数据库读取。

具体有限类型可从既定相等、排序和编码派生ValueOps；一般泛型或opaque值必须通过已定义的With入口传递有类型见证。不能把某次Int实例成功当作所有T都合法，也不能让一个忽略大小写的字典擅自合并仍可观察不同的Text值。普通代码中的相等规则不由导入库改写。

库的Bag输出不承诺列表顺序，错误参照仍有确定次序。`filter`回调为空效果不证明总定义；`take(...,0)`的上游是已严格求值的参数。SQL下推、增量配对和并行只能在相应保持条件成立时改变求值，不为实现方便改变基础短路、错误或契约。库发布与实现范围仍独立于这份规格。

## 选定标准语义模块与基础文法的边界

语言选择统一由[默认组合](紧凑表示与程序范式.md#合同标识默认语言组合与按需能力)负责，语义模块只定义自身语义和必要语法增量。新通用工程已具备有限对象语法；原基础专用模块继续使用原解释，两个版本不通过普通import切换。基础EBNF仍为基础子集的唯一文法，组合的读写规则明确包含对象增量，而不是宣称原文法已自动覆盖class。

[本地流](../状态关系与流/背压与事件时间.md)、[关系](../状态关系与流/关系查询与维护.md)、[状态](../状态关系与流/层级状态与事件.md)以普通库构造保存各自含义；[微分](../数值/自动微分与线性化.md)的F64和Space不会重载原Int。库有接口、方法有实现、目标能保持和运行有权限分别判断。更广对象、分布式时间或微分数学只有在实际支持表中明确承诺时才纳入；它们不阻塞不相交工具的实施。
