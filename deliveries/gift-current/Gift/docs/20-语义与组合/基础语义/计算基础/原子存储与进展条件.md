# 原子存储与进展条件

本页补充[权限与资源管理](../../../50-执行运行与观测/权限与资源/README.md)中的相交能力；原章节继续拥有其已采用的有限语义。**当前选择：保留原子语义与进展约束；复用目标库。** atomic≠lockfree，回收独立；不因std接口缺少而创建并行的自有原子模型/库。

## 原子化什么，不只是给 T 加个名字

```text
AtomicValue<T, ProgressPolicy>
AtomicView<'lease, T, AccessDomain>
```

T 必须有符合所选操作的值表示与复制语义。不能原子复制带独占资源、任意析构器或不合法位模式的对象；指针 payload 还需保留 provenance，不能普遍靠整数序列化恢复拥有关系。

原子值可由真实硬件原语、合格运行库或显式锁路线实现。锁路线仅在允许阻塞、重入／中断条件合格、跨进程域一致时选择。`atomic` 不意味着 `lock_free`，`lock_free` 不意味着某次操作 `wait_free` 或有墙钟时限。

硬性无锁、无分配、signal／ISR 可用、进程共享和地址稳定等要求分别检查。没有目标支持时报告缺项；不得用 mutex 冒充无锁实现。

## 已有存储上的原子访问租约

建立 `AtomicView` 必须证明对齐、存储寿命、访问范围、表示及全部可能并发访问者的协议。租约存续期间不允许不兼容的非原子访问或冲突访问宽度；共享 byte range 不是仅靠某个局部 `&mut` 就能排除外部线程／设备访问的事实。

Rust 目标已提供的 primitive 原子视图可以作为相应路线；泛型 Atomic 名字不能代替对该版本实际类型范围、表示与原语的检查。[依据](../../../../research/sources/Rust与C++映射依据.md#research-r02)[依据](../../../../research/sources/Rust与C++映射依据.md#research-r25) C++ `atomic_ref<T>` 同样有对象类型、对齐、寿命和访问条件，不是对任何已有对象都安全的开关。[依据](../../../../research/sources/Rust与C++映射依据.md#research-c09)

租约结束后恢复普通访问前，必须确认没有仍在使用视图的线程／回调。并发域跨进程时，当前进程独有的借用检查或 mutex 不足以证明其他进程遵守协议。

## 排序、CAS 与回收

内存序是操作合同。默认可以采用顺序一致，低层使用点可明确要求更弱的排序；load、store、RMW 和 CAS 的成功／失败排序分别验证，禁止将不适用的 release 语义赋给纯 load 等无效组合。

对于“至少提供这些排序约束”的要求，更强排序可以是合法实现但必须记录性能代价；对于要求具体可观察行为集合／litmus 结果的兼容请求，不以“更强通常更好”自动判定精确等价。

CAS 比较按选定的值／表示合同处理 NaN、padding 与指针身份，不默认套用普通用户 `==`。使用锁保存实际 T 时也必须遵守相同外部合同。CAS 成功不解决 ABA、节点释放后使用或地址复用；数据结构仍需真实的拥有权、hazard、epoch 或其他合格回收协议。

跨进程原子性不等于崩溃一致性、断电耐久或进程死亡后自动释放锁。共享内存初始化、版本、进程退出与 owner-death 恢复必须单独约定。

**语义消费校核：** **原子性范围：** 单进程CAS可以证明本地内存更新原子，但不替代持久写入者恢复后的实际围栏；对不相交纯值无需人为创建全域提交纪元。若等待队列取消后后台仍占资源，原子状态标记cancelled不能证明其费用、线程或远端执行已释放。 实现或验证此用例时分别消费[恢复后的权威代际、围栏与复写拒绝](../../../50-执行运行与观测/持久化与恢复/持久状态与存储协议.md#gift-fenced-writers)、[取消后的孤儿资源、额度归属与优先级反转](../../../50-执行运行与观测/权限与资源/资源核算调度与交接.md#gift-resource-orphan)的权威交接，当前机制只拥有本地行为含义。

## TS 目标的硬边界

JS 共享内存／Atomics 的可用存储和访问方式由 ECMAScript 与实际宿主共同限制，不能把任意 JS object 变成原地共享原子复合对象。[依据](../../../../research/sources/语言编译与目标工具.md#ecmascript-shared-memory)

满足合同的 byte-buffer 编码、锁协议或已取得的原生模块可以作为路线；无法保留对象身份、进展要求、地址、精度或宿主权限时明确拒绝。单线程事件循环上的“没有数据竞争”不等于跨线程原子 API；Promise 也不等于硬件内存屏障。

## 再次修改与失效

原子宽度、进展画像、共享成员或回收协议变化时，重核全部实际访问域；某个局部借用结束不证明外部进程停止，旧世代不能访问复用地址。

## 等待、通知与底层供给的选择

原子等待/通知属于同步协议，不是把原子值多加一个事件回调。优先使用目标上合格的标准库、成熟库或系统原语；库的等待对象、平台、时限和 no_std 条件必须与当前使用点相容，名字相同不消解差异。

等待者先以规定内存序读取谓词；不满足才进入具有“比较并等待”或等价注册后复查保证的等待协议。唤醒后重新读取谓词并复核当前取消/截止，不能把一次通知等同于条件成立或取得对象拥有权。提供者允许伪唤醒、选择任意等待者或不能保证公平时，接口保留这些条件；有更强公平/硬时限要求时另取实际依据。

所保护对象、等待键及共享存储在所有在途等待、通知和取消结算前保持有效；地址复用不能让旧唤醒误认新对象。跨进程等待必须由所有参与者实际支持的同步域承担；某进程私有锁不提供全局保证。超时返回不抹掉已提交的其他作用，通知缺失、对象销毁、进程死亡的恢复按所选原语另行规定，不虚构通用锁自动释放。

<a id="prebootstrap-concurrency-qualification"></a>
## 并发自由、弱内存与进展声明的目标准入

通用语言允许共享并发和原子能力，但每次启用固定实际目标内存模型、操作宽度/对齐、ordering、失败分支及回收方法。数据竞争自由、线性化、无锁、无等待、有界响应和公平性是不同性质；使用 atomic 名称或消除 mutex 不取得后四者。多字状态的不可分割要求不能被若干独立原子字段拼接代替。

弱内存优化按实际 happens-before 与原子规则检查，不能以 x86 样例通过代签所有目标。锁自由结构的回收要处理旧读者、ABA、地址复用和代际；发布新根后立即释放旧节点不因 CAS 成功而安全。线程暂停、抢占和 GC/设备保留可能影响进展/回收界，必须保留其真实假设。

首个自举可用明确串行/受锁的纯查询协调，避免为尚未要求的高并发引入复杂无锁机制；未来替换必须满足当前公开结果、取消、预算和缓存寿命合同。设计不限制程序只能单线程，也不以“通用自由”为由让未具资格的并发方法进入生产目标。
