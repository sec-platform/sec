# 危害防护与安全论证语义

<a id="gift-unit-safety-semantics"></a>
## 安全要求不等于异常处理

可选 Safety 语义/Assurance module 组织 hazard、scenario、causal path、exposure、control、safe-state、independence、residual-risk 与批准关系。它不是Kernel内置行业安全认证，也不是任何测试成功后自动附加的安全标签。领域风险标准、设备模型、目标用途和可接受风险由相应有权主体提供；[运行/恢复](../../50-执行运行与观测/持久化与恢复/README.md)及[授权/资源](../../50-执行运行与观测/权限与资源/README.md)仍拥有实际作用与责任。

输入固定受保护对象、系统/环境边界、危害事件与损失机制、初始/触发条件、暴露范围、严重性和不确定性、时域、检测/防护/缓解方法、响应资源、故障/共同原因、残余风险、采纳/撤销权限和需符合的标准版本/profile。没有概率依据就保留定性/区间/未知，不凭风险打分制造精确频率。

SafetyClaim/Requirement仍用现有Claim体系，增加的是领域typed关系而非第二Verdict或全局RiskManager。运行日志、静态类型安全、代码测试、模型内证明和现实安全论证有不同覆盖，不能相互代签。

<a id="safety-composition"></a>
## 联合防护与可实现安全过程

对每条危害路径明确防护在何时观察什么、在何处阻断/限制什么、依赖哪些电源/时钟/网络/软件/人/资源，及故障后怎样移交。两个声称独立的通道共享同一故障源时，不能相乘成独立成功保证；两个分别稳定的控制器作用于同一执行量时，按[联合控制](../../50-执行运行与观测/运行生命周期/README.md)的真实耦合与不变量检查，不从局部证书推出联合稳定。

安全状态可能是受控停机、有限运行、维持必要供给、隔离或其他领域定义状态。进入它是包含检测、排队、计算、下发、执行器和反馈的过程，需提前有资源与时间保证；失联/超时不是已完成转换的证据。危险动作有不可逆点时，把允许取消、停止新动作、等待旧动作、局部缓解与不可撤销后果明确区分。

有权自动委派可以定义允许的风险/控制范围；不强制每次合法动作都等人工确认。反之，运行权限或编译通过不能代替需要独立批准的风险接受。应急覆盖/人工接管必须保持其真实身份、权限、时效、冲突顺序、状态观察和旧动作结算；一个override布尔值不构成安全机制。

<a id="safety-evidence"></a>
## 证据与反例

对危害场景派生功能、边界、时序、独立性、失效检测、恢复与残余风险义务。成熟标准/理论/既有实现反例可提前排除错误设计；系统模型的证明在其假设内有效，向真实设备/部署扩展时补相交映射与环境证据。合格旧证据可复用，只因新增未相交模块不全量重验。

一个实际区别见证是“成功捕获异常”与“已阻止危险输出”：异常捕获发生在命令发送之后时，即使软件进入 catch，原设备仍可能行动。合法对照必须在真实阻断边界前拒绝，或有有资格的目标去重/停机/围栏/回执机制证明相应范围。停止命令本身也可失败或未知，不能靠名字叫stop判定安全。

模型抽象、省略通道、假定传感器正确、共同因果、故障相关性、部署配置和维修状态都保留为前提/缺项；Safety method不得将 unknown改为零风险。对反例的修复回到真正错误的规范、实现、方法或环境，不删场景或降低原目标直到通过。

**语义消费校核：** **安全证据独立性：** 设备控制的异常处理器与测试Oracle若共享同一危险假设，两个结果都PASS仍不足以证实防护有效。低信任模型或研究说明可以提供候选危险，但不能授权真实下发设备控制命令；物理响应必须取得独立且与时间窗口相符的观测。 实现或验证此用例时分别消费[关联证据、Oracle来源与共同失败不重复计票](../../60-保证与证据/验收/方法与独立证据-独立性可信基础与求解.md#gift-proof-independence)、[委派能力收窄、重定向与执行时再检查](../../50-执行运行与观测/权限与资源/授权与执行准入.md#gift-delegation-attenuation)的权威交接，当前机制只拥有本地行为含义。

## 演进与持续责任

更换Provider、控制律、模型、硬件、阈值、拓扑或运行范围只失效相交安全依据，但必须检查组合关系和公共依赖。允许的运行重配置按已有切换协议保护在途状态、回调与旧实例；回滚软件不抹去已发生的物理后果。

事故时先执行已授权且可实现的防护/责任移交，同时保留必要受限证据；删日志、清空临时目录或撤销凭证不能销毁仍用于追踪在途作用的唯一材料。结束声明分别包含效果、残余危险、清理/资源、后继责任和需跟进的未知，不把一个Settled标签当现实世界无风险。

<a id="design-c10"></a>
## 用途、保留、删除与派生数据

隐私实例把数据主体/类别、允许目的、处理者、共享对象、地域、保留期限、撤回和删除义务绑定到有来源/版本的Policy。用途或同意不是一次布尔开关；一次分析可读不等于可用于训练、第三方共享或永久日志。具体法律适用、合法基础和期限由真实有权政策来源提供，本设计不代填地域法规或宣称合规。

数据流记录从原始输入到索引、cache、trace、backup、特征、模型与导出件的派生边；删除请求逐域判断可定位删除、加密销毁、保留但隔离、或需要法律/运营例外。不能只删源表就宣称所有派生信息不存在；匿名化是否足够是有威胁模型和证据的Claim，不由字段移名证明。

授权撤回阻止新的目的不兼容处理及披露，已发生外部共享/训练影响按真实可恢复能力说明；不能虚构“删除按钮撤销历史”。保留/法律保全相冲突时由明确权威裁决并记录最小保留与访问限制，不让开发者实现随意选更方便一方。故障恢复及审计日志同样受最小必要披露。

**验证与反例**：源删而cache仍在、训练派生不可逆、backup恢复复活、目的变更、跨区域复制、撤回与保全冲突、去标识仍可链接。

**实际能力边界**：业务/地域法律政策和实际删除能力未取得；本轮没有法律合规结论或个人数据操作。

<a id="design-c30"></a>
## 工业过程与不可逆安全边界

工业实例声明工艺/设备对象、测量与校准、材料/能源单位、允许操作域、危害、失效模式、保护层、人工接管和不可逆点。具体安全等级、标准及许可必须由实际有权工程/监管材料绑定，不能从“工业”标签推导。控制软件、独立保护与物理联锁是不同责任，不因代码正确合并。

操作计划在dispatch前联立现场前像、有效校准、可用保护和授权；越过不可逆点后取消只能限制后继，不能宣称撤销已加工材料/能量释放。失联、传感失真、执行器卡滞和供电/网络故障按hazard model进入明确安全策略；零输出/断电未必安全，不能写死通用措施。

工艺变更、固件/传感器替换和运行环境改变触发相交资格重审；仿真与试验支持各自覆盖，不代签现场长期安全。恢复先确认现场状态和隔离条件，保留事故证据，禁止旧writer/旧工艺版本自动继续生产。

**验证与反例**：校准过期、保护层失效、材料不可逆加工、旧工艺重启、仿真通过实物失配、紧急停机后恢复资格。

**实际能力边界**：实际工业设备、危害等级、法规/标准与现场证据未知；不作操作或安全认证。

## 医疗与公共安全系统的职责限制

高风险实例固定使用目的、对象/身份、专业术语/数据来源、适用人群/场景、输出是信息/建议/自动动作的哪一种、错误代价和所需专业/监管责任。治疗/风险判断语义、阈值与资格必须由真实专业依据及有权主体提供；本通用语言规范不补写诊疗政策、患者参数或声称医疗合格。

系统分离数据质量、算法计算、临床/现实推断、人工审核和实际干预。缺数据/域外输入/冲突证据输出明确不确定性或转交，不允许因生成器想要total Bool便强选结论。身份错配、单位错误、时间过期和来源不可信各有拒绝；强制介入权限不能由软件预测分数自生。

更新涉及模型、知识、术语、设备、运行环境和适用人群时，按风险声明重核实际证据和责任。失败恢复要保留已采取动作、通报/人工接管与纠正路径，不能回滚数据库就说现实干预未发生。隐私、保留和审计按真实Policy，公开报告不泄露敏感主体。

**验证与反例**：身份混淆、单位错配、域外样本、过期知识、建议当执行、缺证强判、更新后外推及历史干预不可逆。

**实际能力边界**：医疗/公共安全专用政策、专业/监管资格和现实数据未取得；不实施医疗动作。

<a id="design-c35"></a>
## 强保证、公理和现实认证

强保证实例必须给精确Claim、对象/版本、观察域、允许公理/环境假设、证明或测试方法、TCB、所需独立性及失效条件。安全、隐私、功能正确、实时、法规/认证是不同Claim；一个类型证明或单元测试不能代签监管认可或现实设备安全。

形式checker只对精确proof对象及公理核验，产生proof的编译器/模型不自动受信。环境事实不能因被写成axiom便被宣布现实为真；需要独立来源时把它作为未履行义务。抽象模型与目标/实际系统之间有明确模拟/细化关系及覆盖，抽象通过却遗漏Fault/调度/外部作用不合格。

要求证书或法律认可时，签发主体、适用标准版本、地域/产品范围和真实有效性由权威记录输入；设计和生成代码不创造证书。事实/规则/目标变更、漏洞或来源撤销使相交资格重新判断，旧记录保留历史解释。无法取得强证据时普通低风险计算是否继续由已接受Policy决定，不擅自把所有工程都强迫等待最高级证明，也不降低明确要求的强保证。

**验证与反例**：公理伪装现实事实、checker由同候选改写、抽象漏Fault、类型PASS代证认证、证书范围不符、版本变化后沿用旧证据。

**实际能力边界**：任何监管/安全/法律认证和全面形式证明都未由本次获得。
