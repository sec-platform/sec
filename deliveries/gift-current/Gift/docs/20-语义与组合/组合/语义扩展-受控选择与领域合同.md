# 受控选择与领域合同

## 把隐含选择提升为受控变化

前述扩展层次处理语义表达，下面按实际兼容损失选择演进动作；不是新建七种平台对象，也不是把所有变化都叫Binding变化。

| 变化 | 允许局部完成的条件 | 必须检查的额外边界 |
|---|---|---|
| 同机制参数 | 参数仍在已接受域内，观察与保证保持 | 生效阶段、相交缓存、资源、旧实例与临时恢复 |
| 同合同供给 | 值、错误、时序、取消、资源、隐私、生命周期及公开ABI均保持所需范围 | 实际旧消费者与反例，不以同名接口判等 |
| 普通新程序 | 既有语言和库足以表达 | 普通类型／行为检查、来源和所请求保证，无须扩核 |
| 局部新语义 | 新区别由 SemanticModule 接口完整传递 | 定义包、真实分析／降低、未知保全及旧含义迁移 |
| 新跨模块关系 | 各局部合同已有，但共同条件尚未表达 | 共同资源、初始化、进展、效果与证据的关系 owner |
| 新运行责任 | 引入远程I/O、驱逐、故障隔离或异步生命周期 | 接口可能必须升级；不把不可保持的同步借用伪装成透明替换 |
| 根规则变化 | 原引用、授权、组合或证据语义不足 | 由当前有权规则批准后继，独立恢复路径及不可逆状态处理 |

提升一个硬编码选择时，先取得当前有效行为和真正消费者，区分应保持的合同与已有缺陷；不把缺陷永久登记为兼容要求。再在原owner中定义其类型、范围、默认、解释与实际控制方法；当前合格实现成为一种供给而不是特权旁路。接通编译、执行和保证后，原直接调用改走同一选择结果；尚未改完的消费者明确留作缺项，不允许配置界面先宣称全域生效。最后检验未配置时的合法行为、显式同值固定、局部覆盖、失败和恢复，并删除确已无人消费的旧选择入口。

新增维度不得默认使所有查询、程序和客户端重新配置；影响来自真实读取和共享约束。若新的观察或失败语义确实穿过多个owner，应修改这些合同而不是用opaque载荷藏起来。[机制演进](../../70-工程系统与演进/演进与实施/实现语言与机制演进.md)给出身份、内存、边界和语言选择的具体判据，[控制案例](../../60-保证与证据/验收/控制与演进区别见证.md)检查局部扩展与必须改共同合同两种正常路径。

解释器、求解策略、证据方法和授权规则本身也允许有权演进。一次任务固定实际解释映像与授权根；新规则不能先解释自己有权，方法不能通过无限请求上一级方法来逃避当前未决。改变根解释沿现有升级或独立恢复路径处理，不把它叫作永恒不可改的常量，也不作为普通配置热切换。历史解释可读与当前执行许可分别维护，具体版本迁移由[兼容与退役](../../70-工程系统与演进/演进与实施/兼容迁移/迁移切换与退役.md#authority-bearing-format-migration)拥有。

## 发现元数据与可选领域合同

[IntentFacetDescriptor](../作者语义/意图描述与作者投影.md#facet-descriptor)可由普通作者库/定义owner提供；仅有可发现参数/表单不要求SemanticModule。[可选交互、学习、因果与安全合同](../可选语义/README.md)在实际方法启用时沿本页全部相交边接合；合同设计、装配、目标映射、Evidence与生产采用保持分开。旧snapshot解释/未知保全及真实有状态Provider继续按本页原规则，不因元数据目录新增而重写历史或禁止领域数据库。
