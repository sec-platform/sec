# 执行许可、解释资格与激活

## 扩展代码的执行许可与解释资格

新域的结构读取器、生成器和分析器继续沿原接口扩展，普通新函数无需核心新增kind。不可信工具通过执行隔离，只说明其作用范围受约束；它产生的规则、观察映射或证明不能因此直接进入可信推理基础。定义扩展保留实际解释，任意公理和未验证规则按[证据接纳](../../60-保证与证据/保证/解释与证据接纳.md)成为准确假设或缺项，不靠`trusted`字段自签。

新性质由自身合同明确所需观察、量词、概率和环境，匹配[相应保持方法](../../30-实现解析/性质保持与开放环境.md)，不以每次输出合法代替所有性质。合格现有语义、直接原生实现和已知证明可继续复用；只有相交强保证缺证据时受限，不把开放扩展变成所有世界理论必须先审核完的全局前置。

<a id="extension-distinction-witness"></a>

## 用可观察区别决定扩展哪一层

五层产品边界的具体判据是是否保留本次要求的可观察区别，而不是行业名字、插件数量或注册接口是否足够长。先取得要表达的新对象/行为、允许上下文、已接受观察和所需保证，再检查已有定义组合、原生直接绑定及现有语义方法。

能够给出由现有构造组成的准确实现与保持依据，就采用普通 Definition/作者库；多个通用消费者确需识别新的可观察语义时，进入 SemanticModule，并由 SemanticDialect/接口/摘要/lowering 精确传递；只有系统级共同不变量仍不足时才修改 Kernel。所有路线都保留独特算法创作能力，不把每个新业务变成写编译器。

认为必须扩核时，给出一对在现有接口中无法区分、但被新要求明确区分的情况，并定位丢失处。例如仅传“纯结果值”的接口无法区分两个返回同值而资源移交责任不同的调用；若已有效果/寿命接口能保留区别，应接入它而不是立即新增核心。真正的共同引用、作用或组合模型缺少这一区别时，才形成有范围的核心修订、旧含义保持与迁移方案。不能宣称已证明所有可能编码均不存在；有限反例证明的是当前合同不足。

新摘要/传递规则按[语义摘要](../../30-实现解析/组合前提与进展闭合.md#domain-summary-contract)说明覆盖和方向，注册成功不获得推理资格。新增代码可在允许的隔离环境作为候选验证；缺少其保持依据只限制依赖该保证的使用，不阻止普通定义、保全导出和无关根。规范/解释升级由实际有权采用关系固定，动态发现新插件不热改旧字节。

<a id="extension-conservative-admission"></a>

## 不相交扩展与解释域变化分别验收

在固定旧输入/画像上加入不相交扩展，应保持旧名字解析、默认、方法选择与规定产物；若新增重载、通配导出候选或默认规则会被旧输入读取，则不是不相交变化，必须按原真实依赖重新判断并取得所需采用。只追加API而不删除名字，不能据此签发行为兼容。

准入同时检查旧输入在新映像上的保持，及新输入到旧读者的保全/拒绝。未知字段不得默默丢弃；首次导入可只保全或有限调用，不以默认值补成managed。解码/生成器的初始化、错误、日志、缓存与析构也在其真实执行/披露边界内；权限元数据不能自授宿主权。所需消费者和推理资格仍沿本篇现有表与证据接纳，不增加第二个扩展登记系统。

<a id="extension-interpretation-activation"></a>

## 未知内容的保全、解释与激活

未知定义的原始内容、来源和所在解释上下文应按其实际保留合同保存；当前不能理解不表示没有含义，也不表示可以执行。保全、结构读取、新含义识别、接受该含义和取得实际作用权限是独立步骤。升级后终于认识一个旧字段，不能把旧保存时间当成作者已接受了新效果。

**U0 固定旧基础。** 捕获原字节、已接受的解释映像与可用声明；没有旧解释资格时，保留未知，不伪造“与旧版等价”。解析器执行本身仍按信任和资源边界处理；读取不可信内容不执行其构建脚本、导入初始化或迁移代码。

**U1 有界解释比较。** 新映像在私有候选上解释相同内容，列出新识别的值、作用域、默认、类型、效果、资源与公开行为。结构Schema没有改变也可能改变这些含义，故格式修订不能代替语义修订。原始字节身份与规范化语义身份分开；签名过的原件不经格式化后继续冒充原字节。

**U2 判断采用。** 已有明确迁移政策与相交保持依据允许自动采用时，在该范围内形成新候选；新增作用、扩大对象集合、提高权限需求或改变硬保证时，保留准确差异并取得要求的采纳。这里不把人工批准设成所有升级前置，也不允许新解释器为自己补授权。

**U3 连接真实消费者。** 核结构读取、语义验证、方法选择、降低、编辑保全、诊断、保证、目标与恢复工具的实际能力。某个方法尚不支持时只阻塞依赖它的用途；通用查看、原件导出、无关修改和合格旧解释仍可继续。未知节点不得被优化器当无效果而删除。

**U4 在原作用点准入。** 被接受的新解释进入相应新锁／映像，不热换旧任务。实际写入、加载或执行再次核当前权限、目标前像与范围；旧客户端、离线保存和新规则识别均不能越过此点。候选失败时旧字节与已有效果分别保留，不能用回滚二进制抹掉新状态。

完整往返验证包括读取、局部编辑、格式化、导出、保存、签名和再次读取。仅证明某decoder保存未知字段不够；经JSON转换或逐字段重建可能失去原格式的信息。协议实例如[未知字段来源](../../../research/sources/语言编译与目标工具.md#open-control-evolution-sources)，不是要求所有工程采用Protobuf。

<a id="unknown-occurrence-fidelity"></a>
**未知值的存在与相对位置也属于保全合同。** 一个 decoder 可能把不认识的枚举值移入 unknown-field 集合，而已知字段 getter 返回默认值；因此“调用 getter 得到一个合法值”不能证明原输入就是该值。对有序重复字段，只保留未知值集合还不够：原序列 `[0, 2, 1, 2]` 可能在旧解释下重编码成 `[0, 1, 2, 2]`，值没有全丢却已改变顺序。该具体反例及适用格式见[枚举与往返依据](../../../research/sources/语言编译与目标工具.md#enum-occurrence-preservation-sources)。

进入语义消费前，按实际 schema/decoder 区分字段不存在、显式默认值、未知 variant 与已知合法值。编辑/重编码按请求的 requiredFidelity 保持未知出现的位置、重数、原字节或可证明等价的表示；不能通过排序 unknown 字段、自造默认值或只复制已知成员假称无损。若现有 decoder 无法给出所需 occurrence 信息，保存受保护原载体并使用有范围/前像的局部编辑，或拒绝相交重写；无关查看与原件导出仍可用。Schema 能读、原字节保留、已知子集可操作与完整语义等价分别声明，不一律把保全未知升级为已解释。
