# 交付语义公共合同

本页集中维护任意交付形态共同消费的完整性、作者/消费者边界和共同数据规则。它不定义封闭的产品家族，也不要求作者选择预置模板；常见技术形态只是在相交合同之上的阅读投影。

<a id="gift-unit-fc3de891eb2355f1aa65579f2f2f8dd3"></a>
## 交付设计完整性合同

“成品”在这里表示一次请求要交给真实消费者的完整结果闭包，而不是新的 Core Entity。其身份仍来自被交付的语义根、Target/Artifact、配置和实际采用关系；本页只规定怎样判断相交设计是否闭合。

### 完整设计必须闭合的十二个方面

对一个具体交付，以下方面由当前作者源、可复用定义、Target、Host、Provider 或明确外部前提共同确定。不适用必须能够从任务和合同推出，不能用省略表示“随实现决定”：

1. **意图与主体**：交付什么准确主体，哪些 Meaning/Requirement 已固定，哪些选择仍委派。
2. **公共消费边界**：消费者通过什么调用、值、消息、流、界面、文件、设备或安装关系取得结果。
3. **输入与表示**：类型、单位、编码、顺序、身份、快照、别名和不可信输入的解码边界。
4. **正常行为与进展**：合法输入产生什么，可等待、分批、持续或无终点到什么程度。
5. **实例与生命周期**：创建、就绪、活动、暂停、关闭、卸载、重启以及定义/实例身份关系。
6. **失败、取消与恢复**：拒绝、协议错、资源故障、取消、未知效果、重试与查回分别怎样表示。
7. **并发、顺序与一致性**：共享主体、并行范围、顺序、背压、幂等、原子边界和竞态如何处理。
8. **资源与权限**：所有权、借用、预算、秘密、文件/网络/设备能力和真正授权位置。
9. **宿主进口与隔离**：哪些依赖内部闭合，哪些由消费者提供；不可信代码需要什么物理隔离。
10. **Target 与 Artifact 闭包**：公开符号、代码、配置、资源、清单、依赖、构建/装载前提及最小完整成员。
11. **兼容、升级与再次修改**：语义、接口、实现、数据、目标或运行实例改变时哪些消费者失效以及怎样迁移。
12. **验收与 Evidence**：哪些可静态判断，哪些必须运行、测量、形式检查或真实宿主验证；设计稿不能自签运行成绩。

这些责任可以由一个小定义完成，也可以跨多个 owner 分担。完整性要求的是**信息与责任闭合**，不是固定字段数、文件数或模板命中。

### 四种完成状态不能合并

- **设计完整**：本次适用的含义与边界无需要实现者猜测的空洞。
- **目标/实现完整**：实际方法、Target、依赖、资源和适配能够形成所需 Artifact 闭包。
- **验证成立**：针对准确 subject/revision/environment 得到所要求 Claim 的 Evidence。
- **现实采用成立**：安装、部署、运行、发布或其他外部作用已按真实 Operation/Readback 结算。

规范包可以设计完整而没有运行实现；生成源码不等于已部署；一个运行实例成功也不自动证明其他目标、配置或 Claim。

### 交付形态是已有合同的组合，不是固定家族

一次交付的“形态”只是一份基于现有 owner 的选择视图。至少要能追到实际相交的引用：

```text
author/semantic roots
  + public consumer boundary
  + lifecycle / state / time / ordering requirements
  + allowed effects / permissions
  + implementation Binding(s)
  + Target / ABI / host assumptions
  + Artifact membership / imports
  + requested Claim / Evidence scope
```

这不是要求新增一个永久 `DeliverableDescriptor` schema。CLI、Workbench 或 API 可以按任务生成相同信息的只读 Projection；唯一事实仍在原 Definition、Requirement、Binding、Target、Artifact、Operation 和 Claim/Evidence owner。

由此得到三个硬规则：

1. **名字不选模板。** `web`、`service`、`plugin`、`firmware`、`trainer` 等词不能触发隐藏 runtime、数据库、网络、Provider 或默认配置。
2. **能力按差额组合。** 同一交付可同时含库接口、后台作业、UI、设备或迁移；每一面只引入自己的真实依赖和保证。
3. **未知必须留下。** 缺失 Method/Provider/Target/权限/Evidence 时返回准确 Needs/Unbound/Unknown，不生成空实现或把要求降级。

### 公共失败表示原则

消费接口必须区分合法空结果、业务/语义拒绝、协议拒绝、取消、资源/宿主故障及可能已发生效果但结果未知。异步完成只说明对应异步值已结算，不自动证明磁盘落盘、网络对端接纳、设备完成或外部事务提交；最终点由相交 owner 定义。

现实作用使用稳定 Operation/Attempt 与可查回状态；查询结果不能靠重复副作用请求“猜”出来。真正违反目标语言编程合同的不可恢复异常可以沿宿主异常机制传播，但不能成为可预期运行失败的唯一通路。

### 机械结构只校验引用闭包，不校验产品分类

文档/编译器可以机械拒绝：引用不存在、公开主体无法解析、Target 根缺成员、同一必需路径发生冲突、外部进口未声明、准确依赖/版本不可取得、需要现实作用却没有相交 Operation/Grant、需要某 Claim 却没有方法或 Evidence 计划等。

它**不得**要求“每个产品必须有 `model/<family>.json`”“必须存在同名 TypeScript namespace”或“36 个根全部有实现”。这些是旧冻结范本的实例结构，不是当前架构不变量。

## 作者成果与交付边界

### 独立决定只维护一次

作者成果是否优秀不由文件短、节点少或术语高级决定。独特可观察决定应只有一个可写 owner；普通复用不迫使调用方读取私有实现；失败能定位到真实缺项；目标交付仍可被独立消费者使用。新管理对象、语法、文件或服务都必须有实际 consumer。

同一成熟能力可以由原生库、作者定义或 Provider 满足。Gift 的价值来自准确 Meaning/Requirement、实现选择、局部变化、目标闭包、受控作用和可解释 Evidence，不来自把成熟代码改写成自己的格式。

### 作者成果有三种常见情形

**完整复用。** 既有定义/库/总成已满足要求，作者只固定准确引用、目标和必要配置。

**只写差额。** 已有行为可复用，只维护确实改变的参数、公开名、边界、映射或目标差额；没有差额时允许零适配。

**新行为。** 由现有语义能够表达时，作者写规则/算法/状态/关系；表达不了的真实区别先进入 Semantic extension 判定，而不是用自由字符串冒充已支持。

三种情形可以在同一工程并存，不能被目录名强制拆成互斥项目类型。

### 必须分开的四个公共边界

| 边界 | 真实拥有者 | 不能自动推出 |
|---|---|---|
| 作者模块公开定义 | 作者/模块合同 | 已存在运行函数、远程端点或现实写权 |
| Requirement 暴露的逻辑主体 | 定义/Requirement | 主体已实例化或所有私有成员可见 |
| 目标程序消费接口 | Requirement + Binding + Target | 相同类型即拥有相同错误、顺序、资源或安全性质 |
| Artifact / 发行与宿主进口 | Artifact/Target/Host | 文件存在即已安装、外部依赖一定可用或已获权限 |

公开定义名、逻辑槽名和目标符号可以有显式映射，但不是默认同一身份。库保留有合同的宿主进口可以是完整库；请求独立运行时，相交进口必须真实提供或明确成为部署前提。

<a id="deliverable-shape-composition"></a>
### 形态由正交约束组合

不要维护一个全局 `mode` 或封闭 `ProductKind`。按实际任务组合：消费方式、同步/异步、生命周期、状态/持久性、并发/顺序、时间/实时、效果/权限、拓扑/隔离、Target/ABI、依赖封闭、Artifact/发行、迁移/恢复和 Evidence。

常见“库、CLI、服务、Worker、Web、流、固件”等只是这些轴上的高频组合。它们可以作为文档导航或生态 Profile，但 Profile 必须有准确 identity/revision，不能改变原 owner 的语义，也不能让未选择的能力进入工程。

### 作者配置不能代替实现证明

作者可以固定硬要求、允许集合、偏好或委派自由；实现侧只能在合法候选里选择。公开协议、宿主能力、资源/隐私或运维责任发生变化时，即使业务计算相同也必须重新判断相交合同。默认值必须来自准确定义/采用关系，不从环境、历史会话或求解失败补造。

### compiler 交付最小且完整的消费闭包

编译/生成应能回答：谁通过什么入口消费；输入/输出/错误是什么；初始化/关闭由谁承担；哪些依赖内部闭合、哪些留给宿主；哪些文件/符号公开；哪些 Requirement/Claim 仍缺供给。成熟实现完全匹配时允许直接复用或重导出；只有编码、错误、生命周期、隔离、ABI 或稳定公共门面存在真实差额时才生成适配。

一种交付新增时不应重新创造业务算法。只变消费边界只重核相交边界；共享 Meaning 改变才传播到所有真实消费者。

### 面向使用者的视图不是第二写源

作者视图、解释视图、实现视图、运行视图和 Evidence 视图都从同一准确对象投影。已知修改回写唯一 owner；生成视图不保存一套可独立漂移的“当前产品定义”。

### 冻结范本只做校准

成品形态冻结范本和开发成品冻结实例可以用来构造固定验收载荷，检查一组边界能否闭合。它们的 `definitions.json`、`model/*.json`、路径、默认参数和 TypeScript 签名都**不是当前作者入口**，也不限制未来组合。

### 作者载体不是消费形式

结构化源、原生源码或其他表示描述“作者怎样维护 Meaning”；库、可执行文件、UI、设备镜像或部署描述“消费者怎样取得结果”。两者是不同关系。采用结构作者源不要求所有目标暴露结构模型；直接维护原生工程也可以生成任何合格交付。

### 原生供给与性能后继

已有源码/库满足合同就直接采用，不复制同义实现。更快方法必须保持要求的语义、精度、错误、寿命、权限与公开进口；无法保持时是不同候选而不是透明优化。

### 设计完整不能被结构合法代替

存在名字、JSON、接口或目录只能证明表示可解析。必须能够追到相交 Meaning、Requirement、实际 Method/Binding、Target/Artifact、生命周期、失败/恢复和 Evidence/现实作用边界，才能声明对应范围闭合。

## 交付的共同数据与完整性

<a id="author-value-reading"></a>
### 共同作者值与目标类型读取

作者结构值按其真实 dialect 无损解码；布尔、整数、文本、字节、单位值、引用和不透明外部身份不能仅因宿主语言表示相似而互换。字段关系、范围、正负、顺序和硬限制由所属语义 owner 判断；结构合法不证明语义满足。

目标表示可选择不同编码，但必须有显式无损/受限映射及失败规则。宿主的小整数、JS `number`、设备定宽整数和数学 `Int`不是默认等义；无法保持所需值域的目标应被拒绝或采用明确的受限 Requirement，而不是静默截断。

### 作者源直接表达原意图

作者只维护独特 Meaning、Requirement、公开定义及必要实现/资源选择。复用标准语义模块或生态定义时通过准确 identity/revision 引用；默认在定义环境中有来源。不存在“因为产品叫 Service 就自动得到端口、数据库和重试”的隐式补全。

### 精确值与交换编码

每个跨边界编码必须定义字节/文本格式、单位、顺序、重复项、身份、预算和异常输入行为。外部 JSON/协议输入先做边界解码再进入可信结构；重复键、无效 Unicode、超界长度、歧义数字或隐式归一化是否允许由该 wire/profile 明确规定，不能从内部类型猜测。

合法空结果与未取得结果分开。错误至少按所属合同区分语义拒绝、协议/解码拒绝、资源/宿主故障、取消和效果未知；不得统一压成 `null`、空数组或“成功但无内容”。

### 身份、预算与效果

请求关联 ID、对象 identity、幂等键、Operation identity 和 Artifact identity 不是同一个东西。幂等资格必须绑定完整意图、调用者/作用域、载荷与有效期；同值结果不能证明历史作用已发生。预算可以收紧接纳范围，但不能在接纳后偷偷降低已固定的正确性要求。

外部作用沿原 Operation/Attempt/Readback 记录真实分项；顶层失败不能抹掉已发生的效果，顶层完成也不能省略要求的验证。

### 交付完成不是一个布尔值

每个所选根分别拥有设计、实现、Target、Artifact、Evidence 和现实采用状态。联合交付只有必需根和共同不变量都满足才能宣称联合完成；独立成功结果应保留，不被一个相交缺项全部抹掉。

### 选择如何进入编译器

Requirement 固定含义和硬条件；resolver 选择满足条件的 Method/Provider 并封存 Binding；lowering/target 形成目标表示；Artifact owner 封存成员；Assurance 评价准确 Claim；Execution 只在请求且获准时产生现实作用。语义缺失、实现缺失、目标缺失、权限缺失和 Evidence 缺失必须保持不同诊断。

### 演进

只改默认、只换实现、改公开接口、增加交付根、改变持久状态或现场协议的失效范围不同。系统按真实读集/消费者和兼容关系传播，不因同属一个“产品家族”全局重建，也不因文件没变就复用已失效的资格。
