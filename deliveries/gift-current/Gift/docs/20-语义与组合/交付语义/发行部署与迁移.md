# 发行、部署与迁移交付边界

本页维护“已有 Artifact 或持久状态怎样进入/离开现实环境”的共同合同。安装、部署和迁移都是现实作用，但它们不构成业务模板，也不会因某个应用形态出现就自动实例化。

<a id="gift-unit-ebf9af0c2a5b587185938ee41b7b75a7"></a>
## 安装、发布与部署组合

**语义消费校核：** **静态产物与现场代际：** 作者的业务部署流程可以利用ArtifactSet和ReleaseSnapshot，但实际已部署实例、存储格式和灰度流量另需观察。旧新消费者仍共存时只对可达组合承诺兼容；一个环境回滚成功不能代签整个业务恢复到旧物理状态。 实现或验证此用例时分别消费[ArtifactSet、发行引用与现场运行的三个不同完成条件](../../40-目标与制品/目标/交付消费合同与发射.md#gift-artifact-qualified-release)、[灰度发布中的读写兼容矩阵与不可逆分界](../../70-工程系统与演进/演进与实施/兼容迁移/迁移切换与退役.md#gift-mixed-release-compatibility)的权威交接，当前机制只拥有本地行为含义。

### 安装/发布

安装输入必须是准确 Artifact 成员、目标环境/架构、预期现状、权限与系统集成要求。路径、摘要、可执行位、许可、依赖和目标兼容在作用前核对；包签名只能证明其声明范围的来源/完整性，不自动授予提权或行为资格。

准备、验证、采用切换、健康确认、清理是不同事实。只有提供者真实支持的原子指针/事务可以作为原子切换；跨多个系统时采用准备/发布/恢复协议，不能把“主要文件复制成功”称整体成功。响应丢失先 Readback 当前采用状态与 Operation，而不是重复安装。

卸载只删除本安装拥有且已满足保留/占用条件的成员；用户数据、共享依赖、仍被旧实例占用的代码和外部服务不会因“卸载产品”自动删除。回滚需要旧 Artifact、当前前像、数据/协议兼容和权限，不能用“上一版本”这个名字猜目标。

### 部署

部署计划固定 Artifact、节点/运行目标、配置/秘密引用、资源、健康、路由/发现和切换方式。规划凭据不等于执行时 authority；运行前重新核实际目标身份与 Grant。

新实例 ready、路由已切换、真实请求已到达、旧实例已排空、旧资源已释放是不同阶段。没有路由/共享端口/调度能力时不能声称零停机；多副本、容错和高可用也必须由实际 topology/Provider/Evidence 支持。

取消部署不能假设撤销已发生的切换或外部效果。部分副本成功、未知旧实例、健康指向旧版本、权限撤销和回滚失败都按原 Operation 分项结算。

### 安装/部署是条件能力

计划本身可以是完整交付，但“现场已安装/部署”必须有实际作用与 Readback。日志、指标、告警、备份、TLS、账号、数据库、容器、Kubernetes 等都只在 Requirement/Target 需要时加入；部署名称不触发默认基础设施。

## 数据与配置迁移

迁移首先是**明确的旧 Meaning/Schema → 新 Meaning/Schema 转换与采用关系**，而不是“有一个 migration 文件”。Plan 固定源/目标 revision、范围、变换、保持量、拒绝条件、实际 Provider 能力、并发/停机前提、验证和切换/恢复策略；纯 plan 不产生现场写入。

常见路线包括停机转换、影子准备后切换、兼容窗口、双读/双写或分阶段 backfill。系统不预设一种“最佳迁移”；选择必须满足实际一致性、容量、可用性和 Provider 能力。多个系统没有共同事务时不能假装全局原子。

逆迁移只有在信息可逆、目标状态没有引入不可映射事实、实际写入历史满足兼容条件且旧实现仍可正确消费时才存在。回滚代码/Artifact 不自动回滚数据、队列、外部事件或现实作用。

迁移执行沿 Operation/Attempt 保存分项状态；回执丢失先查询活动 schema/指针/对象与原操作。重复 apply 不能把已转换过的数据再次转换。中途失败只清理本次拥有且确定安全的影子对象，不碰未知同名数据。

配置迁移、数据库迁移、文件格式迁移和远端对象迁移共享 Meaning/compatibility 原则，但不能互相借 Provider 的事务、锁、快照或恢复保证。

## 冻结实例角色

旧 `Installer/Deployment/Migration` 样本中的保留数、副本数、批大小、具体 schema 与服务只用于固定压力载荷，不是当前默认参数、部署平台或迁移算法。
