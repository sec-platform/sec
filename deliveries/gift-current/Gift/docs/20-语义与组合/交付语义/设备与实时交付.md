# 加速器、设备驻留与实时交付

本页维护接近硬件边界时不可被普通“函数生成成功”吞掉的共同责任。GPU/加速器 kernel、固件和实时任务只是高频技术投影，不是 Gift Core 内置业务或固定产品类型。

## 加速器计算边界

加速器方法必须固定输入/输出值域、布局、对齐、别名、地址空间、同步/队列、设备能力、错误、结果资源寿命和 host/device 数据移动。提交只证明设备工作被接受，不证明执行完成；取消也不证明设备已停止访问内存。只有真实 fence/readback/Provider 状态可以支持相应终点。

设备方法不满足时是否允许 CPU/另一设备回退由 Requirement 决定；要求“必须在设备执行”时不能透明回退。性能比较必须包含传输、排队、同步、编译/缓存和资源释放，而不是只拿 kernel 内部时间代替端到端成本。

Target/Artifact 应包含实际 kernel/模块、host bridge、布局/launch 描述、toolchain/driver 前提和必要依赖；只有头文件、IR 或函数名不构成可运行设备交付。

## 设备驻留程序与固件边界

设备程序必须绑定真实 board/device Profile：芯片/架构、存储布局、启动/复位、时钟、校准、外设、有效电平、保护区域、调试/更新接口和安全状态。逻辑 `Off`、`Safe`、`Reset` 等名称不能从业务语义直接推导物理电平或设备安全结论。

业务/控制状态机可以作为纯语义模块独立验证，但它不替代 ADC/传感器取得、GPIO/总线作用、watchdog、镜像启动、设备身份和刷写权限。Fault/Reset 需要哪些现实前提由该产品 Requirement 决定；不得用陈旧测量或未验证设备状态完成复位。

升级若有双槽/原子切换能力可以使用；单槽或不可恢复写入必须准确暴露断电/失败风险和外部恢复通路。生成镜像不等于已刷写，更不等于现场设备满足安全/可靠性 Claim。

**语义消费校核：** **现场安全与模型结束状态不同：** 屏幕显示指令执行完毕不能保证设备已停止、制动完成或旧主的延迟命令被拒；现场网关应能核有范围的写者代际，设备观测要带实际时间窗和物理进展。缺实际时间上界与安全联锁的Provider不能由一个`realtime=true`标签获得支持资格。 实现或验证此用例时分别消费[恢复后的权威代际、围栏与复写拒绝](../../50-执行运行与观测/持久化与恢复/持久状态与存储协议.md#gift-fenced-writers)、[事件时间、水位、迟到值与全称完成](../基础语义/状态关系与流/背压与事件时间.md#gift-stream-progress-completeness)的权威交接，当前机制只拥有本地行为含义。

## 实时任务边界

实时 Requirement 明确 release、deadline、period/aperiodic 规则、抖动、优先级/资源共享、允许丢帧/降级策略及 deadline miss 后的状态。Deadline 数值本身不创造可调度能力。

实现准入需要实际执行时间/阻塞/调度干扰、时钟与设备延迟、并发任务和所选调度模型的依据。固定优先级响应时间分析、EDF、时间触发、硬件调度或其他模型只能在其前提成立时使用；不能把某一公式写成所有实时目标的默认证明。

周期任务在同一状态上能否重入、miss 后是否跳过/补跑/进入 Fault、关闭时怎样停止新 release 并结算已释放周期，都必须显式。只有 p99/平均延迟不能证明硬 deadline；没有 WCET/上界依据时保留资格缺口，不擅自放宽 deadline。

动态分配、GC、page fault、网络、频率变化等是否允许由具体 Target/Profile 决定。TS/Rust/C 或设备代码只是实现选择，不能从语言名直接推出实时保证。

## 冻结实例角色

旧 `GpuKernel/Firmware/RealTime` 样本中的算式、电压阈值、周期和接口只用于验证上述硬件/实时边界是否能被组合，不是当前默认算法、设备 Profile 或作者根。

## 预测、控制与现实时间的接合

模型预测、求解器内部时间和设备观察时间分别解释。交付控制动作前消费[反馈控制合同](../共同语义/反馈控制与稳定性.md#controller-observe-decide-act)，把采样年龄、队列、求解、下发、执行器与确认放入同一响应要求；模拟先行完成不证明设备已到达。需硬保护的动作不能只依赖可能被普通编译/查询耗尽的调度池。

模型试步/回滚沿[求解合同](数据变换与求解边界.md#solver-completion-contract)停在私有状态；真实设备作用沿原Operation记录，不被取消仿真或回滚模型抹除。未能按时取得新控制量时只采用已接受的保持、备用控制、降级或安全过程；“发送零值”“断电”或“继续上一值”都不是通用安全默认。

## 实时期限和超期动作

实时实例必须绑定clock域、deadline相对事件、周期/到达约束、允许jitter、任务优先级、抢占/阻塞模型、目标硬件/调度器、WCET证据范围及故障动作。软实时的平均/分位延迟不能满足硬截止期合同；只有与任务集/中断/共享资源对应的可调度性和执行界可支持硬Claim。

方法选择联立CPU、内存、I/O、锁阻塞和设备时延；优先级反转使用所选的继承/上限或无阻塞方法，并把额外最坏成本计入。编译器不能为了通过准入把设备超时当正常快速返回。deadline前的资源预留与取消阈值由明确策略处理，未知WCET返回RealTimeEvidenceNeed。

超期时动作固定为进入指定安全状态、降级到有资格控制、丢弃过期结果或请求人工接管之一；不同策略有不同危害/进展含义，不能默认随便重试。时钟跳变/不同步、调度器异常和设备失联触发其独立故障状态。系统重启后epoch隔离旧命令，恢复要重新取得时钟/设备/任务集资格。

**验证与反例**：短任务均值达标但偶发超期、锁阻塞、时钟跳变、不同步deadline、过期命令迟到、故障安全退化分别验收。

**实际能力边界**：硬件、WCET、调度器和安全动作实际参数未知；不作硬实时保证。

## 设备动作、测量和安全状态

设备实例明确DeviceId与真实发行/发现来源、型号/固件/校准版本、传感单位/误差/时间戳、执行器能力/范围、资源拥有者和急停/安全状态。发现到设备、连接成功、接受命令、动作完成及现实目标达成是五种不同观察，不能用ACK代签最后一项。

命令带实际OperationID、目标epoch、前置设备状态、有效期限和幂等/重放规则；接收端若不能拒绝过期fence，发送端不能独自保证旧控制器失权。失联命令的结果保持Unknown并尝试独立传感/日志读回，不盲重发可能不可逆的物理动作。模拟设备返回值只属于模拟域。

异常路径按危害模型指定安全停机/保持/受限模式/人工接管，安全状态不是默认“断电”或“归零”；断电也可能有物理风险，必须由设备合同决定。清理要等待真实动作终止或资源隔离，校准过期使相交精度资格失效。重启恢复依据设备现态而不是只还原控制软件内存。

**验证与反例**：命令ACK但机械未到位、传感漂移、时钟不同步、旧epoch、断线迟到、模拟结果混入生产、急停后回调与重启现态不符。

**实际能力边界**：没有设备/凭据/校准数据或真实动作；这些必要绑定仍未知。
