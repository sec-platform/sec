# 静态结果、代码片段与已有工程变化

本页覆盖无需常驻运行容器也能形成完整交付的几类边界。它们仍要保持 Meaning、目标表示、来源和准确修改范围，但不能因为“静态”就省略身份、兼容或 Evidence。

## 规格、纯值与静态资产

### 规格/Definition 包

规格交付可以只有 Definition、Requirement、接口语义、Schema 或模型，不要求存在运行实现；但其公开引用、版本、依赖、解释条件和兼容边界必须完整。能解析不等于目标实现可用，分发规格也不取得运行权限。

### 纯值/配置

纯值交付必须固定类型、单位、编码、适用主体/环境和来源。默认值、显式值和从外部观察取得的值有不同 provenance；同值不代表来源可互换。秘密、动态令牌和短寿命句柄不应伪装成持久作者常量。

### 静态资源

资源包需要真实成员、内容身份、媒体/格式、路径/逻辑名、许可和消费条件。空目录或不存在的占位图标不能满足必需资源；相同文件字节也不自动说明语义角色相同。资源是否内嵌、外置、延迟取得或由宿主提供由 Target 决定。

## 片段、上下文补丁与已有工程变化

### 代码/表达式片段

片段必须声明或由固定上下文提供其自由名字、类型、效果、目标语言/方言、插入位置和前提。脱离捕获、控制流、ABI、宏/泛型环境或异常模型后可能不再等义；不能把“文本可粘贴”当独立 Artifact 资格。

### 上下文补丁

补丁绑定准确 basis/preimage、目标对象和保持条件。应用前再次核当前 basis；冲突保留候选/草稿，不靠字符串替换越过语义绑定。重命名、接口变化、布局变化和行为变化的消费者集合不同，不能统一成一个 patch kind。

### 原生工程变化

维护已有工程时可以直接以真实原生源码/配置/资源为作者事实，不创建同义 Gift 镜像。候选修改至少保留准确范围、前像、差额、未覆盖消费者和所需检查；未授权不 stash/reset/clean/saveAll，也不把读取工作树等同读取整个仓库。

写入多文件若无真实原子能力，部分成功按分项记录并进入恢复；撤销产生新的受控候选，不能把逆 diff 盲套到已被别人修改的前像。构建/测试/分析缺失意味着该 Claim 未验证，不得通过删检查制造“全部通过”。

## 冻结实例角色

旧 `Definitions/StaticValue/Resources/Expression/ContextPatch/NativeChange` JSON 和区间/改名示例只作为固定校准输入。其字段、文件名和算法不是现行作者模板；活动工程从自己的 Definition/Requirement、原生 source observation 和 Target 形成交付。
