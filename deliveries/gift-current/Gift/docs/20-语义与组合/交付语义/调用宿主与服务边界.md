# 可调用、命令、服务与扩展交付边界

本页维护几类高频**技术消费边界**之间真正不可互换的责任。它们不是 `ProductKind`、默认运行时或自动生成模板；作者没有选择相应边界时，不加载其协议、资源或宿主设施。

<a id="gift-unit-45ae4feed37655728852ff297895ec40"></a>
## 库、SDK与协议客户端

三者都可以暴露“调用”，但生命周期、效果与信任边界不同：

- **库式边界**由当前进程直接调用，默认不暗建线程、网络、账号、日志或持久状态；公开类型、错误、资源所有权和目标 ABI 必须完整。已有实现完全匹配时允许直接导出，不生成空转发层。
- **SDK/会话式边界**只有在确有共享资源、取消、并发额度、关闭或多次调用状态时才建立 Handle。接纳、取消、关闭和资源释放必须绑定同一实例；借用 Provider 资源不能由 SDK 擅自关闭。
- **协议客户端边界**显式拥有远端/跨进程协议、编码、认证/凭据取得、超时、重定向/重试政策和互操作资格。网络失败不能伪装成业务拒绝；发送完成不等于对端执行完成。

同步/异步不是实现速度的别名。公开异步接口需要稳定的取消与终结语义；同步接口若在目标宿主会违反响应/实时要求，则该 Binding 不合格或需要另一明确调度边界。Provider 可以复用成熟连接池/线程池，但所有权、并发额度和关闭责任必须精确。

协议适配只在实际 wire/ABI 差额处存在。状态码、错误对象、重试提示或消息字段由所选协议 Profile 拥有；Gift 不预置 `/normalize`、HTTP、JSON 或任何业务操作名。若响应需要独立验证，验证的 Claim/成本也必须显式，不能因为结构同形就自动信任。

冻结的调用类成品实例只可作为固定载荷校准上述边界，不是当前默认作者根或 SDK 定义。

<a id="gift-unit-fc5a54afe9e857f4a72f5ccb6b2792e6"></a>
## 命令与批处理程序

命令式边界拥有**进程入口、输入/输出协议、退出、信号/取消和传输完成**，而不是某个固定算法。

一次性命令若要求一个完整结果，应在成功退出前满足其公开结果完整性；计算成功但 stdout/文件传输失败不能仍宣称完整成功。stdout/stderr、机器结果/诊断、TTY/非 TTY、编码、参数和环境读取必须由 Target/Profile 明确，不能把 cwd、环境变量或隐式配置当作者事实。

批处理是否有限、能否部分成功、输出是否保持输入顺序、失败是否继续、是否允许 spool/恢复，都由准确 Requirement 决定。并发额度不自动赋予乱序可见权；请求/作业 ID 只在声明的作用域关联结果，不自动成为跨运行幂等键。若作业具有现实副作用，重试必须回到 Operation/Attempt/Readback，而不能沿用“纯计算可重算”的假设。

帮助、版本、诊断或进度是附加消费面；只有被要求时进入 Artifact。Shell 包装必须保持参数字节/边界和退出语义，不能把未转义文本拼成命令。

<a id="gift-unit-7572adbb4b1b5f9894e11eb71131eb1a"></a>
## 请求处理器与独立服务

**Handler** 与 **Service** 的核心差异是监听/运行实例责任：

- Handler 由宿主提供请求、取消和响应通道；它不因能处理请求就拥有 socket、线程、进程、TLS、账号或部署。
- Service 只有在真实启动、bind/listen/注册和依赖就绪后才能发布可用实例；它拥有停止新准入、排空/终结在途工作、关闭资源和实例身份。

路由、媒体类型、协议、认证、健康检查、端口、并发额度、日志和公网暴露都不是 Service 名称的默认赠品。若任务需要 readiness/liveness，它们必须分别绑定实际依赖和实例状态；进程仍活着不证明业务 ready。公开地址成功也不证明真实流量切换、证书或外部网络可达。

关闭通常至少区分：停止新准入、在途结算、外部效果查回、宿主资源释放。预算到期只能报告真实未完成范围；不得把每个调用都伪造成已收到取消。滚动替换、零停机、多副本与高可用属于部署能力，不能从 Service 本身推导。

协议层的错误优先级、重复头、长度冲突、部分响应、连接复用等由实际协议适配器负责；将其过早压成普通对象会丢失真实冲突。Handler 返回一个 Response 值也不证明字节已送达消费者。

<a id="gift-unit-062497369b6e552fa4c0cd9a4098e277"></a>
## 工作器、嵌入组件与插件

三者都是宿主边界，但隔离、加载和资源关系不同：

- **Worker/工作进程**：消息/任务属于具体会话；接纳、结果、协议拒绝、关闭和异常退出要能区分。宿主强杀可能没有逐任务终结消息，未回复任务保持未完成/未知，不能补造 Fault 回执。
- **嵌入组件**：import/export、ABI、内存/句柄所有权和实例释放必须闭合。公开类型同形不证明整数值域、布局、错误、线程或资源语义等价。
- **Plugin**：加载、能力协商、注册、使用和卸载是不同阶段。导入模块不自动注册；注册 token/句柄只控制本实例拥有的贡献。第三方代码是否可同进程运行取决于威胁模型，类型系统不是沙箱。

所有异步回调都必须考虑重入、同步完成、消费者抛错和结果资源寿命；内部锁/协调区不应跨越不受控用户回调。关闭先停止新准入，再结算已接受工作和借出资源，最后释放代码/进程/设备；无法可靠强卸载的原生代码必须采用更强隔离或明确“不支持强卸载”，不能靠 timeout 后 `free` 制造成功。

宿主提供的文件、网络、设备、终端或秘密能力必须显式传入/授权；Plugin/Worker 名称不能得到全环境权限。商店、签名、自动更新和全局注册中心只有真实需求存在时才加入。

## 冻结实例与现行规则

冻结成品形态保存过往 Library/Command/Worker/Handler/Plugin 等具体接口，仅用于固定验收载荷。其方法名、消息结构、端口、HTTP 路由、并发默认和 `model/*.json` 均不属于当前公共合同。活动工程必须从自己的 Meaning/Requirement 和所选 Host/Target 形成这些边界。

<a id="design-c08"></a>
## 连接、消息与命令身份

协议实例固定wire schema/版本协商、消息类型/最大长度、身份认证、连接生命周期、顺序/重复/丢失语义和流控。连接ID、会话ID、请求ID、业务OperationID分开：重连可以换连接而不能自动换扣款/设备命令身份。协议未知版本拒绝，在解释payload前控制大小及深度。

请求超时区分未发送、部分写入、已发送结果未知和确定拒绝。幂等重试仅在具体协议/Provider保证下执行；TCP连接断开或HTTP错误本身不能证明业务未执行。流式响应保留序号、checkpoint和重复规则，背压可阻塞/拒绝但不能无授权丢消息。

认证与授权分离，重连/长连接续期核撤销与当前能力；nonce/反重放窗口、密钥轮转、半开探测和TLS/实际安全协议由相应适配器精确锁定。回调或推送引入的重入遵守资源/锁规则。恢复从已确认消息和真实操作状态继续，无法读回的命令保留Unknown，不由网络库猜成功。

**验证与反例**：拆包/超大消息、未知版本、半开、重复/乱序、重连换身份、流控满、撤权中推送和服务已执行但响应丢失。

**实际能力边界**：HTTP/RPC/MQ/自定义协议的真实SDK和安全配置由实例提供。
