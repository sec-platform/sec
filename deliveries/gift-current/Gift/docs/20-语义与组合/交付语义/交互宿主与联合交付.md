# 交互宿主与多根联合交付

本页维护交互软件和多根共同发行时真正跨业务成立的边界。Web、桌面、移动只是常见宿主能力集合，不是 Gift 的内置应用模板；界面布局、业务动作、页面、账户、遥测、上传和后台服务都必须来自实际作者 Requirement。

<a id="gift-unit-a96c2932952c5dbe979b505373ae8ace"></a>
## 交互宿主能力边界

### 交互状态与业务状态分开

视图输入 revision、当前选择、活动请求/任务、展示结果、未保存状态和业务对象状态必须按真实 owner 分开。异步结果只可安装到它所基于的输入/选择 revision；旧结果到达不能覆盖更新后的编辑。Cancel 先撤销当前结果的安装资格，再请求真实取消；取消确认不自动证明底层资源已停止。

“成功空结果”“尚未运行”“运行失败”“结果属于旧输入”不能在 UI 上折叠为同一空白状态。错误/诊断定位到实际源位置和主体；界面状态不是第二份业务真值。

### 宿主能力按需接入

**Web 宿主**可能具有 DOM、浏览器生命周期、网络/存储/Worker/CSP 等能力；默认没有任何一项业务需要。离线任务不因运行在浏览器中就上传、建账号、写 cookie 或使用远端 Provider。

**桌面宿主**可以提供文件选择、持久文件句柄、进程、系统集成和窗口生命周期。知道路径字符串不等于拥有访问能力；保存需要准确前像/冲突策略，窗口关闭不能越过未保存状态和在途作用的结算。

**移动宿主**还可能有暂停/恢复、进程重建、权限撤销、系统文档 Provider、受限后台执行和设备资源。进程被系统杀死后不能把旧 Running 状态恢复成“已完成”；恢复只安装确有持久依据的状态，并重核短寿命权限/句柄。

一个交互产品可以同时面向多个宿主，但每个 Target 保留自己的能力、资源、打包和 Evidence，不用“响应式 UI”代替系统生命周期差异。

### 可访问性、输入与人机责任

键盘/触控/输入法、屏幕阅读器、缩放、焦点、语言/文化、感官或运动限制属于真实使用合同时必须进入目标验收。自动扫描只能支持其覆盖范围，不能代替真实任务可完成性。不可逆动作需要足够理解与确认；同时也不能为了证明系统“认真”而强塞无价值步骤。

### 文件、网络与外部作用

打开/保存、剪贴板、上传、下载、远端计算、通知、相机/传感器等分别取得宿主能力和权限。增加自动保存会引入持久作用；把本地计算换成远端会改变数据离域、隐私、故障和成本；它们都不是 UI 参数的无害变化。

### Gift 开发客户端只是本合同的一个消费者

Gift 自身的人类开发客户端由[客户端规范](../../80-开发者与接口/客户端/README.md)拥有；它可以消费本节的通用交互宿主机制，但不能反向把自己的树、编辑器、调试器或界面布局提升成所有作者产品的模板。旧 Studio 具体交互要求若需追溯，在同包[Studio 研究](../../../fixtures/compositions/Studio交互产品.md)作为非权威输入保留；被采用的跨产品区别回写相应 canonical owner。

<a id="gift-unit-d7c6dcc84df456909cc59b2346bb2d4a"></a>
## 多根联合交付

多个交付根无需 Core `Family` 类型。只要一次交付明确选择多个根及其共享/独立关系，就形成一个**联合 Artifact/Release 闭包**：

- 每个根保留自己的 Meaning、Binding、Target、Artifact 和完成状态；一个根成功不代签其他根。
- 共享定义/代码/资源必须有唯一真实 owner；内容去重不改变许可、依赖和生命周期。
- 不同根要求同一路径不同内容时必须隔离或报告联合冲突，不能以后写覆盖前写。
- 共同版本/清单只是一种采用机制；消费者需要整组一致时固定同一 release manifest，而不是分别解析每个 `latest`。
- 现场可以存在新旧根混合版本；只有实际相交协议/数据兼容时才允许混部，不因“属于同一发行组”推出兼容。
- 回滚采用指针不撤销已产生的外部作用；未知发布结果先 Readback，再决定完成或恢复。

联合发行可打成一个归档，也可由多个可独立取得的 Artifact 加共同清单组成；物理打包选择由 Target/分发约束决定，不改变各根身份。

冻结开发成品 Family 实例只证明某次固定组合曾有完整输入，不是当前 `Family` schema 或默认产品组合。
