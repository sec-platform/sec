# 反馈控制与稳定性

## 反馈控制、收敛、稳定与振荡

**语义消费校核：** **闭环可观测性：** 一个控制器在各自局部观测下稳定，并不推出依赖多个Provider的联合反馈稳定。离散读回时点、迟到采样、水位与真实执行延迟进入闭环条件；无法证明联合切面时只能取得有范围的控制分析，不能由“两个监视器绿灯”推出全局稳定。 实现或验证此用例时分别消费[跨源读取的观察切面、因果闭包与不可见参与者](../../70-工程系统与演进/信息与生命周期/对象关系与配置基线.md#gift-joint-snapshot-closure)、[事件时间、水位、迟到值与全称完成](../基础语义/状态关系与流/背压与事件时间.md#gift-stream-progress-completeness)的权威交接，当前机制只拥有本地行为含义。

### 一次写入不等于持续收敛

控制器、调和器、自适应系统、缓存刷新和自动修复持续根据目标与观察形成动作。它们需要反馈稳定性与进展模型，而不只是普通事务。目标可以是状态、轨迹、允许包络或被接受的有界策略；不能把所有任务改写为“直到当前值等于一个固定值”。已接受的自适应目标可以由观察参与计算，但生成目标的政策、允许范围及写者必须先固定，不能为了得到通过结论反向改要求。

<a id="controller-contract"></a>
### ControllerContract 的实际责任

ControllerContract 是对已有 Definition、Requirement、Method、Binding 与 Claim 的语义投影，不是一个要求所有控制器填写相同字段的无版本传输协议。按用途绑定下列关系；不适用者说明依据，未知者不写成不适用。

| 原有字段角色 | 解释与接合 |
|---|---|
| desiredStateRef | 被接受的目标状态、轨迹、包络或目标政策；固定修订与有权修改者 |
| observedStateMethodRef | 传感/读取方法、准确主体、时间/时钟域、覆盖、新鲜度和质量；估计与实测不混同 |
| reconciliationFunctionRef | 固定控制律/调和函数及其隐藏状态；方法选型回原 RealizationBinding，不在回调里偷换 |
| controlIntervalAndDelay | 实际采样、发布、排队、执行、反馈与允许抖动；间隔不代替端到端响应上界 |
| convergenceOrBoundedOscillationClaim | 所求收敛、稳定包络、允许振荡、进展或安全不变量及其适用域；不是无条件收敛标签 |
| idempotencyAndMonotonicityRefs | 对确实依赖幂等/单调的算法给出依据；非单调而合法的控制不能被一律禁止 |
| hysteresisAndDebounce | 适用时给出滞回、死区、去抖、冷却；这些是不同机制，不是全部控制器的必选配置 |
| rateAndResourceLimits | 共享资源、执行器饱和、动作幅度/频率、并存与恢复余量；消费原资源核算 |
| conflictResolution | 共同写者、物理执行器或共享环境的协调范围；逻辑字段不同不证明物理上独立 |
| staleObservationPolicy / partitionBehavior | 陈旧、乱序、断流、重启或分区时允许的保持、降级、重新观察与动作边界 |
| safeAndDegradedStates | 具体环境下的安全/降级状态及到达它们的动作和期限；“停机”不自动等于安全 |
| responsibilityAndInterventionRefs | 原有责任、授权、接管/升级和必要人类参与的关系；替代含混的 humanInterventionBoundary，AI/自动控制在合法委派内可连续工作 |

精确身份、当前权限、运行实例、操作尝试和资源不在此重复持久化。旧 humanInterventionBoundary 只有在旧版本映射能保全参与者、触发条件和实际权限时读取；改名不解除确实要求人类批准的约束，也不凭旧字段名给所有任务增加人工关口。

### 故障机制

反馈延迟可能造成过冲；多个控制器争用同一写入对象或不同字段背后的共同执行器；目标被错误地由易达到的当前状态反推；重试和自动扩容正反馈放大故障；陈旧缓存导致反复创建与删除；外部有权修改被误当漂移；恢复动作被另一控制器撤销；资源耗尽使控制循环饥饿。这些是不同故障路径，不只合并成“冲突”。

还需区分执行器饱和与控制律内部积累、观测滤波引入的相位/延迟、指标同时被多个优化环操纵，及升级时控制器隐状态不兼容。采用积分抗饱和、预测补偿或其他领域机制时，由原方法给出条件和依据；Gift 不内置统一控制公式。

### 稳定性策略与接纳

按领域采用单调收敛、固定点、滞回、死区、限幅/限速、退避、leader/fencing、单写者、优先级或有界重试。合格策略须与目标、采样、延迟、噪声、共享约束和实际控制能力相容；设置一个 backoff 数字不能证明稳定。物理系统、离散调和与纯优化共享责任纪律，不共享同一动力学定理。

<a id="controller-observe-decide-act"></a>
**一次循环：**取得同一目标修订及有范围的观察，构造无真实作用的动作候选；核局部/联合不变量、数值和时间预算；由原 execution 在真实作用边界核当前权限、前像/围栏、资源和原操作身份；执行后分别保留受理、实际作用、反馈观察和未结算责任。迟到观察不覆盖新目标，目标已变使未发送候选重评，而已发送的动作按原身份结算。控制器没有前像条件写能力时，只能提供真实较弱保证，不能用反复读回伪造原子控制。

多控制器即使写不同参数，也须通过 BoundaryView 检查共同资源或安全不变量；可用有依据的分解、预算分配、共享仲裁或联合控制。不是一律加全局锁，也不能以字段分区推导动力学独立。局部最优引起整体振荡时撤回的是相交优化/控制资格，不自动改原目标。

### 观察评价不是一个互斥终态枚举

持续系统通常没有永久 terminal。同一观察可能同时满足 `stable-within-envelope`、尚未 `converged-at-observation`、`under-reconciliation`，也可能处于 `degraded` 模式。`oscillating-within-bound` 描述特定轨迹窗口；`blocked` 描述动作准入；`unsafe` 描述已确认的安全违反，均不能互相覆盖。

结果分别引用目标满足/稳定性评价、动作准入/进度、运行模式和安全/数据质量观察，并绑定时间窗口、环境和所求证据。瞬时测量在包络内不证明历史或未来一直安全；未知不直接写成 unsafe，也不能当作合格。已有局部 Outcome 与 VerificationResult 继续分责，不新增万能状态联合。

### 失败、恢复与期限

失联或无新数据时，按已接受策略保持、限制动作、切换有资格的方法、交接或进入具体安全过程；保护装置需要持续供能时，盲目断电可能比继续受限运行更危险。安全过程也有真实权限、动作时延及资源需求，不能在普通队列已饿死时只标记 `Safe`。

硬响应要求按实际采样相位、读取/传输、队列、计算、下发、执行器与确认链组合合格上界；重叠阶段用真实关键路径，未知界不填零。需要预留调度/资源或独立保护通道时在启动前明确；不要求全部离线计算都配安全控制器。

重启/切换保留准确控制器状态、目标代、已发送动作和旧实例责任；只有证明初始化、积分/滤波状态迁移及当前观察足够时重新启动。旧反馈可供历史解释，不自动属于新循环。具体队列唤醒、运行代切换、取消和清理由[运行实例](../../50-执行运行与观测/运行生命周期/运行实例-主线与实例寿命.md)唯一拥有。

### 验证与研究入口

保留观测延迟/乱序、两控制器竞争、目标频繁变化、部分分区、资源上限、外部 override、补偿反复失败、重启恢复、新旧版本并存这些区别见证；同时检查正常稳定运行、合法自动目标、无需人工的委派和可证明分解，防止靠全部拒绝获得安全。

[控制与组织研究](../../../research/theory/控制组织与利益约束.md)保留完整候选与反例；[设备与实时交付](../交付语义/设备与实时交付.md)、[定量合同](../基础语义/计算基础/定量合同与误差传播.md)和[组合摘要](边界摘要与跨域组合.md)承担相交规范。历史研究中的某条控制理论只有在模型、条件和原始命题核实时才解除对应义务；不因理论名出现就签发稳定性。

<a id="coupled-feedback-counterexample"></a>
## 两个各自稳定控制器合起来失稳的可复算构造

取离散模型 `x[n+1] = x[n] + u1[n] + u2[n]`，两控制器同时读取同一个 `x[n]` 并通过相加作用到同一执行量。没有噪声、饱和或延迟；这是用来隔离联合增益问题的明确模型，不代表真实设备已测得。

各自单独使用 `ui[n] = -(6/5)x[n]` 时，闭环乘子为 `-1/5`，任意有限初值都收敛到0；两者一起启用则乘子为 `-7/5`，除零初值外幅度增长。因此两个独立“稳定”证书不能相加得到联合稳定，字段写权互不冲突也不充分。各改为 `ui[n] = -(3/5)x[n]` 后，联合乘子重新为 `-1/5`，是同一模型下的合法成功对照，不是“拒绝所有共同控制器”。

模型里系数的绝对值小于1给出几何收敛；用于实际设备前仍要映射其采样、执行器叠加、时延和模型适用性。当前 CLOS 与 ControllerContract 应追踪共享执行量及联合不变量；两个 Provider 若实际串行覆盖而非相加，则必须分析那个真实语义，不能套本例结论。控制器切换、故障备用和重试引入额外作用时也按同一接合检查，不把这里的6/5或3/5写成全局默认参数。

<a id="design-c21"></a>
## 反馈环的联合稳定与安全退出

控制实例声明被控对象模型、状态/观测、采样和延迟、目标、控制律、增益/饱和、扰动/噪声、执行器约束及安全集合。稳定/可达/跟踪是不同性质；必须指定连续/离散时间及局部/全局、模型/现实的范围。方法对模型稳定不直接证明实际设备稳定。

多个控制器共享对象时按实际耦合矩阵/调度分析联合闭环，不能组合局部证书就算完成。例如离散模型x'=x+u、单控制器u=-1.2x给系数-0.2；两个不协调控制器同时各给-1.2x时系数-1.4，绝对值超过1。该精确模型反例要求共享动作协调或重新设计联合控制，不支持对所有现实系统给固定阈值。

控制输出需结合观测有效期、deadline和设备fence；旧命令迟到不得覆盖新控制epoch。失联、传感器失真、饱和和超期分别选择经过论证的保持/停机/降级/人工接管，而不是一律发零命令。恢复先重建可信观测与资源权威，再在安全入口接管；仿真通过不自动授权现实动作。

**验证与反例**：共享控制器不稳定的有理数模型、延迟、饱和积分累积、失真观测、旧命令迟到、恢复时状态未知。

**实际能力边界**：真实被控对象、稳定性/实时与安全证据未绑定。
