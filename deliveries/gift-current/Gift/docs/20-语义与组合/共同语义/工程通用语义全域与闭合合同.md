# 工程通用语义全域与闭合合同

<a id="gift138-public-semantic-role-boundary"></a>
## “公共语义”不是`public`可见性，也不是另一套作者关键字

K1–K9的60个名字按**跨领域语义/工程接合职责**计数：K1–K7主要约束身份/类型、谓词/逻辑、状态/变化、时间/进展、事实/知识、意图/规范、资源；K8明确现实Effect/Grant/Operation/读回等权责；K9明确Requirement、Method、Target、Evidence、Revision等资格和演进。K8/K9不能当作普通领域谓词与K1–K7同级求值；60项亦包含`Implies`这类可派生便利构造，不是已经证明独立的最小逻辑公理集。

**语法字段**决定能否按版本解码，**公共语义**决定任何业务里角色、范围、状态、时态、四态证据和组合如何解释，**领域语义**决定具体名义谓词的真实定义/观察/权威，**工程实现意义**决定Method/Target/外部作用是否保持已接受要求。缺少任一阶段所需的资格，不允许仅凭相同名称或Schema通过自动提升。45类135侧面只审查该区分是否遗漏，不构成另外135项内核语义。

完整层级与唯一Owner通过[归属图](../../00-系统与原则/开发者源码分层与构造归属图.md#gift-author-source-layer-taxonomy)定位；本文件仍唯一负责语义判断的实际内容、错误与证据条件。


<a id="gift135-meaning-versus-numeric-shape"></a>

精确业务字面量、条件Meaning引用、组件参数绑定在结构上可核，不代表其现实解释成立：单位来源、规则权威、观察域、名义精化、政策例外和对象同一性仍必须逐使用点取得资格。特别区分`Declaration/BoundSource/InterpretedMeaning/QualifiedRequirement/QualifiedMethod/BuiltArtifact/ObservedEffect`，任何上层结果都不得由前一层结构通过自动升级。固定业务值不新增通用函数或Expr求值语义。入口见[作者非计算合同](../作者语义/开发者通用定义Profile-类型计算业务与系统构造.md#gift135-noncomputational-author-closure)。

## 有限语义判断接口、证据和类型不变量（Gift122）

### 被冻结的不是行业名词，而是判断签名与使用资格

公共的60个角色在本篇已有“输入—语义—失败”逐项清单；它们是**语义接合职责**，不是可以无条件展开的60个可执行指令。本增量进一步确定有限Profile真正允许的判断形态：

```text
Resolve(DefinitionRef, SourceLock, ImportLock) -> DeclaredSignature | NeedsDefinition | InvalidLock
TypeOf(Value, Env, TypeLock) -> TypeJudgment | TypeMismatch | NeedsRefinement
Observe(PredicateCall, Bindings, Scope, ObservationSnapshot)
    -> QualifiedTruthEvidence(supportRefs, refuteRefs, completenessRef?, scope)
       | NeedsMeaning | NeedsObservation | ConflictingAuthority
Check(Formula, QualifiedTruthEvidenceEnv) -> EvidencePair | NeedsInterpreter
Elaborate(GoalOrRequirementUse, TypedBindings, ContextLocks)
    -> DerivedObligation + DependencyFootprint | Needs | InvalidDefinition
```

每次语义判断都记录输入的发行者与有效范围：作者`SourceLock`、名义类型、Meaning/Requirement、事实观察、Method及运行Grant分别由其有权Owner签发，不能互相代签。`TruthEvidence(support,refute)`记录支持与反证，不是无条件的宿主布尔值；判真必须绑定问题、时点、范围和解释版本。`MeaningRef`仅用于定位定义，不自行提供谓词资格；参数、结果域、时态、观察完整性、异常和错误解释由锁定的领域解释模块给出。新领域可经同一签名与资格接口扩展，不要求Kernel预置其Method。

### 类型和真值规则的不能互换项

- `null` 是一个有类型值或被明确允许的占位；`absent` 是某角色在完整域中不出现；`unknown` 是事实/表达式缺乏充分证据；`conflict` 是互相冲突的肯/反证。四者绝不共用一个 `None` 或布尔值。
- `set` 按**资格化身份**去重；`bag` 记录身份及正整数重数；`sequence` 保留索引与重复；`optional` 的显式空和“未观察是否存在”不同。TypeRef与IdentityDomainRef/UnitRef的映射必须由实际owner签发；结构相同不意味着名义同型。
- `not` 翻转支持与反证；`all` 合取支持并析取反证；`any` 析取支持并合取反证；该限定公式Profile的`implies(A,B)`定义为`any(not(A),B)`。对`BOTH`不能当作`T`签发单一真结论，对`NEITHER`不能按缺失推出否定。
- 全称在**完整、有界、类型化的量化域**上可借枚举求值；不完整域可由合格反例给反证，不能给正真；存在量词的已见合法见证可给正真，不能从开放域未见证人推出反证。无限域/未来时序需要符号或归纳资格，不由Schema有限递归深度证明。
- 公式只描述逻辑证据，不自动提供**时间历程、因果、规范、自治主体授权**等更强关系；这些由对应Profile和解释者显式接入并保留来源。

### 有效性判据和打开Profile的规则

锁定 Profile 的语义节点分开声明 `Typed`、`Interpreted` 和 `QualifiedForUse`：前者确认引用/类型/作用域，中者取得实际 Meaning 解释，末者取得指定用途的全部资格。缺解释时保留 `Uninterpreted` 与有来源的 `Needs`，不能按结构合法直接签发可使用。扩展模块须覆盖相交 `signature/types/pre/post/observation/authority/failure/compatibility`，附 ReadSet、限制和证据；现有60项签名目录不证明生产实现齐备。只有具可观察新差异、失败反例和迁移证据时，才可能扩展内核职责。

## 从九组60种语义职责到作者源码的可检查接缝

60项是**有类型的公共工程职责目录**，不是60个必须独立出现的作者JSON关键字，也没有被证明为不可约的数学公理。`K1/2`提供可引用身份、Type、Relation与逻辑域；`K3/4`决定状态转移、观察轨迹和进展；`K5`保持正负证据与来源；`K6/7`构造接受目标、规范、容量和硬软约束；`K8`区分请求作用、HostGrant、尝试、结算、读回；`K9`把实现资格、制品、证据、修订和SourceMap接合。这些通过实际Definition/Requirement/Method/Target消费者联系，而不是复制一份“60元素全集”作为每个业务源文件。

对于开放领域的新Type、Money、Reservation、Widget、Network等概念，先选择能给出名义类型、谓词签名、求值/观察来源、时间/权威条件的SemanticModule。一个URI既不是类型定义，也不是世界事实；来源缺失返回`NEEDS_MEANING`，来源冲突返回`CONTESTED`，实际输入范围不可完整观察返回`UNKNOWN_OBSERVATION`。仅具有结构Schema的合法形式不得晋升为D2语义解释资格。证明一个转换在限定观察范围内保持含义，需要来源规则、必要环境前提、前后行为关系和独立证据，不因名字属于K组而自动成立。

## 现行采用设计：有限公共语义基底与开放世界分界

公共基底冻结为九组、60项**类型化语义接合职责**，供不同 Owner 和编译阶段共享签名与判断关系；它们既非数学最小公理，也非60个作者字段或代码指令。同一个语义对象只保存一个权威真源，职责与物理消费者不必一一对应。新行业由有资格的 Definition/Method 扩展；45家族、135侧面是覆盖审计坐标，不是 Kernel 行业枚举。任何增改字段、意义或可观察结果都必须经显式 Profile/codec 版本及消费者迁移，不得沿旧版本静默更义。

### 为什么九组足以作为稳定接合骨架，而不能叫穷尽世界含义

九组分别承担对象指称、逻辑断言、世界状态变化、时间进展、事实证据、目标规范、资源限制、外部作用，以及实现与保证；各组的身份、观察、权力或失败语义不能仅靠改名互换。领域Meaning须绑定已锁定Definition、参数角色、解释器及证据范围，不靠新增行业关键字进入公共内核。如果出现现有组合加领域扩展仍不能表达的可检验差异，应以反例、兼容性和迁移证据申请新Profile；不能据此声称当前60项对一切未来业务完备。

**解释层级**：源与身份 → 有类型的角色/关系/公式 → 事实/轨迹/规范的可接受域 → 只读联合义务 → 资格方法 → 完整目标制品 → 独立现实结算/保证。V0—V5是选择不同观察高度的视图；并非严格的六级必经JSON嵌套或要求普通作者同时提交60个角色。

| K4 时间与进展 · `Safety` | 禁止性质、相关转移/前缀域和Frame | 需覆盖声明范围的所有相关前缀或已证明的转移闭包 | 单快照/部分路径不能签无界安全 |

| K5 事实与知识 · `Assertion` | 主张、肯/反方向、陈述者、时空与来源 | 记录谁在何时何域作何断言，不自动构成事实 | 来源无权、冲突或适用期已过 |
| K5 事实与知识 · `Observation` | 观察器、模型/现实选择、快照及读取权限 | 只支持真实取得的字段、事件和覆盖范围 | 超时、陈旧、未披露或部分观察 |
| K5 事实与知识 · `Completeness` | 枚举域、快照、授权及负查询规则 | 仅完整且可信的域允许从未找到推出域内否定 | 开放域、未读完分页或权限不足 |
| K5 事实与知识 · `Assumption` | 环境/领域前提、提供者、适用范围 | 产生带前提的条件性资格，不冒充已观察事实或Grant | 前提未获确认、被反证或发生变更 |
| K5 事实与知识 · `TruthEvidence` | 同一主张及scope的支持集和反证集 | 分别保留T、F、BOTH、NEITHER及所用证据来源 | 冲突/未知禁止无依据折叠为宿主Boolean |
| K6 意图与规范 · `Achieve` | 目标谓词、有效完成点、Horizon及主体 | 在已接受的完成语义和范围内获得满足见证，另检进展责任 | 中途为真、期限或完成观察缺失 |
| K6 意图与规范 · `Maintain` | 应保持谓词、历史域和受保护转移Frame | 要求所有相关时点/改变保持；未来须另有证明 | 单次快照不能证明持续保持 |
| K6 意图与规范 · `Avoid` | 被禁止的状态/事件/效果及观察范围 | 在完整范围内不发生指定禁止行为或状态 | 未观察不等于未发生，历史覆盖不足 |
| K6 意图与规范 · `Oblige` | 有权规则、主体、触发、履行、期限和例外 | 条件成立后形成独立义务实例；分别判履行、豁免和违约 | 规则无权、触发未知或负履行证据不足 |
| K6 意图与规范 · `Permit` | 主体、行动、许可来源、例外及生效域 | 给出规范许可资格，不发行真实Host Grant | 有权规则冲突、撤销或范围不明 |
| K6 意图与规范 · `Prefer` | 度量、方向、同一比较域及排序授权 | 仅在硬合格候选中作可比较的排序或Pareto选择 | 缺测、不可比或无权取舍时不选唯一最优 |
| K7 资源与约束 · `Quantity` | 数值、量纲、精度及来源 | 同量纲且具有合格换算时才进行算术/比较 | 溢出、精度损失或量纲不匹配 |
| K7 资源与约束 · `Unit` | 单位定义、版本、换算及舍入策略 | 换算保留声明允许的精度与误差界 | 无可靠换算、维度不符或误差超限 |
| K7 资源与约束 · `Resource` | 资源身份、所有者、有效期及竞争域 | 区分声明容量、当前占用和实际上可分配的资源 | 失效、占用未读或资源域错配 |
| K7 资源与约束 · `Ownership` | 资源拥有/借用/共享/转移及释放合同 | 保持有权访问和生命周期关系，不因借用提升权限 | 双重独占、悬垂借用或漏释放 |
| K7 资源与约束 · `Capacity` | 容量、占用、时间交叠、原子更新边界 | 在共享身份与并发模型中联合检查容量不变量 | 非原子争用、峰值未知或过期读回 |
| K7 资源与约束 · `Constraint` | 硬条件、禁止、作用域及激活依据 | 所有已生效硬条件共同满足；偏好不能覆盖 | 有证冲突、条件未知或搜索不完整 |
| K7 资源与约束 · `Quality` | 具体度量、单位、采样、比较口径与来源 | 在有权同域规则内比较，必要时保留多目标Pareto集 | 量纲/数据源不合、缺测或比较策略未知 |
| K8 外部作用与恢复 · `EffectIntent` | 拟发生的外部变化、禁止及用途 | 生成待资格的目标效果要求，不产生外部作用 | 方法、Grant或观察能力缺失 |
| K8 外部作用与恢复 · `Grant` | 执行主体、资源、操作、有效期、撤销代际 | 派发点由有权宿主按当前状态核对执行许可 | 仅有规范Permit或过期/撤销的Grant |
| K8 外部作用与恢复 · `Operation` | 稳定逻辑操作身份、幂等域、前像与效果合同 | 一个业务Effect在跨Attempt中保留同一逻辑身份 | 身份错误、重建导致重复派发风险 |
| K8 外部作用与恢复 · `Attempt` | 单次派发、实际请求、时间和回执 | 记录发生了哪次尝试；取消/超时不证明无效果 | 回执丢失或完成情况未知 |
| K8 外部作用与恢复 · `Settlement` | 逻辑Operation、发生/未发生/部分/未知证据 | 按有资格的协议/读回记录实际结果，不由API返回码推定 | 迟到、冲突或重复结算未澄清 |
| K8 外部作用与恢复 · `Readback` | 观察器权限、查询域、时点及完整性 | 只对覆盖的Operation和实际世界状态签相应证据 | 负查询不完整、来源延迟或不可披露 |
| K8 外部作用与恢复 · `Compensation` | 原Operation身份、补偿政策、独立Grant及副作用 | 作为新Effect执行并留下与旧结果的关联 | 不可逆、重复补偿或补偿自身失败 |
| K9 实现、证据与演进 · `RequirementUse` | 锁定Definition、实例参数、主体及来源 | 派生当前使用点的义务，不复制出新的作者真源 | 引用缺失、绑定不全或解释未资格 |
| K9 实现、证据与演进 · `MethodSpec` | 真实实现、前/后/帧、错误、效果、进展、资源及版本 | 给出可检查的实现供应合同；声明不等于资格 | 实现缺失、合同不全或前提未满足 |
| K9 实现、证据与演进 · `QualifiedBinding` | 具体Method、联合义务、Target/环境及精化证据 | 只在当前声明的输入和效果范围内签发实现绑定 | 共享不变量、前提或跨Method干扰未证 |
| K9 实现、证据与演进 · `TargetArtifact` | 源码、配置、依赖、ABI、成员闭包及SourceMap | 按EntryRoots装配完整Target并分别申请构建/行为资格 | stub、未降低操作、缺成员或构建失败 |
| K9 实现、证据与演进 · `Claim` | 被断言属性、主体、量化域、时间环境及issuer | 只按证据支持的准确范围签发结论 | 超出负载、版本、时间或环境作推断 |
| K9 实现、证据与演进 · `Evidence` | 方法、数据、来源、独立性、有效期和局限 | 为指定Claim提供可检查依据，不把自测自动视为独立 | 失效、利益依赖或与声明性质不匹配 |
| K9 实现、证据与演进 · `Revision` | 各Owner的内容/解释修订和正负依赖 | 变化时只撤回受影响的缓存、绑定与Claim | 漏掉负依赖或把重命名当语义等价 |
| K9 实现、证据与演进 · `Compatibility` | 新旧协议、数据、在途Operation及迁移条件 | 按旧Reader、旧状态和恢复要求验证兼容范围 | 仅有版本号或形式相似而无迁移证据 |
| K9 实现、证据与演进 · `SourceMap` | 作者源→义务→Method→目标成员的有型映射 | 保留来源与受管区域写权；编辑回原Owner | 跨Revision定位漂移或双源争写 |

### 公共作者实际可见的有限判别标签，不要把它们与60个接合角色混数

- 意图模态：六个 `achieve / maintain / avoid / oblige / permit / prefer`；必须逐类检查，不能把未实现的四类默默丢掉。
- `gift.intent-body/1` 公式：五个 `call / all / any / not / implies`，与 RequirementTerm 的同名字不同编码、不同域；普通公式不擅自表达无界量化或规范许可。
- 现有 `gift.requirement-structure/1` Terms：八个 `use / require / prefer / all / any / when / forEach / exists`；不能混入运行式IF或数据查询所有类型。
- 公共 Pattern 角色基数：五个 `one / optional / set / bag / sequence`，以类型化身份及有权读取的真实成员解释。
- 意图时间形态：四个 `model-steps / until-event / wall-clock / unbounded`；有标签不意味着获得合格时间解释器。
- 抽象演算：八类分析/建立动作 `define / abstract / instantiate / specialize / compose / refine / realize / observe-and-verify`。末项含两类**不能相互代签**的观察与保证动作；它们不是业务作者JSON的八个关键词。

前五类属于不同作用域的**28个既有判别标签**，第六类是八个分析操作族。两者只在各自集合内计数；不能因为 28+8=36 就声称公共语言只有36个语义原语。字段、限定符、参数、域、版本和 Method/Effect 另有准确合同。

### 有类型判断及可组合性

<a id="open-meaning-qualification-interface"></a>
**K1–K9六十项的正式使用门槛。** 这60项是不同层次的公共**语义责任**，不等于60个可构造的AST节点，也不等于60个世界概念的完备公理。新增领域Meaning应通过现有 `DefinitionRef` 和被锁定的解释Profile公布：名义类型与单位、参数角色/基数、允许的关系和谓词、部分/冲突事实的解释、时空/观察范围、必要Authority/Environment、纯/读/写Effect类别、错误与Need、相交Requirement及可检验的精化义务。字段由实际语义及来源Owner供给，能从受信上下文求出的字段无需作者重复书写。

解释入口在固定 `(Γ, E, S, T, P)` 下返回 `QualifiedJudgement(result,basis,scope,readSet,unresolved)` 或精确 `Need/Conflict/Unsupported/Incomplete`；这是设计级类型签名，非新发布Wire。`result` 不得因缺失、超预算或权限不足被提升成 `true/false`；`E` 中的 `(support,refute)` 不自动等于世界真相。一个Meaning若需要真实观察，只能消费由L0/L5有权生产者固定的Observation；纯编译器不得自行读隐秘环境或发行操作Grant。合格Method使用此判断去履行要求，不反过来重新定义Meaning。

**开放性边界**：表达与组合能力由当前支持的Profile和有类型扩展接口决定。新行业可以追加有权Meaning和Method，不必修改Kernel行业`switch`；但没有该领域的可信签名、事实、语义或实现时，准确输出Need和未获资格的覆盖前沿。九组中的义务、现实操作和保证分别由已有Owner解释，因此“一个有限集合可以表达无数业务”只是一种可扩展机制，不是任何自然语言都会被自动合成的证明。


令 `Γ` 为本次冻结的类型、名义身份、角色和Meaning锁，`E` 为带来源及完整性的证据集，`S` 为模型或世界的作用域，`T` 为时间/轨迹域，`P` 为当前语义Profile。`
Γ;E;S;T;P ⊢ x : τ` 表示在**精确限定的解释条件**下，`x` 获得类型 `τ`；`Γ;E;S;T;P ⊢ claim ⇓ (support,refute)` 只表示证据支持关系，并非任意真实世界真值证明。类型、权限和证据不得通过字符串相似或布尔强制互换。

所有连接具有一个严格入口：`DefinitionRef` 的真实身份/版本锁 → 类型/量纲/角色/作用域校验 → 相应 owner 的解释/资格方法 → 派生引用和 ReadSet。需要现实值的纯方法不得自己调用外部 Provider，必须通过本次已授权的观察端口取得固定、可追踪的前像。任何带未知的映射不得提升断言强度。不能解释的 Formula 或 Requirement 可保留作者源和局部成果，**整件完整产品的签发**则需要全部相交必要合同合格。

### 证据逻辑与四种知识状态（不是物理世界的第四种真值）

`TruthEvidence=(s,r)`，其中 `s`、`r` 分别代表在该scope、时间和来源资格内存在肯定/否定支持；`(1,0)=T`、`(0,1)=F`、`(1,1)=BOTH`、`(0,0)=NEITHER`。独立的事实真伪不因未观察而被决定。`not(s,r)=(r,s)`；`all(A,B)=(sA∧sB, rA∨rB)`；`any(A,B)=(sA∨sB, rA∧rB)`；本**限定公式Profile**的`implies(A,B)=any(not(A),B)`，它是支持/反证组合的*材料蕴涵*，**不能**自动解释“义务”“授权”或因果。多个来源的陈述联合需保留来源、时点和冲突，不能把support和refute简单地算成权威世界布尔；每个来源的权威与独立性由真实消费者评定。

硬性正面规则要求足够资格的 `T`；`BOTH` 进入冲突协调，`NEITHER` 进入证据或解释缺项，`F` 是适用范围内的反证。对`avoid`须在明确观察和时间范围内取得其禁止谓词的合格否定；没有观察不构成证明。纯有限模型解释器先前使用 `{true,false,unknown}` 仍可在其**明确声明没有冲突证据**的局部输入内作为投影；不能因此宣布产品四态世界解释器已实现。

### 全域、封闭世界与量化

`forEach(x∈D,F)`的正支持要求完整域 `D` 内各实例成立，反证只需有合格反例；`exists(x∈D,F)`的正支持需有一个合格见证，反证要求**完整的有限域或适用的定理证明**排除所有见证。`D=∅`只有在完整性、scope和快照获得资格时才可分别为真/假；未读到元素而未证明域完整，必须 `NEITHER`。有重复的列表按Requirement已有实例化身份保留；`forEach`和`exists`不能交换次序。部分观察策略使用已有集合知识、Pre固定点/rank 方法及受限求解器；隐藏状态不是执行者自动可读的新接口。

### 组合保持、精化和实现合法性

实现 `M` 相对意图 `I` 的资格同时检查：所有必支持输入满足 `Pre(M)`，相关安全、Norm、资源、错误、时间与 Effect 轨迹满足 `Accept(I)`，正常功能及所要求进展有独立证据，并且源→Method→Target 保持可观察区别。`Behaviors(M) ⊆ Allowed(I)` 单独不排除死程序、空输入域或错误假设，故必须加入反空洞、环境与完成义务。一般程序等价、无限未来与开放现实环境没有万能可判定的综合检查；只能在证实范围内发条件性 Claim，超出部分返回 Needs/Unknown。

**闭合含义**：上述60项完成了有限概念接合的**设计枚举及共同解释规则**，不意味着每项领域消费者、Rust内核、TypeScript后端或真实执行已完成。某项独立具体语义的更强闭合只能由其原owner依据实际方法及证据签发。下一段设计—实施边界见[实施闭包](../../90-治理与参考/状态/实施闭包.md)，[闭合施工算法](../../70-工程系统与演进/工程构造手册/28-抽象到业务系统-统一实施闭包.md)。

## 跨业务语义生成规则与作者入口

新领域不靠无限增长的行业标签获得开放性。实际作者首选[版本化 Meaning、类型角色与组合意图](../作者语义/通用意图语言-意图源与语义组合.md)：组合保证保留主体、观测域、权利、时间、资源、效果及未知。普通可计算函数只是诸多 Method 供应之一，不能代表全部业务语义。

通用工程能力不是固定45家族/135语义侧面实现表；新增业务能力如何先由普通函数/类型表达，再按需接语义插件、Method、Target与Provider，参见[开放领域的构造工序](../../70-工程系统与演进/工程构造手册/13-开放领域与跨生态接入.md)。

> **当前规范归属**：本页拥有工程语义**整体覆盖、跨域接合、解释资格与可观察区别**的共同合同。每个具体语义的真正规则继续由对应 owner 保存；本页**不另建一套万能 IR、语言、闭合 `kind` 枚举、业务本体、数据库、证据账本或作者强制填写的表格**。具体的值/控制、状态、关系、规则、物理、效果、权限、目标等按本页定位到原规范。完整世界知识、未来新领域与所有方法的可实现性都不在有限清单内。

## 1. 正确定义“通用语义”，不再把它等同通用计算

Gift 关注的是**有准确主体、适用条件和观察边界的工程含义**：世界中什么存在或被断言存在、对象之间有何关系、主体有什么能力或义务、什么行为允许/禁止/必须完成、事件怎样改变状态、什么资源和外部效果被消耗或产生、什么证据支持何种保证，及目标软件如何忠实兑现它们。计算是一种求值与行为机制，但不是语义整体。授权不是布尔计算结果，现实提交不是函数返回值，外部事实不是静态类型，社会职责不是线程，法律生效不是代码生成。

把“全集”分成三个可区分的目标：

1. **闭合的公共接合规则**：固定引用、身份/修订、定义/用法、类型/范围、观察、假设、保证/义务、作用、责任、候选资格和失败/演进的共同接缝；在选定协议修订、上下文与任务闭包内必须明确，不依赖世界词汇表穷尽。
2. **开放的工程语义家族**：持续识别具有不同语义、证据、权责或失败方式的机制。这里列出高覆盖压力集，**不是产品 Core 的封闭枚举**；家族名称不决定解析器分派，不能以“新行业”新增 Core 分支。
3. **无穷开放的具体领域 Meaning**：作者与合格供应方可创造新的业务、物理、金融、游戏、医疗、组织和未出现的领域 Definition。只有现有抽象连观察区别都无法表达或组合时，才启动语言画像/公共语义升级，不能靠补一个标签冒充解决。

**关键区别**：计算表达能力的普适性（例如能够模拟任意可计算函数）既不蕴含需求信息完整，也不蕴含可推定外部真相、物理可实施性、实现存在、权限已授予、在所有环境满足实时/安全约束、或生成源码在指定质量目标下最优。编译器必须逐项保留这些尚未得到的资格。

## 2. 一份语义怎样进入已有模型：轴，而不是巨型万能对象

对一个具体 Definition、Statement、Requirement、Transition、Method 或 Claim，要能够准确回答下列**相交而不等同**的问题。它们是解释/查询轴，**不是要求每个语法节点保存十份副本**。

| 轴 | 问题与协议责任 | 误合并示例 |
|---|---|---|
| 语义所指 | 主体是某个值、对象、资源、操作发生、角色、关系还是观察记录？是否有稳定身份/修订？ | 同值订单对象当同一个实例；一次事件当一个状态 |
| 内容/语义类别 | 哪个 Definition/SemanticModule 拥有这个语义，输入/输出、关系域、值域、状态、时序和结果如何解释？ | 仅凭 `kind: "security"` 猜安全机制 |
| 陈述的模态 | 是定义、作者需求、外部宣称、已确认事实、观测、实现提案、权限、行动计划，还是经资格审查的保证？ | 需求已写就当实现已满足；计划已写就当已操作 |
| 约束强度 | 这是硬需求、条件义务、禁止、允许、愿望、默认、显式 Pin/Forbid，还是从已有事实派生的结论？ | Prefer 当 Require；作者允许当执行 Grant |
| 适用时空与上下文 | 哪个对象、版本、时间域、环境、地区、目标、观察者、人员及信任域内成立？ | 墙钟与单调时钟；单节点性质当全分布式性质 |
| 事实闭合度 | 是封闭枚举、受限完整快照、开放知识、尚未读取、冲突信息、陈旧信息还是未知？ | 未查到授权就认为已拒绝；未查到风险就当不存在 |
| 来源/权威 | 谁断言或定义？什么权能使它在该作用域生效？证据如何取到、是否新鲜、能否撤销？ | AI 候选当权威需求；Provider 声明当独立证明 |
| 生命周期/因果层 | 输入/语义/解析/目标/实际作用/观察/保证各在哪里取得？演进使哪段义务失效？ | 生成源码当已部署；部署命令成功当生效 |
| 消费者与失效 | 谁真正需要它？如何诊断缺项、冲突、能力不支持、目标不具备和实际未结算？ | 静默忽略未知语义仍声称编译成功 |

这些轴**复用**已有 L0—L6、ASMRVE、Canonical Forms、RequirementTerm、当前ControlFile及其已解析Control贡献，不是替换协议。值、身份、语言AST、作者Definition、原生源码、运行Instance、Claim等只在有独立消费者时持久化；统一入口可以派生多种浏览投影，却只有真实 owner 可以改写权威事实。

## 3. 共同的语义连接：精确槽位与局部结果代数

一个新语义能力通过现有 Definition/Module 发布下列可定位的**接合职责**，不强迫每一条普通值表达式都实例化 Envelope：

1. **Identity / Version**：定义身份、适用语义画像、不可变内容引用、兼容/废弃策略；版本改变但语义不变须说明依据。
2. **Input / Subject / Domain**：类型、单位/精度、参数、空间/时间/地区、可见角色与外部实体的绑定；不对未绑定身份臆造真实对象。
3. **Observable Meaning**：哪些状态、结果、事件/轨迹、时序、错误、外部可见资源、披露与成本是合同所承诺的区别；负约束同样有观察域。
4. **Assumptions / Environment**：时钟、网络、存储隔离、调用方、硬件/物理条件、先验知识覆盖、负载分布和法规版本等成立前提；前提不足时不能加强结论。
5. **Guarantees / Requirements**：正常条件、保持条件、禁止行为、终止/进展、公平性、随机置信限定、恢复和安全义务；未定义时不得自动补成 true/无限/始终成功。
6. **Effect / Authority / Lifecycle**：是纯求值、逻辑状态转移、真实可授权操作还是观察？资源取得/释放和事务结算是什么？声明准许不等于获得现时授权。
7. **Dependencies / Interfaces**：准确依赖的定义、关系端口、调用/事件/流/协议、实现资格、Target/ABI和安全边界；传递条件按类型而非全局字符串判断。
8. **Evidence / Limit**：声明来自何处，由何种独立手段在什么范围验证，结论的未知部分、失效时间和重审触发是什么；实现供应方的自我声明不能自动等于审计资格。

其中每个槽位都可由导入的精确 Definition 合同、专有领域 Schema 或当前作者局部差异提供。完全无需某槽位时写在**语义定义的适用规则**中，不要求每位作者写 `notApplicable`。确实需要但仍缺项时返回精确 Needs/Blocked，而非新增一个默认。

共同关系应保持明确语义和方向：`defines / instantiates / refers / refines / constrains / uses / composes / depends / requires / permits / forbids / delegates / authorizes / observes / supports / contradicts / realizes / generates / commits / invalidates / migrates / compensates`。这些是**关系含义的发现样本**，不得直接作为 Core 全局枚举；相交的专有接口拥有参数、基数、逆向/传递性、时序、写权限及证据的真实规则。`realizes`不自动意味着`verified`，`uses`不意味着已执行，`supports`不意味着已证明，`permits`不意味着已取得运行许可。

### 3.1 四个不能用普通函数调用代替的基础语义区别

- **描述性**：“订单状态=paid”是在给定状态源和时间的事实断言；可能暂时未知或和另一份观测冲突。
- **规范性**：“只有付款已确认才允许交付”是在限定允许轨迹；不声称当前已支付，不自动授予执行权。
- **操作性**：“提交库存占用”有前像、操作身份、可能实际发生的副作用及未知完成，不能以布尔值替换。
- **认识性**：“已有收据表明款项确认”是来源与证据范围，必须区分权威确认、供应声明、缓存、推断和未观测。

### 3.2 已知、未知、冲突、不适用及开放世界

严格区分不存在、未读取、不可见、部分覆盖、观察超时、未知/未证明、逻辑矛盾、显式不适用和确知无值。一个**闭合观察**只有同时给出主体集合、读权限、完整性、时间窗口、修订和负查询语义，才允许从“不在集合”推出“不存在于该有限集合”；开放来源不得使用封闭世界缺失推断。显式冲突不通过“最后写入”消除；在已接受程序主体上若两个生效定义互斥，必须求作者决议或缩小适用域。知识/研究层可以持有相互冲突的来源主张，不能由此推出目标程序同时满足两者。

### 3.3 跨域组合不是简单合并字段

- 两个硬需求同主体同适用域原则上合取；遇到冲突诊断并保留原来源，`prefer`只能在全硬条件合格后排序。
- 时间保证要保留事件时间/处理时间/逻辑时钟、观测窗口和公平性假设；顺序关系不能被图拓扑或文件次序替代。
- 状态机/工作流接入外部效果时必须构造操作/结算边界。纯状态迁移不能证明数据库真的提交或第三方已付款。
- 数据关系的集合/多重集/序列、完整快照/增量更新、null/absent/unknown、递归闭包不能随意等价。
- 权限只可以在授权规则允许时组合与委派；两个独立能力的并集不是更大范围自动许可，禁止以类型引用替代 Grant。
- 资源具有独占、共享、借用、转移与释放义务，不能按纯值多次复制所有权；跨失败边界必须有清理所有者。
- 效果顺序可能影响外部状态；仅有输入输出值等价不足以重排、并行化或缓存有副作用动作。未确认完成不能默认为失败或安全重试。
- 概率、因果、学习和实际性能要求各自需要统计设计、数据/模型版本、环境条件；不可从一次运行、相关性或单一数据集推广。
- 保证的组合只能在假设互相满足、观察域和证据范围覆盖共同约束时成立。独立测试数量相加不等于整体可信度。
- 原生方法、后端和 Provider 可以实现多个语义，但复用必须绑定准确 `Definition`、公开合同、TargetProfile、环境、版本和 Evidence，不得以同名组件自动获得合格资格。

## 3.4 可检查的语义判断，不把世界事实、规范和验证折叠成同一种 Boolean

对任意公开 `Definition` 或 `Requirement`，消费者必须先知道它试图判断的对象是什么，不能让同一个函数返回 `true` 兼任：存在、合法、允许、完成、已验证和最优。

| 判断 | 输入与解释 | 可否从编译成功获得 |
|---|---|---|
| **WellFormed / Resolved** | 作者语法、SourceProfile、精确符号/模块引用、schema/修订 | 只在已运行真实 Reader 的范围内可以 |
| **SemanticMeaning** | 对应领域解释器给出的输入、主体、观察/状态/轨迹语义及前提 | 不可以仅凭 Schema 或文本标签 |
| **Satisfaction** | 相关模型/观察、允许环境、准确义务及足够覆盖下，是否符合 Requirement | 通常不可；对有限可判定子域可以证明或发现反例 |
| **Permitted / Authorized** | 规范策略的允许关系与当前主体的实时授权事实分别判断 | 不可以；持有角色字符串不是 Grant |
| **Realizable / Eligible** | 目标、Method、资源/效果/环境/资格证据，是否存在合格候选 | 不可；已生成一种实现不能证明满足全部条件 |
| **Occurred / Settled** | 真实 Operation/Attempt、环境观察、效果结算范围 | 不可以；不能由 plan/target/source 判定 |
| **SupportedClaim** | 独立 Evidence 的取得、可信、覆盖与新鲜度，所支持 Claim 的上下文 | 不可以；测试只支持实际覆盖的断言 |

抽象模型中，一个产品 Requirement 可以表述为：在约定的输入集合、环境假设及观察域上，**哪些可观察行为/轨迹可接受、哪些不可接受，及未满足时如何处理**。这里的“轨迹”不是强迫所有程序持久化全量 EventLog；纯函数可以只有输入输出关系，流程具有跨时序序列，安全性质可能禁止任意前缀，活性性质需要额外公平性前提，外部效果还要真实读回。依赖的确切表达与判定方法属于实际语义模块，不由此产生通用万能 Trace IR。

“对象事实上是否满足某个性质”与“Gift 是否知道它满足”是两个不同层次。事实真值可以在实际世界中为真或假；Gift 的**认知状态**还可能是未观测、不完整、无法解释、有冲突证据或无法在预算内判定。不能把未知赋值为业务 `false`，也不能把相互冲突的外部断言误写成两个已采纳的程序定义。

规范算子也不能一概化成普通逻辑谓词。例如：

- `require X` 缩小合格实现与允许轨迹的集合（按既有 RequirementTerm/领域解释），不执行 X；
- `prefer X` 只在满足所有有效 `require` 的候选间作已定义比较；
- `permit A` 在其声明的策略/适用范围内授予一种**规范上的允许**，不表示当前调用者必然持有可执行的 Grant；
- `prohibit A` 限制可接受行为，不能靠隐藏 UI 表示已执行；
- `oblige A before T` 产生一个有明确主体、触发时点、期限、例外、违约处理的义务，不等于 `A` 已发生；
- `observe A` 需要来源、覆盖、权限和时间，不等于真实 A 的全部事实；
- `guarantee A` 只有绑定满足前提的 Method 或实际 Evidence 后，才可声明对应级别的实现/验证资格。

这组区别由现有 Requirement/Assertion/Grant/Claim 等 owner 拥有，**不在本页新增一套 7 个返回类型**。上表只是跨消费者禁止错误跳跃的规则。

## 3.5 对各语义模块的实际闭合协议：哪些可判定，哪些不能

一个领域模块的每项消费者能力要逐一声明：

| 消费行为 | 最低必须得到的东西 | 正确的不完成结果 |
|---|---|---|
| 解码结构 | 已选择的语言/Profile/版本及 body schema 的全部输入域 | `UnsupportedProfile` / 精确错误定位 |
| 解析引用 | 固定读集、作用域、可见性和完整的导入闭包 | `Needs(DefinitionRef, revision)` / Conflict |
| 取得语义 | 真实语义解释者、适用主体/环境与可观察合同 | 未提供解释器时停止对应语义推导，**不能** `assume true` |
| 联合组合 | 输入/输出类型、语义边界摘要与相交不变量；非交叉域可独立保全 | MissingJoinRule / UnsatisfiedConstraint |
| 需求检查 | 有限可决定性质的实际决策程序或合法的证明/反例取得路径 | 超预算或不可决定返回 Unknown，不能标 PASS |
| 候选实现 | 合格 Method/Provider/Target 及适用证据、可观察效果/错误保持 | `Needs(Implementation)` 而非制造一个业务模板 |
| 目标降低 | 真实生成器、源图身份、目标原生语义与差额义务 | UnsupportedTarget / 仅设计蓝图 |
| 现实动作 | 当前 Grant、资源/前像、OperationId、执行与读回 | 无授权不得动作；超时可为 UncertainCompletion |
| 证据结算 | 实际 Claim/assumption/evidence/coverage/freshness | Inconclusive 或 Fail，不能用“脚本退出零”代签 |

跨领域求解不要求**每个**语义模块实现所有九行。纯数值模块无需写入权限端口；独立的法律/许可包可发布权威规范和适用性解释而不声称能部署设备；某个行业算法可以保留原生实现且只在已声明范围提供 Bridge。消费者只调用它实际承诺且输入有资格的部分。

新 Definition 是否可以“直接编译”，取决于它的全部可观察义务是否已能够由标准语义、组合定义或合格 Method/Target/Provider 覆盖。**表达覆盖**与**实现覆盖**由不同事实证明。若缺少后者，Gift 应当仍能交付一份精确、有追踪和待履行义务的产品设计，不得把算法猜测冒充补齐现实前提。

## 5. 同一工程请求的真实解释与实现路径

以“订单支付成功后预留库存且重复回调不能重复扣减”为例，作者**优先使用已存在且版本固定的公开语义定义**（例如“权威支付确认”“有限库存预留”“同操作至多生效一次”“未决付款恢复”），只提供该应用特有的主体绑定、阈值/时限与允许的例外。没有这些定义时，作者或领域库作者必须提供它们的可观察合同：

| 语义事实/要求 | 谁必须作真正的决定 | 首先由什么消费 | 何时不能生成或不能宣称合格 |
|---|---|---|---|
| 订单、支付、库存是不同身份，订单有状态及有效转换 | 产品作者/领域 Definition | `req:composite`与状态/关系语义解释器 | 身份、成功标准或时间版本歧义 |
| “确认支付”来自指定 Provider 及有效回执 | 产品 + Provider 契约，现实确认归对应支付方 | 观察/证据端口、资格过滤 | 只有本地布尔值或未验证回调，不知道是否到账 |
| 已支付方可尝试预留，未支付不可履约 | 作者业务硬 Requirement | 关系/状态/规则解释器 | 规则只以文字存储，无语义实现/行为闭包 |
| 回调重复不得重复占用；争用不能超卖 | 业务效果范围由作者决定，事务方法由解析器选择 | Effect、事务、一致性Method | 只有单机 CAS 不能保证跨库/跨节点整体约束 |
| 失败与结果未知的区别；要回收/补偿且不能双退款 | 作者定对外保证，Method 定恢复协议，运行系统执行 | Operation/Attempt/读回/补偿 | 超时就当未发生；重试无同一操作身份 |
| 哪个用户、租户、执行器能看到/执行哪些动作 | 产品授权策略 + 当前授权者 | 运行 Grant 与所有边界的授权检查 | 有策略声明但运行时未取得 Grant |
| 目标 ESM/数据库驱动/地区、延迟与成本 | 开发者只固定必要硬约束，供应方负责候选 | TargetProfile、Resolver、Target generator | 缺环境资格、数据规模或性能依据 |
| 已经实现/部署/实际扣减/正确性保证 | 产物、操作、观察、独立保证分别拥有 | L3—L6 | 编译成功、SDK 返回成功就推定整体成功 |

### 5.1 作者唯一来源，不制造“意图又变 Gift 源码”的二次维护

当前新业务的权威作者源为 `gift.author-module/2`，包含 `req:composite` 与所引用的有类型Definition/RequirementTerm；既有 `gift.author-module/1` 案例仅由兼容读取器按原语义处理；并可与作者选定的 Rust/TS 原生算法区域协作。可选 `.gift` 只属于其受限计算画像；`.intent` 属于仍在研究的简洁投影，不是新增的**必经源码格式**。UI/自然语言转录、图/表和关系投影接受后只回写原 owner；不保存一份另外的“完整展开后语义副本”。

### 5.2 解释—资格—目标—现实的消费序列，不强制作者逐步执行

1. **读集冻结**：固定本次任务接受的 SourceScope、Module/Profile/Definition 身份、内容、授权可见范围和外部依据；来源缺失/被撤销按要求准确返回。
2. **语义解析**：由声明的 SourceProfile/Dialect 解码并解析引用，按原 Definition 的局部解释器计算语义摘要。遇到尚未激活或未知 Dialect：保全但不静默消费，报告 Unsupported/Needs。
3. **联合闭合**：检查主体、关系、时序、规则、错误、效果、所有权、资源及领域交叉不变量；按准确参与关系传播义务，不扫描所有家族全文。一个根可形成完整设计蓝图，即使后续实现缺失。
4. **实现资格**：按 Method/Provider/Target 的真实输入域、环境、效果、成本及证据资格筛选候选；候选缺失返回 implementation Needs，不能重写业务含义或偷偷“补齐”未授权功能。
5. **目标生成**：目标源码、资源、配置、API 和必要运行适配都由合格生成器承担。对每个语义根保留来源/实现选择映射与未闭合保证；“可编译”不能自动得到行为等价。
6. **现实与证据**：写入、构建、运行、部署、支付、告警等分别按现有 Operation/Attempt/Observation/Claim/Evidence 合同取得批准和资格。没有真实操作不能宣称发生；外部结果未知不能由静态蓝图覆盖。
7. **局部演进**：语义/合同/来源变化让相交义务与候选/保证失效；纯方法替换不应无缘无故修改业务含义；实际目标构建、旧部署、数据迁移和未决执行分别保留自身版本和回退边界。

**接口分工**：SourceProfile/Requirement 由 [作者源合同](../../10-作者与输入/作者源/结构化源码.md)与[需求含义](../作者语义/需求含义与实现责任.md)拥有；[领域扩展](../组合/语义扩展-声明投影与系统编译.md)负责 SemanticModule 与解释资格；[边界闭合](边界摘要与跨域组合.md)负责跨域组合；[实现选择](../../30-实现解析/实现选择/实现解析与候选资格.md)负责资格；[目标生成](../../40-目标与制品/目标/交付消费合同与发射.md)负责源码/成员；[运行与事务](../../50-执行运行与观测/持久化与恢复/事务提交-外部效果与幂等交付.md)与[授权](../../50-执行运行与观测/权限与资源/授权与执行准入.md)拥有现实效果；[保证](../../60-保证与证据/保证/要求证据与裁决.md)拥有 Evidence 资格。

## 6. 可组合模块必须发布的边界，不新增强制超级协议

对一个新的跨领域语义模块，模块作者必须拥有**实际解释者**和准确范围；发布的 Capability/Descriptor 可以暴露：`semanticRef + revision/content identity + applicable subjects/types + observations + assumption/guarantee/failure/progress/effect/resource boundary + dependencies + supported query/compilation projections + explicit unsupported cases`。但是记录这些字段本身**不是解释者的实现**。解释能力至少满足：

- 输入端有 schema 与类型/来源校验；所有语义可观察差异要由领域 body 的精确规则或已绑定标准定义解释，不能读一张开放 JSON 属性字典后宣称理解；
- 提供只读取/展开/校验/确定转换等能力中的实际子集，并声明每种能力的版本和失败结果；不能把只是语法可读写误报为可降低目标源码；
- 与其他模块通过 typed ports、关系与局部契约组合，声明异步、顺序、恢复、信息/资源/权限边界；不能用“插拔兼容”掩盖联合不变量；
- 用确定的反例区分“新领域定义”与“现有公共语义不能保持该差异”；只有后者且证据成立才提出 Core Promotion；
- 含外部影响的解释器不能因为拥有解析权限就取得写权限；Provider 只能在真实 Grant 与 Observation 端口上完成实际作用。

[机器接口提案样本](../../../fixtures/semantic-universe/Gift102/README.md)仅校验上述若干交换字段的形状和代表性业务闭合条件；它不是新 `gift.author-module`，不是现有产品Reader已接入的标准，也不证明通用编译器已实现。这些机器字段必须先与上述原 owner 的正式签名比对，再允许产品消费。

## 7. “设计覆盖”与“产品能力”必须独立报告

| 判定 | 只需要什么 | 不能据此推断 |
|---|---|---|
| 家族发现覆盖 | 当前挑战与公开标准中可区分的机制能定位现有 owner 或准确 gap | 世界语义已穷尽 |
| 作者表述完整 | 固定上下文/观察集合内，需求、默认、来源、未知和正反区分都保留 | 有合格实现 |
| 语义可解释 | 至少一个版本固定的真实解释器能解析/联合检查相关 Definition | 能降低所有 Target |
| 实现候选合格 | 具体 Method 在所要求语义/目标/环境/效果下符合候选资格 | 运行性能已测、产品行为已验证 |
| 目标生成成立 | 已产出准确目标字节，构建环境与相关义务已界定 | 已授权写入、部署或现实效果结算 |
| 独立保证成立 | 某 Claim 所需 Evidence 的质量、主体、前提、环境和覆盖已检查 | 任意未知场景也成立 |

**终极验收**应包含至少以下相互独立的能力簇，而不是把成功生成 100 个纯函数当作普适性：数据/关系、状态/过程、外部事务、分布式一致性、身份与权限、资源/寿命、实时/物理、界面交互、组织/规则/法律、演进/迁移、观察与保证、原生多目标。每簇至少设计一个只改变领域 Definition 而不改 Kernel 的正例与一个原本容易误判为满足的反例。缺合格消费者时标记 `design-only/unsupported`；未知是否满足时标记 `unknown`；实测/形式证明只能声明其覆盖域。

## 有限语义生成基底：构造、解释、扩展及无法约简的区别

本篇唯一维护**共同语义构造的解释责任和向更高抽象的组合**，不穷举行业业务定义。原有 45 家族/135 侧面是研究/验收覆盖坐标；十三类跨域责任是发现入口；它们都不是固定的、已证明最小的 Kernel 操作全集。避免把十五种语义词改成十五条业务 `switch`。最小公共内核只负责普通可组合构造、定义/绑定/解释/观察/应用时的准确分派与错误；特定类型、逻辑、时间、规范、概率和世界效果可以由受控 SemanticModule 提供。

### 一、基础区分与解释提供者

| 基础语义区别 | 可复用构造 | 所需解释前提 | 不能用其它条款代签 |
|---|---|---|---|
| 身份、类型与角色 | NominalType、ObjectId、Role、Relation、Cardinality、ScopedBinding | 身份发行域、生命周期、类型/单位、可见性与继承 | 同名字段或结构相等不使实体相同 |
| 值、关系与量化 | Value、Set/Bag/Sequence、Relation、Predicate、Bounded/GeneralQuantifier | 精确等价/顺序、域范围、空域、量化器能力、求值方向 | 有限列表枚举不能代表无穷或未知集合 |
| 状态、变化与事件 | StatePredicate、Event、Transition、Frame、History | 前像/后像、原子域、事件主体、时间及合法失败 | 存储字段修改不等于世界效果发生 |
| 时间、轨迹与进展 | Instant/Duration/Calendar、Interval、Trace、Safety、Liveness | 时间尺度、调度公平、截止、观察窗口、环境行为 | 一次快照真不证明一直真/最终真 |
| 事实、知识与证据 | FactAssertion、Observation、Assumption、Source、Completeness | 可信来源、正反支持、范围、时效、撤回、开放/封闭世界 | 无记录不等于假；声明有来源不等于来源可靠 |
| 目标、禁令和规范 | Achieve/Maintain/Avoid、Oblige/Permit、Preference | 接受者、可观察判据、责任主体、触发、期限、例外 | 可行性不证明合规；Permission 不授予 Grant |
| 资源及约束 | Quantity/Unit、Ownership、Capacity、Constraint、Conflict | 可加性、重数、时间域、共享/独占规则、资源边界 | 容量和抢占语义不是一个 `Int` 的固有属性 |
| 效果与外部世界 | EffectIntent、Authorization、Operation、Attempt、Readback | 真实宿主、权威、幂等键、前像、结果未知恢复 | 生成 SDK 调用不等于外部效果已结算 |
| 合同、保证与变化 | Requirement、MethodClaim、Claim/Evidence、Revision、Compatibility | 输入域覆盖、保证/帧/进展、资格环境、独立观察 | 语义可表达不等于 Method 存在或已验证 |

此表将十三类领域发现坐标归并为九组**工程解释责任**以方便实现，不是宣称九组彼此独立或“只有九个关键词”。一份业务定义可以引用多组，只有命名 `Payment` 等行业实例的不同外延才进入领域库。新现实观察器、语义域或高阶性质可扩展语义族，但不会自动修改现行普通函数和 JSON 作者源的含义。

### 二、语义解释与域内判定结果

统一解释上下文可以表示为 `Context = (DefinitionLocks, SubjectBindings, WorldOrModel, ObservationScope, TimeBasis, Assumptions, Completeness, AuthorityRefs, PolicyRefs)`。`WorldOrModel` 必须标明模拟/推断/现实；`ObservationScope` 标明哪些东西可见、哪些必须保持；语义模块不应从调用名或物理路径猜这些值。解释的正常输出是类型化谓词/关系、义务及所需观察/方法，不是天然布尔 `true/false`。

事实真值的最低可区分集合是：有正支持、明确反支持、两者均有、两者均无；必须保留支持来源与相同主体/时间/范围的对应性。仅当特定已接受的**一致性前提**排除双向支持时，可以收敛到三值 (`true/false/unknown`) 并进入 Gift112 受限模型。双向支持状态不是逻辑爆炸地证明任意谓词；没有支持不是 `false`。封闭世界的 `not found ⇒ false` 只针对有可复核覆盖声明的具体字段、时间和数据快照，不自动延伸到真实世界。求值算法不得将“来源冲突”静默为任一方向的确定结论。

`all/any/not/implies` 的确切真值表由所选逻辑画像拥有；不能在三值与四值、规范“不得”和命题否定之间未经声明地复用 JS 布尔运算。`exists/forAll` 先绑定类型化量化域、有限/无限、可枚举/可观察性和空域政策；未能穷尽无限/未知域时只能报告当前证据等级。涉及跨两次运行的隐私非干扰，也不能把“一个输出等于另一个输出”缩成单轨迹状态公式。

### 三、模式与意图的组合限制

模态作用于相应主体与时间：`achieve P` 需要成功结果与必要进展，`maintain P` 需要声明起止与可观察期间，`avoid P` 可约束状态或事件，`oblige(actor,trigger,fulfillment,deadline)` 是规范上谁对什么负有责任，`permit` 是在特定制度内的许可关系，`prefer` 只在完整硬资格后排序。它们不遵循无条件的交换、分配或抵消定律：`achieve(A) ∧ achieve(B)` 可能因共享资源不可共同实现；`oblige(A) ∧ permit(A)` 不变成已执行 `A`；`avoid(P)` 不是 `achieve(not P)` 的无条件同义形式。尤其长时段义务、终局性、撤销与迟到结果必须由相关模块显式承诺。

一个新业务如“医疗床位分配”可以通过公共资源模式及其域内解释定义；该模式只保证在它拥有的条件下的资源关系。医疗资格/法律效力/医院调度时刻另由领域 Owner/Provider 维护。技术上的谓词可以有确定意义，但其真实世界前像仍可缺失，不能把解释成功当作现实验证成功。

### 四、何时必须加核心语义，何时只应加领域定义

判定序列：尝试使用类型化通用关系与角色绑定表达 → 尝试已有模式+领域差异槽 → 尝试已锁定 SemanticModule 的解释与观察规则 → 尝试现成 Method/Target/Provider → 仅在能给出**公共构造无法保持的最小观察反例**时提议新增 Kernel 操作。新运算除了语法/Schema，还必须给出组合规则、对现有语义不破坏证明/反例、错误、版本、迁移、性能边界及消费者，否则不晋级。

Kernel 不会因为加入了新业务名称而增加 `shop/order/hospital/gpu` 枚举；既有数值、查询、概率、审美、法律与物理语义也不会被强迫实现为同一个布尔函数。基础有限只指**构造规则有界且明确定义**，不是所有世界事实、行业和算法有限或可自动判定。

## 业务抽象视图与语义基底的逐构造归属（当前设计）

这里的 **V0—V5 是阅读和抽象依赖视图，不是固定六层 AST、六个必填表或六个运行进程**。现有 L0—L6 是从来源到保证的横向工程责任；45 家族、135 侧面是发现/遗漏审查目录，不是语言操作数目。`semantic:pattern`、`intent:goal` 与 Method/Target 分属不同权威：前者复用开放业务区别，中者表达产品作者需要的结果，后者只提供实现。任何新家族先尝试由既有构造和合格 Meaning 定义；新的不可约观察、时态、因果或规范操作需新的、有版本的解释模块，不新增行业分派。

| 视图 | 公共构造/主要内容 | 本层生成的值（派生） | 不应出现/不可代签 | 当前产品资格 |
|---|---|---|---|---|
| V0 正交实现供应 | 原生计算、SQL/规则/工作流/求解器/SDK、Target、Runtime | MethodOffer/Binding、目标与操作适配 | 源码函数名代替业务含义；“代码编译了”代签业务正确 | Gift111 有有限通用计算样本，Gift114—117 有限 TS/SQLite 与源码 lowering；无全生产供给 |
| V1 共同构造 | 身份/名义类型，值与关系，事实与观察，状态/事件，时态，规范，资源，效果，合同与证据接口 | 类型化 Meaning 的签名、解释范围和义务规则 | 行业名词词典；事实 Unknown 当 False；Grant 当 Permit | 九组责任已设计，非九个完成的解释器 |
| V2 领域定义 | Entity/Role/Attribute/Relation/Predicate、实例与公理/政策/观察者 | 已锁定 DomainDefinition/MeaningUse | 同名视为相同身份、虚构行业默认/数据源、领域词汇直接触发 Effect | Meaning 库有限模型可用，开放新原语生产解释未闭合 |
| V3 意图与要求 | Achieve/Maintain/Avoid、Oblige/Permit/Prefer、期限/保持/异常/范围及完整 Requirement | 带来源的 TypedObligation 与 Need | Method 选择写回作者意义；只有 Bool 就给 Norm/进展签证 | 六条款结构设计，参考器只执行有限子域 |
| V4 复合能力/协作 | 公开输入输出、角色映射、总目标、共享资源/状态、流程先后/并发、权限及取消 | JointObligationGraph、CapabilityContract/Use | 单项合格拼出整体合格；强制多写一份 business.json | Gift113 有有限联合模型，未有全域生产组合器 |
| V5 整体软件 | 产品 Root、模块/服务/交互、持久状态、部署/运行/迁移/保证 | ProductObligationClosure 与 AssemblyPlan | 有一个函数/TS 工程就签完整系统、跨版本效果由新字节抹去 | Gift114—117 本地纵切，不等于生产全系统 |

V1 的九组**解释责任**与之前十三类发现坐标是多对多映射：①类型身份角色 ②值关系及量化 ③状态事件及转移 ④时间轨迹与进展 ⑤事实来源与知识 ⑥目标规范与偏好 ⑦资源及约束 ⑧外部效果与权力 ⑨合同、保证、演进。它们是模块间接口组，不宣称已形式证明数学最小性，也不把它们复制成九张持久作者对象。实际每一组需要：`Signature(type,domain,scope)`、`Interpretation(meaningVersion,assumptions,observation)`、`CompositionRule`、`UnknownAndFault`、`RealizationNeed`、`EvidenceKind`；只有 Schema 而无消费者时应如实记作 **DESIGN_ONLY**。

**知识真值与规范合法性分离：**事实支撑可为 `support only / refute only / both / neither`，并各自绑定来源、时效、完整性；`permit` 是规范陈述，运行授权由独立 Grant 发出；`oblige` 要有主体/触发/期限/解除/违约观测；`achieve` 是目标，不是已履行的 Effect；`prefer` 只在完整硬合格候选之间比较；`maintain` 按指定历史/时间范围检查，单次快照不能证明无界永远满足。`not` 在正反证据共存时不得简单复写“False”；开放与封闭世界选择必须由有资格的来源指定。概率、跨轨迹隐私、因果和物理模型没有可得解释时保持相应 Need。

**唯一身份/存储责任：**已接受作者 `Definition/Requirement/Intent` 的来源由 `AuthorSource` 保存；V1—V5 中的解析、模式实例化、联合义务图、Binding/Assembly/SourceMap 是派生视图；身份锁、revision、时效、权限和正负依赖按其原责任登记。新领域定义绝不能因 `URI`、文件存在或 `verified:true` 自动装载可执行代码或取得真实世界权利。语义抽象层改变不要求复制相同的事实为另一套持久源。

### 从语义全域目录到实际消费者的跨域闭合

完整阶段准入在[工程全生命周期八阶段与准入合同](../../00-系统与原则/设计方法/工程全生命周期八阶段与准入合同.md)，本节只负责原有**通用语义共同合同**中跨域消费的含义。可执行受限样本在[Gift103](../../../fixtures/semantic-universe/Gift103/README.md)。这里不增设世界业务的封闭 `kind` 列表、第二权威作者源或产品实现的虚假资格。

#### 1. 八种不得相互代签的断言

| 要判断的问题 | 输入的真实 owner | 真正的消费判定 | 典型失败 |
|---|---|---|---|
| 引用了什么 | `SourceProfile`、ModuleUse、DefinitionRef、revision | 固定上下文中的唯一主体/版本、可见性与实际读集 | Ambiguous、Stale、Invisible |
| 产品要求什么 | 作者 Definition、Requirement、Claim 范围 | 区分目标、硬要求、偏好、规范、例外与适用条件 | Incomplete、Conflict |
| 世界事实是否已知 | Evidence/Observation 来源、主体/时刻、证明方式 | 已观察、陈述、推断、冲突及证据闭包范围分别判断 | Unknown、StaleEvidence、ConflictingEvidence |
| 政策是否允许 | Policy/Requirement owner，主体/行动/资源/环境条件 | **规范允许**与禁止及义务按被选中的政策合同判断 | Denied、Undetermined |
| 当前主体是否有权执行 | 当前授予者、Grant、有效期、撤销与运行 Scope | 对本次真实操作单独验证**运行授权** | NeedGrant、Revoked、ScopeMismatch |
| 哪个状态变化可接受 | 已验证当前前像、event/command、guards、时间 | 提出受共同不变量限制的合法**候选**后像 | IllegalTransition、StalePreimage |
| 哪个现实效果需要兑现 | Effect Definition、Method、Target、Operation | 核真实方法的事务域、重试、资源与恢复资格 | NeedMethod、UncertainCompletion |
| 已经发生及获得什么保证 | 真实 Attempt/Readback、Claim 与独立 Evidence | 只在证据覆盖范围内判断 settled 与 assurance | Inconclusive、InsufficientCoverage |

这些只是语义接合的检查位，不要求任何一份作者 Definition 再保存八份同义内容。纯计算可以没有现实 Effect；外部支付必须有供给与现实观察；法律或物理解释需要相应外部权威和校准而不能归约成布尔函数。

#### 2. 消费者顺序与精确退出

```text
Captured SourceSnapshot（授权范围、真实作者字节与Revision）
  → Decoded/Resolved Definitions（绑定的实际语言与使用点）
  → Domain Elaboration（局部含义、来源、Unsupported及Need）
  → Typed Join（跨域主体、状态、时序、资源、规范和效果共同不变量）
  → Qualified Candidate Selection（Method、Target与环境适用性）
  → TargetProjectPlan 或真实 ArtifactSet（不能冒充互相替代）
  → 已获授权的 Operation/Attempt（只有用户需要执行时）
  → 真实 Readback、Claim、Evidence、修订失效与恢复
```

解码成功只证明读懂字节；Elaboration 有资格只证明它真正支持的语义范围；Join 只给当前已绑定 Definition 的联合义务。严格禁止从「产品希望支付成功」推导「实际支付已到账」，从「Policy 允许」推导「Grant 已授予」，从「State 后像可计算」推导「数据库已持久提交」，从「生成源码」推导「现实 Effect 已发生」，从「一次测试通过」推导「所有环境安全」。

开放世界的 unknown、尚未解释的 dialect、与当前授权不符、矛盾的事实来源和方法候选不足是**不同错误**。每一种需要明确的主体、读集、失败原因和后续消费者，不得统一返回 `false`、`null` 或泛化的“编译失败”。

#### 3. 局部解释及组合资格

每个新 SemanticModule/Dialect 只有在声明并兑现下面**实际消费能力**时，才能加入相交编译链：

- 输入域：schema/类型/规范版本、读取 scope、预算、依赖、实际语义模块及完整成员身份。
- 解释：可以解释的 Definition kind、精确主体、观察域、错误/时序/资源和失败边界；无法解释的保全源并返回 `Needs`。
- 跨域端口：类型、版本、角色、资源、时间、真实作用、承诺的假设与保证，及不允许的组合。
- 目标资格：仅支持哪些 Method/Target/Profile，保持哪些值、异常、次序、并发、效果与资源条件；每个未保持项均为残余义务。
- 变化：旧模块/旧 SourceRevision 的解释与当前生效资格分开，撤销/失效应传播到真实相交消费者，不能仅比较字符串名或重用旧 Grant。

组合前提可表述为：在固定使用点上，消费者 B 对输入的假设须由生产者 A 的保证和明确环境条件共同满足；再验证共享资源、作用顺序、权限、状态及时限的不变量。局部通过不自动构成联合通过。缺真实可判定程序时只给联合设计义务或 `Need`，不可强造一个万能 SMT 证明器。

#### 4. 明确的跨域反例及真正的约束

1. **付款回调**：收到 callback/HTTP200 不是 Provider 已结算；必须绑定可信支付标识、对应订单/金额/版本及真实回执的适用范围。
2. **政策与授权**：角色字符串或 Policy permit 不是当前 Grant；真实读写分别核操作范围、撤销及有效期。
3. **库存去重与超卖**：单进程 `operationId` 集合或 `revision+1` 不证明跨库、跨进程的幂等与持久原子提交。断线/超时可能使远端处于 Unknown Completion，必须先查回。
4. **传感器与设备**：温度/压力判断还需要来源校准、单位/时钟域、最坏响应时间及实际执行机构，纯模拟不能替代硬实时和物理互锁。
5. **隐私用途与数据使用**：能访问数据不是法律/组织上允许其新用途；撤权、保留令、位置和留存期限需独立适用范围与权责。
6. **负载与成本**：函数正确不代表延迟、内存、吞吐、可恢复性或性能边界合格。硬质量要求必须先过滤，偏好才有择优意义。
7. **变更和证据**：更换 Provider、方法实现、规则版本或环境后，旧检查只能在其真实读集仍成立时复用；声明“契约同名”不足。

#### 5. Gift103 有限可运行见证，以及为什么不算完成全部产品

演示复用合法的 `gift.author-module/1` **外壳字段**，选择实验性 `gift.fixture.cross-domain` 精确解释器（该 Dialect 未登记为当前生产语义包，也未取得完整 binding lock）。`cd:policy`、`cd:observation`、`cd:flow`、`cd:effect` 是该独立可执行**样本**的有限局部域，不是 Gift Core 的通用种类表。

解释器在模型入口检查重复定义、(state,event) 二义性、缺失引用、状态边界、Policy/Effect/Observation 的合格关联；在单次纯候选判断中检查角色 Policy、同操作事实观察、模拟准入、精确 uint64 revision、重试和外部效果意图。对外状态必须清楚区分 `SIMULATED_PLAN_ONLY`、`NEEDS_GRANT`、`NEEDS_ATTESTATION`、`POLICY_DENIED`、`RECONCILE_OPERATION_FIRST`、`STALE_REVISION`、`REVISION_OVERFLOW` 等结果。输出无条件声明**真实授权未建立、外部效果未执行、结算未知**。

生成的 TypeScript 拥有真实事件/状态分支、已解析的 Domain Definition 参数及共享纯判断方法，能用 `tsc` 严格编译并运行，且新领域使用相同 Generator/Method。**它没有支付签名验证、DB CAS、事务、真实 Grant、外部 Provider 和读回端口，不能部署为有权付款或安全设备控制系统。** 模拟器使用与请求分离的测试前提，但测试输入并不取得现实证据权威。

#### 6. 真正实现的对外接口应当有哪些责任

type Elaborate = (source: CapturedSource, language: BoundLanguageImage)
  => CheckedDefinitions | UnsupportedWithNeeds;

每个边界的字段/codec、权限、失败、取消、租约、版本、固定读集与恢复规则由其原 Owner 定义，不能在本页复制第二份标准协议。正式实施的必要补齐见 [当前实施闭包](../../90-治理与参考/状态/实施闭包.md)，相交物理责任见 [源码分区与机器合同](../../70-工程系统与演进/实现与装配/源码分区与机器合同.md)。

#### 7. 语义等价与作者字节身份不能混用

本轮有限解释器最初直接用整份作者 JSON 的规范化摘要命名语义修订，会导致仅改显示名称也让语义判断/目标源码无谓失效。现已改为**两个独立身份**：作者模块的真实文件字节 `authorByteSha256` 在目标 Manifest 证明精确输入；`modelRevision` 则从已解释的主体、状态、转换、Policy、Observation 和 Effect 规范化后计算。允许对象字段顺序及无关显示名称变化而维持语义身份；issuer、Policy/Effect、实际状态迁移变化必定更新语义摘要。内存中的受限投影并不代替原工程的完整 ModuleIdentity/SourceRevision/Lock；正式产品读取器仍必须固定使用点及依赖图，并在变更时先取真实新字节，按读取的准确消费者传播更新。所有 hash 只是内容身份，不是代码签名、Grant 或安全证明。

#### 8. 针对不同变化的局部失效

- 改 SourceRevision：重核真实包含该 Definition/Use 的解释与相交消费者；未相交模块无需重跑。
- 改事实 issuer：旧观察的可信与适用性必须重审；不能因为数据值一样就沿用。
- 改 Policy：只失效相交授权策略判断及其派生保证，不自动创造/撤销远端 Grant。
- 改 Effect 实现：保持语义与错误/资源/恢复资格须重新核实；必要时更换目标/补偿方案。
- 仅切换合格 Lowering：作者的语义仍稳定，但目标源码字节、性能/错误行为与方法资格可能变化。
- 因真实运行故障改变设计：将失败反例定位回正确 G0—G5 owner，修复后对现有运行/部署/旧 Pending Operation 分别处置，不用重新编译抹掉未知结算。

**本节止于全域合同的实际可消费化设计；其实现只验证有限 CD Dialect 的两类业务。45 家族、135 侧面的全域解释、全部语言目标及现实生产资格仍是独立未完成工程，不能从此演示自动推定。**
### 通用性按生成能力而不是列尽所有行业名判断

跨业务通用性至少涉及开放 Entity/Relation、State/Event、Goal/Invariant、Obligation/Permission、Time/Observation、Preference/Resource/Effect/Recovery 和 Assurance/Evolution 的**组合与扩展能力**。这些是相交机制的生成入口而非固定行业语义枚举。新普通业务 Definition 不改 Kernel；新不可归约的现实观察、规范或权限，需要对应解释、Authority 和 Effect 供应，没有资格仍可表达但不得执行。

同一种资源容量机制被两个不同行业复用时，临床批准、GPU 抢占、超售合法性等不同事实仍独立存在；同名 `confirmed` 不等于同一结算/法律/界面事实。覆盖验收必须区分可表达、可解释、可组合、可装配及真实观察，不能以通用计算表达式数量替代业务意图成果。
