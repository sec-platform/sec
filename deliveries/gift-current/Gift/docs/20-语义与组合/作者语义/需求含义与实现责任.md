# 需求作者与实现精化

## 意图优先的作者控制入口

本章的合同满足关系由[通用意图语言](通用意图语言-意图源与语义组合.md)中的实际被接受目标触发。普通产品不以 `s:function`/递归代码作为唯一目标形态。函数、Requirement/Rule 和状态模块可以作为某个已采纳 Intent 的独立含义或实现供应；不允许把派生计算主体取代原意图发生身份和禁止条款。

本章规定产品作者保存哪些已接受需求：对象、可观察结果、应保持或禁止的行为、合法变化及必要的领域差异。现有Requirement/Definition可直接引用；具体算法、目标语言和运行适配由合格实现供应承担。只有作者明确开发或接管底层算法时，普通函数与原生源码才成为其编辑职责；不能把已有代码的逆向描述代替业务意图。

本章拥有需求含义及接受关系，不重复定义文本或结构Codec。当前新产品作者内容按[结构化意图与Block模块](../../10-作者与输入/作者源/结构化源码.md)保存；下文`use/require/prefer`是语义说明，持久源仍为类型化结构。既有`design`文本方案仅在显式选择时使用；不能由本章另创可写IntentIR、语言服务器或权限存储。

## 作者目标与实现分工

短`fn`、lambda、补全、逆向与连续开发分别服务于计算或维护任务；它们不能替代新产品的完整意图定义。缺少现成库时，需求仍由作者源保留，实际供给由实现责任补齐，不把全部底层主体自动退给产品作者。

现在分开四种内容：

| 内容 | 作者需要决定什么 | 由谁持续维护 |
|---|---|---|
| 自然语言任务与外部依据 | 接受目标、硬约束、可委派选择；允许保留尚未正式化部分 | 任务/需求拥有者；编译不每次重新猜原话 |
| 需求作者源 | 同一产品中的对象关系、行为、负约束、变化政策及复用 | 产品作者，日常主要修改这份内容 |
| 可复用需求定义 | 某项能力究竟约束哪些输入、输出、状态和观察 | 定义作者；可由数个已有定义组成，不必含算法 |
| 实现供给与派生产物 | 采用什么库、布局、调用、算法、资源和目标源码 | 供给作者/受委派生成器与编译器；不是要求每个应用抄一份 |

“源”是可重建工程的权威输入，不等于语句流、类成员或目标语法。需要五处同样不丢失草稿的功能，不写五次恢复算法；要求发布当前搜索结果，不写回调、队列和锁。相同公共关系可以合并，具有不同主体、资源身份、效果和观察的关系不能只因内容相同而合并。

冻结的完整工作台意图源是一个完整实例范本，不是从 Code-OSS 文件逐个翻译来的模块镜像；它固定该实例的选定产品范围，用于校准本节所述作者职责。现行通用作者语义与责任由本节及活动结构化源码规范拥有；原 Code-OSS 源码观察仅为可能的供给校准材料，不决定当前作者合同要写多少类和服务。

## 需求约束的是可接受产品，不直接规定内部步骤

一个绑定后的需求由：主体和观察域、允许输入及环境条件、可接受结果/轨迹、必须保持的外部状态、失败/进展义务，及当前证据责任共同确定。它不必唯一决定一种实现。

例如“替换必须与用户看到的预览相同”至少包含：哪个模型和版本、哪批选中编辑、如何确定替换文本、哪个用户接受、何时失效、失败后什么不能重放。它并不要求作者决定使用双缓冲还是持久数据结构、类如何命名、锁放在哪个模块。可观察差异不能被塞进“实现细节”；不可观察且已委派的自由也不能逼作者逐项指定。

以下是需求的**接受行为语义**，不是要求部署唯一的通用求解器：每个 Requirement 限定一组允许实现。`use A(s)` 与 `use B(s)` 对同一主体取交集，`require`施加硬条件，`prefer`仅对合格域排序。完整实现必须覆盖接受的输入/环境、正常结果、异常和进展，保持跨运行、概率及上下文中实际被要求的关系；永不执行、永不返回或总报错的空实现不能以满足部分安全条件代签一个应当可用的产品。

类型检查、静态证明、有限测试、运行监控和人工/外部接受各有范围。结构合法不是实现存在；监控发现禁止写已发生不是阻止了禁止写；检测到每次读值相同也不证明非干扰。未知条件保存为未知，不修改原需求让当前实现通过。

## 同一套抽象承载哪些不同需求

下列是已识别的**语义形状及组合入口**，不是声称世界只有固定数目的需求原子。新实例通常增加参数/定义；真正出现现有语义无法表达的观察时才增加相交域规则。

| 需求形状 | 作者固定的内容与例子 | 不能省去的差异、编译责任 |
|---|---|---|
| 对象、值域与数据结构 | 文档、区间、账户、图节点；键、单位、边界与相等 | 名义身份/值相等、有限值/循环对象不同；不从路径名猜身份 |
| 转换与结果关系 | 输出等于输入区间的同覆盖规范化、排序或聚合 | 相同输出集合不一定相同顺序/多重性；正向算法由合格方法取得 |
| 关系与查询 | 选择、连接、聚合、唯一、包含和闭包 | Bag/Set/序列、空值、负查询覆盖、递归条件分别进入语义方法 |
| 状态与守恒 | 已确认计划不可变，余额守恒，关闭状态不能写 | 初态、合法转换、帧和错误都需定义；不是一个布尔字段就得到状态机 |
| 输入输出与协议 | 消息类型、版本、协商、错误和交互会话 | 线协议、编码、信号顺序、端点身份与重入由接口供给保持 |
| 时序与进展 | 旧结果不可覆盖当前，正常请求最终完成 | 安全/活性、逻辑取消/物理停止、公平调度假设不能互相代签 |
| 事件与流 | 每个分区有序、窗口、水位和迟到政策 | 输入顺序、事件时间、处理时间及结束/丢失各有语义 |
| 作用与一致性 | 只改选中文档、分项保存、提交或补偿 | 原子范围、观察者、幂等寿命、重试与未决作用不能由一个transaction词包办 |
| 所有权与生命周期 | 草稿归模型、任务子资源归域、关闭时结算 | 共享值/独占资源、借用/移动和暂停/终结不同；物理资源在实现侧检查 |
| 访问、秘密与隐私 | 某范围可读，不得未经许可出网 | 声明不是实际授权；动态扩展必须有完整中介；非干扰可涉及多条运行 |
| 表现与交互 | 可编辑工作台布局、焦点、命令、主题和无障碍 | 不是后端API就算交付UI；像素/文案/设计token有真实资产和默认 |
| 结构与部署拓扑 | 单机/远程、隔离域、副本与共址约束 | 有连线不必RPC；共享语义主体不必同进程；部署不能取消约束 |
| 表示与数值 | 编码、精度、舍入、溢出、ABI与布局 | 数学整数、定宽、浮点、地址观察分别约束目标；不以语言名替代 |
| 资源与性能 | 容量界、工作负载、延迟/吞吐目标 | 有界不等于快；实际测量和误差进入证据，不捏造未测百分位 |
| 变体与配置 | 某条件启用能力、不同发行画像 | 编译期选择与运行状态分开；缺省来源可查，硬约束不能被后写覆盖 |
| 演进与兼容 | 接口、数据迁移、旧运行与退役 | 同schema不等于同语义；迁移可逆性及实际采用独立 |
| 随机、学习与自适应 | 分布、损失、采样、适应范围 | 一个样本不能代签总体误差；模型权重与数据是绑定的实现输入 |
| 选择与优化 | 硬合格后的内存/延迟偏好 | 多目标与未知代价保留；预算停止不声称全局最优 |
| 外部职责与证据 | 法律/组织/物理假设、人工接受、统计保证 | 编译器可编制证据/运行限制，不能凭代码生成使外部命题成真 |

使用这些形状不要求普通作者先挑十九种模板。已有“工作区搜索”定义直接暴露本任务关心的几个决定，其余公开语义继承。只有确实改变含义的点才下钻。研究面开放不意味着每个根必须装载全部语义库。

## 组合不是流程，也不是任意继承覆盖

`use A(s)`把A的约束适用到当前s；不是先运行A，也不创建AService。声明顺序不决定目标执行顺序。需求之间真正的时序通过相应时序/状态定义表达。

硬约束同域合取。同一个替换主体既要求“过期计划拒绝”，又要求“无需再次确认立即按新文本应用”，应报告冲突，不按后写覆盖。把root变量绑定成同一主体才会共享；不同产品根、不同会话或不同有状态实例不能因源字节相同而合并。无状态需求幂等合取可以共享分析，但保留多处来源责任。

复合定义对外仍是普通Definition，形参与公开约束构成边界，可继续被use。没有固定层数，也不要求每个特性单独发包。公共边界不暴露所有私有参数；必要时再引入一个真正可控制的参数。复合证明依赖必须检查初态和保持，不能A只假定B、B只假定A就同时成立。

变体需要可核对的语义，而不是标签：既有RequirementTerm的All/Any/Conditional/ForEach仍为唯一组合语义。文本中`use`承担常见合取；其余通过带类型的需求定义，例如`logic.AnyOf {on: s, alternatives: [a.Design, b.Design]}`。这些构造的字段合同见[供给规格](需求规则与供给合同.md#generic-requirement-constructors)。运行选择必须有运行选择的方法；编译期Any不能未经说明变成运行期随机挑选。动态成员的ForEach不能被当前枚举到的几个成员替代。

### 作者约束不能重新变成实现指令

需求字段必须约束可观察行为而不是替供应者挑内部数据结构。要求“位置无歧义”不自动强制 UTF-16 缓冲，要求“用户可见编辑”不自动指定快照类，要求“未知响应不重复单步”不自动规定未决槽。范本用 UnambiguousSourcePositions、DisplayedEditsOnly、NoDuplicateUncertainCommand 表达这三项；坐标转换、冻结与恢复由合格 Method 实现。只有接口、ABI 或已接受设计使具体表示对外可观察时，该表示才升级为硬要求。

## 省略、缺省与委派不能偷换

作者可以不点名实现，不必不点名业务规则。已导入的定义固定了错误、顺序、默认、资源和变体，这些内容无需逐项目复写。缺省只有在定义明确给出、版本固定且未违背硬约束时使用；字段被省略不自动表示null、0、无限、随便或false。

输入由四部分闭合：本源明确约束；被引用定义的固定公共合同；已接受工程/产品政策；编译器获得委派的实现自由。实际运行参数和当前权限另到运行边界取得。没有明确限时便不宣称毫秒SLA；并不因此要求作者现在填写所有未来性能参数。

在本范本中，默认文案、主题、工作台布局和按键配置由供给的固定公开资产承担。它们不是“编译器随便画一个UI”。作者要求自己的品牌/精确布局时，新增该实际资产/约束；不必改所有事件处理器。固定制品的生成不再触发AI改变文案或选择另一种政策。

## 没有现成供给时，产品作者仍然不必改写全部算法

先区分缺什么：缺语义、缺证据、缺实现和缺目标能力不是同一种问题。

已有需求含义完整，但无适用方法时，保留完整需求作者源并给出**实现义务**。受委派的合成器/实现作者可以组合已有方法、使用领域求解、生成局部实现，或接合成熟组件。得到的主体绑定原需求与证据，保存在原实现定义/Binding/产物体系；不默认把它展开进产品作者文件。不能仅把函数名写出来就登记为已有供给，也不能在编译失败时自动生成`TODO`或返回成功空值。

新实现采用后固定其准确内容、方法、输入域、环境和验证范围。普通重建复用它；原需求变化时检查相交义务，只有相关供给失效才重新生成。合成失败只说明本次方法/预算未完成，不证明所有实现不存在。语义本身有未接受的选择时，按真实委派采用固定保守选择或提出具体决策，不能让搜索器悄悄缩小输入域。

**新需求也可以只写关系，不写算法。**例如“有限半开整数区间列表，忽略空区间，输出保持覆盖、升序、互不重叠，并把相接区间合并”足以定义规范化结果。排序扫描、平衡树和特定增量索引是实现备选，需求作者不必维护三种实现。数学Int的目标需要保持该范围，不能因TS方便而缩成Number安全整数。

相反，“推荐我最喜欢的结果”若未给偏好来源、候选域、评估和可接受误差，只是尚未闭合的需求。可以保存自然语言及证据义务，继续不依赖它的工作；不能生成一个排序函数就声称本义已确定。

### 行为复用与成品差异

相同精确行为可以作为定义包、纯库、CLI、工作器、请求处理器、插件或交互产品的一部分；公开I/O、激活、宿主与交付责任不同，不能只有一个shape字符串就宣称等价。作者维护行为与确实选择的消费边界，供给承担准确差额。共同设计见[作者成果与成品边界](../交付语义/交付公共合同.md#gift-unit-501703299c2052ad9d1e9e2adc6ad993)；多成品范本保留冻结的完整结构实例用于校准。范本不取得当前规范 authority，也不要求每个项目复制多种输出。

## 作者面完成度如何判断

本版不再用小函数生成成功衡量整个需求作者面。对一个明确产品范围，应该能直接取得：全份作者源及其进口含义；每个主体的实际观察与共享关系；正向行为和错误/进展/帧；允许变化与默认；可复用组合；到各目标的实现责任；缺项的准确类型。这个范围以外的真实设计义务继续保留。

源可以完整而实现未完成，正如一种已定义语言可以还没有编译器。反过来，生成出能运行的程序也不证明意图抽象完整。只有复杂要求必须由用户下沉去手写大量无独特价值的函数时，才说明产品作者面仍漏掉了应由复用定义/编译器承担的工作；不能用“图灵完备所以都能写”关闭这个缺口。

**本例产品文件为 `studio.json`；`standard.json` 与八个结构模块完整给出可复用需求定义。它们使用一个现有模块外壳与本次明确的需求体编码；旧十份`.gift`只作未采用文本表面的历史对照，不是第二可编辑真源。**十份文件是本次把定义也展开交付的组织，不是每个应用要重写十份源，更不是十个服务。下一工程可以继续引用同一完整定义，仅改自己的独特条件。源行数没有预设上限或压缩率承诺；更重要的是每条作者声明表达独立需求，而不是实现过程或重复元数据。

## 需求完整性由可区分行为检验，不由表示格式证明

同一结构可以拥有准确语法而漏掉独立的产品区别。例如仅写键升序，没有固定稳定性；生成与Oracle都沿这份结构工作时可以一致通过，却违反另有来源的“同键保持原顺序”。先用已取得的独立接受来源和正负情景确定这一区别，再补回唯一要求定义、方法和消费者；不能为了避免新字段而把未表达偏好猜成实现自由，也不能让产品作者维护排序算法。

当前完整定义可以直接复用；真实委派允许系统选择并固定结果，不要求所有微小行为都先询问作者。尚未取得的私人偏好保持未知；任务没有独立稳定性要求时，也不能凭空追加它。完备声明只覆盖实际取得并处理的需求及已发现区别，不从“有19类需求或若干JSON”推断所有新需求都已可编译。

验证与保证的接合见[解释与证据](../../60-保证与证据/保证/解释与证据接纳.md#evidence-interpretation-boundary)。扩展收益按[分层任务比较](../../60-保证与证据/验收/覆盖与收益判据.md#adaptive-confirmation)检验：已用范本、未见组合、新语义和新供给分别统计，不以复用者的两行入口对比另一方从零实现全库。

## 通用语义覆盖不等于计算覆盖

[工程通用语义全域与闭合合同](../共同语义/工程通用语义全域与闭合合同.md)补足作者定义的模式、时空适用性、权利义务、开放世界与现实效果分层。普通业务创建仍是复用/创建 Definition 及其可观察合同；Method 的缺失不要求作者退回去编写底层循环，也不允许解析器从一句业务标签臆造第三方事实或权限。

<a id="open-intent-universal-authorship"></a>
## 开放的意图语言：自由定义与实现委派的确定性边界

**本节是作者意义的规范补充，不新设一种必须双写的「万能意图IR」。** Gift 必须像通用编程语言一样，允许创建此前没有命名、没有领域包、没有行业模板的新功能；但其主要编辑对象是*可观察承诺*，而非默认要求作者逐条指定算法与目标机器指令。语言自由度不能用「任何文本都接受」衡量，要用新的语义定义能否在不改 Kernel 的情况下被类型化、引用、组合、选择、精化和更新衡量。

### 四种不可互相替代的开放性

1. **定义开放**：作者可在自己的 namespace 发布新 Type、函数、谓词、Relation、State、Protocol、Requirement、Component 与可重用抽象；语义相同的实例沿固定 Definition revision 引用，不向 Core 注册业务词条。新定义不必依赖 LLM 或官方候选目录，也无需改变已有产品源的 Authority。
2. **计算开放**：新算法允许组合抽象数据类型、模式匹配、递归/循环、高阶函数和局部可变状态，必要时表达通用计算。它保证语义*可表示*，不代表编译器能从任意性质自动找到算法，或任意未证实算法均正确。
3. **行为开放**：可定义新的可观察状态变化、轨迹性质、消息协议、外部效果的**意图**和失败政策；纯计算层可以表示这些操作的描述，但现实读写、时间、授权、第三方副作用需要对应 Effect Handler/Provider 的真实资格。定义一个 `EffectOperation` 不等于获得执行其现实效果的权限。
4. **实现开放**：既可引用库、选择适用的已合格 Method、根据约束合成局部主体，也可在用户明确接管时编写真实 Gift 计算体或原生目标代码。后两者提供表达能力退路，不得被伪装成「自动从意图生成」。

这四者分别报告 `SEMANTICALLY_EXPRESSIBLE`、`IMPLEMENTATION_AVAILABLE`、`TARGET_LOWERABLE`、`WORLD_EXECUTABLE`，并提供可区分的失败原因；这些名称是面向文档的结果维度示意，不把它们新增为全局公共状态枚举。跨域组合能够复用旧的计算/关系/效果合同，却不能凭新名字自动获得世界规律、行业规范或设备接口。

### 什么才算一条真正的意图，而不是模板或待猜语句

以任意新功能的合同 `S` 为例，其最小信息分为七组，未用者无须占位：

- **身份与调用域**：此定义的稳定身份、参数/结果的精确 Type、对外可用的入口、被保证接受的合法输入；区分未指定输入和不合法输入。
- **可观察意义**：哪些输入/状态/事件/环境投影参与，哪些返回值、错误、轨迹、资源及其它实例的行为必须区分；`ObservationScope` 是明确的语义边界，不是从文件扩展名猜测。
- **功能关系**：合法前置条件下，输出应满足的关系、正常功能存在/可达的条件及输出完整性的义务；纯安全断言不能允许「永远拒绝」满足一个本来要求提供服务的函数。
- **帧和作用**：不能修改哪些真实资源，允许读/写什么，异常和取消后哪些状态保持；值恢复不等于没发生过写操作。
- **时间、并发与进展**：即时的 safety、条件性的 eventual progress、容量和实时界，分别引用有定义的时间/调度/资源模型；条件假设与结论绑定，不凭编译成功保证外界公平或时钟准确。
- **开放选择与委派**：哪些是作者不可放宽的硬要求，哪些是可比较的偏好，哪些是已批准的可选实现、已固定缺省及无权擅决的公开差异。实现内部自由不等于可修改作者的输入域与契约。
- **解释与保证依据**：语义定义何处取得、外部事实如何被供应、对哪种目标/版本/数据域有证明、符合性测试、运行证据或未知；`NotProven` 不当 `False`，也不当 `True`。

把这些信息展开为概念分组，不意味着一个作者文件每次都要填写七个大对象。完全定义的外部库只需 `DefinitionRef + 实参 + 本次真正差异`；简单纯算法的 `result: Int; ensures: result = x+x` 可以仅保留已锁定 Int 定律。新增原语语义时必须给它一个可审查的解释接口，不能仅以任意 `kind` 字符串获得核心执行含义。

### 「任意功能」的最小反证样本

一种此前不存在的业务功能可以把任务定义为：对有限整数区间列表输出规范化的最小半开区间列表，包含相同整数覆盖、升序、互不重叠且不得有相接段。此合同完全不依赖业务关键字；Method 可选择排序扫描，不要求产品作者管理排序实现。增加「同覆盖时优先最少分段」只是意图加强，仍不等于用户必须写算法。

再定义一个前所未见的规则：输入有向图、起点和终点，输出一条合法路径，若路径存在必须输出；若不存在明确返回 `None`。这个新能力可用图类型、路径谓词与递归 reachability 组合出来；若没有适用图算法，仍可编译保存其 Requirement，也可以由实现作者在结构计算体实现 BFS/DFS。但单给出 `connected` 这个名字、不定义边、可达与无路径语义，就是未取得 Meaning，不得生成一段搜索模板冒充已实现。

第三类是工作台：只发布某个最新修订的成功结果，但必须在输入稳定、计算终止且运行公平的假设下最终发布结果或相应错误。最新版本标记本身能保证丢弃过时结果，却不能替代最终发布的活性义务。第四类是资金清算或远程执行：业务意义可以写出，但没有发行方、真实效果、幂等范围和外部回读，不可从「计划」升级为现实提交。

**接受一次全新语义所需的最小过程**：解析开放定义/版本 → 类型和作用域约束 → 在其发布的语义解释器/定律下产生正式 `Definition/Requirement` → 完成行为与进展的义务 → 查合格候选或请求有权创作实现 → 按目标生成并验证适用范围。新类型和纯函数无需逐项目改 Gift Kernel；真正新原始 Effects/观察事实要额外提供模块/Target/Provider，但不是针对每个业务名注册一个内置分支。

### 三条不可逾越但不妨碍自由的限制

**表达普适 ≠ 自动合成普适。** 自然语言若缺关键判别信息，程序的正确性没有唯一对象；任意通用程序的终止、等价及复杂功能性质一般不可判定，有限预算下也不能无限搜索。Gift 应输出明确的 `NeedsMeaning`、`NeedsAuthorContent`、`NeedsEvidence` 或 `SearchIncomplete`（沿现有公共出口映射）并保留已可用的局部结果，而不是把不可能的问题遮成缺少几个业务模板。

**抽象高低取决于所承诺的区别，不取决于 JSON 长度。** 在相同语义库和公开需求基线下，比对每个作者必须写出的独立业务决策与机器可继承的实现决策；若实现算法固定后才可解释要求，便发生反向依赖。对未有公共定义的独创新算法，编写一次实现是合理成本；要求所有复用者复制算法不是合理默认。

**新颖性不许可绕过权限与证据。** 可以定义尚无执行者的独立效果、协议或实验性模型，允许设计/解析/候选分析；不能将作者在源码中写下的 `authorized=true` 作为 Gift 对现实系统的授权，不能以过去环境的合格 Method 代签当前环境。

## 意图的精确定义、可计算意义和实现自由

### 不再让 meaningRef 的名字代替定义

一个 Meaning 引用必须沿 SourceSnapshot 与锁解析到实际 Definition 及其解释资格。解析结果至少区分：由有限语法解释的计算/关系定义、已登记的原始语义、依赖显式假设的公理/外部模型、尚无解释的作者草稿。前三者保留不同证据基础；第四种不能进入“已理解、可合成”的结果。普通新谓词优先由 `s:function` 等现有语义构造表达完整主体，不为每个规则增设 Kernel `kind`；只有确实新增不可由现有语言组合的原始观察或效果才需要 SemanticModule。

需求可以描述一族合法实现，而不唯一决定算法。公开输入、结果/异常、状态变化、帧条件、进展、精度或披露构成作者承诺；内部索引、循环形状、缓存、布局和并行可以委派。一个行为差异是否“内部”由可观察合同决定：稳定排序、错误先后、数值舍入、取消时释放和网络传输通常不能凭优化器偏好抹掉。成本目标若会反转方法选择，由当前有权作者给定，编译器不能为得到候选偷偷降低。

### 函数规格与一般计算体共用一个定义体系

已有 `s:function` 可有签名与 requires/ensures 而没有 expression。这表示**待实现的合同定义**，不是空函数、抽象桩或永远抛错的实现。Method 指向另一个具有实际表达式的实现 Definition，并检查其对合同的保持；实现的私有辅助函数、数据结构和证明可被库作者维护，调用方只引用公开合同。具有 expression 的函数也可有合同，不要求为每个小函数永久拆两份同义文件。

`requires` 是输入/环境的前置关系；`ensures` 是正常结果上的后置关系。存在实现不意味着前置条件真实成立，返回类型正确也不意味着后置成立。一般计算函数允许不终止；纯函数只表示没有声明的外部效果，不自动取得全函数、可重排或可用于逻辑公理的资格。将某计算函数用作逻辑谓词时，需要定义其终止/定义域，或由相应逻辑明确保留“未定义”的意义；断言执行超时不能读成 false，更不能当成 true。

### 非空洞满足与失败语义

对规格 S、环境假设 A、公开输入域 D 和实现 I，满足至少检查：I 不擅自缩窄 D；正常/异常/取消等可观察结果属于规格允许关系；需要进展的调用在其明确环境条件下有相应进展；只有允许的状态/资源被改变；所声明跨运行关系、分布或误差意义得到保持。安全关系的“所有已返回的结果都正确”不接受一个对全部合法输入永不返回的实现。

D 为空并非语言非法：空类型、不可达分支或矛盾假设可以是合法对象。但某产品要求“对这个已给合法输入成功”时，空域会直接违反该产品要求。检查器分别报告不可满足规格、尚不能证明可满足、合法但空的定义域及实际需求已给的存在见证，不能全局强制每个声明有实例，也不能利用空域替生产能力刷通过。

业务 `Result.Err` 是合同允许的正常数据；Fault、运行预算耗尽、取消和外部完成未知不是同一种 Err。实现方法若允许在无解时返回 None，必须为“确实无解”承担对应证据；搜索停止只能返回不完全结果，不得用 None 混过去。合同不能用 `ensure false` 或拒绝所有输入来伪装通用实现。

### 三条实现路径保持相同作者权限

库复用、限定子域合成和作者提供通用算法都先形成候选实现，再经过相同签名、行为、效果、目标和保证 Gate。AI 创作只增加候选来源，不获得选择/接受/执行的隐式授权。库作者可把已取得的保持依据封装为可复用 Method，使后续业务作者不重复证明同一内容；实际实例新增的前提、目标或环境差异形成残余义务。

实现自由度随硬要求增加而收缩，随明确解除的约束而扩大。语义不变的方法替换不自动改变作者 SourceRevision；方法摘要变化仍使依赖它的源码、性能或安全证据失效。业务作者接管某个实现选择时形成有范围的 Pin 或具体实现源，而不把整个工程切到一套新“手工模式”。

## 十个开放意图样例的语义定案与失效修正

十个Gift106结构草案仍按原字节保留，历史 `urn:gift:proposal:*` 不由名称升级为生产DefinitionRef。本次为每个输入域、正常/异常结果、进展、frame和外部效果提供精确规格，见本文件的“开放意图实例的逐义定义”。规范段落是可审阅的Meaning说明，不是已发布解释映像；后续模块必须把这些含义编码成普通Definition或匹配的轨迹/数值语义对象，并经原Binding锁定，不能让段落锚点直接充当可执行代码。

修正三个不能只加注释的接口错误。陌生Token搜索的 `List<Token>` 不能表达无解及预算结束，正式设计采用判别结果 `Found/NoSolution/Incomplete`；只在完整有限旋转域已穷举时返回NoSolution。最新修订发布涉及对实际文档/工作区的提交，不属于无效果函数；设计拆成纯计划与受权publication Effect，历史 `worldEffects:[]` 只适用于未执行计划。图的零长度路径在节点序列表示下为 `[from]` 而不是空列表。

此外，流窗口缺少窗口/聚合参数不能由名字补齐；数值容差缺少范数/区间/导数模型不能保证误差；泛型map/filter只声明predicate纯而允许f有未声明效果时不能使用纯组合方法。新精确规格显式补这些必要参数和限制，兼容迁移必须由作者采纳公开区别，不能对旧输入静默猜默认。UI输出轨迹的纯模拟与真实renderer、输入设备和无障碍观测分别声明。

对每条proposal依赖及operationRef建立一对一来源→规范位置映射，包含纠错/非兼容的原因、需要的普通定义和资格类型。没有解释器时返回MeaningInterpreterNeed；有精确Meaning但没有方法返回ImplementationNeed；有代码却无运行权限返回AuthorizationNeed。三者不再都写“proposal未绑定”而丢失已设计好的含义。

**验证与反例**：独立有限模型检查区间覆盖/最简、路径合法/不可达、旋转搜索无解与未完成、map/filter顺序、发布CAS；其余案例给轨迹反例和准确证据对象，不冒充已运行外部业务。

**实际能力边界**：十个规格已逐义写出；生产语义模块、方法、Target和Provider资格仍逐域未完成。

## 普通定义的闭环与实现供应独立

对任意作者新Definition，闭环的键是其身份、类型、具体观察合同和引用，不是行业名。Reader只分派既有语言构造；定义 `canFollow(tokenA,tokenB)` 或一个新图标签无需Kernel增加分支。其callees递归进入语义/类型与供应闭包，Method在明确实现关系上挂接，Target在已解释的计算构造上降低，禁止目标打印器根据函数英文名选择算法。

同一新定义由作者甲创建，作者乙通过公开导出和精确import复用；乙不复制甲的实现，也不因知道私有DefinitionId获得访问权。替换Method时甲的公开Definition保持，方法身份/资格及相交产物重新计算；改公开合同则发新revision并通知两位作者的实例。没有实现的被引用函数可以作为合法规格保存，但调用它的可运行输出根返回ImplementationNeed，不发默认源码。

零Kernel修改不要求世界原语凭空有含义。普通定义由已有算子表达时封闭；新增不可归约的时序逻辑、硬件指令或外部Effect时，分别需要SemanticModule、Target或Provider，而非偷偷为其名字加业务模板。闭环验证同时查看Kernel diff、最终调用解析和目标实际操作，单纯“没有编辑Kernel文件”不证明没有在插件中硬编码行业分派。

**验证与反例**：双作者新谓词/新算法、缺Method、私有导出、换Method和新增原始Effect是六个独立检查。与A08的Token谓词和A09的普通清单函数相交。

**实际能力边界**：两个真实作者项目的生产编译及Kernel零改动对照未执行。

<a id="meaning-interval-normalization"></a>
## 半开整数区间的唯一规范结果

输入I是有限有序List，每项为(s,e)，s、e是精确Int且s≤e。s=e是合法空区间；s>e是DomainError，不自动交换端点。覆盖集合定义为Cov(I)={z∈Int | 存在(s,e)∈I且s≤z<e}。输出O也是有限List，逐项s<e，且对相邻两项有前项e<后项s；因此重叠及端点相接都合并，顺序严格按s上升。必须Cov(O)=Cov(I)。

`validIntervalDomain`就是上述输入有限/类型/端点有序条件；`sameIntegerCoverage`就是Cov等式；`minimalOrderedNonAdjacentIntervals`就是输出非空区间、升序及严格间隔条件。三个条件共同使输出为覆盖集合的极大连续整数段列表，而不是只要求某个包含输入的外包区间。空输入及全空区间输出[]；负数、重复区间和很大端点按同一精确整数意义。

实现见证：滤去空区间，以(s,e)字典序排序，扫描维护当前段；next.s≤current.e时合并至max(end)，否则发出当前段。纯计算不改变原List；比较/加索引及整数内存消耗计入预算。`terminatesForFiniteInput`以有限排序和单次扫描、基本精确操作终止为条件；物理资源不足产生Incomplete/Fault，不伪称不存在规范结果。比较次数可为O(n log n)，大整数比较的位成本不能被该次数界吞掉。

验收oracle对有限小整数域枚举覆盖并检查最简结构；超大整数用结构推导及专门词法/算术见证，不通过先转float测试。仅区间列表长度减少不证明覆盖正确。

历史Proposal名字：`validIntervalDomain`、`sameIntegerCoverage`、`minimalOrderedNonAdjacentIntervals`、`terminatesForFiniteInput`。

迁移区别：端点相接合并及合法空区间明确；原有Int语义不改。

<a id="meaning-graph-path"></a>
## 有限图可达与实际节点路径

Graph=(V,E)是有限、可完全遍历的节点身份集合及有向边集合E⊆V×V；节点相等由名义ID或传入的合格相等实现定义，不能按显示名合并。`nodesInGraph(g,s,t)`要求s,t∈V且所有边端点有效；不满足是输入域错误，不等于无路。多重边/自环可以存在于载入表示，但此可达性质按边存在关系解释。

`pathOrNoneIffReachable`分两支：Some([v0,...,vk])要求序列非空，v0=s、vk=t，每个vi∈V，且每个相邻对在E；None当且仅当不存在这样的有限序列。s=t时零条边的合法节点路径是[s]，不是空List。该定义不要求最短；作者增加最短/权重条件时构成新的硬义，原DFS类方法不能自动保持资格。

见证算法用visited/parent和队列或栈，首次访问节点时记录父节点，找到t后按parent逆向重建；遍历完全穷尽且t未访问才返回None。有限输入/相等和邻接遍历终止、必要资源可用条件下，`terminatesForFiniteGraph`成立；流式生成/未知是否穷尽的邻接源不属于这个输入域。预算不足返回Incomplete而非None。frame不改变输入图或未授权状态。

测试既比较独立传递闭包可达性，也逐条核返回边；“返回Some且类型正确”不足。环图合法，不能借A09清单拓扑DAG的拒环规则限制本函数。

历史Proposal名字：`nodesInGraph`、`pathOrNoneIffReachable`、`terminatesForFiniteGraph`。

迁移区别：节点序列形式的零长度路径确定为[from]；预算不足不映射None。

<a id="meaning-latest-revision-editor"></a>
## 当前版本发布与条件进展

纯规划输入为带DocumentId、SourceRevision、源摘要、要求/目标锁及请求代的事件，store视图为明确cut。实际发布另外需要受权PublicationProvider及原子前像比较。`noStalePublication`定义：每个成功Publish事件在其真实提交点，发布所依据的SourceRevision/目标basis必须等于该文档当时被接受的当前基础，且持有当前writer epoch；不能只在工作开始时检查版本。

`eventualCurrentPublicationUnderFairness`为条件时序义务：在某时刻后文档输入/目标/授权稳定、所需Method/资源持续可用、每个必要计算能终止、调度与恢复重试得到公平进展的环境中，最终出现该稳定基础的成功发布。持续变更、永久撤权或资源永久不足时不适用此进展前提，但仍要求不发布过期结果。不能用永不发布满足安全后冒称全部合同成立。

`noUnrelatedDocumentWrites`限定本任务只改变指定输出文档的受管发布状态及已声明的必要恢复元数据；其它文档、原生区域和用户未保存编辑保持。没有观察到其它状态不自证frame。运行以准备候选→检查目标→提交时CAS/epoch→读回的状态机进行；旧worker可保留历史结果，但不能取得新current写权。CAS失败保留候选并按新basis重计划，不强制覆盖。

历史样例worldEffects=[]只适用于输出PublicationPlan/模拟trace。正式现实发布须另显式绑定publication Effect/Grant/readback，这属于非兼容补全，不凭旧草案自动执行。SourceStore本身若无原子提交能力，则拒绝该强发布合同或由作者采纳更弱语义。

历史Proposal名字：`noStalePublication`、`eventualCurrentPublicationUnderFairness`、`noUnrelatedDocumentWrites`。

迁移区别：纯计划和真实发布分离；补实际publication Effect，不保留无效果却写状态的矛盾。

<a id="meaning-stream-window"></a>
## 带水位及回撤的窗口聚合

正式输入补足WindowSpec、聚合Definition及去重策略，不能仅用events/watermark/late三个名字猜窗口。事件为(eid,partition,key,eventTime,value)，value为Int；最小具体画像选择同单位整数时间上的半开滑动窗口[o+k*s,o+k*s+w)，w>0、s>0，聚合为按已接受eid的Int sum。若作者选择其它聚合，则以其公开空值/结合律/顺序和错误合同替代，而非默改这个画像。

`eventTimeSemantics`规定事件时间来自所选事件字段/校准来源，处理时间只用于调度，不替代事件归窗。水位W在同epoch内单调；分区合并、idle分区及允许的迟到完整性假设由WatermarkPolicy给出。水位不证明现实绝不会出现旧事件。去重按eid及payload一致性，重复eid不同payload冲突；保留期短于可能重放范围时不声称无限去重。

`windowEmissionsRespectWatermark`：初次final标记只在所选窗口end及lateness规则已满足相应水位条件时产生，emission含windowId、聚合revision、输入cut、epoch和可撤回/最终性依据。`lateEventHandlingMatchesPolicy`要求三选一：明确丢弃并给计数/范围；side-output；或原聚合加delta、发递增revision及撤回/替代。无限迟到纠正与绝对不可变final不能同时默认成立。

checkpoint包含offset、去重集合、窗口状态、水位/epoch及已输出身份，输出真实作用按B25处理。恢复不能把旧epoch的迟到输出覆盖新结果。序列测试以同一完整输入前缀离线归窗作为纯oracle，再核每次revision/回撤；真实无界流的长期进展和供给能力仍需环境资格。

历史Proposal名字：`eventTimeSemantics`、`lateEventHandlingMatchesPolicy`、`windowEmissionsRespectWatermark`。

迁移区别：补WindowSpec、聚合与去重策略；旧三参数源需作者/锁定库提供这些绑定。

<a id="meaning-double-entry-ledger"></a>
## 按币种守恒的单账本提交

JournalEntry=(accountId,currency,amountMinor:Int)。LedgerSnapshot含LedgerId/revision、账户及币种规则、已提交journal与操作身份。`perCurrencyJournalBalanced(entries)`严格为对entries中每种currency，相关amountMinor之和为0；不同currency互不抵消。它只证明算术守恒，不证明账户有效、资金真实或交易有权。

`singleLedgerCommitOrReject`的正式观察输入需包括journalId/payloadDigest、entries、before、真实commit observation和after，而不是只有state/decision两个无来源参数。Rejected保证未提交本journal且其禁止变化的账本部分保持；Committed包含真实receipt、指定journal唯一提交和受影响余额/索引一致更新；Indeterminate保留原操作及读回坐标，不能被归为Rejected。相同journalId同payload重复返回原结算，不同payload冲突。

`noUnauthorizedJournalMutation`要求每个真实修改由当时有效issuer/Grant允许的账本/账户/动作覆盖，且frame只含所需journal与派生余额/恢复元数据。权限不能由snapshot中的任意字符串自证；撤权阻止新dispatch，旧已发生动作仍需结算。`ledgerCommit`是target-runtime Effect，不是编译过程中的函数调用；仅单个实际事务域能支持该原子性，跨银行/服务沿C07另签。

纯plan可以根据snapshot产生候选JournalDecision并标需commit；不能制造Committed receipt。所需predicate的输入投影扩展为明确before/after/observation是旧Proposal的接口修复，不能从原无参片段补出虚构世界状态。

历史Proposal名字：`perCurrencyJournalBalanced`、`singleLedgerCommitOrReject`、`noUnauthorizedJournalMutation`、`ledgerCommit`。

迁移区别：提交谓词补真实entries/操作/前后像/观察；结果采用Rejected/Committed/Indeterminate，不伪造receipt。

<a id="meaning-numerical-integration"></a>
## 数值积分的量纲与有条件误差界

本实例固定ODE初值问题 y'(t)=f(t,y), y(a)=y0, a≤t≤b；更广DAE/PDE走各自Definition。QuantityVector每分量带单位，`dimensionsConsistent`要求t/interval同时间单位，y0与输出y同状态单位，f的第i分量为y_i单位/时间单位。形状相同不能把状态量当导数量。

正式参数补范数、absTol/relTol、误差作用范围、模型假设和事件/不连续策略。`errorBoundWithinAcceptedModel`仅在被接受的模型及证据下成立：例如存在相应Lipschitz界L≥0，近似轨迹的残差界δ(s)及初值误差e0可被独立核验时，对向前时间可使用 e(t)≤exp(L(t-a))*e0+∫[a,t] exp(L(t-s))*δ(s)ds 的条件界；这要求实际残差/算术/插值证据，不是打印公式就有精度。该界与用户选择的abs/rel容差比较，接近零时相对尺度不能未定义。

返回NumericSolution区分Approximation(轨迹,误差口径,条件/证据)、UncertifiedApproximation、DomainError、NotConverged和Incomplete；声称Certified时所有要求的模型/数值界都已取得。`integrationTerminationOrFailure`针对有明确预算、有限区间和可终止基本操作的算法：完成合格轨迹或准确失败，不保证所有任意f存在解/唯一解或可在预算内达到容差。

方法可自适应步长/阶数/精度，但不能越过未处理事件或静默降低硬容差。纯f不等于Lipschitz/全域可积，必须单独给假设。无真实数值后端时这些为正式规格与数学条件，不是已对任何物理模型完成积分。

历史Proposal名字：`dimensionsConsistent`、`errorBoundWithinAcceptedModel`、`integrationTerminationOrFailure`。

迁移区别：补范数/误差域/模型假设；未认证近似与Certified分开；原容差字符串不再代签界。

<a id="meaning-custom-token-rule"></a>
## 有限旋转轨道上的陌生约束搜索

为消除原rotationAndAdjacencyConstraint名称歧义，本次选择明确可复用的规格：tokens为有限List<Token>，step为正Int，forbidden为纯且在相关Token对上终止的谓词。只搜索按step循环左旋的轨道，不搜索任意排列。若n>0，偏移依次为(k*step) mod n，k∈[0,n/gcd(n,step))；n=0单独定义唯一候选[]，不计算mod 0。

`stepPositive`为step>0。`rotationAndAdjacencyConstraint`要求输出是上述轨道成员，且对输出每个线性相邻对(i,i+1)都有not forbidden；不默认检查末项与首项的环邻接。若业务要环邻接/所有排列，必须选择新Definition/参数并重核Method。Token只需传给谓词，不要求可哈希或按名字相等。

正式返回 `SearchResult<Token> = Found(values,offset) | NoSolution(exhaustedOrbit) | Incomplete(checkedPrefix,bestKnown?)`，另按原错误机制处理非法输入/谓词Fault。按k递增选择第一个合法候选，保证重数与相对旋转次序；不把它称为所有排列中的最优。`boundedSearchTerminatesOrExplicitlyNoSolution`要求仅在整个有限轨道都检查且每个候选确不满足时NoSolution；预算先耗尽则Incomplete。若谓词不终止，调度必须能准确报告预算/隔离不足而不伪装无解。

历史List<Token>返回类型无法表达这些结果，因此采用是公开接口变更；必须迁移消费者，不能用[]同时代表空输入的合法解和无解。见证通过独立枚举全部偏移及逐对检查，并包含step与n不互素导致轨道不覆盖全部旋转的反例。

历史Proposal名字：`stepPositive`、`rotationAndAdjacencyConstraint`、`boundedSearchTerminatesOrExplicitlyNoSolution`。

迁移区别：原模糊旋转规则定为step轨道/线性邻接；结果List升级判别联合，需要明确迁移。

<a id="meaning-new-network-effect"></a>
## 命令协商与不确定现实结果

Command包含实际业务OperationId、规范payload及请求域，RemoteSession包含已核对peer、协商codec/profile、认证/授权观测与传输状态。`encodedProtocolVersionAgreed`要求双方接受同一实际wire语义及参数域，并在发送前完成受限编码检查；连上一个地址不证明对端支持该版本。

`sendRemoteCommand`为实际受权Provider动作。`onlyAuthorizedRuntimeIssuer`要求调用者、受众/资源/动作、时效、委派链与当前撤销在真实派发点有效；作者声明、session字符串和编译器生成的GrantRef都不能自签。连接重建可以换connectionId，不得自动更换原业务OperationId。

`commandResultOrUnknownEffect`正式分为NotDispatched(确定本端未派发)、Rejected(有足够证据证明远端未实施)、Committed(有可核业务receipt/readback)、Indeterminate(派发可能发生但结果未知)。传输错误只说明传输观察，不能直接映射Rejected。重试遵守Provider幂等范围/期限和原payload，同ID不同payload为冲突；超出保证范围只能读回、保留Unknown或接受新的明确风险政策。

失败/恢复包含密钥轮转、撤权、协议降级、超大消息、重复响应和迟到回执。正式意义的实现需要真实Provider/issuer/读回，并保留source capture与现实执行两个相位；本包未产生任何网络业务效果。

历史Proposal名字：`encodedProtocolVersionAgreed`、`commandResultOrUnknownEffect`、`onlyAuthorizedRuntimeIssuer`、`sendRemoteCommand`。

迁移区别：传输错误与业务拒绝分离；连接ID不代替OperationID。

<a id="meaning-generic-composition"></a>
## 真正的泛型 map/filter 合同

参数T/U为刚性类型参数，items为有限List<T>，f:T→U和predicate:U→Bool为闭包。纯画像要求f和predicate在相关输入域上纯、无未声明Fault且终止；predicatePureTotal只刻画predicate，不能由它推导f同样合格。正式前置增加f的对应合同；需要允许Effect/Fault时使用独立顺序画像并公开它们的结果/调用轨迹。

令u_i=f(items_i)。`mapFilterPreservesStableOrder`要求结果精确为按原i升序取所有满足predicate(u_i)的u_i，保持重数；T/U无相等或哈希假设。每项f及其predicate按画像所定次数和顺序调用，不能为求filter先后重复计算f。纯total画像允许保持值/硬资源合同的融合；有Effect画像若规定先完整map再filter，则逐元素交错融合不一定合法。

`completesOnFiniteInputIfFunctionsTerminate`以items有限、全部实际闭包调用能结束、必要资源可用为条件；有无限循环的f不能靠List有限就证明进展。基本构造实现可以foldLeft并维护输出builder，若代价模型把List append定义为线性，应选等价builder/逆序累积+reverse等合格方法，不能伪造线性复杂度。

旧Proposal的类型参数字符串需解析为真正的TypeParam绑定，闭包环境/效果由类型系统核验，不靠名字T/U赋予泛型能力。不同类型实例、非可比较值、稳定次序、Fault/Effect顺序和预算不足均是独立验收面。

历史Proposal名字：`predicatePureTotal`、`mapFilterPreservesStableOrder`、`completesOnFiniteInputIfFunctionsTerminate`。

迁移区别：补f的纯/终止与错误前置；effectful画像和融合合法性独立，不把predicate资格外推。

<a id="meaning-ui-accessibility"></a>
## 渲染状态、焦点与地区资源

DocumentModel携业务revision、组件/控件身份和逻辑状态；UIActionTrace含输入方式、时间/顺序、目标、焦点和被接受/拒绝结果。纯函数可返回RenderPlan/模拟InteractionTrace；真实RenderedInteractionTrace必须由实际renderer/事件/辅助技术观察供应，不把模拟事件当用户实际完成任务。

`renderedStateMatchesDocument`要求每个已发布界面在其声明渲染cut上，公开控件的值/状态/可用动作与模型投影对应，异步结果经当前revision校验，错误/加载状态可被区分。它不要求内部DOM结构相同，也不允许旧异步结果覆盖新文档。输入法组合和未提交用户输入属于交互状态，不能被后台重绘无条件覆盖。

`keyboardAccessibleFocusTraversal`要求指定任务入口下，每个当前应操作的控件可经被支持的键盘动作路径到达并激活，焦点顺序可理解且不被无退出机制困住；modal可限制背景焦点，但必须有可达的完成/取消出口。角色、名称、状态及反馈经所选辅助渠道可观察。对有限焦点图的路径检查只支持该图模型，真实设备/屏幕阅读器行为还需实测。

`localeResourceSemantics`绑定精确locale/资源版本、文本/复数/布局、时区/格式/排序的公开规则；缺翻译和不支持文字有明确fallback/Need，不自动改变业务ID或金额存储。真实翻译意义由被接受资源与作者校验承担，不能从语言标签合成其正确性。升级资源/renderer/辅助技术会重核相交资格，UI或可访问性通过不授予外部业务执行权。

历史Proposal名字：`renderedStateMatchesDocument`、`keyboardAccessibleFocusTraversal`、`localeResourceSemantics`。

迁移区别：纯UI计划与真实renderer观测分开；补焦点出口/输入法/资源版本与作用资格。

## 业务 Meaning 的供给与实现主体不互相替代

`MeaningRef` 需要确定其定义版本、参数类型/名义身份、成立时点/观察域、缺失和冲突事实政策及可用解释者；不能按 Method 函数名推出目标语义。作者的业务目标、禁令、义务与人类/组织权利不是递归函数的一种特殊返回类型。尚无可解释 Meaning 时允许保存草稿但不得生成已合格实现；有 Meaning 但缺执行能力时返回 `NeedsMethod`，不让业务作者必须手写算法。

实现者若选 `gift.semantic-body/1`、Rust/TS/SQL 等计算机制，需要另行提供准确的输入/结果/效果、前后条件、资源和目标资格；计算正确不证明其等同现实业务结果。同一产品多个公开要求需联立检查，单个 Method 的局部证明不能自动延伸为全部共享资源、安全或进展保证。

### 公开意图与实例化模式的不同身份

公共业务模式是带类型与差异槽的 Definition，作者意图是对其实际对象、范围和目标的已接受使用。二者通过原 DefinitionRef/RequirementRef 关联，不能因为引用同一个模式就自动共享实体身份或现实权限。模式实例化需保留前置/后置、错误、帧、进展、证据及相交领域差异。抽象和替代是否合法见[唯一抽象规则](../组合/抽象与开放定义.md#gift-abstraction-calculus)；具体作者输入与有限目标见[一等意图源](通用意图语言-意图源与语义组合.md#gift-intent-abstraction-application)。
