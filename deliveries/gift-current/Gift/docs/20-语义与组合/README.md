# 语义与组合

L1 拥有产品 Meaning、Requirement、作者定义、跨业务基础语义、组合与稳定工程语义。这里的“基础语义”是可独立复用的 Standard Semantic Module，不是完整应用模板。目录只表示物理主归属；ASMRVE 闭合、跨层引用和真实消费者仍由各正文承担。

## 责任入口

- [共享语义关系与能力](共同语义/README.md)：跨作者面复用的共同关系与能力边界。
- [作者语义](作者语义/README.md)：需求含义、实现精化、语言能力映射与供给责任。
- [交付语义](交付语义/README.md)：作者成果、静态/交互/服务/设备等交付边界与完整性。
- [组合](组合/README.md)：定义、模块、公开接口、扩展、结构编辑与跨软件组合。
- [基础语义](基础语义/README.md)：计算、对象/控制、状态/关系/流与数值等可组合语义。

本 README 只维护责任边界与精选入口；完整文件树由真实作者源直接构成，机器导航和 Contract Unit locator 需要时在包外按需生成。

## 行业业务不属于本层 authority

本目录拥有跨业务复用的计算、对象/控制、状态/关系/流、数值及[按需可选的交互、学习、因果和安全语义合同](可选语义/README.md)；作者投影与机制配方只展开普通定义/要求，不建立行业产品。它们是按需组合的 Standard Semantic Modules；把这些模块预组合成事务型应用、游戏循环、仿真栈或其他 turnkey 产品形态不属于本层 authority。游戏、仿真、金融、医疗、制造等具体业务不在 `docs/20` 建立内置领域子系统；相应完整研究在同包[依据区](../../research/README.md)作为研究输入提供；已被采用的结论由实际规范拥有，未采用不意味着失去参考价值。领域新需求首先由作者定义、模块/库、Provider 与现有通用语义组合，Core 扩展按[作者定义组合与核心扩展边界](../70-工程系统与演进/演进与实施/作者定义组合与核心扩展.md#core-promotion-rule)裁决。

## 按需产品语义入口

[可选语义](可选语义/README.md)按实际消费者使用，不把规范设计当已安装支持；[意图描述](作者语义/意图描述与作者投影.md)负责发现/展开/追踪，[机制配方](组合/机制组合与作者配方.md)负责通用组合而非行业成品。

## 跨家族共同接合

[工程通用语义全域与闭合合同](共同语义/工程通用语义全域与闭合合同.md)明确计算只是一个语义家族，并将时间、外部效果、义务、权限、物理、证据等不同 owner 接到一条解释与实现资格链；它不是封闭语义 `kind` 清单。
