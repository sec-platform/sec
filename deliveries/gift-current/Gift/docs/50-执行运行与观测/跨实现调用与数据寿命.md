# 跨实现调用、数据访问与资源结算

本篇负责原生、二进制、Wasm、Worker 与设备之间的**调用协议、数据可达性、寿命、取消和结果移交**。[实现供给与替换](../30-实现解析/供给与替换.md)负责选用版本；原 Method/UseBinding 固定调用资格；外部 Operation、结算和持久恢复归[持久化提交与恢复](持久化与恢复/README.md)，语言内部 Own/Borrow 归[存储寿命](../20-语义与组合/基础语义/对象与控制/控制流与存储寿命.md)。本页只处理跨边界适配，不建立第二套 ABI、作者项目或后台缓冲平台。

## 已选实现仍须具备一份准确的调用解释

类型相容、模块已装载和输入字节仍存在，不独自取得调用资格。UseBinding按实际消费点保存或引用下表信息；可从真实公开合同、构建工具和宿主能力取得的由系统取得，普通作者不重复填写。

| 维度 | 必须固定的含义 | 不应推断的保证 |
|---|---|---|
| 调用与返回 | 同步/异步/流、正常值、业务错误、缺陷、取消与未知 | 有Promise就已经取消；同步函数可偷换成异步 |
| 数据与表示 | 数值域、字符坐标、编码、布局、长度、跨度、空值及非法表示 | 同字段名就同单位；bigint可截成i64 |
| 访问与别名 | 值快照、借用、独占访问、所有权转移或显式共享；允许哪些重叠 | pin等于只读；只有一个JS对象就没有其他视图 |
| 活动与调度 | 可重入位置、线程/事件循环亲和、回调顺序与排队上界 | 任何线程都可触碰JS状态；一个串行队列天然无死锁 |
| 分配与释放 | 哪一实现分配、谁以何种方法释放、结果是否携带原生拥有权 | 任意free可释放任意内存；调用完成就能卸载析构代码 |
| 能力与成本 | 实际作用、所需许可、资源配额、传输和最坏必要工作 | 本地函数无外部效果；零拷贝无同步成本 |
| 版本与加载 | 具体模块及依赖、ABI、CPU能力、初始化与退出合同 | 签名可信就行为正确；主DLL完整路径固定所有依赖 |

这里只形成原调用/运行计划的内部投影，不另存一份竞争版本选择。直接同语言、同内存模型且完全相容的同步调用可以只保留静态检查和普通调用；确有差额才生成适配。缺目标实现时仍可保留规格；生成可隔离检查的候选也不等于已批准生产调用。

**能力缺项显式失败。（消费条件）：** wire字段与ABI兼容仅覆盖编码/调用；运行协议必需的围栏、可取消性和消息语义不能在转接时删除。 合同归属：[协议协商中的降级、未知字段与旧客户端保护](../70-工程系统与演进/演进与实施/兼容迁移/生态协议与版本演进.md#gift-capability-downgrade)。

**动态库迁移。（消费条件）：** 改动布局或ABI时，旧回调和旧分配器的消失应作为退役前提，不能只查看新进程健康。 合同归属：[灰度发布中的读写兼容矩阵与不可逆分界](../70-工程系统与演进/演进与实施/兼容迁移/迁移切换与退役.md#gift-mixed-release-compatibility)。

### 跨ABI、异步调用与资源释放的共同协议

FFI或语言桥接至少固定 `(producer/consumer binary identity, target triple, data layout, calling convention, ownership, aliasing, lifetime, error semantics, thread affinity, cancellation, release function)`。函数名一致、C头文件能编译或JSON可序列化都不能证明全部约定一致；在Rust/C++互调时尤其不得把借用指针延长到调用返回后的异步任务、GC搬迁或设备DMA结束之后。跨进程传值要另外固定wire版本、字节序与身份归属，不使用进程内地址充当持久身份。

跨边界异常或崩溃由双方的错误与寿命合同解释：本侧须保持资源释放/隔离与准确诊断；仅有 `catch` 不能修复已损坏内存。热替换前停止新绑定，等待或安全隔离旧函数对象、句柄、回调及分配器，满足各自持有与退役条件后才卸载。验证覆盖反向回调、取消-释放竞态、线程切换、布局/对齐变化以及新旧库并存。

## 选择访问方式，而不是一律零拷贝

| 方式 | 准入和正常路径 | 退出与不能保持的情况 |
|---|---|---|
| 独立值快照 | 捕获本次被授权的准确切片或序列化值，复制后不再随外部修改 | 原输入不能被重读或有作用getter时，先按原求值合同取得；复制不保留公开的可变别名 |
| 同步只读借用 | 提供者保证不保留指针、不回调出借期间可能修改/扩容的代码；阻止相交写入和搬移 | 返回并完成全部嵌套访问后解除；同进程的恶意库不能仅靠文档约束 |
| 有界独占访问 | 原拥有者停止相交读写，将实际区域的访问权交给调用；在成功和失败路径都结算 | `inout`修改及部分失败依原合同报告；不能用普通重试抹掉已修改输入 |
| 所有权转移 | 实际分配及其全部别名失去发送方可用资格，接收方承担资源寿命 | 失败若已接收未知，不同时把所有权退给双方；一个视图移动不证明整个分配可移动 |
| 显式同步共享 | 两端使用同一被支持的内存和同步协议，保证发布/获取次序及数据竞争规则 | TS readonly、冻结外壳和引用计数均不构成内存屏障；无合格同步则复制或拒绝该强要求 |

**默认跨不可信边界使用可验证的独立值；同进程可信窄核可在证明条件成立时借用。** 这不是全部实现必须复制的硬规则。零拷贝只有在布局、生命周期、权限、别名与同步都相容时才可选；成本比较包含取得独占访问、固定页、缓存同步和最后结算。

多个视图可能指向同一底层分配。检查的是分配身份、准确字节范围和访问角色，不是包装对象数量。转移一个ArrayBuffer可能使其他视图一起失效；池化Buffer还可能关联远大于可见切片的空间。因此不得为了传递一个合法小切片，把整个池中不相关字节发送给工作器。不能合法转移时仅复制所需范围。依据见[原始材料](../../research/sources/表示编辑与协议.md#native-lifetime-sources)。

若调用方能观察两个参数是同一可变区域，分别复制它们可能改变行为。适配必须保留原别名关系或取得允许值快照的合同，不能以“拷贝更安全”为由悄悄改义。写回式副本也需要原版本/独占关系，且不能掩盖回调期间应观察到的修改。

pin或强引用只解决相应对象不被回收；它不阻止别人写入、不保证底层地址不变，也不证明对象仍有当前访问资格。结构不可变、内存不移动、内容不被并发修改是三个分别取得的条件。

## 缓冲、步长与标量必须在窄化前验证

设实际分配有N字节，元素宽度为w>0，首逻辑元素的字节偏移为o，第i维大小为n_i≥0，字节步长为s_i。N、o、w、n_i、s_i均来自已验证描述；维数与元数据数量也先受预算约束。

任一n_i为0时，逻辑视图为空，不访问元素；仍检查类型、维数、分配来源、元数据预算及表示合同。零维视图是一个标量，不误判为空。非空视图的全部访问字节必须满足：

```text
lo = o + Σ_i min(0, (n_i - 1) * s_i)
hi = o + Σ_i max(0, (n_i - 1) * s_i) + w
0 ≤ lo ≤ hi ≤ N
```

在精确或检查溢出的整数域计算这些式子，然后才转换为目标`size_t`、指针偏移或设备索引。不能先做目标整数乘法溢出，再用较小结果通过范围检查。元素数乘积、输出容量、暂存和字节数分别检查；宽度可变的编码使用实际长度表或已知上界，不套定宽公式。

各维索引独立取值，步长为正时最小偏移取0、最大取n_i−1；步长为负时反过来，所以这些端点能够同时取得，得到上述精确包围区间。公式支持负步长和只读广播的零步长，但**只证明字节包围范围**。它不证明对齐、元素已初始化、指针来源有效、可写、没有自身重叠或没有别的并发访问。可写视图若多个逻辑元素别名同一位置，需明确聚合/重复写语义，否则拒绝或在允许的值语义下正规化。两个包围区间相交也不证明两个稀疏视图一定实际重叠；可用更精确分析，无法证明所需不重叠时采取安全的保守路线。

空缓冲适配使用目标ABI允许的合法表示。某语言构造零长切片仍要求非空且对齐的指针，适配器不能因长度为0就调用其不满足前提的构造器。禁止以指针加法本身先产生未定义行为，再依赖之后的不解引用免责。

| 输入/输出 | 默认检查与转换 | 失败含义 |
|---|---|---|
| 中立精确Int ↔ 有界整数 | 比较真实上下界；内部优化域不足时走已绑定的通用分支 | 不能把合法的大整数改成业务输入错误或截断 |
| Bool、和类型与枚举 | 只接纳所用版本的合法标签、有效载荷组合和已初始化字段 | 非0/1的bool字节、未知标签及成功前读取未初始化out值均不合法 |
| Text与位置 | 标量/UTF-16/UTF-8坐标显式转换；保持原字符、不隐式NFC或大小写转换 | 非法编码、非标量代理项或半个字符位置准确拒绝；NUL不自动表示字符串结束 |
| 记录/数组 | 字段顺序、对齐、端序、步长、长度和嵌套预算固定 | 只比较字段名称不证明ABI相容 |
| 原生返回数据 | 在暴露前验证标签、长度、分配来源、拥有权和实际存活；失败也清理已取得资源 | 提供者自报合法不能跳过受信边界；不读未初始化区域 |

外部数据先变成有界普通数据，不在只读解析中任意执行原生getter、代理或用户转换函数。读取这些对象本身有作用时，必须按对应原生调用合同准入，不能用再次“验证”重复执行。

Wasm调用必须绑定具体内存种类。可能增长的固定缓冲在growth后可被替换并使旧视图失效；其他共享或可伸缩种类遵循自己的规则，不能一概假设行为相同。在可能扩容的调用/回调之后，重新取得实际内存视图、核范围并建立访问；或在该借用期间真实禁止增长。只保存线性内存偏移而不绑定内存实例和代际，不能用于跨实例重取。

<a id="call-lifetime"></a>
## 结果完成和物理可回收是不同事实

一次调用沿既有操作身份与运行实例记录相交事实。下面是内部分析维度，不是每个简单调用的持久表，也不是新公共状态枚举。

| 事实 | 意义 |
|---|---|
| 提交资格与接受情况 | 尚未提交、确定未接受、已接受、接受未知；决定是否还可认为未执行 |
| 语义结果 | 未完成、值/业务错误、缺陷、取消或未知；只结算对外结果 |
| 提供者未来访问 | 能否再调用回调、使用输入或产生输出；关闭请求与关闭事实分开 |
| 进入中的执行 | 原生栈帧、回调、已认领通知与设备工作；各有真实占用 |
| 数据访问与输出拥有权 | 输入借用、共享访问、已传出结果及待清理资源 |
| 代码和环境占用 | 初始化、线程、回调函数、释放函数及导出对象仍需哪个模块 |

一个Promise已完成，可以同时存在仍在回调栈上的代码和刚转出的原生结果。一个取消请求已接收，可以同时存在不可抢占设备工作。单个`done=true`不能据此释放输入、回调上下文或动态库。

### CALL0—CALL8：登记、调用、结果和最终释放

**CALL0 固定调用。** 取得准确UseBinding、运行实例、输入/输出合同和当前作用资格；从活动路由取得实例时复用[C1的原子接纳保护](运行生命周期/运行实例-控制调试与Provider.md#runtime-generation-cutover)，不能只捕获裸指针。调用期间固定所用实现，不通过全局“当前模块”查回调和释放函数。缺实现仍是缺项，不临时搜索联网方法。

**CALL1 准备访问与预算。** 按上节取得快照、借用、独占或转移，计入输入、输出上界、暂存、排队、回调和旧新模块同时存活的预算。没有输出上界时采用真实分块/流控合同。不能让调用耗尽全部信用，再等一个必须取得额外信用才能完成的回调，同时持有对方必需的锁；准入时留出结算资源或采用不会形成该等待环的方法。

**CALL2 先登记，后调用。** 建立完成槽、回调上下文、释放责任和代码引用；在短协调段与停止新准入互斥。随后锁外调用提供者。必须允许提供者在`start`返回前同步回调甚至完成；不能等`start`返回才把调用加入表。

**CALL3 处理提交结果。** 确定未接受才退回仍属于调用方的资源。已接受或接受未知时，保留提供者可能访问的内容及代码；不得由超时把同一拥有权同时退给另一使用者。启动栈帧未退出时，即使结果已回调，仍持有该帧需要的环境。

**CALL4 回调进入与线程交接。** 受信桥在同一协调点验证实例、句柄代、操作和当前回调入口，并取得一次活动占用，再锁外运行解码/用户处理。非JS线程只能通过合格的线程安全通道进入JS环境；环境已关闭时仍结算原生载荷而不调用失效JS。重入的取消和关闭进入同一串行协调，不能在持锁调用外部回调时死锁。已认领通知可能晚到，只撤销发布资格，不提前释放它的载荷。

**CALL5 接纳结果。** 对应完成槽仅接受符合其语义的第一次结果；标签、范围和身份失败返回准确缺陷。结果若含独占资源，先建立接收方真实拥有者及其释放方法，再向使用者暴露。重复同结果通知不再析构同一对象；确实额外产生的迟到对象仍有独立清理责任。只在失败时有效的错误字段、只在成功时初始化的out参数分别读取。

CALL5的“验证后暴露”不允许“验证成功前无人负责”。CALL2已准备的受信传输/提供者拥有者先接住实际载荷；解码、表示转换或接收位置构造失败时，它按[取得交接](../20-语义与组合/基础语义/对象与控制/控制流与存储寿命.md#acquisition-custody)清理自己确实拥有的部分。无效元数据中声称的指针、分配器或释放函数不能据此执行free；无法确认来源的部分留在原受信提供者/隔离域核对，不把任意输入当析构指令。进入临时语义结果后，取消或交付失败按[未交付值](../20-语义与组合/基础语义/对象与控制/控制流与存储寿命.md#provisional-result-ownership)继续处理；实际异常与载荷按[边界失败合同](../60-保证与证据/保证/系统不变量与组合.md#failure-boundary-contract)分开。

**CALL6 停止与取消。** 撤销相交安装资格或未来准入，按真实驱动请求停止。取消API返回、JS等待者离开、线程通知已入队均不等于原生任务停止。对不能取消的工作，继续等待安全完成、保留隔离进程及资源，或按已有协议移交；没有有界策略时拒绝原本承诺的有界关闭，而不是释放仍被访问的数据。 驱动若明确保证停止后不会再给正常完成通知，且已取得对应终态事实，由原结果协议结算取消/未开始，不再等待不可能到来的回调；像Node-API这样仍承诺完成回调的接口则继续等待并清理。不得把一个宿主的回调约定套到其他驱动。

**CALL7 确认可回收。** 必须取得未来不会再访问的真实依据，并确认相交的原生帧、活动回调、待交付拥有载荷、借用及设备访问已清零。结果资源要么已清理，要么已转交其独立拥有者；后者不妨碍释放不再使用的调用上下文，但继续保护其自身分配及释放代码。最后在短协调段撤销入口、退休代际并认领释放，锁外调用准确释放函数。释放失败或效果未知沿原恢复原则处理，不再随意调用一次free来“确认”。

**CALL8 收尾与保留范围。** 仅保留仍有恢复、去重或真实外部引用用途的记录；纯同步调用可随着合法栈退出直接结算。高层结果无需等待无关后台责任，但所承诺的close必须覆盖它声明的资源和全部已接受工作。读取最终状态不重新执行目标程序。

Node-API在相应接口中明确：只能取消尚未开始的异步工作，取消后的完成回调仍有清理责任；线程安全函数的队列、引用和最终清理也有独立寿命。这是选定适配的依据，不将Node所有行为推给Bun或其他宿主。[来源](../../research/sources/表示编辑与协议.md#native-lifetime-sources)。

### 句柄验证和释放必须共同原子化

跨不可信边界使用的句柄由签发实例、类型、槽位和代际共同解释，具体编码仍由实际适配拥有。句柄不是权限；每次使用仍核当前调用能力。验证后取得占用必须与退休处于同一互斥或等价原子协议中，不能先检查代际、解锁、再对可能已释放的地址增加引用。

槽位重用分配新代际。代际空间耗尽时退休该命名域或实例，不允许环回使旧句柄复活。排队任务持有真正占用，不仅保存一个裸整数。文本中的`instanceId`或客户端给出的指针值不能自行成为受信引用。

## 加载、初始化与卸载也属于作用边界

解析库文件的被动元数据与实际加载不同。加载原生库可能执行构造/初始化代码，检查ABI不能在纯编译阶段暗中`dlopen`或`LoadLibrary`。需要探测时进入隔离或明确受信执行，并绑定所得记录的真实环境。

所验证范围包含主模块和实际依赖、搜索规则、可执行内存/CPU能力、分配器与运行库。Windows的主DLL完整路径并不自动固定依赖DLL的查找；当前工作目录、环境变量、预加载和全局符号也可能影响其他平台。签名能提供特定来源依据，不能证明满足业务合同或取得运行许可。

取得字节摘要后到真正装载之间仍可能有替换窗口。可以使用真实受保护的不可变安装区域、所选加载器的固定对象能力和必要隔离；没有这种能力时不宣布消除了竞争。装载前检查合法，不能代替实际装载到的对象与依赖记录。

初始化先接住每项取得/启动的责任，再将成功部分登记为真实资源、线程、句柄与回调；B初始化失败不能释放从未取得的B资源，仍在进行的B取得也不能从排空集合消失，A的在途责任不因此变化。加载器限制的初始化入口只做允许的最小工作，复杂启动在正常运行边界进行，避免等待加载锁下无法推进的工作。出处见[供给装载依据](../../research/sources/表示编辑与协议.md#native-lifetime-sources)。

**模块卸载的条件比调用结束更强。** 除活动调用和回调外，还要排空执行该模块代码的线程、TLS清理、设备回调、导出对象及日后需要其析构/释放函数的结果。结果已交给调用者但仍由模块A分配时，不能因为当前绑定切到B就卸载A。可以在合格条件下复制到调用者拥有的表示，从而提前释放A；但必须计入复制成本并保持身份和别名合同。

Rust的普通C ABI、允许展开的ABI和`panic=abort`是不同条件；`catch_unwind`不捕获abort，也不能把任意外来异常转成普通Result。按实际ABI在边界转换可转换的错误；不可信或可能进程级失败的组件按隔离与故障范围处理，不能以try/catch假装进程内完全安全。

## 可信结构与对抗边界各负责什么

私有构造器、句柄代、只读类型和模块依赖检查用于受信实现防误用。恶意同进程原生代码可以任意读写和绕过这些结构，必须在其确属可信计算基的范围内才能加载；否则选择合格隔离及实际权限限制。

隔离后的返回仍校验数据大小、标签、引用和资源预算；进程退出提供了某些本地访问终结事实，不自动关闭已转交远端的操作或独立设备工作。超时不能代替以上任何一个终结条件。

## 具体接回原模块的实现责任

| 原职责中的拟定位置 | 输入与工作 | 结果、写权和失败归属 |
|---|---|---|
| `semantics/native-contract.ts` | 真实接口、数据/效果和来源观察 | 可比较调用合同；不在解析时加载原生库 |
| `compiler/resolve-use.ts` | 要求、目标及方法；判断适配与守卫 | 消费有权选定`RealizationBinding`派生的`UseBinding`，形成只读准确调用计划；缺能力不伪装已支持 |
| `compiler/lower-bound-use.ts` | 固定计划及被求值一次的实参 | 原LoweringResult，生成必要范围检查和真实调用，不自行联网或探测 |
| `execution/prepare-operation.ts` | 当前许可、实例和预算、实际提供者能力 | 准入并取得相交访问；纯任务可不建立持久日志 |
| `execution/native-call.ts` | 既有操作身份、访问租约、提交/回调/停止事实 | `prepareCall / acceptCallback / settleCall / retireCall`承担CALL0—CALL8；外部调用在锁外 |
| `adapters/native/`及实际目标适配 | 固定模块、真实数据和驱动调用 | `openBoundModule / invoke / closeAdmission / confirmQuiescence / release`按所用宿主解释；缺终结能力明确返回 |
| `application`与`entry` | 原结果及当前用途 | 决定显示或待决，不从页面关闭直接释放底层内存 |

以上是文件/函数级实现设计，不是声称这些文件已存在于产品仓库。同步可信小核可以内联责任、复用原资源帮助函数；无需先实现全套异步注册表才能调用一个纯函数。

## 验证及较小合格实现

需要验证：start内立即完成、完成后继续回调、取消时队列已认领、环境关闭而载荷尚在、代际验证与释放竞争、共享视图转移、负步长与整数溢出、Wasm扩容、依赖替换、返回对象比模块活得久、初始化部分失败及释放未知。具体书面输入与结果见[跨实现验收](../60-保证与证据/验收/接缝符合性.md#native-boundary-cases)。

可先采用复制值＋同步可信核，或复制值＋隔离工作器；它们只要符合公开合同就是正常实现，不因没做零拷贝、热卸载或任意回调而被视为不完整。更强能力需要本篇全部相交条件。边界公式和有限调度模型的复算不等于真实C/Rust/Wasm/GPU运行已无数据竞争；实际适配、故障注入、平台工具和成本实测仍需执行。

<a id="logical-view-coordinates-and-storage"></a>
## 逻辑视图坐标、真实占用与移动后释放

零拷贝交换的有效值不只是data指针。offset、length、selection、validity、dictionary、元素布局与原分配共同决定消费含义。若逻辑位置i映射物理位置j=selection[i]，数据与有效性须在相同坐标上读取；值用j而掩码用i会在重排或重复引用时静默错配。独立只读元数据可以复用，但参与解释的元数据必须与数据和输入代一并固定。

小视图可能保留大分配：32字节slice仍借用8MiB父缓冲时，预算不能只计32字节。复制为独立值可能减少长期保留，却改变共享别名、更新可见性与成本；只有原合同允许才复制。峰值计入复制期间新旧同时存活的分配，而非只比较最终大小。池化、共享内存、GPU缓冲和返回结果继续保留各自真实占用及最后使用责任。

采用成熟C数据接口时，base、children、dictionary和释放回调按该接口精确分责；结构移动是责任转移并使旧持有者失活，不是立即释放。回调不得错误依赖已搬移的结构地址。合法后继、元数据与分配责任交接完成之前旧拥有者不能释放；释放代码、延迟回调和模块驻留继续按CALL6—CALL8结算。同进程裸指针和回调接口不是跨信任域验证器，也不自动成为持久格式或进程间协议。

<a id="prebootstrap-ffi-host-failure"></a>
## 自举及一般程序的 ABI 故障、回调与持有关系

跨 Rust/TS/原生库的每次边界调用先绑定准确数据布局、大小/对齐、调用约定、值域、线程亲和、可重入性和错误/取消。内部 Rust enum 的布局、JS 对象地址、某个 arena index 均不能充当稳定 ABI。简单同步可信调用允许直接借用；不可信/跨进程边界使用最小准确切片的已验证值传输，必要零拷贝另证明所有权与最后访问。

回调的代码版本、捕获数据和释放函数在最后可能回调之前都必须存活。调用方超时或 UI 取消只取消等待，不允许提前释放被提供者继续使用的缓冲。先取得接收责任再派发可以产生异步结果的操作；取消和晚到成功竞争时，由唯一接收 owner 清理/移交，不让两个消费者都以为自己不再负责。

反向回调不在持有会阻塞同一调用链的内部锁时触发。线程切换需真实执行器或宿主队列，不能从 Rust 工作线程直接调用仅允许主线程使用的 UI/JS 对象。回调抛错、目标进程退出和远端已接受但未确认分别保留，不以 catch 所有异常宣称内存或世界状态恢复。

ABI 更新时先停止新绑定，保留旧活动调用与旧释放代码，逐步排空或安全隔离。仅看到新进程健康不证明旧引用已清零；旧库文件可以留作读取/恢复供给，但已撤销执行许可的代码不能继续被新请求调用。跨语言共享内存的原子/栅栏必须由同一内存模型合同解释，没有该合同就复制或拒绝并发共享。

<a id="design-b23"></a>
## FFI 的持有、异常和重入边界

ABI合同必须包含实际语言/工具链/平台、布局与对齐、调用约定、参数值域、拥有/借用、异常方式、线程及同步、回调和卸载条件。参数同名同尺寸不证明ABI相同；本地指针不作为持久对象ID或跨进程值。空slice也必须符合被调用ABI对非空指针、对齐及零长度的约定，不能任意用null。

借用view记录底层allocation与偏移长度、别名和可变性；共享只读与排他写不可混同。异步native操作完成前，取消上层等待不允许释放buffer；回调入口持有旧模块映像直到最后可能回调和析构结束。卸载需quiescence及真实release确认，超时进入quarantine，不立刻复用地址/handle。

异常/panic/longjmp不能任意跨未声明的ABI；桥将受支持错误映射到目标Result/Fault，无法安全捕获的失败交给隔离宿主退出及恢复。调用外部代码前释放会被其回调重新取得的内部锁，或明确禁止重入并在入口拒绝；不能靠文档上称“同步调用”忽略真实回调。

重启后持久记录只保存可恢复资源身份、供应版本及reconcile坐标，不复用旧地址。桥版本变化即使功能名不变也重核布局/生命周期和现存任务兼容。代码签名和FfiSafety声明不代替这些具体合同与证据。

**验证与反例**：空slice、不对齐view、同buffer别名写、取消后迟到回调、异常跨ABI、持锁重入、两进程旧handle恢复逐项验收。

**实际能力边界**：真实FFI/native库故障注入和目标ABI核验未执行。
