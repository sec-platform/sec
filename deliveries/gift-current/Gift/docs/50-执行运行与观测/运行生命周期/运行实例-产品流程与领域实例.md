# 产品流程与可选领域实例

## 产品流程与可选领域实例

[Workflow、Scheduling、Telemetry等配方](../../20-语义与组合/组合/机制组合与作者配方.md)的运行对象属于真实产品/Provider，不与Gift任务队列、编译日志或运行代合并。可选交互/ML/因果/安全方法只通过准确Binding及本章准入/切换/寿命接口接入；联合控制、模型回滚、在途命令与安全转换仍消费原实际状态，不以模型预测/目录标签代替readback。

## 工作流控制结果与现实责任的接合

[工作流执行关系与激活](../../20-语义与组合/交付语义/工作流执行关系与激活.md)拥有令牌、循环、子流程、parallel与结果类型；这里拥有它们与实际宿主和恢复Owner的交接。普通有限内存流程可使用本地调用帧，不因用了workflow就强制部署数据库或耐久引擎。请求跨重启续行、或已发效果需要恢复时，所选宿主才必须提供相应持久能力。

运行器在进入时固定Workflow定义revision、ComponentInstance/WorkflowUse发生点、实际输入、角色绑定和目标实现。它按语义Owner的激活规则为本次Execution及每个StepActivation分配身份；仅源stepId、图节点或业务名字都不足以识别一项运行。`needs`是当前因果环境的准入条件，不能被宿主依赖队列解释成自动fork；parallel才在其明确分支范围建立独立子Execution。

对一个调用Effect Port的StepActivation，运行Owner必须在首次派发前把它关联到原[DurableOperationRef与Attempt](../持久化与恢复/事务提交-外部效果与幂等交付.md#unified-operation-unknown-recovery)。因该激活恢复而重新进入适配器时先解析既有Operation及RetryBasis，不能只因调用帧重建就产生新业务操作；源码重新运行产生的新激活也不自动获得重复未知作用的权限。业务流程请求的独立下一次操作，与原操作恢复，必须由真实意图和已接受恢复合同区分。

需要耐久续行时，Execution的持久Owner同时保存准确因果环境、已发布Step结果/控制结果、子Execution关系，以及通往Operation/Attempt/Settlement/Readback和恢复continuation的引用；这些记录保存引用和控制事实，不复制外部效果账本。当控制状态和效果账本不在同一事务域时，先持久关联与操作准备，再按原派发协议作用；崩溃恢复按同一身份重读两侧，不从缺少本地结果槽推断没有效果。若不能可靠恢复该关联，报告恢复能力缺项，不能宣传跨重启恰好一次。

工作流terminal或parallel非成功结果只结束对应控制请求。效果未知、已知业务失败、取消、超时和宿主已停止分别保留；已移交恢复责任的子Execution仍可有逻辑unresolved结果，交接成功不会把它改成cancelled或failed。调用方接收控制结果时也取得可解析的剩余责任引用；不要求它持有已转交的线程或句柄，但不能据此清除原账本。

结果一旦按该激活发布，不因迟到读回而原地改写并再次驱动旧后继。后续证据更新原Operation的当前结算视图；若业务确需继续流程，由所选恢复合同在原有权身份/代际下恢复准确continuation，或发起明确的新流程，并核已完成步骤与禁止重复作用边界。没有合法continuation时只更新观察和待协调状态。更新定义或重新部署也不把在途帧自动解释成新版本。

**区别见证：** 保存已在远端完成但回执丢失，父流程超时并把对账交给恢复者。本地句柄可以在没有使用者后释放；父控制结果仍为准确timed-out或unresolved，原Operation仍需对账。晚到成功只补足原保存事实，不再触发一次保存，不自动重新执行已走过的通知或后继。
