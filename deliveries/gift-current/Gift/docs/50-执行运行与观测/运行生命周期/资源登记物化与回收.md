# 资源登记物化与回收

## 缓存、物化、隔离、回收与资源出生登记

### 目录名不决定生命周期

`.tmp`、cache、ignored、stopped、old 都不能自动授权删除。跨操作、跨崩溃或外部可见且具有清理义务的资源，需要足够定位拥有者、物理身份、用途、保留和恢复责任；短生命局部对象由词法所有权、区域或会话管理，不为每次内存分配创建持久记录。

### BirthRegistration

```text
ResourceBirthRecord = exact {
  resourceRef,
  producerAndOperationRef,
  physicalIdentity,
  resourceClass,
  contentOrGenerationRef,
  ownerAndLease,
  retentionAndRecoveryRole,
  terminalAndRetirementObligations,
  createdByAdmissionRef
}
```

只有实际绑定已创建资源、提交点与恢复根的记录才能用于创建崩溃恢复；先有一行计划但尚不知道资源物理身份时，不能据此认领任意同名对象。可采用受限的操作命名空间、目标幂等创建或目标可查询身份；不具这些能力时保留无法结算的分支，不靠名字和mtime猜拥有者。

### Eligibility 与 Priority 分离

owner 先给出 `eligible | blocked | unknown`；容量/性能策略只在 eligible 集合中按 bytes、last-use、rebuild cost、sharing、reserved space 和 pressure 排序。

### Materialization

依赖、工具链、浏览器和镜像按精确内容代际物化；活动绑定的切换原子性由适配器说明。已有完整合法内容无需重复下载或构建；是否还需取得撤销/信任元数据由[离线与新鲜度准入](#offline-materialization-freshness)按本次用途裁决，内容存在不自动产生当前执行资格。

### 缓存隔离

共享缓存限于可按实际输入重建的结果，不保存活跃授权、凭证或会话控制状态。可重建内容仍可能敏感，按[共享计算和派生数据隔离](../../30-实现解析/增量与性能/依赖与失效模型.md#共享计算的隔离与派生数据)处理。坏缓存只有在固定权威输入合法可得、求值纯且原预算允许时，才按[QueryCache故障合同](../../30-实现解析/增量与性能/查询固定点与缓存.md#query-cache-port-results)隔离并重算，不借fallback重发作用或换身份绕过拒绝；若条目也是唯一恢复资产或必要事件证据，就不是可任意丢弃的缓存。回收沿[垃圾回收协议](../持久化与恢复/持久状态与存储协议.md#垃圾回收)，不能仅凭名字删除。

### 验证：缓存、物化、隔离、回收与资源出生登记

资源创建窗口崩溃、活动 owner、外来同级对象、缓存投毒、跨会话污染、磁盘压力、隔离区恢复、垃圾回收与读取者竞态、离线复用，及禁用缓存、冷缓存和热缓存的等价性。

## 进程树、端口、浏览器、容器与数据库资源

### 物理测试和执行环境由资源组成

单个 PID 或临时目录不能代表完整执行环境。子进程、端口、浏览器上下文、数据库、容器、网络和缓存都有独立生命周期。

### ExecutionEnvironment

```text
ExecutionEnvironment = exact {
  workspaceAndStagingRefs,
  processGroupOrJobRef,
  portAndSocketLeaseRefs,
  browserExecutableAndContextRefs,
  databaseSchemaTenantAndTransactionRefs,
  containerImageInstanceAndVolumeRefs,
  environmentAndSecretRefs,
  networkCapabilityRefs,
  immutableSharedResourceRefs,
  cleanupAndReadbackPlan
}
```

### 端口

禁止“探测空闲端口→释放→稍后 bind”。端口 owner 持有 socket/lease，直到安全交接或直接监听。

### 进程树

direct child退出不代表grandchildren、外部启动器或远端工作已结束。执行画像要声明实际进程成员边界、加入/派生/逃逸规则、终止与查询权限、等待/回收能力和启动崩溃后的原身份恢复。需要完整受控树时，在运行不受信代码之前建立有效归组及子进程继承约束；不能先启动任意代码再把父PID加入一个组，就证明此前派生的进程已受控。加入失败须保持未运行或按原已发生事实结算，不静默降级强隔离。

Windows可采用Job Object或等价原语，但实际保证限定于真实成员、breakaway及句柄策略；POSIX进程组、signal与wait/reaping也只覆盖其实际成员和可等待子进程，不单凭组名认定无法脱组或远端后代已停止。强场景可选择宿主已提供的更强成员约束/隔离边界，不强制容器或Docker。只给合作式停止时准确标明，不能作为敌对代码沙箱。

取消请求、信号发送成功、父退出、成员停止、可等待资源回收和外部责任结算分别观察；异步通知可以唤醒查询，不由“没收到通知”推未退出。超时仍有未知成员时保留原资源/恢复责任并限制新准入，不kill按名字或复用PID找到的无关进程。归组不自动限制文件、网络或凭证权限；实际借用内存的释放继续遵守[读者边界](../持久化与恢复/持久状态与存储协议.md#lease-retention-and-borrow-boundary)。具体宿主事实见[进程边界来源](../../../research/sources/构建分发与迁移.md#process-membership-source-details)。

### 浏览器

可选 browser capability 只有在 applicable Claim 需要 DOM/CSS/layout/interaction 时准备。not-applicable 路径必须零下载、零探测、零启动。

### 容器

image、container、runner registration、credential、cache、volume、logs 和 Evidence 分离生命周期。删除 container 不等于删除 cache；stopped 不等于 reclaimable。

### 数据库

数据库的**可见性隔离、写入隔离、凭证隔离和资源生命周期分别选择**，不要求每个普通业务Action创建新数据库。固定只读分析可以使用具有真实一致性保证的只读事务/快照；共享业务写入按原事务、授权及幂等合同处理，不能在任务结束时把已接受业务数据当残留删除。

测试、预演或临时执行要求互不污染时，选择实际可约束写入范围的专用schema/database/tenant、隔离副本或合格事务回滚画像。名称不同本身不是隔离；共享角色、默认schema/search path、全局对象、DDL、序列、触发器或网络/文件扩展可能越过预期边界，须按实际Provider核对。snapshot isolation主要约束读视图/并发可见性，不自动提供独立命名空间、阻止合格提交修改共享数据或回滚外部作用；串行化也不替代读写授权。回滚画像只有在全部相交写入可回滚、无逃逸提交/外部效果且连接独占规则成立时才足够。

租借连接前核真实数据库/租户、事务与会话状态；归还前结束本次事务并确认所需会话重置，不能把未知事务状态送回共享池。临时schema/drop按原创建身份、准确作用域和当前清理权执行，先关闭仍在使用它的本次会话或移交，再读回连接、事务、临时数据及未结算外部责任。不能因一个Action结束而清空共享池、删除其他租户或销毁外部已有数据库。具体可见性依据见[SQLite隔离来源](../../../research/sources/存储关系与交付.md#sqlite-isolation-scope)。

### 验证：进程树、端口、浏览器、容器与数据库资源

端口检查后使用竞态、孙进程泄漏、浏览器配置污染、容器登记漂移、数据库残留、取消或超时、资源误共享、清理失败和 Provider 能力未知。

## 依赖单写、物化、缓存与离线构建

### 依赖状态分层

```text
Requirement
Candidate
ResolutionDecision
Lock/Binding
Immutable Package Content
MaterializationGeneration
Active Binding
Provider Cache
```

package/lock 只是决定载体，不能代表已安装或可运行。

### 单写

同一可变 workspace/解析闭包的 package/lock 状态只有一个提交协调 owner；共享前像的竞争写须原子串行化或 CAS 检验。不同隔离工作区或互不共享锁状态的解析闭包可并行，不能把局部单写扩大为全平台只允许一项依赖工作。其他作者可产生候选，再由同一提交边界采纳。

### 内容存储

包按 exact version/integrity/source/registry identity 进入 CAS。install scripts、native build 和 network 是 Effect，需 sandbox、authority 和 receipt。

### 物化

在独立 generation 完成依赖树、链接、native artifact 和 runtime validation，再原子切 active pointer。失败保留旧 accepted generation。

### 离线

<a id="offline-materialization-freshness"></a>
锁文件和离线artifact bundle固定完整依赖、toolchain、元数据与解释材料；**字节闭包完整、当前用途资格和本次网络许可是三个条件**。按已有策略执行以下分支，不新增全局offline布尔值来覆盖目标/宿主的各自控制。

- 本地所需内容完整且可校验，本次读/执行用途的授权和信任依据仍在实际有效范围内，政策也允许离线完成：直接复用，零下载、零无关探测，不为使用缓存强制联网或重跑安装。
- 内容完整但本次用途所需新鲜度、撤销/反回滚前沿或可信时间不足：在既有网络授权和预算允许时，只取得必要元数据/依据；信任更新成功不重选锁定依赖或重下全部内容。显式离线/网络被禁时不偷偷联网，返回相交资格未知/缺项。仍合格的原件导出、纯查看或其他独立用途可继续，但不得把旧签名自封为无限执行许可。
- 缺少字节或解释材料：有权时只取准确missing closure并校验；无网时报告具体缺项，不接受同名较新包代替锁定对象，也不把空目录当完成。提供者缺少可信时间或更新渠道时，不能仅重置本地时钟、会话或元数据文件mtime延长有效期。

已接受的有界离线委派可使用其明确范围与截止条件；在线即时撤销要求与断网保证同时不可满足时，停止依赖它的作用而非宣称两个保证兼得。更新信任根、迁移反回滚前沿和补救旧风险仍走原有权路径，不由待验证的新包替自己批准。旧材料不再合格于执行，不自动禁止将其用作所选更新协议明确允许的恢复起点；恢复必须保持该协议的信任连续、版本和最终有效期检查，不把中间恢复资格扩大为发布/执行资格。历史内容的准确重现与今天获准执行分别记录；[TUF依据](../../../research/sources/构建分发与迁移.md#tuf-offline-freshness)只是校准这种区别，不强制所有本地工程部署更新服务。

### 缓存

下载 cache、build cache、active materialization 和 rollback generation 分离。GC 不删除 active/offline pin/recovery。

### 验证：依赖单写、物化、缓存与离线构建

注册表漂移、完整性不匹配、安装后脚本、本机二进制接口、部分安装、离线制品缺失、缓存损坏、并发写入者、回滚和旧代际退役。

## 开发启动图、readiness与复合运行结算

客户端的DeveloperLaunchProfile/compound配置最终只协调现有Operation，不建立第二运行状态机。application固定启动图后，execution为每个实际Effect节点分别准入、分配资源、启动和结算；纯依赖边、gate和readiness判断可以在内存中编排。

```text
LaunchGraphRun = exact {
  graphAndProfileRevisionRefs,
  rootRequestAndAuthorityRefs,
  nodeOperationRefs,
  resourceReservationRefs,
  readinessObservationRefs,
  gateDecisionRefs,
  failureAndCancellationPropagation,
  cleanupAndResidualRefs,
  terminalSummary
}
```

图的terminal summary只是所有child事实的投影，不把“部分服务仍运行”“cleanup未结算”“borrowed dependency仍健康”等压成一个exit code。要求全部ready的场景只有所有required readiness在同一有效窗口成立才进入ready；某服务随后失去ready产生新Observation，不能让历史graph-ready永远有效。

资源在启动前按需要reserve，handoff后由真实child/session接管；失败节点只释放其实际拥有且不再被其他child使用的资源。并行启动中某节点失败时，协调者按policy发起stop/cancel，但必须等待各child真实settlement或明确residual，不能先回收端口、目录、secret lease再让旧进程继续运行。

复合图本身不获得任意shell、文件、网络、数据库或云权限。每个node的Grant是根任务授权的相交子集；两个child各自拥有不同秘密/网络范围时，compound不能把它们合并成一个更宽的共享环境。需要共享credential或service时由真实SecretBinding/ProviderSession提供最小共同能力。

重启单一child形成新的runtime generation，后继依赖若绑定旧endpoint/session/ready evidence则相交失效；不强迫无关siblings重启。restart-all也不是恢复旧状态：有持久数据库、消息、外部设备或用户session时按其领域恢复合同处理。

## 声明资源与实物资源的建立和退出

Rule的Subject是逻辑对象；Target图中的资源角色是设计成员；真实数据库连接、文件句柄、进程、外部部署属于运行资源实例。资源从计划到物化必须有合格Provider、准入、当前owner与释放责任；序列化对象的存在不代表资源已分配。

取消或退出任务后，按实际资源账本处理迟到完成、未知状态、清理重试和有条件释放，不通过删除设计JSON来模拟已回收运行资源。
