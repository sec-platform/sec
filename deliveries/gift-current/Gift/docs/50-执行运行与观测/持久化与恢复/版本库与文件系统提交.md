# 版本库与文件系统提交

## 分支、引用、工作树、候选与收口

### Transport 不是语义

branch 名、PR、commit history 是协作 transport。正式候选由 base tree、candidate tree、Work Package 和验证代际定义。

### Review稳定性、批准与Merge Queue

Review是对**精确候选及其审查基础**的Evidence/治理输入，不是对PR名字、branch名字或未来任意后继的永久许可。至少固定：

```text
ReviewRecord = exact {
  candidateTreeAndSemanticDeltaRefs,
  reviewBaseAndComparisonRefs,
  reviewerPrincipalAndRoleRefs,
  scopeAndReviewMethod,
  disposition,
  findingsAndSuggestionRefs,
  conditionsAndValidity,
  submittedAt
}
```

`approve/request-changes/comment/advisory`是Review disposition，不直接成为merge Grant或产品PASS。组织策略可以要求特定review作为Integration Gate输入，但merge authority仍由当前branch/ruleset/owner准入；reviewer能批准不意味着能写目标ref。

候选发生代码/要求/依赖/生成成员变化，或merge base变化使原review比较对象改变时，按review method与策略使相交approval陈旧。纯表示变化若可证明不影响reviewed scope可以复用部分review evidence，但不能只按“diff行数没变”保留。review comment/suggestion绑定原source/candidate revision；代码移动后要通过真实correspondence重定位，不能按行号猜。

局部接受suggestion会产生新的candidate revision，并重新检查与其他suggestion/当前作者变化的交互；“建议来自已批准review”不跳过类型、语义、权限或测试。一次review里多个建议可成组，但只有真实独立的组才允许部分采纳。

Merge queue是**integration candidate生产与排序Provider**，不是额外真源。入队前PR/candidate已具备的review和checks只证明原主体；队列需要构造：

```text
QueuedIntegrationCandidate = {
  originalCandidateRefs,
  exactTargetBaseRef,
  precedingQueueEntryRefs,
  mergeMethodAndGeneratedTreeRef,
  requiredGateRefs,
  queueGeneration
}
```

并在这个组合树上重新取得要求的checks/review-stability。目标base、前序队列项、merge method或候选变化使相交queue result陈旧；不能把原PR CI绿色贴给新的merge group。成功queue check也不等于目标ref已更新：真正integration仍用expected target ref/CAS，失败后保留新的base并重新构造或退出队列。

队列可以批量验证/合并多个候选，但批内某个PR的individual result、组合树result与最终每次ref更新分别保存。若平台只验证组合head，系统只声明该组合的相应Evidence，不倒推每个成员单独在所有中间base上通过。

### 生命周期

```text
prepare candidate
→ freeze candidate tree
→ verify/review
→ integrate expected tree
→ read back new main
→ close PR disposition
→ worktree closeout
→ branch/ref CAS deletion
→ prune/readback
→ terminal receipt
```

### Closeout

远端 merge 成功不是开发 operation 完成。local main、worktree registry、物理目录、local/remote refs、recovery bundle 和 control projections 都需明确终态。

### Recovery

删除 ref 前生成 durable recovery，绑定 exact SHA/tree、owner、purpose、expiry 和 retirement。recovery ref 不能永久保留，也不能在无法恢复时盲删。

### CAS

remote ref 使用 expected SHA lease，local ref 使用 expected object identity。prepare/finalize 之间变化必须拒绝。

### Worktree residue

registry 已注销但目录删除失败时，保存外部 durable authorization，允许有界 resume；没有授权的历史 orphan 永不自动 adopt/delete。

### 验证：分支、引用、工作树、候选与收口

压缩合并、强制推送、脏根工作区、关联工作树、Windows 待删除状态、关闭但未合并、恢复制品损坏、管理员旁路、本地主分支分叉和重复收口。

## 文件系统无跟随能力对象与安全删除

**跨存储提交。（消费条件）：** 若一个动作同时改仓库索引和工作树，必须指定双方都能拒绝过期提交的前像/代际；任一端无条件写成功，不可报告联合原子提交。 合同归属：[恢复后的权威代际、围栏与复写拒绝](持久状态与存储协议.md#gift-fenced-writers)。

### 字符串路径不是写入或删除能力

高风险 I/O 需要一个经过授权、保留物理身份且限制作用域的 capability，而不是重新拼接绝对路径。

### PhysicalPathCapability

```text
PhysicalPathCapability = exact {
  rootLogicalRef,
  retainedRootPhysicalIdentity,
  allowedRelativeScope,
  allowedOperations,
  objectKindPolicy,
  symlinkReparseHardlinkPolicy,
  expectedPreimageRefs,
  deadlineAndResourceRefs,
  authorityAndAttemptEpoch
}
```

它不可通过序列化复制后扩大，也不能跨 attempt 自动复用。

### No-follow traversal

逐级打开 retained parent，不跟随未知 symlink/junction/reparse；每个 leaf 验证种类和身份；操作前 CAS，操作后 readback。词法 `path.resolve` 不能替代此证明。

### 安全删除

```text
inventory
→ classify owner/liveness/retention
→ determine reclaim eligibility
→ authorize exact identity
→ optional quarantine handoff
→ bounded physical settlement
→ ENOENT/object-identity readback
→ receipt or residue
```

年龄、目录名、ignored、大小和磁盘压力只能在已证明 eligible 集合中决定优先级。

### Quarantine

用于将 operational terminal 与慢删除分离。quarantine 是 owner-bound durable 中间态，不是垃圾箱；保留 recovery、GC authorization、expiry 和 resume。

### 平台

Windows EBUSY/EPERM/long path/reparse 和 POSIX unlink/openat/inode/mount 分别实现。一个平台测试不能替代另一个。

### 验证：文件系统无跟随能力对象与安全删除

根对象替换、祖先符号链接、叶节点硬链接、大小写或 Unicode 别名、删除竞态、未知子对象、只读对象、目录非空、跨设备边界、注销后崩溃和重复调用。

<a id="本地参考的较弱保证必须显式标识"></a>

### 路径与合作锁画像的保证边界

采用路径与合作锁的Workspace画像时，须检查根设备/inode，拒绝控制文件混入输出及不允许的符号链接、硬链接、文件/目录冲突与可移植名称碰撞；读文件比较读取前、文件描述符与读取后的身份和属性。这种画像不是完整的句柄能力实现，不承诺阻止恶意父目录替换、路径重定向或不合作编辑器的最后时刻竞态。需要更强保证时采用相应隔离或句柄机制，不能从路径检查通过推导该保证。

操作临时文件由持久意图和确定名称定位；只有内容与模式匹配已登记前/后像才可自动清理，未知或部分临时数据保留现场并进入有权的恢复分析；只有实际政策要求时才转人工，不一律unlink。回滚后空目录有意保留，不按目录名递归删除。更强画像应实现受约束句柄遍历、排他工作树或原子快照，再用同一并发与故障语料验证。

## 源码写回与目标运行的边界

Gift 编译、Gift 写回和生成程序运行是三个不同操作。

编译产生制品树，不覆盖用户工程。写回读取当前前像、授权写集、生成计划，在需要时使用暂存、逐步日志、CAS、恢复资源和读回。生成程序按自己的目标运行时执行业务；默认不让每个条件语句、数据库调用或本机操作回到 Gift 服务器批准。

纯函数生成可只在新输出目录写文件；多文件覆盖、数据库迁移或部署需要更强策略。不是所有操作都需要同样成本的持久会话。读取敏感源码有独立读取权限，它不授予修改权；写入授权绑定目标和前像，不混入纯程序。

端口的程序效果合同决定生成代码如何访问能力；编译 Host 的工具权限决定 Gift 本次能否启动编译器、安装包或写回。拥有后者不能自称目标程序运行安全。

理由：没有安全写回会伤害存量工程；把生产控制面强加给所有生成业务又违背可独立运行目标。反证为编译命令暗中执行迁移、生成物默认联网 Gift 才能调用纯函数、超时被当未执行而重复不可逆动作。

### 语义源码写回的准入与隔离

语义源码写回沿用本篇的 Operation、Plan、Admission、Journal 和 Readback，不另立 Mutation 状态机。Admission 必须同时绑定受信上下文给出的主体、本次操作、语义目标、规范来源 owner、获准物理区域、必须保持的内容、禁止的效果、实际 Provider 与允许产出的 Claim，及作为前像的工作区修订。任何一项未知、歧义、陈旧或冲突都在写前阻断；读取、观察、路径可达、编译成功或调用方自报字段都不能补签写权。

操作目录只接收调用方有权选择的输入；owner 能从已固定事实导出的路径、区域、保持义务、权限边界和结算字段由 owner 自己产生并读回，调用方不能提交这些派生字段来扩大作用域。没有受支持的操作定义、目标无法映射或 Provider 不具备所需能力时，必须在产生任何暂存或外部效果前返回明确 unsupported。

写回映射必须闭合“已采纳语义 owner → 对精确 Source Program 的当前观察 → 唯一语义映射 → 物理路径和区域证明”。Source Program observation 只提供可验证前像，不能创建语义 owner、授权或采用关系；同名、相似结构和旧映射都不能替代当前唯一映射。若映射只能确定到多个区域，保留冲突并停止写入。

变换只消费冻结的权威输入和明确保持范围，在隔离环境产生候选输出。除 Admission 明确列出的效果外，不得借变换隐式安装依赖、运行构建或脚本、访问网络或启动不受管子进程；时间、内存、进程、网络和输出预算共同约束执行。候选仍须经过前像核对、暂存、CAS、提交和读回，隔离成功本身不表示写回成功。

<a id="snapshot-aba-and-actual-tool-consumption"></a>
## 输入捕获必须绑定实际消费，前后相等不排除ABA

作用与验证工具必须消费已绑定的真实输入。执行前读取A、工具途中读取B、执行后又读取A时，前后摘要相同仍不证明产物来自A。路径固定、文件句柄保留、只读类型和前后mtime各自只提供有限性质；已打开句柄可防某些路径替换，不必然防止其他写者原位改字节。

采用不可变内容、宿主提供的真实快照或足够强的版本/读集与提交协议，将捕获对象连接到最终工具消费点。创建名为snapshot的目录不产生保证；运行期间动态读取的工具、环境、配置、成员与不存在性仍须固定或保留未覆盖范围。只对纯、已隔离且可重放的计算执行安全冷重算；输入不明或效果已可能发生时，不能通过换provider和新身份消除原责任。

## Git 推送、PR 合并和发布环境不是同一个提交边界

本地编辑、生成候选、创建 commit、push ref、PR 通过检查、merge 更新主分支、部署远端环境是独立动作。每步建立准确的 `(repository,ref,expectedHead,objectDigest,actor,grant,effectAttempt)`；Git 中已计算 commit 对象不代表远端 ref 已更新。更新分支/主线应使用受保护的 compare-and-update（例如服务器接受的带预期 head 的更新）并读回；远端拒绝、权限失败或网络不明时，不因本地已构建出相同 SHA 就宣布远程成功。

PR 的 review/CI 资格须绑定审查过的源与 base 关系；base 漂移、所需政策改变、合并前新增提交都需要按真实范围失效。分支清理由确认已保留的工作与归档/合并事实决定，不以“已关闭 PR”自动删除尚未迁移的独立作者内容。部署后的在线状态和外部数据迁移需要单独读回/恢复，Git reset 只能移动存储的源码引用，不能让外部资金/用户输入/设备动作逆转。

异地仓库或平台不同原子域之间不承诺“一次点击完成全部”。失败时保留每步 attempt 的实际状态和下一步可重放位置；允许只完成本地可独立验证的工作，同时准确记录没有远端授权所造成的阻塞。

## 工作区发布和非合作写者

发布以准确受管成员集合和各自前像为条件；暂存候选目录并验证内容、路径/实际对象、所有权与构建结果后，才通过宿主提供的原子根指针或事务完成可见切换。根指针CAS只能保证遵守该指针的读者看到一致版本；绕过它直接读多个文件的外部程序不自动取得原子快照。

需要原位写多个文件而宿主没有跨文件事务时，必须选择显式“非原子可恢复发布”合同或拒绝要求原子性的任务；不能把rename单文件的性质扩展到整个目录树。非原子模式记录每个成员的预期前像、已写后像及剩余动作，读者若不能容忍中间态则必须隔离/停机，不在底层偷偷降级。

路径检查与实际打开之间防TOCTOU：使用宿主受限句柄/目录根能力及打开后身份核对；有符号链接、大小写alias或外部不合作写者时不能仅靠预先字符串检查。恢复只恢复仍与本次已写后像一致的对象；发现别人新写入就冲突隔离，不能用旧备份覆盖无关新工作。删除亦需当前前像和owner确认。

发布成功后旧artifact可能仍被进程使用，按引用/驻留生命周期回收；不能切current后立刻删除旧runtime。Git提交、工作区可见文件和实际运行实例分别有状态，不以其中一个成功推导另外两个。所有失败留下可定位候选与最小Diff，不泄漏无权源内容。

**验证与反例**：多文件半写、旧读者绕根指针、打开前symlink替换、第三方并发写、恢复覆盖他人修改、旧artifact仍驻留的情况分别核对。

**实际能力边界**：真实Windows/Linux文件系统故障及Git写入没有执行。
