# 迁移备份与权威恢复

## 迁移、升级、修复与恢复事务

**恢复到写入的界限。（消费条件）：** 备份校验成功仅得到旧字节及来源，接管正式写权还须重新围栏；应模拟旧主收到恢复前发出的延迟写入并确认被拒绝。 合同归属：[恢复后的权威代际、围栏与复写拒绝](持久状态与存储协议.md#gift-fenced-writers)。

### 统一骨架，专用语义

升级、数据迁移、依赖替换和自动修复都使用同一 Operation/Plan/Admission/Journal/Readback 骨架，但每种操作有不同 correctness、compatibility 和 recovery 义务。

### MigrationTransaction

```text
MigrationTransaction = exact {
  migrationRef,
  oldAndTargetGenerationRefs,
  compatibilityDecisionRefs,
  operationDag,
  perStepPreimageAndPostcondition,
  irreversibleStepRefs,
  checkpointAndJournalRefs,
  compensationOrForwardRecoveryRefs,
  verificationAndCutoverRefs,
  backupAndRecoveryAssetRefs,
  terminalState
}
```

### 计划必须零写

`plan` 和 `dry-run` 不修改 source、control、lock、provenance、artifact 或数据库。需要保存计划时，由独立 `save-plan` Effect 操作拥有目标和 readback。

### 安全变换

迁移命令的已协商封闭信封拒绝未列入该版本的字段/操作、非数据宿主对象和非法路径；开放扩展区及被迁移的原数据按各自schema处理，不能把一切未知字段当攻击或静默删除。JSON应从不执行代码的解析结果进入类型化验证，核解码后重复键、值域、层数/字节/展开预算和路径的真实语法；宿主传入的getter、代理对象或带行为对象不能当普通数据枚举复制。避免原型链写入/隐式setter，使用受限数据映射和已验证更新路径；合法载荷中与宿主特殊键同名的数据不因此被改写，不能安全表示时保全载体并拒绝相交写入。

未知字段、枚举与出现次序沿[未知保全合同](../../20-语义与组合/组合/语义扩展-执行许可与解释激活.md#unknown-occurrence-fidelity)保持。旧reader能无损定位并修改已知区域时可以局部迁移；需要解释未知区域、改父结构会破坏它或无法保持requiredFidelity时，只阻塞相交迁移/取得合格解释器，不把原件导出、无关查看或其他独立对象一并停掉。候选先在受保护前像上形成并验证，实际保存仍比较当前前像/权限，不从“已保全未知”推出迁移的语义等价。

文本替换绑定old digest、expected match count和result digest；regex有复杂度预算。这些校验可约束获准的纯文本替换，但命中数及摘要不证明程序重构或数据库迁移语义正确；这类变化使用结构化Provider及对应保持依据，不能用字符串定位模拟语法。

### 恢复资产

backup 必须来自 exact observed state，有 manifest、digest、范围、保留和 restore drill。恢复失败时保留唯一备份和 durable `recovery-required`，不能在 `finally` 删除。

### 自动修复

修复只针对精确 Failure/Claim/Responsibility，修改最小影响闭包。已有人工实现不能被模板整体覆盖。`applied` 只说明 Effect 提交，`repaired` 需要新 revision 的 required Verification。

### 验证

- plan 零写；
- stale source/plan；
- 第 N 步失败；
- restore 中途失败；
- 外部 writer 新增数据；
- irreversible step；
- retry/replay；
- unsupported operation 不能伪通过；
- rollback 与新 schema 不兼容；
-修复后验证未执行。

## 备份恢复与权威重新加入

恢复默认进入`isolated-restoration`：可校验与解释保全内容，但不接受旧租约、不自动派发旧outbox、不把旧授权当当前授权。先在隔离位置读回manifest与完整内容闭包，验证格式和可用解释器；缺内容、损坏或未知引用均保留具体范围，而不是自动初始化空库。

一致内容不等于最新权威。恢复还需要从没有随这份备份一起回退的可信来源取得所需的拒旧依据：当前协调域的写权/围栏下界、已生效撤销与删除前沿、信任根接受范围，及相关外部作用状态。来源可以是仍存活的权威服务、受保护持久见证、独立备份链或经有权程序重新建立的控制域；不能让备份内部的旧签名或旧计数器自证“截至现在完整”。

若全部最新拒旧信息也一起丢失，就不能同时承诺继续旧写权、拒绝所有旧重放和无需外部协调。保留源代码设计/分析能力；需要恢复写入时，明确评估可能丢失的完成、删除和撤销，隔离旧执行端，由有权主体建立新控制代际及端点接受规则。无法隔离旧写者的目标保持受限，不能只把本地整数加一便宣称围栏安全。

重新加入按目标分别进行：取得新能力；核对当前物理前后像；以原稳定业务事件身份查询尚未结算效果；能够证明已完成的只补结算；允许同键安全重复的按目标窗口处理；既不能查询也不能去重的非幂等作用保留未知，由实际有权主体按明确风险选择业务协调或补偿，人工仅在对应政策要求时参与，不自动新建ID重发。已恢复的数据库是意图与历史证据，不是现实终态。

恢复后开放读写可以分批：仅依赖已核对区域的设计/查询先开放；涉及未核实授权、已删敏感内容或未结算外部效果的范围继续隔离。新控制代际和旧业务事件ID分工不同，前者不能让后者获得重复执行机会。

### 并行恢复副本的重新加入仲裁

当两个管理员从相同旧备份分别恢复到R1、R2，两处本地都可能产生摘要正确、日志连续的后继；仅凭各自 `restoreSucceeded=true` 不能让它们同时成为有写权的当前代际。恢复程序在接回共享服务/目录前取得其真实接受前沿与竞争实例清单，明确隔离的候选写入、唯一被认可的代际，或经原业务约束支持的合并协议。没有可共同确认的围栏时，维持读/导出/人工比较，不能以本地恢复先完成作为自动胜选依据。

若R1已生成外部付款而R2离线还持旧outbox，即使最终只采用R2的源码或数据库内容，也要从独立执行记账/Provider查询原业务事件，先处理重复风险；不能把R1的效果从R2的日志中看不到，当成“未发生”。重新加入所需的信息包括各代际已被接受的事件、未决Attempt、旧租约/凭证、删除前沿及实际可拒绝的端点。能合并结构记录但无法合并现实效果时，只保留已可证明的合并结果与相交未决。

### 删除与离线前沿

删除记录必须说明覆盖哪些存储、副本、派生物、备份和外部提供者。逻辑禁止访问、删除索引、使证据失效与物理擦除不是同一终态；受保留义务约束或无法控制的副本继续标记，不声称已完成全部删除。墓碑/摘要可能仍可关联个人，也要限制披露和保留，不能称其天然匿名。

恢复旧备份时先取得其备份位置之后、达到本次所需新鲜度的删除/撤销记录，再开放相关数据。只有旧备份本身时，不知道“以后是否删除”就是未知，不能空集代替。删除来源丢失的场景按上述隔离和有权重建处理，不承诺无依据的自动修复。

在线/离线成员维护被接受的同步前沿。删除墓碑只有在声明的有效成员已确认，或旧成员/旧请求被端点代际规则可靠拒绝后才可压缩；无法限定离线期限和旧副本重新加入时，选择持续保留拒旧信息或让旧副本重新登记/全量协调，不能有限TTL后无条件允许旧写者加入。重新登记不抹掉其本地草稿；草稿作为待重新校验的候选导入，旧删除目标和旧权限不自动复活。

派生索引、AI上下文切片与缓存沿真实来源处理失效和删除。已披露到系统外的内容只能按可控制范围和提供者合同处理，不能承诺从他人记忆删除；某输出确有独立合法保留依据时单独记录，不能仅以“是派生物”豁免。

<a id="accepted-history-checkpoints-and-dedup-horizon"></a>
## 受理历史、检查点代际与去重有效期

位置、序号和已完成进度必须绑定它们所属对象与代际。旧日志“已回填到10”不能用于重置后新日志的第1条；对象重建、worker替换、分页续做和分片恢复同样不能只比较裸偏移。记录可解析、摘要正确及状态机局部合法，只支持相应结构性质，不证明已可靠受理或确认的效果没有丢失。

任务要求历史不丢时，恢复须对账独立的受理/提交依据、实际效果与仍未结算结果。若期望历史与恢复状态都来自同一个可能丢失的文件，二者一致不能独立证明完整性。当前目标值碰巧相同也不证明某次指定操作发生过；反之，当前值不存在不证明它从未发生。

去重身份仅在提供者实际的作用域、载荷绑定与保留窗口内有效。同key在远端忘记记录之后可能再次产生效果；本地tombstone不创造远端去重保证。窗口到期、查询历史丢失或旧attempt仍可能晚到时，先查回、围栏或结算原责任；不能以新的方法/身份重发绕开未知。允许的补偿与前滚继续按独立授权及业务合同执行。

持久续做还绑定原执行定义、解释、已记录决定与命令顺序。“等待→发布→done”改为“发布→等待→done”不因最终done相同而历史兼容。升级采用真实的版本保持、迁移或排空切换；旧JSON可解码不代签旧历史可以由新代码重放。

<a id="gift-authoritative-restore-fence"></a>
## 恢复权威与防旧备份复活的完整顺序

恢复候选 `RestoreBasis{backupManifest,sourceAuthorityEpoch,restoreTarget,newRootIdentity,policyEpoch,revocationFrontier,tombstoneFrontier,journalFrontier,activeAttemptRefs}` 不是新的当前事实。先校验备份内容/解密或签名能力及快照一致性，再于隔离范围解析 schema、Operation/Attempt/Grant 的身份与寿命。恢复读取完整历史字节不代表恢复原权限；需要重新通过当前 Policy、角色授权、秘密轮换及 writer epoch fencing 才能变为可用目标。

安全切换次序：停止或隔离旧 writer → 安装拒旧 epoch/tombstone 高水位 → 使目标读者具备版本解释 → 读回未结算外部操作并决定 join/对账/隔离 → 发布带前像的新的 Head → 审计读者资格与副本清理。恢复既有不可逆物理 Effect 不能靠回滚备份撤销，后继协调生成新的 Operation 而不改写旧 Attempt。若未知副本仍可能写入且后端无法 fencing，返回 `RESTORED_FOR_INSPECTION_ONLY` 而不签发单一权威写入资格。

每份备份需有可检验的依赖闭包：引用的 Blob、编译/规则解释修订、加密密钥可用性、必要事件日志与已应用位置；只备份当前 Head 而丢失其成员不能成功恢复。删除请求与仍在法律/安全保留期的证据分开记录精确适用期限；不能因一份备份已清除就宣称外部副本已清除。验收注入旧备份包含已撤销凭证、已删除数据、旧 writer 的迟到成功、schema 不兼容和未结算支付回执，分别检查当前权限、内容披露与 Effect 状态。

<a id="prebootstrap-migration-exit"></a>
## 格式、运行代码、证据与权威的联合迁移

升级首先分类：作者语法/意义、公共类型/API、二进制 ABI、存储格式、方法/目标供给、权限与证据各自变化。能读旧字节不等于能按旧义写入；能启动新编译器不等于旧回执和运行实例都可迁移。每个实际读写组合给出接受/拒绝、转换源、可逆性和退休前提，不能只声明一个通用兼容版本范围。

数据迁移先固定真实前像、转换方法、独立验证与失败点，在不覆盖唯一来源的空间准备候选；需要停写或联合版本窗口时显式协调写者。不可逆信息丢失在采用前暴露；仅改 Schema 不能恢复已删除字段的意义。备份要能被现有独立恢复链读取，并取得可恢复性演练结果，文件存在不等于备份有效。

密钥/权限更新可能要求立即停止旧作用，不能为平滑迁移无限延后安全撤销。旧读取器、旧代码和旧证据分别保留到其必要责任结束；保留读取能力不自动保留执行权。迁移完成清除无消费者的兼容壳，但不删除仍支撑法定/业务/结算责任的真实资料；资料敏感性和保留政策来自有权来源。

退出或更换 Gift 版本要交付作者源、普通目标制品、锁与必要解释/恢复资产；依赖专有远端供给的地方明确标出替代/迁出限制。编译器自举的固定点与工作数据迁移是两个不同验收，不能一绿俱绿。

<a id="design-b27"></a>
## 迁移兼容的五个独立方向

迁移分别判断作者源/语义、线协议、原生ABI、持久状态、Evidence/Grant接受五个域，不用一个“向后兼容”布尔覆盖全部。旧reader读新source和新reader读旧source是不同方向；ABI同名函数、数据库新增字段和新证据格式各有自己的可接受转换。

新旧共存时每个资源仍只有一个有效写者或明确协调的事务范围。用epoch/fence隔离旧writer，迁移状态先由新版本只读验证，再建立恢复点、升级读者、受控切换写者；不可逆转换前必须确认有可启动且有权的恢复路径。不能以“备份已生成”替代备份可解码/可恢复/secret仍可取得。

迁移失败保留精确阶段、前像和已发生动作；数据转换可逆不意味着外部作用可逆。旧证据如被新语义不再接受，应保留历史解释及原因，不能改写历史PASS；新的真实授权由当前发行者决定，不能从旧配置自动继承。工具/插件回退若不再认识当前格式则阻断，先执行明确的降级转换或停在安全状态。

**验证与反例**：新source旧reader、ABI布局变更、旧writer回连、不可逆数据转换、恢复密钥缺失、新规则不接受旧proof、已发生Effect的源码回退。

**实际能力边界**：目标存储与旧新运行实例共存实测未进行。
