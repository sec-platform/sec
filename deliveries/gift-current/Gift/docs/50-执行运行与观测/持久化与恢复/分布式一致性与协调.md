# 分布式一致性与协调

## 分布式事务、消息、重试、补偿与幂等

### 跨系统 Effect 通常不可原子

数据库、消息、支付、部署和外部 API 不能假设共享一个 ACID 事务。Gift 必须显式建模部分完成和补偿。

### DistributedOperation

```text
DistributedOperation = exact {
  operationRef,
  participantAndAuthorityRefs,
  stepDag,
  messageAndIdempotencyKeys,
  localTransactionBoundaries,
  deliveryAndOrderingContracts,
  compensationOrForwardRecovery,
  readbackAndReconciliation,
  deadlineAndRetryPolicy,
  terminalAndResidueSemantics
}
```

### 消息语义

at-most-once、at-least-once、effectively-once和exactly-once scope分开。消息去重不等于业务Effect幂等；需要跨崩溃防重复的业务消费者，须由真实本地事务/耐久去重与业务前像、目标端同键去重或原RetryBasis允许的其他准确机制建立保证。纯状态失效提示可在可重观测条件下合并，不强制每个通知持久记账。派生应用状态与已应用位置沿[共同检查点](../../80-开发者与接口/工具协议/客户端与并行会话.md#projection-checkpoint-resync)一起恢复；源已发送、消费者已接收、投影已应用与业务Effect已结算不能互相代签。

### Saga

补偿不是回滚：可能不可完全恢复、依赖新状态、失败或产生新外部性。每个 compensation 有独立授权、风险和验证。

### Outbox/Inbox

需要数据库状态与消息一致时，使用 outbox/inbox 或等价机制；仍需处理重复、乱序、迟到、清理和 schema evolution。

### 不确定完成

外部完成未知时，按实际端点合同使用原 operation/idempotency identity 读回，或在真实同键去重保证内重试。两者都不具备时保留未决并进行有权协调，不用新身份盲重发；timeout本身不证明失败或未执行。

### 验证

网络分区、重复、乱序、消息丢失、consumer crash、补偿失败、旧消息晚到、schema mismatch、duplicate external effect、clock skew 和 poison message。

<a id="merge-invariant-and-offline-budget"></a>
## 副本收敛与全局不变量

两个节点从库存1出发，各自接受销售1，本地都合法；合并后总销售2违反整体约束。副本最终相同、去重和单副本事务不证明不变量。按选定合并规则检查同一合法基础的所有允许并发分支合并后是否仍合法；[协调避免研究](../../../research/sources/全域组合与仿真依据.md#coordination-avoidance-in-database-systems)只提供特定数据库模型的判断依据，不扩张为任意物理系统的定理。

按要求选择实际协调/条件提交、提前分配互不重叠的额度、将离线动作保留为提案，或接受明确冲突后的补救。额度总额不超过真实量，转移需防两端同时可花，旧副本按准确世代重新准入。技术命名空间或随机ID不能证明现实人、物、合同的业务唯一；等同需来源与有权决定。

局部事务、消息传递、处理结果及外部资产结算各自有范围。Exactly-once必须指明观察对象；不合作外部服务没有查询/幂等时不能凭名称获得原子效果。正常可交换更新仍可用无协调路线；资源权利、实际承诺与未结算责任按真实参与者保留。

<a id="consistent-cut-and-control-state-recovery"></a>
## 流与并行运行的恢复切面及控制状态

恢复基线必须说明源进展、算子状态、在途消息、sink作用与控制信号如何构成一致切面。源已发送7和11、算子只计入7、通道保留11时，仅保存“源已发完、sum=7”会丢11；回退源偏移但保留已累加状态又可能重复7。局部文件都合法不能证明组合正确。

屏障对齐、记录在途通道状态、事务提交或可验证重放去重是不同条件方案。端到端保证仍取决于源能否按所需范围重放、sink是否具备实际事务/幂等/查回能力；内部checkpoint成功不授予外部exactly-once。没有共同快照能力时保留相容切换/对账协议和准确保证范围，不虚构跨系统原子性。

不对齐检查点可用更多持久I/O换取较少对齐等待，但不自动消除单条不可中断工作。恢复后算子若消费水位、计时器、随机或其他控制状态，其恢复顺序也属于语义：记录8原来读取watermark=10，恢复后先处理数据再装回水位可能读到0并改变结果。严格前沿、估计水位与本次控制观察分别保持。

扩缩容与重新分片还要保存key/分区身份、在途数据归属、广播状态和各通道进展；仅改worker数量不能证明可继续。旧状态不能合法迁移时可排空、回到合格恢复点或返回限定不支持。新分配与旧责任交接前不删除原恢复资产。

<a id="gift-distributed-cut-fencing-closure"></a>
## 联合协调、分区和最终一致性的条件保证

`JointCommitBasis{participants,participantEpochs,requiredInvariantSet,localAtomicDomains,readVectors,writeIntents,deadline,coordinationProfile}` 必须为每个参与者标明可条件写的比较值、可读回幂等键、事务隔离级别和失败后的观察能力。存在可证明的单个协调域时，在其真实事务中一次提交共同不变量；可交换且满足合并不变量的更新可免协调；不能取得上述任一条件时，只能展示局部进度与 Saga 义务，禁止返回原子联合成功。

分区期间若维持写可用，必须证明两侧提交可交换或拥有相互排他的 escrow/额度，或明确接受后续冲突修复的业务语义。将 lease/fencing token 只写入本机日志无效，必须让**实际受保护目标**拒绝过期 epoch 写入；外部不支持 fencing 的效应，超时和新 leader 不能保证旧请求未继续。消息去重和外部实际业务 exactly-once 分离到明确的效果观察对象、窗口与重试证据。

跨源一致读取采用 `CausalCut{participantSet,participantGenerationVector,sourceEventFrontiers,causalDependencies,enumerationCompleteness}`；无法界定成员全集或因果前驱缺失就返回 `PARTIAL_CUT`，不能据此否定未见对象存在。验证同时考察动态成员加入、时钟漂移、同一请求重复提交、部分补偿、长网络分区、协调节点崩溃和老 epoch 反复恢复；保留具体影响范围，而非永久锁死无关区域。

<a id="design-c06"></a>
## 一致性模型与过期写者围栏

多节点实例选择逐对象/事务范围的一致性模型：线性化、因果、会话或最终一致；模型不是只填一个级别名称，还要给读写、冲突、故障与可用性观察。要求跨对象不变量时声明同一事务/协调域，单对象线性化不推导全业务原子性。

写者资格通过具体epoch/fencing token与接收方检查维持；租约发出不证明旧写者已物理停止，存储/设备必须拒绝过期fence，或合同不能宣称排他。共识画像绑定参与者、quorum交集、故障模型和成员变更协议；分区时选择阻断/降级读写的可接受范围，不能无条件承诺所有节点同时可写且全局强一致。

副本恢复先核当前epoch、快照及增量日志，旧数据重加入只能按所选合并/冲突规则处理。删除和tombstone保留期要覆盖实际离线/重放范围；没有范围证据不能安全删历史并宣称不会复活。灾难恢复切换主权威时撤销旧写者，保留不可逆冲突的显式处理，而非latest timestamp自动赢。

**验证与反例**：网络分区、旧writer仍运行、成员变更、删除后离线副本回归、跨对象不变量、时钟偏差冲突。

**实际能力边界**：具体复制系统、成员/故障模型和fence执行点未绑定。
