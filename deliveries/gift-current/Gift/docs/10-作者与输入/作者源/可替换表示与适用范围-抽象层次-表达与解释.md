# 抽象层次、表达与解释；开发角色、阅读与完成条件

## 抽象层次、表达与解释

### 新语义责任不等于必须另造完整通用语言

用户目标是中立工程语义、简洁自由与持续演进，不是单独发布一款函数式语言。目标要求机器能准确解释作者内容，却不从逻辑上强制全新词法、解析器、标准库和工具链：嵌入式前端、结构表示或现有合适语言都可以承载明确语义。选择复用时仍须说明其宿主含义如何映射，而不是将宿主AST冒充公共模型。

当前公共体系独立规定Int/Text、类型、求值、契约和效果，因而承担形式语言的语义责任；它不要求所有作者学习一套新词法。`.gift`与结构体按共同合同表达同一支持域。宿主构造SDK在原理上也可映射中立语义，但不是当前采用项；目标源码生成器与中立作者前端本来就是不同机制。成熟宿主解析与编辑继续用于实际选定的原生/目标适配，中立映射和保持仍由Gift承担。

新语法只有在直接表达公共含义、高层组合、多目标保持或重复维护消除上有价值才有产品理由。“fn替换function”“保留词更少”“能递归”分别不构成价值证明。当前18词是草案表面，不是固定产品配额；发现必要表达缺项，应修正最小相交规范，不为维护词数把复杂度转嫁给作者。

### 计算语言与工程抽象不是同一高度

当前基础使用类型、函数、不可变列表、精确值和契约，不让作者安排CPU寄存器、栈槽或指令地址；按机器抽象尺度，它是高级计算语言，不是汇编或低级IR。相对用户的工程任务，它仍可能太低：把状态关系、事务意图和错误传播全部手写成函数，虽然可计算，却没有自动获得高层简洁。

因此计算表示和Program语义只在真正需要描述或实现计算主体时进入，不成为所有工程含义的万能入口。状态、关系、时间、资源、权限、持久化、交付和其他领域要求可以在其原owner保持到实现选择阶段；只有选中的方法需要可执行主体时，才降低为对应Program IR、原生调用、查询计划、状态机、设备操作或其他目标机制。不能为了内部统一，先把FIFO、事务、布局、资源寿命等全部改写成函数/循环，再从程序反推原工程含义。

同理，常见宿主结构名不是作者抽象的固定上限。Queue/Stack/Map等可以作为已有Definition、库或目标实现的便捷名字，但公共语义应保持真正需要观察的顺序、重数、键唯一性、访问、持续性、错误和资源条件；HashMap、VecDeque、BTree、数据库索引等物理选择留给合格供给。若作者明确要求某个原生结构或ABI，则按稀疏控制或原生源保全，不以“更抽象”为由删除该决定。

这不是另建一套通用Property IR。Definition、RequirementTerm、领域结构、程序主体、原生资产和目标Binding继续分层拥有事实；[作者信息完整性](../../20-语义与组合/作者语义/作者信息完整性与控制入口.md#author-information-completeness)只规定结果相关区别必须有真实落点，[结构化作者面](结构化源码.md#author-surface-projection)负责把这些分层事实按任务显示给作者。

基础层保证没有预装功能时也能表达算法；高层领域层保存状态、关系、决定、资源和作用义务；实现策略层在明确自由范围内选择算法、布局和执行方案。作者选择某个低层细节后它成为约束；未指定的机械细节交给合格的生成器。三个层次可以对应同一对象的逐步具体化，不要求三份手工同步的源码。

反例判据：作者为了一个普通新需求必须手写整个通用事务框架；一个递归列表例被当成高层工作流已完成；高层需求只能退出模型写原生；用户设置性能要求后编译器悄悄缩窄数值或错误语义。本章不能仅凭基础函数完整而关闭这些工程层缺项。

### 程序表面简洁与需求关系抽象是两项交付

省略可推导类型、简化别名和使用函数值，解决的是源表示成本；它们不能单独代替“对哪些对象施加什么关系、保持什么、如何组合与变更”的产品能力。当前共同需求合同在[语言能力映射与最小控制](../../20-语义与组合/组合/跨软件需求合同.md#cross-software-intent-contract)，由既有Requirement、当前定义、语义方法及任务投影承担。

不新增一种所有用户必写的意图语言。直接源码继续可以是完整需求定义；已有行为关系可以由当前库/结构引用承担；自然语言形成的准确候选须有实际来源和接受关系。一个函数能表达全部计算，不自动使应用开发者拥有合适的高层关系操作；高层关系接口存在，也不免除底层实现与开放创作。

普通任务按实际需要使用值、关系、状态/时间和资源形式，文本、表与图回到同一源。当前语法及原有限组合保持，关系模型新增的实现职责不以“不增关键词”掩盖，也不因此重新打开SDK或扩成第三目标；TS＋Rust目标计划已固定，具体Rust能力仍由真实消费者、目标画像和证据决定实现范围。

### 文本基线与管脚结构入口的共同边界

本章保留可选中立计算文本的具体语法，不以文本后缀独占工程语义；新产品的逻辑结构作者面不依赖先解析此文本，也不要求全部区域采用同一种物理 source format。类型化管脚/组合与结构作者的完整规则分别见[工程语言](../../20-语义与组合/组合/定义与接口.md#控制逻辑能力管脚与库绑定)和[作者归属](工程源/作者编辑保存与迁出.md#多种作者界面如何编辑同一工程)。文本适合算法与局部源差异；机器结构编辑适合连接与参数；选择依实际任务，不宣称任何一种是全域最优。

同一基础构造在两种已支持入口中的类型、作用域、求值、契约与效果相同，结构入口不借外壳绕过检查。不能用纯图的遍历顺序重解释文本求值，也不能要求所有结构节点先打印成本章文本才编译。当前基础EBNF未增加管脚关键字；更广图/领域体合同仍按已选择范围闭合，不由本段宣称全部实现。

## 开发角色、阅读与完成条件

### 阅读次序：普通开发不从最细语义开始

新建产品首先看当前[结构化意图与Block模块](结构化源码.md)；需要端到端实例时再看冻结的完整意图范本。以下函数、类与短写法是实现定义或明确选择的计算作者合同。需求模块直接解码到既有Definition与RequirementTerm，计算文本通过所选前端进入同一语义，二者不是必须先后转换的两份程序。

本章完整语义用于解释、检查和实现，不是每个目标工程必须复写的算法目录。已有需求由准确定义引用、参数和稀疏控制承担时，无须增补类或低层主体；源码范本中的整数比较只检验对应的语言/回写能力。没有对应价值的新包装不能因为“统一进入Gift”成为必经层。

作者可以直接修改已有文本并成组捕获。机器协议中的propose/draft只是可选提交形式及类型化变更入口，不能反向成为语言语法或作者每次必填表。完整规则见[正常编辑](../../80-开发者与接口/用途与任务范围.md#正常写文本不手工驱动全部流水线)和[目标/作者关系](../../20-语义与组合/作者语义/能力映射与表达边界.md#目标工程作者源和需求抽象分别有位置)。

### 语义规格与日常作者面的不同验收

本章列出表示与语义责任，供实现、审查和精确下钻，不是每项任务应输入的字段清单。计算文法只在明确选择该画像时构成有界实施基线；当前产品作者源经其SourceProfile直接进入共同SemanticModel，不先转成另一种作者格式。语法闭合或示例可书写不能证明它是成熟语言的更优替代。保持公共中立语义不冻结全部表面选择，也不因技术提名而自动采用TS元编程或另造一份同义JSON树。

局部赋值与循环已在通用组合中给出确定入口；默认实参、标签控制和通用类型类仍不由本基础文法提供。扩展根据独立语义与作者负担决定，不以维护18个基础词的数量阻止必要能力，也不把其他语言全部词表并入。每项支持须同时有解析、静态含义、运行、目标和编辑合同。

能从表达式与真实上下文唯一确定的局部类型、效果和名字，不要求再次标注。公开兼容边界、故意收窄的要求和无法确定的选择需要保留；推断结果不能反过来修改要求。未知仍局部显式，不以任何缺失都补默认或任何信息都必填两个极端处理。

作者可以在同一模块只维护公开合同、行为体、真正独立约束和确需固定的实现选择，其中无必要的部分可省。库定义应承担其构造和值域条件；调用者只有在输入尚未满足或需要更强保证时处理相应边界。不可变输入检查可以复用，不应通过要求作者在每次调用重复require来实现检查缓存。

对于常见结构，公共作者面应直接保留相应组合与关系，再由工具降低到本章基础构造；对独特算法，允许直接使用完整的中立计算能力。两者只有一个作者来源。查看展开不把低层树升为必写源码，局部具体化也不强迫整个模块变成不透明原生。当前细程序示例是含义见证或一种可用写法，不自动指定最终最简入口。

对不同任务的采用结论及实际比较由[产品作者成本](../../00-系统与原则/产品/全体系能力与边界.md#作者负担不能以规范完备抵消)拥有。未有采用依据不妨碍在明确授权下实现一个有界候选以取得证据；不得将该实现或文档改动说成作者收益已被证明。

### 可编译不等于整个需求已完成

| 状态 | 可以得到什么 | 不能推出什么 |
|---|---|---|
| 原文已保存 | 草稿、位置和诊断 | 已经合法或已采纳 |
| 基础语言有效 | 绑定、类型、效果与结构结论 | 业务满足、程序必终止 |
| 行为闭包明确 | 输出所需主体与绑定已决定 | 所有后端均支持 |
| 所选目标已生成 | 实际源码/制品与artifactRef | 类型、行为、应用已经通过 |
| 特定检查通过 | 绑定主体与范围内的证据 | 其他目标、未来输入或部署同样通过 |
| 实际应用完成 | 指定目标的真实读回 | 未请求的发布、迁移或外部事务完成 |

编辑态允许不完整。源中缺分号、未决类型、未实现要求或未知端口，都应保留实际内容和相交影响。源码格式化、代码补全和自动修复不可以把不存在的决定写成用户已接受的含义。

编译器首先保持最清楚的原义。是否删除检查、融合循环、特化泛型或改变布局由已声明的保持条件决定。没有新的性能依据时，无需为了“极致”先建全局最优搜索器。

### 冻结的是决定，不是所有未来未知

已选基线包括中立作者身份、当前基本写法、类型与运行含义、源与产物的关系，及六工具的输入和结果合同。完整位置见[当前作者面实施基线](可替换表示与适用范围-语言定位与作者基线.md#当前作者面实施基线与决策状态)。这里的冻结是设计基线，不是实际执行授权，也不代表已发布稳定语言。

开始实现某个构造前，补齐它相交的语法消歧、作用域、类型/效果、求值、错误、库或目标映射与编辑反例。具体解析器消歧测试、运行行为和真实AI成本在实现后取得；不能要求先有这些结果才准实现，也不能把未写清的返回/错误留给实现者碰运气。有限层级状态已有独立库与解释设计，尚未实现的语义方法、流、微分和其他高层能力保留各自义务，不阻断有限构造。

同一个产品基线期间，新版本只增加合格定义和目标时可以不改作者写法；改变语法、缺省、数值、错误或公开名称是可观察变化，先修相交规范与迁移，再进入新解释绑定。只有出现实际矛盾、支持任务不可表达、无法保持所需行为或有依据的作者负担反例，才重开对应设计。没有新依据时继续实施和检查当前方案，不反复在JSON、TS元编程和中立文本之间全量重选。

### 作者意图、程序语义与生态完整性的范围

函数、类型、契约和高层声明可以直接表达开发者意图，不要求再写同义的意图文件。重复工作由库定义和编译器承担；独特算法仍可由作者自己定义。仅有要求而没有函数体是合法设计，若存在被选定且满足要求的实现关系，也可进入对应生成；只有必要行为既无定义又无合格绑定时才限制该根。

一个完整合同可允许多个目标实现，不要求生成前证明实现唯一。函数参数由目标运行时取得，也不要求编译期填写具体参数值。相反，未委派的稳定性、错误、隐私或外部作用区别不会因库名存在自动决定。完整过程见[意图完成](../../20-语义与组合/组合/跨软件需求合同.md#意图进入同一作者源的完成与缺省算法)。

有限作者语法、库调用、局部函数和目标控制沿既定入口解释。意图通过具体定义表达；自然语言创作不等于确定解析，其他领域也不必全部降低成函数后才能表达。对象模型、关系、完整时间/流及有限状态图以外的扩展仍按[当前当前未决义务](../../90-治理与参考/状态/README.md)记录所缺设计。生态覆盖是按使用点、解释和目标证明的范围，不是因有18个保留词、完整文法或一张语义目录而整体成立。

### 详细语言规格与每次开发输入分别承担责任

本章的文法和语义规则不因任务视图变短而改变。完整定义、标准库实现和目标规则可以较长，普通使用者通过调用、参数与局部任务视图复用它们；AI不必把本章或结构body全部放进一次上下文。实现器仍须确切解释源，而不是运行一个模型去补全未声明的语言含义。

已有成熟语言的解析、原生类型或目标编译结果应按实际版本复用；`.gift`自己的数值、作用域、契约和降低并不因宿主选择TS而自动已有正确实现。复用算法不同于取得可直接处理当前文法的软件。作者语言若为同等需求持续制造更多独立维护内容，应修改对应表达/库设计，不能仅靠隐藏源码宣称采用价值。

### 不同开发角色在同一作者体系中实际写什么

完整开发面不只支持调用预置库，还要支持创作新行为、复用、公开和扩展。下面规定输入责任，有限语法与领域体仍由各自原规范拥有；它不是新增关键字或暗中承诺所有高级构造已实现。

| 作者任务 | 实际维护的唯一内容 | 推导/复用及需要显式决定的边界 |
|---|---|---|
| 写新算法/纯计算 | 函数、表达式、局部绑定、控制/递归及实际要求；无成熟实现时主体真实写出 | 类型/效果/合法布局按现有合同推导；不要求先命名全局Block或手填CoreIR；不确定数值/终止要求不能猜 |
| 组合已有软件与库 | 真实import、调用/绑定、参数、实例与独特差额 | 已有普通函数可直接用；需要状态/生命周期/效果适配时写真实差额，不为每个轮子强造包装 |
| 定义对象与长期状态 | 真正身份、可变状态、构造/销毁、分派和合同 | 纯值不自动提升为对象，逻辑记录不因想要目标class而暗增共享状态；原对象能力边界保持 |
| 写规则、状态、关系、流、数值 | 对应已有语言或库的源/体、关键顺序/时间/数值/失败要求 | 通用控制面提供相同编辑/生成/检查链，具体领域含义不会被万能图或任意字符串替代；只展开当前用到的合同 |
| 封装公开库 | 源定义、公开出口、准确要求、实例/资源规则、示例与实际依赖 | 私有实现可替换，公共兼容需真实消费者和版本关系；推导不强迫全部签名手抄，需稳定公开接口时可显式固定 |
| 实现宿主/目标Adapter | 原生实现或合格中立方法、精确入口、输入/结果/效果/资源/错误及绑定 | 不隐藏一整个未知实现于Adapter名字；可复用成熟工具，调用/表示/版本差额仍要实现与验收 |
| 扩展语言/生成/查询方法 | 已允许的方法合同、语法/语义/降低/来源规则、能力/发行与验证范围 | 普通组合不需加核心分支；真正新增解释原语需协商及实际方法，不把源插件加载当被动配置读取 |
| 开发Gift自身 | 原十职责内作者文件、共同协议、真实消费者、资源与构建出口 | 可以从原生TS逐个有益纯模块自用中立源；不要求先自编译，不能因自用获得额外写权限或免除独立检查 |

模板、snippet和示例是节省重复输入的供给；插入后成为实际作者内容或保持明确的生成关系，不同时保留两份可编辑真源。注解、控制和要求仅在需要固定含义/约束或确实无法推导时出现；内部计数、身份、缓存与恢复字段由系统承担。显示推导结构可帮助理解，但日常写函数不因此必须学习全部工具协议。

当前完整开发验收应同时包含：没有预制应用函数的新算法；直接调用成熟库无需包一层；跨模块改义与消费者一起更新；原生区域维护；受管生成改动回源；资源/测试/文档/交付连续变化。少数短函数不能替整套开发能力作证，反过来高级方法未实现也不阻止有限语言当前正确用法。
