## 需求关系与作者补全不新增竞争表示

RequirementTerm是已绑定含义的分析形状；SignatureTypeView是类型就绪但调用效果未封存的分析视图；LoweringResult是某次转换的实际输出。三者拥有不同内容，不要求用户维护三份IR，也不能按“都是图”混合生命周期。计划里的对象关系引用真实定义，短源码仍是对应区域唯一作者位置。

一次变换得到相同类型或相同样例输出，仍须保持已接受输入域、错误、控制、状态、资源和所要求的进展。新增调用区域的检查依赖其真实声明和EffectSummarySet，不接受复制的checked标记。需要重建结果时可以丢弃派生视图，不能丢掉作者原文、独立要求、精确绑定或已承诺回源所需的补充。

父版本的可用语言写法不因引入高层关系而作废。参数或关系编辑、私有抽取和受管目标回源都应回到原短源；无相应源位置的推导类型仍不当作作者显式约束。真实新增注解或公开合同必须作为独立作者变化解释。

## 语义保持与任务满足是两条相接而不同的关系

一次转换先绑定源表示、解释版本、所选观察和输入假设，再说明目标表示与源的关系。这个关系可以证明编译器没有改义，却不能独自证明源本来满足独立用户要求。目标代码正确实现一个错误或过窄的候选，仍然没有完成原任务。

因此，每个转换结果继续保存来源与保持依据，并将任务/边界义务关联到真实目标对象。转换改变数据布局、设备位置、可变缓冲、错误通道或检查入口时，同步重新计算相交边界摘要和预算；数学值相同不意味着来源、调用资格和运行成本不变。分析不能跨已声明失效边继续复用。

中间表示可采用不同域的结构，统一的是要求与转换关系，不是把所有行为降成一个万能节点。领域接口可提供实际边界和保持条件；缺接口时使用更保守的局部路径或限定支持。借鉴[MLIR接口机制](https://mlir.llvm.org/docs/Interfaces/)只能说明这种解耦有实际载体，不能自动保证扩展诚实、模型等价或全局最优。

转换链含原生片段时，保留原语言观察与合同。选择中立值抽象、只承诺一部分观察，须从明确任务得到允许，不能为了证明更容易而偷偷删掉用户原有可见行为。

## 中间表示族与按输出阶段提升

### 表示名称不是阶段或持久化命令

`IR` 后缀只给具有独立语义不变量、明确生产者/消费者和跨阶段交换价值的正式表示合同；它**不表示必须落盘**。只为一次查询重排字段的值叫 View/Projection，只为一次选择得到的值叫 Result/Decision/Binding，只描述后续动作的值叫 Plan/Program。不得因为需要缓存、显示、分页或序列化，就把这些局部值升级成新的 IR。

同样禁止维护只有名字没有 canonical schema/owner 的第二别名：实现选择结果使用 `ImplementationBinding`，原生程序观察使用 `SourceProgramIR` 或准确来源事实，目标合法程序使用 `TargetProgramIR`；`SourceIR`、`TargetIR`、`BindingIR` 不再作为独立现行表示族。

IR 表达在某种语义与合法性条件下的信息。保留各专题的独有含义，但不把每个章节、DTO、计划和状态都实现成一套永久模型、独立数据库或全量拷贝。只有具有独立编辑权、外部交换、历史解释、恢复或高价值复用需求时，才在该边界持久化；否则引用或暂态值足够。

下表分类的是权威和计算角色，不把所有领域压成一个最低共同语言。元模型提供引用和接口，领域保留类型、时间、单位、概率、并发和效果语义。

| 表示族 | 权威/派生角色 | 何时需要 | 不应重复维护 |
|---|---|---|---|
| IntentIR、DesignCandidate | 候选解释或工程设计候选；接受后由相应 Definition/Requirement/Contract/Control 负责 | 请求要解释、改变或搜索工程含义 | 已采纳行为的第二份可变副本 |
| source snapshot / 原生作者源 | 原始字节或结构作者源按其真实 authority 保存；source observation 固定本次读取 basis | 存量输入、构建输入或现场取证 | 把派生 AST/IR 当成原源 writer，或从观察自动采纳业务意图 |
| SourceProgramIR | frontend 在准确 source snapshot、语言/配置/frontend revision 上派生的语言中立程序表示；保留 unknown/opaque 与 provenance | typecheck、impact、跨工具分析、目标降低等需要共享源程序事实时 | 第二作者源、直接回写原字节、把 observed program 自动提升为 L1 Definition |
| SemanticIR 与领域定义 | 已采纳含义的类型化工程语义投影，保留各 owner 角色 | 需要公共工程操作和跨表示关系 | 巨型所有字段必填的全工程对象 |
| Application/Behavior、类型/状态/效果视图 | 定义的投影或明确作者源，二者必须注明 | 当前生成、分析或作者入口实际消费 | 同一函数体在两处独立修改 |
| 实现需求、候选与ImplementationBinding | 需求可由作者给出；候选派生；选择绑定显式冻结 | 存在真实实现选择或原生绑定 | 无选择时仍运行全局求解 |
| TargetProgramIR | 后端合法程序投影 | 生成特定目标 | 所有目标同一语法与运行时 |
| MutationPlan、DeliveryProgram/EvolutionProgram | 当前输入和目标下的纯计划 | 所请求的变更/发布/迁移 | 真实权限、尝试状态和已完成结果 |
| VerificationPlan/保证计划 | Claim及政策到方法与动作的派生计划 | 请求对应保证或效果准入要求 | 第二份测试定义、第二套执行器 |
| Explain/Debug/Provenance | 已有模型、动作和来源的查询投影 | 人/AI需要理解和定位 | 手工维护同一因果链的第三份状态 |
| 支持、观测反馈与生命周期 | 定义、观察、声明各自保留身份 | 运行/兼容/退役场景实际存在 | 把“支持”折叠成生成阶段的通过标签 |

### 允许路线与保持条件

原生源 → 原生前端/目标工具链 → 原生制品是一条合法路线，不要求先恢复完整高层意图。一般程序 → 所需分析/绑定 → TargetProgramIR → 目标制品可跳过领域设计搜索。领域作者模型 → 领域检查/降低 → 一般或目标表示只在保持条件成立时进行。配置、数据或文档产物不为形式一致而装成程序函数。

每条转换记录源/目标表示、适用版本、前置语义、保持/近似/丢失条件、生产者、依赖与来源映射。表示可共享底层节点和索引；融合时仍保留必要诊断与边界。没有一种图上的“路径存在”能替代转换的语义正确性证据。

### 函数值、逻辑值与证明模型的接合

函数值在语义、行为及目标表示中保留实际定义/环境和契约入口；立即效果与函数体潜在效果分别表达。编译器可以合并内部存储，不能仅留下参数/返回类型，便让间接调用绕开前置、后置和错误合同。[高阶契约](../../20-语义与组合/基础语义/计算基础/文法类型与求值.md#高阶调用中的契约不能丢失)拥有具体规则，本章不增加另一种函数身份系统。

有限不可变值允许物理共享，但不因此允许中立基础值有循环或地址观察。验证模型的类型域、正常/错误结果、调用前提与目标实现各自保持源含义；模型使用String或Int的同名类型不构成映射证明。求解器不支持完整域时，选择合格编码或报告该方法范围不足，不能把公共语义缩到求解器刚好支持的集合。

类型检查、覆盖、泛型特化和源程序终止是不同计算问题。各结果记录已完成的实际范围；未结束的特化不被当作语义反证，未完成的模式分析也不被当成覆盖证明。

### 请求级闭合

请求投影统一见[流水线](../../30-实现解析/内核/输入与阶段总览-编译责任-阶段与目标.md#编译流水线与阶段边界)。每个输出和声明分别计算必要闭包；部分成功、目标不支持、缺证据和预算耗尽分别返回。普通生成不依赖联邦世界模型；候选预览不等于采纳；部署读回不是该次部署前置。

Binding 决定路线，不因多一种可选后端就使所有旧结果失效。若选择策略实际观察整个候选集，候选集本身才成为依赖。不能把所有备选路线的并集叫“最小闭包”。

### 权威与映射验收

每个被编辑区域必须能指出当前编辑源、上下文与精确版本；其他表示必须是投影、观察或显式候选。双向编辑是两个受控方向，不是两套并行权威；无法精确回写时在实际映射粒度拒绝或提出候选。

相同输入可用两条合法路线时，按声明的保持范围比较观察结果；不要求所有输出字节相同。发生歧义不能按加载次序任取。非法/部分表示不能被消费者当完整目标。未知区域可原生保留，但不能宣称跨语言重建成功。

### 删除与保留裁决

保留上表的语义区别和已有专门合同；取消“每一族都必须独立物化、顺次执行、单独对外开放”的解释。一个纯函数无需 Intent/Design/Mutation/Release 对象；一次真实迁移不能因追求短链删掉数据兼容、前像、结算与恢复。

新增IR必须具有实际的独立语义不变量或变换需求，并说明比现有表示的查询/共享结构更有益；仅多一个消费者或需要较短显示，不足以新增IR。只是字段换名、同义 DTO 或缓存布局时，优先建立已有类型的视图；确有新的语义时允许扩展核心，不以维持现有分类为目标。

## 跨中间表示不变量与合法降低

**保持判据。（消费条件）：** 源到目标的合法性是所要求观察上的精化，而非IR名字、节点数量或输出字节相似；未能证明的副作用重排必须保持原顺序或拒绝降低。 合同归属：[跨目标变换保留可观察轨迹，而非只比较返回值](../目标/具体降低与目标输出.md#gift-target-trace-refinement)。

### 多阶段的原因

一个万能 IR 会允许低层事实污染高层意义、允许未闭合状态进入后端，并迫使所有 pass 理解所有字段。多阶段 IR 通过合法信息边界控制演进。

### 核心不变量

| 从 | 到 | 必须保持 | 禁止引入 |
|---|---|---|---|
| IntentIR | SemanticIR | outcome、scope、constraints、unknown | 自动选择未确认偏好 |
| source snapshot / qualified source Observation | SourceProgramIR | exact bytes/content identity、language/config/frontend revision、coverage/provenance、unknown | 业务 authority；强制先物化 ObservationIR |
| SourceProgramIR / accepted source facts | SemanticIR | source binding、候选、unknown | AST 直接成为 Definition |
| SemanticIR | DesignCandidate | responsibilities、contracts、invariants、设计自由度及其准确修订基础 | 具体 Provider 可用性；把提案自动当已采纳语义 |
| DesignCandidate / accepted design facts | RealizationPlan + ImplementationBinding | requirements、hard constraints、rationale、**现行基础核验后**的实际采纳决定 | 将偏好当资格；用过期设计候选替换正式要求 |
| RealizationPlan / ImplementationBinding | TargetProgramIR | exact selected binding 和闭包 | 未决候选 |
| TargetProgramIR | MutationPlan | desired semantics、preservation、source map | live Grant/lease |
| TargetProgramIR / MutationPlan | VerificationPlan | claims、coverage、environment requirements | 执行 PASS |
| Verification/Evolution | DeliveryProgram | exact artifact、support obligations | 自动用户成功 |

### 禁止越权改义，允许有依据的编辑回源

低层缺项不能修改原要求来适配实现。用户提出的目标修改可以按[受管回源](编辑与受管回源.md#managed-edit-roundtrip)形成准确的作者或控制候选；这是有权改变来源，不是lowering私自修改上位真相。任何采用仍通过原提交边界，新的作者修订再向目标传播。

### 兼容与版本

IR schema 变化分为 additive compatible、validation tightening、semantic reinterpretation、split/merge/replacement。会改变旧含义时必须迁移，不能由新 reader 静默重解释。

### 验证

- 每个 target node 可追溯到 source or explicit generated decision；
- unknown 不能在 lowering 中消失；
- 无 consumer 字段不得进入稳定 schema；
- 旧有效输入在兼容升级后保持同义；
- clean 与 incremental lowering 等价；
- domain extension 不要求通用 pass 添加名称分支。

## 语言中立不等于无差异的万能执行IR

作者语义、原生观察与TargetProgramIR分别有解释身份。中立函数体和共同类型不能直接把ts.Node、TypeChecker类型、JS访问器或Java类加载行为当成普遍事实；原生区域保留原语言标签、边界与未知。共同层保存真实可组合的含义，领域和目标层保留差异，不要求先将所有语言压到最低公分母。

切换目标时保持作者候选与其中已确定的要求，重新生成ImplementationBinding、目标表示、源码与目标相关证据。规则、ABI或目标改变会失效相交产物；不能重新用目标行为解释同一作者文本，得到另一个业务结果后仍称同源保持。纯作者诊断与目标无关分析可以合格复用，目标检查不能跨目标自动晋级。

源文本、结构序列化和内存表示可以等价投影，但只能维护一份作者含义。多层IR不要求每层永久落盘或全部发给AI；按实际消费者融合、按需展开和回收。确定性不同于语义保持，所有目标打印同一字符串也不是多语言正确性证明。

## 一次转换的保存关系与失效清单

每次从一种表示产生另一种表示，先固定输入角色、输出角色和允许观察。源文本到模型保留声明与用户含义；模型到目标保留选定行为；模型到逻辑保留用于该证明的域与关系；目标布局不重新定义需求。输出可以比输入更具体，但具体化自由来自实际要求与授权选择，不来自转换器偏好。

转换合同记录三个映射：输入对象到输出对象的来源；输入允许行为与输出行为的保持关系；分析/位置/资格的失效范围。一个输入可有多个输出，一个输出可来自多个输入，不把来源表误当唯一逆向函数。允许保持的一部分范围要明确，未知原生区域保持其内容与边界，不能静默提升到公共语义。

正常处理顺序是：核对前提→选择已绑定规则→执行有界转换→核对输出的类型、引用与局部不变量→记录保持依据和未决条件→使受修改关系影响的分析失效→发布新表示。失败时保留输入和诊断；多个独立输出可以单独完成，共同不变量组不可拆出非法片段。

验证应包含正向可用性与反例：相同闭合函数的内联、单模块与工程子根输出保持所需行为；公开符号移动后消费者引用仍有效；去掉唯一效果来源后其旧分析消失；源中非法除零不因目标/SMT编码而变成合法值。持久合同中的frame条件要说明哪些原生区域和历史记录保持不变。

目前优先以明确转换规则和可复核轨迹实现；大范围一般等价证明不是每次普通生成的前置。需要加强某项保证时，引入对应分析/证明方法，其输入、假设和预算单独绑定。代码短、类型通过或两个图的名字相同，都不是该映射已成立的替代依据。

## 三种映射保证不能相互替代

从源能力到中立/专有扩展，再到目标，映射关系可以一对多或多对一，不按关键词数量判断覆盖。每条转换声明自己保持的任务观察、依赖、错误、效果、布局/ABI与来源；没有真实接合规则的扩展保留为未支持，不能因为字段可存放就宣称已理解。

行为等价用于生成合法目标；显式形态约束用于保持指定class、导出名或调用约定；具体文本与元数据保全用于既有工程往返。三者按任务叠加。Java类容器可以产生自中立函数集合，但Java对象初始化和动态分派不是只改文件名得到的。原生细节无公共映射时进入版本化专有语义，而不是降低到丢信息的公共交集。

全工程转换同样保留资产关系：模板生成源码、代码引用资源、配置决定构建、数据库迁移消费当前模式。转换必须说明产物是否可重建和作者所有权，不能把所有文件或所有中间状态写成同一种AST。完整规则见[能力映射](../../20-语义与组合/作者语义/README.md)及[资产管理](../../10-作者与输入/作者源/工程源/资产与非源码.md)。

## 完整源与AI任务投影的分离不增加IR

作者源用于决定与维护含义；编译IR用于某项实际分析/降低的不变量；AI任务投影用于本次理解和编辑。后者从已存在的源、绑定和检查结果读取，引用原源保留隐藏补充，不承担独立程序解释。压缩传输、显示更短、不同模型上下文预算，都不是新增编译IR的理由。

视图丢弃的作者字段不能靠逆向生成补回。编辑时使用原S、映射M与Δ，回到唯一作者拥有者；合法操作及帧条件由[任务投影](../../80-开发者与接口/AI协作/上下文取得与任务投影.md#任务投影的读取编辑和回写协议)和[结构编辑](../../20-语义与组合/组合/结构编辑/README.md)承担。摘要是可读解释，明确槽才可编辑，生成物不是第二份应当手修的源。

新领域确实需要张量形状、时间关系或目标控制流等独立语义时，仍可采用对应IR；它要有真正消费者、转换和回收条件。已有合格原生工具表示时优先通过窄适配读取，不把所有AST再编码成另一棵同义树。二进制压缩只省存储/传输，不使模型少理解信息；按任务省读与共享定义才消除对应重复。

## 类型化阶段值不是新的作者IR

ModuleRevision、HeaderIndex、BodyAnalysis和CheckedProgramView是原有程序内容的阶段视图；它们不分别保存可由开发者独立修改的函数体，也不因有一个消费者就各建持久schema。降低器使用区域化before/value保留求值，详细规则在[TS逐构造降低](../目标/具体降低与目标输出.md#用区域化前置语句保持求值顺序)。

标记为已检查的源不是对随后生成节点的永久担保。变换必须返回新增依赖、改变的类型/效果与映射，消费者补查或明确失效。源码位置只在其冻结文本和坐标单位内解释；源/目标map只支持实际精度，不授予任意逆向权限。跨进程值通过真实解码和版本验证进入，不能以类型断言伪造内部检查结果。

## 控制图、计算结构与执行计划不合并

源作用域/激活、有类型调用、编译查询依赖和目标运行调度分别有含义。中立对象可以承载数组、图、关系、状态和普通函数，但不为了统一先抹掉这些高层关系；同样不要求所有程序先编码成单一静态张量图。

当前采用多层适用表示：作者文本/CST或结构是原来源；已有语义区域保留值和执行关系；必要领域结构保留形状/索引/反馈；目标表示决定合法循环、缓冲和调用。只是用于解释/可视化的视图不成为新的作者源或IR。中间表示新增要有独立变换或分析消费者，不能仅因任务摘要换了样式新增一层。

动态尺寸和数据相关分支默认可以留到目标程序。只有实际可用的后端需要静态特化时，设置准确守卫、预算与一般实现；不能按一个样本路径推断所有路径已支持。基于运行追踪的工具若没有捕获作用或分支，需要明确保持边界；它不能自动解释任意Gift程序。

源到优化目标的映射可以多对多。某个源变量被内联/融合后，调试只能取得合格位置和值，缺失标为不可用，不从旧记录补齐。额外插桩形成派生产物；一份观察不升级为等价或性能证明。

## 保持回执的性质、观察与环境

`LoweringReceipt`中的保持引用不是一种全局“语义等价”标签。[性质保持与开放环境](../../30-实现解析/性质保持与开放环境.md#property-receipt-consumption)规定其真实消费者：单轨迹、非干扰、概率/联合分布、开放链接、时限和编辑连续性各用对应关系。现有`preservedInvariantRefs`与`proofOrEvidenceRefs`引用准确Claim、源/目标观察关系、假设及可复合依据；不另加一份作者镜像。

没有某强性质的依据，不能从类型、输入域和结果子集把它填进已保持集合；能够保持普通功能的结果仍可按真实用途取得。观察映射不能由供给者删掉要求中已存在的时间、日志或资源差别。性质及观察上下文改变属于分析、方法和资格的相交依赖；原图中的保持箭头只表示这项有条件的义务，不证明所有性质都已满足。

## IR 资格：正式中间表示、分析视图和一次性结果必须分开

`IR` 不是“结构化数据”的同义词。正式 IR 至少需要：独立语义不变量、明确生产者/消费者、跨阶段交换价值，及可说明的版本/失效/转换边界；是否持久化由真实复用、恢复、交换或历史解释需求决定，**不是 IR 身份本身的要求**。

因此：

- `SourceProgramIR`、`IntentIR`、`SemanticIR`、`TargetProgramIR`、`ObservationIR` 等只有在各自 owner 的不变量和消费者真实成立时作为正式表示合同；
- 正式 IR 可以拥有自己的 content identity、schema/revision、交换与失效边界，但**IR 身份不转移上游事实写权**：`SemanticIR` 由已采纳 Definition/Requirement/Contract/Control、限定源码事实与领域定义确定性物化；`TargetProgramIR` 由 L1/L2/target 输入降低；`ObservationIR` 由 L5 observation records/coverage 投影。任何 IR 的直接编辑都只能形成候选变化或受管回源请求，必须由相应 canonical owner 授权写入后再重建表示，不能以“修改 IR”绕过 owner；
- `MutationPlan`、`VerificationPlan`、`DeliveryProgram`、`EvolutionProgram` 等是从既有事实/表示派生的计划或程序；即使跨阶段传递，也不因此升级为新的 canonical IR；
- `DesignCandidate` 是可评估/可淘汰的工程设计候选；有权采纳后由 `Definition / Requirement / Contract / Control` 等 owner 写入正式事实，不建立额外的 design-IR 第二数据库；
- `RealizationPlan` 与 `ImplementationBinding` 承担实现解析的计划和稳定选择关系，不建立额外 implementation-IR umbrella；
- 查询重排、目录组合、候选摘要使用 `View/Projection`；
- 裁决使用 `Result/Decision/Verdict`；
- 动作准备使用 `Plan/Program`；
- `ImplementationBinding` 等既有稳定关系不为“看起来像中间产物”再加 `IR` 别名；
- 缓存、序列化、分页、AI context 或 UI 展示都不足以创建新 IR。

新增 IR 必须同时说明它比已有类型化 view/relation 更能表达哪项独立语义、谁消费、何时失效/回收，及为什么与现有表示合并会丢信息或制造错误依赖。否则降级为现有 owner 的派生值。

理论推理分类、不可达/不可判定边界、证据不足、资源预算耗尽、规范冲突、架构拒绝和假设分析本身也**不取得 IR 身份**。理论页只能定义推理维度；若某个消费者需要稳定持久形式，必须由该消费者所属的规范 owner 定义 `Result / Assessment / Record / Claim / Evidence` 等正式合同。

## 工程语义表示与可观察义务

### 目标

`SemanticIR` 表示跨语言、跨框架、跨实现仍稳定的工程意义，是**已采纳语义事实、限定源码事实与领域定义的确定性工程投影**。它有独立 schema/content identity 以供跨阶段交换和失效判断，但不取得这些上游事实的写权；直接修改 SemanticIR 只能形成候选变化或受管回源请求，必须由 Definition/Requirement/Contract/Control 等真实 owner 授权后再物化新 SemanticIR。

### 核心对象

```text
SemanticIR = {
  subjects,
  responsibilities,
  contracts,
  operations,
  dataModels,
  states,
  behaviors,
  effects,
  policies,
  invariants,
  qualityClaims,
  relations,
  knowledgeStates,
  provenance
}
```

### 责任

```ts
interface Responsibility {
  readonly identity: ResponsibilityRef;
  readonly purpose: StatementRef;
  readonly ownedState: readonly SubjectRef[];
  readonly operations: readonly OperationRef[];
  readonly providedContracts: readonly ContractRef[];
  readonly requiredContracts: readonly ContractRef[];
  readonly invariants: readonly ConstraintRef[];
  readonly allowedEffects: readonly EffectTypeRef[];
  readonly lifecycle: LifecycleRef;
}
```

责任不等于目录、类、包或服务。实现可以跨文件；一个文件也可能实现多个责任。

### 契约

契约只有在存在独立消费者、失败语义和演进责任时成立：

```text
SemanticContractShape = {
  identity,
  revision,
  inputs,
  outputs,
  failures,
  invariants,
  authorityBoundary,
  effects,
  compatibility,
  consumers
}
```

该结构是跨 owner 的**语义检查形状**，不是要求所有契约持久化为同一个 DTO；只有确有独立寻址、版本和交换消费者的边界才使用相应 `ContractDefinition`/typed envelope。内部 DTO 和普通函数参数不自动升级为公共契约。

### 行为与状态

行为由数据流、控制流、状态转换、错误流和效果声明构成。语言特有实现细节可以保留为 opaque realization，不进入跨语言行为核心。

状态模型必须区分：

- 领域状态；
- 执行状态；
- 验证状态；
- 生命周期状态；
- 界面投影状态。

不能把它们合并为一个 `status` 字段。

### 数据模型

语义数据模型表达：

- 实体身份；
- 值对象；
- 关系和基数；
- 不变量；
- 生命周期；
- 一致性边界；
- 隐私和保留分类；
- 查询和事件语义。

物理表、索引和序列化属于实现或目标 IR。

### 效果

```text
EffectKind =
  ReadSource
| WriteSource
| SpawnProcess
| NetworkCall
| ReadSecret
| WriteData
| PublishArtifact
| ChangeAuthority
| HumanNotification
| CustomDomainEffect
```

效果声明包括目标范围、幂等性、可读回性、可补偿性、所需授权和资源。设计阶段声明“需要什么效果”，不绑定实时句柄。

### 知识与冲突

每个重要语义对象保留：

- 定义来源；
- 源码观测；
- 推断候选；
- 有权采纳；
- 冲突和替代；
- 未知覆盖；
- 适用 revision。

`SemanticIR` 不是把所有输入强行融合为单一真值的数据库。

### 局部存储与公开效果不是同一投影

既有有序区域保存位置身份、读写、捕获、控制目标和清理关系；公开接口只投影调用者能观察的效果。一个私有计数器未逸出时，可以隐藏整个调用的内部状态效果，但不能抹去这个区域里两次闭包调用的写后读依赖。目标优化读取实际关系及对应保持资格，不读取一个“pure=true”代替全部条件。

内部的退出记录沿[控制与寿命](../../20-语义与组合/基础语义/对象与控制/控制流与存储寿命.md#控制出口与清理结果的确定合并)保存待完成结果、主错误、清理诊断及尚需结算的责任。scoped业务Result和函数Fault/Cancel在各自边界组合；这不是新的作者错误类型全集，也不是所有程序要带的永久日志。

结构展开、内联或重构改变捕获和调用者时，类型可能仍相同，但公开效果消解与noescape依据已失效；须重新分析相交区域。物理共享只读类型信息不改变这项语义；同内容闭包不自动共享运行位置。

## 状态模型到控制流的保持条件

[状态语义](../../20-语义与组合/基础语义/状态关系与流/层级状态与事件.md)在公共作者模型中保留层级、声明顺序、转移域、history、激活与回调身份。把它展开成目标分支/循环后，要保持输入标签、选择前态、退出/动作/进入次序及稳定提交；只比较终态名不够。

exit和entry之间配置可能暂时不满足稳定不变量，仍不能暴露为Stable。并行region逻辑上活跃，不表示动作可交换；不得按目标线程先后决定它们共享C的更新。纯动作产生的命令和真正I/O也保留阶段关系，不能把网络发送提到未完成宏步中。

结构体与文本构造可以形成相同ChartModel；原生SCXML保留事件匹配、脚本和失败语义时可能是另一画像。转换者要逐项说明公共域，不把本画像的回滚或强类型Done偷偷用于解释全部SCXML。

## 关系表示的重数、缺失与求值保持

关系IR保存有序的操作输入与回调出现，结果本身可为无序多重集；这两种顺序不混同。SQL NULL、Option.None、外连接无行、解码错误和未取得输入，只有明确映射才能互转。默认ValueOps的相等是原类型相等，不能由原生排序规则静默覆盖。

关系变换必须对任务接受域保持重数、结果、错误/非终止和读取权限。无外部效果不是下推许可；增量代数的相消项可能访问新完整查询不会访问的值，因此回调定义性是额外前提。不能把负权重抵消当成异常也能抵消。当前正确回退是对受影响节点按新输入重算，完整机制由[关系规范](../../20-语义与组合/基础语义/状态关系与流/关系查询与维护.md)拥有。

## 局部可变位置与结构化退出

同一目标程序表示中增加可变位置、读取/写入、循环目标和函数出口；它们的含义由[控制与寿命](../../20-语义与组合/基础语义/对象与控制/控制流与存储寿命.md)定义。位置身份不等于内容摘要；相同值的两个局部槽不能随意合并。闭包按值捕获let，按位置捕获var；可达闭包延长托管环境的寿命，不延长Borrow域或外部授权。

将位置转换成SSA时，在控制合流和循环回边保留需要的phi/块参数；逃逸位置不能只剩一次初始值。Normal、Return、Break、Continue、Fault和Cancel携带所属控制目标和越过的清理边界，不能统一变成普通Result数据。loop无界的目标运行不是编译图无限展开；无体、无正常后继和语义不明也不是同一种状态。

表达式重排、内联、尾调用和死代码消除都要保持已有出口与清理顺序。调用资源作用域产生的close及其失败由实际效果记录，不能因为主体纯或结果未用而删掉；GC可回收与外部资源Closed分别解释。

## 对象、流和导数不能只比较最终数值

对象保持关系包括引用身份、别名、初始化可见性、槽分派、错误和已发生字段更新；目标用class或结构不是单独的等价证明。[对象规范](../../20-语义与组合/基础语义/对象与控制/对象构造与分派.md)中的构造区域在Ready之前不可逸出。

流保持关系包括数据出现、顺序、信用、容量、时间域、进展性质、迟到与终止。窗口和队列不是无序Bag；失败或取消不能降低成End。[流规范](../../20-语义与组合/基础语义/状态关系与流/背压与事件时间.md)产生的严格frontier与估计watermark在IR中使用不同判别。

AD保持原值计算及所选导数量。前向、反向与检查点可以不同，但累加、分支激活、随机固定和残余寿命必须保持。[AD规范](../../20-语义与组合/基础语义/数值/自动微分与线性化.md)的PointDerivative、PathLinearization和替代梯度不能共用一个无标签成功值。

新增专用语义节点只在其支持范围参与分析；图册和任务摘要不是新IR，显示折叠不会删除真实字段、状态和资源。
