# 阶段求值与反射生成

本页补充[编译值服务](../../30-实现解析/内核/编译值服务.md)中的相交能力；原章节继续拥有其已采用的有限语义。**当前选择：保留编译器内部求值/查询；公共反射独立决策。** 查询类型和生成代码是编译器工作，不等于必须让用户运行任意语义元程序；需要时才稳定其权限、阶段及API。

## 三种阶段，不复制三套函数语义

函数具有 runtime、const-capable 或 compile-only 阶段合同；const-capable 仍可以运行时调用，compile-only 不产生运行时可调用入口。显式编译期调用、类型级计算与静态断言要求 compile-time 成功，失败不能偷偷落到运行时。Rust `const fn` 与 const context 的区别正说明这两种承诺不能混同。[依据](../../../research/sources/Rust与C++映射依据.md#research-r14)

同一个泛型函数能否在编译期调用，取决于实际选定 witness 的阶段与效果，而不是仅检查函数名字是否标了 const。阶段分支允许为编译期与运行时选择不同实现，但二者共同承诺的可观察结果必须相符；有意提供不同效果时，差异必须进入该函数合同。

编译期解释器仅消费已封存输入。时钟、随机、环境变量、文件、网络若确是输入，先由获准操作取得并形成可追踪输入；纯编译不能偷偷读取宿主。依赖缺失时准确失败，不采用“当前目录碰巧有这个文件”。

## 常量堆与冻结

编译期可有有界临时分配、容器、局部可变状态和析构；这些资源由编译任务隔离管理。逃逸到结果的只能是可验证的不可变值图或带 relocation 的目标静态数据。宿主指针、文件句柄、锁、未完成借用和执行器状态不能成为目标常量。

冻结图保留对象别名；两个内容相等但要求独立身份的节点不合并。循环不可变图需要目标 relocation 或明确句柄编码支持。目标不支持该形式时可以返回可选择的表示方案，但不能自动改变原生地址合同。

## 反射看到什么

反射对象分为类型、声明、成员、签名、常量、模块、模板／类型函数及可用的 typed body／expression view。所有引用绑定语义快照、访问上下文与实例化参数。反射后的字符串仅用于显示，不代替实体身份。

反射对象不是“随便可写的 compiler AST 指针”。可查询结构、类型、效果、布局要求、可访问成员及来源；对不透明 foreign 类型，只返回真实可得信息。读取未公开函数体、私有布局或敏感 annotation 需要其 own access contract；拿到 reflection token 不自动扩大权限。

C++26 的反射提案提供语义实体、splicing、成员查询等能力，但也有构造器／声明注入等具体限制；本设计不把提案泛称成“任意改写编译器的一切”。[依据](../../../research/sources/Rust与C++映射依据.md#research-c12)

## 生成和拼接

生成器接受有类型参数、查询已固定快照，输出带来源的声明／表达式结构。引用通过声明身份与 hygiene 绑定，不通过字符串拼名字。注入结果重新执行名称、kind、类型、效果、寿命、访问和目标适用性检查，不能因为生成器自称可信就免检。

生成按分阶段 DAG 工作：stage k 读取其输入快照，输出对后续 stage 可见的新节点。需要递归生成时必须显式声明推进规则；无限新增声明／反射自己新输出的环在预算或无进展诊断处停止，不发布半张语义图。

一次生成事务失败，旧快照仍有效；新快照、声明集合、来源映射与缓存依赖共同提交。并行生成只对互不冲突的输出 owner 开放；稳定生成顺序不依赖线程调度。`template for` 是这套 typed expansion 的作者入口，无需再维护第二种代码生成框架。

## 失效粒度

反射调用记录实际查询过的成员集合、属性及 body 范围。新增公开字段必须使消费“所有公开字段”的序列化器失效；改无关私有方法不必重编没有读取它的布局查询。读取“全部成员”本身是一条集合依赖，不能只记录当时已出现的字段而漏掉将来新增者。

## 再次修改与失效

元程序读取的成员集合、理论、源解释或目标数值输入改变时，重新展开受影响内容；原作者源和上一份完整生成结果仍保留，失败不能发布半图。

## 使用点与可检验出口

<a id="cpp-gap-a39"></a>
- **更广泛泛型 constexpr**：保留阶段和目标数值输入；先做真实所需操作，不默认开放无界元程序/整个编译期堆。 硬边界示例：需要通用库操作在目标语义下静态运行、类型检查一致，不能另写host脚本/复制算法；[具体比较与出口](../../../research/comparisons/Rust与C++能力比较.md#a39)。
<a id="cpp-gap-a40"></a>
- **语义静态反射**：编译器内部查询与用户开放反射分开；用例足够才稳定后者，C++26实现成熟度单列。 硬边界示例：需要无额外opt-in地检查未知类型语义，并把结果参与泛型实例化；[具体比较与出口](../../../research/comparisons/Rust与C++能力比较.md#a40)。
<a id="cpp-gap-a41"></a>

<a id="cpp-gap-a42"></a>
- **template for**：归入真正需要的静态展开；不与24/27/40再重复累计成多个底层控制缺口。 硬边界示例：无适配开放的反射/参数包迭代是公共API硬要求；[具体比较与出口](../../../research/comparisons/Rust与C++能力比较.md#a42)。

<a id="meta-allocation"></a>
## 编译期容器、目标事实与卫生生成

编译期临时容器与构建脚本不是等价的语义入口。能由既有 const 方法计算的小值直接使用；合格受控生成器可用临时容器建立结果，但其分配、销毁、循环、节点和输出大小进入该编译任务预算。过程结束只能输出可冻结的值/结构及已绑定引用，不能带出宿主地址、文件句柄或运行中资源。未知或超预算不改为运行时执行，除非原需求明确接受该独立方案。

目标字长、对齐、数值规则和可用能力作为固定输入，而非读取构建机器后假定同一。一个临时 vector 计算成功不证明任意分配器、所有泛型调用或永久分配都可常量求值。若利用外部构建步骤，取得其实际输入、工具内容、产物成员和来源；运行该步骤仍是获准作用，不藏在解析中。

结构生成保留词法绑定，而不只保存字符串名。替换、内联、宏展开和抽取须采用捕获规避的绑定映射；可使用已有符号身份/去布鲁因表示等合格实现，不规定新的全局身份表。例如替换 `λy.x` 中的自由 x 为 y，须得到与 `λz.y` 等义的结构，而非错误的 `λy.y`。未选择的分支依原阶段规则处理；生成中途失败不安装半成品定义，成员集合查询及否定查询都参与增量失效。

## 宏展开与引用卫生的受控能力画像

新增公开元编程能力时采用按阶段标记的编译输入：`MacroDefinition{moduleRevision,phase,syntaxParameterTypes,resultAstKind,scopeContract,dependencyPolicy,resourceBudget,sourceOwnership}`。最低可选形态为**纯、确定、类型检查前受约束的 AST 准引用转换**：`quote` 形成未绑定语法，`splice` 只嵌入允许种类的语法节点，`gensym` 分配不可与调用者名字碰撞的声明身份。用户可读的标识符拼写不能直接代表唯一解析身份；名字解析在展开后依定义点作用域与明确引入点规则执行。

算法：固定宏定义版本和调用点 CST/AuthorSource→检查输入种类及访问域→赋预算递归展开（深度、节点、计算资源、总输出字节）→记录每个生成节点的 `expansionOrigin{macroRevision,callSiteSpan,templateSpan,scopeMark}`→解析/类型/效果校验→降低。预算用尽或循环展开产生带调用点的 `EXPANSION_INCOMPLETE`，不能生成只含部分宏结果的完整 Target。相同 AST 字节但宏定义/阶段/解析环境变化，重新建立作用域与缓存依赖。

编译期执行任意宿主脚本**不是**纯宏的默认实现：若作者要求文件、网络、环境、时钟或外部工具访问，先按 execution/Provider 的能力与权限取得实际效果或显示未允许；运行后结果与输入环境进入不可变决策依据。动态插件的签名、分发信任和内存/时间隔离由各自应用场景承担。禁止让展开器在普通 `check` 中隐式执行安装/上传/命令。

非卫生的“故意捕获”只可显式使用带准确来源的捕获/重绑定声明，默认不得以字符串拼接绕过模块私有性。增量编辑要能从宏展开诊断返回调用处和定义处；若该映射不足以恢复生成节点对应作者内容，客户端只修改调用参数/宏定义，不把生成 AST 回写成第二份作者源。对照反例：调用点与定义点同名 `x`、嵌套展开、递归预算、跨模块私有引用、宏更新但调用字节未变。

## 元编程、反射和编译期执行的无环引导

编译期元程序是有阶段的正常计算与受限方法，不是任意宿主代码。输入为明确冻结的语法/类型/定义/内容引用，输出为被后续消费者重新检查的语法或候选定义；不能通过输出对象绕过类型、作用域、效果或授予权限。元程序所用的 Core/标准库能力必须能由运行它的前一编译阶段消费。

普通宏默认只读取输入结构，新增绑定采用卫生身份，保留展开来源；显式捕获必须指向有权可见的绑定。返回目标语言字符串不是已检查语义 IR，不能取得通用可移植性。语法宏、类型导出、反射遍历、代码生成和外部构建脚本需要不同能力；不能因为都发生在编译期就允许联网、文件搜索和加载动态库。

编译期需要外部工具或新数据时返回 Need，宿主按授权取得结果并将其固定到新输入；纯编译继续消费固定字节。时钟、随机、环境变量、绝对路径和目录顺序不允许作为隐形输入；确实影响结果时成为明确参数/方法前提。元执行预算覆盖递归、输出规模和工作量，超限产生可恢复诊断，不挂住工作台或把未生成部分当空。

Schema/解码器自生成遵守两层核验：源规则由旧阶段可理解的固定格式提供；生成解码器之后，独立消费者按公开合同验证其输入/输出与拒绝行为。不能用新规则生成唯一验证器，再凭该验证器通过宣布新规则无误。发布引导表有实际源坐标和再生方法，后继能独立重建后才取消过渡副本。

编译器反射可以读取获准的定义公开结构，并产生新的作者候选或目标制品，但不能改变其当前运行映像的解释规则。热加载形成新 Image；当前请求继续按原快照完成或被取消。所谓“自修改编译器”若要实际采用，需要经过原作者/制品采用 Gate，而不是一个反射调用就给自己写可执行目录。

<a id="design-b12"></a>
## 阶段计算与新语言能力的引导

静态求值只读取当前SourceSnapshot及显式锁定常量/语义供应；编译期插件要读外部资源时，必须通过capture阶段取得带来源的不可变输入，不直接访问网络/环境。随机化优化若允许，种子进入精确构建输入；它不能改变硬语义。生成声明记录生成器Definition、输入revision、展开位置与输出发生项。

阶段依赖必须有已存在消费者：旧编译器只认识B，新增X的生成器必须先以B写出认识X的bridge，构建并独立核验后才能将作者源码迁到X。由X生成的checker不能成为X含义唯一的依据；静态生成自己认可的证书不构成独立验证。

阶段计算出错保留原源与完整输入cut，输出候选不可发布半截声明；取消只停止尚未完成生成，不撤销已单独提交的源。清缓存重新执行必须给出相同语义输出或承认声明的非确定性；缓存键含生成器及依赖规则版本。budget从父请求分配，不因递归生成新任务重置。

**验证与反例**：读取未捕获时钟、通过插件导入执行I/O、生成器使用未支持X、输出checker自签、取消后半截声明进入current均拒绝。

**实际能力边界**：真实静态求值宿主与bridge构建未执行。
