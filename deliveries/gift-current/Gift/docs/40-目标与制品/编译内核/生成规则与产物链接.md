# 生成规则与产物链接

## 生成规则协议与多制品链接

### 职责与输入

本合同把已冻结且足以生成所选输出的作者模型转换成相关联的源码、模式、接口、依赖和验证义务；未正式采纳的候选也可生成预览。它不决定用户目标，不把候选模型自动采纳，不执行目标程序，也不签发部署权限。与模型存储之间的边界是不可变快照；与写回系统之间的边界是完整制品计划。所有入口继续使用同一模型含义，不要求文本 DSL。

编译输入包含所选输出根、实际模型对象及版本、目标能力画像、精确规则实现、由解析阶段确定的实现绑定（可以自动形成）、请求的保证范围。模型总头只作观察来源；只有真实被规则读取的内容进入规则输入。摘要证明字节身份，不证明调用者有权采纳模型。

### 规则描述符

`GenerationRuleDescriptor` 的责任是声明一个变换可以读取、产生和保证什么：

| 字段 | 含义与检查 |
|---|---|
| ruleIdentity / revision / producerDigest | 稳定规则身份、合同修订和实际执行内容；不能只靠人工版本标签 |
| inputContract | 类型、必需字段、引用、正负依赖、动态输入前沿 |
| applicability | 可执行检查：方言、语言、能力、资源和前置规则 |
| selectionPolicy | 多候选如何选择；没有合法选择时返回歧义，不用加载顺序 |
| outputContract | 制品角色、字节类型、目标路径规则、归属和组关系 |
| preservationContract | 保留哪些行为、数据、效果和错误语义，不把类型相同当等价 |
| executionClass | 纯变换或隔离计算；有进程/文件系统的规则不是偷偷纯化 |
| resourceEnvelope | 输入项、深度、输出字节、计算预算；达到预算返回前沿 |
| diagnostics | 稳定错误码、关联模型节点和可恢复条件 |
| evidenceObligations | 需独立证明的性质、预期测试环境和不能自证的范围 |

规则不自行加载任意 Python/JavaScript 代码。可信解释器、编译器包与工具执行属于选定 Provider 的能力和信任边界。第三方规则只因通过 Schema 不获得宿主进程权限。

### 从已绑定方法到实际目标贡献

本节细化既有`UseBinding → lowerBoundUse → LoweringResult → composeTarget`，不新建程序IR、作者清单或独立生成服务。SourceBody沿其已检查主体降低，ExternalExport贡献真实导入/调用，GenerationMethod调用实际装载的具体化实现；三者可以保留各自表示。相同工程事实、要求解释和目标选择只有原有拥有者，不能让TS与Rust后端再各建一套业务判定。

**绑定接纳。** 描述符必须解析到本次EngineImage里的真实方法及准确执行内容。方法适用性产生自己的强类型Binding；本地私有句柄绑定映像与快照；允许槽位复用时还须校验槽代或等价拒旧机制，不能由序列化报告直接构造。跨进程或持久化时只编码有版本的原Binding记录，并由对应方法重新检查要求发生位置、主体代换、采用分支、参数、目标、方法内容和前提。相同方法名或trait形状不是替代资格，未知修订不能按latest解释。选择、具体化和结果接纳消费同一绑定，禁止打印期间临时换实现。

**贡献的接收合同。** LoweringResult按既有字段关联准确使用点、绑定、目标及实际输入；内容为真实声明/区域或固定资产，附逻辑符号的定义与使用、公共出口、类型/运行/构建/资产依赖、初始化与资源关系、来源、编辑对应和残余义务。它是各方法的私有结果，不直接写共享文件或package/Cargo配置。固定模板是有身份和受限参数的真实实现；自由RawCode插值不能替代绑定或目标合法性。需要外部分析而未取得时返回Needs，不把一个工具请求当成已生成代码。

**接纳算法。** 先验证本次结果与绑定及输入同代、内容完整且未超过预算，再核对已声明的符号/成员和真实贡献。新中立主体重新进入名称、类型、效果和资源检查；目标片段进入相应目标检查/保持合同，原生opaque内部只按实际可得合同和证据评价，不伪造全源码分析。新调用、运行辅助、资源和未满足前提重新进入原工作表；影响早先选择时回到相交选择点。没有新增未处理贡献且根所需内容闭合，才可交目标组合器封存。

覆盖索引只检查每个硬义务有去向，不是证明。方法报告`handled`齐全或Done时，若缺真实导出、漏运行成员或保留必需残余，不能签发完整根；报告满足业务性质仍须有相应保持依据或独立保证评价。相反，真实程序可生成但某项一般性质尚未证明时，保留源码与保证缺口，不能混称没有实现；请求将该性质设为准入条件时才阻断相应交付资格。不得靠同一方法生成的测试期望或自填摘要自证。

**失败与发布。** 未完成builder不成为完整LoweringResult，也不泄漏进共享组合器或成功缓存；取消/超预算可以保留有身份的分析前沿，不返回截断源文件。已完成的独立贡献与其实际读集可保留。后端在打印时才发现helper、导入或初始化条件，必须回到贡献与相交检查形成后继结果，不在旧封存身份下追加文件。回收私有内存不是外部效果回滚；工具和真实写入的未知结算仍交原operation拥有者处理。

普通函数递归、领域固定点、静态需求展开和方法搜索分别使用原有停止合同。反复产生同一未消除义务时记录准确使用点/绑定与前沿，报告缺少降低进展或预算停止，不能把递归边一律拒绝，也不能无限重试直到某方法返回Done。

### 候选选择与链接顺序

1. 验证快照身份和输入作用域。
2. 推导所选输出所需的语义义务，保留缺失、冲突和不支持区别。
3. 只枚举明确目录中的规则；先按硬能力过滤，再按已采用策略选择。
4. 固定每个义务的规则、输入闭包及本次出口的资格范围；显式规则不能被后端悄悄替换。运行前提沿[分层资格](../../30-实现解析/实现选择/实现解析与候选资格.md#method-qualification-by-requested-exit)保留给真实消费者，不将缺内部实现改称环境前提。
5. 建立数据依赖和发布组关系。纯计算依赖必须可调度；源码的递归类型不能被错当任务循环。
6. 执行有界纯计算或消费隔离执行回执，按贡献接纳形成实际片段/字节；新依赖、效果和前提返回原工作表，不能沿用变换前的检查。
7. 解析制品引用、路径冲突、依赖版本和目标合法性；按真实消费根与配置拥有域形成组合闭包。
8. 生成制品集合、来源映射、缺失义务和保证需求；未决保留[原义务、消费根和恢复入口](诊断与追踪.md#need-provenance-and-resumption)，随后交给变更/发布 owner。

构建序列不自动决定业务副作用序列。一个 API 文件和数据库模式没有同一语义版本时，即使二者单独能编译，组合发布也必须阻断。

### 制品集合

```text
ArtifactSet
  sourceSnapshotRef
  targetProfileRef
  producerBindings
  artifacts[]
    logicalArtifactId
    relativeAddress
    role / mediaType / contentDigest / byteLength
    actionKey / ruleRef / inputSelectors
    ownership / executableDependencies
  publicationGroups[]
  retainedAuthoredRegions[]
  requiredUnbound[]
  assuranceObligations[]
  remainingDeploymentBindings[]
```

集合的每个成员及其消费根按[完整成员与组合](../目标/成员布局-变化回源与保证.md#完整成员部分根生成与旧输出对账)解释；字节可用性、源码完整、工具检查和现场采用分别判定。同一逻辑制品与物理路径分开。发布前由目标 Host 检查大小写、Unicode、保留名、父子路径、硬链接和符号链接；固定顶层文件示例不覆盖这些检查。任何两个当前 writer 的输出路径冲突均不得通过“最后写入者获胜”解决。

集合摘要绑定成员、内容和组关系。每个制品的动作键绑定其算法和实际输入；集合来源变化可以改变集合摘要，无需让无关制品动作键变化。该区别不意味着所有传播都必然局部：共享运行库修复与实际共同输入变化仍会扩大闭包。

### 正确复用与代价

起步实现可以采用“每规则输入切片 + 保守规则实现摘要”。只被文档规则读取的描述变化，不影响服务逻辑与数据模式的动作键；若描述参与命名或生成策略，则它也是相应规则输入。规则实现文件变化可以保守失效该规则，但这种文件级依赖不是理论最小闭包。

所选方法的实际输入继续包含其读取的候选集合/负依赖；新增相关供给可能改变歧义或选择，固定且合格的锁不因此自动升级。结果相同但读集变化时，先发布新依赖再判断值传播；条件依赖按原查询合同重验，不按排序后的旧读集盲目执行已失效分支。缓存准入另外检查生成器信任、输入证据、过期策略和当前安全要求。相同键只给出候选复用关系，不替代缓存内容读回，也不替代被撤销规则的风险裁决。更换临时输出目录、进程PID或网络请求ID不改变纯结果。

### 源码、生成、写回与部署的四个状态

`generated` 表示支持范围内的字节和引用已形成；`build-verified` 表示精确产物在所选工具链中构建通过；`workspace-applied` 表示真实写回已读回；`deployment-authorized` 表示部署所需授权、秘密、环境、验证和恢复均满足。

候选导出模式只允许写入拥有创建权的全新目录，拒绝覆盖已有目录。异常会留下 `.gift-incomplete`，消费者不得把它当完整工程。标记移除之前必须校验成员集与摘要。该导出不是存量工作区原子事务，不声称抗断电目录发布。生产发布继续使用受控内容库与元数据提交协议。

多文件源码能生成，不等于 API 已对外监听；OpenAPI 的安全字段是合同，不是认证实现。生成工程必须列明尚未绑定的认证、通知、部署与耐久性义务。

### 生成测试与独立验收

同一模型可以生成验证义务和夹具，但独立业务预期必须来自被接受的业务合同。规则生成的代码与规则生成的期望同时出错，是共同原因失效。改变生成器中的租户查询条件时，手写跨租户测试应失败；把状态修改与审计拆成两次事务时，进程中止测试应失败。

### 权衡与重新裁决

模板直接拼字符串较轻，但必须有受限输入、转义和目标合法性检查；一开始就生成通用 AST 可能增加实现成本。有限模板后端的字段和状态应来自受限语义，模板内容也要绑定具体 revision 和信任边界。扩展复杂表达式或多语言语法时，字符串模板若不能可靠保持结构，应替换为目标 AST，不扩大字符串自由度。

多制品一次全部重生便于建立 clean 基线；增量只在动作输入确切且能与 clean 差分时启用。共享抽象需有实际重复语义、独立边界或已接受扩展义务；两个示例调用同一运行库只证明可复用路径存在，不能单独证明抽象净收益。

### 验收与证据范围

必要测试包括：重复构建；无意义顺序重排；描述性变化；实际角色或状态变化；缺失义务；输出篡改；额外可执行文件；同路径覆盖；精确快照重建；生成程序脱离编译器；完整/部分/阻塞状态不混淆。

贡献接合的区分例还包括：只有描述符无方法实现；旧绑定由新映像消费；方法声称覆盖但漏导出/运行辅助；新资源使先前两个局部可行方法联合冲突；打印后追加未登记依赖；方法失败后共享配置残留该根出口；同字节但不同拥有者的成员误合并；相关候选集合增加但缓存未失效。正文给出验收关系，不声称这些测试已运行。

语义方法匹配须保留实际观察域。半开整数区间`[a,b)`与闭区间`[a,b]`即使字段类型相同也不是同一合同：单点是否为空、端点接触是否重叠均不同。闭区间到半开区间的`b+1`适配，必须先按原闭区间验证反向输入和错误索引，定宽值还须处理溢出；不能因方法名同为normalize而自动替换。该区分是供给适配反例，不改变各自合法业务定义。

历史机制验证及其边界见 [状态聚合生成纵向切片](../../90-治理与参考/维护/设计依据与资料边界.md)。它不证明任意领域模型可自动生成完整应用。

### 输出请求 /2 的分组语义

历史`gift.output-request/2`载荷的边界见旧输出投影。当前作者工具由操作规范定义，以下输出根责任不意味着必须照抄旧请求结构。outputRoots 是所选模型/目标范围内的逻辑输出根，不是任意宿主路径。每个根必须在冻结上下文中可解析；requiredClaimRefs 也须解析到合法声明，存在引用不等于声明通过。

请求中的 publicationGroups 只引用 outputRoots：每组非空、组内无重复、组间不重复归属；未显式分组的根默认为独立组。需要合组时调用者提交明确并集，不让重叠数组的顺序决定原子范围。实际产物链接后，若不同根的制品闭包共享必须共同发布的成员，编译器合并其具体发布闭包并给出见证；若超出授权或宿主原子能力，返回受影响义务，不能谎称原子。

结构 Schema 只约束形状；成员归属、根解析、目标能力、闭包共享和 Claim 适用性由后续语义层检查。/1→/2 增加显式版本并重新验证分组，不删除未知根来凑成功。不请求 publish 的编译仍可定义未来发布组，但不因此取得发布授权。
