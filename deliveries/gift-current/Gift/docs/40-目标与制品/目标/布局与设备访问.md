# 布局与设备访问

本页补充[成员布局与完整产物](成员布局-完整装配与布局.md)中的相交能力；原章节继续拥有其已采用的有限语义。**当前选择：保留目标约束，不扩成所有对象的自定义布局语言。** wire/MMIO/nativeABI分离正确；精确位/字节合同局部启用。修正“泛型对齐不能变”的错误。

## 三种布局对象

**逻辑布局**规定字段与对象身份；**wire layout**规定可交换字节及编码；**native ABI layout**规定某个编译器／平台实际可观察的大小、对齐、偏移、基类与传参布局。三者不得共用一个“packed=true”开关。

```text
LayoutRequirement {
  domain: logical | wire | native_abi,
  size?, alignment?, field_offsets?, bit_order?, byte_order?,
  padding_policy?, address_identity_requirements?, abi_profile?
}
```

问号表示仅在作者要求或协议需要时出现，不强迫每个普通结构填写这些信息。泛型布局表达式在具体实例上计算并验证；必须分别满足目标支持的对齐、尺寸上限、字段边界和对象有效性。

Rust 泛型结构的对齐可通过实际 T 字段或 `[T; 0]` 等载体随 T 改变；仍需检查零尺寸、其他字段、具体目标布局和更强对齐要求。[依据](../../../research/sources/Rust与C++映射依据.md#research-r07) 对无法直接用 Rust `repr` 表达的布局，可选定合格的字节存储＋访问器路线，但这会改变原生字段访问接口；要求真正目标原生布局且没有合法路线时返回缺项。

## 位域与非对齐访问

位域定义必须固定宽度、符号扩展、字节序、位编号、跨存储单元政策及保留位处理。输入超出值域选择检查错误、显式截断或协议指定行为，不以宿主隐式转换偶然决定。C++ 原生位域的具体 ABI 布局交给匹配工具链，不能当成通用协议格式。[依据](../../../research/sources/Rust与C++映射依据.md#research-c07)

非字节寻址成员、未对齐成员和打包位域返回 projection／proxy，而不是伪造普通 `&T`／`&mut T`。访问器负责未对齐 load/store、掩码、符号及生命周期。

共享存储的位域读改写并非天然原子。设备寄存器还可能有 write-one-to-clear、read-to-clear、只写等行为；不能为更新一个位域盲目“先读整字再写回”。这类字段的访问政策由硬件合同决定，必要时仅允许直接掩码写、专用寄存器或平台原语。

## `no_unique_address` 的真正边界

提供“允许共享地址／复用 padding”的布局许可，但不承诺每个目标都能获得更小尺寸。需要字段地址唯一性、原生 C++ ABI 或严格尺寸时分别提出要求。

复用尾部 padding 不等于任意重叠有效字段。不得让一个宽 `&mut T` 或整对象复制覆盖另一个活跃字段；不得把未初始化 padding 当作稳定比较、哈希、序列化输入。可选路线是有证明的精确存储访问，或由原生 ABI 供给拥有该布局；不能把两个重叠对象随意包装成普通安全 Rust 引用。[依据](../../../research/sources/Rust与C++映射依据.md#research-r07)[依据](../../../research/sources/Rust与C++映射依据.md#research-c08)

ZST 地址重合、两个子对象共用一个虚基、tail-padding 复用是三个不同机制，不能因“没有额外空间”混为一项。

## 把 volatile 变成受控访问属性

`VolatileView<T, AccessPolicy>` 将访问宽度、地址空间、只读／只写、操作次数及平台所需约束携带在视图类型中。读取／写入生成真实 volatile 操作；隐式转换不能把它变成普通引用后执行常规内存访问。

volatile 不承诺线程间原子性、设备完成或硬件内存排序。需要 compiler fence、CPU fence、设备屏障或 read-back 时分别采用真实平台操作。MMIO 地址有效性和实际设备访问权限独立于“有此语法”；地址错误不能返回零来伪装成功。

## 原始存储、union 与对象有效性

提供原始字节、tagged union 和受控活动成员操作。切换活动成员必须履行旧成员销毁／新成员初始化；C++ 兼容的 union 生命周期及 common-initial-sequence 等规则属于单独 profile，不以普通 enum 近似替代全部。

`transmute`／bit-cast 只在尺寸、表示有效性、对齐、生命周期及指针 provenance 条件允许时成立。读取无效 bool、伪造引用、从整数恢复任意拥有指针不能因为两边都是“系统语言”自动获准。

## 再次修改与失效

布局、访问宽度、设备寄存器规则或 ABI 改变时，重核所有相交生成访问与外部布局；旧存储不能仅换一个类型标记便重新解释。

## 张量形状、布局与设备生存期

张量实例定义rank/shape、元素类型、单位、索引基准、广播规则、stride/layout、设备/分片、拥有/借用和可变别名。shape是语义维度，stride是表示；两者不混。零维scalar、长度零维、负stride view和非连续layout必须明确支持或拒绝，不能碰到后端不方便便复制并隐藏成本。

广播以精确轴匹配规则检查，不能由相似维数猜测。索引/reshape/transpose说明是view还是copy；允许委派copy时将内存、同步与延迟纳入资源合同。跨CPU/GPU转移记录真实allocation、队列/stream和completion fence；host Future完成或取消不自动说明设备已停止使用buffer。

分布式张量绑定partition、halo/replica、归约顺序和通信一致性；浮点归约换序的误差/确定性按数值Profile。设备丢失或kernel失败后受污染buffer不可回池，需同步/重建并保持Unknown作用范围。checkpoint跨设备映像版本不能直接恢复旧指针。

**验证与反例**：空张量、负stride、别名in-place写、广播错轴、异步拷贝取消、设备丢失、不同归约顺序。

**实际能力边界**：真实设备驱动/ABI、内存布局和算子kernel资格未绑定。
