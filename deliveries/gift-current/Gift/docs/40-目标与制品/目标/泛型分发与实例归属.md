# 泛型分发与实例归属

本页补充[成员布局与完整产物](成员布局-完整装配与布局.md)中的相交能力；原章节继续拥有其已采用的有限语义。**当前选择：放在构建/分发层。** 实例复用、定义归属和真实导出边界有用；不要复制extern-template拼写或把缓存服务放进目标运行时。

显式 `instantiate` 选择具体参数集、目标及产物归属；`import_instantiation` 引用外部同一实例。生成 key 使用已有声明／语义修订、规范化参数、witness、相关目标画像与工具链输入，并保留[真实ModuleUse/名义域](../../10-作者与输入/作者源/工程源/工程准备视图与编译输入.md#module-use-binding-domain)中实际影响实例的投影，不新造另一套摘要或身份算法；相同拼写与实参不足以合并不同包实例。

重复请求同一实例时复用合格的已取得结果，或加入[仍可接纳的共享生产者](../递归并行与远程编译.md#shared-producer-generation)；Closing实例不复活，不以新代号偷开第二生产者。定义归属、导出符号、调用约定与布局必须一致；两个相同显示名、不同语义 key 的强定义是冲突。链接器是否合并 COMDAT 不能替代前面的语义一致性判断。

公开泛型有三种交付形态：可供下游 Gift 继续实例化的语义定义；有限预实例集合；目标原生可表达的泛型。选择需要在公共接口中明确，不能把有限实例集合伪称成对任意 T 的泛型库。

单态化、字典传递、类型擦除由不同 strategy 实现。只有行为、ABI、资源、对象身份和作者硬约束都允许时才能改变 strategy。超出代码体积预算时，返回具体爆炸路径及可行替代；不能未经同意把无分配静态派发改成每次堆分配的动态派发。

实例化任务须检测直接递归、参数持续增长、重复查询、生成循环，支持取消与可重用 checkpoint。确定性失败缓存须绑定完整前提；缺依赖的 Unknown 不应永远负缓存成“不支持”。工具链、公共布局、特化集合或 witness 变更只使相关闭包失效。

原生符号控制包括内部／公开链接、显式导出名、外部定义归属和 ABI 版本。对象／函数地址属于可观察语义时，不能仅凭内容相同做跨对象合并。编译期和链接期控制无需目标程序携带 Gift 控制服务。

## 再次修改与失效

定义、工具链、实例实参或导出集合改变时，重新核相交实例和产物成员；外部符号缺失不能被存在的类型元数据补成成功。

## 使用点与可检验出口

<a id="cpp-gap-a36"></a>
- **显式模板实例化**：交给构建/导出策略，不把编译组织变成运行时语言机制。 硬边界示例：库发布要求精确的实例提供者/符号/构建归属，或编译资源有测得瓶颈；[具体比较与出口](../../../research/comparisons/Rust与C++能力比较.md#a36)。
<a id="cpp-gap-a37"></a>
- **extern template**：明确有限实例、可继续实例化定义和原生泛型三类交付；按真实构建成本采用。 硬边界示例：必须直接保留原生泛型接口、外部实例所有权和稳定构建行为；[具体比较与出口](../../../research/comparisons/Rust与C++能力比较.md#a37)。
