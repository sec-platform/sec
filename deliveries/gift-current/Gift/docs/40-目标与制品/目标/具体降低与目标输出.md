# 具体降低与目标输出


### 目标不是一个解释JSON的空壳

Gift最终产品应是具备正常入口、类型、行为、错误、资源管理、依赖锁、配置和可维护结构的TypeScript/Rust等目标工程，而不是一个JSON运行解释器、空handler、TODO、固定示例脚本或未实现Adapter列表。对于当前未获得合格Method的功能，Target不能声称已完成；可输出准确限定的部分产物或明确不能构造完整产品。


### 可维护性和质量的实际含义

生成源码应遵循选定目标生态成熟惯例：函数/模块粒度服务真实依赖和业务边界，类型准确、错误显式、最少无用封装、重复逻辑可共享、没有因Gift内部临时IR名称而污染公开API；允许合理的数据结构、缓存、索引、异步与原生库组合，但每次优化必须保持需求指定的可观察行为与性能约束。纯粹减少生成文件数或缩短行数不等于可维护性。
<a id="product-activation-static-literal-target-closure"></a>

<a id="gift141-target-multiroot-namespace-and-dispatch"></a>

多根`ArtifactSet`须带明确RootId形成归属键：若多个根会生成同一物理文件、依赖包、进程入口、外部端点或运行存储位置，Target需先确定同文件合并可交换、原子修改协调或物理隔离的合格方案；不能靠输出顺序覆盖，也不能将已选根静默删去。两个根共用同一模板的静态代码可以Dedup；实例Context、Grant、Effect OperationID、可变状态/租约不能因代码相同而被Dedup。

`UiNode.actionRef`的目标意义只能生成**动作输入描述**，不应自行成为Effect调用。因果执行来自 `activationRoutes` 与Workflow/Method资格，重复同源同目标路由拒绝、合法多播先裁决；未知载荷映射/权限不可生成目标默认替代。


## 被激活业务路径与静态实参的目标保持合同

Target消费的必须是**已经锁定的有权产品发生点**，而不只是组件模板Definition与其所有成员引用列表。现行单一作者Schema中的`argumentBindings.value`静态字面值先获得名义类型、单位、集合/精度与ABI合同，才进入目标常量/配置或初始化贡献；因运行时环境不同而不能合法物化时返回Target Need，不把JSON float、`null`或字符串词法的变化静默当语义等价。

`activationRoutes`因果边至少保留实例、UI节点/事件流/API端点/状态事件/时钟来源、Workflow-use身份、上下文及动态输入映射/缺失资格。目标生成器对一个既定Source→Workflow触发关系只能选择一次合格实现路由；不能一边把`UiNode.actionRef`降成直接Effect调用，另一边把同一`activationRoutes`生成第二次Effect。真正重入、队列、认证、重放、触发次数、补偿和读回由已选Method和既有Target合同证明；仅生成事件监听器不满足业务请求。

生成产物应在精确 `ArtifactSet` 中保留启动/停止与实例寿命、组件输入输出、受保护数据/权限、故障处理、构建/依赖锁、状态迁移和SourceMap；一项强制业务行为没有能映射到可用目标实现的Methods时，严格返回 `NoQualifiedMethod`/`NeedsTarget`，不输出含空handler、panic/TODO实现而标记完成的假成品。多根共同资源须先合格联合再装配，目标Backend不能自行改用一个看起来更方便的库/Provider或推断外部Grant。


<a id="gift140-target-instance-coverage"></a>
**当前候选产品实例输入的目标资格**：Target接收的是已绑定的`(ProductRootOccurrence, ComponentInstanceOccurrence, TypedMemberOccurrence, PortSupply, DeploymentPlacement, QualifiedMethod)`，不是从`product:component`模板名直接生成一个进程。`nodes[].instance`必须对应同一选中产品里的真实实例，`replicas`需要Target容量、幂等、隔离和迁移合同；`externalRequirements`必须取得真实宿主供应/Grant，`publicEndpoints`必须生成且测试其命名公共边界。生成源码、真实依赖清单、配置、SourceMap、回滚/迁移目标均保持实例和修订归属；不允许空Stub覆盖未解释Meaning或未合格Method。正文其余原Target标准仍适用。详见[非计算源的具体作者语义](../../20-语义与组合/作者语义/开发者通用定义Profile-类型计算业务与系统构造.md#gift140-typed-product-closure)。


<a id="single-author-product-target-coverage"></a>
## 单一产品根的目标源码覆盖

目标装配以已经资格化的 `SelectedRootSet + JointObligation + QualifiedBinding` 为输入。对选择的`product:system`，目标必须覆盖其显式成员、全部组件所需业务接口、`requirements`硬约束、`workflowRefs`流程、`policyRefs`政策、`qualityRefs`质量及`deploymentRef`目标环境；未降低或缺真实消费者的边必须返回准确Needs，不得输出成功的Stub。旧 `/1` 仅通过保留来源身份的输入适配器参加联合，不生成并存的第二套作者根。生成源码、SourceMap与目标配置均为派生Artifact，作者JSON始终只保留一份写入权威。

<a id="gift135-noncompute-target-handoff"></a>

Gift135新增候选业务字面量、条件和组件绑定仅作为作者源进入Target之前的输入合同：Target必须收到所有选中根的已资格化Meaning、联合业务要求、Method绑定、公开端口连接和量纲条件，才可生成完整源码与传递依赖。Schema识别静态数量/参数不意味着它可直接发射库存算法、保存程序或真实系统；没有相应后端时为NeedsTargetCapability。不得把未降低的`conditionRef`丢掉，以空代码、默认`true`、单机锁或未实现stub冒充行为保持。


## 全开发者定义的合法降低与目标闭包

[类型化作者定义提案](../../20-语义与组合/作者语义/开发者通用定义Profile-类型计算业务与系统构造.md#developer-foundation-gift133)同时包含19种Type、17种Expr、查询/状态/协议/UI/资源等候选Kind。具体Target必须对**当前已选且实际需要的**每个构造完成合法降低或取得精确Method/外部组件绑定；未知构造、未解释业务Meaning、缺 ABI、假UI按钮、假数据库、无恢复效果和未实现Stub均阻止完整ArtifactSet资格。作者的原生TS/Rust源保持其原Owner，不靠复制函数体建立第二真源。项目范本在 [`Gift133`](../../../fixtures/developer-foundation/Gift133/README.md)。

<a id="gift131-root-target-assembly"></a>
## 完整目标的根覆盖不能由文件存在替代

Target消费者接收已由AuthorReader固定的`SelectedRootSet`、经真实解释器取得的`JointObligationSet`、当前环境有资格的`QualifiedRealizationPlan`及准确`TargetProfile`。公开`outputRoots`里的Goal/PatternUse/Requirement表示所选产品义务的来源，不暗示分别发射一个TS入口；真正需要发射的模块/公开API/数据持久化/配置/错误处理与依赖由已资格计划和Target共同确定。每个已接受硬义务必须拥有可追踪的承担者、保持证据或明确未决；未被支持的根Kind、缺失的Method、空Stub、必要Artifact缺失，均阻断`CompleteArtifactSet`。

**必须出具的可检查结果**：`rootCoverage`从每个作者选择和其真实Clause/Requirement发生位置关联到`JointObligation`，再到`QualifiedBinding`、生成成员、行为检查和SourceMap；`targetDependencyClosure`包括入口、静态/动态依赖、资源、ABI、有效配置、必要迁移和Target Toolchain锁。不能只拿构建成功覆盖尚未解释的义务；对完整代码生成任务，断开任何必要根链都必须报告`Unlowered/UnqualifiedRoot`，而不是删除根后重新计算一个看似100%的覆盖率。

**再次生成**：比较旧/新 `BoundRoot`与实际`SourceRevision/Meaning/Method/Target`读集。目标根或公开导出重绑即使显示名未变也重新核资格；根选择被删除并不取消旧真实外部Operation，也不允许生成器覆盖作者拥有的原生源码。以上为正式施工设计，非已运行的TS Target。

## 完整目标工程源码的确定性交付合同（TS首个Target）

输入不是一个未经解释的`intent:goal` JSON，而是**精确TargetProfile、BoundRoot集合、全部相交硬义务、合格实现计划、依赖锁、目标工具链/ABI和环境限制**。TargetOwner先构造独立`TargetProjectPlan`，其每个Artifact成员都须注明角色（受管生成、原生保留、配置、资产、迁移、构建、验证和部署入口）、输入来源、提供者、依赖和生成策略。**所有必要端口都必须被绑定**；根实现者、数据/协议、权限、存储、并发、错误、恢复与启动/关闭因适用场景不同可不存在，但不能因为没有写就认为“默认有”。

对TypeScript目标：先以有类型目标AST建立模块、函数、状态/协议接口和Method调用；按实际绑定选择合法TS库及原生SDK适配；再构造真实入口/导出、`package.json`、`tsconfig.json`、环境配置、数据Schema/迁移（如要求）、必要资源和SourceMap。实际目录/源码组织依TargetProfile固定，业务作者不需要在意图文件中手写这些TS AST。前向SourceMap必须定位作者条件、Method义务与产生的目标符号；反向投影的可修改范围受Owner约束，不得无条件覆盖用户原生代码。

只有所有必要操作完成合法Lowering，所有目标依赖可取得、许可证/ABI/版本满足、构建和声明的独立行为资格被真正执行并得到合格证据，才可签发对应范围的`TargetProducedAndChecked`。`Stub`、`TODO`、未实现接口、缺数据库事务语义、只有路由壳而无业务消费者，均属于完整性失败；若作者仅要求设计或源码草稿，则可返回**不具完整资格**的计划与诊断，但绝不能以成功ArtifactSet掩盖。一次`tsc`通过不能证明真实业务、外部效果、性能或可维护性最优。

次轮修改对每个受管文件执行三方比较（旧生成基线、当前磁盘、拟生成结果）；不相交编辑按已声明策略保留，相交差异拒绝直接覆写并要求采用/迁移。新增/移除公开导出、Method/环境变化或负依赖变化重新计算闭包并按准确ReadSet失效，不用全包一律重生成掩盖错误。

## 完整源码输出根的传递闭包、分级验收与拒绝条件（Gift122）

### 全体闭包的机器可检验含义

`ArtifactSet`的完整性相对于本次`EntryRoots`和选定Target判定：每个必需的公开能力，以及其传递依赖、初始化、错误、协议/ABI、状态迁移、观察、配置、资源与发布接口，均须有合法且可实现的目标表示。该判定从已资格的`QualifiedRealizationPlan`出发，不能由ZIP包含文件或单独通过`tsc`代替。

```text
assemble(plan, target, author_ownership, prior_managed_set):
  assert plan.issuer_scope intersects target and every selected requirement use
  enumerate each required implementation contribution + transitive dependencies
  resolve import/export and native/runtime interface with exact version/ABI/codec
  for every target operation, lower to target typed AST OR return NeedsTargetAdapter
  emit one owner for each path/region, SourceMap back to author decision/Method source
  include required data schema/migration/init/protocol/error/resource/runtime config
  refuse any reachable UnloweredOperation/UnboundImport/MissingMethod/Stub/Conflict
  produce complete candidate ArtifactSet; independently run actual selected toolchain
  issue only BUILD/BEHAVIOR/ASSURANCE claims whose real checker separately passed
```

生成结果必须能从每个生效的硬Root/Requirement追踪到其合格承担者及目标成员，授权、事务、失败恢复和观察等义务也属于该覆盖图。缺Method时不得生成看似正常的占位函数来补洞；静态闭包检查只支持结构资格，实际构建及行为资格仍由独立Toolchain/检查器取得证据。

目标产物分别签发四级资格：`PartialArtifact` 可供预览，允许未覆盖根及未降低操作；`StructurallyCompleteCandidate` 仅证明本次声明的入口、成员、依赖和绑定结构闭合；`BuildQualifiedArtifact` 另证明指定工具链和环境完成真实构建；`BehaviorQualifiedArtifact` 另需输入域、异常及进展的适用行为证据。现场效果与性能独立签 Claim。多个 Root 可以分别保存合格成果，但包含缺根的完整产品不得签 PASS。

首个完整源码Target复用TS AST/printer、TypeScript编译器、数据库迁移和有资格的SDK/框架；插件Method以明确合同进入装配。Rust Kernel负责Gift的语义与资格处理，不要求生成业务代码一律采用Rust。产物必须关联作者Revision、Method来源、文件Region及SourceSpan，才能定位构建错误并支持后续受管修改；缺来源映射不得执行可能覆盖用户代码的破坏性回写。

<a id="stable-target-full-assembly-contract"></a>
## 采用设计：合格计划→完整目标源码的全体合同（R08）

编译器只能从精确合格的 `RealizationPlan/UseBinding` 降低，不能从`meaningRef`名字猜业务功能。可复用现成库、规则/SQL/工作流引擎及受控专用生成器；**不要求普通作者改写成Gift111计算体**。Target自身实现选择与业务Meaning解耦，首个完整源代码目标为TS，Rust产品Kernel应承担类型化前端/联合资格，Rust目标是另一套独立目标合同而非TS的代签。

### Assembly输入/输出与完整性准入

<a id="complete-target-root-legality"></a>
**完整目标的真实判据**不是发射了多少文件，而是对声明交付根和目标环境建立**全体传递闭包**：每一个公开业务根、被选硬义务、已资格Method、依赖、错误/取消、许可及配置、状态/迁移、外部接口、SourceMap、构建入口都能在输出中找到满足其职责且版本相容的承担者。每条根义务只可记录为已被证实覆盖、显式交付后继验证义务、或 `uncovered`；第三种禁止取得完整源码资格。实际ABI、平台、模块解析与迁移条件不能靠同名Stub、空适配器或假Provider存在来证明。

下沉分为`analysis`（识别可合法化的构造及缺口）、`partial`（可保存中间结果并披露剩余非法/未降低项）和`complete`（每一个目标要求的操作均已合法化）。只有`complete`才能签目标完整性；形式上对应成熟编译器的partial/full legalization原则，但Gift还必须检查真实Method前提和软件项目的完整依赖，不因调用某个库就自动成立。Target后端不得自行重新挑选Method或解释领域Meaning；改变ABI或运行前提应退回原解析Owner重新资格化。

生成结果包含实际目标AST/源码成员、可重建依赖拓扑、工具链锁、版本/接口、环境变量名及秘密**引用**（不把秘密值打入包）、状态迁移与发布/恢复计划、受管区域写权、作者→义务→Method→SourceSpan的正反映射及未签发Claims。目标构建、运行、性能、效果分别由真实工具链、运行和保证Owner再签其范围；源码成功打印只证明成员生成，不能越级确认外部业务已完成。


```text
assemble_plan(
  sourceBasis, semanticSelection, jointObligations,
  qualifiedBindings, targetProfile, sourceOwnership, dependencyLocks,
  requestedDelivery='source'|'build'|'run'|'deploy', budget
) -> AssemblyResult { targetAstOrPrivateRepresentation, artifactMembers,
  buildGraph, dependencyManifest, configAndSecretRefs, publicApis,
  dataAndMigrationPlan, operationAdapters, sourceMap, obligationsCoverage,
  diagnostics, qualificationScope }
```

纯编译不得部署或写入真实业务数据；`run/deploy` 只形成后继计划，实际执行需在运行 Owner 获取 Grant。每项硬要求、禁止、时间/Norm、资源、错误和观察义务必须指向可核验承担者：生成源、真实依赖/配置、运行机制、受授权的外部 Operation、独立验收，或显式 `uncoveredObligation`。Stub、同名接口或未装配依赖不得充当已履行。完整覆盖必须包含所有被选 Root、目标成员/入口/依赖、有效 Method 以及其声明级别所必需的构建/行为证据；任何缺口拒绝对应完整 Claim。

| 责任闭包 | 编译器实际要求 | 错误处理 |
|---|---|---|
| 根/公开API | 每个公开业务能力、输入输出、错误、数据/事件/权限入口形成可调用类型化接口 | `UnloweredRoot`；不得丢根后声称完整 |
| 业务逻辑 | Clause/Requirement由真正Method规则、事务/工作流/原生算法实现；受管区域可二次生成 | 非合格Method不发假实现 |
| 运行适配 | Provider/数据库/消息/UI/时钟/观察通过TargetProfile的真实ABI、隔离与生命周期 | `UnsupportedTarget` / 缺前提 |
| 状态数据 | 表/实体/索引与迁移脚本、数据一致性及旧版本兼容按声明需要 | `NeedsDataMigration`，不能空Migration冒充可升级 |
| 依赖与配置 | 精确锁、工具链、许可、原生ABI、环境schema、SecretRef（不含秘密值） | 缺依赖/不匹配不宣称可构建 |
| 生成SourceMap | SourceRevision→义务→Method→文件/范围双向定位；作者/生成/原生写权分开 | 无法映射时不允许破坏性自动回写 |
| 目标正确性 | 语言类型/语法/调用顺序/错误/进展/资源/副作用保持及源独立Oracle | 单独typecheck只能签结构资格 |
| 工程交付 | 完整成员集、构建拓扑、可重复编译输入、启动和恢复边界 | `ArtifactSetIncomplete`明确未覆盖项 |

### 合法降低与无法降低的边界

**有意义的高层操作**须先经Type/Meaning/Method解释，才能进入原目标`lowerValue`或专用MethodLowerer。`permit`绝不打印成`return true`授予真实权限；`oblige`有有权工作流/监控/证据消费者才可降低，并保留期限/豁免/真实履行；`maintain/avoid`若需要所有并发变更点保证，则选择具同事务保护或可证明足够的执行/监控方法，不能只做API入口预检。外部真实Effect调用仅生成受控接口及OperationId/恢复逻辑，不在编译时执行。多线程、FFI、网络/DB读写必须把竞态/异常/撤权视为外部可观察行为。

正确性依据采用“目标合法/动态合法/非法”分档，类似成熟编译器的全/部分Dialect Lowering：分析模式可保留未实现Operation与全部Need，**完整模式**要求每个选定Root和目标公开约束均有合法实现及必要证据，不允许尚未降低的隐藏节点。目标AST/SourceMap只对当前Target和Module构建资格有效；不能从同一计划的另一语言成功推导当前Target正确。

### 不重新生成一个临时业务示范系统

Assembly 必须消费真实 `method-supply/target-profile` 与合格端口：解析依赖、装配受管差额代码、公开 API/运行入口及 SourceMap，并完成对应构建检查；不能按病床、GPU、订单等业务名硬编码模板。缺 Method 只返回附具体 Needs 的 DesignPlan。有限 SQLite 演示不构成通用性证据；增加一个从未见过的领域 Definition 时，若仍能按准确语义和供应接口装配，Kernel 才不应新增行业分派。

实际生成完整维护型TS/Rust源码及独立check需要完整TargetProgramPlan、按求值次序Lowering、ArtifactSet和二次修改；参见[Target与源码施工设计](../../70-工程系统与演进/工程构造手册/06-编译管线与目标源码.md)。规范映射及支持资格仍由本owner承担。

## 从组合到紧凑代码而不是运行解释器

高层组合可以降低成普通调用、融合循环、专门化函数或已有库调用；选择取决于已成立的保持条件和当前布局政策。已存在的高层抽象不要求在每次目标运行中解释JSON或回连Gift。

以先filter、后distinct为例：只有回调、输入读取与错误的观察合同允许，才融合为一个循环。原生getter/Proxy/迭代器或回调可能有作用时，先执行全部filter再执行key，与边过滤边取key并不等价；未知时保留原阶段顺序或限制优化，不暗标pure。分阶段求值不能在编译时执行用户业务来猜测结果。

私有临时Set与数组允许用于纯函数内部；其身份若只在结果数组上可观察，要保持输出的引用共享与变更合同。标准Set选取遵循目标的键等价；字符串场景用精确字符串键，不自动做NFC/大小写折叠。自定义相等需要相应哈希/比较或其他正确实现，不能机械换Set。

相同配置不是共享运行状态的许可。专门化可能增大代码与构建成本，默认保留未优化但正确的通用调用是合法退路；若没有合法目标表示，必须报告能力缺口，不能填空函数。运行时间、内存、产物体积与差异局部性分别评估，不以“源码最短”为唯一优化目标。

### 函数值根与短作者源的目标实现

合格静态函数别名、固定参数lambda与普通fn共用UseBinding和产物组合器。直接别名在目标和公开观察允许时重导出；需要新的公开函数名或调用适配时发出一份必要门面。lambda根据真实类型生成普通目标参数/结果，固定值可按合法规则内联或保留只读捕获；不得为了消除闭包提前执行其主体或重复原本一次的求值。

`transform = value => threshold.apply(value, {threshold: 500, delta: 20})`的目标保持一次apply调用、记录值和原契约入口。缺少给调用者用的返回类型注解是作者表面的省略，不是目标使用Any/undefined的许可。独立公开要求、配置和名义类型仍校验；不把省略视为取消原保证。

发射的完整形式是目标产物，不能反写成作者必须维护的expanded源。目标参数类型、捕获描述和导入别名的EditCorrespondence记录其真实约束/来源，不能把全部派生字段都称为可独立编辑的字面量。每份输出仍按原目标、布局、内容和检查分别绑定。

## 中立语义与目标表示的逐项映射

同一作者源产生不同目标的前提，是每个实际采用的构造有明确表示和保持条件，不只是printer接受同一节点名。TargetBinding固定目标语言/版本、模块/ABI、库与必要运行支持；原生输入保留其自身语义，不因加入中立工程自动规范化。

| 中立含义 | TS目标可选映射 | Java目标可选映射 | 必须保持/拒绝的条件 |
|---|---|---|---|
| 数学Int与向零商余 | bigint及合格辅助 | BigInteger及对应操作 | 不经过Number/double；优化为定宽须有值域与错误保持依据；所有工具包括求解器均按同一商余解释 |
| Bool与Unit | 严格boolean及内部单位表示 | boolean及无结果/单位对象 | 不使用truthiness；Unit可被存入复合值时不能简单抹去所需位置 |
| Unicode标量Text | 校验边界并按所选标量操作 | 校验代理对并按所选标量操作 | UTF-16 code unit不是公共字符索引；无效原生串按明确解码策略拒绝或在原生域保全，不静默替换 |
| 不可变记录、List与和类型 | 封装/冻结/复制或受检封闭构造 | 不可变表示与受检所有权 | readonly/final不是递归不可变证明；含共享可变别名或访问器的原生对象需转换或明确更弱合同 |
| 函数、闭包与递归 | 合法函数值与必要尾调用转换 | 接口/类/静态方法或循环转换 | 捕获和实例身份、调用顺序、错误与资源保持；不让目标栈深差异伪装成业务Result |
| 业务失败与合同结果 | 明确带标签值/目标错误映射 | 带标签对象/目标异常映射 | 业务Err、契约违例、资源终止和宿主故障分开；异常不得穿越不支持的ABI |
| 效果与资源端口 | 绑定目标函数/对象 | 绑定接口/方法/资源 | 参数形状匹配不证明权限、纯度、线程、生命周期与幂等 |

表中是映射选择，不是当前后端已存在。只要请求不涉及某种构造，就不为它加载运行支持或建立空模块；同一目标的多种合格布局也不要求全局唯一最优。精确值的库成本、转换和可观察异常纳入产物合同。Java定宽算术的溢出与精确检测有不同规则，[Java SE25 Math](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/Math.html)提供目标参照；不能用共同的Int名字掩盖选择。

### 原生边界的转换不是免费断言

不可信数据进入纯值区时，先按明确边界读取/解码，验证标签、字段、编码、范围和必要不可变性，再构造中立值或有期限的受信视图。读取getter或复制对象本身可能有作用，不能藏进纯preview。可证明上游已满足合同的内部调用可消除重复检查；公开原生入口仍需其所宣称的边界保证。

新数组不等于深复制；浅冻结不阻止嵌套对象变化；同一对象的不同视图不能因内容摘要相同而合并运行资源身份。输出给原生消费者时，也要明确调用方能否修改，及修改是否影响后续中立计算。不能一面重用可变对象，一面按纯值前提缓存和优化。

各目标的来源位置映射绑定其实际文本与编码单位；业务等价不表示字节相同。具体artifact身份与源候选、目标、布局和字节绑定，不能用同一candidate的另一个目标成绩签发当前输出。证明编码的保持条件见[契约到求解器](../../60-保证与证据/验收/方法与独立证据-独立性可信基础与求解.md#契约到求解器的语义保持)。

### 逻辑值不规定低效的物理表示

不可变List的递归匹配不是每次必须复制整个尾部。`[head, ..tail]`可以用有寿命保护的数组区间、链式共享尾部或其他合格表示；区间不能逃逸到已释放存储，浅只读标记也不能掩盖外部可变别名。朴素实现每步复制尾部，n项递归可能累计复制n(n−1)/2项；前端表达简短不证明目标复杂度合格。

默认先保留简单表示与正确性，再在需要的成本范围避免无收益复制：内部共享的有限不可变DAG可按节点记忆化转换；输出编码若要求展开为逻辑树，计量展开字节而非只计物理节点数。不得因为发现共享就把两个有独立运行身份的资源合并。循环原生图在基础有限值中拒绝，或使用单独的显式图类型；预算用尽时不输出截断但自称完整的值。

对尾递归，先计算是否还有后置检查、清理或其他续体；有责任未完成时采用保持该责任的循环/续体或明确资源限制。stack overflow、辅助分配失败和服务超时都不能改写成业务Err。精确的栈/内存上界只有在所选目标与负载条件下才能承诺，不把此规则当成所有程序总终止证明。

### 中立保证与原生可观察边界

跨目标保持针对已声明的输入域、结果、错误、作用轨迹及资源要求，不要求任意宿主反射都看不出编译器的内部选择。若中立函数不允许观察对象地址或构造器身份，TS导出的值却被任意代码用`===`、`new`、属性修改或反射操作，后端必须说明哪些是公共ABI，哪些不在保证域；不能同时承诺任意原生使用和完全透明的中立表示。

默认导出受检入口和最窄必要类型：值出入按实际所有权协议转换，受限资源句柄不暴露宿主凭证；公共函数表面、错误类别和初始化安排保持。原生资产原有的可观察行为继续按原生合同保全，不借“中立不观察”删除它。只在可信内部边界才消除冗余封装；对不可信同进程代码的完整隔离，需要真实宿主能力，普通包装不自称安全沙箱。

目标文件、辅助库和接口映射是产物依赖；函数值包装与检查策略进入实际绑定。不同目标不必字节相同，却都要满足同一被请求合同。

### 跨目标变换保留可观察轨迹，而非只比较返回值

生成器每个有风险转换应给出**源语义观察→目标观察**的具体保持义务：正常返回值、异常/错误类别、求值顺序与副作用次数、资源释放、并发可见性、边界ABI、数值溢出/舍入、时间及保密性都由本次要求选择，不能只验证类型检查或单个函数输出相等。目标实现可优化内部步骤，但外部可观察事件的偏序、必需进展和失败行为必须满足所宣称的精化关系；对于本来允许非确定性的源，不能为了展示确定性而把错误的行为也排除或加入。

例如把 `f()+g()`转换成两条并行调用：若二者有相交Effect、可能抛错或读取共享状态，即使纯算例的最终整数一样也不证明转换有效。只有从效果分析和冲突关系取得互不干扰的依据，或明确采用新的作者合同，才可并行。高层整数转Rust/C++固定宽类型时，溢出、算术转换和目标ABI必须按真实TargetProfile及语义合同处理。合格结果返回所验证的转换范围、假设、目标配置和无法保持的构造；不能用`unsafe`、包装器或模拟器的存在自动签发全部证明。


**跨语言结果不仅是相等返回值。** 降低器需要保持在公共语义可观察范围内的求值顺序、短路、异常优先级、资源取得与释放、可能外部作用次序和取消结果；同样得到 `true` 但多执行了一次支付、读取了不应披露的数据或提前移动资源，均不是合法精化。TypeScript 数值与字符串的宿主约定、Rust 整数溢出/所有权和 C ABI 调用约束只在目标边界生效，不能倒写成中立语言的全域类型定义。

**现有代码共存与可维护回写。** 作者源码、生成成员与人工原生成代码分别拥有写权。生成器能重新生成的区域要保留稳定来源映射、派生依赖与内容身份；人工编辑过的区域不得被“目标优化”无条件覆盖，也不能自动把生成代码解析回作者语义作为新的第二真源。二次修改只更新真正失效的目标成员，仍要在受影响 ABI、初始化、注册、迁移和原生调用边界上维持共同可观察合同。

## Rust目标的完整降低边界

Rust 已进入当前通用目标计划，但不复制本篇 TypeScript factory/printer 细节。[Rust目标画像与降低](Rust目标画像与降低.md)完整定义精确 toolchain/target 绑定、crate 形态、类型与所有权、泛型、错误与异步、Cargo/依赖、诊断与 SourceMap、FFI/原子/no_std、产物、回源、缓存和失败分类。COMP5—COMP7 与本篇共同 TargetBinding/LoweringResult/ArtifactSet 不变；不同后端不要求产生同形源码。

TS 先行只决定实现顺序。Rust 的 target profile 已有设计并不表示 rustc/Cargo adapter、生成器、构建、ABI 或运行符合性已取得；反之也不得再把 Rust 记成“第二目标未指定”。原生 Rust 作者源仍由其 own source/前端保持，能够直接复用时不生成同义副本。

## 首个TypeScript后端的逐构造降低

**目标输出不是解释JSON的薄封装。** 对每一个被选根，Target 需要从已解释类型、计算/查询/Workflow/State/Component/接口的合格Method绑定产生普通源码、真实入口、公开类型、模块布局、错误与取消传播、权限/资源调用边以及必要的声明/配置/构建依赖。纯计算可产生正常 TypeScript 函数；交互与Effect可引用已经获得资格的宿主方法，不能伪造一个总会返回成功的存根；原生源码应作为明确拥有写权的受管输入保留，而不是重新复制生成一份“更像Gift”的影子。

求值次序、短路、整数溢出/舍入、字符串索引单位、可空/缺失、异常、异步和所有权是可观察语义，不允许因 TS/Rust 的宿主默认不同而静默改变。一个实现不足以精确表达时，Target 必须显式引入合格辅助库/包装层，或留下 `NeedsTargetLowering`；不能通过 `any`、未检查的非空断言或空捕获分支掩盖差异。多根输出允许共享代码生成单元，但产物及源码映射仍保留各根和出现点的可追溯归属。


### TypeScript 目标的具体责任

- 源码组织为可读的ES模块/包，定义、接口、导出/导入及依赖清晰，生成代码的类型准确映射到TS类型；存在重要运行时边界时需实际解码与错误处理，而不是只靠静态类型声称外部JSON正确。
- `WorkflowStep`应按有向控制图和具体Method生成可追踪的调用/结果/异常逻辑；多操作Port必须调用被选择的操作，实参与结果保持Type/Role名，不因数组位置改变映射。
- 事件、流与重试委托合格引擎或Target提供的真实调度实现；异步并发、外部作用和Cancellation应保持实际合同；不能把`await`本身当持久事务、幂等或实时截止的保证。
- UI须由已支持的Renderer/框架Method生成真实组件、数据读写、动作派发和用户反馈；API声明若公开必须有路由、验证、权限、错误响应和实际提供者。
- 配置与秘密分离；被生成与人工所有的文件区域区分；格式化、依赖和模块装配遵从本目标画像并对后续修改保持稳定。

这不指定必须使用React/Vue/Express等固定栈；具体框架属Method与TargetProfile选择，某业务或宿主需求可能需要其他方案。目标编译器不能自行将无资格的框架选择写成唯一实现。

### 普通 TS 工程降低中容易遗失的语义

TypeScript 目标必须生成正常可理解的模块、导出、依赖、构建配置、类型签名、函数体和真实应用入口，不得只输出 JSON 运行器或为缺失 Method 留一个被当成成功的空 Stub。具体降低保持运算顺序与副作用路径：当一个表达式作为被调用参数且需要先求值、可能抛错或资源释放时，按指定源语义引入局部中间语句，而不是依赖对象属性枚举或任意 JS 求值折叠顺序。命名实参按形参名绑定后才映射目标顺序；重复/缺少的必需实参与可选省略不能统一成 `undefined`。

精确整数不得默认转为 JS `number`；必要时使用 `bigint`/有条件的方法或显式拒绝。业务缺失、`null`、`undefined`、JSON 可序列化性、Unicode 索引、浮点舍入、日期和排序规则应有清晰目标映射；`Promise` 的 reject 与业务 Result 错误不自动等价，取消信号不证明远端 Effect 已取消。异常传播、资源 `finally` 清理、可调用闭包捕获和对象身份也必须保持，生成器不能先把用户代码对象复制再“保持引用”标签。

来源映射应精确到一次 Definition/Use/Instance 和被降低的表达式，支持诊断和二次修改；生成多个 Target 文件时保留因果成员清单而不是在每个文件重复生成一个统一状态仓库。临时构建文件与受管源码分开，构建成功不意味着源码已获作者接受。


本节实现既有 COMP5—COMP7 和 LAY1—LAY7，不增加作者语言。目标语法、编译器自身实现语言和可选检查器分别绑定。对独立Rust内核发行，默认由有限Rust目标构造器/发射器生成所声明子集的TypeScript实现源码，不以Bun/Node或完整原生TypeScript前端作为纯源码生成的必装前置。

已绑定的TypeScript 6.x API族factory/printer继续作为可选目标Provider使用；其他API族独立适配，版本、标准库与Host按实际绑定取得，不混用私有编译器类型。选择哪条物理路线由ImplementationBinding固定，不因失败或缓存未命中临时切换。已有JS实现加.d.ts声明画像继续有效，但不是包含实际函数体的.ts源码画像；目标运行及实际检查仍需其真实宿主和工具。

### 输入、表示与输出

输入是该根有效的`CheckedProgramView`、已选实现、目标合同和布局基础。输出为有界目标结构或该实现的私有语法节点、实际运行/类型导入、公开导出、源来源与完整文件成员；打印不写磁盘。使用者没有指定目标库时由既有绑定算法决定，不让作者逐个填写helper与ABI转换。

第一条标量目标路径固定：`Int → bigint`、`Bool → boolean`、`Text → string`并保留合法Unicode标量边界、`Unit → undefined`。Unit存进记录、列表或函数返回时保留该值；只有确实不观察返回值的位置才可以省去显式`return undefined`。字段存在性用独立的成员检查，不把缺字段、显式undefined和Option.None混为一项。Option/Result与其他和类型使用带稳定变体标签的判别联合；标签来自类型合同与布局，不由线程完成先后分配。

记录用目标对象承载；内部访问对已建立的中立纯值进行。数据字段与可执行标识符分别编码；`__proto__`、`constructor`和目标保留词不能触发原型写入或被当成隐含方法。选用计算属性、无原型记录或等价受检构造时固定其公开ABI；目标`readonly`不代签递归不可变，原生getter/Proxy的读取与复制不得偷偷进入纯值区。基础相等按类型编译：整数/布尔/合法文本采用对应值比较，记录逐声明字段，列表按长度和元素逐项比较，和类型先比实际变体。函数、资源和opaque表示不凭目标`===`获得新相等关系。需要显式相等实现时使用已有合格绑定。

列表公开ABI采用目标合同规定的只读数组；内部递归匹配允许用`{data,start,length}`切片视图承担尾部，避免每次复制。视图只读借用已固定的数组，在内部调用与闭包里保留拥有者；向要求数组的外部边界输出时才按合同物化。若当前后端还未实现视图传递或合法循环降低，就明确采用有成本说明的数组基线；任务要求的复杂度/内存不能满足时报告该策略不合格，不假称已具备优化。这个内部布局能力不成为标量函数的前置。

公开中立函数默认有受检入口，私有核心体只可在其前提已满足的内部路径调用。函数值保存受检入口，而不是把裸核心函数传给高阶消费者。已有ABI适配负责不可信值的检查与所有权；不是每个可信内部调用都深复制或做全量输入检查。

### 独立发射与可选Provider的共同边界

两条路线消费相同CheckedProgramView、已冻结UseBinding、目标合同与布局，不能各自推导业务含义。共享输出根/引用闭包、调用契约入口和来源；后端自己的语法、错误表示与Host适配仍属于实际实现。

有限Rust发射器只接受已检查构造和窄目标值，负责优先级、结合性、括号、语句边界、标识符/字面量转义、类型与运行导入及实际字节预算。不以任意RawCode字符串替代名称绑定；固定受信模板另有方法身份、参数和转义合同。当前不支持的语法/目标构造返回准确能力缺项，不伪造undefined主体。

可选Provider边界批量发送已有目标决定，返回字节、实际工具输入、诊断与可提供精度的映射；不传可变Rust对象图，不按节点逐个RPC，也不让Provider重新选实现。原生API版本变化只影响其adapter与相交绑定，目标源码语言版本不随工具升级自动改变。TS6的createProgram/factory/printer方式不能直接当成其他API族的能力证明。

无外部检查也可以交付合法范围的generated-unchecked源码；要求build/check时另取得真实工具结果。若有限发射器不能以可接受成本满足复杂语法、映射或维护要求，可在同一合同下改绑合格Provider；该替换不取消独立生成、错误和产物身份边界。

### 用区域化前置语句保持求值顺序

### TS 目标的求值顺序保持、成员闭包和源码区域归属

Target 的每个已选 Root 需要传递地覆盖实际成员、操作、数据模型、公开 ABI、初始化/退出、错误分支、依赖、配置、必要迁移和资产；这不是“能生成一个入口文件”即可完成。TypeScript Lowering 需要用具名或临时变量表达源语义的求值次序，尤其条件分支内的副作用、optional chaining、具名实参的求值、返回值与清理资源，不得因为把表达式写成一行就改变求值次数。生成 `package.json`、`tsconfig.json`、模块导出和真实 SDK 接合属于 Target 工程构造，并非要求开发者在业务 JSON 中手工声明目标 AST。

每个生成文件或受管片段拥有确定的来源、工具版本、内容身份和更新策略；原生作者文件与手写修改区不能被生成器无条件覆盖。第二次生成需比较上轮受管基线、当前磁盘和拟输出：互不重叠变化可在明确定义的规则下组合，相交修改需由作者处理，不能按“以新生成覆盖全部”将后续开发者工作抹掉。SourceMap 要能从目标符号定位到实际发生点而非只映射整文件；未获资格的业务 Method 不能以 TODO、空服务或抛出未实现异常的 Stub 冒充完整产品。


采用`lowerValue(expr, scope) → {before, value, type, flow}`：`before`是该表达式**在当前激活区域中**需要执行的目标语句，`value`是之后取值的表达式；`flow`记录是否存在正常后继。另有`lowerTail(expr)`将函数或分支末尾直接生成为return/throw/分支，避免为所有表达式生成IIFE。

关键辅助`sequenceValues`按照源码出现顺序处理各孩子：若没有前置语句、无需重排且每值只用一次，可直接组成保持原顺序的目标表达式。只要后续孩子的`before`会跨过前一个尚未执行的value，或最后要按参数槽重排/复用，就先把前值求到局部临时量，再运行后续前置。临时量名称由固定源身份与布局分配，不用全局自增完成时序命名。

例如，不能把`left = f()`留在最后表达式里，却先执行右侧产生的前置语句`g()`。必须保持f先于g；“二者都没写磁盘”也不允许改变陷阱或终止顺序。

| 表达式 | 具体降低 |
|---|---|
| literal/reference | 构造目标字面量或固定符号引用。引用let值不重放初始化；函数引用使用已选调用入口 |
| 普通一元/二元 | 用sequenceValues固定必要求值顺序，再应用该类型的目标操作或helper。未使用值也先保留其计算 |
| `&& / \|\|` | 右侧value和before放在条件激活区；右侧有前置时生成真实if，不把它提升成共同前置 |
| `if` | 条件先计算一次；两分支无语句时用条件表达式，否则生成分支内赋值或尾位置直接return。不能先构造并执行两边的前置 |
| `let / region` | 初始化按作者次序生成局部声明，绑定映射更新后再降低后继。相同文本出现不自动共享；未用且可能陷阱/不终止的初始化保留 |
| call | 先取得被调用值，再按原实参顺序求值，最后按已检查的formalSlot排列临时量进行一次调用。普通中立函数字段取出的值不靠JS receiver隐式传this；原生方法走自己的receiver合同 |
| lambda | 生成目标函数值；其body的所有before留在函数体。捕获当前词法绑定，不在创建时执行未来主体，不把调用方的result或局部跨范围保存 |
| record/list | 字段/元素与尾的前置和value按原数组次序计算。目标字段排序仅对无行为作用的元数据适用，不重排初始化 |
| match | subject只计算一次；按作者顺序生成模式判定及命中分支；嵌套模式逐层检查标签/长度，匹配成功后绑定字段。证明覆盖不够时保持源未合格或要求明确兜底，不生成默认零值 |
| hole/错误节点 | 不生成本根可执行产物；保留源草稿和诊断，不能转成undefined或unchecked cast |

`lowerTail`需要同时查看函数后置条件和清理续体。尚有ensure或资源释放时，不能将末尾调用当作无条件尾调用优化；先保存正常结果，按顺序执行后置，再返回。函数失败没有正常result，不执行只适用于正常返回的后置。诊断、业务Err、计算错误和外部失败仍分开。

### 三个必须直接覆盖的目标反例

**整数一元加。** 中立`+x`对Int表示求值后的同一整数；JavaScript一元`+`调用ToNumber，不是BigInt恒等。因此对`export fn positive(x: Int) -> Int = +x;`，TS体应保留x的一次求值并返回x，不能生成`+x`。这是一项Gift映射义务，无需重跑整个JavaScript编译器测试。

**负整数字面量。** 负号与绝对值字面量用目标prefix-unary节点表示；不要把`-20n`强塞成只接受非负字面量的builder内容。零统一为语义零，源原拼写另由CST保全。所有数值均从规范十进制或已有bigint精确构造，不经Number。

**除零与条件。** BigInt除法的截断商与Gift当前整数选择一致；除零的目标异常类别仍按已接受的错误接口映射。若目标原生RangeError足以满足该有限ABI，直接使用它；需要中立错误标签时生成绑定的边界或小helper。未知异常不能一律改成除零。`if x==0 then 0 else 10/x`的除法只能存在于else激活区。

ECMAScript明确一元加走Number转换，而BigInt除法有自己的截断与除零规则；这些事实支持上述局部映射，不认证全部后端。[一元加](https://tc39.es/ecma262/multipage/ecmascript-language-expressions.html#sec-unary-plus-operator)、[BigInt数值规则](https://tc39.es/ecma262/multipage/ecmascript-data-types-and-values.html#sec-numeric-types-bigint-divide)。活动草案版本及用途在资料章记录。

### 具名实参的完整区分例

```gift
fn spin() -> Int = spin();
fn choose(a: Int, b: Int) -> Int = a;
export fn sample() -> Int = choose(b: 1 / 0, a: spin());
```

按现有源规则，先取得choose，再求第一个实际表达式`1/0`，计算错误发生后不调用spin。即使两个表达式没有外部效果，不能直接打印为`choose(spin(), 1n/0n)`；那会先进入不正常返回的递归。

设计输出形态是：取得被调值；第一个实参求到`argB`；第二个求到`argA`；最后`callee(argA,argB)`。名称只是示意，布局器分配真实私有名。保持方法适用于有错误、非终止或作用的参数；能够证明更短直接调用同义时才消除不必要临时量。此例是书面轨迹，没有运行无限递归或目标程序。

### 一个完整标量输出与来源定位

对：

```gift
export fn safeQuotient(x: Int) -> Int =
  if x == 0 then 0 else 10 / x;
```

在选择普通ES模块、BigInt目标和当前错误映射后，预期源码可为：

```ts
export function safeQuotient(x: bigint): bigint {
  return x === 0n ? 0n : 10n / x;
}
```

这只是目标形态，不是已运行产物。由于源没有约定JS可构造性、prototype和反射，此中立函数容器可由目标决定；原生作者箭头函数则不沿这条规则擅自改成普通函数。函数有require/ensure时按契约入口生成，不能为保持样例短而省掉它们。

分子从10改为20，只改变对应源表达式、相交分析与该目标节点；旧候选和未改文件不变。旧artifact的类型结果不能贴到新artifact。目标body生成完毕后，以实际打印字节重新建立目标位置，不拿打印前的暂定pos当准确最终位置。

### 虚拟CompilerHost与目标检查

目标检查是公共`check`或请求中实际选中的方法，不是preview的无条件附带动作。当前TS6适配使用`createProgram`及相应诊断接口，所有输入由冻结虚拟文件系统提供。

| Host责任 | 当前实现要求 |
|---|---|
| 源文件读取 | `getSourceFile/readFile/fileExists`只读当前VFS；按实际脚本种类、文件后缀和编码创建SourceFile，不落回ts.sys |
| 模块解析 | 使用当前API族的模块解析器并只传本VFS所提供的文件/目录操作；记录包入口、扩展名、候选未找到与实际所读package元数据 |
| 默认库与环境 | `getDefaultLibFileName`返回已绑定库入口；完整lib链、声明包和所需辅助均是捕获内容。固定`types`范围，防止自动扫描机器其他@types |
| 路径规则 | `getCurrentDirectory`为固定虚拟根；canonical名、大小写、realpath、目录存在性均用同一个目标/执行文件系统画像，不读取本机cwd |
| 输出 | `writeFile`写隔离的结果sink或在noEmit检查时拒绝调用；绝不直接写用户文件 |
| 诊断 | 配置、语法、全局及语义诊断分角色处理。缺失lib或不支持工具版本是环境/适配缺项，不能统一报作者代码错误 |

`strict/noEmit/noEmitOnError`等配置要固定实际值并按该次请求消费；目标至少支持BigInt所需版本，但不能为了生成成功暗中提高用户要求的运行最低版本。声明检查是否skipLibCheck也属于实际方法范围，默认不把跳过上游检查记成全部声明都已验证。

用`createCompilerHost`然后只覆盖writeFile，仍可能通过其他默认回调读取本机环境，因此不是闭合Host。Compiler API确实提供Host、Program和Printer分工，[官方接口说明](https://github.com/microsoft/TypeScript/wiki/Using-the-Compiler-API)是可复用基础；Gift仍需实现这层冻结输入与诊断归属。

### 源坐标转换与可复查错误

Gift内部源跨度采用冻结源的UTF-8字节半开区间；TS工具和JavaScript Source Map常用UTF-16码元。每份源记录换行起点和稀疏的字节/码元检查点，在检查点之间按Unicode标量扫描。ASCII一字节一码元，补充平面字符四字节两码元；CRLF是一个逻辑换行但两个实际字符/字节，原位编辑保留原字节。

转换必须拒绝或按诊断协议显式拓宽落在字符中间的范围，不能将UTF-16位置直接当UTF-8偏移切源。一个生成helper可能来源于多处输入，返回相关来源集合；没有精细映射只返回函数或模块级范围并标明精度。不能以运行堆栈或source map制造唯一逆向编辑权限。[ECMA-426位置单位](https://tc39.es/ecma426/)明确区分JS/CSS码元列与Wasm字节列。

打印器是否支持当前生成节点的精确映射，须按实际实现/API族核验；首个实现可以先保证声明/表达式来源表与精确源跨度，未实现逐token目标map时不返回假精度。后续格式化改变字节时，重新取得映射或明确降低精度，不能继续返回格式化前的精确位置；要求精细映射的根仍须满足该硬合同。此限制不阻断不请求细粒度调试图的合法源码生成。

## 通用局部控制和托管资源的逐构造输出

局部let采用不可重新绑定的目标变量；局部var采用合格可变槽。未逃逸且只在本调用观察的位置可直接使用目标局部变量，捕获逃逸的位置使用闭包环境或盒；不同循环体激活产生不同位置，循环外槽继续共享。目标复制一个数值不等于实现按位置捕获。JavaScript和JVM的现成托管内存可复用；无GC目标要另外给出循环对象和逃逸闭包的合格管理，不生成悬空栈地址。

while正常输出为先条件再体的循环。continue跳到本循环下一次条件，break跳到后继，return进入当前函数的统一出口。先计算待返回值，再按[出口合并](../../20-语义与组合/基础语义/对象与控制/控制流与存储寿命.md#控制出口与清理结果的确定合并)处理真正跨过的清理域；记录主结果、清理顺序和未结算资源。一个close失败不自动跳过其他独立可关闭资源，也不能释放仍被失败子任务使用的上游缓冲。scoped先完成自己的业务Result映射；外层函数再按其正常结果合同检查ensure。

目标finally不能无条件return，也不能以最后抛出的异常覆盖主Fault/Cancel。Go的具名返回或Python的finally优先级只有在适配后确实保持本合同才使用。可直接使用成熟语言清理结构的简单情况不强制生成通用运行器；多个失败需要组合时由实际结果槽与有序诊断实现。返回值持有普通合法引用；保持的是已求得的值，不是原对象的隐式深快照。

目标中的私有位置仍有内部读写关系。外层公开效果隐藏不允许将`next()+next()`的两次位置更新合并；需要改成纯表达式时，应由另外的保持变换消除存储，而非删除效果注解。输入域、错误、资源与潜在函数效果也继续参与优化条件。

即时运行与发行采用同一降低规则。即时策略可输出隔离的最小模块；面向交付的源码继续采用固定布局。两种输出的名称与包装可以不同，但语言域、运行错误、调用次数、实际效果和独立资源保证不因“快速模式”变弱。无相关代码变化时，运行参数变化不重排整个源码结构。

## 计算目标布局不是服务模板

[计算结构](../../20-语义与组合/基础语义/计算基础/计算结构与算法.md)拥有算法、数值和访问的完整合同；本章只负责落位。纯核可以生成一个函数；大型图/编译/图像程序按实际阶段和数据访问组织模块，不自动插入Controller/Service/Repository。真实共享不变量定义提交域，缓存行或GPU块的共享数据定义同步域，两者不能按名称合并。

源不可变并不强迫每步深复制。目标可以使用局部可变数组、就地更新或滚动缓冲，前提是保留旧值依赖、别名、线程同步与寿命；唯一外部所有权不能证明算法内部没有读后写冲突。sharpen的顺序基线为旧输入加独立输出，合法优化的私有缓冲属于实现，不进入作者谱系或业务审计。

数组尺寸与字节乘法先检查，数值中间量和地址类型分别选择；布局/向量化/后端版本进入实际Binding。编译期内核生成、目标构建、设备上传、启动、同步和结果回传各报告实际成本。发布普通CPU库不生成GPU占位核，没有订阅的计算应用不链接消息工作器。

只读源码预览无需创建目标运行实例或分配完整输入尺寸的设备内存。配置/目标选择允许的退路可以采用，不支持硬实时、精确浮点或强制设备时不得偷偷改为不同承诺。

## 状态图的普通源码形态与结构稳定

状态图默认生成有限只读拓扑/转移表、纯step/reducer、回调及必要类型，不枚举全部正交组合，不按state拆服务。无activity/timer的模型只需逻辑运行辅助；选用动态解释器、Qt或其他库时列实际依赖，不能宣称没有运行库成本。

固定模型顺序与稳定节点映射决定分派和诊断。改显示位置不重排语义表；改列表次序有可观察优先级影响；改节点名字而身份/顺序保留时，不按字典序重新生成优先级。持久化记录存稳定状态/模型引用，不存只在某次生成中有效的数组下标。

一个模型产物及其运行库、Provider配置、图标与明确资产构成真实输出闭包。pure-step产物可以独立完成，实际活动未绑定时不能将完整应用标完成。生成class只是某目标代码容器，不把有限状态库变成全部对象语言实现。

## 关系结果的普通源码与SQL边界

目标默认按[关系规范](../../20-语义与组合/基础语义/状态关系与流/关系查询与维护.md)生成普通函数、集合/桶索引和排序辅助。主例releaseTotals可在条件成立时采用release键集合、资产遍历和kind精确和，最终按规定Text次序输出；不是为每个关系节点生成一个服务或把整计划JSON放进运行解释器。

选择SQL时，值参数化，列与表从真实模式标识生成；外连接添加不可混淆的右侧存在位，Option层次、空sum、ALL重数、排序及Int/Text范围逐项映射。用户回调部分保留本地时，源范围和传输仍须合法。target class外形、文件布局与preserve规则继续生效，选择查询计划不暗改公开名。

SQL生成成功不是SQL执行成功，更不是完整报表已写出。代码、依赖、配置与报表文件通过原Contribution/ArtifactSet汇合，CheckRecord独立追加；无必要时不生成数据库配置、迁移或Outbox。

## 完整计算程序的目标组织

默认目标是按真实职责组织的库或模块化应用，不是按Gift内部每个类型生成一个类或服务。模型/算法、必要数据结构、宿主I/O、可选会话/展示和入口分别承担责任；小工程可以同文件，具有独立公开合同或寿命才分开。公共函数、类型、资源名按既有布局基础稳定，私有循环、缓冲和临时值由后端生成。

图分析应用可以生成graph、layout、scene、io与main等模块：graph保存校验和SCC，layout使用组结果，scene保留每条边出现，io编码和导出，main处理实际参数与错误。需要交互时增加本地会话和取消关联，不增加账户、数据库、消息和分布式协调。另一个解析器可用树与显式栈；数值求解器可用迭代与工作区；不把这棵示例目录当普遍模板。

源码制品、可运行制品、调试/观察变体和实际运行结果是不同对象。生成命令行入口时保留参数解析、退出分类、错误输出和结果文件规则；库目标不被强加main。目标编译器、加载器和包工具尽量成熟复用，Gift负责真实绑定与中立语义保持。

观察模式只在对应任务请求时贡献source map、调试信息或探针，记录实际转换并核布局/公开接口保持。无法保留某个优化值就返回不可用；编译成功和有调试文件不等于全部源级观察完备。默认制品不携带Gift管理数据库、全量记录和作者隐藏秘密。

## 对象、流与导数的具体输出形态

对象区域输出真实构造入口、私有字段与方法槽；适用目标可以采用本地class或显式接收者/虚表。公开要求是否真的生成，仍由控制后置核对；未承诺反射的内部布局可以调整，不扩大成所有原生观察等价。

无并行与窗口的流默认融合成普通循环或迭代器。选择并发、热源或窗口时才带必要队列与运行辅助；driver与应用资源装配，不复制Gift的开发控制数据库。控制信号及End必须等待相交在途输出。

导数生成原值与JVP/VJP区域、确实需要的残余和数值库引用；无求导请求不生成tape，普通函数引用未变不因新增求导消费者重写原作者源。观察版可以显示形状和有限残余，但不得将调试保存成本当作无探针运行成本。

三类输出共用实际文件布局与ArtifactSet成员组合。只存在一个功能表项或格式合法的代码壳，不能作为相应运行能力完成。

## 对象前态捕获与发行范围的目标保持

[对象契约](../../20-语义与组合/基础语义/对象与控制/对象构造与分派.md#前态契约一个明确入口而非整堆快照)中的before沿现有表达式顺序降低：先取得接收者与实参，执行槽前置，再读取必要不可变字段到局部值；随后调用主体，只在正常返回时检查后置。真实字段写入若已发生，失败路径不把capture解释成回滚快照。新捕获变量使用稳定的私有命名与CST/源映射，不改变公开参数表，也不在调用者中重复求接收者。

默认语言组合包含对象语法不代表目标需要对象运行库。直接函数输出仍为普通目标函数；有限对象可以采用TS/Java类或等价布局/槽表；硬基类、反射或ABI要求另行判断，不用结构加函数冒充。库、资源和入口只从本根的实际输出需求汇合。一个打印成功的class还需真实构造、方法和契约实现；无方法时该根保持缺项，不输出空类取得通过。

## 首个 TypeScript 纵向目标：精确输入、发射和第二次修改

首个能被签发的 TS Target 能力集合应以 `SupportedConstructSet`、`TypeScriptVersion/tsconfig`、目标模块系统、运行宿主与所选 Provider 记录，不用 `targetLanguage=ts` 宣称全部 JavaScript/Node API 已受控支持。可从结构化作者源或合格 `.gift` 子集取得封存语义，复核每一 lowering 对求值次序、异常/Result、整数范围、具名实参、作用、资源、模块身份与来源诊断的保持；未满足时返回准确 `TargetCapabilityGap`，而不是偷偷发出语义相似但错误的代码。

纵向可执行样本至少包含两次相继作者修改：T0 `AuthorSource + project/lock + selected Methods`→IR→`TargetProgramPlan`→规范路径与成员布局→实际输出 TS 文件、source map、锁与构建配置→真实 `tsc` 检查、运行预期结果及独立验证；T1 在用户修改一个已接受公共合同后，重解析唯一源，按精确依赖重求相交部分，保留非相交手工文件，再生成/验证并检查旧输出是否被正确撤销。由编译器而不是模板作者决定必要的临时语句、顺序与成员归属；由宿主而不是纯 lowerer 决定安装/构建执行权限。

`ArtifactSet` 只在当前文件集合、跨文件导出、Runtime 配置和生成器证据闭合后发出 `COMPLETE`；单文件成功不代表混合工程组装合法。开发者可选择仅预览/写文件而不运行，也可以仅检查语义不生成目标；第二次修改的可重复性是比一次 `hello world` 更强的通过条件。Rust 作为 Gift 内核语言与 Rust 用户目标仍分别验收，首个 TS 闭环不等待 Rust 用户目标完成。

## Target 生产合同：可观察轨迹、成员输出和二次编辑

### Target的类型化输入

目标发射接受已冻结Root及每次组件实例、专业成员和操作Use、联立的硬义务、实际合格Method计划、目标/宿主画像和作者原生区域的写权。Target不能跳过Meaning去重新解释业务名词，也不能自己代替Policy授予实际许可；它只按照专业合同将实现计划合法降低到目标语言、配置和构建资产。

**输出范围**按真实选中的Root可达闭包决定，而不是“找到几个Module就都编译成进程”：入口（命令行、桌面UI、HTTP服务、后台作业、库导出）、逻辑模块、公开API、事件/数据连线、组件实例生命周期、状态存储、持久化模式/迁移、配置、必要依赖、错误与SourceMap等必须和目标类型相符。不需要的设施不得为齐全而生成；无服务需求不默认创建容器/数据库/远端Runner。


`TargetBuildBasis{boundRoots,semanticRevisionVector,realizationBinding,sourceProfile,toolchainIdentity,targetTriple,featureAndDependencyResolution,policyAndEnvironment}` 必须先固定。Lowering 的产物不是文件列表而是 `ArtifactSet{members,publicApiAndAbi,sourceMaps,dependencyLock,buildAndRunRecipes,provenance,diagnostics,declaredCompatibility}`；每个成员有原语义实体/目标路径/内容摘要/角色，目标路径冲突是检查错误，不用遍历顺序覆盖最后一个。生成结果与作者状态分别保管，代码符合目标语法也不能证明与作者要求等义。

变换证明基于所声称的可观察轨迹：返回/错误种类、effect先后、资源生存期、异常/取消、并发可见性、ABI布局与数值画像。对不相交的纯计算允许按明确等价类优化；对原生异步、宏卫生、反射与未支持外部效果，明确 `UNSUPPORTED_LOWERING`/`TARGET_CAPABILITY_MISSING`，而不是静默插入万能运行时。目标工具链诊断映射到来源区间时应同时保留 target 原坐标和映射不足的状态，不能把合成代码错误任意归责作者。

发布时先得到全部必需根的可编译/可检查结果与成员内容摘要，并在真实单体原子或可索引的 `publishedHead` 下安装；没有共同提交能力时按根列出 `COMMITTED/FAILED/UNPUBLISHED`，不得因为其中一个入口通过就宣称整组产品交付。第二次作者修改重新进入 source→semantic→binding→Target，保留未改区域、受管/非受管代码边界及新的SourceMap。若第三方直接修改生成区，按真实 owner 进入接管、拒绝或显式三方合并，不用静默下次生成覆盖。

可验证样本要求：同一表达式短路效果在 TS/Rust 下降低顺序保持、路径同名成员冲突、编译器返回准确 target 错误、旧目标文件被真实引用、多根部分失败，及第二次修改只改变相交成员；产品支持资格只由该版本真实 Target 消费者和 Evidence 签发。

## 首个真正有函数体的TypeScript项目生成：结构、质量与边界（Gift 98 实测）

已执行的`Gift98/compiler/compile.py`从合法`gift.author-projection/1`读取作者语义，进行值域/Definition/联合引用检查，绑定局部受限方法后，按实际使用点生成独立TypeScript源码：`<Entity>.ts`提供强类型字段、精确Enum、Value/WriteOutcome及Store入口；`<Workflow>.ts`提供State/Event、initial和纯转移；`<Composition>.ts`提供受检跨方法调用；共享`src/gift-runtime/{record,workflow}.ts`由已绑定方法真实算法提供，另有index、tsconfig、package和产物摘要。没有使用自由拼接的作者代码；目标名称先经保留字和跨平台路径冲突检查，字面量经JSON字面量编码。此发射器是固定构造的试验TypeScript源码生成器，不是已实现全通用TargetAST。

作者只指定不同的`fields/edges/links`，不指定Map、BigInt、文件布局或每个校验语句。不同语义方法生成各自有必要的模块；同一工程可组合，产物仍保留可审阅的类型、独立函数和通用方法库。`tsc --strict`、`exactOptionalPropertyTypes`、`noUncheckedIndexedAccess`、`NodeNext`与实际Node运行用来验证本轮有限支持范围；`tsc`通过不证明所有语义性质，目标源码高质量不等于任意指标上的最优实现。

当前真实代码与下列目标保证分别挂钩：

- `Text`只接收无孤立代理项的Unicode标量字符串，长度按code point计数；这不是通用NFC规范化或Unicode grapheme长短合同。
- `SafeInt`仅接受JavaScript可安全表示的整数及声明上下界；`Revision64`内部使用`bigint`进行受检增长，JSON/公开快照使用规范十进制字符串，拒绝溢出；两者不可混为一种Gift Int。
- Workflow转移关系构建一次局部`Map`索引，当前单次查找常规平均复杂度为O(1)，构建和空间随边数增长，未实测大型负载延迟或最坏哈希情况。记录集合的create/get/replace按当前宿主Map成本工作，收据不能免费无界保留。
- 没有开启持久化、网络、Host IO、复杂结构所有权、异步重入、通用优化器、任意原生导入、目标安全沙箱、完整SourceMap或增量编译图；需要这些的任务必须拒绝该方法或选取真实合格后端。

产物在`--out`请求时只创建**不存在的输出目录**，路径结构由受信Target Layout固定；当前工具会拒绝覆盖以减少作者与生成源互相争夺owner。`--out`省略时只返回内存计划及摘要。保存到生产Git工作区、应用新旧结果的多文件原子替换、Toolchain attestation及旧生成区的协作式CAS仍须由真正Execution/Provider完成，不能因新目录导出成功自动推广。

实例级范围在`fixtures/contract-closure/Gift98/README.md`、编译器源码和源项目真实test/运行证据内；它优先验证可用核心纵切，而非代表全语法/全领域或Rust后端完成。

源码的**受控二次交付**已由同一试验`--update`实现：从现有Artifact Manifest核每个机器所有文件的旧SHA/长度及路径安全，遇到用户修改或非受管路径碰撞明确拒绝，只更新本轮真的改变的源成员，保留用户其他文件。发布前先在`.gift-reconcile/`暂存新源与可恢复的旧字节，写入最终Manifest后移除；异常时`--recover`核已提交全体成员或用旧字节回滚。**这只是单作者单进程的参考发布器**，多个文件的可见替换不是跨文件原子事件，也没有fsync、非协作并发写者隔离或外部副作用的提交资格。

## 真实源码质量的两个独立接合：生成源码和外部实现链接

在同一有限TypeScript目标实例中，已知`VersionedRecord/FiniteTransition/TransitionOnRecord/AllPredicate`由编译器将精确作者参数降低为TypeScript的类型、状态表、组合函数和已选Runtime实现；新增的`BindCallable`则**不合成函数体**，而是从方法供给库获取已固定哈希的现有TypeScript源码，把源字节复制进`src/gift-methods/<stableRef>.ts`，以`src/<Alias>.ts`生成带目标参数/返回类型的re-export封装。两者的成功含义不同：前者是局部已实现lowering，后者是受检复用既有函数；不得将后者计入“意图自动生成未知算法”的覆盖率。

发射要求保持作者事实与运行前提：未改语义的JSON对象键排序、使用点列举顺序和无序转移边变化，不应引发不必要的目标成员重写；输入字节不同仍更新Source身份，受管理的输出成员按实际字节摘要做前像保护。供应库变化要使方法读集哈希与对应目标成员失效，不能重用上次`tsc`成功记录或绕过`sourceDigest/MethodDigest/ArtifactDigest`。输出只可在受管理目标目录写入；存在人手修改或无凭据的保留事务目录必须停止，不得自动删除。实际构建时用 TypeScript严格模式验证成员依赖/声明，但目标层不能从类型正确推出运行时纯度、分布式事务、独立行为证明或性能最优。

通向最终专业源码的Target闭合还必须覆盖：完整源码成员图、包/构建/ABI/环境声明、精确供给依赖、目标语言语义保持证明或相应测试、效果与错误完整映射、资源/并发和安全要求，及改动后局部失效和真实环境验证。不能将单个`tsc`通过等同于所有语言平台、运行环境或规模负载的资格。

## 完整目标合法化、精确表示与源码质量准入

### 从 Meaning 到源码之间必须可检查

目标消费者输入已绑定的语义图、MethodBinding、精确 TargetBinding、布局/作者所有权和所需保证；不能只收一份任意 JSON 然后按业务名选择模板。先列实际可达操作、类型/效果及运行依赖，再为每项选择有保持依据的目标表示/改写，重查新引入操作，直到全部处于本目标合法集或返回 NeedsTargetAdapter。合法集按实际消费者而非声明全集确定。

完整转换不得留下未解释高层节点、未绑定外部函数、假成功分支、`TODO` 函数体或默认零值。部分转换可服务诊断和预览，其未降低集合必须随结果返回，不能与完整 ArtifactSet 共用成功资格。某个后端不支持一个高级扩展不意味着所有目标失败；能独立闭合的输出根可以单独生成。

### 默认表示与允许优化

Int 保持数学整数：TS 用 bigint 或已选精确库，Rust 用合格大整数表示；只有当前值域与所有操作/转换有依据时才缩为固定宽。Bool 不用宿主 truthiness；Unit 与空记录在必要值位置不同；Text 不以宿主字符串长度默认充当 Unicode 标量长度；record/list/sum 的不可变与名义区别不能只靠 TypeScript 的擦除类型注解。

目标可选择直接 struct/enum、普通函数、Vec、共享不可变尾部、闭包环境或分派表，不必携带一套通用运行时 AST 解释器。递归 List 模式不强制每次复制整个 tail；合法的 view 或共享节点须保持寿命与别名。优化成循环须保存仍需执行的 ensure、清理与错误；含待完成后置责任的递归不因为语法上尾调用就可以直接跳转。

泛型函数可采用单态化或字典/封装共享，选择按公开类型身份、ABI、代码体积与预算。无限增长的实例链不能截成 Any；动态闭包不能在构造时调用函数体去“求出常量”。一次性资源捕获对应真实单次调用/移交，不自动转换为可重复调用的函数。

### 发射过程

布局先决定真实输出成员、模块/可见性、公开导出与依赖，再发射每个有用成员。表达式复杂时可引入目标局部变量以保持 callee→参数→主体和短路次序；变量名由稳定来源/冲突规则产生，而非全图遍历序号，使无关插入不重命名整个工程。仅实际用到的辅助函数和运行库进入产物，不为所有语义家族生成空目录。

每个受管成员绑定源发生位置、方法与 Target 修订、内容摘要及生成拥有者。原生用户区域不被发射器覆盖；一个已有原生库若能直接满足接口则直接依赖/重导出，不复制它的源码。生成方法从静态分支换成表驱动可以改变内部源码，但公开行为、初始化、资源、依赖和后续编辑边界必须保持。

### 源码完成不等于产品完成

目标结果至少保留：候选源码完整性、原生构建结果、行为保证范围、尚未部署事实与实际运行资格。`tsc --strict` 或 Cargo 通过仅证明相应目标检查，不证明所有业务/权限/数值/并发性质；未执行的构建返回未核验而非 PASS。不能把只读计划源码记成已执行的 Provider。

维护质量的具体反例是：插入无关定义不改变既有导出名；修改一个条件只影响相关成员；用户手工区不丢；源错误能回到实际参数/引用；依赖不出现未锁版本；纯函数不拖入网络/数据库运行服务；目标运行不回连 Gift 才能解释普通已编译逻辑。这些不是强制所有输出长得一样，而是每个 Target 需保持的工程合同。

<a id="design-b17"></a>
## 完整目标接纳与可运行根

完整Target资格以实际输出根的传递闭包为单位：类型、构造、callee、effects、错误、初始化、ABI、运行库、成员/导入和构建工具全部可接纳。检查发现任何未降低操作、未解释规则、缺Method或缺依赖时，该根不得标成complete；不能发空函数、TODO或默认值补洞。

TypeScript目标最低一般计算画像设计包含exact Int的bigint/合格库表示、名义ADT标签、Result、词法闭包、泛型受资格实例或共享表示、顺序求值、错误及递归策略。Rust目标另核整数宽度、拥有/借用、泛型、panic/Result、Drop和FFI；作为编译器实现语言存在Rust不等于Rust Target已实现。

每个降低规则绑定源构造及语义版本、目标AST生产者、侧条件、源码映射和证据义务。目标打印器仅打印已合法AST，不重新推断业务意义。完整源码构建成功只证明原生工具所检查的部分；行为、性能、授权和恢复分别验收。部分转换用于诊断/开发时必须标出余项，不作为发布ArtifactSet。

目标包中的独立根可单独完成，但共享runtime/导出依赖破损时不能拆掉失败文件却保留引用。产品声明应精确到root/profile/environment；额外Target缺失不降低已合格目标的证据，也不能借首个目标成功代签所有后端。

**验证与反例**：维护构造→type/effect→lowerer→target AST→成员/import→原生工具的矩阵，缺任一列返回具体Need。静态分析能转换与已转换分开。

**实际能力边界**：生产全TS/Rust lowering与真实目标资格未完成。

## 值表示与完整目标发射

序列、名义类型、闭包、调用栈和错误的具体目标表示影响结果、进展与复杂度。首个Target不能借宿主的数组复制或数值便利静默改变已选合同。

实际数据、调用顺序和失败处理见[相应施工设计](../../70-工程系统与演进/工程构造手册/06-编译管线与目标源码.md#target-representation-and-emission)。

## 从合格业务意图到源码和完整系统：具体编译交接与确定性边界

业务意图不能逐条翻译成 `if`：目标产物来源是**已固定的综合实现计划**，其中一部分可直接采用合格现成组件，一部分需要生成按业务 Meaning 专门化的判断/转换函数，一部分是与外部 Provider 交互的受权适配器。一个实现计划的结果不一定必须包含新手写的算法，但必须有完整真实代码、配置、依赖、受管源映射及公开效果/错误接口；不能把整个业务塞进未解释的 JSON 并仍称“语义生成源码完成”。

输入 `AssemblyPlan` 逻辑上由 `AcceptedRootRevision`、`SemanticsSelection`、`BindingDecision`、`TargetProjectProfile`、`DependencyLock`、`SourceOwnership`、`EffectContract`、`VerificationPlan` 组成。真实实例必须有唯一版本及哈希、完整方法闭包、所有 Target 资格与由谁有权修改的成员集合。若一个作用由现实 Provider 承担，生成的是调用其准确 ABI/认证/错误/幂等/观察适配器；不能写 `return true` 代替现实返回。

### 可施工编译过程

```text
assemble(frozenQualifiedPlan, target):
  assert each root obligation has accepted coverage or an explicitly blocking Need
  expand dependency and source ownership closure without duplicating author source
  lower typed predicate/constraint/decision/method/trigger -> target-owned nodes
  leave qualified third-party engines and libraries as locked dependencies, not fake rewrites
  adapt value/ABI/authority/effect and error boundaries with declared conversions
  form target member and import graph; reject illegal cycles and missing target operation
  emit full buildable source/config/assets/migration files as ArtifactSet
  write SourceMap with sourceRevision + occurrence + requirement + method + output span
  run independent build/check as specifically authorized; preserve exact diagnostics
  publish only at correct workspace revision with CAS and original-owner restrictions
```

业务态声明与实现态合同不得互写：业务作者可改一个目标/安全/期限，编译器只使依赖它的决定、代码和证据失效；用户在原生区维护的源码只有明确的原生拥有者，生成器不得覆盖。Generated source 的结构可能随目标技术变化而变，作者意义由原 SourceRef 锁定；需要长期可维护时生成命名、模块、错误、依赖和源映射，不能只生成难以编辑的一大块函数串。

### 确定性的精确含义

固定作者字节、已接受 Meaning、全部库/Method/Target/平台及选型输入，可追求可复算的结构解释、候选排序、Lowering 与 Artifact 字节。执行过程若读取现实时间、外部状态、并发事件、随机数或人类批准，则必须显式规定其输入源/记录或允许非确定性；确定构建不证明未来世界结果相同。方法选择可稳定而不唯一最优，生成源码可构建而不满足业务；三件事各要资格。

TS 目标保留精确整数/布尔/文本、严格错误、闭包捕获、状态转换原子域、能力导入及 `SourceMap`；Rust 目标需要自身所有权/借用/ABI/lifetime 资格。目标适配无需实现新机器码后端；编译器也不因需要持久业务运行而默认启动所有运行时组件。所有不支持的操作应在完整目标覆盖检查时报 `NeedsTarget`，而不是发射 `TODO`、静默省略操作、生成空函数或保留未解析 IR。

### 一次修改、失败和退出

修改已接受业务约束时先产生差异：是否改变输入、结果、错误、时间、规范责任、效果或公开接口。Meaning 变更触发相交 Method、证据和目标失效；仅代码优化而合同不变仍须重新验证具体构建/性能。真实运行实例继续使用其历史版本直到有权迁移；不把新构建直接覆盖旧实例历史数据、已派发操作和收据。目标可独立取出构建/运行的全部代码与依赖，而不是必须连回 Gift IDE 才能使用。

<a id="gift119-complete-source-delivery"></a>
## 完整源代码生成的最小目标闭包与非假实现校验

输入必须是经过资格检查的 `BindingDecision/AssemblyPlan`，而不只是 `intent:goal` 文本。每个产品 Root 的公开接口/业务规则、运行时行为、状态或外部作用、异常/取消、可观测进展、依赖和授权条件，都要被某一实际 Method 或受界源码生成者覆盖；不能将未支持的条款注释掉后称“完整业务源码”。

一次装配算法：①从根获取所有 `Requirement/Method/Effect` 闭包；②为每个已合格 Method 选择准确后端（已存在库→调用与依赖；数据/规则/流程→合格专用构件；已解释的受界计算→直接输出类型化 TS/Rust），保存来源映射；③检查共同事务/异步、时钟、资源、观察接口和回调生命周期；④生成文件集、入口、类型、配置、迁移、Adapter、测试接合与依赖锁；⑤验证没有未降低节点、TODO、虚假 Provider 或缺少目标成员；⑥在工具链实际存在时独立严格构建和运行，记录环境；⑦第二次修改只重建相交派生区域，原生源权利不转移。

内部 `AssemblyRecord` 至少记录 `productRootRef / acceptedSourceRevision / semanticLocks / methodBindings / targetProfile / generatedMembers / vendoredOrReferencedDependencies / sourceMap / uncoveredObligations / qualifiedClaims`。`generatedMembers` 区分按意图专门生成的业务源码、已有组件接合代码、复用的成熟组件与配置；不要因 TypeScript 工程绝大部分是预写 Runtime 就把它叫“意图自动编写了所有代码”。`uncoveredObligations` 非空时可交付部分分析/草稿，但不能声明对应目标的完整产品资格。

跨源重复比较要分开：源码文本确定性、目标构建确定性、运行语义等价、真实世界达成、可维护性/复杂度证据。固定 Source/Meaning/Method/Target/Toolchain/Policy 能允许可重放的编译决定，不意味着生产运行时间、外部金融结算或人类评价是确定的。跨目标选择需要 Target 对错误、精确整数、Unicode、Effect、ABI 和资源上界提供逐构造资格；Gift117 的局部 `semantic_codegen` 不可代签完整目标。

## 生成系统的合格入口不是“任何形式上可展开的业务模式”

Goal、PatternUse 和 Requirement 的展开结果是**待实现的业务义务**，不是目标语言函数主体。Target 只消费完成全部硬资格并已锁定的 `RealizationBinding` 和与之匹配的输入/效果/目标 ABI。`ELABORATED_UNQUALIFIED`、`NEEDS_REQUIREMENT_READER` 和 `NeedsQualifiedConditionalRequirement` 均不可被发射器悄悄变成 `return true`、空处理器或固定 SQLite 状态更新。生成器可以复用确有保障的 SQL、工作流、规则、原生库等组件；只有确有定义的专用逻辑才经过语义 Lowering。

完整系统的成员集合应按本次输出根和实际选中的方法推导：公开 API、数据结构、事务边界、必要迁移、交互、依赖、配置、错误、可恢复控制、源码映射和构建命令。没有要求 UI 的服务不强加 UI，没有现实 Provider 的纯模型系统不能冒充真实业务交付。临时应用、引用系统的代码行数、局部 `tsc --strict` 成功均不构成“通用意图生成系统”的证明。新模块/组件必须通过真实实现被第二次变更消费和失败恢复检查，才可宣称相应能力完成。

## 适用前提、限制与反例

以下按原版本保留相关定义、反例、判断和实测范围。版本名称仅表明形成来源；条款是否现行有效仍由本文件的当前合同、被引责任文件及实际消费者决定。

### 目标降低为合格装配，不等于把每条业务意图翻译成循环

输入为锁定的 `QualifiedAssembly`，包含被选规则、查询、工作流、原生包、真实 Provider 接口、必要 UI 和 Glue，不要求每个 Intent 先具有计算函数体。Target Adapter 可以输出 SQL/规则/工作流/声明配置及受管 TS/Rust 成员；只对目标所消费的节点要求完整合法降低，若某个被使用能力缺 Target/ABI/版本/许可则拒绝完整 ArtifactSet，不能生成空 stub。

SourceMap 从每个组件与方法绑定追溯到原始已采纳 Intent Clause 和 SourceRevision；二次修改只使相交产物失效，原生用户源码不因生成器拥有目录就被覆写。目标代码静态构建不证明业务合同/现实 effect，具体装配及恢复设计见工程构造手册第22章。
### 通用本地装配式目标，而非行业模板

[实际 TypeScript 模型产物](../../70-工程系统与演进/工程构造手册/25-意图到本地持久程序-可运行装配施工.md)由受锁定的 `contract.json`（Meaning、Method、绑定与联合计划）和可严格编译的通用 TypeScript runtime 组成；这属于**装配而不是任意算法自动合成**。产物应有完整源码、依赖、方法版本、编译时合同摘要、构建与实际行为证据。当前无逐语义 SourceMap、完整跨语言 Target 或真实 Provider 资格，不能由 TS `tsc --strict` 成功代签其它能力。
### 从已解释的高层业务 Meaning 发射专用源码

目标降低的正式责任不能只由复制固定运行器来满足。[实际语义 Lowering 参考](../../70-工程系统与演进/工程构造手册/27-业务语义直接降低与有限合成.md)读取意图/Meaning/Method，生成只包含本次业务谓词、方法前提和状态修改的 `logic.ts`；通用 SQLite/搜索框架仍复用，但不再在运行时按照业务表达式 `op` 分派。该参考只证明有限本地模型的 `finite-model-expression` 与 `set/addInt`。真实 SQL/服务/UI/设备 Target 的完整合法化、跨效果资格及多次修改尚未实现，不能以它们的设计接口代替真实消费者。
