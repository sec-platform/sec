## 研究、规范、证据之间怎样接

研究正文保留完整问题、例子、推导、候选方案及边界，供设计发现和反证；其中历史方案、拟定类型和“验收”语句不自动成为现行 API、实现状态或已运行测试。读取时从本页进入相交现行 owner；未有精确原始依据的命题保持待核。资料有独立解释、反例或候选价值即可保留，不要求先被当前 Claim 采用。

发现任务先取真实需求和当前规范，再从与机制相交的理论、领域、组合材料进入；开放发现也可先从异常案例出发，不能只搜索预想结论。按[已有知识接合方法](../docs/60-保证与证据/验收/方法与独立证据-义务方法与已有知识.md#existing-knowledge-design-evidence)判断资料究竟支持什么，把成立的机制、前提、接口或反例写入真正 owner 及消费者，并保留原始定位与未决。

采纳以命题为单位：一个来源支持某项边界，不等于接受它的所有类型、状态机或实现建议。规范负责当前选择和消费者，研究继续保存推导、竞争方案、失败条件与尚未采纳的独立内容；不要求它们全部变成 Core 功能、自动测试或 ProofObligation。名字相同、来源权威、同包收录或已有链接均不签发能力、权限和已运行资格。完整采用/冲突处理由[知识材料的接合路径](../docs/90-治理与参考/维护/知识记录与分域检索.md#knowledge-material-authority-qualification)拥有。

例如组织资料中的 EDMS 多项目关联与 DITA 主题/映射分别支持“同一对象多入口”和“内容单元与阅读组合分离”；它们已在[文档阅读组合](../docs/90-治理与参考/维护/文档架构.md#同一信息怎样服务多个问题)落实为版本、选择条件、异常保全与未知处理。外部软件依赖、XML 格式和审批流程未因此被采用；研究原有版本、读取范围和禁止外推仍在来源条目保留。

外部原文是否允许随包分发按其许可处理；本包保存已有研究正文、必要引文和定位，不批量复制第三方站点或秘密数据。失效网址保留原记录事实，同时补定位，不能把旧核查日期改成今天；待核理论不借作者姓名或定理名称当决定性证据。

**当前规范无需依赖旧聊天或旧压缩包才能理解；完整研究也无需另找 companion 才能使用。** 当前规则唯一与研究内容丰富是两个独立条件。历史聊天流水、重复生成物、迁移账本和已经不存在的原始示例字节不属于当前研究入口；真正影响当前判断的来源、命题、日期、范围和限制直接保留在相应研究作者源中。
