## 协作收敛与一等冲突的边界

**来源与版本：** [Automerge Text][k69]、[Conflicts][k70]；动态官方文档，核对日期：2026-09-22。

**来源与版本：** [Jujutsu First-class conflicts][k71]及[Working copy][k72]；动态官方文档，核对日期：2026-09-22。

## Local History 与 Merge Queue 的恢复/稳定性依据

**来源与版本：** [IntelliJ IDEA 2026.2 Local History][k73]；核对日期：2026-09-22。

**来源与版本：** [Managing a branch protection rule][k74]、[About protected branches][k75]、[Managing a merge queue][k76]；动态官方文档，核对日期：2026-09-22。

**采用与不能推出：** 用于把package、installed、enabled、loaded/active和actual permissions分开；Marketplace签名/评分/安装量不证明扩展安全或正确。

### JetBrains plugin signing / compatibility / update

**来源与版本：** [Plugin Signing][k100]、[Plugin updates][k101]、[Plugins][k102]；当前官方文档，核对日期：2026-09-22。

**所读资料支持的命题：** JetBrains Marketplace/IDE具有plugin package signing与验证，plugin update还需要IDE compatibility检查，可分channel发布，并存在install/update/enable-disable等实际生命周期。

**采用与不能推出：** 签名、兼容验证、Marketplace review和运行时资格分别处理；已下载或已加载实例不会因为listing改变自动从内存和外部状态中消失。

## Snapshot与Visual Baseline更新的边界

### Jest 30 updateSnapshot

**来源与版本：** [Jest 30 CLI][k103]；核对日期：2026-09-22。

**所读资料支持的命题：** Jest `--updateSnapshot/-u`会重新记录本次运行中失败的snapshot，因此runner具备直接改写测试期望资产的能力。

**采用与不能推出：** 用于证明“更新snapshot”不是普通只读test action，必须在Gift侧作为Oracle/baseline候选修改受控；Jest成功写snapshot不证明新期望正确。

### Playwright Visual Comparisons

**来源与版本：** [Playwright Visual comparisons][k104]；Next文档，核对日期：2026-09-22。

**所读资料支持的命题：** Playwright首次运行可以生成reference screenshot，后续按baseline比较，也提供`--update-snapshots`；官方明确提醒browser rendering会因OS、version、settings、hardware、power/headless等因素变化，并建议在与baseline相同的环境中运行。

**采用与不能推出：** 用于把visual baseline、render environment、comparator/tolerance和实际输出分开；截图相等或baseline成功更新不证明DOM、accessibility、交互或业务Claim。

## Formatter配置解析与Import整理的补充依据

### Prettier配置与EditorConfig

**来源与版本：** [Prettier Configuration File][k105]、[Prettier API][k106]、[EditorConfig specification][k107]；动态/EditorConfig 0.17.2文档，核对日期：2026-09-22。

**所读资料支持的命题：** Prettier从被格式化文件位置向上解析配置，支持JSON/YAML/TOML以及JS/TS等可执行配置，并可消费`.editorconfig`；EditorConfig定义indent、EOL、charset、final-newline等文件样式属性。Prettier API还显式提供`resolveConfig(filePath)`和formatWithCursor等编辑器集成能力。

**采用与不能推出：** formatter结果必须绑定实际文件位置、配置解析、formatter/plugin revision；可执行配置不能因“只是格式化”被当纯数据加载。EditorConfig/Prettier设置也不自动授权覆盖作者未请求的字节。

### TypeScript Organize/Sort/Remove Imports

**来源与版本：** [TypeScript 4.9 release notes][k108]及[TypeScript import preservation notes][k109]；核对日期：2026-09-22。

**所读资料支持的命题：** TypeScript把Organize Imports描述为“删除unused imports后排序”，并另提供只Sort、只Remove命令；TypeScript文档同时说明某些框架/eval等场景下静态分析可能看不见实际值import使用，并提供保留相关import的编译选项。

**采用与不能推出：** `organize imports`不是纯排版；删除/转换import需按实际语言/框架/side-effect语义形成普通候选，不能仅凭编辑器命令分类自动应用。
