# 自举与开放编译的依据及独立核验边界

检索日期：2026-10-09。以下为一手来源所支持的机制，不是这些系统已经用于 Gift 的部署证明，也不是对链接所称 latest 文档做了永久版本锁定。本包的采用合同以 docs 的原责任为准；日后实现必须保存真实源码、工具链、目标和核验环境的精确修订。

## 编译器阶段、库和固定点

[Rust Compiler Development Guide — What Bootstrapping does](https://rustc-dev-guide.rust-lang.org/building/bootstrapping/what-bootstrapping-does.html)区分预编译种子、由旧编译器产生的新编译器、使用树内库的后续阶段和可选同结果检查，并专门解释各阶段库与 ABI。该材料支持不能只固定编译器主二进制而忽略标准库、宿主与目标。Gift 沿自己的 Rust 目标/运行边界定义阶段，不照抄文档中的示例版本号。

[GCC — Installing: Building](https://gcc.gnu.org/install/build.html)记录原生三阶段自举和 stage2/stage3 比较，比较失败需要调查。Gift 采用分阶段固定输入与独立比较原则，但二进制相同只证明所比较构建关系，不证明每个用户程序正确。不可比较字段只能按事先固定且有依据的规则隔离，不能用任意归一化把错误抹平。

## “编译自己成功”不能独立证明种子可信

[David A. Wheeler — Fully Countering Trusting Trust through Diverse Double-Compiling](https://dwheeler.com/trusting-trust/)给出 DDC 的来源、方法与适用假设。其目标是检查特定编译器可执行物是否对应声称的源码；依赖多样编译器及环境等条件，不替程序源码内容背书。Gift 的可信自举还要固定挑战、核验器、源码/工具映像和发布授权；若这些也全部由同一不可信候选替换，比较结论没有所声称的独立性。

## 开放语义到目标合法操作

[MLIR — Dialect Conversion](https://mlir.llvm.org/docs/DialectConversion/)把 conversion target 的操作合法性、转换模式和类型转换分开，区分 full、partial 与 analysis conversion。该机制支持 Gift 把“语义扩展已被登记”与“所选 Target 已完整接纳每个实际操作”分开；不能有未降低操作或伪 stub 仍称完整源码。它不证明任何任意意图都能自动合成算法，也不要求 Gift 直接采用 MLIR 作为唯一实现。

## 证明任务、证明产物与核验宿主

[Lean — Validating a Lean Proof](https://lean-lang.org/doc/reference/latest/ValidatingProofs/)区分精确待证陈述、允许公理、实际证明项与核验；指出导入内容、公理、元程序执行和核验环境带来的信任边界。Gift 借鉴的是将候选生成与主张/核验权分开、检查证明引用的全部假设、隔离任意执行，并保留独立挑战。该文档不是 Gift 已有可信证明器或所有物理事实可形式证明的证据。

## JSON 字节、数字和 Unicode

[RFC 8785 — JSON Canonicalization Scheme](https://www.rfc-editor.org/rfc/rfc8785.html)对其数据域的重复键、数值、字符串及属性排序给出明确规则，并强调不隐式 Unicode 规范化。Gift 不把普通 JSON 序列化器的 sort_keys 当成已经实现 JCS，也不把工程所有语义数字放入 JSON Number：精确 Int 仍按既有结构规范使用规范十进制字符串。作者字节保真、语义一致、内容摘要编码与目标字节确定性是四项不同合同；数组求值顺序不能为了哈希被排序。

## 本轮采用的边界

这些来源用于校准自举阶段、ABI、合法降低、独立核验和数据编码。它们不提供 Gift 项目的真实种子、仓库修订、Grant、目标兼容性或性能参数。当前只更新设计，未运行 Gift 的 C0—C3、自举二进制比较、DDC 或生产编译器验收。
