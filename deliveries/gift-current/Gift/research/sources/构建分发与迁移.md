## IaC状态、计划、漂移与字段ownership依据

### Terraform plan/apply/refresh-only

**来源与版本：** [terraform plan][k90]、[terraform apply][k91]、[Use refresh-only mode][k92]；动态官方文档，核对日期：2026-09-22。

**所读资料支持的命题：** Terraform以configuration与state为输入，并在普通plan/apply中刷新远端观察；refresh-only模式只更新state/output以反映外部变化而不修改远端resource。未保存plan后续apply会重新规划，saved plan则保存先前计划结果供apply执行。

**采用与不能推出：** 用于分离configuration、provider state、remote observation、plan和apply。state不是远端现实，plan不是执行授权；refresh-only写state也不是接受作者配置变化。

<a id="kubernetes-ssa-evidence"></a>
### Kubernetes Server-Side Apply

**来源与版本：** [Server-Side Apply][k93]与前述[Kubernetes API观察证据][k61]；动态官方文档，核对日期：2026-09-22。

**所读资料支持的命题：** API server在managedFields中跟踪field manager；Apply试图改变其他manager拥有且值不同的字段时产生conflict，force可覆盖并转移ownership；同值可形成shared ownership。省略字段可能放弃ownership并导致删除/default，字段schema atomic/granular变化会影响ownership语义。

**采用与不能推出：** field manager是workflow协调identity，不是Gift安全principal/Grant，也不是semantic owner。Provider的field ownership只用于精确冲突/调和映射，不能由manager字符串授予写权限。

## Package Registry发布、可移动标签与退役依据

### npm registry、dist-tags、deprecate/unpublish

**来源与版本：** [npm Unpublish Policy][k94]、[Deprecating packages][k95]、[Adding dist-tags][k96]；当前npm官方文档，核对日期：2026-09-22。

**所读资料支持的命题：** npm registry将已发布`name@version`视为不可原地改变的registry data；unpublish只在政策允许范围移除可安装记录且同名版本不能靠unpublish后重新复用。dist-tag是可移动的人类/解析alias；deprecate保留版本但给安装者警告。

**采用与不能推出：** 用于区分immutable-ish package version record、mutable tag、deprecation与withdrawal。npm具体72小时/权限政策不是Gift通用TTL；tag变化不改变artifact/version identity，unpublish也不能擦除已传播副本。

### Cargo / crates.io publish 与 yank

**来源与版本：** [Cargo Book: Publishing on crates.io][k97]；当前官方文档，核对日期：2026-09-22。

**所读资料支持的命题：** crates.io publish的specific version一般永久、不可覆盖；`cargo yank`不删除代码，而是使新的dependency resolution不选择该版本，既有Cargo.lock仍可继续工作。

**采用与不能推出：** 用于把内容可取得性、未来解析资格和当前已锁消费者分开。yank不等于远端删除，也不证明已部署消费者停止使用；owner/publish权限仍映射现有Grant而非代码ownership。
