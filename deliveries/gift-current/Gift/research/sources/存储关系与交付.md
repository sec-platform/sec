### PostgreSQL18隔离

**来源：** [PostgreSQL18隔离][k37]。

**记录日期：** 2026-09-07。

**支持的命题：** PostgreSQL18区分快照隔离与可串行化，跨行不变量不能仅靠一行条件保护；序列与事务回滚有自己的规则，序列化失败需要完整决定和写入过程重试。

**定向复核：** 2026-10-07读取同一18版13.2开头Important及Repeatable Read/Serializable相交说明：序列变化对其他事务可见，并不随发起事务中止回滚；快照隔离与可串行化的保证不同。这是[临时数据库画像][k38]必须逐效果核验的具体反例，不把所有数据库序列或DDL行为一概判同，也不因为业务事务失败而允许盲重发它曾调用的外部效果。

**采用条件与边界：** 不据此宣称团队环境已部署、所有数据库同义、跨服务共同原子或现场可靠。

## 在途尝试、去重寿命与恢复依据

本节材料于2026-09-10读取，支持下面列出的具体机制，不证明Gift Provider已实现这些能力。当前应用合同在[旧尝试关闭与可继续动作][owner-rec]的`attempt-finality-and-retry`片段；它是基于反例的Gift设计选择，不是逐字搬用某家服务。

**AWS Builders’ Library，Making retries safe with idempotent APIs。** [原文][k44]讨论带调用者身份的请求令牌、幂等记录与效果的原子处理，以及迟到请求和保留期限。采用其“相同意图须被目标真实识别”和“迟到请求仍影响设计”的机制，不推导任意HTTP API都提供该保证；文中的具体资源政策不能移植成Gift所有业务的统一结果。

**Stripe，Idempotent requests。** [原文][k45]在所述API中保存首个请求结果并比较复用键的参数，也说明至少24小时后可能清除键，清除后再次使用会形成新请求。记录的是此页所述接口行为，不把24小时变成Gift默认TTL，也不推断所有Stripe接口或版本的事务语义。本设计据此要求真实去重范围和寿命，而非只检查请求带了键。

**独立推导。** 一个权威查询在t2看不见资源，与t0发出的请求在t4创建资源并不矛盾。因此“当前没有”只是一项状态观察；自动重发还需要旧尝试已不能生效，或新旧被真正的去重/条件边界合并。具体程序、错误与资源移交见原恢复规范；没有执行远端支付、创建资源或故障注入。

## 事件信封与CI/CD事件不是业务效果证明

### CloudEvents 1.0

**来源与版本：** [CloudEvents core specification][k46]与[Primer][k47]；specversion 1.0，核对日期：2026-09-22。

**所读资料支持的命题：** `source + id`用于在producer语义下标识不同event并可识别重复重发；规范同时明确一个现实occurrence可以产生多个event，event id的其他外部含义不由CloudEvents定义。

**采用与不能推出：** 用于分离occurrence、event-record和delivery attempt；同event重复传输不是新occurrence，一个occurrence产生两个不同event也不是两次业务Effect。

### CDEvents v0.5.0

**来源与版本：** [CDEvents documentation][k48]；当前文档标release v0.5.0，核对日期：2026-09-22。

**所读资料支持的命题：** CDEvents在CloudEvents之上定义SCM、CI、testing、deployment、operations等软件交付生命周期事件。

**采用与不能推出：** 用于CI/CD外部事件映射；`build/test/deploy finished`只形成对应Provider的事件Observation，不能直接成为Gift Evidence、Gate Verdict、Artifact provenance或Effect settlement。

## 数据库工作台：metadata、plan与可写row依据

### PostgreSQL 18 information_schema 与 session identity

**来源与版本：** [PostgreSQL 18 Information Schema][k49]、[schemata][k50]、[tables][k51]、[System Information Functions][k52]；核对日期：2026-09-22。

**所读资料支持的命题：** information_schema只显示当前数据库中当前用户有权看到的对象，并且不覆盖全部PostgreSQL专有特性；current/session user、current schema与search path等会话事实会影响对象解析和权限。

**采用与不能推出：** 用于给schema introspection附principal/session/coverage；查询不到对象不能推出全数据库不存在，portable metadata也不能代替Provider-specific catalog。

### PostgreSQL 18 EXPLAIN 与 planner statistics

**来源与版本：** [EXPLAIN][k53]、[Using EXPLAIN][k54]、[Statistics Used by the Planner][k55]；核对日期：2026-09-22。

**所读资料支持的命题：** EXPLAIN展示planner针对当前statement产生的plan；cost为planner估计单位。ANALYZE会实际执行statement并带来真实side effects，同时增加测量开销。planner依赖近似statistics，statistics变化甚至随机采样都可能改变估计/plan。

**采用与不能推出：** query plan是绑定statement、parameter、stats、config、provider revision的Observation，不是源码永久属性；estimated cost不能替代可比较的wall-time Evidence。

### PostgreSQL row version、ctid与UPDATE RETURNING

**来源与版本：** [PostgreSQL 18 system-column说明（18文档PDF中ctid条目）][k56]、[UPDATE][k57]；核对日期：2026-09-22。

**所读资料支持的命题：** PostgreSQL每次row update产生新的row version；`ctid`是row version物理位置，update或VACUUM FULL等会改变它，因此不适合作长期逻辑row identity。UPDATE RETURNING可返回实际updated rows的pre/post值。

**采用与不能推出：** 用于live row editor把logical key与短期physical locator分开，并要求写后readback；RETURNING能观察该statement实际返回内容，但仍不证明事务外Effect或更广业务Claim。

## TLS服务身份、会话恢复与证书状态的补充依据

### RFC 9525 Service Identity in TLS

**来源与版本：** [RFC 9525][k58]，Standards Track，2023-11，取代RFC 6125；核对日期：2026-09-22。

**所读资料支持的命题：** 客户端先独立构造reference identifiers，再把server certificate中的presented identifiers与其匹配；RFC 9525要求DNS名通过适当subjectAltName表示/检查，并明确不再使用Common Name自由文本标识服务。它也明确service identity verification不替代完整PKIX certification path、expiry/revocation等检查。

**采用与不能推出：** 用于分离reference service identity、certificate presented identity、PKIX path和业务authorization；证书里出现名字或链可验证都不能单独形成完整Gift peer/Principal资格。

### RFC 5280 PKIX path与subjectAltName

**来源与版本：** [RFC 5280][k59]，Standards Track；核对日期：2026-09-22。

**所读资料支持的命题：** PKIX path validation以trust anchor、certificate chain、有效期、约束等验证certificate/name与public key的绑定；subjectAltName可包含DNS/IP/URI等多种identity，撤销可由CRL/status等机制参与。

**采用与不能推出：** path有效只支持PKIX范围，不决定应用reference identifier、业务Principal、授权或Effect。

### RFC 8446 TLS 1.3 resumption与0-RTT

**来源与版本：** [RFC 8446][k60]，Standards Track；核对日期：2026-09-22。

**所读资料支持的命题：** TLS 1.3把session resumption与PSK机制结合，server可基于既有连接派生并签发ticket供以后握手使用；0-RTT early data依赖PSK，RFC明确其没有TLS层天然的跨连接non-replay保证，并要求应用处理仍可能发生的重放/重试问题。

**采用与不能推出：** resumed connection不等于每次重新完成相同certificate认证过程；0-RTT加密不等于业务Effect恰好一次。应用层仍按当前identity/policy/idempotency/readback合同决定作用。

### RFC 6960 OCSP

**来源与版本：** [RFC 6960][k61]，Standards Track；核对日期：2026-09-22。

**所读资料支持的命题：** OCSP按目标certificate返回`good/revoked/unknown`状态并携带响应有效时间信息，用于取得certificate revocation/status Observation。

**采用与不能推出：** OCSP good不是服务名匹配、证书完整path资格或业务authorization；unknown/过期/不可达如何处理由当前应用和信任政策决定。实时OCSP也不是所有PKI部署永久必须采用的唯一撤销方法。
