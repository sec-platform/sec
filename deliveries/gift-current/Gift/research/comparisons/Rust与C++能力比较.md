# Rust 与 C++：能力差额、替代路线与采用条件

> 来源与比较记录；不是独立语言规格、实现完成表或“Rust 缺少 64 项”的结论。

本篇按真实要求连接来源、替代方案与条件合同。A 编号只保留已有比较条目的对应关系，X 编号保留后来发现的独立分支；条目相交不重复计成底层能力。原早期的“全部实装”与“七构件已证明最小”均不采用。正常设计先复用已有类型、库、静态展开及精确原生供给；只有存在不能消去的观察/接口/资源差额才启用附加合同。

**资料范围。** 比较字段来自 2026-09-22 研究材料的有日期记录；保留当时引用的版本与不确定性，不把保存的历史测试升级为当前运行证据。工具链 API 的 stable/nightly、目标支持与库可用性是可变事实，生产选择始终绑定实际取得的版本。本文不凭保存资料宣称全部来源已经重新访问。除条目明确记录实际实验外，所有“核验出口”都是条件验收标准，不表示对应目标程序已经执行；实际运行证据必须另行绑定主体、工具链、环境与结果。当前复核记录置于本篇末尾。

## 逐项需求、替代与设计去向

<a id="a01"></a>
### 实现继承

**需要什么：** 复用状态与行为，向共同接口传递不同实现。

**可保留的语义区别：** 存在真实基子对象、继承实现、确定的初始化／析构与替代关系；实现复用和可替代关系可以独立约束。

**Rust 已有替代（研究记录）：** 组合字段＋trait 默认方法／泛型／dyn 分派；转发可用宏生成，组合本身不必堆分配。

**剩余差额：** 没有原生基类子对象与继承式覆写规则；转发和保持同一对象身份可能需要额外设计。

**现行规范（采用与硬边界）：** [准确维护 owner][k1]；比较记录只维护研究区别，不承担规范写权。

**条件设计：** [子对象、继承与动态视图][k2]；[place、初始化、复制／转移／赋值][k3]。

**选择额外机制后可用的目标路线：** Rust：生成组合存储、基投影与必要 dispatch；不把它冒充 Rust 原生类继承。 TypeScript：生成受管对象形状与方法；prototype 只在其语义足够时使用。

**不能越过的边界：** 精确 C++ 类 ABI 另查 M14；不得隐藏额外分配。

**核验出口：** 经基视图修改状态后，派生视图观察到同一个基子对象；动态析构顺序符合合同。

**依据：** [C01][k4] [R06][k5] [I01][k6]

<a id="a02"></a>
### 多重实现继承

**需要什么：** 一个对象拥有多个有状态行为部分，并暴露多个接口。

**可保留的语义区别：** 多个基子对象分别有身份、路径、实现与访问规则；重名使用限定路径或明确 override。

**Rust 已有替代（研究记录）：** 组合多个状态字段，实现多个 trait；固定集合也可用 enum。

**剩余差额：** 多 trait 约束不是多基类子对象；基视图间转换、同名方法、整体对象借用要显式处理。

**现行规范（采用与硬边界）：** [准确维护 owner][k7]；比较记录只维护研究区别，不承担规范写权。

**条件设计：** [子对象、继承与动态视图][k2]；[名称、访问、成员投影与 opaque 类型][k8]。

**选择额外机制后可用的目标路线：** Rust：独立字段存储加有类型投影；虚调用按 owner 和效果足迹借用。 TypeScript：受管多子对象形状，而不是只链一个 prototype。

**不能越过的边界：** 同类型重复基不自动合并；不能从一个 mutable 基视图重建与其他借用冲突的完整对象引用。

**核验出口：** A、B 的状态独立；二者同名方法未消歧时报错，不按声明顺序猜测。

**依据：** [C01][k4] [R06][k5] [I01][k6]

<a id="a03"></a>
### 虚继承／菱形共享基

**需要什么：** 两条访问路径必须共享一份根状态，而不是复制两份。

**可保留的语义区别：** 同一完整对象中标明共享的基节点只有一份状态和一次初始化／销毁。

**Rust 已有替代（研究记录）：** 唯一 owner 保存 Root，两条路径借用/投影到它；需要动态共享时才选择适当句柄。

**剩余差额：** 简单复制两个 base 字段不等价；共享路径的借用冲突、动态分派及布局可能增加实现负担。

**现行规范（采用与硬边界）：** [准确维护 owner][k9]；比较记录只维护研究区别，不承担规范写权。

**条件设计：** [子对象、继承与动态视图][k2]；[place、初始化、复制／转移／赋值][k3]。

**选择额外机制后可用的目标路线：** Rust：共享基放在唯一 owner 位置，两条投影指向同一节点。 TypeScript：逻辑共享对象节点及受管视图。

**不能越过的边界：** 共享路径的独占借用互相冲突；必须保留完整对象内共享而非跨实例共享。

**核验出口：** 左右路径读写同一个计数；构造失败与正常析构中共享基均不会销毁两次。

**依据：** [C01][k4] [R08][k10] [R20][k11]

<a id="a04"></a>
### 继承的 public/protected/private

**需要什么：** 限制基类转换、接口暴露和实现细节。

**可保留的语义区别：** 继承边控制基转换的合法调用主体及是否再导出，不混同为字段本身的公开性。

**Rust 已有替代（研究记录）：** 模块可见性、私有组合、显式公开的转换/委托入口。

**剩余差额：** 不能原样表达按继承边传播的访问关系；可能改变 API 的组织方式。

**现行规范（采用与硬边界）：** [准确维护 owner][k12]；比较记录只维护研究区别，不承担规范写权。

**条件设计：** [子对象、继承与动态视图][k2]；[名称、访问、成员投影与 opaque 类型][k8]。

**选择额外机制后可用的目标路线：** Rust：Gift 访问检查后生成私有投影／合法导出入口。 TypeScript：Gift 编译域检查与导出封装；不宣称对恶意同进程 JS 形成安全隔离。

**不能越过的边界：** 外部原生接口无法隐藏的关系不能伪装成已封装；foreign 兼容规则另行固定。

**核验出口：** 同一基转换在派生内部可用、无权外部调用被拒绝；公开包装不能越权扩大关系。

**依据：** [C01][k4] [R18][k13]

<a id="a05"></a>
### protected 派生家族权限

**需要什么：** 准许外部子类访问扩展点，却不向任意调用者公开。

**可保留的语义区别：** 授权依赖派生关系、访问位置和 receiver 限制，不等于同模块可见。

**Rust 已有替代（研究记录）：** 受控扩展 trait、模块重组、私有实现包装与公开的有限能力方法。

**剩余差额：** 继承家族和 module/crate 是不同授权主体；外部可扩展家族不总能由一次改可见性替代。

**现行规范（采用与硬边界）：** [准确维护 owner][k14]；比较记录只维护研究区别，不承担规范写权。

**条件设计：** [名称、访问、成员投影与 opaque 类型][k8]；[子对象、继承与动态视图][k2]。

**选择额外机制后可用的目标路线：** Rust：前端进行派生家族和 receiver 检查，后端只接收合法投影。 TypeScript：同一前端规则，必要封装内部表示。

**不能越过的边界：** 继承一个类不自动得到对所有任意基对象的 unrestricted 私有访问。

**核验出口：** 合法派生 receiver 访问通过；用不合格 receiver 绕过 protected 的程序被拒绝。

**依据：** [C01][k4] [R18][k13]

<a id="a06"></a>
### friend

**需要什么：** 精确授权某函数/类型操作私有表示。

**可保留的语义区别：** 授权精确函数／类型／模板主体访问指定私有内容；授权身份和可否再委派有明确边界。

**Rust 已有替代（研究记录）：** 模块内协调、封装代理、由拥有者签发受限操作句柄/凭证；生成必要转发。

**剩余差额：** 可能要重组代码或新增受控入口；Rust 没有普遍的任意声明 friend 授权。

**现行规范（采用与硬边界）：** [准确维护 owner][k15]；比较记录只维护研究区别，不承担规范写权。

**条件设计：** [名称、访问、成员投影与 opaque 类型][k8]；[阶段化执行与语义反射][k16]。

**选择额外机制后可用的目标路线：** Rust：编译期检查后生成受控内部入口，不向整个 crate 额外开放。 TypeScript：编译期封装与仅需的桥接入口。

**不能越过的边界：** 名称相同或反射生成不获得 friend 权限；授权不是 OS 沙箱或跨不可信代码安全保证。

**核验出口：** 被授予的 serializer 能访问，另一个同名声明与未获权的生成代码不能访问。

**依据：** [R18][k13] [C01][k4] [C14][k17]

<a id="a07"></a>
### 虚函数协变返回

**需要什么：** 具体实现返回更具体对象，仍可经共同接口调用。

**可保留的语义区别：** 返回类型可在真实替代关系内收窄，保留借用寿命、所有权、动态析构器和接口效果。

**Rust 已有替代（研究记录）：** 关联类型处理静态情形；dyn 接口使用统一返回 trait object，具体入口另返回具体类型。

**剩余差额：** 单个 dyn 签名不能自动提供 C++ 类层级式协变；可能多一个适配入口或擦除具体类型。

**现行规范（采用与硬边界）：** [准确维护 owner][k18]；比较记录只维护研究区别，不承担规范写权。

**条件设计：** [子对象、继承与动态视图][k2]；[效果、异常与契约][k19]。

**选择额外机制后可用的目标路线：** Rust：生成适配 thunk 与合格 view／拥有句柄转换。 TypeScript：视图转换并保留动态对象身份。

**不能越过的边界：** 不扩展到可写容器的无条件协变；override 不能增加未允许效果。

**核验出口：** 基调用得到合法基视图，具体调用保留派生能力；释放拥有结果调用正确析构／allocator。

**依据：** [C01][k4] [R06][k5]

<a id="a08"></a>
### dynamic_cast 下转与横转

**需要什么：** 运行时从某接口找到同一对象的具体实现或其他接口。

**可保留的语义区别：** 基于受信完整对象、类型图、可访问和唯一子对象路径做 downcast／sibling cast。

**Rust 已有替代（研究记录）：** Any 精确 downcast；enum；显式 query-interface/投影表；可在统一对象包装中提供。

**剩余差额：** Any 不自动拥有继承图，横转和开放接口查询须登记；还要承担生命周期与表的维护。

**现行规范（采用与硬边界）：** [准确维护 owner][k20]；比较记录只维护研究区别，不承担规范写权。

**条件设计：** [子对象、继承与动态视图][k2]；[foreign ABI、C 变参、回调与卸载][k21]。

**选择额外机制后可用的目标路线：** Rust：按实例类型描述与 projection thunk 实现；不是把 Any 精确类型匹配当成完整图。 TypeScript：受管类型图与运行世代检查。

**不能越过的边界：** 不存在返回失败，路径不唯一返回歧义；不能从任意裸地址猜类型。

**核验出口：** 菱形可达 sibling cast 成功，重复歧义基和不相容类型分别给出规定结果。

**依据：** [R19][k22] [C01][k4] [I01][k6]

<a id="a09"></a>
### typeid 动态类型识别

**需要什么：** 取得动态类型身份以实现诊断、分派和受检转换。

**可保留的语义区别：** 区分声明身份、实例化类型、动态完整对象和模块世代；保留层级查询需求，而非声称 Rust 没有 RTTI。

**Rust 已有替代（研究记录）：** Any/TypeId 已提供常见用途；借用型对象可用受约束标记或静态多态。

**剩余差额：** Any 的 static 约束不涵盖任意非静态借用类型；类型名称/标签也不是自动安全 downcast 证据。

**现行规范（采用与硬边界）：** [准确维护 owner][k23]；比较记录只维护研究区别，不承担规范写权。

**条件设计：** [子对象、继承与动态视图][k2]；[foreign ABI、C 变参、回调与卸载][k21]。

**选择额外机制后可用的目标路线：** Rust：按需要生成身份与类型描述；原生 Any 可用于确实匹配的子问题。 TypeScript：受管身份，不以显示名称或 JS constructor 名称作为完整类型身份。

**不能越过的边界：** 跨插件共享身份需协议；ABI 相容不能仅靠 TypeId 相等推导。

**核验出口：** 同名不同模块类型不误认，旧世代元数据不会调用已卸载代码。

**依据：** [R19][k22] [C01][k4]

<a id="a10"></a>
### 成员指针

**需要什么：** 把字段/方法选择作为值，延迟应用到不同对象。

**可保留的语义区别：** 成员数据／方法句柄保存声明和投影语义，可包含基路径调整或动态 thunk。

**Rust 已有替代（研究记录）：** 类型化 getter/setter、函数指针、闭包、trait 投影；固定字段可生成访问函数。

**剩余差额：** 没有同一套 member-pointer 类型/运算；捕获、基调整、表示大小和可组合泛型 API 可能不同。

**现行规范（采用与硬边界）：** [准确维护 owner][k24]；比较记录只维护研究区别，不承担规范写权。

**条件设计：** [名称、访问、成员投影与 opaque 类型][k8]；[子对象、继承与动态视图][k2]；[布局、位域、padding 与 volatile][k25]。

**选择额外机制后可用的目标路线：** Rust：类型化 projection、函数表／闭包；不承诺一律等于裸指针大小。 TypeScript：成员标识和受管访问器。

**不能越过的边界：** 非字节字段、打包字段返回 proxy；不能伪造普通对齐引用。

**核验出口：** 同一成员句柄用于合法派生对象时定位正确；不合格 owner 拒绝，位域不能直接取普通地址。

**依据：** [C01][k4] [R11][k26] [R05][k27]

<a id="a11"></a>
### 不完整类与前置声明

**需要什么：** 隐藏表示、减少依赖、递归指针关系及外部不透明对象。

**可保留的语义区别：** 先建立唯一名义身份，允许句柄／指针／引用，按值布局仅在定义完整后成立。

**Rust 已有替代（研究记录）：** Rust 通常不需源内前置声明；私有具体类型、模块封装、FFI opaque 句柄与工厂/析构入口。

**剩余差额：** 真正未知大小的 foreign 类型仍有 stable 表达边界；不能按占位零尺寸进行真实对象分配或步进。

**现行规范（采用与硬边界）：** [准确维护 owner][k28]；比较记录只维护研究区别，不承担规范写权。

**条件设计：** [名称、访问、成员投影与 opaque 类型][k8]；[foreign ABI、C 变参、回调与卸载][k21]。

**选择额外机制后可用的目标路线：** Rust：不透明句柄与由真实定义方拥有的构造／析构入口。 TypeScript：不透明受管句柄；不是虚构具有某个 native size 的空对象。

**不能越过的边界：** 禁止假零尺寸外来类型及无限按值递归；无法提供布局时不生成按值 ABI。

**核验出口：** 相互指针引用可用，缺定义的按值成员被拒绝，释放由真正 owner 完成。

**依据：** [R21][k29] [R07][k30]

<a id="a12"></a>
### 函数重载集合

**需要什么：** 同名入口接受多种输入并选择具体实现。

**可保留的语义区别：** 候选域固定；自有画像按其参数、receiver、访问、约束和转换规则固定绑定。精确 C++ 输入先完成其规定的最佳可行选择，再检查所选函数的可访问性，不能先滤 private 再退选。

**Rust 已有替代（研究记录）：** 泛型函数＋trait（含 tuple 参数）、Into、不同入口名；nightly 有实验，不默认采用。

**剩余差额：** 同名多签名和 C++ 候选排序不原生；API 名称/推导/第三方参与扩展方式不同。

**现行规范（采用与硬边界）：** [准确维护 owner][k31]；比较记录只维护研究区别，不承担规范写权。

**条件设计：** [重载、receiver、转换与运算符][k32]；[特化、结构探测与静态分支][k33]。

**选择额外机制后可用的目标路线：** Rust：生成唯一符号；导出原生 Rust API 时提供实际可表达的入口，而非假同名重载。 TypeScript：明确调用绑定／运行分派；TS overload 声明本身不产生多个 runtime 实现。

**不能越过的边界：** 不可比较最优候选是歧义；后端不能再次选择，不能只依赖返回类型消歧。

**核验出口：** 同参数的不同约束只有在所选调用画像能建立严格特化关系时才唯一选择；否则保留歧义。两个分别在不同参数更优的候选也报歧义。

**依据：** [R17][k34] [R04][k35] [C16][k36]

<a id="a13"></a>
### receiver 的 cv/ref 重载

**需要什么：** 按只读/可变/消费上下文选择借用或转移结果。

### 动态浮点环境：真正漏掉的控制边界

**研究记录：** Rust x86 MXCSR 文档明确：在普通 Rust 执行域修改 masking、rounding、DAZ 等被假定为默认的状态会导致未定义行为；即使源码中未写浮点表达式，重排仍会影响。

**替代与对照：** 特殊运算全部放入一个合格 asm 块并恢复状态，或使用明确隔离的数值内核/软件定向舍入。C++/Clang 也必须使用支持动态环境的严格模式，不能用默认优化编译假设代替。

**条件与影响：** 区间算法、严格定向舍入、异常环境等需要普通表达式在动态环境下运行时，Rust 原生表达式不是透明替代；软件/外部内核的ABI、性能和可内联性需核验。

**采用决定：** 数值合同应标明格式/舍入/环境；这比添加 friend 关键字更可能改变真实结果，但仍只在相关数值操作中生效。

**归属：** [数值、SIMD 与优化控制][k107]。

**依据：** [R30][k109] [T02][k110]

<a id="x02"></a>
### 快速浮点也不能按旧印象比较

**研究记录：** Rust 1.98 稳定了 f32/f64 的 algebraic_* 操作，允许按代数性质优化；它们不因这类优化产生UB，但可能产生不同、未指定的数值结果。

**替代与对照：** 在允许误差/重排的区域使用明确操作；普通严格计算保留原顺序和特殊值合同。

**条件与影响：** 不能再声称Rust完全没有类似fast-math的控制；也不能说这等于Clang全部全局fast-math开关及浮点环境语义。

**采用决定：** 把容许的数值变化写在真正需要处，区分快速代数操作、固定ISA和动态舍入。

**归属：** [数值、SIMD 与优化控制][k107]。

**依据：** [R02][k130] [T02][k110]

<a id="x03"></a>
### 带捕获的泛型闭包

**研究记录：** C++ 泛型 lambda 的同一个 closure 对象可对不同参数类型实例化调用；该研究测试使用同一个捕获对象处理 int 与 double。

**替代与对照：** Rust 可定义带泛型方法的具名状态类型、GAT/trait策略或宏生成多态callable；普通闭包的参数类型不是任意类型量化的C++泛型lambda接口。

**条件与影响：** 交给固定原生Fn接口、跨泛型高阶函数传递且不能换协议时，需额外适配；不是“Rust不能写泛型函数”。

**采用决定：** 有高阶泛型库需求再提供相应作者抽象，降低为明确实例/策略，不默认复制全部闭包模板语法。

**归属：** [kind、参数包与常量身份][k39]；[重载、receiver、转换与运算符][k32]。

**依据：** [C17][k139] [R36][k140] [R12][k46] [L01][k60]

<a id="x04"></a>
### 表示族与条件行为

**研究记录：** C++ 类型特化可改变成员、布局和可用操作。Rust 的不重叠 impl、关联存储和条件 trait 实现已能覆盖不少按类型选择需求。

**替代与对照：** 将表示抽到关联类型，把不同策略显式编码；可按bounds条件实现Copy/Clone等允许的traits。

**条件与影响：** 修改已有泛型struct本身的字段集、默认实现再被例外覆盖、条件析构等并不是任意一致支持的统一能力；每种操作需单独检查，不能从能特化一个方法推出全部。

**采用决定：** 将真实不同表示保留为类型差异；纯优化优先交后端，不建立一个名称宽泛的万能specialization开关。

**归属：** [特化、结构探测与静态分支][k33]；[kind、参数包与常量身份][k39]。

**依据：** [R04][k35] [R05][k27] [R15][k73] [C03][k74]

<a id="x05"></a>
### 编译期临时容器与编译宿主

**研究记录：** 该研究中的 C++ 测试验证了合格constexpr函数可临时使用vector并在常量求值结束前释放。Rust常量求值可用的库协议/分配操作需逐项核验。

**替代与对照：** 数据表生成可以移到受控build步骤；小型常量计算用const fn；已知类型先生成。

**条件与影响：** host脚本不自动等于目标类型系统内的const运算；目标字长、浮点、环境依赖、错误时机和共享泛型实现可能不同。

**采用决定：** 有实际编译期算法时保留阶段和目标输入；不能仅因C++有constexpr就默认实现任意元程序堆。

**归属：** [阶段化执行与语义反射][k16]。

**依据：** [R14][k53] [R06][k5] [C02][k69]

<a id="x06"></a>
### unsafe 是证明责任边界，不是无限权限

**研究记录：** Rust unsafe 仍须遵守有效值、引用/别名和生命周期等条件；合法C++程序也不包括借UB得到的虚假能力。

**替代与对照：** 对借用检查器无法证明但可证明安全的图结构/重入/内存操作，可用raw pointer、UnsafeCell及小型安全封装；不必一律Rc/RefCell/锁。

**条件与影响：** 替代若把每次访问变成动态检查或把大量用户代码变成unsafe审计，静态保证/维护成本就发生实质变化；单靠API看起来安全不证明实现健全。

**采用决定：** 优先小而可审核的边界；不把“用unsafe就能写”当作已解决所有接口、证明和维护问题。

**归属：** [place、初始化、复制／转移／赋值][k3]；[使用点保证、目标画像与准入结果][k135]。

**依据：** [R20][k11] [R08][k10]

<a id="x07"></a>
### 原生索引代理与借用型结果

**研究记录：** Index 的固定引用结果不能普遍表达C++按值proxy，packed-bit引用只是一个例子；矩阵视图、多索引、延迟写回也可能相交。

**替代与对照：** get/set、显式借用proxy、自定义投影trait，或生成专用操作。

**条件与影响：** 公共算法必须使用原生[]/=协议时，库方案需要改接口；存储原子性、提交时机和代理寿命不能因语法糖丢掉。

**采用决定：** 作为具体容器接口判断，不把所有operator缺失一起无条件忽略。

**归属：** [重载、receiver、转换与运算符][k32]；[布局、位域、padding 与 volatile][k25]。

**依据：** [R11][k26] [C07][k50]

<a id="x08"></a>
### noexcept、无分配和有界执行不是同一保证

**研究记录：** C++ noexcept 属异常规格；函数内部仍可能执行会失败的操作，异常逃出边界会终止。它不是无分配、必终止或静态证明纯性的统一保证。

**替代与对照：** Rust可显式Result、限定可用API、panic策略/外部检查；不能拿全局panic=abort冒充相同逐函数类型协议。

**条件与影响：** 优化/泛型库可能按nothrow性质选择复制或移动；固定源接口及失败策略可能需要适配。

**采用决定：** 先保留真实错误和清理要求；不能从noexcept/contracts推导Gift必须有完整代数效果系统或一般refinement求解器。

**归属：** [效果、异常与契约][k19]。

**依据：** [C11][k113] [C10][k138] [R22][k112]

<a id="x09"></a>
### GNU computed goto、尾调用与厂商扩展

**研究记录：** GNU labels-as-values 是超出ISO C++的独立能力；Rust显式尾调用处于实验方向。各编译器对调用约定和属性的支持也有版本/目标限制。

**替代与对照：** 结构化循环、显式状态机、汇编/独立原生内核、实际后端支持的tailcall；必须看最终目标证据。

**条件与影响：** 解释器dispatch、保证栈不增长、特定ABI入口有硬性指标时，等价算法可能不等于等价分支/栈行为。GNU computed goto另有跨作用域析构风险。

**采用决定：** 先明确要求标准语言还是指定编译器；不要拿GCC扩展无标记扩大C++标准优势，也别凭优化希望宣称Rust已无损覆盖。

**归属：** [协程、取消与 CFG][k49]；[实例化、分发与链接][k59]。

**依据：** [T04][k120] [R34][k141] [T03][k142] [R33][k80]

<a id="x10"></a>
### 平台、GPU、SDK、认证/资质与工具支持

**研究记录：** Rust存在明确的目标分级；C/C++厂商工具链及GPU等扩展的可用性属于外部供给，不由语言计算完备性决定。

**替代与对照：** Rust调原生内核、复用供应商库、分阶段迁移或保留兼容岛。

**条件与影响：** 某项目实际指定的芯片、驱动接口、调试器或获准工具链不支持所需Rust路线时，这可以成为硬阻碍；该研究未逐一调查所有芯片/资质，不能宣称某个未查型号不支持。

**采用决定：** 把目标/工具版本和支持证据绑定到使用点。Rust宿主能启动一个C++内核，不等于已能用纯Rust编写同一内核。

**归属：** [foreign ABI、C 变参、回调与卸载][k21]；[使用点保证、目标画像与准入结果][k135]。

**依据：** [R32][k143] [T03][k142] [I02][k122]

<a id="x11"></a>
### 标准库之外的工程可用性

**研究记录：** 类似atomic wait/wake等能力可由独立Rust库提供；atomic-wait的支持对象、平台和超时范围需按其文档理解。

**替代与对照：** 复用合格crate/系统API，而不是为了标准库命名对称重新写轮子。

**条件与影响：** 团队只允许特定依赖、no_std目标缺系统服务、外部API固定容器、审计/许可证不接受依赖时，库方案可能不合格。

**采用决定：** 把依赖成本、支持矩阵和API可组合性当真实条件；不枚举每个C++库函数当新语言缺口。

**归属：** [分配器、资源域与 TLS][k48]；[原子值、原子视图与内存模型][k124]。

**依据：** [L07][k144] [L04][k99] [L06][k127] [R32][k143]

<a id="x12"></a>
### 构建、下游泛型和动态插件的开放世界

**研究记录：** 具体实例提前生成，可以绕开目标语言没有的抽象语法；但无法据此承诺未来所有未知原生类型都能直接调用。

**替代与对照：** 分发可继续编译的Gift语义定义、目标原生可表达的泛型、有限实例，或明确的动态字典/接口。

**条件与影响：** 三者的编译工具依赖、二进制体积、内联机会、ABI和动态元数据要求不同；运行时未知插件不能靠构建时无限猜测解决。

**采用决定：** 保留实例化/字典选择和导出边界；若需要额外编译器/JIT必须明示，不把“编译器会lowering”当万能答案。

**归属：** [实例化、分发与链接][k59]；[特化、结构探测与静态分支][k33]。

**依据：** [R33][k80] [R06][k5] [I01][k6]

<a id="x13"></a>
### 较简单规则不等于源语言兼容

**研究记录：** C++先做最佳重载选择，再检查选中函数是否可访问；private精确匹配不会被提前删掉，以便退选public的较差匹配。该研究使用 GCC 与 Clang 验证了该程序被拒绝。

**替代与对照：** Gift可自主选择不同规则；导入C++时由真实C++前端解释，或建立明确覆盖的兼容规则。

**条件与影响：** 把旧设计的“先筛访问权限”直接用于精确C++输入，会接受本来非法的程序。旧规则作为Gift自有语义可以存在，但不能被当作C++等价规则。

**采用决定：** 已解析调用可以进入中立IR；不必把完整重载决议留到每个后端。默认值、临时对象寿命、析构时机同样需要源语义归属。

**归属：** [重载、receiver、转换与运算符][k32]。

**依据：** [C16][k36] [C15][k41] [R21][k29]

<a id="x14"></a>
### 全局初始化、TLS、资源退出和动态卸载

**研究记录：** 运行期资源生命周期不只等于局部Drop。原生TLS导出、外部模块初始化/退出、在途回调和旧对象析构都可能跨越模块边界。

**替代与对照：** 普通新代码用显式初始化/关闭、受控局部状态与已选运行时；特定loader协议通过适配器处理。

**条件与影响：** 该研究未对所有平台的 loader 协议作全面调查，因此不把“C++有全局构造、Rust没有同名语法”直接算新硬缺口；真正约束是指定时机和在用代码不能先卸载。

**采用决定：** 保留旧设计的初始化环、回调注销和卸载安全案例，作为选择相应运行域时才启用的要求。

**归属：** [分配器、资源域与 TLS][k48]；[foreign ABI、C 变参、回调与卸载][k21]。

**依据：** [R26][k133] [R21][k29] [I01][k6]
