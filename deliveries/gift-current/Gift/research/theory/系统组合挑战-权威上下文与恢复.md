# 权威、上下文、恢复与演进

## 权威、上下文、恢复与演进

<a id="challenge-a16"></a>
### 命题和authority字段不是不可伪造的执行权

**问题性质：** 原规范明确已覆盖；代码字段不等于漏洞。

**触发：** 把MayWrite/Possesses/authority="authoritative"当作可以执行副作用的充分条件。

**机制与损失：** 描述某项权利的值可以复制；真实许可还有签发者、主体、范围、时效、撤销和作用点。字段存在既不能证明有安全问题，也不能证明安全边界已生效。

**研究处理：** 继续由execution/adapters在真实作用前消费受信能力，semantics描述需求，assurance评价依据。纯函数不强迫走外部授权流程。

**边界及剩余：** 只读取了FactAssertion类型等有限代码；没有审计全部权限入口，不指控已发生越权。

**规则归属：** [解释与证据接纳](../../docs/60-保证与证据/保证/解释与证据接纳.md)；[原则总纲与归属](../../docs/00-系统与原则/产品/原则总纲与归属.md)。

**研究依据：** R12、R03、R15；完整来源记录见本篇末尾。

<a id="challenge-a18"></a>
### Context不能是可变全局世界或万能缓存键

**问题性质：** 原规范已有防线；保留差分验收。

**触发：** 插件加载、观察模型更新或权限撤销后，继续使用旧“当前Context”的结论。

**机制与损失：** 解释快照、运行状态与当下准入是不同生命周期。只依赖已选成员而漏掉“全集枚举/没有候选”的读取，会在新增成员后假命中；全局序号则可能过度失效。

**研究处理：** 编译固定所需解释与真实读集；查询全集/否定读取记录集合依赖；新解释形成新候选，不热改旧EngineImage。实际权限按作用点核查。

**边界及剩余：** 摘要相同仅固定对应字节；真实性、新鲜度、支持范围另证。没有测量实际缓存行为。

**规则归属：** [语义扩展与外部定义接合](../../docs/20-语义与组合/组合/语义扩展与定义接合.md)；[协作与状态边界](../../docs/70-工程系统与演进/协作与状态边界.md)。

**研究依据：** R09、R14；完整来源记录见本篇末尾。

<a id="challenge-a20"></a>
### 所有东西都变成带证据的持久图会破坏正常路径

**问题性质：** 原规范明确反对；不要因抽象扩大成本。

**触发：** 常量、每次load、每个参数都获得EntityId/Revision/Assertion/持久证据，纯函数启动全平台。

**机制与损失：** 表示、序列化、查询、失效和保留成本可能远超原计算，还制造额外写者和删除责任。“可建模”不推出“应实体化/持久化/全局查询”。

**研究处理：** 局部表达式保留紧凑结构；公共语义摘要按需求派生；独立审查和恢复对象才保留对应记录。小任务在内存工作，不默认数据库、证明服务或守护进程。

**边界及剩余：** 没有基准测量，故不捏造开销倍数，也不宣称某个节点数就是最优。

**规则归属：** [全体系信息结构](../../docs/70-工程系统与演进/信息与生命周期/全体系信息结构.md)；[抽象与开放定义](../../docs/20-语义与组合/组合/抽象与开放定义.md)；[协作与状态边界](../../docs/70-工程系统与演进/协作与状态边界.md)。

**研究依据：** R07、R08、R14；完整来源记录见本篇末尾。

<a id="challenge-a22"></a>
### 旧快照改名、重新打hash不等于语义迁移

**问题性质：** 原规范已有防线；先前固定修订的差分提供历史证据。

**触发：** 升级规则后用新解释器读取旧声明并沿用旧证明；或只据路径404判断能力消失。

**机制与损失：** 旧事实的意义、引用、上下文和证据可能绑定旧版本。先前候选修订7685c73e…把fact-types.ts搬到semantics新路径，blob仍与main相同，表明位置变化和语义改变不能混淆。

**研究处理：** 准确比较main、候选和实际blob；新格式候选需要明确读取/映射/重核路径。无法补出的旧假设保持未证；老运行/外部未结算操作保留原身份，不随新源码撤销。

**边界及剩余：** 该研究没有修改或推送任何分支，也不证明整个迁移已经完成或候选可以合并。

**规则归属：** [协作与状态边界](../../docs/70-工程系统与演进/协作与状态边界.md)；[全体系信息结构](../../docs/70-工程系统与演进/信息与生命周期/全体系信息结构.md)。冻结 fact-types 只作为该历史修订的实现定位证据。

**研究依据：** R14、R07、R19、R20、R21；完整来源记录见本篇末尾。

<a id="challenge-a23"></a>
### 统一Failure/Behavior不能覆盖真实恢复状态

**问题性质：** 原规范已有防线；必须保留运行交接。

**触发：** 超时或取消后重放外部请求，或把整个失败操作当可逆状态迁移。

**机制与损失：** 真实效果可能已发生但回执未到；补偿不是原操作的数学逆，旧任务仍可能占资源。已证安全、任务结束、设备停止、内存可释放是不同事实。

**研究处理：** 复用原操作身份、前像、幂等/查询能力、分项回执与恢复协议。没有真实提供者保证时报告未结算，禁止用新的规范版本改写过去效果。

**边界及剩余：** 没有真实远端/设备测试；这里不是新增分布式事务产品路线。

**规则归属：** [协作与状态边界](../../docs/70-工程系统与演进/协作与状态边界.md)；[组合前提与进展闭合](../../docs/30-实现解析/组合前提与进展闭合.md)。

**研究依据：** R14、R13；完整来源记录见本篇末尾。
