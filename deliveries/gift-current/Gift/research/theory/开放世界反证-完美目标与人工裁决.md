# 完美目标、不可达与人工裁决

## 不可满足的完美目标与最大诚实保证

### 不可同时兑现的承诺

下列目标作为愿景有价值，但不能同时成为对开放任意工程的无条件产品保证：

```text
发现全部问题
理解全部语义
找到唯一全局最优架构
保证任何未来变化只需局部修改
证明系统绝对正确
自动处理所有冲突
零失败、零泄露、零停机、零误判
对所有主体公平
无限扩展且没有治理成本
```

这些措辞作为无条件验收要求时，存在隐藏未知、扩大假设、伪造精确度或把未满足状态包装成“已设计”的风险；是否确有不可满足或冲突，仍需针对具体条件给出依据。

### 最大诚实保证

下面是诚实与作用边界的不变量，不是已经证明存在唯一的“最强保证”，也不是Gift的全部产品目标。具体工程仍应获得有用的定义、生成、修改与交付能力：

> 对一个明示目的、模型组合、观察切面、故障模型、资源预算、法域、权威、风险包络和有效期，系统不会把未知、冲突、不可判定、无解、未执行、未结算、未验证或越权状态伪装成成功；在允许产生效果时，能够追溯决定、限制影响、读回现实、恢复失败并在假设变化后重开结论。

### 条件化保证结构

```text
Guarantee = {
  claim,
  subjectAndPurpose,
  modelCells,
  observationCuts,
  assumptions,
  dependencyEvidence,
  failureAndAdversaryModel,
  resourceAndTimeBounds,
  authorityAndJurisdiction,
  verificationEvidence,
  physicalValidation,
  validityHorizon,
  residualUnknown,
  falsifierAndReopen
}
```

上述是保证可能需要的字段角色，不要求所有纯函数填写完整世界模型。缺少当前声明确实必要的依据时，保留该声明的未知、条件或未满足状态并说明取得方式；已有明确来源的缺省可依法解析，但不能伪造观察和权威。较弱声明可以作为附加结果单独给出，不能以“降低等级”静默改写任务原本要求的保证。

### 完美的不同含义

| “完美”含义 | 可达性 |
| --- | --- |
| 在有限形式域内证明满足全部约束 | 可以，需闭合模型和证明 |
| 在明示候选空间和目标函数内找到最优 | 可以，需有界可判定 |
| 对声明故障模型实现容错界限 | 可以，需满足模型前提 |
| 对开放现实绝对无错 | 不可保证 |
| 对所有未来工程保持同一根架构 | 不可保证 |
| 同时满足所有主体全部偏好 | 通常不可保证 |
| 消除全部可信根和假设 | 不可保证 |
| 证明未知问题不存在 | 一般不可保证 |

<a id="产品行为"></a>
### 请求诊断候选

这份研究提出以下请求诊断候选，适用于已经有具体依据表明目标冲突、不可满足或证据不足的情况：

1. 分解请求中的不同完美含义；
2. 识别可形式证明的有限子域；
3. 给出不可能性、冲突或未知的证据；
4. 说明哪些约束可放宽以及代价；
5. 给出可逆实验或低风险子问题；
6. 输出当前范围内有依据的保证、未决与可继续路径；不把未找到更强保证称为已经证明最大；
7. 保留拒绝和重开条件。

### 防止“诚实边界”成为保守借口

未知应标记可用处理途径及前提：新增观测、限制输入域、形式证明、统计实验、有权主体作规范选择，或在可观测且反应来得及的条件下用运行控制限制危害。这些方法可并用，不构成互斥穷尽分类。

理论上可能补证不等于当前预算、权限或时间内可完成。所选输出必需保证尚不满足时，可以返回待补证、超预算或对该输出拒绝；不能把“可以研究”当作立即执行危险效果的许可。独立可交付的安全子域仍应完成。拒绝说明具体障碍、已完成部分、可改变条件和重新准入要求，不把类别不可判定当作当前实例无解。

<a id="终局标准"></a>
### 保证与演进的检查条件

评价架构的保证与演进能力时，可检查：

- 清楚知道每个结论为何成立；
- 清楚知道哪些结论无法成立；
- 能在边界内尽可能强地证明；
- 能在边界外拒绝伪造确定性；
- 新事实到来时只推翻真正依赖它的结论；
- 根假设被推翻时敢于重建整个受影响模型；
- 保证承诺不超出物理、逻辑和相关主体权利边界。

## 辅助设计的不可达结果与人工裁决

### 目的：辅助设计的不可达结果与人工裁决

本候选代数用于辅助设计与高风险动作准入的具体诊断。不同失败原因应保留，但不要求普通源码生成预先证明全部安全性质。结果是否阻断取决于所选输出、必需声明和效果范围。

### 辅助设计结果候选

```text
DesignExplorationOutcome =
  | VerifiedSolution {
      definitionRef,
      solutionRef,
      assuranceRef,
      validityEnvelope
    }
  | BoundedCandidatePortfolio {
      candidates,
      dominance,
      bounds,
      unexploredFrontier
    }
  | ExperimentRequired {
      informationGap,
      safeExperiment,
      valueOfInformation
    }
  | HumanDecisionRequired {
      normativeConflict,
      authorizedDecisionProcedure,
      safeDefault
    }
  | Infeasible {
      unsatCore,
      nonRelaxableConstraints
    }
  | NoGeneralDecisionProcedure {
      propertyClass,
      knownBoundaryRef,
      perInstanceEvidenceOrUnknown
    }
  | ResourceBoundedUnknown {
      partialResults,
      lowerUpperBounds,
      resumeContract
    }
  | ObservationInsufficient {
      missingCoverage,
      safeObservationPlan
    }
  | CoordinationUnattainable {
      failure/synchrony assumptions,
      conflicting guarantees
    }
  | AssuranceInsufficient {
      openAssumptions,
      TCB/frontier,
      missingEvidence
    }
  | NormativeConflict {
      authorities,
      rights/constraints,
      jurisdiction
    }
  | IrreversibilityUnacceptable {
      potentialLoss,
      missingRecovery,
      acceptingAuthority
    }
  | ArchitectureRefused {
      refusalReasons,
      minimumConditionsForReopen
    }
```

### ArchitectureRefusal

拒绝条件不是随意阈值。至少包括：

```text
ArchitectureRefusalReason =
  | ImpossibleRequirementSet
  | UnboundedUnknownOnIrreversibleEffect
  | NoLegitimateDecisionAuthority
  | UncontrolledCrossDomainCoupling
  | RecoveryPathUnprovable
  | SafetyEnvelopeUnavailable
  | StrategicManipulationDominates
  | GovernanceComplexityExceedsBenefit
  | TrustRootUnclosed
  | RequiredCoordinationImpossible
  | PreservationContractUnavailable
  | PhysicalAssumptionsUnacceptable
```

<a id="拒绝后的产品行为"></a>
### 拒绝诊断的候选输出

拒绝不能只输出一句“做不到”。必须给出：

- 最小冲突或不可达证据；
- 哪些需求可保留；
- 哪些条件若放宽可重新打开；
- 是否存在低风险子问题；
- 是否可以只读观察；
- 是否可以做可逆实验；
- 人工或制度裁决需要什么材料；
- 当前最安全状态；
- 可能的系统拆分方案。

### 人工裁决不是万能兜底

`HumanDecisionRequired` 只用于真正不可推导的规范选择。人工不能：

- 使不可实现需求变得可实现；
- 使物理未知消失；
- 用签字代替权限或安全控制；
- 把未执行测试变成通过；
- 接受他无权代表主体的风险；
- 取消法律和基本权利边界；
- 证明未知外部效果未发生。

### 决策材料

```text
HumanDecisionPacket = {
  exact question,
  affected stakeholders,
  candidate portfolio,
  hard constraints,
  irreducible tradeoffs,
  risk envelopes,
  unknowns,
  reversible options,
  dissenting assertions,
  authority and jurisdiction,
  expiry and appeal
}
```

禁止把数百页文档直接推给人类并称为知情批准。

### 安全默认值

按效果分类：

| 效果 | 默认 |
| --- | --- |
| 纯只读、低披露 | 可降级执行并显示未知 |
| 可逆局部变更 | 可做隔离实验 |
| 可补偿外部效果 | 需要 compensation 与读回 |
| 不可逆高损失 | 未闭合则拒绝 |
| 法律/权利冲突 | 保持最小披露和最小效果，交合法裁决 |
| 协调不可能 | 缩小一致性范围、延迟或人工协调 |

### 结果的可组合性

一个子问题 `VerifiedSolution` 不得覆盖另一个子问题的 `Unknown` 或 `Refused`。组合结果按最强阻断关系计算，并保留局部可用能力。

```text
CompositeOutcome = {
  usableSlices,
  blockedSlices,
  crossSliceConflicts,
  overallEffectCeiling
}
```

### 重开协议

每个不可达结果给出：

- 新信息；
- 新能力；
- 约束放宽；
- authority 变化；
- 安全包络；
- 外部系统升级；
- 可逆实验；

中的哪些变化可以重新编译。没有因果变化不得无限重试同一求解。

<a id="验收辅助设计的不可达结果与人工裁决"></a>
### 候选检验：辅助设计的不可达结果与人工裁决

- 所有不可达状态是稳定机器类型；
- UI/API/CLI 保留它们，不映射成 generic error；
- 无解声明提供可检查的不满足证据；只有执行并通过最小化检验时才称最小冲突；
- 超预算保留进度和界限；
- 人工包有最小充分信息；
- 拒绝不阻断无关低风险切片；
- 拒绝和未知不能被 override 静默改为成功。
