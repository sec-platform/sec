# 领域研究语料

> **研究输入，非现行规范。** [采用、证据与保全边界](../README.md#research-use-boundary)。

本目录保存**非权威的领域研究输入**。游戏、仿真、金融、医疗、制造、科研等材料用于扩展问题空间、寻找反例、比较失败方式和发现公共机制可能遗漏的区别；它们不是 Gift Core 的业务目录、Standard Semantic Module 清单、默认 Profile、Provider/Target 列表、行业 SDK、行业运行时、支持声明或必须执行的测试套件。

一个领域在这里被分析得很深，只证明它曾作为研究对象；不证明 Gift 已实现、发布、验证或承诺支持该领域。具体业务对象、政策、算法、模型和产品配方由作者工程、库与真实 Provider 拥有。研究材料不能给自己签发 `gift.*` authority，也不能因为“很多行业都出现”就直接晋升 Core。

本目录保留两类信息：一是广度研究，用于提醒尚未考虑的对象、生命周期、现实边界和利益主体；二是深度材料，用具体模型、失败方式和专业条件追踪机制差异。真正脱离行业名称后仍会改变合法性、编译、运行、恢复或 Evidence 结论的稳定区别，才提炼到[跨域区别见证](../../docs/60-保证与证据/验收/跨域区别见证.md)；公共机制是否因此升级仍由[核心提升规则](../../docs/70-工程系统与演进/演进与实施/作者定义组合与核心扩展.md#core-promotion-rule)裁决。

需求发现、机制覆盖和接合边界的通用方法已经移到 `docs/00-系统与原则/设计方法/`；完整产品形态的组合研究位于[组合研究](../../fixtures/compositions/README.md)。这里不以文件数量、领域数量或场景数量作为产品覆盖率或支持度。

## 开放 Decision owner / facet 的领域压力映射

本表只攻击开放 DecisionDescriptor 与现有 semantic owner 是否漏掉独立跨域责任。行业对象和规则仍由作者 Definition 拥有；主题词只作研究检索，不建立第二份领域规范、中央 taxonomy 或产品支持声明。

| 场景簇 | 高频工程责任/研究主题 | 典型 domain/mechanism facet | 为什么不新增行业 Core 类型 |
|---|---|---|---|
| 语言工具与系统基础 | 工程身份、行为合同、资源寿命、Target/ABI、Build、依赖供应链、发布分发、开发维护、Assurance | 声明/类型、编译转换、ABI、包构建、OS/设备 | “编译器/IDE/OS”是产品类别；具体决定已分别落入语言/目标/资源/发布等责任 |
| 数据智能与安全 | 数据身份、信息谱系、持久化、分布式、安全隐私、治理合规、可观测、Assurance、AI治理 | 数据查询、学习系统、密码、隐私、来源证据 | dataset/model/AI不应成为一个万能设置；数据来源、模型策略、权限和评测分别决定 |
| 应用交互与内容 | 产品交互、接口协议、文本/名称、配置资产、时间、性能、安全、发布分发 | UI输入、渲染、媒体信号、文档出版 | Web/mobile/media共享交互/资产/协议等机制；framework/codec留Supply/Target |
| 游戏、XR与在线平台 | 状态工作流、时间随机、并发流、资源寿命、分布式、性能、安全/Safety、运行部署 | 渲染、音频、simulation tick、prediction、device resource | ECS/rollback/GPU不是所有游戏前置，更不是 Core 类型 |
| 商业价值与组织流程 | 数值单位、状态工作流、持久一致、故障韧性、安全、治理合规、接口、信息谱系 | 账本、预占、匹配、履约、人工交接 | Order/Payment/ERP是领域 Definition；守恒、幂等、权限等区别回已有 semantic owner/Requirement |
| 健康研究与公共责任 | 信息谱系、数值单位、Safety风险、安全隐私、治理合规、Assurance、演进兼容 | 传感校准、学习系统、危害、人工责任 | 临床/法律语义留领域；患者身份、单位、同意、证据、法规分别有owner |
| 物流交通与自主设备 | 状态工作流、时间并发、分布式、资源、性能、Safety、运行部署、信息谱系 | 空间几何、传感校准、控制执行器、路由规划 | 机器人/航空/芯片不升级成 Core 分类；设备/路径/安全等 Decision 由各自 owner 独立控制 |
| 工业能源与环境 | 数值单位、信息谱系、状态、Safety、治理合规、性能资源、运行部署 | 测量校准、物理制造、过程控制、仿真 | 物料/工艺/能量是领域Meaning；校准、危害、寿命、来源分别保持 |
| 空间设施与个人服务 | 数据身份、数值单位、信息谱系、状态流程、Safety、安全隐私、产品交互 | 空间几何、BIM、传感校准、人类流程 | CRS/拓扑通过facet保持专业语义，数值/来源/权限不被`GIS`标签吞掉 |
| 科学仿真与开放系统 | 数值单位、时间随机、行为合同、信息谱系、性能、分布式、Assurance、Safety（有现实接合时） | 方程求解、仿真推进、实验因果、空间几何、HPC | 模型/solver/experiment是领域Definition与Supply；误差/随机/证据/现实作用仍分责 |

这张研究映射有效的条件不是“每格有几个词”，而是具体场景中的每个独立 Decision 都能取得 A 轴语义类、B 轴 authority、C 轴阶段、D 轴 setting scope（若适用）、真实 semantic owner / descriptor 与必要 facet。若只能靠 `other`、自由 JSON 或行业名字才能保存一个稳定可观察区别，视为语义/descriptor 缺口；若只是现有 UI 没有合适分组，只是 presentation 缺口，不修改 Core。

目录中的关联是发现和检查方向，不是必需依赖。一个场景的有效内容由本身的任务/独特需求与所在领域的对象、不变量、失败恢复和验证共同组成；跨领域深场景另保留其具体输入、输出与规范入口。不得只读取叶子名称就声称完整理解，也不能把所有关联机制并集当作最小部署。
