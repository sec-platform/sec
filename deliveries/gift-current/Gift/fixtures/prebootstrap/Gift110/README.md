# Gift110 泛型最长前缀作者样例（历史研究说明）

这两个模块是已有 `gift.author-module/1` 和 `gift.semantic-body/1` 的设计输入，使用公开JSON构造，不引入业务kind。`span-prefix.module.json` 定义 `spanWhile<T>` 的完整递归主体；`span-consumer.module.json` 从另一个模块导入并转用它。

意图：将有限序列拆成最长满足谓词的前缀和原后缀。第一次false后不再求值谓词；未访问元素是否会Fault/不终止不能改变已决定结果。T不需要相等、哈希或数值能力。纯谓词不自动意味着总函数；所访问调用的失败和进展继续继承。

输入 `[1,2,0,3]` 与 `x>0` 的观察应为 `prefix=[1,2], rest=[0,3]`，调用轨迹 `[1,2,0]`。filter或partition不是替代实现。空输入不调用谓词；全true输入调用每个元素一次并返回空后缀。

这些模块没有真实项目依赖锁、生产解释映像、合格Target绑定或编译运行结果。跨模块引用的声明完整性可检查，但这不等于生产类型/效果检查通过。具体阶段对象、负例和目标表示见 [完整施工轨迹](../../../docs/70-工程系统与演进/工程构造手册/14-完整工程交付与故障验收.md#prefix-example-and-failure-traces)。
