# Gift116：从一次性计划到可重复运行的本地意图模型应用（历史研究说明）

本文记录 **Gift116 的本地重规划实验及验证边界**。不生成第二份“精简工作集”，不改变原 Gift112/113 的有限 JSON 作者输入，也不覆盖 Gift114 历史单次装配样例。生成工程是临时目标产物，**不是第二份可编辑作者源**。

## 原实验声明的有限能力

- 从既有 `gift.author-module/1`、Meaning Library、MethodSupply、显式 `gift.finite-model/1` 读取输入；支持一个模块内多个 `intent:goal`、多个模块和多个意图的联合约束。
- 编译时冻结已检查的类型/Meaning、全部相关有限方法和源码摘要，**不提前冻结唯一的执行步骤**。每次业务操作可以重新选择方法。
- 生成严格 TypeScript / Node `node:sqlite` 应用；`init` 原子建立初始本地模拟模型；`plan` 只读检查当前版本；`apply` 在 `BEGIN IMMEDIATE` 后读取存量事实、有限搜索、逐步检查**所有意图的维持/禁止条件**，再一次事务写对象、状态修订和操作回执。
- 同一操作 ID 与完全相同请求重放不会重复作用；同一 ID 不同意图选择或不同 `--expect` 版本被拒绝。预览与提交之间的版本变更可以用 `--expect` 显式阻断；没有 `--expect` 时根据事务内最新状态重新规划，不使用先前的预览。
- `status`/`plan` 使用只读 SQLite 打开，并在一个显式只读事务内读取状态、修订与回执；并发写者提交不能让同一次查询拼接两个修订。不会偷偷初始化数据库；初始所有对象的身份集合被固定。防止非本运行器私改数据后旧状态摘要继续使用，但 SHA-256 **不是签名或数据访问控制**。
- 无可行解、限制耗尽、前提未知、缺方法、初始安全失败等状态分开。预算有限时，`NoPlanInSuppliedFiniteModel` 只表示已穷尽**这次所给的方法/状态/深度**，不表示业务目标在现实中绝对不可能。

项目根目录

注意上例的共享容量来自离线样本，**既不是现实医院也不是 GPU 服务账户**。示例的两次操作分别将模型占用从 0 改成 1、从 1 改成 2；持久修订为 2。容量只有 1 时，两次操作只能有一个成功；并发写者仍由 SQLite 同一个写事务串行化。省略意图 ID 时，选择全部已编译意图。为新意图定义/新模型重新编译到新空目录，不能原位覆盖现存生成代码。

## 原实验核验范围

测试用真实独立 Node 进程、`tsc --strict`、磁盘 SQLite、Python 原生 SQLite 客户端作直接读回；包含不同业务领域、不满足需求、预览不写、后继两次提交、版本 CAS、幂等/冲突、两个并发写者、触发器故障回滚、状态/合同篡改与四组独立 Python 规划器对照。可通过 `GIFT116_NODE_TYPES` 指向已经装好的 Node typings。**没有互联网联网、云执行、Docker 或真实外部业务效果。**

### 未有资格的能力

作者角色与对象身份仍来自静态 JSON；运行时不能从网络接纳任意新业务实例，不能添加/删除对象，也不接受新的 Meaning、动态角色绑定和新 Provider。形式约束只支持该有限谓词/局部编辑；`oblige/permit/prefer`、未来时序、真实权限、分布式事务、工作台、生产 Rust Kernel、C0—C3 自举都未实现。旧工程数据库不作自动迁移；新 profile 用单独的 `gift116_*` 表，遇其他拥有者的数据库会拒绝初始化。Node 22 的 `node:sqlite` 不能代签生产吞吐、安全和长期稳定性。
