# IDE 降低与目标布局压力样本

> **角色：非权威组合研究。** 本页保存一个工作台型产品如何把具体搜索/编辑/保存要求落实为私有状态、恢复关系与目标工程责任的深度样本。它用于研究 Gift 的通用 Requirement、RealizationMethod、共享主体、Target、Artifact 与恢复合同能否承载这类产品；不是 Core 的固定降低算法、固定方法路线、IDE 模板、目录模板或产品支持声明。现行通用 lowering 由[编译内核与生成][k1]拥有；工作台具体 Requirement/方法样本见[IDE 需求规则与供给样本][k2]。

## 一条真实需求如何变成目标结构：FrozenEdits

源`require search.Replace {... preview: search.DisplayedEditsOnly, acceptance: search.DisplayedPlan, stale: search.Reject ...}`约束行为而非调用顺序。绑定后形成：同一文档主体、搜索来源、选中范围、准确快照、替换表达式/策略版本、禁止用可变输入框重算、最后修改前的版本条件和逐项恢复义务。

“安全替换”实现方法消费这些条件，在目标侧引入以下私有结构，不要求产品源中出现它们：

| 目标内部实体 | 最少保存及其用途 |
|---|---|
| SearchSession | 查询代、范围/覆盖、取消与真实任务引用，判断旧结果是否仍可发布 |
| TextSnapshot | ResourceKey、模型实例、版本、编码/坐标及完整文本依据；不拿预览片段代替源 |
| ReplacePlan | plan身份、精确选中编辑、快照集合、策略/替换表达式版本、前后像与适用范围 |
| PreviewLease | 实际显示的plan及接受代；展示被替换/撤销时不再批准旧可见性 |
| ApplyAttempt | 原意图、目标前提、各资源编辑/保存状态、在途尝试与恢复所需引用 |

具体化规则是：取得相同模型实例的稳定快照；在其坐标上计算替换并检查重叠/零宽；封存计划；用计划渲染；接受绑定这个计划；在真实最终编辑边界检查并施加版本化编辑；逐资源保存及查回。若宿主没有可保持该边界的操作，返回“安全替换”方法的资格缺口，不在文件名里加safe后就生成成功。

模型编辑成功但保存失败时，恢复对象只尝试合格保存，不再重放替换。历史恢复流程仍按旧尝试是否可能晚到处理，不能由“现在未见效果”直接重发。此处消费原恢复规范，不复制成第二算法。

## 源字段变化怎样驱动生成，而不是再次手改流程

将同一源中的`stale: search.Reject`换为`search.RebuildThenConfirm`，意味着：旧计划不可写；重建当前计划并重新显示；取得对新计划的新接受后才允许写。“安全替换”方法需要额外的重建/重显示迁移和消息；旧接受不能批准新计划。搜索算法和文档模型如仍合格则不重写，改变的策略进入其实际缓存键。

若改成“每个已选资源都必须全部保存成功，否则对任何观察者都没有变化”，普通跨文件提供者不具备该事务范围。编译器报告目标能力/合同冲突，不能退回分项保存再报原强要求完成。此变化属于任务含义，不是编译优化。

## 目标工程的完整形状

允许整套成熟工作台总成保留其原文件布局，或在合格独立组合路线生成以下逻辑责任；**这不是要求每条require恰好生成一个文件**：

```text
output/
  package-and-build/       精确依赖、构建配置、平台入口及许可
  application/            启动、能力注册、完整工作台装配
  workspace/              根、资源、模型、快照、保存与恢复
  editor/                 编辑视图、选区、撤销、命令适配
  search/                 查询、结果、预览计划、版本化应用
  language/               服务桥、诊断、辅助和重构
  execution/              任务、终端、测试和调试
  integration/            版本控制及扩展能力/隔离
  interface/              工作台布局、焦点、主题、消息与无障碍
  provenance/             需求到成员/规则/依据的派生映射
```

### 差异压力：目标代码与调试映射的保密/精化压力

源函数可转换为目标源码不代表公开调试包可以携带私有绝对路径；SourceMap保存真实双向定位但导出时要按披露资格裁剪。编译变换重排有相交副作用的表达式时，即使目标运行同样显示UI，也需保持原错误和效果顺序。

**对应公共合同（本页不取得定义权）：** [外部材料、作者私有源码与可复现定位的隔离](../../docs/10-作者与输入/作者源/工程源/资产与非源码.md#gift-source-scope-privacy)；[跨目标变换保留可观察轨迹，而非只比较返回值](../../docs/40-目标与制品/目标/具体降低与目标输出.md#gift-target-trace-refinement)。本段是条件情景和可反驳的预期，不是已执行的产品测试。

## 样本如何被使用

该样本中的 `SearchSession`、`ReplacePlan`、`PreviewLease`、目录名字和 “安全替换”方法 都是**这个压力实例的实现选择**。符合相同公开 Requirement 的另一实现可以使用完全不同的私有状态、文件布局、成熟总成或 Provider，只要其公开主体身份、时序、失败、恢复、作用和 Evidence 合同保持成立。反过来，即使某个目标工程恰好有相同目录，也不能据此获得这些 Requirement 的资格。

若该样本暴露出通用 compiler 无法保持的区别，应先给出区别见证，再修改对应 canonical owner；不得把样本中的某个对象名、目录或方法编号直接提升进 Core。
