# 运行、资源与跨实现调用

## 计算构建运行与观察的复核切点

方法设计使用以下独立输入与允许结果，当前没有执行这些实验：

| 切点 | 预期处理 |
|---|---|
| 只有源码artifact，却请求一个不可用的执行入口 | 返回构建/Runner缺项，不猜脚本执行 |
| 目标工具缺依赖而当前禁止下载 | 保留源码与缺项，不改源或自动联网 |
| requestId同而artifact/输入变了 | 在作用开始前冲突，不重复执行新内容 |
| 完成后响应丢失 | 读回真实原操作；保留窗口已失效时按合同明确不确定，不冒称原身份恢复 |
| 输出被取消但设备仍在使用输入 | 等停止/隔离后释放；有界等待后保留未结算 |
| 间距变化而旧图结果迟到 | 最新组合只采用同图/参数基础，旧结果不覆盖 |
| 已删除的优化中间量被请求 | 返回不可用；观察变体的再次执行独立记录 |
| 观察摘要只采样前100项 | 明确样本范围，不能推断全数组无NaN或值域合格 |
| probe超预算而目标仍正常运行 | 停止观察并标缺口，不把目标返回值改成通过/失败默认 |
| 带观察的运行慢于原版本 | 记录真实制品和方法，不作为无观察性能的直接等价证据 |
| 图标签包含标签字符、重复边或空图 | 正确编码、保留出现；空图产生约定空结果，不创建虚拟节点 |

成功路径同样要复核：可以不保存工作区而构建隔离制品并运行；已拥有合法数据和权限的普通函数不需要数据库、消息、人工审批或全历史证据图。不同Runner的已验证机制按真实范围复用，只对Gift新增转换与接合增加检查。

## 局部控制、资源寿命与即时运行的有限验收

当前验收对象是精确语言修订、结构方法与所选目标，不执行未授权产品试验。书面预期如下；实际实现时核独立结果和错误路径，不能只比较同一错误生成器的两份输出。

| 情形 | 预期与必须观察的区别 |
|---|---|
| while条件首次false | 主体不执行；初始化已经发生的作用保留 |
| gcd(48,18)与gcd(0,0) | 按局部赋值合同分别返回6和0；不强迫编译期求完未来参数 |
| 内层continue与break | 仅作用于同函数最近循环；清理本轮域，不清理仍在用的外层资源 |
| lambda内return | 只结束lambda，不提前结束调用者 |
| set右值故障 | 原槽不改变；已发生的外部作用不回滚 |
| 同一个可变槽被两个闭包捕获 | 共享真实位置；先复制为let再捕获则保持快照 |
| let引用可变对象 | 不能重绑定let，但可执行该对象公开合法修改 |
| acquire失败 | body不运行，close不调用 |
| body与close都失败 | 主体错误保留，并报告清理失败与真实未结算责任 |
| Borrow从作用域经闭包或容器逃逸 | 静态拒绝或返回当前分析缺项，不以GC保持安全 |
| 数据改变但程序未变 | 可复用程序制品，不能跳过有作用运行或混用旧输出 |
| eval候选有错误或解释缺失 | 不运行；只保全准确分析和输入，不回退latest |
| 旧compute-run收到源码产物 | 拒绝该调用形态；只有明确eval分支可准备候选 |
| src改名或同目录混合语言 | 依实际源范围和锁解释，不按目录改语言/权限 |
| 本地模块加入第二消费者 | 不要求公共注册中心或自动下载；公开合同和真实依赖可直接消费 |

目标为硬无GC、锁自由、MMIO或指定ABI时，分别核这些要求；普通JS结果相同不证明它们成立。微分、流和对象中的资源依赖使用同一拥有合同，但各自数值、顺序和终态仍独立验收。

## 跨实现调用、条件方法与资源退出

以下为产品实施时的书面验收条件，不是已运行通过的测试。绑定实际源码、目标ABI、驱动、运行环境、输入和方法，分别使用受控调度、边界输入、资源工具和实际结果检查；有限文档模型不代替真实原生并发。

| 初态与扰动 | 正确结果与观察 | 需要排除的反例 |
| --- | --- | --- |
| 原生函数在start返回前回调成功 | 先登记的槽接纳结果，start帧退出前不释放上下文 | 先调用后登记导致未归属结果或悬空回调 |
| 完成值已公开，但回调栈尚未退出 | 允许使用有效结果，仍持有活动帧所需引用 | Promise完成就释放所有环境 |
| 取消成功而native/设备仍可能访问 | 停止新发布并继续保护缓冲，等真实关闭/隔离/移交；确认不再回调的驱动按终态事实结算，仍承诺完成回调的驱动等待它 | 超时或取消标志代替停止，或永久等待协议已保证不会发生的回调 |
| 一份池化缓冲的小切片交给工作器 | 仅授权范围跨界，不能转移则拷准确切片 | 把整个池复制导致额外披露 |
| 两个视图共用一个ArrayBuffer | 转移和别名资格按实际分配共同处理 | 移一个包装对象后继续读另一个失效视图 |
| 已pin的缓冲被另一个别名写入 | 拒绝只读借用假设或建立真实排他/同步/快照 | 活对象等于不变快照 |
| 两份inout参数有公开可变别名 | 保持别名与操作次序，无法保持不独立拷贝冒充 | 复制后正常值相同就说等义 |
| 负步长非空视图 | 精确计算lo/hi且验证布局、对齐、来源 | 仅offset+length验证遗漏低地址访问 |
| 空维、巨大维数或宽度乘积溢出 | 空值不解引用但仍核元数据预算，乘积在窄化前检查 | 空域绕过解析预算或溢出后小长度通过 |
| 只读零步长广播被用于写出 | 需要真实重复写/聚合含义，否则拒绝或合法正规化 | 把同地址当多个独立目标 |
| 两个稀疏视图包围区间相交 | 允许精确分析，否则保守处理 | 包围相交当成已证明实际别名或反向无别名 |
| Wasm调用中发生memory.grow | 按实际种类刷新视图和代际并复核 | 沿用已失效固定ArrayBuffer |
| i64边界内端点差超过i64 | 使用安全关系比较，结果仍正确 | 比较器用相减溢出导致顺序错误 |
| 业务合法端点超过i64 | 走已绑定G，不截断、不报业务输入非法 | 为满足F悄悄缩小输入域 |
| 大整数与较早反向区间同时出现 | F/G都保留原最早反向位置 | 先排序或按guard拒绝掩盖原错误 |
| 原实参有计数getter | 先按原顺序捕获一次，g与分支消费同一值 | guard和F分别求表达式两次 |
| g超时、缺事实或抛缺陷 | 按准确故障/未知处理，不隐式等于false | catch所有错误自动走G |
| 常时间接口按秘密值选择快慢路径 | 需真实合格轨迹保证或统一方法 | 纯结果正确代替非干扰 |
| F运行中修改输入后失败 | 保持原尝试/资源和恢复，不在半修改输入上重算 | 改方法名字绕过去重 |
| 纯隔离F失败但原输入仍有效 | 在预算和旧占用保护下可合法重算G | 把所有回退一律禁止或一律允许 |
| 同步库只有异步F | 保留G或其他同步方法，不能阻塞自身事件循环 | Promise/忙等冒充同步合格 |
| 图/GUI等待线程也是原生通知消费者 | 不在该线程作需要自身继续事件处理的阻塞等待 | 满队列＋锁＋等待形成闭环 |
| 输出无上界，输入已耗尽配额 | 准入留结算空间或采用可分块合同 | 完成必须新额度但信用全部被自己占住 |
| 重复同一结果与真正额外结果分别到达 | 前者不重析构，后者有独立清理责任 | 所有迟到都扔掉或全部再free |
| JS环境关闭后队列仍携带原生载荷 | 只执行合法原生清理，不触碰失效JS | 无JS回调就认为不需要释放 |
| 句柄代核验后另一线程退休槽位 | 核验与取得占用共同原子化 | 先查代再加引用竞态 |
| 槽位复用或代际到上界 | 旧句柄拒绝，耗尽时换命名域而非环回 | 重复小整数认成旧实例 |
| A已无活动调用但还有A析构的返回对象 | 保留A的代码/分配器直到结果结算 | 只看调用计数卸载A |
| B初始化部分成功后失败 | 只释放取得的B资源，A职责不变 | 释放未创建B或误清旧A |
| 主DLL准确，依赖搜索命中另一库 | 核实际依赖和装载策略，必要隔离/拒绝 | 主文件SHA当整个运行闭包 |
| 静态分析器为检查ABI直接加载未知库 | 改为获准探测或被动元数据解析 | 只读接口暗中执行初始化 |
| C ABI遇到panic=abort或不允许展开的异常 | 按真实ABI隔离/错误合同，不宣称catch全能 | 类型正确就允许任意异常跨界 |
| 仅测过F但运行域也会到G | 产物保留G所有必要成员并核覆盖 | 从bench覆盖推导可删除G |
| 固定平台证明F永不进入 | 合法删去F分支并记录实际输入依据 | 永远包含所有平台依赖 |
| 一个GPU根缺驱动而TS库合格 | 分根返回，共同发行按其真实要求决定 | 可选设备缺失阻断全部工程 |
| 资格需要运行候选才能获得 | 明确验证目的下生成并隔离测试，结论再用于生产资格 | 必须已生产合格才允许生成被测对象 |
| 新实现更快但多复制使整体更慢 | 按端到端相同要求比较，允许保持G | 只报核内部耗时 |
| 取消一次等待而共享结果仍有消费者 | 撤本等待不停止不属于它的生产者 | 同一内容共享就共同取消 |
| 已取得固定共享数据但当前披露被撤销 | 数据保留与是否交付分开核对 | 固定快照等于永久读权 |
| 单个无回调同步纯调用 | 允许普通栈寿命和直接合格引用，无持久台账 | 完整架构迫使简单函数启动服务 |

### 取得、交付和预算组合的接合验收

以下按取得、交付和预算机制分组；它们是具体输入与预期，不是固定题库，也不是任何数量的已通过产品测试。组合依据来自[取得责任][k3]、[结果领取][k4]、[失败边界][k5]与[预算结算][k6]。数值案例使用同一假定维度/单位，不能跨量纲相加。

| 初态与扰动 | 正确结果与观察 | 需要排除的反例 |
| --- | --- | --- |
| 取得前准备接收位置失败 | 不调用acquire；此前实参已产生的责任由原激活收尾 | 先取得后才分配唯一登记记录，失败便丢句柄 |
| 工厂先取得A，再取得B失败 | 工厂清理或保留A的准确未结算责任；不对不存在的B执行close | 整体Acquire失败被当成从未产生任何资源 |
| 资源已创建，包装结果或取得释放方法失败 | 原受信临时拥有者继续保护并结算；释放方法的实际读取次数和失败通道准确 | 外层catch没有句柄却自报无泄漏 |
| acquire仍在进行时关闭域，之后成功回调 | Pending参加排空；原位置接住并清理晚到Own，不启动body | 删除等待者后让晚到结果无人负责 |
| 外部创建是否被接受未知 | 保留原身份、查回与接收寿命，不伪造Own或重新发新创建 | 超时被改写为未取得并无条件重试 |
| Deferred已移动Own捕获，但从未start | 由Deferred实际拥有者弃置捕获，任务体从未执行 | 只管理已启动任务导致冷捕获泄漏 |
| 构造第二个捕获时失败，第一个已移动 | 已移动部分由构造临时位置清理，未移动部分仍属原方 | 故障返回假装整个构造完全没有发生 |
| start在消费Deferred前因额度不足拒绝 | 未消费值保持原有效拥有关系，可合法重试或弃置 | 拒绝返回后既丢捕获又声称调用者仍持有 |
| start已消费捕获，执行器接受未知 | 保持原登记与捕获保护，不再次启动或退回可用Own | 同一资源同时退给调用者和未知运行中的任务 |
| all包含多个Own结果，一个槽已被其他领取者占用 | 整体领取预留拒绝，不对外公开此前其他槽；原拥有关系可核 | 逐项公开后才发现末项冲突 |
| 聚合结果接管部分Own后构造失败 | 临时位置清理已接管项，未接管项仍归原槽；没有半个成功结果 | 部分接管既未回滚又无人收尾，或把已使用值再退回 |
| 返回独立Own，但本函数ensure失败 | 未交付Own由临时结果位置清理；原局部资源不再重复关闭 | 只保留ensure错误，把已算出的Own遗忘 |
| 主体Fault并存未交付值，弃置该值也失败 | 主体原因保留，附弃置失败及残余拥有者；不无限重试清理 | 后一异常覆盖前一异常，或递归日志耗尽恢复预算 |
| 取消在最终交付点之前取得协调权 | 等待者不接管Own，原临时位置/完成槽继续结算 | 已取消等待者仍标记已消费后无人接收 |
| 交付点已完成移交，然后收到取消 | 结果由新拥有者收尾，旧方不索回或二次关闭 | 取消不分时点，原完成槽再次析构 |
| race已选成功赢家，但落败设备仍运行 | 默认受管race不冒称域成功关闭；保护赢家与落败者，按实际停止/移交结算 | first-ready直接代替完整受管域的完成 |
| 原生输出解码失败且元数据中有伪造释放地址 | 受信提供者结算自己确实取得的载荷；不调用输入声明的free地址 | 验证失败路径成为任意析构/函数调用入口 |
| 分别正常返回及抛出undefined/null/false/0/空串 | 正常值保持成功；每个实际throw保持失败及可保留的原值 | error的真假或instanceof检查吞掉异常 |
| 错误对象名字为AbortError，但没有实际取消依据 | 按实际异常事件和提供者合同处理，不伪造Cancelled | 字符串名自动授予取消或重试语义 |
| 错误载荷含抛异常的getter或循环，诊断额度很小 | 不在锁内执行任意转换；保留主失败并给有界投影/准确观测缺口 | 日志序列化取代主失败或无限重复写日志 |
| 父普通工作额度10，两并发子项各要8 | 共同预留至多接纳一个完整8份请求；另一延后/拒绝 | 每子项8≤10便同时派发总支出16 |
| 总窗口10，首attempt已用7，退避又用2 | 后继attempt最多获原窗口剩余1，不再获得完整10 | 新attempt身份重置timeout导致端到端无界 |
| 同源累计用量依次报告5、3、5、7 | 准确已知累计为7；乱序/重复不新增支出，异常重置另判 | 把回调逐次累加成20或回退余额 |
| 预留6份后接受未知，后来确认实际用4且不会再消费 | 原6份先保留未知上界，读回后4转Spent、2归Free | 原6份未结算之外再加4，或超时先全部退款 |
| 额度下调到小于已发生消耗 | 保留真实消耗与超额事实，停止/收窄新准入并合法回收可撤销预留 | 修改历史用量或负余额让账面合规 |
| 两等待者共享物理用量7的生产者，各自复制用量1 | 物理同维合计9，租户分摊另循政策；取消一方不偷偷改其他方账单 | 共享生产者算两次，或共享便忽略两份复制 |
| 单份支出经stage和attempt两级汇总 | 各层可展示同一支出投影，根只计一次 | 父子各记10后根合计20 |
| 计量进程重启，累计计数从头开始 | 取得来源新代与可信基线，旧已用及未知保留 | 看见较小计数就当免费新周期 |
| Runtime关闭并发重入，初始化Pending与借用宿主池仍存在 | join原关闭过程，Pending有归属，借用池不被关闭；未交付Handle仍由工厂负责 | 多次close分别析构，或清理初始化时误删用户数据 |
| 第三方无法预留且允许超额扣费，无可靠支出上界 | 准确保留能力缺口和实际用量，拒绝依赖硬额度的承诺；采用合格保守方法需另有依据 | 本地计数没有超过预算便宣称远端绝不会超支 |
| 执行槽已释放，但CPU时间已花费且内存仍被设备使用 | 槽维度归还，消耗维度不退款，内存维度继续占用 | 所有维度套同一个finally return计数器 |

<a id="dynamic-control-cases"></a>
### 共享代际、切换和调和通知的接合验收

以下是设计输入、交错次序和判据，不是已执行的产品测试。代际核验与占用取得必须共同原子，返回对象必须继续保护其代码/分配器，部分初始化只能清理已取得资源，结果交付、取消与接受未知也必须沿用各自既有合同；这些机制直接适用于运行切换，不另复制为新规则。这里继续检查[J共享代][k7]、[C运行代][k8]、[R调和交接][k9]与[活动依赖][k10]的组合。

| 初态与扰动 | 正确结果与观察 | 需要排除的反例 |
| --- | --- | --- |
| A是最后等待者，B先成功登记，A随后撤离 | 生产者继续服务B；只解除A的引用和等待边 | A按先前读到的数量取消已经有B的生产者 |
| A先把最后登记撤离并置Closing，B随后请求同键 | B不能加入原代；按原期限有界等待结算或准确结束 | 将已发出或即将发出取消的实例重新置Accepting |
| 共享生产者仍在队列中，最后撤离与执行器领取并发 | 确认未派发才按未开始结算；已经开始/接受未知保留原代 | 删队列项后立即启动另一代，导致两次执行或遗失捕获 |
| 旧g已经结算，表项是同键新g2，旧重复完成到达 | 按实际实例比较，g2及其等待者、配额不被修改 | 仅按key删表、退款或发送取消 |
| 新等待者的槽/预算准备失败，原生产者已有合法消费者 | 拒绝新登记并结算其准备部分，旧消费者不受损 | 先增加计数、抢结果或取消旧实例后才发现无法接纳 |
| 两个Runtime共享一次合格生产，R1关闭而R2仍等待 | 只移除R1登记，真实物理占用继续由原生产者管理 | 关闭Runtime时把共享池或生产者一并关闭 |
| 全部等待者离开，但提供者无法证实停止 | 保留Closing、实际占用和原代；新等待有界，不免费重开 | 没有消费者就归还全部预算或无限启动同键后继 |
| 原代Closing但已有独立完整纯缓存值，新调用具备当前资格 | 允许读取准确缓存而不加入原代，也不提前释放其残余 | 为了统一生命周期而拒绝所有正确旧值，或凭缓存使旧执行复活 |
| 新请求明确需要旧解释A，而原A实例正在回收 | 选择明确仍开放的合格兼容入口或获准重新装配；否则准确缺项 | 为了兼容把已经Closing/已回收实例重新开放 |
| 默认运行经历旧A→B→新A，旧A的迟到消息到达 | 区分实际运行代，不能更新新A槽、预算或终态 | 同名同配置被当成同一实例 |
| 默认已切B，旧A请求尚需其已接纳范围内的有限子调用 | 在父保护释放前登记子使用并重核实际权限；原请求可正常结算 | 排空一律拒绝所有子调用使已接纳请求死锁，或让独立新根借旧pin越权 |
| 旧代因设备/返回对象而存活，连续请求升级B、C、D | 先核共同峰值与待退役容量，限制进一步准备/采用；只合并无独立义务的候选 | 每次通知新建Runtime或为腾空间提前销毁旧代 |
| 路由切换已被接受但响应丢失，同时另一个合法采用到来 | 按原切换身份与预期前像读回、保留实际各项状态 | 盲重发切换或用旧默认覆盖并发采用 |
| 调用pin仍在，但安全依据撤销了原方法，清理代码本身也不可信 | 阻止新越权作用，选择当前合格恢复/隔离或保留未结算 | pin等于永久执行权，或者无条件运行可疑析构以制造Closed |
| B已写出A不能读取的新数据，A代码仍在磁盘 | 回退先重评读写及作用兼容，不满足时保持准确阻断/前向修复 | A文件存在就认为可以把当前指针改回A |
| 宿主没有独立代码卸载能力，只能移除分发表引用 | 报告逻辑退役及仍存活范围，采用合格进程退出/替换才声称物理结束 | Map删除被记作DLL卸载、秘密擦除和设备停止 |
| 获准可信纯方法处理短调用，无持久或强隔离要求 | 同进程/栈内正常执行，无额外进程、数据库或常驻调和器 | Provider章节默认把所有本地调用变成受限进程 |
| 不可信方法的初始化会执行代码，普通worker没有本次必需隔离 | 在真实合格边界内装载/初始化或返回不支持 | 先在主进程初始化再检查，或worker标签冒充沙箱 |
| 调和器已经领取并清dirty，处理期间收到新变化 | 结束时保留dirty并有界重新排队一次，不启动第二个写者 | 完成路径无条件清dirty导致最新变化永久遗漏 |
| 本轮先结束并解除processing，随后相同键收到通知 | 通知正常标dirty并入队，无丢失或重复队列拥有者 | 只修处理中路径却漏掉结束后的通知 |
| 按D1得到收敛结果之前，已接受目标变成D2 | 旧结果仍归D1；当前投影比较目标代，重新观察D2 | 旧轮成功把尚未处理的D2标成converged |
| 目标改变，但按旧目标发出的外部操作接受未知 | 保留原operation并查回/结算，后继作用单独准入 | 新一轮自动生成新requestId重放或反向抵消未知操作 |
| Watch历史过期、范围/披露变化或缓冲断档 | 按原握手重取合格基础；保留作者草稿及实际操作责任 | 清缓存顺便删恢复记录，或没有事件就当完整一致 |
| 不同键数量超过等待容量，有权范围可枚举；另一个范围不能枚举 | 前者保留有界待重同步范围，后者背压/保留或准确停止 | 偷偷丢键后宣称整个工程已观察完整，或无限全量重扫 |
| 持续通知使每次debounce都从头计时 | 在已接受最大等待/期限内推进或准确结束，预算不重置 | 调和永远不开始且持续声称即将收敛 |
| 同一真实对象和写入字段，控制器升级改变自身版本 | 原冲突域不因版本改变分裂；旧在途作用仍受同一协调/围栏 | 把controllerVersion放入写锁键产生两个独立合法写者 |
| 同一路径上的对象被删除重建，旧观察/结果迟到 | 核真实实例与本轮基础，不把旧状态写到新对象投影或目标 | 路径字符串或较大本地序号冒充对象同一性 |
| 活动查询从读A改读B，B在新通知安装前变化 | 新读域保护与切面重查/补事件接合，保留dirty，再撤旧保护 | 只原子替换value和deps却漏掉订阅之前的变化 |
| 控制器关闭时已有dirty或在途作用，之后仍有人提交通知 | 已接纳任务明确排空/取消/移交，新提交准确拒绝；旧作用继续结算 | 关闭静默丢接受语义，或退出即删除未结算操作 |
| 一次固定快照的纯查询，不要求持续观察或热替换 | 直接返回准确值及其切面，不强制创建订阅或升级服务 | 为了统一动态管理让所有小请求都支付长期控制成本 |

实施核验应使取得保护、关闭接纳、真正派发、完成发布、回调退出和最后释放可分别控制，并核两种竞争次序；不能只给一个有利sleep。验证默认单生产者不误停别人、合法旧调用可结束、短纯路径无多余设施，与拒绝不安全行为同样必要。通知队列不丢失只证明再次观察的条件，不证明目标稳定、当前权限或外部作用恰好一次。

数据算例应独立枚举真实元素地址与范围公式，并将范围正确、无别名、对齐和来源作为不同断言。生命周期检查应使用可控制在start内完成/回调认领/停止确认/析构时点的真实驱动；仅测试几个计数值不证明执行器没有遗漏。成功的小同步路线也要验证，不能用拒绝所有调用取得安全分数。
