# 复用接合、故障切点与总装

## 复用路径的接缝验收与任务投影反例

执行计划先调用[剩余验证责任][k2]。原样复用的成熟组件默认不复制上游全部测试项目；本地案例服务于实际Adapter、输入配置、语义映射、共同不变量与原任务。需要更强保证时再增加该范围的方法，不能以成熟名声代替风险判断，也不通过堆测试数制造成熟度。

有限案例集当前包含：冻结输入透传到官方工具且结果归属不串；相同显示值但不同基础或库合同的视图不能互换；空编辑保持原字节；单槽修改保留未显示成员；失效editRef不改指latest；字符串值不执行代码；不合法枚举不替换成默认；短请求与显式set-input在同基础上结果等义；源错误仍可按草稿保存；当前权限拒绝不由旧视图绕过。

还要构造误继承：TS类型检查通过但Gift把条件除法提前；数据库事务正确但外部发送重复；解析器保留AST而格式器丢注释；同一上游方法应用到不同VFS/API版本却继续复用。期望来自选定合同与独立推导，不把被测生成器的输出作为唯一Oracle。

本页定义验收案例，不记录实际执行结果。实施验证须在相应授权和真实环境中先验证小范围完整正确路线与接缝，再增加优化回归；列出负例本身不等于已经创建或运行测试工程。

## 实现接合的独立判据与故障切点

本节给出对应实现应执行的检验设计；上游解析器、打印器和数据库原样复用的内部正确性不再重写整套测试，检查集中于Gift新增边界和所需实际环境。每行只有满足该范围才改善对应U项，不以文档计数或运行一次标全系统通过。

| 输入或切点 | 独立期望 | 真正检查的责任 |
|---|---|---|
| 内存source请求，存在不可写工作目录 | 仍可创建候选并在输入完整时返回源码；不领取工作区写租约、不写lock | 应用与纯编译拆分，不是测试数据库能否写入 |
| 旧Block合同指向不存在Block | 保持旧画像错误；中立独立模块另经真实ModuleOwner成立 | 归属适配不能通过放宽全部校验完成 |
| 捕获后调用方修改原buffer | 编译继续消费捕获字节，或入口已拒绝共享可写输入 | 所有权与摘要一致；不测试哈希函数全部安全性 |
| `+x`，x为中立Int，取值7 | 目标正常结果7，不因JS ToNumber产生异常 | Gift一元运算映射 |
| 条件除法，x为0与2 | 分别为0和5；未选择分支无除零 | 激活区域保持 |
| 具名实参第一个除零，第二个不终止 | 先出现计算错误；不能先进入无限递归 | sourceOrder与formalSlot分离 |
| 非调用的lambda创建 | 只建立函数值和捕获；不执行body效果 | closure降低和立即/潜在效果 |
| 相等记录为不同目标对象 | 按中立值相等结果，而非目标指针身份 | equality降低与opaque边界 |
| 同形记录的不同名义类型 | 仍按源类型拒绝不合法替换 | 不以TS结构赋值替代Gift名义规则 |
| 展开器新增一个调用或效果 | 新区域补绑定/类型/效果检查；原checked标记不覆盖新节点 | 分析失效与pass接合 |
| Host缺少lib文件或读取未捕获package | 准确方法缺项或NeedInput，不落回本机读取，不误判全部是源错误 | 虚拟Host闭包与环境诊断 |
| 文本`a😀\r\nb`的b位置 | UTF-8起始偏移7，UTF-16起始偏移5；均指向第二行首 | 编码坐标映射，不运行源语言 |
| ticket查到后并发回收 | 输入已被同一协议固定，或请求在开始时准确失效 | lookup与pin的原子接合 |
| c1 ticket遇到新头c3 | 只形成c1分支，工作树及c3不变 | 编辑快照与当前头分责 |
| 短编辑响应丢失、memo已回收 | 不保证原候选ID；原base可取得时允许等义重算 | 轻量候选与强幂等分开 |
| 外部同步分析超时但worker仍运行 | 返回等待/中止状态不代表已经停止；输入与内存仍有归属 | 取消/资源结算 |
| TS已生成、Java目标缺项，原请求需要两者 | TS作为独立产物可返回，整体仍有Java未完成义务 | 按根状态及共同交付 |
| parser在错误分隔符位置恢复 | 每次消费token或退出父产生式，有限预算内结束 | 恢复算法进展，而非仅拒绝非法输入 |

预期来源分别是已定语言运算、作者任务、引用/生命周期合同和编码定义，不由新目标生成器输出反过来成为唯一答案。相同正式源通过文本/结构两条路径可做差分，但共用检查器可能共享错误，因此仍需上表的独立语义预期。对有限第一次实现，不运行无限程序来等超时证明非终止；可在对应行为方法中使用受控步数/调用桩暴露顺序，范围如实说明。

具体命令、机器、工具版本和结果在以后实际授权实施时绑定。当前单个静态接口的schema合法不证明以上责任，也不要求在写这份设计之前先实现这些测试工程。

## 成品总装的独立复核轨迹

本节是检查设计，不执行产品。每项期望来自公开合同，不以新实现输出作为唯一答案。

| 初态与扰动 | 必须观察什么 | 要拒绝的伪成功 |
|---|---|---|
| 请求J1固定image A，装配B改变默认 | J1仍读A；J2可明确读B | 同一请求分阶段取latest却仍宣称确定 |
| 编译已固定模块m1，补输入返回不同m1 | 产生捕获冲突或新basis，不覆盖原m1 | 相同ActionKey下静默混合字节 |
| C1 fork C2，同时外部头由h1变h2 | C2存在但旧expected=h1的应用冲突 | candidate创建成功等于工作树写入成功 |
| A2产生，E2通过后失效 | A2字节身份不变；相交采用资格重评 | 证据修改导致artifact内容身份漂移或借E1认证A2 |
| 模块M已检查，模块N有类型错误 | 各模块实际状态明确，依赖N的根不生成 | 取最高phase=checked认证全部 |
| 同一包两个领域争用输出path | 有明确组合则合成；否则真实冲突 | 后完成者覆盖而整体成功 |
| 代码完整、必需图标未捕获 | 代码根可返回，包根未完整 | 用源码成功签全发行 |
| 外部工具超时仍在执行 | 保留资源并取消/隔离/移交 | 仅Promise返回就回收buffer |
| 纯库画像没有数据库/网络驱动 | 固定输入和纯方法仍可生成 | 缺可选设施阻断纯函数 |

架构依赖检查、类型接口和静态包图只验证相应边界。真实线程、存储、设备和跨进程安全还需对应环境的检查；没有执行就不写通过。
