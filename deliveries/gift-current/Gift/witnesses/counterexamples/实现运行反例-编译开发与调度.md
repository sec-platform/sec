# 编译、连续开发与调度反例

## 全工程装配、编译、连续开发与调试的接合验收

本节是设计的预期与反例，不是已运行测试。输入来自准确工程/工具合同，期望从独立要求、明确状态和实际成员推导；待实现后才取得命令、观测和覆盖。文档链接、图源或ZIP通过不关闭这些行为项。已有领域案例保留其数学与语义责任，不因下面使用同一个Gift产品工程而被替代。

### 工程输入、编译与实际输出

| 场景 | 固定输入与动作 | 必须得到的结果与可检验反证 |
|---|---|---|
| 本地最小装配 | 仅内联源和实际内存HostPorts，不提供文件/数据库/调试器 | 正常生成所支持目标；不存在被隐式初始化的磁盘/网络服务；缺调试器不使类型检查失败 |
| 两项目同文本 | 同一文件字节分别处于不同锁出现/原生配置，名义类型含义不同 | 可以共享解析字节，不串用语义身份/导入；与各自独立全量结果比较 |
| 同源双入口 | library与cli在同一解析域共享核心，只cli增加消息资产 | 公共分析可复用；根与实际成员分别绑定，不能给library强加无用CLI资产 |
| 嵌套作者冲突 | 父范围含子目录，子工程已被明确接受为独立作者 | 父只通过边界引用；两可写认领必须诊断，不按扫描顺序决定覆盖权 |
| 缓冲与磁盘 | 已打开模型内容不同于磁盘，再捕获工作集 | 每个前像带实际层与版本；不得把一层摘要当另一层覆盖许可或全局原子证据 |
| 负解析依赖 | 首次查找a模块得精确缺失，后在原查找范围新增a | 重新解析相关消费者；不得无限复用缺失，也不让无关根全部失效 |
| 相对导入移动 | 模块内容字节不改但路径移动，./dep解析落点改变 | 解析/语义按新真实上下文重核；只用内容哈希的缓存应被反例击中 |
| 有声明环无初始化环 | 互递归函数拥有合格签名/效果，运行递归不在编译时执行 | 正常编译或给真实类型错误，不把所有环当死锁；对独立期望函数检查 |
| 严格生成源环 | 生成器源码依赖其自己尚未产生的源，无种子 | 给出有限因果环和受阻根；不得造空头或靠增加worker伪进展 |
| 合法生成种子 | W09改为明确绑定已有独立工具或已接受引导源 | 正常生成，新源重新走类型/效果与依赖闭包；种子内容进入真实输入 |
| Needs无进展 | 相同basis和所需内容反复返回相同不可得观察 | 返回准确等待/未完成，不反复执行同工具；有新事实时允许合法继续 |
| 生成额外依赖 | 工具返回新源并引入新模块/资源 | 新输入进入后继PreparedJob与完整成员；未重新检查不能复用旧合格标签 |
| 部分根结果 | library完整，cli缺必需运行资源，任务要求两者 | 单根成果保留且AND结果未完成；不以先到的library签发整任务成功 |
| 同路径贡献 | 两生产者给同路径相同字节但不同拥有者/共同配置义务 | 只有明确可合并的同一责任才合并；字节相同本身不证明无冲突 |
| 输出之外的干扰 | generated目录多出未列启动脚本，某旧资源仍在 | 构建读取精确成员而非扫目录凑输入；缺必需资源与多余干扰均可检测 |
| 未选根保全 | 只重建library，cli使用共享成员且未获升级范围 | 不删除cli成员或悄悄更新不兼容共享配置；协调/隔离或报告共同修改需要 |
| 作者手改生成物 | 前次B与新D不同，现场X既不等B也不等D | 保留X为目标草稿/冲突，不覆盖；合法回源后才能纳入新作者 |
| 成员删除与未知 | 新D不含旧成员；旧B有所有权但X无法准确读取 | 不以“新清单没有”执行盲删；取得真实前像和未使用关系后再准入 |
| 同值不同来源 | 新分析值和旧值相等，真实导入/来源边已换 | 更新读集/来源后才截断纯值传播；删除新来源可触发正确失效 |
| 新旧解释并存 | 新请求使用新EngineImage，旧操作仍在结算 | 旧意图按原解释与恢复责任继续，新候选不自批旧操作；普通内部替换不必重建全作者 |

Gift 工作区工程输入还须以同一解析器核当前 Plan 显式 block 选择在已锁定 manifest 集合中的有效依赖闭包：Plan 新增选择而 Lock 缺项，以及 Plan 删除独立选择而 Lock 遗留多余 block，均不得把旧 Lock 的解析结果交给后续消费者。隐式依赖可使 Lock 的 block 数多于 Plan 显式选择数，不能直接比较两个列表相等。两次普通文件观察只约束捕获期间的稳定性，不证明原子工作区快照；重新解析全 registry catalog 是否必要，由实际选择和目录消费合同决定。

### 多客户端、调试与第二轮修改

| 场景 | 固定输入与动作 | 必须得到的结果与可检验反证 |
|---|---|---|
| 返回代ABA | 同一显示槽选择C1→C2→C1，第一次C1慢回 | 旧回调不能凭候选相同发布；第三次请求可显式复用合格缓存但有自己的代 |
| 共享生产者取消 | 两任务共享纯计算，只一方取消 | 取消者失发布资格，另一方可完成；实际最后停止前不提前释放输入/占用 |
| 写入响应丢失 | 已发真实保存请求而响应丢失 | 查回原operation，不用新ID重放；实际已经发生与未知分别呈现 |
| 调试未协商 | 旧v2客户端/服务收到debug-launch或action:debug | 准确不支持，不能默默当status；普通preview/compute-run仍可用 |
| 调试器选择 | 无唯一绑定画像，或选的画像不具真实启动能力 | 返回具体选择/能力缺项，不安装最新调试器，不按注册顺序选 |
| PID复用 | 已发现目标退出，同PID后来指另一进程 | 旧runtimeTargetRef附加被拒，不能把新进程当原目标 |
| 必需断点 | required=true但只能在用户代码已执行后验证 | 不宣称执行前保护；启动前拒或在真实可控边界保留未完成；required=false准确显示未验证 |
| 清空断点 | 曾在某源设置一个断点，完整新集合不再含该源 | 实际发送该源空集合；不得因为没有新条目而跳过清除 |
| 两暂停同底层句柄 | p1继续后出现p2，调试器重复使用frameId/变量数字 | p1的FrameRef/ValueRef/游标失效；返回p2的新引用而非串用旧栈 |
| 单步响应丢失 | p1上的next已发送，响应未知且随后可能出现p2 | 按同requestId查已知状态或未决，不再次next；先后顺序不能仅凭最后消息猜 |
| 属性读取有作用 | 目标属性是getter或适配器为显示值会执行用户代码 | 默认拒绝展开/opaque；不能因调用了variables API就宣称只读无作用 |
| 部分线程暂停 | 一个线程停止，其他线程仍可能写共享对象 | 值标明实际观察范围，不拼成全堆同一时刻；要求强快照的请求不能虚假满足 |
| 旧运行新源码 | B1暂停期间作者改C3生成B3 | B1栈仍定位原源；新调试使用B3新operation；无热替换能力不改现有进程 |
| 附加结束 | 只有attach/detach权，无终止权 | 解除本次连接不杀目标；会话ended与目标exited分别返回 |
| Runtime关闭 | 一个借用池仍供另一Runtime使用，当前有未结算工具 | 停接新任务、结算本实例拥有内容；不杀借用池，不把超时报告成完全关闭 |
| 文档派生独立 | 修改规范MD，原有旧HTML未重建 | 当前规范正确可交付；旧HTML保持旧版本，不能复制版本号冒充当前；不影响目标编译键 |

| 同暂停并发控制 | 两客户端同时对p1发送不同requestId的next/continue，第一次命令尚未结算 | 仅一条占pendingControl，另一条明确拒绝/待前提；不因串行收包而串行执行两次；旧暂停活读取资格立即关闭 |
| 强配置与范围 | 暂停时加入required断点但一组失败，再请求continue；或请求只恢复单线程而适配只能全部恢复 | 不越过未完成的必需配置，不扩大runScope；running时动态强配置缺有效全目标暂停则准确拒绝 |

### 如何取得独立证据

纯解析/根计划/成员协调先与正确全量串行路径比较，比较内容、来源、成员和失败范围，不只比较摘要。并发返回、暂停与作用的关键切点需要可控事件轨迹：先记录应被隔离的主体，再改变完成顺序检查实际结果。宿主快照、未知前像、写入未知完成、PID/暂停/控制/读取作用/Runtime关闭等物理边界必须在实际适配边界取证；模拟函数和同一错误实现生成的期望都不能签发物理保证。

有限模型可穷举已有状态/消息排列；无界程序、目标运行时和文件系统保证不能由有限样例推成普遍成立。真实证据按[组合保证][k1]绑定到对应子范围，既不把一次失败解释为所有设计无效，也不让一个成功案例代表其余独立机制。

## TS工程往返的有限正向验收

本节是验收设计，不是已执行成绩。当前语言支持不能仅以读取器存在、目标能编译或source map有位置结束。相应“TS工程支持”必须完成原生直接编辑和受管生成物回源中已声明的任务；纯生成可以单独发布，但只能声明纯生成范围。

| 输入与动作 | 准确预期 |
|---|---|
| 原生文件含注释、CRLF、BOM和emoji，无变化读取保存 | 原字节不变，不借AST打印重格式化 |
| 局部变量改名会捕获同名内层变量 | 重构失败或给出准确联合候选，不能以类型通过代签 |
| 同一文本10出现在不同定义与配置 | 只改实际映射到的源槽；其他字段保持 |
| 10n→12n的准确目标变化 | 源Int常量改12，再生成12n；不得仅在输出留补丁 |
| 10n→12或加入目标类型不支持的值 | 准确诊断/目标草稿，不隐式截断或强转 |
| 原源一处内联到两个调用，目标只改一处 | 合法的局部特化或ScopeConflict，不改全部 |
| 当前作者已有同槽变化，旧目标再请求回写 | 保留双方差异和原基础，返回冲突 |
| 当前作者只有无关README修改 | 合并后README保持，目标比较以当前作者生成基线为准 |
| 当前规则升级而目标来自旧规则 | 旧解释解码，新规则显式核迁移/重生成，不复用错误坐标 |
| 非语义注释与真正编译指令分别改变 | 前者保留局部呈现；后者进入实际语义/工具输入 |
| 目标加入未知动态调用 | 草稿保全、相交未知可定位，不丢代码、不伪造纯效果 |
| 取消发生在回源候选生成中 | 不发布半批作者；原源与目标保留，资源按真实停止释放 |
| 缺少原源/锁/写回规则 | 具体缺项；可读原生目标不被误称已恢复中立意图 |
| 原产物被直接覆盖或错误移贴检查 | 内容身份检查失败；不得改变旧ArtifactSet |
| 源、资源URL与人工资源文件共同存在 | 只更新有真实生成关系的内容；人工区和无关资源保持 |
| Java未安装也未被请求 | 当前TS闭环可完成，不产生Java前置 |
| C空输入与非空全零输入 | 最大值存在标志分别0和1，不合并这两种结果 |
| C长度超容量、别名或生命周期不合格 | 在有检查依据的入口拒绝或保留资源条件，不调用未定义行为 |

每个规则需要自己的合法正例、失败与保持推导。再生成比较检验关系闭合，但不能让同一个错误前后端互相认证；目标工具、独立期望、差异和实际运行按要求选用。旧上游测试只在前提相交时继承，不重跑全部生态以代替新接缝用例。

统计按语言角色、编辑类、目标和实际样本公开；不以一项简单常量变化代表完整逆向，不以所有困难输入都拒绝代表安全可靠。对未知边界可以保守，但已承诺正常任务必须能进展。

## 自主发现与编译调度的独立验收设计

分别检查“有没有找到问题”“找到后是否选择了正确工作”“所选编译调度能否完成”三个对象。发现器只检查已有列表，会漏掉新增根目标；排程只按严重性会把未激活远程设施置于普通函数之前；调度器只看DAG会漏掉父线程占满池的资源等待。三个失败不能由同一个全局passed覆盖。

| 固定输入与切点 | 独立预期 | 实际验证需要的范围 |
|---|---|---|
| 删除一条从目标到必需接口的映射，但保留所有旧U记录 | 反向检查发现目标义务缺口；问题总数未变不证明覆盖 | 设计追踪与规则解释 |
| 新增与当前任务无关的目标或库 | 当前就绪前沿和编译依赖只在真实相交处改变 | 有类型边、激活与输出根 |
| 两个父任务同时请求同一查询 | 同一隔离范围只计算一次，两个消费者分别取得合格结果 | 查询身份、单飞和披露 |
| 所有CPU槽被等待子结果的父任务占有 | 父挂起归还执行槽，子任务可继续；真正内存不足单独返回 | 线程与内存共同预算 |
| 两工作线程互相等待对方查询 | 发现跨线程等待环，交合法固定点或准确诊断 | 完整等待边和领域循环规则 |
| 本地与远端同确定动作生成不同结果 | 隔离冲突，不用最快/最后结果掩盖 | 输入闭包、工具与产物资格 |
| Java后端失败而TS与图标完成 | 独立TS产物可返回；要求两目标的发行保持未完成 | 输出AND关系与适用性 |
| 无效取消或迟到尝试返回 | 不改当前可变状态，真实资源和费用仍结算 | 权限、尝试、引用和实际停止 |

正常值、错误、取消、资源与调度不能都用目标代码的同一输出作为Oracle。可以用明确小图手算、有限状态检查、受限模型或实际注入验证各自范围；当前设计任务只给这些输入与允许结果，不自行建设参考调度器。
