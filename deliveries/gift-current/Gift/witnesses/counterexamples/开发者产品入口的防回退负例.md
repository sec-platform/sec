# 开发者产品入口与分层的防回退负例

这里的反例是**将来真实实现的失效见证**，不是当前产品已经出现故障的断言。其合同owner见[开发面符合性](../../docs/60-保证与证据/验收/开发面符合性接缝.md#developer-implementation-ready-acceptance-matrix)。

| 不合格的实现捷径 | 最小触发 | 具体损害 | 合格实现/复核证据 |
|---|---|---|---|
| 预览自动写`dist`以方便IDE看结果 | 临时snippet纯preview | 无授权物理副作用、旧目标被覆盖，后续无法区分预览与提交 | 预览前后整个工作区字节快照一致；仅ArtifactRef变化 |
| 自动加全项目`gift.project.json`和SQLite | 只预览一个Int函数 | 用户工程被意外改变，短路径被重依赖拖累 | 先后无新增文件，仍返回C/A或Needs |
| TS控制层把字符串替换成TS源码当编译器 | 泛型/require/ensure或名字阴影 | 被认为理解语义而实际静默错编译 | 真实Rust语义结果/实现绑定/Target lowering的来源链接及反例 |
| 不存在的业务能力只生成`TODO reserveStock()` | 缺订单库存规则 | 空实现被当可运行并触发外部错误 | Needs/unsupported且不签Artifact Complete |
| `save`混入push/deploy | 用户只要求保存本地修改 | 权限越界、额外付费与不可逆发布 | `apply`只允许现有两个mode，Git/发布操作另授权另Operation |
| CLI、IDE、AI各自使用独立解析器 | 同一作者模块来自三客户端 | 语言、默认与错误表现不一致造成锁漂移 | 同一basis产生同一解析结果和归因；不同呈现等价 |
| 接口错误只返回`success=false` | worker失联/权限拒绝/源冲突 | 用户不能安全恢复，系统盲重试未知Effect | 分别返回stale/needs/unsupported/unknown，保留原identity |
| 缓存命中绕过当前披露资格 | 旧source已经移出SourceProfile/被撤权 | 用户看到已不允许披露的历史内容 | Cache hit前按当前范围与Basis复核 |
| 两个目标只汇总一个`completed` | TS成功、Rust未支持 | 对整个交付能力作虚假承诺 | 根级状态与整个请求资格独立 |
| AI说“已运行”，工具只有代码预览 | 用户要求测试通过 | 假证据使错误被接受 | check/operation需要真实producer/tool/version/env/ref |
| 把worker句柄ID当持久对象ID | 进程崩溃后局部handle数字重用 | 读取另一会话内存/错误对象 | workerEpoch+session/snapshot绑定，旧handle拒绝 |
| 使用生成代码作为新作者唯一源 | 先改C1→C2再反编译A1 | 丢失原语义与可解释控制、二次修订结果错乱 | 原作者源仍有唯一owner，目标更改走受控回源/草稿 |
| 取消外部操作即清空数据库 | 用户在网络断联时点击取消 | 外部可能已发生作用，操作不可核账 | Operation/Attempt/readback持久保留，按真实回执恢复 |
| 把全部开发问题要求先LLM推断 | AI服务不可用或用户禁用AI | 已知确定性工程操作被无端阻断 | 结构/原生/文本作者源独立，编译器不依赖LLM |

这些负例应进入对应源码仓库的可执行fixture，逐条包含明确输入/真实运行环境/输出assertion；新增反例不在这里产生另一套规范优先级。对未知实现/不合格Provider的正确行为是准确拒绝和保留成果，不是强迫“绿灯”。
