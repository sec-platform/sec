# Gift149 实际修订与覆盖边界

## 已修订的设计

1. **作者工程与发行。** 库发布信息进入严格具名的 Project.library，补完整字段与版本/别名/变体约束；旧 extensions 只按准确迁移处理。原生选择使用已有 SourceScope/Profile 发现，补实际模块身份、路径、依赖冻结、读取资格和再次修改规则。projection 必须有真实 producerRef。
2. **输出根与控制。** 保留输出根的完整公开出口集合；contextBindings 仅允许集合恰有一个 product:system。控制仍按 Descriptor 的主体种类、基数和传播规则解释，不能误删集合根能力，也不能把单符号设置广播到新增成员。
3. **工作流。** needs 仅检查当前因果前驱，不隐式启动并行；控制令牌、自然循环与并行未决沿唯一执行正文解释。作者 Profile、错误/证据处理、UI 激活和 Schema 同步，旧含糊条件不能通过改名猜测迁移。
4. **选择与生成。** 资格按源码、构建、运行和保证出口判断；缺生产运行许可不自动阻断完整源码，缺内部实现不能伪装成部署前提。供给新增重核相交负依赖；有限候选枚举完毕但检查仍未知，不能宣布无解。Needs 保留原义务、根、阶段、恢复与失效；等待新输入和预算前沿续算分开。
5. **外部作用与恢复。** 派发前持久保存 Attempt/dispatch-intent；隔离、责任转交与真实结算分开。基础 operation 控制一次绑定稳定恢复意图，迟到 resume 不作用于新暂停，重放 rollback 不新建补偿。流程激活恢复使用原操作身份，迟到结果不能再次驱动旧后继。
6. **工具返回。** effectRef 保持操作引用，不再混写未知状态。结果覆盖必须完整划分所求范围，完成、失败、未决与领域结算分别解释；定位端点和 JSON Pointer 有明确限制。移除五份工具 Schema 中没有根引用或外部消费者的递归 Json 辅助定义。
7. **文本组织。** 重复的逐命题保全规则融合到原写作规范；纠正不存在的包内 manifest/工具及纯设计强制产品验证。研究中的多关系组织、主题与阅读组合落实为范围、版本、访问、异常和失效规则，保留来源条件与未采用部分。撤掉过期轮次、原型交付及 U 台账的现行指示。
