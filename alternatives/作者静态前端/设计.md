# 可选静态作者前端与构造 SDK

本篇是一个**未采用、未发行的候选设计**的唯一可维护正文。它保存类型化静态构造、观察语义及源表示迁移的完整机制，便于未来比较；不启用 `gift.author-text/1`、`gift.author-static/1`、`gift/author` 或 Rust/TS SDK，不创建实施队列。候选的完整原始来源及摘要见[本组入口](README.md)，三个来源快照只读保存，不分别维护第二套候选规则。

当前作者面与不采用决定继续由[作者表示](../../docs/作者/可替换表示与适用范围.md)、[D02](../../docs/决策/设计理由-目标与核心.md)及[扩展前端接入](../../docs/作者/组合/结构编辑与身份保持.md)拥有；当前结构、工程格式及真实工具分别消费原正文。本篇不重述整套文法、类型、Schema、项目字段或目标协议，也不把候选中的旧版本地位变成现行事实。

## 目的、替代对象与当前取舍

候选尝试让有明确需求的作者通过已存在的计算语法或成熟宿主工具构造已有 Definition、RequirementTerm 和有型编辑候选。它不增加业务关键字，不负责自动取得实现，不把高层要求翻译成名称相近的算法。普通产品作者仍可直接使用当前结构输入，已有 TS/Rust 算法继续由原生源拥有，非源码资产保留成熟格式。

不同路线分别判断，不能用“不采用嵌套 SDK”同时否定所有原生工具：

| 路线 | 候选实际差额 | 当前不新增正式供给的理由 |
|---|---|---|
| `.gift` 静态作者文本 | 锁定类型化构造库、纯静态求值及 text→Definition 映射 | 尚无明确消费者及相同任务下净收益证据；额外 reader、宿主、来源映射、诊断和双向迁移未取得资格，不成为结构输入或自举前置 |
| Rust/TS 纯构造 SDK | 用成熟语言构造/检查结构候选，输出同一作者协议 | 当前编辑与候选流程可工作；没有已证明必要的 SDK 消费者与发行收益，不为便利预建另一套产品 API 或让每个运算写嵌套树 |
| 显式代码生成器 | 获准运行宿主程序，冻结其结果为作者候选 | 这属于已有有作用工具过程，可按原协议请求；不因保留此路线就新增默认或隐式生成器 |
| 原生运行库绑定 | 真实库作为 Method/Target 供给 | 这是现行独立责任，不属于被拒绝的作者 SDK；继续按实际接口、ABI、版本、资源和许可核资格 |

表示较短、宿主能编程、存在 EBNF 或几个范例可编译，都不单独构成采用依据。候选不强迫全工程转为 JSON 或文本，不要求普通作者学习另一门语言。

## 类型化构造库

下列是研究接口的语义签名，不是已安装库、已发布泛型语法或新 Core 类型。`Static<T>`、`ExportRef<T>`、`FiniteDomain<T>` 等必须由所选候选库及解释映像提供真实名义定义和资格。构造库只生成所选协议已定义的结构，不借函数名增加隐藏字段或新 Term。

| API | 输入与输出角色 | 必须保持的条件 |
|---|---|---|
| `exportOf` | 单一已解析公开 callable/value → `ExportRef` | 公开、可追溯且有权引用的准确身份；任意无出处闭包不能取得持久导出引用 |
| `subject` | Definition 内局部 ID 与确定 Type → `SubjectRef` | 局部唯一，建立逻辑主体而非运行对象；发生身份不按全局同名合并 |
| `definition` | `DefinitionSpec` → `DefinitionRef` | 生成一份有准确含义的 Definition；缺实现可保留，未知字段或不可解引用拒绝 |
| `requirement` | `RuleSpec` → `RuleRef` | 表达独立要求，保留来源；不证明要求成立、不授权执行，不从现有实现摘要自造独立验收依据 |
| `compose` | `CompositeSpec` → `DefinitionRef` | 构造已有 composite 逻辑；不求解、下载、启动后台或生成目标源码 |
| `use` | 公开 DefinitionRef 与有型参数列表 → `Term.use` | 准确形参身份、类型和默认补全；缺参、重复/同名错配或非法默认拒绝 |
| `hard` | RuleRef 与有型参数 → `Term.require` | 同其余硬规则合取，不将未证要求变成 true |
| `prefer` | RuleRef、参数、正整数 priority → `Term.prefer` | 只比较全部硬条件满足的候选；不能在有限 any/exists 中偷偷改变评价域 |
| `all/any` | `List<Term>` → 对应 Term | 合取/析取及独立作用域保持；源顺序不是执行调度，负向结论有实际有限域和搜索资格 |
| `when` | 静态纯条件与 Terms → `Term.when` | 只消费冻结作者值；false 表示不施加该分支条件，不是禁止功能，也不读取 live Provider |
| `forEach/exists` | 已知有限域与纯 `(T)->List<Term> !{}` → 对应 Term | 保留词法绑定、捕获、顺序、重数和主体发生；不是未来运行循环；空 exists 为 false，见证不代替业务进展 |
| `ref` | 准确模块公开名或 Definition 定位 → `DefinitionRef` | 受控解析，不凭私有 ID 或相似字符串越过访问边界 |
| `allValidInputs` | 所观察 callable 的全部 require 合法域 → `RuleQuantifier` | 固定保证作用域；不证明无限域性质，空域不证明产品可用 |
| `normalReturnWithInputs` | 已解析 callable → `CallObservation` | 绑定准确输入槽和正常返回值；正常的 Result.Err 值、语言异常、超时与不终止分别处理 |

`normalReturnWithInputs/allValidInputs` 属于观察与量化资格，不增加第九种 Term。逻辑结构仍为 `use/require/prefer/all/any/when/forEach/exists`。准确现行结构与含义见[结构化源码](../../docs/作者/结构化源码.md)及[需求规则合同](../../docs/作者/需求规则与供给合同.md)；实际重新采用须绑定当时准确版本，不因旧材料出现 `gift.author-module/1` 就把新候选原地装进旧 reader。

### 构造参数的完整约束

`DefinitionSpec` 是严格有型记录：`{name:Text, parameters:List<ParameterDecl>, subjects:List<SubjectDecl>, exposes:List<ExposeDecl>, terms:List<Term>}`；`CompositeSpec` 使用相同字段。两者都没有 `implementation` 槽；真正实现由原 Binding/Control owner 选择，不能在定义构造时暗选 npm 函数改写业务含义。

- ParameterDecl 恰含稳定参数局部名、subject/value 角色、已解析 Type、可选 closed default；subject 不允许默认。
- SubjectDecl 恰含定义内唯一局部名和类型；重复使用的私有主体按发生点实例化，显式传入同一 subject 才共享。
- ExposeDecl 恰含公开边界名及合法主体/主体参数引用，不暴露私有路径写权。
- Argument 必须引用当前被调 Definition 的准确 parameter identity 和有型 Value，不能按相似字段名自动嫁接。
- RuleSpec 恰含 name、可定位 scope、有确定签名的纯 predicate/定量关系、observation、quantifier/obligation scope 和独立来源。含义不能由当前实现体反向削弱。
- 默认、hard 和 prefer 各保留原强度与来源。显式固定一个当前默认值仍是独立作者决定，未来默认升级不能把它当作省略。

### 正常返回观察与合法输入量化

对 `scope:(P1,…,Pn)->R`，`predicate` 必须引用公开、无外部效果的 `(P1,…,Pn,R)->Bool`。观察把调用时的实际实参与正常结果逐槽映射；具名实参先依已绑定形参放入准确位置，不按记录字段名猜参数。

例如 `replaceAll(before,expectedRevision,nextContent)` 的谓词需要四个准确槽 `(before,expectedRevision,nextContent,outcome)`；只写 `(before,after)` 而没有绑定规则不形成完整契约。签名不匹配、匿名无出处闭包、开放返回形态或不支持该调用观察时，候选结果为 `AUTHOR_OBSERVATION_UNSUPPORTED`，不能把义务默认为 true。

`Result.Err` 若是 R 的值，就属于正常返回的一个和类型分支；谓词须明确匹配。仅有 `Result.Err(_) => true` 不证明错误码正确，仍需独立需求、实际主体分析或证据。异常、陷阱、超时、耗尽、宿主未知和未终止不由“正常返回时”的蕴含证明，须另有失败/进展合同。`allValidInputs` 的域由函数全部 require 联合限定；已拒绝输入不暗加正常后置，空域也不能掩盖没有正常功能。

## 纯静态阶段、预算与结构映射

静态作者文本只在项目明确选择准确 SourceProfile、库内容和解释映像之后执行；普通 import、文件后缀或安装扩展不启用它。函数/类型定义与静态工程定义有各自唯一身份；`exportOf` 按真实符号身份定位，公开静态值还须显式选为根，不因存在就自动成为产品要求。

处理次序是固定源及锁→普通符号/类型/效果检查→有预算的纯静态求值→有型 Definition/RequirementTerm 物化→原结构和语义消费者复核。只有合格封闭纯函数、固定常量、受控作者构造可用；所有捕获来自准确源快照/锁内字节。禁止 eval、任意 JS/宿主脚本、port、网络、文件、进程、环境、时钟、随机数、凭证及数据库访问，不能编码一个 port 后换成本机 Provider 绕过阶段。

工作量、递归深度和分配预算继承原请求。递归/量化过大、内存耗尽或缺抽象方法，返回 `AUTHOR_EVAL_INCOMPLETE` 与来源、受影响导出；未读取来源返回准确 Needs。部分结果不成为完整源，也不降为 any(false)、空 terms、零值或随机实现分支。静态成功只确定含义，不证明终止、运行保证或实际业务可用。

映射保持实际库/方言版本、模块/定义身份、公开出口、类型化实参、词法作用域、默认的继承/固定、硬/软强度、有限量化和每个发生位置。`definition/compose` 映射既有 composite；`hard/prefer/use` 及组合构造分别映射相应 Term；`requirement` 引用原 Rule 语义；直接 fn/type/port 仍由所选计算/原生画像解释，不复制一份行为给 Rule。每个产物保留源 span、引用及适用域，不能只保留最终 JSON 字符串。

无法忠实表示原方言、Rule 类型或元量化时保留原 owner 与字节，返回不支持及准确位置；不得伪造 req:rule 元数据、填任意对象或静默删义。共同计算文法、类型、效果、求值及来源映射分别沿[计算语义](../../docs/领域/计算基础/文法类型与求值.md)、[阶段求值](../../docs/编译/内核/阶段求值与反射生成.md)与[编辑往返](../../docs/编译/表示/编辑与受管回源.md)消费，不在本候选重定义。

## SDK 的三种流程与最小表面

SDK 是成熟宿主语言的构造/编辑客户端，不是新的 Gift 通用语言；普通作者无需写 Rust。SDK 类型化构造与 JSON codec 使用同一准确解释、类型及限制，不能用本地默认、枚举或时钟增加共同含义。对象是临时候选，不是第二份永久作者源。

1. **离线纯构造。** 显式参数与固定库语义产生逻辑候选、诊断及可序列化作者字节。检查完整结果后走原候选提交；构造代码不必成为工程正式依赖。
2. **显式有作用生成器。** 用户选择运行构造程序时，沿原授权/Operation 声明工具链、输入、读取及副作用，再冻结真实结果字节为候选。纯重建读取固定字节，不每次重跑程序猜作者意图。
3. **运行库绑定。** 原生 crate/包提供真实业务实现，按准确接口、版本、Target/ABI、资源、效果和许可取得 Method 资格。它不等于生成作者 JSON，也不因 Rust 库存在就取得 TS 等价实现。

```text
read_module(snapshot, module_ref) -> ReadResult<AuthorModuleView>
new_module(module_id, namespace, dialect_requirements) -> ModuleDraft
add_definition(draft, stable_definition_id, TypedDefinitionDraft) -> DraftResult
add_term(draft, composite_ref, TypedRequirementTerm) -> DraftResult
export(draft, public_name, DefinitionRef) -> DraftResult
serialize(draft, encoding = explicitlySelectedAuthorContract) -> BytesWithSourceMap
propose(base_revision, changed_bytes, intended_owner) -> Candidate | Conflict | Diagnostics
apply(candidate, expected_source_revision, grant) -> Applied | Rejected | Unknown
```

这是能力表面，非真实已发行函数。来源示例的默认 `/2` 只是那个候选版本的选择；当前采用时显式绑定准确作者合同，旧 `/1` 只按自己的合法读取、写入及获权迁移条件解释，不能将“旧版”统一改称非法。ModuleDraft 可不完整，但不能因对象已存在就称业务含义已采纳。serialize、propose、apply 是三个动作；纯 API 不隐读 live workspace，不触发网络、下载或 Provider。跨模块 binding 复用同一 exact context；工具接合仍是[现有六工具](../../docs/开发/工具协议/六工具与请求.md)，不新增第七个工具或权限系统。

## 六步迁移、编辑连续性与退出

每个 AuthorRegion 固定 owner、sourceBytes、SourceRevision、所选 SourceProfile、language/dialect revision、允许编辑操作及相交读范围。没有可靠映射时可只读展示，不能猜回写；同一区域的静态文本及派生 JSON 不得双写。迁移步骤必须相邻完整执行：

1. 捕获并固定原字节、导入/导出与依赖闭包及各相交消费者支持范围，保留无法解码原片段。
2. 在非 current 区生成目标表示候选；JSON→文本、文本→JSON或 SDK 编辑结果都不同时签发两个 owner。
3. 比较适用域内可判定的结构意义：模块/定义身份、参数、默认来源、Required/Preferred/Quantified、公开出口、有序发生和实际资源/效果。一般计算程序等价不可判定，AST 相似不能代证。
4. 取得相交消费者所需额外证据、显式变化接受及冲突裁决；旧未知扩展、注释/布局、原生专有观察不能悄悄删除。
5. 用有权原子提交或原可恢复 Journal/CAS 切换该 region 的唯一源 owner。没有多文件原子能力时消费原恢复协议，不先删旧源再写新源。
6. 保存合法修订映射、必要来源和恢复原字节，使真实相交缓存、锁、目标与保证失效；不复活旧写权。

serialize(parse(bytes)) 的逻辑等价只适用于明确结构方言和完整支持域，字节保持依赖 CST/精确 patch，不能用 canonical JSON 抹注释、顺序或未知字段。不能表示的原生片段返回 RepresentabilityNeed 并保留旧 owner；迁移失败保留旧源、锁与可恢复候选。已存在的 Operation 仍按原输入/代际结算，不因迁移重新派发。

复制模块建立新身份；正常 rename/move 仅凭有资格映射延续身份，手改导致多义时停止自动续接并请求准确对应。语言服务在固定模块图下解析定义/引用/签名，补全来自已锁定库；未完成文本、注释、源跨度和用户 buffer 保留，迟到分析不能污染新版本。图/结构回写必须定位唯一真实 owner，不能把相同值投影解释成修改全部来源。

停止采用时先把必要定义实质物化为仍合格的 JSON/其他已接受表示并经消费者读回，再移除前端执行依赖；只删入口而留下不可解释作者事实不算退出。候选原始来源继续保留其独立比较用途，不因此保留旧执行权。

## 失败出口、反例与重新采用

| 触发 | 候选必须如何处理 |
|---|---|
| 私有导出、无出处闭包、准确参数/类型/观察不匹配 | 访问/类型拒绝或 AUTHOR_OBSERVATION_UNSUPPORTED；不猜名称或把后置改 true |
| 静态 I/O、未固定来源、未选 Profile、库/锁版本不匹配 | 拒绝作者期效果或返回准确 Needs/unsupported；保留源，不换成空产品 |
| 递归/量化/内存预算耗尽 | AUTHOR_EVAL_INCOMPLETE；保留来源和受影响范围，不报告 UNSAT/空集合 |
| any/exists 的分支改变偏好评价域 | 此有限画像拒绝，或须另有已资格化共同评价合同 |
| 双 writer、模糊 rename/move、提交前像或读集被其他 writer 改动 | 作者归属/CAS/联合不变量冲突；保留双方及候选，停止自动切换 |
| 不可表示片段或缺准确反向来源映射 | RepresentabilityNeed/拒绝自动回写，保留原源和目标草稿 |
| 新旧 reader 不理解 Profile/静态定义/Schema | 明确拒绝依赖它的消费并保全；不影响只消费普通合法源的独立根 |
| 只有工程树、类型检查、构造成功或一个目标通过 | 仅报告各自设计/结构/目标范围，不能标产品完成或另一目标通过 |

采用前的检验至少覆盖非法静态 I/O、预算耗尽、不可表示原生片段、双真源、未知 Profile、两个方向身份/默认/发生保持；另检查具名实参槽、Result.Err 与异常、空合法域、分支偏好、重命名歧义、迟到诊断、锁版本不匹配及并发保存。模板展开、宿主类型通过或同一生成器自产预期不代替独立语义检查。

重新考虑必须由明确真实消费者和同任务比较支持，衡量结构编辑/成熟工具无法合理承担的声明复杂度、诊断、跨目标保持、可靠回写及特化成本，连同前端维护、资源、依赖、迁移和退出成本。只有净收益和完整语义消费者成立，才回当前 owner 重开选择；没有收益时继续保持非阻断候选。

重新发行还需准确版本 reader、纯静态宿主、真实名义类型/构造库、受界求值与定位、正负边界向量、双向迁移证据和真实支持域。SourceProfile 的语义映射资格、Method/Target 资格、外部授权、Artifact 生成、构建、运行及 Evidence 各自独立，候选不能为自己签发。当前尚无这些真实发行与行为证据；原文过去的 fixtures/已测叙述也不移植为本仓当下完成事实。
