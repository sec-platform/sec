## 本记录的用途

本记录不是第二份关系语义规范，也不授权把参考实现直接提升为产品能力。规范语义仍由 docs/领域/状态关系与流/关系查询与维护.md 的“具名有型注解关系的条件方法画像”和“有型双侧绑定、见证及有限排除的投影下推条件”负责；编译阶段与方法资格由 docs/编译/内核/领域方法与整体根.md 及其现有 MethodSpec/UseBinding 责任负责。

本记录把上述合同映射到当前 Rust 内核的真实代码边界，防止恢复工作错误地扩张现有 /2 方法。

## 当前代码事实

检查基线：PR #896 head 8398d46ceb209ce194c8936b4fdac654cb2f7634，也是 PR #897 的 base。

1. crates/gift-author-kernel/src/model.rs
   - Definition::Query 持有 inputs、algebra: Query、result。

   - read_query 对 project、join、union、group、sort、limit、fixpoint 明确返回 NeedsMethod。这不是解析器偶然漏掉分支，而是当前方法不承诺这些运算。
2. crates/gift-author-kernel/src/lib.rs
   - 当前 METHOD 固定为 gift:finite-ordered-records/2。
   - Query 检查要求 result 是 Sequence<Record>；Scan 必须解析为完整、静态、类型完全相同的 Sequence 常量。
   - Filter 只接受同一 Record 类型的纯、全、单参数 Row -> Bool 谓词。
   - OrderedPlan 只有 Scan 和 Filter；Checker::query 只构造这两种节点。
   - inputRefs 必须与计划中不同 Scan 源的集合精确相等。
3. 当前 Type 画像只有 Int、Bool、Text、闭合 Record 和 Sequence；没有具名关系 Role、Scope、Sort 修订、注解代数或 Bag 类型的生产表示。
4. 当前 UseBinding 是源出现位置、Definition 和字符串角色到位置的映射。它没有单独表达双侧关系绑定的两个端口身份、Scope/Sort 资格、等同性见证或注解解释。
5. crates/gift-author-kernel/src/typescript.rs 的 OrderedPlan 生成路径只输出静态序列 Scan 和按顺序执行的 .filter。当前目标不包含关系注解代数、Bag 投影聚合或关系算子目标合法化。

因此，不能把 Join、Semijoin、Exclude 或 Bag 投影直接塞进现有 gift:finite-ordered-records/2，也不能只给 QueryKind 增加几个枚举值便宣称接入完成。

## 必须保持的两条语义路线

### A. 有序 Sequence 方法

继续保持 /2 的原合同：输入是同一完整作者快照中的有限静态 Sequence<Row>，按原始位置保留每次出现；Filter 按既定次序逐次判断。不能因本次关系优化而把它自动变成 Bag、Set 或数据库查询。

### B. 具名有型注解关系方法

新增关系方法必须有独立、版本化的 Method identity 和输入资格。它消费的是有限关系事实及其显式解释，而不是 /2 的有序列表。它必须在方法边界中绑定：

- 精确 Scope identity + revision；
- 每个 Role 的 owner、occurrence identity、显示名与 Sort；
- Sort identity + revision 及合法值/编码/比较合同；
- 明确的双侧 Binding，不从显示名或字段同名推断连接；
- 具名注解代数、单位元、零元、加法、乘法、支持关系及已证明的代数性质；
- 每个 Scan 的真实输入来源、快照修订、读集和来源完整性；
- 谓词的自由角色、纯性、全性、失败和终止资格；
- 输出角色顺序/无序化声明及消费者可观察的结果合同。

Bag 的重复次数与 /2 的 Sequence 出现位置是两种不同的身份与观察模型，必须在转换处显式处理。

## 优化规则的最低证明义务

1. Join 投影下推：投影后仍须保留所有显式绑定端口、剩余消费者字段和谓词字段；Count 的乘法与投影后的加法不能被 distinct 代替。
2. Semijoin：只有明确的 existence-only 画像才可保留左注解一次而不乘右侧权重。Provenance 是否保留见证来源必须单独定义；Events 必须按世界求交/并。
3. Exclude：只能在右侧精确快照完整时使用。开放世界、未授权、部分读取或快照错配不能推导“无匹配”。
4. 角色/值筛选：判定前保留所有自由角色；只有谓词已证明 pure、total 且相关错误/顺序/资源观察保持时才可移动。
5. 共享 DAG：先求所有消费者的需求并集；再决定共享宽节点还是按消费者拆分。缓存键必须覆盖 Scope、Sort、代数、绑定、快照、谓词与方法修订。
6. 零注解：源事实先完整做角色/值/注解类型校验，再按代数消去零项；不能让非法零权事实通过提前删除隐藏。
7. 递归：有限载体不等于加权固定点必然终止。递归方法必须独立声明固定点语义、序/收敛/有界停止资格和资源出口。
