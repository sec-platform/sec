# 成品结构与语义责任

## 1. 交付对象

这次交付是一个可直接使用的本地研究工作台，而不是再增加一种本原、世界维数或分类数。它把既有准确语义片段和全部研究内容接成可以持续使用的操作流程。

整个世界的开放语义设计仍是原目标；工作台只是让已经取得的内容和方法能够被实际消费、比较和修改。它不借“成品”二字抹掉尚未取得的专业能力。

## 2. 真实依赖方向

```text
原研究内容、原出处、原资格 ──完整阅读器──→ 查阅、多维筛选、关系与来源
                 （不自动成为现场事实或语义执行器）

准确模块 + 固定导入 + 类型/绑定/定义/约束
  └─完整有限模型 ──解释器──→ 有型查询 / 分类 / 明示共同资源方法
                              └─结果、条件、覆盖与准确摘要
                                   └─表格、文字和导出

准确前像 + 明确源差额
  └─候选形成 → 全部相交检查 → 差额预览 → 明确采用
                                  └─独立本地修订 → 旧版重放 / 备份 / 可运行快照
```

`gift_core/` 和 `semantic_views/` 不依赖研究目录、HTML、U编号或D编号。`app/engine.py` 组织准确工程的实际消费者；它也不读取资料目录。Python工作进程只解释所声明构造，不执行源中的任意宿主代码。

## 3. 内容与源的身份

研究语料的原ID和原字段保留。研究备注是独立记录，不能覆盖原定义或自签采用。

模型项目的摘要表示准确内容；采用修订另有独立ID、父修订、说明和回执。恢复某个旧项目内容仍产生新的采用记录，而不是覆盖时间线。

查询结果带理论、模型、查询和参数的准确摘要。显示相同不合并发生身份，显示改变也不重写作者决定。

## 4. 预览与采用

预览端点先核当前项目头，再通过独立语义进程取得候选与全部结果差额。数据库仅保存预览；当前头不变。

采用只接受服务端已经保存的预览ID，并在SQLite事务中再次核当前头。过期前像、未知预览或非法输入都不发布。已保存的历史项目不修改。

声明约束决定模型是否符合该理论。某个查询得到false或某项资源选择不合格，可以成为对失败世界的准确描述；因此“结构合法并可保存”和“任务全部成功”分别显示。系统不会为了让结果通过而删除难处理输入。

## 5. 不同修改的后果

- 修改布局或标题：只改变显示。
- 修改原始解释表：形成新的模型候选，旧模型不变。
- 新鲜定义扩展：只有旧类型、符号、约束和导入保持且新增内容可由无环定义体解释时成立。
- 全项目导入：显式选择另一份准确工程并检查；不是定义性等价的自动证明。
- 恢复历史：复用旧内容形成新采用记录，不撤销现实作用。
- 改研究备注：不修改模型或原语料。
- 发起真实动作：本成品没有该能力。

## 6. 可复用的工程接口

`compile_project(project)`：校验工程结构并取得准确理论和模型。

`run_project(project, selection)`：取得实际投影、分类、声明约束与相交资源结果。

`dispatch(request)`：执行明确的运行、查询、表达式、精确单元格候选、新鲜定义候选和全源导入候选。

`Store.preview / Store.adopt`：分开候选与当前头，原子地保存采用关系。该Store管理本地研究项目，不是现实授权机构。

`Service.snapshot`：打包准确项目和必要解释器，独立于资料目录、HTML和工作区数据库。

这些接口没有承诺所有表达可决定；不支持和预算不足有准确出口。完整例子和负例在tests及verification中可复查。

## 7. 全部资料怎样保留

原完整阅读器以相同字节隔离承载。其源数据、关系类型、出处和执行限制仍然存在。上一份完整交付以原ZIP字节和展开成员两种形式保留。当前摘要文件记录整个发行的文件完整性，不把摘要相等作为全部语义正确的证明。

没有新增一套必须与原件同步写入的“世界本质数据库”。本地SQLite只承担明确的新项目修订和备注；研究目录继续由准确来源产生，语义定义继续由实际模块承担。

## 8. 可用程度与最强未完成项

在明确支持的有限画像中，用户现在能够实际构造、解释、分类、修改、比较、保存和导出。这个交付层级已经超过仅有示例代码或设计提纲。

但全部研究文字没有自动获得形式解释，所有专业机制没有被通用Bool代签，现场授权和真实效果没有被模型结果代签。更广的元理论、概率/连续/因果/规范桥和生产目标工程生成，仍需要沿原语义责任继续取得，不靠换一个界面消失。
