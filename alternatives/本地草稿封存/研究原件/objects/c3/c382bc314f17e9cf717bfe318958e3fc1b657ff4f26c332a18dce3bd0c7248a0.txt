# Gift：抽象生成基础、概念派生、控制归属与语言接合研究设计 v0.1

> 研究性设计候选；不是已经被证明的宇宙本体、语言最小基底、可运行语法或仓库正式规范。核查时点：2026-10-31（北京时间）；GitHub `main@7e70f411755d37f2612aa37996a205e892147ca3`，设计候选 `codex/design-closure-20261023@68b8786f70c16bddb14ea357d9d058aa88af68da`。未修改 GitHub 仓库；未运行 Gift 编译器/全套测试。

## 0. 首先解决什么问题

研究产物不是一张从“信息”逐级向下展开到 `if/while/class` 的单向树，而是一个**带语义、适用条件、来源和可逆修改责任的生成网络**。开发者可以在不同尺度声明独立意图；只有那些在本次任务中改变可接受结果、无法从已有合同推导、且没有有效委派的决定才必须请求对应有权人。系统应保留数学表达、实施、现实取证之间的边界。

拟解决的五个问题是：（1）哪些构造是足以形成所承诺语义片段的基础？（2）复杂概念怎样经可检查的规则派生、复合和相互制约？（3）人在什么尺度必须决策，何时可以不决策？（4）怎样接合现有语言、库、工具和已有原生源码？（5）一种语义变化如何传播、验证和回写而不双写作者含义？

“完备”必须总是带参照：相对于已定义的规格类、模型类、观察集合、构造/翻译规则、可实现支持域及真实验证证据。不能从可编码、可求解、可实施、已部署互相代签。不要预先承诺统一解释一切现实、所有可满足任务均自动有限实现、对所有指标全局最优或所有作者绝对最少输入。

## 1. 一个起点、三个候选操作与四项不可缺的接口

建议的**研究出发点**是“在特定语境中能够作出并保持的、有含义的区别”，而不是未经证明的“宇宙只由信息构成”。此处的“一个”是分析对象，不是哲学证明。

三项候选生成操作：

- **D / 区分 Distinguish**：在特定类型、论域、身份政策和观察下，判定、声明或保留不同（也要能准确声明相同）。须区分不同对象身份、值不相等、不同发生点、不同来源、不同权限；不能合并成一份 `id`。
- **C / 组合 Compose**：按有类型接口，把已有内容关联、嵌套、实例化、复用、量化或共同约束；明确是共享、复制、并列、选择、合取、序列、反馈还是调用；没有“所有组合都等价”的规则。
- **T / 变化 Transform**：在明确上下文中形成从前像到后像的关系或构造新的候选；需区分现实状态变化、程序计算、作者源修订、知识更新、解释/规则升级及证明精化，不能将它们全部当成相同的可执行写入。

四项**必要语义接口**，不是“宇宙第四到第七个本原”，也不是新增 Gift 文件类型：

1. **解释与语境**：符号的论域、签名、意义、版本、条件和用于判断的模型类是什么；现实相同名字不自动等于同一对象。
2. **观察与证据**：能看到什么、哪些来源支持结论、覆盖了哪些对象/时期、什么仍未知；无观察不自动是反证。
3. **选择与权威**：谁有权给出要求、接受解释、委托实现选择或批准外部动作；偏好、规范上的许可和真正执行授权分别解释。
4. **目标与完成口径**：需要保留的性质、输入及环境、成功/失败/进展/资源/兼容性要求；要求能表达并不保证所有情形下有程序或高效算法可得。

它们可以由普通 Definition、约束和专门理论具体编码，但不能从裸的 D/C/T 字母自动获取现实含义或权限。建议每个实际模型使用的形式背景是一个明确的解释上下文 `K`：包含本次类型/名称/真实定义、约定输入与环境、可观察属性、已接受要求、有效权威和参考语义修订。`K` 是分析记号，**不要**因此在仓库再造强制的全局 `ContextIR`。

一个适于试验的形式化：

- `D_K(x,y;O)`：在指定观察/身份映射 O 下，x 与 y 可区分。可区分性相对 O；不同身份不代表值必异，值相等也不代表同一实例。
- `C_K(A,B;w)`：依照已声明接口绑定 w 组合 A、B；结果是否有效还取决于类型、身份、共享/复制、前提-保证、作用、时间、资源与来源规则。纯图拼接不证明联合合同可满足。
- `T_K(s,a,s')`：在 K 的合法模型中，a 可以令 s 转为 s' 的关系；若 a 是一次编辑操作，s/s' 是作者修订；若 a 是现实操作，必须有运行权能、结算和读回。两种不能靠相同字段混同。

即使全部内容都可翻译为有类型图、项或集合，**表示的同构并不自动带来语义的同构**。要求（应当）与事实（已经）可能用相同关系符号编码，但仍需不同解释/权威；概率需要测度及条件化规则；因果需要干预解释；时序需要顺序和时钟语义。

## 2. 三项操作的派生网络（不是单线层级）

| 派生入口 | 可由哪些结构性机制形成 | 需要另外选择/证实什么 | 可派生程度 |
|---|---|---|---|
| 名称、同一性、分类 | D + 绑定；等价类、名义身份、类型限制 | 何种相同、命名空间、主体与生命周期 | 需固定身份/类型政策 |
| 部分、整体、结构、记录 | C + 指定成员发生 | 成员顺序、重数、别名、可变性、公开性 | 有条件的结构构造 |
| 属性、函数、多元关系 | D + C + 角色/参数/结果 | 类型、取值域、是否总定义、效果、观测 | 有型关系构造 |
| 集合、序列、多重集 | D + C + 成员/位置/重数 | 相等准则、出现身份、有限/开放论域 | 三种不同集合解释 |
| 基数、计数、数值、单位 | 区分实例 + 聚合 + 运算关系 | 数学域与运算公理、重复计数、单位、精度 | 不能仅凭“区分+重复”推出全部数值理论 |
| 条件、量词、逻辑判断 | C + 谓词/变量的绑定 | 采用哪一种逻辑、否定/未知/空域、解释模型 | 每个选定逻辑内可形成 |
| 状态、事件、历史 | T + D（前后/事件发生身份）+ C（状态分量） | 时钟、轨迹、环境、同时性、观察点 | 结构可形成；解释另固定 |
| 时间与期限 | 事件/观察的排序与时间坐标 | 偏序或物理度量、计时误差、持续与公平性 | 不能只由“变化”推出唯一时钟 |
| 规则、程序、策略 | C 组成的有型结构 + T 的可选转移 | 有效算法、可用信息、分支选择者、终止/进展 | 计算/策略是额外理论 |
| 并行与反馈 | 多个 T 经 C 联合并共享状态 | 交错/同步/因果顺序、固定点、冲突与死锁 | 条件组合；不能自动取唯一固定点 |
| 不变量、保持、性质 | D（可观察区别）+ C（约束集合）+ T（允许变化） | 安全、活性、非干扰、概率等不同性质类 | 依所选语义成立 |
| 意图、偏好、目标 | 可接受模型或行为的选择限制 | 主体、权威、何时选择、比较政策 | 不从物理变化自动产生规范主体 |
| 义务、许可、违例 | T 的历史 + C 的规则 + D 的主体与行为 | 规范效力、issuer、例外、期限、补救 | 必须加入有效规范解释 |
| 知识、证据、不确定 | D（可区分观察）+ C（支持关系）+ T（修订） | 来源可靠性、覆盖、模型/概率规则 | 不能用事实缺席充当否定 |
| 因果、干预、反事实 | 变量关系 + T 的干预变化 | 结构方程、保持背景变量的反事实解释及识别证据 | 观察相关性不够 |
| 资源、效果与权限 | 身份 + C 的资源关系 + T 的转移 | 所有权、配额、独占/线性、原子性、Grant | 物理许可/真实作用另取证 |
| 学习与自适应 | 信息更新 + 候选模型变化 + 反馈 | 损失/接受目标、样本偏差、更新权限、漂移/撤回 | 需要真实训练/评价合同 |
| 源修订、重构、演化 | T(作者源版本) + D(身份/差异) + C(依赖图) | 显式固定与默认升级的区别、兼容/撤销/迁移 | 可设计为精确编辑演算 |

将这些定义形成**有向带类型依赖图**，不是一棵从 1 到 3 到 10 的树。许多概念有多个前提，反馈使图含有合法循环；这时须明示其递归/固定点条件，而不是靠同名节点自证。每条派生边标注四种资格之一：

- **定义性消去**：存在结构翻译，经过相同模型、作用域和观察后意义等价；普通短写适合此类。
- **保义精化**：只保留某类允许观察/指定性质，可能收紧实现集合，不能冒称完全等价。
- **专业语义扩展**：必须增加一个新模型/运算/观察的解释，不能说旧结构已经自动推出它。
- **外部事实或接受**：由真人、合同、标准、仪器或 Provider 给出；只有证据/权威才能授予它实际资格。

每个派生节点的研究产物至少有：独立需求区别、正式形成/类型规则、解释模型、前提、组合规则、反例/证明、默认/委派/权威、实现/验证责任、版本/回写和其当前状态。**这是一份研究元数据模板，不是每个运行实例必须填写的用户表单。**

## 3. 把“信息架构”拆成不同的关系图

不能将所有关系都压成一种没有标注的边。建议在**一份作者权威源、按需派生多种关系视图**下保留以下信息图：

| 信息视图 | 节点/边 | 真正需要保障 |
|---|---|---|
| 定义图 | Definition、Signature、Import、Ref | 名字、身份、解释版本、可见性与绑定 |
| 发生与装配图 | DefinitionUse、ComponentUse、Port/Connection | 发生点、共享/复制、接线、资源/寿命、公共出口 |
| 约束与接受图 | Meaning、Requirement、Goal、Preference、Authority | 所求性质、必须/偏好、来源、独立接受、冲突 |
| 状态/因果/时序图 | Event、Transition、History、Observation | 真实顺序、覆盖、干预与非干预、前后状态 |
| 证据与支持图 | Claim、Evidence、Method、Assumption | 可验证的支持方向、用途、环境、覆盖、失效 |
| 供给与精化图 | Method、UseBinding、Target、Artifact | 实现资格、共同见证、转换保持、目标完整成员 |
| 权限与作用图 | Actor、Grant、Operation、Receipt、Recovery | 实际权能、并发效果、不可逆责任及读回 |
| 版本与变化图 | SourceRevision、Correspondence、Delta、Consumer | 局部影响、迁移、显式固定与继承默认、兼容性 |

这些图相互投影和连接，原始素材不会因此复制成八套可写数据库。Gift 现有 `Definition / Use / Requirement / Goal / Control / Claim / Operation` 等承担实际 owner；需要的是概念派生/消费的**可检查关系**，不要新增同义持久字段。

## 4. 开发者控制：先判意义和权威，再决定显隐尺度

建议把“层”替换为两个可交叉的坐标：

**A. 控制的对象**

1. 意义/身份：究竟是什么、不同对象如何区分；
2. 可接受性：结果、失败、持续、兼容、约束、偏好；
3. 实现自由：算法、库、目标、布局、资源；
4. 现实决策与作用：环境输入、主体承诺、执行授权与接受；
5. 交互表示：怎么展示、选择、编辑，而不改变前四项含义。

**B. 控制的决定来源**：已固定（旧作者/标准/库合同）、严格可推导（系统）、已获授权的委派选择（系统做并在相应语义 owner 固定）、尚未委派且有后果的真正差异（交给有权主体）、外部事实/权限（由实际 issuer 提供）、无法判断（保留 Needs）。

因此用户可在“目标结果”尺度工作，也可控制内部组件、算法乃至目标 ABI；区别只在于那一项决定属于哪一类、怎样保留并向下传播。控制越低并不自动替换上层要求。控制越高也不自动授予对外部世界的执行权。

对于选定的任务上下文 `K`，考虑两个候选实现 p/q：如果在所有已约定的环境和观察下都满足同一已接受合同，且差别没有被用户固定，系统可从合格候选内自行选取；如果改变了公开行为、允许失败、进展/成本硬边界、被固定的实现限制、外部数据/披露或权限，就须依据已有委派或有权决定来处理。**等价未知 ≠ 等价已证**。拥有多个合法不同结果可以是作者明确保留的自由，并不总要选择唯一结果。

控制归属的最小判断流程：冻结任务目的和已有定义 → 找本次真正受影响的观察与独立接受 → 继承固有合同与有效默认 → 严格推导可确定项 → 按已授权政策委派可选项 → 对有后果且未委派的剩余区别提出精准问题 → 有权接受后形成唯一作者候选 → 编译、验证、回写。禁止用“配置列表一定要填满”“默认是后写优先”“AI知道常识”替代上述规则。

三个反例必须常驻设计检验：

- 现在都等于阈值 5：一份显式固定 `5`，另一份继承默认 `5`；默认升级为 6 后含义不同，不能省掉来源差异。
- 两个独立支付发生点金额与字节相同，不应自动合并成同一业务效果；同一业务授权重放与不同授权必须区分。
- 不同算法只要在选定合法输入上保持所需性质，通常属于系统选择；但作者明确固定内存布局或 ABI 时，也须保留这一限制而不是认为“实现细节一律系统决定”。

## 5. 形式基础的竞争候选与选型准则

候选 1：**多类有类型代数/项组合**。以 sorts、operations、terms、equations 和作用规则形成抽象；优势是组合、类型和保义推导，限制是资源身份、开放观测、外部作用及事件不能无代价地当普通纯函数。

候选 2：**有类型带接口图/超图 + 受条件限制的重写**。自然表达发生点、关系、多端口、共享身份、结构修改和效果；可借鉴双推导式（DPO）图重写的匹配、悬挂边与并发条件。限制是图能画出来 ≠ 业务要求真、可求解或具有正确现实效果。

候选 3：**关系/约束逻辑与固定点**。适合允许结果集合、全称/存在、政策组合、查询及有限综合；可用 Alloy、CUE、Datalog、SMT 等成熟方法。局限是开放领域、否定、时序、干预、随机、外部副作用与不可判定问题需专业理论。

候选 4：**状态、动作、过程/重写逻辑**。适合历史、协议、生命周期、并发与恢复；Maude、TLA+、Petri/进程模型及 K Framework 有成熟工作。局限是把纯约束或主观接受硬转成事件流程会增加不必要控制。

候选 5：**异质逻辑/模型之间的解释与保持接口**。以 Institution 理论/DOL 式的签名、语句、模型、满足关系与语义映射接合不同理论；优势是保留不同逻辑与用途，限制是跨理论的精确翻译、保守性和实际工具连接有成本，不是一个统一求解器。

候选 6：**结构编辑/多视图/双向同步**。MPS 式投影编辑或 Lens 式投影/回写给“顶层可操作性”提供候选，不自行解决真实语义或实现综合。

**当前建议的试验组合**：以 Gift 已有结构源码为唯一持久作者权威；以多类有类型图/项为研究和检验的共通结构视图；用不同 Meaning/Profile 承担各自语义；以规则/约束求解、精化和程序合成作为不同 Method；通过真实 source correspondence 对接目标语言。不要把“候选图内核”正式写成第二套 IR，除非实际比较显示现有 owner 无法准确承担某项必要关系。

选型严格比较：（a）相对表达保义，（b）局部组合及非法连接识别，（c）开放定义与老版本保守扩展，（d）新语义的真实来源和消费者，（e）控制/委派决定数与错误恢复，（f）有限方法可得性及复杂度，（g）同源编辑与跨语言目标，（h）真实全生命周期成本。计数“原语数”只是一个指标，不可以单独裁决。

## 6. 一个端到端推导样例：从 D/C/T 到排班产品

**独立要求**：把固定资料中的全部班次分配给有空的人员；每班恰一人，同一人不可被分到时间重叠的两个班次；在合格结果中优先降低个人最大总工时。上述公平准则是本样例已被接受的设计选择，并不把“均衡”一般性定义成这一个指标。

- 区分 D：人员身份 P、班次身份 S、每个班次起止时间、空闲关系的发生点；班次 id 与显示顺序/时刻不是同一身份。时间采用同一坐标、左闭右开区间；可能没有合法排班。
- 组合 C：建立人员×班次的候选分配关系 M；逐班恰一人、只安排可到场者、相同人员对应的班次不重叠。偏好是合格 M 上的一个比较，不能拿偏好取消硬条件。
- 变化 T：形成候选/预览→用户确认→发布；候选可变化，已接受的某份排班不能被自动优化后悄悄替换；资料变更与修订也必须保持旧会话责任。
- 外部接口：谁提供准确可到场事实、谁确认政策、谁有权限发布、实际发布结果如何回读；上述都不能由 D/C/T 的图形自动产生。
- 实现：小规模可以完整枚举；更大规模选择合格约束求解器/规划算法，并检查覆盖、复杂度和预算；若使用目标 TS，可以生成有型输入/结果、合法算法、错误与未决出口、构建资产。不能以仅有函数签名/空 stub 作为实现成功。
- 再次修改：改一个人的可到场事实影响本次候选；改公共公平政策影响其所有消费者；更换实现方法但保持合格 M 集合和接受比较时不改变产品含义；旧发布事实不被新作者源重写。

**对照纯计算**：稳定排序只需数组发生位置、比较关系、输出保序/保重与稳定性；不强制生成权限、支付、观察服务。只有当真实消费者把它接到外部作用时才激活相交责任。

## 7. 语言接合：不要把研究结果简化成传统语法字典

概念生成和语言表面的关系应是：

`独立要求及真实来源` → `绑定/定义/接受` → `Gift 同一可维护作者源` → `所需专业语义的解释` → `联合义务与实际方法` → `目标语言源码/资产` → `验证/运行/回源`。

D/C/T 在这里是用于**研究表达基础的分析操作**，不是强迫所有作者源码改成 `D(...) / C(...) / T(...)` 三个函数。对同一作者源至少支持：简短意图视图、关系或规则表、结构/连接图、精确源码结构、专业模型和局部计算文本；无损可编辑部分可回源，不可无损回写的原生区域明确保留或只读。没有已证明反向转换时不可根据屏幕图重写整个原源。

具体 Gift 映射：

| 研究对象 | 优先复用的现有 owner | 禁止的新负担 |
|---|---|---|
| 名称/类型/定义与发生点 | `docs/作者/结构化源码.md`、Definition/Use、绑定与 Type | 第二套身份图数据库 |
| 允许行为与接受条件 | `docs/作者/需求含义与实现责任.md`、Meaning/Goal/Requirement | 每个业务条件另做一个必须手填的 Goal |
| 组合/控制/源修改 | `docs/作者/第一层语言.md`、组件连接、Control、R0–R5 | 作者手维护展开 IR 和目标副本 |
| 专业语义、跨逻辑保持 | `schema/author/first-layer/SEMANTICS.md`、`docs/作者/组合/语义扩展与领域接合.md` | 用单 Bool/四态/通用 JSON payload 冒充所有解释 |
| 编译承接 | `docs/开发/第一层编译承接.md`、原 P0–P7、C0–C6 | 新建竞争 compiler pipeline |
| 真实验证和控制资格 | `docs/运行/验收/第一层开发面.md`、Assurance/Execution | 以模型通过自签现场正确或授权 |
| 现有实现 | `src/compiler/**`、`src/semantics/**`、`src/bootstrap/**` | 将现有有限 `engineeringIRInput` 查询误称为上述新作者 Reader |

当前设计分支对 `main` 有约 540 个文件路径差异，`src/**` 相对 `main` 无文件变化；增加了作者候选文法、专业 Schema、文档和大量示例。不能据此认定上述新 Reader/Target 已经运行。另有 PR #892 同时修改若干同名设计/Schema，其最终内容需要在正式采用时按语义合并而非照搬一端。

## 8. 语义保持的四组独立关系

1. **定义等价**：对确定的模型、输入、观察、版本和条件，新旧表达保留同一含义及独立来源。例：纯 Boolean 逻辑里的 `P=>Q` 可改写为 `not P or Q`，不能因此重排带效果的计算。
2. **上下文观察等价**：在明确的允许外部上下文与观察中，差异是否可被区分；当前输出一致不足以证明未来升级/并发/失败下等价。局部可计算的上下文集只能构成有限保证。
3. **精化保持**：一个目标实现的行为/策略满足公开保证、正常成功、失败、进展及资源的实际要求；数值、概率、权限、信息可得性与组合需各自的保持关系。限制允许实现空间不是与原意图完全同义。
4. **视图—源回写**：保持隐藏内容，来源与身份，保证在可支持编辑上的 `GetPut`/`PutGet` 类型规律及陈旧重基协议；无损文本要求另检查 CST/字节等更强范围。

对每一条替换/Lowering/Adapter 都要知道它声称的是哪一种，何时有正确性证明，缺证据保留什么 Needs。绝不能把目标类型检查通过当作现实意图已被真正接受。

## 9. 研究实施方式：逐项产生实物而非无限讨论

### R0. 固定基线、禁止双写

取 GitHub 指定 commit 树，定位已存在的 Definition/Use/Goal/Requirement/Meaning/Control/Method/Claim/Operation、候选编码和正式 status；输出文件/概念所有者图及冲突范围。尚未有正式授权，不动 `main`，不新建第二权威规范。此步已经部分完成：`main@7e70f411`、设计候选 `68b8786f`、PR #892 并行差异、`src/**` 无新通用生产 Reader。

### R1. 定义独立参照与观察合同

不要用“现有 Gift 能表达什么”来定义测试域。选典型但可相互区分的参照理论/性质：有限经典关系及序列重数、值与实例身份、时间/持续与活性、纯计算/非终止、并行共享资源、概率/零事件条件、知识与不完整观察、规范权威、干预/因果、连续数值与误差、流与更正、公开协议及回调、构建/资产与 ABI、后继修改及兼容、现实权限及不可逆作用。每类须给正例、最强反例、边界条件，另选择跨类耦合（如支付+并发+迟到证据；纯函数+别名资源；规则+反向更新）。

### R2. 候选基底的准确形式化

让 D/C/T、代数/类型、关系/约束、图/重写、异质逻辑桥等拥有同等的参照任务、类型和失败定义。写出形成和判断规则、递归/反馈条件、可观察等价、来源/权威如何接入；对每个候选识别它只是可编码还是可以局部保义。输出完整可比较的解释及小模型，不只列术语名。

### R3. 构建“派生边”并真正消去

对每个候选高级概念尝试从已有基础构造翻译；成功时给逐规则解释和保义证明，失败时交一对旧界面不可区分、新规格却要求不同结果的反例；还要检查它是否实际上是缺数据/Method/Provider。正式输出：派生 DAG/合法 SCC、定义/解释及其读集、可简写边、需要专业扩展的边。此环节决定“哪种新的核心区别真有必要”。

### R4. 交叉作用与反馈

组合不是把两个各自正确的模块并列：必须核同一实例/主体、量词和决策时点、环境假设、共享状态、资源、失败和证据。递归、重写规则与单调固定点在已证明条件下形成；非单调否定、异步、公平、随机耦合、跨运行与真实外部作用以专业语义接合。独立证明安全与进展，不允许全拒绝/永等待伪造完成。

### R5. 决定权与用户视图实证

同一参照任务在四种入口尝试：自然语言形成候选、规则/关系、结构/图、可选程序/原生代码。对每种准确记录：作者独立决策数、需重新解释的业务决定、实际修改路径、不可推导的缺项、相交源与回写的稳定性、工具开销和总完成成本。控制策略接受证据优于以标题分层划分角色。可并存 Pareto 候选，不造任意加权“最优分”。

### R6. 与 Gift 和目标语言做保义映射

冻结一个实际作者候选，沿既有 P0–P7 及目标写入责任做精确映射：一份纯计算/列表关系、一个有状态与共同资源/确认的产品、一个多根完整工程。验证首次形成、至少一次局部改动、一次共享定义修改和一次实现替换；每条成果要能区分：已设计、已编码、结构校验、解释成功、已合格 Method、目标编译成功、实际运行/验证通过。首目标可以用现有 TypeScript，不要求先创建新 `.gift` 文本语言或实现所有专业求解器。

### R7. 比较、采用、重开

逐目标判定是否比直接成熟语言/库、AI 生成普通代码、独立专业求解工具等更有优势。若一个成熟方案已满足必要控制、保义、成本和演化目标，应直接采用或提供适配；已有设计投入不构成保留理由。反例根据失效的正式命题定位到原 owner，重算相交结论，保留已有正确材料；完成有限范围后正常退出活动研究，不要求“宇宙最小性”作为所有项目交付的先决条件。

## 10. 检验矩阵与失败出口

| 检验 | 合格出口 | 不能称成功的情形 |
|---|---|---|
| 基础形成 | 对独立参照类的每个合法构造有类型、有意义的翻译 | 仅能把任意外部文件塞入 opaque payload |
| 区分保全 | 两个含义不同的要求不会在相同语境中被无差别合并 | 同值不同实例/发生/接受/默认被消除 |
| 组合闭包 | 保留同一见证、绑定、允许输入、作用与寿命 | A/B 各有实现却没有一个共同实现 |
| 动态与反馈 | 真实历史、前提、终止/进展、并发边界明确 | 把流程箭头当作已经授权且按时执行 |
| 多逻辑桥 | 映射方向、环境、属性类、语义保持证据明确 | 仅将不同专业术语转写成 Bool |
| 开放扩展 | 新区别有实际定义、解释、消费者和回源 | 新建名字/Kind 就冒称理解、可运行 |
| 最小控制 | 可推导与可委派内容自动接续；独特、有权差异准确保留 | 为省问题删掉必须接受的业务政策 |
| 目标实现 | 合格的真实算法、完整工程成员和有效检查 | 只有接口签名/测试模板/空生成器 |
| 现实与权限 | 有效授权、来源、证据、实际结算及恢复 | 根据规范“应付款”直接声明已到账 |
| 演化 | 编辑原源，保留未显示内容，准确重算相交消费者 | 把派生代码与作者 JSON 变成双写 |

在本方案里，“无解/未找到/未经证明/没有语义解释/现实未知/无授权”分别具有不同完成边界。拒绝所有输入不是对可用语言的正向验收。

## 11. 当前结论和下一次研究要推翻的具体假设

- **已支持的判断**：图/关系/类型/重写等可以在明确片段中构成复杂信息结构；不同专业逻辑可通过显式语义映射连接；作者结构源不必是一种按行编写的传统文本语言；一份被接受的唯一权威源可具有多个派生视图。
- **当前方案的推导**：D/C/T 适合用作发现候选构造的分析坐标；复用现有 Gift Definition/Use/Goal/Requirement 等比强制重写成 `D/C/T` 原语更少引入竞争写源和迁移风险；精确意义、来源和权威不能由裸三操作自动赋予。
- **尚未证实**：D/C/T 是在任何选定成本函数下的最优基底；这些操作严格不可消去；全语言的所有专业语义有机械保义证明；现有作者主面实际比成熟工具更省时；真实 Gift 已由候选作者语义完整生成目标工程。
- **会改变方向的反例**：某独立需求的可观察区别无法用现有结构组合与专业接口保留；某成熟作者语言/库在同等保证下全面优于现方案；新底层基底使作者必须重复维护更多独立语义；或候选抽象在真实运行/演化时无法保持本应保留的权益/历史/证据。

原则：研究只应向已发现的真实信息损失和实现证据缺口扩张；设计得更抽象不是目标本身，完整有效的生成、理解、控制和维护才是目标。
