# Gift 通用关系统一工作台：直接使用

本包继续使用原工作台和全部完整研究资料，新增通用方法调用与关系计划。它是可运行的本地研究成品，不是生产Gift发布或完整世界解释器。

## 启动

需要Python 3.10或更新版本，只使用标准库。Windows双击`启动工作台.cmd`；其他系统在包目录执行：

```sh
python3 launch.py
```

关闭终端或按Ctrl+C停止。只监听127.0.0.1；默认工作区在`.workspace`。完整研究资料也可直接打开`Gift_语义工作台.html`离线阅读，但离线模式不会冒充后端执行。

## 已有工作区的迁移

1. 进入语义工作区，运行旧源。
2. 点击“预览迁移为通用调用格式”。
3. 检查原查询、分类和资源结果均保持，候选尚未写入当前头。
4. 明确确认后产生新修订。历史中的/1源仍然可重新运行。

不在旧目录中直接覆盖整个应用。将本包解压到新目录；旧工作区需要转移时，用原导出备份与`restore_workspace.py --target 新目录`恢复，再以`python launch.py --workspace 新目录`启动。

## 直接查看通用结果

在“完整工程源”页面导入下列JSON，先预览后采用：

- `projects/relation_world_v2.json`：从已解释的edge关系形成两步关系，不依赖共享设施。
- `projects/six_interpretations_v2.json`：同一个关系计划分别取得存在、重数、成本、有理权重、来源与事件结果。
- `projects/unified_facility_v2.json`：同一模型中同时计算单项合格关系和共同资源方法，不以一个结果替另一个。

六种解释例中，将same_plan_count的R第一行annotation从2改为5，再导入候选。计数应由10变19；其他五种方法未改输入，不会因此发生同样变更。修改标题则不会改变任何语义结果。

## 声明自己的方法调用

`methods`是调用位置到准确方法说明的映射。`method`固定id、revision、profile。`arguments`是字面数据。需要使用当前选择时，另用`bindings`绑定顶层参数；字面数据内出现类似字段不会被当作指令。

已安装方法可在页面中查看，或者GET `/api/methods`（需本地会话凭据）。新的业务定义属于原模块；新的算法作为可信安装方法接入。源文件不能提供任意Python路径或shell命令。

## 快照、备份与重放

“修订与导出”可下载独立语义快照。解压后执行：

```sh
python run.py
```

得到`result.json`。快照包括实际解释代码、方法引导和准确源，不需要目录、UI、网络或第三方库。它不是生产目标代码，也不包括现场授权。

工作区备份保留修订历史和备注；恢复只写新目录。旧源的字段和所有已有研究内容不因本轮迁移删除。

## 复核

```sh
python tools/check_unified.py
```

重新运行本轮40项集成检查、原17项关系性质测试、原54项应用回归和实际示例。浏览器检查单独位于`tools/check_unified_browser.py`，需要Playwright和Chromium，不是运行应用的前置。

实际检查结果见`verification_unified/`。读取其中报告时保留测试环境和范围，不把有限检查解释成世界语义完备或生产能力签发。
