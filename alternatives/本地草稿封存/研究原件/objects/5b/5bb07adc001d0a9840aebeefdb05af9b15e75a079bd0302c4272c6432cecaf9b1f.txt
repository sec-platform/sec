# Gift 语义工作台 · 本地研究成品 1.0

交付日期：2026-11-03。

这份成品把既有完整内容、多维检索与关系、准确语义模块、模型修改、差额预览、采用与历史、独立快照放在一个实际入口中。可用范围是下述明确的本地研究任务，不将其称为完整世界模型或生产 Gift 编译器。

## 1. 打开与启动

**只读全部内容：** 直接打开 `Gift_语义工作台.html`，进入“全部内容与多维结构”。不需要 Python、联网或服务器。浏览器须支持本地 `DecompressionStream/gzip`；不支持时直接阅读 `docs/` 或 `reference/data/`。

**启用计算和持久修改：** 在 Windows 解压完整包，双击 `启动工作台.cmd`。需要 Python 3.10 或更新版本；不需要安装第三方库。页面会在本机浏览器打开。未安装 Python 时，脚本不会自动安装，仍可使用只读 HTML。

macOS / Linux 可在包目录运行：

```sh
python3 launch.py
```

也可以指定一个新的工作区：

```sh
python launch.py --workspace ./my-workspace --port 8765
```

服务只监听 `127.0.0.1`。端口已占用时会另选本机端口，以控制台给出的地址为准。关掉控制台或按 Ctrl+C 即停止服务；没有后台计划任务。不要将它部署到公网。

本轮实际执行环境为 Python 3.13.5 与 Chromium 144.0.7559.96；没有在所有 Python/Windows/macOS/浏览器组合上实测。

## 2. 一条已经实测的操作路径

1. 进入“语义工作区”。原模型中 r1、r6 各需4单位，在同一 `[0,2)` 区间使用同一容量6的资源。二者各自局部合格，完整共同选择却超额。
2. 进入“模型数据”，点击 `r6改为[2,4)`。这一步只填入候选，不修改当前源。
3. 点击“预览并重新计算”。系统检查准确前像、类型、完整解释表和共同模型约束，实际重算所有登记的无参数查询以及所选资源检查。结果显示新共同峰值4；候选仍未采用。
4. 阅读差额，点击“确认采用为本地新修订”。此时才在 SQLite 事务中发布新头；原修订仍然存在。
5. 进入“定义与查询”，检查预填的新概念模块和查询后，点击“检查扩展并预览”。新符号通过已有对象、关系、量词和数量运算定义；不增加原始事实或硬要求。采用后，新查询出现在结果中，旧查询含义不变。
6. 进入“修订与导出”，对原始修订点击“重放结果”。仍可得到原来的联合超额，不用当前结果覆盖历史。
7. 点击“导出独立可运行快照”。解压后执行 `python run.py`，产生 `result.json`。该快照不包含研究目录或界面，也无需网络。

这些操作都针对准确的假设模型；没有创建现场资源预留、取得权限或执行设备动作。若模型描述的是失败情景，结构合法的候选可以保存，但不能因此说它满足全部业务目标。界面分别显示模型合法和所选共同资源判断。

## 3. 不只是固定演示

“完整工程源”可以导入完整的 `gift-studio-project/1` JSON。包内 `projects/relation_world.json` 是另一份无共享设施、义务或权限名称的工程：三个节点与完整关系解释，普通定义计算后继存在及两步返回，分类由谓词产生。选择这个文件、校验候选、确认采用即可切换到另一准确世界模型；旧工程仍在历史里。

项目包括：准确模块、版本锁定的根、完整模型、声明式查询、分类政策，以及已安装方法所需的符号签名。核心按形成规则和声明解释，不按 U/D 编号或业务名称决定意义。

“模型数据”可编辑任何已声明原始解释表的准确单元格，不只编辑演示按钮中的字段。派生定义不允许在原始表里覆写。

“定义与查询”允许改写实际查询源和参数。共享设施工程预填共同超额伙伴示例；导入其他工程后，界面按当前类型预填一个准确的自等定义模板。它只是明确示例，不自动猜测业务含义；实际新概念仍由你的定义体决定。

全源导入不是无损视图的任意逆写。编辑聚合显示如“总量8”时，不自动猜测该削减哪个请求；需要准确单元格或明确源内容。

## 4. 内容与结构保全

入口完整包含原1,786项单元、568项问题合同、31,324条登记关系、62项理论和93份规则/裁决，以及原来源、分类与多维归属。它直接复用并隔离承载了原全量阅读器；没有用新的摘要替换原正文。

其中导航、资料引用、词面线索、组级画像、单项研究判断、条件语义接合保持原资格。能查询到记录不表示它已证明；多个资料包不自动表示独立证据；未连线不表示不存在关系。568项问题不是568个已经安装的求解器。

`reference/` 保存上一份完整可运行交付的原成员；`baseline/previous_delivery.zip` 保存其完整原压缩字节。新代码只在独立 `app/`、界面和本地工作区中接续，未改原 `gift_core/` 与 `semantic_views/`。

## 5. 知识与模型、事实与许可的边界

原语义文字作为研究材料查阅。实际进入计算的是被准确模块声明、绑定和解释的模型内容。研究记录存在，不会自动成为模型事实。

模型许可不等于现场授权。增加记录覆盖值只改变假设模型里的知识条件，不等于实际收齐现场历史。修改模型不改写真实过去，也不产生真实执行。

同一显示值可以有不同发生身份；投影保留根身份，r1和r6不会因字段相等被合并。改变标题或列标题不修改模型；改变含义则必须经过准确源及修订。

## 6. 持久化、备份与恢复

默认工作区是包目录下的 `.workspace/workspace.sqlite`。语义修订、当前选择和研究备注持久保存。程序升级或删除包之前，请导出完整工作区备份。

研究备注带独立版本。它不会直接改写原1,786项，不授予正式采用或事实资格。两次编辑竞争时检查前像，旧版本写入会被拒绝。

“导出完整工作区备份”得到 JSON，包含所有修订、原项目内容、采用回执、备注版本和当前头。

恢复到**不存在的新目录**：

```sh
python restore_workspace.py Gift_工作区备份.json --target ./restored-workspace
python launch.py --workspace ./restored-workspace
```

恢复前重新检查项目摘要、父历史、完整源合法性、当前头和备注版本。已有目标目录不会被覆盖。仅核验而不写入：

```sh
python restore_workspace.py Gift_工作区备份.json --check-only
```

在界面直接导入备份文件时，只提取其当前工程作为候选。要恢复全部历史和备注，应使用上述恢复工具。

## 7. 独立使用，无须界面

运行准确工程：

```sh
python tools/run_snapshot.py projects/shared_facility.json --output result.json
python tools/run_snapshot.py projects/relation_world.json --output relation-result.json
```

完整原分类和旧语义投影可继续由 `reference/` 中的原程序重建。执行原回归会产生其结果文件，因此本产品的回归工具在临时副本中运行，原件不变：

```sh
python tools/verify_release.py
python tools/check_baseline.py
```

浏览器检查可选，需要检查环境另外具有 Playwright 和 Chromium；普通用户运行成品不需要它们。

## 8. 当前准确支持范围

- 多类经典一阶逻辑；变量身份、绑定、类型和元数检查。
- 准确版本导入与摘要核对；同一解释中不静默混用同身份的不同修订。
- 非循环定义；完整有限自定义载体和总函数表。
- 精确整数、有理数、文本和布尔值；无限内建域不会通过取样伪装成完整量词计算。
- 有型声明式投影；参数明确；失败和预算耗尽不释放部分行冒充完整结果。
- 有条件的新鲜定义扩展；保留旧载体、符号、约束和模块；原包的单射重命名方法保留。
- 明示有限常量负载、同名时钟、半开区间的共同资源检查。
- 受检查的本地候选、原子采用、历史查询、恢复为新修订和独立快照。

没有取得：所有1,786项专业形式化；全部568问题的求解器；一般递归、高阶或依赖类型；通用证明、综合和完整生产Target；所有连续、概率、因果、规范理论的解释与跨理论证明；完整现实模型对应；现场身份、授权、执行或部署。

这是当前支持范围内的可使用研究成品，不是对整个世界已经完成形式化的声明。

## 9. 安全和预算

本地接口使用每次启动生成的会话凭据，核对Host与Origin，不开放CORS，没有任意路径读取、任意Python执行或材料指定插件入口。不调用 GitHub、邮箱、日历、设备或支付服务。

模型请求最多2MB，另有结构深度、节点、整数位数、符号、查询数量和解释步数预算。每次计算进入独立进程，父进程有14秒超时；Linux还设置CPU和地址空间限制。Windows没有相同的地址空间限制。它不是完整的恶意输入隔离沙箱；不要公开监听，也不要向他人提供多租户保密服务。

HTML包含已经交付给你的完整研究材料。界面筛选不是秘密隔离；不要把秘密放进离线文件后声称“没显示就没披露”。

## 10. 本轮实际核验

以 `verification/` 的实际回执为准。字段/哈希保全、接口和浏览器测试不代替语义定理或现实事实验证。

当前浏览器管理政策阻止直接localhost导航。本轮使用同一HTML内容载入，并用Python桥传输真实的本机HTTP请求来完成界面到实际后端的测试；没有声称当前环境验证了原生 `file://` 或原生localhost导航。HTTP本身另用真实客户端独立检查Host、Origin、凭据和接口。

代码、输入、结果、限制和屏幕截图都包含在交付中；没有新增字体文件。
