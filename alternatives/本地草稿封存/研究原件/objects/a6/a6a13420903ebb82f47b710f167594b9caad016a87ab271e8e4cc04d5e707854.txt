# Gift：统一语义模型（唯一主稿）

> 2026-11-05 · **模型设计基线**。本文取代本次精简工作包的多份导航、维度总数宣言、重复结论与应用演示说明；保留原研究全文与条件于 `data/research_model.original.json`，未修改生产仓库。称“已设计”不表示“已实现、已验证、已部署”。

## 一、目标和不变的边界

**Gift不是要求开发者写 `fn/let/for` 的新文本编程语言，也不是从1,786个词条或568列Excel直接拼程序的工具。** 人/AI在共同的作者语义上形成、采用、连接、约束和必要地控制实际工程内容（对象、组件、端口、关系、状态、行为、输入输出、效果、资源和目标）；文本、图、表都是同一内容的操作表示，已有原生代码也可作为有明确owner的真实源。系统只在已有解释、真实供给或合法创作的基础上取得实现，最终按选定目标生成完整源代码、配置及资产。

同样，Gift的语义模型可描述数学、物理、社会、知识等非程序内容；这些描述不自动成为编译任务。世界描述、工程要求、实现方案、目标产物、外部现实是不同对象，不能相互代签。

**原多维研究的正确角色**：发现全部已知必要区别，为Gift模型的形成、解释、关系、条件和扩展设计提供覆盖要求、反例和可检索依据；其查询合同又可由模型生成分析投影。不是仅用于导航，但也不能把568个问题机械提升为568个实体种类或568根固定维度。

这里的“统一”指一套共享准确身份和解释/组合约束的体系。它不强迫所有领域采用一个万能GraphIR、同一种Bool、一个全球writer或一种物理存储。

## 二、真正的底层结构：谁拥有含义、谁只是消费

| 实际责任与原规范owner | 需要真实保存/形成的东西 | 不允许的错误合并 |
|---|---|---|
| **Definition / Type / Expr / Meaning** | 声明、结构或函数/关系/行为定义、形成规则、变量/角色绑定、参数、精确解释修订 | 不能把名称、JSON schema、D编号当作含义；不能把普通关系当调用、把组件实例当值 |
| **Use / Instance / Relation application** | 实际采用发生点、具名端口/角色实参、同一实例与独立实例、重复次数、局部配置 | 同名或同值不等于同一实体；图边不自行解释所有权、广播、执行次序 |
| **Requirement / Goal / Control / Decision** | 允许输入域、应保留的结果/历史、失败、进展及边界；硬要求、偏好、被委派与显式固定的实现差异 | 偏好不消除硬约束，算法选择不悄悄改变公开产品承诺 |
| **Model / Theory / Qualified Method** | 适用解释、模型类或具体模型、逻辑/概率/时间/因果/规范等领域规则与算法资格 | 某有限解释器不能冒充所有专业理论；可表达不等于可决定、可实现 |
| **Source / Observation / Claim / Evidence** | 原字节、出现/发生与记录、精确主张、来源与独立性、支持/反驳、覆盖、未知和审查资格 | 签名有效不证明含义正确；模型为真不证明现实为真；观察不签发许可 |
| **Semantic/Source Revision 与 Correspondence** | 原owner、语义修订、解释和源修订、目标产物及运行代，映射/变更前像/失效关系 | 内容相同不证明授权和未来行为相同，删除索引不能删除历史原件 |
| **Method / RealizationBinding / Target** | 同一可接受实现、真实实现来源/锁、前提、效果和目标保持、生成源码与构建资产 | 方法注册不等于已实现；每条需求分别合格不代表一个共同实现存在 |
| **Projection / Editor** | 查询、维面、工作台、布局、文本/图/表/源码视图及明确回写规则 | 目录/渲染没有改源权；不能把未经同义证明的有损视图强行逆写 |
| **Runtime action / Grant / Receipt**（需要时） | 执行身份、实际许可、物理效果、回执与恢复 | 编译成功或模型允许不自动成为真实执行 |

这些是**语义责任角色**，不是规定必须新增九种存储表或原语。相应定义已在仓库属于已有原owner：`docs/作者/第一层语言.md`、`docs/作者/共同语义关系.md`、`docs/作者/组合/语义扩展与领域接合.md`、`docs/信息/全体系信息结构.md`、`docs/开发/第一层编译承接.md`。本稿收敛其相交问题，不建立第二套可写Gift模型。

### 2.1 最通用的关系到底是什么

**不是无类型的 `A → B`，而是在准确理论T、环境K下的一次有型、多角色关系应用**。举例 `R(提供者:p, 接收者:c, 通道:k, 使用发生:u)`：要有关系定义、角色类型、实际绑定、共同发生、条件与解释。只有该关系定义规定了合成律，才能把它与下一个关系组合；只有接口相容且资源/效果/进展前提成立，才能做执行组合。

结构、数学关系、知识支持、因果作用、权限、资源、调用与变换之间**可以共享身份、绑定、条件和依赖机制**，不能共享未经证明的同一推理律。理论桥要携带实际映射和性质保持依据；未知专业机制可保全，但不能当成已解释结果。

模型需允许：开放声明/用户定义、参数化与卫生绑定、名义相等及别名、部分和无限域、关系的多元共同条件、作用/历史、递归与固定点（按专业）、选择权及信息、连续/概率/因果解释（按专业）和不同认识状态。**允许表达，不等于当前已经全部有求值器。**

### 2.2 什么时候才新增公共结构

1. 若已有类型/参数/关系/组合能够保义表达，就**只新增普通定义与实例**。
2. 含义清楚但无算法或目标供给，增加合格Method/Target映射，不改原含义。
3. 专业解释确实不同，增加有形成/解释/保持合同的领域接口，不把全部逻辑变成Bool。
4. 只有对一项有独立区分见证的内容，原公共结构无损容纳确实失败，才修改相交公共规则；需要实际受影响消费者及迁移验证。

绝不因来了一个新行业名、一个新D问题、一幅图或一个业务例子就新增核心关键字。

### 2.3 可供实现者检查的模型接口（不是新文件格式）

为避免一份大而空的“世界节点表”，每个实际作者模型至少按其真实内容解释以下关系，缺少无关角色时不制造占位：

```text
Definition:  签名/名字解析域 + 类型和角色 + 实际定义体或已取得的领域解释
Use:         引用Definition@修订 + 本次采用发生身份 + 真实参数/端口绑定 + 实例策略
RelationUse: 关系签名 + 同一次参与者的具名角色 + 适用条件/解释修订
Requirement: 被约束主体和输入/环境域 + 应保持的结果/错误/状态/资源 + 接受来源
Method:      目标效果和实现能力 + 前提/保证/限制 + 实现来源/版本 + 合格消费者
TargetUse:   固定Method/UseBinding + 目标语言/工具/依赖 + 观察对应及源码映射
```

这是一张**互相依赖的接口速查表**，不是要求用户手填以上六份记录，也不是替换仓库中原Definition、Meaning、Requirement、MethodSpec、Engineering IR的第二套规范。真实类型、逻辑、求值和资格判定仍由相应owner决定。

形成顺序按实际引用而定：解析/选择正确作者源，绑定定义与发生，检查类型及专业解释，组成结构和要求；只有要生成程序时才取合格Method与Target。不涉及证据、权限、真实动作的纯定义不自动产生审查/操作台账。

**F01—F20是对内容和使用的一套研究视角；D0001—D0568是可被精确提问的专业合同。它们同时承担“设计输入”和“将来派生查询”的责任，但绝非统一的568列对象属性。** 逐项原问、输入、答型、来源U与模型责任全部见 `data/多维到Gift模型_568项逐项追溯.json`；不是仅保留名称。

### 3.3 实际怎样消费568项而不增加568个编译步骤

一个D合同有subject、selector、准确答案结构、解释与条件。建模时先从它提取**必须保留的区别、产生这个区别的专业规则与可能的反例**。把它交回相应已有Definition、Meaning、Requirement、Model、Method、Evidence或Target owner。已得到形成与解释后，才可以按D的签名查询；没有取得时保留Needs/unknown并标识欠缺的实际方法。

例如：`D0048`要求同一次关系中每个角色绑定正确；这是通用关系应用的形成条件。`D0089`要求量词树保留嵌套和共享见证，这是逻辑/绑定结构。`D0172`和`D0175`分别要求事件与记录时间。`D0245—D0247`要求随机样本空间、事件集合和真实测度，不允许把相关事件独立乘概率。`D0294—D0296`要求目标、强度、规范模态。`D0423`要求实际Method合同。`D0444`要求可回写视图对应。`D0560—D0568`负责当前查询的适用/资格/覆盖，而不是多出九个世界基本值。

**反例：**`D0001.scheme`需要 `ConceptScheme`，旧研究接合却连向D0558的 `ResearchCoverage`。类型不符，不能把它用成数据供应或语义依赖。这个错误不否定研究的覆盖价值，但禁止将1,294条问题连线无条件编成IR。

1,786条原U是为了找到上述区别的定义、机制、例子和来源材料；2,148份去重后的U—D内容对应只表明它们有研究支持关系，**不是2,148项可执行算法或现场属性值**。62份理论和93份规则按各自范围保留，参考文献不能自动授予生产实现资格。

## 四、工程内一次正确的非代码作者操作

用户在画布或表格建立一个**共享资料源**、两个独立**视图组件**，把共同源连接到两个读取端口，分别给出各自不同的筛选阈值；指定同次查询的结果要保留输入顺序与重复项。开发者没有写函数、循环或闭包。

- **声明与采用**：源定义与两次视图`Use`各有身份；两视图共享同一个资料源，但各自参数/局部实例独立。
- **连接与接口**：源输出、视图输入有类型；“共享引用”不同于复制资料或重新查询；接口规定值传递、订阅或调用。
- **行为**：定义在一次读切面上对序列应用已选比较关系，输入顺序、重数和失败政策完整保留；可以沿普通定义组合，不要求业务专用Block。
- **要求**：如完整覆盖、目标运行环境、数据一致性和异常响应，只在真正被接受时加进实现资格；既有关系确定的无需重复填。
- **实现取得**：复用合格函数/库或在系统获授权范围内生成可执行计算；同一实现组合必须满足全部有效要求，并经过Target lowering。
- **输出**：实际TypeScript函数、组件模块、导入、类型、必要配置/资产和来源对应；没有Method或目标能力时明确Needs，不能制造空函数宣布完成。
- **再次编辑**：局部比较`≥→>`若已有准确绑定，直接改比较规则，重新编译相交使用者，不调用568个问题、审查全部证据或重构整个工程；若改共享定义，才按实际依赖确定所有使用点。

这个例子只用于约束**实现关系**，不能从“描述可写”推成“完整Gift编译器已能做到”。

## 五、从语义到真正完整目标程序

**应用编译主线**：读取本次作者修订与确定导入→类型/角色/身份/含义绑定→组合有效结构与被接受的要求→复用合格Method或合法创作候选→核共同实现可接受性→选择目标并lowering→生成合法源码、配置、资产→运行真实工具链检查→在准确owner上完成后继修改/保留旧实例。对简单任务跳过不存在的工作，编译不是每一步都自动做全域证明。

特别区分四条方向：

1. **忠实解析/表示变换**：改变源的表示，保持绑定/含义及原生保全义务。
2. **定义性展开**：在有前提时新增可复用定义，不能改变旧定义的解释。
3. **实现精化**：从允许实现集合取得一个合格策略，通常减少合法实现自由，不要求逐行为等同所有候选。
4. **Target生成与真实执行**：根据适用目标规则保持用户要求的结果、错误、效果、时间/资源等；执行另需要真实资格。

类型同型、名字相似、查询边连通不足以提供目标保持证明；只有当前实际需要的专业保证才被请求。完全无关的研究材料不应进入平常编译输入。

## 六、修改、依赖、查询和多视图

准确变更的最小形式是：`owner + source@revision + location/binding + new semantic value + accepted change scope`。源编辑先形成候选；单处改动可局部检查，引用范围涉及多个采用点时才按真实依赖扩散；缓存索引是可重建的，不成为第二真源。缺实际影响依据时报告可能受影响和未覆盖，不能因为值不变就认为未来资格不变。

查询/分类也是模型的真实消费者：18域、136组、20维面、568合同继续用于检查模型遗漏、显示实际内容、构造分析或审计。但索引和文本视图不是对模型写入的权威。对于有损图表回写，必须能够定位唯一源owner和保持隐藏条款；不能确定时拒绝或请求真实差异。

**任何分类的值都不是世界的元信息真值**。一次现实观察、一条断言、一条定义、一个研究概念同处“知识族”，并不具有同一种真实性、作者权或可执行性。

## 九、本次新增：从统一模型到可检查、目标中立的 Gift IR（2026-11-05）

本节**是实际执行增量，不替换上文的模型职责**。本包只有这份模型主稿和README作为维护文档，全部研究原文字节仍位于`data/research_model.original.json`，568项逐项研究映射保持于`data/多维到Gift模型_568项逐项追溯.json`。原始更大归档保持在单独的研究文件，不在每个发布ZIP内重复嵌套。

### 9.1 一个明确但非万能的 IR

Gift作者可以经图、表、结构输入等方式形成非代码模型：**Definition（定义）+ Use（独立采用）+ 具名端口连接 + Requirement（要求）**。用户不编写`fn/let/loop`。系统把被选根的内容解释成派生的目标中立IR，再按选定且真正安装的专业解释和Target生成普通源码。

本次真实采用的IR记录格式为`gift.typed-implementation-ir/1`。它包含：

| 字段 | 实际职责 |
|---|---|
| `identity` | 工程身份及作者修订；有意义名称与物理文件路径分开 |
| `source` | 精确作者源的SHA-256；未被选择的内容及原格式仍由原字节拥有 |
| `research` | 原多维模型的准确摘要及其**设计依据**地位；不作为当前运行数值或权限 |
| `semantics` | 实际安装的专业解释画像；不可把新名字当成已支持算法 |
| `records` | 名义记录类型、字段、`I64/Bool/Text`；这是此次安装的窄画像而非全部类型系统 |
| `nodes` | 使用发生身份、定义修订、专业Method、真实具名输入角色、参数、表达式定义和输出类型 |
| `exports` | 准确公开结果根和来源；不由输入字段顺序随机决定 |
| `obligations` | 本次经实际Method承担的要求；当前只支持完整有限有序序列中的顺序及重复保持 |
| `ir_sha256` | IR发布载荷内容身份，**不是证明两种作者写法语义等价的唯一依据** |

最重要的区别：**原Engineering IR侧重工程事实及索引，受支持的专业模型负责实际语义；这个执行IR是按所选工程根从它们取得的消费视图，不是第二套可编辑世界本体库。** 在正式`sec-platform/sec`中，应由既有Definition/Meaning/Use/Requirement/Method/Target owner生成并消费，不应另外注册一个竞争writer。目前尚未提交GitHub，也没有完成这些实际仓库消费者的迁移。

### 9.2 此次已安装的真实语义画像

`gift:finite-ordered-records/1`是一个有限、有序、允许重复出现的记录序列模型。当前方法分别为：

- `sequence.literal`：提供准确有序的记录发生，而非推断外部世界事实。
- `sequence.filter`：在相同输入发生域上筛选，保留原顺序及重复次数；谓词要求`Bool`。
- `sequence.project`：对每次发生按准确具名列产生新记录，不进行隐式去重。
- `sequence.join`：在两份输入的具名共同角色上，使用左优先、右次序的有限嵌套匹配；输出每次合格组合，不把同值的两次发生合成一次。

可在这些方法内组合基础的`I64`精确比较和检查式加减、`Text/Bool`相等、短路的`and/or/not`。任意状态机、递归、不完整观察、随机事件或外部效果**不自动套用这个语义**；当前不是万能Data/Graph节点。旧有限一阶语义与六种标注关系代数原代码保留为独立参考方法，真实方法桥必须核其专业意义及目标保持后才能使用。

这个受支持片段包括角色类型检查、参数绑定、共用定义和各Use的独立参数、精确输入到输出DAG、未安装机制的明确拒绝、错误类型/端口/循环/未知硬要求的拒绝。任何一个未受支持的必要输出不会被当成`null/false`后继续生成。

### 9.3 同一份IR如何生成不同目标

固定的IR由两份不修改任何作者意图的Emitter消费：`src/emit_targets.py::emit_ts`生成`generated/*/program.ts`；`emit_rust`生成`generated/*/program.rs`。二者使用**同一IR中的Use、角色、类型、表达式和输出发生**，分别给出目标表示：

- `I64` → TS `bigint`，Rust `i64`；加减需检查越界，不暗用TS普通Number。
- `Bool` → TS `boolean`，Rust `bool`；合取和析取在本画像中可短路。
- `Text` → TS `string`，Rust `String`；生成器为源码采用安全字面量，不将用户名称当源代码标识符插入。
- `Sequence[Record]` → TS数组，Rust `Vec<Struct>`；保持明确的顺序及重复发生。
- `Definition/Use` → 固定生成的类型、局部标识及表达式循环；用户可创建新定义和新采用实例，生成器无需业务名称分派。

**真实验收范围**：Python独立解释器对所有导出的行产生参考结果；在本环境中同一IR生成的TS通过`tsc`实际编译并由Node执行，输出逐行与参考值一致。Rust源码确实生成，目标语言的独立`rustc`编译/执行**本次未运行**，因为环境没有Rust工具链。具备Rust环境时`compile.py`会尝试真实构建并比较，只有成功才写验证回执。

`generated/*/semantic_ir.json`是实际已导出的IR实物，不是设计图；`source_map.json`保存每个Use及Definition到TS/Rust代码行区间的只读溯源。还不能从随意编辑的目标源码逆向重建唯一Gift含义，因此**只有原作者源具有相应修改权**。

### 9.4 从多维研究得到的真实约束与验证资格

这份IR的构造直接受到原维面及研究区别约束：D0009的身份提醒不能把同名当实例；D0048要求多角色同次绑定；D0423要求方法有真实输入/结果/效果合同；D0444要求源及视图对应。它们不是原语的数量定义。`data/IR模型设计_具名追溯.json`给出少数已经有实际消费者的**部分支持**与尚未支持内容，完整568项始终保留在原映射中。当前逻辑量词D0089由旧参考方法支持有限解释，但**没有**被本次有序序列IR冒充为目标多语言量词生成。

未经过独立检查的1,294条历史问题接合保持研究资格，不能用类型像是Ref就判为可执行桥。研究材料表中已有内容是“模型应能描述什么”的候选与证据，不是已取得的观察、物理实现或数学定理。这个边界是**保证不丢信息**所必需的，而不是额外工作台功能。

### 9.5 还有哪些真正未完成

本次获得的是**受支持专业片段内的目标中立编译与双Emitter成功**，而不是一个已穷尽世界意义且能自动选择任意算法的编译器。决定性缺口仍包括：

1. 将该派生执行IR作为既有SEC Engineering IR/原Definition与Requirement的真正下游方法，不建立第二份可写源；正式仓库尚未集成。
2. 新增具备真实类型/解释/行为规则的计算、组件、状态、时间、资源等专业方法及对应TS/Rust lowering；现在不能让新方法只注册名称。
3. Requirement→共同合格Method取得/创作及实现精化；不存在Method或已知模型不能产生所求真实功能时必须返回Need。
4. Rust目标必须在安装`rustc`的环境中实际编译运行与差分检查；当前不存在这份实测证据。
5. 逐项对568项研究区别完成实际模型覆盖审查，而不仅是研究族责任映射；更广理论、现实事实、保证与部署仍分别受其专业资格约束。

**工程取舍**：不为了“任何目标都能接入”的口号先发明一套全世界万能节点表。应先固定现有语义模型的真正消费者，增加合格专业方法与Target适配，复用成熟编译器编译生成的目标语言源；扩核要由真实不能保留的区别触发。
