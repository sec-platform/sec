# Gift：让通用关系成为工作台的实际执行路径

日期：2026-11-04。性质：对上一份通用关系执行库与本地工作台1.0的实际接合及无破坏迁移。不是新的世界维数、本体层数，也不声明全部专业语义已经实现。没有访问或修改GitHub、Library和现场资源。

## 1. 本轮的主成果

上一轮已有纯有限正关系演算、六种明确注解和可信方法注册，但原应用仍只允许名为resource的方法，计算、差额和界面沿资源字段处理；原库没有成为原应用的统一调用路径。

本轮把普通有限查询、分类、表达式求值、区间资源方法和正关系计划接到同一个版本化方法入口。运行、候选预览、明确采用、旧版重新计算、完整备份恢复、独立导出均使用这条路径。不同专业的语义没有被压成同一个布尔值；共同的是调用如何取得准确绑定、检查、计算、取得结果、显示及持续修改。

新格式不要求用户手填所有底层信息。已有模块、引用和运行上下文能确定的内容继续由系统取得；明确的参数选择只在实际需要的使用点绑定。工作台仍为研究工具，不取得替用户改变公开政策或执行外部动作的权力。

## 2. 不另造第二套核心：共同结构怎样实际运作

```text
准确模块、模型及其版本
        ↓ 既有形成、绑定、解释和共同约束检查
通用方法调用：方法身份/修订/解释 + 字面参数 + 显式参数绑定
        ↓ 受信安装清单检查、方法输入及专业检查
实际语义方法
        ├─原有限查询 / 分类 / 表达式
        ├─原完整区间资源检查
        └─有型正关系表达式 → 合法优化 → 精确注解结果
        ↓
结果内容 + 准确调用依据 + 实现字节摘要 + 原始结果状态
        ↓
统一显示 / 通用差额 / 候选采用 / 历史重放 / 独立导出
```

图表示真实代码接合，而不是新的固定软件层数。语义形成仍由原gift_core承担；semantic_views中的原方法原字节保留。新增的wire接口只是把关系库的真实构造变成准确可校验的输入，而不是在数据里允许任意Python回调。

查询和分类可以使用相同模型，却不自动得到相同的意义。分类谓词在模型中为真，与业务整体要求被满足、相应事实在现场成立和已取得执行权限，分别判断。

## 3. 共享的是机制，不是一个万能真值

注册的五种方法为：

| 方法身份 | 解释画像 | 实际承担 |
|---|---|---|
| gift.method.finite-view | gift:classical-sorted/1 | 已有查询的绑定、完整有限根域与结果投影 |
| gift.method.finite-classification | gift:classical-sorted/1 | 准确谓词类别及可选覆盖/互斥检查 |
| gift.method.classical-expression | gift:classical-sorted/1 | 固定模型中的有型表达式求值 |
| gift.method.finite-interval-capacity | gift:constant-load-half-open/1 | 同一时钟、常量负载、半开区间的共同资源检查 |
| gift.method.finite-positive-relations | gift:finite-positive-plan/1 | 类型化有限关系及准确注解的正组合 |

这五个是当前安装的方法，不是五种世界基础，也不限制未来方法数。通过可信引导安装一个新方法，不需要改通用路由、差额、历史或快照代码。材料中声明方法名并不安装方法；本版拒绝外部作用方法。

每个调用有准确的id、revision、profile。注册输入检查、真实计算、输出检查分别执行。返回信封叫method_returned，仅表示该方法返回；专业结果可为真、假、needs、候选集合或其他准确结构。不会把方法调用正常结束升级成全部要求满足。

实现摘要由本包实际Python源字节取得。它用于区分本地计算依据和复算，不是数字签名、代码正确性证明或来自外部的信任背书。

## 4. 方法参数与控制指令分开

`arguments`内的内容作为字面数据保留。不会递归扫描某个字段名，然后把它猜成执行指令。

调用期选择使用独立的`bindings`：

```json
{
  "method": {
    "id": "gift.method.finite-interval-capacity",
    "revision": "1",
    "profile": "gift:constant-load-half-open/1"
  },
  "arguments": {"signature": "这里应放准确的原符号签名对象"},
  "bindings": {"selection": "project.selection"},
  "presentation": {"title": "共同容量检查"}
}
```

上例的signature文字仅用于说明位置，实际接口必须给完整有型签名。正式可运行对象见`projects/shared_facility_v2.json`。

当前动态来源只接纳明确的project.selection。一个参数不能同时由字面值和动态绑定覆盖。未知来源被拒绝。模型上下文由检查后的应用内部对象提供，不接受用户材料自报已认证的模型对象。

## 5. 正关系计划：一次定义，多种用途

计划具有有类型的具名角色和明确来源。支持的公共构造是source、join、alternative、project、rename。声明必须满足准确字段、唯一节点身份、合法引用、无递归、完整可达、共享角色类型相容等条件。投影和重命名不会静默创建变量捕获或删除共同连接条件。

输入可以是：

1. 已由原有限语义解释器解释的Bool谓词。将其完整有限载体枚举为关系，符号、元数、角色和模型成员均核对。本路径目前只提供布尔关系。
2. 作者明确提供的有类型有限关系及注解。载体、角色和原始行属于声明的有限输入，不冒充真实观察。零注解的行也必须有合法的绑定，不能通过结果为零绕过类型检查。

只使用同一次准确模型和全部相交输入所形成的组合语境。数据不能伪造scope来接入另一个模型。模型、来源、载体或参数变化都会改变绑定依据。

关系元素的身份是其具名绑定和注解解释所决定的内容；需要保留业务发生身份时，发生角色必须在源中明确存在。采用集合隐藏发生以后，不能再承诺恢复所有原发生。

## 6. 同一正组合采用六种准确解释

在有限纯关系中，连接使用注解乘法，备选和隐藏的汇总使用注解加法。已安装的六种交换半环解释，分别保留布尔可行性、自然数重数、非负min-plus成本、非负有理权重、来源多项式与固定样本空间中的事件集合。

`projects/six_interpretations_v2.json`让同一角色和组合计划分别使用相应输入注解。它不是把一个概率数随意换成计数或成本；各次输入注解与解释明确给出。

该模型的两条路径为a—b—d与a—c—d。实际得到：

| 解释 | 结果 |
|---|---|
| Bool | 存在完整路径：true |
| 重数 | 2×3+1×4=10 |
| 非负min-plus | min(2+3,7+1)=5 |
| 非负有理权重 | 2/10×3/10+1/10×4/10=1/10 |
| 来源多项式 | r1×s1+r2×s2 |
| 事件集合 | {bad} |

事件示例中，同一bad事件在路径的两处出现，并交后仍是bad。在外部明确给定bad/good各1/2的有限测度下，结果概率为1/2，不是1/4。该测度用于演示，不是系统从数据中识别出的现实概率或因果结构。

正关系代数没有因此取得一般否定、差集、无限固定点或权限语义。半环只给出加法和乘法；差运算需要额外结构，不能通过一个新操作名直接取得。[S1]

## 7. 优化由已取得的规律控制

优化器继续复用上一版真实代码：在纯、有限、相容的交换半环解释中，投影可以提前，条件是保留所有最终需要的角色和共同连接角色。嵌套投影可以合并，纯计算子表达式可以共享。

精确适用条件属于受信实现，不由输入材料自报“可交换”“可删除”取得。

共同计算缓存不会删除重复使用。若关系R的注解为2，则使用R两次形成的乘积注解仍为4；计算节点只求值一次，并不把两次使用合成一次。

对有限正表达式，可用结构归纳证明合法注解同态与求值交换；原说明和测试继续保留。不将这项证明外推到没有相应定律的状态、外部动作、随机抽样和规范冲突。

方法结果包括实际使用的解释、输入摘要、计划摘要、优化条件与结果摘要。工作量统计和显示标题不参与结果的数学内容；改变标题不会改变调用的语义结果。优化开关可以改变计划和工作量，但不应改变同一输入的准确答案。

## 8. 对旧应用的迁移已经实际完成

旧`gift-studio-project/1`继续可读。唯一旧业务名resource保留在兼容边界，映射成准确注册方法的调用；新`gift-studio-project/2`通过方法身份、参数与绑定调用，不依赖这个名称。

迁移先形成纯候选。旧模块、模型、查询、分类和完整源不改写；准确资源方法仍是原实现，既有视图、类别、约束及资源结果逐项比较相同。确认以后才形成新本地修订。格式迁移不凭空改变模型要求或取得现场权限。

同一计划还可以与资源方法在同一项目里运行。例如共享设施项目中，r1和r6各自属于局部合格关系，却共同超容量。登记了两份正面单项结果，也不会使负面的共同判断消失。

这体现一种结构事实：统一调用和统一展示，不是把不同要求的结果压成一个“全绿”。

## 9. 源修改、历史与导出使用同一执行路径

通用差额现在同时处理原查询、分类和全部方法结果，而不是只比较一个专用resource字段。方法输入由2改5后，计数结果从10变成19，其他五种未改调用的结果不受该参数修改影响；旧工程源仍保留。

导入未知方法、错误解释、角色冲突、递归计划、非法来源或不合格模型时，预览拒绝，不产生部分采用。运行预算耗尽按needs返回，不按false、空集或完整前缀处理。

采用仍由原本地工作区处理准确前像。恢复旧修订会形成新的采用记录，旧事实和中间记录不删除。备份恢复到新目录，不覆盖旧目录。

独立快照导出现在包含真正所需的语义核、投影、关系执行库和可信方法引导，连同准确工程和回执。它已经在没有研究目录、没有UI、没有完整模型资料包的临时目录实际运行，与工作台结果一致。

历史重放明确使用本包所携实现代码，并把实现摘要写入结果。导出的快照固定其代码字节。不能仅凭方法名字相同，就宣称任意未来解释器重算仍是原结果。

## 10. 工作台与旧完整内容

沿用原完整阅读器及原内容。原1,786项、568项合同、31,324条登记关系没有被本轮改义；旧画像和候选不升级。

界面新增或替换的是通用方法清单、关系结果显示、通用差额和显式格式迁移。不再用某个业务名字选择执行实现。原示例仍是普通源文件；新定义编辑器提供基于当前类型的中性示例，不再识别某个业务符号来选择定义规则。

类型、目录、源码和界面仍有各自职责。新接口成功不证明原自然语言已全部形式化，能保存记录也不证明已经有专业解释。

## 11. 实际验证及一般论证

新增一套集成测试核对：受信安装与版本；准确参数；词面数据不转控制；角色与载体；不支持操作与递归拒绝；预算needs；六种解释；合法优化前后；重复使用与共享事件；原模型谓词；显示不改义；字面输入变化；新方法无需改路由；迁移、存储、备份、HTTP、快照。

原工作台54项回归与原关系17项性质测试也在更新后的代码上重新执行。后者包含全部4096组两元素布尔关系结合律对照及六种解释上的240组优化前后对照。有限测试不是对全部Python实现的机器证明。

本轮保持的是：
- 在原方法合同相同的条件下，旧格式迁移后的方法输入、实现与结果相同；
- 共同关系计划继续受原类型与代数规律约束；
- 接受的纯方法只能经受信版本入口，材料不能自行安装新语义；
- 展示、预览、历史与导出调用实际相同的语义实现，不各写一套逻辑。

这是一种可扩展的结构改进；并没有通过新增案例得出所有未来领域都适用同一正关系代数。

## 12. 完成与未完成

已完成本地旧应用相关消费者的实际迁移：普通查询、分类、表达式、方法、关系计划、差额、源候选、采用、恢复、导出和UI展示。此前仅在独立库中存在的通用关系机制现在在同一工作台中运行。

未完成：全部自然语言的语义终审与形式化；全部旧1,294接合的专业适配；任意方法输出之间的自动配线；一般递归、否定、线性效果、高阶、连续和全部概率/因果/规范解释；通用程序综合与生产Target；真正的现场身份、授权和作用。

本包不提供公网多人保密服务。输入限制、解释预算、工作进程超时和部分平台CPU/内存限制不是恶意代码执行沙箱或安全认证。大整数、来源多项式、DAG和关系组合仍有成本边界；超过本地支持范围必须拒绝或保持needs，不制造总能完成承诺。

统一是指共同的形成、接线、解释选择、依据和修改机制；不是“任何同形字段都可传递”，不是“所有方法都拥有同样定律”，也不是“一个注册表已经解释世界”。
