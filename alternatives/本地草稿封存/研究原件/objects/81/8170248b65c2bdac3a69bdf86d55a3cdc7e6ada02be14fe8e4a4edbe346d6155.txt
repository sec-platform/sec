# Gift：从信息清单进入语义校准与局部生成

日期：2026-11-02。性质：基于已提供1784项固定清单的可撤销语义研究。不修改仓库，不改变正式采用，不宣称全域完备，也不再以追加数量作为本轮主要成果。

## 1. 本轮真正完成的阶段变化

此前已将大量分散信息写成可讨论的工作条目。现在开始回答另外的问题：这些条目之间什么相同、什么不同；一个词是否掩盖多个对象；哪个高层构造可以由已有含义准确形成；怎样连接表达、主张、依据、决定和实现而不混淆。

本轮从整份清单的名称导航定位候选，然后完整对照267项原记录，在42个具体问题中给出处置、正向构造、条件、区分例与使用后果。不是对1784项全部作了独立语义复审，也不是将267项强制合成42个概念。一个条目可以参与多个问题。

成果包括：42份具体语义裁决；12项可复用的生成与消费规则；若干自含的局部归约与保持论证；一个贯穿定义、使用、观察、反证与后继修改的共同例子。校准发现了原条目的12处限定问题，并将“观察”总题中的活动与记录展开为两项明确内容，形成1786项完整续订。其余1772项逐字段保留；所有原ID保留，不执行永久概念合并。

这不是新的四层、十二层架构。42是本轮实际问题数，12是本轮写出的规则数，1786是可寻址工作条目数，都不构成世界原语数或完成比例。

## 2. 固定基线和真实读取范围

基线：`baseline/1784项原清单.json`，SHA-256为 `f559ccac2f46915af2432522f59b2827dfd51afbc5e18d693b71b62c88541092`。旧来源键仍按它们原来绑定的版本解释，不能把原记录中“本轮”改读为这次重新验证。

本轮直接使用了三个不同历史正文的列明范围：

- `CAL8-HREF`：信息对象、类型化关系与配置基线。读取1—170、242—299、338—360、433—461行。
- `CAL8-RESULT`：规范元模型与结果语义。读取1—40、48—65、129—158、217—317行。
- `CAL8-EDIT`：作者权切换、并发与往返。读取1—52行。

相同字节的 `H-NORM` 与 `H7-RESULT` 视为同一份历史内容的两个来源定位，不计两项独立支持。本轮没有重新查询仓库HEAD；这些历史文本是设计材料，不是当前实现或正式采用的证据。

外部采用固定版本的一手资料作窄范围核对：SKOS 2009的映射性质；PROV-DM 2013的实体、活动和修订；OWL2 Primer 2012的个体同一及名称假设；W3C 2006多元关系模式说明；SSN/SOSA 2017的观察、结果、过程与时间。使用历史固定版是为了可复查，不声称它们都是今天最新版本，也不要求Gift采用其全部本体、公理或技术栈。具体来源和所读章节在同包登记。

## 3. 先校准含义，而不是急着减少条目

### 3.1 “实例”不是一个默认运行阶段

旧U0020只用“定义在使用和生命周期中形成的对象”解释实例，容易让模型个体、类型成员或静态参数化内容被强制解释成一次运行创建。

本轮分别保留：一个对象满足某类型的成员判断；把实参接入定义的实例化；定义在某上下文中的使用点；真正进入运行生命周期的实例。它们可由具体合同连接，但不存在一般的一对一关系。

例如同一组件定义有两个使用点；某使用点每次调用创建新实例，另一个使用点共享长期实例，都可能合法。数学模型中的个体3不必先被某个构造器在现场创建。这里不删除“实例”这个常用词，而要求每次使用能恢复其具体关系。

### 3.2 “关系发生”不能同时表示关系成立和被人提出

旧U0067的“一次成立或被提出”将角色绑定、命题成立、断言行为和现实发生混写。现已修为：准确关系签名下的一组具名实参和语境；需要保留重复业务发生时，再绑定对应的发生身份。

一笔转账可以被两份回执描述；两笔同额转账也可以有相同字段。两份记录、一个事件，与两个事件，不能由字段相同自动裁决。数学关系2<3则可以只是一个静态关系应用，不必创建时间事件。

W3C的多元关系说明也区分关系实例和关于该实例的陈述。本研究借用的是这项区别，而非照搬某种RDF编码：关系表、有型项、角色化图均可以保留共同绑定。[CAL8-NARY]

### 3.3 “观察”需要区分活动和记录

原U0322把过程与结果列在同一总题中。本轮保留总题，新增：

- U1785：观察活动的取得过程。对象、方法、实际活动、失败和世界分支分别可定位。
- U1786：观察记录与再解释依据。保存内容、来源、时域、覆盖和解释；不直接冒充世界本身。

一次采样可失败、可产生多份记录；复制记录并不重复采样；修改校准解释可能改变从同一电压记录算出的温度，但不意味着更正时设备升温。

SOSA将Observation定义为实施观察过程的活动，并单独表示Result。本稿的“记录”还包含来源保全和再解释责任，不声称与SOSA的Result完全同义。[CAL8-SSN] PROV的活动与实体区别亦提供独立对应。[CAL8-PROV]

### 3.4 “证据”不是文件的一种固有等级

同一份材料可以支持不同主张；是否适用、支持哪一方向和依赖什么前提，各次用途要分别判断。字节不变而证据用途失效，是可能的。

一份纯函数证明可以支持明确数学结果，却不直接证明现场输入新鲜；日志可以支持这次观测，却不自动证明所有输入。真实签名可以支持签发身份，但不自动提供规范决定权、观察精度或事实真值。U0324、U0336、U0320和U0693据此作限定修订。

### 3.5 不同“相同”，只能得到各自允许的替换

值相等、实体同一、字节相同、结构同构、模型初等等价、定义换算、命题相等证明和观察等价，各有比较对象和范围。它们不宜统一为一个无条件sameAs。

有等价关系只是能形成等价类；想让某操作在等价类上执行，还需要同余。相同当前输出也不足以合并固定政策与默认继承，因为它们在下一次升级后不同。

SKOS的exactMatch/closeMatch用于概念映射，不等于OWL个体同一；其中没有依据的传递链也不能擅自加入。[CAL8-SKOS] OWL不默认不同名称必指不同个体，但这既不证明它们相同，也不取消Gift中已经明确的发生身份合同。[CAL8-OWL]

### 3.6 本轮未永久合并整项，并非没有开始收缩

可以立即共享的是：在准确语境内已确定相同的定义内容、解析结果和符合条件的计算。不能一起吞掉的，是不同提出、接受、来源、业务发生、权利和历史。

本轮未找到足够依据把任何两个完整工作记录及其全部未来用途永久合并，因此保留所有ID。但已给出下面的精确派生与部分共享规则。收缩的是可证明重复的内容，不是为了得到更小数字而删除记录。

## 4. 从条目形成可复用内容的12项规则

完整的输入、条件、输出、构造、禁止推论、变化处理和依据另见《生成与消费规则.md》。本节给出共同逻辑：

| 规则 | 正向形成什么 | 必须保持的条件 |
|---|---|---|
| G01 表达取得绑定 | 原表达在实际环境中的有型绑定 | 自由变量、词法作用域、命名域、解释和源修订 |
| G02 定义与参数化采用 | 可复用定义在该使用点的实例化内容 | 卫生代换、作用次数、实例及共享合同 |
| G03 多元关系内容 | 同一组角色绑定下的关系应用或实例 | 共同发生、角色域、顺序和重数 |
| G04 唯一性派生 | 从量词和相等形成“恰好一个” | 量化的是值、位置还是发生已固定 |
| G05 主张对齐与证据准入 | 对准确问题取得有方向的依据 | 主体、时域、量词、逻辑和模型相容 |
| G06 观察形成记录 | 活动产生记录，记录再参与判断 | 真正活动、覆盖、方法、误差与来源 |
| G07 有根支持闭包 | 合格前提经规则形成共同或替代支持 | 全部必需前提，正向片段，真实基础 |
| G08 支持反驳摘要 | 同题证据的存在性摘要 | 不抹掉撤回、审计所需的来源和推导 |
| G09 局部结果消费 | 方法、检查、操作等各自得到准确结果 | 不同局部结果不经同名状态自动互换 |
| G10 有权要求变化 | 新候选及其允许实现空间变化 | 独立要求、来源、前像与旧责任 |
| G11 跨表示组合 | 两个合格映射构成新的保持映射 | 中间解释匹配，前提共同成立，方向准确 |
| G12 同源回写与实际作用 | 原源上的可回读编辑及独立执行结果 | 隐藏补余、并发基础、当前权限和结算 |

这些规则并不要求所有输入顺序通过十二个阶段。纯常量可以只用一小段规则；带外部作用的任务才激活相交责任。它们也不要求建设另一总图数据库。实际角色可由原Definition、Use、Claim、Assurance、Operation和源管理承担。

## 5. 可直接复查的局部归约与保持论证

### 5.1 唯一存在不需要新增数学原语

在固定的经典模型、域D和等号下，定义：

\[
Unique_D(P)\;:=\;\exists x\in D\;\big(P(x)\land \forall y\in D(P(y)\rightarrow y=x)\big).
\]

若右边成立，有一个满足者x且所有满足者等于x，所以恰有一个。若恰有一个满足者，取它作x，右边成立。空域上两边均不成立。

因此U0137可以作为可读概念保留，而底层定义复用量词、合取和相等。该结论不提供一般自动判定器。序列`[a,a]`若按值集合量化，唯一值可能是a；若按位置量化，则有两个发生，必须用位置域，不能拿去重域的证明替代。

### 5.2 新鲜定义不等于新增要求

固定旧签名Σ和其中公式φ(x)，引入Σ中不存在的新谓词R，并加入定义：`∀x (R(x) ↔ φ(x))`，φ不出现R。

给定任意旧模型M，将R解释为在M中满足φ的元组集合，就得到一个扩张模型。定义式迫使R的外延恰为这个集合，所以扩张唯一。限制回Σ得到原M，旧符号的含义没有变化。若φ还带已有参数，固定参数赋值即可采用同样构造。

与之相对，给旧模型增加一个独立条件H，只保留满足H的模型，可能删掉旧的允许情况，甚至无解。把“命名正数”当成“所有输入必须为正”会把定义性展开变成产品政策变更。

递归R、开放新对象和不满足上述前提的理论扩展不能套用唯一扩张证明。它们需要自己的固定点或模型解释。本论证是成熟定义扩展思想的自含应用，不声称新发现。

### 5.3 等价类上的操作，需要同余

令~是X上的等价关系，f:X→X。想用`[x] ↦ [f(x)]`定义商上的操作，恰需：`x~y ⇒ f(x)~f(y)`。

充分性：同一类选任意代表，结果仍在同一类，定义无歧义。必要性：若商上结果不依赖代表，则原同类输入必须给同类输出。

例如按整数奇偶分组，0~2，但f(n)=⌊n/2⌋使f(0)=0、f(2)=1落到不同类。奇偶等价本身有效，却不能让此操作无损下降。因此不能把“观察上相同”直接提升为所有编辑、运行和理论语境下均可替换。

### 5.4 二比特证据摘要可以合并，不能独立撤回

只考虑同一已解释、已对齐、当前合格的主张。令E为有效的支持/反驳材料集合，定义：

\[
h(E)=(s(E),r(E)),
\]

s表示存在支持，r表示存在反驳。因为存在量化分配到集合并集，得到：

\[
h(E\cup F)=h(E)\lor_{component}h(F).
\]

该式只描述证据集合的摘要合并，不是逻辑公式合取，不是规范冲突裁决，也不是概率相加。

再取两组只有支持的集合：E₁={s₁}，E₂={s₁,s₂}。它们的摘要都为(1,0)。删除同一s₁以后，E₁变(0,0)，E₂仍为(1,0)。如果更新函数只能取得旧二比特和被删除的s₁，它收到的输入完全相同，却必须产生不同结果，因此不存在对两种情形都准确的这种更新函数。

所以四态不是错误；错误是将它当成可承担任意撤回、独立性和审计的全部证据状态。U1782据此补足来源和推导结构。某个有限受控场景只需要当前摘要时，不必强迫它保存无关历史；一旦承诺撤回或追溯，必须保留足够补余。

### 5.5 正向推导需要有根，替代推导可以保留结论

在有限命题、有限正向Horn规则和合格基础集合F上，从F出发，仅当一条规则全部前提已取得时加入其结论。该过程单调；每次真正扩张至少增加一个命题，因此在有限域终止。每个导出结论都有从F出发的有限规则依据，得到包含F且对规则闭合的最小集合。

只有a→b、b→a且F为空，闭包仍为空。若另有合格基础a，则b可导出；撤去基础后，不能靠两者互相循环留住结论。

若P可由a和b共同支持，或者由c单独支持，撤去a只删除第一条路径；c仍合格时P仍可支持。这个“共同前提／替代路径”结构可以复用计算，却不能合并独立来源和接受义务。含默认否定、优先级、概率或规范的系统需要相应解释，不能偷偷并入本证明。

## 6. 一个共同例子把构造、判断和修改接起来

以下是受控的研究例，不是Gift已运行的演示。相应有限计算在`tools/reference_examples.py`中提供。

### 6.1 先形成定义与使用

已有筛选定义D@7：输入有限整数序列xs和阈值k，保留全部满足x≥k的发生，保持原次序和重数。

两个使用点引用它：A明确固定k=5；B继承策略P@3，其默认也为5。输入为`[3,5,5,9]`。当前两个使用点的正确结果都是`[5,5,9]`。

D@7是共享定义；A、B是使用点；两处有效阈值当前相同。尚无理由宣布运行实例相同，更无理由合并A的固定政策和B的继承来源。

### 6.2 方法与检查不是同一种成功

候选M@4错误地先把序列改成集合，返回`[5,9]`。某次检查活动对准确输入执行它，取得含输入、结果、候选修订和实际方法的记录。

检查活动成功结束，并提供了违背重数要求的反例；目标主张“这个候选保持该筛选合同”被反驳。这不是“检查器失败”，也不是“整个任务已成功”。是否部署、是否获得真实执行权限，此例没有发生也没有据此声称。

### 6.3 复制记录和不同修订不能制造证据矛盾

把该记录复制到三份报告，仍只有一次原始检查。另有证明针对M@3，并不能与M@4的反例直接组成同题冲突；需要先核两者是否真的对应同一个候选及全部相交假设。

即使M@3与M@4部分代码相同，也不能凭相同名称复用整项证明。反过来，已经证明未受变化影响的部分可以继续用，无需全部推倒。

### 6.4 后继变化检验来源是否被保留

P更新为默认6且B有权采用新版本后，B结果为`[9]`；A仍为`[5,5,9]`。只保存“有效值5”会无法恢复这个差异，因此来源和控制方式是后继编辑中的必要信息。

D的文件换路径可以不改变定义身份；明确的源对应仍需保留。修改政策不会改写旧检查确实发生的输入和结果。纠正算法产生新候选，旧反例继续作为旧候选的历史依据。

### 6.5 用户实际控制和系统负责的内容

用户可以引用已有的完整筛选定义，只固定自己关心的阈值、复用方式、输入域和质量要求；系统负责继承保序保重合同、形成绑定、选择合格算法、生成目标并检查实际要求。若用户指定算法、内存或ABI，它们收窄相交实现自由，但不取消原结果合同。

这条路径不是要求用户填写十份证明表。大部分共同内容可由选定定义及上下文获得，只有真实独立决定、缺事实或缺权限才交给相应有权来源。

## 7. 42个具体问题如何承接原条目

《42项具体语义裁决.md》逐项保存：所涉及原ID和名称、当前裁决、正向构造、成立条件、区分见证、实际使用后果、来源及可撤销地位。它们不是没有规则的图边。

《267项原条目与本轮处置.md》则从原条目回查到本轮裁决；每项保留完整原记录，变更者另显示当前记录。这样可以查到本轮究竟处理了什么，也不会因为最终正文较短而静默吞掉条件。

本轮没有宣布任何永久同义合并。定义、共享正文和已合格重复计算可以在所列范围复用；独立身份、历史、规范效力及外部权利仍分别保留。

本轮未细排全部概念的上下位、因果与影响网络。只有这42个问题取得了具体处置；其他原条目继续有效且保持待进一步审查的地位。所有材料未审范围、历史分支差额和其他理论入口的覆盖任务也没有因进入下一步而被关闭。

## 8. 对Gift与AI有什么实际作用

对Gift，映射沿原接口：定义/采用交给Definition与Use；含义和要求交给Meaning/Requirement；依据与裁决交给Claim/Assurance；合法动作交给真实Grant/Operation；回写交给原源管理。这里只使用给定历史正文的职责，不声称当前仓库已实现这些构造。

对AI，输出前至少区分它在做的是：引用来源、解释表达、提出候选、在前提下推导、报告观察、评价Claim、接受有权决定，还是实际执行。句子表面都可以是“X成立”，但依据和消费者不同。

可采用一个有内容的回答模式，而不把每句话变成元数据表：说明准确对象和范围；给出当前结论及依据；继承已固定上下文；在真实影响结论的位置指出未知与假设；不要把来源声明升级为现实事实或把关联路径升级为授权。

例如用户问“支持新语言了吗”：如果只有准确Schema和可保存样例，系统应分别回答结构支持、解释支持、生成支持和实际产品资格。它应尽量取得能得到的真实结果，而非永远返回unknown；但不能从已拥有其中一项推出其余全部。
