# Gift 融合方案：语义责任不丢失、真实接口接合与可恢复工程交付

日期：2026-11-08。范围：本源多维研究、Gift 意图作者源、设计分支、语义与编译实现、本地参考工程以及它们的融合。排除 SEC 测试清理。本文是设计与只读审查成果，不代表已修改、推送、合并、发布或部署产品。

本版依据完整读取的《Gift_设计差异审查与融合实施方案_20261108.md》修订。仍成立的来源、语义差异、旧格式保全、六代数边界、分支处理及验收责任在下文保留；纠正已经过时的末次任务状态、当前目标语言顺序和过度简化的实施接合。本文不是仓库的新规范权威，也不是第二份长期工作台账。真正采用的变化应落回原有 owner；原报告保留为历史判断，不与本版并列维护。

## 1. 推荐判断

当前证据最支持的方案是：**以 #896 的精确树作为工程接合载体，以真实目标与原规范责任裁决内容；先融合独立语义与作者连续修改合同，再在原 TS/Bun 控制面和 Rust 内核之间补齐有型接合，按实际方法、目标和消费者逐能力迁移；保留可复算原研究与独立参考，不复制第二套生产平台。**

统一的是每一项作者决定、专业含义、方法保证及其修订责任，不是把所有文件、类型、算法、事实和现实权限塞入一个对象、一张图或一种数据库。原生源码、需求和研究可以同时存在，因为它们可以拥有不同事实；禁止的是同一个决定的竞争写权，而不是禁止多个合格实现或不同用途的表示。

新生产内核能力按已经选择的 Rust 方向实施；TS/Bun 继续承担控制、宿主与产品交互。当前新目标工程优先交付 Rust，既有 TS 能力保留和回归，不将“先补齐所有 TS”设为 Rust 的前置。保留 Python 的朴素参考与反例，但不因此默认增加第三条核心生产语言。

这不是已证明对所有未来规模都最优的架构。其优势是保留现有正确工作、减少重复生产内核和大爆炸迁移，且能在真实作者任务、运行机制和全生命周期成本上被反证。反转条件见第 20 节。

## 4. 竞争方案与为什么选择渐进接合

**整包复制本地工程。** 可以将原包作为只读、可寻址的来源保全；不能据此把其中所有 Reader、CLI、缓存、UI、旧报告和生成器都变成活动生产层。否则还需维护 Python/TS/Rust 三种核心解释、不同源格式与各自运行资格。其有用部分是保存源与见证，不是整体提升为权威。

**一次性全 Rust 重写。** 新内核能力应直接 Rust，但整体替换会把语义核验、端口映射、数字域、构建、旧源兼容和运行机制同时变化。错误归因与回退变难。只在被替换区域已经封闭、原责任和支持边界明确、真实迁移成本支持时采用整段替换，不全平台启动重写。

**长期双核心。** 两个实现可以是同一合同的可选 Method，或者一个参考、一个生产；这不违反单一含义。问题是两套均能任意决定 Meaning、源格式和默认选择的核心会竞争。当前没有足够证据支持第三条长期生产核心，应沿已选 Rust 内核＋TS/Bun 控制保持。确有专业 Provider 不可替代时，在原接口绑定其范围，而非扩为全局核心。

**新建万能 GraphIR、直接以关系代数代替全部意图。** 对有限关系计算有价值，不能代替规范义务、开放世界、时序、因果、资源和授权各自解释。能够编码一种对象不等于可以推导它的专业规律。拒绝这一层面的整体替代，不拒绝有型多元关系作为恰当的专业表示。

**直接引入 MLIR/CUE/e-graph/流式平台完成统一。** 可以复用其中机制，但没有成熟工具能替项目选择语义、恢复丢失来源或自动证明所有转换。当前先复用已存在基础设施；具体引入门槛见第 19 节。

**只合并文档。** 本次用户要求设计，因此本轮以完整方案交付是正确的；但未来产品融合不能以“规范都写了”宣布接合完成。设计要指定实际消费者和闭环验收，随后实施仍须单独授权。

**推荐：责任与合同先收敛，保留可验证现状，围绕完整作者任务逐能力替换。** 完成单位不是“移入一个文件”“多一个算子”，而是一项在明确输入、用途、失败与恢复条件下可被真实消费者调用的能力。

## 5. 基础抽象研究必须参与设计，但不能冒充执行事实

### 5.1 不把研究压成索引，也不预设宇宙原语表

原 U 保存区别、机制、条件和反例；D 是具名被问对象及答案解释合同；20 面、32 族是可重组视角；理论、规则和问项关联是形成抽象的候选依据。它们不是 568 个必填编译字段，也不是 1786 个运行节点种类。应保留原始字节、关系发生、语境和出处，并让其改变真正的 Definition、Meaning、Requirement、Type、Method 或边界；单有目录引用不算接合。

每项跨域抽象需要能够恢复以下信息：输入基础及其准确解释；新增的必要区别；有型参数、角色与作用域；构造/翻译方向；保持的观察与前提；最强已知反例；实际消费者及迁移影响。这是研究论证内容，不要求每次普通程序编辑填写一张元理论表。

例：数学幂等、重复请求返回同值、支付不重复扣款，都涉及重复和身份，但第三种还需要真实作用标识、持久去重、提供者语义、授权和失败后查询。不能把“结果相等”提升为“外部作用仅发生一次”。把这种独立区别落入原效果与执行合同，才是研究对工程的真实贡献。[R7]

### 5.2 保持六种不同关系的含义

资料引用/支持、定义性派生、逻辑后承、理论翻译/性质保持、实现精化、现场观测分别带成立条件。观察可冲突；规范可有不同签发者；定义和实现可一对多；证据存在不等于授权。索引可统一定位，推理不能统一成一个无条件 `edge(a,b)`。

研究数据采用按内容保留、按需查询的结构。不把 36,217,206 字节原模型塞入当前单文件 4 MiB Reader，不为研究而放宽普通工程全部输入预算。拆分查询投影必须携原快照、版本和覆盖；分页的未返回项不解释为不存在。资料不完整时仅阻断依赖它的主张，不能补造原文。

### 5.3 “一次建立通用基础”与“不断增加专业规律”的边界

先稳定当前已接受的形成规则、绑定、组合、解释与未知表达，再审查相交构造闭包。专业规律通常作为普通定义或合格专业解释接入；只有旧基础无法区分必须不同处理的案例，才改变公共构造。不能把全部专业内容永久塞进 `unknown JSON`，也不能为每个行业加核心 kind。

闭包证明是相对于准确构造集合和解释的命题；不能删掉已接受的输入域、把未实现分支叫未来扩展，再对缩小后的集合宣布目标完整。图形、表格、简写和文本是同源表达入口，不决定专业规律的真假。

## 6. 统一写权，不强迫统一物理表示

建议在既有 owner 内保留三类不可混淆的表示，而不是新增三个持久平台：

**作者源与原始资产。** 保存实际接受的目标、定义、实例、参数、明确限制、绑定选择及其来源；原生程序、图像、配置按原格式保留。独立需求与满足它的原生实现可同时拥有各自源，不是同义双写。

**解释后的语义与工程事实。** 由准确 Reader、解释、类型、作用域和已绑定引用形成只读结果。公共事实图用于工程身份和影响；词法/类型 arena 用于分析；专业域保留自身必要的结构。不得把 arena 索引当持久对象身份，也不得以有同名字段宣称上下游合同相同。

**方法与目标执行表示。** 合格 Method 从所需语义区域导出执行计划，再按目标合法性降低到 TS/Rust/其他实际产物。优化与 emitter 不重新选择作者意思。一个共享有型域计划可以有多个目标专用后继；不强迫在目标早已不同的布局、借用、ABI 或运行时处仍保持一个物理节点格式。

有类型的边界应说明值域、效果、来源、前后置、正常/错误/未决/停止和资源责任。未知专业块可保全并局部分析，不得标为已解释；独立可生成根不因无关未知被全局阻断。反过来，已经独立接受的约束不能被“该节点未被代码引用”删除。[R8]

MLIR 的分析、部分转换和完整合法化区分是可借鉴的设计参照：能分析或局部降低，不能冒充整个请求根已完成。此处不要求引入 MLIR 依赖。[E1]

## 7. 真正缺少的接合：从分析输出到合格方法和原交付边界

### 7.1 不用旧 `/2` 编译器假扮新源通路

当前 `design-converged` 的 read/names/analyze 与 `/2` 有限 TS 编译分属不同入口。新实现应消费前者产生的准确捕获、声明、类型、实际引用和专业未决，完成目标根的语义资格、方法选择与降低。旧方法可作为其准确输入域内的供应，不能仅替换 schema 标记或丢掉“不支持”的源成员后调用旧入口。[R3,R4]

旧 `finite-ordered-records/2` 使用数学 Int 等合同，不能被本地 checked-I64 演示的较窄域覆盖。公开 Callable 没有合法输入 codec 时不能绕过原拒绝。存在性分析、类型正确、可调用资格、已选择实现、目标合法、构建与运行是不同状态。

### 7.2 对现有窄生成计划作有边界的演进

`SemanticGeneratorPlan` 的真实联合只拥有状态转换图，不是现成的通用执行器。施工先定位原管线消费点、验证器、影响选择及产物归属；保留其现有状态能力。关系/意图方法贡献应在原接合责任下形成明确有型分支或窄适配器，保持输入/语义修订、方法选择、产物和来源一致。

不要把 Relation Plan 塞进状态图字段，不将所有内容改成无校验的 `payload:any`；也不要一次建一个覆盖所有未来领域的插件总线。接口改动以真实纵切面需要的能力为边界，保留旧消费者的准确适配与负例。真实前像未恢复、消费方未查明时不能宣布已接通。[R5]

### 7.3 跨进程的“合格”不能由对方自签

当前 TS 管线通过本进程对象签发和修订一致性检查建立链接。Rust 传输是数据，不会携带该 WeakMap 身份。接入需要依次检查：协议版本/能力、输入与解释基准、合法图边和来源、方法的实际注册与资格、目标画像及输出闭包；然后由原合法入口构造本地认可的结果或继续保留未决。

需要复用的不是一个 `verified:true`，而是精确主体、方法、证据及其接受条件。跨进程签名、摘要或类型反序列化都不能单独证明语义正确，也不授予文件写入、构建执行或外部授权。[R6]

### 7.4 最小接合信息，不新增同义协议

以下为设计所需信息，优先映射现有字段；不是宣称这些同名结构已经实现：

| 边界 | 不可省的输入 | 输出及错误归属 |
|---|---|---|
| 作者捕获→分析 | 原字节/内容引用、工程与模块使用域、准确文法/解释、覆盖和预算 | 有来源的声明/类型/效果与专业未决；错误回作者位置 |
| 分析→方法选择 | 选定根、仍有效接受义务、实际角色实参、观察域、目标硬条件 | 已绑定方法及前提或准确缺项；不隐式执行作者程序补信息 |
| 方法→降低 | 合格有型区域、依赖、代数/数值/顺序/效果合同、冻结绑定 | 可重建计划、目标贡献、来源与剩余义务；不悄悄改目标 |
| 内核→宿主 | 精确基准、请求代、阶段、结果长度与资源结算、结构化诊断 | 独立产物或 Need；宿主核实际采纳权限与快照有效性 |
| 产物→应用 | 完整成员清单、目标前像、生成/人工归属、预期版本和用户授权 | 原子性范围内提交及回读；冲突/失败不覆盖人工工作 |

## 8. 首个验收不再是孤立 Join，而是连续作者任务

复用已有名称/根、共享定义、公开转导及完整工程范本，不另外设计一套演示语言。选一个足以暴露当前接缝的任务，并与两项独立反例共同验收：

**共享定义与两次不同使用。** 一份可复用规则、两个 Use；A 使用有来源的继承默认，B 显式固定数值。两者绑定不同真实实例，参数值可以相同。先生成当前选择的 Rust 库或应用工程；修改共享规则后 A 按其依赖变化，B 的明确决定不能被格式化或默认回填覆盖；实例状态不合并。恢复源后比较允许确定的产物及来源，不热改旧发行。

**专业关系与目标保持。** 在上述任务真正需要的区域使用有型有限关系 Join、投影、重数或见证过滤。先从当前作者源进入真实方法，不以手写目标结果绕过缺失环节。Python 朴素算法、独立有限定义和目标运行分别提供证据；无共享角色的合法笛卡尔积、空结果、同名异类型、非法零注解都需要准确处理。

**非关系语义与失败恢复。** 选择现有的规范义务、共享资源或连续编辑反例，验证有限关系模型不能代签未观察、无权限、持续义务或外部效果。此类能力尚未实现时，正确交付是可保存的准确源、具体未决和不受影响根的结果，不伪造完整产品成功。后继作者编辑、取消、崩溃、版本冲突不得失去原源和已接受结果。

这三项不是三套子产品。第一项防止只做数据库，第二项承接已有本地价值，第三项检验专业边界与机制。实现交付可按真实依赖分批，但设计不能等一种代数全部做完才发现其他已接受语义没有落点。[R7]

## 9. 源格式、身份、编辑与迁移

### 9.1 相同字节、相同值、相同名字不是同一身份

区分语义实体、修订/内容、使用发生、运行句柄与物理位置。重新排序、重命名、公开别名与多次实例化各有不同映射；不能让 hash 相等自动合并两个实例，不能让路径移动自动新建定义，不能把一次 arena 索引写入长期绑定锁。公开转导应保留每跳来源和终端定义，别名不能放宽私有性或产生 Grant。

同一模块在不同 Project/解析域出现可选不同版本，不能压成全局 `moduleId → value`。同一解析槽内出现竞争声明必须拒绝或保留冲突，不按文件枚举顺序裁决。导入阴影、缺失模块、目录覆盖不足都进入依赖。[R9]

### 9.2 精确版本化读取，不能失败后猜别的格式

旧 `/1`、`/2`、实验 `gift.author-structure/1`、候选 `design-converged` 各按准确标记＋文法内容＋Reader 资格读取。相同 `/2` 标签的历史实验也可能不同。错误不能自动重试更宽 Reader；未知扩展可以保全，不自动执行。

#892 ASCII Identifier 与 converged 精确 Unicode Name（含空名）是不同格式域。迁移不能只改正则；须检查引用形状、空名与省略的区别、同名映射、目标名字编码、Unicode 标量/字节/UTF-16/字素位置和诊断。名字不是路径或宿主命令；目标编译器标识符可由稳定内部映射生成，同时保留真实公开名及非法目标导出的明确结果。

直接 JSON 数值词元、任意精度 Int、结构安全整数索引、定宽值、Decimal 刻度、浮点位值、Bytes 编码分别解释。先 `JSON.parse` 舍入再补类型不可恢复原值。`Absent` 与 `Present(null)`、省略默认与显式相同值、未知与 false、零长度与缺项不能合并。

### 9.3 编辑与同源投影

源文本、图、表和短视图提交到同一作者决定。投影回写要保留未显示的源余部、顺序、来源和显式控制，不是只证明两个往返等式。以准确文档版本/语义基准形成候选；写入前比较前像；不同字段能证明无冲突才重基，相交含义冲突不能最后写入者获胜。

运行结果必须带请求代和输入基准，过时诊断不能覆盖新编辑；同语义结果可以复用，但旧位置映射须针对当前源重新核定。撤销/重做保留身份连续性，删除再新建不能自动复活旧对象权限。

### 9.4 一次迁移的明确提交过程

先保存不可变旧源与解释闭包；在新目录/候选中转换；对正向含义、剩余信息、旧引用、目标和回源做检查；展示差异与不可转换项；取得本次接受；用前像条件提交；持久读回后才改变活动 Writer。失败保持旧 Writer 有效，不让新旧同时维护同一决定。

迁移回退并非保证所有数据都可逆。若新状态已超出旧解释域，回到旧二进制可能损坏含义，应停止相交能力并前向修复或选已验证新发行；不能按请求静默回落旧实现。

## 10. 内核、宿主、协议与工作进程

### 10.1 复用已选物理方向，不再造语言路线

当前规范已经设计 TS/Bun 控制面＋Rust 编译内核。纯内核处理固定输入、类型/解释、依赖查询和降低；文件、网络、Git、工具执行、凭据和部署在宿主端。核心缺新事实时返回准确 Need，宿主经授权补取并构成新准备态，不在纯函数里偷偷访问环境。

桌面/无界面开发可用受管暖 worker，一次性 CLI 可短寿命，Rust 嵌入可直调同一粗粒度 API。这是设计采用方向，不是当前单次 `runCommandBytes` 已经实现暖 worker 的事实。先保持简单受管进程和内核共享库，再以启动成本、取消和资源测试决定何时增加驻留；不为“完整”先建远程微服务。[R9]

### 10.2 粗粒度请求，不逐 AST 节点跨语言调用

握手固定协议版本、内核映像、准确文法和能力；请求引用被捕获的内容/快照及目标，不传可任意读取的工作区路径。会话内内容可按摘要去重，首次传送仍有长度、总量和校验；热 arena 与其依赖留在内核。跨境 ID 总有所属请求/快照/代，外部不直接持有内部内存指针。

响应包括实际基准、已完成阶段、有型结果/缺项、实际依赖/覆盖、来源和资源结算。消息有长度及总量限制，stdout 协议与 stderr 日志隔离；部分帧、重复终态、超量输出、版本不符分别拒绝。握手不能声称未安装能力已可用，`.passthrough` 也不能让未知字段获得语义权。

### 10.3 取消、共享计算和重启

取消是请求状态变化，不是已经终止的证明。给共享查询一个等待者集合；取消某位调用者只解除其等待，不终止仍被其他请求需要的工作。最后消费者退出后才取消可中止计算。收到取消确认前，资源仍属原操作；强制终止后取得子树结束证据才能回收对应目录/句柄。

发布结果前核活动请求代、快照/绑定/目标与撤销状态；过时结果可作为只读历史或经重新资格核验的缓存，不得写入当前工程。worker 崩溃使其运行句柄全部失效；新 worker 重建或读取准确可恢复状态，不复用旧数字 ID。

纯、已固定输入任务可以按合同重试。外部动作发生后失去回执时先查询实际效果/操作身份，不能因超时重放安装、推送、付款或部署。副作用幂等能力须由真实 Provider 保证。

## 11. 查询、增量、缓存与确定性

依赖图不是关系图的同义物。源拥有、声明/类型、效果/合同、严格结果前置、生成资源、初始化运行、成员组合七类边可同存储但须保留种类；类型 SCC 合法不意味着等待环可执行。递归需求展开不断产生新键时，同键去重不能证明终止。

查询键按真正影响因素拆分：源/解释、方法/规则版本、必要配置、已选目标、真实环境读集。纯语义查询不要无端带所有工具链版本；目标构建必须包含实际工具、配置、依赖、链接器和目标环境闭包。授权可撤销、外部资源可变化的判断不能当作永久纯缓存。

依赖记录必须包含正读、负查找、成员集合/覆盖和影响控制流的观察。值没有变化可以阻止下游值计算，但必须更新新的 read-set、资格和来源。错误缓存要区分稳定输入下的语义失败与暂时 I/O/容量/权限故障；未知和部分结果不能缓存成全量成功。[E2]

**编译增量与运行数据增量分开。** 前者是源/方法/目标变化后如何重算语义与工件；后者是某个已绑定关系程序如何维护数据结果。二者可以共享不可变快照和依赖思想，但不能共用一个含义不清的 delta，尤其不能把旧运行状态带入新语义修订。

默认正确的全量或分量重算是合法恢复路线；细粒度复用在有健全依赖时启用。新增非局部约束可能必须重查全图，不承诺所有修改永远局部。缓存可有界驱逐，源码、已接受选择与不可再生证据不是缓存，不能因清理缓存而删除。

确定性分别定义：语义结果、生成源、成员顺序、诊断顺序与可复现构建。源顺序本身有意义时不能排序；unordered 集合可用确定编码。时间戳/临时路径可以在明确交付规则中隔离，不能随意删除影响行为的环境输入。机器不同但环境不等时不能声称“同源码必同二进制”。

## 12. 有限关系、六类注解及优化资格

### 12.1 接合映射保留原有独立区别

| 本地责任 | 承接位置与保留边界 |
|---|---|
| Scope：理论/模型/解释修订 | 原准确专业解释绑定与实际适用域；不只比较三个字符串就宣告同义 |
| Sort/有限 carrier | 公共 Type/名义类型＋明确的有限域解释；同值列表不自动同类型 |
| Relation：多元角色与注解事实 | 合格领域输入/结果；角色、重数、来源与覆盖保留；不与类型约束 `Relation` 混合 |
| Algebra | 准确方法画像的运算、相等、零/单位、编码、支持/否定及资源资格 |
| Join/Project/Rename/Alternative/过滤计划 | 原方法下的可重建执行结构；共享角色或显式绑定决定相关性 |
| 增量状态 | 对准旧/新输入修订与方法的候选状态；成功提交，失败留旧态 |
| emitter | 只做既定语义的目标映射；不在打印阶段猜语义或方法 |

### 12.2 六类解释不可被统一去重或统一减法

Boolean 为存在性 OR/AND；Count 为自然数加/乘；Tropical 为 min/+ 并有无穷编码；Rational 为非负精确分数；Provenance 为来源多项式；Events 为固定样本世界子集的并/交。Events 不是外部事件流，Rational 不是统计真实性，Provenance 不是司法/安全信任证明。最新优化新增的支持、半连接和有限排除应按实际源审计，不由名字推断含义。

必须先核输入有型、Scope/Algebra/Sort 合格，再消零或剪掉无用字段。无共享角色 Join 仍可为合法笛卡尔积；不同名角色的显式绑定不能变为按名字合并；Rename 必须维护其声明的单射/冲突规则；Alternative 的端口与解释须兼容。合法空关系不是未知输入；有限排除不能证明开放现实不存在。

**有限元组域不保证加权递归收敛。** 一个元组的 Count 方程 `x=1+x` 在自然数上没有有限解；迭代可无限增长。每个递归方法须声明单调性、序、有限高度/收敛条件或合格加速及结果含义。达到预算返回停止/未决，不把近似值标精确固定点。否定、非单调聚合和外部效果不能随普通 SCC 无条件放行。

删除维护需要当前代数可用的支持结构或局部/全量重算。Tropical 最小值删除后要找剩余支持；Count 实际状态可用有符号差分中间表示时必须明确边界，不能令其普通注解出现非法负重数。Differential Dataflow 的部分撤回算子要求 negation，并不意味着所有算子都要求群，也不意味着六种注解都能无条件用同一种差分。[E3]

### 12.3 优化必须有适用域，不能仅看最终值相等

每条规则固定输入/输出型、角色绑定、代数律、顺序/重数、错误与效果、覆盖、来源和预算约定。投影下推须留住连接键、比较角色、过滤见证；纯函数可移动不代表含外部动作也可移动。校验语义规定必须拒绝的输入，不能通过提前优化抹去。

资源预算属于明确运行合同：优化后更少工作、避免旧实现的额外预算失败通常是改进，不要求保留偶然低效；但必须保留真实硬资源上限和正确停止状态，不能以不同计量口径算出“倍速”。计费操作、CPU、墙钟、峰值存活内存、复制和最终输出规模分别测量。

先有能够直接检查的规则集与退回路径，再按实际争夺优化次序的需要引入 e-graph。`egg` 可以限制迭代/节点/时间并按给定成本抽取，但其结果只是在探索范围及成本模型下的选择，不是现实全局最优证明。[E4]

## 13. 目标代码必须是完整可独立使用的工程

当前新目标优先 Rust；其源码、crate/清单、锁、入口、资源、配置、必要运行库、许可证和 SourceMap 构成同一明确产物。保留 TS 旧能力并按相交转换做回归或对照，不能因为只测试 Rust 内核就认为 Rust 目标成立。[R10]

数学 Int 需要准确有界选择或合格大整数实现，不能偷偷压成 i64；精确 Rational、Decimal 刻度、IEEE 位值/NaN/负零、Unicode Text、Bytes、错误/取消、借用/寿命、初始化顺序、并发和可见 ABI 都按所选目标分别闭合。目标缺某能力时返回具体目标缺项，不修改原作者要求。

Rust host 与输出 target、构建 host 与目标 triple、edition、features、panic 策略、std/no_std、链接器与运行环境分别固定。选择 Rust 输出不等于所有平台可运行；Linux 上过关不证明 Windows 文件与进程生命周期正确，交叉编译成功不证明目标机器运行通过。

复用既有原生实现而不是生成同义副本；包与原生 API 的签名只证明结构，效果和语义还需对应资格。FFI 的布局、调用约定、编码、拥有权、线程与错误处理必须明确，不以 Rust 默认 ABI 建立稳定第三方生态接口。

当前 bundle 以文本 content 携产物；二进制资源不能因此丢弃或强行转换 UTF-8。需要支持时由原 Artifact/内容存储边界增加准确字节成员或内容引用，源模型不装大块 base64。生成、构建、验证、安装、运行、发布是不同作用：源码预览不得偷偷联网下载依赖或执行构建脚本。

编译工具也可能执行代码。Rust procedural macro 与 build script 带文件和进程环境风险，所以实际构建必须在合格执行边界内固定工具/依赖/网络与权限，而非因“只是编译”视作纯计算。[E5]

独立退出路径是：生成工程在记录的依赖与工具环境下可脱离 Gift 构建运行；作者工程、解释锁、必要源映射与使用许可可导出。不承诺没有任何依赖，也不把依赖只留在生成器私有工作区。

## 14. 并发、故障、资源与发布恢复

### 14.1 单写者不是阻止并行，而是明确提交责任

同一可变候选及相交 owner 只允许一个写入者；互不相交且有真实收益的研究/适配可以并行，最终集成者核前像与消费者。源分支可并行不等于可忽略语义冲突；两个文件不同行仍可能改变同一默认或解释。

调度同时约束 CPU、内存、进程、句柄、临时空间和 I/O。不能每个子任务各拿完整父预算，再把全局限制变成并发倍增。任务扩展、递归实例化和输出爆炸都消耗原预算；已有硬上限不能靠提高 timeout 遮蔽。

### 14.2 保存与发布采用可恢复状态，而不是一串无条件覆盖

拟定流程为：准备不可变候选→验证所需成员与资格→在目标旁建立 staging→核目标前像和操作代→提交可原子替换的活动引用/manifest→持久读回→按已确认归属退役旧暂存。多文件 rename 不是天然跨文件事务；需要由完整成员清单和原子活动引用或已有事务机制给出真实可见性边界。

处理磁盘满、权限拒绝、文件占用、目录替换、杀进程、断电、半写 manifest、摘要不符与并发用户修改。重启先依据真实 journal/操作状态判断 prepared/committed/未决，不能以“目录已存在”认领旧输出。未知归属保留并定位，不任意删除。

清理必须在真实子进程树结束及消费者释放后进行；路径字符串不是所有权凭据。Windows FileId/持有句柄、POSIX inode/链接/挂载边界、大小写碰撞与原生权限按支持平台取得证据。未选旧输出和人工文件保留；更新清单不应把用户新增文件当垃圾。

### 14.3 回退与业务状态恢复不是同一件事

撤回内核 Binding 不自动撤回已经发布的产物、数据库迁移或外部作用。代码发布回退、数据格式回退、运行操作补偿各有条件。已不可逆的真实效果需要查询、补偿或人工处置，不能称为原子回滚。

复用原 K0—K5：冻结合同→独立 oracle→获准影子验证→按新 Binding revision 单 owner 切换→优化→消费者清零后退役。回归先隔离相交能力和在途请求；只有旧实现仍满足当前合同且所需状态可读取才显式回绑，否则前向修复。不使用“新内核超时就调用旧内核”的隐式按请求漂移。[R11]

## 15. 安全、供应链、隐私和信任

作者源、研究文件和代码中的指令性文本是数据，不是本次行动权限。AI 对源的建议需要经过与人同等的类型/权限/前像检查；不能从注释“可执行”得到外部操作许可。工具 schema/ref/路径不等于授权。

解析攻击包括重复键、巨大深度、恶意别名/递归、Unicode 混淆、超大指数/整数、多项式膨胀、正则回溯和反序列化不受限分配。输入长度、展开图节点、词元工作、实例化、内存与输出预算都要在分配/复制前检查；未知语义保全但不得进入执行。

原生子进程不是天然沙箱；明确哪些代码受信、哪些需操作系统或 Wasm/容器等真实隔离。Wasm 的外部作用经显式 imports 暴露，但宿主给出的能力及实现漏洞仍构成边界；不能把选择某个运行时当作全平台安全证明。[E6]

对内容共享、缓存和影子执行按项目/租户与敏感域隔离；摘要相等不赋予另一主体读取权，缓存命中也可能泄露内容存在。日志/诊断/SourceMap 不写入秘密；保留期限、删除请求、备份与证据相互约束，证据身份不能无限延长原始数据使用权。用户没有授权的远程分析和上传不得作为性能默认。

依赖采用记录实际来源、固定版本/摘要、许可证、平台能力、漏洞处置及离线恢复。Hash 验证的是字节一致，不是作者身份、无恶意或行为正确；有签名也需核信任主体与声明范围。可借鉴 SLSA 的构建者和参数核验，不自称已经取得 SLSA 等级，不为每次纯编辑强建供应链平台。[E7]

## 17. 验证设计：从共有错误、异常和真实交付反推

### 17.1 独立性按失败来源判断

同一个 Python Evaluator 执行原计划和优化计划，是重写保义的有效差分，但二者会共享解释错误。TS 和 Rust 由同一错误计划生成，也可能一致地错。一个源错误被两个工具接受不证明含义正确。

组合使用：直接规格上的小域枚举/手工预期；保留未优化、容易审查的参考；真实优化与增量路径；目标自身编译器和执行；选择性故障注入/协议状态模型。每个证据说明它覆盖哪一层，不把随机样本提升为定理。全量重算不天然独立于错误的基本算子，因此还需基本算子的独立定义。[R12]

形式方法按真实义务选：代数/编码保持可用小证明或证明器；并发/恢复可用有界状态模型；实现级边界按对应验证器能力处理。工具版本、模型映射和公理进入证据范围，不强制所有开发者安装一整套形式工具，也不因“未形式证明整个系统”拒绝已有可靠局部事实。

### 17.2 本轮实际执行的八个设计反例

本轮编写并执行了独立的 Python 设计核对脚本，结果 8/8。它不导入 Gift，也不是产品测试，不能据此宣称任何实现 PASS。

| 反例 | 结果 | 限定结论 |
|---|---|---|
| Count Join 前丢关联键 | 正确输出 A 的重数1，错误提前投影后为2 | 投影必须保留相关性，不能只看最终字段 |
| 存在性半连接与加权连接 | 已选存在性画像保留左权2，加权连接为14 | 两种语义不能混用；不主张所有本地 Semijoin 的定义必如此 |
| 一个元组的加权固定点 | N 上迭代0,1,…,6；Bool 上进入true | `x=1+x` 无有限自然数解由代数推出，有限迭代仅作展示 |
| 最小值删除 | min{1,3}=1，删1后为3，不是1−1 | 需要剩余支持或重算 |
| 零注解非法成员 | outside 不属 {a}，先消零会掩盖不合法源 | 形成检查不可被优化抹去 |
| Rational 与宿主浮点 | 1/10+2/10=3/10，浮点表示0.30000000000000004 | 精确画像不能隐式换成二进制浮点 |
| 同值新依赖 | 两次结果都是7，但读取a变为b | 可复用下游值，但必须更新依赖 |
| 发布基准相等门 | 两个二值字段16组合，仅4个匹配可发布 | 只验证逻辑门真值表，不证明真实并发或文件系统原子性 |

### 17.3 不能省的工程验收矩阵

| 边界 | 实际验收与失败场景 | 完成判据 |
|---|---|---|
| 目标与责任 | 一个要求、多方法；同值不同实例；硬约束冲突；缺专业解释 | 未决不伪false；方法不改原要求；无主张丢失 |
| 源读取 | 重复键、非标量Unicode、原数字词元、未知格式、过深/超量源 | 准确拒绝/保全；不舍入/猜格式 |
| 名称与模块 | 空名/省略、转导、私有引用、别名环、同名多解析域 | 真实终端和来源保持；未知覆盖不补不存在 |
| 类型与形成 | 名义类型、单位、carrier、零注解非法值、空Relation | 先形成合格再优化；同形不冒充相容 |
| 作者编辑 | 默认继承/显式固定、未知余部、并发修改、撤销重做 | 无双写、无身份串换、旧结果不覆盖新源 |

| Relation | 六代数、端口绑定、投影、重名、无共享键、重复/空 | 所选画像下结果/来源/重数一致 |
| 优化 | 角色依赖、非幂等、有限排除、错误可观察性 | 规则适用条件成立，域外不优化 |
| 增量与递归 | 删除、同值新依赖、负查找、计数发散、固定点 | 更新依赖；失败保旧态；终止与结果资格分开 |
| 缓存 | 解释/锁/工具改变，权限撤销，跨项目命中 | 不复用失效资格、不泄密、不把暂时故障永久化 |
| IPC | 超量/截断帧、错基准、伪arena边、旧代结果、协议版本差 | 有界拒绝；不得构造未签发认可对象 |
| 并发取消 | 多等待者、最后取消、worker崩溃、未知子进程终止 | 不误杀借用计算、不提前释放、不发布过时结果 |
| 目标构建 | Rust实际源→Cargo/rustc→运行；TS既有消费者 | 每目标独立证据；不以kernel测试代替target |
| 数值与ABI | 大Int、Rational、NaN/负零、Bytes、FFI拥有权 | 不缩值域、不泄露不稳定ABI或隐式编码 |
| 资产与路径 | 二进制、相对路径、大小写碰撞、symlink、Windows占用 | 成员完整，人工文件与越界路径不被覆盖 |
| 发布恢复 | 磁盘满、半写、崩溃、并发源改变、回读失败 | 不见半成品；journal/前像决定恢复 |
| 外部作用 | 执行成功回执丢失、重试、撤销、补偿失败 | 查询真实结果；无虚构exactly-once |
| 安全供应链 | proc-macro/build脚本、恶意源、依赖替换、秘密输入 | 固定与隔离真实作用，不靠hash/语言自签安全 |
| 性能资源 | 冷暖、编辑、Join倾斜/密集、输出爆炸、内存/磁盘耗尽 | 记录真实成本，不以元组计数代替时延 |

| 退出与兼容 | 离线重建、旧发行、数据库/缓存格式变更、独立导出 | 旧消费者结算、恢复依据明确、可脱离Gift交付 |

编辑期只跑相交有效哨兵，冻结候选才付昂贵证据成本。现有 timeout 不被覆盖为绿灯；测试支持平台、配置、源码修订和环境准确绑定。产品级全量验证本轮未运行。

**来源前沿。** 取末次 5722… 包、前像和完整研究；核成员安全与严格差异。缺包阻断其源级移植和全量保存声明，不阻断已取得规范与仓库接缝设计。保留自动任务暂停状态。

**合同前沿。** 同时完成 #892 未结算语义和本地六类解释的责任映射；确定作者决定、旧输入、新源、方法与目标的准确边界。不要求先把整个研究宇宙证明完才能实施一个已明确区域，也不因此放弃其余研究分支。

**真实接合前沿。** 在现有Rust Reader/分析、TS宿主和原生成/验证 owner 内补齐当前新作者源→选择根/义务→方法→目标贡献这条链。旧状态转换图保留；新领域有型接入，不造第二总编译器。缺失一般Method能力按真实需要实现，不假设名字存在就是API就绪。

**完整作者切片。** 共享定义/两Use/默认与显式控制/后继修改为主例，关系计算和专业未知为对照；新目标 Rust 实编运行，TS保留已有回归。可以先以朴素合格执行取得正确闭环，不为测前置而重复做TS生产实现。

**算法与机制接合。** 按成熟批次迁入需要的Join索引、投影下推、六代数、维护算法。先验明其型/律/预算，再比真实成本。运行机制同时承担取消、版本发布和资源，不等所有功能完成才补安全和恢复。

**资格与采用。** 冻结代码树，运行相交缺失证据、独立审查与真实目标验收；在明确授权后更新原PR/合并通路；确认远端读回及支持范围，逐能力切换。旧生产writer只有消费者与恢复依赖都清零才退役；历史字节和独立oracle不因清理活动入口消失。

| egg/e-graph | 合格纯域的多种重写与受限成本搜索 | 专业规律发现、外部效果、世界本体 | 简单规则集不足且测试/内存/搜索成本可控 |
| Wasm/隔离Provider | 受限第三方执行边界 | 宿主权限、输入披露、网络与供应链管理 | 真实不受信可执行扩展出现，平台提供相应隔离资格 |
| 证明/模型工具 | 指定编码、代数、不变量、协议性质 | 真实实现映射、部署环境与外部事实 | 高风险或复用范围足够大，不强制全栈工具化 |
| 标准构建provenance | 生产者、输入和参数的可信核验 | 行为正确、运行授权 | 真实发布与供应链场景需要，复用原Evidence机制 |

这些不是购物清单，也不是必须同时安装的技术栈。CUE 的值格及缺省/null含义有自己的精确定义；映射到Gift必须单独取得保持依据。[E8]

## 20. 成本、选择依据与反转条件

性能目标按真实工作流：首次载入、一次小编辑、共享定义大范围变化、冷/暖生成、首个Rust构建、增量构建、取消到资源停止、崩溃恢复、独立导出。分开记录端到端时延分布、CPU、峰值存活内存、分配/复制、IPC字节、磁盘、缓存与构建成本；开发改模、调试和维护成本也要计入。尚无这些同口径测量，不给固定倍率、节点阈值或胜率。

默认机制尽量小：局部纯方法、不可变输入、普通集合/有型arena、粗粒度IPC、已有存储和构建工具。已知硬时限/容量直接要求更强机制时从第一份生产实现满足，不强制先写一个必定不合格的慢版本。无真实工作负载支持，不上锁自由、分布式调度、全面零拷贝或每域一个crate/服务。

以下情况会改变局部方案而不是否定全部设计：Rust目标必须的平台不具备可用工具/运行能力；跨语言传输成为实际主瓶颈；关系维护规模确实需要不同执行器且语义可保持；现有生成owner无法承载需要的结果而改动波及不可接受；可用成熟Provider在完整生命周期上显著优于自研；已有合同经反例证明丢失必要区别。对其给出实际反例/测量，再调整相交owner，不以沉没成本、工具品牌或一项微基准强定全平台。
