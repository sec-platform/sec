# Gift 编译器与工程语义：从底层机制到可落地系统的系统教材

**修订日期：2026-11-05。目标读者：**准备亲自设计、实现和审查 Gift 的开发者。内容是可自学、可复核的工程教材，不是“业界所有知识已经穷尽”的宣言；每章给出定义、真实机制、例子、能力边界与验收问题。附独立 Node.js 教学编译器，源在《Gift_编译器精通_学习实验室.zip》。

## 0. 先定目标与能力边界

Gift 的最低独特成果不是画图、目录或实现一个查询平台，而是让人/AI创作真实的新定义、函数、状态、组件、接口与工程要求；系统能够解析、绑定、检查、复用、编译成可运行目标代码，并支持后继修改。相应的世界描述、来源、知识、证据、规范、影响分析与多维投影按真实需要介入，不能阻塞简单的局部编译。

**区分三件事：**（1）世界中真实发生了什么；（2）程序和规范的模型表示什么；（3）程序实际执行和外部环境承诺了什么。编译器可校验模型与转换，不会自动确认现实事实或取得外部权限。

**掌握级别：**

- **A：能从空项目亲手实现，并能调试和解释每一步。** TypeScript/JavaScript核心、Git、操作系统与文件、函数、数据结构、AST、绑定、类型、错误、代码生成、增量编译、构建与测试。
- **B：能设计正确合同，阅读专业工具源码并写必要子集。** 泛型/类型推断、操作语义、控制流、效果与生命周期、状态机、模块链接、编译优化、语义保持、异步与并发、缓存与依赖。
- **C：能判断适用性、接合专家工具并识别错误结论。** 依赖类型、高阶逻辑、模型检查、概率/因果、分布式一致性、形式化证明、机器码后端、高级优化、理论映射与现实证据。无需在第一阶段自行重写所有C级算法。

最重要的是不要把“读过词语”误认成“能设计、能调试、能验收”。达到A级的验收是：独立写出一个端到端有型小编译器，生成可执行代码，能够处理新函数和两次连续修改，并能解释错误与反例。

## 1. 计算机执行程序的第一性原理

### 1.1 计算的最小模型

程序运行是**状态变化**：在某一时刻，机器具有寄存器、内存、程序计数器、外部设备和进程状态；一条或多条指令根据规则读写这些状态。源语言的变量、函数、对象、异常和异步任务是为了让人编程而建立的抽象，不是CPU天然认识的对象。编译器/解释器必须建立这些抽象到目标执行环境的对应。

“语法合法”与“运行有意义”与“目标能执行”不同：`x + y`是可能的语法，若 `x` 为对象、`y`为没有加法含义的资源令牌，类型检查或具体语义可能拒绝；即使类型合法，目标环境也可能不支持其资源、精度或效果。

### 1.2 数据表示不是值本身

八位为一个字节是典型现代计算系统的基本约定，但字节序列如何解释由编码和类型决定。`0x41`可以解释为数字65或ASCII字符`A`。字符串还有Unicode码点、UTF-8字节、UTF-16码元和用户感知的字素簇；它们不是同一个“字符长度”。

整数还区分：数学整数（无限精度）、固定位宽二进制补码、有符号/无符号、溢出策略、宿主JavaScript `number`与`bigint`。浮点数表示有限近似值，必须核对NaN、正负零、无穷、舍入与次序关系；`0.1 + 0.2`不能无条件当作精确的数学`0.3`。Gift不应让精确数学整数暗中降低到不能精确表示的JS `number`。教学编译器把 `Int` 明确映射为`bigint`，这是可行的有限目标选择，不是所有领域默认都应使用bigint。

### 1.3 内存、栈、堆与生命周期

**栈**（stack）按调用与作用域组织自动存储；**堆**（heap）容纳生命周期不容易与调用栈同步的对象。但编译器/运行时可优化、逃逸分析或分配在寄存器，所以不要把“对象一定在堆上”当成语义公理。变量本身是符号绑定，不一定等于一块唯一存储地址。

例：`const a={count:1}; const b=a; b.count=2;`，通常`a`与`b`引用同一对象。若误把`b=a`解释为复制对象，就会生成错误程序。共享别名（alias）、所有权（ownership）、可变性（mutability）、生命周期（lifetime）是复杂语言的基础差别。`const`冻结变量绑定，不会自动冻结所引用对象的内部属性。

### 1.4 进程、线程、事件循环和外部效果

进程是运行资源与隔离边界之一，线程是进程内可并发调度的执行流；异步任务不一定创造新线程。JavaScript事件循环按任务与微任务规则调度，`await`不是CPU暂停等待的普遍机器指令。读时钟、文件、数据库、网络、随机源是不同**效果**（effect），常常不满足重复求值等价。若两次读取时间代替一次共享结果，程序可能已经改变。

与Gift的直接联系：IR不仅要表示“算出什么值”，还要在必要时保留“读取发生了几次、是否共享同一对象、是否允许重新排序、失败后是什么状态”。

**练习：**解释为什么`const t=Date.now(); use(t,t)`与`use(Date.now(),Date.now())`不能无条件互换；为什么复制内存里的数值不等于复制独占文件句柄；为什么只改源文件不改变已启动的旧进程。

## 2. 先成为能独立写工程的程序员

### 2.1 TypeScript/JavaScript真正必须精通的内容

从表达式、语句、函数、对象、模块、导入导出、数组与Map/Set开始；接着是词法作用域、闭包、递归、异常、Promise、async/await、生成器、迭代协议、泛型、结构类型和类型缩窄。理解类型检查发生在构建阶段，而JavaScript运行时通常没有TypeScript类型。

```ts
function counter(start: number) {
  let n = start;
  return () => ++n;
}
const a = counter(0);
console.log(a(), a()); // 1, 2
```

闭包并非把函数定义时的全部变量值永久复制一份；这里的闭包保持对同一`n`绑定的持续访问。若 Gift 把`counter(0)`的两个不同调用合并成同一个运行实例，就会错误地共享计数器状态。

**类型与运行值分开：**TypeScript结构化类型使`{x:number}`可兼容形状相同的类型；但业务身份证、用户ID、资产ID可以需要名义区分（nominal distinction），不能仅凭同为`string`合并。运行校验不等于静态类型保证，外部JSON不受源类型注解自动保护。

### 2.2 JavaScript与TypeScript中最容易造成编译器错误的地方

- `===`与`==`不同；`number`与`bigint`有不同运算约束；对象相等通常按引用身份；`Object.is`对NaN与±0的行为又不同。
- `undefined`、`null`、字段不存在、`false`、0和空集合是不同状态。
- `Array.sort`默认比较不是数值排序；对象键枚举、Map顺序与业务顺序不总等价。
- `async`函数返回Promise；异常与rejected Promise的传播和同步异常并不在全部边界相同。
- 模块有初始化顺序、循环依赖与副作用。只根据静态导入图，不一定知道完整运行行为。
- TS可在编译期检查，但实际编译/转译是否执行类型检查由所用工具决定。Bun的Transpiler用于转译，不等于TS类型检查器。[官方Bun Transpiler文档](https://bun.sh/docs/runtime/transpiler)。

### 2.3 工程工具掌握标准

能独立使用`git diff`、`git status`、`git log`、`git show`、分支、提交、rebase、merge、冲突恢复，且理解工作区、暂存区、Git对象数据库和远端仓库不是同一东西。会读`package.json`、lockfile、tsconfig，理解ESM/CJS、Node/Bun模块解析、文件系统路径、进程退出码、标准输入输出、环境变量、Shell转义、Windows/WSL边界。

**练习：**写一个包含三模块的TS项目：循环依赖、同名导出、类型错误、运行时文件不存在各制造一次；分别指出解析、类型、链接/加载、运行哪个阶段发现问题。

## 3. 数学：真正会用的部分，不是追求所有数学分支

### 3.1 集合、函数、关系

集合是成员结构；序列另有顺序和重复；多重集（bag）保留重复次数。函数`f:A→B`要求对A中每个输入有唯一的B值；**偏函数**可对部分A无结果；有返回错误的计算不是直接将错误当普通B值。关系`R⊆A×B`可对同一A关联多个B，关系并非自动是函数。

关系组合：

\[
(R;S)(a,c)\iff\exists b\;(R(a,b)\land S(b,c)).
\]

这可以解释数据库连接、关系路径和一部分规则推导，但不能自动表示调用顺序、并发、所有权转移或因果。买方-卖方-金额-同次交易必须保留四元角色/发生身份，不能任意拆成不相关的二元边。

**单射**（injective）不同输入不会合并成相同输出；**满射**（surjective）目标域每个元素都有原像；**双射**（bijection）兼具两者。这三种关系直接影响对象身份、理论映射、序列化和源码位置能否往返恢复。

### 3.2 命题逻辑与量词

`P∧Q`是共同满足，`P∨Q`是至少一种，`P⇒Q`是不满足P时没有违背该条件命题，不是执行P然后执行Q。`∀x∃y`与`∃y∀x`一般不等价。`¬∃x P(x)`等价于`∀x¬P(x)`（在同一标准经典逻辑及给定域下）；而“不知道存在”绝不自动等于“已经证明不存在”。

逻辑中**自由变量**依赖外层环境，**绑定变量**受对应量词或λ绑定者控制。对表达式做代换时必须避免捕获：将`y`代入`λy.x`的`x`位置，若直接得到`λy.y`，就错误地改变了原来自由的`y`。正确处理可采用新鲜命名或de Bruijn索引等。

### 3.3 证明你真的需要掌握的技巧

**归纳法**适于证明所有有限语法树上的性质：先证明常量、变量，再证明若子表达式性质成立，则函数应用、比较、分支也成立。证明类型保持、语义保持、输出完备经常使用结构归纳。

**不变量**是运行中必须保持的性质，例如每次插入/删除后哈希表中的键定位正确。设计循环时使用初始化、保持、退出三部分说明。**反例**用于推翻不成立的全称命题，只需给一个满足前提却违反结论的合法对象。形式验证不是“没有看见失败”，而是证据对所声明范围覆盖的程度。

### 3.4 偏序、格、不动点与图

编译器数据流分析经常需要逐步累积信息，例如每个基本块入口可能已定义的变量集合。按集合包含形成偏序，转移函数反复应用直至稳定：`X_{n+1}=F(X_n)`。在适用的单调性和域条件下可以研究最小/最大不动点。有限高度域上的单调迭代能够停止；无限域需要更明确的收敛和近似策略，不能直接宣布所有不动点都能枚举。

图知识包括可达性、拓扑排序、强连通分量（SCC）、树与DAG区别、最短路、支配关系、依赖传播。递归调用图允许环；简单的常量定义图可能要求无环；同样一条画出来的边，算法约束不同。

### 3.5 复杂度与数学成本

时间复杂度`O(n)`并不表示一定比`O(n log n)`快；常数、内存访问、数据规模和缓存也重要。哈希表平均查找通常可接近常数，但冲突、安全输入和实现决定最坏行为；排序通常是`O(n log n)`量级；大型查询和多对多连接可能让中间结果爆炸。

**练习：**证明`∀x:P(x)∧Q(x)`等价于`(∀x:P(x))∧(∀x:Q(x))`（同一域）；构造一个“每个模块局部可满足，但共同约束不可满足”的二元模型；解释同值的两个独立请求为什么不能合并为一次资源占用。

## 4. 算法与数据结构：编译器每天都在使用

**数组/向量：**顺序存储、批量遍历、随机访问；适合Token序列、AST子节点、表。**哈希表：**由符号键找声明、缓存查询结果。**树：**递归表示表达式与语句；理解语法树是“形成结构”，不是所有关系天然都是树。**DAG：**共享依赖且无环，适合很多确定编译工作项。**有向图：**符号引用、模块依赖、控制流、调用关系和数据流。**工作队列（worklist）：**不断处理新发现的影响直到没有待处理项。**并查集：**跟踪等价类；**优先队列**用于候选搜索和调度。

**核心数据结构选择：**不要因为统一世界语义就强迫所有内容变成长期持久图记录。局部表达式可以是一棵普通AST，临时类型约束可以是内存Map，复杂行为有CFG，源码资产有文件树，知识关系可用索引/关系表。共同身份与准确转换比共享一个物理容器重要。

**关键反例：**同一段源码在两个地点引用同一个不可变纯定义，可以共享编译计算；但两次调用具有真实副作用的函数，不能因为AST相同就只运行一次。优化器必须依据“纯度、效果、共享身份”作决定，而不是依据结构哈希。

**练习：**实现符号表`Map<string,Decl>`、作用域栈、Tarjan SCC检测递归定义群、一个基于依赖边的工作队列；增加第三个调用者时验证增量影响结果。

## 5. 语言构成：从字符到有意义的程序

### 5.1 词法分析（lexing）：切分合法符号

输入是源码字符序列，输出是Token。`score >= threshold`可被切成：标识符`score`、运算符`>=`、标识符`threshold`。最长匹配规则保证`>=`不被意外分成`>`和`=`；换行与注释在很多语言中不影响求值，但对精确源回写、格式化、宏或某些语言语法仍可能重要。定位（source span）保存原源码起止偏移与坐标；若字节、UTF-16码元、Unicode码点混用，编辑定位会错。

Token不是AST。`if`单词可以被词法识别，但它属于哪一种控制结构取决于后续语法。

### 5.2 语法分析（parsing）：恢复嵌套结构

表达式`1 + 2 * 3`通常应理解为`1 + (2 * 3)`；这由运算符优先级决定。`a-b-c`通常是`(a-b)-c`，这是结合性规则。递归下降可以处理声明与结构；Pratt parser可用很短的代码处理有优先级的表达式。别把“能解析JSON”误认为已经能解析通用程序：JSON数据结构并不会自动说明运算、绑定、控制流和类型。

示例：

```text
源：  score >= threshold
AST： Binary('>=', Var('score'), Var('threshold'))
```

AST刻画程序结构；CST（Concrete Syntax Tree，具体语法树）通常保留更多源细节，如空格、注释、括号，适合IDE和精确保真重写。是否同时保存CST/AST按功能决定，不必为了“最通用”一律持久化两份可写源。

**错误恢复：**IDE应在括号不闭合时继续提供有意义的补全，常用方法是保留错误节点并在分号、闭括号等位置同步；但错误AST不能偷偷获得“合法可执行”的资格。

### 5.3 名称解析（name resolution）和词法作用域（lexical scope）

`x`是一个名字，不是变量身份。绑定发生在**特定词法环境**内。例如：

```ts
const x = 1;
function f() {
  const x = 2;
  return x;
}
```

`return x`指内层的`x`，不能根据全局字符串表误绑到外层。符号表通常按嵌套作用域查找。`symbolId`属于一个声明；每个引用必须有可解释的目标。两个同名声明是两个身份，除非语言显式规定相应重载/合并规则。

**前向声明**：允许`f`在源码前面调用后来定义的`g`，可先收集所有函数签名，再检查函数体。递归调用仍是引用，编译器不能直接文本内联直到无限展开。

**捕获问题：**宏展开、Lambda代换、重命名都需要保持绑定卫生（hygiene）。直接查找替换单词通常不足以构成正确重构器。

### 5.4 类型（type）：允许什么操作，不只是字段格式

类型判断的简化形式是：

\[
\Gamma\vdash e:T
\]

含义：在环境Γ记录的变量/符号类型下，表达式e具有类型T。对于整数比较：若`Γ⊢a:Int`和`Γ⊢b:Int`，则`Γ⊢(a>b):Bool`；对`a+b`则结果是Int。类型检查是使用已声明规则的**证明过程或约束求解过程**，不是每个符号靠应用逻辑独立手写一套if。

```text
score: Int
threshold: Int
score >= threshold: Bool
```

重要区分：结构类型、名义类型、子类型、泛型参数、代数数据类型、可空/可选、宽化/窄化、类型推断、重载解析和效果类型。入门先实现精确基础类型，再逐步扩展产品需要的类型，别一开始就追求依赖类型完整求解。

**类型推断**不是“由字符串猜名称含义”。常见方法是产生等式约束与合一，例如从`x+1`推得x与结果具有满足加法规则的类型；泛型的推断还需处理约束、多态实例化和目标上下文。

### 5.5 语义（semantics）：程序实际意味着什么

语法`score >= threshold`本身只是树。具体解释还需`score`、`threshold`的类型与值域，`>=`在那个值域上的定义，例如整数全序、浮点偏序（NaN）、字符串词典序或用户定义顺序。变量环境ρ给出当前绑定值，解释可写为`⟦e⟧ρ`。语法树相同不表示在所有语义画像下结果相同。

**操作语义**描述计算怎样一步一步改变状态，如`⟨e,σ⟩→⟨e′,σ′⟩`。**指称语义**描述表达整体映射到什么数学对象，如纯函数、输入输出关系或行为集合。两种角度互补：编译IR操作、效果次序更容易使用操作语义；等义证明和合成规范可以借助指称模型。

### 5.6 三个不同的“正确”

1. **形成正确**：词法、语法、名字、类型合法。
2. **求值正确**：代码在指定模型中按定义求值，或转换前后保持所需观察。
3. **需求正确**：实际用户期望、现实环境和公开效果都得到满足。这需要独立任务与证据，不能由编译器型检查自动证明。

**练习：**在教学编译器中加入`/`操作。先分别规定除零、负数除法取整、返回类型、异常/未定义行为，再写解析和Emitter；如果仅增加一个`'/'`字符而不回答这些问题，你就看到了“新增语法不等于新增语义”的区别。

## 6. 把有型表示变成能够执行的程序

### 6.1 AST、HIR、MIR、IR的真实区别

AST偏作者结构，High-level IR可消除语法糖并保存较高层含义；控制流IR偏机器执行顺序，适合路径分析；SSA（Static Single Assignment，静态单赋值）让每个IR名字在静态表示中只赋值一次，简化数据依赖。Rust编译器官方把AST、HIR、THIR、MIR和最终LLVM IR区分开，见[官方总览](https://rustc-dev-guide.rust-lang.org/overview.html)。

**不要为命名整齐而建立十层IR。** 如果Gift起步直接生成TypeScript，在小型纯函数片段中“有型AST→TS语法树/源码”即可。真正需要控制流/所有权/异步变换时再引入适合该需求的IR。多个IR必须有明确用处、转换入口及正确性合同。

### 6.2 控制流图（CFG）与数据流

假设：

```ts
let z: bigint;
if (cond) z = 1n; else z = 2n;
return z * 3n;
```

CFG至少具有入口、分支、合流和出口基本块。SSA可以把分支中的`z1`与`z2`分别作为值，合流处用φ函数或基本块参数选取真实前驱传递的值。对于直接生成TS，不一定需要实体SSA；但要理解为何合流处的值不来自“两个分支随便选一个”。

**支配（dominate）**：节点A支配节点B，意味着所有从入口到B的路径都经过A。该概念用于SSA构造、代码移动、变量定义合法性。**活跃性（liveness）**：某变量在一个点之后是否仍可能被使用，用于寄存器分配、资源分析、死码消除。

### 6.3 降低（lowering）：保留必要语义的结构转换

将高级`foreach`降低成`while`可能改变：迭代器何时创建、对象是否快照、异常、取消、资源释放、集合是否允许同时修改。正确降低需要先固定源语义，然后按目标实现对应。

例如：

```text
源： if x > 0 then f(x) else g(x)
目标： x > 0 ? f(x) : g(x)
```

若源规定只计算被选分支，目标条件表达式对应；但若把两边的函数调用都提前执行再选择结果，就在`f/g`有副作用或异常时改义。一次优化的可用性由语义前提决定，不是由语法树看起来相似决定。

### 6.4 源码生成（emission）

Emitter输入应是合法且语义已固定的结构；输出不仅有文本，还应考虑合法标识符、转义、运算符优先级、导入、导出、运行时helper、目标类型表示、错误出口、代码布局、文件路径与重复声明。尽量用成熟目标语言AST/Printer，或在严格受限的语法片段中使用已测试的安全渲染器；不能直接把不可信字符串当目标源结构拼接。

**类型擦除（type erasure）**：TypeScript输出JavaScript时通常不保留静态类型注解，因此运行时验证必须由相应代码/宿主保证。目标有源程序也不代表能在任意Node版本、模块模式或安全沙箱内运行。

### 6.5 从目标平台倒推接口，而不让目标语言定义人类意图

最初目标选择TypeScript可以显著降低工作量，但不能默认为Gift精确整数=JS number、Gift对象身份=JS引用、所有计算都允许抛异常、所有异步都无取消。目标后端应声明可表示的类型、效果和错误模型，不支持时采用有根据的实现策略或返回明确缺项。

**2026版特别提醒：**微软已发布TypeScript 7.0原生编译器；官方在发布说明中明确7.0没有旧式程序化Compiler API，预计7.1提供不同新API，见[官方公告](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/)。TS6及以前的[Compiler API](https://github.com/microsoft/TypeScript/wiki/Using-the-Compiler-API)仍有学习价值。Gift应隔离适配边界，不假设长期可直接复用旧`ts.factory`或`Program`接口在TS7主包中不变。

**练习：**编译给定`fn add(x:Int,y:Int)->Int=x+y;`。检查TS目标类型、精确整数、函数公开性、调用次数、参数作用域；让`foo`调用尚在后面声明的`bar`；确保从源码到运行结果能够复算。

## 7. 如何判断优化真的正确

优化不是“性能听起来更好就可以做”。它要保存一项明确的可观察性质。比如常量折叠：`2n+3n→5n`在精确整数、没有特殊可观察效果的条件下通常可行；如果源采用固定宽度溢出异常，前提就不同。

**公共子表达式消除（CSE）**：把重复`pure(x)`计算一次可能安全；把两次`random()`、`readClock()`或`nextIterator()`合并通常不安全。**死代码消除（DCE）**：删除没有使用的纯计算可行；删除没有使用结果但执行写文件的调用不行。**循环不变量外提**：把循环内调用移到外面，要核入参是否变化、调用是否有副作用及可否改变执行次数。**内联**：要保留词法绑定、递归限制、求值次数、返回/异常和调试边界。

优化可以使用**重写规则（rewrite）**，但规则应声明模式、前提、保持性质和适用目标。对浮点数，即便数学上的加法交换/结合成立，机器运算也未必可在所有舍入与NaN条件下安全重排。完整程序等价通常不可判定，不能把“没有找到差异”写成形式证明。

**抽象解释（abstract interpretation）**：通过保守抽象域（例如变量可能值范围、可达状态集合）推导程序性质。抽象精度不足时返回“不足以证明”，而不是假定安全。它可以帮助检查溢出、边界与无用分支，但其分析方法不能改变原被分析程序的含义。

**基准对照：**对一个pass先跑类型检查、已有语义回归和专项反例；在受支持范围内可用解释器对优化前后程序做差分。跑1000个样例相同并不等于一般等价，但比只检查编译成功更有价值。

## 8. 增量编译：为什么可以一改就快，而不需要全局重算

### 8.1 编译是一组依赖查询

设`parse(file)`取得AST、`resolve(module)`取得符号、`typecheck(function)`取得有型函数、`emit(function,target)`生成目标。每项应主要由已固定输入和真正读取的其他查询决定。改变一个函数的内部纯表达式，若没有修改其公开签名，其他函数可能只需验证其所依赖的接口仍然一致，不必重做全仓所有工作。

但“文件没变”并非充分条件：被导入库版本、类型声明、编译选项、目标、解释语义或隐含环境改变，也可能使缓存失效。要识别**内容变化**与**语义相关变化**的区别。

Salsa的[官方增量计算概览](https://salsa-rs.github.io/salsa/overview.html)展示了输入、tracked函数、缓存和依赖重验。它的red-green算法用于判断某些上游变化是否真的改变了消费者依赖结果。[算法说明](https://salsa-rs.github.io/salsa/reference/algorithm.html)

### 8.2 正依赖、负依赖和集合依赖

`f`调用`g`是显式正依赖。代码做“查找所有匹配名字x的定义，然后确认只有一个”，还依赖**没有另一个同名声明**；新增一个声明也会让先前成功的“唯一性”结论失效。这是负依赖/集合完整性依赖。只记录已命中的节点，缓存将错误。

同样：“选出最低成本提供者”依赖被搜索候选范围，新增候选可能改变最优性；但若用户明确锁定某个已经合格的实现，候选目录变化不一定使当前编译失败。具体失效语义与查询目的有关。

### 8.3 性能正确性

缓存键应包含实际语义输入，包括语言版本、目标、正确需要的选项、库解释、可见源修订等；不必把无关展示设置、整个研究目录或所有历史记录拼进每次编译缓存键。增量算法自身也有CPU、内存、序列化、查找与失效传播成本，不能只报告更新了50个节点就宣称总体加速100倍。

**练习：**给一个两文件程序分别修改函数体、函数签名、依赖版本、仅修改注释、修改全局编译目标，记录哪些查询应该无条件重算、哪些可复用、哪些必须依据精确源保全条件判断。

## 9. 模块、库、编译、链接和运行不是一回事

模块系统负责名字、可见性、导入、导出、包与初始化。编译器构造合法程序并产生制品；链接器或目标模块解析将多个独立产物的符号/依赖连接；加载器决定实际运行时怎样取得模块；运行引擎处理值、异常、文件、网络和线程。

现代JS/TS工程还有打包、转译、摇树优化、动态导入、环境变量注入和原生扩展。`tsc --noEmit`的类型检查成功并不证明运行所需模块存在；`bun build`产物生成并不证明某个数据库服务器可达。插件列在Registry里也不代表它已安装、可用、合规、取得了目标权限。

**应精通的边界：**编译时符号、目标文件、原生包、系统库、运行环境、依赖锁定、ABI、FFI、错误/取消、平台差异。ABI不仅是输入输出类型名，还包含内存布局、调用约定、对齐、生命周期和错误/资源释放。

新领域开发可以通过三个途径进入Gift：用已有表达式/类型定义新函数；复用真实库及其签名/效果/许可证；确需新语义时提供领域操作及有型lowering。不要为了复用一个成熟JSON库重新实现JSON解析器；也不要因为接口写了`read`就误以为取得了真实文件访问权限。

## 10. 工程系统：怎样让编译器成为能长期维护的软件

### 10.1 操作系统与构建

熟悉文件路径与符号链接、权限、写入原子性、进程生成、锁、文件描述符、标准流、退出码、取消信号、超时、工作目录、环境变量、编码与换行。跨Windows/WSL需核路径、大小写、权限、挂载性能与代理；不因网络可Ping就宣布HTTPS、代理和目标认证有效。

构建系统应从真实输入图产生制品：源码、依赖锁、编译器版本、目标选项和必要外部资产均可影响输出。可重现构建需固定实际被消费的输入，控制时间戳、随机数、绝对路径、网络、隐式生成脚本和环境读取。内容寻址可以帮助复用，但“摘要相同”不证明语义等义，尤其在改变了解释规则或外部环境时。

### 10.2 软件架构与真实责任边界

重点学习模块边界、依赖倒置、单一维护责任、接口契约、分层与六边形架构、数据流与控制流、插件系统及生命周期。**不能因为文件很多就断言架构差，也不能因为把所有类装到一个`Kernel`就叫统一。** 一个模块应有稳定的责任、可替换实现和实际消费者。

通用编译器可以区分：前端解码/绑定、语义检查、变换/优化、目标后端、工作区应用、宿主执行与工具接入。这是行为责任划分，不要求每项成为独立服务。编译期间纯计算应尽量保持纯；读取文件/运行程序/发布工件由拥有实际权限的外层负责。

### 10.3 测试策略与故障模型

**单元测试**验证一个有限函数；**集成测试**验证多个部件边界；**端到端测试**验证真实输入到真实产物；**差分测试**让独立实现对同一输入比较；**性质测试**基于通用不变量生成输入；**变形测试（metamorphic testing）**检验应当保持的变换，如重命名保义、格式变更不改义。

还需要错误路径：无效Token、重名、缺变量、类型不符、递归不终止、模块循环、目标类型不支持、源文件中途变化、输出文件写失败、测试超时、取消及后继恢复。不可重现的测试绿灯不是足够的交付证据；必须保留版本、输入、命令、输出和测试覆盖范围。

**编译器尤其需要正反见证**：即使`>=`改`>`后结果差异只有等于阈值的边界，那个边界也可能恰是唯一能区分两种语义的样本。别只测大量随机非边界输入。

### 10.4 安全边界

解析外部源码不等于执行源码。AST构建、getter、动态插件发现、宏、postinstall、构建脚本和动态import具有不同执行风险。对不受信数据，应限制实际字节大小、递归深度、节点数、整数长度、CPU时间和内存；单靠“解释步数预算”不是完整隔离沙箱。拒绝注入拼接、路径穿越、权限提升、秘密泄露、非预期网络访问。

源码生成目标可能是恶意指令载体；Gift不能把“可编译”当成“安全”。代码签名证明作者或密钥对字节负责，不自动证明语义、正确性、许可证、现实真实性或权限。

### 10.5 数据存储、数据库与可追溯性

理解关系模型、主键/外键、唯一约束、事务/隔离级别、索引、MVCC、日志、迁移、备份、恢复和幂等。研究知识条目、作者源、生成物、版本、证据和缓存可能都要保存，但**它们的写权和删除条件不同**。一张万能图表不是“所有真实内容已经统一”的证明。引用定位与实体本身、事实声明与实际事实、缓存与作者原始输入应分别保存身份。

示例：从作者源A推导生成源码T可以记录`generatedFrom(T,A@rev)`；这是生成过程及依赖关系，不表示T能反向唯一恢复A。一个IR节点有两个引用不必产生两份运行状态；两份来源恰好内容相同也不意味着是同一观察。

### 10.6 AI协作的定位

AI善于提出候选解析、写实现、补测试和解释错误，但可能捏造目标接口、依赖版本、语义前提和已执行结果。正确系统应让AI提交可追溯的作者源候选与明确的未决事项；编译器用固定规则解析、检查与生成。人工及AI“应该如此”的偏好与已采用硬要求分开。

**最重要的分界：创作可以不确定，重新编译必须确定。** 同一已接受源、工具版本、依赖和目标输入应尽可能由确定过程重建，不能每次都重新询问模型“这个业务应该什么意思”。

## 11. 语义与形式方法：提高正确性，但不让它堵住普通编译

### 11.1 程序规格与实现的区分

对于纯函数，可以用输入输出关系表示要求：`∀x∈D, result=f(x)`；对于有状态程序，需要前态/后态/错误/外部效果；对于交互系统，还需完整轨迹、可用信息、选择者和进展。所谓“合格实现集合”是**实现的集合**，不是一个布尔查询结果，也不是所有行为集合本身。

例如，`sort`“返回的每个元素都来自输入”不足以保证排序；还需保留输入元素出现次数（bag）、排序顺序及异常处理。只用Set相等会错误吞掉重复元素。这是形式化为什么有价值的直接例子。

### 11.2 Hoare逻辑与循环不变量

Hoare三元组`{P} C {Q}`一般描述：若初始满足P，命令C正常终止，则终态满足Q；不带终止证明时通常只保证部分正确性。要保证总正确性还须证明终止（或采用明确的非终止行为规格）。对不变量的证明既要说明每一步保持，也要说明初始化与退出条件。

**不要把“空程序什么也不做”默认当作满足所有要求。** 某要求有进展、可用性或真实输出义务，即使安全不变量全都保持，永不响应仍可能不合格。

### 11.3 精化（refinement）不是等义

高层规格可以允许多个算法，具体实现选其中一个，通常是收窄实现自由而非完整双向等价。举例：要求`sort`结果递增且保重，快速排序与归并排序都可能合格，不要求每个内部步骤或内存行为相同。但若公开规定稳定排序或内存上限，那么具体算法必须继续满足。

Target lowering需要解释从源观察到目标观察的映射：值的精度、公开API、错误、事件、时间、性能/资源与生命周期应按已接受的合同保留。部分正确性证明不能被高层“保义”二字放大为全工程安全结论。

### 11.4 效果、线性资源与所有权

普通纯函数对相同输入给相同值，便于缓存和自由重排；有效果的调用需要保存调用发生和顺序。效果类型可以表达某函数可能读取网络或写文件，但“声明可能有网络效果”不是实际已取得网络权限。**线性/仿射资源**限制可复制、可丢弃或转移的方式；把两个独占资源引用当可复制普通值是语义错误。

Rust的借用检查提供强有用的例子，但Gift的第一版不必自己重写Rust的全套借用系统。若目标为TypeScript，可以复用其类型检查，再在Gift真正承诺的资源场景增补必要的特殊约束。

### 11.5 概率、时间、因果、规范的专业边界

概率需要明确定义联合分布、条件、随机变量与独立性；同一随机事件出现两次不能直接概率相乘。时间模型需要时钟、观察时点、事件发生时点、持续与顺序；任意外界时间精度不来自代码标签。因果涉及干预和反事实模型，不能由统计相关边直接推出。规范涉及主体、签发权限、适用范围、例外与效力；模型内部`allowed=true`不是宿主真实Grant。

这些是世界语义体系未来的重要专业机制。**普通`x+1`函数不应先通过概率、规范、授权、来源签名和多维证成流程才能编译。** 按需调用专业语义，同时在确实承诺跨专业性质时验证真实组合。

### 11.6 不确定性必须保留其原因

至少区分：语法不合法、名称未绑定、类型错误、语义尚未解释、模型未给、方法未找到、证明未知、已证不满足、目标不支持、权限禁止、运行未执行、证据过期。所有这些都输出“false”将误导开发者；全部都叫“unknown”又会让系统无法修复。诊断应引用准确的源位置、相交阶段和可行动原因，但不要求每次产生全球审计档案。

## 12. 打开世界语义：如何统一而不制造万能解释器

### 12.1 世界不是一张固定维度表

对象、关系、过程、事件、时间、知识、理论、规范、软件和数值可以通过**有型定义及明确解释**接入。18域、136组、568个查询合同用于查看已有内容，不是物理宇宙的独立坐标。一个维度可问“这个对象属于哪类”，其答案可能多值；另一维度问“何时发生”，答案是时间；某专业模型有自己的数学维数，不能与问题个数混计。

**族**可以是概念家族、问题家族、机制家族或理论家族，不必是一维。属性有时是函数，分类通常是谓词，机制可能是状态转移、概率核、微分方程或规范规则；它们有共享的形成/引用/解释责任，但没有必然相同的值类型。

### 12.2 统一的是接口和保持条件

准确语义模块至少提供它在当前用途下真正消费的：签名、类型/角色、作用域、定义或模型、使用/观察条件、版本与有效范围；有条件变换提供保持命题与验证方法。模块不能只写`meaningRef`并宣称有意义。多个模型可能同样满足同一公理，不能私选唯一模型当真值。

**模型链接**需要真实映射：某一领域的金额与另一领域的资源数量不因两个字段都叫`Amount`就可以直接相加。单位、计量、时点、粒度、权利和对象身份必须取得准确桥。映射可能是等义、保守嵌入、信息损失、实现精化或模型近似，各自保留不同性质。

### 12.3 抽象的判断标准

真正有价值的抽象让不同问题共享同一形成/推导方法，减少重复作者工作，同时不丢独立差别。例如，函数调用、关系应用和组件实例化有共同的参数角色绑定，但不是同一种运行：函数可能求值与抛错，关系只是关于域的成立条件，组件会创建独立的运行状态。若强行合并成`invoke(anything)`，反而需要各处隐式业务分支恢复原区别。

**判断一个新原语是否必要的反例法：**给出两个在现有模型中不可区分、但应有不同合法行为的程序；若已有类型/参数/控制能够区分，先复用已有结构；若确实缺少独立语义，则扩相应公共规则与真实消费者。不要让“添加一个族名称”成为语言扩展的理由。

## 13. Gift架构：如何把上述知识落实到当前工程

### 13.1 已有仓库与研究原型的真实状态

以2026-11-05核对的`sec-platform/sec`当前公开`main@7e70f411`为底：`src/compiler/semantic-compiler.ts`把已捕获工程输入构成验证后的Engineering IR、生成计划与语义视图；`src/compiler/ir/build-engineering-ir.ts`登记App/Block/Capability/Port及关系事实；`src/semantics/definitions/types.ts`拥有部分实体/状态/操作/效果合同；`src/semantics/generation/types.ts`登记的生成种类仅`generate-state-transition-map`。这些是现有工程的真实结构，不能直接断言它们已经支持通用计算源码创作。

设计分支`codex/design-closure-20261023`已有较完整第一层作者语言、通用定义、源码控制、实现选择和Target保持合同。**设计成熟度与可运行生产闭环是两回事。** 定时研究原型具备有限解释、关系代数、来源和检查等能力，但未因此进入正式仓库作为生产通用编译器。

### 13.2 保持原owner，补真实编译消费者

适合的推进路径不是建立第二套`UniversalGraphIR`，也不是让568项问题目录驱动函数编译，而是让原作者`Definition/Meaning/Type/Expr/Use`取得可用的源入口与类型检查；必要时形成供Target使用的有型计算表示。具体目标输出交给受信后端。有效作者内容与编译器推导的视图分开，现有Engineering IR继续承担它准确拥有的工程信息，而不冒充万能计算AST。

一个实际工作流：

```text
读取 Gift 模块作者源（精确byte/revision）
    ↓ 词法/语法，产生 AST（保留源坐标）
绑定声明/导入/函数局部变量（精确声明身份）
    ↓ 形成有型AST，检查纯计算或相应效果
若目标需要，降低控制流/求值到合适IR
    ↓ 正确选择实现及目标表示
Emitter生成TypeScript完整合法文件与导入
    ↓ 使用目标TS工具真实检查、构建、运行
记录来源映射；局部修改后重算真实依赖
```

对纯表达式直接修改，通常仅改AST运算符、重查类型、重生受影响源和必要测试。对公共API变化，需查实际调用方及兼容。对数据库交易，需额外检查事务、效果、幂等、恢复。**成本与真实风险决定需要哪条分析路径，而不是“每项开发都走所有流程”。**

### 13.3 第一个真正有用的支持范围

一个含函数声明、名字、参数与返回类型、常量、二元运算、if、调用和模块引用的语言足以实现可检验的通用表达式闭环；随后扩函数局部变量、循环/递归、记录/数组、泛型、模式匹配、异常、模块与库，再扩状态和效果。这个顺序是依赖导向，不宣称这些功能构成Gift最终全部语言。

每增加一个新构造要同时考虑其解析、绑定、类型、解释、转换、目标、诊断和回源路径；但是**不要求每次都增加一个全世界查询维度或语义分类标签**。

### 13.4 不重造成熟技术

TS目标可直接消费当前正式TypeScript编译器命令行做类型检查/构建；若使用程序化旧TypeScript API，需明确隔离TS6及以前的API变化；TS7.0原生实现没有相同公开程序化API。Bun可用于运行与转译，不能代替完整类型分析。若以后需要低级机器码，可研究LLVM；若需多专业高层IR/方言和分层降低，可借MLIR的操作/类型/接口思想，但引入其整个C++生态需有明确收益。官方文档：[LLVM Kaleidoscope](https://llvm.org/docs/tutorial/index.html)、[MLIR](https://mlir.llvm.org/docs/)、[Rust编译器开发指南](https://rustc-dev-guide.rust-lang.org/overview.html)。

## 14. 具体路线：用有产物的能力验收推进，而不是按页面数学习

| 阶段 | 必须真正做出来的能力 | 反例与验收 |
|---|---|---|
| P0 程序与运行 | TS函数、模块、类型、闭包与异步；可操作Git与Node/Bun | 不会把静态检查当执行，不会混淆对象与绑定 |
| P1 词法与语法 | 可解析新函数和复杂表达式，保存Token/AST坐标 | 非法字符/括号/优先级/一元二元操作失败准确 |
| P2 绑定与类型 | 多函数、前向声明、作用域和类型错误，能解释为什么错误 | 重名、自由变量、捕获、参数数量、返回类型 |
| P3 有型运行语义 | 简单解释器与目标代码在相同输入得相同结果 | Int/BigInt、Bool、if惰性分支、错误语义 |
| P4 可用后端 | 生成完整TS文件，通过真实TS检查与Node运行 | 新函数无需新业务生成器，目标不支持给明确诊断 |
| P5 后继修改 | 修改函数体及共享定义，准确重算依赖与测试 | >=改>只动实际相关对象，公共签名更改影响消费者 |
| P6 可组合程序 | 局部变量、循环、递归、函数值、记录/列表、模块 | 作用域卫生、终止/发散、重复发生与状态共享 |
| P7 状态与效果 | 实际资源、错误、异步或数据操作的可用程序 | 不把重复读取合并、不把效果删掉、取消可恢复 |
| P8 多目标/实际工程 | 导入、外部库、完整目标根、资产、配置、错误与测试 | 生成源不是空壳，合法输入可真实调用，失败出口正确 |
| P9 工程稳定性 | 增量查询、源码映射、回源、缓存、并发与重建 | 新候选、负依赖、旧实例、源冲突和回滚准确 |
| P10 世界/意图层 | 专业规则、事实与证据、决策委派、跨域语义 | 普通函数仍快，复杂语义确需时才加载合格解释 |

这不是“完成P10后才可以学习P0”。一旦达到P4，就能交付一个真实的编译原型；其后用真实消费者带动扩展。阶段编号不代表固定软件包层数。

## 15. 你不应该先投入大量时间精通的内容

不需要先重写LLVM优化器、TS类型检查器、Node事件循环、操作系统内核或Git对象存储；不需要先建立全部世界本体，形式化1,786段自然语言，或者把568项查询全部实现成求解器。无生产使用需求时，也不必先建立完整的分布式事务系统、零知识证明、定理证明器、通用模型检验器、宇宙万物知识图谱。

这不是说这些内容无价值，而是说 **Gift第一项必须兑现的独立能力是用户自己创作的程序能够被正确编译，且新语言构造可以通过真实规则增长**。当后续功能确实需要更强能力，再学习该专业的精确前提并接入现成方法。
