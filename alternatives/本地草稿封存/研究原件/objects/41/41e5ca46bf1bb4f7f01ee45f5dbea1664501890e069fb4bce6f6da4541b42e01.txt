# Gift 编译器精通·第二讲：从AST到运行行为，建立可验证的编译正确性

日期：2026-11-05。承接《Gift_编译器精通_知识手册_20261105.md》章节5–8。附带的 `Gift_编译器精通_学习实验室` 是独立教育用小语言和测试，不是 `sec-platform/sec` 正式编译器。

## 一、同一程序怎样通过五种形态

源：

```text
fn eligible(score: Int, threshold: Int) -> Bool = score >= threshold;
```

词法：`fn`、`eligible`、`(`、`score`、`:`、`Int`、`,`、`threshold`、`:`、`Int`、`)`、`->`、`Bool`、`=`、`score`、`>=`、`threshold`、`;`。

语法树：

```text
Function eligible
  parameters score:Int, threshold:Int
  returnType Bool
  body Binary(>=)
    left  Variable(score)
    right Variable(threshold)
```

绑定后的表达式理论上还要保存 `Ref(score)→parameter#0`、`Ref(threshold)→parameter#1`。教学版分析器使用当前函数的参数 `Map` 进行静态核验，尚未在节点上持久保存显式符号ID；这是下一阶段应补齐的基础。

类型规则：`
Γ(score)=Int, Γ(threshold)=Int`，整数比较要求两边为`Int`，结果为`Bool`；函数声明返回`Bool`，所以合法。

目标TypeScript：

```ts
export function eligible(score: bigint, threshold: bigint): boolean {
  return (score >= threshold);
}
```

执行：调用 `eligible(5n,5n)` 产生`true`；如果作者把 `>=` 改为 `>`，同样输入产生`false`。对一次局部纯表达式更改而言，不需要执行目录搜索、568维查询或世界事实审查。

## 二、一个程序的意义是什么

“表达式的意义”在支持的纯函数片段中，可以使用大步求值判断来定义：

`⟨e,ρ⟩ ⇓ v`。

`ρ`（环境）为变量提供值，`e`为表达式，`v`是求得的值。它不只是编译器中的JS对象，而是一份对语言行为的明确规定。

规则示例：

- 字面量：`⟨42,ρ⟩⇓42`。
- 变量：如果`ρ(x)=7`，则`⟨x,ρ⟩⇓7`。
- 整数加法：子式依源语言规定的求值顺序取得`a`,`b`，结果为精确整数`a+b`。
- 比较：在整数上使用该语言声明的序关系，结果为Bool。
- 条件：先求条件；若为真只计算then分支，否则只计算else分支。
- 函数调用：先确定函数定义和传参规则，再以新词法环境计算函数体；同名形参每次调用拥有相应动态值，而不是从全局变量表偷读。
- 与/或：纯布尔逻辑对完整结果满足对应真值表；若求值可能不终止，短路顺序也成为可观察行为。例如`false && infinite()`必须能够返回false，不去计算右边。

这个定义目前只覆盖`Int`、`Bool`、函数、条件与运算，尚未覆盖可变内存、异常、随机、异步、资源所有权。后者不能悄悄继承当前的纯函数解释。

## 三、为什么编译器不能只有一个AST和一个打印函数

真正的编译器至少同时面对以下四类不同性质：

1. **语法合法性**：Token能否组成有效程序；`(`无`)`属于此类。
2. **绑定合法性**：每个变量和函数引用是否定位到声明；`return missing`属于此类。
3. **类型合法性**：算子和调用是否按规定类型使用；`1 + true`属于此类。
4. **行为保持**：生成代码是否按源语言执行；`if true then 1 else loop()`不能变成提前执行loop。

前3项检查通过，不足以证明第4项。例如一个不正确的Emitter可能把`x-y`打印为`y-x`，其目标TS仍然完全通过类型检查，但意义已改变。

同样，源类型为`Int`并不自动意味着目标使用`number`：JS `number`无法精确保存每一个整数。教学编译器选择了`bigint`，使支持范围内的整数加减乘和比较有精确的目标对应。

## 四、从语义推导“允许转换什么”

设 `Emit(A)` 生成目标TS；设 `E_Gift(A,args)` 为直接按Gift片段解释的结果，`E_JS(Emit(A),args')` 为目标JavaScript的执行结果。一个理想的保持声明是：

`encode(E_Gift(A,args)) = E_JS(Emit(A), encode(args))`

但它的使用前提必须明确：

- `A`通过相应解析、绑定和类型检查；
- 所用程序构造的源/目标解释已经匹配；
- 函数及输入域受支持，目标模块正确构建；
- 被比较的运行正常终止，或另行定义两边的发散/错误保持；
- 源和目标的整数、布尔、求值顺序及公共入口对应；
- 当前教学生成器不能普遍处理所有JavaScript保留字或作用域卫生，生产后端需专门解决目标标识符的编码与捕获；
- 目标运行时及外部环境不会暗中更改相关规则。

**证明思路**：对有型表达式结构归纳。字面量由BigInt编码保值；变量按同一环境对应；函数调用以相应参数环境计算函数体；整数算子和比较使用明确对应的目标原语；条件及短路只求同一个被选分支。因此，在这些局部构造及终止前提下逐步取得相同结果。递归调用自身不会无限展开源码，其正确性还依赖于相应递归语义/有限求值证明；不能从“AST有有限节点”推出函数一定终止。正式全语言证明需要覆盖模块、错误、效果、存储和其他未实现构造。

## 五、为什么加入独立解释器

如果只测试编译出的TS，你最多知道它在选定输入上能执行，却不知道它有没有忠实表达原Gift程序。因而加入另一条独立的路径：

```text
同一份Gift源
   ├── Parser → AST → Analyze → AST解释器 → 实际结果A
   └── Parser → AST → Analyze → TypeScript → tsc → Node → 实际结果B

对同样参数，比较A与B。
```

两条路径共享Parser和类型分析，因此不是完整独立证明；但独立的执行器能够发现目标打印或目标值表示中的大量错误。例如把 `x-y` 错写成 `y-x` 时，类型检查可能仍绿，差分运行能在`x≠y`时发现差别。

**本次验证**：扩充前20项测试；新增12项AST解释器与语义专项测试，全部32项通过。`node tools/compare.mjs examples/calc.gift`以真正的`tsc`生成JavaScript，再用Node执行，11组精心选择的输入全部与AST解释器相等。包括`9007199254740993n`高精度边界、`x=threshold`比较边界、两个函数组合与前向调用。

结果是**可重复的有限测试**，不是无限输入上的形式证明。测试使用当前环境 `node v22.16.0` 和本机 `tsc 5.8.3`。截至2026-11-05 TypeScript 7.0已正式发布，7.1仍为beta；演示使用本机既有tsc，不宣称本轮在TS7上测试。官方7.0发布说明强调其没有旧式程序化API，目标适配要单独维护：[TypeScript 7.0](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/)。

## 六、为什么递归编译很简单，递归运行可能很复杂

代码：

```text
fn fact(n: Int) -> Int = if n <= 1 then 1 else n * fact(n - 1);
```

编译器只需要在符号表里确认`fact: Int→Int`已经存在；函数体中的调用保留这个引用，生成`fact(n-1n)`即可。它不需要在编译时把递归全部展开。

真正求值时，`fact(6)=720`，每次调用创建新的参数环境。`fn loop() -> Int = loop();`同样可以是类型合法的程序，却没有返回值。**类型正确不等于终止。** 教学AST解释器允许设置调用深度和求值步数上限，耗尽时返回明确异常，不把它当`false`或数学无解。目标Node上同样可能出现运行栈耗尽。

## 七、如何正确扩大成通用语言

下一批不是添加银行、商城或温控箱业务关键字，而是按形成规律扩充：

- **声明/变量**：局部`let`与嵌套作用域，赋值与不可变绑定的区别。
- **函数值与闭包**：函数可以作为值传递，捕获与调用按词法环境解释。
- **结构数据**：record、tuple、array、variant及其构造、访问与模式匹配；名义/结构类型有不同合同。
- **控制与递归**：完整语句、循环、提前return、异常和递归，必要时建立CFG和基本块。
- **模块**：独立文件、导入导出、版本、签名及初始化行为。
- **效果和状态**：共享/复制、读写、调用顺序、错误/取消、资源所有权，严格区别纯计算。
- **目标表示**：安全标识符命名、BigInt/Bool映射、源码映射、合法目标打印、模块格式与运行依赖。
- **工程闭环**：一次编译、目标测试、相关函数重新编译、源码精确回写和旧运行实例保留。

每一扩展必须以真实的新程序、正反例、编译生成与目标执行取得资格；不能只在类型列表里多加字符串。

## 八、可操作的学习顺序

在实验室执行：

```bash
node --test tests/test.mjs tests/interpreter.test.mjs
node tools/trace.mjs examples/calc.gift eligible 5 5
node tools/compare.mjs examples/calc.gift
```

随后完成：

1. 把 `>=` 改成 `>`，指出Token、AST、绑定、类型与生成代码分别哪些改变，哪些保持。
2. 写 `fn f(x:Int)->Int = 1 + x*2;`，绘制AST，并解释为什么目标得到`1n+(x*2n)`。
3. 写 `fn f(x:Bool)->Int = x+1;`，确认它在类型检查阶段而非运行阶段拒绝。
4. 写 `fn g()->Int = if true then 1 else loop();`，说明为什么没选中的分支不能执行，测试一个递归loop。
5. 写阶乘函数，在直接解释与目标运行中比较不同正整数，解释为什么某次通过不足以证明全部递归终止。
6. 试着用源语言命名一个函数为`class`，观察目标Emitter可能失败，设计独立的目标名字编码和绑定映射。该问题与“世界语义维度”无关，是实际目标正确性的普遍机制。
