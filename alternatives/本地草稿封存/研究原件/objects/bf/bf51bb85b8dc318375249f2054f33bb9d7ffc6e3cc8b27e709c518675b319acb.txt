# Gift 通用关系持续维护版：使用与继续推进

## 直接使用

解压后双击 `启动工作台.cmd`，或运行 `python launch.py`。只需Python 3.10+和标准库，无联网依赖。直接打开HTML仅作离线阅读，实际计算需要本地服务。

在“完整工程源”导入 `projects/six_interpretations_v2.json`，预览并明确采用。将`same_plan_count`调用的R源第一行注解2改成5，再预览：结果由10变为19；界面的“变更计算依据”列出各方法走完整计算、重建还是维护、哪些源绑定和结果绑定改变。

其他五项调用输入未改，语义值不会被改写。丢弃预览不会采用新源；确认后可回看旧修订，得到10。导出独立快照仍可单独`python run.py`重新完整计算。

也可以直接运行：

```sh
python tools/run_maintenance_demo.py
python tools/check_maintenance.py
```

前者输出撤回、替代支持、同时两端插入及有限工作量的实际结果；后者重新执行新检查、旧回归、原件保全和演示。浏览器核对单独运行`python tools/check_maintenance_browser.py`，需要Playwright和Chromium；它们不是使用成品的依赖。

## 当前操作能力

用户改变的是准确信息源，不直接修改缓存。缓存/索引可随时重建，结果包含新源身份。增量计算只在已证明适用的有限正关系合同内使用；原模型、解释、计划、角色或载体变化时回退完整计算，并显示原因。

本机程序不是持续在后台自改项目的Agent。另设的ChatGPT定时任务每小时推进研究和成品；它与本工作台运行进程不同，也不自动采用用户的模型修改。

## 下轮延续文件

本版产物：`Gift_通用关系_持续维护整合版.zip`。原件记录：`baseline_incremental/input_manifest.json`；变更前像：`baseline_incremental/original/`；检查结果：`verification_incremental/`。

不要把下一轮缩成维护更多测试或界面。整体目标仍是：最通用的有类型关系、准确专业解释、共同组合、保义投影、合法控制与可持续修改。当前五个构造的维护已经有一般书面论证与六解释实测，不需要为新业务名再复制实现。

可以继续检验的实质未闭合面包括：不同已安装方法之间的准确类型化配线与共同前提；规律的适用画像与专业桥；非单调关系、递归和资源效果的真实解释。必须先核最新实际成品，选择有独立价值的一整族机制；不要仅为了有新数目加维度、加条目、再发明一份全局核心。新结构先承担明确的生成和使用，不将资料登记当语义实现。

未经用户额外授权不改GitHub、不写持久Library、不执行现场动作。定时结果仍需给出实际文件及准确边界，不承诺常驻无间断计算。
