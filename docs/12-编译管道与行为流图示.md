# 编译管道与行为流图示

> 目标：提供 SpecEngineer 编译器各命令管道、五大 Stitching Pass 以及验证（Verify）流程的直观图示，减小开发者与 AI 的心智负担。

> **代码生成约束（v0.2.x 末段起）**：compose 层所有生成 `.ts`/`.tsx` 源码的子节点（RPC route / RPC client / route graph / slot skeleton 等）均由 `CodeBuilder`（LLVM IRBuilder 风格）程序化构造，详见 `05` §9.10。下方图示中的"代码生成"节点默认指向 `CodeBuilder`，不再画大段模板字符串拼接路径。

## 1. 编译器生命周期主管道 (Compiler Command Pipeline)

下图展示了从声明式的 `source/app.yaml` 规格输入，到最终在 `project/` 生成物理运行项目的完整编译与验证流程：

```mermaid
graph TD
    %% Define styles
    classDef sourceStyle fill:#e6f7ff,stroke:#1890ff,stroke-width:2px;
    classDef controlStyle fill:#f6ffed,stroke:#52c41a,stroke-width:2px;
    classDef targetStyle fill:#fff7e6,stroke:#ffa940,stroke-width:2px;
    classDef cmdStyle fill:#f9f0ff,stroke:#722ed1,stroke-width:2px;

    %% Source Files
    SrcPlan["source/app.yaml <br>(应用规格声明)"]:::sourceStyle
    SrcCustom["source/code/slots/**<br>source/custom/**<br>(自定义逻辑与管脚实现)"]:::sourceStyle

    %% CLI Commands
    CmdResolve["1. sec resolve<br>(解析依赖/生成 Slot 任务)"]:::cmdStyle
    CmdCompose["2. sec compose<br>(执行装配与五大缝合 Pass)"]:::cmdStyle
    CmdAdapt["3. sec adapt<br>(注入 Slot 与自定义代码)"]:::cmdStyle
    CmdVerify["4. sec verify<br>(只读漂移门禁与测试验证)"]:::cmdStyle
    CmdLockExplain["5. sec lock & explain<br>(锁定图状态并输出可视化)"]:::cmdStyle

    %% Control Plane & Target Artifacts
    StateLock["control/state/graph.lock.json<br>(图依赖锁定)"]:::controlStyle
    TargetProject["project/**<br>(生成的目标物理项目-只读)"]:::targetStyle
    Provenance["control/provenance/provenance.json<br>(防篡改哈希签名)"]:::controlStyle
    ExplainGraph["control/graph/explain-graph.json<br>(可视化依赖图谱)"]:::controlStyle
    Evidence["control/evidence/review-summary.json<br>(编译验证质量报告)"]:::controlStyle

    %% Flow
    SrcPlan --> CmdResolve
    CmdResolve --> StateLock
    StateLock --> CmdCompose
    
    CmdCompose --> TargetProject
    SrcCustom --> CmdAdapt
    
    TargetProject & SrcCustom --> CmdAdapt
    CmdAdapt --> Provenance
    
    Provenance & TargetProject --> CmdVerify
    CmdVerify --> Evidence
    
    Evidence --> CmdLockExplain
    CmdLockExplain --> ExplainGraph
```

## 2. Composer 缝合引擎五大 Pass 细节 (Composer Stitching Passes)

在 `sec compose` 阶段，除了直接的文件拷贝，编译器会执行 5 个增量缝合 Pass，将开发者的非结构化自定义代码无缝且安全地组织到生成的物理项目结构中：

```mermaid
graph TB
    classDef passStyle fill:#fff0f6,stroke:#eb2f96,stroke-width:2px;
    classDef fileStyle fill:#e6f7ff,stroke:#1890ff,stroke-width:1px;

    subgraph Composer ["Composer 物理合成过程"]
        direction TB
        Pass1["Pass 1: merge-prisma-template<br>(Prisma Schema 增量缝合)"]:::passStyle
        Pass2["Pass 2: install-opaque-modules<br>(不透明模块自动挂载)"]:::passStyle
        Pass3["Pass 3: merge-tailwind-theme<br>(Tailwind 样式与主题融合)"]:::passStyle
        Pass4["Pass 4: map-custom-routes<br>(路由映射与安全布局兜底)"]:::passStyle
        Pass5["Pass 5: format-output-files<br>(进程内 Prettier 并行格式化)"]:::passStyle

        Pass1 --> Pass2 --> Pass3 --> Pass4 --> Pass5
    end

    %% Inputs and Outputs for each pass
    InPrisma["source/schema/db.prisma.template"]:::fileStyle
    OutPrisma["project/prisma/schema.prisma<br>(执行 prisma db push)"]:::fileStyle
    InPrisma --> Pass1 --> OutPrisma

    InOpaque["source/code/opaque/**/module.yaml"]:::fileStyle
    OutOpaque["project/package.json<br>(本地 link / 生产物理复制)"]:::fileStyle
    InOpaque --> Pass2 --> OutOpaque

    InTailwind["source/assets/theme/tailwind.config.extend.json<br>globals.css"]:::fileStyle
    OutTailwind["project/tailwind.config.ts<br>project/src/app/globals.css"]:::fileStyle
    InTailwind --> Pass3 --> OutTailwind

    InRoutes["source/ui/routes/**<br>source/ui/layouts/dashboard-layout.tsx"]:::fileStyle
    OutRoutes["project/src/app/**<br>(缺失 layout 时自动套用全局布局)"]:::fileStyle
    InRoutes --> Pass4 --> OutRoutes
```

## 3. 验证与门禁执行流 (Verification & Gate Execution Flow)

在 `sec verify` 阶段，系统对生成项目进行极其严格的多重防御拦截，拦截任何未经平台允许的带外编辑行为，保障生成的物理项目不会发生退化：

```mermaid
flowchart TD
    classDef stepStyle fill:#f9f0ff,stroke:#722ed1,stroke-width:2px;
    classDef failStyle fill:#fff1f0,stroke:#f5222d,stroke-width:2px;
    classDef successStyle fill:#f6ffed,stroke:#52c41a,stroke-width:2px;

    Start(["开始 sec verify"]) --> StepDrift["1. 代码漂移检查 (check-drift)"]:::stepStyle
    
    StepDrift -- "检测到只读区修改" --> ErrDrift["抛出 ERROR-DRIFT-001<br>(强行中断编译)"]:::failStyle
    StepDrift -- "签名验证通过" --> StepTypecheck["2. TypeScript 类型检查 (typecheck)"]:::stepStyle
    
    StepTypecheck -- "类型报错" --> ErrType["编译中断"]:::failStyle
    StepTypecheck -- "无类型错误" --> StepTests["3. 运行测试套件 (tests)"]:::stepStyle
    
    StepTests -- "单元/集成/E2E 失败" --> ErrTest["测试失败中断"]:::failStyle
    StepTests -- "测试通过" --> StepPolicy["4. Policy Gate (合规审计)"]:::stepStyle
    
    StepPolicy -- "违规项 (Violation)" --> ErrPolicy["Policy 强行拦截"]:::failStyle
    StepPolicy -- "合规" --> Success(["验证成功 (Lock Graph & Emit)"]):::successStyle
```

## 4. 自定义代码（Overrides & Slots）管脚挂载流

自定义代码通过声明式的 Override 规则被映射在编译产物的物理 Slot 位置。以下是注入与哈希签名追踪流：

```mermaid
graph LR
    classDef sourceStyle fill:#e6f7ff,stroke:#1890ff,stroke-width:2px;
    classDef manifestStyle fill:#fffbe6,stroke:#ffe58f,stroke-width:2px;
    classDef projectStyle fill:#fff7e6,stroke:#ffa940,stroke-width:2px;
    classDef provStyle fill:#f6ffed,stroke:#52c41a,stroke-width:2px;

    SrcCode["source/custom/customer_normalizer.ts<br>(开发者自定义源码)"]:::sourceStyle
    Manifest["override-manifest.yaml<br>(声明管脚挂载目标)"]:::manifestStyle
    
    CompilerAdapt["sec adapt<br>(编译器挂载)"]
    
    TargetCode["project/custom/customer_normalizer.ts<br>(目标物理 Slot-只读锁定)"]:::projectStyle
    Provenance["provenance.json<br>(文件哈希签名锁定)"]:::provStyle

    SrcCode --> CompilerAdapt
    Manifest --> CompilerAdapt
    CompilerAdapt --> TargetCode
    CompilerAdapt --> Provenance
```
