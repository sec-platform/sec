# 编译管道与行为流图示

本文只提供当前目标架构的数据流图。字段和状态以对应实现规范为准。

## 1. 总体编译链

```mermaid
flowchart TD
  A[Authoring Source\napp/model/code/patch/private block] --> P[Parse]
  R[Registry\nmanifest/contracts/generators/files/tests] --> P
  P --> N[Normalize]
  N --> AL[Align]
  AL --> RE[Resolve]
  RE --> L[Resolution Lock]
  RE --> IR[Build Engineering IR]
  L --> IR
  IR --> LOW[Lower / Generator Plan]
  L --> C[Compatibility Compose]
  LOW --> C
  C --> AD[Adapt / Bounded Synthesis]
  AD --> V[Verify]
  V -->|failed & repairable| RP[Repair]
  RP --> V
  V -->|accepted| LK[Lock Accepted State]
  LK --> E[Emit Governance Artifacts]
  IR --> E
  E --> PR[Explain / Review / Semantic View Projections]
```

`Normalize`、正式 `build-ir` 与 IR-owned `lower` 已进入 v0.3 主链；文件装配继续兼容，但 Generator 不再由 resolve/raw Contract 旁路规划。

## 2. Canonical 与 Projection

```mermaid
flowchart LR
  S[Authoring Source] --> SF[Semantic Frontend]
  SF --> IR[Engineering IR]
  IR --> CP[Compiler Passes]
  CP --> ART[Project Artifacts]
  IR --> VG[Verification & Governance]
  ART --> VG

  IR --> PX[Projection Builders]
  VG --> PX
  PX --> EG[ExplainGraph]
  PX --> RS[ReviewSummary]
  PX --> SV[SemanticView]
  EG --> WB[Workbench / CLI / IDE]
  RS --> WB
  SV --> WB
```

约束：`ExplainGraph`、`ReviewSummary`、`SemanticView` 都不能反向成为 canonical semantic source。

## 3. AI 执行链

```mermaid
flowchart TD
  IR[Engineering IR] --> TS[Task Selector]
  G[Governance / Policy / Verification] --> TS
  TS --> TE[Task Envelope]
  TE --> CTX[Context Packet Projection]
  EV[Optional Evidence Providers] --> CTX
  CTX --> AI[AI Operator]
  AI --> OUT[Source Patch or Semantic Mutation]
  OUT --> VAL[Trusted Authorization + Semantic Mutation Plan]
  VAL -->|reject| D[Diagnostic]
  VAL -->|ready| APPLY[Exclusive Lease + Re-plan + CAS]
  APPLY --> STG[Isolated Staging + Source Adapter]
  STG --> RB[Canonical Rebuild IR]
  RB --> FD[Actual Fact Delta + Impact]
  FD --> VER[Conservative Verification Union]
  VER -->|pass| CAS[Final Source CAS + Atomic Publish]
  CAS -->|accepted| ACC[Accept Revision]
  CAS -->|failure after publish| ROL[Verified Rollback or Recovery Required]
```

AI 永远不直接写 IR。

## 4. Semantic Mutation

本图只同步 `14` 第 18 节权威 transaction，不拥有字段或状态定义：

```mermaid
flowchart LR
  UI[Workbench or AI] --> REQ[Untrusted Request V2]
  AUTH[Platform Authorization] --> PLAN[Plan without Live Writes]
  IR0[Transaction-owned Base Snapshot] --> PLAN
  REQ --> PLAN
  PLAN -->|rejected| REJ[Rejected]
  PLAN -->|ready + Plan Revision| APPLY[Exclusive Lease + Recheck CAS]
  APPLY --> STG[Isolated Source Edit + Canonical Rebuild]
  STG --> DELTA[Actual Fact Delta]
  DELTA --> MATCH[Exact Expectation + Postconditions]
  MATCH --> IMPACT[Canonical Impact]
  IMPACT --> VERIFY[Derived Verification Union]
  VERIFY -->|pass| PUB[Atomic Source Publish + Canonical Rebuild]
  PUB -->|pass| OK[Accepted]
  PUB -->|failure after publish| ROL[CAS-safe Rollback]
  ROL -->|restored and rebuilt| BACK[Rolled Back]
  ROL -->|failed| REC[Recovery Required]
```

## 5. Artifact 与 Fact Provenance

```mermaid
flowchart TB
  B[Block/Generator/Slot/Override] --> AP[Artifact Provenance]
  AP --> F[Generated File / Test / Schema]

  C[Contract] --> FP[Fact Provenance]
  CR[Compiler Rule] --> FP
  SA[Static Analysis] --> FP
  RT[Runtime Observation] --> FP
  AI[AI Inference] --> FP
  FP --> FACT[Semantic Fact]

  FACT --> IR[Engineering IR]
  F --> GOV[Governance / Review]
  IR --> GOV
```

Artifact origin 不能自动成为文件内所有 Semantic Fact 的 authority。

## 6. 七类投影

```mermaid
flowchart TD
  IR[Engineering IR] --> A[Architecture]
  IR --> S[Scenario]
  IR --> D[Data]
  IR --> ST[State]
  IR --> C[Contract]
  IR --> E[Effect Permission Trust]
  IR0[Validated IR A] --> I[Canonical Impact]
  IR1[Validated IR B] --> I
  FD[Fact Delta] --> I
  I --> VR[Verification Recommendation]

  RE[Runtime Evidence] -. overlay .-> A
  RE -. overlay .-> S
  PF[Authority / Provenance] -. overlay .-> ST
```

Impact 是 Fact Delta 与两端 validated graph 的只读语义推导，不是仅由 Delta 构成的 UI overlay。Workbench 展示同一语义空间的不同投影，而不是维护七套业务事实。
