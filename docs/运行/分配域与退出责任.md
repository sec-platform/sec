### 分配器的真实合同

```text
allocate(layout, allocation_policy) -> Result<Allocation, AllocError>
Allocation = owner + region + address_or_handle + actual_layout
release(allocation) -> release result defined by that owner
```

`owner` 决定谁释放，`layout` 至少包含字节数和对齐；分配区域寿命、增长能力、线程限制与失败政策只在相关时附加。`allocate` 不开始 T 的完整对象生命周期，`destroy_at` 也不自动释放存储。构造失败后必须使用原分配者释放，不能用“同样大小”的另一个 allocator。

容量乘法、增长计算及向上对齐先检查溢出。OOM 可以作为显式错误，也可以由已采用的终止政策结束运行；不能把一个返回错误的分配器降为不可捕获的终止而仍称等价。

类级 `new/delete` 作为类型绑定的分配政策，影响其明确使用的构造入口；全局默认只影响没有局部指定的使用点。导入一个库不得悄悄改写其他库的全局分配策略。C++ 兼容入口中的具体重载选择、对齐参数、构造失败释放及数组释放由该 compatibility profile 承担。

### 容器、pmr 与传播

`Collection<T, A>` 可用编译期 allocator 参数，或显式的运行时 memory-resource 句柄。原有成熟容器足够就采用，不为统一 API 自写全部数据结构。Rust 目标逐项检查其固定版本的分配器和容器接口；stable 路线必须选实际可用的合格供给／适配器，不能在生成末期偷偷打开 nightly。独立分配器容器不自动与第三方固定的 std 容器类型兼容。[依据](../依据/来源/Rust与C++能力比较.md#baseline-s11)

复制、赋值、转移和 swap 分别规定是否传播 allocator。不同分配域之间只能合法转移所有权、重新分配并复制／转移元素，或返回不支持；不能直接交换裸指针后让错误的 allocator 释放。需要强失败保证时，准备新存储成功后再提交；源被部分转移后不能伪称它未变化。

arena／region 中的对象不得比区域活得更久。需要逃逸就显式提升到更长寿命的区域并履行转移语义，或拒绝该引用。区域统一释放不意味着元素的外部资源析构可以省略。

### 确定性清理与异步关闭

同步 `drop` 的默认合同是不得挂起、不得抛出恢复性错误；可能失败的 flush、commit、close 是显式操作。容器销毁、异常退出、初始化回退都遵守这一分离。

异步 close 必须由能保留关闭续体的拥有者执行。取消调用者并不自动等于资源已关闭；仍未完成的关闭交给明确定义的运行域／监督者，返回 `Closing` 或 `OutstandingCleanup`。没有这样的拥有者时，带必需异步清理的对象不能被降为普通 Rust Future 的任意丢弃或 JS GC 最终化。

### ThreadLocal 不是 TaskLocal

`ThreadLocal<T>` 的实例身份依赖物理线程；`TaskLocal<T>` 依赖逻辑任务。任务迁移时 task-local 跟随任务，thread-local 不跟随。跨挂起保留线程亲和资源必须限制调度器或使任务不可迁移，不能仅靠变量名表示 TLS。

TLS 访问通过带寿命的借用操作或合法拥有句柄进行。Rust `LocalKey` 路线可以满足访问行为，不自动满足“导出一个原生 TLS 符号／原始地址”的 ABI 要求。TS 的 worker-local 存储只在该宿主实例模型确实对应要求时适用；不能冒充可被外部 C 线程读取的原生 TLS。

初始化、递归访问、销毁顺序、线程退出、运行时关闭后再次访问均有明确失败分支。原生 TLS ABI 是单独目标能力，不由包装对象推导出来。

### 全局对象及初始化顺序

需要全局有状态对象时，状态为 `Uninitialized → Initializing → Ready`，另有 `Failed`、`Destroying`、`Dead`。并发首次访问只允许一个合法初始化者；递归初始化检测到环时返回具体循环，而非死锁等待自己。

默认失败结果保留；重试须是显式政策，且确认前次外部效果及资源已处理。对有依赖的全局对象按真实初始化依赖建立顺序，逆向清理。C++ 兼容输入的可观察初始化顺序不能被“改成 lazy 更方便”悄悄改变；动态库卸载还须满足 [foreign ABI、C 变参、回调与卸载](原生边界与模块驻留.md) 的在用引用清零条件。

## 再次修改与失效

分配器、容量、线程归属或关闭协议变化时，重核传播、别名和错误分支；预算下调不抹去已支出额度，区域退役先结算真实借用。

## 使用点与可检验出口

这些分支保留各自的真实输入、替代路径与边界，不按条数声称更多底层能力；[比较记录](../依据/来源/Rust与C++能力比较.md)不拥有另一套语义。

- **额外运算符与代理下标**：保留精确代理/借用/求值需求；先显式方法或局部糖，别把每个运算符升级为核心原语。 硬边界示例：算法固定以原生下标/赋值处理代理结果，或需保留特殊求值顺序、eager逻辑等源语义；[具体比较与出口](../依据/来源/Rust与C++能力比较.md#a19)。
- **复制/移动赋值**：默认显式更新和所有权转移；保留allocator/失败保证；与17共用需求，不重复计数。 硬边界示例：必须与固定原生赋值语法/第三方generic接口配合，或必须保持源对象post-move状态；[具体比较与出口](../依据/来源/Rust与C++能力比较.md#a45)。
- **不可移动值的直接目的地构造**：保留原位初始化和地址稳定合同；不要把Pin单独称无损平替，也别把NRVO当强保证。 硬边界示例：必须原生按值工厂+不可移动类型+栈/内联存储，无新增间接层；C++同类型prvalue可满足特定情形；[具体比较与出口](../依据/来源/Rust与C++能力比较.md#a46)。
- **全局/类级 new/delete**：优先显式资源政策；不要让导入库悄悄接管全局，也不重复自写全部容器。 硬边界示例：要求未修改第三方代码的每次new自动走该类型策略，或nativeallocatorABI不可改；[具体比较与出口](../依据/来源/Rust与C++能力比较.md#a48)。
- **通用可定制协程**：先复用Future/Iterator或生成状态机；取消/清理必须正确，但不由此自动推出multi-shot或通用effect系统。 硬边界示例：库必须暴露原生通用resume/yield协议、保留地址/帧分配控制，且宏/手工状态机成本不可接受；[具体比较与出口](../依据/来源/Rust与C++能力比较.md#a55)。
- **泛型 atomic<T>**：按真实进展、表示和访问域选择供给；不因std少一个模板就自己重造atomic系统。 硬边界示例：禁止锁/分配、进程共享/ISR安全或精确复合ABI，目标原语和库不足；[具体比较与出口](../依据/来源/Rust与C++能力比较.md#a59)。
- **allocator参数标准容器/pmr**：这是实际生态可组合性差异；先检查依赖接受什么容器/策略，不能说随便用全局分配器就解决。 硬边界示例：无法改依赖签名，却要求其内部容器逐实例使用不同allocator；或资质只允许指定标准库；[具体比较与出口](../依据/来源/Rust与C++能力比较.md#a61)。
- **原生thread_local变量**：通常复用标准库；线程亲和跨await需要正确处理，但不把TLS便利升级为新语言核心。 硬边界示例：现成二进制要直接引用TLS符号，或指定TLS模型/初始化顺序；[具体比较与出口](../依据/来源/Rust与C++能力比较.md#a62)。

实际组合与拒绝条件见[验收案例](验收/跨语言控制与组合案例.md)；从作者要求到再次修改见[连续开发情景](../../examples/连续开发/跨语言能力连续开发.md)。

## 隐式生命周期与显式退出的选择

普通新代码优先显式初始化、局部作用域和明确关闭；已有外部程序依赖模块加载、全局构造/销毁或 TLS 导出时，保留所选 loader/运行库的真实时机，不从两个语言的关键字数量推断可替代性。任务局部值、线程局部值、模块静态值和进程资源不能共用一个生命周期。

初始化由实际实例拥有者协调，区分未开始、正在建立、可用、失败与退出。递归 A→B→A 必须定位同一初始化链，不能让初始化者等待自身；并发等待者按实际失败政策收到错误或加入获准的后继。重试不能重复已经发生的注册、文件或设备作用。退出先阻止新增调用，再等待在途使用/注销回调并履行所需销毁；不可控进程死亡不能被普通析构承诺覆盖。

资源分配策略与容器 API 同时选择：成熟库满足当前生命周期、错误和依赖政策时直接采用，不因其不在标准库就重造。自定义分配器容器与第三方固定类型之间可能有实质接口差额；适配复制、转换和跨域释放的成本必须计入，不能只看分配速度。
