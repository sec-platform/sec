# 组织保持与连续变化的验收设计

> **阅读范围**：组织、布局、树形导航、发布、恢复和多目标组合的验收设计；不是已执行结果或所有任务必跑的固定套件。

本篇拥有这些接缝的有限验收构造和连续轨迹，不定义第二套政策、字段、状态机或工程模型。规范义务分别回到[共同语义](../../作者/共同语义关系.md)、[目标布局](../../编译/目标/成员布局与完整产物.md)、[受管回源](../../编译/表示/编辑与受管回源.md)、[信息解析][k2]、[恢复](../持久化提交与恢复.md)和[文档保全](../../维护/组织修改与来源保全.md)。只有真实Claim实例化后，相交构造才作为ProofObligation输入；出现领域冲突时修原拥有者，不以案例文字覆盖其合同。

信息、任务、流、导数、分页与外部尝试的完成边界已有[独立案例](信息与完成边界案例.md)，本页只补组织、布局和连续变化的区别，不复制那套完整表。

## 共同验收方式

每个案例固定源/配置、用途、目标规则、当前布局与实际前像，分别观察计划、目标内容、真实作用和证据。比较单位是带类型的对象/成员/关系和对应字节，不只比较文件数、目录深度或一张渲染图。没有要求真实作用的案例只读/规划；涉及写盘、工具、网络或部署的部分由实际授权与环境另行准入。

每个构造的保持义务都必须定位到原有 Requirement、方法前提、消费者和能够反转结论的反例。列表没有为所有领域宣布统一 oracle；语言等价、文档语义、运行最终性仍用各自真实方法。表格行只用于阅读，不取得稳定机器身份；真正需要身份的是 Claim / ProofObligation / Evidence。

## 对象、关系与组织责任

| 案例 | 固定输入与动作 | 必须观察到的结果 | 不合格结果与理由 |
|---|---|---|---|
| 同一实体多次展示 | 一个准确 Money TypeRef，同一配置中分别从 Payments 和 Shared Types 导航进入 | 两个 view occurrence 指同一 TypeRef，编辑路由到原作者；各 occurrence 的展开/选择可以独立 | 复制成两个可独立修改的类型，或让第二处显示获得额外写权 |
| 同名不是同一 | 两个项目各自定义名为 Money、结构完全相同的名义类型 | 两个身份与所属域保留；显式转换需要合同 | 按名称或字节哈希合成一个类型/单例 |
| 一实体多表示 | 同一业务定义输出 Rust、TS，并生成 API 文档 | 各表示绑定同一准确来源以及不同目标方法；每个可写区域只有自己的合法写回协议 | 宣称“一实体一文件”而删掉合法表示，或把三个产物当三个独立业务真源 |
| 多来源一个成员 | 一个 module 文件承载多个公开类型，另有私有共享 helper | 每个声明/区域保留来源集合、粒度与未知；目标文件可有多个来源 | 强造一个虚假的单来源，或为了映射简单拆出无意义文件 |
| 局部分区规则 | 根按 src/tests/docs，src 按 orders/payments，各责任内按模型/接口/存储细分 | 各兄弟组规则清晰，语义归属与引用不重复；可保持原树 | 因“全树只能一个轴”拒绝合法树，或用分类顺序裁决重叠写源 |
| 树外关系 | 模块 A/B 互相引用类型，但父目录无环；另有 A 运行初始化依赖 B | 保存类型边、初始化边与包含边各自方向；合法性按其合同判断 | 把依赖环写成目录父环，或把所有环都删掉以取得一张 DAG |
| 事务不是文件 | 订单更新、审计和 outbox 必须同一数据库事务；代码位于三个模块 | 同一真实事务边界仍成立，模块可以独立；布局不变也可能完整满足要求 | 只移到同文件就称原子性成立，或拆模块时偷偷改为三个事务 |
| 隔离不是目录 | 某插件不可信且需能力隔离，源码在独立目录 | 真实执行画像仍要求进程/宿主能力边界和许可；目录只定位 | 创建 plugins/ 就把插件标成安全，或由导航隐藏代替访问控制 |
| 共享不变量与多状态机 | 一个受管提交协议共同拥有准备、发布和清理状态 | 可由一个 owner 协调多个子状态机；拆分方案需保持联合不变量 | 仅因有多个状态机就强制拆出多个 writer |

## 布局、输入与候选选择

| 案例 | 固定输入与动作 | 必须观察到的结果 | 不合格结果与理由 |
|---|---|---|---|
| 零变化 | 相同作者/规则/目标/旧布局，提出空编辑或只展开视图 | 原作者字节、身份及固定布局不变；不产生新锁/安装/保存作用 | 重新格式化整个作者文件，或创建证明进度用的文件 |
| preserve 与 canonical | 两个工程语义相同但有不同合法旧布局 | preserve 可输出不同树，因为旧布局是输入；canonical 在相同完整输入下相同 | 一方面消费旧位置，一方面称结果与历史无关 |
| 稳定命名碰撞 | 保留旧私有符号的合法名字，增加与其首选名冲突的新成员 | preserve 按固定规则保护旧名并给新成员合法可追溯名字；公开名冲突明确诊断 | 依线程返回次序抢名字，或截短哈希后不查碰撞 |
| 负依赖 | 原来准确观察某个查找位置不存在，后新增同名可解析成员 | 相交名称解析和导入/布局键失效；原分析不能继续声称没变化 | 只跟踪已读文件，不记录被依赖的不存在/成员集合 |
| Rust 模块移动 | 把外部 mod 源从旧路径移动，包含相对 path/include/资源引用或公开路径消费者 | 按固定 Rust 解释与对应配置重核模块解析、可见性、资源和消费；无法保持则冲突或明确迁移 | 只改磁盘路径/显示树，不更新真实解析；同时产生 foo.rs 与 foo/mod.rs |
| 目标限定 | 一类型在 Rust 固定 C ABI，在 TS 只要求相同业务值 | Rust布局约束只扩展到真实共享接口闭包；TS保持自己的表示合同 | 全工程强制 C 布局，或把共享 wire schema 的变化误说成仅Rust私有 |
| 多根共享配置 | 两根各自可生成，但对同一个 package manifest 的单值字段要求不同 | 原组合器给准确冲突及根集合；独立不相交根仍可返回真实结果 | 后生成者覆盖前生成者，或用任一根成功宣称整包完成 |
| 未知动态消费者 | 包公开符号可能被运行反射/插件使用，当前只取得静态引用 | 保留未知边界，局部证明充分的变化仍可做；删改公开面要求对应证据或迁移 | 没搜到调用即删除公开符号并报告“全世界无消费者” |
| 成本不齐 | 候选甲更少文件，乙更快构建，丙更低运行内存，其中某成本未测 | 先硬资格，再用对应单位和证据比较；不可比/未知保留，已委派稳定选择不冒领最优 | 把文件数、ms、MB和风险直接相加，或把缺值取零 |
| 搜索调度与截止 | 同一冻结候选域及逻辑工作界，分别以串行、并行和不同墙钟截止运行 | 完成同一逻辑探索时确定归并；宿主中断仅返回准确未完成范围；采纳部分结果另绑定候选与回执 | 把最早返回或超时前最后发现的候选当同输入唯一结果，或缓存为全域最优 |
| 预算耗尽 | 有一个已验证可行布局，搜索其他合法候选时达到实际预算 | 返回可行布局与未搜索范围/最优性限制；没有见证时返回未完成 | 将未探索候选判不合格，或因“预算结束”自动取得世界最优 |

## 编辑、发布、取消与恢复

| 案例 | 固定输入与动作 | 必须观察到的结果 | 不合格结果与理由 |
|---|---|---|---|
| 生成三方合并 | B为上次生成，W含用户编辑，N含新生成；依次覆盖W=B、N=B、双方修改、删除/新建 | 按原受管回源与合并合同保留用户内容，冲突携带来源和前像 | 两方都改时直接覆盖，或用同路径当同一身份 |
| 移动与编辑并发 | 计划移动旧文件时，另一个合法作者修改源或目标 | commit前重核实际前像；重基/冲突不丢任一内容 | 操作开始时检查过就不再检查，或者复制后删除新写的源 |
| 路径别名 | 大小写不敏感宿主下移动 Foo→foo，另有symlink/硬链接/根外引用 | 使用宿主实际身份与冲突规则；需要临时名按原事务计划处理，根外读取不隐式授予 | 字符串不同就当不同对象，或任意跟随链接读取私密根 |
| 多文件中断 | 发布三个成员，在前两个完成后中断，第三个结果未知 | 恢复读取原意图/准确前像/回执，确认真实完成并结算残余；不报告瞬时多文件原子性 | 只见一条成功返回即标整组完成，或未知后盲重放副作用 |
| 取消在不同阶段 | 分别在纯规划、批准待执行、已发生部分真实作用时取消 | 纯规划可丢可重建候选；已接受/执行的旧尝试仍按原owner结算，释放真实占用 | 一律删缓存/日志，或新候选覆盖旧尝试恢复资料 |
| 旧运行保留 | 新布局已采用，但旧进程仍保留旧代码/数据/回调 | 旧代保留到真实消费者结束；新配置不改变旧实例语义 | 以旧文件从新ArtifactSet消失为理由删除仍在使用的实现 |
| 回写不唯一 | 一个生成函数来自共享定义与两个使用点，用户修改其目标片段 | 提出真实可能owner及影响；无唯一映射时保持草稿/待决 | 按最近文本位置猜写共享定义，误改全部消费者 |

## 文档、历史与交付

文档重组必须逐义务保留，不把“一个H2分配一次”当作充分证明。下列改变展示会直接反转语义结论的典型反例：原文“未知不等于false”被压缩成“unknown按false”；“只在真实原子域内”被删；保存整数范围而丢舍入条件；把设计验收预期改写成“测试通过”；把某特定平台反例改成普遍结论；把引用带的时间/版本/来源强度吞掉。每一种都可能保持标题和链接，却损坏语义。

当前设计、具有独立用途且被本次交付明确选择的固定范本和派生导航可以共同交付；历史原件按其实际证据与恢复责任保留，不默认纳入当前规范包。它们须有明确身份和读取角色，旧锁继续指向原准确字节，不能仅改source hash让旧例假装符合新设计。当前规范应自足，不以读历史记录为正常前置；仍未完成重新符合性验证的固定范本须保留限制。

ZIP验收同时检查内容CRC、逐文件摘要、成员覆盖、路径无越界、中文名正常解码及UTF-8标志。CRC相同而文件名乱码是失败；文件成员相同而缺被链接的独立范本是阅读覆盖缺口。只修文件位置不宣称文本语义已重新综合。

导航索引不得因ACL裁剪暴露不可披露对象的名称、计数、子节点或候选排除原因。受限视图可以报告与权限相容的“覆盖受限”，不能据此声称全局不存在。选择/分页/延迟展开只改变显示，不把未加载值变成零/不存在。

## 三个端到端设计轨迹

### 一个金额规则生成多个目标，再修改数值含义

假定产品已接受准确的币种、整数最小单位、溢出/舍入与业务错误规则，并要求订单更新和outbox同库事务。来源进入同一Definition/Requirement；Resolver选择满足这些条件的实际方法和数据库供给。Rust/TS目标分别产生合法源、依赖和必要资源，API文档引用同一公共合同。目录可以不同，也不能从“都叫Money”推出机器表示相同。

仅把Rust私有helper移动且保持所有消费者时，业务语义修订不必改变，Rust布局及相关缓存改变；仅调整文档章节时不重新解析数据库。若把金额最小单位从整数分改成另一精度，真正Meaning变化会影响序列化、存储、公开API、迁移、目标程序与相交Evidence；这时不能为了保持文件diff小而藏掉变化。旧部署继续使用其原Artifact和schema，直到有权迁移且读回确认。

没有获得满足需求的方法时，输出准确缺项而非生成TODO处理器。这个轨迹展示所有责任怎样串联，不宣称本包已存在金额实现、数据库适配和真实运行证据。

### 同一份文档由积累叙事变为可维护规范

固定原文与所有链接/锚点后，辨识一个共同提交协议中的准备、写入、读回、失败与恢复；它们可以留在同一规范中，不按“五个步骤”拆五个owner。将独立的授权颁发合同回其原owner，用准确链接代替复制；保留提交协议消费授权的时间点和撤销行为。相同句子若约束不同角色，仍保留各自范围，不能按字符串去重吞掉差额。

重写后的当前文档包含完整机制、必要性和反例；已完成用途且无独立责任的制作记录退出；仍有保全义务的原件按既有来源或证据责任保存。机械校验确认链接/内容覆盖，人工语义核对确认否定、参数、前提、消费者与证据等级。二者共同支持本次已检查范围，不自动认证未读历史。

### 从单模块工具增长到可分发工作区

最初只请求一个纯函数，输出可直接是函数文本；没有持久项目、包、服务或部署。出现真实多个公开根、共享实现与独立版本责任后，由原实现选择评估一个包、多包或已有库复用；若只是文件变长，仍可在同包内分模块。确定合法包边界以后，布局器选择实际文件与引用，生态解析器提供真实成员/锁/构建闭包。

拆包后新增的可见性、依赖、发布、版本兼容、构建和恢复成本必须计入选择；不能以“高内聚”名义隐藏这些成本。若没有独立发行/替换收益，退回单包不是架构倒退；若有真实隔离或兼容边界，文件少也不能抵消硬义务。

## 联合义务与规范组织的补充反例

| 案例 | 固定输入与动作 | 必须保持 | 不合格结果 |
|---|---|---|---|
| 三方共享预算 | 三个同时活跃成员各需4，单池容量10；所有两两检查为8 | 整组12超过容量；返回原约束和三个参与者 | 用两两可行证明整组可行 |
| 互斥聚合 | 相同三个成员，但已证明最多一者活跃 | 在该合同下按互斥聚合为4；未证明互斥时不借用此结论 | 不看activation一律加总，或将未知互斥当真 |
| 同一配置见证 | 两个根各自在不同依赖版本下通过，现要求共享同一实例 | 检查实际共同配置和统一见证；必要时保持冲突 | 将两个不同配置的通过拼接成联合通过 |
| 元数据可删性 | 同目录中有可重建索引及唯一迁移前像/来源记录 | 索引可重建；唯一记录按保留责任保护 | 因目录名是_meta就全部删除 |
| 候选与正式采用 | 新设计包提出替换，main仍采用旧合同 | 保全双方并经有权采用后更新；新方案仍可继续本地设计 | 因包号较大把main降为无效材料 |
| 表内运算符 | Markdown单元格包含逻辑或及三种引用角色 | 转义后完整显示右侧条件和失败约束，源码符号仍准确 | 单元格被切断却只用链接检查宣称完整 |

这些是用于区分组织合同的设计构造，不是 Gift 运行测试结果，也不形成固定待跑题库。实际交付工具只按它机械检查过的工件属性报告结果。

| 案例 | 固定输入与动作 | 必须观察到的结果 | 不合格结果 |
|---|---|---|---|
| 不采用也能预览 | 旧作者A已采用，新候选B尚未保存/合入，B和其解释完整 | 可以检查B、产生B的目标源码；旧采用和旧运行不变；独立要求照常检查 | 先改current头才能编译B，或因B通过而自动采用 |
| 自然语言是值 | 确切Text值含产品帮助语句，作为数据生成两目标；没有未绑定语义 | 原字面量按语言编码保持；不调用LLM、不因中文存在拒绝 | 把所有自然语言文本当不确定意图重写，或以此宣称无需任何精确语义输入 |
| 构建与运行权限分开 | 已有全部准确输入，用户只要完整应用源码，没有部署凭据 | 返回行为/资源/配置/依赖与构建说明及真实限制，不启动应用 | 用缺部署凭据阻断源码生成，或只给接口桩称应用已完成 |
| 构建输入不等于已构建 | 获得锁和全部所需本地源码，但未调用工具链 | 可报告输入闭合与未验证构建，不报告构建通过 | 因目录齐全或manifest合法就标可运行验证成功 |
| feature重新开启 | 对同一package的A依赖禁default，另一条B依赖按当前resolver规则启用相同feature；硬要求禁止该目标能力 | 消费实际解析结果，重核能力和共享域，必要时换候选/调整合法参数或报冲突 | 只看A局部Cargo.toml就报告feature禁用成功 |
| host与target不同用途 | 工具构建侧需要std，目标设备要求no_std，真实resolver支持相应隔离 | 保留两种用途/构建域；分别验证权限、feature与产物，不因同package合并 | 把工具侧std误判为设备违约，或把两侧条件合并后伪称合格 |
| 锁相同构建不同 | Cargo.lock相同，target/profile/rustflags或实际features不同 | 有相交物理输入的ActionKey/Artifact/Evidence不同；不相交前端分析仍可共享 | 复用旧二进制或旧性能结果，仅因锁摘要一致 |
| 解析改变排名 | A的直接成本2、B为3，生态闭包使A新增固定共同成本10而B无新增；同单位同scope | 稳定实际闭包后A为12、B为3，重新比较；不能复用解析前局部优胜 | 先选A再补锁，仍称其更低成本 |
| 共享成本不重复加总 | 两消费者分别需同一个可合法共享工具，工具固定8，每消费者附加1 | 完整组合成本10，不是18；若工具必须两实例则按真实责任重算 | 一律两次计8，或无共享资格也强去重 |
| 解析失败与无解 | 候选需包P，Provider超时/无读权/未缓存 | 保留具体Needs或未完成，继续不相交根；有预算/许可才重试 | 把未取得P当P不存在并签发全域UNSAT |
| 无进展反馈 | 选型与布局反复交回同一规范化选择，未增加事实或排除项 | 检出重复且停止该反馈；保留已验证可行结果与未完成范围 | 无限解析，或靠累积重复回执证明收敛 |
| 过期资格不篡改选择 | 配置仍固定P1，P1的新执行资格被当前authority撤销；旧实例有独立恢复义务 | 源和历史选择仍准确；新执行受阻，旧恢复由原owner结算 | 删除P1来源使旧运行不能恢复，或借锁定版本复活新执行权 |
| 当前性不是全局时点 | 两Provider各返回明确版本，尚无跨源一致切面证明 | 可以固定所选向量；跨源一致Claim保持未决，允许不依赖该Claim的分析 | 把两个本地版本等于一次全局原子快照 |
| 自举而非透传 | 一个工具原样复制自身Rust源码，rustc可构建，连续产物相等 | 支持实际复制/原生构建与对应重现范围；不能报告语义自举完成 | 因A2=A3就认定解释/降低由Gift完成或无共同错误 |
| 分类调整不改事实 | 把同一规范从某导航family换到另一family，原语义/主体/内容不变 | 导航索引失效，语义身份不变；无重分配对象/重写锁 | 因Layer/ASMRVE地址变化生成新类型、实例或权限 |
| 正文未交付 | 工作记录说修改20份，但实际封装与父包docs逐字节相同 | 报告正文修改0，未保存提案不算纳入；继续从实际前像修订 | 用搜索索引更新或ZIPhash变化宣称20份设计已修改 |

### 从新候选到多目标源码，再到一次有权构建

产品以一个结构作者模块表达订单/金额合同，独立要求固定精度、错误、事务与本地数据边界。新候选C2尚未替换C1；本次只要求Rust与TS两套完整应用源码。workspace封存C2与解释；semantics保留同一名义类型和主体；compiler组合两个目标的实际方法。两目标共享中立分析，但目标表示、工具链和依赖锁各自准确，不能用“同一Binding”省掉目标差异。

Rust候选最初选择供给A。原Cargo解析器返回目标features与传递依赖后发现另一条依赖启用了受限制能力；此时回原RealizationPlan检查该能力是否真正落在被禁止的目标运行域。只是构建工具侧合法能力则保留其独立域；确实越过硬边界则调整合法选择或采用供给B，重核成本、共享实例、许可和目标能力。没有证据时给具体缺项，不用泛泛offline标签抹去未知。若TS根确实与失败输入无关可交付其结果，但整批两目标请求仍明确Rust剩余，不改成任一根成功。

选择稳定后形成源码、资源、必要配置及依赖说明；未被请求的安装、部署和运行不发生。人工审查后可以保存C2，也可以保留候选不采用；两种选择都不改写C1运行实例。后续明确请求构建时，取得当时有效执行准入及完整工具输入，消费已冻结源码和目标配置，不重新让LLM猜意图。实际构建反馈、产物与Assurance证据绑定本次构建；原锁相同而profile/features不同仍是另一次物理输入。

若构建尝试响应丢失，按原Operation身份读回并结算；不能因重新选出B就抹掉A已发生的下载/费用/恢复义务。最后只有完成真正的运行采用与读回，才能说新版本在运行；只有其保留消费者和恢复责任结束，才能退役旧内容。这个连续轨迹检查已定接口是否接合，不增加第十种总控状态机或新的产品测试已通过声明。

## 树形出现、信息归属与导航验收

以下消费[树形导航合同][k6]、[具体归属][k7]及原query/修改/恢复协议。表内产品行为是**待执行的设计验收**；文档生成工具实际检查成员、标题、层级和链接时另报自己的结果，不能代签控件、Provider或权限安全。

| 情形 | 固定输入与动作 | 合格结果 | 应拒绝的替代 |
|---|---|---|---|
| 一个主体两次出现 | Orders、Payments均引用M@r1，分别展开 | 两个出现各有父路线，均指向同一主体 | 全局visited删除第二处，或同TreeItem id造成合并 |
| 相同参数不同use | 同模块存在u1、u2，参数与显示名相同但出现身份不同 | 两个use保留；批操作按use粒度消费 | 按内容hash或主体名去重 |
| 合法循环 | 声明导入A→B→A，另一根也引用B | 当前祖先链回边作引用叶；另一根仍可展开B | 无限递归，或禁止所有语义环 |
| 未读与空 | 可取得子项但首请求尚未完成，随后失败 | 未加载/失败明确显示且保留查询入口 | `[]`当完整空集合并永久设置叶 |
| 分页多重性 | 两页含同主体的不同出现，第二页重传一次 | 不同出现保留，重传同出现幂等显示 | 按主体去重或把重传增加为新实体 |
| 迟到旧页 | C1首屏，切C2后C1续页才到 | 旧结果不接入C2，只结算旧请求 | 取消已请求便假定无迟到，或按父标签接页 |
| cursor失效 | 续页前改filter、解释或披露范围 | 使旧cursor失效，重取新合格范围 | 清空剩余页并宣称范围完整 |
| 多Provider局部结果 | 一源有完整页，另一源尚无排序下界 | 返回准确局部覆盖或继续等待所需证据 | 把当前页叫全局首屏/全域最优匹配 |
| 过滤祖先 | 子项命中，祖先只用于定位 | 祖先标路径上下文；命中数不含祖先 | 把祖先也当满足条件，或展开越权父名 |
| 已加载筛选 | 当前只加载10项，其余未知；没有命中 | 明示“已加载范围无命中” | 报告全工程不存在 |
| 范围全选 | 只看第一页后请求全结果批次 | 固定选择用途、基准及完整必要成员；未取得保持未完成 | 默认包含未来对象，边枚举边删除 |
| 重复显示批操作 | 同一主体两处高亮，但动作针对引用关系 | 保留两个准确关系；只有动作合同允许时按主体去重 | 通用set<EntityRef>吞掉一条应修改关系 |
| 折叠与选择 | 已选子项被折叠隐藏，再提交批次 | 明示隐藏选项与覆盖，不默认丢选或扩大 | 只显示当前可见行却执行隐藏新成员 |
| 焦点与效果 | 方向键移动、Home/End、前缀定位 | 只移动/选择/查看；不保存、部署、改Binding | focus事件签发工程动作 |
| 重命名与重建 | 原映射能证明重命名；另一场景删除重建同名 | 前者可延续出现；后者新主体并提示书签失配 | 以标签/旧行号继承权限和身份 |
| 拖到另一父 | 将use跨模块移动，影响共享类型及局部资源 | 形成真实owner迁移候选并联审，失败原源不变 | 只改UI parent后标工程已移动 |
| 增量删除覆盖 | 局部新页未包含旧成员，尚未取得完整枚举/删除事件 | 不据此删除旧成员；保持陈旧或继续取得 | 差集即删除，未知即不存在 |
| 撤权及局部失败 | 子树读取权限撤销，另一独立公开子树正常 | 清相交披露与选择资格，保留允许的独立浏览 | tooltip/计数仍泄露，或无差别锁死全部独立读 |
| 文档主体分开 | 同名Studio目标与Gift开发客户端具有独立规范 | 成品行为归目标作者/产品合同，开发布局归客户端拥有者，各自验收 | 相同标题混为一页或共享PASS |
| 人工导航保全 | README含唯一范围说明，内容树为生成区 | 保护原说明，只重建明确派生区；丢输入时报缺失 | 见README就整页当缓存删除 |
| 当前完整树 | 文件名与标题不同，目录自有README，新增一篇 | 每份文件恰一次进入全量树；目录行承接README；新页与标题同步 | 扁平只列首页、重复README或标题当路径 |
| 协议命令与包环境 | 离线包未含仓库.documentation和旧执行器 | 说明环境边界，运行实际交付工具；不伪造永久document_id | 文档命令指向不存在文件却称可直接复核 |

### 一次带失败与重连的树形浏览

用[同一Shop工程][k8]验证两条Money引用和两个独立use。先在固定C1展开Orders并搜索Money；再展开Payments首个有界页，保持另一页未知。切换C2时保存合法presentation提示，但不复用C1续页；模拟旧页晚到及cursor过期，确认新成员与计数不混用旧基础。

随后在C2按已加载范围过滤，只显示一个命中及它的路径祖先；进行全结果操作前需要原owner固定完整选择域。重命名有映射的M可保持定位，删除重建同名M不能复活旧选择。拖动u-a引发真实作用域迁移，预览发现联合资源条件冲突时不写源，仍可浏览u-b。最后关闭树只释放自身页与监听，实际正在运行的Operation继续由原恢复协议结算。每步记录输入、覆盖、主体/出现和结果，不用截图或目录条目数代替这些断言。
