# 系统组合挑战与反例

> 条件验收与审查情景；不是逐条新发现的仓库缺陷，也不是通过记录。

本篇保留原研究的全部独立挑战，并指向真实规则拥有者。已有规则覆盖的案例用来核消费和实现，不再增加同义规则；候选理论过强的结论撤回，但其有效问题和正向路径保留。历史代码观察有原修订，不能当成本轮已审当前全调用图。

<a id="concepts-representations-responsibilities"></a>
## 概念、表示、责任与可信基础的分工

语义概念、IR节点构造、模块责任、可信计算基不是同一个分割问题。一个概念可以由多个局部表示承载；多个概念可以共享数据结构却拥有不同校验/写权限；十个职责并不要求十个进程；证据模块在代码目录上独立，也不能使其错误不再影响受它控制的结论。

所以，本设计不采用“概念减少=架构更好”的推论。应比较是否保留实际观察、引用与状态约束，是否有明确消费者，是否减少真正重复，是否降低正常使用与迁移成本。MLIR的共同操作/值/块/区域结构与方言语义、traits/interfaces并存，是一个可复用的工程先例；它并未因为共同结构而取消作用域或具体操作约束。这里借鉴边界，不据此要求Gift改用MLIR。（原研究来源R04，见来源表） （原研究来源R07，见来源表） （原研究来源R09，见来源表） （原研究来源P01，见来源表）

### 七个审查问题的实际归属

| 聊天词汇 | 原设计中的实际落位 | 明确不能做什么 |
|---|---|---|
| Entity | 工程身份、引用、版本、来源与实例边界 | 不把每个临时值持久实体化；不按内容合并活资源 |
| Term | 当前作者/领域的紧凑表达式、类型和值结构 | 不以万能object代替解析、作用域、类型与解释 |
| Binder | 定义参数、词法引用、实例化与替换 | 不用稳定EntityId代替局部绑定和捕获规避 |
| Judgment | 允许共享的受类型约束命题内容和推导视图 | 不合并要求、观察、权威、证据和采用的写责任 |
| Definition | 已有普通定义、模块、方言与方法 | 不把任意公理登记为安全定义；不另建第二注册表 |
| Behavior | 各域行为解释、观察关系、阶段化结果 | 不取代真实Operation/RunRecord，不强制统一成一种事件序列 |
| Context | 精确解释快照与实际所需环境参数 | 不做可变全球World，不让旧证明热跟随新解释 |

这些属于原workspace/semantics/compiler/assurance/execution等责任之间的接合；无需新增`gift-kernel-v2`、第二Engineering IR或第二条执行流水线。（原研究来源R04，见来源表） （原研究来源R09，见来源表） （原研究来源R14，见来源表）

## 七个名称不是已证明的工程最小内核

**问题性质：** 撤回聊天中的过强结论。

**触发：** 把“各领域都可放进七类”作为最小性、完备性或实现目录依据。

**机制与损失：** Entity可编码为带命名域/生成标识的Term；Binder可由带作用域规则的项构造表示；Behavior可成为特定语义域中的项。这些编码不自动更好，但足以否定“分类表已经证明互不可约”。删除一个顶层类后，必要检查可能迁到别处，不能靠名字多少比较总复杂度。

**当前处置：** 保留七问作为审查视图，撤销“工程最小点”资格。核心节点种类由实际不变量、消费者和成本决定；不设7、8、10的配额。

**边界及剩余：** 没有做多种实装在同一真实工作负载上的表示大小、编译时延、诊断质量和迁移成本比较。

**规则归属：** [总体设计](../../架构/总体设计.md)；[语义扩展与领域接合](../../作者/组合/语义扩展与领域接合.md)。

**研究依据：** R04、R09、P01；完整来源记录见本篇末尾。

<a id="challenge-a02"></a>
## 有容器容纳，不等于有语义和能力

**问题性质：** 纠正聊天模型；原规范已有防线。

**触发：** 新领域只返回Term/Behavior对象或不透明JSON，却宣称已支持。

**机制与损失：** 还缺合法项、类型/作用域、解释、组合前提、观察、错误、目标实现与保持依据。量子态或连续系统塞进字段只是存储；这不提供其运算、测量、离散化误差或可用后端。

**当前处置：** 使用已有DomainDialect和明确支持子集。普通库、结构扩展、领域解释、原生保留与核心修订分别裁决。未知可保全，不允许未解释内容参与强语义变换。

**边界及剩余：** 未逐个实现量子、连续、所有弱内存画像，不以名词映射消解这些义务。

**规则归属：** [语义扩展与领域接合](../../作者/组合/语义扩展与领域接合.md)。

**研究依据：** R09、R10、P01；完整来源记录见本篇末尾。

<a id="challenge-a03"></a>
## 共用命题表达不等于合并知识角色

**问题性质：** 撤回Fact/Constraint无条件合并方案。

**触发：** 把“要求成立的P”“观察到P”“获准采用P”合并为一个可写Judgment。

**机制与损失：** 内容可能相同，修改者、证据来源、有效范围和消费者不同；实现者可以通过改写同一对象抹掉原要求。命题P与“在规则和上下文Γ中可导出P”的判断也不同。

**当前处置：** 可共享受类型约束的命题载荷；保留Definition、Assertion、Authority、Resolution、Evidence、Verdict的现有职责。要求、假设、观察和接纳不可通过改角色字段自升格。

**边界及剩余：** 是否物理共享内部对象是实现选择；共享不得造成第二写者或混合生命周期。

**规则归属：** [原则总纲与归属](../../产品/原则总纲与归属.md)；[解释与证据接纳](../保证/解释与证据接纳.md)。

**研究依据：** R03、R12；完整来源记录见本篇末尾。

<a id="challenge-a04"></a>
## 一个万能status会合并本可同时成立的事实

**问题性质：** 新增审查反例；原精确状态规则应复用。

**触发：** 将established/refuted/unknown/ambiguous/unsupported/cancelled放入同一个全局互斥枚举。

**机制与损失：** 一个数学命题可已有证明，同时当前目标不支持、当前查询取消、当前权限过期。选择有歧义不等于命题既真又假；工具故障不是反证。一个状态覆盖其余状态会丢失有效成果或误放行。

**当前处置：** 按实际主体保存逻辑支持、方法运行结果、候选选择、目标可用性、采用决定、执行状态；仅用面向本次请求的派生摘要聚合。

**边界及剩余：** 这不是要求新增六张表。原Verdict/CheckRecord/Operation等足够时不新增协议。

**规则归属：** [解释与证据接纳](../保证/解释与证据接纳.md)；[协作与状态边界](../../架构/协作与状态边界.md)。

**研究依据：** R12、R14；完整来源记录见本篇末尾。

<a id="challenge-a05"></a>
## fixpoint标签不提供存在性或求值算法

**问题性质：** 撤回标签式闭合；原规范已有相应责任。

**触发：** 对任意规则填least_fixpoint，并默认不断执行直到稳定。

**机制与损失：** 在U={0}上令F(X)=U\X，没有不动点，迭代在空集和全集间振荡。即使某域中不动点存在，也不自动得到有限计算过程；无限域、近似和预算另有语义。

**当前处置：** 普通目标递归可保留；证明规则/规范化规则需绑定实际语义与合格求解方法。无限循环、未证存在、资源耗尽、不支持与反证分开；需要时复用成熟逻辑内核，不让任意definition成为公理。

**边界及剩余：** Lean严格正性是其可信类型系统的一种具体纪律，不是要求Gift照搬全部依赖类型系统。

**规则归属：** [组合前提与进展闭合](../../编译/组合前提与进展闭合.md)；[解释与证据接纳](../保证/解释与证据接纳.md)。

**有限构造：** W01；仅可支持对应模型，不证明产品实现。

**研究依据：** R13、R12、P02；完整来源记录见本篇末尾。

<a id="challenge-a06"></a>
## 相互条件保证不是初始事实

**问题性质：** 原仓库明确已覆盖；复算其反例。

**触发：** A保证B成立的前提是A，B保证A成立的前提是B；没有初始支持，或初始支持已撤回。

**机制与损失：** 循环图连通不证明任何节点为真。撤销种子后若只保留双向依赖，就会留下互相自证的旧结论；安全不变量也不能代替系统启动与活性。

**当前处置：** 复用C3稀疏支持、剩余分量重算和C4的有根据循环检查。初态、每个转移、环境进展和同拍代数反馈分别处理。

**边界及剩余：** 小模型重算通过不证明全部真实线程/设备模型；不为复算新增一套全局证明器。

**规则归属：** [组合前提与进展闭合](../../编译/组合前提与进展闭合.md)。

**有限构造：** W02；仅可支持对应模型，不证明产品实现。

**研究依据：** R13；完整来源记录见本篇末尾。

<a id="challenge-a07"></a>
## Binder必须有捕获规避和引用纪律

**问题性质：** 聊天模型需要补语义；不自动加根类型。

**触发：** 以通用图替换，把lambda x.y中的自由y替为x。

**机制与损失：** 朴素替换产生lambda x.x，原本应保持自由的x被捕获；正确结果可为lambda z.x。序列参数的长度依赖、影子名字、关联类型的投影也不能只靠Sequence标签处理。

**当前处置：** 让现有表达式/定义消费者拥有词法引用、freshness、替换和种类检查。长期EntityId不替代局部绑定；alpha相等不合并两个独立运行资源。

**边界及剩余：** 这里只计算有限自由变量例子，未实现或验证Gift的泛型/替换引擎。

**规则归属：** [抽象与开放定义](../../作者/组合/抽象与开放定义.md)；[语义扩展与领域接合](../../作者/组合/语义扩展与领域接合.md)。

**有限构造：** W07；仅可支持对应模型，不证明产品实现。

**研究依据：** R08、R09、P01；完整来源记录见本篇末尾。

<a id="challenge-a08"></a>
## 同内容、同语义与同一实体不是一种相等

**问题性质：** 原规范已有防线；保留为跨层验收。

**触发：** 以内容摘要合并对象，或把所有局部值都变成长期版本实体。

**机制与损失：** 两个初值相同的锁/文件句柄不应合并；改显示名不必改变工程身份，但原生导出名或反射可见字符串可能改变外部行为。内容去重不等于状态实例去重。

**当前处置：** 保留工程身份、局部绑定、值等价、表示兼容、运行实例与来源对应的差异。仅需要独立编辑/引用/迁移的边界持长期身份。

**边界及剩余：** 不能单凭id前缀或hash文件判断整个身份算法；本次未审计所有来源映射和迁移实现。

**规则归属：** [全体系信息结构](../../信息/全体系信息结构.md)；[原则总纲与归属](../../产品/原则总纲与归属.md)。

**研究依据：** R07、R03、R16、R20；完整来源记录见本篇末尾。

<a id="challenge-a09"></a>
## 统一候选框架不能统一各语言的选择顺序

**问题性质：** 纠正聊天中过度归一；真实语言规则仍归原提供者。

**触发：** C++原生输入被改成“先删不可访问函数、再选最佳匹配”。

**机制与损失：** C++对重载集是在选择函数后检查访问。若private f(int)比public f(double)更匹配，先删除private会把应报错的程序变成成功调用。共享框架不代表相同选择政策。

**当前处置：** 原生前端按原语言规则建立绑定/诊断；中立调用消费已解析语义。只有确实共用的匹配、引用和诊断结构复用，不把所有语言装进唯一排名算法。

**边界及剩余：** 本轮根据C++工作草案核查该规则；没有重新编译该C++样例。

**规则归属：** [语义扩展与领域接合](../../作者/组合/语义扩展与领域接合.md)；[实现选择与设计搜索](../../编译/实现选择与设计搜索.md)。

**研究依据：** R09、P04；完整来源记录见本篇末尾。

<a id="challenge-a10"></a>
## 逐项存在方案不等于共同存在一个方案

**问题性质：** 有限量词反例；原共同选择规则应复用。

**触发：** 对每个输入或根分别找到方法，随后宣称一个共同制品已满足全部要求。

**机制与损失：** 输入{0,1}，方法m0仅满足0、m1仅满足1。forall x exists m成立，exists m forall x不成立。运行时分派可能解决，但它是带观察、成本和接口条件的真实实现，不是交换量词。

**当前处置：** 保留共同选择的见证、适用域与阶段；允许合法分派/多制品时显式构造并验证组合；否则报告共同义务缺项。

**边界及剩余：** 本反例不意味着所有方法必须单选；分开主体的合法独立输出仍可分别成功。

**规则归属：** [组合前提与进展闭合](../../编译/组合前提与进展闭合.md)；[总体设计](../../架构/总体设计.md)。

**有限构造：** W03；仅可支持对应模型，不证明产品实现。

**研究依据：** R13、R04；完整来源记录见本篇末尾。

<a id="challenge-a11"></a>
## Transition并未被数学上击穿；行为模型不宜单一化

**问题性质：** 纠正上轮理论断言。

**触发：** 由弱内存/无限轨迹需要，推出状态迁移模型不能表达，必须替换为Behavior根对象。

**机制与损失：** 可以通过更丰富状态或全局约束描述更复杂行为；问题是该表示是否适合分析，不是简单不可表达。事件结构也不会自动带来准确内存序、公平性、概率调度或物理时钟。

**当前处置：** 保留适合任务的AST/SSA/CFG/事件/关系或其他领域表示，并通过已定义边界接合。Behavior可为解释视图，不能取代真实操作记录或把所有域硬塞入一个event[]结构。

**边界及剩余：** 本次未提供统一弱内存/实时/概率理论的健全性证明。

**规则归属：** [语义扩展与领域接合](../../作者/组合/语义扩展与领域接合.md)；[性质保持与开放环境](../../编译/性质保持与开放环境.md)。

**研究依据：** R09、R11、P01；完整来源记录见本篇末尾。

<a id="challenge-a12"></a>
## 单运行细化不自动保持跨运行安全

**问题性质：** 原规范明确已覆盖；复算已有反例。

**触发：** 源对每个秘密h允许输出{0,1}，目标返回h。

**机制与损失：** 每个h下目标输出集合都是源的子集，但h=0和h=1的公开观察可区分。一般输出集合包含检查不能签发所有非干扰或隐私保证。

**当前处置：** 沿原Claim固定观察与跨运行关系，匹配相应保持方法。常量目标可保持这里的可能性非干扰，但不满足独立公平随机的更强要求。

**边界及剩余：** 这只是明确给出的可能性模型；强线性化等成果也只能在其准确模型下复用。

**规则归属：** [性质保持与开放环境](../../编译/性质保持与开放环境.md)。

**有限构造：** W04；仅可支持对应模型，不证明产品实现。

<a id="challenge-a13"></a>
## 边际、联合分布、复现和调度不同

**问题性质：** 原规范明确已覆盖；精确分数复算。

**触发：** 将两个独立随机调用缓存成一次抽样并重复返回，或用固定seed通过代替分布保持。

**机制与损失：** 独立(A,B)与(R,R)每项都公平，但相等概率从1/2变成1。非确定选择不等于概率，调度者是否可见秘密/未来随机值也会改变保证。

**当前处置：** 按数值/随机合同保留样本身份、联合结构和允许耦合；方法选择和缓存自身也进入被要求的观察范围。

**边界及剩余：** 没有统计采样或概率编译器测试；这里是四个结果上的精确枚举。

**规则归属：** [性质保持与开放环境](../../编译/性质保持与开放环境.md)。

<a id="challenge-a14"></a>
## 保持证明不能自行选择一个过弱的观察

**问题性质：** 原规范明确已覆盖。

**触发：** 原要求关心时间/日志/设备写，但证明只投影最终返回值。

**机制与损失：** 投影删除了义务所关心的信息，得到的等价不能回填成原保证；有证明的编译器也有明确阶段和观察边界。

**当前处置：** 观察由独立要求和合格域解释固定；lowering回执只列实际保持的Claim，资源/时限/安全各取对应证据。

**边界及剩余：** CompCert手册不把执行时间和内存消耗纳入该观察定理；这不削弱它在已证明范围中的价值。

**规则归属：** [性质保持与开放环境](../../编译/性质保持与开放环境.md)；[解释与证据接纳](../保证/解释与证据接纳.md)。

**研究依据：** R11、R12、P03；完整来源记录见本篇末尾。

<a id="challenge-a15"></a>
## 实现和证明器一起使用错误编码仍会一致

**问题性质：** 原规范明确已覆盖；复算已有反例。

**触发：** 原要求是数学整数加法，候选与检查器同时用有符号64位回绕。

**机制与损失：** 对2^63-1加1，两者可共同输出-2^63并互相“验证”，但真实要求是2^63。两个后端一致、自编译固定点或签名都不消除共同模型错误。

**当前处置：** 原要求、语义解释、公式映射、候选与验证依据分别保留来源；缺少关键输入时保留相交义务，不让实现者改掉唯一判据。

**边界及剩余：** 例子不说明当前Gift已产生该错误；也不要求清楚的普通函数额外复制一份需求文档。

**规则归属：** [解释与证据接纳](../保证/解释与证据接纳.md)。

**有限构造：** W06；仅可支持对应模型，不证明产品实现。

**研究依据：** R12；完整来源记录见本篇末尾。

<a id="challenge-a16"></a>
## 命题和authority字段不是不可伪造的执行权

**问题性质：** 原规范明确已覆盖；代码字段不等于漏洞。

**触发：** 把MayWrite/Possesses/authority="authoritative"当作可以执行副作用的充分条件。

**机制与损失：** 描述某项权利的值可以复制；真实许可还有签发者、主体、范围、时效、撤销和作用点。字段存在既不能证明有安全问题，也不能证明安全边界已生效。

**当前处置：** 继续由execution/adapters在真实作用前消费受信能力，semantics描述需求，assurance评价依据。纯函数不强迫走外部授权流程。

**边界及剩余：** 只读取了FactAssertion类型等有限代码；没有审计全部权限入口，不指控已发生越权。

**规则归属：** [解释与证据接纳](../保证/解释与证据接纳.md)；[原则总纲与归属](../../产品/原则总纲与归属.md)。

<a id="challenge-a17"></a>
## 隔离任意检查器不等于获得可信逻辑

**问题性质：** 原规范明确已覆盖。

**触发：** 无I/O、确定执行、签名齐全的检查器总返回true；或把未经核验公理重命名为definition。

**机制与损失：** 宿主隔离保护资源与权限，不保证推理规则健全。源到公式映射、理论、公理、检查器和实际选项都是某项Claim的可信依赖。

**当前处置：** 复用E0—E7；建立材料资格、执行资格、逻辑支持与任务采用的分界。允许有条件信任，不能把信任写成已完成的形式证明。

**边界及剩余：** 证明可用性与业务适合性不同；本轮没有独立重证第三方证明器。

**规则归属：** [解释与证据接纳](../保证/解释与证据接纳.md)。

**研究依据：** R12、P02；完整来源记录见本篇末尾。

<a id="challenge-a18"></a>
## Context不能是可变全局世界或万能缓存键

**问题性质：** 原规范已有防线；保留差分验收。

**触发：** 插件加载、观察模型更新或权限撤销后，继续使用旧“当前Context”的结论。

**机制与损失：** 解释快照、运行状态与当下准入是不同生命周期。只依赖已选成员而漏掉“全集枚举/没有候选”的读取，会在新增成员后假命中；全局序号则可能过度失效。

**当前处置：** 编译固定所需解释与真实读集；查询全集/否定读取记录集合依赖；新解释形成新候选，不热改旧EngineImage。实际权限按作用点核查。

**边界及剩余：** 摘要相同仅固定对应字节；真实性、新鲜度、支持范围另证。没有测量实际缓存行为。

**规则归属：** [语义扩展与领域接合](../../作者/组合/语义扩展与领域接合.md)；[协作与状态边界](../../架构/协作与状态边界.md)。

**研究依据：** R09、R14；完整来源记录见本篇末尾。

<a id="challenge-a19"></a>
## 跨理论同签名不代表可组合

**问题性质：** 原规范已有防线；扩展消费义务。

**触发：** 把不同域的Int、引用、时间、关系或“相同”运算按同名签名接起来。

**机制与损失：** 数学整数和位向量、集合和多重集、值相等和对象身份、逻辑时间和物理时钟不同；单个部件正确不提供桥接的保持定理。直接把两组公理相加还可能改变原结论。

**当前处置：** 通过版本化接口固定值域、单位、别名、效果、观察与误差；转换本身产生准确义务。能保全不等于能转换，无法证明只限制相交用途。

**边界及剩余：** 不为所有潜在理论组合预先建立全球求解器；按真实被选边界处理。

**规则归属：** [语义扩展与领域接合](../../作者/组合/语义扩展与领域接合.md)；[组合前提与进展闭合](../../编译/组合前提与进展闭合.md)。

**研究依据：** R09、R13；完整来源记录见本篇末尾。

<a id="challenge-a20"></a>
## 所有东西都变成带证据的持久图会破坏正常路径

**问题性质：** 原规范明确反对；不要因抽象扩大成本。

**触发：** 常量、每次load、每个参数都获得EntityId/Revision/Assertion/持久证据，纯函数启动全平台。

**机制与损失：** 表示、序列化、查询、失效和保留成本可能远超原计算，还制造额外写者和删除责任。“可建模”不推出“应实体化/持久化/全局查询”。

**当前处置：** 局部表达式保留紧凑结构；公共语义摘要按需求派生；独立审查和恢复对象才保留对应记录。小任务在内存工作，不默认数据库、证明服务或守护进程。

**边界及剩余：** 没有基准测量，故不捏造开销倍数，也不宣称某个节点数就是最优。

**规则归属：** [全体系信息结构](../../信息/全体系信息结构.md)；[抽象与开放定义](../../作者/组合/抽象与开放定义.md)；[协作与状态边界](../../架构/协作与状态边界.md)。

**研究依据：** R07、R08、R14；完整来源记录见本篇末尾。

<a id="challenge-a21"></a>
## 有限IR不能通过改成string自动获得开放扩展

**问题性质：** 已定位真实代码接点；是否扩展由使用点决定。

**触发：** 将当前SEMANTIC_PREDICATES放宽为string，未同步签名、锁、身份、修改器与影响传播。

**机制与损失：** 先前固定修订中已读校验器拒绝未登记谓词，传播表要求与固定集合精确一致；忽略这些检查会丢失端点类型和影响范围。另一方面，固定基础构造可以支持无限普通定义，本身并非架构错误。

**当前处置：** 默认普通定义/库走已有语义；确需通用分析器看到新领域关系时，沿已选DomainDialect/解释快照解引用合法签名和行为接口，不能自由字符串兜底。

**边界及剩余：** 先前研究只确认所固定旧修订中这条IR路径的边界，没有证明所有其他入口都不支持扩展，也没有运行原仓库测试。

**规则归属：** [语义扩展与领域接合](../../作者/组合/语义扩展与领域接合.md)；[fact-types](../../../src/semantics/engineering-ir/fact-types.ts)；[validate-engineering-ir](../../../src/compiler/ir/validate-engineering-ir.ts)。

**研究依据：** R09、R15、R17、R18、R19、R21、R22、R23、R24；完整来源记录见本篇末尾。

**规则归属：** [协作与状态边界](../../架构/协作与状态边界.md)；[全体系信息结构](../../信息/全体系信息结构.md)；[fact-types](../../../src/semantics/engineering-ir/fact-types.ts)。

<a id="challenge-a23"></a>
## 统一Failure/Behavior不能覆盖真实恢复状态

**问题性质：** 原规范已有防线；必须保留运行交接。

**触发：** 超时或取消后重放外部请求，或把整个失败操作当可逆状态迁移。

**机制与损失：** 真实效果可能已发生但回执未到；补偿不是原操作的数学逆，旧任务仍可能占资源。已证安全、任务结束、设备停止、内存可释放是不同事实。

**当前处置：** 复用原操作身份、前像、幂等/查询能力、分项回执与恢复协议。没有真实提供者保证时报告未结算，禁止用新的规范版本改写过去效果。

**边界及剩余：** 没有真实远端/设备测试；这里不是新增分布式事务产品路线。

**规则归属：** [协作与状态边界](../../架构/协作与状态边界.md)；[组合前提与进展闭合](../../编译/组合前提与进展闭合.md)。

<a id="challenge-a24"></a>
## 有限展开、原生泛型API与运行时开放世界不同

**问题性质：** 保留前期研究的正确边界。

**触发：** 生成几个Rust/TS实例后，宣称已经提供任意未来原生调用者的同形泛型API或所有插件能力。

**机制与损失：** 源编译器可在实例已知时消除参数包/常量计算等抽象；下游原生编译器面对未知实例时，仍受自身接口和工具链限制。动态组件还带来重入、别名、ABI和观察范围变化。

**当前处置：** 逐用途声明中立定义继续实例化、预生成具体制品、目标原生API与运行时动态接口；成熟原生工具可直接复用，不要求重建全部C++。

**边界及剩余：** 本轮不重新裁决目标语言顺序，不承诺所有语言和ABI；直接原生保全也是合格的有限支持路径。

**规则归属：** [抽象与开放定义](../../作者/组合/抽象与开放定义.md)；[性质保持与开放环境](../../编译/性质保持与开放环境.md)。

## 实施审查定位与重新打开

研究曾在所绑定旧修订中观察到 `SEMANTIC_PREDICATES`、`z.enum(SEMANTIC_PREDICATES)`、谓词签名与验证/变更请求等有限消费者。这些位置是恢复源码审查的线索，不说明当前分支的同名路径全部未迁移，也不单凭有限枚举证明产品架构错误。实施时从当前规则取得准确调用闭包；需要扩展的真实使用点能通过所有消费者并保持旧合法输入，才算实现接合。现阶段没有执行该产品迁移。

状态图只是表达工具，不天然排斥弱内存、概率或连续系统；将所有性质强行压成单条事件轨迹则可能丢掉必要关系。保留各域的真实模型、可观察关系与保持方向。非干扰比较多次执行，联合分布不能只比较边际，时延/顺序/释放不能只比较最终值。有限求解器的近似和完整范围另沿原证据合同。

下一次修改先核该挑战的前提是否仍成立；已有适用依据可复用。反例推翻源要求、公式编码或目标方法中的哪一项，就回那个 owner 重算相交消费者；不要用“全部拒绝”“全部动态化”或“全部新增原语”回避正向功能。

<a id="boundary-design-reasons"></a>
## 边界判据的具体应用与反例

### 事实、要求、证据、决定与权限

必要的是不能让不同处置所需的信息不可恢复，而不是强制五张表或五个服务。相同命题可被要求、声称、反驳或证明；同时还可能尚未获准执行、当前环境不支持、对应操作已经部分发生。这些轴并不互斥，不能塞成一个万能成功状态。

可以合并物理存储、共用命题表达、采用紧凑tagged union或按用例投影；不得由候选修改同一状态位就获得采用资格。严格独立复核是特定任务的要求，不是所有纯函数检查的普遍前置。原原则2、5、8、11、21保持；这里不把它们升级为服务数量定理。

### Identity、绑定与相等

名字、地址、字节相同不能一般推出对象相同：两个独立锁可以初值相同；一个文件描述符数字可以被后继对象复用；两个作用域都可以有名为`x`的绑定。真正需要的是消费者辨别“是否同一个对象／哪一代／哪个绑定”。

可由词法作用域、静态类型、生成标识、原生句柄或显式代际分别实现。不能要求每个常量创建长期Entity，也不能仅为共用Term结构删除绑定卫生。不会跨寿命传播的局部值无需再加一层运行时身份服务。工程身份、词法绑定、内容身份、运行实例身份、值等价和ABI兼容分别按实际消费者保留。

### 一个决议责任，不等于一个物理写者

无额外限制的集合增加操作可以按并集合并；并集交换、结合、幂等，因此重复和次序不会改变该集合结果。这个例子不需要一个全局串行写进程。引入删除、权限、顺序、配额或保密观察后，原证明范围可能不够，必须重新判断。

相反，余额1被两个互不通信的执行者同时各花1，并都向外承诺成功，就突破非负余额不变量。原子裁决、事务、预先分配不可重复的花费权、限制一个执行者或等待通信都可能解决；具体选哪种依赖可用性、延迟与故障要求。

所以当前答案是按冲突资源和不变量取得真实协调／可合并／权利分配机制，不是“全系统只能一个writer”。原原则6已有正确的对象、版本、作用域限定，保留；也不因可多写就取消实际围栏。

### Definition、推理与逻辑基础

把递归对象叫Definition没有提供其含义。`F(X)=U\X`在`U={0}`的幂集上没有不动点；“least_fixpoint”标签不会使它产生解。函数执行、归纳定义、规则闭包和同拍代数约束分别由适用的解释与算法处理。

一般递归可以属于普通目标程序；被当作证明规则、类型归一化或编译期必须完成的过程，则需要相应可信条件和预算。不能为避免逻辑风险拒绝所有目标递归，也不能把允许普通递归扩大为任意公理可自签。循环支持在没有种子、归纳基础或合法共同不变量时不产生真实依据。

### Behavior、效果与目标语言

有结构能保存事件不等于已定义并发内存模型；能保存概率不等于已定义调度与随机性的组合。共同载体与领域解释分开，但不要求每个领域各造一个独立数据平台。

效果摘要可以来自类型、声明、分析或受信下层接口，并不一定要先枚举全部执行轨迹。摘要不完备时不能当作“无效果”。语义需求、目标实现、目标原生公共接口和外部ABI必须分别核对。原生库已经满足实际合同的，不因没有Gift同名节点而重写；精确外部约束不能用“最终能算出来”替代。

### Scope、Stage与Context

解释版本、编译目标、观察政策及已封存输入用于解释当前对象；运行内存、当前远端状态和撤销权限不因被写入Context就变成不可变事实。可以使用同一数据结构保存这些值，但消费者必须保留各自寿命与读回条件。

纯编译消费固定输入，与来源采集或获准工具动作分责，是可复现和效果控制的当前实现选择。它不要求每个阶段都是一个进程，也不意味着编译器完全不能使用文件：读取应在准确捕获的边界发生。重新检查权限不等于重算全部纯结果；缓存命中也不省略当前作用准入。

### 泛型、选择与源语言规则

参数化可以共享绑定、替换和种类检查结构；变参、类型构造器、依赖常量的实际规则仍要存在。共用候选框架不能让Rust trait、C++重载和目标方法选择自动采用相同排序。

例如C++先选更匹配但不可访问的成员，再报告访问错误，不等于先删除所有不可访问候选后继续选择另一个。Gift自身可以选别的规则，但C++导入必须保持原语义。所谓“统一”必须说明保留了什么，而不是让名称相似的方法偷偷互换。

### 资源、生命周期与效果结算

移动所有权、复制值、搬迁地址、原位初始化、替换目标、销毁对象和释放存储可以共享底层表达，但不能在消费者处不加区分。GC、引用计数、区域分配与手工所有权是可选策略；GC可达性不证明文件、设备和异步请求已停止使用。

一个请求超时可以对应远端未执行，也可以对应已经执行但回执丢失。把两者压成“失败可重试”会在后者重复效果；仅返回值相同不证明恢复状态相同。保留原操作身份、真实幂等/观察机制、余留资源与移交责任，且不为无外部效果的纯函数制造这套成本。

### 优化、性能与不可补偿要求

算法相同并不证明ABI、计时、峰值内存和浮点舍入相同；指定参数相同也不证明实际保证成立。只对任务需要的观察取得相应依据，不默认要求所有程序位级、时序级、源文本级全部相同。

允许多个可行实现后，可以依已接受的偏好选一个。安全或权限已被任务定义成不可补偿条件，就不能拿速度抵消违反；这是任务约束，不是某个技术栈的自然定律。不同量纲可以在明确且适用的政策下换算，不能由模型私自造分数。没有平台实测时，机制推导不是延迟测量。

### 合成与完整范围

`∀x∃m`不自动成为`∃m∀x`；共同运行的候选要有共同见证，而不是每个局部选择一个不兼容方法。某一方法的支持域也不能被包装成世界上不存在其他方法。

有限基础构造与有限能力不是同一个断言：固定谓词和节点集合可以表达任意多普通定义。因此现有Engineering IR的有限枚举不能单独证明开放定义缺失；但它也不能代签尚未接合的领域语义。应沿真实定义、解释、方法、目标、编辑、迁移和保证消费者检查，而不是把枚举放宽成字符串就宣布开放。
