# 系统组合挑战与反例

> 设计攻击集；用于检查现行 owner 是否真的覆盖边界，不是另一套内核、评分表或已执行测试。反例只推翻相交命题，不能从一个失败扩张成“整个 SEC 不可行”。

## 24 个系统级反例

| # | 反例与实际损失 | 当前设计处置 |
|---|---|---|
| 01 | 七类概念能够描述对象，不证明七类是数学最小、物理模块数最优；Entity/Term/Binder 等还能有其他无损编码 | 保存真正影响解释、权限、寿命和算法的区别；物理模块按消费者与成本选择，不以“原语最少”作为唯一目标 |
| 02 | 把连续、概率或设备语义塞进 opaque JSON，只保全字节却没有合法运算、观察和后端 | opaque 只提供保全；需要强语义时必须有相应 DomainDialect/方法/目标供给 |
| 03 | Claim、Evidence、Authority 共用一个可写状态对象，候选通过改状态就能同时改要求和签发自己 | 载荷可共享存储，但要求、断言、权威、证据和裁决的写权与效力分开 |
| 04 | 命题可证明、目标不支持、查询被取消、权限又过期可以同时成立；一个全局 status 会丢事实 | 各真实主体保留自己的状态；摘要只能投影，不能覆盖其他层事实 |
| 05 | U={0}, F(X)=U-X 在空集/全集间振荡，没有固定点；“有 fixpoint 标签”不产生收敛 | 固定实际算子、域及求解依据；超时、无固定点和无解分别返回 |
| 06 | A=>B、B=>A 且无种子时，两条条件定理不能自己证明 A/B；撤销唯一种子后旧缓存也不能互相保活 | C3/C4 从当前支持重算相交分量，循环支持要求合法种子/归纳基础 |
| 07 | 捕获规避失败：把自由 y 直接替换进 lambda y.x 可能错误捕获，字符串相同不能代表符号相同 | 生成/变换保留词法绑定并做 capture-avoiding substitution |
| 08 | 两把锁、两个文件句柄初值相同仍不是同一现实对象；反过来每个局部常量都做永久 Entity 又制造平台膨胀 | 内容、语义、实体、存储和运行实例分离；只有真实生命周期消费者才持久实体化 |
| 09 | C++ private 的 f(int) 是最佳候选，public f(double) 较差；先删除 private 会把原本编译错误变成成功 | 精确原生导入由成熟前端先做最佳候选选择，再做访问检查 |
| 10 | 输入0只有 m0 成功、输入1只有 m1 成功，得到的是 forall x exists m，不是 exists m forall x | 实现/策略必须保持量词顺序、共同 witness 和可见信息；必要时真实动态分派 |
| 11 | 弱内存、事件结构、无限轨迹有更合适表示，不证明 Behavior 或 Transition 某一个万能节点应吞掉全部 | AST/CFG/SSA/事件/关系/行为按实际方法存在；共享的是语义关系，不强制一种物理表示 |
| 12 | 每个秘密输入的单次输出集合都被目标包含，但目标直接输出秘密；单轨迹 refinement 仍可能破坏非干扰 | 跨运行、信息流、hyperproperty 使用相应关系检查，不能由单轨迹结论升级 |
| 13 | 独立公平 (A,B) 改成 (R,R) 时两个边际都一样，但“二者相等”概率由1/2变1 | 保留随机变量身份与联合分布；边际一致或固定 seed 不证明分布保持 |
| 14 | 最终返回值相同，但日志、设备写、时间或资源观察发生变化 | Observation scope 来自原要求，优化器不能为方便证明私自缩小观察 |
| 15 | 规格使用数学整数，impl 与 checker 共同把 2^63-1+1 回绕成负数；二者一致仍共同错误 | 要求编码、模型和候选实现分别核验；独立性看共同原因而非“两个工具都绿” |
| 16 | 复制 MayWrite:true、authority 字符串或签名字段不能产生现实写权 | 描述与 Grant 分离；真实作用点重新核当前主体、目标、载荷、前像和提供者能力 |
| 17 | 无 I/O、沙箱内且总返回 true 的 checker 依旧可以逻辑错误 | 隔离只限制效果；逻辑/编码/可信基础/覆盖另外进入 Evidence 接纳 |
| 18 | 可变全局 Context/current-world 在插件、观察或权限变化后让旧缓存继续“当前” | EngineImage/请求上下文冻结；正/负/集合依赖和实时准入分别进入失效 |
| 19 | Int、集合/多重集、身份/值相等、逻辑/物理时间可能有相同函数签名，却不是同一理论 | 转换绑定真实域、单位、量词和观察；同签名不证明理论兼容 |
| 20 | 为每个 load、局部值、临时 AST 建永久 ID/Revision/Proof 图，让简单纯函数也支付平台成本 | 原则20：没有消费者的结构不建设；局部值用类型/作用域即可 |
| 21 | 把固定 enum 改成 string，但签名、校验、编辑、影响传播和 lowering 仍只认识旧集合，并没有真正扩展 | 真扩展同时接合解释、签名、身份、编辑、依赖、降低与证据；字符串不是开放语义 |
| 22 | 路径/版本号改变后直接沿用旧证据或把旧字节当新语义，既可能误复用也可能误失效 | 内容、语义、位置、资格和权限分开迁移；先按原版本验真再转换 |
| 23 | 外部写超时后换 requestId 重发，或把 cancelled 当“从未发生”，会重复现实作用 | 沿原 operation 身份 readback/fence/dedup；作用未知保留未结算，不换身份绕开 |
| 24 | 生成若干具体 Rust 实例就宣称“任意未来 T 都有开放原生泛型 API” | 四种交付形态分开：中立定义、有限实例、目标原生泛型、动态字典/固定接口 |

## 10 个边界裁决

1. **概念分类不是最小内核证明。** 必要区别由消费者、反例和保持义务证明；物理分层可以合并或拆分。
2. **确定有限任务的充分抽象有精确判据。** 固定合法域 D、要求结果 R 和抽象 A，仅依赖 A(x) 能交付 R 当且仅当 A(x)=A(y) 推出 R(x)=R(y)；这不证明该表示最便宜或已经实现。
3. **允许多个合法结果时要有共同见证。** 对同一抽象类必须存在所有 L(x) 的共同交集；两两相容不够，也不保证唯一最粗划分。
4. **交互策略只能用实际可见历史。** 部分观察下知识状态表示仍可能的真实状态；不能按隐藏真状态偷偷选不同动作。
5. **安全和完成分开。** 最大安全固定点可能只给出“永远等待”；完成还要在安全区存在严格下降的 rank/吸引域或其他合格活性依据。
6. **观察能力是现实供给。** 数学模型里增加 sense 不会让真实系统自动可观察；提供者、权限、时序、失败和成本必须实际成立。
7. **抽象反例需要整条具体化。** 每条抽象边分别有不同 concrete witness 不足以证明整条坏轨迹真实可达。
8. **证明不产生执行权。** 正确策略/证书仍需目标供给、当前权限、资源及未结算操作检查。
9. **有限封闭域可以完整证明，开放样本不能。** 域、转移、环境、性质和方法完备时允许全称结论；挑战集“没找到反例”不能外推未知世界。
10. **成本和最优不能压成一个任意分数。** 字节、延迟、费用、作者负担、风险、ABI 损失及不同主体成本保持各自量纲；硬条件先满足，再在真实可行集上比较。

## 根原则回查

P01—P30 均继续由[原则总纲](../../产品/原则总纲与归属.md)唯一拥有。本攻击集核对后保留的关键修正是：

- **P14** 不是“任何问题都不存在全局最优”，而是 optimal 声明必须绑定候选域、目标、约束、输入/分布、成本模型和证明范围。
- **P20** 的“最小”是没有无消费者结构，不是固定原语数量最少。
- **P21** 人与 AI 都可以创作、自测和提出修正；创作能力与现实裁决/发布权限分离，只有需要独立保证时才要求独立来源。
- **P19** 重试要求因果变化；真实 Effect 的重试还必须满足稳定身份、读回/围栏与重复安全。
- **P26** 组件正确不推出系统正确，组合要核共享状态、资源、转换和共同故障。
- **P27** 明确允许在完整有限封闭域中给出完整证明，同时拒绝把有限挑战集/非完备测试升级成未知世界正确。
- **P30** 完成包括真实退役和重开条件；设计完成、实现完成、运行完成和发布完成保持不同。

其余原则没有因本轮反例被推翻；未来反例命中某一原则时，应改原则 owner 及全部消费者，而不是在本页叠加覆盖条款。

## 验收与退出

这些反例进入静态设计审查、有限数学复算、目标/ABI/并发/运行验证的相应层。拒绝所有输入不能作为“安全”正例；有限模型通过不能代签真实驱动，目标编译通过也不能代签现实权限或外部作用完成。

当某条反例的前提不在实际使用点成立，不为它激活额外运行平台；当相交时，必须能定位负责的 owner、正常路径、失败出口、恢复/迁移与验证方式。
