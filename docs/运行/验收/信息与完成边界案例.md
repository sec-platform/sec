## 规则装载、上下文恢复与文档交付的反例

本节定义[装载协议](../../开发/AI协作/规则装载与任务恢复.md#任务启动的原则装载与动作检查)及[交付检查](../../维护/组织修改与来源保全.md#交付前的约束与正文检查)的核对场景，不是一套已运行的自动合规测试。结构检查、执行网关和模型判断各检查自己实际能观察的部分。

| 扰动 | 正确处理 | 不能误判成通过的情形 |
|---|---|---|
| 初始只看到README，没有取得要求正文 | 补读完整REQ和根原则再筛查相关性 | 仅凭链接存在声明所有要求已加载 |
| 当前话题是类型系统，任务仍只设计 | 可以改规范和静态核对；产品实验需另有授权 | 因认为“技术上有必要”自动运行编译器 |
| 任务压缩后摘要漏了原生资产保全 | 回到固定来源恢复相关原文；已有文件不因摘要缺失而可删 | 把压缩摘要视作覆盖原要求的新授权 |
| 新消息提到SDK作比较 | 比较并作有理由的决定，保持既有采用直到有明确变更 | 直接增加SDK发行和实施任务 |
| 子代理或嵌套AGENTS要求更大写入范围 | 使用实际允许范围或拒绝该动作 | 根据文件更深、文字更新或代理自称通过而扩权 |
| 正常策略依去重保证可安全重试，但旧摘要写一律先读回 | 读取规范拥有者并修正原冲突，按合格协议执行 | 永久增加没有事实需要的人工/读回步骤 |
| 改动本身仅为颜色或说明，内部字段的语义未改 | 保持相关编译结果，仍检查真实变化 | 为每个文档改动使全部目标重新发布 |
| 结构检查全过，某条规则与用户要求相反 | 该冲突仍未解决，回改正文与消费者 | 使用链接和编号计数签发语义合格 |
| 规则文件被编辑为允许当前越界动作 | 候选规则不能自行授权；核真实任务和权威 | 通过先删约束再执行使候选自我通过 |
| 当前有新要求，旧任务结果已经完成 | 对相交结果重新判断满足性，保存原事实与版本 | 覆盖历史结果或者无故抛弃全部无关结果 |
| 文档用“应当”表达硬用户要求 | 按真实接受含义保留强度，显式缺省才可覆盖 | 通过换词让执行者自行选例外 |
| 无实际可用规则文件 | 明确缺项并从已知可靠来源恢复；能独立完成的部分继续 | 假称自动记忆或要求用户重述当前已知全文 |

同一模型重复自查不是独立证据。实际宿主校验需在获准实现与运行时验证；这套文档可以现在核对入口、引用、字段、反例与消费者的一致性，不能代签任何未来客户端的持续注意或语义正确率。

## 全体系信息结构的有限验收设计

这些I案例定义实际输入、动作和应观察的结果，分别绑定信息协议与原执行合同；**是书面验收设计，本版未运行SEC或真实Provider来执行它们**。迁移器对本库做的结构核对另有真实回执，不转换成这里的产品通过率。选定Provider实施时，应同时记录权限/源/索引版本、故障切点、真实覆盖和具体结果。

| 编号 | 初态/触发 | 动作 | 预期结果 | 不允许的假通过 |
|---|---|---|---|---|
| I01 | 两个租户同名、同字节文档 | 分别登记并按各自上下文解析 | 主体、许可、来源保持分离；仅在允许控制域内共享字节 | 不能自动合并后让一方删除另一方内容 |
| I02 | 同一文档移名，标题也改变 | 保留主体并更新locator与已知引用 | 旧精确锚点去向可核，普通新标题索引重建 | 不按新路径重新分配原主体身份 |
| I03 | 一个文档完整拆成多个子篇 | 按原连续区间建映射并保留必要父上下文 | 每一源区间与旧显式片段有唯一准确去向；未知外部片段明确未映射 | 不能所有旧链接都跳首页称成功 |
| I04 | Markdown含行内链接语法示例及代码围栏 | 只重写实际正文导航 | 原代码/图源字节不变，确切纠错另有前后记录 | 围栏中的#不被当标题，反引号中的链接不被当导航 |
| I05 | 两个输入配置为同一主体选择不同版本 | 尝试形成同一用途的InformationSelection | 存在明确变体/隔离时分别保留，否则返回选择冲突 | 不最后写者赢，不静默解析latest |
| I06 | 输入引用都可解析但API不兼容 | 运行有限兼容检查 | 基线候选可记录，所需构建/发布资格不成立并指出冲突 | 版本固定不等于兼容 |
| I07 | 旧发行固定归档版本，新默认已更新 | 查询旧发行及当前文档 | 分别返回准确选择；冷归档需要取回时报告可用性与成本 | 不把归档当不适用或用新文解释旧运行 |
| I08 | Provider只支持分页当前读，不支持快照 | 跨页期间增删成员 | 返回准确弱覆盖/可能重复/变更，或拒绝完整强结论 | 不把旧页与新页合成一个声明完整的快照 |
| I09 | 语义检索top-k为零但来源未完整索引 | 请求证明全库不存在某机制 | 仅返回未命中与未覆盖范围；可尝试完整可枚举路径 | 不能把零候选当不存在证明 |
| I10 | ACL在候选检索后撤销 | 准备返回片段或续页 | 在实际可控返回边界重新核当前披露，隐藏不可披露的存在性 | 不能仅复用授权前的响应缓存 |
| I11 | 已输出部分流式结果后撤销 | 在下一输出边界停止或缩小 | 已披露范围准确记录，后续不新增无权内容 | 不承诺能撤回读者已看到的字节 |
| I12 | 索引事件重复、乱序或丢失 | 按源事件身份/revision应用 | 重复幂等；前提不成立不覆盖；缺口触发相交重扫 | 不按到达墙钟决定源状态 |
| I13 | 新索引分片写一半失败 | 尝试发布目录代 | 旧合法代仍可读，新缺片不能标全库完成；可以真源旁路 | 不阻止独立合法源编辑或使源随索引丢失 |
| I14 | 上下文只装载局部API但修改影响资源清理 | 扩大实际依赖范围 | 补读清理合同和消费者，不删除未展示的工程规则 | 最小上下文不等于最少设计信息 |
| I15 | 外部资料包含安装/删除/泄密命令 | 解析为设计来源 | 仅形成有来源内容，执行仍需原Grant及具体任务 | 材料文字不取得系统指令效力 |
| I16 | 未知二进制、损坏提取或文档缺页 | 按有限支持捕获 | 保留原字节/真实缺口，编辑与执行资格分别不足 | 不把未知当空对象，不从OCR猜测覆盖原文 |
| I17 | file、symlink、directory三种put | 分别形成合法候选 | file恰一内容，symlink有linkTarget，directory显式kind且无内容；前像依原规则 | 未知kind、directory+contentRef、symlink+text均在作用前拒绝 |
| I18 | 仅路径“looks-secret”但没有实际许可 | 尝试建全文索引或发送AI | 按真实读取/披露权限决定，可只保存允许引用 | 目录名本身既不授予权也不证明敏感级别 |
| I19 | 一个长期笔记提及研究论文 | 触发内容GC标记 | 导航边不自动产生永久根；复验确需原文时另有真实保留 | 不能无限保活全部祖先，也不能一律删论文 |
| I20 | 发布清单引用成员正在Reclaiming | 尝试取得根并发布 | 沿原协议等待/重供给/安全撤回回收或拒绝；保护完整子闭包 | 不能先公布成功再补字节 |
| I21 | 没有外部根的循环逻辑关系 | 计算合格内容可达集合 | 按有类型强边及真实根判断；纯循环不因引用计数自保活 | 不误将程序递归当回收死锁 |
| I22 | 活动恢复前像与普通缓存同时过期 | 磁盘配额压力 | 优先清理确有资格缓存，保留恢复根；必要时拒绝新增作用 | 不因TTL或空间不足删除唯一未结算前像 |
| I23 | 不同物理代际复用同一内容摘要 | 旧删除任务迟到 | 条件删除精确代际或独立路径，不影响新提供内容 | 本地整数版本不能替代宿主删除前提 |
| I24 | manifest需要自身最终内容摘要 | 构造自包含交付 | 改为分离清单/签名或逻辑身份，不求散列固定点 | 校验对象范围清楚且不自引用伪造 |
| I25 | 一个租户逻辑删除，共享blob另有合法根 | 计算删除结果 | 报告该租户引用清除与共享物理字节仍存的区别 | 不删除他方合法内容，不称全物理擦除 |
| I26 | 旧备份含已撤销凭证和已删数据 | 恢复到隔离环境 | 取得当前删除/拒旧前沿，控制披露与写权；凭证按真实撤销源 | 不能从旧Grant或未连网默认恢复执行权 |
| I27 | 外部非幂等作用响应丢失 | 读取操作恢复状态 | 有真实查询/去重能力时结算；否则保留未知与有权处置 | 不换一个新操作ID重复发送以查结果 |
| I28 | 导出给新保管者但尚未确认接收 | 请求源系统释放最后根 | 保留责任，完成准确成员/访问/接受条件后再移交 | 复制一个压缩包不等于已履行移交 |
| I29 | 存储新旧服务迁移且新侧有写入 | 准备回退 | 核新格式与不可逆效果；维持单一当前写权，必要时停止相交回退 | 不无协议双写然后按时间戳选数据 |
| I30 | 生成全文HTML时只传入搜索命中的文件 | 请求声明完整阅读版 | 按固定源成员清单发现缺项，拒绝完整标签或准确标节选 | 无新HTML可以正常交付Markdown |
| I31 | 译文依据旧版，原文否定条件改变 | 传播派生失效 | 相交译文待复核，未相交译文仍可用；保留源对照 | 不能翻译流畅就默认语义准确 |
| I32 | 报告SARIF合法或来源签名有效 | 尝试采纳为产品符合证据 | 仅支持对应结构/来源性质；检查具体Claim、运行和覆盖 | 格式/签名不替产品正确性作证 |
| I33 | 制品字节相同但来源/安装环境不同 | 尝试复用旧测试 | 按具体Claim允许字节性质复用，其他性质重新核所需证据 | 不统一全部接受或无理由全部拒绝 |
| I34 | 产品导出目录残留未选资源与旧生成物 | 按ArtifactSet交付 | 仅选择准确成员；未知/foreign不悄悄打包，也不擅自清理 | 全库索引不等于发行成员 |
| I35 | 新增硬件/模型/数据媒介超出已有40类 | 进入有限保全与能力讨论 | 保留真实信息和未知，扩展实际关系与消费者 | 不得为了维持分类整齐而伪装进错误类别 |
| I36 | 结构迁移全部通过，但算法语义未全面审查 | 形成交付声明 | 报告字节/链接/范围核对与实际语义审查的各自范围 | 不得据此宣称全世界信息、全系统设计或产品验证完结 |

上述接口拥有者分别为[信息对象与配置](../../信息/对象关系与配置基线.md)、[接入检索](../../信息/接入检索与派生.md)、[保留恢复](../../信息/存储保留与恢复.md)、[文档重组](../../维护/文档身份与重组协议.md)和[资产变更](../../作者/工程源/资产与非源码.md)。每个案例只支持其限定的区分，不把有限案例数量当开放世界穷尽；新反例应首先修相交拥有者与原U状态。


### I37：空目录不能被普通文件校验和替代

初态是一个需要真正空目录的源包或发行，所选Provider能创建目录但其通常的版本控制检出不能保留该空目录。动作是在原asset-change下创建并请求后续可重建发行。期望分别报告当前创建和持久/发行能力；具备已定义且被消费者接受的资源清单/构建规则时记录其准确来源，缺失时拒绝相交强保证。不自动加占位文件；验收包含目录成员及空性，而非只核已列文件摘要。此案例是设计，未运行真实Git/发布器试验。


### I38—I47：准确引用、绑定与连续性

以下是产品符合性的书面验收设计，不是已执行结果。文档制作期间的解析、链接和字节检查只验证本包，不能转成这些产品案例的通过率。

| 编号 | 准确初态与动作 | 应观察的结果 | 失败反例 |
|---|---|---|---|
| I38 | R2固定Q@2，旧说明URL现在返回Q@3，标题/签名一样 | 阅读可给当前页并注明角色；编译取得准确Q@2或报告内容/选择缺项 | 把HTTP或本地迁移成功当合同兼容成功 |
| I39 | 原位置不可用，另一镜像提供Q@2准确字节，原解释与读取资格仍有效 | 可按该用途复用；不要求无意义地升级到Q@3 | 因位置变化一律阻断原合格构建，或跳过来源/资格核验 |
| I40 | Q@2拆成两份，只有条款位置映射而无新组合保持依据 | 导航保留全部实际去向；编译与证据继续保留相交缺项 | 自动选择首项或把新两页当原版本完整等价 |
| I41 | 方法M@2支持Q@2，Q@3同类型但改变错误和进展 | 重新核方法的真实保持范围；合格则复用，不合格则选择/创作/Needs | 只检查类型签名；或因为版本变动永久禁用所有旧供给 |
| I42 | 库根K完整，调试根D缺驱动，两根共同发行有明确要求 | K结果可保存，D缺项，共同发行未完成；共享冲突继续阻断相交部分 | 只返回全部失败，或只因K成功称整个发行完成 |
| I43 | C1使用点[2]在C2插入后移到[3]；另复制一个同参数使用点 | 按准确编辑映射保持旧主体，复制项独立；无映射明确待决 | 用下标恢复旧运行，或按内容哈希合并两个实例 |
| I44 | 同一subject经两条use传入，私有subjects各自产生 | 共同外传主体保持一致，私有主体保持不同，接受来源完整 | 两端重建两份公共模型或把私有状态合为一份 |
| I45 | 规范只改排版，但生成方法实际读取了整段自然语言定义 | 更新真实来源并按实际输入重读；仅有明确健全语义抽取时共享已证同义结果 | 人工忽略自然语言字节后称缓存仍准确 |
| I46 | 纯缓存可复用，旧读者在返回前撤权；操作随后请求写入 | 披露与新作用在真实边界重核；历史只读结果与操作责任分开 | 缓存命中或保留pin替代当前授权 |
| I47 | 只改本设计库的当前导航，目标工程未读取它 | 核对该库的当前入口与基线，不强制重编译或部署无关目标；真实自用工具依赖另记 | 把本库source_set作为所有用户ActionKey或运行输入 |

解释与责任见[信息解析](../../信息/对象关系与配置基线.md#resolution-fidelity-consumers)、[装配](../../架构/装配/源绑定与解释映像.md#qualified-binding-consumption)与[增量](../../编译/查询增量与性能.md#reference-role-invalidation)。

<a id="completion-boundary-cases"></a>
## CPL：任务、信号、导数、页与作用完成边界

下列均为**验收设计，产品运行结果未取得**。与本章已有W/I、领域算法和独立数学案例并存，不用此数量代签全库。实际验证须固定语义/目标/Provider版本、可观察调度、当前权限和预算；观测应来自独立宿主边界、精确记录或可复算要求，不能仅检查被测函数自报success。

| 案例 | 输入与受控动作 | 期望及直接反证/观察 |
|---|---|---|
| CPL01 | 执行器在start内部立即完成 | 完成找到既有登记槽；先回调后注册的实现应被记录击中；一次结果可领取。 |
| CPL02 | 域关闭与子任务启动并发 | 只有已登记者被启动并纳入必等；关闭后请求不得执行函数体；核实际执行器入口次数。 |
| CPL03 | 热Promise已发送请求才被包装Deferred | 报告已启动接管并核能力，不得自报未作用；核真实请求时序。 |
| CPL04 | 同一Own结果同时有两个领取者或重复完成回调 | 恰有一个所有权移交；重复同结果不再清理；独立新资源有独立结算。 |
| CPL05 | all的A失败，B已成功生成未领取Own | 先结算活动使用再清理B一次；原已发行B不属于临时值不得删除。 |
| CPL06 | 两组合等待同一共享任务，一组合失败 | 只撤自己的等待关系，另一组合仍能完成；要求取消共享任务时须真实委派。 |
| CPL07 | race首成功遇失败先到，另一路稍后成功 | 不中途按首终态政策失败；所有路失败才集合失败；空race启动前拒绝。 |
| CPL08 | 子任务返回T=Result中的Err，但方法不映射为TaskFailure | 它是Success(T)数据，不能自动取消兄弟；明确改变方法后才改变组合解释。 |
| CPL09 | cleanup同时失败且外部取消已到 | 保留原退出原因和次要清理/取消事实，不以内部兄弟取消吞外部取消。 |
| CPL10 | 不响应任务仍借用父栈，尝试转移监督者 | 不得使父帧返回；真实停止、保留原帧或合法可移实现才成立；核悬空访问反例。 |
| CPL11 | 主体返回后已登记子任务建立自身嵌套域 | 嵌套域在子任务退出前结算；不能向关闭父域补登记，也不拒绝独立活动子域。 |
| CPL12 | 子任务join包含自己的父域，或所有worker占槽等待孩子 | 已知自等待拒绝；等待释放执行槽并保留续体内存，不能仅靠加超时假正常。 |
| CPL13 | mapOrdered的1先Fault、0后Value，信用足够 | 可观察为Value0再Fault1，无正常End；核输出序而非完成回调序。 |
| CPL14 | mapOrdered的1先Fault、0后Fault | 只以最早可观察位置Fault0终结，Fault1保留诊断范围；不可先报1。 |
| CPL15 | 头部未完成且后部失败，调用方预算到期 | 终结为实际预算/取消并说明已发前缀，不伪造更后数据失败提前出现。 |
| CPL16 | Data(t=2)后有Frontier(10)，映射尚未完成，后面还有Data | Frontier既受前面cut阻挡，后续Data也不得越过该控制；改变timeOf另核下界，不能把合法2当后来迟到。 |
| CPL17 | 很多窗口同时Final且无新增信用，随后End | Final保持有界/暂停，End不越过它们；取消可结束但不声称完整Final已送达。 |
| CPL18 | 余额0不申请；另一路已grant 2后停止新增；再单测request(0) | 第一种暂停，第二种仍可交付原额度；第三种协议错误，不作暂停/撤信号；不影响另一独立订阅。 |
| CPL19 | 信用相加溢出或控制信号无限快 | 不变为负数/无限；按真实可表示计数与控制预算分段或拒绝，核峰值占用。 |
| CPL20 | Data回调同步request/cancel，恰逢排空者退出 | 串行排空不无限递归、不丢唤醒；cancel后不再认领新通知，之前已认领者单独结算。 |
| CPL21 | x=1,dx=1e308；f先2*x再1/(x-x) | 原值y可表示、dy越界、随后原除零，返回PrimalFailure；记录derivative次要问题。 |
| CPL22 | 同输入但f仅2*x | 原值成功而切向越界，返回NumericFailure；不能补零或伪成功。 |
| CPL23 | 先切向失败，后续primal无限循环直到预算 | BudgetExceeded/中断，不能说原值成功；主程序不被为找PrimalFailure无限续命。 |
| CPL24 | 未选非法分支、stopGradient或不活动导数 | 不人为计算无用导数制造Fault；可观察的原值失败仍不得消除。 |
| CPL25 | VJP原值成功但tape或反向累加预算/数值失败 | 分阶段记录，部分cotangent不成功；检查点须保持固定原状态。 |
| CPL26 | 外部黑盒JVP先抛导数错误且原状态已丢 | 不宣称满足原值优先；选择有资格分离实现或准确缺项，不盲重跑有观察f。 |
| CPL27 | Provider重复返回同一请求页 | 有序页身份去重，不重复条目/证据；同字节不同主体或bag出现仍保留。 |
| CPL28 | 返回空页但token实际前移；或空页同token无限重复 | 前者可继续且不误判Exhausted，后者无进展停止并留缺口。 |
| CPL29 | A=[a,c]，B暂无头或下界；请求全局前2 | 不把[a,c]当确定首屏；B=[b,d]后结果[a,b]，c,d进入续页缓冲。 |
| CPL30 | 已预取页但只展示一半，下次继续 | 先消费准确未显示缓冲，不因底层token已前移而跳过它；缓冲丢失使强续页失效。 |
| CPL31 | 分页间来源快照过期或改变比较器/locale | 拒旧cursor或新建明确查询，不混旧新仍标同一完整排序。 |
| CPL32 | 同排序键多个主体/出现；Provider主键有序但平局无序；不同搜索引擎分数 | 完整比较器保证或收齐同值段后排序才形成确定前缀；超预算准确停止；无校准不把分数当同量纲全局排序。 |
| CPL33 | 一源完整、一源仅top-k且无完整枚举能力 | 可返回实际局部内容，不能全库否定/穷尽；显示limit不替源覆盖。 |
| CPL34 | 预取后撤权或另一任务替代当前槽 | 输出时核披露与结果代，禁止泄露内容/计数；合法共享计算不因此全销毁。 |
| CPL35 | t0提交A,t1超时,t2强读无,t3想提交B | 只有点时不存在仍阻止自动重发；允许目标有效去重或关闭旧尝试后的无效果依据。 |
| CPL36 | 本地租约更新/取消已受理，但请求已越过最终准入 | 不可声称旧尝试关闭；目标实际终结或覆盖该工作的拒旧依据才充分。 |
| CPL37 | 确切关闭所有旧尝试，其后权威证明全效果未发生 | 当前许可/前像成立后可以新尝试完成原意图；不能永远拒绝合法恢复。 |
| CPL38 | 同意图有效目标去重，尚无法知道旧请求是否结束 | 可按同键原载荷继续；不能无条件要求先无效果证明，核目标实际一个业务结果。 |
| CPL39 | 键仅发送时有效，可能到达时已被清理 | 未有拒旧/关闭时不能保证自动重发安全；不臆造固定TTL或网络上界。 |
| CPL40 | 目标当前已等期望但曾额外通知/增版本/收费 | 按ProtectedConvergence的实际许可判断，值相同不签exactly-once及历史无作用。 |
| CPL41 | 资源由原意图创建成功后被他方删除，再查无 | 保留历史成功；再次创建属于新意图与当前授权，非恢复原请求。 |
| CPL42 | 关闭集合后另一持有者试图重新提交旧尝试 | 同operation/实际拒旧协议阻止；仅本地锁不被当跨端点证明。 |
| CPL43 | 上述语义由并行改串行，源和目标正常结果相同 | 比较失败次序、控制cut、资源移交与覆盖，不只比成功字节；允许较小合格实现。 |
| CPL44 | 旧产物仍运行，新候选只改CLI消息 | 旧活动/诊断仍绑定旧产物，独立库和AD分析按实际依赖复用；新源不解释旧栈。 |
| CPL45 | 只做同步纯函数或单一本地直接读取 | 不初始化任务域、AD、远端恢复日志或多Provider协调；检查性能/资源前置未被虚构。 |

规则拥有者依次为[任务域](../../领域/计算基础/通用计算与任务语义.md#structured-task-lifecycle)、[流](../../领域/状态关系与流/背压与事件时间.md#ordered-stream-control)、[AD](../../领域/数值/自动微分与线性化.md#ad-fault-precedence)、[页组合](../../信息/接入检索与派生.md#provider-page-composition)与[尝试关闭](../持久化提交与恢复.md#attempt-finality-and-retry)。跨方法的结果政策不要求相同：all先观察的失败、有序流按输入位失败、JVP原值优先、信息的完整性与外部作用的未知，各自承担不同承诺。它们通过有类型结果接合，不归成一个无限扩展的万能错误枚举。
