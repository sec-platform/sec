## 完整开发面DEV01—DEV48：正常操作、能力不足和恢复

下表是**未运行的产品验收设计**。每项在实际实现就绪后，从同一固定源/目标/环境执行，观察对应作者内容、候选、真实作用和结果；不能用界面能打开、JSON可解析或本文表格存在宣布通过。使用[连续开发范本](../../../examples/连续开发/全工程连续开发.md#developer-surface-walkthrough)，需要更多机制时采用原大型SEC/Code-OSS和领域范本，不靠一个小函数代签全系统。

| 案例 | 触发与实际操作 | 独立期望与核验办法 |
|---|---|---|
| DEV01 最小新源 | 无工程目录/后端，提交完整有限.sec模块 | 可保全和合法源检查；无目标不标已生成；检查未启动数据库/调试器/安装程序 |
| DEV02 模板效果 | 新项目模板含静态资源及初始化脚本，目录已有用户文件 | 先生成冲突/作用计划，获准才运行；逐成员核原内容保全，不以模板名取得执行权 |
| DEV03 多根和缓冲 | 两根同名模块，打开文件缓冲不同于磁盘 | 按各解析域和缓冲修订捕获；不混用类型/磁盘旧诊断，读取覆盖有依据 |
| DEV04 新原生文件 | 使用简单files新建.ts，并用合格原生捕获对照 | 前者准确不支持/解释缺项，不猜语言；后者保持真实TS且无.sec镜像 |
| DEV05 保存不重复 | 编辑器已保存同一变更后检查/生成 | 直接捕获，不再apply或覆盖现场；比较实际写操作次数及前像 |
| DEV06 请求分支 | source+base与source+context、base+edits分别解码 | 错误联合拒绝，两个合法分支按各自基础处理；不能因客户端不同而宽松接受 |
| DEV07 短源推导 | 使用show lambda和真实levels定义，查询推导签名 | 类型/效果来自真实定义；保存仍是原短源，不自动另写展开签名/JSON程序 |
| DEV08 局部覆盖 | 改单次参数、定义级默认和撤销局部控制 | 真实作用域各异；撤销回到原继承源，null不被当通用重置；核全部真实消费者 |
| DEV09 补全附加编辑 | 选择需加入import的补全 | 主插入与附加编辑形成同一候选并复查；不留半完成源码 |
| DEV10 过期补全 | 提示返回前用户修改当前位置 | 前像变化返回重解/冲突；旧offset不得覆盖新字，普通源继续可编辑 |
| DEV11 公共重构 | 更名公开函数且存在动态/外部调用 | 精确引用更新，未知外部范围明确；保留兼容门面只声明真实范围，不按文本计数说无引用 |
| DEV12 格式与初始化 | 含效果导入、未知扩展和非法区的源执行整理 | 保持有语义顺序与不支持原文；受限方法不全文件重印，比较实际前后字节 |
| DEV13 草稿保存 | 尚未更新调用方的公开更名草稿 | 可保存原文及当前诊断，不用旧AST替代，不标可运行通过 |
| DEV14 分区空诊断 | A生产者局部空，B仍有错误，A另分区未完成 | 只清A真正完整覆盖的对应旧分区；B和未知范围不消失 |
| DEV15 晚到诊断 | C1慢结果在C2当前检查后返回 | 保存为C1结果，不清C2错误；核主体/发布代而非内容文本 |
| DEV16 期望独立 | 修复候选尝试删失败例或放宽阈值规则 | 展示要求改变及新候选，不自动采纳；旧反例/验收不被覆盖 |
| DEV17 循环修复 | 两修复轮流改同一表达式回原样 | 识别无进展/策略冲突，保留所得候选和原因，不按重试次数声称改善 |
| DEV18 部分采纳 | 只选接口变更、不选必须调用方修改 | 重新物化与检查；可留非法草稿但不可称组已可运行；独立说明变更保留 |
| DEV19 依赖升级 | 请求升级一个包，解算牵动传递包/目标 | 准确差异及消费者；未请求但必须改变的依赖显露，原生锁不双写 |
| DEV20 按锁安装 | 已有活动node_modules被其他运行使用，准备方法会清目录 | 隔离/停机方案须具实际条件；不得破坏其他会话环境，锁定不被说成无作用 |
| DEV21 离线与缺工具 | 网络不可用、某调试器缺失但源工具可用 | 独立源检查/已有内容工作继续；准确环境缺项不标源错误或重写语言 |
| DEV22 懒测试目录 | 父测试节点未展开，用户选全部 | 取得完整相交发现或报覆盖不足；不把当前已加载几个孩子当全量 |
| DEV23 发现执行 | 参数工厂/配置导入会写文件或访问网络 | 查询不暗中运行，发现作为获准工具作用；拒绝时保留准确测试能力缺项 |
| DEV24 零与跳过 | 框架exit 0却零测试/全部被过滤/跳过 | 返回无适用或未满足范围，不凭退出码PASS；核原覆盖义务 |
| DEV25 参数例身份 | 同名案例参数集合变化或重排 | 按准确实例/源辨别选择，旧序号不串用；新casesRef反映真实变化 |
| DEV26 复跑与波动 | 首次失败后重跑通过，fixture或seed变化 | 保留每attempt与环境变化；不抹首次失败，不把不同实验当同次验证 |
| DEV27 覆盖与基准 | 只插桩一部分，调试运行参与性能比较 | 分母和未测范围准确，插桩/调试基线不同；不把覆盖当正确性证明 |
| DEV28 多根生成 | library成功、CLI缺资源，只重生library | 分根结果，旧CLI及人工区不删；任务AND仍有缺项 |
| DEV29 运行参数 | 只改这次level输入/环境变量 | 新argumentsRef/运行，不改源阈值或旧运行；输入验证不执行程序猜类型 |
| DEV30 旧调试源 | B1运行时作者生成B2，再读B1暂停栈 | 仍绑定B1对应源；旧PauseRef不跨新暂停，优化掉值明确不可用 |
| DEV31 输入重复 | 相同requestId/inputRef重试但输入头已推进 | 读回原接纳结果，不重复发送；同ID不同字节冲突 |
| DEV32 短写未知 | input部分已发，随后确认丢失 | 仅已知后缀可续发，未知不整段重发；forwarded与consumed分开 |
| DEV33 竞争与关闭 | 两客户端用同输入头写，随后关闭 | 仅一新意图先获接纳；close按队列有序且关闭新准入，不静默丢旧字节 |
| DEV34 输出范围 | stdout/stderr并发且收集额度用尽 | 独立流顺序/缺口真实，不能伪造全局精确交错或完整输出 |
| DEV35 控制结束 | signal被接收但目标/子进程未停 | 状态与资源仍未结算；不得释放在用资源或把父终端关闭当全部停止 |
| DEV36 监听回路 | 生成文件触发自身watch，期间源暂时非法 | 按来源阻止自触发循环；新诊断准确，旧运行标旧版，不自动安装/发布 |
| DEV37 共享任务退出 | 两客户端共享检查，一方关闭 | 只撤对应等待；另一方结果与资源有效，未决操作不因页面关闭丢失 |
| DEV38 部分暂存 | 同文件index和worktree不同，另有无关暂存内容 | 按选择产生提交候选并保全无关index；没有隐藏stash/reset/stage-all |
| DEV39 过滤及hook | clean/编码过滤或hook改变提交blob | 取得最终内容与副作用，重核相交检查；旧工作树检查不代签新tree |
| DEV40 树与历史 | 同tree不同commit，构建使用commit/describe/归档信息 | 历史输入变化触发相关检查；内容证据仍可在实际范围复用 |
| DEV41 合并竞争 | 准备后目标ref被他人推进 | 预期条件失败或新集成候选，不force覆盖；多ref读不假装全局快照 |
| DEV42 推送未知 | 远端可能成功但响应丢失，本地又有新工作 | 查原意图与远端事实，不盲重发或reset本地；当前状态与历史执行分开 |
| DEV43 撤销的层 | 分别舍弃草稿、反向保存、revert和补偿外部作用 | 使用各层真实合同，不能删除回执伪装从未发生；第三者新内容不覆盖 |
| DEV44 目标回源 | helper一对多或原前像已改时编辑生成代码 | 保全目标草稿/冲突，取得准确来源；不将生成目录另设可写真源 |
| DEV45 AI交接 | 子代理报告成功但无源/证据，日志带命令，模型换会话 | 核真实候选和回执、拒绝指令提升；以必要准确引用继续，不要求重建全私聊 |
| DEV46 秘密与权限 | 运行需秘密，随后撤权，旧诊断/输出待返回 | 引用经当前资格消费/披露；不在菜单、计数、日志或输入记录泄露秘密 |
| DEV47 工程画像 | 浏览器仍缓存旧bundle，或设备运行旧安装镜像 | 开发服务器/构建成功不代表目标已加载；显示真实运行/资源和来源，原动作可继续 |
| DEV48 多客户端与较小路线 | 相同源由文件/六工具/SDK进入，无GUI环境 | 在共同支持范围产生同义候选和结果阶段；内部台账不成为作者必填，未提供宿主能力如实返回 |

这些用例配合原语义与恢复案例验证接合，不替代高级跨语言、资源重构、平台UI/设备/数据库自身的独立符合性。全自动工作是否更省维护/时间，应在首次、二次、失败恢复和换人四类实际任务中比较：作者维护内容、真实工具/模型交互、等待、重做、依赖成本与最终保证都计入；不能把省略未完成工作计为性能提升。

## 跨协议、Provider与运行观测攻击组

这些反例专门攻击“外部工具接上以后，SEC自己的身份、权限、证据和恢复语义是否被协议字段偷换”。它们是设计验收，不报告已运行。

| 攻击 | 错误实现会发生什么 | 必须保留/拒绝的结果 |
|---|---|---|
| 未保存buffer为C2，但LSP/索引结果来自磁盘C1 | C1诊断/definition覆盖当前编辑器 | 保留C1来源并拒绝贴成C2；重取或重新分析相交范围 |
| 跨仓SCIP/搜索只覆盖部分依赖 | 搜不到引用就宣布“无外部消费者” | 返回not-observed-within-coverage；没有封闭依赖全集不得签发全局否定 |
| BSP/构建服务重用target/session字符串 | 新构建被冒认为旧Artifact/Target | 外部ID只作provider locator；SEC主体和revision另行绑定 |
| feature evaluation的before hook先写遥测，随后resolver报错 | “flag读取”被当纯query并可随意重跑 | 作用进入execution/Observation并结算；失败不擦除已发生hook Effect |
| policy返回allow但调用方绕过/未执行enforcement | allow被报告成操作已授权且已发生 | decision、enforcement和Effect分开；缺receipt只保留决定事实 |
| 一个现实事件被broker重复投递两次 | 两次delivery被冒认为两次业务occurrence | occurrence/event-record/delivery/Effect分别有身份和去重合同 |
| profile文件可读但debug symbols属于另一构建 | 样本按同名函数强行归到当前作者 | 保留runtime/artifact层样本并标symbolization不合格，不伪造作者热点 |
| record/replay包含一次已付款运行 | replay调试再次发送付款 | 只重放被记录计算；外部Effect仍引用原operation/readback，禁止从trace复制执行权 |
| 外部Agent/MCP task暂停后原Grant被撤销再恢复 | 旧task/session id复活旧权限 | 任务句柄只定位工作；每次Effect按当前Grant重新准入 |
| ReqIF/SysML外部源已换revision但本地映射仍旧 | 同名requirement/model被偷偷替latest | 旧映射标stale或继续绑定旧revision；不得按名字替换 |
| 制品有有效Sigstore签名但build provenance缺失/不匹配 | “签名有效”升级成可信构建/正确产品 | 只支持签发者/签名完整性Claim；构建来源和产品保证继续缺项 |
| Provider自报supports/compatible且自己的测试全绿 | Provider给自己签发产品资格 | 自报只作候选事实；符合性和产品Claim需要独立Oracle/读回/相应证据 |
| 外部协议缺字段，adapter自动补default并导出 | 派生default被写回成“源明确声明” | default保留映射来源/用途；不得取得作者或外部authority |
| 有损投影导出→导入后可见字段逐字相同 | round-trip被当无损证明 | 比较omitted/unsupported语义与原主体；往返相等不恢复未表示的evidence/authority/unknown |

攻击通过的标准不是所有外部工具都拒绝，而是每项事实只提升到它真实支持的层级；已有合法部分继续可用，未知和未决不被空集合或成功码吞掉。

## 交互工作台状态错贴攻击组

| 攻击 | 错误实现 | 正确结果 |
|---|---|---|
| Notebook cell从C1改成C2但未重跑 | 旧output显示为C2当前结果 | output继续绑定C1对应execution；C2为未执行或另有状态 |
| kernel真实执行顺序1→3→2 | 按文档cell顺序重建变量状态 | 运行状态按真实attempt/order；文档顺序只是表示 |
| kernel重启后execution_count重新从较小值开始 | 用prompt编号合并新旧运行 | kernel birth/session参与身份，旧引用不跨重启复用 |
| 两个frontend共享kernel | parent message被当作者ownership | client session、kernel state、workspace author source分别归属 |
| SQL控制台点Analyze执行 `EXPLAIN ANALYZE UPDATE` | 认为只是计划查询而无Effect | 按Provider语义作为真实执行；数据库与事务外Effect分别结算 |
| HTTP client重复发送相同request文本 | 文本相同就当同一操作 | 每次attempt独立；仅目标真实idempotency/operation identity允许合并 |
| devcontainer配置被读取 | 自动执行Feature安装/lifecycle script以“解析环境” | 读取只产生配置事实；materialize/install/start另经operation准入 |
| 远程环境rebuild但旧language-server结果迟到 | 旧环境诊断覆盖新generation | 结果绑定原Environment/Provider session；新环境重新取得资格 |
| 删除开发容器 | 同时删除bind-mounted源码/volume/云资源 | 分别按真实ownership/Provider结算，不从容器删除外推 |
| SBOM命中CVE但当前路径不可达 | CVE存在即产品可利用 | 漏洞存在与exploitability assessment分开；保留依据和失效条件 |
| VEX写not_affected后feature/config改变 | 旧VEX永久豁免 | 相交assessment stale并重新评价，不改写历史VEX |
| 供应商VEX与独立reachability测试冲突 | 只保留最后一个state | 两份assertion/evidence并存并按Resolution/assurance裁决 |
| ML实验别名best指向新模型 | 历史结果自动解释为新权重 | run/metric仍绑定原ModelRevision；alias变化只影响新选择 |

## 实时协作与冲突攻击组

| 攻击 | 错误实现 | 正确结果 |
|---|---|---|
| 两个客户端并发改同一属性，CRDT选择确定性winner | winner被当成业务裁决 | 保留provider conflict/两侧来源；语义候选未裁决，只有明确Resolution后才消失 |
| 两人改不同文件但共同破坏一个公开接口不变量 | “不同文件”自动判可合并 | 按semantic read/write/constraint闭包检测冲突，文件边界不签独立性 |
| 两人在同一文件改精确不相交区域 | “同文件”一律串行/冲突 | 能证明局部与共同约束独立时允许合并，仍重算实际语义 |
| presence超时 | 自动释放业务Lease或认定作者退出 | presence只陈旧；真实Lease/ownership按自己的lifecycle结算 |
| CRDT actorId或head hash与另一个项目碰巧相同 | 被当全局Subject/Revision | 仅Provider-local locator；通过workspace/candidate映射取得正式身份 |
| 离线副本删除对象，在线副本继续编辑旧对象 | reconnect后last-write-wins复活或丢删除 | tombstone/identity/权限与当前候选共同解析；未知保持冲突，不靠墙钟裁决 |
| CRDT“撤销”一个编辑 | 推断远端Git提交/外部Effect也撤销 | 只产生协作层后继变化；VCS与现实Effect分别处理 |
| review UI只展示最终收敛文本 | 被覆盖的并发意图不可见 | review可取冲突来源/候选和semantic diff；显示简化不能删除工程事实 |

## 运行保证、告警与事故攻击组

| 攻击 | 错误实现 | 正确结果 |
|---|---|---|
| telemetry collector断流，查询无样本 | 空结果被当正常0 | coverage/collection failure为unknown，不签健康 |
| firing alert被silence | silence被当问题已消失 | AlertInstance仍firing，只是Notification被抑制 |
| 多个alerts被group/dedupe成一个page | 只剩一个故障事实 | 原alerts分别保留，notification只是聚合投影 |
| receiver返回200但人未看到 | 发送成功被当incident已ack | provider receipt与目标/人工ack分别观察 |
| SLO超标 | 直接宣布根因是最近部署 | 只形成SLO violation；根因需timeline/对照/其他evidence |
| 用户事故发生但现有SLI全绿 | 宣称“没有事故” | 保留未覆盖影响；SLI coverage不足 |
| rollback operation成功 | 自动关闭incident | 重新观察用户/服务状态，残余未知继续存在 |
| alert resolved但用户仍受损 | 自动判恢复 | alert状态与RecoveryClaim分离 |
| postmortem写“已修复”但action未部署 | 文档文字成为完成证据 | corrective action走真实candidate/check/operation/readback |
| 修改SLO过滤/窗口后budget恢复 | 不同定义拼成同一历史 | 新SLO revision；跨revision比较需明确映射或重算 |

## 外部策略、身份、事件与Agent协议攻击组

| 攻击 | 错误实现 | 正确结果 |

| `.prettierrc.js`/plugin含顶层文件或网络操作 | 作为“纯格式化”在高权进程直接require | 按Provider执行/沙箱/权限边界处理，可执行config不是数据 |
| range formatter请求10—20行却返回全文件edit | 静默重写无权区域 | 展示真实expanded write set；无相应写权则拒绝/缩域 |
| 用户继续输入C2，C1的format-on-save迟到 | C1格式结果覆盖C2 | 结果绑定C1并陈旧，不写latest |
| 保存未请求format | 自动统一quotes/EOL | 普通save字节保全；format是显式Candidate |
| formatter A与B每次保存相互改写 | watch/save无限振荡 | 固定owner/pipeline并验证稳定性，检测循环后停止 |
| Organize Imports删除“未使用”side-effect import | UI当排版直接应用 | 走semantic edit，核module side effect/框架/动态消费者 |
| remove-unused依静态分析看不到模板/eval消费者 | 合法import被删除 | Provider不具备相交闭包时保留或要求显式依据 |
| formatter删/移动 `@ts-ignore`、pure/directive comment | 认为注释都不影响语义 | 指令性trivia按语言/工具语义保护和重验 |
| generated TS被另一个formatter改，regen又恢复 | 目标反复漂移 | formatter进入generator布局合同或明确仅最终目标阶段，不建第二作者 |

## File watcher、Atomic-save与Fresh-instance攻击组

| 攻击 | 错误实现 | 正确结果 |
|---|---|---|
| 初次扫描结束后、watch真正生效前文件改变 | 永久漏掉变化 | 用同步cursor/cookie或重叠重扫闭合竞态；否则保留unknown |
| 编辑器temp+rename原子保存 | event序列被当真实rename identity | 事件只触发重观测；按physical/source correspondence判连续性 |
| Linux/macOS watch旧inode，文件删后同路径重建 | 继续等旧watch而漏新文件 | 识别replacement并重建subscription/baseline |
| watcher buffer overflow | 继续从下一event增量前进 | 自上次可靠cut起coverage失效，按scope完整重扫 |
| Watchman/Provider返回fresh instance | 空/全new结果被当真实delta | 视为cursor历史不可用，重建current observation与依赖 |
| 同一次保存产生Created+Changed+Changed | 运行三次全编译 | 可以合并invalidation，重读一次真实内容 |
| 两次真实快速写被debounce成一个event | 认为只发生一次作者operation | 最终current bytes可重读；需要中间状态的任务必须有更强journal/editor source |
| filename=null或Provider只给blanket change | 猜最近文件 | 扩大重观测范围，不伪造具体路径 |
| watched root被move/replaced | 旧subscription被当同一workspace | 新root physical identity→新subscription generation+baseline |
| watcher停止 | 推断停止期间文件不再变化 | 只结束通知覆盖；重开前重新建立基线 |

## TLS、PKIX、mTLS与0-RTT攻击组

| 攻击 | 错误实现 | 正确结果 |
|---|---|---|
| CA可信且链有效，但SAN是别的服务 | “证书有效”就建立目标service identity | path valid与reference↔presented identifier match分别检查 |
| SAN匹配目标名，但链到未信任CA | 名字对就接受 | 服务名匹配不能替代PKIX path/trust qualification |
| Common Name看起来等于host、SAN不匹配/缺失 | 继续用CN兜底 | 按采用的RFC 9525/application profile验证明确identifier，不猜自由文本CN |
| OCSP响应曾为good但已超freshness | 永久缓存not-revoked | 绑定status method/response validity，过期后按当前policy重取/降级/阻断 |
| OCSP unknown | 当作good或业务Deny二选一 | 保留certificate-status unknown，再由本用途revocation policy裁决资格 |
| mTLS client cert含role=admin文字 | 自动生成Admin Grant | credential identity与业务Principal/role mapping及Grant分开 |
| sidecar mTLS到后端 | 后端把sidecar当最终用户 | 只认证sidecar/workload；最终caller需独立可信映射 |
| TLS 1.3 session ticket来自旧合法证书，之后证书/Grant撤销 | resumption永久沿旧资格 | ticket绑定原auth context并受当前session/revocation/business policy重新判定 |
| active TLS connection建立后trust root被撤销 | 修改trust store就声称旧连接已经停止 | 历史握手不改写；需要终止/reauth则执行实际控制并readback |
| 0-RTT中发送付款/删除 | TLS加密被当anti-replay | 只有真实业务idempotency/anti-replay资格才允许该Effect进入0-RTT |
| server拒绝0-RTT后TLS库/客户端自动重发 | 同一业务Effect可能重复 | 应用按original operation/attempt决定是否重发并保持去重身份 |
| proxy终止用户TLS后向服务重建TLS | 后端peer cert被当用户证书 | 两段TLS各自认证；原用户identity通过独立受信链映射 |

| DF10 增量同步断档 | 缺失中间缓冲版本却收到新增量 | 重取该实例准确全文，相关候选重建；不贴最近字符串 |
| DF11 同路径新实例 | 文件关闭删除重建后得到相同路径和内容 | 旧位置/计划不自动认新实例；实际身份映射合格才接续 |
| DF12 位置单位 | A😀B行中UTF-16位置3和2，UTF-8位置5 | 3和5都定位B；2截断代理对拒绝，CRLF中间字节不作为任意列 |

| DF17 计划期中到期 | 已合法取得并占用计划，处理期间TTL到期 | 阻止新使用但不回收正在使用的源；完成按正常责任释放 |
| DF18 补全和import | 主插入需要另增一个导入 | 同候选/同原版本物化；只接受一半只能是草稿，不能标完整补全 |
| DF19 模板占位 | snippet还有未填参数 | 可保存未完成源，不执行占位、不填0/Any冒充完成 |
| DF20 辅助外部command | 语言服务建议completion.command运行安装脚本 | 不在query中执行，给实际效果缺项并走独立准入 |
| DF21 辅助越权 | query完成后、结果披露前撤销访问 | 按当前资格拒绝/净化，缓存命中不越权，不泄露隐藏名字/计数 |
| DF22 改签名实参顺序 | f(logA(),logB())从a,b换成b,a | 按原求值顺序绑定后调用，或拒绝保持式重构；不得变成先B再A |
| DF23 删实参有作用 | 被删参数表达式会写日志/抛错 | 保持实际求值或明确行为变化，不能直接删计算 |
| DF24 默认表达式阶段 | 默认值在被调函数每次计算，拟移到模块常量 | 保持次数/错误/捕获；无法保持则拒绝纯重构 |
| DF25 新增必需参数 | 公开函数新增需要真实策略的参数 | 补实际消费者/要求；不自动null/0/false凑类型 |
| DF26 公开未知消费者 | 反射调用、插件或外部使用未完整枚举 | 静态已知修改保留，公开完整性不宣称；可明确兼容路径或未完成 |
| DF27 格式化未知token | 原生预处理、注释指令或不完整区域 | 保留未解释内容，合格完整容器可格式化，不能删后生成绿色 |
| DF28 导入初始化 | 无被引用名字的纯副作用import | 不因unused删除；排序需证明初始化保持，不能只按字母序 |
| DF29 完整空诊断 | 生产者A对模块a返回完整空，B对b仍报错 | 只清A/a对应版本；不能清B/b或全工程 |
| DF30 迟到/崩溃诊断 | C1空结果晚于C2错误，或检查器进程崩溃 | C2仍有错误，崩溃标失败/陈旧，不能转空PASS |

| DF33 动态测试发现 | 扫描时会导入用户模块并写文件 | 只读发现不执行；明确获准运行已准备发现入口后才能形成实际casesRef |
| DF34 参数化/同名案例 | 两个同名测试或一次参数化多实例 | 按实际定义/出现身份区分；名字不能合并结果 |
| DF35 发现与运行不一致 | 固定发现集合后运行器新增/漏注册用例 | 记录差异及未执行范围，不默改选集后称完整 |

| DF37 失败后重跑 | 同一测试先失败后通过 | 保留尝试和环境，标不稳定/准确范围，不抹去失败分母 |

| DF40 改快照期望 | AI把失败snapshot替换为新输出 | 识别接受依据变化，不能自动称原缺陷已修；需要真实变更目的 |

| DF42 跨文件语义冲突 | 两个代理分别改公共接口与另一文件调用 | 联合候选核共享读依赖；不同路径不算独立 |
| DF43 hook后变字节 | CI/提交前hook改变实际源/资源 | 新输入重新绑定检查，旧证据不贴新提交 |
| DF44 worktree共享设置 | 并行工作树修改共享配置或引用 | 按真实共享范围处理，不把目录隔离推为完全隔离 |
| DF45 两根成员 | 只生成library而cli旧文件仍被合法运行使用 | 不删除未选cli，部分成功显露；共享成员需协调 |
| DF46 生成目标手改 | 修改generated TS条件，回源非唯一 | 保留草稿和选择；有确定映射才改唯一作者并再生成 |
| DF47 旧运行定位 | B2暂停时作者已C3/B3 | 栈和source绑定B2；新断点重映射/验证，旧验证不代签 |
| DF48 profile口径 | 加插桩后变慢或少采样 | 记录方法/开销/缺口，不能与无观察运行直接比较并宣称回归修复 |
| DF49 离线依赖 | 锁定版本未缓存、发现相近版本存在 | 源草稿可继续；构建缺项，不默装或换版本 |
| DF50 动态配置 | 补全配置字段需要执行任意代码 | 合格静态部分可返回，执行另准入；不得按config文件名免检 |
| DF51 全工程资源 | API改名需要消息、README、图标/引用及测试更新 | 按真实消费者同批评估，SEC不做GUI不等于目标UI资产无关 |
| DF52 AI无进展 | 相同基础/错误/补丁反复尝试 | 停止相同重试，调整解释/取得真实新输入或报告具体阻塞，独立工作继续 |
| DF53 发版响应丢失 | 已有requestId的发布不知是否完成 | 按原意图查回/合格重试，不能新ID发送来测试效果 |
| DF54 迁出/会话继续 | 关闭可选服务后仍需作者源和历史说明 | 真实导出/保留源与依赖，短引用不当永恒身份；未结算责任另续 |
| DF55 有限退出策略 | 普通partial查询与明确要求完整的partial查询 | 前者可正常0并显露partial，后者1；仅请求异步启动且已受理可0，要求完成但未结算为1；非法2、无可靠响应3，不把数字当总保证 |
| DF56 禁入负担 | 一个小函数被要求建graph、安装调试器或填全IR | 沿普通源+原工具完成；辅助/GUI/数据库/第二语言不成为强制前置 |

同一任务至少比较直接文本/库/脚本路径和已支持的辅助路径；没有薄编辑器实现时不虚构GUI结果，已支持某编辑器时另核其版本/能力。围绕基础C1、后继C2、当前C3、生成G和真实运行O排列迟到/取消/变更，观察实际字节、引用、阶段与授权，不能只看最终一个success。验收的统计分母包含失败、拒绝和无法完成任务，冷暖成本不混合；源码少、协议短或表格条数不是开发收益证据。
