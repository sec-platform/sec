## 实验、灰度发布、现场证据与因果推断

### 1. 上线观察需要因果边界

指标变化可能由季节、流量、用户构成、外部事件和其他发布共同造成。相关性不能自动证明新设计有效。

### 2. ExperimentPlan

```text
ExperimentPlan = exact {
  hypothesisAndClaim,
  populationAndEligibility,
  assignmentMethod,
  treatmentAndControl,
  primaryAndGuardrailMetrics,
  sampleAndDurationPolicy,
  contaminationAndInterferenceModel,
  stoppingAndRollbackRules,
  privacyAndRiskConstraints,
  analysisMethod
}
```

### 3. 灰度

canary/ring/feature flag 限制 blast radius，但必须代表关键环境和用户。只选健康内部流量会低估风险。

### 4. 干扰

用户之间、服务之间和缓存/模型共享会违反独立样本假设。需要 cluster assignment、switchback、时间序列或其他适当设计。

### 5. 守护指标

性能收益不能以错误率、安全、隐私、可访问性、成本和长期维护恶化换取。硬边界触发立即停止。

### 6. 现场证据

现场 evidence 有时间、版本、环境、流量和选择偏差。它可以升级或降级 SupportClaim，但不能无边界外推。

### 7. 验证

样本比例不匹配、提前停止、指标操纵、新奇效应、组间溢出、数据缺失、分群伤害、回滚失败和并发发布。


## 性能、容量、尾延迟、资源与成本真值

### 1. 性能 Claim 必须绑定场景

```text
PerformanceScenario = exact {
  userOrOperationGoal,
  exactInputAndScale,
  environmentAndResourceClass,
  correctnessAndVerificationOutcome,
  workloadShape,
  concurrencyAndArrivalPattern,
  warmColdState,
  measurementMethod
}
```

### 2. 指标

wall、CPU、RSS、I/O、网络、queue、startup、materialization、execution、cleanup、readback、cache hit/miss、physical starts、cost 和 energy 分开。平均值不能替代 P95/P99、最坏界和长尾。

### 3. 样本

单次样本不能产生 percentile。分布需要样本量、稳定环境、异常值政策和置信范围。跨环境不可直接比较。

### 4. 容量

容量模型结合 arrival rate、service time、并发、资源 pool、burst、backpressure、failure/retry 和 recovery reserve。CPU 充足不代表 memory/IO/lock 可用。

### 5. 优化 Claim

```text
OptimizationClaim =
  baseline + mechanism + expected critical path change
  + correctness equivalence
  + new state/cache/provider
  + failure/recovery
  + before/after evidence
  + rollback/retirement
```

### 6. 成本

云费用、开发时间、认知、维护、迁移、退出和事故成本保留为向量。价格和供应商条件有 revision 和地域。

### 7. 验证

冷缓存、热缓存和禁用缓存；小规模与大规模；高并发、资源压力、尾延迟、长会话、失败恢复、跨平台、前后等价和回归阈值。


## 性质、模型、故障、模糊、变形、差分与突变测试

### 1. 测试机制分工

| 机制 | 主要发现 | 不能单独证明 |
|---|---|---|
| 单元/契约 | 局部示例和接口 | 未枚举输入与组合 |
| Property | 普遍不变量的随机/生成样本 | generator 未覆盖空间 |
| Model-based | 状态机和序列 | 模型本身正确 |
| Fuzz | parser/边界/崩溃 | 业务语义完整 |
| Metamorphic | 无 oracle 时关系性质 | relation 选择正确 |
| Differential | 多实现不一致 | 哪个实现正确 |
| Fault injection | 故障、恢复和 residue | 未注入故障类别 |
| Mutation | 测试能否杀死人工缺陷 | mutant 代表真实故障程度 |
| Formal/model checking | 有界状态和性质 | 现实环境完整性 |

### 2. TestCase 元数据

每个测试绑定稳定 test identity、owner、obligation、FailureMeaning、layer、resource/environment、independence、lifecycle 和 retirement。路径和标题只是 locator。

### 3. Generator 和 Shrinker

生成器必须覆盖有效、无效、边界、冲突和未知。shrinker 保持 failure identity，不得缩成另一故障。

### 4. Fault Model

故障族至少覆盖：输入损坏、并发、超时、取消、资源耗尽、进程 crash、网络分区、存储失败、权限变化、provider drift、恢复失败和攻击。

### 5. Mutation 使用

突变测试只用于校准测试敏感性，不能把 mutation score 当产品质量。mutant 生成规则、等价 mutant 和不可达代码需要显式处理。

### 6. 验证

测试框架自身要通过 seed 可重放、clean environment、cache-off parity、oracle integrity、fixture isolation 和长时运行污染检查。


## 恢复演练、备份可恢复性与灾难验证

### 1. 有备份不等于可恢复

恢复能力要求备份内容、身份、完整性、可访问性、密钥、工具、人员、时间和目标环境都可用。

### 2. RecoveryCapability

```text
RecoveryCapability = exact {
  protectedSubjectAndObjectives,
  backupAndJournalRefs,
  backupGenerationAndRetention,
  encryptionKeyAndAccessRefs,
  restoreProcedureAndToolchain,
  targetEnvironment,
  RPOAndRTOClaims,
  drillEvidence,
  dependencyAndCommonCauseRefs,
  operatorAndEscalationRefs
}
```

### 3. Drill

定期在隔离环境从零恢复，并验证业务不变量、权限、数据完整性和可运行性。只校验压缩包可解压不够。

### 4. Common Cause

备份、控制面、密钥和文档不能全部依赖同一账号、区域、存储或软件。恢复路径需要独立性分析。

### 5. 失败状态

备份缺失或损坏、密钥不可用、模式或工具不兼容、恢复时间目标超限、部分恢复、外部依赖不可用和操作员状态未知。

### 6. 删除与恢复冲突

法律删除和用户遗忘要求必须传播到备份；恢复旧备份后使用墓碑/删除 ledger 防止数据复活。

### 7. 验证

随机恢复演练、区域不可用、凭证撤销、旧工具链、大规模恢复、写入期间备份、恢复中断、租户错误和旧数据复活。


## 测试生成、选择与故障体系

### 1. 从声明到测试

测试不是按目录全跑的脚本集合。流程是：

```text
Claim
→ Proof obligation
→ Applicable methods
→ Verification actions
→ Evidence coverage
```

每种方法说明能证明和不能证明什么。

### 2. 测试层次

| 类型 | 主要证明 |
| --- | --- |
| 类型/Schema | 各自声明片段的结构/类型约束；普通JSON结构不自动提供名义身份、真实引用或行为闭合 |
| 单元 | 纯函数和局部规则 |
| 属性 | 幂等、往返、单调、增量等价 |
| 契约 | Port、Adapter、Provider、协议 |
| 集成 | 文件、进程、存储、网络组合 |
| 端到端 | 用户目标到重新观测闭环 |
| 故障 | 崩溃、超时、资源、重复、乱序 |
| 对抗 | 越权、污染、欺骗和边界绕过 |
| 性能 | 工作负载和资源目标 |
| 运行 | 部署读回、SLO 和恢复演练 |

### 3. 影响选择

测试选择输入：

- 精确 `SemanticDelta`；
- 反向依赖；
- 声明覆盖；
- 目标画像；
- 风险和变更类型；
- 历史失败；
- 迁移阶段；
- 政策。

零新增执行要逐项解释：全部适用义务已被当前合格结果覆盖，则返回复用/满足及其证据；确无适用动作时返回`NoApplicableAction`及范围依据；二者都不足才返回覆盖缺口。不能以空列表自行签发通过，也不能否定已经有依据的合格复用。

### 4. 测试生成

可生成：

- 边界值；
- 状态机路径；
- 类型和 Schema 实例；
- 约束反例；
- 变形关系；
- 随机/属性样本；
- 并发交错；
- 故障注入点；
- 跨后端差分输入；
- 安全恶意输入。

生成器也需 revision、seed、覆盖和缩减回执。

### 5. 故障模型

统一故障类别：

```text
Crash
Timeout
Cancellation
ResourceExhaustion
PartialWrite
ResponseLoss
Duplicate
Reorder
Partition
ClockSkew
PermissionRevocation
ProviderDrift
DataCorruption
CacheCorruption
LateWriter
```

每个持久状态机对相关故障定义期望下一步。

### 6. Flake

Flake 不是简单重跑后忽略。系统区分：

- 测试本身非确定；
- 被测系统竞态；
- 环境污染；
- 外部依赖波动；
- 时序门槛不稳定；
- 数据共享。

确定性失败可复用；瞬态失败按分类重试并保留首次证据。

### 7. 测试隔离

测试环境绑定：

- 候选摘要；
- 工具链；
- 依赖；
- 配置；
- 数据集；
- 秘密和权限；
- Host 能力；
- 网络模拟；
- 清理回执。

环境无法清理时销毁，不把污染状态复用给其他租户或候选。

### 8. 覆盖

覆盖不只统计代码行，还包括：

- Claim；
- 状态和转换；
- 错误分支；
- 权限正负路径；
- 资源边界；
- 目标画像；
- 数据版本；
- 故障；
- 迁移阶段；
- 不透明边界。

### 9. Test Oracle

Oracle 可来自：

- 明确定义；
- 参考实现；
- 形式模型；
- 多实现一致；
- 变形关系；
- 目标系统权威读回；
- 人工有权判断。

被测实现不能独自生成 Oracle。

### 10. 验收

- 每个高风险 Claim 有匹配方法；
- 影响选择无漏测；
- 空选择不通过；
- 故障点覆盖每个非终态；
- 属性失败可缩减；
- Flake 分类和隔离；
- 环境可复现；
- Oracle 独立；
- 测试自身有契约和版本；
- 运行证据可追到测试定义。
