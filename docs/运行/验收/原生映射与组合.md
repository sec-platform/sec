# 原生映射与组合验收

本篇为[使用点采用](../../编译/原生映射/采用与导出边界.md)及其分题规定正常、拒绝和组合验收。V01—V40是条件案例，不是所有工程必须运行的40个测试，也不代表这些能力已实现。只选择实际相交的要求、目标、画像与消费者；复用合格上游结果，缺真实实现或执行权限时保留相应未验证状态，不安装临时平台或重复全套CI。

语义诊断、生成结构、目标编译、运行观察、ABI、并发/内存模型、设备以及性能证据分别绑定具体主体。一个源能被解析不证明生成保持行为；一次运行不能证明全输入、无锁或任意平台。有限闭域证明和样本测试使用[有限方法](../../编译/有限抽象与观察策略.md)的不同资格；材料完整、工具可运行、逻辑支持与任务采用仍分离。

## 条件案例

表中“核验层”是应取得的方法，不是已执行结果。每行都要先固定合法域及正常成功例；拒绝例不能通过关闭整个功能获得虚假合格。损失只阻断相交用途，已有独立可用根保持。

|---|---|---|---|
| V01 共享基与别名 | 实际需要共享子对象；Diamond两条基路径同时申请独占可变view | 路径先映到同一存储；不形成冲突独占借用，合法串行访问看到同一状态 | 类型/借用与运行观察 |
| V02 构造阶段分派 | 构造/销毁中的动态调用相交；派生字段尚未建立却试图访问 | 按源构造阶段使用合法动态类型/已建部分；不得访问未初始化字段，不用默认新语义改C++合法分派 | 语义诊断、构造轨迹 |
| V03 重复基与转换 | 实际对象图中有两个同类型非虚基，经动态投影查询 | 无明确唯一关系时报告歧义，显式合法路径指向正确子对象；共享基只指同一份 | 类型、RTTI/投影运行 |

## 跨机制同时成立的条件

这些检查不要求作者重复输入二十套表；编译和适配在实际相交使用点消费原合同。正反条件保留不同的失败机制。

| 相交关系 | 必须保持的结果 |
|---|---|
| 虚共享基与可变借用 | 两路径先归约到同一真实子对象，再判别名 |
| override与部分初始化 | 源构造阶段的动态分派与已建立字段一致 |
| 重载、转换与默认参数 | 固定完整调用计划后组合全部效果，不让选择隐蔽改变约束 |
| 特化与开放插件 | 新成员不改变旧绑定，集合变化形成新候选与相交失效 |
| 特化与擦除 | 需要的witness/寿命/分派区别不在降低时丢失 |
| 反射与可见性 | 元数据查询及生成后的访问各自遵守原范围 |
| 反射与增量 | 全集/否定查询也是依赖，新成员不能漏失效 |
| 复制、转移与异常 | 初始化事实、源状态和失败保证共同决定清理 |
| 固定地址与增长 | 不搬动仍要求稳定的存储，不无声改变分配策略 |
| allocator与赋值/swap | 值、存储和释放资格一起合法迁移 |
| padding与原子视图 | 真实字节范围、生命周期和访问宽度不相互破坏 |
| volatile与转换/借用 | 属性延续到最后实际访问，不经普通引用偷偷丢失 |
| 协程、TLS与迁移 | 真实线程亲和性进入调度/借用条件 |
| 协程、异步close与取消 | 停止等待后，必须收尾的续体仍有人拥有 |
| 浮点、SIMD与const | 使用固定目标数值/误差/顺序，不能因阶段切换变宿主默认 |
| 外部异常与Rust回调 | 在正确异常域捕获/转译，传播和析构都有真实边界 |
| 类型元数据与卸载 | 活跃方法/类型/析构引用保留原代码世代 |
| 原子与回收 | CAS正确与节点存活分别成立 |
| 忽略契约与裸访问 | 被省去检查的前提另有充分保证，否则不允许省去 |
| 独立编译与泛型分发 | 下游实际取得可继续实例化定义或所承诺的具体/原生接口 |

## 三条完整正常路径、失败与再次修改

### 异构序列化器

作者选定已有序列化定义，提供需要的类型、字段选择、顺序、wire format、错误与版本要求；不手写完整反射树或目标实现。workspace固定作者及导入源；semantics按可见范围取得成员与类型；compiler记录成员全集/负依赖，固定具体序列、已选整数/文本/用户类型方法和转换，检查wire布局、大小、效果及错误。

Rust/TS可以输出普通函数，成员包含真正需要的依赖和来源映射。生成第三字段失败时不发布前两个字段为完整serializer；字段无权或未知时返回准确范围。需要真实运行验证时由原execution取得许可并固定测试输入/期望，不能把元生成成功当运行成功。

第二次新增字段使全集查询失效，重新生成相交成员；只改无关说明不强迫全域重建。wire变更按原兼容合同保留旧reader/writer与迁移条件，不默认覆盖已有协议。用户手改受管产物时先走有限回源或显式接管，不能下次生成静默丢弃。

### 固定地址异步资源

作者要求指定区域、稳定地址、跨挂起持有外部句柄并必须异步关闭。先取得合格区域与最终slot，逐字段初始化；在完整有效及地址固定后注册回调。实际帧/驱动保留区域、线程、借用和代码世代；恢复只通过当前活跃状态与有效句柄。

正常完成后停止新回调、注销并join，在原关闭协议确认后释放对象和区域。取消则进入Closing，调用者退出不销毁未停止的目标；只有运行域能接管该续体才满足必须关闭。还要求无堆而目标只有堆帧时，报告具体资源冲突，不暗中放宽。

第二次换驱动或帧布局产生新世代，旧运行继续旧协议；迁移需真实安全切面、回调围栏和状态转换。源码回退不使已发生设备作用逆转，未知旧作用按原operationRef恢复。

### 共享复合计数状态

作者要求`(count,generation)`一致读取、跨线程CAS、lock-free且通过精确C ABI暴露。选择前联合核实际原子宽度/值表示、对齐、共享访问域、内存序、回收与导出；数字大小、原子名字和类型检查不能分别代签组合。

真实宽原子且全部条件成立时生成对应原语/库与完整ABI成员。只有mutex模拟则不满足无锁；普通TS对象不合该原地共享接口，但独立纯计算仍可生成TS。包含节点指针时另核回收和ABA，CAS成功不自动提供存活。

第二次增加计数位宽或变更布局时重核原子供给和ABI；旧共享存储不能按新布局原地读取，迁移按新旧writer、初始化和一致性合同执行。运行证据与目标指令/进展证据分开，不能只看一次结果正确。

## 体系与推理反例

以下24项校准现有设计，不规定24个新增功能或一套七原语内核。原合同已经覆盖时，检查实际消费而非复制同义规则。

| 反例 | 具体触发与可检验损失 | 正确处置及主要拥有者 |
|---|---|---|
| 结构反例01 最小内核 | Entity可用带域/代的Term编码，Binder也可由带作用域规则的项表示；分类数不能证明互不可约或成本最小 | 保留必要语义区别，不固定根节点/模块配额；总体架构与语义扩展 |
| 结构反例02 只有容器 | 将连续/量子领域放入opaque JSON，没有合法运算、观察、误差或后端 | 只能保全；按真实DomainDialect/供给闭合才能用于强变换；语义扩展 |
| 结构反例03 混合知识角色 | 同一P既被要求成立又被观察声称，允许实现者修改共同对象即可抹掉原要求 | 载荷可共享，要求、断言、权威、证据与采纳的写权/寿命分开；根原则与证据接纳 |
| 结构反例04 万能status | 命题已有证明，同时目标不支持、查询取消且权限过期 | 各真实主体保留同时成立的事实；摘要不覆盖其余状态；应用、保证、执行 |
| 结构反例05 空标签固定点 | U={0}，F(X)=U\X，空集/全集间振荡且无固定点 | 标签不提供存在/收敛；绑定域与实际方法，预算结束不等于反证；组合前提 |
| 结构反例06 循环自证 | A⇒B、B⇒A无种子，或种子已撤销却互相保活旧结论 | 从真实支持重算相交分量，归纳与活性另核；原C3/C4 |
| 结构反例07 捕获 | `λx.y`中把自由y换为x，朴素替换得到改变含义的`λx.x` | fresh改名可得`λz.x`，保留词法引用/kind；泛型与编译期映射 |
| 结构反例08 身份混淆 | 初值相同的两把锁/文件句柄被hash去重，或每个局部值都持久实体化 | 内容、语义、实体、存储与运行实例分开；原身份与信息规范 |
| 结构反例09 统一排名 | C++private f(int)最佳，public f(double)较差；预删private会把错误变成功 | 成熟原生前端先选择后检查访问；中立层消费固定调用；对象与调用映射 |
| 结构反例10 交换量词 | m0只满足输入0，m1只满足1；逐输入成功不提供同一实现 | 取得同一方法或真实因果分派及成本/权限；组合与有限方法 |
| 结构反例11 否定全部Transition | 弱内存/无限行为有更适合的事件表示，不证明丰富状态迁移数学上不能表示 | AST/SSA/CFG/事件/关系按用途接合，不用一个Behavior容器替代实际协议 |
| 结构反例12 单轨迹与非干扰 | 每个秘密h的源输出都可为{0,1}，目标直接输出h；逐h集合包含成立却泄漏 | 使用原要求的跨运行关系；单轨迹保证不升级；性质保持 |
| 结构反例13 边际与联合 | 独立公平(A,B)改成同一公平R返回(R,R)，各边际不变，相等概率从1/2变1 | 保留随机样本身份、联合结构和允许调度；固定seed不代签分布；性质保持 |
| 结构反例14 缩小观察 | 原要求含日志、设备写或时延，证明只检查最后返回 | 观察来自独立要求，降低回执不放大保证；性质保持/保证 |
| 结构反例15 共同错误模型 | 原数学整数`2^63-1+1`应为`2^63`，实现和checker都回绕为`-2^63` | 独立要求、编码与候选分别核；两个后端一致不消除共同错误；证据接纳 |
| 结构反例16 字段当权力 | 复制MayWrite/authority字符串后直接执行 | 描述不是Grant；实际作用点核受信许可、前像与资源，纯函数不强制外部准入 |
| 结构反例17 沙箱当证明 | 无I/O且签名齐全的checker总返回true，或任意公理改名definition | 隔离不保证逻辑健全，执行资格与编码/理论/采用分开；原E0—E7 |
| 结构反例18 全局Context | 插件/观察/权限改变后沿旧“当前世界”缓存，或全集查询只跟踪旧成员 | 固定EngineImage和精确读集，集合/否定依赖与实时准入分开；查询与扩展 |
| 结构反例19 同签名跨理论 | Int、集合/多重集、身份/值相等、逻辑/物理时间按同名相接 | 转换有真实域、单位、观察及保持义务；同签名不证明理论相容 |
| 结构反例20 万物持久化 | 每次load/局部常量都有全局ID、Revision和永久证据，纯函数被迫启动平台 | 局部紧凑值、按需摘要及真实保留消费者分开，不凭节点数造最优；信息与架构 |
| 结构反例21 enum改string | 删除有限谓词校验，未同步签名、锁、编辑和影响传播 | 基础构造可支持无限普通定义；真领域扩展沿已定协议，不用字符串兜底 |
| 结构反例22 重命名当迁移 | 新解释读取旧字节并沿旧证明，或路径变化就断言能力消失 | 内容、位置、语义与权限分别迁移，真实旧作用不随新版本抹去；兼容与恢复 |
| 结构反例23 Failure覆盖结算 | 超时后换requestId重发，或把补偿当原作用数学逆 | 沿原身份查回、围栏、重复安全与分项结算；传输结束不等于真实停止 |
| 结构反例24 展开冒充开放 | 生成几个实例就声称任意未来native类型/插件可用 | 四种真实交付形态分别判断，成熟供给直接复用；采用与导出边界 |
