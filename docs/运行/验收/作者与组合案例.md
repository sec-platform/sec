## 需求计划、简洁作者和组合实现的联动验收

本节给实现后的验收设计，不记录当前产品已经执行。以相同Task、原要求、语言与目标为基础，在直接文本、完整files批次和已有结构映射输入之间核同义结果；实际义务由[按根闭合](../保证/要求证据与裁决.md#intent-root-obligation-closure)拥有，不用新增检查表覆盖真实算法。

| 检查对象 | 必须区分的输入与结果 |
|---|---|
| 作者成果保持 | 相同短import、未标返回的有体fn、export let在需求计划后仍可读取/生成/继续修改；显式注解不因可推导被删 |
| 效果封存 | type-ready而效果未知不得可调用；显式签名互递归可以闭合有限效果但不声称终止；导入Unknown不补空 |
| 组合保证 | 两方法仅循环假设对方正确不能完整通过；All两个局部成功缺共同状态发布仍失败 |
| 计划完成 | 已有直接供给不造镜像源码；只有未来函数名时必须NeedsAuthorContent，不能以计划字符串代替真实内容 |
| 批次物化 | 同批改签名及所有调用可以在最终闭合；结构重构发现捕获错误不能以“草稿可保存”报成功 |
| 并发重基 | README改动保留；共享图形状/效果前提改变即使文件不重叠也重规划；同槽相反修改保留双方 |
| 缓存依赖 | 类型相同但效果改变、同值却来源改变、候选集合增加、负查找转存在，分别更新实际消费者 |
| 运行一致 | GraphRevision与pred同代发布，G0晚于G1只结算；异步显示队列也核版本；容量占用不能因取消返回提前释放 |
| 目标与作用 | 目标资产缺失不能完整交付；有源码不等于已运行；缺权限不修改原算法来取得绿色 |
| 恢复与再次修改 | 取消物化不发布半个身份映射，不回滚编辑器当前文字；合法回源不将短源永久展开 |

对应实现可先使用全模块与受影响分量重算作为正确基线，再与缓存/并行结果作同输入差分。外部工具、环境或性能实验只在实际实施授权与相应条件下取得，不将这个设计矩阵当作产品测试成绩。


## 跨软件意图抽象的验收，不以同一商业例替代

下面是有限能力的设计验收输入，尚未执行产品测试。完整算法和当前作者操作由[三个实例](../../../examples/连续开发/全工程连续开发.md#cross-software-author-example)拥有；验收不复制一份实现。

| 检查对象 | 正向预期 | 有区分力的反例 |
|---|---|---|
| 同一请求的作用层 | 增加删除功能仅产生作者/目标变化 | 生成程序权限被拿来删除当前工作区 |
| NoWrite与SameValue | 写后还原只能支持相应终态等值 | 终态内容相同被报成全过程没有写入 |
| 参数化关系组合 | 文件映射先核全集单射和宿主碰撞 | 逐文件合法却A/B写同一目标；循环被顺序覆盖 |
| 当前结果发布 | g2先完成时，g1迟到不得覆盖 | 检查修订后释放保护，随后旧结果覆盖新输入 |
| 进展和容量 | 稳定输入、可完成工作与公平调度下有结果或当前错误 | 永不发布也被认为满足“只发布最新”；取消后提前回收缓冲 |
| 逆关系 | a→c、b→c时pred(c)保留两项 | 每个节点只有一个prev，静默丢掉合法前驱 |
| 结构更新 | 删除边同步撤销逆索引，读者不见半更新 | 正向正确、逆向仍有幽灵成员 |
| 表示与业务变化 | 改图布局不改变R；要求稳定地址才限制表示 | 同名字段或目录位置被当作稳定语义身份 |
| 泛化边界 | 可重算预览可合并最新输入 | 命令/交易也按最新替换，丢掉必须执行的操作 |
| 检查方法 | 类型、模型、运行各报告自己能支持的范围 | 选择了BoundedModelCheck就声称需求自然变成有限任务 |

同时验证首次需求绑定、已覆盖参数化实现、真实新主体、错误/冲突保存、再修改和目标回源。例子不要求产品预装新的商业模板；成熟语言＋同等库也参与作者总成本对照。不存在数据时不报改进百分比、固定时间或全域最优。


## 简洁作者面的联合符合性

使用[完整两文件范本](../../../examples/实现校准/简洁计算与TS往返.md#compact-author-example)和[补全算法](../../编译/内核/编译值服务.md#concise-author-elaboration)验证同一范围。当前是验收设计，不是已经执行的测试成绩。

| 判据 | 正例 | 反例与失败出口 |
|---|---|---|
| 导入可省as | pricing.sec唯一末段，绑定pricing | sales-rules.sec、两个同名末段、移动改名；要求显式别名或合法重命名，不挑首项 |
| 普通返回推导 | Int参数、两个Int分支得到Int | 无体、未锚定递归、混合Int/Text、公开私有类型；不生成Any |
| 单参数lambda推导 | 被调payable签名决定total类型 | 无上下文恒等函数、未知字段、冲突约束；局部注解，不全模型补填 |
| 静态阶段 | 构造函数值，不执行其体 | I/O、发散和副作用只在合法运行时发生；顶层getter/资源捕获不被动化 |
| 完整可调用根 | export let函数值能preview及获准eval | 导出Int不是可调用；待推导签名不是已合格；不绕可见性 |
| 原契约保持 | 499、500等结果与库合同一致，负输入经原入口失败 | 省包装不允许跳过原require；显式独立条件不被合并消失 |
| 持续简洁 | 折扣20→30后源仍是lambda和原import | 禁止自动保存展开源码、额外需求JSON或强加运行类 |
| 回源和并发 | 目标30n回写准确字面量，C1无关修改保持 | 推导类型无法定位为唯一作者槽则冲突；旧产物不贴新候选 |
| 净收益 | 同库、同保证下计全部源、读取、诊断与二次修改 | 不能仅靠代码字符减少或把维护转给库作者宣称总体更快 |

有限规则的类型推导不穷举程序行为；结构校验不证明语义保持。需要运行的闭包、生成与回源结论应取得对应真实结果；当前设计可以独立审查数据、算法、反例和准入，不以先实现全部生态作为本范围前置。

## 直接编辑、恢复与展示同源的验收边界

以下是待相应实现核验的设计对象，不表示已经运行产品。文档内容比对与ZIP检查不能替代这些程序行为。

| 输入/切点 | 预期与反证 |
|---|---|
| 编辑器先改函数签名、后改两个调用文件 | 可保留中间错误；完成批次按实际版本联合检查，不要求逐行propose |
| 两个缓冲与磁盘内容不同 | 明确选择有效层；不能拿缓冲前像覆盖磁盘，也不能自称全局原子快照 |
| 普通source/files候选 | 无默认编译所有目标、运行或文件写入；保存错误草稿不回滚作者内容 |
| generated-edit正常回源 | 按固定C0/G0/M0及C1核映射，必要再生成仅覆盖相交根；不是默示全构建 |
| 整文件替换且另一路径未在files中出现 | 未出现路径保留，null才按协议删除；路径别名与重复键在覆盖前诊断 |
| 已保存作者文件后来检查失败 | 字节保留为当前工作，不因旧候选合格而恢复旧文件 |
| 两份源因注释消去或常量折叠得到同一产物 | 不宣称只由产物恢复唯一原文；保留多个可能来源或所选新表达 |
| 有完整机器语义的有限例 | 可以证明或分析恢复行为；不把“原文不唯一”当拒绝条件 |
| 平方和重构从整数换到浮点或有作用回调 | 重新核求值、顺序、数值和失败；只通过小整数例不取得全域资格 |
| 无来源候选满足旧程序但违背独立任务 | 分开保持与修复，不能改需求以让恢复通过 |
| HTML选定正文和MD一致，未选章节缺失 | 只声明节选同源，不称HTML覆盖全部规范；图和视觉单独核 |
| 用户只举C/Rust等例子 | 产生比较义务而非采用/排程；没有真实缺口不创建第二目标任务 |

可针对固定、完整、有限状态模型使用穷举；可以复用成熟提升和证明供给；一般无限程序不能靠有限运行样例证明所有输入等价。相应试验只有在任务许可后执行，未知/超额保持原资格，不变成失败即不等价或通过即历史唯一。


## Block闭包与逐层开发的验收对象

此处规定预期与反例，不代表已经运行产品测试。固定解释、基底与目标后分别检查接口闭包、表达式改写、编译保持和完整任务成本；一种通过不替代另外三种。

| 输入／变化 | 正确预期 | 必须检测的错误 |
|---|---|---|
| filter与maxByKey封装为selectCandidates | 复合结果可作为普通定义再次调用 | 要求新注册核心kind或重写生成器 |
| 只改门槛0→6 | 只改变实际使用点，库源和其他调用保持 | 修改所有同值字面量或公共库 |
| 只折叠内部展示 | 作者源、绑定和目标内容不因此改变 | 删除未显示节点或改为opaque无分析 |
| 外提if分支中的除法 | 保持分支激活，必要时使用函数参数 | 先算除法再进入原函数 |
| 一个已有值连到两处 | 生产调用次数不变 | 两处各调用一次生产者 |
| 两个状态block配置相同 | 按构造规则仍是独立状态 | 内容去重合并运行实例 |
| 一个独占资源接到两个拥有者 | 必须有合法移动／共享合同，否则准确拒绝 | 仅因类型相同就连接 |
| 抽取含局部可变捕获的表达式 | 保持原位置和寿命，或给受限变换诊断 | 把捕获位置换成旧值快照 |
| 复合边界内方法缺失 | 草稿可保存，受影响生成根报缺项 | 名称和外壳合法即输出空成功 |
| 自递归定义与无限结构展开 | 递归调用保留；展开按有限规则或预算结束 | 展示完整树导致无限物化 |
| 后端内联整个复合block | 接受行为、资源与源映射保持 | 短目标代码掩盖失败顺序变化 |
| 新图与源同时修改 | 同一作者源及基底形成候选或冲突 | 图和文本独立更新为两份当前版本 |

任务成本对照包括第一次得到合格定义、一次参数变化、一次普通新组合、一次真正需要内部修改、一次错误恢复；同等成熟库与保证是对照基线。不以函数更短、节点更少、仍有过程代码或库名更多单独判定抽象优劣。有限当前路径满足后关闭该设计子项，其他领域的自动抽取及实际实现仍按U记录继续。


## 完整语言组合的有限验收组

此表定义所选规则的书面预期，不记录已执行成绩。完整输入须由对应文法和真实库合同构造；不能用一个没有公开入口的伪API代替测试对象。继承的成熟工具只减免它真实承担的机制，新增映射仍按使用点检查。

| 组合 | 必须区分的预期 | 主要消费者 |
|---|---|---|
| var＋lambda＋局部效果消解 | 新建n=0，两次递增闭包返回1、2，相加3；外层无外逸不允许改成2或4 | 类型/效果、CSE、目标 |
| var＋let＋泛型 | 同一可变槽不能在不同使用点被当作Int与Bool；显式泛型函数不同实例不误共享位置 | 类型、捕获、泛型表示 |
| 闭包＋返回＋运行实例 | 返回闭包延长位置寿命且保留潜在效果；独立工厂调用得到独立状态 | 寿命、调用、缓存 |
| Result.Err＋资源清理 | 业务失败和清理失败共同保存，调用方仍按自己的Result处理 | scoped、生成、运行 |
| Return/Break/Continue＋close失败 | 不执行被清理失败打断的成功出口，不能被目标finally最后返回覆盖 | 控制降低、契约 |
| 主体Fault＋多个资源＋一个清理失败 | 逆序处理；能安全独立关闭的外层继续；仍被依赖资源占用的内容不得释放 | 资源、恢复 |
| 关闭未确认＋取消 | 等待结束不等于资源停止；保持原主因与未结算责任 | 宿主、设备、流 |
| 编译期＋函数值＋隐含环境 | 不因函数体能由宿主执行就读取机器环境；固定输入缺少时返回NeedInput或阶段缺项 | 展开、构建、权限 |
| 原生finally/defer＋中立出口 | 保全原生行为与按中立合同生成两种请求分别检查，不按同名关键字共用错误优先级 | 原生适配、后端 |
| 新规则＋旧候选＋新目标 | 解释及实际方法固定；不以相同/1名或同名函数重用旧语义资格 | 装配、迁移、缓存 |

语言增加一个构造时，按[组合准入](../../作者/需求关系与能力边界.md#4-完整语言能力的当前裁决)扩展实际相交组，而不是每次运行世界上所有语言的测试。当前表的明确反例归原U009/U014/U028/U049/U050，不再为同一缺口创建重复问题编号。


## 结构作者与重构的独立期望设计

沿[当前完整范本](../../../examples/连续开发/组合结构与任务轨迹.md#当前完整范本一个绑定正确的结构编辑闭环)，另由基础语言语义取得期望：零输入不执行除法；改分子只改被选分支的结果；一次let求值不因两条使用边变成两次；重命名不能改变引用绑定。不要让结构解码器和打印器共享同一个错误映射后互相比较就算通过。

设计的检查分为：表示体的字段/类型合法性；共享作用域和效果规则；原文保全；实际语义增量；目标行为；写回当前前像。可以先实现每模块全检查的较小路线。真正运行前准备独立的源码范本、期望与反例，不以内部节点数或同一个解释器的重复执行充当独立性。

扰动包括重复局部键、跨分支引用、未知体版本、公开参数改名、注释内同名词、非完整表达式、同批签名与调用变更、父节点删除与子节点修改冲突，以及旧句柄在新候选中的误用。每个失败明确是否拒绝协议、保存草稿或仅限制相交输出，不统一伪装成一个验证失败。当前只设计这些检查，不运行程序。

## 有限结构组合与统一实现的验收

以下是结构读取、实例化、选择与保证接合的验收设计，不记录产品已通过。每项使用准确源、规则、有限域、方法和输入；文档阶段的有限枚举只能复核其中的数学关系，不能代替生产读取器或目标运行。实际结构范本在[产品族](../../../examples/结构化工作台/说明.md#finite-family-example)，协议在[有限组合](../../作者/结构化源码.md#finite-requirement-composition)。

| 案例 | 输入与变化 | 必须得到的结果及可观察反证 |
|---|---|---|
| RC01 当前入口保持 | 同一十份主作者JSON、同一需求合同，未启用额外根 | 仍是同一Studio的34个硬要求和2个偏好；不能因新增例子目录自动加载负例或改变目标 |
| RC02 每项独立选择 | 产品族Independent，两个准确wanted及两个候选 | 两个各自相等的选择，68项原硬要求与4条偏好保留；不能只完成一个产品就报整个根 |
| RC03 同一共同选择 | 相同上下文选择SharedDefault | 有限等式域冲突，指向实际wanted与共同量化位置；不得用两个不同见证偷偷满足一个外层exists |
| RC04 不按名称判冲突 | 两种策略名字不同，但没有声明共享参数等式 | 先比较行为合同，不能仅因枚举字面不同宣称行为不可相容 |
| RC05 空域 | 空forEach、空exists、空all、空any | 分别为true/false/true/false；未给itemType的无预期空量化列表另报类型缺项；空真不代签正常功能 |
| RC06 局部绑定 | 嵌套bind重名、in自引用、body后引用bound、兄弟bind同名 | 前三者拒绝；合法兄弟作用域独立；不要求作者创建全局ID |
| RC07 精确类型 | Bool与Int混合列表、异名义枚举equal、主体equal、越界path | 按真实类型拒绝，不由宿主True==1或对象字符串相同通过 |
| RC08 隐含空值 | 缺必需根参数、literal null、float词元混入Int | 保留具体缺项/错误；不能填false、0或浮点截断 |
| RC09 未采用分支 | 静态false体有错字段；另一体只有缺少方法 | 错字段仍报；含义已知但未激活体的缺方法不阻塞独立生成 |
| RC10 有限符号与外部缺参 | exists见证尚未选择，when引用它；另一个未绑定root Bool | 前者保持符号进入联合搜索；后者明确Needs，不能把二者都当false或都要求用户先选 |
| RC11 传递偏好 | any/exists通过use引用含prefer的定义 | 在传递检查拒绝该有限结构；外层共同prefer及固定when/forEach中的prefer合法 |
| RC12 选择不能改目标 | 一个分支性能差，另一个分支通过不包含偏好获胜 | 必须按同一外层目标比较；不得把少比较一项当成本更小 |
| RC13 高层未知 | M内存未知/延迟1，N内存40/延迟8，内存优先 | 比较在第一层未定；有权稳定选可行者可以继续，但不宣布M更优 |
| RC14 高层支配与相等 | 将M内存补为60，再补为40；其他条件相同 | 60时N第一层优；40时进入第二层M优；不按总分抵消 |
| RC15 同层折中与区间 | 同层60/1对40/8；相交区间；不交上/下界 | 折中非支配，重叠非相等；只有真实全方向界证明才可剪枝 |
| RC16 证据口径 | 平均对p99、冷启动对暖启动、不同负载、失效样本 | 不作未经转换的直接比较，不伪造单位换算或统计确定性 |
| RC17 共同资源 | 两个单独合格方法均需独占同一资源 | 联合不合格或取得实际适配后再核；分项绿色不能代签全局 |
| RC18 统一程序 | 每个输入均有某个常量程序通过，但没有一个共同程序覆盖全部 | 不由逐例挑程序产生全域实现结论；合格统一调度策略必须实际存在 |
| RC19 观察和因果 | 在取得未来环境位之前要求确定输出等于该位；对照先取得位后回传 | 前者保留策略不可实现依据或相应未决，后者可有普通策略；不让存在模型赋予未来观察 |
| RC20 预算与候选穷尽 | 只有一部分any被排除、搜索超预算；或全部有限分支有反证 | 前者不完整，后者仅声明该域不满足；没有方法不是逻辑false |
| RC21 发生与重数 | forEach中重复相同值，两次use各定义私有主体；另例显式传同主体 | 前者保留两个发生，后者保持共享；既不能随意合并也不能复制共享主体 |
| RC22 缓存作用域 | 同JSON在两外层值下实例化；向量化域新增成员 | 结果键含实际环境，相关全称/不存在判断失效；原合格见证可在条件保持时复用 |
| RC23 采用及证据 | 方法片段或证据来自未采用分支，版本与签名看似相同 | 核实际分支/主体/输入/方法对应，不借名称接受；正确跨范围保持依据可显式复用 |
| RC24 副作用与撤权 | 失败分支想安装依赖；得到静态true后实际授权被撤销 | 探查不暗中写工作区，实际作用再核权与前像；模型字段不授予权限 |
| RC25 不做也是安全 | 禁止条件全满足，但实现从不接收合法任务或总错误 | 原功能、输入与进展仍未满足；只有原任务明确允许空产物才可按该目的结束 |
| RC26 当前规范完整性 | 修改规则正文，字段目录/设计锁仍引用旧摘要 | 当前包核验应拒绝；刷新准确来源而非删除规则、移走反例或伪造运行记录 |

较小合格实现可以全量分析有限例子、单线程枚举、保持已有可行绑定；不以实现了索引、求解器数量或分布式平台作为准入。规模增长后再由实际读集与预算验证延迟展开、剪枝和复用，所有优化保持上述观察。

| 案例 | 初态与变化 | 必须观察的结果与反例 |

| AF11 部分失败 | Library方法可用、Plugin宿主适配缺失 | 库可准确交付，插件保留缺项，共同发行未完成；不删除已合格的库 |

| AF13 数学边界 | [0,1),[1,2)分别求两种模式；再加[0,2) | 仅相接在KeepTouching分离，桥接重叠后合并；不采用任意等覆盖切分 |

| AF16 CLI输出 | 完整计算后stdout写出一部分遇到I/O故障 | 非正常结束并保留已写事实，只续确认后缀；不能重写整段或报告完整成功 |
| AF17 消息工作器 | 两活动请求乱序完成、相同活动ID再入 | 按准确会话/id接纳；重复活动请求通过不结算原槽的protocolError拒绝，原请求仍可正常返回；不伪造持久幂等 |
| AF18 HTTP边界 | 请求错路径/方法/媒体/数据，或客户端中断 | 按合同次序处理且不隐含监听部署；断连不声称状态已送达，不取消其他请求 |
| AF19 插件关闭 | 有已接受工作时宿主卸载 | 停止新准入；固定异步API不因方法变化改义，关闭Promise等实际结算，重复close不二次清理；仅撤入口不是任务已经结束 |
| AF20 交互结果 | 输入g1启动后用户改g2，g1晚到 | 旧结果不覆盖当前；草稿保留、错误不变空成功、没有默认上传 |
| AF21 输入响应性 | 目标允许的大输入会形成长计算 | 采用符合实际预算的调度/工作器或准确拒绝强交互声明；函数纯不证明UI不阻塞 |
| AF22 插件与页面权限 | 外部输入尝试执行getter、隐式网络或工程脚本 | 解码/能力边界拒绝；结构字段不自授权限，读取不暗藏安装 |
| AF23 目标成员 | 新增CLI根但只重生成库，旧目录有其他人工内容 | 不删除未选择的根或人工文件；共同配置变更真实消费者一并处理 |
| AF24 规范与独立数据 | 修改说明行或翻译但真实语义提取仍未能证明等价 | 不把文档默认排除出解释键；确有健全不变结果时才复用，性能改善不凭猜测 |
| AF25 包与实例 | 同一个纯库被两应用采用，一个退出 | 可共享纯实现与准确结果，不销毁另一应用任务；版本与实例分开 |

同一要求用成熟库＋原生工具完成时作为公平基线。比较实际作者变化、解释负担、构建/运行依赖和再次修改范围，而不是按JSON行数、生成文件数或“顶级”称号评分。约束过强或额外机制没有真实收益时，可采用合格的更小方案；不同成品公开行为与故障条件必须继续满足。

| FP11 未证明公理 | 逻辑证书含假定后置或trust step | 保留条件/未证步骤；成功退出不升为无条件证明 |
| FP12 假规则纯运行 | 沙箱内checker恒true且签名有效 | 仅确认字节和允许执行；不得自动消解Claim |
| FP13 成熟有条件工具 | 真实无证书分析器为已允许信任基础 | 可得准确条件支持；不虚造独立检查器，不全盘拒绝 |
| FP14 候选改判据 | 保持式优化同时改要求/Oracle使失败消失 | 保持原独立要求；另行形成可审阅的要求变更 |
| FP15 理论升级 | 源码同字节但逻辑/编码/公理发生变化 | 相交资格失效重评，原纯结果按真实依赖可保留 |
| FP16 重复报告 | 复制同一个报告100次 | 独立观测数未增加，不能缩小统计区间 |
| FP17 反复择优 | 100个无优势候选各按未校正单次5%测试 | 不能把第一个阳性当确认优于；公式仅在独立假设下 |
| FP18 确认数据回流 | 失败详情反馈优化器后继续在同数据修到绿 | 该数据已参与探索；换新确认范围或合格适应性方法 |
| FP19 无确认预算 | 功能合格，只有探索性能观察 | 可按委派交付可行实现，准确不声称证实更快 |
| FP20 确定全域证明 | 有限域完整枚举或合格全称证书 | 按其精确范围采用，不强制随机留出和显著性流程 |
| FP21 共享缓存侧信道 | 两个租户没有数据边但有可测共享命中/争用 | 强隐私/可用性核资源边界；不由数据DAG判无影响 |
| FP22 固定设备无限域 | 原要求显式物化任意长度输出且统一有限容量 | 不能将必然超容量错误算全域成功；处理真实范围/方法或冲突 |
| FP23 未见语义成本 | 新任务每次需创造规则及供给，原对照已有同等库 | 计入一次成本和后续维护；不能只报应用入口短 |
| FP24 增量全局耦合 | 改变全部根共享的数值语义 | 允许实际影响全部根；无关目标仍可复用，不保证恒定局部耗时 |
| FP25 模板无解 | 当前文法方法证明没有解，域外存在已知实现 | 仅报告本方法域无解；可直接采用合格域外供给 |
| FP26 不可信材料指令 | 报告要求关闭检查/发送秘密并附伪permission | 作为材料读取，不进入新的授权或执行请求 |
| FP27 旧图源和正确索引 | 内容字节、图缓存和索引均一致但语义矛盾 | 只证明派生对应；不能由核验工具宣布全设计无缺陷 |
| FP28 U身份归属 | U013补充位于U014锚点之后而标题之前 | 补充归回U013完整范围，不改两项语义或编号 |

共同规范是[性质保持](../../编译/性质保持与开放环境.md)、[解释接纳](../保证/解释与证据接纳.md)及[探索确认](覆盖与收益判据.md#adaptive-confirmation)。现有类型、作用、取消、恢复和预算案例继续适用，不以本表覆盖全部未来问题。

## 义务消解、摘要、作者分工与自举的接合验收

以下OC01—OC30是设计输入与预期，不是已运行的SEC测试。共同拥有者为[义务与摘要](../../编译/组合前提与进展闭合.md)、[分析维护](../../编译/查询增量与性能.md#analysis-maintenance-contract)、[成本界](../../编译/实现选择与设计搜索.md#cost-bound-accounting)、[资源重构](../../作者/组合/结构编辑与身份保持.md#cross-module-capture-refactoring)及[自举声明](../../编译/内核/确定性与自举.md#bootstrap-claim-boundary)。

| 编号 | 输入与扰动 | 必须得到的结果及排除的反例 |
|---|---|---|
| OC01 | 同一服务先需硬延迟≤50ms，后需≤10ms；原有效界为40ms | 该界支持第一项，对第二项仅是依据不足；只有实际大于10ms的合格反例才可反驳，不能因节点visited继承通过 |
| OC02 | 将OC01两项到达次序交换 | 两项最终判断与来源保持相同；顺序不改变接受标准 |
| OC03 | 两个来源提出同一准确命题，支持仍有效 | 可共享判定与计算，仍能回溯两个来源；不重复扣物理预算 |
| OC04 | 同单位同域已有≤10ms硬界，需≤50ms；另一个请求需实测分位数 | 仅在接受的蕴含规则下消解第一请求；不同保证种类另核，不比较裸数字 |
| OC05 | 同对象要求至少保留30天并须7天内删除 | 保留两项及准确冲突，不能取max或选择其中“更强”项覆盖 |
| OC06 | 条件未知；同节点另有无条件要求 | 条件项保留，独立项照常处理；不能将未知当false后清整个节点 |
| OC07 | 条件已证false，另一来源仍要求相同节点的性质 | 只解除受该条件控制的义务；其他来源不消失 |
| OC08 | 同一w需P且Q；a只满足P，b只满足Q | 不接受拼接见证；具有P和Q的同一w才可闭合 |
| OC09 | 两个独立词法存在量词都叫w，分别有合法见证 | 可以各自取值，不按变量拼写强制同一个对象 |
| OC10 | A或B是完整备选；A的半份义务与B的另一半分别满足 | 不能拼成合格路线；选择一致的完整备选或保留缺项 |
| OC11 | 原支持规则被撤销，数据值仍相同 | 原值可按其真正性质复用；依赖该规则的判定失效并重新求解 |
| OC12 | 当前轮即将发布时到达更强要求 | 旧判断只归旧要求修订；保留新待办，不以完成回调覆盖新义务 |
| OC13 | 效果摘要未知，方法却填为空效果集合 | 拒绝以此证明纯度；有范围的未知不转无效果 |
| OC14 | 范围过近似包含坏值，但尚无源级可达见证 | 精化或联合检查；不直接报告真实程序必然违反 |
| OC15 | 两个变量实际x=y，独立区间丢掉相关性 | 原语义仍有关系；区间不足时换合格关系域或联合检查，不自行证明不等/等式 |
| OC16 | 正常出口满足P，但Fault出口有未释放资源 | 正常后置不覆盖Fault；保留清理/恢复义务，不能只比成功值 |
| OC17 | 递归效果分量删除唯一种子，旧SCC互相支持原效果 | 从新输入/底重算或健全删除；不在旧解上空转自证 |
| OC18 | CFG不变但常量、调用目标或捕获改变 | 重核值域/效果/寿命；CFG保留不代签所有分析仍有效 |
| OC19 | 独立候选可用成本12；另一方案两处共用一次初始化8 | 合格联合下界计实际8，不以8+8=16剪掉它 |
| OC20 | 两个同字节缓冲却确实独立分配，各需8容量 | 物理存活同时计16，不因内容摘要相同合成一份 |
| OC21 | 原剪枝下界依赖无共享，后来发现可共享/批处理 | 撤销该剪枝依据并重开相交搜索前沿；不能只改最终显示分数 |
| OC22 | 同步借用缓冲的扫描迁出，helper不保留/不暂停 | 在完整借用及观察保持条件下允许，不因出现资源而一律拒绝 |
| OC23 | 可变x在选区中写后读，helper只收到旧值快照 | 不接受保持式改写；保留实际位置/别名或原源 |
| OC24 | 抽取使Borrow跨暂停或提前释放Own | 要有真实长寿命/移交和原退出次序；否则保留缺项，不生成伪安全签名 |
| OC25 | helper迁往新模块造成初始化反序或私有状态公开 | 留原域或给合格更大变更；不偷偷懒加载、重造this或公开私有实现 |
| OC26 | 产品意图JSON已足够，所选供给是原生TS | 直接读结构并绑定供给；不要求先写新.sec文本或填IR/回执 |
| OC27 | 新资源操作返回相同值，但释放责任不同 | 先使用已有寿命/效果合同保留区别；真的缺共同观察时才有范围扩核 |
| OC28 | C0只能经现成TS工具建立，尚无中立计算前端 | 独立原生构建取得种子，后续逐阶段；不要求先运行尚未存在的SEC |
| OC29 | A2/A3只是相同原生文件的透传，字节完全相等 | 可支持转交保全，不证明SEC新增编译语义、自编译符合性或没有共同错误 |
| OC30 | 设计接口/算法完整但设备证据未取得；另一个条目真缺算法 | 前者可限定设计闭合但不签发运行保证；后者保留设计缺口，不统一改成“只待测试” |

这些案例分别检查正向可用、义务不丢、非空成功与准确缺口。实施验证需绑定实际前端/分析器、要求修订、源与目标；模型原子步骤和假定成本仅在所述范围有效。既有CP、FP、BI和领域反例继续有效，不以新增编号代替产品符合性。
