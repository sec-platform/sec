## 开放世界覆盖前沿、挑战过拟合与残余未知

### 1. 不存在“覆盖所有未来”证明

任何有限问题目录、测试集、事故集和领域集合都不能证明未知机制不存在。Coverage 只能绑定精确系统、来源、时间、环境和搜索策略。

### 2. CoverageClaim

```text
CoverageClaim = {
  purposeAndSystemDefinitionRefs,
  challengeCorpusRefs,
  sourceLineages,
  mechanismFamilies,
  environmentsAndScales,
  stakeholdersAndJurisdictions,
  searchStrategies,
  holdoutChallenges,
  blindSpots,
  residualUnknownBudget,
  validityHorizon,
  reopenTriggers
}
```

### 3. 坐标状态

```text
satisfied
not-applicable-with-proof
required-unmaterialized
bounded-unknown
violated
stale
holdout-unassessed
```

`not-applicable` 需要关系不可达证明；“没想到”不是不适用。

### 4. Challenge Record

每个外部案例或 escaped defect 记录来源、事件、机制、放大因素、失败控制、恢复、模型映射、最强竞争解释、反证、处理状态和反转条件。案例不能直接成为 architecture authority。

### 5. 防过拟合机制

- 留出领域和事故家族；
- 盲测未参与设计的挑战；
- 删除关键词和品牌；
- 表面结构变换；
- 不同学科来源；
- 让攻击者构造 schema 无法表达的状态；
- 检查是否用 `other/unknown` 掩盖根缺口；
- 检查新领域需要改Core是扩展接缝遗漏，还是确实出现新的不可替代语义；必要时重开Core，不强行藏进other。

### 6. 来源独立性

多个转述同一原始材料只算一个 lineage。挑战轮换形式理论、事故、负面论文、用户失败、硬件 errata、法律冲突、安全报告、组织绕过和高成本成功案例。

### 7. ResidualUnknownBudget

```text
ResidualUnknownBudget = {
  affectedSubjects,
  requestedEffects,
  potentialSeverity,
  reversibility,
  observationBlindSpots,
  modelUncertainty,
  commonCauseExposure,
  toleratedUnknownClass,
  acceptingAuthority,
  expiryAndReassessment
}
```

不可逆高风险效果不能接受无界未知。

### 8. 条件化轮次关闭

```text
CoverageEpochClosed =
  all selected challenges have disposition
  and no known critical seam is ownerless
  and holdout does not expose unhandled root failure
  and source diversity meets declared profile
  and residual unknown budget is accepted and current
  and reopen triggers operate
```

这不表示问题世界永久完成。

### 9. 根回退

新案例若推翻 identity、authority、observation、effect、assurance、locality 或 optimization 根合同，必须回到根层重建依赖闭包，而不是末尾追加例外。

### 10. 完成条件

- Coverage 语言从“完整”改为“在声明边界内未发现新缺口”；
- 有 holdout 和盲评；
- 有残余未知预算；
- 来源 lineage 去重；
- 新分布触发旧 Evidence 陈旧；
- 不存在 `allProblemsCovered=true`；
- Challenge Corpus 本身不成为第二 architecture。

### 11. 新场景的持续接入算法

先取一个实际任务的输入、目标制品、效果和观察范围；从失败反例倒推所需时间、资源、状态、权限、知识和语义关系，生成此前没有的坐标，而非只从行业目录选标签。再构造一个最小实例、一个跨域组合、一个边界/故障实例和一个已有输出保全实例。需求命题与可观察验收分别保存，不能因目标难测就删掉目标。

对每个支持维度分别记录：可保全、可读取、可校验、可生成、可验证、可迁移、可治理。不支持高层理解时可以保留原生制品，不能从“保存了全部字节”推导“支持了全部工程”。无适用后端时继续设计接口和替代，阻断只归属目标输出。具体实例见[跨领域机制场景与实例化合同](../../演进/领域组合与扩展条件.md#跨领域机制场景与实例化合同)。

32种当前实例是显式设计夹具，不是32个生产已支持领域，也不是独立盲测。组合覆盖只报告实际选定坐标/组合和测试；没有执行覆盖数组生成/测量就不报告t-way覆盖率。某一事故需要高阶相互作用时补专门反例，不认为成对组合足以排除。


## 成熟度、实施、采用与退役证据

### 成熟度不能靠标签

成熟度轴及其含义唯一见[系统成熟度与现实边界](../../状态/前沿与登记规则.md)。本篇只规定证据采集、更新和退役验收，不再复制一条 proposed→retired 状态链。设计、实现、验证、约束入口、实际采用与旧对象退役分别绑定各自主体和作用范围。

### 各状态的独立证据

每条被支持的声明保存精确主体、适用画像/环境、证据引用、观察时点、有效期或失效触发。状态的证据定义沿用总览，不复制第二份状态表。

Implementation 查真实 producer/consumer，而非仅类型；Verification 查实际执行环境和失败路径；Enforcement 查全部声明入口与旁路；Adoption 查真实使用与默认消费者；Retirement 查被替代对象的读写消费者、持久状态及剩余义务。证据可以由同一次观测支持多个命题，但每个推断边界要明确。

### 状态降级

新绕过、旧路径复活、Evidence 失效、Provider 漂移、实现 consumer 消失、法域变化和恢复演练失败，都可使高状态降级。成熟度不是单调荣誉等级。

### 作用范围

成熟度绑定 exact capability、profile、environment 和 support horizon。Linux 上 verified 不自动推出 Windows；CLI 上 enforced 不自动推出 API；内部使用 adopted 不推出公共支持。

### 防止中央大账本

只为真实消费者需要查询的能力建立成熟度记录。记录引用领域 owner 和证据，不复制设计正文、测试结果或动态平台状态。当前事实由 live observation 重建。

### 完成条件

每个对外支持能力都能追到所承诺的设计、实现、环境和验证证据；不要求所有能力“最终到达 retired”。实际退役发生时，单独关闭旧主体的读写路径和残余义务。通过注入旁路、移除消费者、使证据陈旧等测试，验证只降级受影响的证据轴。UI、文档和发布页投影同一主体事实，不补造高等级。


## 系统终局验收与反向否证

### 验收原则

SEC 的终局不是“文档写完”或“代码进入主干”，而是一个真实工程问题从目标、观测、语义、设计、实现、执行、验证、部署到用户结果全部闭合，并能在失败、变化和退役中继续保持真值。

### 必需纵向链

验收按公开承诺选择场景组合，不把所有功能串成每次请求必经的链。

| 场景 | 必需链及边界 |
|---|---|
| 新建工程的确定性生成 | 已采纳的结构化意图/模型 → 语义校验与所需绑定 → 目标程序 → 生成源码和所需工件 → 构建/行为验证；无需先有存量工程、AI 或设计搜索 |
| 存量工程受控演进 | 有覆盖证据的观测 → 保全/重建 → 受权采纳 → 相关模型变更 → 最小合法补丁 → 并发验证与写回 → 权威读回；保留 opaque/未知边界 |
| 候选设计辅助 | 明确目标、约束和预算 → 候选搜索/求解 → 可检验证据或带边界的未知 → 有权选择；不取代普通 lowering |
| 对外发布与运行 | 冻结制品 → 发布准入 → 受控效果 → 提交与读回 → 对承诺运行环境的验证/用户结果；适用时才启用部署、canary 和迁移 |
| 替换与退役 | 新路径采纳 → 已存在旧路径的消费者/写者和状态收敛 → 处理残余义务 → 退役；新建无旧机制不制造一条虚构迁移链 |

多上下文联邦模型只用于真实依赖该决议的场景。系统整体能力由被承诺的场景集合检验，单个场景通过不替其他场景签发完成。

### 正向验收

1. 同一输入可重复生成同一规范结果；
2. 用户意图和目标工程事实均有来源与未知边界；
3. 已证明不满足时给出可复核解释；最小化另报方法和预算，超预算或求解未知不伪造无解证书；
4. 已声明扩展接口能承载的新语言/Provider/后端通过局部扩展接入；超出内核语义假设时允许显式核心迁移；
5. 变更仅触达 owner-approved 范围；精确依赖时最小化，健全过近似可保守扩张，不以错误“最小”漏掉影响；
6. 故障可恢复，外部不确定完成先读回；
7. 所需验证在 owning environment 执行；
8. 用户在预期环境中完成目标；
9. 支持与成熟度状态真实；
10. 本次确实替换的旧机制在声明支持域内迁移、排空或受控拒绝，并处理必要历史/恢复；无替换义务不虚构退役对象，不等开放世界消费者全部消失才撤销危险执行。

### 反向否证

最终验收必须主动尝试推翻系统：

| 攻击 | 预期结果 |
| --- | --- |
| 修改与已证明精确依赖无关的文件 | ActionKey 与可复用结果保持；过近似范围内允许额外失效，实时资格仍须满足 |
| 新增可能影响 absence 的文件 | 依赖负事实的结果正确失效 |
| candidate 修改 verifier | 只能作为被测对象，不能自证 |
| Provider 超时但实际已执行 | 进入 unknown completion，先读回 |
| 编辑器内容与磁盘分叉 | 阻断或显式协调，不覆盖 |
| 多文件第 N 步崩溃 | 恢复到可判定终态，无混合成功 |
| 共享缓存损坏 | 删除或隔离缓存后 clean 结果相同 |
| 一个租户试图污染另一个租户 | 物理和语义隔离阻断并留证据 |
| 权限撤销发生在 apply 前 | 准入或提交点重新验证并阻断 |
| 恢复备份损坏 | 不宣称可恢复，进入明确风险/阻断 |
| 新领域扩展加载顺序变化 | 系统定义和规范 bytes 不变 |
| 旧兼容入口被再次调用 | 明确拒绝或迁移，不成为第二 writer |

### 完成不等于永久正确

终局验收只对 exact generation、support profile、environment 和证据 freshness 成立。任何决定性输入变化都可使相应声明陈旧；系统必须能够重新观测、局部重算和降级成熟度。

### V1 完成门

以下是建议采用的 V1 发布挑战矩阵，不是不可约架构公理，也不证明“两种语言/六领域”就代表任意工程。正式目标必须由项目 owner 绑定支持范围、预算和验收证据：

- 至少一个真实项目完成其承诺的端到端场景；
- 以两个语言前端或一个语言加一个非代码工件前端，检验已声明的前端边界；
- 以两个后端或 Provider 实现，检验指定替换合同；
- 以六个明确记录的领域挑战检验核心扩展假设，失败可推翻假设，而不是要求无限无修改适配；
- 对承诺缓存/增量的动作检验 clean/incremental 等价；
- 对实际启用的效果与平台合同检验 crash-prefix、并发、资源耗尽、权限撤销、缓存损坏、网络分区和恢复失败；
- 真实用户确认所承诺结果；确实被替换的旧竞争 writer/状态源退役；
- 声明受控写入的入口有不可绕过的门禁和适用读回，不强迫离线纯编译工具托管整个运行平台。

未采纳数量与测量阈值保留为验证设计候选，不按文档存在判为已确定产品架构。

### 整体结构验收不以测试总数替代

架构候选必须给出能力保持与边界删减表：删的是重复定义、无消费者的公共面、冗余持久化或必经工作，不能删掉真实恢复与权限义务。比较固定输入与所选保证下的冷路径、热路径、人工/AI重复决定、上下文读取、峰值内存、写回失败恢复与迁移成本；未测值明确未测，不能用测试通过条数或文件数替代。

加入以下组合反证：草稿预览被迫采纳；纯库加载控制服务；新增未选择画像使普通编译键全失效；一个原生源被迫通过所有公共IR；模型新/制品旧/证据旧被显示为完整；业务事务被通用重试覆盖；不可信插件复用纯查询入口取得I/O；候选自行修改验收再签发资格。

架构关系检查最多验证已经声明的边界，不能发现所有隐藏调用，也不等于执行了完整编辑、编译、写回和部署。图中的关系、局部算法检查与真实纵向结果分别判断，不把“关系检查通过”当产品完成。

### 同一请求的可重复集成验收

在得到相应实验或实施授权后，端到端验证应从同一精确输入连续完成分析、生成、严格检查、独立期望运行与新目录读回。正常路径至少包含用户自定义一般程序与带相对导入的用户原生模块；新算法/原生实现不修改内核。结果要明确哪一阶段执行、哪个subject被检查、哪些动作未观察。

反向检查不是单纯增加单元测试：候选换修订而复用旧验收、改变情境资格、工具字节漂移、原生锁错配、假构建输入、伪造标准库、撤权后重试、验收先过后败、清单与内容同时被替换、取消发生在完成之后、导出响应丢失和目录预先存在，均必须保持真实状态而不盲目重放。

记录实际工具调用和查询命中，不将引用关系检查次数或样例参数数膨胀成整体改进数。新应用接合证明本机有限组合成立；生产性能、实际用户净收益、持久重启、已有工作区更新和部署不因此通过。原问题台账继续列明剩余义务。

### 持久接合的额外否证义务

同一次真实生成及有限验收后，在已有目录准备精确意图，删除原会话引用并让不同进程继续；在准备、准入、物化和结算事务切点终止进程。检查desired/observed没有被单个成功位吞并；两竞争操作只有一项接纳当前revision；负依赖和只读依赖改变会拒绝；终态重试不覆盖后来人工修改。

主动删除或破坏前像、代际摘要、索引成员、根身份、格式版本和当前授权时应得到相应诊断。逆回滚必须在第三方修改时拒绝，在回滚中止后保留方向，回到旧内容时仍递增revision。一次多断言案例、同案例重跑和不同进程里的相同输入不重复计数。声明为原子多文件、掉电耐久、多人授权或语义无损回写时，必须取得比当前本机进程测试更强的独立证据。


## 计算工程是独立完整的验收范围

一个计算库、编译器、渲染器或仿真器可以没有事务业务，并仍然有完整工程保证。任务需要的输入域、算法结果/误差、终止或可报告的未完成、内存/设备寿命、真实消费者和持续修改共同决定出口；不额外要求审计、消息、跨制品数量或数据库案例。

计算域的证据分别覆盖源含义、库合同、索引/数值、缓冲/并行、目标工具与运行；纯度不证明总终止，唯一所有权不证明无循环数据依赖，GPU成功启动不证明已回传结果。sharpen的原地污染、分块接缝、零尺寸和整数地址溢出，以及浮点重排、随机布局改变和不收敛迭代是独立反例，不是检查器名称可以替代的义务。

未选择的能力不产生通过声明，也不作为整个任务失败。若要求明确不加载某设施，则需相应构建与实际激活证据，不能只查源里没有关键字。接口相交时，事务和计算保证组合判断；单纯任务不加载全验证矩阵。详细处置见[按需协议](../../演进/适用性与能力协商.md#不需要部分的处置与退出协议)。


## MVP的作者闭环不是语法与生成成绩相加

MVP声明绑定[当前实施范围](../../演进/实施/仓库迁移与自托管.md#当前mvp范围与支持清单)。设计已选择一个作者面，并不证明AI已经更省工作；成功解析一个函数，并不证明六工具的完整开发可用。接受声明应分别由实际输入和结果支持。

完整会话至少保留：给定任务与原接受范围；AI收到的工具/语言/库上下文；首次源和精确候选；目标与源码；对应检查；一次合法参数变化；一次不在固定模板里的新组合；一次类型或合同故障的定位修复；一个陈旧前像冲突；保存后新会话继续；实际消费者的结果。多个范围可以复用同一事件记录，不要求每项单独建审计表。

基线也可使用同样成熟库和自动化，比较实际的完整冷/暖任务与失败。词数、文件数、变更次数、元数据字节、工具往返和运行成本分别记录；没有测就保留为未测。一个范围已设计、已实现、已通过有限验证、已在消费者采用和相对收益，各自报告，不把五项压成百分比。

设计阶段可以实际完成书面走查，发现未定义字段、未知来源、必须手修目标或异常无返回时修规范。运行阶段再取得解析/类型/目标符合性与真实AI结果。不能要求实现前就有运行成功数据，也不能将只有理论可用的一段源码报告为已被产品接受。


## 目标追踪和并行编译的两类闭合声明

设计管理的追踪闭合声明必须给出采用的根目标集合、观察/语言/目标范围、已拆解义务、未审前沿与判断方法。全部已登记问题都有归属，最多证明当前登记没有孤儿；不能由此证明所有潜在问题都已被发现。模块、接口、状态与作用的有限枚举可以在明确输入中完成穷举，开放需求空间则保留发现过程与未覆盖范围。

编译执行的结果声明按精确输入和动作支持范围比较：串行与并行的完整正常产物应满足同一确定性和语义合同；超预算、取消、工具崩溃和不同授权的结果单列。设计过等待算法不是已经证明没有所有死锁；还需实际并发、资源和故障验证。远程内容校验通过不等于来源与动作归属已认证，来源认证不等于语义正确。

独立复核对象包括：四个父任务占满执行槽后等待子任务；父挂起后仍占满内存；跨工作线程等待成环；同键多等待者中一人取消；新参数持续产生新特化键；远端隐藏输入、结果冲突与迟到；并行名字分配和诊断合并；多目标一项失败时的完整/独立结果区分。对应条件、默认动作与有限预期见[编译调度规范](../../编译/递归并行与远程编译.md#13-设计复核关闭范围与反转条件)。这些是验证设计，不是已经运行的测试。


## 状态图的支持与完成声明按对象限定

本领域至少分五种声明：有限模型结构合法；反应语义符合所选版本；给定输入轨迹到达特定稳定配置；目标活动实际完成；采用后的业务/资源要求满足。SCXML规范、接口形状或一条通路到final不同时证明这五项。

采用成熟状态机时，先复用完全相同的层级/转移规则与相应上游依据；事件匹配、guard错误、history、动作计划、完成轮次、取消和版本迁移存在差别时，留下确切接缝义务。W3C实现报告是实现性/互操作记录，不是当前SEC符合性认证。

[规范中的反例表](../../领域/状态关系与流/层级状态与事件.md#14-对照例失败切点与尚未实现范围)提供可独立推导的预期。尚未运行就保存为设计预期，不能将图可解析或目标类型检查通过称为控制程序、实时性和全部故障路径正确。逻辑Completed/资源Pending的组合按真实任务聚合。


## 关系任务的剩余验证义务

采用成熟SQL或增量引擎可以复用其真实覆盖，但不能把“支持join/MV”替代本章库的重数、空值、错误、权限和双边更新。先固定声明及使用范围，核来源支持，再检查SEC新翻译与连接；正常数学推导可以现在支持设计，不要求先实施一套临时产品。

[关系反例集](../../领域/状态关系与流/关系查询与维护.md)分别检验完整求值、SQL映射、增删状态和真实源。用300/400区分semi与join；Some(全空右行)与None区分缺失；空两侧同批插入检查交叉项；旧左零值删除/右新增检查差量额外除零。真正实现时比较全量与增量，同时仍保留独立小输入期望，不能让同一错误实现互相认证。

查到了正确行不代表全域输入已完整；源码检查不证明数据库角色；统计报告不证明自动匿名化；有限批次通过不签流窗口或全SQL支持。各声明仍绑定准确模块、根、产物与真实运行，不批量关闭U039。


## 完整计算工程的三条横向验收

当前去掉“每个计算出口必须先用事务/作用画像校准”的前置。完整计算采用应分别验证：控制/解析型的动态分支、递归与诊断；数据并行型的形状、别名、边界与表示；反馈迭代型的状态、停止、误差和观察。它们用于攻击共同架构，不要求为每个任务建立三款测试应用，也不要求每个项目启用所有画像。

对选中的一个实际工程，至少有源创建、多模块组合、公开封装、真实目标生成、构建、运行结果、失败定位、一次参数变化、一次结构变化和全资产交付。每项事实只由相应方法支持：文档例是推导，库测试覆盖上游范围，Runner输出是本次运行，只有独立要求检查才支持需求满足。不能从结构原子、编译成功或exit=0推出整任务完成。

图工具的书面反例固定在计算规范：SCC公共顺序不等同DFS内部编号；spacing只影响位置，但一条回边可使全图合并；重复边必须保留；旧运行不能推进新代；SVG标签必须按内容编码。性能验证计入排序、文本长度、转换、构建、启动、观察和输出，不只给出SCC内核O(V+E)。

在新接口未实施时，可以完成字段/分支/责任与错误分类的设计审查，不能记录为真实运行通过。有限定点观察具备方案，也不把完整交互式调试、任意自动微分或全部目标发布标成已支持。
