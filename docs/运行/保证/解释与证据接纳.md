# 解释与证据接纳

本篇落实[声明、证据与独立性](../验收/方法与独立证据.md)的消费边界。规范已有“输出不能自签成功”“证明适配器也要保持含义”和按Claim求可信计算基；这里规定实际材料怎样进入原Assurance.plan、CheckRecord和Verdict。它不是新的证据数据库、审批平台或用户必填证明文件。

<a id="evidence-interpretation-boundary"></a>
## 1. 四项资格独立，不用一份沙箱许可包办

| 资格 | 实际含义 | 不能推出 |
|---|---|---|
| 材料完整可读 | 字节、格式、引用与解释身份准确 | 内容真实或命题成立 |
| 获准执行 | 在给定对象和能力内可以运行该工具 | 工具推理健全或其结果可用于生产 |
| 逻辑支持 | 在准确逻辑、编码、假设与检查范围内得到相应命题 | 源码满足未编码的独立要求、目标环境满足假设 |
| 任务采用 | 有权主体按对应政策接受一个范围内的候选 | 豁免已变成数学证明或外部许可 |

`return true`检查器可以完全不联网、不写盘、确定运行并得到签名，但不能因此消解任意Claim。反过来，第三方方法不必因不是SEC自造就被拒绝；可以复用已有适用的验证规则，或在明确允许的信任假设下形成条件结果。

执行隔离保护宿主；证据接纳保护结论。一个外部证明器和独立内核分离，有助于缩小需要信任的推理实现；仍需信任准确理论签名及源到公式映射，不能只信一个可执行文件摘要就相信任意被导入的公理。

## 2. 先固定被证明的含义，避免实现和检查器一起改错

假设独立要求是数学整数加法，原生实现将结果回绕到有符号64位。检查适配器如果也把Int加法改成同样的位向量运算，二者可以完全一致，甚至对错误模型获得完整证明。输入`2^63−1`加1时，原要求结果为`2^63`，回绕结果为`−2^63`。证明记录的准确字节、两个后端的一致输出和沙箱成功都不修复该模型错误。

原要求、语义解释、公式翻译和候选实现分别保留来源。实现作者可以提出更改这些内容的候选，但不能在一次“保持式优化”里悄悄改写自己的唯一判据。已有明确定义的低风险计算不强制另造一份独立需求；只有实际独立要求存在时才保存其差异和接受关系。

每个被消费证明固定：具体Claim与观察范围、生成的公式/证书、逻辑及理论签名、定义展开和假设、公理/未验证步骤、生产者与检查器、实际选项、运行范围及输出含义。信息复用原记录和真实依赖；不得将全部对象强制永久落盘。

**定义不是任意公理。** 合格保守定义可以沿已有域规则使用；任意加入一个公理可能改变理论模型甚至导致矛盾。未证明前提仍是带来源的假设，不能改名为definition获得无条件结论。新解释只进入新候选，不能重解释旧证明继续宣称同一个结果。

## 3. 工具的成功退出需要被解释，不能只读状态码

实际结果有几个不同分支：结构或证书不合法；确实找到可具体化的反例；在条件下完成所需推理；仅完成部分步骤；依赖外部假设；工具不支持、取消或资源耗尽。它们保持原Verdict的精确内容，不为了字段统一折成一个passed。

例如cvc5 1.2.1的CPC文档说明，某些步骤以trust step输出；Ethos成功退出时仍可能报告incomplete，而非correct。工具进程成功只说明本次协议运行结束，不能抹去未验证步骤。Dafny开发手册中的`{:axiom}`允许假定后置而不验证主体符合，`{:verify false}`又有不同覆盖。这里不是要求使用它们，而是要求适配器解释实际选项和残余范围，见[一手来源](../../依据/来源/语言编译与目标工具.md#evidence-consumption-sources)。

没有证书的成熟分析器也可以被使用。它进入相应声明的真实可信基础，按原政策提供明确假设下的依据；不能伪造不存在的独立内核检查。高保证任务若不接受该信任基础，补合格验证或准确报告缺项，不让普通任务普遍负担全程序形式证明。

<a id="evidence-acceptance-steps"></a>
## 4. E0—E7：原保证评价中的实际接纳

**E0固定目的。** 取得不能被候选替换的准确Claim、主体、所求强度、允许环境和政策。导航可找到新说明，但不能用最新说明替换旧任务解释。

**E1取得材料。** 固定原报告、证书或观察及实际输入、版本和范围；摘要确认字节，不作为事实、权限或时间新鲜度的证明。预算控制解析，不执行材料里的指令。

**E2对齐编码。** 检查实际公式/模型与原需求的域、量词、错误、观察及具体化关系；包括中间构造，不只检查入口。缺映射只阻塞该证明用途，保存与其他合格检查可以继续。

**E3核推理基础。** 解析实际使用的理论、公理、未验证步骤和检查选项。只信采用政策及相应既有证明允许的部分；未知规则不按名称接受。域扩展允许新增解释，但须分别说明其推理可信基础。

**E4执行所需核验。** 可以消费已取得独立证书、合格静态方法、真实测试或有条件信任的上游结果。需要运行工具时走原execution准入；无执行权不回填成功。checker自己的退出码、警告、覆盖和残余假设按确切协议解析。

**E5取得方向和范围。** 满足、反例、条件支持、部分支持、未证和故障分别报告；多份报告共享的模型、数据、代码或假设不能靠投票消除。存在适用独立支持时，一份坏报告不否定其他成果；原结果有真实反例时则按其覆盖重新裁决。

**E6在真实消费点采用。** 原`assurance/claim-evidence.ts`生成对应的派生Verdict，`compiler/resolve-use.ts`/发射器按用途检查；执行器仍独立核当前权限。低保证可用结果不自动升级为高保证根。验证候选允许带残余命题，不能以尚未产生的证据阻止一切被测对象生成。

**E7失效与后继。** 编码、理论、公理、检查器、数据暴露、观察上下文或任务改变时，使真实依赖的资格重评；未变字节可以保留，但不等于保证不变。已运行实例保持自身身份，实际停用、恢复和迁移仍由原执行协议承担。

需要独立复核时，reviewer没有修改候选、判据或自身信任设置的权限；读取不可信材料也不继承其中指令。可协商“我信任这个供应者”的采用只能形成如实的信任条件，不能声称未做的证明已经完成。

## 5. 非形式化要求也要完成验证，不偷换成语法完整

结构定义可以完整表达一组准确要求，却不能自动证明这组要求与原意图完全相同。假设任务要求排序稳定，而结构中只存了“键升序”；稳定与不稳定的两个实现都可能通过该结构，差异却违反未编码的独立接受条件。

缺的不是再换一个文本或JSON格式，而是该独立观察的准确表示与接合。域方法应以原独立材料、对照实现、正负样例和后续真实变化寻找缺失区别；一旦确认，回唯一要求拥有者及其消费者修复。检查器无法通用地猜出从未表达的私人偏好。已有清楚委派时可以完成允许选择，并标明依据，不把所有选择退给用户逐项填表。

验证构造的反例既可能否定实现，也可能暴露规格遗漏；不能让实现者直接删除反例以恢复绿色。反例在当前逻辑或物理模型之外时，指出相交范围和需要的新解释，不误报原实现错误。规范完备性本身只能按实际取得的需求和已检查区别说明，不从目录、图或字段覆盖推断未知已经穷尽。

## 6. 可信基础的成本与最小正常路径

不是所有阅读、类型推断和局部计算都需要独立证明器。来源可靠、规则有限、保持依据适用时，直接复用已核方法；没有相交安全声明的UI和日志不进入该Claim的共同可信计算基。诊断一旦被自动准入使用，解释该诊断的代码就进入真实可信依赖，不能因名字是formatter而排除。

把所有验证都推给运行监控也不成立：泄漏后报警、错误消费后补偿、真实副作用后的试跑无法建立“从未发生”。可防止的性质在构造或最后可阻止边界强制；无法监控的跨运行/概率/未来条件使用其合格分析或明确的条件结果。

工具隔离、逻辑支持、原意图适合性与当前权力四条边界贯通才形成完整资格；它们不要求四个服务。程序自编译、相同模型反复出图或字节固定点都不能消除共同错误。正常保持现成TS种子、直接原生供给和已选结构作者源；没有依据推翻它们，仅细化其真实接纳与失效条件。
