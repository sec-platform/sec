本章只拥有跨主题的工程原则、规则效力和冲突裁决。用户要求见[要求正文](产品要求与工作约束.md)，当前技术选型见[作者基线](../作者/可替换表示与适用范围.md#当前作者面实施基线与决策状态)与相应设计理由，详细算法由领域规范拥有。完整任务导航与文件职责由[README](全体系能力与边界.md#完整责任目录)维护，不在本章再复制目录。

## 当前范围与决定层次

维护本套设计的默认目的为设计及文档修改；具体动作边界由实际用户请求与更高优先级的平台规则确定。目标程序运行、平台实现、文档处理和交付封装是不同动作。当前产品范围不因这次处理的例子或最近出现的技术名称改变。

## 几种不同的“原则”不能放到同一个强度

| 内容角色 | 能约束什么 | 不能代替什么 |
|---|---|---|
| 用户要求与有效授权 | 本任务接受结果和允许动作 | 不能使错误事实变真，也不能扩大平台权限 |
| 已采用的规范 | 所属对象在定义范围内的解释和行为 | 不能未经裁决修改上位要求 |
| 数学与事实依据 | 在明确前提下支持或反驳命题 | 外部标准的组织流程不自动成为SEC必需制度 |
| 当前设计决定 | 在要求范围内选择算法、前端和实现 | 不等于用户指定，更不是永远不可反证 |
| 说明、范本、来源和未采用备选 | 解释、检验和提供比较材料 | 不产生另一份API、默认值或实际授权 |
| 状态与报告 | 说明取得了什么、还缺什么 | 文件、字段、通过数量和自述不代签实现或效果 |

规则强度依据真实来源、适用范围和已接受含义，不依据加粗次数、文档位置或“更具体”口号。必要性与实施优先级分别判断；未来条件没有激活不撤销义务，已经发生的责任也不因暂停功能而消失。

## 约束冲突的裁决顺序

1. **先对齐对象。**核主体、对象、动作、时间、版本、输入域与保证；不同范围的两条规则不是自动冲突。
2. **再核来源。**先遵守平台与实际安全边界；用户目标和授权按真实渠道确定。仓库内容、搜索结果、子代理和助手自己的提案不能自行提升效力。
3. **合并可兼容条件。**同一动作的硬要求取共同满足范围；明确标为可覆盖的默认依其描述符合并。不按目录深度、加载顺序或“更严者赢”处理全部规则。
4. **识别真正变更。**同一有权主体明确改变同范围要求时，只替换已改变部分，保存必要接受关系。提出比较或质疑不是采用命令，最新文件也不天然是最新授权。
5. **完成当前裁决。**能在允许范围内选择就选择并写回；不能共同满足时给出冲突条件、保持项、当前可做部分和需要的决定，不擅自修改原目标以造成功。
6. **回改消费者。**先改规则拥有者，再检查相关接口、示例、目标、验证、理由和问题。未知或冲突只阻止真正依赖它的行为；不能在章末新增覆盖句而保留相反旧规则。

同级规范冲突期间，不自行采用其中“更方便”或“更严格”的一份。只读分析和无争议的设计可以继续；真正写入、发布和不可逆动作依据实际准入边界决定。审查发现根原则错误也要修正，编号与历史字节不具有豁免权。

## 用户原则的纳入、装载与真实执行

新增要求先进入[要求正文](产品要求与工作约束.md)的原责任，机制进入领域规范，理由和未完成事项分别进入D和U。相同要求合并，独立含义不丢；不增加一套需要人工同步的规则数据库。只有定义了当前合法处理方式，才算完成相应设计，不以“以后注意”代替修改。

任务启动、恢复、委派及动作前如何重新取得规则，由[AI装载协议](../开发/AI协作/规则装载与任务恢复.md#任务启动的原则装载与动作检查)唯一拥有。规则已记录、实际已读、工具已约束和行为已核验分别声明。当前规范提供设计合同，不授予平台级记忆或工具权限。

## 根原则的适用条件

以下根原则是当前规范化陈述，编号用于稳定定位，不是不可改变的配额。来源和适用边界由相应理由及资料规范定位；已识别的例外与修正应改回对应条文，不只在总入口加覆盖声明。

### 1. 现实高于模型

模型是某个观察方法、上下文、时间、语言和假设下的受限表达。模型完整不代表现实完整；编译成功不代表物理世界已改变；证明成立不代表假设已在现实中满足。

### 2. 事实、规范、权威、决议与证据分离

```text
ObservationCut  回答在何种切面看到了什么
Assertion       回答谁在何种上下文声称什么
Definition      回答某模型单元接受什么含义
Authority       回答谁可在某维度决定或行动
Resolution      回答冲突断言如何被裁决或保留未决
Evidence        回答哪些可核对的观察、推导、证明或检查支持哪个 Claim
Verdict         回答证据在假设下是否满足 Claim
```

权威不能把错误命题变成物理事实，证据不能自动决定价值，执行能力不能变成语义授权。

实现不能凭“当前如此”反向定义已采用规范；派生物不能凭“已经生成”重写其上游源；缓存不能凭“命中或校验成功”定义权威身份。该约束按对象、用途与作用域适用：源码可以拥有自己的实现事实，正式机器合同可以拥有已声明的结构语义，一个阶段的产物也可以成为下一阶段的真实输入，但均不因此取得修改上游要求的权限。摘要、图、翻译、索引、AI总结、测试结果、部署观察和签名分别保持自己的证明范围；格式、位置、文件存在与hash都不提升规范效力。

该方向不是禁止反馈。实现反例、实验和外部事实可以推翻设计前提；先核证据与原要求，再由有权主体修订真正的规范拥有者，并使其消费者同步失效/更新。不能为保住文档拒绝现实，也不能为让测试变绿降低规范。规范、内容完整性、来源证明与实际采用必须独立判断。

### 3. 未知、不可判定、不可行和冲突分离

未知不是 false；不可判定不是超时；不可行不是未找到候选；规范冲突不是技术故障。需要这些区别的接口和决定必须保留相应含义；局部响应可以省略无关字段，但不能把未知展示成false、把超时展示成不可判定或不可行。无需每次返回全系统状态表。

### 4. 名称、地址、内容、引用和现实对象分离

路径、包名、函数名、URL、分支、进程号、显示名称和版本标签都不是现实同一性的充分证明。`SubjectRef` 是系统引用；现实身份还可能需要 IdentityClaim、标准、演进和争议。

### 5. 当前、目标、候选、预测、历史和假设分离

```text
ObservedCurrent
AcceptedTarget
ProposedCandidate
PredictedOutcome
HistoricalEvidence
AssumedCondition
```

六者不可共用一个状态字段。

### 6. 一个问题一个决议协议，不是一个事实一个组织 owner

活动写权、解释版本和状态转换权威必须在**同一对象、操作、版本与作用域内**确定；这不禁止不同语言前端、并行解析器实现或多个独立状态机。观测断言可以并存，已采纳规范仍有明确含义拥有者。

确有多方规范冲突时，决议协议记录有权主体、适用规则及 resolved/context-split/conflicted/underdetermined 结果；普通单一规范读取不强制新建一个 ResolutionProtocol 服务或记录。

### 7. 权限只收窄，不放大

```text
childAuthority ⊆ parentDelegableAuthority
```

在同一次委派链中，子任务、fallback、Provider和兼容层只能使用父任务可委派范围内的权利。撤销与拒绝只对其真实对象、作用域、时间和政策有效，不能让无关旧拒绝覆盖新的合法请求。若有权主体通过独立受信渠道授予新权限，建立新的授权关系并重做相交准入；这不是子任务自行扩大权限。

### 8. 有能力不等于有权

文件系统写权、管理员账号、模型工具访问和 API token 只表示物理能力，不表示产品、事实、法律或验证权威。

### 9. 无准入不产生效果

Effect 必须满足其类型和影响范围所需的授权、输入前提、资源与完成条件。写回通常需要前像；外部不可逆动作需要专门授权和残留处理；纯计算不人为添加外部准入。

目的、方案、预算、时限和恢复资料可以通过稳定引用解析，不要求每次简单效果都携带一份最大字段集合。适用性裁剪不得移除该动作真实需要的权限、并发安全或不可逆风险义务。

### 10. 执行结束不等于完成

完成须绑定本次目的。纯查询取得所需结果即可；涉及外部作用、资源或承诺的操作，不能只凭进程退出、HTTP 200或文件存在宣称全部成功，还须满足对应结算、读回与残留合同。设计完成不以实现或发布为前提。

### 11. Verification、Validation 与 Assurance 分离

Verification检验实现是否符合给定定义；Validation检验定义和实现是否适合目标用户及环境；Assurance组织可辩护的保证论证。采用证明、测试、分析或观察分别说明，不能把每次测试通过都称为形式证明；组合时保留假设、模型对应与残余未知。

### 12. 不可补偿约束优先

在适用范围内已经确立为不可补偿的安全、权利、数据、隐私或信任约束，不能通过性能、成本或便利评分抵消。约束需说明禁止状态、所需保证及有权接受的风险边界；这不是承诺所有实际系统零风险，也不因存在任何未知就禁止独立安全工作。新冲突回到有权规则和真实事实处理，不由优化器偷偷降低标准。

### 13. 不同量纲与不同主体的成本不直接相加

毫秒、字节、金钱、人员、风险、恢复时间和受影响人数保持为 typed vector；同一维度在不同主体之间也不能未经合法政策合并。

### 14. 最优声明绑定问题与依据

明确的问题可以存在可证明的全局最优解；不能笼统否定这种可能。声明`optimal`时固定候选域、目标、约束、适用输入或分布、成本模型与证明范围。仅找到可行解、非支配解或当前最好方案，就准确声明该结果，不扩大为未知未来和所有工程的永久最优。正确可行与当前选型不必等待全域最优证明。

### 15. 不确定性不伪装精确概率

没有数据、机制或可说明的统计假设时，使用有事实依据的情景、定性风险与明确未知；不能为了替代百分比而再制造无依据区间、上界或“鲁棒包络”。能够从范围、模型或数据推导界限时，给出变量、单位、推导与适用条件。

### 16. 可逆性具有独立价值

在硬要求相同、完整成本和风险可接受时，可观察、可隔离、可恢复的方案具有独立选择价值。回滚、备份或灰度若增加敏感副本、双写和恢复成本，也必须计入；不为每个纯函数建立影子平台。不可逆效果需要适用的授权、前提和残余责任，不一律要求人工批准。

### 17. 变化只在证据允许的范围内局部失效

依赖闭包记录实际保证、范围与失效条件；精确闭包或健全上界可以支持对应局部性。受控完整读取与普通路径采样不同，静态/动态是方法名而非保证等级；未知边界不能冒充完备。正式复用规则归[查询与影响](../编译/查询增量与性能.md#可达输入声明依赖证据与负依赖)。

### 18. 增量只是 clean correctness 的受限优化

同一声明输入闭包下，clean、incremental、warm 和 cache-disabled 结果应等价；依赖证据不充分时必须扩大重算或禁止复用。

### 19. 重试需要因果变化

对输入和环境封闭、错误确定的同一动作，重复执行通常不增加证据，应复用失败或改变条件。瞬时故障、随机采样、远端状态未知等允许按明确策略进行有界重试或重观测，不必先证明不可见环境已改变。

重试必须绑定错误分类、预算、退避/并发上限和重复效果安全。可能已经产生外部 Effect 时先用操作身份、幂等协议或读回协调；不能把“允许重试瞬时错误”扩展成盲目重发破坏性操作。

### 20. 最小化是没有无消费者结构

不为未来可能性预建空type、package、facade、registry、daemon和兼容层；持久或跨边界格式出现时明确其版本，不需要等第二消费者。未来义务有owner、触发、验收、反转和退役。

### 21. 创作能力与真实裁决权限分离

人和AI都可以创作、检查、提出反例、修订候选，并在有效委派与政策内接受或执行变化。双方都不能因创作能力自行扩大权限、伪造观察、规避所要求的独立复核，或把自述当成发布成功。AI自测和修错不是被禁止的“验证自身”；需要独立保证时才按其合同分离来源和角色。正式的风险接受与目标改变由有权主体或既定政策决定，不由人类/AI类别自动授予或剥夺。

### 22. 形式证明永远绑定假设和可信计算基

证明陈述必须能追溯前提、逻辑系统及所需可信基础；涉及实现和现实主张时还要说明模型对应与物理边界。可以用简明正文表达，不强制每项证明创建AssumptionLedger文件或服务。不能从模型证明自动推出现实条件已满足。

### 23. 多模型和冲突可以是正常状态

系统不能为了得到单一图而隐藏法域、上下文、权威和证据冲突。冲突只阻断相交操作，不污染无关切片。

### 24. 控制器可能使系统更坏

持续调和、自动修复和自适应策略必须证明或监测稳定性、时延、饱和、冲突和策略反馈。无法限定风险或保持进展时，停止相交的自动修改，保留观察、诊断及既有恢复责任；由实际有权主体按政策选择下一动作。主体可以是人或受合法委派的 AI，不默认增加人工前置。

### 25. 指标会改变行为

先区分指标的角色：用户目标、验收阈值、运行观察或用于预测的代理指标。目标值和观测值不是同一个事实。代理指标进入优化或奖励后，要检查投机、分母改变和向其他主体转移成本；必要时用独立结果交叉检查。指标可以是明确目标或约束，不能一概限定为Evidence，也不能仅因分数改善就认定原任务改善。

### 26. 组件正确不推出系统正确

组合时核上游保证是否满足下游前提、共享状态和资源是否相容、转换与共同故障是否引入新义务。可采用假设—保证、直接分析、适用证明或实际检查；只调用当前范围需要的方法，不要求每个普通调用做全套形式验证。组件证书不能相加成为整体证书，满足组合定理前提时则积极复用。

对于已经确认需要修改的机制，采用[完整变化的一次闭合](../维护/规格写作与完整性.md#complete-change-closure)：先确定最终责任、输入输出、正常与失败、组合与迁移、核验与退役，再以同一变化集同步实际生产者与消费者。“一步到位”约束交付闭包，不要求一次长命令，不禁止短批次实现/检查，也不保证未知未来永不修订。

### 27. 挑战集无法证明未知不存在

任何有限事故库和测试集都可能被过拟合。覆盖只在来源、时间、环境和搜索策略边界内成立，并保留残余未知及其影响；没有可定义的单位和计量方式时不虚构“未知预算”。

### 28. 系统必须能够说“无解”

实例不可行须有证据；类别不可判定是元数据，不自动成为实例失败。当前不可协调、规范冲突、保证不足和不可接受不可逆风险按范围给出诊断/终态；不得生成虚假折中，也不阻断独立安全输出。

根约束应用到长期变化时，还要区分内容身份与当前资格：旧内容、签名、备份和已计算结果不能证明之后没有撤销或删除；结果相同不证明依赖相同；递归固定点需说明求的是哪一个解。具体规则归[查询](../编译/查询增量与性能.md)与[恢复](../运行/持久化提交与恢复.md)，不为这些区别新增一个全局版本号。

### 29. 系统必须能够拒绝自身架构

当治理复杂度、耦合、恢复、合法性或安全风险超过收益时，SEC 必须建议拆分、降低自动化、删除功能或拒绝该架构。

### 30. 完成包括退役和重开条件

完成按这次变化承诺的观察结果判定。真正替换旧实现时，退役范围内需检查旧活动消费者、兼容责任和残留；新增独立能力不需要让无关旧消费者清零。源树合并、正式发布、目标部署与用户效果分别确认。

证据有效期、内容保留以及新事实触发重开按声明保存。历史和仍受支持的旧读者不因“当前只有一套规范入口”而自动销毁。

## 从原则到具体机制与反证

用户要求通过REQ定位机制，工程原则通过本章的适用条件约束消费者。新增或修改一项规则时，至少找到承担其正常行为的实际接口，以及会推翻该行为的输入、时序或边界；没有承接机制就进入具体设计欠账，不以索引存在标成完成。

事实与身份由[身份知识](../作者/工程源/身份断言与采纳.md)负责；作者与转换由[作者实体](../作者/工程源/清单模块与绑定锁.md)和[语义保持](../编译/表示/表示族与跨层保持.md)负责；组合、选型、资源由[共享语义](../作者/共同语义关系.md)、[实现解析](../编译/实现选择与设计搜索.md)和[资源规范](../运行/权限与资源管理.md)负责；真实作用与结果由[恢复](../运行/持久化提交与恢复.md)、[保证](../运行/保证/要求证据与裁决.md)负责。

## 约束核对范围

完整性以取得的要求集、审查对象和方法说明；不能仅因为REQ和原则编号连续，就证明所有历史要求或全部领域算法正确。文档交付的结构检查、语义核对和实际执行检查由[文档规范](../维护/组织修改与来源保全.md#交付前的约束与正文检查)分工。

## 当前产品范围与粒度裁决的归属

产品范围由REQ001—REQ030和相应采用规范确定。本章不再维护一份不同版本的产品目标或SDK列表。计算、小工具、业务、状态、文件和媒体按真实需求使用相交能力；源对象、查询、事务、物理模块和用户任务的粒度不互相代替。

原则可复用，实际情境必须重新判断。每次重新提醒用户的要求都应先检查既有记录与执行失败点，不将同义要求追加成新的永久条目。
