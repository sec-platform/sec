本章只保存实际取得的用户要求及其适用范围，不把设计者的技术选择、用户提问中的候选方案或外部标准升级成用户命令。工程原则由[原则总纲](原则总纲与归属.md)维护，机制由领域规范维护；本章提供要求到机制的直接定位，不再复制完整算法。

## 范围与使用

本章是已取得要求的完整正文，不是每轮自动生成的摘要。产品要求、设计工作要求和交付要求分开适用；本章的范围是实际取得的用户要求，不代称未取得的历史。技术采用、理论判断和外部资料只按其真实角色进入设计，不自动成为用户命令。

| 要求范围 | 责任主体与触发 | 如何使用 |
|---|---|---|
| REQ001—REQ020：产品与作者能力 | SEC设计者；设计产品、入口、表达、封装或工作范围时 | 保持产品目标；字段、语法、SDK和MVP是满足目标的方案，不是目标本身 |
| REQ021—REQ030：工程机制 | 对应设计者与实现责任模块；修改相交合同或使用能力时 | 读取机制正文，核对输入、实际动作、结果和保持范围；条件未激活不部署设施 |
| REQ031—REQ042：设计工作 | 本套文档的执行者；接受任何续作、研究、裁决和修改时 | 限定本次目的，主动发现，作当前决定，并准确区分设计与运行成果 |
| REQ043—REQ051：文档、知识和规则执行 | 本套文档的维护与交付者；每次修改、委派、恢复和交付时 | 同次完成保全、去重、来源与范围核对；不能把它们放到下一轮再做 |

所有条目在设计任务启动时检查一遍是否相交，不依据文件名或关键词命中才决定是否存在。任务只读取数据或只改一个值时，可以复用同版本、同范围已取得的要求；不能将这套设计维护协议注入目标程序的每次函数调用。适用、条件尚未激活、与当前动作无关、存在冲突和缺必要信息，是不同判断；未读不是不适用。

当前“只设计”允许修改本套Markdown、进行必要资料读取和文档静态核对；不授权实现SEC、运行产品样例、安装依赖、部署或修改在线仓库。新的明确执行请求只能在它实际授权的对象和范围内改变此限制。“继续一切”“做彻底”不自行扩大动作类别。

详细规范与精简作者输入是同时成立的要求。减少重复工作是目标，不是所有程序必然更短的既成事实；减少架构返工是目标，不是任意未来前提变化都无需调整的保证。发现可检验反例时，保留原目标，修正具体方案或说明相交冲突。

当前作者前端、实现语言、模块布局和工具选择由[作者基线](../作者/可替换表示与适用范围.md#当前作者面实施基线与决策状态)及其设计理由负责。本章不重复维护第二套技术选择。

每条“机制归属”表示当前规范责任，不表示该要求已实现；“相交问题”指向具体剩余义务。记录、实际读取、工具约束与行为核验分别判断。

## 产品与范围

<a id="req001"></a>

### REQ001｜语言中立

公共语义独立于输入、实现及目标语言；逐种语言接入不能把首个宿主的语义变成全产品默认。

**机制归属：** [语言体系与开发规格](../作者/可替换表示与适用范围.md)。**相交问题：** U013。

<a id="req002"></a>

### REQ002｜先行目标不改变产品

TS先行是实施次序；TypeScript与Rust均已纳入通用目标计划，当前先闭合TS端到端路径，Rust的具体能力、目标画像与交付范围按真实消费者逐项实现和验证。TS工程读取、可靠编辑与受管生成物回源是独立能力，不能将它们设为新产品意图设计的前置。Java继续暂缓，不作为当前前置；C/C++等作为原生供给与互操作候选按角色和成本选择。纳入Rust目标不授权迁写SEC核心，也不表示Rust后端已经实现。首个工具或样例只检验一部分能力，不替代全工程目标；技术举例既不构成立即实施许可，也不改变已经采用的TS＋Rust目标计划。

**机制归属：** [统一架构与责任边界](../架构/协作与状态边界.md)。**相交问题：** U037。

<a id="req003"></a>

### REQ003｜小工具与业务同样在范围内

覆盖普通小工具、格式转换、文件、业务规则、交互、自动化和复杂算法，不以计算量或是否有数据库决定工程资格。

**机制归属：** [计算结构与算法实现设计](../领域/计算基础/计算结构与算法.md)。**相交问题：** U026。

<a id="req004"></a>

### REQ004｜成品架构先于迁移

先确定最终产品模块、数据与接口；既有源码只在具体复用或迁移任务中作为事实输入，不决定最终架构。

成品形态必须落实到用户工程、产品模块、成熟供给和目标产物的实际数据/调用关系；不能只变更选型结论而让接口仍要求被撤销的工作。

**机制归属：** [物理架构与模块责任](../架构/装配/模块与运行实例.md)。**相交问题：** U016。

<a id="req005"></a>

### REQ005｜暂缓不撤销

中间件和数据库内部深化暂缓；已选外部合同及实际产生的责任仍设计、保留，不制造全局前置或永远成功的占位。

**机制归属：** [适用性与能力协商](../演进/适用性与能力协商.md)。**相交问题：** U027。

<a id="req006"></a>

### REQ006｜AI首期

首期服务AI／脚本，不以人类图形界面、人工审批或人的操作习惯作为普遍前置。实际政策要求的授权单独处理。

**机制归属：** [AI上下文与受控协作](../开发/AI协作/需求与作者上下文.md)。**相交问题：** U004。

<a id="req007"></a>

### REQ007｜自用与自举

设计真实自用、库自用、编译器自编译及开发控制自管理的次序、种子和退出，不能相互代签能力或权限。

**机制归属：** [编译内核与生成](../编译/内核/输入与阶段总览.md)。**相交问题：** U035、U036。

<a id="req008"></a>

### REQ008｜全工程资产

源码之外的配置、构建、资源、文档、数据及其他文件均有纳入、保全、修改、生成、交付与退出方式。未知格式先保全，不强制全转成JSON。目录不定义语言、权限或包边界；本地模块复用不必建设分发生态，清单要求与机器锁的角色分开。 全体系信息还包括来源、决定、证据、运行观测、操作恢复、协作与长期保留；按独立用途设计路由，不把未来支持设计冒称已收集全部现实资料。

**机制归属：** [全工程资产与非源码管理](../作者/工程源/资产与非源码.md)。**相交问题：** U032。

## 作者与控制

<a id="req009"></a>

### REQ009｜短程序独立使用

表达式、函数和模块可以在准确上下文中使用，不为短代码先建设完整项目、数据库或控制服务。

**机制归属：** [开发操作与任务边界](../开发/用途与任务范围.md)。**相交问题：** U008。

<a id="req010"></a>

### REQ010｜准确意图不重复抄写

准确意图可以直接由自己的SEC封装定义、参数、连接和独特要求承担作者语义；不强制发明新文本语言、不另造同义副本；结构化JSON可以直接承载已定义意图/Block，不需先转成自定义文本；采用何种具体表示仍由D02按这些约束选择。已有库含义、推导结果和生成实现不重复维护，真正未决定的行为保留为待决。 作者源可以是高层定义引用、关系、参数和少量策略，不把语言底层范本当成所有需求的主面；真实独特行为由准确新定义/结构承担；缺实现由供给侧补齐，不自动把实现源转嫁给产品作者。跨软件相同的结果关系、结构依赖、状态/时间、资源保持和开发变更必须有共同表达与组合，不能仅用某个商业例、短函数名或类型省略证明意图抽象已完成。目标程序行为、编辑过程与本次现实作用分别绑定对象和权限。

**机制归属：** [语言能力映射与最小控制](../作者/需求关系与能力边界.md)。**相交问题：** U046、U047。

<a id="req011"></a>

### REQ011｜开放定义

没有官方封装时，作者可用已有构造定义算法、类型、规则和组合；普通新业务不要求修改SEC核心。

**机制归属：** [工程语言与用户定义](../作者/组合/抽象与开放定义.md)。**相交问题：** U010。

<a id="req012"></a>

### REQ012｜自由与高层简洁

高层定义可组合并局部具体化；特殊部分不迫使整个功能退出系统；重复结构可以重新提取，不强制无限模板参数。

**机制归属：** [工程语言与用户定义](../作者/组合/抽象与开放定义.md)。**相交问题：** U007、U010。

<a id="req013"></a>

### REQ013｜正常封装自己的源码

普通SEC函数、类型和模块可形成库，不必重新命名成“大意图”；使用者、维护者和编译器的权限与表示访问分别规定。

**机制归属：** [封装模块与库演进](../作者/组合/模块封装与复用库.md)。**相交问题：** U033、U034。

<a id="req014"></a>

### REQ014｜最小必要控制

对任务需要的语言能力、目标结构、库、算法、ABI和资源选择提供准确入口；未主动控制的合法实现自由由工具决定。普通局部控制、变量/常量范围和内存/外部资源寿命属于实际语言责任；低层表达能力、目标供给和执行许可分别交代，不用关键词数量代替覆盖。表达能力可用不等于每项需求都须写类或控制语句；仅需要的差异进入作者内容。

**机制归属：** [语言能力映射与最小控制](../作者/需求关系与能力边界.md)。**相交问题：** U030、U031。

<a id="req015"></a>

### REQ015｜自动选合格实现

作者可只描述所需含义，编译器在允许范围选择库或生成方案并固定绑定；显式指定属于可选约束，不是每个调用的必填项。

**机制归属：** [实现解析与设计搜索](../编译/实现选择与设计搜索.md)。**相交问题：** U044。

<a id="req016"></a>

### REQ016｜管脚与多表示

保留按任务使用文本、结构与类型化管脚的能力，并准确比较它们的作者负担；不把用户提及芯片或block当成指定全局开发主面的命令。复用、层级封装和组合闭包是需要检验的机制，Block与管脚可以成为设计者在当前约束下选用的主结构，但不规定每项需求先手工选块连线或建立GUI。各表示保持唯一作者归属与真实往返范围；作者连接、分析依赖、目标运行、工作安排和文档插图的边、环、顺序与完成条件分别解释。

**机制归属：** [结构作者与语义编辑](../作者/组合/结构编辑与身份保持.md)。**相交问题：** U002、U006。

<a id="req017"></a>

### REQ017｜作者形式由设计者负责选择

前端与整体路线须比较普通框架、现有多目标编译器、语言工作台、阶段化／引用、结构与独立文本的实际成本。完整替代应从同一组产品目标评价，不能把“增加第三入口”的成本当作“独立语言优于其他路线”的证明；也不以缩小多目标或自由定义要求换取表面简化。当前采用由设计者明确记录，技术提醒不是用户指定。

**机制归属：** [设计理由-目标与核心](../决策/设计理由-目标与核心.md)。**相交问题：** U054。

<a id="req018"></a>

### REQ018｜不强迫原生补洞

支持范围内允许零原生应用作者；语义或后端缺项明确登记，原生是可选接入，不是所有复杂需求的默认补洞。

**机制归属：** [导入观察与原生资产](../开发/原生维护/导入观察与原生资产.md)。**相交问题：** U013。

<a id="req019"></a>

### REQ019｜作者总负担与交互负担分别降低

不能以短摘要掩盖更长的重复源码；同时控制独立决定、维护内容、读取、往返和诊断成本，对照允许使用同等成熟库与保证。


简洁性必须落实到实际可维护来源：结果与保持关系能组合，直接修改不要求重复实现；能够从已固定定义确定的类型、别名、捕获和生成信息不再要求作者重复输入。句法补全只解决一层负担，独立硬要求、时间进展和跨对象不变量仍保持。不能把长源码隐藏到配置、派生文件或库维护账外充作减负。

**机制归属：** [目标术语与质量属性](术语与质量属性.md)。**相交问题：** U019。

<a id="req020"></a>

### REQ020｜任务视图不是第二份源码

完整源保留，AI只读取和修改相交内容；已知符号不强制查询目录，局部参数不重发整模型，不为压缩显示增加新IR。

**机制归属：** [AI上下文与受控协作](../开发/AI协作/需求与作者上下文.md)。**相交问题：** U004、U008。

## 工程机制

<a id="req021"></a>

### REQ021｜数据和实施算法明确

规范明确数据所有者、接口、调用顺序、状态、正常算法、失败和实际装配；不只列概念或将关键选择留给实现者。语义合同、库、编码与实际模块分别解释，并明确标识实际存在哪个请求/模块/锁字段；不要把标签写进每个业务文件名，或让它变成开发者逐项配置和重复平台。

需要控制、优化和管理的资源、变量、状态、寿命及其他工程对象，须形成架构级、结构级约束及真实消费边界，不能只修当前任务涉及的几个调用点。解决单位是相应不变量及其全系统生产者、消费者、组合、失败、恢复和退役闭包；现有旁路和新增入口均须处置。复用下层已有类型、作用域与宿主保证，不为统一控制建立万能管理器或要求每个局部变量维护台账。准确的权限/验证边界不取消产品责任，局部修复不等于整体控制已完成。具体闭合准则由[系统控制合同](../架构/约束强制与整体一致性.md#system-control-closure)承担。

**机制归属：** [物理架构与模块责任](../架构/装配/模块与运行实例.md)。**相交问题：** U016、U049。

<a id="req022"></a>

### REQ022｜编译链有真实方案

描述解析、绑定、类型效果、展开、目标降低、布局、打印、检查与所需输入的具体合同，复用已有工具而不只画流水线。

**机制归属：** [编译内核与生成](../编译/内核/输入与阶段总览.md)。**相交问题：** U049。

<a id="req023"></a>

### REQ023｜生成行为与结构分别保持

正确保持结果、错误、顺序、效果和公开结构；重复生成使用明确布局基础，只有实际需求和控制允许才重组。工程逆向必须落实为可使用的源保全、结构读取、常用编辑和再生成；受管产物有来源时支持已选范围的准确回源，不将定位映射当成逆算法，也不以任意程序恢复原作者意图为全部工程支持的前置。 无来源时仍应在支持域主动恢复行为和可用抽象；历史原文不唯一、程序行为恢复、候选需求重建及有来源回写分别评价，不以一个全称否定取消实际逆向能力。

**机制归属：** [目标源码组织与生成策略](../编译/目标/成员布局与完整产物.md)。**相交问题：** U014、U053。

<a id="req024"></a>

### REQ024｜减少架构返工

以公开合同、封装、真实依赖和可替换适配限制变化；内部替换保持既定外部条件。根前提改变时说明必要迁移，不能无条件保证任何未来变化都只改局部。

**机制归属：** [统一架构与责任边界](../架构/协作与状态边界.md)。**相交问题：** U043。

<a id="req025"></a>

### REQ025｜成熟成果实际复用

优先直接使用合格成熟实现、规范、证明和工具；明确本地新增语义、适配与组合的剩余责任，不只在资料里列名字。支持某能力不等于将它重新实现为SEC源码；没有独立合同或传递差额时不增加同名转发层。自己的库可以自由建立，不能把每个新需求转成必须新增的公共库或平台原语。

复用要进入读取、类型链接、实现分支、目标依赖和运行全链；已有实现不因缺SEC同名主体而被要求重写。实际新增适配与剩余实现责任必须明确，不用引用库名冒充已接入。

**机制归属：** [宿主生态与技术约束](../运行/宿主生态与技术约束.md)。**相交问题：** U065。

<a id="req026"></a>

### REQ026｜设计推导与运行证据分工

有足够机制依据的设计现在裁决；不为每个结论先造临时实现、证据图或重复上游测试。现实耗时、状态、安装和已发生作用要有实际依据。

**机制归属：** [保证证据与验收](../运行/保证/要求证据与裁决.md)。**相交问题：** U065。

<a id="req027"></a>

### REQ027｜不需要的设施真正不生成

区分不适用、未选择、禁止、延期、必需缺失和退役残留；无需求不生成空服务或强制前置，已有作用责任不能随删除配置消失。

**机制归属：** [适用性与能力协商](../演进/适用性与能力协商.md)。**相交问题：** U027。

<a id="req028"></a>

### REQ028｜外部合同与内部实现分离

已选外部边界先明确值域、错误、时序、取消、版本及资源；方法未实现、环境缺失和无权分别返回，不用空成功处理器伪装接入。

**机制归属：** [兼容迁移与退役](../演进/兼容迁移与退役.md)。**相交问题：** U015、U025。

<a id="req029"></a>

### REQ029｜开发到运行再修改的完整过程

设计首次创作、多模块组合、生成、构建、运行、观察、错误修复、保存和下一次变化；不把第一段生成成功当成完整产品。普通交互允许按入口准备并运行，不以全工程生成作为普遍前置，也不把即时运行暗中加到预览。 直接编辑作者文本和成组修改是正常入口；propose/draft是可选的机器交接，不强制每次小改都完整编译或重写输入信封。

**机制归属：** [开发操作与任务边界](../开发/用途与任务范围.md)。**相交问题：** U066。

<a id="req030"></a>

### REQ030｜语义扩展与调度分层

函数、结构展开、编译查询、单机并行和远程执行分别定义；普通库扩展不改核心，部署方式不改变源含义。

**机制归属：** [递归并行与远程编译](../编译/递归并行与远程编译.md)。**相交问题：** U058—U064。

## 设计工作

<a id="req031"></a>

### REQ031｜只设计的权限边界

延续设计任务只交付规范和必要文档核对，不自行写产品程序、运行样例、安装依赖、部署或修改在线仓库。新的明确执行任务另按授权处理。

**机制归属：** [原则总纲与归属](原则总纲与归属.md)。**相交问题：** U005。

<a id="req032"></a>

### REQ032｜成果回到同一套规范

能裁决的设计直接修改对应正文、合同、示例和理由；必须给出实际数据拥有者、接口、正常/失败算法、开发者操作、产物和再次修改，并同步真实消费者。报告只说明实际结果，不成为另一套权威或以正反分析代替实际交付。


核心作者面修改必须同时完成实际写法、读入与有限补全算法、目标与运行入口、保存/回源和第二次修改；仅给新简写、字段或原则而让实现者猜其余行为不算完成设计。跨软件需求抽象与既有简洁源码是共同能力，接入现有模块不表示回退或替换；实际修订要说明哪些规则保持、哪些差错修正及其真实消费者，不用“重新设计”模糊成果去向。

**机制归属：** [文档编写与维护](../维护/规格写作与完整性.md)。**相交问题：** U048。

<a id="req033"></a>

### REQ033｜主动发现而不是等用户补名词

每次续作从目标正向推导义务，从机制反向核必要性，沿组合、故障和不同路径找反例；用户不是常规遗漏的唯一发现来源。

对已经明确的条件不重复追问；缺失但可安全推定的条件，写出基线和会改变结论的分支后继续完成可做工作，不把分析退回用户。真实授权、隐私、安全与工具边界仍须遵守。

**机制归属：** [工程挑战与覆盖边界](../演进/工程挑战与覆盖边界.md)。**相交问题：** U056。

<a id="req034"></a>

### REQ034｜目标到全部必要义务

总表与关系应区分共同满足、替代、条件激活、硬前置和协同；必要性、重要性、紧迫性、就绪和优先级不合成一个分数。

**机制归属：** [工程演进与实施设计](../演进/实施/主线前沿与准入.md)。**相交问题：** U057。

<a id="req035"></a>

### REQ035｜根假设受攻击后重算

先核原要求和最强竞争解释；发现根前提、分类或证据冲突时回到相关上游，改完整消费者，不只在末尾补例外。

开放设计先去锚并补齐变量，发现横向问题，再下探可检验的不可绕过约束；追踪间接效应、反馈、时滞、阈值和退出，核对事实，构造最强反例，必要时回退重算后才综合裁决。检验字面、机制与实际效果，不以其中一个代替另两个。

**机制归属：** [工程挑战与覆盖边界](../演进/工程挑战与覆盖边界.md)。**相交问题：** U056。

<a id="req036"></a>

### REQ036｜现在作出可实施决定

有条件裁决的接口、算法和默认应当选定并说明理由与重开条件；当前未取得全局最优证明不是无限延迟决定的理由。已经确认的机制变化按[完整变化的一次闭合](../维护/规格写作与完整性.md#complete-change-closure)先形成覆盖生产、消费、失败恢复、资源并发、迁移核验和退出的目标方案，再整体落实；短步骤实现不减免闭包义务，反证出现后重算相关决定，不承诺未知未来永不修改。明确当前范围哪些设计输入已足以编码、哪些只待实现或现实核验；全域未来义务不自动成为当前实施前置，设计阶段也不因此扩大授权。

**机制归属：** [实现解析与设计搜索](../编译/实现选择与设计搜索.md)。**相交问题：** U044。

<a id="req037"></a>

### REQ037｜不能迎合批评改产品

用户目标和授权是约束，事实和评价仍独立核查；提醒比较不等于采用命令，助手自己的选型不能伪装成用户要求。

**机制归属：** [原则总纲与归属](原则总纲与归属.md)。**相交问题：** U054。

<a id="req038"></a>

### REQ038｜所有已知不足持续存在

发现即保存具体问题、影响、责任、当前处理和下一交付；暂时没有方案仍要登记，合并不丢反例，延期不等于不存在。

**机制归属：** [设计状态与验证路线](../状态/前沿与登记规则.md)。**相交问题：** U048。

<a id="req039"></a>

### REQ039｜状态随成果更新

已完成有限设计不永久列为缺方案；设计、实现、验证、采用和收益分别更新，不由父主题未全关闭取消已有成果。

**机制归属：** [设计状态与验证路线](../状态/前沿与登记规则.md)。**相交问题：** U048。

<a id="req040"></a>

### REQ040｜基础能力系统研究

主动研究成熟语言的关键词、上下文词、运算符与完整机制，以及模块/库、工具链、目标、失败和相互作用；不能等用户逐项点名。SEC既已定义自己的语义，就承担完整语言体系责任；不能用关键词少、图灵可计算性或封装能力代替普通控制、内存与组合设计。研究范围广不等于无条件采用所有互斥机制，当前选择须明确落到作者、检查、运行、目标和编辑。

对会变化的公开事实核对其实际版本、日期、地域、样本和覆盖；追溯原始规范、数据、实现或事故记录，并检查独立支持、反方和共同来源。没有发现不自动等于不存在；稳定命题的条件未变时可以复用。

**机制归属：** [语言能力映射与最小控制](../作者/需求关系与能力边界.md)。**相交问题：** U030、U049。

<a id="req041"></a>

### REQ041｜安全边界之外要有正常成功路径

每个设计同时说明合法输入怎样完成、禁止什么、保持什么及资源和进展条件；永远拒绝不是满足任务。

**机制归属：** [文档编写与维护](../维护/规格写作与完整性.md)。**相交问题：** U005、U049。

<a id="req042"></a>

### REQ042｜不能把全局优越性作无依据承诺

比较同等任务、库、保证、冷暖成本和连续修改；明确支持范围，不能用架构图、关键词少或文档完整证明优于成熟工具。

区分事实、证明、重复验证、机制推导、现实推断、假设、预测和价值取舍；有不确定性时给出当前最佳判断、理由、最强竞争解释、反证、关键未知和反转条件，不用含糊并列代替决定。

**机制归属：** [目标术语与质量属性](术语与质量属性.md)。**相交问题：** U019。

## 文档与知识

<a id="req043"></a>

### REQ043｜详细说明可以长

完整合同和理由按消歧需要充分展开；不为短而删掉独立条件、算法或反例。作者任务输入简洁与设计解释详尽分别实现。

对外说明使用准确直接的语言，不强制输出固定模板或披露私密推理链；提供核对需要的公开事实、推导、反例、边界与未知。格式和篇幅不作为删去独立信息的理由。

**机制归属：** [文档编写与维护](../维护/规格写作与完整性.md)。**相交问题：** U019。

<a id="req044"></a>

### REQ044｜有效信息不能因整理丢失

保留会改变行为、决策或保证的独立机制、失败、替代、代价与来源；只删除同义重复、失效叙述和无实际作用的包装。

低权重、少数、异常和低证据分支只要有独立机制、反例或决策价值就保留并标明等级。不能以主流程度、已有代表例、文本长度或无法证明绝对穷尽为由取消已发现义务；只有重复、无依据猜测或真实边界才停止相应展开。

**机制归属：** [文档编写与维护](../维护/规格写作与完整性.md)。**相交问题：** U048。

<a id="req045"></a>

### REQ045｜每次修改同时清理

规范修订与其相交清理一起完成；不等待用户再次指出重复、旧版本、无效链接和未采用载荷。**实现、重构、测试、性能、目录或内部表示变化本身不触发规范修改。**先按[规范写入准入](../维护/规格写作与完整性.md#documentation-write-admission)判断是否实际改变已采用的公共合同、架构责任、用户可见行为、长期保证、设计理由或明确未决；没有这类语义变化且原文不存在独立遗漏、错误、歧义或理解/使用缺口时，规范文档写集保持为空；已有文档缺陷应修正，不要求先制造代码变化。纯实现情形下，实施事实留在源码、测试、提交或对应证据系统。只有准入成立后，才以受影响的规则及其真实消费者为单位同步拥有者、接口、例子、理由、状态和必要导航；只读扫描可定位同类残留，实际删改须核对上下文。检查不过时先修正相交内容，不把已知缺陷当作下一轮的例行提醒。

**机制归属：** [文档编写与维护](../维护/规格写作与完整性.md)。**相交问题：** U048。

<a id="req046"></a>

### REQ046｜当前工程文档不是修改日记

现行文档只描述当前采用的完整目标设计，保存需求、规范、理由、例子、依据及准确未决；**不镜像当前函数、文件布局、临时实现手法、测试计数、提交、PR、性能采样或某次修复步骤，除非其中某项本身就是稳定公共合同或长期保证。**仍正确且属于范围的旧成果须完整融合到当前拥有者；不要求读者沿历史版本、旧路径或修订记录拼出设计。旧聊天、逐轮成果、原型成绩、打包日志、快照迁移过程及文档旧址兼容工具不进入当前规范包；制作时的比较与去向核对不因此成为永久交付物。SEC产品自身的版本、依赖锁、兼容、证据和恢复机制仍是目标设计内容，不与文档历轮兼容混同。

外层交付包使用简短连续编号；准确当前源边界由包内基线声明，内容摘要由独立源清单从真实输入重算，发行字节由制品清单另行绑定，父输入及具体改动仅在确需的包外记录说明。无需每轮另发完整审计包；编号不自证采用、兼容或产品版本。

**机制归属：** [文档编写与维护](../维护/规格写作与完整性.md)。**相交问题：** U048。

<a id="req047"></a>

### REQ047｜知识按命题及工程用途组织

所有参考资料统一保存来源版本、命题、前提、限制、采用或不采用及其使用/维护位置；相同来源的独立命题可合并，多个转载不作多个证据。表格、单独链接和理论线索也须按身份纳入，不能仅维护当前讨论中被点名的少数技术。 组织应参考已取得的历史讨论与相交世界知识，但规模实例必须区分纯规范、图纸、历史制品和运行/实验数据；不能把材料库容量或无依据的行数配额转成SEC的目标。

**机制归属：** [设计依据与资料边界](../依据/来源/设计依据与资料边界.md)。**相交问题：** U055。

<a id="req048"></a>

### REQ048｜条件复用而非无理由重搜

每次任务和机制变更先按实际使用点查已有判断并触发来源协议；前提与用途不变可复用，动态事实、实际采用、版本或新反例变化时定向核原始资料并更新消费者。交付前检查全目录的归属与未决，不无理由重搜全部资料，也不把结构整理当外部重新核验。没有已部署的持续任务就不承诺后台监控或未来永不搜索。

**机制归属：** [设计依据与资料边界](../依据/来源/设计依据与资料边界.md)。**相交问题：** U055。

<a id="req049"></a>

### REQ049｜唯一归属和必要导航

完整规则由一个位置维护；索引链接定位而不复制，锚点只为实际引用；结构可解析不等于工程正确。 系统级入口先说明产品、环境、主要职责及相互关系，具体表示和机制在所属子主题展开；不让局部术语、最新范本或后续工作流程占据总架构。不得为符合层次而全局改名、删掉精确概念或用更抽象的词隐藏原语义。目录按责任，入口按任务，段落按因果和接口组织。每个正文有清楚的职责与交接；长规范允许详细，相关任务能够直达所需范围，不按修改轮次组织知识。维护理念必须在改原文、同步图表/代码围栏和消费者、保留独立信息及准确更新状态中执行；写有哲学原则不替代这些动作。 图必须覆盖读者需要理解的系统边界、模块和状态拥有者、数据与调用、关键时序、失败恢复及算法结构。数量、层级和细节不足属于设计交付缺项；不能仅检查已有图的正确性就称完成。需要分层时补充关联视图，放回机制拥有者，不用一张总览、纯文字列表或删除正确细图代替充分图解。 HTML及便捷摘录仅按实际阅读用途从固定正文派生；没有独有规范，也不作为每次交付前置，版本/节选与验证范围准确标注。

**机制归属：** [文档编写与维护](../维护/规格写作与完整性.md)、[全体系信息结构](../信息/全体系信息结构.md)、[文档重组](../维护/文档身份与重组协议.md)。**相交问题：** U048。

<a id="req050"></a>

### REQ050｜要求到机制的可查映射

把实际取得的用户约束映射到规范或明确缺口；产品要求、设计者选择、技术提醒和外部观点分别标识，不以保留若干原则编号代替要求核对。核查内容包含主体、对象、条件、强度、来源、正常行为、禁止与例外，以及调用方是否真的遵守；一条要求有链接只证明可定位。新要求先合并到已有相交条目，确有独立义务才新增编号。

**机制归属：** [原则总纲与归属](原则总纲与归属.md)。**相交问题：** U054。

<a id="req051"></a>

### REQ051｜写入、装载、执行和核验分开

文件存在只能证明已写入；未来任务须实际读取；工具强制与运行符合性另有证据。不宣称所有历史已读取或平台自动永久记忆。启动、上下文压缩后、委派交接、范围或规范变更、危险动作前和最终交付前，均按[装载与动作检查](../开发/AI协作/规则装载与任务恢复.md#任务启动的原则装载与动作检查)恢复并核对相交约束。执行者负责发现缺失并补读，不能要求用户重复已经存在的要求；短提示、缓存或下级文件不能静默删除条件和禁止项。

**机制归属：** [AI上下文与受控协作](../开发/AI协作/需求与作者上下文.md)。**相交问题：** U054。

## 维护与冲突

收到新输入，先辨别目标、条件、事实、技术比较、采用决定和实际授权。相同要求进入原条目；授权主体、对象或作用范围不同的要求分别保留。决定改变旧要求时，按[原则冲突裁决](原则总纲与归属.md#约束冲突的裁决顺序)处理，修改原拥有者和相交消费者，不在末尾追加一条相反规则。

本章规定“应满足什么”。具体算法由机制规范负责，当前采用与替代由D理由负责，剩余问题由U登记负责；REQ、D、U不能互相代替。文档整理仅改变表述与归属时不偷偷改变产品范围。已经证实的错句须改正，不以原字节保全代替正确性。

对没有落实位置的要求先登记实际缺口；对已有机制但违反要求的正文直接修正。检查分别说明取得范围、文字与引用检查、语义核对、实际装载、工具执行及运行证据。只有对应依据存在时才能声明相应层次完成。包外核对可保留必要原句和删改去向，不进入当前产品的永久执行日志。
