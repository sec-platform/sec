## 适用性与最小闭包

### 不把最大模型强加给所有工程

请求必须说明输出、保证和允许的动作。类型、语义、数据依赖、真实权限与故障恢复按当前请求展开；不是把所有领域、画像、验证方法、IR和研究模型预先实例化。裁剪也不能靠忽略未知边和真实风险得到虚假最小。

### 三种“最小”必须区分

在已经固定的一条实现路线、有限图与单调依赖规则上，从请求根迭代加入所有必需依赖，可求该模型中的最小不动点。它不证明依赖发现完整，也不证明现实中没有更小的另一种实现。

存在替代后端、可选保证或互斥约束时，先在明确预算内解析可行路线；每条路线计算自身闭包。不能将所有替代路线做并集后叫最小，也不能仅因未搜索到某路线就断言不支持。成本按向量与明确策略排序，硬约束不参与任意加权抵消。

依赖未知时，返回健全过近似、未决前沿或对应输出阻断。完整结果需要证明所需闭包足够；最小化只是可关闭的优化。非单调规则不能混入宣称单调的固定点组。

### 需求、数据、证据与准入闭包

定义依赖决定如何解释输入；数据/降低依赖决定如何生成产物；证据生产依赖决定怎样检验声明；动作准入决定当前能做什么。它们共享引用，但边类型和时间方向不同。

缺少部署后的读回阻断最终结算，不阻断该次部署开始前的合理准入；缺少当前写权阻断写回，不阻断有读取权限的候选预览；缺少必需类型或绑定阻断完整生成，不阻断保全原文。发布组有共同不变量时一起检查，不能用局部就绪拆开原子义务。

### 适用性结果

要求、适用性、实现支持、执行结果与现存责任是不同坐标，完整类别及生成/执行/移除动作由本章[不需要部分的处置与退出协议](#不需要部分的处置与退出协议)唯一规定。必要能力当前不支持，不能反推不适用；未知也不变成默认允许。

零新增执行可以来自合格复用，也可以没有适用义务；没有足够输入不能从零动作推出通过。[变更影响](../编译/查询增量与性能.md#变更影响选择与最小充分闭包)规定各目的的选择。

### 默认不加载与按需增加

内存纯生成只需要当前定义、类型、绑定、降低和结果；不要求持久事务、AI和发布。文件导出增加文件能力和完整清单；受控写增加前像、协调、恢复及读回；团队、离线、运行保证按真实需求增加。画像可以开放组合，不是固定六类产品枚举；组合不允许后加载覆盖前面的硬条件。

### 可见信息切片与代价

CLI、IDE和AI只读取与当前目的、依赖和披露权限相关的切片。未知、阻断和展开引用必须保留，不能因显示预算被折叠为成功。AI上下文不默认包含全库设计、所有历史报告或所有生成AST；展开后仍能追到来源和当前状态。

新增字段、对象、端口、服务、索引或检查前，说明真实消费者、删除后果、已有可派生替代、独立生命周期/权限/故障、普通路径固定成本和退出条件。没有消费者的未来义务留作设计约束，不进入运行时和公共API。

真实读写范围、负依赖、共享不变量、不可逆效果、预算/取消、未知完成、兼容与残余风险只要适用就不能删。对新类型/语义无法解释的情况允许原生边界或核心版本演进，不能为了现有框架优雅牺牲用户能力。

## 模型组合、断言集与目的绑定定义

### 1. 位置

本中间表示是多上下文冲突或跨模型联合设计时的可选分析视图，不是普通工程编译的强制入口。启用时，它位于相关观测/工程语义与该次设计搜索之间。它解决的问题是：多个上下文、法域、领域、证据和权威断言如何在不伪造全局一致性的情况下，编译为某一用途可消费的最小系统定义。

### 2. ModelPortfolioIR

```text
ModelPortfolioIR = {
  kernelRevision,
  modelCells,
  crossCellRelations,
  assertionSets,
  resolutionProtocolRefs,
  conflicts,
  translationLosses,
  assumptions,
  unresolvedFrontier,
  portfolioDigest
}
```

### 3. ModelCellIR

```text
ModelCellIR = {
  cellRef,
  contextAndJurisdiction,
  subjectUniverse,
  definitions,
  invariants,
  operations,
  authorityRoots,
  validityHorizon,
  privateStateBoundary,
  importedPublicContracts
}
```

ModelCell 不等于进程、目录或包。一个领域可以因法域和目标环境形成多个 cell；一个物理服务也可以承载多个 cell adapter。

### 4. AssertionSetIR

```text
AssertionSetIR = {
  propositionFamily,
  assertions,
  compatibilityGroups,
  conflictEdges,
  precedenceCandidates,
  evidenceAndAuthorityRefs,
  challengeAndRevocationState
}
```

矛盾断言不能触发经典逻辑爆炸。查询必须指定上下文、决议状态和容忍策略。

### 5. ResolutionIR

```text
ResolutionIR =
  | Resolved
  | ConditionallyResolved
  | ContextSplit
  | Conflicted
  | UnderDetermined
  | NonJusticiable
```

每个结果引用唯一 ResolutionProtocol 和输入断言集。`Resolved` 不是删除异议；历史断言和重开条件仍保留。

### 6. PurposeBoundDefinitionIR

```text
PurposeBoundDefinitionIR = {
  purposeRef,
  selectedCellRefs,
  selectedDefinitions,
  resolutionReceipts,
  isolatedConflictRefs,
  observationCutRefs,
  operationAndAuthorityClosure,
  assumptionAndUnknownEnvelope,
  validityHorizon,
  definitionDigest
}
```

仅当该请求选择了此联邦分析分支，且后续输出依赖相应决议时，才要求所选 PurposeBoundDefinitionIR 的相关部分闭合。单一已采纳模型可直接进入常规 DesignIR/ImplementationIR 或确定性 lowering。无关上下文的未决冲突不阻断已封闭输出；所需冲突无法隔离时才阻断受影响保证。

### 7. 降低规则

```text
ModelPortfolioIR
+ purpose/query/effect roots
+ resolution receipts
+ risk/unknown budget
→ PurposeBoundDefinitionIR | NonSolutionIR
```

不得：

- 通过加载顺序选择冲突值；
- 把多数票当通用真值；
- 把组织 owner 当事实证明；
- 为了生成单一 IR 删除法域差异；
- 让低层实现限制反向改写定义。

### 8. 增量语义

ModelCell 内局部变化只失效引用它的 purpose 定义；ResolutionProtocol 变化只失效消费该决议的问题；共享 kernel 变化才可能广泛迁移。

### 9. 验收

- 冲突断言可往返；
- 不同 purpose 可选择不同兼容 cell；
- 同一 purpose 的必需依赖若仍有未决冲突，则拒绝对应输出/保证；可隔离部分仍可产生诊断或合法输出；
- 顺序变化不改变输出；
- 历史决议可重放；
- 新 ModelCell 不修改无关通用 pass。

## 工程情境组合与能力协商

### 不以行业名单定义可支持世界

本篇把既有ProductProfile、TargetProfile、DomainModule和适用闭包连接起来，不新增覆盖它们的超级模型。工程属于哪个行业只供检索；真正决定设计的是对象、可观察状态、时间、效果、权限、资源、失败、消费者和所要求的保证。一个工程可以同时含交互界面、数据流水线、设备控制、人工批准和商业协作，不能被强塞进互斥行业枚举。

目标是尽可能扩大可表达、可集成、可生成、可验证的需求集合，同时对每个动作保持准确支持范围。不能把“可导入不透明附件”计为“已理解并能正确生成全部语义”；也不能因为不透明附件存在就拒绝其他已闭合模块。

### 情境的可组合坐标

`EngineeringContext` 是一次请求的冻结选择视图，不是又一份世界事实。坐标用命名空间键、值类型、单位、revision、来源和知识状态表示；新增坐标无需修改核心行业switch。初始关注族包含：运行形态；数据与状态；时间与连续性；交互与人；效果与可逆性；权限与信任；资源与规模；连接与同步；目标语义；生命周期；所需保证；组织与外部约束。该划分是发现入口，不限制后续扩展。

已知、采用的假设、未知和冲突不可互换。未知硬件字节序不能默认成当前宿主；以假设做仿真可以生成仿真结果，但证据必须绑定假设。单位不同先通过显式有理转换或单位方言检查，不能拿20毫秒和20秒直接相等比较。时间点必须带时间域。

一项需求引用能力合同、精确合同revision、必要保证与允许效果。`sec.storage.transaction/1` 是能力身份，不是SQLite品牌；具体Provider的实现revision、部署实例、健康和资格另行记录。

### 组合而非最后写入获胜

导入多个画像不等于启用全部能力。先按所选输出、阶段和适用条件确定生效范围，再合并相交必需能力、禁止效果和硬约束；互斥或条件性的备选分别求解，不将未选择分支的全部依赖取并集。相同事实在同一语义scope有不同值时保留冲突；权威规则可以选择适用事实，但必须留下选择依据。偏好按已采用的排序或效用规则处理，不覆盖硬约束。

要求离线持续执行与每次动作都查询远程当前撤销状态存在真实条件冲突。可行分支是：只允许离线读取与提案；预先授予有上限且仍符合目标的离线能力；提供本地可验证的短期授权；或改变连接要求。不能把无法在线验证直接解释成仍被授权。严格即时撤销与无连接无限期写入不能靠同一个配置开关同时实现。

一个目标同时要求无界精度、严格有限内存和任意输入完成，也须说明输入界限或拒绝条件。约束求解未完成不能称为不满足；已证实的冲突返回实际取得的冲突关系及范围；只有执行了相应最小化并具备依据时，才声称子集极小或基数最小。

### 有限闭包与能力解析算法

先固定请求根、模块revision、画像和受信政策。每个根的必要依赖分别展开，记录引入原因；缺失Provider只影响到达它的根。新增无关领域不会自动扩大原根的装载、运行、测试或读取成本。共享必要依赖失败则影响所有真实消费者。

一个能力需求只有在合同revision、所需保证、效果许可、目标约束和相关资格都满足时才可形成合格Provider绑定。接口名称相同不等于语义符合。排名表达已采纳的选择政策；最高优先级有多个候选时，先确认它们是否都满足当前完整合同，并检查已委派的稳定破同分或成本规则。有合格决定规则即可选择，不要求作者手填绑定；没有相应委派且差别影响任务时，才返回该项选择未定。目录注册先后不是破同分依据。唯一候选依然可能缺真实资格，解析成功不等于当前有权执行。

对依赖循环分型：纯声明可两阶段链接；受限单调分析可采用带终止依据的固定点；无种子的效果/证据依赖环必须改设计。某实现若仅支持无环解析，应声明该实现子集并在遇到合法循环时返回实现能力缺口；不能把它写成整个产品拒绝递归的语言规则。节点、边、深度和计算预算到限输出已解析部分与前沿，不返回假无解。

最终得到 `ResolvedRoot`、`UnresolvedRoot` 或 `UnsupportedRoot`，以及选定Provider、必要依赖、能力缺口、假设和证据义务。三者是解析状态，不是产品成熟度。全请求可以部分解析；需要原子组合的输出组仍需全部相关成员满足，不能把可独立返回误用到原子发布。

### 支持是多维关系，不是一个布尔值

每个 `(语义模块revision, 目标画像revision, 操作, 保证范围)` 分别报告：保留、解析、检查、执行解释、降低生成、往返编辑、目标运行验证、迁移、现场支持。某模块能保留原文但不能优化时，仍能被集成；优化器不得穿透未知效果。某语言能生成不代表能逆向重建任意源码。默认显示当前请求实际需要的能力单元与其中的缺口，允许展开完整矩阵。读取、生成、逆向编辑和现场验证没有一个共同的最低序；不能因逆向尚不支持就把合法正向生成显示为不可用，也不能取最高项冒充全部支持。

TargetProfile 按数值域、布局、资源、错误、并发、效果和目标可表达性声明限制。降低必须保留所承诺语义，或产生带范围的残余义务；不得为“支持更多语言”静默把大整数转浮点或把阻塞调用转异步而改变顺序。

### 开放模块、原生区域与核心演进

领域模块提供类型/操作、公开语义接口、验证器、降低、来源映射及迁移。通用Pass只访问它声明需要的接口；接口缺失时选择保守处理、跳过该变换或返回残余，而非猜测。MLIR的接口和目标合法性机制提供了可检索的工程先例，不证明SEC的完整实现已经完成。[接口依据](https://mlir.llvm.org/docs/Interfaces/)；[转换依据](https://mlir.llvm.org/docs/DialectConversion/)。

原生源码、人工决策、外部服务、物理过程可以通过显式边界参与：输入/输出、可观察效果、权限、失败、超时、读回与保证范围必须表达。不能把未知内部语义序列化为 `any` 然后允许任意重排。新类型若揭示原有“离散状态就足够”是假设，应加入连续时间或概率语义的领域合同；若身份、因果、权限等公共关系也无法表示，再演进共享核并迁移受影响消费者。

### 控制面不进入被控系统的硬实时回路

SEC可以生成控制代码、配置、测试、固件与保证材料，但不因此成为目标实时调度器。传感器的连续物理语义、采样、离散化误差、WCET与稳定性由目标方言和验证方法承担。普通Node/Bun控制面不能因一次平均耗时很低就获得硬实时资格。不可观察的物理状态保留建模误差与外部校准任务。

### 可扩展性的反证与测试

关键测试包括：加入无关插件不改原输出；加载顺序置换不改绑定；同级竞争仅按已接受的稳定规则选择，未委派行为不静默决定；不支持的高风险目标不牵连独立纯输出；新的维度能有类型地进入条件和报告；出现跨模块共享不变量时激活组合验证；移除Provider后保留已生成内容但取消其新执行资格；策略变化只失效受影响证据。

“新领域不改Core”是一项待测属性，不是无限保证。有限异质插件能证明这些实例无需改核心；一个无法自然表达的真实新域仍可推翻当前接口。兼容升级、新核心能力和原生保留都是合法答案，禁止为了维护通用宣传把异常藏在字符串中。

### 情境修订绑定

实现计划同时绑定 `contextRef` 和 `contextRevision`，只比较稳定ID不够。情境修订改变时旧计划拒绝直接复用，重新解析需求/候选/资格闭包；只改对象内容却保留同一revision属于上游身份合同违例，不能由一个字符串匹配检查独自认证。有限示例的身份来自冻结夹具，生产需由权威不可变记录和内容身份支撑。

### 情境不是自由表达的上限

画像描述部署/风险/目标约束，不拥有用户可定义类型和行为的全集。普通新算法不需要新增画像；新业务概念可由一般定义包表达；确需新语义时由用户提供方言合同。协商器选择已经注册的实现能力，但其目录不是用户可计算行为的白名单。

作者与扩展生命周期归[用户定义语言语义与编译扩展](../作者/组合/语义扩展与领域接合.md#用户定义语言语义与编译扩展)。本篇32实例等消费者用来发现组合冲突，不证明图灵完备或所有工程可自动生成。一般程序底座与能力目录的区分必须进入新增场景和产品说明的验收。

## 产品画像、能力开关与最小部署形态

### 1. 同一核心，多种产品画像

SEC 可作为本地 CLI、IDE 扩展、团队服务、企业平台、离线系统或受控 AI 工程环境。画像选择适用能力，不复制核心语义。

### 2. ProductProfile

```text
ProductProfile = exact {
  acceptedOutcomesAndNonGoals,
  userAndOrganizationModel?,       // 仅实际存在的主体/组织约束
  enabledDomainAndCapabilityRefs,
  targetAndHostProfiles,
  authorityAndTrustModel?,         // 实际读取/执行边界；纯值不伪造主体
  dataPrivacyAndResidency,
  deploymentAndSupportScope,
  resourceAndCostConstraints,
  optionalCapabilityTriggers
}
```

### 3. 能力开关

语言画像选用、编译实现选择、目标功能启用和实际作用权限不是同一种开关。各自绑定适用范围、缺省、依赖和演进；目标能力或策略修订有真实副作用时再走相应准入。纯函数使用一个类型不需要先激活企业政策。业务可选功能不以启动全部后台设施再提前return实现；实际移除见本章处置协议。

### 4. 最小部署

纯内存编译和计算库不要求持久库。需要长期操作才使用本地恢复存储；需要共享写入才增加相应协调。团队不必远程执行，云部署不必多租户，每种组合按实际要求判定而不是逐层购买一整套平台。

### 5. Optional capability

browser、container、native、remote model、cloud 和 telemetry 缺失不阻断不需要它们的核心路径。required 由具体 operation/claim 决定。

### 6. 画像迁移

从本地到团队或云不是配置翻转，需要身份、数据、权限、存储、secret、Support 和部署迁移。

### 7. 验证

最小安装、离线运行、可选 Provider 缺失、画像切换、功能依赖、租户启用、支持范围不匹配和旧画像数据迁移。

### 实例化而非全局开关叠加

ProductProfile描述被接受的产品需求，TargetProfile描述目标平台及语义边界，DomainModule提供扩展合同；[工程情境组合与能力协商](#工程情境组合与能力协商)的EngineeringContext只是从这些对象取出的冻结求解输入。禁止在UI、Provider和部署配置中各维护一套相互独立的能力开关。

使用步骤是：合并不可抵消的硬要求，生成按输出需求闭包，选择显式Provider和保证，选择[物理实现画像与可逆落位方案](../架构/装配/模块与运行实例.md#物理实现画像与可逆落位方案)的物理映射，生成缺口/证据计划。只生成纯源码时不初始化数据库、调度服务、网络会话或全生命周期审批。组合冲突返回具体条目和替代分支，不把用户需求悄悄降级成默认值。

## 事务画像的组合资格不是单项交集

对[事务作者画像](../领域/状态关系与流/事务与交付.md)，语言支持、目标表示、存储原子集、授权见证、事件编码、投递顺序与去重必须组成实际可行的同一绑定。两份独立可用的驱动不能组合出它们都没有提供的跨库原子性；支持JSON的端口也不自动保持中立Int/Text/变体。

支持按所选输出根判断。仅输出纯decision时可以不具备数据库；要求生成并运行operation时必须具备它实际依赖的事务和准入；加入可靠通知再引入对应交付义务。缺项报告精确到这个组合，不能静默丢通知、换成Saga或把不支持降成不适用。

某目标可借助明确运行库满足语义，不要求所有底层语言原生提供同样构造。实际库、配置和读写域成为绑定输入。首期可用静态显式选择和局部规则判断，不先建设能自动搜索一切最佳组合的全局求解器。

## 不需要部分的处置与退出协议

“设计里有这个机制”不等于本次要求它；“源模块声明了它”不等于已经实例化；“目标支持它”不等于应该启用；“没有实现”也不等于它不适用。本节是这些处置的唯一规范，其他篇只引用，不重复维护一张全局开关表。

### 四个判断先分开

对同一个范围分别判断：**要求与禁止；适用条件；当前实现/证据；已经存在的状态与剩余责任**。不要合成一个required/unsupported/off的大枚举。未选择的功能可以已有实现；必需的功能也可能尚未实现；一种功能已停用仍可能有恢复数据或待完成外部作用。

简单请求不用创建所有这些状态对象。服务从本次源、目标、政策及观察派生相交判定；无争议的无关项不进入AI默认结果。只有影响当前输出、调用者明确询问或者存在真实残余义务时，才展开其理由。

### 具体处置表

| 情况 | 当前设计、构建与执行动作 | 保留什么、何时重开 |
|---|---|---|
| 不适用：条件在已知范围内为假 | 不加入当前语义/生成/检查义务闭包，不生成占位代码或not-run仪式 | 保留可检查的适用条件；相关输入改变时重新判断；不是证明开放世界永远不会用到 |
| 可选且未选择 | 保留用户有意维护的定义；当前实例不建立，不激活插件执行、不拉依赖、不生成目标模块/配置/后台任务 | 选择发生或当前请求新增消费者时再处理；库可用与实例启用分开 |
| 明确禁止 | 排除违反项与其替代路径，校验实际执行/产物所需闭包；不能在失败回退时偷偷重新引入 | 禁止约束及可信来源；修改禁令必须有实际决定。编译期联网与目标程序联网分别限制 |
| 有未来实际需求但本次延期 | 记录具体义务、触发、当前默认、依赖和验收；不建立空服务/Stub/注册表和永久兼容壳 | 内容留在唯一的相关设计或工作范围，延期不是当前支持；触发后不能再当无关 |
| 本次必需而当前不支持 | 对相交输出报告缺设计、缺库、缺后端、缺目标或缺证据；允许完整的独立子集继续 | 真正缺项和合法替代，不能丢弃要求后仍叫原请求完整，也不自动转交用户手写原生 |
| 未知是否需要 | 先按相关引用、阶段及真实观察收窄；与当前保证相关时保守计划、限制强声明或阻断对应作用 | 明确未知及获取方法；未观察不是absent，未知亦不全局停机 |
| 已启用但现在要求关闭 | 停止新准入；处理活动写者、消息、资源和恢复责任，再移除可删除实现 | 保留当前作用结果和必要读取/解释资产；不得因配置变false就递归删除用户状态 |
| 重复、失效或无消费者内容 | 在确认无实际运行/法定/恢复依赖后合并或删除；独立理由/反例先落到拥有者 | 当前有效规则，不复制全部旧账本；删除定义不抹去实际发生的效果 |

明确禁用可能要求立即撤销目标权限，而不等待旧任务自然排空。此时选择实际可执行的停止、隔离、停放或补偿路径；不能为“平滑关闭”违反禁令，也不能在目标无法中止时谎称作用已经停止。恢复数据与历史读取器可以保留，但不因此继续给旧代码执行权。

### 从声明到运行的分阶段消除

**源与解析。**不属于当前输出的模块可以仍保存在用户工作区；它们不是垃圾。当前显式导入的模块按语言规则检查合法性和初始化依赖；不能随意跳过同模块语法错误。尚未选择的整个语言画像不自动加载；增加普通库不动态改变解析器。

**选择与绑定。**先评价本次真正需要的能力和条件，再合并生效的硬要求、禁令及组合限制。不能把所有可选画像的能力取并集，随后要求纯计算同时配备身份/数据库/消息。缺少必要提供者仍明确失败，不通过关闭相关要求伪造最小依赖。

**生成与链接。**只物化选定输出和真实依赖。一个定义从未被选中时不产生空Handler或disabled分支。删去未引用代码仍要保持模块初始化、反射、动态调用和显式保留规则；原生动态边界未知时可保守保留相交部分，但必须说明更强的“完全不含该能力”尚未得到支持，不能用字符串扫描认证安全。

**运行。**未启用就不启动对应线程、连接、探测、计时器、日志写入和后台轮询；不是启动以后让函数立即return。实际宿主仍有其资源与权限要求。目标纯计算没有身份平台，不表示运行它的工具获得随意联网或文件读写权。

**升级与移除。**先识别运行实例、在途内容与当前权威，决定停用、排空、转换、隔离或补偿；然后删除确实可删除的实现。只删编译产物不能代替目标关闭；仅停止新代码也不能自动结清旧消息。独立不相交的计算输出不等待这些残余工作结束。

### 可执行的裁剪步骤

1. 从本次任务目的、所选输出根、实际源/目标/政策建立固定输入；不默认生成整棵工程。
2. 解析实际引用和解释合同，区分语义依赖、数据依赖、检查与真实作用，保留负观察及选择目录的变化关系。
3. 在明确条件下选择一条可行实现路线，按该路线加入必需依赖，检查禁止项与共享约束；不把所有备选实现混到一张强制执行图中。
4. 结果只列应当生成或执行的内容及影响当前结论的缺口；无相交内容的功能既不算完成，也不算失败。
5. 对要移除的已存在机制读取实际运行/持久状态，按上表处置；无历史实例的新纯函数跳过此步骤。
6. 发布或执行时复查与当前条件相交的前提；不能让旧裁剪缓存复活旧权限或漏掉新增强规则。

这些步骤是规则而非六个新服务。小实现可采用显式选择和全量闭包；有证据表明成本过高再细化索引与增量。明确输出是否完整，比宣称找到了绝对最小包更重要。

### 必须通过的反例与证明范围

无关库和未选事务画像的增加，不应改变纯核的实际工具表、目标依赖、产物或模型提示闭包；若存在真实全局注册，则先承认依赖而不能冒称无关。无网络允许范围内的目标不能在GPU不可用时自动切到远程GPU。源里没有审计事件的纯算法不生成审计表，真实宿主的安全日志政策又不会被算法擅自关掉。

目标程序要求可靠通知而通知提供者缺失时，仍是相交输出未完成；关闭并删除已有订阅时，必须处理尚未交付事件。这与全新纯函数完全不需要通知，是不同的事实。

设计中的精确零成本指“没有引入该类无关设施”，不是保证编译器没有读取任何配置字节，也不是未测就声称内存或时间等于零。静态不可达、构建未链接、运行未激活、权限不允许和责任已退出分别有相应证据，不能只用一个off字段认证全部。

## 请求闭包与组合闭包的先后

先由请求目的和被选择的语义根确定当前义务；实现搜索在这组要求内选择路线；路线之间的连接再产生所需适配、环境与资源义务。三者迭代到有限稳定范围或预算结束，而不是把所有可能路线、所有检查和所有治理画像取并集。

新增适配带来的网络、磁盘或权限如果被原任务禁止，则该路线不合法，不能以“系统内部步骤”绕开。用户仅要求生成时，后续部署假设可以作为未执行条件保存，但不成为已经运行成功的依据。用户要求当前产物满足全部任务时，相交的真实缺项必须保留，不能将它降成可选。

并非所有义务都要跑同一个证明器。简单类型/范围直接判断，复杂关系按已选择的方法处理，无法完成的返回具体声明与原因。闭合普通函数不必证明整个环境永久可用；已经选择可靠投递时，则不能用当前正向代码生成忽略接收方和重试条件。

候选有部分独立输出时，独立性依据真实共享要求、全局限制和目标副产物判断，而不是依据两个文件名不同。共享一个公共条件的根不能各自忽略它后合并通过。完整过程分别见[边界闭合](../作者/共同语义关系.md#组合边界摘要与义务闭合算法)和[任务判定](../运行/保证/要求证据与裁决.md#原任务要求与候选合同的满足判定)。

## 从请求根计算实际义务与激活集合

本节拥有按请求裁剪的工作算法；它消费已接受要求与解析器选定路线，不重新定义业务、不授予权限。输入是目的、输出根组、规则与能力目录的固定修订、每个已知条件的来源、当前预算。结果包括必需定义/数据、所需计算、实际作用前置、作用后义务及未决前沿；它们可以引用同一对象，但不合并为一个无类型的依赖集合。

### 边的具体含义

| 边 | 什么时候加入 | 达成条件 |
|---|---|---|
| 解释/数据需要 | 所选节点的含义或结果需要该输入 | 内容和解释匹配本次主体 |
| 执行前置 | 当前动作开始前必须满足 | 在实际准入时成立，不凭旧缓存永久化 |
| 替代路线 | 多个实现可以满足同一要求 | 从合格候选中选定一条或明确组合，而非全部加入 |
| 结果义务 | 执行后必须产生读回、证据或交付 | 在后置阶段取得；不会倒过来阻止产生它的动作 |
| 失效关系 | 变更使已有资格需要重检 | 更新相交结论，不表示重新执行已经完成的外部作用 |
| 恢复责任 | 已发生状态要求保存/继续处理 | 由当前真实状态关闭，不因当前请求不再引用就删除 |

### 有限工作表算法

从当前R建立待处理队列，每个元素为“节点、目的阶段、要求强度、适用条件”。已有完成的同修订结果先作资格检查，合格时记录复用而不新增执行。取一个元素后：

1. 判断适用条件。确定为假则记录该条件与不适用范围；确定为真继续；未知则记录缺失来源，允许条件设计或保守覆盖，不把未知改成假。
2. 查找本阶段必需的规则与真实依赖。实例化必要泛型/关系；能力名称存在而实现不合格时返回具体支持缺项。
3. 存在替代路线时交给[固定输入选择](../编译/实现选择与设计搜索.md#固定输入下的实现选择算法)。选定后只加入该路线必需边。未来备选仅保留选择依据，不加载其全部设施。
4. 将解释和数据前置加入相应队列；将后置义务登记到执行后的阶段。共享不变量连接的根合并为共同验收组，而不把无关根一起锁住。
5. 已访问相同节点/阶段/解释时复用结果。遇环先区分声明互引、允许的语义固定点和必须先完成的执行环：前两者交给对应算法；无种子执行环报告具体环，不无限排队。
6. 队列结束时，每个根要么闭合，要么有可定位的未知/缺项/冲突。预算先结束时，保留已完成根和实际未读前沿；已有不完整节点不贴完成标记。

这是固定有限规则与路线下的闭包计算，不证明已找出全世界最小方案。若依赖发现仍是保守范围，允许更大但正确的计算；精细化只减少确实无关的工作，不减少必要语义。

### 实际激活、禁用与退出

纯计算根只激活相交解析、检查和后端，不创建运行数据库；某个函数引入明确文件端口后，只为该真实作用增加文件宿主。请求只看源码时，目标部署后的消息确认是未请求义务，不进入本次成功条件。请求本来包含可靠消息保证时，该义务必需；不能通过不选消息工作器把原任务伪装成完整。

对已运行组件，未再被新请求选中只停止新增准入，不删除现存责任。退出算法读取其真实在途引用、持久意图和资源拥有者，依次选择继续排空、转交、显式取消/补偿或保留停放。没有实际完成证据就不宣布退役；禁止继续使用的组件先阻断不安全入口，再处理可允许的恢复路径。

默认工作表同进程运行，使用局部集合与类型化边；不要求产品一开始部署图数据库或服务编排器。规模使完整闭包成本不合适时，可以采用正确的增量查询，但与相同输入的完整算法比较保持结果和前沿含义。

## 规划义务和运行能力的激活不互相冒充

[目标义务关系](工程挑战与覆盖边界.md#目标到义务的自主发现主循环)说明为什么需要某能力，[当前工作前沿](实施/主线前沿与准入.md#问题优先级与当前可推进前沿)说明此刻应该设计或实现什么，[编译动作图](../编译/递归并行与远程编译.md#2-三张关系视图不是一棵万能任务树)说明本次产物怎样计算。三者共享来源与引用，但不生成一张必须全量满足的世界依赖图。

远程编译是并行工作的一个条件部署选项，不是一般编译或增量的必要能力。用户指定必须远程/设备执行时检查对应硬条件；只是希望更快时，可以选择合格的单机路线。未经允许不能为回退扩大上传、工具执行、数据驻留或依赖获取。

一组请求需要多个产物时，每个产物根有自己的闭合范围，最终交付按原AND/OR关系聚合。调度器可以先返回完整独立根，不能把缺失的必需根改成“不适用”；也不能让一个可选根失败取消无关已完成的值。

## 关系方法按实际请求启用

没有关系算子时不装关系运行库、SQL或维护状态。只请求纯列表上的完整计算时，合法普通目标集合方法就能满足，不以没有数据库判为不支持。请求双边任意增删时，仅单侧插入触发的物化视图不合格；请求强快照时，仅分别固定各源版本的适配不合格。

这些是不同能力行，不是对某产品的整体好坏评分。已有合格绑定按原委派选择；只读源不足、本地披露不允许、目标值域不覆盖时保留实际缺项，不把它们解释为默认空表。具体资格见[关系规范](../领域/状态关系与流/关系查询与维护.md)。

## 当前计算优先与条件设施的准确裁剪

本次任务明确先完整设计计算系统。数据库、SQL执行、消息、耐久工作流、远程编译和多租户服务在当前工作范围保持未激活；已有规范和问题保留来源与触发，不删除成永久禁用。有限内存关系、图算法、状态和本地任务调度仍属于计算，不因共享术语而一并禁用。

新目标的必须项从实际输出根导出：库不要求main和图标，CLI需要入口/参数/输出规则，交互应用还需要会话与显示，GPU需要设备与同步；都不先附加事务系统。当前范围没有声称全部这些目标已实现。普通函数能生成而完整应用缺Runner，是不同支持维度，应分别返回。

`sec.compute-run/1`也是按需协商的能力，旧工具的operation控制分支仍有效；不声明就不接受start，不以同名内部方法替代公开实现。未启用观察时不产生probe和日志；已启动真实工作即使后来暂缓相关能力，也先按其原责任结算。

## 暂缓实现时仍然完整的外部边界

“暂缓数据库或中间件深化”推迟的是所选内部机制，不自动撤销既有功能合同，也不表示未来所有外部能力已经由几个端口名保证。外部接入分成**合同可描述、方法可执行、环境可用、当前有权**四个判断。它们由已有Definition/MethodSpec/Binding与宿主状态表达，不新增一个总开关。

### 什么必须现在决定，什么可以留给实现

当前确实选中的边界，设计必须给出：输入/输出类型及单位和编码、合法域、缺省、正常行为、错误优先级与部分结果、调用和回调次序、初始化、取消与资源寿命、同步/异步、重试身份、版本范围、权限及数据披露、结果如何核对。不是每个纯函数都写全部字段；只有真实相交项适用。接口未知的细节不能放一个`Any`或“自行实现”占位后宣称闭合。

内部算法、索引、表、线程与服务拓扑只要不改变以上可观察承诺，就可以由后来实现决定。提出尚无真实消费者的外部能力时，只保留需求和待决接口，不能假设存在一个普遍接口能兼容一切未来机制。当前已知边界可以完整到足以实现；开放世界的未来能力不以“架构完美”预先认证。

| 当前事实 | 请求如何推进 | 对外怎样报告 |
|---|---|---|
| 合同和语义规则完整，尚无实现方法 | 类型、组合与设计继续；需要实际降低或执行的方法返回具体缺项 | 合同可理解，指定目标尚不可生成/执行 |
| 已有实现方法，目标环境缺少工具或资源 | 纯前序结果可以保存；实际动作按原许可补齐环境，或选择合法替代 | 环境未就绪，而不是作者语义错误 |
| 方法和环境都有，但当前没有作用许可 | 预览、计划和允许的只读步骤可继续，真实作用不发生 | 当前未准入，不标为不支持整个产品 |
| 连语义都不明确或版本未知 | 允许原文/字节保全，返回准确未解释区域 | 不能由类型形状签发可组合和保持结论 |
| 所选任务并不需要该边界 | 不实例化、不加载相应执行方法、不生成设施 | 不适用，不制造失败或假通过 |

EngineImage中的可阅读定义集合，与本次可调用的方法集合不必相同。没有method的Definition可以是合法设计要求；请求实际调用该method时才形成Needs/Stopped。不可将一个always-success空handler或固定零返回当作延期实现。契约目录不是已安装软件清单。

### 一个外部接口怎样保持不变

例如，格式转换器需要`Decoder<Bytes, Table>`：它承诺严格UTF-8、完整记录、错误位置和输入不变；取消后输出不得被发布，实际资源何时释放另按运行器规则。最初本地实现可以使用某成熟库，后来换一个库，甚至通过不同进程调用。只有值域、错误、顺序、取消、披露和资源等任务承诺都满足，客户端才可以不改作者源。

改为远程服务可能增加网络披露、失败、时延和超时后未知结果。这不是单纯“内部更换”，不能因函数签名没变就自动采用。可以设计满足同一合同的桥接，也可以明确要求重新选择目标条件；不把不兼容藏进Adapter。

延期处理不改变在途义务：旧动作固定原合同与输入；新实现只影响明确采用的新动作。旧输出可能需重新生成，旧数据可能需迁移，当前权限仍需重新取得。调用方源码保持、重编译、ABI兼容、数据兼容、部署迁移和恢复责任分别判断。

### 现在采用的正向接入步骤

1. 从实际消费者取得所需合同和允许观察，补齐本范围内不能推断的语义；同名接口不自动等价。
2. 将该合同固定为可读取的定义，给出至少一个成功、失败、取消或条件不适用路径，并保留待决部分。
3. 只有实际方法存在且满足需求时形成Binding。按实际使用点计算输入、资源与能力闭包，不把全部未来提供者加载。
4. 对可复用上游方法继承相应依据；SEC新增的映射、组合和环境边界形成残余检查。不是重做整个上游测试集。
5. 新旧方法比较相交公共承诺，建立采用与回退；变化不可保持时返回冲突或版本迁移候选，不悄悄降低要求。
6. 运行前重新检查当前环境与权限。实现故障、缺方法、无权和业务失败分别返回，恢复依据原操作而非最新默认。

本节完成“延期不等于没有外部设计”和“声明与可执行供给不同”的共同合同；它不替每个尚未定义的数据库、对象、流或设备接口填完专有语义。那些具体缺口按原问题记录继续存在，也不阻挡不使用它们的小工具。
