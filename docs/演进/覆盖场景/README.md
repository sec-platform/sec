# 全域工程场景

领域名称用于发现问题，机制合同用于解释和组合，实际供给与证据兑现支持范围。目录是开放、有限的设计材料：同一项目可以相交多个领域；未列的情景不被视为不存在；列出条目不表示已经实现、发布或验证。

目录中的关联是发现和检查方向，不是必需依赖。一个场景的有效内容由本身的任务/独特需求与所在领域的对象、不变量、失败恢复和验证共同组成；跨领域深场景另保留其具体输入、输出与规范入口。不得只读取叶子名称就声称完整理解，也不能把所有关联机制并集当作最小部署。

新需求先定位可观察区别，再检查普通定义、已有实现、接口适配和领域组合；只有这些无法保持区别时才演进领域或核心语义。[语义扩展](../../作者/组合/语义扩展与领域接合.md)拥有准入，[覆盖成熟度](../../运行/保证/覆盖成熟度与验收范围.md)拥有支持声明。
