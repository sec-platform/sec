# 设计剩余全量清单

> **性质**：这是当前状态的导航/分类投影，不是第二份设计 authority。每个 U 项的采用、算法、失败、消费者和关闭条件仍由原状态条目及其责任正文拥有。本页回答“还有哪些是设计没定，哪些其实只是没实现/没验证”，防止以后把二者混在一起。

## 当前结论

按整合候选对 U001—U066 全量回读，并加入本轮 Rust 目标、跨语言能力、有限抽象/策略和授权格式设计后，**当前已经明确的产品范围内，没有发现仍缺 owner、正常方案或失败边界的强制设计项**。这不是声称未来未知都已穷尽；新的真实需求、反例、平台事实或相交约束可以按重开条件产生新设计工作。

当前剩余被分成三类：

- **B 条件性设计前沿：13 项。** 当前范围已有有限方案，但更强/更广语义只有在真实触发条件出现时才继续设计；不预建完整世界模型。
- **C 外部事实/测量/具体供给前沿：13 项。** 设计方法已经确定，下一步需要真实工具、Provider、成本、格式、平台或发行事实，不能靠继续写文档假装闭合。
- **D 实现/符合性/证据前沿：40 项。** 当前设计已定，剩余工作是实现、适配、运行、验证、迁移或收益测量；它们不是“设计还没想”。

Rust 现在是已选目标而不是未指定第二语言。[Rust目标画像与降低](../编译/目标/Rust目标画像与降低.md)闭合其工具链、crate、类型/所有权、Cargo、诊断、FFI、并发/no_std、产物、回源和验收设计；后端尚未实现不再写成语言目标未设计。

## 使用规则

1. 新发现先定位到原 U/owner；已有合同能处理就作为实现/证据问题，不重复增加同义原则。
2. 只有出现**新的独立可观察区别、接口义务、失败/恢复路径或现有方案矛盾**，才把条目从 C/D 或条件 B 重开为真正设计债。
3. “未运行、未部署、未验证、未测性能、Provider 未接入、目标 SDK 未取得”均不能单独证明缺设计。
4. B 类激活时要把触发输入、原有限方案为什么不足、需要保持的新观察和目标消费者写回 owner；不能只把标题改成“支持更多”。
5. 本页每次大规模设计整合后重新从 U001—U066 生成/核对；U 的原文仍是唯一状态 authority。
