## 局部控制、托管值与即时运行的共同装配

semantics消费[局部控制合同](../../领域/对象与控制/控制流与存储寿命.md)，建立绑定种类、控制出口和region依赖；compiler在既有BodyAnalysis保存局部槽/捕获/退出摘要，降低到所选目标。普通托管值和闭包使用目标运行时，不建立SEC全局对象登记。Own资源的运行责任属于目标Runtime/Provider，SEC自身的文件句柄与worker则由execution管理，不能因为类型名字相同合并两个资源空间。

compute-eval由application固定候选和参数，调用同一Compiler.evaluate取得最小可调用产物，再调用Execution.run。固定制品已有时直接复用；需真实工具构建时将它作为有权ToolResultNeed处理。没有另一个Evaluator服务、独立解释型类型系统或第二份权限根。代码缓存与运行实例分开，复用代码不共享用户未要求的可变状态。

共同接口返回值、待补内容和停止状态不改义。局部控制分析新增的信息只在对应模块阶段产生；没有使用该组合的基础模块不被新关键字重新解释。控制/借用算法未实现的目标准确报告方法缺项，不能以通用架构接口存在而标成可运行。


## 需求开发请求在既有模块中的调度

application持有原Task及本次允许动作，开发AI是创作参与者，不是拥有任意工具权限的语言求值器。它读取相交要求并选择propose输入，workspace形成候选；semantics和compiler只消费固定内容及精确输入。外部工具结果经execution取得后，形成新的已捕获输入继续原阶段，不向纯函数传入任意活动文件系统回调。

运行上只需一个请求协调器和已有阶段服务，不新增IntentEngine、BlockManager或用户方案审批服务。候选、产物、检查、实际头和运行实例分别拥有；Task只关联它们。客户端显示“一个任务完成”，内部仍以所请求的输出根与实际作用条件判断，不能取所有结果中的最大stage。

普通调用的一个作者值可由库合同覆盖；规则太弱时扩大读取或分析，不能直接把用户送入全部内部图。所有数据由语言前端、精确锁、领域方法、目标和宿主按现行责任供给。完整的操作判定、状态与失败出口只在[需求主协议](../../开发/需求到交付主链.md#intent-to-product)维护。

## 领域共享编译责任，运行状态由目标拥有

所有已选领域复用同一ModuleRevision、名称与类型/效果框架、方法调用联合、产物贡献与当前作用入口。下表只指出各域实际保存的区别；完整字段和算法由链接规范拥有，不复制为第二套接口。

| 领域 | 领域检查与生成责任 | 目标运行状态与实际边界 |
|---|---|---|
| [对象](../../领域/对象与控制/对象构造与分派.md) | 检查成员、父链、确定初始化、槽合同及before；生成布局、构造与调用 | 目标实例和所选执行所有者；前态捕获是方法局部，不建ObjectHeadStore |
| [状态](../../领域/状态关系与流/层级状态与事件.md) | 检查有限图、回调与历史；生成表/step及必要driver | 目标实例持有ChartSnapshot与活动责任；逻辑结束不证明资源停止，旧实例不被image更新热替换 |
| [关系](../../领域/状态关系与流/关系查询与维护.md) | 检查重数、缺失、顺序与回调；生成循环或合格查询 | 需要增量才有ViewState/索引/源边界；读取活动来源经实际宿主，不能混作编译器缓存 |
| [流](../../领域/状态关系与流/背压与事件时间.md) | 检查时间、背压和顺序；生成本地拉取/并发策略 | 游标、队列、在途工作和窗口；等待结束不归还仍被使用的内容 |
| [微分](../../领域/数值/自动微分与线性化.md) | 检查导数资格与规则；生成前向/反向 | tape和余切由真实调用/复用合同持有，固定输入和旧值不能被对象后续修改替换 |

上述方法只写自己的Done结果、真实读集和Contribution；共同组合器处理输出名称、初始化和成员。缺方法限制相交根。内容相同不合并两个有状态提供者；共享状态也不产生第二份作者源。无活动、增量、对象或AD使用时，对应运行存储不生成。需要耐久或外部作用，接原提交/恢复，不能建立域内竞争写头。成熟提供者依精确语义/API进入adapters，而不是其名字覆盖公共规则。


## 完整计算产品的运行与观察装配

十个逻辑模块不变。目标程序的算法/模型/入口、编译器自己的阶段、SEC执行域三个对象分开：计算应用中的`SessionState`或图索引由目标程序拥有，不放进开发者候选库；SEC对一次运行的内容和结果关联由application/execution承担。

| 已有拥有者 | 新的具体接合 | 输入输出与失败 |
|---|---|---|
| workspace | 保存源、库、配置、输入描述和资产的新候选；提供局部视图 | 原内容不被运行修改；大输入交内容引用，不复制到每个作者节点 |
| semantics | 分析计算域、控制区域、动态形状、契约与公开接口 | 未闭合能力按根返回，不能为了计划静态化执行所有未来数据 |
| compiler | 生成函数库/入口、数据布局和必要来源映射；输出可构建制品 | 源码已生成不等于已构建；观察插桩形成新的派生产物而非原地改字节 |
| application | 解析已协商compute-build/run/eval请求，关联候选、制品、入口与输入 | 设计/预览没有实际运行准入；未知入口不猜main或shell命令 |
| execution | 准备固定工具环境、资源、隔离输出，执行并结算 | 运行结束、结果取得、数据观察和任务满足分开；取消以实际停止为界 |
| assurance | 对原要求与具体产物/运行结果评价 | 运行exit=0、得到图像或一次profile不自动通过全部要求 |
| adapters | 提供当前目标的BuildRunner、ComputeRunner和有限Observer | 复用成熟工具；每项能力需协商，不能返回不可读变量的旧值 |

`BuildRunner`消费固定源码产物、工具绑定和执行条件，返回新产物成员或准确工具错误。`ComputeRunner`消费合格可运行制品、入口、类型化输入和允许能力，返回正常值/数据、计算错误、取消、资源终止或未结算；它不写作者工作区。`Observer`采用已有方法合同声明无需改制品或需要派生观察制品，取得限定范围数据；单独失败不改源和期望。

RunRecord属于既有操作结果的计算投影，保存artifact、输入/选项、实际Runner与环境、状态、outputRefs和必要观察。它不是所有程序都必须持久化的运行账本。可重放的有限纯运行默认会话保存；跨崩溃跟踪或外部作用需要时再选择合格保存，不因本协议自动创建数据库。快照、参考计数与资源保留沿原机制；取消一个读者不销毁另一个仍在读取的大对象。

默认本地装配是内容读取、编译服务和当前目标工具/Runner；一次可运行模块无需HTTP、RPC、用户表或消息队列。实际桌面/浏览器目标的UI是开发者产物，不迫使SEC先造人类IDE。单机CPU为正确基线；GPU或远程选项由真实需求和目标资格启用，不是完整架构的定义前置。

## 全体系信息的实际模块接合

[信息协议的十职责表](../../信息/接入检索与派生.md#7-原十职责里的实际交接)是本章既有接口的领域细化，不增加顶层模块。contracts只传有解释的引用/选择/覆盖；workspace与adapters负责捕获和解析；application组织查询与上下文；semantics识别关系；compiler只消费真实构建依赖；assurance绑定具体Claim；execution负责实际发布/导出/删除；entry复用六工具；bootstrap按真实需求装配。

建议实现位置在现有职责内部：workspace/information-reference处理resolve/capture，application/information-read处理有权检索与上下文，adapters/information-provider处理原系统映射；这些是文件职责建议，不是已经存在的仓库文件或每个角色都需单独进程。文档目录可以仅用文件和解析索引，嵌入实例不强制创建数据库；持久恢复与多Provider能力沿已有HostPorts协商。

消费层只发布自己获得的能力。未知关系可以保全，但不得默认为无需检查；选择向量可以构成，但兼容和读取可用性仍逐项核。共享检索任务结束或单个客户端撤销不擅自释放其他消费者的根，仍沿原RuntimeHandle和作用域拥有者清理。

## 完成边界的物理接合与调用责任

下表是本设计中的拟定实现位置与最小函数责任，不声称当前仓库已有这些文件；十逻辑职责不变。选择另一文件划分仍须保持下列状态拥有者与真实调用边界。内部可用类型化结果，不要求每项写独立JSON账本。

| 原职责内的位置/函数 | 实际输入→结果与拥有范围 | 调用者和失败处理 |
|---|---|---|
| `semantics/task-scope.ts`的`checkTaskScope`；`compiler/async-lowering.ts`的`lowerTaskScope` | 方法、捕获、别名/借用、共享消费与退出合同→合格计划或带源位置的缺项 | 既有语义/降低阶段；不运行任务。真实不可取消能力不得在lower阶段伪造 |
| `execution/task-scope.ts`的`registerAndStart`、`claimCompleted`、`drainScope`、`transferScope` | 同一运行域、捕获和预算→登记/一次结果/尚未结算；协调段只改状态，不调用用户代码 | 已生成的目标运行方法或合格宿主runtime；调用启动未知保留登记，Own移交失败不释放；目标端可复用库不必须引用SEC服务进程 |
| `compiler/stream-lowering.ts`的`planOrderedDrain`；目标所选流驱动的`drainSignals` | 时间/失败/信用画像与有限队列→连续值和控制前缀/停止 | 类型与方法核定后生成或复用真实驱动；回调重入排队，未完源保留后续可能，不伪报End |
| `compiler/ad-lowering.ts`的`lowerCheckedDerivative` | 活动依赖、原计算次序、导数规则→双通道或先原值后反向计划 | differentiate及目标合法化；能力不符拒绝相交画像，不能吞宿主取消和不可恢复异常 |
| `execution/reconcile.ts`的`classifyRetryBasis`、`prepareNextAttempt` | 原意图/全部可能在途尝试、真实观察、目标能力与当前许可→四种RetryBasis或需查回 | 原operation状态拥有者；先登记下一尝试再交adapter，读回只是输入，不独自授权重发 |
| `adapters/effect-provider.ts`的`observeAttempt`、`closeAttempt`（能力分支） | 提供者命名域及真实请求身份→实际结果/是否可关闭及保证范围 | 不支持强关闭就返回缺项；发送取消只报告cancel-requested，不编造ClosedNoEffect |
| `adapters/information-provider.ts`的`readPage`；`application/information-read.ts`的`acceptPage`、`mergeNext` | 原ReadBinding及前驱→ProviderPage；所有源前沿与预取保护→本次可披露页、续页或Stopped | query原内部读取链；只变更本查询续页，预算/撤权在输出前重核，失效不重定向到新快照 |

共享服务可以复用已核的纯解析与有权读取，但任务拥有集合、订阅输出槽、操作尝试和页续接仍按各自身份隔离。没有一个全局completed布尔决定所有资源可销毁。提供者调用在锁外运行，接受结果回到相应拥有者的短协调段；等待I/O不占CPU执行槽，持有的缓冲/快照/恢复保护继续计费。原生侧没有这些能力时，不创建空成功桩补齐字段。

**实施先后。** 可先以单进程、一个本地Provider、串行流及有限标量AD实现共同值与结果分支；然后增加多客户端、并行回调和跨Provider归并，每次都保留相同可观察合同。只有真实外部效果需要既有持久操作记录；普通纯计算不为恢复语义启动数据库。对应源、消费者、情景与验收见[连续开发范本](../../../examples/连续开发/全工程连续开发.md#completion-development-change)。

## 完整开发面的实际接合点与较小实现

这些是原十职责内的拟定文件/函数，不声明当前仓库已经具有它们。文档中的记录是运行时派生值；短任务不要求先建数据库、注册中心或LSP服务器。类型/schema最终由contracts拥有，原生IDE/包管理器/测试器/VCS协议留在adapters，不能扩散为核心依赖。

| 拟定文件与函数 | 输入和产出 | 拥有者、失败与副作用边界 |
|---|---|---|
| entry/developer-client.ts — prepareDevelopmentInput | 自然目的/实际源或选择、现有调用上下文 → 原六工具合法请求或准确宿主任务 | entry只适配；不得新猜语言、目标、权限或context；复合动作仍保留原子阶段 |
| application/developer-view.ts — describeDevelopment | 原PreparedJob/任务结果、请求用途、可披露能力 → 按需DeveloperView/NextAction | application不持久化第二套源；当前资格需行动时再核，不从建议字符串运行命令 |
| workspace/open-project.ts — captureDevelopmentWorkspace | 真实根/缓冲/资源与读取能力 → 原projectView/context和覆盖 | workspace拥有捕获；新/旧/多根/远端同走真实前像；打开不执行工具脚本 |
| semantics/author-services.ts — describeLocation/resolveAuthorAction | 准确源位置/绑定、方法和用户局部参数 → 符号/补全或原语义变更/Needs | semantics解释保持范围；非法源局部服务有限，重构结果不直接写磁盘 |
| adapters/language-service/ — collectEdits | 固定原生模型/版本、受限动作 → 源编辑及独立命令/效果描述 | adapter处理坐标、附加编辑和真实能力；命令不是静默后续，失败保留源 |
| application/diagnostics.ts — publishDiagnosticPartition | producer/subject/coverage/generation与结果 → 该分区新视图 | 原返回槽和更新策略；局部空/工具失败不清其他或旧完整诊断 |
| assurance/case-selection.ts — prepareCaseSelection | 真实发现、选择、期望/fixture/runner → casesRef或准确Needs/Conflict | assurance拥有被检义务；发现执行由execution，选择本身不运行测试 |
| entry/invocation-input.ts — prepareInvocation | 真实入口、普通值/配置/安全引用 → argumentsRef或字段诊断 | entry/application封存输入，保持类型/单位/作用；不让模型手算hash或调用目标试错 |
| application/development-watch.ts — advanceWatch | 已选策略、真实捕获事件/旧任务 → 相交新任务与接纳槽 | 只派发所选动作；共享任务取消有范围，重复自写不无限循环 |
| application/environment-plan.ts — prepareEnvironment | projectView、依赖意图和已选工具 → 原需求/锁候选或MaterializationPlan | 只准备不执行；环境实际更换进execution，不借check自动安装 |
| adapters/vcs/ — prepareIntegration/recordIntegration/publishIntegration | 固定selection/tree/history/policy → 计划、真实本地/远端结果 | VCS对象与工作树分责；ref条件更新不代替文件事务，失败进原reconcile |
| execution/process-input.ts — acceptInput/drainInput/reconcileInput | 原RunRecord、命令与准确载荷/前提 → 队列接纳、发送范围和状态 | 原operation登记去重和拥有，I/O锁外；未知发送不重发，持久性按承诺 |
| adapters/process/ — write/closeInput/signal/resize | 准确进程出生身份/端口、已准入命令 → 实际字节数/控制结果 | 报实际能力；不接受任意pid/shell/协议透传，不从信号接收推断终止 |
| workspace/development-handoff.ts — captureHandoff | 原任务/源/候选/独立差异/未决操作 → 最小可恢复交接内容 | 只保留确需内容并按权限引用；丢草稿不能删在途恢复证据 |

先可实现无新UI的SDK/CLI和现有文件/语言工具适配，获得创建→原文编辑→检查→生成→保存；再实现选定案例与构建/运行；交互进程和有限调试按实际方法启用；有真实需求再接环境/VCS/发行自动化。顺序是可用性和依赖关系，不把后一项设计删除或称为不存在。普通单进程/串行方法可以满足相同合同，服务端和远端并发不是每个客户端前置。

语义服务、只读查询和候选批次均不默认持有真实目录写权。宿主动作的准确计划经execution及受信ProviderSession才可作用；既有原生工具在SEC之外运行时，只把可确认观察纳入系统，不给外部活动捏造operationRef。统一查询/控制覆盖到哪里由真实注册和协议决定。

开发面适配的兼容要求包括：同一输入路径产生同义候选；六工具解码器拒绝未协商字段；命令行/SDK/可选编辑器共享类型与状态说明；同一修改没有多份“快捷实现”。能从原生工具取得正确结果就复用，不能满足的强保证明确标缺项，不重建整个编辑器来掩盖一个能力差额。

## 开发面的具体文件、函数和交接责任

### 装配、调用与并发的最小形态

首次本地进程只创建实际请求所需组件：短propose不创建DebugDriver，普通preview不启动测试，静态辅助不运行用户插件。可用现有TS语言服务提供native分析/重构，但它的编译上下文、文档版本和编辑语义经具体Adapter固定；服务端返回代码建议不自动可信。中立作者使用同一基础前端/semantics，不让LSP成为核心依赖。

辅助典型调用是entry→application固定输入→compiler既有查询取得相交分析→semantics产生定位/计划→workspace保留实际计划→entry呈现；accept时再次entry→application→workspace物化→semantics核相交→返回候选。语义分析依赖编译查询时由application先取只读输入，不使semantics反向import compiler。改动不需要辅助时直接跳过这整段。

测试典型调用是application→assurance形成已知选择/真实缺项→原preview/operation准备并执行动态发现（仅需要时）→assurance核记录生成casesRef→原check/执行器→绑定结果/来源→客户端。不能拿未发送的未来引用填casesRef；结果很小时可以同一次客户端用例自动传递真实返回引用，不要求AI复制长标识。

每个任务的缓冲、计划、诊断、生成与运行都有原身份。CPU任务取消的等待者与真正worker寿命分开；计划回收按有界原保留机制；当前写入在真实执行边界。较小合法实现可以单进程、单事件循环、全量分析/物化、无编辑器扩展。只有实际并发/远程需求才增加隔离或持久设施，不把设计表行数当必装进程数。

## 作者边界到成品的具体接合

以下是原十职责中的拟定实现位置，不是本包已实现文件，也不增加公共工具。字段与语义唯一拥有者在[结构源码](../../作者/结构化源码.md)和[成品边界](../../作者/成品形态与公共边界.md)。

| 原责任/拟定文件与函数 | 输入与结果 | 必须拒绝或保留的边界 |
|---|---|---|
| semantics/author-structure/decode.ts | 固定JSON→合法composite、default、exposes及位置 | 重复键/未知结构、subject默认、非法公开引用不能忽略 |
| semantics/requirements/instantiate.ts::completeDesignArguments | 准确定义/显式实参/导入→确定值、来源与缺项 | 不运行代码、不捕获调用方环境、不以默认替代求解见证 |
| semantics/requirements/instantiate.ts::resolveExposedSubjects | 同一作用域及角色表→公开名到准确Subject的映射 | 不读取子use私有主体，不合并同型实例，不自动转导 |
| compiler/realization/resolve.ts | 原义务/边界/目的/供给→共同合格Binding或缺额 | 类型同形不足；保持公开进口与独立应用环境的区别 |
| compiler/target/compose.ts::composeTarget | 实际方法贡献/目标/公共映射→按根成员及边界 | 共用配置冲突、私有类型泄漏、假完整运行库 |
| assurance现有计划与评价 | 精确行为、边界、参数及已取得证据→相交结论 | 静态范本检查不代签实现；一个形式不替全部宿主证明 |

application准备所需上下文，entry只投影准确结果；任何安装、I/O、宿主启动仍由execution/adapters在真实权限与资源边界执行。上下游共享的是原PreparedJob、RequirementTerm、UseBinding、LoweringResult与Artifact，不为每一行增加一种持久Plan或管理器。
