# 实现语言与机制演进

本篇拥有SEC自身实现的语言比较、数据表示边界和改模成本判据，细化[实现供给与替换](实现供给与替换.md)，不新增运行owner、决策内核或目标语言。TypeScript与Rust的目标计划、SEC自身实现语言、参考模型语言及外部工具语言分别选择；采用一种目标不授权迁写编译器。

## 语义设计、参考方法与最终机制分开验证

必须尽早明确的内容是对象身份、含义、允许观察、责任、阶段前后置、依赖、失败、恢复、权限和保证。具体算法、表示、索引、分配与调度也由各owner控制，但不因“需要控制”而全部成为全局公开参数。现有[类型化控制](../作者/组合/稀疏控制与目标限定.md#control-actuation-contract)记录实际选择范围；选项的定义、选择、作用与观察均须有消费者。

规范、代数推导、可执行参考算法、状态模型、随机生成、真实实现和运行测量各提供不同证据。参考方法不要求先做一套完整TS编译器，也不要求与生产实现异语言；有限穷举、全量重算和直接解释可以在最容易审查的表示中存在。其职责是给出可核结果和反例，不承担全部生产缓存、UI、发行、调度与兼容义务。

最终机制改变时，语义正确并不自动证明性能、取消、生命周期或并发正确。对象图改成紧凑表、全量改成增量、进程内改成RPC、GC改成显式寿命，均需检查各自新增约束。先在与生产相符的最简单机制中建立纵向路径，可以避免验证一个完全不会用于最终系统的完整中间架构；这不是为了避免迁移而拒绝必要的参考模型。

设计允许普通单线程、显式拥有数据、简单集合与不可变输入先成立；已知规模、宿主或硬保证直接要求另一机制时，从第一份正式实现使用该合格机制，不强制先制造慢版本。反之，不把没有工作负载依据的锁自由、分布式、SIMD、全局泛型化或零拷贝作为“完善架构”的条件。

## 四种身份及其存储边界

[信息引用](../信息/对象关系与配置基线.md)拥有持久对象解释；本节只规定其在内存与互操作中的映射。

| 身份 | 回答的问题 | 不可替代的边界 |
|---|---|---|
| 语义实体身份 | 这是哪个定义、事实或长期对象 | 文件改名、重新排序和压缩不自动换实体；新建同名对象也不自动继承 |
| 修订／内容身份 | 是哪一版含义、字节或固定输入 | 同一实体的后继不能承接旧证据；同字节不同解释仍需上下文 |
| 运行句柄 | 在本次进程、arena或快照中如何取得对象 | 局部索引不是可持久引用；槽位复用、跨arena和旧句柄分别校验 |
| 物理定位 | 字节或对象目前在哪里 | 路径、偏移、地址和服务端locator不证明身份、版本或权限 |

例如`NodeId(u32)`只能在明确拥有者与快照下作为紧凑索引。需要删除和槽位复用时，可用带代的句柄或不复用策略；跨arena查询还需归属检查。代计数回绕必须拒绝复用、扩大表示或完成可证明的整体退役，不能静默恢复旧句柄有效性。内部句柄可在封存时映为持久引用，但须保存准确映射并核跨修订关系。

内存表示、交换编码、磁盘格式和外部ABI是四种合同。内部`struct`增加字段不应强迫所有历史快照按当前内存布局读取。持久格式固定自己的版本、字节序、数值域、引用编码和完整性；读取先有界解码并校验，再构造内部类型。零拷贝只在对齐、范围、寿命、可变性、可信度与格式兼容全部成立时采用；否则显式转换，不让性能优化暗中锁死长期格式。

Rust的默认表示并不承诺声明顺序就是字段布局，布局相同也不足以承诺函数ABI相容，见[语言机制依据](../依据/来源/语言编译与目标工具.md#implementation-language-sources)。换摘要算法也不是换一个hash函数：内容用途、编码、算法标识、外部协议、持久引用和双读迁移分别处理；Git OID及外部指定摘要遵守其真实格式，不用平台偏好统一替换。

## 可替换边界必须保留完整合同

值关系可以通过ID访问，使长期语义不依赖某种对象指针拓扑；局部实现仍可正常借用、采用不可变视图和编译器检查。不禁止所有lifetime、trait或共享引用，而是禁止无必要地把跨所有owner的存储寿命、锁策略和具体容器暴露为公共合同。

局部闭合状态适合明确的代数类型与穷尽分支；开放领域扩展通过现有类型化定义、方法接口和固定解释映像接合。不能用一个枚举列出所有未来控制项，也不能用`Map<String, unknown>`放弃领域校验。静态组合、泛型、enum分派、虚调用与协议边界按实际调用粒度选择；不要求所有机制运行时可插拔，避免将配置组合、代码体积和构建成本无条件扩大。

以下替换演练分别检验不同责任，不能以其中一个通过证明全部可替换：

| 变化 | 理想的相交修改 | 发现合同不足时的正确动作 |
|---|---|---|
| Map到紧凑表／arena | 存储owner、句柄映射及相交遍历 | 若迭代顺序或引用寿命可观察，显式保持或迁移该合同 |
| 全量到增量查询 | 缓存、依赖观测与失效owner | 用全量结果与读集反例校准；负候选、删除和同值新依赖不能漏 |
| 串行到并行 | 合法依赖、调度和结果归并 | 顺序相关推导、共享可变状态或资源竞争是语义问题，不能仅排序输出 |
| 内存到分页／远程 | 存储与取得边界 | 若新增I/O失败、取消、部分覆盖或异步，必须升级相交接口 |
| 当前Schema到新解释 | 解码、迁移、解释及消费者 | 未知旧内容不自动获得新效果；旧读者与恢复路径分别处理 |
| 同语言到原生／Wasm／进程 | 选定计算区域及其适配 | 固定数字、Unicode、错误、回调、寿命和构建条件；不强制全工程迁写 |
| 扩展一项领域控制 | 定义、真实消费者、反例及投影 | 没有新的跨域区别时不改所有通用Pass；确有新区别则改相交共同合同 |

分页／远程查询有两条不同合法路线：在纯计算前取得完整且固定的所需快照，或明确暴露可失败、可取消、可能不完整的查询结果及其修订覆盖。不能一边承诺纯同步引用、一边在任意访问时隐式联网。新旧页没有同一切面时，不拼成一个“完整快照”。局部查询依赖全图性质时，影响范围可能就是全图；可演进不保证所有修改永远小。

## 语言候选的机制比较

语言选择的单位是具有真实owner和交付边界的实现区域，不是“整个平台必须同一种语言”。下表给出应验证的机制与条件，不是已经跑过的排名；引用资料只证明语言或工具具有相应特征。当前TS实现及有效成果不因比较自动退役，也不把它作为未来所有正式核心必须重复实现一遍的原型。

| 候选 | 值得利用的机制 | SEC需要实际验证的代价与反转条件 |
|---|---|---|
| Rust | 代数类型、名义句柄、借用／拥有及显式布局，适合紧凑存储和原生区域 | 跨owner借用拓扑、泛型体积、编译增量、插件ABI与维护成本；静态类型不证明算法、授权和迁移正确 |
| Go | GC管理图、直接原生程序、统一工具与并发设施 | 复杂变体／名义区别如何表达，GC与峰值内存、实际并行、FFI和模块分发；不能把语法少等同整条机制更简单 |
| OCaml | 变体、模式匹配、类型推导和直接语义变换 | 与大图、并行、原生依赖、部署和工具环境的接合；不因有GC就预先否定性能，也不因适合语义就忽略运行机制 |
| F#／C#与.NET | 判别联合／类型建模、值与引用表示、运行时及调试分析工具 | 热路径分配、表示和AOT／JIT环境、原生互操作与发行；成熟运行时可以是优势，不用“托管”替代测量 |
| Kotlin／Java／Scala与JVM | 封闭层次／模式建模、成熟运行时及生态；具体特征按所选语言判断 | 冷启动、GC、对象与紧凑数组、堆外使用和部署；同属JVM不意味着三种语言的类型与构建代价相同 |
| TypeScript／JavaScript宿主 | 当前集成、结构化数据、Web／IDE接口和生态复用 | 运行时数值、集合／对象分配、隔离与共享并发；TypedArray和原生库可改变成本，不能按语言标签推出固定倍率 |
| C++ | 成熟编译基础设施、原生生态、表示和分配控制 | 生命周期、未定义行为、ABI、模板／构建与安全审查；合格既有组件可直接复用，不因不选全核C++而重写它 |
| Zig | 显式分配和低层互操作的可观察机制 | 内存责任、工具链／库及平台支持，版本更新造成的工程成本；不将显式分配误当自动内存安全证明 |
| Haskell | 纯变换、代数建模和参考语义组织 | 惰性求值的实际空间／严格性、并行、外部作用与发行；需要堆分析而非仅看纯代码简洁 |

这些候选不意味着九条生产实现线。已有库承担的内部机制优先复用；只有新收益或硬约束确实不能由当前合格实现覆盖时才承担新语言的工具链、包管理、供应链、调试、发布和长期消费者成本。形式验证也不绑定生产语言：有限集合推导、状态模型、SMT／证书或小型解释器按命题选择；不用一种工具包装全部问题。

## 同口径纵向验证与改模实验

比较前固定一份足以暴露真实机制的任务：持久实体与revision输入、带删除的快照、全量／增量依赖查询、有约束的候选选择、带来源的结果与一次局部修改。输入包括字符串／类型重复、稀疏和密集关系、长链／递归分量、负依赖、冷暖缓存、失败与取消；规模和硬预算来自实际目标，不在本文虚构统一节点阈值。

保持同一允许行为、错误、数值、观察、工具环境和输出资格，再比较初始实现、类型检查／编译反馈、正常与尾延迟、峰值存活内存、分配与复制、并发、启动、编码／FFI／IPC、崩溃恢复和发行。运行成本与开发改模成本分别记录；行数少、编译错误少和一次最快样本都不是完整维护收益。

至少演练新增状态、新控制、旧格式读取者、存储替换和一项新增失败。记录实际改变的公共合同、owner、消费者、证明义务、测试与迁移，而不是给package数量设武断阈值。穷尽match暴露遗漏有价值，但通配分支、未检查反序列化、unsafe、动态载荷或错误的旧模型仍可留下漏洞；“编译通过”不能等价为“影响已经全部闭合”。

已确定的硬条件可提前排除不合格路线，不必为了形式公平完成所有语言原型。缺少区分证据时保留合格现状或限定试验，不编造迁移百分比、固定收益倍数或团队速度。结论发生反转时更新对应实现决定与所有真实消费者，仍正确的语义、Oracle、案例和来源继续保留。

## 实现接合与正常退出

选定原生核心时，把共享同寿命数据的连通计算留在同一执行区域；跨边界传准确快照／请求／结果或粗粒度查询，避免每节点往返完整IR。一次性嵌入、可选暖服务、原生扩展与隔离进程均按实际调用成本和信任选择；不预设永久守护进程。接口须有输入版本、支持能力、取消／完成、诊断归属和结果寿命，不把零拷贝指针当永久跨进程引用。

TS产品面可以继续存在；实现语言的选择不改变目标代码的运行性能承诺，也不要求重写目标语言前端、完整类型检查器或成熟工具。复用某编译器的CLI不等于其嵌入API兼容；版本、Host读取、解析／类型／发射能力分别接入。动态特性必须区分规范存在、实现存在、API可用、默认启用、指定平台测试及安全维护，不能只写supports=true。

整个演进遵循[七类变化](../作者/组合/语义扩展与领域接合.md#mechanism-evolution-classes)和原S0—S8采用链：先固定语义与机制差额，再取得有范围的证据，形成后继绑定／迁移，处理旧调用与资源，最后退役旧消费者。纯参考模型可以长期保留为Oracle；临时重复生产内核、未受支持的插件版本和只能靠聊天解释的运行入口不因此获得永久保留资格。
