# Gift 工程总纲：声明式意图语言、全仓六层单一真源与内核统一演进

> **阅读范围**：全仓 **295 份规范文档（9.14 MB）** 的唯一高层总控入口与导航收口；本篇不复制各子系统的字段表与算法细节，所有具体规则仍由下表标注的唯一权威正文承担；不以总纲完备代签生产实现或运行验证。

本总纲用于解决“工程文档浩如烟海、上下两层语义与内核脱节、根目录投影与最新研究分支漂移”三大问题，将全仓收敛为一条唯一主线：**Gift 声明式意图语言（结构化语义真源 + 人类极简声明式同源投影）→ 意图消解与供给绑定 → 纯确定性 Rust 内核与多目标降低 → 受控执行与可验证证据**。

<a id="gift-intent-language-essence"></a>
## 1. Gift 源码到底是什么：彻底划清“意图语言”与“传统源代码”

Gift **不是**另一门类 Rust / TypeScript / SQL 的传统命令式或函数式编程语言，**也不是**让人手写 693 行 JSON 的配置格式，更**不是**每次重猜原话的无锚定自然语言 Prompt：

| 维度 | 传统编程语言源码（Rust / TS / SQL） | Gift 第一层作者源（真实目标形态） | 规范权威依据 |
| :--- | :--- | :--- | :--- |
| **作者写什么** | 循环、控制流、`match`、`scan \|> filter`、比较函数、导入表、类型模板 | **对象、结果、保持、采用与差额、多方规范、偏好与局部钉选**；只写系统推不出来、必须由人拍板的独立信息 | [第一层语言](../作者/第一层语言.md#实际作者记法与省略)（`L309, 371-385, 474`） |
| **持久真源 vs. 人类日常视图** | 单一文本文件既是存储也是界面 | **持久化真源**是带稳定身份与 `SourceRemainder` 的结构化语义源；**人类日常看和改**的是同源极简声明式投影（支持自然语言入口、短视图、表/图与局部控制），修改任何一处反算最小补丁 | [紧凑结构与同源编辑](../作者/紧凑结构与同源编辑.md)；[冻结文本草案](../../alternatives/文本意图/README.md) |
| **复用与修改** | 复制粘贴或手写包装函数，局部魔改易破坏不变量 | `SpecializeUse`（契约内参数特化，保持 `instanceOf`）与 `ForkDefinition`（改未参数化固有条款时显式分叉 + `derivedFrom` + 触发上层违约检查）严格二分 | [第一层语言](../作者/第一层语言.md)（`L393, 399`） |
| **算法与实现去哪儿了** | 应用作者必须自己写完底层算法 | 90% 产品作者只声明意图与约束，算法/数据结构/并发/导入/目标代码由系统复用合格库或委派实现作者完成；缺实现诚实报 `Needs`，绝不退回逼产品作者写代码；只有主动创作独特算法或接管原生代码时才下沉到 Rust/TS 实现层 | [第一层语言](../作者/第一层语言.md)（`L311, 476-478`） |

```text
人类日常输入（自然语言 / 极简声明式短视图：对象·结果·保持·采用差额·规范·局部控制 / 图表控制面）
                        ↕  同源无损投影（同一结构化语义真源 + SourceRemainder）
[第一层：声明式意图与需求内核]  Definition / Use / Fork / Requirement / 四元 Norm / 稀疏 Control / 32 族承接
                        ↓  意图消解、极性桥接与实现资格绑定（复用合格库 / 委派创作 / 诚实返回 Needs）
[第二层：纯确定性计算与目标降低]  crates/gift-author-kernel/（零 I/O）→ 统一 GLIR → TypeScript / Rust / 原生库
                        ↓  受控宿主执行、持久化提交、物理回读与证据裁决
[第三层：运行与可验证交付]       src/（10 职责 TS 宿主）→ 目标产物 + SourceMap + 真实工具链/运行回执
```

## 3. 全仓规范深度审计与原位闭合的 8 项核心形式张力（`T1–T8`）

## 4. 打通上下断层：让 `crates/gift-author-kernel/` 从“函数编译器”进化为“意图编译器”

逐文件审查 `crates/gift-author-kernel/src/`（23 模块、11,006 LOC、205 单测）后，确认当前最大工程断层在于**上层规范是声明式意图语言，下层内核却只实现了 `core:function` 函数编译子集**：

- `header_seeds.rs:155` 将所有 `intent:goal`、`req:composite`、`domain:meaning`、`state:machine` 全部落入 `HeaderKind::Uninterpreted`；
- 流水线 A（`model.rs:357` 强制 `termination == "total"`）与流水线 B（`callable_analysis.rs:250` 拒绝 `total`、`binding.rs:241` 拒全量 `std:*`、`reader.rs:44` 硬编码阻塞 `comprehension`、`rust_target.rs:531` 回读原始 JSON 树）双轨割裂。

唯一主线演进按四阶段直接打通此断层（全部保持纯内核零外部 I/O 纪律）：

1. **阶段 0（内核解阻与索引统一）**：在 `source.rs` 引入密集 `NodeId(u32)` + `SpanTable` 替代跨层 JSON Pointer 字符串键；新增 `prelude.rs` 解除 `std:*` 与 `comprehension` 硬阻塞；统一 `termination == "total"` 冻结规则。
2. **阶段 1（声明式意图一等入核）**：新增 `requirement_ir.rs`（承接 `Goal / Constraint / Preference / 四元 Norm / InheritedContractDelta`，落实 `T1–T7`）与 `control_binding.rs`（承接 `Pin / Require / Forbid / Prefer` 与 `S05` 缺测禁填零消解），替代 `header_seeds.rs:155` 的 `Uninterpreted` 兜底。
3. **阶段 2（同源投影与 CST 无损回写）**：新增 `compact_codec.rs` + `cosource_edit.rs`，以 `SourceRemainder` 精确保全短写形态、Unicode 分空间引用与未知 `wireVariant` 帧，支撑声明式短视图与结构化真源之间的最小字节补丁与往返自检。
4. **阶段 3（统一 GLIR、偏态射专业桥与双目标闭合）**：`body_analysis.rs` 直接产出 `TypedHir`；新增 `lowering_ir.rs`（`GlirType / GlirExpr / TargetBackend`）与 `profile_bridge.rs`（极性代数 + 10 条反例见证 `W01–W10`），让 `typescript.rs` 与 `rust_target.rs` 共用同一 GLIR 并彻底消除对原始 JSON 的二次嗅探。
