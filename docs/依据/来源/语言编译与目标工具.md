### SciPy：数组协议、后端委派与转换边界

**来源：** [SciPy Array API support](https://docs.scipy.org/doc/scipy/dev/api-dev/array_api.html)。

**实际读取：** 2026-09-09；所读页面标识SciPy 1.18.0；范围为实现说明、共享命名空间、委派与转换条件，没有安装或运行SciPy。

**支持的命题：** 共享数组协议和命名空间可以复用一批操作的调用形状；某些编译实现可以委派给原生后端。文档要求对真实功能、设备和JIT能力分别记录支持，并减少重复格式转换。

**采用条件与边界：** 所读页面明确只覆盖部分公共API且支持仍有实验范围；一个方法能处理某种数组不能扩大成整个库或所有设备支持。编译代码、设备传输和可变语义可能限制共享。用于论证“一组共同接口可复用适配”，不要求SEC使用SciPy、不认证任意库自动中立，也不把标记表当实现证明。

**使用与维护位置：** [库供给与封装](../../作者/组合/模块封装与复用库.md#semantic-supply-boundary)、[提供者接合][owner-host]、[目标交付](../../编译/目标/成员布局与完整产物.md#复用实现的源码与依赖交付边界)。实际采用某个方法或版本时核该方法/数据类型/设备/执行模式；稳定的接口复用原则不因无关任务重复搜索。

### Python itertools：有限组合机制与开放配方

**来源：** [Python itertools](https://docs.python.org/3/library/itertools.html)。

**实际读取：** 2026-09-09；页面标识Python 3.14.7；读取模块说明和组合用途，没有运行库或其配方。

**支持的命题：** 一组有限迭代工具可以组合出更多专用处理，不要求每种排列组合都有新的平台内置函数。

**采用条件与边界：** 这些工具具有Python自身的迭代与惰性行为；SEC的严格列表、错误顺序、资源与可重放性不能按同名自动采用。组合能力可以在成熟语言中实现，因此不能把同等高层调用的全部简洁性归为SEC独占价值。

**使用与维护位置：** [封装与供给](../../作者/组合/模块封装与复用库.md#semantic-supply-boundary)、[新增价值验收](../../产品/术语与质量属性.md#底层相似性与新增价值的验收)。采用具体算子或改变惰性/失败要求时定向复核；不新增第二份需求目录。

### MLIR PassManagement

**来源：** [MLIR PassManagement](https://mlir.llvm.org/docs/PassManagement/)。

**实际复核：** 2026-09-09，Operation Pass限制、Analysis Management、Preserving Analyses和Pass Failure；未运行MLIR。早期条目的逐项日期仍无历史记录，不追补。

**支持的命题：** 变换只能在明确可修改范围运行，分析不能修改被分析对象；依赖分析也会影响失效。没有明确保留依据时，旧分析不能自动沿用。Pass失败可能留下不合法中间状态，因此失败应停止对应管线而非对外冒称成功。

**采用条件与边界：** 用于SEC私有变换结果、实际读集、封存与失败隔离；不要求SEC采用MLIR或在每个任务执行全局Pass序列，不证明本系统的语义、规划和编辑已经正确。

**使用与维护位置：** [编译内核][owner-comp]、[整批物化](../../作者/组合/结构编辑与身份保持.md#whole-change-materialization)、[目标组合][owner-target]。变换读写范围、保留条件或失败恢复实现改变时复核；普通任务参数变化不重搜整套文档。

### MLIR Interfaces

**来源：** [MLIR Interfaces](https://mlir.llvm.org/docs/Interfaces/)。

**实际读取：** 2026-09-09，接口概念、外部模型及缺少预期实现的处理；未构建或运行MLIR。

**支持的命题：** 通用分析和变换可以通过明确接口读取操作/类型含义；外部模型可在不修改原定义代码的条件下补充接口实现。方言级接口可以承担覆盖一组对象的共同查询，避免将同一种高层分析样板注册到每个操作；仍需明确方法实际覆盖。声明或承诺方法与方法真的提供是两件事，缺失须有明确处理。

**采用条件与边界：** 支持普通SEC主体之外的可选分析与特化方法，不要求每个用户函数自己注册插件；采用接口不会自动证明效果、变换或目标行为正确，也不保证所有运行环境能随意热替换方法。接口声明、方法注册和上下文装配分别检查；接口存在也不认证插件可信、全目标覆盖或全局最优。当前不将全工程迁入MLIR。

**使用与维护位置：** [开发主链](../../开发/需求到交付主链.md#intent-to-product)、[共享语义关系与能力][owner-sem]、[库的共同编译路径](../../作者/组合/模块封装与复用库.md#普通库与编译型定义的共同路径)、[控制消费](../../作者/组合/稀疏控制与目标限定.md#k0至k6控制从提出到实际结果)、[编译内核](../../编译/内核/输入与阶段总览.md)。方法注册、目标规则或共享实例语义变化时核对，稳定接口分责不因用户未点名而遗漏。

### 反编译、行为验证与可重新编译表示

**来源：** [Myreen：Decompilation into logic](https://www.cl.cam.ac.uk/~mom22/decompilation.html)、[Ghidra P-code参考](https://ghidra.re/ghidra_docs/languages/html/pcoderef.html)、[rev.ng设计说明](https://docs.rev.ng/what-is-revng/)、[Decomperson，USENIX Security 2022](https://www.usenix.org/conference/usenixsecurity22/presentation/burk)。

**使用与维护位置：** [恢复目的及R0—R6](../../开发/原生维护/导入观察与原生资产.md#recovery-purpose)、[无来源与回写](../../编译/表示/编辑与受管回源.md#无来源恢复与有来源回写采用不同证明目标)、[验收](../../运行/验收/作者与组合案例.md#reverse-and-edit-acceptance)。真实选择某个二进制/工具族或提升保证时复核相交版本与支持域；只讨论固定的非单射推导时无需重复搜索，不将参考项目写进默认依赖。

**来源与版本：** [WCAG 2.2](https://www.w3.org/TR/WCAG22/)、[WCAG 2.4.3 Focus Order](https://www.w3.org/WAI/WCAG22/Understanding/focus-order)、[WAI-ARIA APG Accessible Names](https://www.w3.org/WAI/ARIA/apg/practices/names-and-descriptions/)、[WAI-ARIA Practices](https://www.w3.org/WAI/ARIA/apg/practices/)、[WCAG C39 prefers-reduced-motion](https://www.w3.org/WAI/WCAG22/Techniques/css/C39)、[Chrome DevTools Protocol Accessibility domain](https://chromedevtools.github.io/devtools-protocol/tot/Accessibility/)；本次核对2026-09-22。

**本轮实际支持：** WCAG把keyboard access、focus order/visibility、reflow/contrast/motion等定义为不同success criteria；APG说明accessible name由浏览器按ARIA/host-language来源计算，并强调需要实际AT测试；ARIA实践要求自定义GUI组件自行提供键盘行为。CDP Accessibility domain暴露AX tree查询/更新，可用于浏览器层运行Observation；`prefers-reduced-motion`技术需要实际在用户偏好启用后检查motion是否被抑制。

**采用与不能推出：** 用于分离Source/DOM/AX/keyboard/visual/AT/user-task Evidence。AX tree正确不证明具体screen reader或用户任务成功；自动WCAG规则无finding也不证明完整conformance；一套browser/OS/AT结果不能无边界外推到另一平台。静态ARIA属性只提供作者输入，不代签browser最终accessible name/role/state。
