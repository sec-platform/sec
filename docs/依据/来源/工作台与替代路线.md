## 测试、构建输入与协作的开发机制

复核日期2026-09-10。下列为本轮直接读取的官方动态文档，不是固定提交、不代表安装或执行结果；保留适用范围而不强迫采用这些产品。

**VS Code Testing API。** 已读[官方指南](https://code.visualstudio.com/api/extension-guides/testing)的发现与延迟解析、run/debug/coverage配置、选择/排除、运行结果、覆盖及避免重复配置段。它支持“发现、运行和覆盖是分别接合的能力，优先复用原框架配置”的设计依据。不证明动态发现没有效果，也不证明SEC casesRef/未保存源已经接入；不要求先开发VS Code扩展。

**Bazel hermeticity。** 已读[官方说明](https://bazel.build/basics/hermeticity)的固定输入/工具依赖及破坏隔离的系统二进制、非确定过程和源树写入因素。用于说明准确候选、环境与真实构建输入应对应；不从目录临时副本就推完全隔离，不把Bazel设为SEC运行前置。

**Git worktree。** 已读[官方手册](https://git-scm.com/docs/git-worktree)的工作树/分支、LIST/DETAILS/CONFIGURATION及引用共享说明。独立工作树有各自某些状态，包括HEAD/index，但并非所有配置/refs及外部工具都隔离。用于并行开发与暂存/合并的输入分层，不自动授权创建/删除用户worktree、reset或远端推送。

这些材料校准开发合同，不为候选正确、测试通过、跨工具原子或作者净收益作保证。本轮CLI退出策略、可选作者辅助、精确未保存测试和诊断接纳是SEC设计选择；真实实现和成本必须另验。
