## 表示、编辑与协议

### Debug Adapter Protocol Overview

**来源：** [Debug Adapter Protocol Overview](https://microsoft.github.io/debug-adapter-protocol/overview)。

**记录日期：** 2026-09-08。

**支持的命题：** 能力协商、launch/attach、调试器特定参数、暂停引用生命周期是分别的合同。

**采用条件与边界：** 复用调试适配思路，仍需SEC来源、权限和启动接合；新的compute-run是本设计选择，不是DAP已有接口。

**使用与维护位置：** [操作语义接口与批处理][owner-api]、[发布运行与资源生命周期][owner-run]。

### LSP 3.18 CodeAction源文档，lazy resolve/data/capability

**来源：** [LSP 3.18 CodeAction源文档](https://github.com/microsoft/language-server-protocol/blob/gh-pages/_specifications/lsp/3.18/language/codeAction.md)，lazy resolve/data/capability。

**记录日期：** 2026-09-08。

**支持的命题：** 有限动作结果与较贵编辑可按需解析，能减少无关传输。

**采用条件与边界：** 读取的是活动3.18文档，不冒充锁定协议已实现；editRef为SEC新增设计，不是LSP原字段。

**使用与维护位置：** [操作语义接口与批处理][owner-api]、[结构作者与语义编辑][owner-edit]。

### LSP 3.17 WorkspaceEdit源文档，版本与有序编辑

**来源：** [LSP 3.17 WorkspaceEdit源文档](https://github.com/microsoft/language-server-protocol/blob/gh-pages/_specifications/lsp/3.17/types/workspaceEdit.md)。

**记录与实际复核：** 原记录2026-09-08；2026-09-09复核WorkspaceEdit及documentChanges条件。读取的是该文件的公开内容，不代表全部LSP或当前客户端实现已验证。

**支持的命题：** 工作区编辑可以覆盖多个资源；支持版本化文档编辑的客户端应采用相应文档变化形式，具体行为与能力协商有关。

**采用条件与边界：** 用于原生适配和成组编辑，不自动证明跨文件的磁盘原子性，也不能检测SEC跨文件共享语义。SEC继续核真实前像、绑定、读集、作用与失败，不把客户端接受补丁当成任务已满足。

**使用与维护位置：** [工具接口][owner-api]、[整批物化与重基](../../作者/组合/结构编辑与身份保持.md#whole-change-materialization)。客户端能力、文档版本或资源操作规则变化时复核。

### LibCST Metadata

**来源：** [LibCST Metadata](https://libcst.readthedocs.io/en/latest/metadata.html)。

**记录日期：** 2026-09-08。

**支持的命题：** 节点身份、位置与词法作用域分别管理；树节点的重复使用可能使位置和元数据对应含糊，内容相同不等于绑定相同。

**采用条件与边界：** 用于CST回写与绑定安全重构；不要求SEC每次深复制整树，其他语言有自己的适配义务，库机制不等于本项目重构已验证。

**使用与维护位置：** [结构作者与语义编辑][owner-edit]、[身份知识与模型采纳][owner-id]。

### RFC 6902 §4

**来源：** [RFC 6902 §4](https://www.rfc-editor.org/rfc/rfc6902.html)。

**记录日期：** 2026-09-08。

**支持的命题：** RFC6902按规定顺序执行补丁，并忽略操作对象中未识别的成员。

**采用条件与边界：** 版本、权限和并发前提必须由真正检查它们的外壳承担；仅加入expectedRevision不能使普通Patch具备该保证，数组位置也不跨修订稳定。更换补丁协议时重核。

**使用与维护位置：** [操作语义接口与批处理][owner-api]、[工程实体与持久表示][owner-source]。

### LibCST Motivation

### RFC 8259、RFC 8785 JCS

**来源：** [RFC 8259](https://www.rfc-editor.org/rfc/rfc8259.html)、[RFC 8785 JCS](https://www.rfc-editor.org/rfc/rfc8785.html)。

**记录日期：** 未逐项记录。

**支持的命题：** RFC8259描述JSON语法与互操作；RFC8785的JCS按UTF-16码元排序对象属性，不作Unicode规范化，数组顺序保持。

**采用条件与边界：** JSON实例不是完整语言；普通键排序不是JCS；字节摘要不等于业务语义身份。

**使用与维护位置：** [工程实体与持久表示][owner-source]、[身份知识与模型采纳][owner-id]。

**使用与维护位置：** [操作语义接口与批处理][owner-api]、[结构作者与语义编辑][owner-edit]。

### MPS Basic notions

**来源：** [Basic notions](https://www.jetbrains.com/help/mps/basic-notions.html)、[Project structure](https://www.jetbrains.com/help/mps/mps-project-structure.html)。

**记录与复核：** 原记录未逐项记日期；2026-09-09读取上述官方页面相交章节。页面为MPS 2026.1帮助、标示2026-05-05，不代表本地已安装。

**支持的命题：** 模型可作为AST直接编辑，存在多个投影；语言由结构、类型/数据流、编辑与生成等方面组成；生成可分阶段产出程序及配置。语言扩展、模块依赖和生成目标不是同一关系。

**采用条件与边界：** 用于比较可扩展语言工作台，表明不必在普通SDK和全栈自造语言之间二选一。不推导所有领域已定义、任意投影无损或AI使用其IDE/模型格式更便宜；当前未采用整个MPS。

**使用与维护位置：** [D02](../../决策/设计理由-目标与核心.md#d02-中立语义与可替换作者表示)、[结构作者与语义编辑][owner-edit]。实际采用版本或改变作者存储/编辑方式时重核。

## 作者位置与编辑批次的一手协议核对

复核日期2026-09-10。本轮读取微软language-server-protocol仓库`gh-pages`下**3.17章节源**，不是读取全部LSP、没有安装语言服务器，也不把移动分支URL当不可变提交。使用范围是这些明确的字段和顺序，不宣称SEC兼容所有LSP能力。

| 已读来源 | 支持的具体事实 | 在SEC采用及不采用什么 |
|---|---|---|
| [TextDocumentEdit](https://raw.githubusercontent.com/microsoft/language-server-protocol/gh-pages/_specifications/lsp/3.17/types/textDocumentEdit.md)全文 | 一组文本编辑使用同一原版本坐标、必须不重叠，可从S1构造S2 | SEC顺序old/new不是该模型；适配先同基准物化，不改变原edits语义 |
| [TextEdit[]](https://raw.githubusercontent.com/microsoft/language-server-protocol/gh-pages/_specifications/lsp/3.17/types/textEditArray.md)全文 | 同一原文坐标，禁止区间重叠；合法同位置多插入保留数组次序，也允许多插入后接单次删除或替换 | 准确解释外批次，不能使用统一“排序去重”消掉合法重复；completion额外编辑另受更严格规则 |
| [TextEdit](https://raw.githubusercontent.com/microsoft/language-server-protocol/gh-pages/_specifications/lsp/3.17/types/textEdit.md)全文及[Position](https://raw.githubusercontent.com/microsoft/language-server-protocol/gh-pages/_specifications/lsp/3.17/types/position.md)全文 | 范围/空插入与位置的编码/单位规则；客户端与服务端需要一致解释 | 位置不是字节/字素的同义词；SEC强编辑输入明确编码与边界，不能据此自动认定工程身份 |
| [initialize](https://raw.githubusercontent.com/microsoft/language-server-protocol/gh-pages/_specifications/lsp/3.17/general/initialize.md)positionEncodings和positionEncoding段 | 3.17协商位置编码；缺省兼容UTF-16 | 薄适配按真实协商转为内部位置；不要求SEC核心实现LSP初始化服务 |
| [WorkspaceEdit](https://raw.githubusercontent.com/microsoft/language-server-protocol/gh-pages/_specifications/lsp/3.17/types/workspaceEdit.md)全文 | 资源操作按序；abort/transactional/textOnlyTransactional/undo是不同失败处理能力，undo无成功保证 | 不由候选原子或批量编辑名推跨文件事务；强应用只有真实宿主支持才承诺 |
| [completion](https://raw.githubusercontent.com/microsoft/language-server-protocol/gh-pages/_specifications/lsp/3.17/language/completion.md)textEdit、additionalTextEdits、command和snippet段 | 主插入与额外编辑、位置范围、额外编辑不可重叠含同位置、可附后续命令 | 建整组作者候选；额外command不是只读辅助许可，snippet不是作者新语法；不证明所有第三方服务遵守 |

旧规范有基本版本/坐标与候选批次原则；本轮补的是具体编辑模型的转换、消费者和失效条件，未找到现实SEC运行出错的记录，不把机制风险说成已发生事故。官方协议的动作或示例可作为实现参照，但当前辅助能力的字段、策略与错误处理是本设计选择，需要实际符合性检查。
