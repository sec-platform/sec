## 对象、流与微分的补充来源

### Java 25对象初始化观察

**来源：** [Java 25对象初始化观察](https://docs.oracle.com/javase/specs/jls/se25/html/jls-12.html#jls-12.5)。

**记录日期：** 未逐项记录。

**支持的命题：** 类、成员、继承和初始化有可观察的规则；初始化期间的动态分派需要单独解释。

**采用条件与边界：** 并读[JLS 25 §8](https://docs.oracle.com/javase/specs/jls/se25/html/jls-8.html)。SEC安全构造限制不等于Java全行为；原生源不能自动改义。

**使用与维护位置：** [对象构造与动态分派][owner-obj]、[导入观察与原生资产][owner-native]。

### Rust trait objects：动态分派

**来源：** [Rust trait objects：动态分派](https://doc.rust-lang.org/reference/types/trait-object.html)。

**记录日期：** 未逐项记录。

**支持的命题：** 动态调用可由数据引用与虚表承担，不以目标class关键词为必要。

**采用条件与边界：** 不因此统一全部反射、ABI或生命周期；仅作为目标分派机制参照。

**使用与维护位置：** [对象构造与动态分派][owner-obj]、[目标源码组织与生成策略][owner-target]。

### Reactive Streams 1.0.4

**来源：** [Reactive Streams 1.0.4](https://github.com/reactive-streams/reactive-streams-jvm/blob/v1.0.4/README.md)。

**记录日期：** 未逐项记录。

**支持的命题：** 需求约束交付，信号串行与取消最终性分别处理；取消后在途信号可能仍到达。

**采用条件与边界：** 不由背压规范推出全部窗口、时间或物理停止；SEC需处理资源释放与适配。

**使用与维护位置：** [本地流背压与事件时间][owner-stream]、[权限执行与资源管理][owner-exec]。

### Beam Programming Guide：水位与迟到

**来源：** [Beam Programming Guide：水位与迟到](https://beam.apache.org/documentation/programming-guide/)。

**记录日期：** 未逐项记录。

**支持的命题：** 事件时间、水位估计、迟到和输出策略有独立责任，在途输出影响进展。

**采用条件与边界：** 不据此宣称本地有限画像已经实现分布式全序或世界完整性。

**使用与维护位置：** [本地流背压与事件时间][owner-stream]、[层级状态与事件反应][owner-state]。

### JAX Autodiff Cookbook

**来源：** [JAX Autodiff Cookbook](https://docs.jax.dev/en/latest/notebooks/autodiff_cookbook.html)。

**记录日期：** 未逐项记录。

**支持的命题：** JVP/VJP及正反模式提供不同的数学接口。

**采用条件与边界：** 只在所选数域与函数条件内复用；不为任意副作用或非光滑点提供普通导数。

**使用与维护位置：** [自动微分与数值线性化][owner-ad]、[计算结构与算法实现设计][owner-calc]。

### JAX checkpointing：残余与重算

**来源：** [JAX checkpointing：残余与重算](https://docs.jax.dev/en/latest/gradient-checkpointing.html)。

**记录日期：** 未逐项记录。

**支持的命题：** 残余保存与重新计算在存储和计算之间交换。

**采用条件与边界：** 重算有成本且须保持状态与随机条件；不允许重放任意外部效果。

**使用与维护位置：** [自动微分与数值线性化][owner-ad]、[控制流与存储寿命][owner-ctrl]。

### Enzyme：既有AD变换

**来源：** [Enzyme：既有AD变换](https://enzyme.mit.edu/)。

**记录日期：** 未逐项记录。

**支持的命题：** 符合其实际支持范围的LLVM程序可以利用已有自动微分变换。

**采用条件与边界：** SEC新增源映射、数值域与契约仍需对应验证；不是所有目标都要依赖LLVM。

**使用与维护位置：** [自动微分与数值线性化][owner-ad]、[目标源码组织与生成策略][owner-target]。

## 信用、控制信号与微分错误对象

**Reactive Streams JVM 1.0.4。** 于2026-09-10读取[固定版本规范](https://github.com/reactive-streams/reactive-streams-jvm/blob/v1.0.4/README.md)及其[raw正文](https://raw.githubusercontent.com/reactive-streams/reactive-streams-jvm/v1.0.4/README.md)。本次实际对照Publisher 1.1/1.3/1.6—1.8、Subscriber 2.8—2.10及Subscription 3.2/3.3/3.9/3.12—3.13：需求数量、串行信号、终结、取消最终生效，以及同步重入与有限递归；其request(n≤0)为错误；SEC有限游标也采用正增量请求，将零余额等待与非法零增量调用分开。这些条目不定义事件水位，也不选择mapOrdered的按输入位故障顺序；后者是本版明确选择的有限流画像。

**JAX checkify guide。** 同日读取[原文的jitted/grad代码检查与限制部分](https://docs.jax.dev/en/latest/debugging/checkify_guide.html)：原计算检查和变换所产生的导数数值检查有不同覆盖；错误可作为值随计算传递，但检查和传输有实际代价。它支持区分被检查计算，不强制SEC采用PrimalFailure优先；[两通道算法](../../领域/数值/自动微分与线性化.md#ad-fault-precedence)是本设计为兑现原合同而作的选择。该动态文档不是固定JAX版本的源码证明。

本轮只对设计算例作算术和顺序复核，没有运行Reactive Streams符合性套件、JAX或SEC。已有有限差分的步长/舍入/非光滑限制、正反模式差异及检查点依据保留，不能把一个方向的一致结果推广为所有函数与全部输入上的导数正确。
