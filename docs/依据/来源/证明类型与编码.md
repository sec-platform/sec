## LLVM动态分析、coverage与coverage-guided fuzz的边界

### Clang AddressSanitizer / ThreadSanitizer

**来源与版本：** [AddressSanitizer](https://clang.llvm.org/docs/AddressSanitizer.html)、[ThreadSanitizer](https://clang.llvm.org/docs/ThreadSanitizer.html)；动态LLVM/Clang文档，本次核对2026-09-22。

**本轮实际支持：** ASan和TSan都由compiler instrumentation与runtime组成，并明确带来显著运行/内存开销；它们检测的是相应动态执行中可观察到的内存错误或data race。

**采用与不能推出：** 用于把sanitizer result绑定instrumented artifact、执行输入和检测域。无报告不证明未执行路径或未插桩组件安全，带插桩run也不直接代表生产性能/时序。

### Clang source-based coverage

**来源与版本：** [Source-based Code Coverage](https://clang.llvm.org/docs/SourceBasedCodeCoverage.html)；动态Clang文档，本次核对2026-09-22。

**本轮实际支持：** coverage依赖编译期instrumentation和source-to-counter mapping；官方明确支持instrumented与uninstrumented code混合，未插桩代码不会出现在报告中；MC/DC需要独立开关。

**采用与不能推出：** 用于将coverage分母、instrumented subject与指标类型显式化；报告不包含的代码不能自动当0%或已覆盖，100%某种coverage也不产生功能正确性证明。

### libFuzzer

**来源与版本：** [LLVM libFuzzer](https://llvm.org/docs/LibFuzzer.html)；动态LLVM文档，本次核对2026-09-22。

**本轮实际支持：** libFuzzer是in-process coverage-guided engine，依赖corpus、coverage feedback、seed、runs/time budget，可保存crash/timeout/OOM artifacts并支持corpus/crash minimization；文档还明确长期线程、全局状态等会影响fuzz结果可靠性。

**采用与不能推出：** 用于FuzzCampaign、corpus generation与reproducer合同；coverage feature增加不是业务状态覆盖，跑满时间没有finding也不能推广为“没有bug”。

## SARIF、Taint与Finding生命周期的补充依据

### SARIF 2.1.0 suppressions、baselineState与fingerprints

**来源与版本：** [OASIS SARIF 2.1.0](https://docs.oasis-open.org/sarif/sarif/v2.1.0/os/sarif-v2.1.0-os.html)，含2023 Errata 01；本次核对2026-09-22。

**本轮实际支持：** SARIF把result suppression与baselineState分开；baselineState的new/unchanged/updated/absent依赖当前run和指定baseline之间的comprehensive comparison及result matching，fingerprint用于结果管理系统判断两个result在其规则下是否“逻辑相同”。

**采用与不能推出：** suppression不等于修复或false-positive；`absent`只描述所比较run中该result关系，不能在coverage/rule/config变化后自动升级为漏洞已消失；fingerprint不成为SEC canonical finding/vulnerability identity。

### Semgrep taint model

**来源与版本：** [Semgrep Glossary](https://semgrep.dev/docs/writing-rules/glossary)及官方taint说明；动态文档，本次核对2026-09-22。

**本轮实际支持：** taint rule由rule定义的sources、sinks、sanitizers与propagators驱动；分析支持范围可为function/file/interfile等不同层级，工具能力/产品档次也会改变覆盖。

**采用与不能推出：** taint finding首先是该rule/model下的数据流分析结果。sanitizer annotation不自行证明现实安全属性，静态source→sink path不是运行trace或成功exploit，未报告路径也只在实际分析coverage内有意义。

## 时间、Locale、Unicode与单位语义的补充依据

### IANA Time Zone Database

**来源与版本：** [Theory and pragmatics of the tz code and data](https://www.iana.org/time-zones/theory)；动态tzdb，本次核对2026-09-22。

**支持的命题：** tzdb记录地点时区的历史和预测未来clock transitions；不同地点即使当前同offset也可能拥有不同历史/未来规则。民用时区包含DST等clock transition，因此local civil time与UTC Instant不是简单固定offset。

**采用与不能推出：** 用于`LocalDateTime/ZonedCivilTime/Instant/tzdb revision`分离；tzdb不是所有历史历法/时间尺度的完整真值，也不能把某次当前offset永久固化成未来规则。

### Unicode 18.0 UAX #31

**来源与版本：** [Unicode Standard Annex #31, Revision 45, Unicode 18.0.0](https://unicode.org/reports/tr31/)；页面日期2026-09-01，本次核对2026-09-22。

**支持的命题：** UAX #31为identifier字符集合、normalization与case handling提供可版本化规范，并明确display form与内部comparison form可以不同，同时提醒identifier存在security约束。

**采用与不能推出：** SEC基础语言当前仍采用自己的ASCII identifier规则，不因Unicode 18发布自动扩展文法；外部语言Provider若支持Unicode identifier，须绑定其实际Unicode版本、normalization/case/security规则。Text显示相同不自动形成相同identifier或path identity。

### Unicode CLDR

**来源与版本：** [CLDR locale option names](https://cldr.unicode.org/translation/displaynames/locale-option-names-key)与[Plurals & Units](https://cldr.unicode.org/translation/getting-started/plurals)；动态数据/规范，本次核对2026-09-22。

**支持的命题：** locale可以影响calendar、collation、currency display、numbering system、plural category和unit formatting；同一个数值在不同locale有不同显示和plural处理。

**采用与不能推出：** 用于`LocaleProfile`的展示/解析能力；CLDR格式化规则不改变机器数值、symbol identity或canonical encoding，除非具体领域明确把locale-aware parsing/collation纳入语义。

### SI / NIST 温度单位

**来源与版本：** [BIPM SI Brochure, 9th edition updated 2026](https://www.bipm.org/en/publications/si-brochure)及[NIST SI Units — Temperature](https://www.nist.gov/pml/owm/si-units-temperature)；本次核对2026-09-22。

**支持的命题：** degree Celsius的interval大小等于kelvin，但绝对Celsius temperature与thermodynamic temperature之间存在273.15的offset；温度转换因此不能统一成纯比例乘法。

**采用与不能推出：** 用于`Linear/Affine/Contextual`单位转换分型；SI单位定义不决定金融、市场、法域等contextual conversion，货币等继续使用有来源/time/fees的Provider observation。
