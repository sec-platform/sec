## 构建、内容、分布式与迁移

### Bazel Hermeticity

**来源：** [Bazel Hermeticity](https://bazel.build/basics/hermeticity)。

**记录日期：** 未逐项记录。

**支持的命题：** 构建隔离依赖明确源码、实际输入、工具和环境，隐藏读取会破坏可复现与缓存关系。

**采用条件与边界：** 用于动态补输入和准备基础；代码哈希或锁文件本身不证明完全密闭、固定解析成本，也不强制采用Bazel。

**使用与维护位置：** [编译内核与生成][owner-comp]、[宿主生态与技术约束][owner-host]。

### Bazel remote caching，动作元数据和内容存储

**来源：** [Bazel remote caching](https://bazel.build/remote/caching)，动作元数据和内容存储。

**记录日期：** 2026-09-07、2026-09-08。

**支持的命题：** 远程缓存中的动作键到结果元数据映射，与按内容存储的输出字节，是不同角色。

**采用条件与边界：** 字节完整性与动作归属分别核对；缓存不成为作者或运行权威，任务投影无需因此新增缓存服务。错误映射是威胁分析对象，不是已执行的Bazel攻击实验。

**使用与维护位置：** [查询影响与性能][owner-cache]、[编译内核与生成][owner-comp]。

### Bazel Remote Rules，活动页面

**来源：** [Bazel Remote Rules](https://bazel.build/remote/rules)，活动页面。

**记录日期：** 2026-09-08。

**支持的命题：** 远程动作依赖显式输入与工具；host、execution、target平台不同，本地隐含状态可能破坏远程执行。

**采用条件与边界：** 用于远程准入和输入闭包；给函数标记确定性不能直接取得远程资格。

**使用与维护位置：** [递归并行与远程编译][owner-par]、[宿主生态与技术约束][owner-host]。

### Bazel Dynamic execution，活动页面

**来源：** [Bazel Dynamic execution](https://bazel.build/remote/dynamic)，活动页面。

**记录日期：** 2026-09-08。

**支持的命题：** 本地与远程可竞速，但会重复消耗资源；执行系统需处理首先返回失败及环境差异。

**采用条件与边界：** SEC按传输、资源、语义和完整产物分类接纳，不无条件复制竞速政策或等待常数。

**使用与维护位置：** [递归并行与远程编译][owner-par]、[权限执行与资源管理][owner-exec]。

### Ninja manual，页面标v1.13.1（2025-07）

**来源：** [Ninja manual](https://ninja-build.org/manual.html#_gnu_jobserver_support)，页面标v1.13.1（2025-07）。

**记录日期：** 2026-09-08。

**支持的命题：** 记录的Ninja手册标v1.13.1；jobserver支持取决于版本、参数和平台，POSIX FIFO、旧pipe和显式-j条件不同。

**采用条件与边界：** 嵌套工具采用时核实际能力；设置MAKEFLAGS本身不证明统一资源预算已生效。

**使用与维护位置：** [递归并行与远程编译][owner-par]、[宿主生态与技术约束][owner-host]。

### Reproducible Builds Definition与环境范围

**来源：** [Reproducible Builds Definition](https://reproducible-builds.org/docs/definition/)与[环境范围](https://reproducible-builds.org/docs/perimeter/)。

**记录日期：** 2026-09-08。

**支持的命题：** 可复现目标需明确源、环境、指令与产物范围。

**采用条件与边界：** 完整生成键；不保证源改动后结构不变，不强迫新旧工具产生相同字节。

**使用与维护位置：** [目标源码组织与生成策略][owner-target]、[查询影响与性能][owner-cache]。

### Git update-ref

**来源：** [Git update-ref](https://git-scm.com/docs/git-update-ref)。

**记录日期：** 未逐项记录。

**支持的命题：** 可按预期旧值更新引用；每个引用的更新有原子性，多个引用的并发读取仍可能看到子集。

**排除项与适用限制：** Git事务等于任意文件集合或所有外部观察者的一次原子切换；提交成功就是部署完成。

**使用与维护位置：** [持久化提交与恢复][owner-rec]、[工程实体与持久表示][owner-source]。

### Bazel Skyframe、远程缓存、Rust编译器查询

**来源：** [Bazel Skyframe](https://bazel.build/reference/skyframe)、[远程缓存](https://bazel.build/remote/caching)、[Rust编译器查询](https://rustc-dev-guide.rust-lang.org/query.html)。

**记录日期：** 未逐项记录。

**支持的命题：** 实际依赖读取、不可变结果、动作输入/命令/环境与内容存储分别绑定；隐藏读取破坏复用。

**排除项与适用限制：** 缓存携带永久权限；SEC已经完成符号级或分布式增量。

**使用与维护位置：** [查询影响与性能][owner-cache]、[编译内核与生成][owner-comp]。

## 开发环境、准确提交与原生过滤的接合依据

读取日期2026-09-10；固定文档版本只在下面明确给出时成立。没有在本轮安装依赖、操作产品仓库或推送远端。

| 官方直接材料 | 实际核对的内容 | 采用边界 |
|---|---|---|
| [npm cli v10：npm ci](https://docs.npmjs.com/cli/v10/commands/npm-ci/)的Description与配置相关小节 | 锁先存在、锁与声明不匹配失败、不改锁、已有node_modules会先移除；真实脚本/配置影响执行 | 锁定解析与无现场作用分开；不选择npm为SEC唯一包管理器，也不把忽略脚本结果等同完整可用 |
| [Git commit](https://git-scm.com/docs/git-commit)的Description与内容选择小节 | 正常commit采用index；路径/-a/交互选择有不同内容语义，记录父提交并推进分支 | 明确index与worktree候选、选择和真实提交；动态文档非当前容器Git版本证明 |
| [Git update-ref](https://git-scm.com/docs/git-update-ref)的old-oid、事务及读取限制小节 | 可以比较旧ref再更新；多引用修改不保证并发读者获得全局一致快照 | 用于ref保护而非工作树/全系统原子性；旧尝试是否生效仍需原恢复依据 |
| [Git attributes](https://git-scm.com/docs/gitattributes)的text/eol、working-tree-encoding、filter、export-subst小节 | 签入/签出可能变换字节并调用真实过滤器，归档展开可依赖commit信息 | 检查实际提交blob与相交配置/历史；同tree不能覆盖所有历史敏感构建，也不默认强制用户重规范化全库 |

这些资料支持具体操作差异，不证明SEC的候选捕获、挂钩隔离、VCS协调和环境切换已经有效。本版准备计划、阶段对账与开发者选择是基于原拥有者的设计；原生工具缺少所需保证时准确报告，不绕开项目政策或伪造原子能力。
