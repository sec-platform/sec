## 构建、内容、分布式与迁移

### Bazel Hermeticity

**来源：** [Bazel Hermeticity](https://bazel.build/basics/hermeticity)。

**记录日期：** 未逐项记录。

**支持的命题：** 构建隔离依赖明确源码、实际输入、工具和环境，隐藏读取会破坏可复现与缓存关系。

**采用条件与边界：** 用于动态补输入和准备基础；代码哈希或锁文件本身不证明完全密闭、固定解析成本，也不强制采用Bazel。

**使用与维护位置：** [编译内核与生成][owner-comp]、[宿主生态与技术约束][owner-host]。

### Bazel remote caching，动作元数据和内容存储

**来源：** [Bazel remote caching](https://bazel.build/remote/caching)，动作元数据和内容存储。

**记录日期：** 2026-09-07、2026-09-08。

**支持的命题：** 远程缓存中的动作键到结果元数据映射，与按内容存储的输出字节，是不同角色。

**采用条件与边界：** 字节完整性与动作归属分别核对；缓存不成为作者或运行权威，任务投影无需因此新增缓存服务。错误映射是威胁分析对象，不是已执行的Bazel攻击实验。

**使用与维护位置：** [查询影响与性能][owner-cache]、[编译内核与生成][owner-comp]。

### Bazel Remote Rules，活动页面

**来源：** [Bazel Remote Rules](https://bazel.build/remote/rules)，活动页面。

**记录日期：** 2026-09-08。

**支持的命题：** 远程动作依赖显式输入与工具；host、execution、target平台不同，本地隐含状态可能破坏远程执行。

**采用条件与边界：** 用于远程准入和输入闭包；给函数标记确定性不能直接取得远程资格。

**使用与维护位置：** [递归并行与远程编译][owner-par]、[宿主生态与技术约束][owner-host]。

### Bazel Dynamic execution，活动页面

**来源：** [Bazel Dynamic execution](https://bazel.build/remote/dynamic)，活动页面。

**记录日期：** 2026-09-08。

**支持的命题：** 本地与远程可竞速，但会重复消耗资源；执行系统需处理首先返回失败及环境差异。

**采用条件与边界：** SEC按传输、资源、语义和完整产物分类接纳，不无条件复制竞速政策或等待常数。

**使用与维护位置：** [递归并行与远程编译][owner-par]、[权限执行与资源管理][owner-exec]。

## 开发环境、准确提交与原生过滤的接合依据

读取日期2026-09-10；固定文档版本只在下面明确给出时成立。没有在本轮安装依赖、操作产品仓库或推送远端。

| 官方直接材料 | 实际核对的内容 | 采用边界 |
|---|---|---|
| [npm cli v10：npm ci](https://docs.npmjs.com/cli/v10/commands/npm-ci/)的Description与配置相关小节 | 锁先存在、锁与声明不匹配失败、不改锁、已有node_modules会先移除；真实脚本/配置影响执行 | 锁定解析与无现场作用分开；不选择npm为SEC唯一包管理器，也不把忽略脚本结果等同完整可用 |
| [Git commit](https://git-scm.com/docs/git-commit)的Description与内容选择小节 | 正常commit采用index；路径/-a/交互选择有不同内容语义，记录父提交并推进分支 | 明确index与worktree候选、选择和真实提交；动态文档非当前容器Git版本证明 |
| [Git update-ref](https://git-scm.com/docs/git-update-ref)的old-oid、事务及读取限制小节 | 可以比较旧ref再更新；多引用修改不保证并发读者获得全局一致快照 | 用于ref保护而非工作树/全系统原子性；旧尝试是否生效仍需原恢复依据 |
| [Git attributes](https://git-scm.com/docs/gitattributes)的text/eol、working-tree-encoding、filter、export-subst小节 | 签入/签出可能变换字节并调用真实过滤器，归档展开可依赖commit信息 | 检查实际提交blob与相交配置/历史；同tree不能覆盖所有历史敏感构建，也不默认强制用户重规范化全库 |

这些资料支持具体操作差异，不证明SEC的候选捕获、挂钩隔离、VCS协调和环境切换已经有效。本版准备计划、阶段对账与开发者选择是基于原拥有者的设计；原生工具缺少所需保证时准确报告，不绕开项目政策或伪造原子能力。

## 动态执行代、回收与通知交接的依据

读取日期2026-09-20。以下四项只支持所述机制；SEC的接纳、权限、预算、调用和恢复组合是本库设计，不由外部代码认证，也没有据此安装依赖或采用新的运行服务。

| 直接材料与准确范围 | 支持的具体观察 | 使用、限制与复核条件 |
|---|---|---|
| [Go内部singleflight源码](https://go.dev/src/internal/singleflight/singleflight.go)，读取页的doCall与ForgetUnshared | 完成删除前比较表中是否仍为该call；忘记键与原执行终结不是同一动作 | [共享生产代际](../../编译/递归并行与远程编译.md#shared-producer-generation)采用实例比较的必要性；该实现的dups不是当前活跃等待者数，不照搬为SEC取消、资源或锁外回调保证。页面未固定发行版，实际采用代码需另锁修订 |
| [Linux RCU说明](https://docs.kernel.org/RCU/whatisRCU.html)，Overview、read-side与call_rcu说明 | 移除新访问路径与等旧读者后回收分开；异步回收需控制更新速率；超出受保护读段的引用需额外寿命安排 | [运行代切换](../../运行/发布运行与资源生命周期.md#runtime-generation-cutover)的机制参照；不把kernel原语直接移植到TS，不用grace period证明设备/业务已停止。换成实际无锁实现时重核内存模型与异步引用 |
| [client-go工作队列](https://github.com/kubernetes/client-go/blob/a1f10fd517a228182a15925dbef6abb2209d927d/util/workqueue/queue.go)，Typed、Add、Get、Done，blob `9bffddd634c1a7444a849011c80b528f6af30472` | dirty与processing可并存，Done把处理中再次变脏的键送回队列；非同步Len不承担接纳条件 | [调和交接](../../运行/发布运行与资源生命周期.md#reconcile-wakeup-handoff)采用唤醒保留思路；不采用关闭后静默忽略新Add为SEC公开接受语义，不据此声称实际目标已更新 |
| [Kubernetes API Concepts](https://kubernetes.io/docs/reference/using-api/api-concepts/#efficient-detection-of-changes)，list/watch及历史过期说明 | 从快照返回的位置续Watch；历史不可用时重新取得基础再观察 | [原快照事件握手](../../开发/工具协议/客户端与并行会话.md#快照与事件之间的无缺口接合)、[活动依赖交接](../../编译/查询增量与性能.md#live-projection-dependency-handoff)与R0消费；不引入Kubernetes依赖，不照搬具体保留时长，不把列表/Watch规则推成任意第三方能力 |

前两项解决运行实例仍被使用与名称槽位复用，后两项解决观察触发的交接；它们不是一套可互相替代的“版本控制”。外部材料没有保证SEC跨进程切换、设备终结、强隔离、当前授权或持续收敛，必须在相应真实提供者上验证。

## CycloneDX VEX的上下文可利用性边界

**来源与版本：** [CycloneDX VEX capability](https://cyclonedx.org/capabilities/vex/)及[1.7 specification overview](https://cyclonedx.org/specification/overview/)；本次核对2026-09-22。

## Workload身份与短期凭证租约的边界

### SPIFFE Workload API 与 Trust Bundle

**来源与版本：** [SPIFFE Workload API](https://spiffe.io/docs/latest/spiffe-specs/spiffe_workload_api/)与[Trust Domain and Bundle](https://spiffe.io/docs/latest/spiffe-specs/spiffe_trust_domain_and_bundle/)；latest规范，本次核对2026-09-22。

**本轮实际支持：** Workload API向workload交付SVID与trust bundle；验证时需要使用与SVID trust domain对应的bundle，而bundle内容会随key rotation变化。

**采用与不能推出：** 用于workload authentication Provider、trust-root rotation和身份观察；SVID通过只证明相应认证链，不能签发业务authorization。SVID/bundle的Provider locator也不成为SEC主体身份。

### HashiCorp Vault leases

**来源与版本：** [Lease, Renew, and Revoke](https://developer.hashicorp.com/vault/docs/concepts/lease)与[lease revoke](https://developer.hashicorp.com/vault/docs/commands/lease/revoke)；动态官方文档，本次核对2026-09-22。

**本轮实际支持：** Vault动态secret和service token可带lease/TTL/renewability；lease过期或revoke会使consumer不能继续确信credential有效。force revoke还可能只移除Vault侧lease记录而下游secret-engine revocation失败并造成不同步。

**采用与不能推出：** 用于SecretBinding的有效期、续租、撤销和残余建模；本地TTL未过不证明未被撤销，控制面删除lease也不能在Provider明确失败/未知时冒充下游凭证已失效。

## 移动应用与固件部署身份的补充依据

### Android adb

**来源与版本：** [Android Debug Bridge](https://developer.android.com/tools/adb)；动态官方文档，本次核对2026-09-22。

**本轮实际支持：** 多device/emulator时命令必须明确选择target serial；adb install、install-multiple、incremental install、uninstall等是独立设备作用，incremental安装还区分“足以launch”与完整内容继续流式物化。

**采用与不能推出：** 用于AppInstallationBinding中的device/provider locator与安装代；adb serial不成为跨重建物理设备identity，install返回不证明app launch/readiness/test完成。

### Apple provisioning 与 code signing

**来源与版本：** [TN3125: Inside Code Signing: Provisioning Profiles](https://developer.apple.com/documentation/technotes/tn3125-inside-code-signing-provisioning-profiles)、[Distributing your app to registered devices](https://developer.apple.com/documentation/xcode/distributing-your-app-to-registered-devices)；本次核对2026-09-22。

**本轮实际支持：** provisioning profile把允许签名者、app、运行位置/设备、时间和entitlements连接起来；目标device、App ID、certificate/profile均参与运行/分发资格。

**采用与不能推出：** 签名格式/签名验证不能代替当前provisioning、device、entitlement或用户许可；安装、签名、profile生成/刷新、launch分别是不同作用。

### OpenOCD flash programming

**来源与版本：** [OpenOCD Flash Programming](https://openocd.org/doc-release/html/Flash-Programming.html)；官方用户指南，本次核对2026-09-22。

**本轮实际支持：** OpenOCD program流程可以串联reset/halt、flash write、可选verify、reset run和shutdown；这些步骤本身可分别成功或失败。

**采用与不能推出：** 用于HardwareDeploymentBinding把flash attempt、verify、reset/boot与运行Evidence分开；verify flash内容不证明目标已经boot、外设工作或安全/实时Claim成立。

## IaC状态、计划、漂移与字段ownership依据

### Terraform plan/apply/refresh-only

**来源与版本：** [terraform plan](https://developer.hashicorp.com/terraform/cli/commands/plan)、[terraform apply](https://developer.hashicorp.com/terraform/cli/commands/apply)、[Use refresh-only mode](https://developer.hashicorp.com/terraform/tutorials/state/refresh)；动态官方文档，本次核对2026-09-22。

**本轮实际支持：** Terraform以configuration与state为输入，并在普通plan/apply中刷新远端观察；refresh-only模式只更新state/output以反映外部变化而不修改远端resource。未保存plan后续apply会重新规划，saved plan则保存先前计划结果供apply执行。

**采用与不能推出：** 用于分离configuration、provider state、remote observation、plan和apply。state不是远端现实，plan不是执行授权；refresh-only写state也不是接受作者配置变化。

### Kubernetes Server-Side Apply

**来源与版本：** [Server-Side Apply](https://kubernetes.io/docs/reference/using-api/server-side-apply/)与[API Concepts](https://kubernetes.io/docs/reference/using-api/api-concepts/)；动态官方文档，本次核对2026-09-22。

**本轮实际支持：** API server在managedFields中跟踪field manager；Apply试图改变其他manager拥有且值不同的字段时产生conflict，force可覆盖并转移ownership；同值可形成shared ownership。省略字段可能放弃ownership并导致删除/default，字段schema atomic/granular变化会影响ownership语义。

**采用与不能推出：** field manager是workflow协调identity，不是SEC安全principal/Grant，也不是semantic owner。Provider的field ownership只用于精确冲突/调和映射，不能由manager字符串授予写权限。

## Package Registry发布、可移动标签与退役依据

### npm registry、dist-tags、deprecate/unpublish

**来源与版本：** [npm Unpublish Policy](https://docs.npmjs.com/policies/unpublish/)、[Deprecating packages](https://docs.npmjs.com/deprecating-and-undeprecating-packages-or-package-versions/)、[Adding dist-tags](https://docs.npmjs.com/adding-dist-tags-to-packages/)；当前npm官方文档，本次核对2026-09-22。

**本轮实际支持：** npm registry将已发布`name@version`视为不可原地改变的registry data；unpublish只在政策允许范围移除可安装记录且同名版本不能靠unpublish后重新复用。dist-tag是可移动的人类/解析alias；deprecate保留版本但给安装者警告。

**采用与不能推出：** 用于区分immutable-ish package version record、mutable tag、deprecation与withdrawal。npm具体72小时/权限政策不是SEC通用TTL；tag变化不改变artifact/version identity，unpublish也不能擦除已传播副本。

### Cargo / crates.io publish 与 yank

**来源与版本：** [Cargo Book: Publishing on crates.io](https://doc.rust-lang.org/cargo/reference/publishing.html)；当前官方文档，本次核对2026-09-22。

**本轮实际支持：** crates.io publish的specific version一般永久、不可覆盖；`cargo yank`不删除代码，而是使新的dependency resolution不选择该版本，既有Cargo.lock仍可继续工作。

**采用与不能推出：** 用于把内容可取得性、未来解析资格和当前已锁消费者分开。yank不等于远端删除，也不证明已部署消费者停止使用；owner/publish权限仍映射现有Grant而非代码ownership。
