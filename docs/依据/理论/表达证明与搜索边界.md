## 通用性与简化可以共存

### 表达能力、作者工作与全局最优不是同一个命题

保留一般计算能力，同时让某类或很多实际工程更短、更少重复决定，是允许且可以构造的设计目标。不能从“任意信息不能全部无损压缩”推出“通用工具不能比现有编程方式简洁”。图灵完备讨论理想资源下的可计算函数，不决定代码长度、作者成本、硬件适配、可分析性质或工程权限。有限主机与任务预算也不改变所讨论抽象语言的计算类别。

必须分别陈述：可表达的程序集合；对同一行为的作者长度；共享库与解释器成本；从意图到合格结果的总工作；运行时间/内存；支持的证明与保证。某些维度可以同时改善，某些有权衡；不能把它们机械写成通用性与简洁的零和关系。

### 一个保留通用性的构造

固定一种通用语言P及其解释。构造S：它既接受完整的P程序，又接受可以按确定规则转换到P的高层定义与组合。对任意P程序p，S保留对应的含义；高层表达也有明确降低含义。因此在相同计算模型下，S至少保留P的计算表达能力，不需要穷举业务种类。

若采用常数长度的模式前缀来选择底座解释器，随后原样承载程序p，则只需固定封装成本c，存在等义S表示，其长度不超过p的长度加c；`base(p)`只是这一构造的文字示意，不主张任意实际转义格式都有常数开销。若采用不破坏旧语法的保守扩展，原程序可以直接保留。这个构造只证明计算表达与高层简写可共存，不证明实际SEC已支持全部P宿主能力，也不证明类型、安全、跨目标和总使用成本同步继承。

新增的高层定义可以把重复模式表示为名称、参数及局部差异。对这些模式，作者表达可以明显缩短；没有收益的程序继续用原有表示。不能因此要求每个基础程序都附全量元数据，否则实际实现破坏了这项设计意图。Racket宏和MetaOCaml保守扩展提供具体机制参照，来源归[资料](../来源/语言编译与目标工具.md#语言编译与目标工具)。

### 计数反例究竟限制什么

固定解释器、共享词典和环境，要求用二进制描述精确区分全部长度为n的二进制结果。结果有2^n个，而长度严格小于n的描述总共只有1+2+…+2^(n-1)=2^n−1个。一个确定描述只能选择一个精确结果，所以不可能让所有这些结果都获得小于n比特的无损描述。

这是一项有限计数推导，不需要假设业务一定随机。它没有证明某个现有语言的写法已经最短，也没有排除对有大量冗余的代码普遍改进；并不禁止通过共享库、参数化、推导或更合适的表示缩短实际任务。若给每个结果临时新增一个字典条目，条目本身的内容与维护代价要计入，不能把省略的信息藏进不计成本的解码器。

### 不用最坏情况压低产品目标，也不用短表达冒领总成本

开发者没有提供、不受既有约束决定的业务差异，需要形成明确选择；若用户确实接受多种结果，则选择一个合法实现不要求补齐无关偏好。可推导的类型、连线、规范化和实现细节应尽量推导；稳定项目政策可避免反复选择；真正未定的意图不能因模型猜中一次就改成确定事实。

比较SEC和原生路线时，双方可以使用相同成熟库、相同可复用模式与同等正确性要求。调用一个标准功能比徒手实现它短，不能证明SEC独有优势。应另外检验定义能否持续编辑、跨产物能否消除重复维护、未预装需求能否保持一般表达，以及复杂局部是否能展开修改后继续由原作者源生成。

当前允许的强结论是“通用性与很多场景下的简化可共存”；“SEC在实际任务分布上更便宜”仍需对应证据；“对所有程序、所有成本同时严格最优”不能从上述构造推出。没有全局最优证明不构成放弃更强架构设计的理由。

## 不可判定性结论的适用范围与误用

### 必须撤销的错误推论

“不能普遍判定任意程序的非平凡行为性质”不推出“不能实现跨语言编译器”。“不能保证任意工程完整自动提升”不推出“不能把工程导入自身项目表示”。“不存在对所有问题都最优的求解器”不推出“不能根据用户明确写出的控制逻辑生成代码”。

从明确源码进行翻译，与从不完整要求中合成程序，是不同任务。不可解性分析、世界模型选择和候选搜索仅在具体任务确实需要时启用，不作为普通编译的统一前置。

### 应保留的边界

一般停机、全程序等价和完整静态依赖不可无条件解决；具体有限语言片段、明确语义的转换规则、受控输入快照和目标合法性则可以被实现并验证。编译器可以保留非终止行为，不需先证明终止。

无法判断一种构造是否安全可以触发专门诊断、保留原生区域或限制高风险动作。普通类型正确程序不应因为缺少社会选择理论或全球最优证明被拒绝生成。

### 正确的理论使用

每项理论记录模型假设、量词、所否定的性质及其与当前操作的映射。已知问题类不可判定不等于每个实例无解；在预算内没找到不等于不可满足；多个候选不等于无法选择。研究结论只修改真实依赖它的保证，不通过“终局架构”标题取得产品层权威。

### 理由与反证

理论研究的价值是阻止伪承诺。若它不再产生具体 bug、测试或边界，只让用户的工程语言消失，就是治理本身成为故障。继续攻击时必须同时攻击新防线的必要性，而不能永远只增加限制。

## 形式不可判定、自指与证明边界

<a id="1-根裁决-6"></a>

### 1. 根裁决

通用工程编译器不能对任意程序、任意需求和任意环境普遍决定下列问题：

- 程序是否终止；
- 两个任意实现是否对所有上下文等价；
- 某个非平凡语义性质是否成立；
- 任意并发或混合系统是否永远安全；
- 任意安全信息流性质是否成立；
- 任意系统定义是否包含全部真实依赖；
- 足够强的自描述验证系统是否能在自身内部证明自身一致性与完整可信。

因此，SEC 的根合同不能是：

```text
输入任何工程
→ 完全理解
→ 找到全部问题
→ 证明最优方案
→ 证明自身证明可靠
```

必须改为：

```text
输入一个声明的模型、语言、环境、资源和假设域
→ 依据已知定理、受支持语言片段和显式假设匹配可判定性画像；不能普遍分类的实例保留未知
→ 对可判定片段给出证明或反例
→ 对半判定片段给出单侧结果
→ 对近似片段给出 soundness/completeness 方向
→ 对不可判定或超预算片段保留结构化未知
```

### 2. 可判定性画像

每个分析、求解、优化和验证动作必须声明：

```text
DecisionProcedureProfile = {
  subjectLanguage,
  semanticPropertyClass,
  inputUniverse,
  assumptions,
  decidabilityClass,
  soundnessDirection,
  completenessDirection,
  terminationCondition,
  complexityBounds,
  resourceBudget,
  certificateOrCounterexample,
  unknownSemantics
}
```

`decidabilityClass`只记录所选问题类的已知分类或分类未知，不容纳执行结果：

可判定性、分析方向、执行结果和假设是独立坐标，不建立一个互斥大枚举。有限/半判定的问题类只描述所选方法适用范围；具体调用仍记录证明、见证、有界结果、未知或失败。完整字段与方向见[证明结果的方向与组合](../../运行/验收/方法与独立证据.md#证明结果的方向与组合)。

系统不得把 `timeout`、`out-of-memory`、`solver-unknown`、`abstraction-gap`、`unsupported-theory` 和 `unsatisfied` 合并。

### 3. Rice 型边界对 SEC 的直接影响

任意非平凡程序语义性质在足够一般的程序类上都不能由一个总是终止且总是正确的算法决定。对 SEC 而言，这意味着：

- “该模块永远不泄漏秘密”不能对任意语言和任意环境由通用静态分析完全判定；
- “这个变更不影响任何用户行为”不能对任意程序完全判定；
- “这段代码没有隐藏依赖”不能仅靠一般程序文本完全判定；
- “两个语言后端完全等价”不能在无约束上下文中普遍判定；
- “此修复是最小且唯一正确修复”不能普遍判定。

正确设计不是放弃分析，而是记录[近似集合包含方向](../../运行/验收/方法与独立证据.md#证明结果的方向与组合)。过近似排除全部坏行为可支持安全，发现坏抽象行为需再具体化；欠近似的真实见证可反驳，但没有见证不能证明全域安全。名字含sound或complete不替代这些前提。

### 4. 自指与自托管边界

SEC 最终会编译、修改和验证 SEC 自身。这会形成：

```text
compiler validates validator
validator validates compiler
policy authorizes policy migration
assurance system evaluates assurance system
```

纯内部闭环不能自动产生绝对信任。必须至少保留一种不由候选控制的外部根：

- 冻结的小型 proof checker；
- 独立实现的 translation validator；
- 可信旧代际；
- 多样化构建和双编译；
- 人工签发的不可逆迁移授权；
- 外部硬件或签名根；
- 可重演的公开证书。

即便如此，结论也只在假设下成立。

### 5. Gödel 型限制的工程含义

足够表达算术的形式系统无法同时在自身内部完成所有真命题证明，并以通常条件证明自身一致性。工程上应避免两种误读：

1. 不能由此推断“形式验证没用”；
2. 也不能宣称“只要把 SEC 元模型再扩一层，就能消除所有证明外部性”。

正确结构是无限回归的有界截断：

```text
Claim
→ Proof/Certificate
→ Small Checker
→ Checker Implementation Assurance
→ Toolchain/Hardware Assumptions
→ Physical Validation
→ Residual Trust
```

每层减少需要信任的表面，但不能把残余信任降为零。

### 6. 运行时监控也有不可证明边界

有限执行前缀不能普遍证明未来永远会发生的活性性质，例如“请求最终必定完成”。运行时监控适合：

- 已发生的安全违反；
- 有界时限；
- 可观测状态约束；
- 资源和权限边界；
- 需要触发降级的风险信号。

它不能单独证明：

- 无限未来活性；
- 未观测通道不存在；
- 所有潜在执行都安全；
- 所有对手都已覆盖。

### 7. 新的编译结果

结果采用[统一的证明方向与组合合同](../../运行/验收/方法与独立证据.md#证明结果的方向与组合)，不在理论章节重定义一套返回枚举。

所有下游必须保持分类，禁止只保存 `passed: boolean`。

### 8. 架构反转条件

若某个 SEC 子系统仍宣称对开放任意工程完成以下动作之一，则该设计必须被拒绝：

- 完整发现全部语义依赖；
- 完整证明所有非平凡行为性质；
- 自动证明自身完整可信；
- 对无限或未约束状态空间给出完全终止判定；
- 把近似分析结果展示为形式证明；
- 把模型内证明展示为物理现实的绝对保证。

### 9. 验证义务

- 每个分析器声明判定域和未知语义；
- 已知不可判定的是问题类别时，把 `UndecidableInDeclaredClass` 记录为类别边界；具体实例仍可有证明、反例或未知，不强制产生实例无解/拒绝；
- 超预算与逻辑不满足分离；
- sound overapproximation 通过漏报对抗测试；
- underapproximation 通过反例真实性验证；
- proof checker、模型翻译和 TCB 变化使旧证据陈旧；
- 自托管升级必须由旧根或外部根验证，候选不得自签完成。

### 10. 类别元数据不覆盖实例结论

`decidabilityClass` 描述给定语言与性质族有没有通用程序保证；`instanceResult` 描述本次对象获得了什么证据。两者正交：一般停机不可判定不阻止证明某个有界循环终止，也不阻止编译该程序。没有通用完备判定器不等于当前实例无解。

只在某个输出确实要求的保证无法由现有证据/方法在所需范围满足时，阻断该输出的相应保证。普通语法检查、明确 lowering 和已采纳模型生成不以这些研究画像全部完成为前置。

## 形式证明、可信计算基与物理现实

<a id="1-根裁决-7"></a>

### 1. 根裁决

形式证明是最高强度证据之一，但它证明的是：在某个形式系统、模型、解释、输入和假设下，结论可由规则推出。它不能自动证明：

- 规范就是用户真正需要的；
- 模型完整描述了物理环境；
- 源码到模型的翻译正确；
- 编译器、链接器、固件、硬件和设备没有未建模行为；
- 证明器和检查器没有实现缺陷；
- 侧信道、故障注入和供应链未越出模型；
- 操作员会按证明要求配置和使用系统。

因此 `formal-proof=true` 不能成为 SEC 顶层布尔完成状态。

### 2. AssumptionLedger

```text
AssumptionLedger = {
  logicalAxioms,
  modelAbstractions,
  environmentAssumptions,
  hardwareAssumptions,
  toolchainAssumptions,
  initializationAssumptions,
  configurationAssumptions,
  adversaryModel,
  excludedChannels,
  humanProcedureAssumptions,
  validityAndRevalidation,
  evidenceForAssumptions,
  residualUnknowns
}
```

每个顶层保证必须能够追到这份账本；假设变化只使依赖它的 Claim 陈旧。

### 3. TCB 不是一个文件清单

```text
TrustedComputingBaseGraph = {
  trustSubjects,
  trustReasons,
  dependencyEdges,
  configurationAndBuildClosure,
  hardwareAndFirmware,
  credentialAndSigningRoots,
  proofCheckers,
  bootstrapPath,
  updateAndRevocation,
  commonCauseClusters
}
```

文件摘要只证明字节身份，不证明：

- 这些字节就是实际执行对象；
- loader 没有选择另一份库；
- 微码、固件和硬件符合模型；
- 编译器没有植入自传播后门；
- 初始化和配置满足证明前提。

### 4. Trusting Trust 对自举的攻击

一个被篡改编译器可以在编译编译器自身时保留后门，即使源代码看起来干净。SEC 的自托管链必须支持：

- 多样化双编译；
- 独立工具链重建；
- 二进制或 translation validation；
- 可重复构建只能证明相同，不证明正确；
- 受信种子和种子来源保全；
- 候选不得修改并独自验证自己的 bootstrap oracle。

### 5. 证明范围必须绑定配置

相同项目不同配置可能走完全不同的代码和硬件路径。ProofCoverage 至少包含：

```text
architecture
platform
feature flags
build profile
memory model
compiler options
linked components
runtime configuration
device/DMA assumptions
initialization state
excluded features
```

未覆盖配置必须是 `unverified`，不能继承相邻配置的 proof badge。

### 6. 硬件和侧信道边界

功能正确和信息流证明通常基于抽象机器。真实系统还可能包含：

- cache/timing/channel；
- speculative execution；
- DMA；
- fault injection；
- microarchitectural state；
- power/EM/acoustic leakage；
- memory disturbance；
- clock/voltage/temperature effects；
- undocumented device behavior。

系统必须明确 `ExcludedPhysicalChannels`。声明“confidentiality proved”只能在相应观察模型内成立。

### 7. 小检查器也不是绝对根

小型证书检查器显著减少 TCB，但仍需：

- 源码和二进制一致性；
- 内存安全与整数语义；
- 解析器严格性；
- 证书与目标主体绑定；
- 拒绝未知算法和版本；
- 运行环境和硬件假设；
- 独立重演。

### 8. Proof 与现实保证组合

```text
Assurance =
  formal theorem
  + model-to-implementation conformance
  + binary/build provenance
  + configuration proof
  + physical environment evidence
  + adversarial testing
  + runtime monitoring
  + user/operational validation
  + residual assumption acceptance
```

这些分量不能相互替代。

### 9. 证明债务和演进

每次修改：

- 模型；
- 证明脚本；
- compiler；
- checker；
- configuration；
- hardware target；
- adversary model；
- external dependency；

都必须计算受影响 proof closure。证明维护成本进入架构成本，不能只计算运行性能。

### 10. 无法达成绝对信任时的输出

```text
AssuranceOutcome =
  | ProvedAndAssumptionsValidated
  | ProvedWithOpenAssumptions
  | BoundedVerified
  | PhysicalEvidenceOnly
  | ConflictingEvidence
  | TCBUnclosed
  | MappingUnvalidated
  | AssuranceInsufficient
```

高风险 Effect 只有在适用 policy 接受相应 outcome 时才可执行。

### 11. 验收

- 每个 proof 有 AssumptionLedger；
- proof badge 不能跨配置继承；
- candidate 不能独自替换 checker 和证明根；
- 二进制、配置和实际加载闭包可读回；
- 侧信道和硬件未覆盖范围明确；
- 多样化构建或 translation validation 覆盖关键自举；
- 绝对安全、绝对正确、零 TCB 等无条件措辞被禁止。

## 无普适最优、复杂度与搜索极限

<a id="1-根裁决-8"></a>

### 1. 根裁决

“为任何工程找到全局最优架构”不是可实现的产品保证。原因不是单纯算力不足，而是四种更深限制同时存在：

1. **目标函数不存在或不唯一**：不同主体、时间尺度和法域采用不同价值序；
2. **候选空间不可完全生成**：未来算法、未观察约束和外部能力尚不存在；
3. **搜索和验证代价不可承受**：组合空间、状态空间和证明空间常呈指数增长；
4. **某些可计算问题甚至不存在最终最优算法**：对每个算法还可能存在系统性更快算法。

因此 SEC 应从“最优架构编译器”改为：

> 在声明的候选生成器、目标、风险、资源、证据和时间边界内，编译可行集、支配关系、不可能性证书、鲁棒满意解与继续获取信息的价值。

### 2. 五种“最优”必须分开

```text
OptimalityKind =
  | LogicalOptimality          // 在形式模型和完整候选集内
  | ParetoNonDominance         // 没有已知候选在全部维度支配
  | RobustOptimality           // 在不确定集内最坏或后悔值较优
  | StatisticalOptimality      // 对声明分布或样本过程较优
  | InstitutionalLegitimacy   // 经有权主体按合法程序选择
```

任何一种都不能自动推出另外四种。

### 3. 无免费午餐对通用优化器的攻击

若对所有可能问题分布平均，没有一个优化算法普遍优于其他算法。工程含义：

- 一个搜索器在 Web 工程上优秀，不证明在实时控制、数据库迁移或密码协议上优秀；
- 一个启发式只有绑定问题分布、候选生成器和损失函数才有意义；
- “通用最强规划器”必须被拆成带领域先验和可验证适用域的策略组合；
- 性能比较必须保留 benchmark 分布、训练污染、实例族和失败样本。

### 4. Blum 加速对“最终最快实现”的攻击

存在可计算问题，使得每个计算它的算法都可以被另一个算法任意显著加速；因此某些问题不存在稳定意义上的最佳算法。对 SEC：

- 不能为所有编译任务声称存在一个终局最优 pass pipeline；
- `best-known` 必须绑定时间、语料、硬件、成本模型和候选空间；
- 算法替换不一定收敛到终点，长期可能持续出现更优实现；
- 需要把算法身份、比较证据和退役条件作为演进对象，而不是冻结“永久最佳”。

### 5. 复杂度与状态爆炸

以下子问题在一般形式下可能是 NP-hard、PSPACE-hard、EXPTIME 或不可判定：

- 领域边界划分；
- 最小修改集合；
- 调度和资源分配；
- 测试最小覆盖；
- 多目标实现选择；
- 程序等价和超优化；
- 状态机组合与模型检查；
- 分布式合成；
- 依赖版本解析和兼容组合。

系统必须区分：

```text
exact-complete
exact-bounded
parameterized
approximation-with-ratio
heuristic-with-no-guarantee
anytime-with-bounds
unknown
```

### 6. 搜索预算是语义输入

```text
SearchContract = {
  candidateGenerators,
  exploredRegion,
  pruningProofs,
  admissibleHeuristics,
  time/memory/provider budgets,
  incumbentCandidates,
  lowerUpperBounds,
  unexploredFrontier,
  optimalityClaimKind
}
```

超预算时，正确结果是：

```text
BoundedCandidatePortfolio {
  nonDominatedKnown,
  provedDominated,
  infeasibleRegions,
  unexploredFrontier,
  bestKnownBounds,
  valueOfAdditionalSearch
}
```

而不是把当前最好候选标记为 `optimal`。

### 7. 多目标和社会选择的不可比性

安全、隐私、公平、可访问性、成本、速度、自治、可解释性和不同主体利益可能互相冲突。即使每个维度可测，也未必存在所有主体共同接受的排序。

SEC 必须在输出中区分：

- 逻辑不可行；
- 技术可行但规范冲突；
- 方案互不支配；
- 决策程序本身可被策略操纵；
- 需要合法的人类或制度裁决。

### 8. “最小改动”也可能不是最佳

最小文件 diff、最少行数或最少模块变化可能：

- 保留错误边界；
- 延长兼容债务；
- 增加未来迁移成本；
- 隐藏根因；
- 使安全证明更难；
- 造成更大的长期总成本。

因此修改优化对象应为：

```text
LifecycleChangeVector = {
  semanticDelta,
  implementationDelta,
  migrationDelta,
  verificationDelta,
  operationalDelta,
  retirementDelta,
  residualRisk
}
```

### 9. 修订后的决策流水线

```text
hard impossibility checks
→ non-compensable constraints
→ candidate generation with provenance
→ eligibility and assumption checks
→ infeasibility/undecidability classification
→ risk and uncertainty envelope
→ Pareto reduction only under comparable continuation boundaries
→ robust satisficing or reversible experiment
→ legitimate decision authority
→ post-decision monitoring and reversal
```

完整操作规则由[联合搜索](../../编译/实现选择与设计搜索.md#带边界状态的联合搜索与合法剪枝)拥有：可比较性包含剩余义务、公开观察、真实表示和未来成本关系，不仅是局部接口类型。一般程序的完整等价不被假设可判定；没有充分比较依据时保留候选或明确探索范围。

<a id="10-验收-4"></a>

### 10. 验收

- 搜索结果不使用无条件 `optimal`；
- 所有最优性声明绑定候选空间和证明等级；
- 增加新的候选生成器可以重新打开旧决策，但只失效依赖该候选完备假设的结论；
- 超时保留上下界和未探索前沿；
- 多目标冲突不能被隐藏权重自动解决；
- 不存在支配解时可输出 `NoDominantSolution`；
- 不可接受的规范冲突可输出 `ArchitectureRefused`。

## 跨语言语义保持、全抽象与隐式接口

<a id="1-根裁决-12"></a>

### 1. 根裁决

一个通用工程编译器不能无条件保证任意源语言和目标语言之间“完整语义等价”。原因包括：

- 目标上下文可观察源语言中不存在的行为；
- 内存模型、未定义行为、异常、并发、反射和 FFI 不同；
- 时间、资源、布局、地址、浮点、I/O 和错误语义不同；
- 安全性质取决于攻击者能否链接目标级上下文；
- 外部消费者可能依赖未声明行为；
- 语言中的抽象边界可能在低层被突破。

因此 `semantic-preserving` 必须始终带属性集合和上下文集合。

### 2. PreservationContract

```text
PreservationContract = {
  sourceSemanticsRef,
  targetSemanticsRef,
  sourceProgramClass,
  targetContextClass,
  preservedObservationKinds,
  reflectedObservationKinds,
  undefined/unspecified behavior policy,
  resourceAndTimingPolicy,
  concurrencyAndMemoryModel,
  FFIAndExternalEffects,
  securityAdversaryModel,
  proofOrValidationMethod,
  excludedFrontier
}
```

### 3. 多种保持性质

```text
PreservationKind =
  | FunctionalRefinement
  | TraceInclusion
  | TraceEquivalence
  | SafetyPreservation
  | RobustSafety
  | NoninterferencePreservation
  | ConstantTimeWithinModel
  | ResourceBoundPreservation
  | FailureSemanticsPreservation
  | FullAbstraction
```

Full abstraction 要求源级不可区分恰好对应目标级不可区分，通常比普通语义保持更强，也更依赖上下文和链接模型。它不能作为所有后端的默认合同。

### 4. 目标比源更有观察力

例如：

- 源语言抽象对象在目标中暴露地址或布局；
- 源语言原子操作被 lowering 为多个可观察步骤；
- 源语言无未定义行为，目标语言有；
- 源语言异常统一，目标平台区分信号、进程退出和设备故障；
- 源语言安全模块可被目标级恶意代码链接；
- 源语言大整数被映射为有限整数；
- 浮点重排改变边界结果。

正确方案是能力和上下文约束，而不是声称“IR 已统一所以等价”。

### 5. 隐式接口与 Hyrum 型效应

只要系统有足够多消费者，任何可观察行为都可能被依赖，即使它未写进正式 API：

- 输出顺序；
- 错误文本；
- 时延；
- 资源占用；
- 临时文件；
- 未记录字段；
- 并发时序；
- 容错行为；
- 安全边界外泄。

因此迁移前必须区分：

```text
DeclaredContract
ObservedBehavior
KnownConsumerDependency
UnknownExternalDependency
```

不能用“未文档化”推断“无人依赖”。

### 6. 语言特有语义不能被最低公分母吞掉

公共 IR 只承载真正共享语义。语言特有能力通过 typed extension 保留：

- Rust borrow/lifetime；
- Java class loading/reflection/memory model；
- TypeScript structural typing/runtime erasure；
- C/C++ undefined behavior、layout 和 ABI；
- Go goroutine/channel semantics；
- JavaScript event loop/prototype；
- SQL isolation and null semantics；
- GPU/SIMD memory spaces；
- hardware timing and interrupts。

如果目标后端不能表达某项源语义，输出 `UnsupportedPreservation` 或要求运行时机制，不能静默近似。

### 7. 跨语言 equivalence 的可判定边界

对任意程序的完全等价不可普遍判定。可用方法包括：

- 有界模型检查；
- translation validation；
- proof-carrying lowering；
- property-specific differential testing；
- metamorphic tests；
- reference interpreter；
- runtime assertions；
- abstraction relation；
- manual assumption acceptance。

结果必须保留方法强度。

### 8. 编译器 phase-ordering 与优化

不同 pass 顺序可影响性能、代码形态，甚至在缺陷或未定义行为下影响可观察结果。Pass Manager 必须：

- 声明 pre/postconditions；
- 证明或验证每次 lowering；
- 记录 pass 顺序和 revision；
- 对优化失败回退到正确基线；
- 不能把更快输出当作语义正确证据；
- 对不稳定优化保留独立 differential oracle。

### 9. 架构修订

TargetProgramIR 不再承诺是所有语言行为的终极统一语义。它是：

```text
SharedEngineeringSemantics
+ Domain/Language Semantic Extensions
+ PreservationObligations
+ TargetCapabilityRequirements
+ Explicit UnrepresentableFrontier
```

<a id="10-验收-7"></a>

### 10. 验收

- 每个后端声明 preservation kind 和 context；
- 未定义/未指定行为显式处理；
- FFI、内存模型、浮点和时间进入合同；
- 目标不能表达时拒绝或引入有证据的运行时；
- 跨语言测试不只比较文本输出；
- 外部未声明消费者进入迁移未知前沿；
- full abstraction 不被当作默认宣传语。
