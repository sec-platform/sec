# 文档索引与一致性规则

> 目标：把 `docs/01-10` 从“很多文档”收束成一套有层级、有权威顺序、可维护的规格栈，避免重复、漂移和冲突。

## 1. 文档分层

| 层级 | 文档 | 职责 | 是否权威 |
| --- | --- | --- | --- |
| 索引与治理 | `00-文档索引与一致性规则.md` | 定义文档职责、冲突优先级、维护规则 | 是，负责文档体系治理 |
| 概念总纲 | `01-用户能力模块化开发-主题整理稿.md` | 问题定义、概念边界、长期愿景、相邻物种、采用影响 | 是，但不覆盖实现细节 |

| 路线图 | `03-MVP实施计划与路线图.md` | 当前进度清单、阶段目标、里程碑、优先级、进入/退出条件 | 是，负责阶段推进顺序和进度记录 |

## 2. 冲突优先级

当文档之间出现冲突时，按以下顺序判断：

1. `05-10` 实现级协议优先于 `02-04`。
2. `04` 只约束 AI/Agent 如何执行，不覆盖 `05-10` 的 schema 和协议。
3. `03` 只决定阶段顺序，不覆盖 `05-10` 的字段定义。
4. `02` 负责产品和架构口径，不覆盖实现级字段。
5. `01` 负责概念和长期愿景，不直接作为实现依据。
6. `用户能力模块化开发.md` 只是原始资料，不作为当前规范源。
7. 如果 `00` 的文档治理规则与其他文档冲突，优先更新 `00` 或明确例外，不允许隐式漂移。

## 3. 允许重复的信息

以下信息允许在多个文档出现，但必须保持口径一致：

- 产品不是低代码、模板市场或自由 AI 编码器。
- 权威输入是 plan、manifest、graph、slot、acceptance、policy、provenance。
- AI 只作为受控 pass，不是全仓主控制器。
- `v0.1` 当前母例是 Customer Admin。
- `v0.2+` 可演进 Work Tracking / Ticket SaaS 母例。
- `v0.1` 默认目标栈是 Next.js + TypeScript + React + Tailwind + Prisma + SQLite + Vitest + Playwright。
- Bun 是可选本地执行/测试加速路径，不是 `v0.1` 主规范运行时。

重复时应使用短摘要，并引用权威文档；不要复制大段实现细节。

## 4. 不允许重复维护的信息

以下信息只能以对应文档为准，其他文档不得另起一套定义：

| 信息 | 权威位置 |
| --- | --- |
| `app.plan.yaml` schema | `05` |
| `block.manifest.yaml` schema | `05`、`06` |
| `graph.lock.json` schema | `05` |
| block 分类、命名、版本、信任 | `06` |
| pass 状态、错误码、repair 边界 | `07` |
| verification report、provenance、graph node/edge | `08` |
| task envelope、AI allowed paths、预算 | `09` |
| override manifest、upgrade migration、冲突优先级 | `10` |
| 阶段进入/退出条件 | `03` |
| 产品定位与非目标 | `02` |

## 5. 文档维护规则

- 新增概念：先进入 `01`，再决定是否需要落到 `02-10` 的权威协议中。
- 新增产品决策：写入 `02`，如果影响阶段顺序，同步 `03`。
- 新增实现字段：必须写入对应 `05-10`，不能只写在 `01/02/03`。
- 新增 AI 行为规则：写入 `04` 或 `09`；如果涉及写入边界，以 `09` 为准。
- 新增升级/override 规则：写入 `10`；如果影响 block manifest，也同步 `06`。
- 新增 graph/provenance/verification 对象：写入 `08`；如果影响 CLI 或 lock，也同步 `05`。
- 原始讨论材料不要继续扩写为规范；需要保留时放在 `用户能力模块化开发.md`，整理后再迁移到 `01-10`。

## 6. 当前文档体系判断

`01-10` 的数量不是主要问题；它们对应的是一个工程编译器的不同协议面。真正的风险是：

- 01 和 02 都写愿景，导致定位漂移。
- 02、03、04 都写阶段范围，导致 v0.1/v0.2 边界漂移。
- 05-10 的字段被上层文档重复描述，导致实现时引用错误。
- 原始长文继续作为事实源，导致整理后的规格被旧材料反向污染。

因此当前策略不是合并掉编号文档，而是：保留分层、明确权威、减少跨文档复制。

## 7. 下一步清理建议

1. 在 `01` 顶部补一句：本文件是概念总纲，不覆盖 `05-10` 实现协议。
2. 在 `02` 顶部补一句：产品/架构口径以本文为准，实现字段以 `05-10` 为准。
3. 在 `03` 顶部补一句：路线图只决定阶段顺序，不直接定义 schema。
4. 给 `用户能力模块化开发.md` 文件头加 archive 说明，防止后续 Agent 把它当最高优先级规范。
5. 后续每次改协议字段，都先改 `05-10`，再回填 `02/03/04` 摘要。
