## 2. 冲突优先级

1. `05-11` 实现级协议与操作面协议优先于 `01-04`。
2. `04` 只约束 Agent 执行，不覆盖 `05-11` 的 schema。
3. `03` 只决定阶段顺序，不覆盖实现级字段。
4. `02` 负责产品和架构口径，不覆盖实现级字段。
5. `01` 负责概念和长期愿景，不直接作为实现依据。
6. 如果 `00` 的治理规则与其他文档冲突，优先更新 `00`。

## 3. 允许重复的信息

以下口径允许在多文档出现，但必须保持一致（使用短摘要 + 引用权威文档）：

- 产品不是低代码、模板市场或自由 AI 编码器。
- 权威输入是 `source/app.yaml`、manifest、graph.lock、slot、acceptance、policy、provenance。
- AI 只作为受控 pass，不是全仓主控制器。
- 当前母例：Customer Admin（`v0.2` 可演进 Work Tracking 纵切面）。
- 目标栈：`nextjs-ts-prisma-sqlite`（Next.js + TS + React + Tailwind + Prisma + SQLite + Vitest + Playwright）。
- Bun 是可选本地执行/测试加速路径，不是主规范运行时。
- Workspace 四根布局：`source/`（开发事实源）、`project/`（生成运行目标）、`control/`（项目控制面）、`.pjc/`（可重建本地状态）。
- 当前开发即面向最终形态：任何 v0.x 实现都必须能自然演进到语义合约型 block、Engineering IR、Review Workbench，不允许把临时 hardcode 固化为平台架构。
- 当前开发阶段：`v0.2`（工程可持续化），详见 `03`。

## 5. 文档维护规则

- **新增概念**：先入 `01`，再决定是否落到 `02-10`。
- **新增产品决策**：写入 `02`，若影响阶段顺序，同步 `03`。
- **新增实现字段**：必须写入对应 `05-10`，不能只写在 `01/02/03`。
- **新增 AI 行为规则**：写入 `04` 或 `09`；写入边界以 `09` 为准。
- **新增升级/override 规则**：写入 `10`；影响 block manifest 则同步 `06`。
- **新增验证/图谱对象**：写入 `08`；影响 CLI 或 lock 则同步 `05`。
- **新增 Workbench/可视化能力**：写入 `11`；新增产物路径同步 `08`，新增 CLI 合同同步 `05`。
- **新增语义合约字段**：先写入 `11` 的演进原则，再落到 `05`/`06` 的 schema；不得只以复制文件或业务专用安装器表达长期能力。
- **每次改协议字段**：先改 `05-11`，再回填 `02/03/04` 摘要。
- 原始讨论材料不要继续扩写为规范，保留在 `用户能力模块化开发.md`。

## 6. 当前文档体系判断

策略不是合并编号文档，而是：**保留分层、明确权威、减少跨文档复制**。

真正风险：
- 01 和 02 都写愿景 → 定位漂移
- 02、03、04 都写阶段范围 → v0.1/v0.2 边界漂移
- 05-10 的字段被上层文档重复描述 → 实现引用错误
