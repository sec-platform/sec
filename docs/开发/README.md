# 开发操作与客户端

说明怎样使用能力，而不替代作者成果。开发任务沿开放意图、真实对象和有类型组合进入相交拥有者；六工具协议、已识别能力目录、请求见证、连续编辑、测试输入与AI协作分别承担输入、结果及作用合同，不以固定任务分类限定可表达意图。准确对象与动作已知时直接进入。

[返回上层](../README.md)

## 建议从这里进入

[用途与任务范围](用途与任务范围.md) → [需求到交付主链](需求到交付主链.md) → [六工具与请求](工具协议/六工具与请求.md) → [测试发现与执行](测试发现与执行.md) → [编辑审查与客户端](编辑审查与客户端.md)

已有完整定义与短作者输入怎样进入上述主链，见[第一层编译承接](第一层编译承接.md#first-layer-compiler-delegation)及[继承合同的实际消费者](第一层编译承接.md#inherited-contract-elaboration)。系统取得已有合同、可推导内容与有效委派，只将真正需要有权决定的差异交回；缺解释、实现或目标方法不默认要求应用作者维护内部IR。原六工具、准确候选、确定编译与真实作用仍按各自范围工作。

| [版本控制与集成](版本控制与集成.md) | 从选定内容到准确提交、引用推进、集成和真实查回；不把读取成功当写入授权。 |
