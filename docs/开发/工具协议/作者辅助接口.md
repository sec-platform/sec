## 可选作者辅助：定位、补全与有基础的编辑建议

`sec.authoring-assist/1`是**未发布、需准确协商的能力草案**，复用query/propose，不增加顶层工具、不引入另一份作者语言。它解决已有v2的at/find难以表达的确切光标/选区及联合编辑建议。未支持者继续source/files/edits、现有edit-value/1和语义增量；已有六种propose分支的字段和默认不变。下述新增分支只有相应能力的解码器与实际消费者存在才接收。

### query新增的互斥分支

| 字段 | 合同 |
|---|---|
| `candidateRef` | 必需，固定作者内容快照；本分支不与原at/find/view混用 |
| `assist` | 必需对象：`kind`、`path`、`positionEncoding`，以及`position`或`range`；只有actions可额外给`action` |
| `limit`、`cursor` | 沿原分页范围；limit默认20，1—200；cursor延续同一查询与来源，不能换候选/位置/动作 |

`path`是该候选中真实可读的作者文本资产路径；不把URI、文件系统路径和虚拟源名字相互猜换。`positionEncoding`必需且只取`utf-8/utf-16/utf-32`，单位是行内对应编码单元；position为`{line,character}`，二者均从0开始的非负整数；range为`{start,end}`，闭开且start不在end之后。行按真实LF/CRLF/CR读取，位置不含换行符；拒绝越界、断开的Unicode编码单元及不合法字符位置，最后一个空行起点可表示EOF。无有效解码的二进制/异常文本不发位置建议，仍保全原字节。

kind只有以下七种；未知字段/枚举拒绝，不把它传给插件任意方法：

| kind | 位置要求及结果内容 |
|---|---|
| describe | position或range恰一个；真实符号/选区含义、类型/效果、作者显式值或推导/缺省来源与可读说明 |
| complete | 只position；当前解析上下文中候选名字/片段、所需输入和import及可继续编辑状态；不合格库候选可说明缺项但不伪装已绑定 |
| signature | 只position；确切调用的候选签名、活动参数、返回/效果、已知绑定；重载歧义与未完成表达式分别说明 |
| definition | 只position；真实声明位置，类型/别名可沿已有来源继续；不按同名搜索充当准确解析 |
| references | 只position；静态绑定引用、声明是否包含的明确元数据及真实覆盖；默认不把声明本身计作一次使用 |
| implementations | 只position；当前已知实现/Binding位置与覆盖；开放分派不伪造全量 |
| actions | position或range恰一个；可选action为下表的具体请求，省略时只列当前位置可行的编辑种类与缺参数说明 |

`action`是严格联合：`{kind:"rename",newName}`、`{kind:"extract-function",newName}`、`{kind:"inline"}`、`{kind:"organize-imports"}`、`{kind:"format"}`、`{kind:"move-file",to}`。newName由实际语言词法和作用域核验；to是同一候选根下的合法资产路径，不授权覆盖。extract-function必需range；move-file/organize-imports是整文件目的，position用作该文件的定位而非限制实际影响；format有range时只请求该选区允许的完整容器。方法/格式选择来自固定上下文，未知默认先报告，不能新增未定义options。更广的改签名、跨工程迁移和领域重构继续用准确source/files或原semantic-change，不假称有限actions已覆盖。

结果的必需顶层为实际`candidateRef`、与请求一致的`kind`、`items`、`coverage`和`diagnostics`数组；有后续页时才给原`cursor`。通用拒绝/失败仍走原错误合同，不伪造一个空的正常辅助集合。`coverage`复用原查询覆盖和缺项编码，至少区分已读范围、未完成/无权/不支持和是否耗尽本请求；limit截断后不只返回`complete:true`，权限政策禁止披露的范围只给不泄露存在性的合法说明。

每项必需`label`（普通文本）与`state`（`ready/needs-input/unavailable`），可带`detail`普通文本和可安全披露的`diagnostics`。没有需要展开的内容就不签发裸itemRef；大说明只有原query能够实际读取且寿命明确时才用`detailRef`替代detail，不能两份内容独立改义。不同query kind仅接受以下相应字段；其他字段按本能力拒绝，尤其不能出现任意command/脚本或接收端默执行的元数据。

| kind对应的item | 相应字段与精确含义 |
|---|---|
| describe | `subjectRef?`为实际语义对象；`typeText?`、`effectText?`是仅供理解的显示，不作为可执行类型定义；`locations?`取得的准确源位置。未知类型不填Any，缺字段不表示纯 |
| complete | `planRef?`、`locations?`。ready且要自动接受时必须有planRef；没有完整变化计划只能列为needs-input/不可自动接受，不凭label猜插入文本。简单文本建议可以直接展示detail供作者手写 |
| signature | `parameters`为有序`{label,detail?}`数组；`activeParameter?`为0起有效索引；`returnText?`、`effectText?`及`locations?`。完整签名的label和参数是可见说明，实际调用解析仍由真实语义对象承担；重载各一个item，未确定活动参数不随便取0 |
| definition/references/implementations | ready时`locations`非空；unavailable时省略locations，引用还可带`relation:"declaration"|"use"|"implementation"`；无法定位保留unavailable+诊断，不造0:0。查询引用默认排除声明，对实际开放引用覆盖作准确说明 |
| actions | `actionKind`为本节action联合中的kind；`planRef?`、`locations?`。ready且可自动接受必有planRef；缺newName等必要参数时state=needs-input，并在detail说明下一次应提供的参数，不代填 |

`locations`各项包含真实`sourceRef`、`path`、`positionEncoding`和`range`。sourceRef固定包含该源的候选或实际内容/制品版本；不是未解释的编辑器URI。位置来自别的依赖候选/产物时绑定它，而不是强填请求candidateRef；生成源到作者一对多可以返回多项，近似或不可取得的对应不伪装成精确位置。当前显示编码与位置一起传递，client不得只复制range到另一编码。

ready只意味着该项具备其kind所述内容或可形成作者候选，不代表目标程序已正确或已执行。帮助文档是数据，不执行其中脚本或获取远程图片。字符串、参数数、位置数及detailRef继续受原请求/输出预算约束。

编辑项可附`planRef`与作者差异摘要、必要参数/前提、受影响文件和检查状态；只有已固定完整写集和读依赖的方法才能给planRef。未准备好的建议明确为needs-input/unsupported，不给假句柄。只读辅助允许合格的编译分析/纯格式方法，不加载会执行工程代码的未知插件；需要执行发现或安装时给准确缺项并由其他获准动作先取得结果。

### 嵌入位置仍使用同一七种query kind

本协议不为SQL/RegExp/GraphQL/模板等增加第八种assist kind。服务在处理 `candidateRef + path + position/range` 时，先按当前host语言和已绑定injection规则判断该位置是否存在唯一可用的embedded projection；若存在，原describe/complete/signature/definition/references/implementations/actions由相应Provider回答，再映回host位置。

位置同时落在host语法与embedded hole、存在多条竞争injection rule、或动态运行值才能决定语言时，不按插件优先级猜一种；返回歧义/需要上下文或只提供双方都安全的较弱结果。启发式injection可作为诊断/建议，但不能使rename/format等编辑自动ready。

所有返回range仍使用本请求的host `positionEncoding`。embedded provider内部采用byte/UTF-16/virtual coordinate时，adapter必须经固定mapping转换；落在synthetic prefix/suffix或无法反映射的virtual范围返回不可写。嵌入edit最终仍作为本协议既有 `actions` item中的完整host edit plan，或者交回普通source/files/semantic-change，不新增 `applyEmbedded` 或任意provider command。

### propose接受一个已准备编辑项

同能力新增draft变体`{kind:"author-edit",base,planRef}`，外层只能再带原`return`，默认summary；其他字段及未知kind拒绝。base必须与计划原作者基础完全相同。需要在新头上使用则重新取得或按原有重基规则形成新计划，不能把base字符串换成新值。planRef只是现有EditPlan的有界定位句柄，不是持久操作、许可或另一个业务对象；无需强制所有文本编辑先制计划。

内部记录固定原候选、源语言/解释/角色、定位、真实读依赖、完整作者变化组、实际方法版本、语义保持/行为变化的范围与证据、预算和保留责任。主插入、import与必要资源放在同一组；read集不能被客户端缩小。读取并固定计划和源内容遵守原editRef的同一准入占用机制，当前权限在使用和披露时复核；工作中到期不回收活动输入，完成后正常释放。

处理过程为：核协商与输入联合；解析并固定计划/基础；核当前访问与方法实际前提；在私有候选物化完整变化；重解析、重绑定和相交检查；返回普通candidateRef、实际diff及诊断。未知、过期、交叉基础或保持前提失败不改原源；方法确实给出普通编辑而新源类型不合法时可以保存为带诊断草稿，但不能标成已完成保持式重构。它不自动提升工作区头、写磁盘或执行原生command。

在同一计划仍存在时允许纯结果memo；没有承诺跨进程永久同候选身份。需要提交级重放时用已有完整semantic-change身份和实际保存/执行合同。已知精确文本无需经过此分支；一个只会简单源码编辑的客户端仍可完成所有其已知语义的作者变化，不能因为没有authoring-assist便禁止开发。

```json
{"candidateRef":"C1","assist":{"kind":"complete","path":"src/main.sec","positionEncoding":"utf-16","position":{"line":4,"character":8}}}
```

只有当前位置确实存在且服务返回planRef=P1，下面才是合法后继；占位引用和坐标不是可直接执行的实数据：

```json
{"draft":{"kind":"author-edit","base":"C1","planRef":"P1"},"return":"diff"}
```

服务不支持该能力时可通过原source/files/edits明确完成等义修改；没有现成语义保持依据就准确称“源码变更候选”，而不是伪装成经过验证的重构。能力局限和作者语言的表达能力是两回事。
