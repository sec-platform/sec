## 有限交互调试：sec.debug-session/1

### 当前决定与能力边界

全工程开发不仅要“能运行”，还要在失败位置停下、读取准确调用栈和允许的值、继续或单步，然后修改真正作者源。当前选择复用成熟调试适配，通过原`sec.operation`和`sec.query`提供这一机器开发面；不建设新的图形界面，不把原生调试协议直接作为无限权限隧道。

`sec.debug-session/1`是本设计中新增的、需精确内容绑定及能力协商的**可选协议草案**，不是已发布或已实现能力。它包含启动、附加、源码断点、暂停、有限读取、继续、单步和结束。任意表达式求值、getter调用、变量/内存修改、条件表达式/日志点、时间倒流和热替换不属于该有限合同。它们有不同执行/安全/恢复责任，不能藏在字符串参数里；需要时另设计并协商相交能力。普通纯函数生成不依赖调试提供者。

### 启动和发现的精确字段

下表列每个新分支允许的全部顶层字段；表内未列字段拒绝。字符串引用必须由实际内容/宿主提供，名字不是授权。可选`return`为`summary`或`state`，默认summary。

| 分支 | 必需字段 | 可选字段；确切用途 |
|---|---|---|
| 启动目标 | `action:"start"`、`kind:"debug-launch"`、`artifactRef`、`entryRef`、`argumentsRef`、`requestId` | `debugProfileRef`、`breakpoints`默认空数组、`return`。只启动该已准备可运行制品及入口，缺构建结果不暗中编译另一个候选 |
| 附加现有目标 | `action:"start"`、`kind:"debug-attach"`、`runtimeTargetRef`、`requestId` | `debugProfileRef`、`breakpoints`默认空数组、`return`。目标由实际宿主身份和当前许可固定，不用可复用PID或任意TCP地址定位 |
| 发现可附加目标 | `sec.query`原`find`中新增已协商联合`{kind:"debug-targets",scopeRef}`；`view:"state"` | 仅原limit/cursor；返回获准范围内的runtimeTargetRef、可披露标签、实际能力与覆盖，不枚举无权进程 |

运行入口与输入沿compute-run的精确合同；目标运行中读取/写入、设备、网络等仍需其原权限。


`debugProfileRef`固定实际适配方法、协议内容、准备/控制能力和启动参数解释。省略只可采用该制品/目标与本次Runtime已经明确绑定且唯一的调试画像；没有或存在竞争选择时返回准确待选择/不支持，不按安装扩展顺序选择，更不安装最新调试器。画像和目标能力共同决定可用行为，不因客户端选择强画像而产生宿主能力。它不替代原运行画像、argumentsRef或当前授权。`runtimeTargetRef`由真实宿主发现或已有RunRecord的state视图取得，绑定宿主/进程出生身份、实际可验证的可执行内容与适配端点、当前观测范围。附加前重新核身份，PID被复用或可执行内容改变则不沿旧引用附加。可执行内容确实无法取得时只提供已接受的原生有限定位，不声明与某份SEC制品同源。

每项`breakpoints`为`{sourceRef, byteOffset, required?}`：sourceRef为制品相交的固定源内容及其来源引用；byteOffset是该源UTF-8中的非负安全整数，必须在内容范围并位于合法标量边界；required默认false。UI可以把行列换算为此位置，AI可以从实际源/位置引用取得，不填写目标调试器内部句柄。其他编码先通过准确源坐标表换算，不按字节数或可见字符数猜列。

一个请求位置表示在该源位置对应的可执行出现处设置断点；映射一对多时，返回全部实际对应及所采用范围，不默挑其中一个。相同sourceRef/offset重复项合并为同一请求，required取逻辑或。相邻位置不因此合并。每项结果为`verified`、`unverified`、`relocated`、`unmapped`或`unsupported`，保留准确目标位置和原因；verified仅表示实际适配器已确认该断点位置，不证明一定会执行到那里。

required=true要求在本合同承诺的目标执行边界之前已满足准确断点配置。仅有延迟验证或可能执行用户代码后才完成配置的适配器不能满足这一要求；启动前能确定不支持就拒绝，准备过程中才发现则保持可控制暂停/结束并报告未完成，不能自动继续越过该边界。required=false允许会话启动后断点仍未验证，但必须可见，不能显示为已经安装。移动位置要明确呈现；本合同不自动接受“最近可停行”替代精确必需位置。

### 会话、暂停和读取的对象

启动接受后返回真实operationRef以及当前会话状态引用；逻辑会话已分配不表示目标进程已启动。


接受返回的固定主体是`operationRef`、`sessionRef`和`stateRef`；`return:state`另带与stateRef一致的状态投影，summary只带相同事实的摘要。已在接受前拒绝时不伪造operationRef；接收后才失败必须留下原操作和已知副作用。控制返回同一operationRef、该requestId的接收/发送/确认/未决状态及实际stateRef；“命令已确认”和“目标现已暂停/结束”不是同一字段。断点配置返回期望configurationRef及逐源实际结果，所选返回简短时仍须显露未安装、偏移或未决。

stateRef、PauseRef与configurationRef都包含会话出生身份及其相应变化代，不是仅按可见字段内容去重。running→paused→running的两个running不是同一可控制状态；相同断点内容重新配置也不能复活已经失效的配置前提。公开调用只消费实际返回引用，不要求作者手算这些代。后续通过原query的state/contract查询，不让客户端重新拼调试器对象。

| 引用对象 | `view:"state"`的内容 | 有效期与限制 |
|---|---|---|
| `DebugSessionRef` | operationRef、launch/attach来源、当前phase、stateRef、configurationRef、实际线程/暂停引用和已知结束/未决原因 | 一次调试会话；不随PID复用，结束后只有实际保留的历史 |
| `PauseRef` | 暂停代、原因、实际stopScope、线程与调用栈条目/FrameRef、覆盖 | 当前被核实的暂停；继续/单步或实际恢复后失效 |
| `FrameRef` | 该暂停下的帧、源/目标位置、允许披露的参数/局部变量描述及ValueRef | 不跨暂停复用，即使底层帧数字相同 |
| `ValueRef` | 实际已读取的有限值/子项、类型或opaque表示、截断与不可用原因 | 在允许的暂停中继续展开；已复制成不可变内容的快照可按独立引用保留 |
| `runtimeTargetRef` | 受限目标身份、当前观测和可附加能力 | 只是目标定位；附加前重新核当前许可和出生身份 |

上述对象的contract视图给出当前适配能力、字段与作用限制；不支持的source/impact等投影返回原不支持诊断，不凭空制造值。query默认contract保持；需要栈和值时显式state。分页使用原limit/cursor，游标还绑定暂停代；继续执行后旧游标不能读到下一次暂停的同号变量。

返回的值区分：按该暂停实际读取、并发对象的有限观察、明确捕获的不可变快照、被优化/不可读取、预算截断。一个线程暂停不证明整个共享堆冻结；stopScope可以是all-threads、thread或unknown，并说明这是适配器实际报告/保证的哪一层事实。没有可信快照能力时，不把异步多次读取拼成同一时刻的整对象。

读取默认不得执行目标用户代码。缺少这种能力时，相关变量显示不可安全展开；不能为了显示一个属性执行getter、代理陷阱、toString或表达式求值。纯粹调用调试器variables API本身不证明该保证，适配者要提供真实读取方法和边界。

### 控制联合与前提

控制请求为`sec.operation({operationRef, action:"debug", command, ...})`，仅协商本扩展才接受。每个分支都必需requestId；可选return同启动合同。下面列分支其余允许字段：

| command | 必需字段 | 行为 |
|---|---|---|
| `pause` | `expectedStateRef` | 对当前运行目标请求暂停；返回已请求不等于已经暂停。目标已结束或代不符时不发旧命令 |
| `continue` | `expectedPauseRef`、`threadRef` | 继续该次暂停中的准确线程/目标；可选runScope见下，不把旧暂停命令作用于新断点 |
| `next` / `step-in` / `step-out` | `expectedPauseRef`、`threadRef` | 针对该暂停中的实际线程单步；可选runScope见下，准确返回控制范围 |
| `set-breakpoints` | `expectedConfigurationRef`、`breakpoints`；含required=true时还必需`expectedPauseRef` | 用本次完整期望集合替换该会话断点配置；不是只增一个断点，也不清除别的会话 |
| `detach` | `expectedStateRef` | 解除调试连接，目标继续/停止的实际结果由适配合同和本次许可确定；launch目标仍有原运行归属 |
| `terminate` | `expectedStateRef` | 请求终止目标及本次拥有的相交资源；附加目标需要额外终止许可，附加权不蕴含杀进程权 |


continue与三种单步可以带`runScope:"target"|"thread"`，默认target：target明确允许驱动按其目标继续语义运行其他线程；thread要求只恢复所选线程，实际适配不支持则拒绝，不默默扩大到整个目标。threadRef必须属于本次有效暂停且未被复用；runScope不改变线程/共享堆的实际可观察性，也不授予额外执行权。其他控制分支不接收runScope。

动态set-breakpoints包含必需断点时，expectedPauseRef还必须指本会话已核实、可控制的全目标停止边界；否则本有限协议拒绝强配置，不能在正在运行的目标上补一句“之前都安全”。attach中的必需断点也是在附加后实际取得的停止边界至下一次允许目标执行之间保证，绝不保证附加前历史未运行。配置每组结果保留；任何必需位置尚未准确verified时，continue/step均不发送。普通非必需配置可以按适配能力在运行中更新并明确未验证范围。

每个会话至多有一个未结算的状态/配置改变命令。接受时在本会话串行状态下登记`pendingControl`、原requestId与所需代；其他独立改变命令返回`DEBUG_COMMAND_PENDING`及可披露的当前状态，不把两条对p1的next先后发出去。status与合法历史读取仍可进行。取消/结束可以记录意图并撤去尚未发送的命令，已经发送的则按真实适配可承担的停止方式结算，不能伪造撤销。

开始接受continue/step会立即关闭旧PauseRef的活读取/控制资格，而不是等待响应才使其失效；这不宣称目标已经物理恢复。需要发送前再核本会话状态、必需断点配置和实际控制能力；事件已改变基础时不发旧命令。确定未发送或未改变目标且取得真实暂停确认后，可签发新暂停引用，不复活旧引用。驱动I/O在全局锁外进行，pendingControl保留到明确结算或未决，不因调用栈返回而清空。

标准`status/cancel`仍沿原operation工作。调试目标不使用没有expectedPauseRef的基础resume隐式继续；对debug operation该请求返回准确缺少前提。rollback不解释为倒放程序、撤销已执行文件写入或发送。`cancel`对launch按原运行取消/结算处理，对attach默认解除本次附加而不杀外部目标；要求不同策略须在已有任务/宿主合同中明确接受。

同一会话的控制由一个有权协调者串行接受，先核前提并登记精确意图再发送适配命令。底层完成、断点事件和目标终止可能异步到达，响应与当前phase分别保存。一个命令已经送出但响应丢失，不再次执行next来“查询是否成功”；按原requestId返回已知状态或未决。新暂停代立即使旧FrameRef/ValueRef和继续前提失效。

本服务的串行队列不是目标平台上的万能CAS。存在外部控制者、自发恢复或不能确认控制事件顺序时，必须说明较弱观察并拒绝依赖强暂停前提的命令，或者使用具有真实代校验/独占控制的适配；不能仅比较本地变量就签发远端原子保证。

### 状态、配置与错误的准确返回

会话phase为`preparing / configuring / running / paused / ending / ended / unsettled`。paused还带真实线程范围；unsettled保留最后可信状态、可能已发命令和需要查回的对象，不伪装成稳定暂停。ended只表示本次调试会话结束，目标是否退出及退出码另有实际字段。phase变化产生新的stateRef；断点期望集合变化产生新的configurationRef，二者不互相替代。

断点按source分组交适配器的全量替换接口；删除最后一个断点仍发送空集合，不能因为空数组跳过而留下旧断点。每组实际结果单独记录；某组失败不得把整份配置标为已安装。只有实际实现支持幂等全量配置时，失联后才可在适当控制边界重新建立同一配置；没有可靠枚举/重建能力就保留未决。

错误沿原ErrorEnvelope表达。当前扩展新增原因：`DEBUG_UNSUPPORTED`、`DEBUG_TARGET_STALE`、`DEBUG_PAUSE_STALE`、`DEBUG_CONFIGURATION_STALE`、`DEBUG_BREAKPOINT_UNRESOLVED`、`DEBUG_VALUE_UNAVAILABLE`、`DEBUG_COMMAND_PENDING`、`DEBUG_COMMAND_UNSETTLED`；分别指能力、附加目标、暂停代、配置代、位置、读取能力/优化/预算、已有未结算控制和命令完成性。诊断参数包含实际主体、已知作用和合法下一步，不把任何新原因默认设为可重试。

### 从暂停回到真实源码修改

设A0是已生成并准备运行的精确制品，启动后得到op0和暂停p0。`query(at=p0,view=state)`取得当前栈，继续查询某帧只取实际需要的局部值。定位到原生作者则直接改原生文件并捕获C1；定位到中立作者则修改该作者；定位到合成辅助但无法唯一映射时呈现来源与规则，不把某行目标代码随便写回一个源。

C1生成A1不修改op0正在运行的A0。旧调试窗口继续明确标A0，新的调试请求使用A1和新requestId；本有限协议不热替换现有进程。这样第二次修改能够真实进入新运行，而不会用新源行号解释旧栈。受管生成物编辑仍走原generated-edit，源码映射不能代签编辑逆向。
