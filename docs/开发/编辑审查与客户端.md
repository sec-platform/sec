## 当前范围

首期开发客户端以AI/脚本为主，本章不要求实现专用图编辑器、属性面板、LSP服务器、拖线或人类交互产品。直接使用现有编辑器、文件或补丁工具是合法入口；这与新建一套人类IDE不同。其内容层、版本及联合捕获沿[文本工作集](原生维护/导入观察与原生资产.md#text-workspace-capture)进入共同候选，语义、权限和真实结果不因客户端形式改变。

当前查询、成组修改、诊断、编译与恢复由[共同操作接口](工具协议/六工具与请求.md)和[AI开发协议](AI协作/需求与作者上下文.md)拥有。人类读取报告或检查生成代码，不构成开发一套专用交互产品的需求。

## 后续客户端只适配不重定义

未来明确需要人类或其他客户端时，复用作者源、基础修订、语义增量与实际效果合同。客户端可以组织自己的光标、选区、展示和撤销组，但不增加独立业务规则、生成器或权限根。局部显示状态不是业务含义；目标软件本身的布局、顺序或导航可能是业务，仍由对应领域拥有。

不得把编辑器缓冲版本当工程版本，不得把显示的“通过”当真实证据。编辑往返与坐标、注释、未完成草稿和多对一映射由[唯一往返合同](../编译/表示/编辑与受管回源.md#编辑往返的具体合同)承担，不在此重复。

## 采用条件与退出

只有出现实际人类开发消费者、共同接口无法满足任务且独立交互收益可检验时，才选择现有编辑器的薄适配或其他界面。采用时补齐该客户端真实需要的可用性、无障碍与安全条件；不能以“未来可能有人”预先实现全部控件。

即使未来开发人类入口，也不要求两类客户端有完全相同的调用次数、显示格式和本地状态。共同的是被解释的变化及其前提；权限按实际主体，不按“人”或“AI”类别自动相等。

## 完整开发面：工作对象、动作和结果，不是一套新界面

本节把前述客户端边界落实为可操作的设计。开发面包括人、AI、脚本和已有编辑器实际输入、查看、修改、调用与继续工作的全部接合；不等于图形界面，也不等于六个工具名。当前以原生文件工具/补丁、SDK/CLI宿主和原六工具承载。编辑器面板、网页、终端布局可独立采用；不因本节设计完整而要求先实现新GUI。

一项开发任务通常只需说明**要改变的行为或资产、已有工程或局部源，以及无法推导的取舍**。准确版本、CST/IR、检查依赖、编辑引用、制品成员和运行身份由系统取得和维护；开发者不手填这些内部台账。已经知道对象和动作就直达，不要求先浏览能力全集、创建会话表或取得批准卡。

### 作者真正维护的四类内容

| 对象 | 正常开发方式 | 系统提供而非作者重复维护的内容 |
|---|---|---|
| 新的中立行为或抽象 | 简洁.sec、已有定义/库的引用、必要参数和独特算法；支持未写完草稿 | 从真实定义推导类型/效果、局部身份、依赖与生成对应；不展开回写成另一份作者程序 |
| 已有原生源 | 继续在TS等实际原文中编辑，保留注释、BOM、行尾、路径与原工具 | 可取得范围的符号、类型、调用与原生工具诊断；不强制生成.sec镜像 |
| 工程控制与非代码资产 | 原项目配置、依赖声明/锁、入口、资源、测试和独立说明；没有该信息则不建空文件 | 仅建立缺少且有消费者的稀疏控制；同一规则不在package、工程表和意图JSON中三写 |
| 生成/运行观察 | 默认看目标源、差异、栈和值；要改则定位真实作者，或保全受管目标编辑草稿 | 固定生成与运行来源；一对多和不可逆明确呈现。运行值、生成helper和推导签名不伪装成任意可写作者槽 |

`.sec`并不是所有控制的同义配置语言。导入/模块、一般函数/类型、对象/状态/关系/流/数值的实际语法由各语言和领域拥有者定义；表格只规定它们如何进入共同开发过程。成熟供给够用时直接绑定；确有独特含义才定义新函数、类型或库；没有可验证供给不能仅写一个功能名冒充完整实现。

### 操作目录按任务展开，不按所有协议字段展开

下面各行都是应有的开发动作族。一个能力当前不可用时，仍能在明确请求时取得准确原因及合法替代；不显示虚假的可执行按钮，也不隐藏任务本身的缺口。没有请求相交能力就不把全目录塞进每次AI上下文。

| 动作族 | 作者最小输入 | 正常结果及真实通路 | 独立的不足/退出 |
|---|---|---|---|
| 临时试写/空工程/已有工程打开 | 一段源或真实路径；新工程必要目标 | 内存候选或获准工作区捕获；原context和projectView形成 | 未装编译后端不妨碍保全和源级检查；打开不执行项目脚本 |
| 克隆/多根/远程/恢复工作区 | 明确来源及范围，恢复时准确保存点 | 实际宿主连接/克隆后捕获；多根保持独立归属和解析域 | 下载、凭据、子模块/大文件取得是单独作用；不能读到的范围显露 |
| 定位/解释/搜索 | 名字、位置或问题；已知引用直读 | query的source/contract/origin/impact及原生语义查询 | 引用搜索与文本搜索分开；动态调用未知不叫零引用 |
| 创建一般程序/复用供给 | 完整源、局部表达式、真实调用/参数 | 直接编辑或propose形成同一候选；库查找按本次需要 | 类型未知只问最小注解；意图歧义不替用户改变要求 |
| 补全/参数提示/查看推导 | 当前内容与合法位置，已有签名/预期 | 有来源的候选项或说明；选定后变成普通编辑批次 | 不将模型生成的猜测显示为已存在符号；不执行用户函数探测类型 |
| 修改字段/组合/对象/状态/关系等 | 真实源差异或已有editRef与值 | 现有类型化作者/结构语义，统一候选 | 原本不支持的复杂语义保留原生/草稿及具体缺项，不伪造通用控件 |
| 移文件/更名/签名变更/抽取/内联 | 准确声明或范围及新要求 | 同一语义批次含引用、出口、资源与配置消费者 | 动态引用、外部公共API和资源捕获按真实保持范围处理 |
| 格式化/整理导入/批量修复 | 明确范围和合格方法 | 工具结果先成为源候选，显示副作用与完整差异 | 不以“格式化”重排有初始化效果的导入或清掉非法草稿 |
| 配置/环境变量/资源/秘密 | 改真实配置或安全输入引用 | 格式拥有者校验，输入与目标/运行绑定 | 秘密不写进日志/普通文本补全；检查存在不泄露内容 |
| 依赖添加/升级/移除/物化 | 所需能力/版本政策/明确变更 | 依赖计划、候选锁与消费者；物化另有获准实际操作 | 解析与安装分开；没有网络时只需网络的动作受阻 |
| 浏览诊断/定位修复 | 问题引用或选定范围 | 分生产者/主体/覆盖的诊断与可行修复 | 旧诊断、工具失败、未覆盖与当前错误分开 |
| 差异/部分选择/比较方案 | 候选、基础及保留哪些语义组 | 原preview或源差异、共同前提与冲突 | 半个不变量不能勾选通过；方案较优不等于已采用 |
| 源检查/案例/性质/覆盖/基准 | 明确方法与准确主体、范围 | check types/cases及已选原生测试/性能工具 | 测试发现可能执行代码；无案例/跳过/工具崩溃不叫全部通过 |
| 生成/构建/导出 | 已定候选和一个或多个输出根 | preview生成；compute-build实际构建；apply按需写出 | 各根单独结算，未选根不清理；生成不自动执行 |
| 运行函数/CLI/服务 | 真实入口及参数、环境选择 | 绑定参数并compute-run/eval；已有宿主提供活动会话 | 参数错误先定位输入；缺环境不改源；stdin/服务就绪不是退出码 |
| 调试/性能定位 | 准确运行、断点/观察用途 | 既有有限debug、profile与来源映射 | 无安全读取显示不可用；旧运行不映射为最新源；求值不偷进只读 |
| 监听/再次构建/连续测试 | 范围和自动动作策略 | 捕获最新有效输入，派发受限同类任务 | 默认不自动发布/提交/安装；旧任务完成只留原归属 |
| 保存/撤销/舍弃/清理 | 要处理的层和准确选择 | 源保存、草稿历史、生成协调、原操作查回 | 丢草稿、编辑器undo、Git revert与外部补偿不是一个撤销 |
| 提交/分支/评审/合并/同步 | 内容选择、目标ref与真正集成策略 | 原生VCS适配固定树/索引/历史/策略后操作 | 不擅自stage全部、stash、reset、force-push；远端成功与本地跟进分开 |
| 打包/发行/部署/迁移 | 发行选择及授权目标 | 已有产物、信息发布及真实Provider流程 | 不把save-source命名成publish；用户验收与技术检查分开 |
| AI委派/审查/交接/退出 | 目标、已取得源、必要范围/预算 | 同一候选分支和只读审查；精确引用交接 | 子任务结论不是根授权；关闭客户端不杀其他人使用的工作 |

### 一个统一的结果，不是一个万能success

内部`DeveloperView`是已有候选/产物/检查/操作的按需投影，不是新的持久权威。它由下列信息组成：本次请求与准确基础；已取得的source/contract/diagnostics/impact/origin/state；各受请求步骤的实际结果；仍需的最小决定或能力；当前合法下一动作。只有受请求且影响判断的未完成步骤才出现，不能在每次小编辑后刷几十项not-requested。

`NextAction`在内部含purpose、作用对象及基础、实际方法/消费者、必须输入的局部模式、效果范围、当前资格/阻塞理由和精确调用路径。客户端通常只显示自然语言动作、关键差异和缺项；完整结构按需取得。它不是可执行网页命令、授权票据或永不过期的能力。已知基础和动作可以直接构造原请求，不必先创建这个对象。

资格分成可准备、缺输入、方法不支持、当前禁止、基础过期、已有动作未决；不能把它们都翻译成“请重试”。权限类理由按当前可披露范围返回，不能通过被禁动作菜单泄露他人资源。行动前重新核实际前提。菜单上的建议或诊断的preferred标记不是必须采纳；涉及改变要求/期望或扩大作用，必须在任务现有授权内有明确选择，不因为发起者是AI而加确认，也不因为是人而免检。

### 读取、编辑和宿主动作的实际分工

source/contract/diagnostics/impact/origin/state仍是原query投影；补全和重构的语义提供者可通过现有编辑器/SDK请求位置和意图，再归一成原source/files/edits/edit-value/semantic-change。**本章没有添加`view:actions`、`propose(actionRef)`或`apply(mode:commit)`等未声明请求。** 远端只提供原六工具时，已可通过查询和真实源/批次完成同义开发；专用补全服务不可用时不假称有原生IDE能力。

克隆、依赖安装、Git集成和发行由真实宿主/原生工具或已注册Provider承担，使用下面的有限内部计划，不默认成为第七个公共工具，也不把任意shell字符串藏进compute-run。宿主尚无通路时返回所需能力和可执行原生路径设计，而非假造一个已有API。实现某远端客户端需要这些通路时，显式注册合格适配和精确协议后再公布；六个名字相同不证明所有客户端已支持全部能力。

### 同一开发过程在不同客户端中的表现

AI与脚本按真实源片段、必要诊断和最小差异操作；人可用现有编辑器文本、命令和终端。两者共享含义与前提，但输入节奏、展示、快捷键、访问权限和审批职责不必相同。面板若被采用，键盘可达、屏幕阅读语义、焦点恢复、非颜色状态和大内容渐进展开是该面板验收，不强制无GUI服务先做页面。命令行的机器结果与人类进度分别走实际输出通道；日志中的ANSI/终端控制和工具文本不作为可执行指令。

正常最短路径仍是“写源→看结果”，或“直接改已有文件→捕获→所需检查”；必须保持一个闭合小函数无需先启动服务器、调试器、数据库、Git仓库和完整工作台。大型工程增加的是准确范围、消费者和恢复责任，不把每个开发者变成内部状态管理员。

## 不同工程的开发面接合，不能全部压成CLI运行

以下是当前应显式保留的工程入口差异，按组合需要启用；不是封闭工程分类，也不声明相关产品适配已实现。通用的源/配置/测试/运行/恢复通路相同，实际对象与效果不能合并。

| 工程形态 | 作者直接处理的东西与正常开发动作 | 必须另核的目标事实 |
|---|---|---|
| 库、SDK、小工具和命令行 | 公共入口、类型/错误、兼容调用、参数/流输入、打包和使用说明 | 库被消费者真实链接与CLI可启动不同；标准输入、退出、编码和依赖交付各有结果 |
| Web/前端/样式/媒体 | 组件/路由/模板/样式/资源同候选，生成bundle，启动开发服务器，在准确页面状态检查功能/布局/无障碍 | 服务器就绪不等于浏览器已加载新bundle；缓存、service worker、source map、热替换状态分别绑定。截图只是视觉证据，不能代替行为和键盘/屏幕阅读验证 |
| 后端、服务、任务与消息 | API/模式/配置、局部数据fixture、请求/事件、日志和追踪；在选定环境测试与调试 | 本地启动与真实数据库/消息/认证可用分开；不能用生产凭据跑测试，超时请求恢复遵守真实效果合同 |
| 移动/桌面与插件宿主 | 代码/界面资源、打包签名、模拟器/设备/宿主实例、调试附加与更新 | 应用标识、签名、安装对象、进程出生和真实已装制品；重新安装可能清数据，插件加载/配置读取可能执行代码 |
| 数据、数据库与迁移 | 模式/查询/索引、迁移脚本与数据样本、回填/校验/兼容窗口 | 源回退不等于数据回退；数据量、外部观察、读写竞争、保留和恢复按原事务/数据合同，不由文本diff保证 |
| 计算、GPU、ML与仿真 | 算法、数据/模型/参数、内存设备预算、训练/推理/评估与性能 | 代码、数据、权重、随机性及设备对应；采样数据/观察有权限，运行完成不等于精度/误差或可重现实验合格 |
| 编译器、生成器、构建与开发工具自身 | 工具源码与工具输入分开，固定引导种子/规则，生成/编译/比较和自用 | 新检查器不独自为自己签证；工具元程序执行是构建效果，不能变成query；宿主与目标工具不混同 |
| 嵌入式、设备和实时工程 | 硬件配置、镜像、接口与时序约束、设备部署/调试/恢复 | 实际设备身份、权限、刷写/断电风险、固件和物理状态；模拟通过不代表真设备保证 |
| 文档、规范、数据表和其他非源码 | 按真实格式编辑、关系/链接/引用重构、检查并按需生成派生物 | 格式通过不证明语义正确；图/HTML/译文不成第二真源，秘密/许可/大对象有独立存储及退出责任 |

每种画像最少需要准确作者范围、目标入口/参数、运行/测试/观察能力、结果对应和退出方式；复用这些角色，不为每个业务名称建新顶层模块或工具。需要的新目标字段由所属领域版本化解释，无法表达的语义不能用开放字典默默接收。界面可以有真实浏览器/设备预览，也可以先只用文件与脚本；未选可视客户端不意味着不设计目标软件的交互和资源行为。


## 动作的完整性不能替代作者成果

本章的动作族描述如何操作，最终维护的作者结构由[作者源码结构与需求抽象](../领域/计算基础/作者表示与实现分工.md)拥有。只列21个动作或成功调用六工具，并不证明需求已经能在源中准确表达。设计验收需分别核：源码结构是否足够、真实行为是否有主体、目标/宿主缺项是否准确、第二次修改是否仍只维护其真源。本章已有编辑/诊断/运行交互继续有效，不因新增成果层被删除。

<a id="developer-entry-contract"></a>
## 当前可实施的文本、CLI、SDK和代理入口

以下是已有源和六工具的**开发客户端设计**，不要求创建专用IDE。面向人的文本与面向AI/脚本的数据可以不同；运行身份、候选含义、读取权限与效果不得改变。文件已经由编辑器保存时，直接捕获得到候选；不先复制到聊天再propose，也不重复save-source。

### CLI的单请求合同

CLI绑定发行提供的真实Runtime配置；拟定命令形状为`sec <query|propose|preview|check|apply|operation> --request <文件路径|-> --format <json|text>`，`--request`必需，`--format`默认json，`--help/--version`可独立使用。示例是设计语法，不声称当前产品已可安装。子命令只把请求交给同一解码器；不新增save/deploy等模糊合并命令。

request文件路径仅定位载荷，`-`读取标准输入；载荷是恰一个有界UTF-8 JSON对象，重复键、尾随第二对象和超限先拒绝。载荷内路径按它已绑定的项目/对象解释，不随request文件所在目录改变，不对字符串做shell展开。语言、目标与base继续遵守原工具字段；stdin的普通文本不因扩展名猜成TS。示例：

```sh
sec preview --request preview.json --format json
```

preview.json是使用原source分支或实际candidateRef的请求，不携带本段未定义字段。stdout在JSON模式只包含一个最终结构化结果及换行；日志、进度和交互提示不得混入，stderr输出有界且净化的诊断。流式进度需要明确的传输分帧能力，不把多条JSON偷偷写成单响应。终端渲染必须转义控制序列，颜色不携带独占含义。无交互环境缺少决定时返回缺项，不无限等待键盘、不默选有风险答案。

退出码定义为：0表示本请求在其范围内得到正常结果（允许propose产生带诊断草稿，query正常返回空/部分集合）；1表示得到可靠领域结果但本次明确的完成目标未达到，如check失败，或本次要求确认完成而apply仍未结算；2表示命令/载荷/协议非法且未派发作用；3表示没有取得可靠最终结果，如传输中断或客户端内部故障。partial query仍必须在数据中保留覆盖，0不等于全工程通过。这里的“最终结果”是本次工具请求的最终响应，不等于后台作用已经终结。只请求启动时，返回已受理和真实可查回operationRef可以满足本请求而退出0，正文仍标运行中；明确等待完成却只取得可靠未完成状态时才按该目的返回1。未知物理效果的状态本身可以是可靠响应，不能一概与客户端未收到响应的3混同。收到中断后若能取得最终领域状态就用该状态；进程被强杀或写stdout失败不能伪造未执行。存在作用时先保留事前requestId和目标范围用于查询，不以重跑命令验证是否已执行。

### 从纯函数开始，不必经过辅助查询

在真实发行支持基础语言且本任务只创建源的条件下，完整请求文件可以只有：

```json
{"source":"export fn double(x: Int) = x + x;"}
```

把它交给`sec propose --request create.json`得到可继续候选，不必先创建项目、补全会话、EditPlan或运行测试。要在一个进程内直接生成代码，可将同一个source请求交给`sec preview --request create.json`，但前提是该运行环境确实固定了默认目标；否则返回target-required，不能因为本设计优先TS就悄悄选择目标。

已得到真实绑定的目标键时，可以明确请求：

```json
{"source":"export fn double(x: Int) = x + x;","target":"<实际已绑定目标键>","return":"code"}
```

尖括号是替换说明，不是可用目标。已有源码文件由调用方实际读出或宿主成组捕获，不凭文件名产生伪candidateRef。创建错误草稿与生成失败是不同结果；主动生成会做所需的检查，不反向把推导注解或完整IR写进短源。这条无辅助路线与大型项目完整工作集共用同一语义，不为片段设计一个不同解释器。

### 一个进程的引用不能假装跨进程永久有效

同进程纯片段模式无需守护服务或数据库，返回小源/代码及明确的临时引用寿命；关闭后这些引用不可供下一次独立命令使用。CLI可以连接已经配置且获准的Runtime，会话/连接标识由受信配置和握手取得，不自动搜索“最近那个服务”。另一种小实现是一次进程内完成已明确请求的依赖动作后内联结果；不把六步流程强制分成六个进程。

跨命令继续的源可以保存在真实作者文件后重新捕获；要求稳定引用或真实操作恢复时，必须由该Runtime实际提供相应保留和查回能力。服务端返回一个字符串不是持久化的证明。申请保留失败或旧引用失效时返回准确缺项，可重新读取原源形成新候选但不得伪造旧身份。大结果不能因本地进程即将退出而只留下即刻失效的下载引用；要么仍有实际服务保留，要么在允许范围内交付内容/明确导出位置，否则该交付目的未完成。

### SDK与代理协议

这里的SDK是调用六工具的普通程序接口，不是已排除的“逐运算搭建作者AST的嵌套构造SDK”。SDK消费原`RuntimeHandle.handle/close`及受信HostPorts。库用户在一个Runtime内调用六工具，不必JSON序列化纯内存值；边界类型和错误结果仍与相同协议一致。上下文不从全局currentCandidate取得。关闭由调用者拥有的Runtime需结算其工作；借用已有Runtime只释放自己的连接/等待，不销毁其他用户的任务与引用。

AI协议桥接只声明真实支持的字段、扩展和返回范围，配置握手可返回发行/解释标识、源语言、目标键、引用寿命、工具能力与可取得的绑定说明；这不是第七个业务工具。连接身份来自真实认证，元数据不签发授权。协商成功不证明相关Provider或目标可用，缺失以相交动作返回。旧端不识别可选作者辅助就保留source/files/edits的正常路径，不假报已支持补全或“全部功能”。

### 默认任务压缩与检查点

开发者已知源且只要目标代码时，允许原preview内联源一次完成必要准备与生成；只要修改源时使用propose或外部编辑，不强行生成。明确要求构建/测试时可以在同一客户端任务内顺序调度已有动作，公开各自结果、作用和失败范围，不要求每个无歧义中间步骤人工确认。审批仅由真实权限/任务条件触发；大型多文件变化按一个完整批次检查，不逐行问批次表单。

## 未保存缓冲、辅助编辑与接受变化

现有编辑器接入时，先把实际可见缓冲及其语言角色、版本、编码和根配置交给原文本工作集捕获。客户端本地撤销/选区不是作者语义；多个编辑器实例打开同一路径也不是同一文档实例。IME组合输入可作为本地未完成状态，不为每个中间键触发昂贵全工程检查；提交组后才发对应版本的工作项。增量同步丢段或基础不符时重取全量该文档，不猜着接增量。

本地输入立即保留；补全/格式化/快速修复产生候选或[准确编辑计划](工具协议/作者辅助接口.md#authoring-assist-contract)，不是另一个可编辑业务模型。接纳建议时核实际基础与影响组；未相交的后续编辑可以按真实对应重基，不能只比较字符串仍相同。无合格重基则展示旧计划与新源差异，可继续手工编辑，不悄悄改latest。

补全包含主插入和必要import时一并形成后继候选；只收主插入可以成为普通错误草稿，不能标作完整可用补全。插入/替换模式、snippet占位和提交字符由客户端明确选择并在得到准确最终字节后捕获；不把snippet中的`${...}`交给语言解释器当新语法。未填占位的草稿继续合法保存。建议附带的外部command、包安装和生成器执行不在只读辅助中执行，另走实际准入。

客户端把候选应用到缓冲的动作，与写磁盘、更新索引及写输出分别处理。宿主只支持顺序应用且可能中途失败，就呈现实际已改范围；可尝试恢复但不宣称事务。必要的完整变化可先在私有候选中构造，只有宿主能兑现相应边界才进行强应用；否则保留候选/导出差异，不占用不可得能力。应用后的缓冲版本由宿主返回并重新捕获，不能提前给即将生成的版本编号。

直接写文件、AI成组编辑、CLI请求和可选编辑器接受，在相同基础、解释与变化下应得到相同语义候选。允许表示/注释保全结果有各方法声明的差别，但不能因为客户端不同改变要求或绕过检查。生成目标上的修改仍沿generated-edit；没有唯一逆映射时保留草稿和选择，不反向改全部模板实例。

## 诊断、进度与下一步可用行动

诊断按照真实`生产者＋范围＋输入版本/解释＋请求代`发布。增量追加、该范围完整替换、未变复用、失败/取消是不同结束方式；完整空结果只能清除同生产者同范围的旧诊断。旧候选迟到的空结果不能清除新候选，编译器崩溃也不能变成一页绿灯。已有输入结果可以显示为陈旧历史，但其状态和来源要可见。

每条面向开发者的主要诊断至少足以定位：谁生产，在哪份源/配置/产物及范围，实际需要什么而取得什么，以及相交可行的下一步。给主位置、必要相关位置、原因码和可披露文本；只有这些确实帮助理解时给反例与精确类型。例：未保存src/a.sec的公开返回从Int改成Text而b.sec仍做加法，定位两端和该候选，不让用户重装工具链。缺编译器、权限拒绝、程序类型错误、测试不满足、适配失败与数据覆盖不足分开归因。

连续语法错误可能产生大量派生报错。界面可以按确定因果归组、先展示能阻止级联的上游错误，但保留全部原诊断及覆盖；独立错误不因“根因模式”隐藏。快速修复是有基础/读集/要求影响的候选建议，不自动选择宽松类型、关闭检查、改变验收或删失败案例。没有可靠修复时给准确允许的手动路线，不伪造“自动修复”按钮。

进度说明当前等待的是解析、输入、工具、计算还是外部确认；无真实总工作量不显示伪精确百分比。已完成的独立根允许查看，后继停止的原因可追溯；高频日志有背压、截断标记及准确原记录取得方式。取消按钮只撤销对应请求/授权范围，不能影响共享任务或把已发送的效果当未发生。

<a id="developer-review-integration"></a>
## 审查、局部采纳、版本控制与多方协作

审查默认显示真实作者差异，另按需显示契约/要求变化、推导/生成变化、资产成员和实际作用计划。三个层次关联同一候选，不把生成差异反写成第二作者源。审查者可局部采纳实际独立修改；涉及定义与消费者、资源与引用、主插入与import的依赖组，拆开后重新形成候选并检查。可以保存未完草稿，不能沿用拆分前的检查通过。

工作树、未保存缓冲、Git索引、分支提交和合并候选分别捕获。运行测试的主体必须是声称接受的那一份：工作树C2通过不证明只暂存一半的S2通过；构建完成后hook或生成器改了文件，原结果仍绑定原输入，不能贴给新提交。查看stage/unstage属于读取/索引编辑，reset、clean、强制切分支和丢草稿是独立授权的破坏性操作，不能作为自动“修好冲突”的默认动作。

并行人/AI从各自base形成完整批次，短协调只发布引用；跨文件不同不证明语义独立，接口、公共配置、要求、锁和生成资源可能相交。真正不相交可合并并保留各方变化；相交而同值仍重新核读集；无法确定则返回冲突范围和可保留方案，不全仓最后写者获胜。形成合并候选后重新解析/类型/相交案例，不复用分支通过来证明组合通过。

独立worktree可以隔离某些文件与index，但配置、引用和外部缓存/工具状态不必隔离；不由目录不同推导完全独立。跨进程/远端协作仍用已有前像、围栏和操作恢复，离线缓存不签发新写权。Git/其他版本控制不是唯一要求，等价的准确内容与历史选择也可接入；不把本设计规范版本包当成已经部署的协作服务。

### 文本优先的可用性与无障碍

帮助、诊断和差异必须能用纯文本完整理解；路径/范围可复制，关键状态不能只用颜色或图标表达。未来薄编辑器适配应支持键盘、焦点返回、可读标签、缩放/换行和屏幕阅读器，不要求先造自有控件库。选择显示文字与真实源码字节分别编码；中文消息不得改协议枚举，双向控制字和终端转义不静默执行。大文件采用分页和局部任务，不阻止立即输入；精确全工程引用查询仍报告真实覆盖而非以“快”代替完整。

性能准入以同任务冷/暖过程、首次有效反馈、最终结果、需要的输入量、失败/恢复成本及实用完成率衡量，未实测不设毫秒承诺。可用普通文本/脚本完成同一任务时，薄GUI不是支持条件。
