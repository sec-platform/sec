## 当前范围

首期开发客户端以AI/脚本为主，本章不要求实现专用图编辑器、属性面板、LSP服务器、拖线或人类交互产品。直接使用现有编辑器、文件或补丁工具是合法入口；这与新建一套人类IDE不同。其内容层、版本及联合捕获沿[文本工作集](原生维护/导入观察与原生资产.md#text-workspace-capture)进入共同候选，语义、权限和真实结果不因客户端形式改变。

当前查询、成组修改、诊断、编译与恢复由[共同操作接口](工具协议/六工具与请求.md)和[AI开发协议](AI协作/需求与作者上下文.md)拥有。人类读取报告或检查生成代码，不构成开发一套专用交互产品的需求。

## 后续客户端只适配不重定义

未来明确需要人类或其他客户端时，复用作者源、基础修订、语义增量与实际效果合同。客户端可以组织自己的光标、选区、展示和撤销组，但不增加独立业务规则、生成器或权限根。局部显示状态不是业务含义；目标软件本身的布局、顺序或导航可能是业务，仍由对应领域拥有。

不得把编辑器缓冲版本当工程版本，不得把显示的“通过”当真实证据。编辑往返与坐标、注释、未完成草稿和多对一映射由[唯一往返合同](../编译/表示/编辑与受管回源.md#编辑往返的具体合同)承担，不在此重复。

## 采用条件与退出

只有出现实际人类开发消费者、共同接口无法满足任务且独立交互收益可检验时，才选择现有编辑器的薄适配或其他界面。采用时补齐该客户端真实需要的可用性、无障碍与安全条件；不能以“未来可能有人”预先实现全部控件。

即使未来开发人类入口，也不要求两类客户端有完全相同的调用次数、显示格式和本地状态。共同的是被解释的变化及其前提；权限按实际主体，不按“人”或“AI”类别自动相等。

## 完整开发面：工作对象、动作和结果，不是一套新界面

本节把前述客户端边界落实为可操作的设计。开发面包括人、AI、脚本和已有编辑器实际输入、查看、修改、调用与继续工作的全部接合；不等于图形界面，也不等于六个工具名。当前以原生文件工具/补丁、SDK/CLI宿主和原六工具承载。编辑器面板、网页、终端布局可独立采用；不因本节设计完整而要求先实现新GUI。

一项开发任务通常只需说明**要改变的行为或资产、已有工程或局部源，以及无法推导的取舍**。准确版本、CST/IR、检查依赖、编辑引用、制品成员和运行身份由系统取得和维护；开发者不手填这些内部台账。已经知道对象和动作就直达，不要求先浏览能力全集、创建会话表或取得批准卡。

### 作者真正维护的四类内容

| 对象 | 正常开发方式 | 系统提供而非作者重复维护的内容 |
|---|---|---|
| 新的中立行为或抽象 | 简洁.sec、已有定义/库的引用、必要参数和独特算法；支持未写完草稿 | 从真实定义推导类型/效果、局部身份、依赖与生成对应；不展开回写成另一份作者程序 |
| 已有原生源 | 继续在TS等实际原文中编辑，保留注释、BOM、行尾、路径与原工具 | 可取得范围的符号、类型、调用与原生工具诊断；不强制生成.sec镜像 |
| 工程控制与非代码资产 | 原项目配置、依赖声明/锁、入口、资源、测试和独立说明；没有该信息则不建空文件 | 仅建立缺少且有消费者的稀疏控制；同一规则不在package、工程表和意图JSON中三写 |
| 生成/运行观察 | 默认看目标源、差异、栈和值；要改则定位真实作者，或保全受管目标编辑草稿 | 固定生成与运行来源；一对多和不可逆明确呈现。运行值、生成helper和推导签名不伪装成任意可写作者槽 |

`.sec`并不是所有控制的同义配置语言。导入/模块、一般函数/类型、对象/状态/关系/流/数值的实际语法由各语言和领域拥有者定义；表格只规定它们如何进入共同开发过程。成熟供给够用时直接绑定；确有独特含义才定义新函数、类型或库；没有可验证供给不能仅写一个功能名冒充完整实现。

### 操作目录按任务展开，不按所有协议字段展开

下面各行都是应有的开发动作族。一个能力当前不可用时，仍能在明确请求时取得准确原因及合法替代；不显示虚假的可执行按钮，也不隐藏任务本身的缺口。没有请求相交能力就不把全目录塞进每次AI上下文。

| 动作族 | 作者最小输入 | 正常结果及真实通路 | 独立的不足/退出 |
|---|---|---|---|
| 临时试写/空工程/已有工程打开 | 一段源或真实路径；新工程必要目标 | 内存候选或获准工作区捕获；原context和projectView形成 | 未装编译后端不妨碍保全和源级检查；打开不执行项目脚本 |
| 克隆/多根/远程/恢复工作区 | 明确来源及范围，恢复时准确保存点 | 实际宿主连接/克隆后捕获；多根保持独立归属和解析域 | 下载、凭据、子模块/大文件取得是单独作用；不能读到的范围显露 |
| 定位/解释/搜索 | 名字、位置或问题；已知引用直读 | query的source/contract/origin/impact及原生语义查询 | 引用搜索与文本搜索分开；动态调用未知不叫零引用 |
| 创建一般程序/复用供给 | 完整源、局部表达式、真实调用/参数 | 直接编辑或propose形成同一候选；库查找按本次需要 | 类型未知只问最小注解；意图歧义不替用户改变要求 |
| 补全/参数提示/查看推导 | 当前内容与合法位置，已有签名/预期 | 有来源的候选项或说明；选定后变成普通编辑批次 | 不将模型生成的猜测显示为已存在符号；不执行用户函数探测类型 |
| 修改字段/组合/对象/状态/关系等 | 真实源差异或已有editRef与值 | 现有类型化作者/结构语义，统一候选 | 原本不支持的复杂语义保留原生/草稿及具体缺项，不伪造通用控件 |
| 移文件/更名/签名变更/抽取/内联 | 准确声明或范围及新要求 | 同一语义批次含引用、出口、资源与配置消费者 | 动态引用、外部公共API和资源捕获按真实保持范围处理 |
| 格式化/整理导入/批量修复 | 明确范围和合格方法 | 工具结果先成为源候选，显示副作用与完整差异 | 不以“格式化”重排有初始化效果的导入或清掉非法草稿 |
| 配置/环境变量/资源/秘密 | 改真实配置或安全输入引用 | 格式拥有者校验，输入与目标/运行绑定 | 秘密不写进日志/普通文本补全；检查存在不泄露内容 |
| 依赖添加/升级/移除/物化 | 所需能力/版本政策/明确变更 | 依赖计划、候选锁与消费者；物化另有获准实际操作 | 解析与安装分开；没有网络时只需网络的动作受阻 |
| 浏览诊断/定位修复 | 问题引用或选定范围 | 分生产者/主体/覆盖的诊断与可行修复 | 旧诊断、工具失败、未覆盖与当前错误分开 |
| 差异/部分选择/比较方案 | 候选、基础及保留哪些语义组 | 原preview或源差异、共同前提与冲突 | 半个不变量不能勾选通过；方案较优不等于已采用 |
| 源检查/案例/性质/覆盖/基准 | 明确方法与准确主体、范围 | check types/cases及已选原生测试/性能工具 | 测试发现可能执行代码；无案例/跳过/工具崩溃不叫全部通过 |
| 生成/构建/导出 | 已定候选和一个或多个输出根 | preview生成；compute-build实际构建；apply按需写出 | 各根单独结算，未选根不清理；生成不自动执行 |
| 运行函数/CLI/服务 | 真实入口及参数、环境选择 | 绑定参数并compute-run/eval；已有宿主提供活动会话 | 参数错误先定位输入；缺环境不改源；stdin/服务就绪不是退出码 |
| 调试/性能定位 | 准确运行、断点/观察用途 | 既有有限debug、profile与来源映射 | 无安全读取显示不可用；旧运行不映射为最新源；求值不偷进只读 |
| 监听/再次构建/连续测试 | 范围和自动动作策略 | 捕获最新有效输入，派发受限同类任务 | 默认不自动发布/提交/安装；旧任务完成只留原归属 |
| 保存/撤销/舍弃/清理 | 要处理的层和准确选择 | 源保存、草稿历史、生成协调、原操作查回 | 丢草稿、编辑器undo、Git revert与外部补偿不是一个撤销 |
| 提交/分支/评审/合并/同步 | 内容选择、目标ref与真正集成策略 | 原生VCS适配固定树/索引/历史/策略后操作 | 不擅自stage全部、stash、reset、force-push；远端成功与本地跟进分开 |
| 打包/发行/部署/迁移 | 发行选择及授权目标 | 已有产物、信息发布及真实Provider流程 | 不把save-source命名成publish；用户验收与技术检查分开 |
| AI委派/审查/交接/退出 | 目标、已取得源、必要范围/预算 | 同一候选分支和只读审查；精确引用交接 | 子任务结论不是根授权；关闭客户端不杀其他人使用的工作 |

### 一个统一的结果，不是一个万能success

内部`DeveloperView`是已有候选/产物/检查/操作的按需投影，不是新的持久权威。它由下列信息组成：本次请求与准确基础；已取得的source/contract/diagnostics/impact/origin/state；各受请求步骤的实际结果；仍需的最小决定或能力；当前合法下一动作。只有受请求且影响判断的未完成步骤才出现，不能在每次小编辑后刷几十项not-requested。

`NextAction`在内部含purpose、作用对象及基础、实际方法/消费者、必须输入的局部模式、效果范围、当前资格/阻塞理由和精确调用路径。客户端通常只显示自然语言动作、关键差异和缺项；完整结构按需取得。它不是可执行网页命令、授权票据或永不过期的能力。已知基础和动作可以直接构造原请求，不必先创建这个对象。

资格分成可准备、缺输入、方法不支持、当前禁止、基础过期、已有动作未决；不能把它们都翻译成“请重试”。权限类理由按当前可披露范围返回，不能通过被禁动作菜单泄露他人资源。行动前重新核实际前提。菜单上的建议或诊断的preferred标记不是必须采纳；涉及改变要求/期望或扩大作用，必须在任务现有授权内有明确选择，不因为发起者是AI而加确认，也不因为是人而免检。

### 读取、编辑和宿主动作的实际分工

source/contract/diagnostics/impact/origin/state仍是原query投影；补全和重构的语义提供者可通过现有编辑器/SDK请求位置和意图，再归一成原source/files/edits/edit-value/semantic-change。**本章没有添加`view:actions`、`propose(actionRef)`或`apply(mode:commit)`等未声明请求。** 远端只提供原六工具时，已可通过查询和真实源/批次完成同义开发；专用补全服务不可用时不假称有原生IDE能力。

克隆、依赖安装、Git集成和发行由真实宿主/原生工具或已注册Provider承担，使用下面的有限内部计划，不默认成为第七个公共工具，也不把任意shell字符串藏进compute-run。宿主尚无通路时返回所需能力和可执行原生路径设计，而非假造一个已有API。实现某远端客户端需要这些通路时，显式注册合格适配和精确协议后再公布；六个名字相同不证明所有客户端已支持全部能力。

### 同一开发过程在不同客户端中的表现

AI与脚本按真实源片段、必要诊断和最小差异操作；人可用现有编辑器文本、命令和终端。两者共享含义与前提，但输入节奏、展示、快捷键、访问权限和审批职责不必相同。面板若被采用，键盘可达、屏幕阅读语义、焦点恢复、非颜色状态和大内容渐进展开是该面板验收，不强制无GUI服务先做页面。命令行的机器结果与人类进度分别走实际输出通道；日志中的ANSI/终端控制和工具文本不作为可执行指令。

正常最短路径仍是“写源→看结果”，或“直接改已有文件→捕获→所需检查”；必须保持一个闭合小函数无需先启动服务器、调试器、数据库、Git仓库和完整工作台。大型工程增加的是准确范围、消费者和恢复责任，不把每个开发者变成内部状态管理员。

## 可视图、表单、结构面板与直接操作

类图、依赖图、状态机图、关系图、配置表单、属性面板和拖拽工作台都是**同一作者/语义事实的投影**。它们可以成为高效客户端，但不能为了可视编辑复制第二份可写模型。

```text
VisualWorkbenchProjection = derived {
  subjectSelectionAndRevision,
  projectionMethodAndRevision,
  semanticNodeAndRelationRefs,
  sourceAndEditMappings,
  visibilityFiltersAndCoverage,
  viewLayoutAndViewportState,
  editableActionDescriptors,
  staleAndConflictState
}
```

节点位置、缩放、折叠、颜色、网格、edge routing、自动layout和当前selection默认属于客户端view；可以保存为用户/团队展示偏好，但不进入程序语义摘要。**例外必须来自领域本身**：GUI坐标、CAD几何、工作流人工布局若被目标程序消费，则它们是该领域作者数据，不得以“图的布局”标签排除。

### 直接操作必须降低到同一候选

图上新增继承边、删除关系、拖线连接端口、修改属性、创建类/节点等，如果存在唯一有资格的语义映射，就降低为已有 `semantic-change/EditPlan` 并生成正常workspace candidate；随后重新解析、类型/关系检查和review。图形客户端不能直接改自己的edge store后再异步“同步源码”。

一个视觉动作可能需要多个真实编辑，例如创建引用同时加入import、生成缺失声明、更新配置消费者；它们作为一个依赖组呈现。只有真实独立的子变化才允许局部采纳。映射到多个源位置、宏展开、generated-only节点、runtime observation或opaque外部对象时，默认只读或要求用户选择真实owner，不能按最近文本位置猜回写。

### stale view、过滤与“没看到”

Visual projection绑定精确subject revision。作者源变化后，旧图可以作为历史view继续查看，但拖拽/删除前必须重定位到当前source correspondence或基于旧revision形成分支candidate；不能把旧node id应用到latest。节点被filter/scope/collapse隐藏只说明当前view没显示，不能作为consumer-zero、删除安全或“没有引用”的证据。

布局算法重跑不使semantic candidate陈旧；semantic identity/relationship或projection method改变则相交view需重建。客户端可以缓存layout keyed by view/semantic refs，但缓存丢失只影响展示，不影响工程真相。

### 导出与可访问性

导出PNG/SVG/PDF/PlantUML/其他图格式是派生Artifact，绑定subject/projection revision和实际覆盖；不能导回一张图片后作为canonical source，除非所选外部格式本来就是该领域唯一作者源并经过显式接管。可视功能应有等价的文本/结构读取和键盘操作路径，节点/边有可读标签与关系说明；颜色、线型、空间位置不承担唯一工程含义。

## Developer Intelligence 是共同工程事实的投影

补全、导航、层级、诊断、重构、测试定位、调试定位和性能热点都需要项目级知识，但它们不形成第十一项逻辑责任，也不建立IDE专用语义库。**Developer Intelligence**只是 `workspace + semantics + compiler + information + assurance + execution` 的有界投影；每项结果继续携带真实主体、selection/revision、覆盖、来源和资格，客户端只改变交互和编码。 它不拥有持久缓存、索引代、symbol identity、诊断生命周期或变换身份；复用和失效继续由information/query/workspace及实际生产者承担。

| 开发智能 | 真正owner | 结果 |
|---|---|---|
| describe/hover、signature、type/effect | semantics | 说明、签名、推导来源 |
| definition/type-definition/implementation/references | semantics + information | 精确位置、关系种类、覆盖 |
| call/type/module hierarchy、impact | typed relations + query | 分页关系与未闭合范围 |
| completion、quick-fix、refactor、format | semantics + EditPlan/TransformationView | 建议或有基础的完整计划 |
| diagnostics、test/evidence navigation | compiler + assurance | 生产者、主体、方法、覆盖 |
| debug/profile/runtime navigation | execution + SourceMap/Observation | 运行到制品、目标、作者的可证明对应 |
| symbol/search/index | information | 固定切面的索引投影 |
| semantic tokens/highlights、outline/document symbols、folding/selection/linked ranges | parser + semantics + workspace | 与固定source revision绑定的结构/语义标注；只是显示投影 |
| inlay hints、inline values、code lens、moniker/document link | semantics + execution/assurance/information按项目 | 带生产者、revision和来源的派生注解；其中command/link不自动执行 |

同一路径可以同时存在未保存buffer、候选工作区、磁盘工作树、索引代、生成制品、依赖索引和历史revision。它们不是一个全局“最新覆盖栈”。查询明确或由客户端会话固定 `selectionRef` 与用途；“当前草稿的引用”“发行制品对应源码的引用”“已知依赖仓库的公开引用”是不同结果。索引落后时可旁路真源或返回较弱覆盖，不能把旧索引结果贴到新buffer。

LSP可以承载completion/navigation/diagnostics/workspace edit，SCIP类格式可以搬运代码索引，BSP类协议可以接build target与compile/test/run/debug；它们都只是投影。外部document version、symbol、build target、task/session id不自动成为SEC canonical identity。协议表达不了的evidence、authority、effect、unknown和跨表示对应必须保留在SEC结果中或显式记录投影损失。

## 嵌入语言与结构化搜索复用同一Developer Intelligence

当authoring-assist的position落在合格的[嵌入语言投影](../编译/表示/编辑与受管回源.md#embedded-language-roundtrip)中，原有 `describe/complete/signature/definition/references/implementations/actions` **不增加新kind**：应用层先固定host candidate和embedding rule，再把位置投影给相应语言Provider，最后把结果、coverage和可编辑范围映回host坐标。客户端可以显示“SQL / RegExp / GraphQL”等语言标签，但标签不创建另一文档身份。

### 搜索有四个不同层级

```text
text search       字节/文本出现
regex search      文本模式
structural query  语法/CST/AST形状
semantic query    绑定、类型、效果、关系及工程事实
```

四者不能相互冒充。结构模式匹配 `foo($X)` 只证明当前parser/strictness下有相应语法形状，不证明两个 `foo` 绑定同一symbol；semantic rename必须使用真实definition/reference relation。反过来，结构搜索仍有独立价值：迁移API调用形状、查找反模式、批量语法升级、模板/配置结构审查，不必把所有查询提升到全项目类型检查。

```text
StructuralQueryView = derived {
  sourceSelectionAndRevision,
  languageParserAndRuleRevision,
  queryPatternAndPatternLanguage,
  matchSemanticsOrStrictness,
  scopeAndCoverage,
  matchesWithHostRanges,
  metavariableBindings,
  unknownOrUnparsedRegions
}
```

它属于query/information投影，不拥有索引或作者状态。可使用Tree-sitter query、ast-grep、Semgrep或语言原生AST工具等成熟Provider；Provider结果先规范化成匹配事实，不能把工具的node id/metavariable id变成SEC稳定身份。

### Structural rewrite仍是候选变换

结构化工具给出的rewrite/fix首先是 `TransformationView` 的来源之一，然后降低成已有编辑候选。批量rewrite必须在**同一固定source selection**上产生全部原始匹配和前像；不能边改边重新搜索后把匹配集合偷换成另一含义。重叠匹配、一个rewrite产生/删除其他match、跨文件共同约束和生成代码区域分别处理。

应用前检查：匹配仍对应原revision；rewrite只触及声明范围；新文本能被host/embedded parser重新读取；需要语义保持的动作重新走类型/引用/合同验证。结构化工具的interactive“accept all”只是客户端选择，不能绕过当前workspace前像或写权限。可安全独立的matches可以分组采纳；共享不变量或相交write set必须共同检查。

## 不同工程的开发面接合，不能全部压成CLI运行

以下是当前应显式保留的工程入口差异，按组合需要启用；不是封闭工程分类，也不声明相关产品适配已实现。通用的源/配置/测试/运行/恢复通路相同，实际对象与效果不能合并。

| 工程形态 | 作者直接处理的东西与正常开发动作 | 必须另核的目标事实 |
|---|---|---|
| 库、SDK、小工具和命令行 | 公共入口、类型/错误、兼容调用、参数/流输入、打包和使用说明 | 库被消费者真实链接与CLI可启动不同；标准输入、退出、编码和依赖交付各有结果 |
| Web/前端/样式/媒体 | 组件/路由/模板/样式/资源同候选，生成bundle，启动开发服务器，在准确页面状态检查功能/布局/无障碍 | 服务器就绪不等于浏览器已加载新bundle；缓存、service worker、source map、热替换状态分别绑定。截图只是视觉证据，不能代替行为和键盘/屏幕阅读验证 |
| 后端、服务、任务与消息 | API/模式/配置、局部数据fixture、请求/事件、日志和追踪；在选定环境测试与调试 | 本地启动与真实数据库/消息/认证可用分开；不能用生产凭据跑测试，超时请求恢复遵守真实效果合同 |
| 移动/桌面与插件宿主 | 代码/界面资源、打包签名、模拟器/设备/宿主实例、调试附加与更新 | 应用标识、签名、安装对象、进程出生和真实已装制品；重新安装可能清数据，插件加载/配置读取可能执行代码 |
| 数据、数据库与迁移 | 模式/查询/索引、迁移脚本与数据样本、回填/校验/兼容窗口 | 源回退不等于数据回退；数据量、外部观察、读写竞争、保留和恢复按原事务/数据合同，不由文本diff保证 |
| 计算、GPU、ML与仿真 | 算法、数据/模型/参数、内存设备预算、训练/推理/评估与性能 | 代码、数据、权重、随机性及设备对应；采样数据/观察有权限，运行完成不等于精度/误差或可重现实验合格 |
| 编译器、生成器、构建与开发工具自身 | 工具源码与工具输入分开，固定引导种子/规则，生成/编译/比较和自用 | 新检查器不独自为自己签证；工具元程序执行是构建效果，不能变成query；宿主与目标工具不混同 |
| 嵌入式、设备和实时工程 | 硬件配置、镜像、接口与时序约束、设备部署/调试/恢复 | 实际设备身份、权限、刷写/断电风险、固件和物理状态；模拟通过不代表真设备保证 |
| 文档、规范、数据表和其他非源码 | 按真实格式编辑、关系/链接/引用重构、检查并按需生成派生物 | 格式通过不证明语义正确；图/HTML/译文不成第二真源，秘密/许可/大对象有独立存储及退出责任 |

每种画像最少需要准确作者范围、目标入口/参数、运行/测试/观察能力、结果对应和退出方式；复用这些角色，不为每个业务名称建新顶层模块或工具。需要的新目标字段由所属领域版本化解释，无法表达的语义不能用开放字典默默接收。界面可以有真实浏览器/设备预览，也可以先只用文件与脚本；未选可视客户端不意味着不设计目标软件的交互和资源行为。


## 动作的完整性不能替代作者成果

本章的动作族描述如何操作，最终维护的作者结构由[作者源码结构与需求抽象](../领域/计算基础/作者表示与实现分工.md)拥有。只列21个动作或成功调用六工具，并不证明需求已经能在源中准确表达。设计验收需分别核：源码结构是否足够、真实行为是否有主体、目标/宿主缺项是否准确、第二次修改是否仍只维护其真源。本章已有编辑/诊断/运行交互继续有效，不因新增成果层被删除。

## Run Configuration、任务图与复合启动

IDE中的Run/Debug Configuration可以作为开发者保存和复用启动意图的客户端表示，但不能成为新的执行authority。单一运行最终仍降低到已有 `compute-build / compute-run / debug-session / process-session` 等Operation；多个任务的顺序/并行关系形成一个**有类型的开发启动图**，而不是一段任意shell。

```text
DeveloperLaunchProfile = authored-or-client-config {
  profileIdentityAndRevision,
  workspaceAndTargetScope,
  launchMode,
  artifactEntryAndArgumentsRefs,
  runtimeEnvironmentSelection,
  workingDirectoryBinding,
  environmentAndSecretRefs,
  terminalInputAndObservationProfile,
  resourceAndDeadlinePolicy,
  orchestrationRef?
}

LaunchOrchestration = derived {
  profileRevisionRefs,
  dependencyDag,
  sequentialAndParallelEdges,
  readinessPredicates,
  gatePredicates,
  childOwnershipAndBorrowing,
  failurePropagationPolicy,
  stopAndCleanupPolicy,
  observationAndDebugBindings
}
```

`DeveloperLaunchProfile`可以保存在项目开发配置或客户端私有设置中；它只是作者/客户端选择的启动参数源，不保存运行session、已获Grant、占用端口、活动PID或“上次成功”作为下一次事实。临时配置可以仅驻客户端；永久配置有稳定revision后才能被团队共享和review。

### before-launch 不等于“先跑任意命令”

构建、代码生成、准备fixture、启动browser、准备数据库、安装已明确依赖等前置动作分别引用其真实Provider/Operation合同。前置步骤成功退出只满足其自己的result；是否允许进入下一节点由显式gate决定。例如build失败通常阻止run，但用户明确选择“build no error check”的配置只能改变该gate，不能把失败改写成成功。

外部tool或shell只有在项目/宿主实际允许这一能力时作为受限Process/ToolInvocation执行，固定executable/argv/cwd/env/权限/资源；配置字符串不由shell自动解释。browser launch、SSH tool、容器启动、数据库准备等都是真实Effect，不因为它们处在before-launch列表就变成setup metadata。

### 进程启动、端口监听和业务ready分开

长运行服务至少区分：operation accepted、process spawned、transport/port reachable、protocol ready、application ready、dependency ready和最终业务健康。一个TCP端口能connect不证明数据库schema已迁移、HTTP handler已加载或消息consumer已订阅。

```text
ReadinessPredicate = exact {
  subjectAndRuntimeInstanceRef,
  methodAndProviderRevision,
  requiredObservation,
  scopeAndMeaning,
  deadlineAndPollingBudget,
  successFailureUnknownMapping
}
```

readiness check本身可能有Effect，例如健康URL触发懒初始化或数据库探测执行查询；是否可重复、是否只读由Provider合同决定。没有合格readiness方法时，等待固定秒数只能作为延迟策略，不能签发ready。

### compound launch 与生命周期

并行启动多个服务时，每个child有独立operation/session/资源；compound只持有协调关系。父compound停止时，只能按声明stop policy终止自己拥有的child；attach/borrow来的外部数据库、浏览器、服务或共享worker不能被顺带kill。一个child失败后，已启动siblings是继续、优雅停止、立即取消还是保留诊断现场，由profile固定并逐项结算。

顺序依赖的上游如果是long-running service，后继等待的是其readiness，不是进程exit；一次性build/migration任务则通常等待terminal result。DAG中循环依赖必须通过已定义的共同启动协议/外部已存在资源解决，不能无限互等。

端口、socket、临时目录、container/network和测试数据库是运行Resource。端口“探测到空闲”与实际child bind之间存在竞态；需要强保证时由拥有者预留/传递真实socket或使用目标平台合格分配机制，不用scan-then-use冒充原子保留。

### run 与 debug 共享意图但不共享证据

同一profile可以派生run/debug变体，但debug adapter、暂停、instrumentation、coverage/profiler等会改变环境、时序和资源。debug成功不自动成为普通run性能Evidence，普通run也不证明debug attach/source-map能力。复合debug中的每个target分别绑定其DebugSessionRef，不能一个“Debug All”session吞掉子目标身份。

## 当前可实施的文本、CLI、SDK和代理入口

以下是已有源和六工具的**开发客户端设计**，不要求创建专用IDE。面向人的文本与面向AI/脚本的数据可以不同；运行身份、候选含义、读取权限与效果不得改变。文件已经由编辑器保存时，直接捕获得到候选；不先复制到聊天再propose，也不重复save-source。

### CLI的单请求合同

CLI绑定发行提供的真实Runtime配置；拟定命令形状为`sec <query|propose|preview|check|apply|operation> --request <文件路径|-> --format <json|text>`，`--request`必需，`--format`默认json，`--help/--version`可独立使用。示例是设计语法，不声称当前产品已可安装。子命令只把请求交给同一解码器；不新增save/deploy等模糊合并命令。

request文件路径仅定位载荷，`-`读取标准输入；载荷是恰一个有界UTF-8 JSON对象，重复键、尾随第二对象和超限先拒绝。载荷内路径按它已绑定的项目/对象解释，不随request文件所在目录改变，不对字符串做shell展开。语言、目标与base继续遵守原工具字段；stdin的普通文本不因扩展名猜成TS。示例：

```sh
sec preview --request preview.json --format json
```

preview.json是使用原source分支或实际candidateRef的请求，不携带本段未定义字段。stdout在JSON模式只包含一个最终结构化结果及换行；日志、进度和交互提示不得混入，stderr输出有界且净化的诊断。流式进度需要明确的传输分帧能力，不把多条JSON偷偷写成单响应。终端渲染必须转义控制序列，颜色不携带独占含义。无交互环境缺少决定时返回缺项，不无限等待键盘、不默选有风险答案。

退出码定义为：0表示本请求在其范围内得到正常结果（允许propose产生带诊断草稿，query正常返回空/部分集合）；1表示得到可靠领域结果但本次明确的完成目标未达到，如check失败，或本次要求确认完成而apply仍未结算；2表示命令/载荷/协议非法且未派发作用；3表示没有取得可靠最终结果，如传输中断或客户端内部故障。partial query仍必须在数据中保留覆盖，0不等于全工程通过。这里的“最终结果”是本次工具请求的最终响应，不等于后台作用已经终结。只请求启动时，返回已受理和真实可查回operationRef可以满足本请求而退出0，正文仍标运行中；明确等待完成却只取得可靠未完成状态时才按该目的返回1。未知物理效果的状态本身可以是可靠响应，不能一概与客户端未收到响应的3混同。收到中断后若能取得最终领域状态就用该状态；进程被强杀或写stdout失败不能伪造未执行。存在作用时先保留事前requestId和目标范围用于查询，不以重跑命令验证是否已执行。

### 从纯函数开始，不必经过辅助查询

在真实发行支持基础语言且本任务只创建源的条件下，完整请求文件可以只有：

```json
{"source":"export fn double(x: Int) = x + x;"}
```

把它交给`sec propose --request create.json`得到可继续候选，不必先创建项目、补全会话、EditPlan或运行测试。要在一个进程内直接生成代码，可将同一个source请求交给`sec preview --request create.json`，但前提是该运行环境确实固定了默认目标；否则返回target-required，不能因为本设计优先TS就悄悄选择目标。

已得到真实绑定的目标键时，可以明确请求：

```json
{"source":"export fn double(x: Int) = x + x;","target":"<实际已绑定目标键>","return":"code"}
```

尖括号是替换说明，不是可用目标。已有源码文件由调用方实际读出或宿主成组捕获，不凭文件名产生伪candidateRef。创建错误草稿与生成失败是不同结果；主动生成会做所需的检查，不反向把推导注解或完整IR写进短源。这条无辅助路线与大型项目完整工作集共用同一语义，不为片段设计一个不同解释器。

### 一个进程的引用不能假装跨进程永久有效

同进程纯片段模式无需守护服务或数据库，返回小源/代码及明确的临时引用寿命；关闭后这些引用不可供下一次独立命令使用。CLI可以连接已经配置且获准的Runtime，会话/连接标识由受信配置和握手取得，不自动搜索“最近那个服务”。另一种小实现是一次进程内完成已明确请求的依赖动作后内联结果；不把六步流程强制分成六个进程。

跨命令继续的源可以保存在真实作者文件后重新捕获；要求稳定引用或真实操作恢复时，必须由该Runtime实际提供相应保留和查回能力。服务端返回一个字符串不是持久化的证明。申请保留失败或旧引用失效时返回准确缺项，可重新读取原源形成新候选但不得伪造旧身份。大结果不能因本地进程即将退出而只留下即刻失效的下载引用；要么仍有实际服务保留，要么在允许范围内交付内容/明确导出位置，否则该交付目的未完成。

### SDK与代理协议

这里的SDK是调用六工具的普通程序接口，不是已排除的“逐运算搭建作者AST的嵌套构造SDK”。SDK消费原`RuntimeHandle.handle/close`及受信HostPorts。库用户在一个Runtime内调用六工具，不必JSON序列化纯内存值；边界类型和错误结果仍与相同协议一致。上下文不从全局currentCandidate取得。关闭由调用者拥有的Runtime需结算其工作；借用已有Runtime只释放自己的连接/等待，不销毁其他用户的任务与引用。

AI协议桥接只声明真实支持的字段、扩展和返回范围，配置握手可返回发行/解释标识、源语言、目标键、引用寿命、工具能力与可取得的绑定说明；这不是第七个业务工具。连接身份来自真实认证，元数据不签发授权。协商成功不证明相关Provider或目标可用，缺失以相交动作返回。旧端不识别可选作者辅助就保留source/files/edits的正常路径，不假报已支持补全或“全部功能”。

### 默认任务压缩与检查点

开发者已知源且只要目标代码时，允许原preview内联源一次完成必要准备与生成；只要修改源时使用propose或外部编辑，不强行生成。明确要求构建/测试时可以在同一客户端任务内顺序调度已有动作，公开各自结果、作用和失败范围，不要求每个无歧义中间步骤人工确认。审批仅由真实权限/任务条件触发；大型多文件变化按一个完整批次检查，不逐行问批次表单。

## Notebook、REPL、数据库/API控制台与远程工作台

交互式工作台不是新的工程真源。它们最容易把**可编辑定义、可变会话、一次执行、显示输出和当前外部状态**压成一个cell/console/tab；SEC只投影既有workspace、execution、Observation和Artifact责任。

### Notebook / REPL

至少区分 `CellSourceRevision`、`KernelSession/RuntimeInstance`、`ExecutionAttempt`、`OutputObservation` 与可选的 `DocumentOutputAttachment`。cell文本变化不修改既有kernel变量；kernel执行也不自动改cell作者源。execution_count、prompt编号或消息序号只属于该kernel/session运行历史，不能当cell revision。乱序执行允许较新的cell文本旁边显示较旧运行输出；只有绑定精确source revision、kernel birth/session、attempt和相关environment的输出才可作为对应运行结果。kernel restart使旧可变状态失效，但历史output仍可作为带来源的旧Observation保留。

execute是真实运行，可以I/O、启动进程、改数据库、联网或等待stdin。“预览cell”只有所选语言/Provider能证明纯分析时才走query/preview，否则仍走operation。多个frontend共享kernel时，客户端source/buffer identity、消息session与共享kernel state分别保留，message parent关系不创造作者ownership。

### 数据库、HTTP、GraphQL和消息控制台

SQL/request/document只是请求定义或候选输入；prepare/parse/plan与真实执行分开。数据库结果绑定实际connection/transaction/snapshot、schema与权限观察；重跑同一文本不保证同一结果。`EXPLAIN`类静态计划仅在具体Provider保证下视为只读；`EXPLAIN ANALYZE`等“分析”命令可能真实执行DML或用户代码，必须按实际Provider语义分类，不能根据按钮名、HTTP方法名或UI“查询”标签判断纯度。

请求发送形成独立operation/attempt；response、stream item、broker acknowledgement和business effect分别结算。OpenAPI/GraphQL/AsyncAPI等描述可以提供schema与协议合同，但不签发凭证、幂等、事务或效果完成。

#### 数据库专业工作台仍是既有工程事实的投影

数据库浏览器、schema tree、query console、plan viewer、row editor、schema diff/migration和import/export都可以由成熟数据库客户端提供；SEC需要的是它们返回/执行的事实能准确进入现有模型，而不是复制一套DataGrip。

一次数据库工作会话至少把endpoint/database、认证主体与effective role、Provider revision、连接/会话出生身份、当前transaction/autocommit、isolation/read-only、search path/locale/timezone/client encoding、临时schema及相交session settings分开。连接池把同一逻辑console切到另一物理connection时，旧temp table、prepared statement、transaction、backend-local setting和cursor不能自动续用；UI tab名字不成为session identity。

```text
DatabaseSessionBinding = derived {
  providerAndServerRevision,
  endpointDatabaseAndTenantRefs,
  authenticatedAndEffectivePrincipalRefs,
  connectionAndSessionGeneration,
  transactionAndAutocommitState,
  isolationReadOnlyAndSnapshotRefs,
  namespaceAndSessionSettings,
  temporaryObjectScope,
  capabilityAndDisclosureRefs
}
```

**schema introspection。** information_schema、system catalog、JDBC/driver metadata等只形成有Provider、权限、snapshot/时间和coverage的 `SchemaIntrospectionSnapshot`。当前用户看不到某schema/table不证明它不存在；portable information schema缺少Provider特有对象也不证明数据库没有该能力。刷新schema tree只替换相同Provider/数据库/coverage的投影，不写作者DDL。

**query plan。** `EXPLAIN`/planner输出是 `QueryPlanObservation`：绑定statement/parameter、schema/catalog、statistics、session/planner settings、role、server/provider revision和plan mode。estimated plan与actual execution profile分开；statistics近似/更新、参数、配置或server upgrade都可能在SQL未改时改变plan。plan node cost不自动等于wall time，plan viewer差异也不是业务行为差异证明。

**schema diff。** A与B两个introspection/source schema之间的diff是directional comparison，不能按同名猜对象连续性；rename与drop+create、column type rewrite、constraint/index变化和Provider-specific attribute需要真实identity/migration依据。生成DDL时只是TransformationView/迁移候选；执行DDL仍走Operation，并且实际lock、rewrite、transaction支持与不可逆点由Provider报告。

**live row edit。** query result中的“第3行”、屏幕位置、分页offset或临时排序不是可写row identity。只有能构造当前表/视图上的强locator与preimage时，UI才可给安全直接编辑：例如明确primary/unique key及相交version/preimage；Provider物理locator只能按其真实寿命使用。无稳定key、join/aggregation/view不可更新、row-level policy或trigger使写入语义不闭合时，返回只读/需要显式DML，而不是猜一条底层row。

row update形成真实DML Operation；提交前核row preimage/transaction/current Grant，提交后读取generated/default/trigger/RETURNING及实际新row。optimistic conflict、0-row update、多row update分别报告，不能把“SQL无错误”当只改了眼前一行。物理row-version locator如PostgreSQL ctid在更新/重写后可能变化，不能跨编辑永久保存。

**import/export。** 导出是固定data artifact，绑定query/table、snapshot、schema、ordering、encoding、null/locale、row/byte coverage、权限/脱敏和生成工具；没有排序保证时CSV行序不获得语义。导入是外部Effect，绑定目标schema、mapping、conflict/duplicate策略、transaction/批次边界、partial progress、validation和readback。流式大数据中途失败必须知道已消费/提交范围，不能把一个下载/上传文件名当全量完成。

### 远程工作区与 development container

远程SSH/容器/云工作区首先是ExecutionEnvironment和source projection，不是第二份项目。配置可以描述image、Feature、mount、port、environment、lifecycle command和编辑器customization；**读取配置**与**materialize/rebuild/start**分开。Feature安装、image build/pull、lifecycle script、mount host socket、注入secret、端口转发和扩展安装都可能有Effect或披露，必须经现有Provider与权限边界。

本地路径、容器路径和远端路径只是位置映射；同路径字符串不证明同一文件。environment rebuild产生新generation，旧进程、terminal、language server、debug session和cache是否仍合法逐项判断。删除容器不自动删除bind mount、volume、远端仓库或外部资源。

### 数据与ML实验工作台

实验定义、代码/Notebook revision、Dataset revision、Model revision、参数、随机源、Environment、Run、Metric/Artifact和采用结论分别记录。图表或最佳一次run只是Observation；注册或部署模型是新的adoption/deployment Effect。实验工具内部的latest/best/alias不成为SEC稳定model identity。

## 未保存缓冲、辅助编辑与接受变化

现有编辑器接入时，先把实际可见缓冲及其语言角色、版本、编码和根配置交给原文本工作集捕获。客户端本地撤销/选区不是作者语义；多个编辑器实例打开同一路径也不是同一文档实例。IME组合输入可作为本地未完成状态，不为每个中间键触发昂贵全工程检查；提交组后才发对应版本的工作项。增量同步丢段或基础不符时重取全量该文档，不猜着接增量。

本地输入立即保留；补全/格式化/快速修复产生候选或[准确编辑计划](工具协议/作者辅助接口.md#authoring-assist-contract)，不是另一个可编辑业务模型。接纳建议时核实际基础与影响组；未相交的后续编辑可以按真实对应重基，不能只比较字符串仍相同。无合格重基则展示旧计划与新源差异，可继续手工编辑，不悄悄改latest。

补全包含主插入和必要import时一并形成后继候选；只收主插入可以成为普通错误草稿，不能标作完整可用补全。插入/替换模式、snippet占位和提交字符由客户端明确选择并在得到准确最终字节后捕获；不把snippet中的`${...}`交给语言解释器当新语法。未填占位的草稿继续合法保存。建议附带的外部command、包安装和生成器执行不在只读辅助中执行，另走实际准入。

客户端把候选应用到缓冲的动作，与写磁盘、更新索引及写输出分别处理。宿主只支持顺序应用且可能中途失败，就呈现实际已改范围；可尝试恢复但不宣称事务。必要的完整变化可先在私有候选中构造，只有宿主能兑现相应边界才进行强应用；否则保留候选/导出差异，不占用不可得能力。应用后的缓冲版本由宿主返回并重新捕获，不能提前给即将生成的版本编号。

直接写文件、AI成组编辑、CLI请求和可选编辑器接受，在相同基础、解释与变化下应得到相同语义候选。允许表示/注释保全结果有各方法声明的差别，但不能因为客户端不同改变要求或绕过检查。生成目标上的修改仍沿generated-edit；没有唯一逆映射时保留草稿和选择，不反向改全部模板实例。

<a id="developer-diagnostics"></a>
## 诊断、进度与下一步可用行动

诊断按照真实`生产者＋范围＋输入版本/解释＋请求代`发布。增量追加、该范围完整替换、未变复用、失败/取消是不同结束方式；完整空结果只能清除同生产者同范围的旧诊断。旧候选迟到的空结果不能清除新候选，编译器崩溃也不能变成一页绿灯。已有输入结果可以显示为陈旧历史，但其状态和来源要可见。

每条面向开发者的主要诊断至少足以定位：谁生产，在哪份源/配置/产物及范围，实际需要什么而取得什么，以及相交可行的下一步。给主位置、必要相关位置、原因码和可披露文本；只有这些确实帮助理解时给反例与精确类型。例：未保存src/a.sec的公开返回从Int改成Text而b.sec仍做加法，定位两端和该候选，不让用户重装工具链。缺编译器、权限拒绝、程序类型错误、测试不满足、适配失败与数据覆盖不足分开归因。

连续语法错误可能产生大量派生报错。界面可以按确定因果归组、先展示能阻止级联的上游错误，但保留全部原诊断及覆盖；独立错误不因“根因模式”隐藏。快速修复是有基础/读集/要求影响的候选建议，不自动选择宽松类型、关闭检查、改变验收或删失败案例。没有可靠修复时给准确允许的手动路线，不伪造“自动修复”按钮。

进度说明当前等待的是解析、输入、工具、计算还是外部确认；无真实总工作量不显示伪精确百分比。已完成的独立根允许查看，后继停止的原因可追溯；高频日志有背压、截断标记及准确原记录取得方式。取消按钮只撤销对应请求/授权范围，不能影响共享任务或把已发送的效果当未发生。

<a id="developer-review-integration"></a>
## 审查、局部采纳、版本控制与多方协作

### Local History 与草稿恢复不是VCS

开发客户端可以提供类似IDE Local History的**本地恢复层**，但它不成为新的作者authority、Git替代品或长期发行历史。它只保存已经实际观察/捕获过的workspace/buffer内容及其局部上下文，供崩溃、误删、远离最近commit的编辑和未提交实验恢复。

```text
WorkspaceHistoryRecord = exact {
  workspaceAndClientScope,
  capturedSubjectRefs,
  capturedWorkspaceOrBufferRevision,
  contentRefsAndDeletionState,
  captureReasonAndObservedAt,
  optionalLabel,
  retentionAndSensitivity,
  parentOrRelatedHistoryRefs
}
```

这里的revision只是被捕获对象的真实revision引用，不新增一个“历史revision”解释程序。History record不能被compiler/query当latest，也不自动进入共享索引、发布、review或Evidence。手工label只是给某个已捕获状态增加可导航标记，不改变内容身份、保留策略、权限或验证资格。

恢复整文件、目录或片段时，先取**历史状态H、当前工作区C、必要共同基础B**，形成普通新候选C′。当前内容自H以后已有变化时，不以“恢复”名义覆盖；能三方保全就形成合并候选，不能唯一保全则显示冲突。被删除文件的历史字节也只是恢复输入，选择恢复后才重新进入当前workspace candidate。

Local History允许保留语法错误、未保存中间态和外部编辑的已观察版本；这正是其恢复价值，但也意味着它们没有编译/测试/发布资格。历史记录可能因容量/TTL/明确清理而消失，未实际捕获的键盘状态不能承诺可恢复。若产品承诺某范围的崩溃恢复，就把相交history content登记为recovery asset并在承诺窗口内受保留根保护；其余仍可按本地缓存策略淘汰。

历史内容可能保存用户后来删除的secret、PII或受限源码，因此继承原读取限制、加密/本地目录保护和retention；“文件已经删掉”不自动授权长期保留。跨租户/跨项目不能凭内容hash共用私有history。导出patch是新的披露动作，按当前权限处理。



### 实时副本收敛不是语义合并

多人实时编辑可以采用CRDT、OT或其他合格同步实现，但它们只拥有**协作buffer/结构副本的收敛与传输**，不能取得作者语义、候选采纳、权限或验证authority。客户端先把同步后的实际buffer revision捕获为workspace候选，再由既有解析、类型、关系、semantic-change、review与check处理。

```text
local editing events
→ collaboration replica state
→ captured buffer/workspace revision
→ semantic candidate
→ semantic conflict / verification
→ authorized adoption
```

文本/结构副本已经收敛仍可能出现：类型错误、两处修改共同破坏不变量、同名实体身份冲突、删除与引用竞争、旧权限写入、一个确定性winner掩盖另一合法意图。CRDT内部operation id、actor id、heads或vector clock只在该协作Provider命名域中定位变化/因果，不自动成为SEC的Subject/Revision/Grant。需要跨会话稳定追踪时，通过映射绑定真实workspace/candidate revision，而不是复制provider内部ID做全平台身份。

### Presence、光标、选区和编辑意图

在线状态、光标、选区、正在输入、用户头像和临时锁提示属于短寿命 `PresenceObservation`/客户端view；默认不进入作者源、Git历史、工程revision或审计真相。断线/超时只使presence陈旧，不能据此判定用户已离开项目、放弃候选或释放业务写权。需要真正排他写入时仍取得现有Lease/Fencing/authoritative ownership，不能把“正在编辑”提示当锁。

undo/redo也分层：本地编辑器撤销可以生成新的buffer状态；CRDT撤销只在其操作域内产生新的协作变化；Git revert是版本历史操作；外部Effect补偿又是独立operation。四者都不能用一个“撤销”按钮的视觉概念互相替代。

### 冲突可以长期存在，但不能静默获胜

传输/VCS/CRDT能够保存一个未决冲突是合法状态。冲突需要携带真实基础、参与候选、相交读写集、已知关系与可继续动作；不强迫为了“仓库干净”立即选择任一侧。反过来，Provider因为实现需要选择一个可读winner，也不能让隐藏的loser从工程冲突中消失；只有对应语义问题已经由有权规则裁决、验证并形成新候选时才算解决。



审查默认显示真实作者差异，另按需显示契约/要求变化、推导/生成变化、资产成员和实际作用计划。三个层次关联同一候选，不把生成差异反写成第二作者源。审查者可局部采纳实际独立修改；涉及定义与消费者、资源与引用、主插入与import的依赖组，拆开后重新形成候选并检查。可以保存未完草稿，不能沿用拆分前的检查通过。

工作树、未保存缓冲、Git索引、分支提交和合并候选分别捕获。运行测试的主体必须是声称接受的那一份：工作树C2通过不证明只暂存一半的S2通过；构建完成后hook或生成器改了文件，原结果仍绑定原输入，不能贴给新提交。查看stage/unstage属于读取/索引编辑，reset、clean、强制切分支和丢草稿是独立授权的破坏性操作，不能作为自动“修好冲突”的默认动作。

并行人/AI从各自base形成完整批次，短协调只发布引用；跨文件不同不证明语义独立，接口、公共配置、要求、锁和生成资源可能相交。真正不相交可合并并保留各方变化；相交而同值仍重新核读集；无法确定则返回冲突范围和可保留方案，不全仓最后写者获胜。形成合并候选后重新解析/类型/相交案例，不复用分支通过来证明组合通过。

独立worktree可以隔离某些文件与index，但配置、引用和外部缓存/工具状态不必隔离；不由目录不同推导完全独立。跨进程/远端协作仍用已有前像、围栏和操作恢复，离线缓存不签发新写权。Git/其他版本控制不是唯一要求，等价的准确内容与历史选择也可接入；不把本设计规范版本包当成已经部署的协作服务。

### 文本优先的可用性与无障碍

### 国际化、Unicode、双向文本与机器协议分离

客户端本地化只改变**呈现文本**，不能改变机器协议、源码字节、路径身份、排序语义、错误码或领域值。Diagnostic至少保留稳定reason/code、结构化参数、source/span和producer revision；本地化message由这些值派生。日志/CLI JSON继续使用固定机器枚举，人类text模式才按locale渲染。

```text
LocalizedPresentation = derived {
  sourceStructuredValueRef,
  localeAndMessageCatalogRevision,
  formattedText,
  directionAndIsolationMetadata,
  accessibilityAnnotations
}
```

日期、时间、数字、小数分隔、单位和排序也分领域值与显示格式。`1,234`在某locale可能表示不同数值，不能把本地化字符串重新解析为程序参数；机器输入采用原有类型化编码。文件/符号搜索可以提供locale-aware或normalization-aware辅助匹配，但结果必须指向真实精确字节/标量序列，不把“看起来一样”合并成同一身份。

中立语言当前identifier仍服从其明确ASCII规则；其他原生语言若允许Unicode identifier，适配器绑定该语言实际Unicode/profile/normalization规则，不由客户端擅自NFC/NFKC。路径、JSON identity和外部协议也只按自己的合同比较；显示层不得为了“统一”改写底层字节。

对源码、diff、diagnostic、文件名和依赖名中的双向控制、不可见字符、confusable字符，客户端至少能安全隔离渲染方向并在可能误导编辑/审查时提供可见提示或诊断。提示不自动把合法非拉丁文本视为恶意；安全策略按实际语言允许集、脚本混用、不可见字符和受保护命名域判断。复制/粘贴和patch仍使用原字节，视觉顺序不作为range/offset。

IME composition、组合字素和emoji只影响交互分组/光标显示，不改变已有byte/UTF-16/scalar坐标合同。屏幕阅读器读取应给出逻辑文本和必要的不可见字符说明，不能只朗读视觉重排后的字符串。



帮助、诊断和差异必须能用纯文本完整理解；路径/范围可复制，关键状态不能只用颜色或图标表达。未来薄编辑器适配应支持键盘、焦点返回、可读标签、缩放/换行和屏幕阅读器，不要求先造自有控件库。选择显示文字与真实源码字节分别编码；中文消息不得改协议枚举，双向控制字和终端转义不静默执行。大文件采用分页和局部任务，不阻止立即输入；精确全工程引用查询仍报告真实覆盖而非以“快”代替完整。

性能准入以同任务冷/暖过程、首次有效反馈、最终结果、需要的输入量、失败/恢复成本及实用完成率衡量，未实测不设毫秒承诺。可用普通文本/脚本完成同一任务时，薄GUI不是支持条件。
