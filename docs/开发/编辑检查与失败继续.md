## 打开、新建与接入

打开工程首先读取用户选定的范围，显示读取失败、排除项、未保存缓冲区和原生工具依赖。打开不自动安装依赖、加载工作区提供的可执行配置、运行构建或接受其中的 Agent 指令。需要这些能力时单独显示用途、影响和许可。

新建工程从目标与当前选择开始；用户可以选已知模板、定义自己的模型、直接放入原生源码，或暂时只保存设计。没有选择框架不要求系统猜一个并伪装成已接受决定。

接入存量工程先保全原生资产。发现的结构与推断出的业务意图分开记录；可靠的语言分析可作为相应证据，名称猜测只是候选。只提升当前有收益的区域，不要求先解释整个仓库。不能读取的文件不是空文件；因权限、预算或工具缺失而未观察的内容继续作为明确未知。

工程设定保存真正长期重复使用的默认值：目标环境、语言或库约束、数据与安全边界、允许的自动化、交付目的及验证政策。每次任务只补充差异；改变长期默认会产生新的设定修订，不静默重解释正在执行的旧操作。


## 用户怎样发起一次变化

首期通过受信请求输入目标，AI查询并修改定义、功能实例、约束或原生源码。结构化修改与原生补丁关联同一候选，不分别维护“自然语言版、模型版、代码版”的独立真相；未来图形入口只投影已有操作。

候选至少能回答目标是什么、相对哪个基础、涉及哪些对象、明确不得改变什么、尚有哪些决定、怎样判断任务完成。用户不必手填所有字段；工具从已存在的工程状态与政策取得，新增推断显式标为建议或假设。

歧义分三类处理。可以从现有材料确定的，先查询而不是反问；可逆且在既有偏好内的，用显示来源的默认候选继续；会改变业务含义、权利、不可逆后果或用户明确偏好的，只把这一个决定交给有权主体，并给出现有方案、差异和推荐依据。未知不自动阻止所有设计，也不自动赋予系统代替别人作决定的资格。

“继续优化”不能自动变成无终点增加实体、文档或抽象。系统先识别当前已登记的缺陷、重复决定、失败风险或实测成本；没有可辩护的改变时返回无需修改。潜在改进可以保留为有触发条件的候选，不强制建立空模块。


## 编辑时的即时反馈

草稿允许临时不完整：缺少引用、类型尚未决定、函数未写完、图中端点未连接都可以保存。界面显示问题所在的对象和实际受影响的输出，不能为了保持“绿色”偷偷补空实现或默认许可。

轻量绑定和局部诊断随编辑更新；昂贵分析有预算与取消。迟到结果绑定其原基础，只作为旧结果显示，不覆盖新草稿。没有足够能力推断影响时扩大检查范围并说明，不伪称精确最小。

新业务不需要系统团队增加一个行业分支。优先调整已有功能参数、组合已有定义，或直接定义中立算法；已经选择原生作者区域时才编辑相应原生算法。复用有收益时形成用户自定义组合，真正新语义才扩展解释与降低。功能粒度由[意图与组合](../作者/组合/定义与接口.md#意图粒度与可复用功能组合)规定，不以每句话或每个表达式建立新能力。


## 预览不是只有代码差异

预览从同一候选派生三种相关视图：用户要求的行为变化、实际将改变的模型或文件、检查与作用的计划。首先显示会改变的行为、保留的行为、需要的用户决定、风险和未完成部分；需要时再展开类型、依赖、来源、目标代码和完整诊断。

预览绑定候选、输入范围和目标环境。用户编辑后，依赖旧内容的预览陈旧；未受影响的结果可以复用，但整个当前结论需要重新聚合。生成成功只说明取得制品，不代表写回、验收或发布已经完成。

设计任务的预览是设计增量、接口、状态和取舍；它不要求先运行生成器或测试软件。实现任务可以在获准的隔离范围构建候选。高风险操作前的预览还必须说明真实写入与删除集合、外部作用、允许的失败范围、恢复能力和不可逆部分。


## 采纳、保存与应用

保存草稿只保存创作状态。采纳定义表示有权主体或既定政策接受该候选含义。生成把明确输入推导成制品。应用改变指定目标。集成改变指定版本库状态。部署改变指定环境。它们可以由一个符合政策的用户动作编排，但不得在状态和权限上混为一件事。

普通低风险修改可以由事先接受的政策自动采纳与检查，不要求每个字段弹窗。超出政策、存在关键并列方案、涉及高风险效果或独立职责分离时，显示精确的待决对象。批准绑定选择、目标、影响和条件；有意义的变化使批准失效。重复弹出相同内容并不能提高安全。

一键应用只执行该按钮显示并绑定的计划。用户选择部分变更时，系统重新计算所选子集的依赖、共享不变量、检查和恢复条件；不允许按文件勾选后破坏语义事务。可以形成独立合法子集时允许部分完成，不能因一个不相关候选失败全局停止。真正要求一起提交的组仍整体接受或拒绝。

正在应用的文件和已采纳定义可以处于不同代际。界面必须说清楚“目标已采纳、文件部分更新、尚未结算”，并隔离冲突范围，而不是显示一个含糊的完成百分比。具体提交、围栏、原子性和恢复由执行合同承担。


## 已有源码和模型如何共同编辑

每个受管理区域都有当前编辑来源与映射能力。用户管理的原生区域可以直接编辑；确定生成区优先跳回定义或生成规则修改；混合文件划分明确区域；不透明区域保全原样。

对生成源码直接修改时，只有已支持且经过前像检查的逆向转换可以变成模型增量。否则，界面提供有明确后果的选择：放弃补丁、修改上游定义、在可证明的保留区保存扩展，或把该区域转为用户管理。不能既保留手改代码又继续宣称它随时可由旧模型无损重建。

外部编辑器的缓冲区、磁盘、索引和提交树分别有身份。应用前指定比较的是哪一层；有未保存冲突时由编辑器合同协调。只移动图形布局不改变业务语义，但目标界面的尺寸、顺序和导航本身可以是语义属性，不能把所有“布局”一概视为装饰。


## AI 怎样执行同一任务

AI 收到的是任务相关视图，不是整包文档。视图包含任务目的、允许与禁止动作、候选与基础、相关定义及原生片段、必须保留的约束、实际未知、检查要求和可继续查询的引用。

AI 可以检索、定义自己的算法、提出设计增量、比较实现和寻找反例；无需手算摘要、维护索引或伪造回执。工具根据同一语义协议检查它的提案。AI 返回“完成”只是文字，完成状态来自目标产物和真实回执。

遇到上下文不足时先按需展开；预算不足则保留有标记的局部结果与缺口。上下文完整性仅限于当前读取合同，不能证明 AI 已理解所有知识，更不能证明不存在未建模依赖。候选中的注释、网页和日志不会因被模型总结而成为更高权限指令。

一个 Agent 可以设计，一个可以提出反例，一个可以检查实现；共同来源错误仍需要独立方法处理，增加 Agent 数量不自动构成独立证据。子任务只能收窄父任务目的、数据、作用和预算。设计代理不能通过把工作委派给“实现代理”绕过设计边界。

模型会话终止后，从工程保存的目标、候选、实际状态和未决项继续；不是要求新模型先读完全部旧聊天。运行权限重新取得，旧缓存和历史批准不能自动复活。


## 用户实际看到的工作台

首期返回三类按需结果：工程现状、当前候选、实际操作及恢复状态。它们是查询投影，不是三个界面项目或三份数据库。结果以机器可读内容为主，同时提供简短解释和可继续展开的来源。

当前目的、允许作用、输入与候选修订、未读/未知、真实状态始终可查询。高层功能实例可以展开到生成规则、原生实现和相交诊断；AI不必每次读取全量展开树。没有实现图形客户端不限制任务完成，也不将高层摘要误当成完整可验证事实。


## 一个完整设计任务

用户要求：“只设计现有工单的关闭规则：关闭必须填写原因，管理员可以重新开启；不要改程序。”

系统读取该模块已有状态、角色、接口与验收，确认当前编辑来源和范围。候选设计补齐关闭的输入条件、错误反馈、重新开启的权限与事件、历史记录、旧数据兼容和前后端一致性。若已有约定决定原因是否可修改，就复用；没有约定则显示合理默认及其代价，不把假设伪造成已有事实。

交付是同一套设计中的行为变化、状态与接口、失败条件、权衡和验收设计。系统不会建立 Python 见证、写 TypeScript 实现、生成测试工程或执行迁移。文档整理可以进行，因为它是请求的产物；已有源码没有写入。

随后用户单独要求实现时，才取得实现范围和工具许可。固定已接受含义后，生成可确定推导的部分，独特逻辑由用户或 AI 创作并保存。检查发现缺陷回到相应定义或实现；应用前检查当前文件；成功后报告实际改变了哪些层。测试通过但尚未部署时，部署状态保持未执行。


## 一个直接原生修改任务

用户在原生区域修改一个算法，不需要先建立完整领域模型。系统按当前语言能力更新分析，指出引用与检查范围；无法理解的外部调用保持不透明边界。用户可保持普通 Git、编辑器和构建工具。SEC 增加的是可选的结构化追踪与受控变化，不以强制迁移为使用门槛。

当某模式重复出现并且抽象有实际收益时，可从多个真实例子提取规则候选，比较行为、约束、差异和维护成本，再采纳为用户定义模块。一个 AI 恰好写出的函数不自动成为全工程生成规则；收益不足时继续保持原生代码。


## 失败、停止、撤销与继续

| 现象 | 用户看到的解释 | 下一步的安全边界 |
|---|---|---|
| 缺少模型信息 | 影响哪些输出、哪里仍未知、可继续什么 | 查询、保留假设或完成独立子集，不假装无依赖 |
| 陈旧候选或外部编辑 | 精确冲突和原基础 | 重新观察或三方合并，不覆盖 |
| 类型或行为不满足 | 出错对象、反例与对应定义 | 修改真正错误的层，不偷偷改验收 |
| 权限拒绝 | 被拒动作与不泄露敏感内容的原因 | 继续无作用工作，或由有权主体调整 |
| 资源不足 | 消耗、剩余结果、未执行范围 | 分片、继续或停止，不重置父预算 |
| 外部作用后超时 | 已知作用、未知完成、稳定操作身份 | 按目标合同读回或进行有去重保证的同键重试；两者都没有则保留未决，不用新身份重发 |
| 部分写入 | 实际前后像、冲突范围、恢复方向 | 继续、反向恢复或人工协调均需当前许可 |
| 不需要修改 | 已有机制满足目标及核查范围 | 结束，不为了持续活动制造改动 |

撤销草稿、撤销已提交模型、还原文件和补偿外部效果分别设计。已发送通知或已发生外部交易不能承诺被普通 Undo 消除。取消只说明停止继续执行的请求，不能把已经发生的作用改写成没有发生。

## 连续检查与自动动作的用户语义

监听是一份已选择范围和动作政策，不是“任何文件变化就执行所有命令”。默认只捕获/分析当前作者变化和已请求的纯生成；可以显式启用选定测试、重启本次拥有的开发进程或自动保存。安装、提交、外部发布和数据迁移不由默认watch继承。无需每次人工点击，但既有委派必须覆盖动作和预算。

W0绑定源/配置/策略与生产者；W1归并事件并重新捕获真实版本，文件事件只提供失效线索；W2计算相交任务和最迟仍有用的输入；W3取消或共享尚可安全停止的旧纯工作；W4启动准确新任务；W5结果按本次返回槽安装，旧源结果进入旧主体；W6退出时结算本次真正拥有的运行和临时资源。不能取消其他客户端共享的检查，不能以旧任务超时触发无限重启。

同源多根分别可用；新草稿暂时非法时保留旧可运行制品并标旧版本，不以旧检查清空新错误。文件系统事件丢失/队列溢出时重新枚举准确范围，不能从未收到事件推出未变化。生成输出与自己的日志按真实来源区分，避免自写触发回路；若用户故意手改受管输出，则捕获为目标草稿而不是忽略。

检查、延迟、缓存占用与中断成本在同等任务/相同保证下实测，不能因为用了增量就宣称更快。小工程串行全量重算是合格替代；大工程调度可以延后低优先级分析，但不得隐去当前必需诊断。

## 环境、供给、默认选择与第二次变更

环境发现先读取已有项目根、语言角色、工具配置继承、依赖锁和已安装工具身份，返回能确定的有效值与来源；没有项目时使用明确的片段上下文。目录名、编辑器语言猜测与操作系统默认只是线索，不覆盖显式绑定。配置冲突由相应工具的真实优先级解释，不引入跨所有语言的“最后一项获胜”。嵌套项目、多个运行目标与测试画像分开选择，真正歧义只影响相关动作。

首次选择成熟库时，开发AI先使用当前合法依赖和准确公开合同；新增库的版本、目标支持、许可证/来源、调用形状、效果与维护成本有独立差异。已知名字直接import，不强制生成Adapter。模型给出一个不存在的版本不能成为锁；取得元数据是读取，下载/安装及安装脚本是分开的真实作用。普通阅读或补全不隐含执行包配置、插件代码或生成器。

升级已有依赖采用同一候选：更新真实manifest与锁的相交部分；保留非相交锁项；比较公开接口/行为/许可及目标变化；检查真实消费者、消息、文档和构建成员；再按实际许可取得工具并运行检查。维护同一个依赖解析规则，不能新添“SEC锁”与原生锁各说各话。锁格式、包管理器或宿主不能完成离线解析时，源草稿可以继续，相关构建明确缺输入。

目标选型与优化默认复用当前Binding、布局与既有合格方法。query可解释为何选它、真实代价和可替换的方法；不必每轮跑开放搜索，不用自造百分比分数做推荐。改变默认可能只改变生成字节，也可能改变数值/顺序/错误合同，后二者作为行为变化显示。需要库/语言升级才能支持的构造，不建议用任意cast、删约束或复制库源码来伪装完成。

支持切换工作区/解释版本的客户端，先关闭新工作准入、保留尚在执行的旧操作责任，再按真实来源建立新上下文。新上下文的诊断和补全不能覆盖旧运行来源；不可取得的历史仍准确标缺。离线可用的是已获得、解释相符且仍允许使用的内容；索引缺失可降为直接读源，关键依赖缺失不能偷偷换相近版本。

## 计划、应用与恢复的真实事务边界

编辑面的候选、预览和真实应用必须继续分离。纯 `plan`／dry-run 的实际 Effect 集合为零：它可以解析请求、固定基础、计算候选、预期 Delta、影响、检查义务与资源估计，但不能为了“准备计划”取得写 lease、创建持久 staging/journal、运行安装脚本、修改工作区或启动外部服务。确需保存计划本身时，那是另一个有明确目标和 readback 的写操作。

计划至少绑定本次操作身份、当前候选/源修订、唯一可写 owner、目标和必须保留的条件、预期变化、相交检查、所需 Provider/工具画像以及失效条件。caller、AI 或 UI 可以声明想要的变化，不能提交 path owner、actual Delta、Impact、terminal 或 Verification verdict 等派生事实来扩大权限。

真实应用开始时重新观察当前 source owner、前像、策略、Provider 和权限；旧计划与当前输入不等价就重新计划或阻断。持久写入沿[持久化提交与恢复](../运行/持久化提交与恢复.md)已有的唯一写者、准备记录、lease/fence、staging、CAS、readback 和恢复协议执行，本节不复制第二套事务机。**prepared intent 必须早于该 operation 的第一个耐久写作用**；写后重新构建 actual 状态，再比较 predicted 与 actual，而不是把预览当事实。

开发面必须把下面几种结果分开：

| 结果 | 可以依赖的含义 | 禁止宣称 |
|---|---|---|
| blocked / rejected-before-effect | 当前计划或准入未成立，没有开始对应 live Effect | 永久不支持、目标已经改变 |
| accepted | 目标源/状态已发布，actual 变化和必需 readback/检查闭合 | 所有环境、发行或外部系统都已采用 |
| rolled-back | 精确前像按该操作拥有范围恢复并读回 | 原目标曾经完成 |
| recovery-required / residue | 已有或可能已有 Effect，无法证明 accepted 或精确 rollback | 简单失败、可安全用新身份重试 |

多文件或跨外部系统不能用“部分成功”抹掉真实残余；独立可提交的子组可以分别结算，但每组有自己的 operation identity、前像、终态和 Evidence。journal/恢复记录保存执行事实，不签发新 authority；响应丢失时先按原身份查询、join 或恢复，不能从“文件看起来像目标”倒推历史尝试已经正确执行。
