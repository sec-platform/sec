# AI 自主实现执行蓝图

本文定义参与 SEC 仓库开发的 Agent 的**稳定协议和行为路由**。它不复制具体 Skill、测试矩阵、产品架构或当前状态。

## 1. 上下文与授权顺序

```text
latest main + GitHub facts
→ canonical authority
→ AGENTS.md
→ live document-control resolver
→ selected frozen Work Package
→ one Task Envelope
→ relevant code / tests
→ exact-head Evidence
```

- `main` 是唯一正式工程事实；branch、PR、Issue、聊天、计划、报告和代码图只提供线索或 Evidence。
- 新 Work Package 开始时运行一次 `bun scripts/codex/document-control-plane.ts status --json`。default ref、pointer、manifest 或 GitHub 事实无法解析时 fail closed。
- resolver 未选择 manifest 时不得把 `rolling-plan.md` 的候选当作已授权任务。
- selected Work Package 只授权 declared owned paths、acceptance、tests 和 forbidden boundary；Worker 不能自行扩大。
- 普通任务只读取相关 authority、types、tests 和 source；全仓审计是独立操作，不是默认上下文加载方式。

## 2. 生效模型

| 层 | 载体 | 责任 |
| --- | --- | --- |
| 机器硬合同 | 类型、Schema、parser、validator、tests、Hooks、CI | 拒绝可观察的非法状态 |
| 本次授权 | Work Package / Task Envelope | 冻结 scope、owner、acceptance、tests |
| 行为判断 | 唯一 Skill | 触发、选择、回退、停止、恢复 |
| 稳定事实 | `main` 与 canonical docs | 描述产品和架构 |
| 验证证据 | exact-head Evidence | 证明一次执行结果 |

不能由机器观察的比例、次数或口号不得写成强制 Gate；可以作为 telemetry 或优化目标，但不能替代正确性、scope、authority 和验证证据。

## 4. 单写者与交付状态

- 同一 canonical authority、public contract、state owner、pipeline order 和 active Work Package 同时只有一个写者。
- A0 拥有 integration、Gate custody、merge、readback 和 branch hygiene；Worker 默认停止于提交、Draft PR/update 和 Reconciliation Delta。
- 交付状态必须区分：设计冻结、实现提交、exact-head verification 通过、进入 `main`、merge readback/清理完成、用户可观察能力闭合。
- Squash merge 后按新 `main` tree 和实际结果判断，不按旧 commit ancestry、ahead/behind 或分支名判断。
- 失败后先判定根因、authority 和 Evidence 是否失效；只重跑受 delta 影响的最小验证。新证据推翻 root assumption 时返回上游重算。

## 5. 动态控制面

- `current-state.yaml`：resolver 配置和少量跨候选稳定前提；不维护完整能力清单。
- `rolling-plan.md`：一个当前包和二至五个候选；候选不是授权。
- `active-work-package.md`：唯一 manifest path 与 raw Git blob digest；完整 scope 只在 manifest。
- 新 manifest 原子接管 pointer 后，旧 manifest 才能归档。

本文件不复制具体 repository dispatch payload、Gate 矩阵、命令细节、产品 IR 合同或 Development Run Kernel 内部状态机。
