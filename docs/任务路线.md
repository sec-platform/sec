这是人工维护的任务路线，不定义接口或授权。链接之后需要按实际变更展开完整前提、失败与消费者；不要求每次顺序通读全库，也不把未展示内容删出工程。全体文件及其标题索引见[全库导航](内容索引.md)。

| 第一次进入或恢复旧任务 | [全部取得的要求、根原则、当前采用与未决](维护/设计任务规则.md) | 不要用来源网页或最后一个范本替代用户目标；已有精确版本可以复用 |
| 从产品需求查全工程模块和运行形态 | [总体架构](架构/总体设计.md)及[真实装配](架构/装配/模块与运行实例.md) | 再看开发操作与编译主链，不将目录结构当实际进程部署 |
| 决定一条规则在哪里维护 | [文档责任与跨域信息结构](维护/规格写作与完整性.md) | 理由回D、状态回U、外部支持回研究，实际接口回规范拥有者 |

| 用关键词、关系或AI查全库 | [有覆盖的接入与查询](信息/接入检索与派生.md) | 精确引用先直读；检索只给候选，全量否定另需完备范围 |

| 设计事务、状态、关系、时间或数值计算 | [能力与领域边界入口](作者/需求关系与能力边界.md) | 五个领域拥有者分别定义其语义，不由图灵完备或一个搜索例子代签 |

| 看一次改动从作者到目标再到下一次修改 | [完整工程设计范本入口](../examples/范本角色与原导览.md) | 选相交完整场景，不把代码短例当全系统实现 |
| 判断报告/签名/证明能支持什么 | [保证证据与验收](运行/保证/要求证据与裁决.md) | 核被测主体、方法、版本、环境与覆盖，设计案例不计已运行通过 |
| 发布、保存、失败后查回或清理 | [持久化提交与恢复](运行/持久化提交与恢复.md) | 强内容保留目的在信息存储篇，实际GC/恢复由此篇执行合同负责 |
| 处理秘密、权限、披露和预算 | [权限执行与资源管理](运行/权限与资源管理.md) | 引用/计数/摘要也可能泄露；签名或accepted不能自行扩大Grant |

| 换存储、长期档案、删除和移交 | [保留、删除与恢复](信息/存储保留与恢复.md) | 热度不决定知识效力；普通引用不自动保活，活动恢复不能按缓存删 |
| 选择JSON、计算文本或原生源 | [作者载体与原生接合](作者/可替换表示与适用范围.md#作者载体实现供给与原生工程的选择) | 按内容角色和任务选择，不强制迁写或再造同义算法 |
| 生成图册、全文阅读版或翻译 | [实际阅读构建](维护/阅读构建.md)与[同源派生合同](维护/图表与阅读派生.md#derived-reading-view) | 确有用途才生成；节选与全量分开，不人工双写HTML |
| 继续尚未完成的设计与实现准备 | [原U主登记及全工程前沿](状态/前沿与登记规则.md) | 依真实条件关闭子项；信息整理、目录绿色和案例数量不能关闭全体系 |

## 并发、流、数值和信息的完成边界

要实现子任务及结果回收，读[任务域](领域/计算基础/通用计算与任务语义.md#structured-task-lifecycle)再读[物理接合](架构/装配/能力接合与文件责任.md#completion-physical-seams)。改变数据流并行度，读[顺序与cut](领域/状态关系与流/背压与事件时间.md#ordered-stream-control)；改变微分变换，读[原值与导数故障](领域/数值/自动微分与线性化.md#ad-fault-precedence)。跨源查找用[页组合](信息/接入检索与派生.md#provider-page-composition)，作用响应丢失用[重试依据](运行/持久化提交与恢复.md#attempt-finality-and-retry)。然后沿同一[连续修改范本](../examples/连续开发/全工程连续开发.md#completion-development-change)核消费者，不为每个任务通读无关领域。

## 信息结构连续使用

从[字段冲突到修订、实际实现、测试、旧版本查询、发布、恢复与退出](../examples/连续开发/工程信息全生命周期.md)读一条完整路径。它引用各唯一规范，不再复制字段表；实际产品动作仍是设计。


## 从真实开发动作进入

首次创建/打开、查看动作、普通作者与工程类型入口，先读[完整开发面](开发/编辑审查与客户端.md#developer-surface-contract)。实际一次任务沿[T0—T7](开发/需求到交付主链.md#developer-task-cycle)及[完整源与连续修改](../examples/连续开发/全工程连续开发.md#developer-surface-walkthrough)进入。修改源码能力看[作者服务](作者/组合/结构编辑与身份保持.md#developer-author-services)；测试看[发现到casesRef](开发/测试发现与执行.md#developer-test-selection)；安装/依赖看[环境计划](运行/宿主生态与技术约束.md#developer-environment-setup)；提交/合并看[精确集成](开发/原生维护/导入观察与原生资产.md#developer-vcs-integration)；交互看[进程有限协议](开发/工具协议/交互进程接口.md#process-session-contract)。

真实接入位置见[文件与函数](架构/装配/能力接合与文件责任.md#developer-surface-physical)，实现后检查[DEV01—DEV48](运行/验收/开发面案例.md#developer-surface-acceptance)，仍未完成内容在[唯一前沿](状态/前沿与登记规则.md#developer-surface-frontier)。本导航不复制规则，不要求小编辑每次遍历这条全链。


## 先看需求如何成为最终源码

要判断SEC究竟给产品作者什么，读[当前结构化源码](作者/结构化源码.md)与[实际JSON范本](../examples/结构化工作台/说明.md)。只有选择计算实现或维护供给时，再读[计算表示与实现分工](领域/计算基础/作者表示与实现分工.md)、[完整28模块计算源](../examples/实现校准/内存编辑器计算范本.md)及[记录更新文法](领域/计算基础/文法类型与求值.md#record-update-expression)。表示、供给与开发操作各有用途，不互相冒充完成。

## 完善或实施全部开发面

先读[开发用例范围](开发/需求到交付主链.md#developer-surface-coverage)和[作者角色](作者/可替换表示与适用范围.md#developer-author-roles)，再按实际任务进入[CLI/SDK与编辑](开发/编辑审查与客户端.md#developer-entry-contract)、[辅助协议](开发/工具协议/作者辅助接口.md#authoring-assist-contract)、[未保存源检查](开发/测试发现与执行.md#developer-check-loop)、[协作审查](开发/编辑审查与客户端.md#developer-review-integration)和[交付迁出](演进/开源协作与支持.md#developer-delivery-route)。这些均是同一套正文，普通直接源路径不必依次阅读全部。

[两次完整源码与全工程消费者](../examples/连续开发/全工程连续开发.md#developer-surface-full-session)用于检验能否实际继续开发；[物理接合](架构/装配/能力接合与文件责任.md#developer-surface-physical)用于落到函数/数据；[DF验收](运行/验收/开发面案例.md#developer-surface-cases)是未运行的符合性设计。现有全部U及高级领域的未完成范围保持，不用本导航宣称全产品完成。

## 看完整新工程最终的意图作者源
