# Exact-main retained lease contract repair

MainHealth failed because one source-contract marker still required the V3
owner publication call to declare and assign its result in a single statement.
The production implementation now deliberately declares the typed outcome
before the conditional publication path and assigns it at the same canonical
call site.  This repair parses the production TypeScript and binds the awaited
publication result to its not-published, target-exists, durability-unknown, and
system-code control flow.  A variable rename remains valid; comments, copied
strings, or removal of an executable guard cannot satisfy the contract.

The failed MainHealth observation is reused during authoring.  The candidate
runs the exact failed contract and a focused workflow-join sentinel while the
tree is changing, then runs the selector-derived affected closure once after
the final tree is frozen.  No unchanged Linux MainHealth replay is part of the
edit loop.  One exact-new-main MainHealth is required only after merge.
For Bun authoring sentinels, `--filter` precedes the one exact test file; any
accidental wider invocation is stopped and excluded from verification evidence.
The committed exact-head affected check explicitly binds
`SEC_AFFECTED_TESTS_BASE=95fb5d1deb773c3f2f7663997455cd06363557be`; ambient
no-base discovery is a working-tree authoring mode and its empty result is not
accepted as final candidate evidence.

The first hosted attempt also exposed a provider-shape defect: GitHub returns
the evaluated `run-name` in the REST `name` field, while the join logic treated
that field as a fixed workflow identifier.  Workflow authority now comes from
the exact workflow path, event, title, and main SHA; mutable UI naming cannot
create or reject authority.  Independent Review then found the same stale name
check throughout downstream Session, Action, MainHealth, and Integration
consumers.  A shared pure predicate now owns this identity rule; every TypeScript
consumer calls it, the YAML integration gate enforces the equivalent immutable
workflow-path check, and focused real-shape fixtures use GitHub's evaluated
presentation name while rejecting path, event, title, and head substitutions.

Because the provider adapter is part of the trusted causal closure, its byte
change invalidates the prior TCB lock.  The lock is regenerated only by the
canonical `tcb-closure-lock apply` command and then verified in `check` mode;
the manifest owns the generated lock, not handwritten digest maintenance.

Performance and lifecycle observations found during this repair remain routed
to their existing owners instead of expanding this package: #316 owns the
long document-control closure and Docker dependency-cache critical path; #271
owns ignored generated-state settlement; and #186 owns the detached scratch
worktree closeout that those ignored directories currently block.  The local
provider image is retained across stops, but container-local
`~/.bun/install/cache`, `/tmp/sec-hosted-dependency-home/.bun/install/cache`,
and `_work` are ephemeral until #316 supplies an identity-bound persistent
cache design.
