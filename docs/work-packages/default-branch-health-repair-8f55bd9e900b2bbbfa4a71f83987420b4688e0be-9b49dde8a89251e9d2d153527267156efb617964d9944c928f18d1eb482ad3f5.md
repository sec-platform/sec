# Observed process target-Windows path and impact-closure repair

The automatic MainHealth run for `main@8f55bd9e900b2bbbfa4a71f83987420b4688e0be`
completed checkout, installation, import organization, TypeScript and documentation authority before the
fast inventory exposed one deterministic cross-platform lifecycle defect. The shared observed-process
terminator selected its Windows algorithm from an injected target runtime, but constructed the Windows
`taskkill.exe` command and working directory through the ambient host `node:path` dialect. A Linux
host therefore produced a mixed-separator Windows path even though the declared target was `win32`.

This repair binds Windows helper paths to `path.win32` inside the already unique Windows termination
branch and extends the existing lifecycle regression to observe both the executable and working
directory. It does not create a second path adapter, move termination into AppContainer, accept the
mixed path, trust caller environment as executable authority, or change any public lifecycle schema.
The existing graceful-first, bounded-force, Job-controller and stream/tree-settlement mechanisms remain
the only process termination algorithm.

The same vertical slice closes the previously validated direct-consumer gap. The
`observed-process-lifecycle` declaration currently disables the repository's existing reverse-import
selection and consequently omits two fast tests that directly import the changed shared source. The
repair restores that canonical fail-closed mechanism so future direct static consumers are selected by
the import graph instead of another hand-maintained list. This test-impact rule is a trusted static
directory, so its exact generated TCB closure is updated and the candidate deliberately follows the
trusted bootstrap boundary. AppContainer production, native helper, workflows, dependencies, ordinary
work selection and the broader performance roadmap remain outside this package.

The first affected execution then exposed two deterministic default-branch defects that the original
MainHealth fail-fast position had hidden. The gate execution test still treated retired logical
Work Package paths as their physical Git blob locations even though the immutable bytes had already
moved to test fixtures. Independently, an August canonical-primitives refactor changed the byte
serialization behind already published Semantic Mutation recovery and nested revision domains without
changing their versions. This replan keeps the same package, branch and worktree, maps logical identity
to the existing fixture source, and restores the frozen Semantic Mutation digest at its local owner.
It does not rewrite retained journals, broaden the global digest primitive, accept mixed digest
families under one version, or create another repair generation.
