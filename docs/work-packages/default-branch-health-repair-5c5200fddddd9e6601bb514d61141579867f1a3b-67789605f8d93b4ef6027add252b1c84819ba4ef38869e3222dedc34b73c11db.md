# Local Linux verification runner repair

The exact merged MainHealth check never acquired a GitHub-hosted runner because
the account has no usable hosted Actions allocation.  Registering an isolated
repository self-hosted runner with the same `ubuntu-24.04` label proved that the
single hosted label is provider-routed and cannot transparently consume local
capacity.

This repair moves the physical Linux compute for every required SEC workflow
onto one bounded, repository-scoped three-role local provider while retaining GitHub only as
the existing dispatch, App identity, check and collaboration projection.  The
runner lifecycle is versioned and reproducible, credentials never enter the
image, command line or durable state, and no container has host or Docker
control mounts.  Control, trusted readback and candidate SUT are separate trust
domains under one atomic provider lease, so the coordinator cannot deadlock its
executor and SUT bytes cannot poison trusted evidence.  This is the minimal bridge that removes paid hosted compute
from the critical path; the longer-term capability-delta Evidence plane remains
owned by Issues 179, 188 and 316 rather than being duplicated here.

After the new route produces a healthy exact-main ledger, the package resumes
the already durable Issue 186 operation and settles both remaining Issue 186
local branches through their canonical physical-then-ref dependency order.
