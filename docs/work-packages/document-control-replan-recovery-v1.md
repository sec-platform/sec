# Work Package: Document Control Replan Recovery V1

This package repairs the single document-control transaction rather than adding
another candidate manager. Recovery namespace identity becomes
`operation identity + logical target key`; physical paths and retained object
handles remain effect-time safety preconditions, never semantic identity.

The Git index is split the same way. Its stage-zero tree is the semantic
candidate identity. Raw index bytes remain durable transport material only
while an interrupted publication must be resumed. Equal control bytes and an
equal index tree are true zero-publication outcomes. The equality decision is
made before the candidate-index builder; a real delta hashes only changed
control blobs and publishes their index-info records in one batch.

The terminal journal is a temporary recovery authority. Once exact candidate
tree, manifest, pointer, rolling plan, Git index and worktree readbacks have
closed, every known recovery object has zero consumers. The writer then retires
the closed exact census, tolerates only a prefix of its own already-completed
deletions on resume, proves each retired namespace absent and parent-durable,
removes the journal last with the same barrier and removes the empty dedicated
transaction directory. If a crash lands between those last two effects, only
that exact empty directory is a valid journal-less suffix; a nonempty directory
has no deletion authority. Unknown bytes, names, identities or topology remain
preserved and blocking.

The pre-existing V3 terminal artifact used to activate this package is a
one-time migration input at its already-bound location. It is retired under a
closed legacy census before the final V4-only implementation is frozen; V3 is
not retained as a production reader, writer, relocation promise, alias or
fallback.
