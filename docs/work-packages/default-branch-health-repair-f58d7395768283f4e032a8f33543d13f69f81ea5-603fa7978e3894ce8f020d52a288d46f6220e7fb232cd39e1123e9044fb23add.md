# Exact-main fast-process policy closure repair

MainHealth did not expose a Linux product defect. It exposed a missing causal
edge in local affected selection: changing a test ran that test, but did not
run the global scheduler invariant that decides whether the test may share a
Bun process. The changed physical-no-follow test introduced deterministic
Linux race fixtures that mutate process environment variables, so the global
census correctly rejected the absent process-isolation registration.

The repair closes three layers together. First, the current hazardous test has
one typed independent-process registration. Second, changes to the scheduler
policy select its executable consumer test through the unique dev-runner
impact owner. Third, every raw fast-test delta selects the same policy census,
including deleted tests that are no longer runnable. This makes the invariant
fail in the local affected loop within seconds instead of waiting for a full
exact-main MainHealth run.

The invariant remains explicit rather than silently rewriting policy. A test
that introduces process-global state must declare its isolation class; the AST
census supplies the exact file and hazard kind when it does not. This preserves
typed resource scheduling and makes an unsafe omission mechanically
unmergeable without adding a broad suite to every edit.

Authoring reuses the failed exact-main observation and runs only the two
focused sentinels while bytes change. The canonical affected closure runs once
after the tree is final, followed by independent exact-head Review. Only the
merged new main receives one MainHealth run on the already-active local Linux
provider, preserving its image and warm container caches throughout repair.
