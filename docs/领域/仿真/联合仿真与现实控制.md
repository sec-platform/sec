# 联合仿真与现实控制

联合模型结果、参数估计、影子运行和真实控制是不同用途。仿真部分由实际模型/方法实现；真实操作仍进入原[执行与结算协议](../../运行/持久化提交与恢复.md)，时限由原[资源与准入](../../运行/权限与资源管理.md)承担，不新建设备权限入口。

<a id="cosimulation-coupling"></a>
## 联合仿真的耦合、守恒与误差闭环

联合仿真连接需明确每条边交换的是状态、流量、势量、累计量、事件还是控制命令，单位、方向与参考框架各自固定。力与速度的相容配对可以表示机械功率；热流率积分才对应交换热量，温度通常进入本构/边界条件，不能将温度与热流率的乘积冒充功率。交换方向、面积及符号必须与具体接口一致，不能只因两个值都是float就相连。守恒应检查正确的物理总量与边界通量，而非要求每个中间数值都不变。

主算法固定通信点、输入保持/插值、事件同步、代数依赖、收敛判据、拒步与回滚路线。存在代数环时，只有有实际可迭代接口、收敛依据和状态恢复，才允许重复步或求不动点。一个子模型不能回滚却被当可回滚求解器调用，会产生静默错误；可选非迭代路线需要原任务接受其误差，不能无条件替换。

误差验收不只有单体求解器的容差，还要考虑采样、通信、耦合延迟、插值、离散化、参数和模型误差。至少通过相交的通信步/网格变化、守恒残差和独立小例检查；有强非线性、刚性或不连续切换时不能直接外推平滑区间的误差界。某些稳定性条件依赖耦合步，改并行调度也可能改变它。

多尺度模型应显式说明快慢变量交换与平均化前提。低保真代理替换高保真模型时，适用域、边界行为、罕见事件和置信/误差资格必须随路线带入；代理在已知数据上准确，不证明对新工况安全。动态切换保真度必须迁移模型状态，并重评控制/优化消费者的假设。

实验失败应保留最后接受步、每个模型的准确状态切面、拒绝原因、资源消耗与可恢复范围。不能把一个求解器的终态同另一个的旧中间态混成“联合结果”。分项成果仍可用于诊断，但整体用途保持未通过。

**适用范围：**耦合算法是实际方法，不由接口标准或命名推得。

**重新检查条件：**耦合拓扑、通信步、同步方式、状态映射或代理域改变。

<a id="real-control-response-boundary"></a>
## 真实控制、运行假设监测与安全响应期限

将离线模型接到真实控制之前，需要区分模型内可测试假设、在线可观察假设和无法及时观察的现实条件。监测器可以发现某些条件不再成立，但不能因此宣称全部模型前提实时成立。未测量的状态、传感盲区和数据延迟保持未知，不能由模型预测代填。

对需要在危害发生前响应的保护，必须有检测延迟、传输与调度、动作完成时间及剩余安全裕度的有依据界。设这些真实上界合计为τr，当前模型支持的最早失控时间下界为τh；只有原条件下τr小于τh且保护动作本身有效，才可能支撑该及时性要求。这个条件不是通用安全证明：边界模型、故障检测和执行器失效仍需独立依据。没有这些界就只能提供监控功能，不能承诺硬实时防护。

当前授权、设备身份、配置和安全互锁在真实执行入口检查，探索性仿真与影子模式不得持有能产生现场动作的能力。控制任务错过期限时不能默认补跑所有过期输出；按项目合同丢弃、保持、受控降级或转交安全控制。设备停止、保持扭矩、释放制动和持续冷却是不同动作，不能统一为一个stop布尔。

运行时适应只在已接受的包络内切换：允许替代方法、观测前提、状态迁移、资源、deadline和退出路径必须同时具备。选择器本身有错误/延迟与权限，不能因被称为“智能”就越过原约束。迁移失败时保留旧可用路线或进入准确降级，不在新旧控制同时活跃时制造双写。

监测与动作可能共享电源、网络或传感器；保护系统也需要故障域分析。人工接管需要真实可理解的信息、足够时间、可用操作员和接管资格；一条告警已发送不等于人已完成接管。

**适用范围：**具体危害边界、专业模型、硬件时序和安全态由项目及适当主体确定。

**重新检查条件：**控制域、环境、传感时效、保护动作、实时上界或接管组织条件改变。

验收的具体触发与观察见[全域接合检查](../../运行/验收/全域接合检查.md)；这里定义机制与条件，不签发任何实现、执行或现场合格状态。
