# 仿真时间推进与状态恢复

模型、场景、时间、方法、资源、观察与现实效果分别拥有状态。本篇细化[计算结构与算法](../计算基础/计算结构与算法.md)的仿真区域；事件、方程和随机方法保持自己的语义，统一编译器不成为万能仿真运行时。

<a id="simulation-progress-and-checkpoints"></a>
## 仿真内核族、时间推进与并行事件提交

仿真最小可消费边界包括模型/场景、初态与边界、输入输出、时间和事件语义、状态拥有者、推进方法、停止条件、观察、错误与恢复资格。数值积分、事件日历、约束求解、状态空间探索和群体更新分别拥有具体进展规则。统一实验组织可以安排它们，但不能替它们决定一个步长或一条更新顺序。

连续求解器需区分接受步、拒绝步、事件定位、模型终止与数值失败；离散事件需区分时间、阶段与同刻优先；同步离散系统明确旧值同步更新还是顺序更新；非因果方程先由合格方法得到因果计算安排，不能按源码排列替代求解。未取得一致初态时保留失败，不把所有变量设0。

并行离散事件有保守推进与乐观推进两种实际路线。保守路线需要已知不会有更早事件到达的安全前沿及进展条件；乐观路线需要可恢复状态、消息撤回或等价协议、真实全局提交前沿和足够历史预算。没有这些能力就不能因可并行而宣称可回滚。未提交模拟事件不得触发真实设备/资金；历史回收不能越过仍可能收到回溯事件的范围。

每次检查点区分进程局部句柄、可序列化模型状态、求解器内部历史、随机流、事件日历、通信消息和外部世界的已提交效果。序列化必须绑定格式/方法/模型修订；单纯保存可见变量可能不足。FMI 3.0.2明确将延迟缓冲及内部状态纳入完整FMU状态，并由实际支持能力控制取/设/序列化；其同一实例函数也不默认线程安全。[Functional Mock-up Interface 3.0.2](../../依据/来源/全域组合与仿真依据.md#functional-mock-up-interface-302)

实验可以在不同核数和分区下运行；若承诺位级重放则排序、归约、随机和事件竞争都需满足相同观察合同；若只承诺统计一致性，应按对应分布与误差检验。不能将因分区引入的人工顺序效应解释成被研究系统的真实规律。

**适用范围：**接口投影沿现有方法与资源合同，不新建所有项目必须加载的Simulator。

**重新检查条件：**模型事件语义、并行策略、通信前沿、内部状态可恢复性或确定性要求改变。

验收的具体触发与观察见[全域接合检查](../../运行/验收/全域接合检查.md)；这里定义机制与条件，不签发任何实现、执行或现场合格状态。
