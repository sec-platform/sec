# 仿真时间推进与状态恢复

模型、场景、时间、方法、资源、观察与现实效果分别拥有状态。本篇细化[计算结构与算法](../计算基础/计算结构与算法.md)的仿真区域；事件、方程和随机方法保持自己的语义，统一编译器不成为万能仿真运行时。

<a id="simulation-progress-and-checkpoints"></a>
## 仿真内核族、时间推进与并行事件提交

仿真最小可消费边界包括模型/场景、初态与边界、输入输出、时间和事件语义、状态拥有者、推进方法、停止条件、观察、错误与恢复资格。数值积分、事件日历、约束求解、状态空间探索和群体更新分别拥有具体进展规则。统一实验组织可以安排它们，但不能替它们决定一个步长或一条更新顺序。

连续求解器需区分接受步、拒绝步、事件定位、模型终止与数值失败；离散事件需区分时间、阶段与同刻优先；同步离散系统明确旧值同步更新还是顺序更新；非因果方程先由合格方法得到因果计算安排，不能按源码排列替代求解。未取得一致初态时保留失败，不把所有变量设0。

并行离散事件有保守推进与乐观推进两种实际路线。保守路线需要已知不会有更早事件到达的安全前沿及进展条件；乐观路线需要可恢复状态、消息撤回或等价协议、真实全局提交前沿和足够历史预算。没有这些能力就不能因可并行而宣称可回滚。未提交模拟事件不得触发真实设备/资金；历史回收不能越过仍可能收到回溯事件的范围。

每次检查点区分进程局部句柄、可序列化模型状态、求解器内部历史、随机流、事件日历、通信消息和外部世界的已提交效果。序列化必须绑定格式/方法/模型修订；单纯保存可见变量可能不足。FMI 3.0.2明确将延迟缓冲及内部状态纳入完整FMU状态，并由实际支持能力控制取/设/序列化；其同一实例函数也不默认线程安全。[Functional Mock-up Interface 3.0.2](../../依据/来源/全域组合与仿真依据.md#functional-mock-up-interface-302)

实验可以在不同核数和分区下运行；若承诺位级重放则排序、归约、随机和事件竞争都需满足相同观察合同；若只承诺统计一致性，应按对应分布与误差检验。不能将因分区引入的人工顺序效应解释成被研究系统的真实规律。

**适用范围：**接口投影沿现有方法与资源合同，不新建所有项目必须加载的Simulator。

**重新检查条件：**模型事件语义、并行策略、通信前沿、内部状态可恢复性或确定性要求改变。

验收的具体触发与观察见[全域接合检查](../../运行/验收/全域接合检查.md)；这里定义机制与条件，不签发任何实现、执行或现场合格状态。


<a id="simulation-model-values"></a>
## 模型、场景与推进的普通有类型边界

模型由普通名义record/variant、共同TypeTerm、Expr及准确函数引用定义；不要求Model一律为DefinitionRef，不新增通用引用role。定义模型、构造场景、传递模型与运行推进是不同阶段。配置构造不分配求解器实例、事件cursor、随机流或设备，纯构造不执行advance。实际模型/函数/codec修订由源与绑定依赖取得，不让作者另填可信revision字符串。

```text
TimeDomain<T> = nominal record {
  compare:(T,T)->Int !{}, distance:(T,T)->Result<F64,SimulationError> !{}
}
SimulationError = InvalidModel | InconsistentInitialState | MissingHistory
                | NumericFailure | NoProgress | UnsupportedRecovery
                | BudgetExceeded | Cancelled
CheckpointCodec<S> = nominal record {
  encode:(S)->Result<Bytes,SimulationError> !{},
  decode:(Bytes)->Result<S,SimulationError> !{}
}
Step<S,O,T> = Accepted { state:S, time:T, output:O }
            | Rejected { retryState:S, proposedTime:T }
            | Terminated { state:S, time:T, output:O }
Model<S,I,O,T> = nominal record {
  time:TimeDomain<T>,
  initialize:(I)->Result<S,SimulationError> !{},
  propose:(S,I,T)->Result<Step<S,O,T>,SimulationError> !{},
  observe:(S)->Result<O,SimulationError> !{},
  checkpoint:Option<CheckpointCodec<S>>
}
Scenario<S,I,O,T> = nominal record { model:Model<S,I,O,T>, input:I, until:T }
initialize<S,I,O,T>(scenario:Scenario<S,I,O,T>) -> Result<S,SimulationError>
advance<S,I,O,T>(model:Model<S,I,O,T>, state:S, input:I, until:T)
  -> Result<Step<S,O,T>,SimulationError>
```

T是所选模型的名义时间类型，不自动等于墙钟或帧数；compare必须给同一时间域的总序，distance的尺度由该域固定。I包含真实所需初始/边界与历史输入，S包含本方法恢复所需的完整模型、求解器、随机和事件状态；局部不可序列化句柄不伪装为Bytes。检查点启用还需encode/decode保持同一模型/方法/格式下的恢复关系，Option有值只是声明能力，不证明已符合。序列化结果的解释身份由外层实际制品/模型绑定保留，不裸存一份无法解释的字节。

Accepted/Terminated状态可成为接受切面，Rejected只能保留该路线合同允许的retryState，不能输出为成功步；所有候选运行资源仍按真实最后使用结算。until不是保证在预算内到达，数值故障、无进展、预算和取消不作为数学无解。上述纯函数是显式状态的纯方法画像；函数本身或捕获环境不因纯度自动可序列化，跨进程交付须保留准确代码/静态绑定，checkpoint只编码其S而不偷偷序列化闭包。必须有活跃求解器或设备的供给经原运行资源边界接合，不冒称纯Model函数，仍可满足同一逻辑推进合同。

非因果声明采用普通`EquationModel<X,DX,R,T>={residual:(X,DX,T)->Result<R,SimulationError>, initial:(X,DX,T)->Bool, time:TimeDomain<T>}`；函数字段均为纯函数。X是状态，DX是该坐标与时间域下的时间导数类型，R是联立残差的准确名义记录/容器型，三者独立绑定。例如位置m的时间导数为m/s，不能因内存同为F64就把DX写成X。R的每个分量保留自己的单位/尺度与方程对应，残差成立判据由实际方程Rule与方法解释；不假定不同量纲分量都可用同一F64阈值比较。initial约束同一x、dx、t切面，不用初始化x成功代替一致导数。残差向量是同一联立关系，保留位置/重数与方程来源，**不是按数组顺序逐个运行的赋值程序**。一致初值与DAE因果安排由选定方法求解；缺方法保留模型与义务，不强迫作者改写手工推进算法。

Rule通过kind:value字段接收该Model/Scenario值，真实资源与现实对象通过独立subject字段绑定；Rule正文承担时间、正常进展、停止、观察与结果接受合同。任务引用该规则与输出根，流端消费实际Accepted输出并保留T和缺样含义，不能把静态forEach当无限推进。改模型函数、初值/历史、time、事件次序、方法或codec时重核相交解析/求解/恢复与目标资格；旧运行和旧检查点继续绑定旧解释，新源码不热改旧实例。
