## 需求未决定实现时怎样工作

```sec
export fn estimate(total: Int) -> Int
  require total >= 0
  ensure 0 <= result && result <= total;
```

没有函数体的声明可以保存、导出设计或用于比较候选。这些条件没有唯一决定实现。下一步是补行为体或选取可检查的实现绑定；不是编译器任选一个返回值，也不要求先完成所有其他不相干定义。

仅含签名不具备的效果继续未知。纯度、输入域非空、终止和业务满足是不同判断。类型检查可以得到有限结构结论；生成所选输出时必须检查它的真实调用闭包。未使用的独立要求可以保留为设计，不能用一个未完成声明让全工程所有任务失败。


## 工程画像与基础语言的明确组合

[事务应用与交付作者规格](../状态关系与流/事务与交付.md)定义`sec.transaction/1`，显式继承本章`sec.semantic/1`。同一份导入、类型、表达式、函数调用、契约与诊断规则继续使用，不再创造另一种TS元编程语言。画像增加aggregate/decision/operation/subscription的上下文声明；基础全局保留词集合不因该领域声明而扩大；当前基础文法已经包含记录更新，共46项产生式。领域上下文声明与基础扩充都有独立解析成本，不能声称整个工程画像没有新增作者语法。

纯函数/类型模块可以同时被基础和工程画像消费；工程声明模块必须由明确支持该画像的读取器处理。导入不自动激活新语法、不执行模块、不取得端口权限。当前语言环境的组合版本固定在输入/锁中；对同名语法、类型或扩展解释冲突直接诊断，不以加载顺序选择。

只选择纯decision或其他纯函数输出时，未选存储与订阅不成为运行前提；选择含operation/subscription的可运行应用时，其策略、存储、编码和端口必须完整绑定。语言检查通过仍只表明所检查的语义，不能代替端点实际支持。

目前已具体化的是命中政策、单根create/update/delete、同事务记录和事件订阅。基础函数不等待这组实现；需要持久闭环的任务也不能以纯状态函数代替。有限层级状态、关系、本地流和微分已有各自规范，更广跨源、时间与数学范围仍按具体义务扩展，不由事务四类声明吞并。

## 普通工具和计算软件不以事务画像为前置

基础函数、模块、契约和效果可以构造完整计算程序，而不只是演示。网格、稀疏结构、求解和流的高层接口按真实库/画像绑定进入，目标实现可以使用受检的局部可变缓冲和并行，不要求作者把每个元素转换成工程实体。[计算结构与算法实现设计](计算结构与算法.md)提供现有文法下的完整网格例、有限库合同、算法与调度分离和连续变更。

该例没有增加保留词；`grid`是显式导入别名，`Grid/Shape2/Index2/Border`及五个调用由具体库合同定义，不是本包已经发行的能力。把一个普通计算库加入当前作用域不激活`sec.transaction/1`。没有真实时间/浮点/资源画像支持时，不因写出一个名字就获得那些语义。

本章默认不可变是作者可观察的值模型，不是禁止所有目标使用可变内存的指令。计算域的依赖、内存与数值必须保留；事务示例不是全部软件的骨架，发布口径按实际任务区分。


## 基础文法不是全部语言能力的控制上限

当前18个保留词、opaque修饰和已有产生式描述一个具体中立基础，并不证明已经覆盖所有源语言的能力，也不要求将各语言词表取并集。语义和意图在确定时可以是同一份作者内容；没有必要为了叫“意图”额外包装一个字段或关键词。

对不同语言的实际能力，按[语言能力映射与最小控制](../../作者/需求关系与能力边界.md)逐项说明公共含义、源/目标专有含义、作者入口、转换、保全和支持状态。类型、对象、异常、内存、并发、元编程、初始化和非源码属性均需要研究。不能因基础文法暂不含class就把目标class控制永久推给原生作者；也不能声称一个record已经完整表示了对象继承和反射。

普通源先表达需要保持的行为与合同；编译器对已委派的具体实现自由作合法选择。源码中的SEC库导入选择复用定义，不必点名目标npm/Maven/系统库。精确目标结构或实现限制使用稀疏的类型化控制，并与作者源同一候选维护。控制draft的字段、解码、实际消费者与产物核对须同时满足；仅有可序列化对象不证明目标已经执行控制。

原生源的关键词和语义按其真实语言保全；跨目标转换可以一对多、多对一，但保持所要求的观察。要求原文往返时还要保留具体语法、注释和未理解资产；仅生成等价行为不能冒称逐字还原。完整工程文件按资产合同管理，不要求都成为语言声明。


## 有限关系库与基础类型的接合

[关系查询](../状态关系与流/关系查询与维护.md)使用现有函数、块、记录、lambda和导入。`Bag<T>`与`Ordered<T>`是库抽象值，不是新增内置关键字。运行输入尚未赋值可以正常生成；纯关系构造也不触发数据库读取。

具体有限类型可从既定相等、排序和编码派生ValueOps；一般泛型或opaque值必须通过已定义的With入口传递有类型见证。不能把某次Int实例成功当作所有T都合法，也不能让一个忽略大小写的字典擅自合并仍可观察不同的Text值。普通代码中的相等规则不由导入库改写。

库的Bag输出不承诺列表顺序，错误参照仍有确定次序。`filter`回调为空效果不证明总定义；`take(...,0)`的上游是已经严格求值的参数。SQL下推、增量配对和并行只能在相应保持条件成立时改变求值，不为实现方便改变基础短路、错误或契约。库发布与实现范围仍独立于这份规格。


## 选定领域画像与基础文法的边界

语言选择统一由[默认组合](紧凑表示与程序范式.md#合同标识默认语言组合与按需能力)负责，领域章节只定义自身语义和语法增量。新通用工程已经具备有限对象语法；原基础专用模块继续使用原解释，两个版本不通过普通import切换。基础EBNF仍为基础子集的唯一文法，组合的读写规则明确包含对象增量，而不是宣称原文法已自动覆盖class。

[本地流](../状态关系与流/背压与事件时间.md)、[关系](../状态关系与流/关系查询与维护.md)、[状态](../状态关系与流/层级状态与事件.md)以普通库构造保存各自含义；[微分](../数值/自动微分与线性化.md)的F64和Space不会重载原Int。库有接口、方法有实现、目标能保持和运行有权限分别判断。更广对象、分布式时间或微分数学只有在实际支持表中明确承诺时才纳入；它们不阻塞不相交工具的实施。
