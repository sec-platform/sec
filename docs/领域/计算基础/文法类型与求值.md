# 文法类型与求值

> **阅读范围**：计算语义与可选文本接口；不是主面前置 · [共同上下文](../../作者/可替换表示与适用范围.md)。


## 语言无关的作者合同与当前规格

### 主线、草案版本与适用范围

`sec.semantic/1` 是已有共同计算语义合同；选择其文本前端时使用 `.sec`，不是全部产品作者文件的默认扩展名。它定义值、类型、调用、契约、效果与绑定，不以 TS／Java 的 AST 或运行库为公共含义。TS 当前作为实现工具、输出和原生维护的重点；实际选择第二目标后，才使用同一冻结语义校准，不把它作为TS可用的统一前置。原生区域分别保留真实语言；其他作者前端的采用条件由当前基线与 D02 维护。

协议草案号不是“实现已符合”的证据。基础产生式与消歧以本节为准；若以后发现实际采用者依赖另一种解释，按真实前像做兼容裁决，不以“补文档”为名静默改其含义。规范内部的数据结构、论文示意、历史参考子集与此作者文法不混用。

这里的基础文本覆盖纯值、显式函数、局部不可变绑定、列表/记录/和类型、条件、匹配、递归、契约和有类型端口。可变状态、资源借用、异步/流、时间与概率等已有领域设计仍保留，但只有其扩展解释被显式选择且实际受支持时进入对应作者域。基础文本不假装已经实现全部高层领域语法，也不阻止用已有构造直接定义新算法。

### 语法词形、库词汇与任务负担的计量口径

基础的18个保留词不是当前通用环境的全部语法词汇。通用环境还包含`opaque`，对象构造`class/interface/init/new/this/super/var/set/override/static/final`，以及`while/break/continue/return`。按这组明确范围去重为34个语法专用词形，其中有全局保留词和上下文构造，不将它们全部误称为全局保留字。选定的事务等其他扩展另按其真实范围计算，普通类型名、库函数、字段与工具名不计入词法集合。

这个有限数目不能证明语言简单，也不是永久配额。新增函数/算法/领域组合通常扩展库内容，不改词法；新增真正的绑定、控制或作用构造则同时承担解析、类型、执行、目标与编辑责任。语言规则、库语义、目标控制和作者一次任务所需知识分别衡量，不能通过挪到函数名或JSON字段掩盖负担。普通函数库定义如maxByKey可表达复用的关系，但仍须完整语义与实现；不从“不新增关键词”直接推导“已简化”。

### 固定词法与阶段

基础专用解释的保留词为18个：`import as export type fn let if then else match case require ensure result port bind true false`。类型、构造器、普通函数、业务名字和六个工具名不是关键词。库增长不改变这份词法表。

文本采用UTF-8；标识符以ASCII字母或下划线起始，后续为字母、数字或下划线，单独的 `_` 仅作模式通配符。显示名称可以是Text。空白为SP、HT、CR、LF；CRLF作为一次换行定位，原始字节另行保全。`//` 到行末为注释，字符串内不生效。最长合法词法单元优先，`!=` 不拆成两个符号；`<`、`>`逐个计为标点，不引入移位运算符。

整数文本为十进制 `0` 或非零数字后接数字；负号是一元运算，`-0` 的Int值就是0。基础文本不接受浮点字面量、`n`后缀、数字分隔符或暗示目标宽度的后缀；更强数值画像采用自己的明确构造。字符串用双引号，允许 `\\`、`\"`、`\n`、`\r`、`\t`、`\u{1至6位十六进制}`，转义结果必须是Unicode标量；不接受代理码位、越界码位和未经转义的控制字符。字符串没有模板插值或隐式规范化。

`()` 是Unit唯一的字面量；`{}` 是空记录，不是Unit或空代码块。定义、导入、端口、绑定和匹配分支以分号结束；块最后的表达式给出块值。源可不完整地保存为草稿，解析失败不能被格式化成另一段合法程序。

读取声明、静态绑定求值、目标执行是不同阶段。顶层 `let` 是预算内静态纯值或被动构造的函数值，不执行函数体；函数体中的 `let` 在该函数运行时求值。导入不执行目标模块、联网、安装包或读取宿主环境。

### 闭合结构文法

以下是基础文本的文法设计，不是已实现解析器。`Ident`、`String`、`Integer`采用上述词法；方括号和花括号在EBNF中表示可选与重复，带引号的标点才是作者文本。`StaticExpr`与`BindingExpr`先按同一Expr解析，再按后述阶段和类型规则限制，不留给实现者另创一个可执行脚本语法。

```ebnf
Module       = { Import | TypeDecl | Function | PortDecl | BindDecl | ConstDecl } ;
Import       = "import" String ["as" Ident] ";" ;
TypeDecl     = ["export"] ["opaque"] "type" Ident [TypeParams] "=" DeclType ";" ;
DeclType     = SumType | Type ;
Function     = ["export"] "fn" Ident [TypeParams] "(" [Params] ")"
               (["->" ReturnType] [Effects] {Pre} {Post} "=" Expr ";"
               | "->" ReturnType [Effects] {Pre} {Post} ";") ;
Pre          = "require" Expr ;
Post         = "ensure" Expr ;
PortDecl     = ["export"] "port" Ident ":" "(" [TypeList] ")" "->" ReturnType Effects ";" ;
BindDecl     = "bind" QualifiedName "=" BindingExpr ";" ;
ConstDecl    = ["export"] "let" Ident [":" Type] "=" StaticExpr ";" ;
TypeParams   = "<" Ident {"," Ident} ">" ;
Params       = Ident ":" Type {"," Ident ":" Type} ;
Effects      = "!" "{" [QualifiedName {"," QualifiedName}] "}" ;
TypeList     = Type {"," Type} ;
QualifiedName = Ident {"." Ident} ;
Type         = FunctionType | RecordType | NamedType | GroupedType ;
ReturnType   = RecordType | NamedType | GroupedType ;
GroupedType  = "(" Type ")" ;
NamedType    = QualifiedName ["<" TypeList ">"] ;
RecordType   = "{" [Ident ":" Type {"," Ident ":" Type}] "}" ;
FunctionType = "(" [TypeList] ")" "->" ReturnType [Effects] ;
SumType      = Variant {"|" Variant} ;
Variant      = Ident "(" [TypeList] ")" ;
Expr         = Lambda | LetExpr | IfExpr | MatchExpr | UpdateExpr ;
UpdateExpr   = OrExpr ["with" "{" Ident ":" Expr {"," Ident ":" Expr} "}"] ;
Lambda       = (Ident | "(" [Params] ")") "=>" Expr ;
LetExpr      = "let" Ident [":" Type] "=" Expr ";" Expr ;
IfExpr       = "if" Expr "then" Expr "else" Expr ;
MatchExpr    = "match" Expr "{" CaseArm {CaseArm} "}" ;
CaseArm      = "case" Pattern "=>" Expr ";" ;
Pattern      = "_" | "()" | ["-"] Integer | String | "true" | "false"
             | "[" "]" | "[" Ident "," ".." Ident "]"
             | QualifiedName "(" [Pattern {"," Pattern}] ")" | Ident ;
OrExpr       = AndExpr {"||" AndExpr} ;
AndExpr      = CompareExpr {"&&" CompareExpr} ;
CompareExpr  = AddExpr [("==" | "!=" | "<" | "<=" | ">" | ">=") AddExpr] ;
AddExpr      = MulExpr {("+" | "-") MulExpr} ;
MulExpr      = PrefixExpr {("*" | "/" | "%") PrefixExpr} ;
PrefixExpr   = {"!" | "+" | "-"} PostfixExpr ;
PostfixExpr  = Primary {"." Ident | "(" [Arguments] ")"} ;
Arguments    = Argument {"," Argument} ;
Argument     = [Ident ":"] Expr ;
Primary      = Integer | String | "true" | "false" | "result" | Ident
             | "(" [Expr] ")" | RecordValue | ListValue | BlockExpr ;
RecordValue  = "{" [Ident ":" Expr {"," Ident ":" Expr}] "}" ;
ListValue    = "[" [Expr {"," Expr} ["," ".." Expr] | ".." Expr] "]" ;
BlockExpr    = "{" {"let" Ident [":" Type] "=" Expr ";"} Expr "}" ;
StaticExpr   = Expr ;
BindingExpr  = Expr ;
```

消歧规则也属于规范。`{}`优先且仅为空记录；非空`{`后以`Ident :`开头的是记录值，其余必须是带结果的块。需要以带类型lambda为块的唯一结果时加括号，例如`{ ((x: Int) => x) }`。`()`后出现`=>`是零参lambda，否则是Unit；`(Params)=>`是带类型lambda；其他括号包围表达式。块开头连续的let按块内声明优先解析，后面必须有最终Expr；函数体直接以let开头时采用LetExpr。这两者不由解析器随机选择绑定范围。不依赖符号类型回头改变已经解析的语法。

比较运算不可串写：`a < b < c`诊断，写成`a < b && b < c`；乘加和布尔层按左结合建立结构，前缀由内到外作用。直接作为函数/端口返回类型的函数类型必须加一层分组，例如`fn make() -> ((Int) -> Int !{}) !{} = (x: Int) => x;`；内外两条效果行分别属于返回的函数值与make调用，不允许同一个!{...}由解析器任取归属。`if/let/match/lambda`若用作算术子项必须括号化。基础调用不提供`f<T>(x)`这样的显式类型实参语法，因此不与比较符冲突；公开秩一泛型从签名、实参及预期结果实例化，不能唯一确定时用类型注解或具名包装函数，而不是隐式Any。需要更高级显式类型应用时版本化扩展，不在同一文法里靠宿主猜测。

基础列表下标不单独定义为`xs[i]`；使用所绑定库中返回Option的读取或带明确边界检查的操作。`..`只在列表尾部拼接一个List，位置和求值次序不改变。不接受记录展开、尾逗号或位置不明确的参数省略作为隐式扩展。基础和类型仅能在具名type声明右侧定义；签名、类型实参和嵌套字段通过该类型的名称引用，不用`A(Int) | B()`临时创建无归属构造器。匿名记录仍为结构类型。这是当前未发布文法的收紧，不声称旧输入已自动迁移。

`StaticExpr`允许闭合原始常量、不可变有限记录/列表、已解析绑定引用、字段选择、无作用运算与条件，以及符合下述规则且各孩子仍为StaticExpr的记录更新；并允许按[简洁作者合同](紧凑表示与程序范式.md#compact-author-contract)被动构造lambda或取得稳定函数引用。已经解析到具名和类型数据构造器的应用，只构造不可变值且每个实参均符合StaticExpr时允许，例如静态命令表中的`Command.Search()`；构造器身份来自真实类型解析，不能因为函数首字母大写或注解纯就放行任意调用。lambda主体另按运行语义检查，不在静态阶段执行。顶层任意函数调用、目标端口执行、资源句柄、可变环境和隐式宿主读取仍拒绝；静态值循环、除零与预算耗尽分别诊断。`BindingExpr`更窄，只允许不可变记录/列表/原始值及已解析绑定引用的选择，结果必须符合实际ImplementationReference；目标依赖的选择放在TargetBinding，不把TS/Java文件位置写进公共行为体。

### 不可变记录的局部更新

`base with {field: value, other: value}`产生与base同一记录类型的新值；不是赋值、深合并、开放字段扩展、JSON patch、对象getter调用或隐式IO。`with`仅在UpdateExpr的OrExpr之后并由`{`引入时作为上下文标记，普通名字与字段位置仍可用Ident。先解析再按类型检查，不根据未知变量类型倒推语法。

这里只允许一个直接更新后缀；链式更新写`(base with {x: a}) with {y: b}`。优先级低于OrExpr，所以把一个更新结果再参与算术、调用等子表达式时按原分组规则括号化。字段至少一个，无尾逗号，重复字段即使值相同也拒绝；空更新直接使用base。嵌套更新必须显式写为`base with {child: base.child with {x: a}}`，它不猜递归修改路径。

**求值。** receiver先求一次，再按源字段次序求每个更新值一次；先前字段更新不进入后面表达式的词法环境，`r with {x: 1, y: r.x}`的y仍读取旧r.x。需要依赖新x时先let绑定或显式分两次更新。任一求值失败按原错误和效果顺序结束，原base不被修改；不得因为字段最后按布局排序就重排更新表达式。

**类型与资源。** 当前有限形式用于具有可见表示权限、闭合字段集合、可重复读取的不可变记录值。字段必须实际存在，更新值接受该字段的准确预期类型，保留未更新字段和原名义身份；不能借更新增添/删除字段、转换成同布局的另一类型，或在定义模块外访问opaque表示。未知字段、重复、类型不符在生成前诊断。记录带独占资源、可变单元/借用等受限成分时，必须由已有类型/资源规则证明更新不会复制、丢弃或越界使用；本轮基础快捷形式没有取得该证明就拒绝，使用已定义的显式消费/构造接口，不能强行复制Own。

**保持义务。** 数据记录不是任意原生class/proxy。结构保全不自动证明高层不变量：例如`min <= max`仍由实际构造/使用合同承担；不透明类型应只公开合格更新函数。修改的值若含活动能力或原生引用，也不能用“字段不可变”推论引用目标不可变。优化器只有实际语义/别名/失败条件允许，才可消除分配；源码仍解释为产生新值。

**结构、降低与版本。** 文本节点对应`record-update(receiver,fields)`，精确结构字段见[结构作者](../../作者/组合/结构编辑与身份保持.md#record-update-node)。检查后降低为receiver临时绑定、按次序更新值绑定和同类型记录构造；未改字段引用原receiver，合成字段不成为第二份作者写源。基础编码`sec.semantic-body/1`须绑定确实支持该tag的规则/编码修订；仅识别旧字符串的解码器遇到新tag准确拒绝。语法、结构读取、写出、类型、目标生成和回源分别协商，不能只有解析器通过就宣布全支持。

这一扩充的理由是大记录局部变化，否则作者每次列出所有旧字段，增加独立字段遗漏与消费者维护。普通库函数可作为单个类型的较小替代，但不能在本语言当前参数机制下为任意记录定义一个同样静态精确的开放更新函数；每类型每字段生成setter又增加维护和来源映射成本。本构造保持有限语义，不趁机加入任意lens、反射或记录子类型系统。

### opaque修饰与签名投影

TypeDecl 接受可选上下文修饰 `opaque`；新增真实解释能力须由当前语言修订明确支持，不借“不是全局关键字”掩盖它。该词仅紧邻type的声明头参与解释；表达式、字段和普通Ident位置照旧。它只用于名义记录或和类型，含分组的等价声明也按同一规则；对透明别名使用本修饰返回类型声明诊断。

解析后先登记名义身份，再在定义模块内检查私有表示，随后形成公开投影。消费者只读取抽象身份、参数及公开操作的类型/效果/契约；不能结构构造、字段访问或穷尽隐藏变体。表示权限是静态定义模块的权限，不跟随运行调用栈或客户端提供的模块名转移。完整值、泛型、序列化、原生防伪和升级规则由[库规范](../../作者/组合/模块封装与复用库.md)拥有。

现有`export type`含义未变，旧工程不因新修饰自动改为opaque。旧阅读器遇到这一新语法准确返回不支持。opaque引入时基础文法仍有45项具名产生式、TypeDecl已有可观察的草案扩充；本版另增加UpdateExpr成为46项。两种上下文构造都需要实际读写能力，不能沿用“EBNF未变”或“只有18个保留词就无新成本”的说法。

### 名称、类型与作用域判断

每个模块分别维护类型、值、端口与导入域；同一域重名拒绝，种类不能靠相同字符串互换。只有显式export的函数、类型、端口和合法静态值公开（包括合格的函数值）；bind是实现选择记录，不因被导入而变成另一方的授权。导入只建立限定别名，不导入未声明的传递依赖或模块私有定义；别名与当前模块顶层可用名字冲突时诊断。先收声明名、显式签名与待推导头，再按[有限补全](紧凑表示与程序范式.md#compact-author-contract)完成可调用签名；允许前向引用，递归分量需要的注解明确给出。之后完整检查主体与效果；函数签名的预/后置合同不是已被证明的事实。

基础let和参数绑定不可重赋值；通用组合的var另按局部控制规范处理。初始化表达式在旧环境求值，之后才引入名字。相同块内重复绑定拒绝，嵌套作用域可以显式遮蔽；工具保留符号身份而不是依赖同名字符串。`result`仅指所属函数后置条件的正常返回值，不在主体、前提或顶层绑定，也不允许被用户重定义。

`type Name = OtherType`是透明别名，纯别名环拒绝；声明右侧去掉不改变结构的分组后，直接记录构造取得该声明的名义身份；直接和类型构造也取得该声明身份。`type A = R`和`type A = (R)`同为R的透明别名，不能靠多一层括号偷偷创建或擦除身份；匿名记录出现在字段、参数等位置时仍是结构类型。两个同布局命名类型不自动相等。匿名记录在明确预期类型下可构造调用位置有表示权限的命名记录，否则保留结构类型；定义模块外不能借预期opaque类型取得构造权限。把已存在的另一命名值当作该记录需要显式转换。字段重复或缺失拒绝，原生undefined不当缺省。和类型构造器在所属类型命名空间内，简单名字仅在上下文唯一时可省略限定；`Outcome.Accepted(1)`与另一个类型的同名构造器不混淆。

空列表和未标注lambda需要预期类型或相邻约束；仍有歧义时给本地诊断，不强迫AI重复整份类型树。记录字段、返回、每个match分支和调用结果共同检查。match的嵌套覆盖、顺序和失败统一采用[模式匹配](#模式覆盖与分支顺序)，不能只看最外层标签是否出现。

调用先求被调用表达式一次，再按源码顺序求每个实参一次，最后把值放入形参槽。位置实参必须在具名实参之前；重名、缺参、额外参数拒绝。具名调用只适用于已解析且具有形参名合同的声明；函数类型本身不承诺参数名，通过函数值调用使用位置实参。重排参数槽不能重排原本有作用的实参。

基础相等只对合同规定可相等的值成立：Int、Bool、Unit、Text、Bytes以及成员均可相等且表示公开的列表/记录/和类型；命名类型身份和构造器也参与。opaque不获得自动结构相等；定义模块可通过有合同的普通函数比较其允许观察的字段。函数和外部资源没有默认结构相等。基础泛型体不能在没有相等能力依据时对任意T使用`==`；带约束泛型属于显式高级画像。hash是相等实现的优化，不以摘要相等替代真实键比较。

基础运算也有固定类型，不让宿主推断改变含义。`+ - * / %`仅接受Int，前缀`+ -`仅接受Int；Text拼接走有合同的库函数。`! && ||`仅接受Bool，&&/||短路；`< <= > >=`在本基础域仅比较Int。==/!=依上述相等资格。if条件必须为Bool，两分支按预期类型或无歧义统一取得一个结果类型；没有公共类型时诊断，不自动合成Any或新的和类型。基础函数参数类型按已解析的类型相容检查，效果行允许实际集合不超过参数声明上界；名义类型不同仍须显式转换，不能仅因布局一样自动协变。基础表达式没有null、undefined、truthiness或隐式数值/文本转换。

函数类型中的效果省略表示空上界，函数声明省略行可从明确主体推导；把函数作为值传递时，上界属于其类型，不能在调用点重新猜测。显式泛型实参及Eq约束暂不进入该文本草案；绑定实例仍可以由参数和预期结果确定，无法表达的受约束泛型可保持为高级结构画像，不伪称本基础文法已接受。

预置类型与库来自固定画像，不通过打开模块隐式覆盖。用户模块可以声明自有同名类型，但与预置名字冲突时必须使用可解析的限定方式；不能静默重新解释当前文件已有的Int/List含义。import别名及公共类型的重名冲突在加载时诊断。

### 模式覆盖与分支顺序

先求被匹配值一次，再按作者顺序选择第一个匹配分支；模式是无用户回调的结构观察，失败的模式不执行其分支体。构造器按所属名义类型解析；`A()`是零参构造器模式，单独的`A`是绑定变量，不能依据全局同名符号回头改变词法含义。模式内同一绑定名出现两次拒绝，而不是隐含相等测试。所有分支仍检查类型和引用；发现冗余分支给诊断，但不默认令全模块不可编译。

覆盖检验按模式矩阵或等价构造器分解：对闭合类型列出当前可见的构造器，分别检查其参数组合；Bool分解true/false，List分解Nil/Cons并递归检查子模式；Unit只有一个值。Int/Text有限字面量只是分区中的单点，剩余域需要通配或绑定模式。递归类型按符号状态与已处理子问题计算，不枚举无限值、不按递归深度假造“全部覆盖”。[Rust编译器的usefulness分析](https://rustc-dev-guide.rust-lang.org/pat-exhaustive-checking.html)是算法参照，不能直接搬用其类型和模式语义。

反例：`type Choice = A(Bool) | B();`只写`case A(true)`与`case B()`，虽然两个顶层标签都出现，仍遗漏`A(false)`。诊断给可表示的缺失模式。若算法预算耗尽，返回coverage-unknown与范围，不能报exhaustive；调用者可以添加明确兜底、缩小目标或使用独立覆盖依据。已证明的前置条件可以参与专门的受限域证明，但普通类型检查不通过假定未证require来消灭遗漏。

未知/不透明类型不获得一张猜测的构造器全集。未来版本增加构造器，会使依赖旧全集的覆盖结果失效；公开闭合枚举可以用于穷尽匹配，开放演进的线协议另用显式Unknown载体或拒绝策略，不能让旧match的默认分支自动认证新语义。非穷尽源仍能保存为草稿，合格生成不能默补零、空值或未声明的异常路径。

### 泛型检查与特化的不同终止问题

公开泛型声明先建立量化签名；检查主体时把其类型参数视为不可任意收窄的刚性变量。`fn fake<T>(x: T) -> T = 1;`不能只因当前调用恰好传Int就通过。每个使用点对已声明签名作新鲜实例化；函数体的推断不把整个模块唯一绑定成第一次调用的类型。检查解代入要有occurs-check，不能把有限类型变量等同无限结构。

递归声明有显式签名时，可以按这些签名分别检查多态递归；缺少签名的信息不能交给无限搜索补齐。源递归是否终止、类型推断是否完成、编译时实例是否有限是不同问题。比如`fn grow<T>(x: T) -> Unit = grow([x]);`具有可检查的签名，却使逐个类型单态化产生T、`List<T>`、List<`List<T>`>……。不能把“已类型检查”当作特化一定结束。

目标默认只在能够有限闭合的范围专门化；出现实例递归增长时，选择已合格的统一泛型表示/共享函数体，或在预算内停止并准确说明该目标策略不支持。只有表示与调用合同确实允许，才退回共享实现；不能删除递归、截断类型或导出Any来凑结果。未选定输出根的泛型不为每一种理论实参预生成代码。高级泛型、类型类和效应多态仍按显式画像接入，不因这个基本规则无限扩张首版。

当前不新增let的隐式全称泛化规则。显式`fn<T>`的每个使用点仍按量化签名新鲜实例化；普通函数值和局部var使用当前环境中的实际类型，不把一个隐藏可变槽同时看成多个独立类型。let不可重绑定不足以证明其结果没有可变捕获，方差和noescape也须在实际范围判断。位置、捕获和外部效果的消解条件由[控制与寿命](../对象与控制/控制流与存储寿命.md#闭包存储依赖与外部效果投影)拥有，不向调用方额外展示一棵分析图。

### 公开类型闭包与有限值

导出的签名、端口与契约引用形成公共接口闭包。普通公开记录/和类型暴露已声明表示；`export opaque type`只公开类型身份与参数，由定义模块保有字段、构造器和表示等式。使用者可以持有该类型而无需知道布局；公共类型引用仍须可解析，私有辅助不能意外泄漏。这个区别由[封装与库](../../作者/组合/模块封装与复用库.md#3-不透明类型的最小作者方式)完整规定，不再将基础封装推迟到一个未定义画像。私有实现体可以使用私有类型，但不得使客户端必须命名它们。

递归声明只定义可能的值，不保证有有限构造。基础值采用有限、不可变、无循环的归纳含义：`type Empty = Again(Empty);`可以描述空值域，但不存在有限合法实例，不能在原生桥接时以自指对象制造一个值。递归名义引用无需在类型检查时完整展开；能直接确定的不可构造诊断与一般域存在性未知分开，不把空类型自动说成非法语言。列表可以共享物理尾部；共享本身不增加逻辑元素，也不允许作者观察地址。

相等和序列化依此合同处理：函数/资源没有默认结构相等，递归类型中实际遇到的成员都要具备相等资格；同一对象对可以记忆化避免重复比较，但不能因哈希相同跳过必要比较。原生循环值在这个有限值画像下拒绝或留在独立的显式图/资源类型，不能无限递归解码。

### 闭包构造与调用的效果

创建闭包保存自由值和代码，不执行lambda主体。其立即效果只来自实际求值的捕获表达式；函数体的潜在效果属于返回函数的类型，等到调用时才计入调用者。例如构造一个以后发送消息的函数，不等于当前已经发送；但把这样的函数交给只接受`!{}`的参数也不能通过。

现有高阶效果上界继续使用：函数签名分别保存当前调用效果与返回函数潜在效果，嵌套lambda不是静态调用图的一次立即调用。端口句柄在闭包中被捕获，不等于旧授权永久有效；真正调用仍遵守对应资源和目标授权合同。let按值捕获，所选通用组合的var按受管理位置捕获；资源和借用捕获仍须其类型/区域合同；新工具或新关键字不是这项区别的前提。

闭包访问的内部位置和函数的公开效果采用不同投影。先建立位置/捕获关系与潜在读写，再判断外逸，最后确定相应调用的公开上界；不能先把闭包标为纯，再依靠后来逃逸分析补救被删除的读写。封闭局部状态可以不成为外层调用的公开效果，但这个结论不允许合并内部两次计数调用或提前执行可能除零的表达式。外逸未知时保留相交效果，只限制确实需要纯合同的使用点或优化。

### 基础值、效果与通用程序

Int是数学整数，`/`向零截断，`%`满足`a = q*b + r`且非零余数与a同号；除零是明确计算错误。Bool无truthiness；Text为Unicode标量序列；List为有限、稠密、有序的不可变值序列；记录读取不触发getter/原型。中立值不承诺可观察的宿主对象地址、哈希随机种子或物理共享。原生对象需按明确解码边界进入这些值域，不能只凭readonly/final获得纯值资格。

函数体直接表达行为，不返回目标代码对象。函数、条件、递归和无界理想整数/列表提供一般计算基础，现实执行仍有资源边界；不需要在生成前证明任意程序终止。尾调用是否用循环、蹦床或真实目标尾调用实现，按所承诺的进展和资源边界选择，不能将某宿主较浅调用栈产生的失败藏成业务返回。

已有函数体的省略效果行可由体与所有被调用合同推导；显式`!{...}`是允许效果的上界，推导结果不得超过它。**端口必须写效果行**，包括明确的`!{}`；无函数体且未声明效果的要求保留未决，不默认纯。端口写空效果也只是要求，选中实现还必须满足纯度/输入依赖合同。递归效果在固定有限域中求最小固定点，规则删除时采用对应重算协议；纯不等于总终止、不会陷阱或随意可交换。

高阶调用的效果来自函数值的类型合同。静态调用图不能解析到唯一函数时采用其声明上界，而不是漏掉整个调用；未闭合上界限制所需优化或生成，不以原生函数名猜纯度。端口可调用、宿主有权执行、业务效果成功是三个判断。

### 行为契约的执行与证明责任

`require`限定可接受输入；`ensure`限定正常结果；函数体给出具体行为。声明先写全部require，再写全部ensure；各分区内按源码顺序处理，不允许在ensure之后插入require。条件必须是纯Bool，但这不自动证明它有定义、能终止或计算廉价。`x != 0 && 10/x > 1`与把两个子句倒过来不等义：契约也遵守短路和源码顺序。每个条款先检查自身可求值条件，再使用已经成立的前置条款；不能用尚未成立的后置条件证明它自己有定义。

checked边界先按调用语义计算实参，再检查require，随后执行主体；主体正常返回时才检查ensure并交付结果。若实参求值已有外部作用，require失败不会抹掉它。若主体已完成外部作用，ensure失败同样不是自动回滚。需要“任何违反都发生在不可逆效果之前”的要求，必须用可前置检查、保持证明或对应事务/补偿设计满足，不能靠普通后置检查承诺。

运行谓词得到false是合同违例；谓词自身陷阱是合同求值错误；超预算、取消或未终止是检查未完成/相应执行状态，不能当成false或true。静态证明、运行插入检查、实际通过样本和未知分别记录。预算由相应目标/检查画像明确绑定，不在某后端隐加一个不同的任意超时。

缺少函数体的声明可以保存、查询与组合要求；没有合格行为绑定时不生成空函数。矛盾的前提可能使正常输入域为空，逻辑蕴含可真但不能据此签发“用户任务可完成”。确定矛盾时给出无可接受输入的诊断；域非空未知时保留未知，仅在承诺可用输入的任务需要时补证。递归合同可在健全归纳或明确模块化规则下使用，不把调用图中的互相假设当成独立证明。证明后端的数值/错误编码见[求解编码保持](../../运行/验收/方法与独立证据.md#契约到求解器的语义保持)。

### 高阶调用中的契约不能丢失

基础箭头类型`(Int) -> Int !{}`只约束参数、正常返回及效果上界，不承诺对所有Int正常终止，也不把某个具体函数的require/ensure自动抄给所有同型函数。函数值保留其实际定义、绑定和checked调用入口；传参、返回、放入容器或跨模块不能把该入口换成裸主体。

例如`quotient(x)`要求`x != 0`，另一个`call(f, x)`只知道f的普通函数类型。`call(quotient, 0)`在checked画像下仍应到达quotient的前置违例，不因为间接调用而先进入除法、返回任意值或获得“合同已满足”。反过来，检查call时也不能把quotient的后置条件套给任意f。具有具名行为契约的高阶参数需要显式行为要求；普通类型签名不代替它。

直接调用可以在证明本次实参与前置、结果和边界均保持时消除重复检查；函数值的逃逸、未知调用者和可重新绑定端口必须重新判断。内联保留前置/后置的原位置及错误分类；把`f(x)`改为其主体，不是天然合法的内联。[Dafny对函数值前置与包装的处理](https://dafny.org/latest/DafnyRef/DafnyRef)说明此类信息不能只看参数类型，SEC不因此新增Dafny的多套箭头语法。

### 契约怎样成为可运行产物

默认checked交付为实际入口保留可执行前置和后置。编译器对每条义务选择“运行检查”“由绑定的保持证据消解”或“尚未闭合”；该选择是产物计划的派生内容，不要求AI为每个函数填清单。纯检查不是任意终止保证，无法执行或证明的强制条款不能被静默删除。只请求设计可以保留未闭合要求；需要qualified产物时，相交未闭合义务必须可见。

省去检查必须同时有条款成立、条款求值有定义以及移除不改变所承诺错误/进展的依据。证据绑定原语义、实际调用范围、目标表示和所需不变量；仅有与条款结论相同的一份字符串或生成器自述不够。依赖某外部状态持续成立的前提应由入口核查或有效运行控制维持，不能用一次旧静态证明永久替代。

发布后某证据被撤销，改变的是该产物在当前使用范围的资格，不会魔法般重新插入检查、修改已运行代码或擦掉执行事实。下一次采用/部署需重新核验、重建为checked形式或按明确政策限制；独立离线产物没有宣称受SEC在线围栏保护时，应明确剩余风险而不是伪称已被远程停用。业务契约变更与实现替换也分开：替代实现不能收紧已承诺接受的输入或削弱保证而仍标“无行为变化”。

### 作者表示、领域语义与目标的统一

同一Definition、Requirement、Relation与Binding可以由文本或结构前端表达；输入格式不签发语义。纯函数体可以同时具有独立的类型、前后置与来源关系，不要求AI把每个节点再写一次JSON。高层状态机/决定表/事务/时间方言保留其自己的解释与合法变换；把这些结构降低为函数是编译选择，不代表只用一个函数黑盒就已说明其全部工程义务。

公共核心只使用语义符号、类型、效果和要求，不依赖ts.Symbol、Java Method或某个异常类。一个冻结候选可以生成多个目标；目标布局、工具、ABI、产物和证据分别绑定。原生代码转换需自己的实际覆盖，不从“中立可多目标”推出“任意TS自动无损转Java”。新普通函数与组合是作者内容，不新增关键词；真正新语义才更新明确的语言画像。

读取不执行、绑定卫生、求值次数、阶段分离与产物不授予权限，是所有获准前端需要满足的接合条件。未采用的作者前端不进入当前发行、锁或实施任务；比较与重开条件由 D02 维护。
