### 一个候选选择算法

候选来源为词法可见集合、明确导入的扩展集合，以及类型声明中公开的 associated customization。最后一类保留 ADL 的类型关联扩展用途，但不扫描整个包依赖图来碰运气。

自有调用画像按名字、参数标签、arity／pack 形状、receiver 与该画像规定的可访问性收集候选，再检查参数类型与所需约束；精确原生导入必须由对应前端按其查找顺序解释。C++ 的重载选择先决定最佳可行函数，再核所选函数的访问资格；不能删除 private 精确匹配而退选 public 的较差匹配。转换等级只使用公开定义的有限关系，例如精确匹配、合法 reborrow、规定的无损内建转换、已启用的用户适配。比较按**逐参数不更差且至少一项更好**的偏序进行，不把不同参数的好坏加权相加。

平局时，仅在能证明一组约束是另一组的严格细化时选择较专门者。仍不可比较就给出候选及显式解决方式；不按声明顺序、函数长度、作者声望或预计运行速度决胜。默认实参数量不自动消除歧义；返回类型本身不构成一般函数重载的唯一键。

选择冻结到实际使用点；后端只打印已经选定的调用，不再次运行一套目标语言候选选择。

### Receiver 与精确表达式类型

receiver 是显式类型化参数，可以是 owned、shared borrow、exclusive borrow、pinned view、volatile view 或合格 smart receiver。智能 receiver 需提供投影与寿命／借约合同，转换链循环或无法收敛返回诊断。模板推导可以引用 receiver 的类型与访问模式，不必用多份近似函数体模拟 deducing-this。

提供 `type_of(expr)` 和独立的 `place_info(expr)`。前者取得精确表达式类型，后者取得是否可寻址、借用与可写性等位置性质。查询不执行表达式，不能为了得知类型实际读 MMIO 或调用网络；返回借用仍必须通过寿命检查。推导是类型／效果机制，不是“返回任何引用都合法”。

### 默认参数与推导指南

默认参数属于声明方的语义版本。本节选配调用画像中，显式实参按书写顺序求值一次，随后按形参顺序求值缺省项；缺省表达式只可引用定义环境与已绑定的较早形参。C++ 源语义导入可保留其自己的求值规则，不能伪称两套规则完全相同。

遗漏参数与显式传入 null／None／undefined 分开。泛型推导指南是显式的类型函数，产出实参替换；多条不可比较指南报歧义。指南不借构造器执行副作用来决定类型。

### 隐式转换的完整控制

默认仅启用声明为无损、无可观察外部副作用、不挂起且不会引入未处理失败的转换。更强的用户转换仍可定义；显式调用总能暴露其完整效果。需要 C++ 式隐式 effectful conversion 的兼容区可以显式启用，调用的效果与成本必须包含转换本身，并保留唯一候选规则。

不允许搜索无界的“把 A 转成 B 再转 C 再试一次”链。默认每个参数最多一个用户转换步骤；复杂适配声明为一个确定入口或显式组合。临时对象与隐式转换产生的借用不得逃出真实寿命。

### 运算符不能吞掉各自差异

| 能力 | SEC 的操作合同 |
|---|---|
| 调用 `()` | `Call<Args, Result, Effects, Receiver>`；用户类型可实现，普通函数与闭包消费同一调用协议 |
| 赋值 `=` | 位置替换、对象内容赋值、copy assignment、move assignment 分开建模，见 [place、初始化、复制／转移／赋值](../对象与控制/位置初始化与转移.md) |
| 下标 `[]` | 允许值、借用或位置代理结果；多索引和 proxy write 有明确顺序、借约与失败 |
| `->` | smart receiver 的受控投影；每一步执行次数、效果与最终 owner 均可追踪 |
| `->*`、`.*` | 应用类型化成员句柄；不能把任意整数当偏移 |
| 前／后 `++`、`--` | 前置返回更新结果；后置按声明取得旧值再更新，复制成本与失败不能被隐藏 |
| 逗号 | 明确的 eager sequencing 与返回模式；不是随意抹掉左侧效果 |
| 用户自定义取址 | 作为 address-like 自定义操作保留；不覆盖编译器建立真实借用／取原始地址的内建操作 |
| `&&`、`\|\|` | 默认短路协议接受至多调用一次的 RHS thunk；兼容 eager 重载另有明确画像，不能混淆 |
| `new`、`delete` | 进入 [分配器、资源域与 TLS](../../运行/分配域与退出责任.md) 分配／回收策略，而不是另开全局隐式分配通道 |
| `co_await` | 进入 [协程、取消与 CFG](../对象与控制/协程帧与控制流降低.md) awaiter 协议；yield、取消与 frame 生命周期也必须检查 |
| 算术、位运算、比较 | 普通类型化调用；短路、溢出、舍入、比较次序分别由对应协议规定 |

自定义 literal 以 lexer 保留的数值／字节文本和明确注册的 parser 进入编译期或双阶段函数；默认不会损失超过宿主整数范围的原始数字。命名冲突须限定来源。字面量 parser 不因在编译时运行就自动得到文件或网络权限。

Rust 输出可以生成唯一命名函数／方法及闭包桥，不依赖手写稳定 `Fn` impl；外部调用者拿到闭包适配器与拿到原对象本身可直接调用不是同一个原生接口承诺。[依据](../../依据/来源/Rust与C++能力比较.md#baseline-s05) TS 的 overload declarations 不等于多个运行实体；需要 runtime 分派时必须明确测试哪些类型标记以及成本，不能依赖编译后已擦除的信息。

## 再次修改与失效

默认表达式、转换、导入集合、定制点或源语言策略改变时，重算相交候选与效果并形成新绑定；不能仅重打印旧目标。

## 使用点与可检验出口

这些分支保留各自的真实输入、替代路径与边界，不按条数声称更多底层能力；[比较记录](../../依据/来源/Rust与C++能力比较.md)不拥有另一套语义。

- **函数重载集合**：作者便利可在解析期降为确定调用；是否提供重载按可用性测试决定，非系统完备性必需。 硬边界示例：原生调用语法必须不变，或库要求无需合作即可按任意输入参与自动重载；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a12)。
- **receiver 的 cv/ref 重载**：保持 receiver 拥有权语义；同名便利可局部语法降低，不必复制全部 C++ cv/ref 体系。 硬边界示例：必须保持既有 fluent API 或由通用表达式精确选择值类别；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a13)。
- **explicit object parameter / deducing this**：先用显式参数与目标已有 receiver；撤回把 deducing-this 等同 arbitrary-self-types 的粗糙比较。 硬边界示例：下游原生方法语法或精确 receiver 转换协议被固定；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a14)。
- **默认参数**：可作为作者糖或库 API；不因为 C++ 有它就创建新语义子系统。 硬边界示例：目标原生调用语法不能改变；否则通常是设计便利而非底层控制缺失；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a15)。
- **用户定义隐式转换**：默认显式资源/失败语义；是否允许受限转换由使用性决定，不自动复制有隐式成本的规则。 硬边界示例：保持原生源调用或既有重载匹配行为是硬要求；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a16)。
- **自定义赋值 operator=**：保留替换与内容更新的差别；显式操作默认足够。与45合并计成本，不重复累计缺口。 硬边界示例：外部泛型算法必须以 = 调用你的自定义协议，且不能改为 trait 方法；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a17)。
- **任意用户类型 operator()**：call 语法可以下降为方法；保留导出原生 callable 的边界，不为普通闭包重造调用框架。 硬边界示例：要求原对象直接满足外部 Fn 接口且不能增加适配层/改变暴露类型；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a18)。
- **额外运算符与代理下标**：保留精确代理/借用/求值需求；先显式方法或局部糖，别把每个运算符升级为核心原语。 硬边界示例：算法固定以原生下标/赋值处理代理结果，或需保留特殊求值顺序、eager逻辑等源语义；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a19)。
- **用户字面量后缀**：字面量/DSL 属作者层可选便利；保留解析错误与数值精度，不是新系统控制缺口。 硬边界示例：必须兼容既有后缀语法或无宏入口的第三方常量协议；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a20)。
- **ADL**：设计明确的定制入口；不移植整套 C++ 查找算法作为默认。也不声称 C++ 开放扩展不受 ODR/可见性约束。 硬边界示例：需要对不合作的外部类型与外部算法做全局透明扩展，不能包装/传策略；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a21)。
- **类模板推导指南**：先工厂和推导规则；这不是运行时缺失，也不必另建全局推导指南注册表。 硬边界示例：既存构造语法/推导结果身份不可改；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a22)。
- **decltype / decltype(auto)**：编译器内部类型查询本来必要；是否向作者开放为语法/API，是独立决定。 硬边界示例：编写通用库必须在类型位置复用任意表达式类型，且不允许改写为新 trait/辅助入口；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a23)。
- **fold 表达式**：通常复用泛型序列机制；不是在24之外又一个独立机器能力。 硬边界示例：必须原生包语法，或类型级归约规模使替代方案失去可用性；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a27)。
- **重叠候选按专门程度选择**：优化分支可放优化器；语义差异必须在明示候选域/witness绑定中表达。不能默认全局开放特化。 硬边界示例：要求不改调用点、任意新类型可合作/不合作地加入选择，且全局唯一性必须维持；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a33)。
- **volatile类型限定**：常规设备访问可库化；volatile不等于atomic或CPU屏障，分别履行真实硬件合同。 硬边界示例：固定外部类型/overload/volatile调用约定无法改，或未知代码必须靠原生qualifier传播；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a52)。

实际组合与拒绝条件见[验收案例](../../运行/验收/跨语言控制与组合案例.md)；从作者要求到再次修改见[连续开发情景](../../../examples/连续开发/跨语言能力连续开发.md)。

## 借用型索引代理、写回与源规则

packed bit、矩阵视图、多索引和延迟写回可能要求“读取像值、写入命中原存储”的代理位置，而非一个普通引用。默认以显式 get/set 或有类型投影完成；只有确需兼容特定 `[]`/赋值协议或能降低实际作者负担时才提供相应操作面。

代理绑定实际 owner、索引/范围、存活期、访问域、写回时点及错误行为；读取、写入、读改写和提交不是可自由互换的一次访问。多字段提交若被要求原子，必须有真实原子/事务方法，不能由代理对象名获得保证。目标需要返回 `&T` 而底层只有位域时，不构造不存在的对齐对象；使用原生不兼容诊断或显式接口适配。异步保留代理必须满足真实存储与授权寿命。

精确 C++ 导入由对应前端完成重载选择、访问检查、默认值与临时对象寿命解释；本页自有调用便利不能覆盖其规则。源语言将 private 最佳候选判为不可访问时，不退选较差 public 候选。选中调用进入中立绑定后，各后端不再重新决议另一套规则。
