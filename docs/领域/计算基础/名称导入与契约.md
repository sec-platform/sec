## 文本与结构共用的基础程序含义

本章拥有词法、文法、作用域、类型、效果与执行规则；[结构作者规范](../../作者/组合/结构编辑与身份保持.md)仅给这套基础含义另一种精确编码以及结构编辑协议，不增加第二种程序语言。完整JSON模块用于适配器/持久交换，不是每次AI请求的默认输入。结构编码不得暗中增加文本语言没有定义的行为。

结构函数先收声明，再在参数、块、let、lambda和match区域中解析引用；同样的合法表达式进入同一静态判断。普通函数声明和port参数的命名能力不同，effects省略在声明与函数类型中也不同，解码按所属槽而不是统一填默认。源和结构能同义生成的前提是使用相同解释、公开/名义身份关系和实际目标约束；首次独立创建的谱系不因为行为相同就等同。

区域表示必须保留块内重复名称检查、嵌套遮蔽、短路、分支激活和闭包延迟。仅复制一个值结构不能合并两次调用，仅通过类型检查不能认证重命名保持绑定。结构hole是草稿，不是基础语言新增一个可执行未知值；完整函数体缺省与无行为要求也分别处理。


## 一个作者模块的读取检查与继续修改流程

本节把已有文法、类型、效果和契约接成实现者可照着完成的处理顺序，不增加关键字，不建立第二套类型规则。语言是被检查对象，设计文档中的步骤编号不是作者语法。

### 从原文到可用语义

**S1 读取。** 给定原始文本与已经固定的语言组合（或原基础专用解释）的精确绑定，得到token、跨度和语法树。错误区域保存原文与局部诊断；解析恢复只用于编辑，不发明缺失的业务定义。注释和空白有原文保全位置，类型检查不靠重新打印覆盖草稿。

**S2 收集声明。** 先建立全部声明名、类型、显式签名和待推导头，解析真实导入；按有限签名依赖补全返回及函数值类型，再完成必要组件的主体和效果检查，最后发布可调用结果。声明互引合法性与值初始化顺序分别分析；类型/函数递归不要求编译期运行函数。

**S3 建立类型判断。** 检查具名类型及构造器来源；显式泛型签名的变量在主体内刚性处理，不能由首次调用固定。表达式在有期望类型时双向检查，没有期望时根据既有规则推导。变量从最近词法绑定取得，分支结果按已定义的合一或显式类型要求处理；混合Int/Bool、错误构造器或不匹配调用得到定位诊断，不插入隐式宿主强转。

**S4 检查控制、模式与效果。** 模式按构造器及参数空间检查嵌套覆盖，作者顺序决定首次匹配。函数值的潜在效果来自其类型与实际定义；构造闭包时的立即效果另算。静态已知调用可以汇总实际效果，动态调用采用上界，递归按既定有限分析求解。分析超预算保留未确定范围，不能删除未知调用。

**S5 处理契约。** 依作者顺序检查require的良构与定义域，再在满足前提的主体环境中分析行为；ensure在正常结果环境中检查。运行检查、静态证明和条件未知分别记录。高阶传递保留真实契约入口；要消解检查时引用对应依据，不能只看返回类型。

**S6 选择当前可做的事情。** 没有函数体的要求可以保存并被查询；所选输出必须有实现体或合格绑定才能生成。模块中的未使用要求可保持设计状态，不让一个未实现声明阻止全部独立根。源检查可以在没有后端时返回其有限结论；实际生成沿[编译阶段协议](../../编译/内核/编译值服务.md#从作者候选到目标字节的阶段协议)。

### 一个非事务的完整轨迹

输入 `export fn twice(n: Int) -> Int = n * 2;`。词法和文法取得一个公开函数；n绑定参数，乘法要求两个Int，字面量2按预期为Int，结果与声明相符，函数效果为空。中立结果无需运行n相关计算。TS后端选择bigint乘法表示，打印普通目标函数；没有运行类型/案例检查时只返回generated-unchecked。

第二次将2改成3：旧候选C1保持，C2记录实际文本变化；声明谱系能从明确修改对应时保留函数身份，内容修订变化。相交计算更新，无关模块不因文件时间变化被强制重算。再改成`n * true`时，C3可保留为非法草稿，输出TYPE_MISMATCH且不产生该根的合格目标；C2既有产物不被改贴成C3的产物。

上述推导是规格例。它说明一次成功、一次合法变更和一次失败怎样共享语言与工具边界，而不是只有“不能越界”的规则。普通函数不产生aggregate、请求幂等表或后台服务。

### 当前实现选择与改变条件

先采用明确的全量模块判断与有限类型/效果算法，可以在后续细化局部缓存；输入、规则和目标保持不变时，优化后的判断必须返回同义结论。编辑期允许部分树和未决信息；输出期按所选根闭合，不要求整个未来生态先完成。用户确需新语义时更新相交画像和映射，普通新函数使用现有构造。


## 函数契约与工程要求的使用边界

本章的类型、require、ensure和效果规定作者程序本身的含义；外层任务还可能独立要求接受输入范围、结果、资源或跨模块关系。两者都可用已有声明表示，但相应版本与采纳角色保持明确。修改一条require是语义变化，不是自动证明旧任务仍然完成。

高阶函数继续携带实际契约入口；跨函数组合除了普通函数类型，还检查实际使用点的输入域与后续需要的保证。无法静态证明的连接可以保留运行检查或产生条件结果，但如果任务承诺合法输入正常完成，新增拒绝不能替代实现缺失。完整算法见[任务要求判定](../../运行/保证/要求证据与裁决.md#原任务要求与候选合同的满足判定)与[组合边界](../../作者/共同语义关系.md#组合边界摘要与义务闭合算法)。

这些规则不增加关键字，也不要求每个函数写一套外部规格。普通闭合函数以给定源为语义输入即可生成；有真实独立要求时才形成相应满足义务。合法递归仍可以编译，不要求为得到目标源码先证明总终止。


## 名称机制与表达能力的实际分工

`import`选择依赖，`as`建立当前模块的限定别名，`export`给出公开合同，`let`表达一次求值与不可重绑名字。它们不是业务规则，但会影响绑定、复用和封装，不能凭省四个词取消这些责任。普通局部表达式不用导入，无外部消费者的辅助定义不用export；已有context知道绑定时可省相应导入，独立保存则按作者资产合同固化，不靠全局名字搜索。

当前不另造省略这些词的第二语法。工具可以自动生成合法导入、别名和门面，作者只在相交源码中看到真实变化；别名冲突、公开接口扩张和新的依赖不能无提示发生。let绑定对象引用不意味着对象内容深度不可变，词法作用域不等于物理释放时点，完整含义见[存储寿命](../对象与控制/控制流与存储寿命.md#名字存储与资源的寿命不是同一条线)。

可表达一般计算不代表已有系统ABI、内存映射、原子、设备和所有数值操作。按[能力覆盖](../../作者/需求关系与能力边界.md#底层能力的具体落位与支持边界)将实际需求落在已有构造、普通库、目标内在操作或明确扩展上，不用关键词数量或图灵完备替代支持表。


## 基础环境与导入

### 固定的隐式环境

一个基础模块的类型环境预置Unit、Bool、Int、Text、Bytes、`List<T>`、`Option<T>`与Result<T,E>。其中Option含`None()/Some(T)`，Result含`Ok(T)/Err(E)`，其类型与构造器身份来自当前语言画像，不由后端按名字重新创建。建议使用`Option.Some`和`Result.Ok`限定构造器；既有上下文唯一时的简写规则仍保持。

Bytes是不可变字节序列，不自带新的字面量，构造与外部读取采用明确的库/端口。没有可用的构造方法时，这个名字本身不获得凭空制造字节的能力。Nothing/Never、目标类、SQL类型和随机源不隐式进入该基础环境。

标准函数不自动成为全局关键字。只有实际固定的context明示了某短名绑定，才能在小片段中省略import；独立保存时必须保留对应导入或解释绑定。多个同名符号产生冲突，不按安装顺序选择。

### 普通模块和库解析

相对说明符从实际包含文件的逻辑目录解析，命中候选中的精确路径；文件不存在、超出可见范围或被阻止均给出相应诊断，不到cwd另寻。`./pricing.sec`要求精确后缀；基础作者不进行TS式后缀替换。实际操作中的越界、符号链接和秘密读取仍受宿主合同约束。

非相对说明符由当前锁或显式内存绑定解析，不联网猜测、不在编译期间自动升级。导入别名只开放相应模块已经export的名字；导入也不执行顶层目标行为。临时多文件候选可以仅靠自身模块和固定基础环境编译，不为此伪造持久projectId或锁文件。

### 从公开声明到可替换的库

公开门面、opaque表示、包导出、版本与实际ABI分别遵守[封装模块与库演进](../../作者/组合/模块封装与复用库.md)。一个文件有export不足以保证实现可替换；客户端只能依赖公开合同，生成器仍要绑定实际实现并在其变化后重新生成相交内容。库可以在本地模块中建立，不以注册中心为前置。

在明确选择的中立计算文本画像中，`.sec`不只承载算法；该区域角色不替代产品意图的结构化JSON主面。函数体表达精确行为，契约表达约束，高层计算/事务等声明表达结构及作用义务，目标与实现选择单独绑定。意图既可以是当前未定要求，也可以精化成明确行为；并不等于一句无解析规则的自然语言。相同语义还可有结构投影，但单个区域不双写。

### 库是语言的一部分成本，但不是无限工具集合

首版序列库可采用已定语义的普通名字：`filter`和`distinctBy`。独立模块必须写明导入，不能依赖文档中出现过这个函数就假定已安装。

```sec
import "sec/seq" as seq;

export type Item = { id: Text, enabled: Bool };

export fn enabledUnique(items: List<Item>) -> List<Item> =
  seq.distinctBy(seq.filter(items, x => x.enabled), x => x.id, keep: "first");
```

基础辅助库入口采用以下合同：
- `filter的参数为List<T>`与`(T)->Bool !{}`，按输入顺序求值一次，产生新的逻辑列表。
- `distinctBy的参数为List<T>`、`(T)->Text !{}`与必需Text参数keep。keep只接受"first"或"last"，无默认实参；非法值是该函数的合同违例。Text按精确标量序列比较；输出按被保留项的原位置排列。
- 上述类型是已绑定的库合同，不意味着基础文法新增了默认参数、重载或Eq约束语法。任意K的自定义相等去重仍可由用户直接定义，或采用显式比较函数的独立库合同；不能让示例暗中突破泛型限制。

这只是固定的最小示例库面，不宣称完整标准库已设计或发布。Bytes构造、文本处理、序列高级操作、平台I/O等按实际库交付清单进语言发行画像；缺项如实报告。**语言规格、最小随附库、完整生态必须分别列状态**，不能以“已可图灵完备”忽略实际可用性。


## 状态模型工厂与基础静态阶段

状态模型是普通库值，来源可以是`.sec`函数，也可以是已验证结构体。采用`export fn`返回`sc.Model<C,E,O>`不增加关键字，通常调用仍服从本语言。编译器为明确的状态输出根使用已装配方法，在有限预算中解释合格的纯构造和闭合参数，见[模型工厂](../状态关系与流/层级状态与事件.md#4-工厂静态模型与动态模型不混同)。

基础顶层StaticExpr不因为领域库增加而自动允许任意函数执行；带动态拓扑参数的函数也不因此变非法。分别处理“能够编译该函数”“能够取得有限模型”“能够专门化成目标表”和“能够实际运行活动”。没有静态模型时，只有任务允许且目标支持才保留模型运行库，不能默换路线。守卫/动作以原类型和效果规则检查，构造输出计划的纯性不签发未来目标I/O权限。
