# 原子存储与进展条件

> 条件能力设计；不改变已固定的基础画像，不表示实现或目标符合性已完成。

本页补充[权限与资源管理](../../运行/权限与资源管理.md)中的相交能力；原章节继续拥有其已采用的有限语义。**当前选择：保留原子语义与进展约束；复用目标库。** atomic≠lockfree，回收独立；不因std接口缺少而创建并行的自有原子模型/库。

这里的选择不是删除能力或承诺全部默认启用。满足真实要求的成熟库、静态展开和原生适配可以作为最终方案；额外语义只在现有路线不能保持该使用点的明确要求时激活。未提供对应解释、实现或目标条件时保留作者要求并返回具体缺项，不强迫所有项目携带设施。

文中的类型名、操作名与代码块为合同记法，不向现有作者文法添加关键词，也不直接发布 wire 字段。作者仍通过已有 Definition/require/prefer 或已解析原生定义提供真实差异；内部信息归入原 MethodSpec/BoundaryView/UseBinding，公开扩展必须另有准确版本及能力协商。共同准入见[能力履行](../../编译/目标/能力履行与接口差额.md)。

### 原子化什么，不只是给 T 加个名字

```text
AtomicValue<T, ProgressPolicy>
AtomicView<'lease, T, AccessDomain>
```

T 必须有符合所选操作的值表示与复制语义。不能原子复制带独占资源、任意析构器或不合法位模式的对象；指针 payload 还需保留 provenance，不能普遍靠整数序列化恢复拥有关系。

原子值可由真实硬件原语、合格运行库或显式锁路线实现。锁路线仅在允许阻塞、重入／中断条件合格、跨进程域一致时选择。`atomic` 不意味着 `lock_free`，`lock_free` 不意味着某次操作 `wait_free` 或有墙钟时限。

硬性无锁、无分配、signal／ISR 可用、进程共享和地址稳定等要求分别检查。没有目标支持时报告缺项；不得用 mutex 冒充无锁实现。

### 已有存储上的原子访问租约

建立 `AtomicView` 必须证明对齐、存储寿命、访问范围、表示以及全部可能并发访问者的协议。租约存续期间不允许不兼容的非原子访问或冲突访问宽度；共享 byte range 不是仅靠某个局部 `&mut` 就能排除外部线程／设备访问的事实。

Rust 目标已提供的 primitive 原子视图可以作为相应路线；泛型 Atomic 名字不能代替对该版本实际类型范围、表示与原语的检查。[依据](../../依据/来源/Rust与C++能力比较.md#baseline-s01)[依据](../../依据/来源/Rust与C++能力比较.md#baseline-s13) C++ `atomic_ref<T>` 同样有对象类型、对齐、寿命和访问条件，不是对任何已有对象都安全的开关。[依据](../../依据/来源/Rust与C++能力比较.md#baseline-s20)

租约结束后恢复普通访问前，必须确认没有仍在使用视图的线程／回调。并发域跨进程时，当前进程独有的借用检查或 mutex 不足以证明其他进程遵守协议。

### 排序、CAS 与回收

内存序是操作合同。默认可以采用顺序一致，低层使用点可明确要求更弱的排序；load、store、RMW 和 CAS 的成功／失败排序分别验证，禁止将不适用的 release 语义赋给纯 load 等无效组合。

对于“至少提供这些排序约束”的要求，更强排序可以是合法实现但必须记录性能代价；对于要求具体可观察行为集合／litmus 结果的兼容请求，不以“更强通常更好”自动判定精确等价。

CAS 比较按选定的值／表示合同处理 NaN、padding 与指针身份，不默认套用普通用户 `==`。使用锁保存实际 T 时也必须遵守相同外部合同。CAS 成功不解决 ABA、节点释放后使用或地址复用；数据结构仍需真实的拥有权、hazard、epoch 或其他合格回收协议。

跨进程原子性不等于崩溃一致性、断电耐久或进程死亡后自动释放锁。共享内存初始化、版本、进程退出与 owner-death 恢复必须单独约定。

### TS 目标的硬边界

JS 共享内存／Atomics 的可用存储和访问方式由 ECMAScript 与实际宿主共同限制，不能把任意 JS object 变成原地共享原子复合对象。[依据](../../依据/来源/Rust与C++能力比较.md#baseline-s27)[依据](../../依据/来源/Rust与C++能力比较.md#baseline-s28)

满足合同的 byte-buffer 编码、锁协议或已取得的原生模块可以作为路线；无法保留对象身份、进展要求、地址、精度或宿主权限时明确拒绝。单线程事件循环上的“没有数据竞争”不等于跨线程原子 API；Promise 也不等于硬件内存屏障。

## 再次修改与失效

原子宽度、进展画像、共享成员或回收协议变化时，重核全部实际访问域；某个局部借用结束不证明外部进程停止，旧世代不能访问复用地址。

## 使用点与可检验出口

这些分支保留各自的真实输入、替代路径与边界，不按条数声称更多底层能力；[比较记录](../../依据/来源/Rust与C++能力比较.md)不拥有另一套语义。

- **泛型 atomic<T>**：按真实进展、表示和访问域选择供给；不因std少一个模板就自己重造atomic系统。 硬边界示例：禁止锁/分配、进程共享/ISR安全或精确复合ABI，目标原语和库不足；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a59)。
- **atomic_ref<T>**：保留租约、对齐及混合访问规则；撤回Rust一概没有原子视图。 硬边界示例：既有共享内存布局/复合类型/无锁要求不可改，且没有匹配原语和访问协议；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a60)。

实际组合与拒绝条件见[验收案例](../../运行/验收/跨语言控制与组合案例.md)；从作者要求到再次修改见[连续开发情景](../../../examples/连续开发/跨语言能力连续开发.md)。

## 等待、通知与底层供给的选择

原子等待/通知属于同步协议，不是把原子值多加一个事件回调。优先使用目标上合格的标准库、成熟库或系统原语；库的等待对象、平台、时限和 no_std 条件必须与当前使用点相容，名字相同不消解差异。

等待者先以规定内存序读取谓词；不满足才进入具有“比较并等待”或等价注册后复查保证的等待协议。唤醒后重新读取谓词并复核当前取消/截止，不能把一次通知等同于条件成立或取得对象拥有权。提供者允许伪唤醒、选择任意等待者或不能保证公平时，接口保留这些条件；有更强公平/硬时限要求时另取实际依据。

所保护对象、等待键及共享存储在所有在途等待、通知和取消结算前保持有效；地址复用不能让旧唤醒误认新对象。跨进程等待必须由所有参与者实际支持的同步域承担；某进程私有锁不提供全局保证。超时返回不抹掉已经提交的其他作用，通知缺失、对象销毁、进程死亡的恢复按所选原语另行规定，不虚构通用锁自动释放。
