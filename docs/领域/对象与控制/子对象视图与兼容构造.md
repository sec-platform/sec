# 子对象视图与兼容构造

> 条件能力设计；不改变已固定的基础画像，不表示实现或目标符合性已完成。

本页补充[对象构造与分派](对象构造与分派.md)中的相交能力；原章节继续拥有其已采用的有限语义。**当前选择：不进入默认核心；保留兼容/显式对象视图候选。** 组合、多接口与身份即可满足很多新代码；真实多基拓扑、共享根和C++RTTI只对相应用例启用。

这里的选择不是删除能力或承诺全部默认启用。满足真实要求的成熟库、静态展开和原生适配可以作为最终方案；额外语义只在现有路线不能保持该使用点的明确要求时激活。未提供对应解释、实现或目标条件时保留作者要求并返回具体缺项，不强迫所有项目携带设施。

文中的类型名、操作名与代码块为合同记法，不向现有作者文法添加关键词，也不直接发布 wire 字段。作者仍通过已有 Definition/require/prefer 或已解析原生定义提供真实差异；内部信息归入原 MethodSpec/BoundaryView/UseBinding，公开扩展必须另有准确版本及能力协商。共同准入见[能力履行](../../编译/目标/能力履行与接口差额.md)。

### 对象不是把几个 trait 放在一起

定义 `ObjectShape`，包含名义类型、子对象节点、有序继承边、共享基节点、初始化顺序及虚调用槽。**实现复用、包含关系、可替代关系、访问许可和 ABI 布局分开描述**，不能由一个 `extends` 隐含推出全部。

普通继承路径产生不同子对象；虚共享路径以同一个完整对象内的共享节点为身份。跨完整对象不共享；仅仅同名、同值、同类型也不合并。

```text
Diamond
  left  : Left  -> shared Root#r
  right : Right -> shared Root#r
```

这里从左右两条路径写 Root，必须观察到同一份状态。非共享路径则必须观察到两份独立状态。这是功能语义，不是代码复用的示意图。

同名成员须由限定路径或显式 override 解决。每个虚槽在给定动态对象和子对象路径上必须有唯一 final target；两个不可比较的最终实现构成错误，不按导入次序或源文件先后选一个。

### 视图、投影与借用

`View<T>` 表示“某个完整对象中的某个子对象／接口”，逻辑上携带 owner、projection path、借用种类和调用表。实现可按证明消除这些元数据；不要求每个普通结构都携带 RTTI。

动态调用默认借用相关完整对象，因为 override 可能访问其其他状态。只有已验证的效果足迹允许缩小借用范围。不能从 `&mut Base` 无条件重建 `&mut Derived`，同时还允许活跃的兄弟字段引用。

共享基的两个 mutable view 是同一存储的两条路径，不得同时建立不相容的独占借用。可静态证明互斥就静态通过；需要动态借约时必须声明成本与失败；native unsafe 路线必须保留责任，不能伪装成安全引用。

### 协变与 cast

只在真实的可替代关系中允许协变。借用返回保留寿命；拥有型返回转换必须同时保留动态析构器与分配器。可写容器不因元素有子类型关系而自动协变。

动态 cast 依据完整对象的受信类型描述和可达、可访问、唯一的子对象路径。允许 downcast 和 sibling cross-cast；不唯一返回 `AmbiguousProjection`，不存在返回失败。可提供返回可选值与失败即抛出声明错误两种操作，不由调用者的裸地址猜类型。

类型查询区分稳定声明身份、一次编译中的实例化类型、运行模块世代与 ABI／布局兼容。显示名称不作跨插件的 TypeId；旧插件的表和指针不能指向已经卸载的代码。

### 构造／析构时期

SEC 自有对象默认在完整不变量建立后才能虚调用。需要 C++ 构造／析构期间的动态分派语义时，启用相应 compatibility profile，记录当前构造阶段与可见子对象，不能在 base 构造期间派发到尚未建立的 derived 状态。C++ 自身对这些时期有专门规则，不是“始终用最派生类”。[依据](../../依据/来源/Rust与C++能力比较.md#baseline-s16)

析构从完整对象的实际动态类型进入，子对象按确定顺序逆向释放；共享基只销毁一次。构造失败只销毁成功建立的子对象，不调用未完成对象的完整析构器。

### 后端与代价

Rust 路线是生成组合存储、投影及必要的 dispatch table；不是让 Rust 原生获得 C++ 继承。TS 路线是对象状态加受控视图／dispatch，不能把 JavaScript prototype 单继承当作多共享子对象的完整语义。精确 C++ vtable／基类偏移由匹配 ABI 的外部工具生成并拥有。严格要求 inline 存储而后端路线只能用额外堆对象时，返回不满足，不静默分配。

## 再次修改与失效

基拓扑、共享节点、构造阶段或分派槽改变时，失效相交投影、布局、反射和 ABI；活动旧对象继续使用原解释与驻留代码，不能直接改表换类。

## 使用点与可检验出口

这些分支保留各自的真实输入、替代路径与边界，不按条数声称更多底层能力；[比较记录](../../依据/来源/Rust与C++能力比较.md)不拥有另一套语义。

- **实现继承**：新代码先用组合和接口；需要原生继承协议时做适配，不给普通类型默认加继承图。 硬边界示例：既存框架要求由外部派生类覆写、基指针代表同一完整对象，或指定 C++ 类 ABI；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a01)。
- **多重实现继承**：保留多接口/组合需求；多基类对象模型只在兼容需求成立时启用。 硬边界示例：开放插件按多个基类 ABI 操作同一对象，且禁止额外间接层或改变原生接口；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a02)。
- **虚继承／菱形共享基**：保留共享身份与别名规则；不为所有 Gift 对象默认支持虚继承。 硬边界示例：要求 C++ 虚基转换和精确子对象布局，或开放扩展下的透明跨接口访问；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a03)。
- **继承的 public/protected/private**：默认模块与导出规则；原生继承访问属于源适配器，不是通用新增权限系统。 硬边界示例：必须源兼容既有继承家族的访问规则，而不能重构模块或包装；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a04)。
- **protected 派生家族权限**：承认细粒度封装差异，按插件/扩展用例设计有限接口；不把 protected 当安全沙箱。 硬边界示例：库要求任意下游派生者访问受限成员，但普通用户不得获得同样入口；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a05)。
- **虚函数协变返回**：一般化接口和拥有权正确即可；源语言协变由适配保留，不扩展到可写容器的任意协变。 硬边界示例：原生虚函数 ABI 或同一 override 的精确返回接口不可改；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a07)。
- **dynamic_cast 下转与横转**：保留明确的接口查询协议；不要求全部对象携带继承 RTTI。 硬边界示例：未知插件仍需按既定 C++ RTTI 图横转，或原生地址调整/ABI 固定；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a08)。
- **typeid 动态类型识别**：撤回“Rust 没有 RTTI”；仅在真实跨模块协议处区分类型身份、生命周期与 ABI。 硬边界示例：要求任意借用对象的通用原生 RTTI、继承图转换或跨 ABI 身份一致；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a09)。
- **成员指针**：常规访问器足够时不新造原语；确需字段投影时保留 owner/借用/不可寻址字段约束。 硬边界示例：要求精确 C++ pointer-to-member 表示，或既存泛型接口必须原生接收这种值；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a10)。
- **原生C++ ABI与模板生态**：明确支持的ABI边界并复用成熟前端/编译器；不默认让Gift成为完整C++实现。 硬边界示例：不可加shim、不能改变现成API、没有可用兼容toolchain，或要求任意C++源码逐文件替换；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a58)。

实际组合与拒绝条件见[验收案例](../../运行/验收/跨语言控制与组合案例.md)；从作者要求到再次修改见[连续开发情景](../../../examples/连续开发/跨语言能力连续开发.md)。

## 原生转换与中立视图的不同出口

中立视图可以返回受管失败/歧义，但精确原生兼容必须保留源表达式规定的出口，包括静态非法与运行时转换失败的区别。指针转换失败、引用转换失败及构造/析构期间的动态类型规则各由所选原生前端与运行库解释，不把本页统一的概念结果当成所有 C++ 表达式的逐字语义。跨 cast 后的访问、删除与反射继续使用真实完整对象、子对象和模块世代；转换成功不扩大源级可见性或现实执行权限。
