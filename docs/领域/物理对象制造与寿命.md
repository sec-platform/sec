# 物理对象、制造与寿命

本篇细化[对象关系与配置基线](../信息/对象关系与配置基线.md)在制造和现场生命周期上的领域含义。通用引用与版本不变，具体物料、几何、工艺和检验由领域方法及真实项目定义。

<a id="physical-genealogy-and-life"></a>
## 物理工程、物料谱系、制造与寿命闭合

物理对象同时具有设计、计划、制造、安装、现场运行、维护和退役视图。as-designed、as-planned、as-built、as-installed、as-maintained不按“最新版本”合成一份真相。设计允许的替代件、实际安装件、维修后状态和验收证据需分别绑定对象与配置基线；设计改了，不意味着现场已更换。

数量和组成不仅是包含树。原料可以拆分、混合、加工、损耗、返工、回收或产生副产品；批次与件号可以多对多映射。过程输入输出保留物料/单位、数量与测量不确定、来源、条件、转换方法和去向。质量/能量守恒只在选定封闭边界和适当计量下检查，不机械要求每个生产步骤质量恒等而忽略排放、蒸发或边界流。

制造要求涉及尺寸、形位、公差、材料/本构、表面、装配顺序、工艺窗口、检验和可维护性。几何可显示不证明可制造；BOM齐全不证明装配可行；每个零件尺寸合格也可能因公差叠加无法装配。公差采用最坏界、统计或其他方法需有来源与假设，不能把各件中心值拼接当验收。

磨损、疲劳、腐蚀、老化、热循环、校准历史和修复形成路径依赖。恢复软件快照不重置设备寿命；更换零件不自动更换整机身份或清除所有历史责任。维修后依据范围重评相交保证，保留尚未检验区域；传感器测到正常不等于所有隐藏损伤不存在。

完整交付可包括模型、图纸、BOM、工艺/配置候选、检验程序、仿真工程、软件固件、接口与来源，但工具输出、实际制造完成、安装、验收和现场资格分别观察。现实动作进入原execution，不由图纸生成隐式下发到生产设备。退役还包含残余能量、危险材料、数据、密钥、资产归属和可回收责任，不能用删除文件代表物理退出。

**适用范围：**Gift交付工程模型与获准工具结果，不宣称自动替代实际制造和专业验收。

**重新检查条件：**物料转换、实际配置、工艺窗口、寿命模型、检验能力或退役责任改变。

验收的具体触发与观察见[全域接合检查](../运行/验收/全域接合检查.md)；这里定义机制与条件，不签发任何实现、执行或现场合格状态。

## 物料、配置与寿命的普通作者模型

工程模型采用共同名义record/variant与函数，真实对象由Rule的subject槽绑定；数据模型不捕获Subject、Grant或运行设备。设计对象与现实对象的原信息引用仍由[对象关系与配置基线](../信息/对象关系与配置基线.md)解析和保全，不以普通Text ID自签存在、同一性或当前状态。以下类型中Part、Material、Configuration与History为项目公开的准确名义值类型，其内部字段由该项目定义，不能以任意JSON替代。

```text
ConfigurationView = Designed | Planned | Built | Installed | Maintained
ConfigurationModel<C> = nominal record { view:ConfigurationView, value:C }
MaterialAmount<M,Q> = nominal record { material:M, quantity:Q }
Transform<I,O,L> = nominal record {
  permitted:(I,O,L)->Bool !{},
  process:(I)->Result<{outputs:O,boundaryLosses:L},PhysicalModelError> !{}
}
LifeModel<H,O> = nominal record {
  observe:(H)->Result<O,PhysicalModelError> !{},
  update:(H,O)->Result<H,PhysicalModelError> !{},
  admissible:(H)->Bool !{}
}
PhysicalModelError = InvalidConfiguration | InvalidQuantity | OutsideProcessWindow
                   | MissingHistory | UnsupportedAssessment | NumericFailure
```

Q是带单位/Frame/测量不确定的准确数量型，不能把件数、质量、长度与中心估计混用。I/O/L可为普通列表/记录形成多对多拆混输入、产品与边界流；L可以与O不同型，例如产品为件数而损耗为质量/气体排放。process返回的outputs与boundaryLosses共同接受permitted判定，不能固定一份无关outputs字段再运行另一输出。每种I/O/L的准确公开记录还必须包含相应物料型、Quantity及来源对应；位置、重数与输入输出谱系映射由该实际项目定义，缺这些相交定义时为InvalidConfiguration/UnsupportedAssessment，不能只剩任意列表就宣称制造闭合。boundaryLosses不能以空值掩盖排放/副产品。permitted描述所选封闭边界与工艺条件，不因为返回Bool就证明守恒或可制造。process计算工程候选/预测，不授权实际制造；需实际设备的方法使用原Effect/Operation合同，不冒充本纯函数。

ConfigurationModel的view是观察角色，不按枚举顺序取latest；真实对象、配置基线、工艺/检验与源对应在使用此值的Rule/原信息关系分别绑定。同一对象可同时有不同view，不以Designed覆盖Installed。LifeModel消费完整所需历史，update是模型状态演进；现实维修/磨损事件在独立执行事实中取得，恢复H只能恢复模型解释，不撤回现实消耗。配置/物料/工艺/寿命/检验定义改变时，重核真实相交消费者和现场适用资格，保留原历史及未检区域。

被动构造这些值可在合格设计阶段完成，符合原闭合构造规则的默认仍不执行process/update。图纸、BOM、仿真、固件和检验程序各按原输出根交付；普通模型值完整不表示已制造、安装、验收或完成物理退役。
