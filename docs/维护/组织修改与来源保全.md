## 目录按责任，入口按任务，内容按性质

物理目录先区分规范、范本、决策、研究、状态和导航；规范内部再按目标、开发面、工程模型、语言、领域、编译、执行、演进和信息体系分责。当前布局及扩展条件由[文档架构](文档架构.md)拥有，根入口按读者任务链接到同一正文。章节编号是位置提示，不是权威、实现先后或读者必须依次通读的证明。

规范、解释、决定、参考、当前状态和研究可以属于同一主题，但要有明确身份。既不把几十章全压成同级知识清单，也不为每个关键词建一层空目录。章节过长且读者只需其中一个独立问题时可以拆开；相邻内容共享同一责任并大量互相复制时可以融合。文件数和目录深度没有固定最优值。

当前是设计包，不是已发布软件的教程站。教程与操作指南要有对应可用入口后才称为可执行指南；设计中的路径、界面和命令应标为示意或目标协议。[Diátaxis](https://diataxis.fr/)区分教程、操作指南、参考与解释，可用于识别不同阅读需求，不机械要求四套平行正文。


## 修改、删并与来源保全

修改先确认源版本和相应消费者，再检查是否新增、修正、合并、移除或仅移动。删除同义段落可只记录承接位置；撤销独立规则要给反例或条件变化；暂未实现但有明确消费者的义务不能因当前不做而删除。

没有消费者的口号、重复导航、过期进度状态和无效引用可以移除。历史原型、实验和快照在其原制品保留；当前设计不递归携带全部历史。真正法律、事故取证或恢复义务要求保存的内容，按该范围保存，不能用文档精简替代数据保全判断。

来源区分用户要求、历史设计、仓库观察、外部标准、实验和当前推导。同一新闻或标准的多次转载不算独立证据。没有核对当前仓库就不写“源码已完成”；没读到旧原则不能写“全部无遗漏”。当前重新裁决要标为当前裁决，不伪造历史作者理由。

从旧原则继承时保持独立约束，但复审绝对措辞。例如“必须常驻进程”只能在重复任务节省成本且宿主允许时成为具体策略；不能因过去写成必须，就强迫一次性SDK启动守护服务。


## 中文、术语、链接与长文访问

当前中文规范是权威维护源；代码标识、协议字面量、单位和标准名保留明确拼写。译文的身份、版本、失效与回退由[兼容迁移与退役](../演进/兼容迁移与退役.md)拥有，不在这里复制状态机。历史英文权威版本可以作为历史来源，不能自动覆盖本版已明确的中文权威。

新概念先定义对象与边界，再命名。事实、要求、模型、源码、缓存、证据和授权不互相换词。正文用完整因果句；表格用于比较，标题用于检索，不用术语名单冒充设计覆盖。

链接直接指向当前实际章节；移动后重写全部相交入链。当前包不承担历轮文档路径兼容，不为每个自然段创建外部ID。未来真实发布的翻译或产品API如有长期引用合同，应按那个系统的具体范围实现，不能先成为本设计包必须维护的旧址服务。

人可以沿任务地图浏览；AI可以按标题与范围取文。索引只提供定位，不是已读证明。长章节要有清晰段落边界，不能因为文件合并就把全部内容塞入每次上下文。删除一个重复小文件与把不相关内容合并为巨卷，是两种不同动作。


## 根要求和组合设计的联动审查

每次提升“整体正确”“完整”“最优”“更简洁”的结论，先固定评价对象与任务范围。候选是否符合自己的规则、是否满足原任务、是否在目标实现正确以及是否值得采用，分别给出依据。不能以文档自洽替代要求满足，也不能通过修改要求来修复实现失败而不披露目标变化。

写组合机制时至少说明上游实际提供什么、下游真正需要什么、转换保存与改变什么、共同资源由谁承担、开放假设怎样闭合。只写“各组件先校验，然后拼装”是不完整的设计。写优化时明确部分状态何时可比较、下界和估计来自哪里、被剪枝候选为何不可能更好。未经这些前提，不把局部更快直接升级为整体更优。

规范引用的正向流程应当可追踪：根要求到组合、组合到实现选择、选择到目标、目标到检查与作用，各自拥有者提供输入和结果。允许长篇消歧，但总览不重新抄写领域算法；可以以完整轨迹联结已有规范，避免新增多个能独立修改的总计划。新结论必须同时检查原合法路径和最强反例，不能靠持续增加拒绝条件制造安全假象。

假设数值必须明确标为构造案例，列出单位、共同省略项和可计算关系；不可写成实际性能报告。规范名含Proof或Evidence不意味着文档自动产生证明。静态计数只说明已检查的结构，源文献的机制说明只支持相应边界，不认证本项目实现。


## 跨章冲突与问题发现的审查单位

审查单位不是文件数量，而是一个能够改变行为的规则及其消费者。先提取该规则的对象、身份命名空间、版本、前置、正常/失败顺序、读写范围和授权点，再与调用方、状态机、组合示例、理由和合同解释交叉比较。相同关键词可能是不同对象；相反措辞也可能分别描述历史反例与当前规则，不能机械替换。

持续审查重点包括删除、回退、权限变化、集合新增、同结果不同依据、语义翻译和异步重连等接缝；它们常在单组件正常路径中不可见。找到根冲突先修规范拥有者，再同步直接消费者；无法完成的相交处明确保留，不能只追加“以本章为准”。发现策略及未审状态由[覆盖与反例方法](../演进/工程挑战与覆盖边界.md#3-反例生成与跨边界追踪)承担，本章不再复制发现轴。

删并理由时回看被删文本是否还有独立更小替代、失败路径、时间/权限范围、例外和反转条件。文档历史定位不保留在当前包，也不作为内容已融合的证据；同一条规范在理由中可解释但不再复制完整字段表。外部依据用来源版本、命题范围与实际记录日期区分，旧结果不因复制就成为当前核验。

## 交付前的约束与正文检查

这是每次设计文档修改的结束过程，不能延期到用户再指出问题后处理。它检查本次实际成果和相交规则，不声称对开放世界作完全证明。规则装载由[AI协议](../开发/AI协作/规则装载与任务恢复.md#任务启动的原则装载与动作检查)负责，此处只定义交付动作，不重复维护另一份入口流程。

| 检查 | 实际做什么 | 不合格时的处理 |
|---|---|---|
| 需求与目的 | 对照全部已取得要求的适用分类及本次授权，辨别要求、事实、建议与采用 | 回到原要求修方案；技术比较不自动加入发行或实施 |
| 正常与反例 | 对变更规则说明主体、条件、动作、结果、保持范围；构造最强的相反路径 | 有机制可裁决就修改；独立未知登记准确缺项，不让所有合法路径只剩拒绝 |
| 真实消费者 | 沿调用、语义、目标、权限、图表、伪代码、示例、理由与问题核同一规则；代码围栏不是免检区 | 修改原冲突及相交边和默认，不追加“以最新说明为准”；独立消费者未查不能称已覆盖 |
| 删除与融合 | 对删除块检查独立约束、反例、资源/错误路径、来源与重开条件的去向 | 有独立内容先吸收再删；历史恢复、版本兼容和实际证据不按关键词删除 |
| 组织与定位 | 职责唯一，入口按任务；无重复完整协议、过期接口、历史工作流和未采用活动载荷 | 合并到拥有者并改入链；旧版本保留工作历史，正文只保留当前机制 |
| 结构与制品 | 先核原始ID重复，再核UTF-8、标题、围栏、链接/锚点、文法差异和文件成员；按图文规则分别检查源、实际渲染和语义 | 修正后重查最终解压结果；未做渲染不能写视觉通过，脚本留包外，不增加参考产品 |
| 结论与交付 | 区分改了的规范、静态结果、实际实现、运行和覆盖限制 | 报告只写取得结果；不能用链接数量或“已审查”代签语义正确 |

结构性错误和已经确定的约束冲突是这次交付的修复责任。确有工具、权限、数据或平台限制无法完成时，仍可交付有用成果，但要明确剩余范围和对使用的影响，不能把受影响部分标成通过或静默省略。一般设计未知不必阻挡全部无争议工作。

### 三类约束由不同机制处理

**结构与动作边界：** 路径、操作类别、写入范围、协议字段及格式，可以由实际读取器或宿主检查。未部署就仍是实现义务。

**规则含义与组合：** 范围是否完整、两个接口是否相容、错误顺序和要求是否保持，需要具体算法与领域审查；全文搜索和LLM自述不能证明它们成立。

**现实效果：** 工具是否运行、目标是否改变、多少成本与实际资源是否停止，需要现实对象和对应观察。文档工作不擅自补做这些实验，也不以没有实验为由拒绝现在能完成的设计裁决。

当前文档审查可以使用解析、差异、模式搜索和引用扫描定位问题。读到一个关键词不等于有错；没匹配到也不等于正确。记录实际读过的对象和检查范围，避免全绿的模板化声明。

### 跨章一致性的一个检查单位

“实参按源出现顺序求值”涉及语言、结构体、IR、目标降低、示例和验证。若IR又写成“按形参定义顺序”，即使两章都各自能解析，也是实质冲突。修正原句后，用具名参数、报错与非终止的反例核所有相交消费者。

“AI首期”不意味着所有人工参与都禁止；它意味着人工不被无依据地设为普遍前置。检查应保留实际政策要求的人类或多人审批，同时修正“无查询就转人工”“控制失稳必须人工停机”等过宽默认。

**关闭一个文字冲突，不等于关闭整个功能。** 当前问题保留稳定ID，实际更新相应设计子项；旧读者、原语言版本、数据和在途操作的兼容另按其合同处理。


## 架构选择必须改到实际数据和流程

一次声称“直接复用成熟实现”的设计修改，至少回查：项目根能否引用该实现，读取器是否仍强求本地源，签名是否只能从body产生，编译器是否无条件展开主体，目标是否强制Host包装，依赖是否由多个生产者竞争写，运行实例是否被编译缓存共享。只在总纲写优先复用而保留这些旧路径，仍属未完成修改。

总览应展示作者工程、产品代码责任、运行依赖和生成工程四个对象；实现接口应给出真实联合、拥有者、分支和失败结果；至少一条正向范本走完多个模块。没有新增工作需要的现有规范直接引用，不把每轮“重设计”变成新增整套平行架构。历史反例和旧画像保留其范围，不再冒充所有消费者的默认路径。

实际核对接口还须追踪生产顺序：消费者不能要求一个由自己后继步骤才产生的完整对象；类型就绪、效果闭合和最终调用资格不能因名称相近混用。计划必须产出真实差异/方法或准确缺口；跨文件关系要核语义读集、共同发布、取消和第二次修改，不能只逐文件检查语法。高层需求新增时保留既有短源与精确编辑能力；改变某项旧规则要有反例和相交改动，不为“保全全部字节”留错误，也不为“统一”删除正确成果。


## 本地链接和锚点的作用及删并规则

Markdown形如`[恢复算法](../运行/持久化提交与恢复.md#attempt-finality-and-retry)`的本地链接，表达一个文件及其段落定位。`#...`是目标页面的锚点，通常由标题形成，也可以是显式HTML id。它不是代码调用、编译依赖、测试、权限或规范本身；链接数不计作设计完成数。

它有三种实际用途：读者直达当前规则，调用方不复制整份规则，材料与其当前解释在同一版本内可定位。一个问题必须明确说依赖什么，链接才有关系含义；仅将所有文件互相链接不能证明相容或追踪完整。

当前选择是**责任入口保留，重复导航收拢**。首次交接到另一个规范给准确链接；危险动作旁可重复短关键前提，不在每段末尾重复同一目录。根目录提供任务入口和完整文件导航，普通任务不必逐项点击。链接目标范围过宽时改善标题/锚点，而不是复制正文。

移动或合并章节先更新当前本地入链并核对含义完整承接。不为本设计包推定未知外部读者、建立旧址兼容义务或默认保留历轮别名。真实外部站点的发布合同与本库范围分别处理；删去旧址表不删除旧原件，也不能据此宣布外部旧链接已迁移。标题变化仍不自动改变产品语义身份。

静态检查验证路径和锚点存在、重复id与围栏；语义审查另核链接是否指向正确规则、版本是否相容、接口是否真正满足调用方。两者均有价值，不能让上千个链接通过掩盖一个关键未定规则。统计计数只放核对记录，不作为首页质量标题。


## 语言体系和资料目录的同次交付

语言审查不能只列一张关键词表，也不能以“不是关键词并集”拒绝系统比较。当前按[能力裁决](../作者/需求关系与能力边界.md#4-完整语言能力的当前裁决)给语法、类型、控制、内存、错误、模块、阶段、目标和编辑各自选择，再审实际交点；用户只提出其中一项时仍承担关联检查。新构造必须同时修改实际消费者，已知语言空白与已明确不采用分别保存。

所有来源格式接受同一[维护协议](../依据/来源/设计依据与资料边界.md#研究结论的保存复用与失效协议)。交付检查核源码外的实际引用能否定位到已有来源命题，每条记录有没有使用/维护位置，新增命题是否写清版本、范围和限制；普通链接、表格来源、补充段落和未定位理论不能成为漏检通道。未知历史日期不编造，目录结构完整也不等于原始网页全体重新核验。

本协议只新增必要的使用关系，不复制整套领域算法。长路径可用标准Markdown引用链接在该文件定义一次；显示标签和引用定义都要参与静态定位。来源改变真实设计前提时同步改规范、图和U/D，而不是建立一份“所有资料需要更新”的永久工作流水账。


## 知识保存与工作材料分流

| 内容 | 唯一去向 | 保留方式 |
|---|---|---|
| 用户要求及当前任务边界 | 产品要求清单；根原则处理跨主题冲突 | 准确范围、来源和机制位置；不保存重复对话全文 |
| 当前接口、算法、状态与失败处理 | 对应领域规范 | 直接描述系统应如何工作，附条件和反例 |
| 采用或拒绝一个方案的理由 | 对应D条目 | 当前选择、最强替代、代价和重开条件，不写讨论时间线 |
| 外部知识 | 来源目录与相交正文 | 命题、版本、前提、限制和采用，不按搜索轮次编排 |
| 当前未完成工作 | U主登记 | 当前方案、真实剩余、下一交付、关闭与重开；不积累空进展 |
| 文件修改、旧仓库观察、实验与封装成绩 | 独立工作记录或原证据制品 | 精确输入、结果、范围与日期，不递归打包进现行设计 |
| 真实迁移、事故或恢复仍需要的历史 | 对应操作和证据存储 | 按实际法定、取证、兼容和恢复义务保留，不按文档简短程度删除 |

每次编辑先分类，再修改唯一拥有者。历史描述中含有有效机制时，将机制改写为现行条件、算法或反例；只含编辑经过的段落移出。只有标题、旧ADR编号或裸链接但没有可用定位的条目不充当知识依据。删除时保留必要来源的外部去向，不能删除未解决义务或断言所有读者已迁移。

交付前检查两个方向：新增规则是否取得明确要求、实现责任和消费者；被删内容中的独立条件是否已保留。词法扫描只定位候选，不能机械删除状态机history、恢复历史、版本锁或用户原文中的“历史”。未发现关键词不构成语义无遗漏证明。

[产品要求与工作约束](../产品/产品要求与工作约束.md)用于核对实际取得的要求，依据覆盖范围报告记录、装载、强制和核验；它不是平台自动记忆。文档身份与支持边界由根入口统一说明，不在每章复制一段“本次没有运行”的工作报告。

## 信息体系规则的唯一拥有者

本章继续定义写作与独立内容保全；[文档身份与重组协议](文档身份与重组协议.md)拥有移动、分拆、引用和发布算法；[对象关系与配置基线](../信息/对象关系与配置基线.md)拥有SEC产品对象与准确修订的解释，不拥有本库旧文档导航；[接入检索与派生协议](../信息/接入检索与派生.md)拥有查询、覆盖、披露与派生。普通目录层级和一个搜索框不能替代这些合同，反过来也不能把每个自然段登记成产品对象。
