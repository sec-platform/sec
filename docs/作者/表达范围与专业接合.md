# Gift 开发面表达能力统一收敛

本章归并已识别的表达范围与采用决定；具体语义由引用的唯一正文承担。此分支为设计候选，正式采用与产品实现分别取证。

## 本次采用

保留VS Code Extension-first、JSON单源、原六工具/十职责、原Requirement/Claim/Execution分工。新作者候选接纳准确旧Body，增加Unicode分空间引用；高级类型与专业模型通过既有extension边界取得完整语义。不要求普通开发者逐层写IR或自建求解器。

“收敛”的对象是这26项指定问题的设计决定和本包所给具体见证。以下每项都有采用结果和边界，不把“尚未实现”说成没有表达；也不把有限画像扩大成所有未来专业模型已经实现或形式证明。

## 实际表示与唯一拥有者

完整语义由[SEMANTICS](../../schema/author/first-layer/SEMANTICS.md)拥有，三个Schema只检查其各自结构。第一层语言、结构源、编译承接、VS Code、连续修改和验收分别由相应正文拥有；阅读投影不成为第二规范。每个新源都能追到具体Body和解释规则，不依赖只在聊天出现的名字。

`sem`和`surface`供给清单是绑定准确设计字节的声明，implementation明确NOT_IMPLEMENTED；没有安装供给，不会有运行权限。旧req解码直接复用其已固定专业合同，不建立不完整的复制语义。各专业画像共同使用一个源容器，不强制共享错误的否定、状态、时间、概率或证明含义。

## 未被本轮冒领的结果

设计与结构校准不证明Gift运行、产品套件通过、正式采用或生产Reader切换。没有机械证明System F/依赖片段所有健全性、任意超逻辑组合、一般连续系统或所有物理目标；没有从有限样本保证所有未来意图都存在有限有效实现。

本包保留表达、方法与实施的区分：对本次给定专业对象，实际源码及规范已给；特定求解器/目标的能力和成本另取证；未指定的未来专业对象不靠空payload或一张目录表自动接纳。更复杂的原生语义保留原生单源与合格专业适配，不强迫作者改写成较弱中立画像。

## 后继施工的具体接合

要实施时，先沿已定源边界实现准确Reader、绑定和源映射，再按实际首个产品根选择所需方法；不把全部画像同时实现设为普通项目的前置。旧格式迁移需完整相交引用图、消费者、事务提交和回退，单个校准补丁不能代签全仓迁移。新专业运行返回Needs时，继续完成独立合法根，不把未知转换成通过或把下层工作退给应用作者。

当前本包新增的是设计与结构校准，不产生新的长期Work记录或第二套项目台账。所有旧例仍保留各自准确版本和支持域，不能跨版本读取后静默重解释。

## 本轮继续的真实差额

[专业解释与消费者](../../schema/author/first-layer/SEMANTICS.md#model-contract-use)拥有两个相交变化：专业模型成为原require消费的声明，以及原/补救义务与接受事件的独立身份。原有架构规则不重做；新增源、解释、校准、二次修改和实际未完成边界分别交付。
