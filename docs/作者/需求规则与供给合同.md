本章拥有工作台范本实际使用的设计库合同：公开主体、字段和值、约束含义以及实现消除责任。它不是一份宣称已安装的 `sec/spec/*` 包目录。**每个名字在本章有明确设计，当前没有发布其运行库或实现适配。**文档结构检查只能检查这份源是否引用了已写出的合同，不能证明这些合同已经被实现。

普通项目使用这些合同不复制本章。生产实现应把同样的精确公开定义和方法置于原Definition/ImportedModuleView与语言锁中；当前文档表不能在每次构建中被AI重新解释成新语义。纯底层库也能实现一个要求，不必伪造同名SEC算法体。

## 1. 定义不是营销名称，参数也不是任意JSON

一个RequirementDefinition必须拥有以下内容：精确身份/版本；字段schema与值域/单位/引用种类；被约束的SubjectSchema；适用输入与观察；正常、错误、帧及进展条件；组合/默认/失效规则；真实实现方法或明确未实现；方法前提与证据责任。未知字段、同一字段重复、普通字符串代替名义枚举、无绑定引用均不能默默通过。

`SubjectRef<K>`标识被约束对象，不是机器地址；`RuleRef`引用需求定义；`DesignRef<S>`引用一参数复合需求定义；`PredicateRef<X>`引用有确定语义的谓词/关系；`Selector<S>`标识有明确成员解释和范围的主体集合。它们是已有语义实体的类型化引用，不能互相强转。此处不新增运行时句柄协议。

记录字段排列只是书写顺序。`operations/features/access/platforms/modes/targets`为有限集合，重复值去重不产生重复调用，并保留来源；`scopes`的实际优先级由`precedence`字段规定，不由列表顺序猜。指向同一准确逻辑主体的硬约束合取；同名义类型但身份不同的Subject分别受约束，除非存在明确关系连接二者。类型相同不等于主体相同。同一主体同一字段的相冲突要求不按最后一项覆盖。必要的关系顺序、输入多重性和事件顺序由其具体合同拥有。

除了下文明确的变体，表中给出的名义值具有其完整说明，不能用名字相近的另一个值替换。定义可以继续发布新变体而不新增语言关键词，旧绑定不自动升级。结构条款中的`require`标签（可选文本示意同名）不是构建时调用构造器，方法被选择与执行属于编译/受授权运行阶段。

## 2. Workbench主体图是观察模型，不是强制服务图

`sec/spec/ide.Workbench`是本文范本的名义根schema。角色从一个根s派生稳定局部身份；两个不同根的相同角色不是同一主体。角色在模型上存在不意味着对应运行实体一定被分配；只有有效要求需要它时才取得实现。

| 路径 | Subject种类与公开观察 |
|---|---|
| s.workspace | Workspace：根、资源身份、枚举覆盖、读写与工作区状态 |
| s.documents | DocumentSpace：文档集合、实例、版本、字节/文本及草稿 |
| s.editor | EditorSurface：视图、选区、输入、焦点及编辑动作 |
| s.history | EditHistory：动作组、撤销/重做及相交资源 |
| s.search | SearchSurface：请求、查询代、结果、覆盖和选择 |
| s.replace | ReplacementSurface：预览计划、接受、应用与逐项结果 |
| s.languages | LanguageServiceSet：版本化方法能力、文档输入及结果 |
| s.diagnostics | DiagnosticSet：生产者、范围、输入代与诊断 |
| s.tasks | TaskSet：声明入口、实际运行及子资源寿命 |
| s.terminal | TerminalSet：进程输入、输出、信号与关闭 |
| s.debug | DebugSessionSet：已加载来源、停点、控制及观察 |
| s.tests | TestSet：发现范围、案例、期望、实际运行与结果 |
| s.vcs | VersionIntegration：工作树、暂存、提交与远端状态 |
| s.extensions | ExtensionSet：内容、贡献、能力需求与隔离运行 |
| s.settings | Configuration：schema、各层值、秘密引用和生效版本 |
| s.shell | WorkbenchSurface：布局、命令、焦点、主题、消息与可访问性 |
| s.release | DeliverySet：各平台源树、成员、依赖、来源及发行条件 |
| s.effects | EffectBoundary：根下所有受管外部作用的真实准入和结算 |

每项字段的`on/documents/workspace/...`必须匹配对应种类，s本身为Workbench。`experience.Commands.targets`接收异质的公开动作主体引用，但不是任意JSON；每个主体必须有真实的动作/输入/输出/错误描述。Role到实现可是一对多或多个角色共享一个实体，前提是身份、生命周期和隔离要求允许；不得按同样字符串给每个需求各分配一个不同模型。

## 3. 本范本采用的具体需求定义

下列所有契约都要求其定义的正常功能在满足公开前提且资源允许的合法输入上可用，不能用总是返回Unavailable空实现满足。环境前提只能来自公开定义及已接受部署，不可由方法为了通过而私自加强。失败结果保持草稿/来源/恢复责任，不能作为吞掉硬要求的捷径。

### workspace.Roots

打开、关闭、列举根与资源。重叠根的同一资源只在明确展示语义允许时重复展示；搜索去重不能跨主体误合并。空工作区仍可用。

| 字段 | 本源的值/引用 | 准确含义 |
|---|---|---|
| `on` | `s.workspace` | 根集合的主体身份 |
| `multiplicity` | `workspace.Many` | 允许零个或多个根；未打开根不算失败 |
| `identity` | `workspace.ProviderIdentity` | 按提供者的规范资源身份，显示路径不定义相等 |
| `nested` | `workspace.ExplicitMembership` | 嵌套根的归属选择显式，不按扫描先后隐式抢占 |

**实现责任：**[M01](#realization-methods)。**失败与限制：**提供者不能枚举时返回覆盖缺口；不把不可读根当空根。

### workspace.Files

文件树提供读取、新建、移动、删除；移动更新资源关系但不凭显示名改写身份。相交编辑草稿不因操作失败被静默删除。

| 字段 | 本源的值/引用 | 准确含义 |
|---|---|---|
| `on` | `s.workspace` | 同一工作区主体 |
| `operations` | `[workspace.Read, workspace.Create, workspace.Move, workspace.Delete]` | 要求的真实资源操作集合 |
| `conflicts` | `workspace.PreserveDrafts` | 相交未保存内容必须保留或明确冲突 |
| `access` | `workspace.RuntimeGrant` | 产品在每次作用处检查实际许可，不是此声明给予许可 |

**实现责任：**[M01](#realization-methods)。**失败与限制：**跨卷、大小写等价、只读和并发修改分别走提供者合同，不承诺跨文件原子。

### workspace.Snapshot

每次读取绑定根、模型实例与内容代；已打开文档按当前模型解释，其他资源按提供者版本。显式报告枚举缺口、失效或取消。

| 字段 | 本源的值/引用 | 准确含义 |
|---|---|---|
| `on` | `s.workspace` | 捕获的工作区主体 |
| `documents` | `s.documents` | 此工作区采用的开放文档集合 |
| `precedence` | `workspace.OpenModelWins` | 已打开模型对该资源权威于旧磁盘内容 |
| `absence` | `workspace.OpenEmptySuppressesDisk` | 打开模型零命中或空内容也抑制旧磁盘结果 |

**实现责任：**[M02](#realization-methods)。**失败与限制：**无法得到同代稳定输入时保留部分结果/失效；不拼出伪全局同时刻。

### workspace.Recovery

异常退出后能区分已保存、草稿及未知现场；恢复草稿前核原身份与前像，冲突保留。已开始的外部操作按原意图查回而不是再执行。

| 字段 | 本源的值/引用 | 准确含义 |
|---|---|---|
| `documents` | `s.documents` | 可恢复草稿主体 |
| `history` | `s.history` | 与草稿绑定的编辑历史 |
| `mode` | `workspace.RecoverDraftNotReplayEffects` | 恢复内容与历史不重放外部执行 |

**实现责任：**[M03](#realization-methods)。**失败与限制：**缺恢复存储能力时不能承诺持久草稿；恢复失败不覆盖新现场。

### editing.Documents

每个文档有模型实例、版本、语言与原编码依据；合法范围不拆代理对，跨协议坐标需转换。二进制/未知编码不假装可无损文本编辑。

| 字段 | 本源的值/引用 | 准确含义 |
|---|---|---|
| `on` | `s.documents` | 文档集合主体 |
| `resourceIdentity` | `editing.FromWorkspace` | 与根/文件操作共用资源身份 |
| `coordinates` | `editing.UnambiguousSourcePositions` | 位置绑定准确文本及可核对的坐标含义；字节、标量、字素及UTF-16等内部/外部单位由适配转换，不强制一种内部缓冲 |
| `encoding` | `editing.PreserveOrExplicitConvert` | 保存保留可复现原编码，改变必须是明确转换 |
| `newlines` | `editing.PreserveOriginal` | 保留原换行；显式规范化是独立行为 |

**实现责任：**[M02](#realization-methods)。**失败与限制：**无法无损解码时保留字节并要求明确文本/二进制选择，不静默替换字符。

### editing.Editor

支持打开、切换、选区、输入、删除、分屏、查找本文件；同一文档在多个视图中的文本一致，光标/滚动可按视图独立。输入组合/撤销按真实编辑动作分组。

| 字段 | 本源的值/引用 | 准确含义 |
|---|---|---|
| `on` | `s.editor` | 编辑交互主体 |
| `documents` | `s.documents` | 实际被编辑的模型集合 |
| `selections` | `editing.Multiple` | 多个选区与光标及确定合并/冲突规则 |
| `views` | `editing.ManyViewsOneModel` | 多个视图绑定同一模型而不是各复制一份内容 |

**实现责任：**[M04](#realization-methods)。**失败与限制：**IME和坐标映射能力不足不得标成完整编辑支持；重叠编辑按固定规则处理。

### editing.History

撤销和重做保留精确作用资源、模型和次序。跨资源撤销组不等于磁盘事务；用户之后继续修改时必须协调，不能覆盖现场。

| 字段 | 本源的值/引用 | 准确含义 |
|---|---|---|
| `on` | `s.history` | 历史主体 |
| `documents` | `s.documents` | 同一模型集合 |
| `grouping` | `editing.ByUserAction` | 一组实际用户动作形成一个逻辑撤销组 |
| `undo` | `editing.IfCurrentCompatible` | 只有现场/历史允许才执行逆编辑 |

**实现责任：**[M03](#realization-methods)。**失败与限制：**不兼容前像或已失效外部观察返回冲突；不把补偿称为时间倒流。

### editing.Save

保存选定模型，记录参与者前后像和各提供者结果；未保存、保存失败和未知不可报成全完成。这里只要求普通可见保存，不冒称断电耐久或跨文件事务。

| 字段 | 本源的值/引用 | 准确含义 |
|---|---|---|
| `documents` | `s.documents` | 编辑完成的模型 |
| `workspace` | `s.workspace` | 真正持久化目的地 |
| `completion` | `editing.PerResource` | 模型编辑与各资源保存分别结算 |
| `participants` | `editing.ExplicitChanges` | 格式化等保存参与者产生的字节变化可见 |
| `conflicts` | `editing.PreserveBoth` | 外部写冲突保留双方内容/依据 |

**实现责任：**[M03](#realization-methods)。**失败与限制：**提供者没有耐久、CAS或冲突能力时不代签；改了但未保存只重试合格保存。

### search.Text

搜索多根文件并按当前模型覆盖磁盘；范围、大小写、包含/排除和语言/编码选择进入请求。结果支持导航与逐文件聚合。完整上下文与截短展示分开。

| 字段 | 本源的值/引用 | 准确含义 |
|---|---|---|
| `on` | `s.search` | 查询、结果与覆盖主体 |
| `workspace` | `s.workspace` | 检索范围 |
| `documents` | `s.documents` | 同一编辑内容集合 |
| `pattern` | `search.LiteralAndDeclaredRegexDialect` | 字面量及绑定的正则方言；不是所有引擎等价 |
| `results` | `search.MatchWithSourceVersion` | 完整命中含模型/源版本与坐标 |
| `coverage` | `search.Explicit` | 完整、截断、未读、失败、取消不同 |
| `cancellation` | `search.SupersededCannotPublish` | 旧查询可在途但不能发布为当前 |

**实现责任：**[M05](#realization-methods)。**失败与限制：**正则不可保持或覆盖不足时给真实缺项；不因命中数达到展示上限声称全部。

### search.Replace

从真实命中与完整文本计算编辑及前后像；预览只改独立模型。应用前及最后写边界核实际模型版本，逐资源编辑/保存。并发更新使旧计划失效。

| 字段 | 本源的值/引用 | 准确含义 |
|---|---|---|
| `on` | `s.replace` | 替换计划主体 |
| `matches` | `s.search` | 来源为同一搜索结果 |
| `documents` | `s.documents` | 写入同一组模型 |
| `preview` | `search.DisplayedEditsOnly` | 预览固定选择、替换表达式、源和精确编辑 |
| `acceptance` | `search.DisplayedPlan` | 应用接受的是显示计划而非当前输入框重算值 |
| `stale` | `search.Reject` | 源/模型/策略过期时本计划拒绝应用 |
| `scope` | `search.SelectedOrCompleteScope` | 允许明确选择；未明确选择的全量要求必须完整 |
| `recovery` | `search.ReconcileNoBlindReplay` | 分项查回，不重放已发生编辑 |

**实现责任：**[M06](#realization-methods)。**失败与限制：**不存在最终版本保护能力时拒绝强写入；不把只读命中默默剔除后称全部替换。

### search.Presentation

结果树、计数、选中范围、差异预览及逐资源结算使用同一事实来源；焦点/展开状态保留；移除显示项不是删除资源。

| 字段 | 本源的值/引用 | 准确含义 |
|---|---|---|
| `search` | `s.search` | 结果模型 |
| `replace` | `s.replace` | 替换计划 |
| `shell` | `s.shell` | 交互展示主体 |
| `navigation` | `search.ExactSourceMatch` | 定位到准确结果来源，陈旧项显示失效 |
| `readonly` | `search.InspectableNotWritable` | 只读项可看可导航但不可写 |

**实现责任：**[M04](#realization-methods)。**失败与限制：**不能显示源或完整差异时不得当作用户已确认；展示预算不决定计算覆盖。

### language.Providers

语言识别、token、诊断及导航使用明确服务和精确输入；本例发行至少绑定TypeScript服务及纯文本回退。新语言通过同一能力接口添加，不保证任意语言。

| 字段 | 本源的值/引用 | 准确含义 |

| `capability` | `language.NegotiateExact` | 逐方法、编码和版本协商 |
| `unsupported` | `language.ExplicitUnavailable` | 未支持与零结果区分 |

**实现责任：**[M07](#realization-methods)。**失败与限制：**服务退出或不支持分项报告；不得用旧磁盘分析结果覆盖新缓冲。

### language.Diagnostics

完整空结果只清本生产者及所声明完整范围；旧回调不得清新诊断。报告错误、未覆盖与工具失败，允许独立生产者共同贡献。

**实现责任：**[M07](#realization-methods)。**失败与限制：**没有版本依据或覆盖信息时降为有标识的历史/局部观察。

### language.Refactoring

更名、改签名、快速修复和导入整理输出普通候选；多文件与资源变化分清原坐标及順序语义，不能自动执行服务附带任意命令。

**实现责任：**[M07](#realization-methods)。**失败与限制：**未知动态引用和非事务宿主保留缺口；不把字段替换成功称为语义保持。

### language.Assistance

补全主编辑与导入形成同一候选；定义、引用、含义和参数提示按真实符号及输入返回。新建议不成为已安装库或已证明事实。

### execution.Tasks

运行、构建和watch以明确输入/工具/环境开始；只停止所拥有任务，结果绑定制品；C2不改写C1正在运行实例。

## 4. 本版明确支持的源变体

`search.Replace.stale`除`search.Reject`之外定义`search.RebuildThenConfirm`：旧计划一律不得写；系统可以取得新快照重算并展示新计划；必须取得对新计划的重新接受，旧接受不能迁移。它不是后台按新文本直接应用。两种值的差异是产品行为，不能由并发度或缓存优化偷偷切换。

`quality.Cost.metric`包含`quality.ResidentMemory`和`quality.InteractiveLatency`。前者是同负载下测量驻留内存，后者按同一事件起终点和采样口径测量交互延迟；未提供负载/测量时标未知。priority为正整数，按较小值先比较；同priority使用Pareto关系。只有高层全部已知相等才继续低层，折中、缺测、不可比较或重叠区间保留在该层，不能跳过；任何未知不得按零排序。比较和剪枝的具体规则由[实现选择](../编译/实现选择与设计搜索.md#preference-partial-order)拥有。当前锁合格而未请求优化时复用，不为了比较永远阻塞生成。无法分出优劣时，已委派的固定保守顺序可以选择可行者，但没有“最优”结论。

本版搜索请求的正则方言是显式输入/发行能力的一部分：发行必须公开至少一个已固定、定义清楚的RegexDialect，不能拿两个方言的同串模式互相冒充；字面量查找总可用。无方言参数的请求只能使用发行明确公布的默认；不根据当前机器安装了哪个搜索器改变解释。模式、大小写、全词、包含/排除及跨行设置的精确含义也在对应发行的PatternSpec中固定。这里允许采用不同方言发行，不承诺本例已经逐字复制某现有IDE的全部搜索行为；要求指定方言时它成为硬字段并限制供给。

默认界面资产`DesktopBaseline1`必须提供可读主题、消息键/参数签名、中文与英文回退、菜单/命令及键盘路由。在生产绑定中这些是确切文件/值，不是名字推断；本次只定义其行为与资产义务，没有生成冒充已完成的UI文件。作者后来提供品牌资产时按实际差异替换，来源与许可同时改变。

## 5. 新需求无需先增加官方业务名字

复合需求定义可以由已有要求组成，没有算法体也仍是一等定义。直接结构编码使用[有限逻辑组合](结构化源码.md#finite-requirement-composition)；以下更广开放构造是领域层的合同，必须分别具有实际字段、类型、解释和方法，不能因表内有名字就默认具有任意结构读取或求解能力。

| 公开需求构造 | 字段与准确含义 | 非平凡边界 |
|---|---|---|
| logic.AllOf | on:Subject<S>；parts:有限List<DesignRef<S>>。同一on同时满足所有parts | 空集合只无附加条件，不生成正常功能；功能由其他要求承担 |
| logic.AnyOf | on:Subject<S>；alternatives:非空List<DesignRef<S>>。选择至少一个完整满足的方案 | 不是每个方案挑一部分；不默认在运行期重选；相交硬条件仍都成立 |
| logic.When | on:Subject<S>；condition:PredicateRef<S>；then:DesignRef<S>；else:DesignRef<S>可选 | condition必须标编译期或运行期；未能决定的静态条件不能当false；运行分支需对应方法 |
| logic.Each | over:Selector<S>；rule:DesignRef<S> | 静态集要求真实覆盖；动态集要求每个实际成员进入时约束生效，不能只检查构建时成员 |
| relation.Transform | on:Subject<Function<I,O>>；accept:PredicateRef<BeforeAfter<I,O>>；frame:PredicateRef<`BeforeAfter<World>`> | 明确正常输入、允许结果及保持项；一个事后校验器不自动是转换实现 |
| state.Machine | on:Subject<S>；model:已绑定状态/事件/守卫/转移模型 | 表达状态语义，不要求作者写switch；非法、同时触发、资源与历史由状态合同处理 |
| temporal.Invariant | on:Subject<S>；property:PredicateRef<Observation<S>> | 声明全局保持，选择证明/构造/运行阻止方法；事后发现不等于预防 |
| temporal.Progress | on:Subject<S>；trigger/goal:PredicateRef<Observation<S>>；under:明确环境/公平性合同 | 永不触发或永不返回不能冒充正常可用；环境假设不能循环自证 |
| privacy.Noninterference | on:Subject<S>；secret/public:Selector；relation:多运行观察合同 | 不等于一次运行不写日志；侧信道与时间是否纳入由观察合同决定 |
| quality.StatisticalTarget | on:Subject<S>；population/method/metric/bound:精确绑定 | 一次样例/固定随机种子不证明分布保证；生成可输出待验证义务，不造证据 |

构造引用的是原RequirementTerm和对应域方法，不是普通JSON任意扩展口。结构any允许空域并将其解释为false；本表logic.AnyOf则以非空alternatives作为其接口前提，两者的定义域不同，不互相放宽字段。结构when/forEach/exists只覆盖准确有限静态条件与列表；logic.When/Each中的运行条件或动态集合仍需相应时序、成员与实现合同，不能用一次构建快照冒充全部运行范围。没有实现/逻辑规则的新PredicateRef可作为研究材料保存；只有取得其确切含义与方法后才能在强生成或证明中使用。真正新领域引入必要观察、参数和解释，仍沿原DomainDialect/Definition；不强制全部变成标量函数或万能谓词求解。

### 一个没有算法体的完整计算需求

“区间规范化”的输入是有限List<{start:Int,end:Int}>，采用半开区间。start>end为明确输入错误；start=end为空区间忽略。输出同覆盖、按start升序、区间非空、彼此不重叠也不相邻。这些条件唯一确定按并集最大连通分量划分的输出；数学Int不溢出。

```sec
import "sec/spec/interval" as interval;
export design Normalize(f: interval.Normalization) {
  require interval.Input { on: f, invalid: interval.RejectReversed, empty: interval.Ignore };
  require interval.Coverage { on: f, relation: interval.SameUnion };
  require interval.Canonical { on: f, order: interval.StartAscending, adjacency: interval.Merge };
}
```

这里interval三个合同的字段、类型和语义就由上述段落定义：on为同一个Normalization函数主体，invalid/empty/order/adjacency为本节名义枚举；Input引入合法域及错误，Coverage与Canonical约束成功结果。不调用排序、不写循环。排序扫描是一个实现：取得副本、按(start,end)排序、逐项归并当前最大end、输出最大不相接段；平衡树是另一实现。方法要证明同覆盖与最大段、处理原输入帧并绑定Int目标。此例只给设计，没有运行求解器或生成该程序。

作者可以把这三个要求封装成Normalize，下一处直接use它。再要求“输出与输入一一对应、区间数保持”时会与重叠输入合并发生冲突；不能为了支持新条件悄悄减少原输入域。改变为闭区间需要不同整数邻接语义，不能只替换展示括号。
