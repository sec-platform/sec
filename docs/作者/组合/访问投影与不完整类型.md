# 访问投影与不完整类型

> 条件能力设计；不改变已固定的基础画像，不表示实现或目标符合性已完成。

本页补充[语义扩展与领域接合](语义扩展与领域接合.md)中的相交能力；原章节继续拥有其已采用的有限语义。**当前选择：拆开保留，不整包采纳。** opaque、模块可见性、合法成员访问属于常用能力；protected/friend/成员指针原生语义是条件性接口需求。

这里的选择不是删除能力或承诺全部默认启用。满足真实要求的成熟库、静态展开和原生适配可以作为最终方案；额外语义只在现有路线不能保持该使用点的明确要求时激活。未提供对应解释、实现或目标条件时保留作者要求并返回具体缺项，不强迫所有项目携带设施。

文中的类型名、操作名与代码块为合同记法，不向现有作者文法添加关键词，也不直接发布 wire 字段。作者仍通过已有 Definition/require/prefer 或已解析原生定义提供真实差异；内部信息归入原 MethodSpec/BoundaryView/UseBinding，公开扩展必须另有准确版本及能力协商。共同准入见[能力履行](../../编译/目标/能力履行与接口差额.md)。

访问合同把“谁可访问哪个声明／成员、以什么 receiver、可否再导出”写清。公开／私有继承只控制相应的子对象转换与公开关系，不能自动改变已有成员的其他授权。

`protected` 使用受约束的派生关系与 receiver 路径判定，而不是放开整个包。`friend` 可以授予某个函数、类型或模板声明；授权绑定声明身份和适用版本，不绑定容易撞名的字符串。库明确转交成员能力时允许受控委派，否则生成代码与反射不能扩大授权。这里是语言封装机制，不是抵抗同进程任意机器码的安全沙箱。

成员指针用两种类型化句柄表达：`MemberProjection<Owner, Value, Access>` 与 `MemberCallable<Owner, Signature>`。它们可以携带固定偏移、动态路径、调整 thunk 或受限 accessor；不是普通地址。应用时检查 owner／路径／借用；位域或不可地址化的 packed 成员只能得到读写代理，不能得到假的 `&T`。要求 C++ pointer-to-member 原生字节表示时走指定 ABI 适配。

不完整声明只建立名义身份及可用签名，不伪造 size、align、字段或 Drop。允许经过指针／句柄的相互递归。按值存储、完整布局查询及某些析构实例化会触发定义完成；按值无穷递归的布局 SCC 必须被拒绝。公开不透明类型通过 owner 的工厂、析构和操作使用；把私有完整定义泄露给反射查询不是默认副作用。

Opaque 类型分两类：隐藏表示但实际 Sized 的模块私有类型；真正仅允许通过外部句柄使用的 foreign 类型。不能用大小为零的占位结构冒充真实 foreign 对象，更不能据此执行指针步进或内联分配。

## 再次修改与失效

可见性、名义声明或不完整定义补齐改变时，重查真实访问与布局消费者；公开句柄不能因名字不变获得新的读取权，缺定义的原字节继续可保全。

## 使用点与可检验出口

这些分支保留各自的真实输入、替代路径与边界，不按条数声称更多底层能力；[比较记录](../../依据/来源/Rust与C++能力比较.md)不拥有另一套语义。

- **多重实现继承**：保留多接口/组合需求；多基类对象模型只在兼容需求成立时启用。 硬边界示例：开放插件按多个基类 ABI 操作同一对象，且禁止额外间接层或改变原生接口；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a02)。
- **继承的 public/protected/private**：默认模块与导出规则；原生继承访问属于源适配器，不是通用新增权限系统。 硬边界示例：必须源兼容既有继承家族的访问规则，而不能重构模块或包装；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a04)。
- **protected 派生家族权限**：承认细粒度封装差异，按插件/扩展用例设计有限接口；不把 protected 当安全沙箱。 硬边界示例：库要求任意下游派生者访问受限成员，但普通用户不得获得同样入口；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a05)。
- **friend**：普通封装先用已有规则；有实际授权主体差异再加局部机制，不能从 friend 推出全局 capability 平台。 硬边界示例：固定模块边界、公开 API 与单个特权主体都不可改，且确需绕过普通私有性；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a06)。
- **成员指针**：常规访问器足够时不新造原语；确需字段投影时保留 owner/借用/不可寻址字段约束。 硬边界示例：要求精确 C++ pointer-to-member 表示，或既存泛型接口必须原生接收这种值；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a10)。
- **不完整类与前置声明**：复用现有 opaque/模块依赖；不是为了模仿 C++ 头文件而增加前置声明系统。 硬边界示例：原生接口要求同一外来名义类型的精确按值布局，但定义并未提供；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a11)。
- **语义静态反射**：编译器内部查询与用户开放反射分开；用例足够才稳定后者，C++26实现成熟度单列。 硬边界示例：需要无额外opt-in地检查未知类型语义，并把结果参与泛型实例化；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a40)。
- **reflection splice**：hygiene和绑定正确性必须保留；公共splice不是编译器项目天然必须暴露的语言功能。 硬边界示例：通用反射结果必须无损保持语义实体绑定，不能依赖字符串/显式metadata协议；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a41)。
- **原生位域**：按wire、设备、nativeABI分开；设备W1C等操作不可被通用RMW掩盖。 硬边界示例：必须精确匹配某编译器C++位域ABI且无可用布局信息/访问器；否则常规库足够；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a50)。

实际组合与拒绝条件见[验收案例](../../运行/验收/跨语言控制与组合案例.md)；从作者要求到再次修改见[连续开发情景](../../../examples/连续开发/跨语言能力连续开发.md)。
