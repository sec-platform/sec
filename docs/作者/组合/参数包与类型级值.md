# 参数包与类型级值

> 条件能力设计；不改变已固定的基础画像，不表示实现或目标符合性已完成。

本页补充[抽象与开放定义](抽象与开放定义.md)中的相交能力；原章节继续拥有其已采用的有限语义。**当前选择：复用现有泛型/生成，再按反例扩展。** HList、GAT、关联存储已经解决不少要求。pack/值参数是否原生化取决于真实API/编译负担，不预设全套kind系统。

这里的选择不是删除能力或承诺全部默认启用。满足真实要求的成熟库、静态展开和原生适配可以作为最终方案；额外语义只在现有路线不能保持该使用点的明确要求时激活。未提供对应解释、实现或目标条件时保留作者要求并返回具体缺项，不强迫所有项目携带设施。

文中的类型名、操作名与代码块为合同记法，不向现有作者文法添加关键词，也不直接发布 wire 字段。作者仍通过已有 Definition/require/prefer 或已解析原生定义提供真实差异；内部信息归入原 MethodSpec/BoundaryView/UseBinding，公开扩展必须另有准确版本及能力协商。共同准入见[能力履行](../../编译/目标/能力履行与接口差额.md)。

泛型参数支持类型、编译期值、类型构造器及其有限参数包。用 kind 区分 `Type`、`Value<T>`、`Type -> Type` 等，不把函数、类型和宿主 JS 对象塞进无类型 `any`。类型构造器是含显式绑定环境的类型函数；借用／寿命参数是语义参数，但不随便物化为进程全局类型名字。

参数包支持长度、索引、连接、逐项 map、zip、左／右 fold 和 expansion。zip 的长度不匹配、负索引、越界和没有单位元的空 fold 都是明确错误。空逻辑 fold 等已知单位元由具体操作定义，不给任意用户 `+` 擅自假定零。展开按定义的顺序生成声明与效果；无固定“最多支持到 16 个类型”的语言上限，但实际编译有资源限制。

类型级常量允许整数、布尔、字符、枚举、固定结构值、有限序列、函数／静态对象符号、成员投影、明确浮点格式的位值。其身份规则必须独立于进程地址与打印文本：

- 结构值按类型和有序字段递归规范化，不能通过未经定义的 `toString()` 形成类型身份。
- 浮点类型参数使用格式与明确定义的位表示身份；`+0`、`-0` 与不同 NaN payload 是否合并必须由所选值类型规定。默认位值不合并；需要数值等价类时使用显式规范化包装类型。
- 指针／引用型常量是静态符号加合法 relocation／offset，不能把编译器进程的地址写入产物。引用身份与所指内容相等不是同一个比较。
- 函数与成员常量引用其声明和实例化，不把机器地址作为跨构建 key。

`Array<T, N*2+1>` 在具体实例化后计算长度；符号阶段只用有边界的约束语言推导必要条件。类型级算术默认以明确的数学整数／固定宽整数类型运算，转换到目标 size 时检查非负、溢出、乘法尺寸、对齐与对象大小限制。不是先让目标 Rust 报一个晦涩的 const generic 错误。[依据](../../依据/来源/Rust与C++能力比较.md#baseline-s02)[依据](../../依据/来源/Rust与C++能力比较.md#baseline-s17)

**多态函数值**保留可量化签名，如“对任意满足约束的 T，可接收 T 并返回 T”。静态使用可单态化；需要跨模块继续保持多态时保留 Gift 语义定义。动态／原生边界必须使用可表达的 witness／字典、有限实例集合或实际支持的目标泛型，不允许暗中加入 JIT。

Rust 后端先由 Gift 展开其自身不能直接表达的包／类型函数／复杂常量，再输出具体目标类型；简单可保持的泛型才原样保留。TS 输出也不能仅擦除泛型：运行所需的 serializer、数值操作和类型信息必须实参化或提供字典。动态边界无法恢复已擦除的任意 T 时返回缺项。

## 共同语义参数、实参与卫生代换

本节将已有kind/参数包及寿命语义接到同一typeParams与TypeTerm，不增加另一种参数语言。只在明确选择支持此扩充的准确方法修订中采用；普通Type参数仍可写`{key,name}`，不要求所有程序加载资源/任务能力。

```text
Kind = "Type" | "Region" | "Scope" | "EffectRow"
     | {value: TypeTerm}
     | {constructor: {parameters:[Kind...], result:"Type"}}
     | {pack: Kind}
SemanticParameter = {key,name,kind?,binding?}
SemanticArgument = TypeTerm
     | {value: Expr}
     | {region: RegionTerm}
     | {scope: ScopeTerm}
     | {effectRow: EffectRow}
     | {typeConstructor: ConstructorTerm}
     | {pack: PackTerm}
     | {packElement: {pack:PackTerm,index:Expr}}
RegionTerm = {parameter:K}
ScopeTerm = {parameter:K}
ConstructorTerm = {decl:DefinitionRef,arguments?:[SemanticArgument...]} | {parameter:K}
                | {apply:{constructor:ConstructorTerm,arguments:[SemanticArgument...]}}
PackTerm = [SemanticArgument...] | {parameter:K} | {concat:[PackTerm...]}
```

kind省略为Type，binding省略为argument；另一值fresh只对Region/Scope、且只有实际方法规定新鲜性时合法。联合恰选一支，附加字段拒绝。TypeTerm.parameter只绑定Type；RegionTerm/ScopeTerm必须出现在region/scope的有tag槽，不因内部也用parameter键就作普通类型。Value<T>沿原阶段求值取得可冻结的准确T，不把runtime程序或地址当常量；Type constructor核实际声明、剩余参数/结果kind及绑定环境；pack核元素kind和次序，运行List不是参数包。kind依赖需先能准确绑定，缺T的Value<T>不是Any。

Region表示借用寿命关系，Scope表示任务拥有域索引，不能隐式互换，均不是req:subject、Grant、真实Own或运行句柄。fresh见证由一次真实调用/构造发生的受检合同引入，不占调用者可提供的实参槽，不按同源字节/创建位置/相同参数合并。scoped为body引入局部fresh Region，返回T及闭包不得携带该见证；这是受限方法边界binder，不开放任意高秩推断。

向外返回带fresh Region/Scope索引的值时，共同TypeTerm使用`{exists:{parameters:[SemanticParameter...],type:TypeTerm}}`，只允许此处的fresh Region/Scope参数。封装保留真实拥有者、有效范围及隐藏见证；实际类型化打开方法引入新鲜局部见证，不能逃逸，除非连同仍有效的拥有者重新合法封装。封装不是普通record/任意JSON，不复制Own，不延长Borrow实际寿命；关闭封装不等于close资源。公共或目标接口不能保留该关系时返回相交缺项。

任务域创建可由存在封装返回Scope<sigma>；start从真实scope实参的类型推得同一sigma，共享scope引用保持它，重新创建域产生不同见证。受限借用闭包的潜在依赖也穿过存在封装和签名，不能因藏起索引就失去捕获/取消/清理责任。Region/Scope见证不作为可跨运行持久值，显示名字和进程地址都不是其身份。

约束沿原Definition/MethodSpec的有类型约束引用及SemanticArguments传递；每个实际约束声明参数kind、含义及检查方法。寿命outlives、scope包含、效果子集与类型约束分别由原owner承担；名字或说明文字不自签证明，缺解释/方法/可判定依据分别返回原诊断/Needs/AnalysisIncomplete。不新建核心业务kind枚举或独立约束真源。

代换顺序固定：收集声明/binder/kind依赖→卫生改名内层binder→对齐argument槽并仅补唯一推导→在实际边界引入fresh见证→按kind检查规范化→同时替换类型、效果尾、约束、Rule字段与方法前提→核资源/捕获/阶段和目标义务→冻结原HeaderIndex/BoundaryView。同一binder用同一环境；不得对before/after各推一个T，不得把Type替Region、Scope替Region、EffectRow替普通值。预算不足保持未完成。

实例身份消费准确定义/语义修订、实参kind、名义类型/规范静态值/效果/构造器环境/有序包与实际约束witness；alpha-renaming不改变封闭泛型身份。运行fresh brand不注册成跨运行全局类型；目标代码可在有依据时共享，真实scope/资源/捕获状态不能合并。TS擦除不能去掉面向任意JS消费者的once/句柄保护，Rust原生Drop与生成guard仍只能有一个cleanup owner。

结构作者的decl/definition-reference，复合定义/Rule/SubjectSchema及use/require/prefer的原typeArguments槽，普通call的semanticArguments，函数/port/对象签名，效果/约束、阶段求值、调用捕获、ImplementationBinding/UseBinding、目标及编辑/序列化都消费本算法。旧普通Type参数与实参保持原义；非Type实参必须有tag，未知不猜成Type。未发布结构合同采用新字段时绑定准确规则/编码修订，旧方法按原未知保全或返回相交不支持，不能忽略字段后生成完整产物。

普通表达式的显式实例化只由[call.semanticArguments](结构编辑与身份保持.md#调用的显式语义实参)拥有：显式数组完整对应实际量化签名的argument槽，fresh槽不由调用者提供；省略整槽才请求唯一推导。静态实参在调用者词法环境按kind、约束及Value阶段资格规范化，不能借运行arguments取得尚未发生的值。同一代换环境用于实际调用签名、效果、捕获和方法前提；实例身份与ReadSet保留规范实参及其真实来源/求值/约束依赖。原基础文本的有限推导画像不因此自动取得显式应用语法，投影缺项不能删除实参。改变实参、kind、约束、phase或绑定修订时重核相交实例、目标及编辑对应，旧已固定实例仍按原解释；不另建引用实例化协议或第二套缓存身份。

### 构造器与包的实际应用

ConstructorTerm.parameter只绑定constructor-kind参数，decl分支指实际类型构造器及合法部分实例。本页的构造器最终结果固定为Type，不开放任意Kind→Kind元函数；未应用完的剩余constructor kind由部分应用派生，不能由该apply制造Value、Region、Scope或pack结果，普通值级函数继续用Expr。共同TypeTerm使用`{apply:{constructor:ConstructorTerm,arguments:[SemanticArgument...]}}`：先代换构造器环境，再按剩余形参kind/数量/约束检查实参；该类型槽只接受result=Type。F为Type→Type时F<Int>用apply的parameter头，不伪造DefinitionRef。部分实例结果若仍为constructor，使用ConstructorTerm.apply并核剩余kind，只在相应ConstructorTerm槽消费，不当普通类型。类型应用不执行runtime代码，卫生替换、依赖循环及预算沿原类型求值。

PackTerm.parameter只绑定pack参数，数组按准确element kind检查；concat要求element kind一致并保持次序。`packElement:{pack:PackTerm,index:Expr}`在SemanticArgument按预期kind取项，在TypeTerm槽要求element kind=Type；index沿原阶段求值得到精确非负Int，越界为错误，未知/预算不足保持未完成。长度沿准确PackTerm的原阶段查询取得，不是runtime List.length。

类型构造器实参序列与函数类型parameters序列中的唯一展开项为`{expand:PackTerm}`，只在明确支持该包能力的方法修订中使用；有限展开逐项插入，函数类型parameters只接受Pack<Type>。这些明确可展开序列的元素类型为原元素联合`{expand:PackTerm}`；展开后才按实际arity和parameterContracts.position检查。expand不是普通TypeTerm或单个SemanticArgument；声明为一个pack参数的槽仍接`{pack:PackTerm}`。普通call的运行arguments不因此得到变参/展开。map/zip/fold等条件合同沿原阶段方法，未定义相应交换编码时不能以本有限编码声称全部操作可直接书写。

### 存在引入与受限回调消去

exists类型的隐藏参数不在读类型时创建运行对象。存在引入发生在已有返回、实参或注解的预期类型检查点：从普通Expr的真实类型求唯一且已经合法存在的见证替换，使payload符合存在体及约束，再按原拥有方式隐藏它。不能从预期类型制造scope或把推导变量当fresh runtime brand；没有唯一预期/见证返回Needs。关联字段共享同一替换，BodyAnalysis保存隐藏对应及拥有形状，不新增pack Expr/第二作者源。

一阶箭头只能引用外层固定索引，不能表达“打开包后对其中未知局部索引检查body”；因此本能力确需同一FunctionType.function及lambda的可选typeParams，复用SemanticParameter但仅允许Region/Scope局部binder且binding为argument（省略同义），不能在函数类型内自创建fresh运行实例。lambda显式提供时核kind与alpha对应，省略时仅从唯一预期签名卫生引入。回调body在刚性局部见证下检查，不能统一成外部scope；见证不得逃到在打开前固定的结果T、约束或返回闭包captures。这是受限binder能力，不开放任意高秩Type/Value/constructor推断，也不冒称普通一阶call已经具备消去。

有限公开消去合同为`unpackWith<F,T,Fx:EffectRow>(package:exists s:Scope.F<s>, body:[局部s:Scope](F<s>)->T !Fx)->T !Fx`，F的准确kind为Scope→Type，T在打开前固定且不含s；body采用consume调用与noescape位置合同，Fx沿共同效果行推导并同时约束回调与消去调用，不能将资源/任务操作的潜在效果擦为空。Region使用独立准确导出`unpackRegionWith<F,T,Fx:EffectRow>(package:exists r:Region.F<r>, body:[局部r:Region](F<r>)->T !Fx)->T !Fx`，其中F为Region→Type、T不含r；两入口复用同一消费/保留/失败机制，各自绑定实际MethodSpec，不能把同一普通导出暗当kind级多态。作者用原call/reference准确公开定义及lambda，不新增关键词或Expr tag。该定义的MethodSpec须真正绑定本段检查/消去规则及目标实现；声明qualification、同名函数或用户自报metadata不签发能力。普通库可以调用并封装该内在能力，不能仅靠一阶函数体实现未受支持的消去。

unpackWith消费package的实际payload资格、只调用body一次且不在退出后保留它；不复制Own。接纳前拒绝保留原包；接纳后payload移动到body参数的受保护激活，正常结果只可为不含s的T，或携带真实拥有者且已重新合法存在封装的值。Fault/Cancel及交付失败均结算body/临时结果仍拥有的资源，接受未知不把资格退回双方，cleanup失败沿原资源owner。借用打开需另一准确签名，不把消费模式静默改为借用。

具体Scope轨迹：`createScope(config)->Result<exists s:Scope.Own<Scope<s>>,ScopeCreationError>`由任务域创建方法真正产生fresh s，部分失败沿原取得责任处理，成功按预期exists封装。作者match取成功包，再普通call调用unpackWith；body在局部s下取得Own<Scope<s>>，通过原resource.scoped的acquire移交唯一清理owner；其body在局部rho下取得Borrow<Scope<s>,rho>，调用`start(scopeBorrow,deferred)`从真实第一个实参推同一s，返回TaskHandle<T,E,s>。等待/领取结果后返回不含s/rho的业务值，域退出先按S0—S7排空再close，失败按原ScopeFailure/Fault/Cancel。直接返回handle或捕获它的闭包拒绝；需要传出时连同有效scope拥有者及依赖重新封装。

createScope/start/unpackWith是这组有限公开库合同的角色记法，实际公开声明须给准确类型、效果及所选MethodSpec；没有解释/目标实现保留缺项，不按拼写赋权。createScope不在导入阶段运行，start不因类型实例化而执行。无需传出域的程序可用具有同一Scope局部binder的withScope回调，在域内启动/等待并结算，省去存在包。类型级参数pack、存在隐藏、运行record/list分别解释，不能用同一个无类型pack指令混合。

## 再次修改与失效

参数值、kind、量词或导出形态变化时，重核实例尺寸与公共接口；原有限实例仍是原实例，不被重新解释成开放泛型。

## 使用点与可检验出口

这些分支保留各自的真实输入、替代路径与边界，不按条数声称更多底层能力；[比较记录](../../依据/来源/Rust与C++能力比较.md)不拥有另一套语义。

- **explicit object parameter / deducing this**：先用显式参数与目标已有 receiver；撤回把 deducing-this 等同 arbitrary-self-types 的粗糙比较。 硬边界示例：下游原生方法语法或精确 receiver 转换协议被固定；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a14)。
- **类模板推导指南**：先工厂和推导规则；这不是运行时缺失，也不必另建全局推导指南注册表。 硬边界示例：既存构造语法/推导结果身份不可改；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a22)。
- **decltype / decltype(auto)**：编译器内部类型查询本来必要；是否向作者开放为语法/API，是独立决定。 硬边界示例：编写通用库必须在类型位置复用任意表达式类型，且不允许改写为新 trait/辅助入口；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a23)。
- **类型参数包**：有反复用例可统一为 pack；否则复用列表与生成。不给所有程序强加变参泛型设计。 硬边界示例：外部库要求原生任意 arity 函数/tuple 接口；或编码的编译负担超出真实预算；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a24)。
- **值参数包**：区分值序列计算与类型身份；只在实际输出依赖时保留编译期参数，不整套复制 NTTP。 硬边界示例：任意结构值/符号序列必须原生成为公开模板身份，或需要未合作外部泛型接口；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a25)。
- **template-template 参数和包**：GAT 式设计足够则复用；作者高阶类型便利不自动意味着再造完备 kind calculus。 硬边界示例：下游通用库必须无适配地接受任意外部类型构造器，或要求原生签名完全一致；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a26)。
- **fold 表达式**：通常复用泛型序列机制；不是在24之外又一个独立机器能力。 硬边界示例：必须原生包语法，或类型级归约规模使替代方案失去可用性；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a27)。
- **pack indexing**：作为包/反射的派生操作；C++26支持按实际编译器核验，不混入已成熟C++23比较。 硬边界示例：要求对外暴露原生通用 pack 索引，且不能接受另一套表示；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a28)。
- **广义非类型模板参数**：保留真正需要的形状/值身份；不要默认纳入全部浮点NaN与符号指针模板规则。 硬边界示例：开放原生 API 必须按这种值身份自动匹配，或类型计算无法被有限提前展开；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a29)。
- **泛型常量表达式进入类型**：静态尺寸有真实价值；先常量求值/库映射，在高频需求下再扩展作者表达。 硬边界示例：原生 [T;expr] 公开 API 被固定，或编码复杂度/编译时间实际不合格；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a30)。
- **完全特化**：区分不重叠实现、语义类型族与等价优化；只有后两者确需时才引入相应规则。 硬边界示例：必须保留通用默认＋任意具体例外的开放接口或不同实体定义；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a31)。
- **部分特化**：撤回“Rust 没有部分模式实现”；真正审查重叠与定义变化，不按关键词裁决。 硬边界示例：需要重叠结构模式自动排序、公开字段/类型族变化，且不能分离策略；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a32)。
- **显式模板实例化**：交给构建/导出策略，不把编译组织变成运行时语言机制。 硬边界示例：库发布要求精确的实例提供者/符号/构建归属，或编译资源有测得瓶颈；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a36)。
- **template for**：归入真正需要的静态展开；不与24/27/40再重复累计成多个底层控制缺口。 硬边界示例：无适配开放的反射/参数包迭代是公共API硬要求；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a42)。
- **依赖泛型的对齐**：撤销错误缺口；只对真实的精确布局要求建立检查。 硬边界示例：指定align表达式和原生导出类型必须同时成立，不能改表示/生成具体实例；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a49)。
- **定义C变参函数**：只在FFI适配器中处理，不让每个Gift函数都背C变参模型。 硬边界示例：禁止任何额外原生对象且要求pure stable Rust导出真实变参符号；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a56)。

实际组合与拒绝条件见[验收案例](../../运行/验收/跨语言控制与组合案例.md)；从作者要求到再次修改见[连续开发情景](../../../examples/连续开发/跨语言能力连续开发.md)。

## 捕获状态与开放多态调用

带捕获的多态 callable 不能只按“能写泛型函数”消解。需要保存同一捕获状态、允许的借用/可变/一次性调用，并在每次具体调用中绑定类型参数、返回和效果。默认可采用具有泛型方法的状态对象、显式参数或已生成的具体调用；不为了仿照 lambda 拼写增加另一套闭包运行时。

进入外部原生接口前另外检查：该接口是否要求原生闭包类型、`Fn` 族约束、对象安全/动态分派或任意未来类型。一个具有泛型方法的对象不自动满足全部这些要求；必要时提供合格闭包适配、有限实例集合、真实字典接口或可继续实例化的语义定义。捕获的可变状态不能为了生成不同类型实例被复制成多个状态；一次性捕获不能因调用参数类型不同就再次消费。

正常流程为收集捕获及其所有权、绑定本次类型参数、生成实际调用、合并效果并更新原捕获状态。新增调用类型仅生成相交实例；改变捕获布局或借用范围时重核全部活动闭包及导出，不把一个泛型名字当成稳定 ABI。外部接口不可表达时返回该导出缺项，内部明确实例仍可用。
