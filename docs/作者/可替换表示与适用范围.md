本章拥有共同计算语义及既有`.sec`文本前端的精确合同。新产品主要作者源采用[结构化意图与Block模块](结构化源码.md)，不以实现新的文本语法为前置。本章的基础语法、对象/控制/资源规则和记录更新仍供明确选择该计算画像的实现定义使用；它们不是普通产品作者必须展开或学习的内容。高级领域、目标与宿主各由原规范负责，保留同一语义和编译体系，不建立竞争真源。

`sec.semantic/1` 与 `sec.ai-tools/2` 的草案解释绑定精确内容修订。相同 `/1` 标签不能把不同草案内容混用；已声明结构、方法实现与实际符合性分别判断。


## 语言责任与产品范围

公共结构需要准确的类型、关系、求值、控制、资源与模块含义；采用`.sec`文本画像时还需要其词法和文法。前一项不推出所有作者必须使用后一项。JSON能够直接编码已定义的Block与需求，不能因其可解析便省略语义检查，也不能因称为模型便免除语义责任。研究尽可能覆盖成熟机制，采用时固定相容的当前语义；低层可计算性、作者便利、目标可实现和实际许可分别核查。

全体系的当前选择与剩余入口由[能力裁决](需求关系与能力边界.md#4-完整语言能力的当前裁决)维护，新增机制按其中C0—C5检查组合。这里继续作为可实施语法与语义的唯一入口，不把新关键词变成日常作者必须学习的全部词表。封装使用者只表达自己的差异；创建独特功能的作者可以使用语言相应能力。




## 作者载体、实现供给与原生工程的选择

当前采用结构化JSON表达产品意图与组合，不要求全工程所有内容都成为JSON。表示选择跟随该内容的真实角色、已有拥有者和消费目的；它不是按文件后缀比较哪种语言“更高级”。

| 内容与任务 | 直接维护的来源 | 仍须成立的责任 |
|---|---|---|
| 产品意图、定义复用、共享主体与独立约束 | 当前结构化模块JSON；工具维护机械身份、默认来源和准确绑定 | 规则有精确语义；公开合同不能仅凭标签存在就称已实现 |
| 已存在且满足任务的程序 | 原生TS/其他实际语言文件、原清单和锁；可以直接导出已有入口 | 固定原语言和环境；检查相交行为、错误、资源与公共边界 |
| 确实需要中立计算定义或语言变换校准 | 明确选择的`.sec`计算画像，或者已有合格中立表示 | 有真实读取、类型/效果、降低与运行供给；本画像不是普通产品作者前置 |
| 已经按原生实现完成的供给 | 实际原生源码/包与相交契约；不翻写一份同算法JSON或`.sec` | 说明它满足哪份要求、在哪个目标与范围成立；函数签名不是行为证明 |
| 文本意图备选 | `alternatives/文本意图/`中的冻结方案 | 比较材料，不作为当前已实现入口，也不因存在范本就自动采用 |
| 配置、数据、媒体、测试和解释 | 真实格式及原拥有者 | 只在任务相交时读取、修改或交付；不base64进通用作者模型 |
| 目标源码、分析投影和阅读版 | 从准确输入派生；需接管时显式转移区域拥有权 | 不与原作者源双写同一决定；派生成功不等于运行或采用 |

**直接用现有源码不是退化。** 单目标、已有框架/库已经表达完整任务，且本任务不需要独立意图求解、组合验证或跨目标保持时，直接维护它通常是更小的候选。SEC可只承担获准的工程内容、检查与交付工作；没有额外作用时，工程也可以不使用SEC。比较必须使用同样的库、质量、范围和持续修改，不能把“别人从零写库”与“SEC引用成熟库”相比。这里是按任务选择，不把整个SEC的意图主面换成原生逆向优先。

**JSON也不是完美的通用程序表示。** 对结构引用、序列和名义字段，它有成熟读取工具和明确边界；长标识、严格语法、注释能力和合并冲突会增加直接手改成本。编辑器可以提供紧凑投影、标签和结构增量，但不另存竞争真源。若必须将普通循环、局部变量、每次运算都扩成冗长树才完成日常开发，应复核边界或选择实际程序表示；不能以“统一”强迫不合适的转换。

**不完整需求与选择自由分开。** 已有规则给出完整允许行为并委派实现时，可以从多个合格实现中选择；规则还没说明关键行为时，保持准确未决或按已有委派补充，不能由当前代码倒推成原接受要求。采用一项已有实现不要求它另附同义`.sec`主体；只适用单目标的供给也不自动满足跨目标任务。

独立需求和实现程序可以同时保存，它们不是同一决定的两份镜像：前者是验收依据，后者是满足它的一个实现。派生签名、接口视图、目标代码与同义AST才按原唯一拥有权处理。反过来，没有独立要求的普通文件编辑无需凭空生成一份需求表。具体接合见[混合作者与供给](../开发/原生维护/导入观察与原生资产.md#mixed-author-supply)；成本判断仍由[成品边界](成品形态与公共边界.md)承担。

## 阅读次序：普通开发不从最细语义开始

新建产品首先看[结构化意图与Block模块](结构化源码.md)与[完整意图源](../../examples/结构化工作台/说明.md)。以下函数、类与短写法是实现定义或明确选择的计算作者合同。需求模块直接解码到既有Definition与RequirementTerm，计算文本通过所选前端进入同一语义，二者不是必须先后转换的两份程序。

本章完整语义用于解释、检查和实现，不是每个目标工程必须复写的算法目录。已有需求由准确定义引用、参数和稀疏控制承担时，无须增补类或低层主体；源码范本中的整数比较只检验对应的语言/回写能力。没有对应价值的新包装不能因为“统一进入SEC”成为必经层。

作者可以直接修改已有文本并成组捕获。机器协议中的propose/draft只是可选提交形式及类型化变更入口，不能反向成为语言语法或作者每次必填表。完整规则见[正常编辑](../开发/用途与任务范围.md#正常写文本不手工驱动全部流水线)和[目标/作者关系](需求关系与能力边界.md#目标工程作者源和需求抽象分别有位置)。


## 当前作者面实施基线与决策状态

当前成品实现次序先闭合结构化意图源、定义与共享主体、需求/供给组合及目标生成，再接相交操作能力；具体拥有者见[实施路线](../演进/实施/主线前沿与准入.md#language-roadmap)。SEC实现语言、作者结构、原生语言、目标和FFI不同。TypeScript优先，Rust属于已选的目标语言计划；目标支持按准确能力逐项交付，不要求首个TS发行等到Rust全部完成。核心实现语言不因此迁写；原生深维护/逆向有独立价值，但不是新建产品作者面的前置。

**当前交付选择：新建产品用分层意图/Block定义、公开管脚及必要约束表达独特决定；按既有`sec.author-module/1`外壳直接保存为JSON，具体需求体见[结构合同](结构化源码.md)。JSON是载体而非权限、实现或正确性证明。编辑工具代管机械身份和已定义字段，不要求手填展开AST。已有`.sec`计算源、原生源和精确绑定保持其合法角色；新增`design/use/prefer`只保留为未采用的可选文本表面，不是结构编译器前置。实现缺额由真实供给/受委派创作承担，不自动转成产品作者的手写义务。普通新业务不增加核心关键词、服务或并行真源。**

这个选择是设计者在现有目标下作出的方案，不是用户要求必须发明一种语法。用户要求比较某个方案，只增加比较义务，不自动改变产品要求或采用状态。公共语义、输入前端和目标语言分别绑定。

| 决定对象 | 当前必须实施的选择 | 不进入当前交付的备选及原因 |
|---|---|---|
| AI日常操作 | 已知源码直接source/files/edits；已取得局部定位时用现有editRef或结构增量 | 不为变短而强制先查ID，不逐次重发完整树 |
| 新建产品与独特行为 | 产品引用/组合准确Block与需求，必要差异存结构模块；真正新含义由对应定义拥有，实现可由合格供给、领域结构或所选程序表示承担 | 不强制产品作者手写函数，不按标签猜实现，不要求先设计新文本语言 |
| 结构组合 | 使用既有基础结构体和领域模型；维护真实绑定、激活与唯一写权 | 不建立与文本独立可写的镜像图，不要求表达式全部上画布 |
| 已有工程 | 继续原作者来源和精确解释；确需迁移时按已定转换合同进行 | 不因当前默认改变而批量迁写既有区域 |
| 语义与目标 | 固定共同值域/效果/需求关系；TS首目标，Rust纳入计划；新产品直接编译与原生维护/受管回源分别交付，读取、生成、构建、ABI和回源各有支持范围 | 不把逆向或首个宿主设为所有新工程前置 |
| 库与实现 | 普通定义直接封装；已绑定实现继续用；新选择在既有委派内由编译器决定 | 不要求作者点名所有轮子，不为每种业务新增工具 |
| 工程架构 | 使用既定workspace/semantics/compiler/assurance/application/execution及适配责任 | 不因前端备选增加第二套头、权限、编译器和存储 |
| 验证责任 | 成熟实现按前提复用；本系统新增映射、组合和任务满足承担残余检查 | 不将所有上游能力从零证明，也不以尚无性能数据取消当前设计决定 |

当前采用面由[D02](../决策/设计理由-目标与核心.md#d02-中立语义与可替换作者表示)确定：共同定义、直接结构输入、合格供给和单源编辑。结构输入不必先打印成`.sec`再解析；`.sec`是可选计算画像，其真实语义/目标义务保留。不存在“结构可编译就永远不用语言语义设计”的捷径，也不存在“要设计语义就必须新增文本关键字”的推论。

现有多目标编译器、语言工作台和引用式前端都是完整替代类别。技术可行不等于已经适配：在值域、求值／错误、效果、目标源码与编辑合同相容时，能够接管相应基底或后端；确有全路径成本优势时重开表面选择。现有模块不会因本次比较而自动迁写，没有新增作者SDK、F#/Haxe入口或MPS模型发行。

当前不交付嵌套SDK；普通程序不逐运算写构造器树。这个决定只限定本次供给，不禁止真正可消除重复的阶段化库、成熟宏工具或未来取得资格的前端。新业务优先复用或组合合格供给，真正差额才写普通定义；有实际高层分析价值时才提供附加语义方法。解释、编译与多目标责任仍然存在，不能通过称为框架而取消。

已经明确的接口和有限算法可以成为相应实现输入；每项替代须比较整体责任和原硬目标，不通过降低可移植、自定义或无原生补洞要求来制造短期优势。实现、符合性与采用收益继续分开记录。


## 实际作者控制与编译供给的当前分工

当前方案维护一份有确定解释的工程作者源。产品作者主要维护意图定义、管脚实参、主体关系和必要约束；维护者可以下钻实现，但不被迫维护它。`.sec`计算画像承担自身语义责任，JSON结构承担直接读取与对应语义责任，二者在同一区域不得独立双写。原生实现与生成物的回源/接管保持原合同。

当前控制落点由[最小控制](需求关系与能力边界.md#作者实际控制什么以及唯一修改入口)唯一规定：共同含义由定义拥有，使用点改参数，独特逻辑改函数/领域结构，必要目标或实现要求改稀疏记录，实际数据改运行输入。自然语言是创作请求；它不会在source字段中被不确定地解释为代码，也不会在每次固定构建中重新求助AI。真正的新算法需要足以确定行为的定义，不因称为“意图”就变成几句含义不确定的话；它可以由普通主体承担。已有合格算法则使用实际绑定，不为满足这句话再转写一份同义主体。代码可由受委派AI创作，但接受的内容及修改责任仍然存在。

新增功能优先使用现有语法、库和普通组合；本分工不增加关键字、语法配额或强制生成器。只有新的可观察语义确需语言支持时，才设计相交构造与目标保持。独立语法能直接表达宿主难以捕获的控制，并统一诊断和默认；它不能免掉类型、作用域、错误、资源、兼容与源码成本。嵌入式形式也不是免设计捷径。当前不为避免“语言”这个名称改用更长的组合器，也不因为已选择`.sec`就无条件拒绝成熟实现接管。

已有有限作者环境及首个直接TS降低作为当前可实施选择；新比较不成为实现前必经的无界全生态研究。某成熟前端/基底或后端实际满足同一合同且成本更小时，按明确转换替换那段供给；不能以“还没证明任何替代最优”不断暂停当前已定工作，也不能把替换供给当成客户源已全部迁移。

### 高层主面与底层表达的当前分工

本章提供可选计算文本的准确解释；当前产品作者表示由[结构合同](结构化源码.md)直接承担。开发AI按[需求及操作路由](../开发/用途与任务范围.md#authoring-route)修改公开参数、局部组合或必要定义。Block是封装角色，JSON是结构载体；都不要求全图画布、逐运算节点、继承层次或新增运行对象。

唯一采用的程序仍须有确定含义和真实实现。隐藏内部循环不取消类型、效果、资源和目标责任；没有适用封装时，作者可以正常写自己的主体，并继续纳入同一组合体系。有限组合规则不等于所有业务名称有限，也不是承诺全世界需求存在唯一的原子分解。


## 语言身份与不可替换的目标

**选择SEC中立计算画像时，就是在使用该画像自己的语言语义，而不只是给原生代码加注释。** 该画像规定值域、绑定、求值、错误、契约和效果，`.sec`文本与对应计算结构可以表达它。产品需求JSON引用的规则保留自己的精确含义，不因此被要求先转换成此计算画像。原生区域继续由其实际语言解释；命名为“工程语义”不免除解释责任，也不构成强制采用新文本语言的依据。

“语言无关”限定公共工程语义不由某个输入或输出语言垄断，不表示 SEC 没有作者语言。实现可以采用 TS/Bun，第一个后端可以生成 TypeScript；它们不定义公共 Int、Text、顺序和权限。原生 TypeScript、Java、Go、Rust、Python 或其他区域保留自身语义，经明确前端与绑定接入；不能把所有原生代码先写成 TS 再声称语言中立。

产品也不等于强制所有工程迁到新语言，更不要求每个新工程保留原生作者区域。AI可以在中立源中完成全部所支持的应用行为；使用库/宿主的目标语言实现不产生第二份应用作者源码。原生作者入口用于用户选择和存量连续性，不是缺少一个高层模板时必须采用的逃生口。具体分界由[原生责任](../开发/原生维护/导入观察与原生资产.md#原生作者区域不是必备组成)拥有。每个区域只有一个作者来源。自然语言形成候选，但固定构建不重新让模型猜业务。JSON是清单或结构编码，不是作者必须填写的AST。


## 新语义责任不等于必须另造完整通用语言

用户目标是中立工程语义、简洁自由与持续演进，不是单独发布一款函数式语言。目标要求机器能准确解释作者内容，却不从逻辑上强制全新词法、解析器、标准库和工具链：嵌入式前端、结构表示或现有合适语言都可以承载明确语义。选择复用时仍须说明其宿主含义如何映射，而不是将宿主AST冒充公共模型。

当前公共体系独立规定Int/Text、类型、求值、契约和效果，因而承担形式语言的语义责任；它不要求所有作者学习一套新词法。`.sec`与结构体按共同合同表达同一支持域。宿主构造SDK在原理上也可映射中立语义，但不是当前采用项；目标源码生成器与中立作者前端本来就是不同机制。成熟宿主解析与编辑继续用于实际选定的原生/目标适配，中立映射和保持仍由SEC承担。

新语法只有在直接表达公共含义、高层组合、多目标保持或重复维护消除上有价值才有产品理由。“fn替换function”“保留词更少”“能递归”分别不构成价值证明。当前18词是草案表面，不是固定产品配额；发现必要表达缺项，应修正最小相交规范，不为维护词数把复杂度转嫁给作者。


## 计算语言与工程抽象不是同一高度

当前基础使用类型、函数、不可变列表、精确值和契约，不让作者安排CPU寄存器、栈槽或指令地址；按机器抽象尺度，它是高级计算语言，不是汇编或低级IR。相对用户的工程任务，它仍可能太低：把状态关系、事务意图和错误传播全部手写成函数，虽然可计算，却没有自动获得高层简洁。

基础层保证没有预装功能时也能表达算法；高层领域层保存状态、关系、决定、资源和作用义务；实现策略层在明确自由范围内选择算法、布局和执行方案。作者选择某个低层细节后它成为约束；未指定的机械细节交给合格的生成器。三个层次可以对应同一对象的逐步具体化，不要求三份手工同步的源码。

反例判据：作者为了一个普通新需求必须手写整个通用事务框架；一个递归列表例被当成高层工作流已完成；高层需求只能退出模型写原生；用户设置性能要求后编译器悄悄缩窄数值或错误语义。本章不能仅凭基础函数完整而关闭这些工程层缺项。

## 程序表面简洁与需求关系抽象是两项交付

省略可推导类型、简化别名和使用函数值，解决的是源表示成本；它们不能单独代替“对哪些对象施加什么关系、保持什么、如何组合与变更”的产品能力。当前共同需求合同在[语言能力映射与最小控制](组合/跨软件需求合同.md#cross-software-intent-contract)，由既有Requirement、当前定义、领域方法及任务投影承担。

不新增一种所有用户必写的意图语言。直接源码继续可以是完整需求定义；已有行为关系可以由当前库/结构引用承担；自然语言形成的准确候选须有实际来源和接受关系。一个函数能表达全部计算，不自动使应用开发者拥有合适的高层关系操作；高层关系接口存在，也不免除底层实现与开放创作。

普通任务按实际需要使用值、关系、状态/时间和资源形式，文本、表与图回到同一源。当前语法及原有限组合保持，关系模型新增的实现职责不以“不增关键词”掩盖，也不因此重新打开SDK或扩成第三目标；TS＋Rust目标计划已经固定，具体Rust能力仍由真实消费者、目标画像和证据决定实现范围。


## 语义规格与日常作者面的不同验收

本章列出表示与语义责任，供实现、审查和精确下钻，不是每项任务应输入的字段清单。计算文法只在明确选择该画像时构成有界实施基线；当前产品结构化作者源可直接编译，不先转成计算文本。语法闭合或示例可书写不能证明它是成熟语言的更优替代。保持公共中立语义不冻结全部表面选择，也不因技术提名而自动采用TS元编程或另造一份同义JSON树。

局部赋值与循环已在通用组合中给出确定入口；默认实参、标签控制和通用类型类仍不由本基础文法提供。扩展根据独立语义与作者负担决定，不以维护18个基础词的数量阻止必要能力，也不把其他语言全部词表并入。每项支持须同时有解析、静态含义、运行、目标和编辑合同。

能从表达式与真实上下文唯一确定的局部类型、效果和名字，不要求再次标注。公开兼容边界、故意收窄的要求和无法确定的选择需要保留；推断结果不能反过来修改要求。未知仍局部显式，不以任何缺失都补默认或任何信息都必填两个极端处理。

作者可以在同一模块只维护公开合同、行为体、真正独立约束和确需固定的实现选择，其中无必要的部分可省。库定义应承担其构造和值域条件；调用者只有在输入尚未满足或需要更强保证时处理相应边界。不可变输入检查可以复用，不应通过要求作者在每次调用重复require来实现检查缓存。

对于常见结构，公共作者面应直接保留相应组合与关系，再由工具降低到本章基础构造；对独特算法，允许直接使用完整的中立计算能力。两者只有一个作者来源。查看展开不把低层树升为必写源码，局部具体化也不强迫整个模块变成不透明原生。当前细程序示例是含义见证或一种可用写法，不自动指定最终最简入口。

对不同任务的采用结论及实际比较由[产品作者成本](../产品/术语与质量属性.md#作者负担不能以规范完备抵消)拥有。未有采用依据不妨碍在明确授权下实现一个有界候选以取得证据；不得将该实现或文档改动说成作者收益已被证明。


## 可编译不等于整个需求已完成

| 状态 | 可以得到什么 | 不能推出什么 |
|---|---|---|
| 原文已保存 | 草稿、位置和诊断 | 已经合法或已采纳 |
| 基础语言有效 | 绑定、类型、效果与结构结论 | 业务满足、程序必终止 |
| 行为闭包明确 | 输出所需主体与绑定已决定 | 所有后端均支持 |
| 所选目标已生成 | 实际源码/制品与artifactRef | 类型、行为、应用已经通过 |
| 特定检查通过 | 绑定主体与范围内的证据 | 其他目标、未来输入或部署同样通过 |
| 实际应用完成 | 指定目标的真实读回 | 未请求的发布、迁移或外部事务完成 |

编辑态允许不完整。源中缺分号、未决类型、未实现要求或者未知端口，都应保留实际内容和相交影响。源码格式化、代码补全和自动修复不可以把不存在的决定写成用户已接受的含义。

编译器首先保持最清楚的原义。是否删除检查、融合循环、特化泛型或改变布局由已经声明的保持条件决定。没有新的性能依据时，不需要为了“极致”先建全局最优搜索器。


## 冻结的是决定，不是所有未来未知

已选基线包括中立作者身份、当前基本写法、类型与运行含义、源与产物的关系，以及六工具的输入和结果合同。完整位置见[当前作者面实施基线](#当前作者面实施基线与决策状态)。这里的冻结是设计基线，不是实际执行授权，也不代表已发布稳定语言。

开始实现某个构造前，补齐它相交的语法消歧、作用域、类型/效果、求值、错误、库或目标映射与编辑反例。具体解析器消歧测试、运行行为和真实AI成本在实现后取得；不能要求先有这些结果才准实现，也不能把未写清的返回/错误留给实现者碰运气。有限层级状态已有独立库与解释设计，尚未实现的领域方法、流、微分和其他高层能力保留各自义务，不阻断有限构造。

同一个产品基线期间，新版本只增加合格定义和目标时可以不改作者写法；改变语法、缺省、数值、错误或公开名称是可观察变化，先修相交规范与迁移，再进入新解释绑定。只有出现实际矛盾、支持任务不可表达、无法保持所需行为或有依据的作者负担反例，才重开对应设计。没有新依据时继续实施和检查当前方案，不反复在JSON、TS元编程和中立文本之间全量重选。


## 作者意图、程序语义与生态完整性的范围

函数、类型、契约和高层声明可以直接表达开发者意图，不要求再写同义的意图文件。重复工作由库定义和编译器承担；独特算法仍可由作者自己定义。仅有要求而没有函数体是合法设计，若存在被选定且满足要求的实现关系，也可进入对应生成；只有必要行为既无定义又无合格绑定时才限制该根。

一个完整合同可允许多个目标实现，不要求生成前证明实现唯一。函数参数由目标运行时取得，也不要求编译期填写具体参数值。相反，未委派的稳定性、错误、隐私或外部作用区别不会因库名存在自动决定。完整过程见[意图完成](组合/跨软件需求合同.md#11-意图进入同一作者源的完成与缺省算法)。

有限作者语法、库调用、局部函数和目标控制沿既定入口解释。意图通过具体定义表达；自然语言创作不等于确定解析，其他领域也不必全部降低成函数后才能表达。对象模型、关系、完整时间/流以及有限状态图以外的扩展仍按[当前问题登记](../状态/前沿与登记规则.md#已知问题主登记)记录所缺设计。生态覆盖是按使用点、解释和目标证明的范围，不是因有18个保留词、完整文法或一张领域目录而整体成立。


## 文本基线与管脚结构入口的共同边界

本章保留可选中立计算文本的具体语法，不以文本后缀独占工程语义；新产品结构化主面不依赖先解析此文本。类型化管脚/组合与结构作者的完整规则分别见[工程语言](组合/定义与接口.md#控制逻辑能力管脚与库绑定)和[作者归属](工程源/清单模块与绑定锁.md#多种作者界面如何编辑同一工程)。文本适合算法与局部源差异；机器结构编辑适合连接与参数；选择依实际任务，不宣称任何一种是全域最优。

同一基础构造在两种已支持入口中的类型、作用域、求值、契约与效果相同，结构入口不借外壳绕过检查。不能用纯图的遍历顺序重解释文本求值，也不能要求所有结构节点先打印成本章文本才编译。当前基础EBNF未增加管脚关键字；更广图/领域体合同仍按已选择范围闭合，不由本段宣称全部实现。


## 详细语言规格与每次开发输入分别承担责任

本章的文法和语义规则不因任务视图变短而改变。完整定义、标准库实现和目标规则可以较长，普通使用者通过调用、参数与局部任务视图复用它们；AI不必把本章或结构body全部放进一次上下文。实现器仍须确切解释源，而不是运行一个模型去补全未声明的语言含义。

已有成熟语言的解析、原生类型或目标编译结果应按实际版本复用；`.sec`自己的数值、作用域、契约和降低并不因宿主选择TS而自动已有正确实现。复用算法不同于取得可直接处理当前文法的软件。作者语言若为同等需求持续制造更多独立维护内容，应修改对应表达/库设计，不能仅靠隐藏源码宣称采用价值。

## 不同开发角色在同一作者体系中实际写什么

完整开发面不只支持调用预置库，还要支持创作新行为、复用、公开和扩展。下面规定输入责任，有限语法与领域体仍由各自原规范拥有；它不是新增关键字或暗中承诺所有高级构造已实现。

| 作者任务 | 实际维护的唯一内容 | 推导/复用及需要显式决定的边界 |
|---|---|---|
| 写新算法/纯计算 | 函数、表达式、局部绑定、控制/递归及实际要求；无成熟实现时主体真实写出 | 类型/效果/合法布局按现有合同推导；不要求先命名全局Block或手填CoreIR；不确定数值/终止要求不能猜 |
| 组合已有软件与库 | 真实import、调用/绑定、参数、实例与独特差额 | 已有普通函数可直接用；需要状态/生命周期/效果适配时写真实差额，不为每个轮子强造包装 |
| 定义对象与长期状态 | 真正身份、可变状态、构造/销毁、分派和合同 | 纯值不自动提升为对象，逻辑记录不因想要目标class而暗增共享状态；原对象能力边界保持 |
| 写规则、状态、关系、流、数值 | 对应已有语言或库的源/体、关键顺序/时间/数值/失败要求 | 通用控制面提供相同编辑/生成/检查链，具体领域含义不会被万能图或任意字符串替代；只展开当前用到的合同 |
| 封装公开库 | 源定义、公开出口、准确要求、实例/资源规则、示例与实际依赖 | 私有实现可替换，公共兼容需真实消费者和版本关系；推导不强迫全部签名手抄，需稳定公开接口时可显式固定 |
| 实现宿主/目标Adapter | 原生实现或合格中立方法、精确入口、输入/结果/效果/资源/错误及绑定 | 不隐藏一整个未知实现于Adapter名字；可复用成熟工具，调用/表示/版本差额仍要实现与验收 |
| 扩展语言/生成/查询方法 | 已允许的方法合同、语法/语义/降低/来源规则、能力/发行与验证范围 | 普通组合不需加核心分支；真正新增解释原语需协商及实际方法，不把源插件加载当被动配置读取 |
| 开发SEC自身 | 原十职责内作者文件、共同协议、真实消费者、资源与构建出口 | 可以从原生TS逐个有益纯模块自用中立源；不要求先自编译，不能因自用获得额外写权限或免除独立检查 |

模板、snippet和示例是节省重复输入的供给；插入后成为实际作者内容或保持明确的生成关系，不同时保留两份可编辑真源。注解、控制和要求仅在需要固定含义/约束或确实无法推导时出现；内部计数、身份、缓存与恢复字段由系统承担。显示推导结构可帮助理解，但日常写函数不因此必须学习全部工具协议。

当前完整开发验收应同时包含：没有预制应用函数的新算法；直接调用成熟库无需包一层；跨模块改义与消费者一起更新；原生区域维护；受管生成改动回源；资源/测试/文档/交付连续变化。少数短函数不能替整套开发能力作证，反过来高级方法未实现也不阻止有限语言当前正确用法。
