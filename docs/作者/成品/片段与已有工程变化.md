# 片段、上下文补丁与已有工程变化

本篇拥有两类成品的完整有限选择：独立语法单位与指定工程变更。它们不是其他形态的前置。作者根Expression、ContextPatch、NativeChange见[真实源](../../../examples/开发成品/README.md)。

## Expression：精确计算片段

原意图是精确倍增整数，不修改输入、不读外部状态。作者`factor:Int`默认2，目标公开表达式或函数均要求数学乘法；本例选择TS目标值为bigint。Expression根无外部词法上下文，公开输入一个bigint，结果bigint，资源故障走宿主故障而不回绕。直接用合格原生实现，无`.sec`算法前置。

生成函数时公开`scale(x: bigint): bigint`；请求表达式时以固定符号绑定x生成合法表达式并返回其自由名和类型。具体目标代码的临时变量名由生成器决定，不能捕获已有词法名字。若上下文只允许number，需要另选准确转换/范围合同，不能悄悄损失整数域。返回源码不写文件、不执行函数。

接受条件包括0、负数、极大整数及factor=0；同一输入只求值一次。调用方传getter表达式时，插入后不得因优化出现两次读取。公开序列中的其他作用顺序不改变。改变factor是行为变化；更换乘法供给只是实现变化。只有declare不满足“可调用函数”输出。

## ContextPatch：在一份准确基础上更改公开名称

原意图是在绑定的TS模块中将公开函数`oldName`改为`newName`，为旧客户保留重导出别名，不改变参数、结果、错误和求值。作者参数oldName/newName默认normalize/canonicalize；两者须是该目标的合法且不冲突的导出名，相同名字为明确NoChange。

本例当前fixture实际有一个源模块和一个调用模块。补丁基于两份精确字节、解析模式、导出解析和消费图；文档中的行号不是写入依据。真实外部代码不在范围内，兼容别名保护已知公开契约，不宣称全部动态字符串引用已修改。

输出是同一候选中的完整目标文本和逐文件前像，不是未经定义的regex替换。先取得符号引用，再生成公开定义更名、旧名重导出和所选本地消费者变化；局部变量、注释和无关字符串不动。文件有同名新符号则Conflict；无法解析原生片段则保留草稿和覆盖缺项，不打印一个丢失未知代码的新文件。

实际保存按原execute/apply前像协议；候选原子性不外推多文件磁盘事务。写到第一份后第二份失败要记录分项，不重复改已完成文件，不恢复覆盖用户新写的内容。撤销生成新候选，不能盲套逆diff。未保存缓冲与磁盘不同则明确以哪份为基础；未经授权不saveAll。

验收需比较运行结果、作用次序、公开导出与消费者，再做改名冲突、编辑期间插入内容、部分保存、旧别名调用和同名非目标符号。编译通过不能证明公开兼容。

## NativeChange：交付一个原生工程的准确修改集

该根消费本例fixture，直接维护TS，不生成同义JSON算法或文本意图副本。要求在上述兼容更名之外同步公开README和测试的真实消费名称，保留未选择文件；用户可以明确只要求源候选，不必创建Git提交。

输入含作者范围、当前缓冲/工作树/暂存内容的准确选择、依赖锁与可用工具。公开`propose(input) -> Promise<Result<ResultSet,Fault>>`；成功ResultSet至少含改后源、配置和资源的实际差额、未覆盖消费者与所需检查；工具读取、解析、预算或宿主故障不能通过空ResultSet冒充“没有变化”。提交根则还要在准确候选树检查hook及过滤后的字节，并使用预期分支头推进。没有获准不stash/reset/clean，不自动暂存无关改动。

直接维护可以含尚未解决的错误，但这种草稿不能交为可构建发行。链接、构建、测试和原独立需求各自检查；某种测试器不存在，说明该范围未验证，不把它删除为“全部通过”。撤回分支引用不撤回外部发布。再次变更参数类型时已超出本兼容改名合同，必须联合设计调用适配及接受关系，不只替换字符串。

此页字段中的基础来自真实捕获，不让作者写假contentRef。范本提供的fixture只是可读输入，不证明任意TS/JS工程的完整逆向已实现。精确区域转换与写回沿[原生边界](../工程源/README.md)；实际文件名若由主题索引定位，以[工程源入口](../工程源/README.md)取得对应合同。
