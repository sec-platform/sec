# 多应用、产品族与共同发行

Family根不是“编译目录下全部模块”。本例明确选择Library、Command和WebPanel三个成品，使用同一版本的规范化行为，但拥有不同的交付主体。原作者可只采用其中一个根；未选根不参与它的完成判断。

## 作者的确切选择

Family的`title`参数默认`Interval Suite`，只传给WebPanel；不会改变库公开函数名或CLI线协议。主体root、library、command、web分别声明；条款复用三份准确定义，并用同一行为合同/版本约束它们。共享是含义和可复用不可变代码，不是共享工作器、临时文件、账户或全局缓存。

新产品引用Family即可，不复制三份算法。改变一项共同结果策略，要同时检查三个消费边界；只改Web标题不重算规范化算法。一个目标对bigint不支持时不能令所有产品偷偷改用浮点。

## 发行对象与实际组成

共同发行由一个根清单列三份子制品的准确引用、公共规则版本、各自环境前提、公开入口和共享资产关系。Library输出库成员；Command输出可启动程序；Web输出离线页面。可以打成同一个归档，也可以交三个可取的独立包加共同清单，但不能把下载URL可访问当内容身份。

SEC 自身的 runtime + documentation 发行是这条规则的仓库级具体实例：两份成员可以拥有不同许可和布局，但共同根必须绑定同一 source commit/tree、成员 manifest digest 与实际成员数量。分别构建两个“最新包”再把名字放在一起不构成共同发行；第二成员必须证明与第一成员的冻结 revision 相同，根清单读回还要再次核对两成员。这样代码与文档可独立消费，却不能在完整 release 名义下发生跨 revision 拼接。

共享成员必须有一个真实写入拥有者。不同产物要求同一路径的不同内容时，选择隔离目录或不兼容诊断，不能由后写覆盖。内容去重不改变依赖和许可条件。源图与运行部署图不是同一结构。

## 组合判据

每根分别保留Ready、MissingSupply、Rejected、Failed、Unknown等准确阶段结果；共同发行只有必需根及共同不变量都满足才Ready。库已经完整、Web缺渲染方法时，可以保留库成果，但Family不完整。可选附加项须在作者接受范围内明确标为可选，构建失败后不能临时把必需项改名为可选。

共同发布采用分版本路径加清单切换：先封存全部子内容，再验证引用可取，最后在真实提供者支持的边界切换共同指针。多个存储系统没有原子提交时，采用准备/发布及明确恢复，保留未完成，不声称全局瞬时切换。消费者按固定清单取整组，不能每个包分别取latest。

## 运行混部与再次升级

现场仍使用旧Web与新CLI时，真实使用配置是混合向量；只有相应交叉协议经核对才接受混部，不因属于同一家族就推导兼容。纯规范化无共享持久数据，可分别升级；以后增加共享数据库则必须引入其迁移与兼容窗口。

关闭Library消费者不关闭Web；CLI结束也不释放另一个进程的共享缓存。回滚共同指针只影响未来采用，不撤销已经发送的命令和写入。原发布响应丢失先查共同指针及各子记录，不重复上传和执行安装。

## 实施与验证

compiler取得明确根集合，联合检查同主体要求与共享成员，按目的复用独立产物，再形成共同Artifact；execution负责实际发布。没有新增产品族中央运行管理器。核对用例包括单根缺项、两根路径冲突、同规则不同版本、关闭title变化后的实际读集、发布中断、消费者仍读旧清单和取消一根不误杀共享生产者。结构化Family实际文件及全部叶定义都在[范本](../../../examples/开发成品/README.md)，不是目录名字的说明。
