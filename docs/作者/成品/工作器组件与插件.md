# 工作器、嵌入组件与插件

三者分别具有消息、显式宿主进口与加载扩展边界。它们复用同一算法时仍有不同的运行责任；不是三种名字对应一个万能Host对象。

## Worker：消息会话与结算

沿[原Worker](../../../examples/成品形态/规则合同.md#33-worker)使用{id,items}请求，结果与protocolError可区分。作者`maxInFlight`默认4且>0，本定义不建立额外无界等待队列：超出接受槽则protocolError/Busy；活动id重复拒绝新请求而不结束原请求。正常结果允许乱序，接收者按会话及id接纳。

补全控制协议为独立消息`{control:'close',id:Text}`，与业务包判别；关闭请求不与业务ID混用。接收close后拒新，已接纳纯任务继续结算；最后回`{controlResult:'closed',id}`，真实工作器退出由宿主另观察。强terminate可能使部分请求无响应，只报告实际范围。收到格式错而无可用id时不编造业务结果。

目标模块的宿主入口也必须完整：`Worker.start(emit, limits) -> Handle`建立一个会话实例；`Handle.receive(message)`只向本实例提交一条已经结构解码的消息，业务结果、协议拒绝和关闭结果全部经同一个`emit(Output)`返回；`Handle.close()`等价于本地拥有者发起关闭并等待本实例的关闭义务完成，不制造一条虚假的业务结果。`receive`在Closed后拒绝新输入，Closing阶段只允许真实关闭协议继续结算。`emit`在内部协调锁外调用；若宿主回调抛错，本实例进入故障关闭并保留尚未送达结果的未完成状态，不能继续假装下游已经接纳。

复制/转移输入按[跨实现寿命](../../运行/跨实现调用与数据寿命.md)；一个包装数组readonly不证明底层无别名写。worker bootstrap、编码、共同算法、关闭处理及加载说明均为必需成员。改变并发数不改变关联规则；共享多个调用者必须分别隔离会话，不把id当全局随机账户。

## Component：可嵌入的固定进口集合

该有限组件提供纯normalize，进口集合为空；可生成可调用的原生模块或Wasm组件，选择后的接口及精确整数表示必须固定。Wasm核心i64不能冒充无限Int；采用规范十进制值或其他已定义无损ABI，并把转换/分配计入成本。无法提供无损接口时该目标不合格，不能缩小Canonical。

公开`instantiate() -> Result<Handle,Fault>`，只有ABI、所需进口和实例资源建立成功才返回Handle；初始化只取得本实例需要的内部资源，不读取全局环境、注册表或网络；release释放本实例拥有的内存。公开无共享可变状态，多个实例相互独立；共享代码可以，分配器和资源句柄按ABI检查。向外借出的结果必须在释放组件之前完成复制或保持组件代码与释放函数有效。

完整产物含模块字节/源、进口出口、编码及释放合同、目标ABI和加载说明。只交WIT/头文件不能称运行组件。已有模块满足接口但行为未证时，只能作被测候选。用例是未知import拒绝、大整数不截断、错误解码、重复释放、结果尚存时卸载及新旧实例并存。

## Plugin：加载、注册与卸载分开

复用[原Plugin](../../../examples/成品形态/规则合同.md#35-plugin)的`normalization.plugin/1`工厂，`createPlugin() -> Result<Handle,Fault>`只在实例建立成功后返回；normalize固定为`Promise<Result<NormalizeResult,Fault>>`，close固定为`Promise<Result<void,Fault>>`。插件导入不自动注册；宿主核接口后为本实例建立注册token，只有token所有者可撤销。创建失败回收已取得资源，不撤销其他插件注册。

宿主支持多个版本时，按已协商消息和能力选择；同名包不是兼容证据。调用在接受时保留输入和模块占用；关闭先停入口和新请求，再排空/真实取消，在途调用和结果资源结算后释放代码。不支持热替换时创建新实例并显式切换，不能把旧句柄指到新实现。

默认只有宿主传入的纯值能力，不授予终端、全文件系统或外部网络。第三方未受信代码需要真实隔离；类型品牌不是沙箱。可信本机插件可以选择同进程小成本路线，但保证不得超过威胁模型。

插件发行成员是实现、类型、实际宿主需要的描述和许可；商店、签名、账号与更新服务只有被要求时才加入。签名证明来源而不证明逻辑合格。允许失败的插件卸载不应拖垮宿主；若原生代码无法有界停，必须拒绝“可靠强卸载”要求或采用进程隔离，不能靠超时后free。

这些合同可由成熟运行系统适配；产品作者不写回调桥、引用计数和分配器。组件的进口/出口概念参考[WIT worlds](https://component-model.bytecodealliance.org/design/worlds.html)，但具体行为与资源责任仍由本页和原规范维护。

## 已接受工作与控制请求的终结消息

Output的`{id,ok,...}`只承载完整业务成功或Reversed；已接受任务发生取消、预算或内部故障时使用`{id,fault:{code,message,...}}`，终结该任务一次。`{protocolError:{...}}`只拒绝未接受请求，不清理同id的原等待槽。宿主直接杀死工作器时可能没有任何终结消息，调用者必须通过该会话实际退出将未回复请求标为未完成，不制造已收到fault的假回执。

`{control:"close",id}`的id位于独立控制名字域，不与计算请求id混用。同一次close重复提交复用真实关闭结果，冲突控制不能重新开启会话；先停计算准入，再结算所有已接受工作与输出队列，最后给`{controlResult:"closed",id}`。读取到closed意味着该工作器接口已完成其关闭义务，不代替消费者对各计算结果的采用。非正常消失仍按未知/崩溃处理。

`on`对每条Rule都是必需的Product主体。下表参数由复合定义在声明处提供默认，实例化到Rule时必须全部有准确值；Rule字段不再另存默认。所用形态为[同一字段类型合同](../结构化源码.md#规则值字段沿同一类型检查)。

| Rule | 其他必需字段／类型 | 完整作者根 |
|---|---|---|
| Worker | operation:Operation（与Canonical相同主体）；maxInFlight:Int | [Worker](../../../examples/开发成品/model/worker.json) |
| Component | operation:Operation（与Canonical相同主体） | [Component](../../../examples/开发成品/model/component.json) |
| Plugin | operation:Operation（与Canonical相同主体） | [Plugin](../../../examples/开发成品/model/plugin.json) |
