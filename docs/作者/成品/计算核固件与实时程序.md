# 计算核、固件与实时程序

这些形态都接近物理资源，但所需语义、接口和完成证明不同。不能把生成一个C函数、Wasm模块或镜像称为三者都完成。本页提供三个完整的选定合同；具体设备、驱动和时限依据来自真实目标绑定，而不是作者猜引用。

## GpuKernel：有检查边界的整数批计算

原意图逐项计算y=2x+1，输入输出是i32向量。合法x范围恰为[-1073741824,1073741823]，保证y在i32内；不合法元素报告最小原索引OutOfRange，目标输出在全部预检查完成前不对消费者可见。作者无算法参数，n来自运行输入；n=0正常返回空且不发无效kernel。

公开host调用`submit(inputView,device) -> Result<Job,Fault>`，只有视图/设备/必要资源在提交前合法才产生Job；`Job.result -> Promise<Result<OwnedBuffer,OutOfRange|Fault>>`与`cancel()`；成功OwnedBuffer的`release()`按真实资源寿命；ABI固定元素宽4字节、有符号、选定端序和stride，必要转换由host适配承担。view的偏移、长度、对齐、越界、别名与实际拥有权都检查；包围范围合法不代签无竞态。

设备方法先固定输入快照/合法借用，取得输出和状态资源，提交校验与计算或合格等义融合，等待真实fence，读回错误/成功后结算。设备不可用且任务允许CPU时可选择同语义CPU方法；要求必须在设备执行时不能悄悄回退。取消信号不等于GPU已不访问；device-lost返回准确故障，直到驱动保证不再访问或隔离丢弃才释放内存。

成品有kernel源码/二进制、host桥、布局/launch描述、目标编译与驱动要求。驱动未取得是部署缺项，不伪造一个profileRef。性能包含传输、队列、同步与释放，微kernel benchmark不替完整比较。检查边界正负值、n=0、负stride/溢出、非连续切片、设备重置、取消/完成竞争以及返回资源尚存时卸载。

## Firmware：有启动与失效状态的设备控制

选定功能是毫伏监测指示器，不是通用安全控制器。作者`lowMv`默认1000、`highMv`默认1200，要求low<high；每周期取得一个经过目标校准的Sample，v>=high则指示On，v<=low则Off，中间保持上次状态。初始Off；传感器错误、明显过期或看门狗触发进入FaultOff并发有界诊断。FaultOff不会因随后普通Sample自动恢复；明确`ResetFault`必须同时携带**本次复位时重新取得的**合法且fresh的毫伏样本，系统才回到Off并重新开始迟滞控制。这样不需要靠一个没有时钟依据的“最近样本仍然新鲜”隐含状态；过期或非法复位返回`ResetRejected`并保持FaultOff。

`boardProfile`属于真实目标输入：芯片/存储布局、复位向量、启动代码、时钟、ADC校准、输出有效电平、允许引脚、调试口、看门狗和编程接口必须可取得。逻辑Off的物理电平由该配置决定，不假定所有板卡低电平安全。不能从任意二进制推导它能烧录到任意设备。

为使控制逻辑本身可直接实现和独立验证，目标消费合同还提供纯状态转移：`initial() -> Machine{state:Off}`；`step(machine,input) -> {machine,observation}`。`sample`输入携带`milliVolt`与fresh标志；`sensor-fault`和`watchdog`进入FaultOff；`reset-fault`携带当次复位样本。`Observation.driveOn`是逻辑输出，物理电平仍由boardProfile映射。这个纯转移接口不替代ADC读取、看门狗、GPIO写入和镜像启动，只固定它们必须共同实现的业务状态机。

输出完整镜像、必要引导/链接/校准配置、允许地址区间、校验与载入步骤，以及符号（被要求时）。装载前核设备身份与板配置，禁止越过保护区。支持双槽才采用准备/校验/切换/试启动/确认；单槽断电可能不可恢复，要明确采用范围和外部恢复通路，不宣称总能原子升级。

高低阈值变化影响控制结果，校准变化影响物理含义，两者分别重核。热替换须能迁移状态和在途I/O；默认受控停机或重新启动。验收包括迟滞边界、保持区间、错误样本、复位、不同有效电平、校准不匹配、掉电装载和旧镜像回退。真实硬件故障率与环境安全结论未因这份设计成立。

## RealTime：可调度边界是交付条件

功能沿固件迟滞控制，但运行在周期任务上。作者`periodUs`默认10000、`deadlineUs`默认10000，均>0且deadline<=period；实例期间的任务不能重入同一状态。任务要求从本周期释放到输出提交不超过deadline；late样本和截止违约是独立Fault，不能补发一个旧周期输出当正常。

实现准入需要实际最坏执行C、阻塞B、中断/调度干扰、频率和迁移策略、采样/输出设备延迟、同时任务及优先级。作者固定的period/deadline不会作为运行调用参数再暴露给调用者覆盖；运行环境只提供实际execution/blocking/higher-priority等边界。本例采用固定优先级抢占单核模型，响应时间迭代R=C+B+Σceil(R/Tj)Cj；超过D或不能收敛即不合格。多核、非抢占DMA、动态频率和其他调度模型不套此公式。计数、单位和截止覆盖从采样还是从释放计算必须明确。

运行目标除了`admit(environmentBounds)`还必须有实际周期入口：`start(environment,driver) -> Result<Handle,Fault>`。period/deadline由编译后的产品固定为`Timing`，不是调用者的可变参数；scheduler接收这份Timing和实际环境边界，按已接受的周期产生release并提供单调`nowUs`；driver只暴露校准采样、逻辑输出和FaultOff。每个release最多有一个活动周期；周期先取样，再调用同一Firmware状态转移，再提交输出，并用真实完成时刻核deadline。scheduler、driver或采样失败进入该周期故障和FaultOff，不能仍报告正常周期完成。`Handle.close()`停止新release，等待或准确终结已释放周期，再把输出置于真实安全态；关闭Promise完成才允许释放本实例拥有的调度和设备资源。

默认部署不在关键循环分配、page fault或执行不受界定的GC/网络；采用TS协调与原生实时核可以，但边界延迟仍计入。Linux SCHED_DEADLINE的参数和准入不代替程序WCET，参考[内核说明](https://docs.kernel.org/scheduler/sched-deadline.html)；本页没有指定它为唯一调度器。

错过期限时请求本目标已定义的FaultOff，不快速补跑历史任务挤压后续截止；关闭在受控切面先停新释放，再结束/隔离已释放任务，最后交设备到确定状态。产物须含任务、调度与资源配置、实际方法/硬件假设、响应时间依据及失效行为；只有p99或仿真平均耗时不能标硬实时已满足。设计参数已定、实测C未知时准确保留运行资格缺口，不擅自把deadline改大。
