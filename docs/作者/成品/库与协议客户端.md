# 库、SDK与协议客户端

Library、SDK、ProtocolClient三个根使用同一精确区间规范化行为，不把一种调用形式推广为所有软件。原Library完整值及错误合同见[规范化规则](../../../examples/成品形态/规则合同.md#31-library)。字段与实际源见[开发成品](../../../examples/开发成品/README.md)。

## Library：没有运行容器的同步库

公开`normalize(items: readonly Interval[]): NormalizeResult`，Interval端点为bigint，NormalizeResult恰为成功完整序列或Reversed的原始index。源输入、失败次序及两种相接策略沿Canonical；本例Library采用MergeTouching。调用不读文件、时钟、环境或网络，不暗建线程。合法类型值的资源失败与业务Reversed分别传播；不可信对象须在外部解码边界验证，不通过读取getter假装纯值。

产物有实际实现、公开类型和消费说明；被选择为包时提供package.json及明确exports。Node ESM是本例打包基线；无要求不再同时生成CJS。JS运行成员与声明必须来自同一份实际目标，不允许只有.d.ts。源码包可交TS与真实编译前提；可直接安装包必须交对应JS。是否含source map由调试要求决定，不改变行为。

供给完全匹配时可直接重导出，不强制一层空适配。实例没有可变状态，调用可并发；返回列表与输入不共享可变所有权。包名、显示名称、公开接口名和类型身份不是同一个ID。修改私有算法只重核真实内联/实现消费者；修改结果联合则检查公开调用者。

## SDK：同一行为的显式资源会话

原意图是给嵌入宿主一个可统一取消和关闭的异步访问器；不是给纯库强加SDK。公开`createNormalizer() -> Handle`，`Handle.normalize(items,{cancel?}) -> Promise<Result<NormalizeResult,Fault>>`及`Handle.close() -> Promise<Result<void,Fault>>`。内层NormalizeResult只表达完整业务成功或Reversed；外层Fault表达取消、Busy、Closed、预算与内部/宿主故障，不能把这些故障伪装成业务Reversed。作者maxInFlight默认4且为正Int；它是本例资源选择，不是语言普遍阈值。运行工厂不再接受一个可随意放宽此值的同名参数；宿主可以拒绝或收紧实际资源，但不得违反作者已固定的上限。

Open状态才接纳。接受时捕获不可变输入并登记请求，成功/业务拒绝作为值；已关闭、取消、预算和内部故障为带稳定code的拒绝。没有额度立即Busy，不建立无界队列。取消一个调用只影响它，close先停准入再等待已接受工作；重复close复用相同终结，不重复释放。外部传入的池/执行器是借用，SDK不关闭它；自己创建的资源最后结算。

公开异步不随内核速度改变。同步算法可在合格调度里使用，主线程有响应约束时须有界切片或工作器。完成回调可能同步发生，须先登记。SDK不会自动选择远端以“加速”；这种变化涉及数据离域，须另有接受。

输出为实际factory、Handle实现、共同算法或准确依赖、类型与关闭说明。空Handle和永远pending的Promise不合格。必须测接纳前取消、运行中取消、结果到达与close并发、同一结果双回调、借用池仍被别处使用及资源零余额。

## ProtocolClient：公开网络语义不能藏在SDK实现里

原意图是调用已存在的`POST /normalize`服务；参数`requestTimeoutMs`默认30000且>0。`createClient`先验证baseURL/静态选项并返回`Result<Client,Fault>`；Client.normalize返回`Promise<Result<NormalizeResult,Fault>>`。运行输入是显式baseURL、显式凭据提供者和每次items；baseURL必须HTTPS，只有明确的本机开发配置允许loopback HTTP，不读取某个隐式全局账户。

请求体沿Command的规范整数编码，Accept与Content-Type均为application/json；拼接固定路径不得改变base的origin，不接受userinfo。默认不跟随重定向，不把授权头转发到新origin。请求体在发送前固定；连接池属于client或明确借用，close按相同归属处理。

返回：200必须解码为合格完整区间；400为结构/业务拒绝；401/403为授权失败；413为预算；429/503保留Retry-After提示但**默认不自动重试**；其他状态为RemoteFailure；HTTP成功但响应非法为ProtocolFailure。超时和断连不伪造服务未执行，上传/发送完成不等于收到结果。纯计算可以在明确没有计费等附带效果时重新请求；默认关闭的自动重试由有权任务另行启用并固定总截止、退避与去重条件。

对端返回序列还需检查类型、排序和已绑定结果关系；返回的同形JSON不自动可信。错误不记录原始凭据或完整用户输入。TLS、DNS、代理和证书失败有不同定位，但不把它们包装成Reversed。

客户端完整交付是实际客户端模块、编码器、协议说明和所需依赖，不捆绑服务器。验收用确定响应/断连/迟到/畸形体/重定向场景校准；没有真实对端测试不得写“已互操作”。Library、SDK、Client由不同根选取，不因都叫normalize互换同步/异步或网络责任。

## 实现与兼容的共同依据

包出口按实际目标工具解析；[Node包文档](https://nodejs.org/api/packages.html)区分导出与包入口，不为本例提供完整ABI保持证明。[HTTP语义](https://www.rfc-editor.org/rfc/rfc9110.html)用于状态、方法和重定向边界；本例的重试禁用、接口名和资源策略是这里作出的选择，不是HTTP对所有SDK的规定。

## 400与成功结果的准确解码

Client收到400时，只有精确匹配Reversed及合法Dec索引、并与原输入范围和该错误关系相容，才返回NormalizeResult的业务Err；其他格式/结构拒绝属于InvalidInput故障，错误对象不合法则ProtocolFailure。状态200但结果关系不符合原要求也不得作为成功；核验可采用独立合格方法，不要求无条件在客户端重复昂贵求解，不能取得所需保证时保留该保证缺项。默认超时包括连接、发送和接收的本次总时段，用户取消、超时和收到远端失败分别定位。
