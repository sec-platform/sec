# 特化与结构查询

> 条件能力设计；不改变已固定的基础画像，不表示实现或目标符合性已完成。

本页补充[实现选择与设计搜索](实现选择与设计搜索.md)中的相交能力；原章节继续拥有其已采用的有限语义。**当前选择：区分编译优化与公开语义，条件采用。** 相同合同的快路径可以是后端优化；公开可见的不同表示/行为需要明确选择和一致性，但不默认开放全局特化。

这里的选择不是删除能力或承诺全部默认启用。满足真实要求的成熟库、静态展开和原生适配可以作为最终方案；额外语义只在现有路线不能保持该使用点的明确要求时激活。未提供对应解释、实现或目标条件时保留作者要求并返回具体缺项，不强迫所有项目携带设施。

文中的类型名、操作名与代码块为合同记法，不向现有作者文法添加关键词，也不直接发布 wire 字段。作者仍通过已有 Definition/require/prefer 或已解析原生定义提供真实差异；内部信息归入原 MethodSpec/BoundaryView/UseBinding，公开扩展必须另有准确版本及能力协商。共同准入见[能力履行](目标/能力履行与接口差额.md)。

### 两种不同的特化

**语义类型族**允许按参数选择不同定义，包括不同成员／布局。它本来就是公开语义差异，不能假称只是性能优化。

**实现特化**为同一个公开合同选择不同实现。优化分支不能加强前置条件、削弱后置条件、引入未声明效果，或改变已承诺的溢出／排序／精度语义。不能仅因为更快就替换。

两类都允许完整模式与部分模式；函数重载、类型族、实例化 witness 各自绑定明确的声明 owner，不混成一张“谁先注册谁赢”的表。

### 开放世界中的一致性

提供三条路径：owner 管理的默认实现；声明了扩展规则的 specialization family；显式传入的局部 witness。第三方可以为自己的使用点选择外部类型的行为，不需要全局修改 foreign trait／foreign type，也不能因此影响所有其他调用者。Rust coherence 解决的是全局冲突问题，不能仅删除 orphan 检查而保留其余编译假设。[依据](../依据/来源/Rust与C++能力比较.md#baseline-s04)[依据](../依据/来源/Rust与C++能力比较.md#baseline-s06)

特化按模式包含与可证明约束蕴含形成偏序。具体使用点必须有唯一可接受目标；无法比较时报告 witness 或显式分支需求。开放依赖集合中“暂未发现某实现”不等于否定该能力。只有 sealed／已冻结候选集合允许可靠的否定查询。

默认不允许依赖已擦除的寿命细节来选择改变运行语义的全局特化。确需该区别时把证明前提留在使用点证据和缓存 key 中，不在擦除后重新猜测。

### 结构式探测

`probe` 查询表达式、关联类型、可调用性和效果是否满足合同；不要求被查询类型事先声明名义 trait。查询只做有限语义分析，不执行被探测的函数体。

结果区分成功、确定不适用、前提不齐、歧义、内部错误和资源耗尽。替换立即上下文中的合法不匹配可排除候选；编译器崩溃、权限不足、供应缺失或 solver 超时不能伪装成 SFINAE 的 false 再悄悄换实现。

### 编译期分支

`static if`／`match type` 在选择后才实例化相应依赖分支。所有分支必须是合法的源结构；与参数无关的语法错误不能隐藏在未选择分支中。对该参数才有意义的操作只要求被选分支成立，不强迫两个分支成为同一个目标泛型函数体。

静态分支的真／假若尚未确定，就保留 symbolic obligation；不能以 runtime if 代替后声称未选分支不需类型检查。公共接口随分支变化时属于类型族输出，必须体现在模块签名与依赖失效关系中。

### 计算边界

默认求解器使用可处理的结构匹配、有限域及指定算术片段。一般用户元程序可以更强，但会受到编译预算约束；无法决定的证明义务返回 Unknown／BudgetExceeded。可以使用外部证明供给，但按原保证接纳合同核验逻辑、编码、真实证书或明确允许的可信基础后，才取得相应用途的支持；配置了 checker 或成功退出本身不提升信任。编译超时不是数学上的不可判定证明。

## 再次修改与失效

新增候选、解除封闭域或修改否定查询时，失效候选集合与负依赖；已有运行绑定不随插件装载次序重选。

## 使用点与可检验出口

这些分支保留各自的真实输入、替代路径与边界，不按条数声称更多底层能力；[比较记录](../依据/来源/Rust与C++能力比较.md)不拥有另一套语义。

- **函数重载集合**：作者便利可在解析期降为确定调用；是否提供重载按可用性测试决定，非系统完备性必需。 硬边界示例：原生调用语法必须不变，或库要求无需合作即可按任意输入参与自动重载；[具体比较与出口](../依据/来源/Rust与C++能力比较.md#a12)。
- **ADL**：设计明确的定制入口；不移植整套 C++ 查找算法作为默认。也不声称 C++ 开放扩展不受 ODR/可见性约束。 硬边界示例：需要对不合作的外部类型与外部算法做全局透明扩展，不能包装/传策略；[具体比较与出口](../依据/来源/Rust与C++能力比较.md#a21)。
- **完全特化**：区分不重叠实现、语义类型族与等价优化；只有后两者确需时才引入相应规则。 硬边界示例：必须保留通用默认＋任意具体例外的开放接口或不同实体定义；[具体比较与出口](../依据/来源/Rust与C++能力比较.md#a31)。
- **部分特化**：撤回“Rust 没有部分模式实现”；真正审查重叠与定义变化，不按关键词裁决。 硬边界示例：需要重叠结构模式自动排序、公开字段/类型族变化，且不能分离策略；[具体比较与出口](../依据/来源/Rust与C++能力比较.md#a32)。
- **重叠候选按专门程度选择**：优化分支可放优化器；语义差异必须在明示候选域/witness绑定中表达。不能默认全局开放特化。 硬边界示例：要求不改调用点、任意新类型可合作/不合作地加入选择，且全局唯一性必须维持；[具体比较与出口](../依据/来源/Rust与C++能力比较.md#a33)。
- **SFINAE/requires 结构式探测**：这是比没有默认参数更实质的抽象限制；Gift有需要时用已有语义查询，不必因此照搬SFINAE所有历史规则。 硬边界示例：公共通用库必须接受未来未适配类型并按成员存在性分派；[具体比较与出口](../依据/来源/Rust与C++能力比较.md#a34)。
- **if constexpr 丢弃依赖分支**：可在实例化/生成阶段解决；先复用分派，避免把它误称CPU控制能力。 硬边界示例：一个开放泛型定义必须按未知T的结构探测自动选依赖分支；[具体比较与出口](../依据/来源/Rust与C++能力比较.md#a35)。
- **更广泛泛型 constexpr**：保留阶段和目标数值输入；先做真实所需操作，不默认开放无界元程序/整个编译期堆。 硬边界示例：需要通用库操作在目标语义下静态运行、类型检查一致，不能另写host脚本/复制算法；[具体比较与出口](../依据/来源/Rust与C++能力比较.md#a39)。
- **reflection splice**：hygiene和绑定正确性必须保留；公共splice不是编译器项目天然必须暴露的语言功能。 硬边界示例：通用反射结果必须无损保持语义实体绑定，不能依赖字符串/显式metadata协议；[具体比较与出口](../依据/来源/Rust与C++能力比较.md#a41)。

实际组合与拒绝条件见[验收案例](../运行/验收/跨语言控制与组合案例.md)；从作者要求到再次修改见[连续开发情景](../../examples/连续开发/跨语言能力连续开发.md)。

## 表示族、条件操作与公开特化

先判断差异是同一公开合同下的实现优化，还是会改变成员、布局、可用操作、错误或资源保证。前者由已有实现选择及后端优化处理；后者属于真实类型/能力差异，必须以固定实例、关联表示或显式版本化定义保留，不能只有一个无约束 specialization 开关。

默认尝试不重叠实现、关联类型/存储和显式策略；它们满足要求时就是最终路线。需要重叠规则时才启用本页已限定的候选域、偏序与见证。允许条件性复制不推出允许同样方式的条件性析构、布局改写或任意对象安全；每种操作分别检查其目标语言合法性和使用点合同。新插件不改变已固定实例。

生成时将选择后的真实表示连到访问、初始化、析构、反射、导出和布局消费者；没有某个字段的实例不能沿通用访问器读该字段。迁移到另一表示时先检查既有对象及公共接口；保持原行为的内部优化可以局部更换，公开表示变化则必须走真实迁移或新版本，不用相同类型名隐藏。
