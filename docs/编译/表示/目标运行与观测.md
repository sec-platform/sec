## 发布、部署与支持中间表示

### 1. 目的

源码编译成功与可发布、可部署、可运行、可支持是不同阶段。`DeliveryIR` 把制品、环境、部署计划、验证和支持声明分离。

### 2. 对象

```text
DeliveryProgram = exact {
  releaseArtifactRefs,
  artifactManifestAndSbomRefs,
  sourceAndToolchainClosureRefs,
  targetEnvironmentProfiles,
  deploymentTopology,
  configurationAndSecretBindingRequirements,
  rolloutAndRollbackPlan,
  healthAndReadbackClaims,
  compatibilityAndDataMigrationRefs,
  supportClaimCandidates,
  observabilityAndIncidentRequirements,
  unknownFrontier
}
```

### 3. Release 与 Deployment

Release Artifact 是内容寻址、可安装、可验证的制品；Deployment 是将 exact artifact 与 exact environment/config/secrets 绑定并产生运行状态的 Effect。上传文件不等于部署，部署成功也不等于用户支持。

### 4. SupportClaim

```text
SupportClaim = exact {
  capabilityAndEnvironmentCell,
  minimumAndReferenceVersions,
  evidenceRefs,
  knownLimitations,
  incidentAndMaintenanceBoundary,
  supportWindow,
  deprecationAndWithdrawalConditions
}
```

Support 不由 package 存在、测试通过或文档写明自动产生。

### 5. 降低

DeliveryIR 降为 release build plan、deployment operations、configuration bindings、migration actions、verification sessions 和 monitoring setup。任何平台特化由对应 backend/provider 处理。

### 6. 验证

- exact source tree 与 artifact 不匹配；
- clean install 失败；
- runtime asset 缺失；
- secret/config 错绑定；
- canary 不代表关键流量；
- rollback 与新 schema 不兼容；
- deployed but unsupported；
- upstream EOL 使旧 SupportClaim 失效。


## 演进、迁移与退役中间表示

### 1. 目的

`EvolutionIR` 表示从旧定义、实现或物理状态到新代际的合法过渡。版本号变化不自动要求数据迁移。临时竞争双写有边界与退出条件；长期多协议服务是另一种有权威和一致性合同的稳定架构，不能凭其名字永久豁免迁移义务。

### 2. 结构

```text
EvolutionProgram = exact {
  subjectAndScopeRefs,
  oldAndNewDefinitionRefs,
  compatibilityDecisionRefs,
  currentConsumerAndWriterCensus,
  preservationAndTransformationRules,
  migrationOperationDag,
  qualificationAndOptionalShadowPlan,
  readerWriterCompatibilityAndCutoverPlan,
  recoveryAndFallbackBoundaries,
  supportWindow,
  retirementPredicates,
  evidenceAndUnknownFrontier
}
```

### 3. 兼容维度

结构兼容、语义兼容、行为兼容、数据兼容、权限兼容、操作兼容、部署兼容和支持兼容分别判定。字段可解析不代表含义兼容。

### 4. 阶段与路线选择

```text
proposed → qualified → cutover-ready → active-new → old-restricted → retired
```

这表示可能的业务阶段，不是全部任务的强制管线。`qualified`可以来自足够的静态保持检查、有限符合性验证或需要时的影子运行；数据回填、双读/写、分批流量和恢复检查按所选路线作为有依赖的子任务。修改没有状态的文档或实现不要求创建影子服务。路线、观测方法、失败状态和撤销条件归[迁移合同](../../演进/兼容迁移与退役.md#兼容迁移切换与退役)。

### 5. 迁移失败

实际作用步骤明确前提、效果、检查点、读回，以及可回滚、可补偿、只能向前或尚未知的恢复能力。无法保证恢复的步骤先显示不可逆点与当前准入条件，不能写成“每阶段都可恢复”。取消或预算耗尽不修改已发生事实。

### 6. 退役

退役针对声明的支持和权威范围确认：旧在线写入已切走或被目标端拒绝；必要消费者已有替代、明确退出或隔离；历史读取、备份与未结算恢复内容按真实保留义务处理。不要求找到开放世界全部消费者才撤销危险版本，也不因活动实现退役删除唯一历史解释或恢复路径。简单删重文档不套运行退役流程。

### 7. 验证

覆盖旧数据、混合版本、部分迁移、并发 writer、回滚失败、离线节点回归、旧备份复活、消费者漏计、兼容窗口过期和新旧语义不等价。


## 目标程序中间表示

### 职责与输入

`PortableProgramIR` 表达可跨目标的已选行为与声明语义；`TargetProgramIR` 绑定一种目标画像，明确目标类型、运行接口、调用约定、数据布局、错误和依赖。后端将它序列化为目标源码或制品，不能在这个阶段重新决定业务意图。

输入必须包含公共语义 revision、所选输出根、目标画像、已固定实现绑定、降低规则和保持声明。未知与未支持区域可以保留供诊断，但必须进入输出完成状态，不能生成空实现代替。

### 节点与引用

每个定义节点具有稳定语义来源和目标局部身份。声明、表达式、控制流、数据布局、外部导入、资源及制品依赖使用类型化引用。一个公共节点可以降低为多个目标节点；多个公共节点也可合成为目标结构，来源对应必须保留。

图允许目标语言合法的递归类型和调用，但不得把源码递归错误地转换成无法调度的构建任务环。递归解析与制品生成的依赖图分别检查。

### 目标闭合检查

| 检查 | 合法条件 | 失败结果 |
|---|---|---|
| 符号 | 每个必需引用可在选定目标命名空间解析 | 未绑定/歧义，附源节点 |
| 类型 | 赋值、调用、可空、集合、递归满足目标规则 | 类型诊断，不强制转换掩盖 |
| 数值与文本 | 溢出、精度、编码、单位按保持合同处理 | 无合法表示或需明确替代 |
| 控制流 | 返回、异常、取消和资源释放路径有定义 | 缺失路径或目标不支持 |
| 效果 | 文件、网络、状态与并发效果由明确绑定实现 | 未声明效果或权限义务 |
| 依赖 | 包/库/运行时内容与能力闭合 | 未解析、冲突或分发资格不足 |
| 目标源码 | 标识符、路径、语法、声明顺序符合目标 | 源映射诊断或拒绝完整输出 |
| 发布组合 | API、模式、运行库和迁移属于兼容的组 | 可单独生成但不可组合发布 |

必须在对应阶段检查，但不要求重复执行同一分析。可信检查回执绑定输入、检查器版本和范围，供后续消费者复用。

### 开放区域与输出分类

依赖模式（目标原生、显式混合、未确定）与完成范围（完整、局部、被阻断）正交记录；源码形式（表达式、区域、声明、模块、工程）是第三个独立坐标。片段可以完整满足片段请求，混合依赖也可以完整满足已接受目标。桥接仍需明确协议、数据与错误转换、性能、安全和生命周期，不是免费或无损转换。

只要缺口不进入所选输出及发布组，可以生成闭合部分；同一原子发布组不能把缺失部分隐藏后宣称完整。原生区域的编辑权、原字节与旧运行依赖继续追踪。

### 源码组织是目标表示的投影

目标声明、类型/运行引用、初始化依赖、局部/实例资源范围与输出所有权共同决定源码布局。实际投影记录符号到文件/作用域、命名和导入、公开导出、状态初始化位置、原生保留区及辅助库绑定，不复制作者业务定义。完整选择规则见[目标源码组织与生成策略](../目标/成员布局与完整产物.md)。

片段前端可以在内存构造虚拟宿主进行所需检查，虚拟模块不是长期作者源。检查回执分别标出显式假设、已绑定上下文和独立输出条件；不把“在提供的Item类型下通过”扩展为“任意输入都安全”。插入现有源码时重新绑定真实位置、语法类别和控制出口，不能仅因两边拥有同名符号就替换。

### 源码映射与调试

映射记录源位置、语义节点、降低规则、目标范围、合成原因和信息损失。调试器和错误诊断可以定位原工程含义，不依靠目标行号作语义身份。优化删除或合并节点后仍需能解释来源；无法反向恢复的修改不得静默覆盖作者区域。

### 增量失效

目标画像、实际使用的表示规则、绑定内容或源语义变化使相应目标节点失效。其他目标的独有配置不污染本目标输入。共享运行库修复可能影响多个目标组，应按真实依赖扩大，不预先承诺每次只能改单文件。

### 边界测试

最低场景包括大整数与溢出、文本编码、求值顺序、异常、取消、递归、并发可观察顺序、未绑定外部调用、依赖冲突、目标保留名、大小写/Unicode 路径碰撞、桥接运行依赖和同组模式错配。跨语言差分只在声明的观察范围内比较；格式相同不证明行为相同，行为样例相同也不证明所有输入等价。

### 理由与替代

从公共模型直接拼接所有语言源码省去一层表示，但会使每个模板重复类型、效果与目标合法性判断。独立目标表示集中这些差异，代价是降低规则和映射维护。小型固定输出可以融合阶段实现，但逻辑检查边界和输出分类仍要保留，不能为遵守层数强制序列化每个中间结果。

### 一般程序后端与原生接入

目标表示必须能保留用户一般控制流、调用、数据和Effect，不得只容纳官方示例生成器。历史有限画像以精确整数/布尔/名义包装、函数与循环映射到TypeScript AST，并要求目标编译器严格检查；本包不附该实现；完整目标设计中的泛型、闭包、异步、类、模块与原生FFI仍按目标能力扩展，不因有限参照省略就删除设计承诺。

复用原生库优先保留其语言级签名、调用约定、依赖锁和错误/Effect边界。没有SEC业务语义适配器时仍允许原生工程保全与合法目标调用；未知属性限制对应分析和优化，不自动阻断所有编译。不能从签名正确推断事务、时间或权限保持。详见[开放编译器内核](../内核/编译值服务.md#开放编译器内核设计)与[用户定义语言语义与编译扩展](../../作者/组合/语义扩展与领域接合.md#用户定义语言语义与编译扩展)。

## 运行调试位置绑定：来源图不是可恢复值的证明

有限调试消费现有SourceMap、来源链和制品成员，不建立另一份作者IR。每次DebugSession固定实际可执行制品、构建/插桩转换和源内容；源文件名只能显示和定位，不能用同路径当前编辑器内容替换该运行的原字节。

源码断点位置先验证sourceRef与byteOffset，再沿准确转换链定位实际目标成员/位置。映射结果分别为准确单点、多个出现、可解释的合成区域、删除/融合后的不可定位或未知。多个出现保留其实际范围，由断点配置说明要处理哪些；缺映射不得按相同行号猜。调试器返回重定位位置时反向标出实际位置与原请求差异，必需精确断点不能自动变为邻近位置。

SEC源坐标、目标打印坐标与底层调试器路径/行列合同分别转换：绑定编码、行尾、基数和具体适配器列单位。UTF-8字节、Unicode标量、UTF-16 code unit并不相同；代理对、组合字符、CRLF和文件首标记都可能改变偏移。转换表从实际字节建立，超范围/落在非法编码中间的请求拒绝，不在错误一列时继续假装精确。

生成后再经打包、缩小或原生编译的制品必须组合实际映射；缺某一阶段的映射时，只提供能证明的边界。代码被内联后可有多调用上下文，局部变量被消掉后可能没有运行位置。即使来源能定位一个变量，也不能从编译常量、旧运行记录或相似名字伪造它本次运行的值。

`PauseRef/FrameRef/ValueRef`是运行观察引用，不是Definition身份、源码节点ID或生成编辑的EditRef。继续后旧帧失效；同一底层编号在新暂停复用不延长其寿命。值需要离开暂停继续查看时，仅保存实际读取到的不可变内容及其覆盖，不能保留一个后来指向新对象的活句柄冒充快照。

调试定位到原生作者，可以沿原生编辑；定位到中立作者，修改原源；定位到合成辅助，使用其实际规则与来源解释，必要时调整有权控制或受管回源。生成A1不热替换正在执行A0的会话；旧源码引用与新的当前编辑器内容分别展示。目标调试、源码导航、保持性逆向编辑是三个独立合同。


## 观测中间表示

### 1. 定位

`ObservationIR` 是物理观察进入编译分析的统一有类型记录边界，不是把外部断言自动提升为可信事实的入口。它记录观察到的对象、方法、覆盖、环境、错误和未知，不包含业务采用和目标裁决。内容真实及其对具体Claim的支持由[解释与证据接纳](../../运行/保证/解释与证据接纳.md)按实际来源、模型、覆盖和信任条件评价；不同来源的冲突可以同时保留。结构通过、签名或已获准执行本身不证明观察正确。

### 2. 结构

```text
ObservationGeneration = exact {
  generationRef,
  subjectScope,
  observationEntries,
  membershipAndNegativeFacts,
  environmentRef,
  methodAndProviderRefs,
  preAndPostReadbackRefs,
  coverage,
  unsupportedAndUnknownFrontier,
  canonicalDigest
}
```

每个 entry 绑定 logical identity candidate、physical binding、raw bytes or structured value、kind、mode、source revision 和读取结果。

### 3. 读取结果

```text
ObservationResult =
  observed
  | absent-with-complete-coverage
  | inaccessible
  | unsupported-kind
  | invalidated-during-read
  | ambiguous-identity
  | corrupt
  | bounded-unknown
```

`absent`仅对明确对象与覆盖范围成立：一次可信精确路径查询的不存在可以形成该路径负观察，不要求先扫描全工程；“不存在其他成员/候选”则需要该集合的完整枚举边界。权限错误或未观察不能写成不存在。

### 4. 不可变边界

parser、frontend、resolver 和 verifier 只消费 observed bytes/objects，不在 validated boundary 之后重新打开 live path 或 API。需要新内容时创建新 ObservationGeneration。

### 5. 多源 join

跨文件、数据库、外部 API 和运行时观察必须明确是否共享一致性边界。不存在原子快照时，结果是带 partial-order 和 uncertainty 的 composite observation，而不是假装同一时刻。

### 6. 降低

ObservationIR 可以产生 SourceProgram candidate、runtime Evidence、provider capability facts 和 current-state facts；不能直接产生 accepted Definition、Binding、Grant 或 Verdict。

### 7. 验证

覆盖 same-size replacement、目录 membership change、symlink/reparse、API pagination、权限错误、采样、外部 drift、clock mismatch、partial read、provider schema drift 和敏感数据泄露。


## 解释、调试与溯源中间表示

### 1. 解释不是日志拼接

SEC 的每个重要结果必须能够解释“为什么成立、为什么未成立、谁决定、读了什么、淘汰了什么、发生了什么以及哪些未知仍存在”。

### 2. ExplainGraph

```text
ExplainNode =
  Intent | Definition | Observation | Fact | Constraint
  | Candidate | Decision | Binding | Plan | Admission
  | Effect | Readback | Evidence | Verdict | Unknown

ExplainEdge =
  derived-from | rejected-by | selected-because | authorized-by
  | depends-on | invalidated-by | observed-by | supports
  | conflicts-with | replaced-by
```

### 3. 解释查询

- 为什么选择实现 A 而不是 B？
- 哪个输入变化使结果 stale？
- 为什么某测试 required/not-applicable？
- 哪个授权允许了某 Effect？
- 哪个未知阻断了发布？
- 哪条关系使一次局部变化传播到另一个领域？
- 如何恢复或反转？

### 4. 最小解释

输出应覆盖所查询结论必需的因果与约束，并尽量减少无关上下文；只在已声明的有限模型内承诺最小性。保留 identity、source、counterfactual 和 expansion handle。它不能为了简短删除改变结论的约束或未知。

### 5. 调试

调试对象包括 compiler pass、query、cache、provider、operation attempt、verification action 和 migration step。每个对象提供稳定 reason code、输入闭包摘要和重现 capsule，避免依赖自由文本匹配。

### 6. 隐私

解释图默认引用摘要和受控查看句柄，不复制秘密、完整源码和个人数据。不同主体按披露权限获得不同投影，底层事实不因查看者改写。可披露结论可能更弱或被隐藏；甚至“存在受限证据”也须有披露依据，不能用解释消息泄漏秘密对象的存在。

### 7. 验证

- 输入排列变化不改变解释语义；
- 删除关键节点使 explanation validator 失败；
- 自由文本无法改变决策；
- 同一 reason code 可定位不同实例；
- 权限不足时按披露政策隐藏内容及必要的存在性，给出仍允许采取的动作；
- 解释与实际 decision/receipt digest 一致。


## 验证中间表示

### 1. 目的

`VerificationIR` 把目标程序、变更和工程声明编译为可执行验证图。它明确要证明什么、在何种环境、使用何种方法、需要什么独立性和证据。

### 2. 核心对象

```text
Claim
Gate
VerificationRequirement
VerificationAction
Observation
Result
Evidence
Aggregate
Review
Verdict
```

这些对象不能折叠为“测试通过”。

### 3. 声明

```ts
interface Claim {
  readonly claimId: string;
  readonly subject: SubjectRevisionRef;
  readonly proposition: Proposition;
  readonly scope: ScopeRef;
  readonly environmentAssumptions: readonly ConstraintRef[];
  readonly strength: ClaimStrength;
  readonly validityWindow?: TimeRange;
}
```

声明可以是：类型性质、行为示例、状态不变量、关系超性质、统计性能、鲁棒性、恢复能力、供应链来源或运行效果。

### 4. 验证要求

```text
VerificationRequirement = {
  claimRef,
  acceptableMethods,
  requiredCoverage,
  requiredIndependence,
  environmentProfile,
  freshness,
  failurePolicy
}
```

不同声明需要不同证明方法。单元测试不能单独证明跨进程崩溃恢复；统计测试不能支配形式安全证明。

### 5. 动作图

验证动作的选择与裁决流程唯一由[声明到裁决的证据链](../../运行/验收/方法与独立证据.md#声明到裁决的证据链)维护。本节消费其声明、对象、方法与范围，不再绘制另一条“所有测试→独立复核”的必经图。

实际执行的动作携带`ActionKey`、输入、资源、环境和完成状态；直接推导、已有证明及合格结果复用按各自依据关系处理，不伪造一次未发生的执行。
动作有 `ActionKey`、资源、环境、输入闭包、完成状态和证据输出。

### 6. 结果状态

```text
Passed
Failed
NotRun
NotApplicable
Unknown
Stale
Invalid
UncertainCompletion
```

零个选中测试不能成为 `Passed`。执行器退出成功也不自动形成 Verdict。

### 7. 证据

依据类型和保留策略由[最小证据载荷](../../运行/保证/要求证据与裁决.md#设计判断运行事实与最小证据载荷)拥有。IR消费准确声明、对象、结果和适用条件，按来源保留不同内容：

| 依据来源 | 必要对应 |
|---|---|
| 实际执行 | 实际ActionKey、输入、方法、环境、观察及覆盖 |
| 可检查推导 | 所用规则、前提、推导关系及适用范围；不伪造一次执行 |
| 合格复用 | 原依据、前提匹配与本次范围 |
| 外部规范或资料 | 精确来源、支持命题、条件和限制；不冒充本地已运行 |

这些是原协议的消费关系，不定义另一份独立Evidence Schema。

需要长期采用的依据保存到可准确取得的内容及来源；临时CI页面不是唯一恢复来源。Evidence投影遵守保证规范的实际数据合同，不为每条纯表达式或设计推导强制创建持久证据图。

### 8. 独立性

独立性按风险分级：

- 不同函数或模块；
- 不同进程和不可写候选；
- 不同实现；
- 不同身份；
- 不同环境和供应链；
- 外部认证。

候选产生者不能单独签发高风险发布裁决。

### 9. 复用

验证结果只在以下闭包相同或有合法蕴含时复用：

```text
claim
+ subject revision
+ exact reachable inputs
+ test definition
+ toolchain
+ environment
+ policy
+ coverage
```

无关文档变化不应使编译测试失效；工具链、环境或权限前提变化必须局部失效。

### 10. 发布资格

`Verdict` 可以作为提升输入，但合并或发布仍需要：

- 精确候选；
- 一次性授权；
- 当前目标前像；
- 分支或环境政策；
- 发布后权威读回。

### 11. 验收

- 每个目标约束有 Claim 或明确非验证决定；
- 声明与测试方法匹配；
- 状态不压扁；
- 证据输入和环境闭合；
- 关键声明有独立复核；
- 复用合法；
- 陈旧传播局部；
- 合并和部署后读回；
- 验证器自身有符合性和故障测试。

### 组合执行与代际一致性

本篇VerificationIR拥有验证含义和计划，不另写工具进程、资源、重试、幂等或恢复内核；这些动作通过已有操作执行协议完成。所有证据subject须解析到本次实际测试的模型/制品，不能仅绑定用户工作ID或最新分支名。

第10节的发布后权威读回是该次发布的后置结算义务，不是发布尚未执行时的前置条件。生成结果、验证结论、当前写回状态和发布资格分别保存；同一请求总体显示Partial不能丢失已就绪输出，也不能把旧产物PASS借给新产物。跨对象映射以[流水线状态规则](../内核/输入与阶段总览.md#编译流水线与阶段边界)和[项目代际关系](../../作者/工程源/身份断言与采纳.md#项目组成与表示等级)为准。

### 有限验收的subject与资格组合

`sec.acceptance/1`定义oracle出处描述、具名输入和预期结果；Int采用规范十进制字符串，Bool采用布尔值。Schema检查结构，应用另检查案例ID唯一性。它不包含执行授权、生产部署状态或任意代码脚本，不自动成为全部行为的形式规范。

构建记录绑定实际源码树及实际目标输出；行为记录进一步绑定完整代际引用、原始验收输入摘要、宿主身份和逐案例观察。应用只接受自己受信执行路径生成的证据，外部JSON或另一个会话的句柄不会成为通过证明。所需情境、允许的宿主与验收摘要由消费动作明确要求；缺少要求不等于偷偷推断某个全局安全等级。

同一subject和同一验收输入曾通过、后来失败时，不能用旧绿色遮住新失败。对同一分支的确定性验收，当前设计使用最后匹配记录处理该要求；统计或安全保证则按独立样本、时间、环境与撤销政策合成，不能把最后一次观察泛化成所有问题的真理规则。

有限验收可以失败而严格类型检查仍通过；未运行不是失败；目标运行异常与比较不满足分开保留。source→build→observed→verdict的单向引用避免自摘要和循环自证。回执完整性不等于签发者真实可信，跨系统消费必须采用实际签名/认证与资格检查。
