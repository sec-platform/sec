# 性质保持与开放环境

本篇拥有从作者含义到具体实现时，**何种关系足以保持本次所求性质**的合同。它细化[表示族与跨层保持](表示/表示族与跨层保持.md)、[有条件实现](有条件实现与公共行为保持.md)和[组合前提](组合前提与进展闭合.md)，继续使用原Claim、BoundaryView、MethodSpec、UseBinding和LoweringReceipt；不增加作者必填清单、万能语义节点或全局证明服务。

同类型、同样例、同结果集合、相同分布、相同开放环境保证不是互相替代的证据。当前有限结构主面和直接原生供给都继续合法；本篇改变的是其保证接纳条件，而非要求产品作者写低层算法或另学文本语言。

## 1. 先固定性质，而不是先选一个统一的“等价”

一个Claim由原独立要求取得：主体与准确版本、输入/环境域、公开观察、失败/进展、量词、概率与允许误差、可参与的外部上下文。所需信息按实际Claim携带；普通确定纯函数无需统计模型、攻击者或永久台账。只有字段名称，没有该性质在绑定语义中的解释，仍然是缺解释。

| 性质的实际范围 | 所需保持关系 | 不能代替它的检查 |
|---|---|---|
| 单次确定计算 | 在准确输入和错误/作用域中保持结果与所要求的终止行为 | 只比较类型或少数样例 |
| 对每条轨迹的安全或活性要求 | 将目标轨迹按合格观察关系对应到允许的源轨迹，并保留终止、完整轨迹和调度前提 | 只比较有限前缀，或者无条件删掉源允许的进展 |
| 多次运行间的隐私与非干扰 | 比较低等价输入下的允许观察关系；有概率时使用对应分布语义 | 分别证明每次输出属于同一个允许集合 |
| 随机分布、相关性与估计性质 | 联合分布、样本逻辑身份、随机源/调度模型和误差关系符合要求 | 支撑集相同、每个边际相同或同一个固定seed通过 |
| 开放组件安全 | 对被允许的链接方、宿主与攻击者上下文仍保持该性质，或以真实边界限制上下文 | 闭合测试程序通过、接口同形、供应者自报安全 |
| 时延、资源与物理观察 | 实际成本模型及上下界、时钟、环境和资源合同成立 | 不包含时间/内存的功能保持定理 |
| 编辑与调试连续性 | 准确来源、可定位范围、目标变化到作者变化的合法关系 | 目标行为保持或source map文件存在 |

该表不是封闭分类。新性质可能组合多种关系；不能因为当前后端只会检查第一行，就把其他要求降成第一行。保留原[精确与近似方向](../运行/验收/方法与独立证据.md#证明结果的方向与组合)：过近似和欠近似须作用于本次性质的正确对象，不能把针对单轨迹坏状态的集合证明直接用于所有多轨迹性质。

## 2. 减少允许行为仍可能破坏非干扰

令秘密输入h属于{0,1}，公开观察为一个比特。源模型P对每个h都允许输出{0,1}；此处不指定概率，也不把秘密作为公开输入。该模型满足有限可能性非干扰：低等价输入得到相同的公开可能结果集合。

目标Q采用`output=h`，于是Q(0)={0}、Q(1)={1}。对每个固定h都有Q(h)⊆P(h)，所有输入均可接纳、正常结束且使用相同有限资源；但看到输出就能区分h。单轨迹细化与输入、进展、资源保持仍不足以证明所求非干扰。

这是一个有限关系反例，不是声称真实SEC已经生成过该泄漏程序，也不是所有形式的非干扰都采用集合相等。若原任务只要求返回0或1而没有跨秘密关系，Q是否允许由其真实输入和效果合同决定；不能反向为该普通任务强加保密要求。若已要求非干扰，条件实现的守卫、方法选择、缓存命中、异常、日志和共享资源行为都属于需要核对的相交观察。

**可行正向方案。** 在这个可能性模型里，总是公开0或总是公开1都保持相同的可能集合，不必保留全部源非确定性。如果要求的是独立且公平的随机输出，常量就不合格，须采用符合概率合同的方法。若需要对所有合法目标上下文提供安全，不能只证明封闭例程，须执行第4节的上下文条件。

因此，“细化选择更小的行为集合”只能在相应性质对该关系具有保持性时用于接纳；不作为全部要求的通用证明规则。选择性限制允许行为与隐藏非法输入、抹去活性仍是另外的错误。

## 3. 支撑集、边际、联合分布和可复现性各有含义

独立公平比特A、B的联合分布在00、01、10、11上各为1/4。为了缓存或减少随机调用而改为只取一个公平比特R、返回(R,R)，两个边际仍各为1/2，但P(A=B)从1/2变成1；支撑集被收窄且关联性改变。另一个实现即使保留{0,1}支撑集，将一次输出的概率从1/2改为3/4，也不保持原分布。

编译器须从原数值/随机合同取得：哪些随机选择在定义中可被实现者确定，哪些属于有概率分布的输入，样本之间需要何种独立性或耦合，调度器是否能依赖秘密或未来随机选择。不能把非确定分支、概率分支、设计期择一、未来环境输入和同一随机键的重复解释混为一项。

具体方法可以采用固定逻辑样本到随机源的合格映射、保留概率语义的变换或相交分布证明。仅要求可复现序列时不得多宣称统计独立；仅要求分布性质时不强迫所有目标产生相同逐项序列。近似允许量、距离和累计条件来自原要求；没有误差预算时不自动添加。

随机结果如果已经以固定键、输入和方法构成一个纯值，可以按该含义缓存。新抽样请求不是相同纯值请求，不因调用签名相同而共用一个结果。边界见[数值与随机](../领域/计算基础/计算结构与算法.md)，统计证据取得见[探索与确认](../运行/验收/覆盖与收益判据.md#adaptive-confirmation)。

## 4. 观察映射与链接环境不能由实现者自行缩小

同一目标轨迹`(结果, 时间, 日志)`投影成`结果`后可能相同，但只支持忽略时间与日志的观察合同。若原要求包含常时间或禁止泄漏，供应者不能通过选择该投影把差异消去。观察关系由独立要求和合格域方法固定；代码生成者可以提出映射，不能自行接受它以解除原义务。

对不同源/目标字母表，记录准确关系及其方向、定义域和具体化前提。类型名相同、存在一条来源边、两个局部映射分别声称可用，不足以完成复合；中间解释和观察必须相容。未知高层效果保留为未知，不因底层日志里没有相应事件就证明不存在。

**闭合与开放输出分开。** 一个库被独立测试时不发生的重入、别名修改、反射、直接内存读取、动态加载或非标准ABI调用，在目标上下文中可能发生。保证至少选择一条真实路线：

1. 交付已固定并核验的闭合总成，保证限定该组合；
2. 公开精确宿主进口与允许上下文条件，由实际消费者提供，形成条件保证；
3. 生成或复用真实封装、隔离与边界检查，使不满足条件的交互无法绕过；
4. 使用适用于该上下文类及性质的稳健保持依据。

这些路线可以组合；不要求所有纯库都证明对任意恶意机器码的全抽象。TS类型品牌、私有构造器或Wasm名称本身不构成真实隔离，隔离也未必消除共享处理器时序侧信道。新增插件、共享内存、设备映射和调试权限改变相交上下文，不能沿用只针对旧闭合实例的保证。

**无定义行为不扩大原要求。** 原生语言只在明确定义的执行范围提供保证时，实际调用必须建立该前提。把存在未定义行为的源模型解释成允许一切，虽能令任意输出“被允许”，却不满足独立精确整数、资源或安全要求。可以选择有范围保护和全域后备的原实现方法，或准确限制相应用途；不能为了接入原生库暗改产品输入域。

CompCert手册明确区分其定理的具体阶段和观察，且其相关观察不包括时间与内存消耗；这说明成熟编译正确性成果也需要按实际定理范围消费，而非削弱其已经取得的正确性。参见[原始资料](../依据/来源/语言编译与目标工具.md#property-preservation-sources)。

## 5. 接入原选择、降低和接纳的规则

本节是原R3、C3—C4、H4及T4—T6的共同消费条件，不是新公开流水线。

**取得。** 从实际Claim引用取得性质、观察、主体、域和上下文。相关信息已在准确规则中时直接解析，不要求普通作者填写“hyperproperty”标签；缺少含义时返回该Claim的缺解释，不按未知即普通函数处理。

**匹配。** 方法的保持依据说明支持的性质类、量词与输入/环境前提、源/目标关系、假设、证据强度及残余范围。标签只是索引，资格来自引用的真实内容。可用已有成熟方法与适用信任政策，不要求重证全部上游。

**形成候选。** 结构、目标与隔离条件成立的验证候选，可以先生成待测对象；尚未证明的安全/分布命题继续保留。验证用途不授予生产资格，也不允许用其不安全输出影响真实用户。

**复合。** 只有性质所需的源、目标和中间解释相容、观察映射可组合、各前提在同一环境成立，才串接依据。单轨迹后端不能自动转移上游的非干扰；分布边界通过后也不代替宿主的时间条件。共同Claim跨多个部件时沿原联合方法检查，而不按个别通过数打分。

**发布。** `LoweringReceipt.preservedInvariantRefs`只列实际被对应依据保持的Claim；`proofOrEvidenceRefs`固定所用关系/规则、公式或模型、假设和覆盖；未消解的Claim留在原残余义务。无需增加第二张当前证据表或修改客户端输入；旧回执没有取得这种依据时可以保全，但不能升级成新保证。

**继续。** 可选优化不满足某个强Claim时，保留合格旧方法或另选方法；独立弱保证根可完成，但共同任务必须明确未满足的强条件。合同强化、外部上下文、观察、随机源或信任基础改变后，按真实读集重核，旧执行仍保留原身份。

| 原职责的拟定接合 | 输入与工作 | 结果 |
|---|---|---|
| `semantics/boundary-view.ts` | 从现有Claim/规则解析观察与量词上下文 | 原BoundaryView中的准确义务投影，不发明事实 |
| `compiler/resolve-use.ts` | 对所求Claim匹配实际保持关系和残余条件 | 原UseBinding/Needs/Unsupported/Conflict |
| `compiler/pass-manager.ts::acceptPass` | 私有目标与原绑定；核复合映射及性质所需证据 | 原PassResult及LoweringReceipt，不自签通过 |
| `assurance/claim-evidence.ts` | 核模型、推理与解释是否被允许信任 | 适用支持、条件保证、反例或未知 |
| `compiler/compose-target.ts` | 真实链接环境、进口、边界和成员 | 分根资格；公共闭包或条件进口不丢 |

## 6. 更小路径与不能被省掉的成本

确定纯函数、已有准确数值合同、相同受信目标和合格方法，可以直接沿原类型/范围和生成路径工作，不启用跨运行分析。隐私方法缺失只影响请求该保证的输出；需求本身不能被删除。强要求与普通功能可以分别取得准确部分结果。

模型关系、隔离、独立随机、证据核验和上下文检查具有真实成本。采用某种更快内核前仍计适配、复制、资格及全部可达后备。用更弱观察证明“等价”可能更容易，但只有原要求本来允许时才是有效简化。

具体反例和正例见[保证边界案例](../运行/验收/作者与组合案例.md#foundation-preservation-cases)。本篇设计了匹配与接纳责任；没有运行安全编译器、概率验证器或真实插件，不能据此宣称所有性质自动可判定或所有宿主已经安全。
