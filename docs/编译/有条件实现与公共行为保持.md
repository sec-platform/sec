# 有条件实现与公共行为保持

本篇拥有“一个实现只在部分输入或环境下合格，怎样仍为原完整需求提供正确方法”的编译合同。它接入[实现选择](实现选择与设计搜索.md)、既有MethodSpec/UseBinding和P0—P7，不增加作者语言、万能求解器、运行期全局方法搜索或新的作者文件。实际调用与资源寿命由[跨实现边界](../运行/跨实现调用与数据寿命.md)拥有；原成本优先级、证据和恢复规则继续有效。

## 1. 特化条件不是缩小作者要求

设本次接受的合法输入域为D，运行前提为E。F是在子域上可用的高性能方法，G是在其余范围内符合相同公开合同的方法。守卫g读取本次固定、允许观察的输入和真实能力，在有限预算内作明确判定。

采用条件组合时必须成立：

```text
对所有 x ∈ D：
  g(x) = true  ⇒ F 在当前环境和本次输入上满足接受合同
  g(x) = false ⇒ G 在当前环境和本次输入上满足接受合同
```

两条分支共同覆盖D，且同一实际调用采用已固定的分派计划。运行前提变化失去资格时返回真实缺项/故障或采用计划中已获准的较弱能力分支；不能临时修改作者D，也不能从新发现的同名库选一个实现。

守卫本身还要符合原观察合同。无外部I/O不等于任意求值都不可观察：错误、取消、预算和处理秘密输入产生的时间/内存轨迹可能影响要求。要求常时间或非干扰的任务，只能采用已证明不泄露敏感区别的守卫与分支，或者固定一个统一的合格方法，不能以“结果一样”代签。

一份单独F的证据仍只支持其原子域。合成方法的保证还需要g、G、适配、调用顺序、依赖成员和共同状态的证据。不是把不同样例分别选择不同程序后，宣称存在一个共同实现；实际分派本身就是待保持的程序部分。

## 2. 四种条件分别处理

| 条件 | 决定时点和来源 | 完成方式 |
|---|---|---|
| 已固定目标属性 | 目标画像、实际ABI、编译特性 | 编译时选择并保留准确依赖，可去掉确定不可达分支 |
| 安装/启动能力 | 已取得的模块、依赖、真实CPU/设备能力及当前许可 | 原运行准备固定能力结果；装载是获准作用，不放进纯守卫 |
| 本次值的有限性质 | 真实已捕获值的范围、shape、长度、排序或布局性质 | 按一次求值和预算检查，进入固定F或G |
| 有作用之后才可得的结果 | 调用响应、部分修改、设备结果或远端观察 | 不是前置守卫；按原失败/恢复处理，不能盲重试另一分支 |

条件未知不能当假值，除非计划明确把“无需该能力也合格”的替代作为不同的正常条件，并且无需冒称未知事实。某CPU扩展确定不可用可走通用实现；未能安全查明装载对象身份，不应把它当作可运行的F。需求明确固定“只用F”时，不能自动改选G。

普通使用者无需填写g。实现供给可带真实适用域，编译器在所选方法和已允许组合中构造其守卫；生成器不能从函数名字猜范围或复制一份作者要求后擅自放宽。

## 3. H0—H8：构造、选择和发射

**H0 固定接受对象。** 取得准确主体、输入域、正常/错误/进展/资源与公开同步合同，保留原需求来源。多个输出根可以共用行为而有不同消费边界，不先强迫一个方法覆盖全部形式。

**H1 分离行为前提与实现前提。** 业务上允许任意精确整数，不意味着F只能接收i64就可把产品输入域改成i64。F的长度、CPU、对齐、线程和资源限制是适用前提；除非作者明确接受，不成为新的业务错误。

**H2 取得固定方法和适配。** 可以直接复用已合格M，也可以生成在隔离验证用途下的候选。候选能被降低以便检查，不等于生产调用资格已签发；需要真实测试才取得资格时，不要求“先有生产合格证据才能生成被测候选”，避免循环前置。测试运行走已有准入，合格结论只对真实输入/环境成立。 验证候选仍须满足其读取、类型、目标生成及隔离运行前提；其有限资格沿原目的和证据记录保存。客户端自填“验证”不解除权限，生产消费点也不能接受仅有验证用途资格的候选。

**H3 形成守卫与覆盖。** g必须在原合法域可定义，并具有所需终止/成本/披露条件。优先使用既有类型、范围与不可变事实消去冗余守卫；没有这些依据就执行准确检查。F不可用的其余输入由G覆盖；无G时保留缺方法，不输出伪完整产品。复杂条件求解耗尽预算与逻辑反证分开。

**H4 保持一次求值与状态。** 原callee和实参按原次序取得一次，再把同一捕获值交给g与所选分支。getter、迭代器推进、随机数、状态读取和资源消耗不能执行两次。不能在g中为了测速度先调用F；旧输入已转移或修改后，不能用原地址走G。guard新增的分配和检查计入原预算，不暗藏新的公开业务错误。

**H5 比较完整成本。** 包含守卫、编码/复制、调度、F/G分支、峰值存活及结算成本；按原高优先级、未知和Pareto规则比较。不存在性能证据时保留功能合格而成本未定的选择。小输入直接G可能优于原生调用；已排序/已检查事实可以被准确复用，但不能按旧版本位置推断当前值性质。

**H6 封存同一选择。** 守卫、分支及其依赖属于原UseBinding/方法计划内部结果，不增加`dispatch.json`等作者台账。所需支持按[组合前提](组合前提与进展闭合.md)绑定范围、条件和依据，不能用F与G互相自报填满彼此前提；验证候选与生产用途资格分别保留。`resolveUse`结果区分合格、Needs、冲突和不支持；生产计划包含实际会使用的方法身份和版本。变化只使真实消费者失效。

**H7 按目标发射。** `lowerBoundUse`发射一个准确分支与必要适配。`composeTarget`纳入所有运行时可达分支需要的代码、库、资源及许可；只有条件已在固定构建输入中确定，才能删除相应分支成员。不能只打包benchmark走到的一支。保留合法公共宿主进口，不强迫纯库带进程或整个SEC控制面。

**H8 检查并结算。** 评价守卫边界、同义结果、错误次序、资源、缺分支和环境变化。候选检查失败可回到已有选择；调用已经开始后则依[恢复](../运行/持久化提交与恢复.md#attempt-finality-and-retry)。纯孤立计算在输入仍有效、旧责任受保护且预算允许时可以重算；外部效果未知不能借分支更名重发。

## 4. 完整例：精确区间需求与i64内核

复用[成品形态](../../examples/成品形态/README.md)的Normalize需求。D仍为有限列表、端点是精确整数；最早反向区间按原输入位置报错，空区间忽略。MergeTouching和KeepTouching分别遵守原连通分量合同；输入不被修改，业务错误与计算/资源故障分开。

G是符合该合同的TS bigint排序扫描方法；F是允许的原生有符号64位内核。这里给出方法设计，不宣称已安装、已发布或经生产测试。完整的供给资格仍需实际代码、适配和证据。

候选守卫的正向条件包括：每个被传递端点满足`−2^63 ≤ endpoint ≤ 2^63−1`；列表长度、传递布局、输出与临时容量可用目标索引表示；真实同步或异步调用方式符合所选根；模块、ABI和线程等实际前提已在运行准备阶段成立。比对端点时使用精确整数，不先转成Number或i64再检查。

任一合法端点超范围时直接走G，不把它当成Normalize的输入错误。零长度输入按原正常空结果；反向输入仍按原位置处理，不能由于F先排序而报另一个错误。排序器比较使用关系比较或已证明不溢出的方式，不能计算`left.start - right.start`并放入i64，因两个合法端点之差仍可能溢出。

本例输出每个端点来自输入，区间数不超过非空输入数，因此可以推导输出布局上界；具体字节数还要计编码、原输入、临时缓冲、索引和二者并存的峰值。没有预算就返回原资源结果，不静默丢区间、截短输入或把KeepTouching改成MergeTouching。

合法替代包括：直接G；已有平台内建等价实现；同步窄原生F加G；具有合格取消/结算合同的异步F加G。无证据表明优化有收益时，不为“高性能”标签增加编码和跨边界开销。

### 同一行为，不同交付根可以选择不同方法

| 交付根 | 合格实现路线 | 被排除的偷换 |
|---|---|---|
| 同步Library | G或同步F/G；需要的内部检查在同步公开合同内完成 | 返回Promise；在必须依赖当前事件循环的回调上同步阻塞 |
| 异步Worker或Plugin | 固定消息/异步接口，工作器或F/G组合；关闭覆盖原已接受工作 | 后台仍访问输入却立即close成功；重复ID错误结算原请求 |
| Panel | 保留输入代与过期显示资格；在声明输入预算内使用合格分块/工作器 | 大计算占满主线程却声称纯就不会卡；为提速改用户输入 |
| 规格包 | 交付行为和公开合同即可，目标实现仍明确未绑定 | 空实现函数冒充可运行库 |

共享不可变方法代码不等于共用会话、输入内存或可变状态。六个根不强求相同物理布局。一个优化分支未合格，只影响其真实依赖根；纯库的合格G不因为GPU驱动不可用而失败，除非原任务确实要求那个驱动或共同发行。

## 5. 错误、隐藏效果和降级

预校验对原始业务非法输入的错误含义仍由Normalize合同决定；守卫无法取得事实、预算耗尽和适配器缺陷属于自己的准确故障。不得把所有异常`catch`为g=false，再悄悄走G，从而隐藏F已经开始的修改、费用或资源泄漏。

F若接受可变借用并写了一部分，回退前必须有允许的恢复或独立原输入；G不能读取半修改数组。即使结果是纯值，F可能仍持有输入或后来回调；只有值可重算不意味着旧访问已经关闭。原责任沿[调用寿命](../运行/跨实现调用与数据寿命.md#call-lifetime)继续持有，重算成本也进入预算。

默认不双执行有外部作用的候选。影子比较只适用于真实隔离、输入可合法复制、没有不可重复作用且成本被允许的范围。若常时间、密钥保护或硬截止要求不允许G，F不合格时拒绝该范围，而非“降级”到违反硬要求的通用实现。

## 6. 变更、来源和生成代码

改变F的实现而保持合同：保留作者JSON；更新F及适配、资格依据、真实消费根。改变g会影响哪些输入走哪支，必须检查与成本及非功能观察相交的要求。改变作者需求：重新核F/G适用域，不能靠旧同名方法跳过。

降低的优化遍可能不改变CFG却改变范围或别名。其preserved声明只有在[真实分析保持](内核/变换接纳与分析保持.md)成立时才可复用；旧范围失效后必须重新检查g的覆盖和可删除分支，不能由相同节点ID继续删除守卫。

输出表示和来源映射应能区分原需求、生成的守卫、F/G分支及本次选择依据；不要求向作者展开全部内部程序。人工修改生成的g是实现策略候选，需要回到对应供给或显式接管，不能改掉产品D来让旧实现继续通过。

计划派生不导致普通源码每次改字都改工程锁。真实方法/目标选择变更才更新相交绑定。日后信任或权限变化会使后续调用失去资格，不倒改旧证据说它从未存在；旧运行及未结算资源按自己的版本处理。

## 7. 实施责任与可检查边界

既有`semantics/native-contract.ts`提供准确适用前提；`compiler/resolve-use.ts`构造并联合检查H0—H6；`compiler/lower-bound-use.ts`消费固定分派而不再挑方法；`compiler/compose-target.ts`汇合所有真实可达成员；`assurance/method-qualification.ts`区分适配、分支、覆盖和性能依据。实际装载与调用由execution和adapters完成，不在编译器建立全局动态路由器。

书面案例见[跨实现验收](../运行/验收/实现与运行案例.md#native-boundary-cases)；完整连续变化见[局部实现替换](../../examples/连续开发/局部实现替换与成品接合.md)。有限整数边界复算与模型枚举只能验证各自模型，不能证明未来原生核、依赖库和全部平台已经满足这些合同。


## 9. 条件实现的跨运行与开放环境保证

H4不仅核每次分支输出是否属于源结果。秘密相关的守卫、缓存、异常、不同分支的共享预算，以及分支采用不同随机源，可能在逐次结果合法时破坏非干扰或联合分布。按[性质保持](性质保持与开放环境.md)取得整个条件实现的对应依据，不能用每支各自有限测试替代。

已有统一合格G仍是正常路线；没有强保持依据就不采用该优化，而不是令作者删除强要求。H5的性能评价按[探索与确认](../运行/验收/覆盖与收益判据.md#adaptive-confirmation)解释，搜过多个候选的偶然最小值不自动构成已确认优势。新宿主上下文、共享环境或数据暴露改变时重核相交资格，不因源文件未动沿用旧结论。
