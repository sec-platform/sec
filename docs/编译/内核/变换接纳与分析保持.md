# 变换接纳与分析保持

本篇细化[PassDefinition及遍调度](遍管理与插件.md)的输入隔离、失败处置、结果接纳和分析复用。继续使用原PassInput、PassResult、IR generation、ActionKey、UseBinding及保证记录，不新增公共工具、作者配置或编译后端。意图JSON、原生实现与已选目标保持不变；下面是编译器和供给实现者承担的责任。

## 1. 绑定、可检查和可生产使用不是同一资格

一份候选可以已经确定具体方法、输入、输出种类和目标，具备在隔离条件下生成及检查的资格，却还没有完成某个生产消费者要求的语义保持证据。UseBinding固定“这次到底选择什么及其依据/剩余条件”，不自行表示所有可能用途均获批准。

| 消费目的 | 最低进入条件 | 不能因此取得的资格 |
|---|---|---|
| 保存/阅读候选 | 有界可保存内容、准确来源与访问；非法草稿标明缺额 | 目标执行、类型正确或保持证明 |
| 运行相交静态检查 | 所选检查器能够解释其输入，满足检查自身前提 | 生产使用和任意后端支持 |
| 生成被测产物 | 基础绑定、所需结构/类型、目标及隔离运行前提成立；未证明命题明确保留 | 候选没有失败就自动发布；客户端自称测试就取得宿主权限 |
| 生产或强保证发射 | 该消费者要求的全部资格及接受政策实际满足 | 永久运行许可、未来环境不变或任意更强性质 |

实际检查能够复用时无需再执行一次。普通开发要求并不自动升级为全程序形式证明；明确采用的检查等级可以包含分析、测试和有范围接受，但每种依据只支持其真实结论。不允许通过改用途字符串把违反已要求安全条件的候选变为可运行对象。

## 2. 变换的可写范围先于执行确定

分析持有固定输入和只读查询接口；不能从分析回调修改IR。转换取得一个私有编辑范围，返回新的generation或准确失败；投影不取得作者写权。

所谓私有范围必须包含变换实际能够改变的关系，不仅是一个语法子树。修改符号、SSA使用链、父容器、共享类型表或跨模块出口时，相交关系也要被准确拥有或通过指定组合者处理。上下文可以按需只读引用，不能把只读输入中的可变宿主对象偷偷交给Pass。

允许三条实施路线：

- 不可变结构共享，创建变更部分和新的父关系，未变部分按真实不可变性共享。
- 对成熟可变IR进行区域克隆或私有工作器变换；克隆边界的外部引用固定，只能在明确能力内读取和写入。
- 受信流水线在证明没有其他读者/缓存对象指针会观察时转移私有片段所有权；同时保留原固定内容或能够从固定输入准确重建的恢复路线。

不要求每个Pass深拷贝全工程。反过来，零拷贝和“只有一个变量引用”也不能证明无其他别名。只有候选中被改变的某个分片有唯一拥有权，不意味着它关联的共享符号索引也可以原地改。跨不可信原生Pass必须使用真实隔离，不以TypeScript品牌代替沙箱。

需要读文件、启动工具或探测设备时，按原ContentNeed/ToolResultNeed取得结果后形成新准备输入；纯Pass不能将I/O藏在run里。需要运行生成器的语义与需要变换已生成的IR分别处理。

## 3. 在原Pass运行中接纳一个结果

下述T0—T7是原工作项运行与发布的内部细化，不增加用户必须执行的八个动作。

**T0 固定目标和目的。** 确定输入generation、所有片段与解释、Pass实现和策略、输出阶段、预期改变的范围、预算及实际用途。阶段允许的中间形状由该阶段合同决定，不要求临时IR在每个内部语句后满足最终目标规范。

**T1 建立隔离编辑与资源拥有。** 取得上一节的私有写域，登记真实借用和可撤销的分析视图，准备输出/收尾预算。输入仍被其他任务使用时不得修改；区域不足则扩大到真实自足范围、选择串行/克隆方式或准确停止，不绕过边界。

**T2 执行并取得候选。** 按固定策略运行，动态产生的新依赖按原协议取得或报告。变换期间允许内部暂态；成功输出必须符合声明的阶段形状。取消、超预算、返回错误、子Pass失败分别保留原因和相交状态；外部作用依原执行协议结算。

**T3 检查准确差额。** 核对原基础、实际写集、身份/引用/符号、来源映射、声明与实际产物。提供者的改动清单是候选输入，不能仅凭它的自报遗漏就认为其他位置没变。受信builder可实际记录写入，外部返回物需要重新解析和比较所需边界。

**T4 独立判断结果层次。** 原阶段验证器核结构/类型/效果与目标合法性；保持旧行为另据真实规则、证明或被接受范围的检验。校验合法IR不证明它与输入等价，签名和成功退出码也不证明相同错误、精度和进展。没有独立验收依据不能把变换生成的期望再当唯一oracle。

**T5 处理分析保持。** 按下一节计算仍适用、可更新和必须失效的分析及其传递依赖。Pass返回的preserved声明不自动授信；未知作用范围用健全保守失效，不全局掩盖为成功NoChange。

**T6 封存并发布。** 完整结果、实际读集、有效分析、来源和该用途资格在同一发布边界成为本工作项结果；发布前取得必要引用，消费者看不到“新IR＋旧不适用分析”的中间组合。任务页面已切换时计算结果仍可按缓存范围保留，但不能越过原显示安装资格。

**T7 收尾与继续。** 释放真正不再使用的私有对象和上下文；返还可归还资源，不释放其他任务共享的输入。允许的后续阶段从已接纳结果开始；失败时按下一节回到原合格基础。状态和依据仅按必要用途保留，不为每遍生成永久历史账本。

## 4. 失败不等于撤销，恢复不能使用半成品

某些成熟变换允许在修改IR后失败，失败后的IR甚至不再合法。MLIR的Pass文档明确说明此种情况，并停止该管线的后续遍。本设计因此不假设一个返回失败的第三方Pass已经把输入恢复原样。

失败候选不安装到共享结果槽；取消也按同样边界处理。上一合法输入可仍由不可变内容或隔离副本持有，后续采用它继续。只有存在有界并已验证的撤销日志时，才使用逆操作恢复；默认允许丢弃私有结果并从准确基础重建，不能在已部分修改对象上运行“备用优化”后冒称保持。

可选优化失败且原方法仍满足目的时，可以返回原方法结果与准确优化失败说明；任务明确要求新方法、指定优化或原方法不再合格时则不能把退回写成任务完成。随机崩溃后不无限重试相同方法，保留准确失败和预算。旧工作若仍在外部进程或设备里，继续保护其输入及收尾资源；丢弃高层候选不是目标已经终结。

已经发生的安装、网络写入、持久提交不属于这个IR私有恢复承诺。其未知结果沿原意图和实际提供者查回，不能用“编译事务失败”宣布它们被撤销。变换触发的声明发现和配置读取也仍属于真实依赖。

## 5. 分析保持是有依赖的证明，不是一个全局布尔值

每项分析按被观察的IR基础、范围、解释、方法及实际依赖定位。新generation不要求所有事实全部丢弃，但沿用旧分析要同时满足含义仍成立、引用仍合法和资格适用于当前消费者。

| 分析/依据 | 可以保持的典型条件 | 不应采用的推断 |
|---|---|---|
| 类型形状 | 相交定义/表示未变，或通过合格局部更新重核 | 返回类型相同就推断效果、异常和生命周期相同 |
| 控制流、支配关系 | 实际相关边/节点和模型不变，或经适用更新器处理 | CFG不变就保留值域、别名、成本或常时间 |
| 值域/常量 | 依赖的计算、条件和输入域保持；或重算新范围 | literal从0改为16但块名/节点ID不变便保留旧范围 |
| 别名与资源 | 真实位置、分配身份、捕获和寿命关系保持 | 复制相同字节便继承对象/分配身份 |
| 效果与数值保证 | 所用规则、实现、错误/舍入及观察域仍相容 | 纯标签或函数名相同就可以重排 |
| 目标/方法选择 | 相交范围、能力、约束和选择依据仍适用 | 新输入落出专用域仍调用原窄内核 |
| 性能/排序结论 | 原比较中的工作负载、边界成本和方法未受影响 | 代码合法、结果一样就保持“更快”或“最优” |
| 真实测试、安装与回执 | 按各自证据的原主体保存，需要转用时另外证明适用 | 复制旧记录或改标签就生成新的测试、安装事实 |

分析B依赖A时，A失效必须重核B。缓存删除IR对象后不能保留以裸地址为键的分析；内存复用不让旧结果获得新对象身份。保留引用时使用仍受保护的固定对象或有根据的新旧对应。只保留一个Boolean结果而遗失它的前提、输入和返回指针，也不构成有效复用。

保守上界和精确值的资格不同。旧范围仍包含全部新结果时，可以作为保守界继续使用，但不能贴成新精确范围，也不能继续作只有精确值才能成立的成本比较或分派裁剪。旧分析对象含旧IR指针时，即使命题可迁移，也须建立新合法视图或明确保留旧基础，不能直接返回悬空引用。

**默认策略：** 对实际受影响且无法证明保持的分析失效，按需重算；有明确、受信保持规则才复用或更新。未受影响的函数、其他输出根和解析结果不做无理由全局重算。all-preserved只在真实无语义/结构变化或完整保持依据成立时接受，不能因为插件自报而保留全部缓存。

## 6. 一个CFG不变但结果危险的具体反例

输入x属于0至255。原值y等于x，已得到`y∈[0,255]`。后续生成变化把它变为`y=x+16`，函数和控制流边保持不变。

此时新范围是`[16,271]`。若仍使用旧分析，后续可能删除有界编码检查或把全部输入交给u8方法，造成截断或错结果。合法选择包括重新计算范围；在原需求允许的空间中用已固定守卫与通用方法覆盖全部输入；或报告有界目标不支持。原任务没有要求饱和时，不自动插入Clamp，也不把入口收窄到0至239。

这个变化可以是作者升级，也可以是已固定参数的实例化；它不是一个可以宣称保持旧行为的优化。若某个优化Pass声称等价却做出此修改，T4应按其真实保持依据判定失败。即使范围更新正确，也不修复它“自称等价”的错误。这个区分避免用缓存正确掩盖转换本身改义。

## 7. 实施接口与有限可信边界

| 原职责的拟定实现位置 | 工作 | 强制边界 |
|---|---|---|
| `compiler/pass-manager.ts` | `preparePass / runPass / acceptPass / discardPass`串起T0—T7 | 单工作项的私有结果发布，不向分析注入写能力 |
| `semantics/ir-builder.ts` | 固定引用、区域拥有、差额和阶段验证 | 有效身份、可见性、结构与真实改动记录；不是不可信代码沙箱 |
| `compiler/analysis-manager.ts` | `classifyPreservation / invalidateDependents / acquireAnalysis` | 真实读集和保持规则；删除键退休；无证据则按需重算 |
| `assurance/transform-check.ts` | 评价差额、规则/证明、有限测试与接受范围 | 检查器与被测变换不靠互相自报完成晋级 |
| `adapters/compiler/` | 成熟可变IR、原工具链和外部进程的隔离输入输出 | 具体输入、失败IR、编解码和终结合同必须已知 |
| 原`application/execution` | 取得外部检查与后续运行准入 | 验证目的不提供新权限，取消仍保护在途资源 |

这些是函数责任设计，不是已存在产品源文件的清单。纯串行实现可以将相交责任合并为普通函数，直接解析原生源码、调用成熟工具并检查结果；不必先实现完整增量证明系统。不同过程的合同使用原Frame/Effect/Permission边界，不另造全局transaction mode。

## 8. 依据与适用边界

[LLVM18.1.1 New Pass Manager](https://releases.llvm.org/18.1.1/docs/NewPassManager.html)提供分析保留、传递失效和删除对象缓存处理的具体参照；[MLIR Pass Management](https://mlir.llvm.org/docs/PassManagement/)分别说明分析不修改IR、线程/区域限制及失败后停止管线。这些材料不是要求以LLVM或MLIR实现SEC，也不证明任意自报的保持集合正确。引用范围和采用限制集中在[来源](../../依据/来源/语言编译与目标工具.md#composition-pass-sources)。

设计验收包括原输入被共享时的私有转换、失败半成品不发布、CFG保持而范围失效、传递依赖失效、删除地址重用、候选生成但不能生产采用、正常NoChange和可选优化失败的成功继续。实际工具与平台符合性须据真实实现核验，不能把Markdown中的T0—T7算作产品测试。


## 9. T4—T6按性质接纳，不把更确定等同于更正确

私有结果避免污染原输入，但不证明该结果保持了全部要求。T4取得[性质保持合同](../性质保持与开放环境.md#property-receipt-consumption)；T5区分单次观察、跨运行关系、概率、开放链接和成本；T6仅发布实际被相交依据支持的结果。减少非确定性、合并随机调用、加入缓存或更换秘密相关分派都须按其真实性质检查。

回执里的preserved集合和分析标记由合格的接纳路径解释，不接受工具自写true、证书包含未验证公理而仍自称完整、或改变独立Oracle后恢复绿色。证据入口见[解释与证据](../../运行/保证/解释与证据接纳.md#evidence-acceptance-steps)。旧合格方法可在任务允许时继续，不在失败私有结果上改标签发射。
