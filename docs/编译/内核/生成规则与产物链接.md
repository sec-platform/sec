## 状态聚合方言与目标工程生成

本节定义所选事务应用合同的目标生成接合。作者声明、命中政策和业务作用由[事务应用与交付](../../领域/状态关系与流/事务与交付.md)拥有；本节只决定怎样将这些已选含义落实为代码、存储约束和接口。未采用持久业务的程序不进入这条生成路径。

### 何时采用及正常生成

实际任务需要持久状态、版本保护和跨制品一致性时，先固定类型、状态、转换、不变量、错误、授权和提交范围；所选画像允许时生成状态处理、存储与接口。没有审计或可靠通知要求，就不强制生成审计/Outbox；纯计算也不需要证明一次事务应用才能完成工程出口。

一个选定Python/SQLite与TS客户端的目标可生成service.py的业务处理、runtime.py的实际提交能力、schema.sql、api.py、client.ts、openapi.json和必要说明。它们是有真实消费者时的可选布局，不是所有程序的固定文件表。每个文件有来源、拥有者和内容身份；验证义务说明要检查什么，不能凭一个verification-obligations.json称已经通过。

模型合法性先检查：初始/目标状态真实存在、字段与操作名称唯一、值域有序、引用及未知成立范围清楚。随后按照现行合同连接真实提供者、生成相交源码与资源；只有请求实际构建、采用或运行时才执行相应操作。未绑定义务可以留在合法设计中，所选输出真正依赖它时才限制该输出的完整性。

### 值域、写入范围与重试保持

目标协议若使用JSON数值或宿主定宽表示，先证明实际值域可精确表示；例如非负安全整数范围仅是该传输画像的限制，不定义中立Int。范围不足时采用合格编码或报告该目标缺项；版本耗尽不能回绕。文本解释指定标量与编码规则，字段标识和业务文本分别检查，不能将文本拼成任意SQL、路由或执行代码。

写入集合来自当前operation明确的变更及其生成规则。只声明状态改变时，其余载荷保持；声明金额或算法参数改变时，检查相交不变量并更新对应字段。稀疏修改不隐含整行覆盖，新增字段也不被旧完整记录默认值抹除。

同键重试返回原确定结果，当前披露权限和新执行权限分开。already-target的return-current与reject是公开行为选择；return-current仍核对声明的前提，必要时保存逻辑结果，但不伪造新的状态改变、审计或事件。请求身份、行版本和语言修订不混用。

### 存储、初始化与迁移

可以采用当前状态表加按需记录，而不建立全局事件溯源。主键、状态、范围和共同约束由真实事务/数据库与应用协议承担；只将载荷存成JSON不能取得全部索引或查询能力。更强查询和多根事务需要相交设计，不通过串联独立操作宣称共同原子。

只有显式初始化任务、合格目标与当前权限满足时，才从空目标建立模式；连接库或读取声明不默认创建数据库。既有库的语义摘要与当前目标不兼容时返回MigrationRequired，选择明确迁移；相同摘要允许按原合同使用，但不自动证明内容无漂移。说明文字变化可不改变运行含义，解释器、字段值域和错误变化则应进入相交身份。

迁移先处理旧状态、数据范围、角色、事件、幂等保留与在途交付，真实旧写者也参与保证范围。管理端口、seed和授权设置只在对应权限内使用，不因不暴露公共HTTP路由就具有系统安全隔离。持有数据库文件的其他进程可能绕过应用协议，需真实宿主保护或限定保证。

### 保持、失败与退出

源码、API和客户端能生成，不证明网络监听、认证、TLS、通知或部署已经满足。科研任务的状态转换正确，也不证明其中科学算法正确。目标运行可以脱离SEC控制面，但真实依赖和授权仍存在。

当字段扩展侵入事务内核、当前表示无法保持任务或目标能力不够时，修改相应语义/Provider而非增加工单专用中央分支。需要任意计算时直接使用计算作者能力；要求更强消息保证而端点不支持时给准确缺项。退出和恢复沿真实操作、原内容与目标前后像；废弃编码或删除工具不能取消仍未结算的作用责任。


## 生成规则协议与多制品链接

### 职责与输入

本合同把已冻结且足以生成所选输出的作者模型转换成相关联的源码、模式、接口、依赖和验证义务；未正式采纳的候选也可生成预览。它不决定用户目标，不把候选模型自动采纳，不执行目标程序，也不签发部署权限。与模型存储之间的边界是不可变快照；与写回系统之间的边界是完整制品计划。所有入口继续使用同一模型含义，不要求文本 DSL。

编译输入包含所选输出根、实际模型对象及版本、目标能力画像、精确规则实现、由解析阶段确定的实现绑定（可以自动形成）、请求的保证范围。模型总头只作观察来源；只有真实被规则读取的内容进入规则输入。摘要证明字节身份，不证明调用者有权采纳模型。

### 规则描述符

`GenerationRuleDescriptor` 的责任是声明一个变换可以读取、产生和保证什么：

| 字段 | 含义与检查 |
|---|---|
| ruleIdentity / revision / producerDigest | 稳定规则身份、合同修订和实际执行内容；不能只靠人工版本标签 |
| inputContract | 类型、必需字段、引用、正负依赖、动态输入前沿 |
| applicability | 可执行检查：方言、语言、能力、资源和前置规则 |
| selectionPolicy | 多候选如何选择；没有合法选择时返回歧义，不用加载顺序 |
| outputContract | 制品角色、字节类型、目标路径规则、归属和组关系 |
| preservationContract | 保留哪些行为、数据、效果和错误语义，不把类型相同当等价 |
| executionClass | 纯变换或隔离计算；有进程/文件系统的规则不是偷偷纯化 |
| resourceEnvelope | 输入项、深度、输出字节、计算预算；达到预算返回前沿 |
| diagnostics | 稳定错误码、关联模型节点和可恢复条件 |
| evidenceObligations | 需独立证明的性质、预期测试环境和不能自证的范围 |

规则不自行加载任意 Python/JavaScript 代码。可信解释器、编译器包与工具执行属于选定 Provider 的能力和信任边界。第三方规则只因通过 Schema 不获得宿主进程权限。

### 候选选择与链接顺序

1. 验证快照身份和输入作用域。
2. 推导所选输出所需的语义义务，保留缺失、冲突和不支持区别。
3. 只枚举明确目录中的规则；先按硬能力过滤，再按已采用策略选择。
4. 固定每个义务的规则与输入闭包；显式规则不能被后端悄悄替换。
5. 建立数据依赖和发布组关系。纯计算依赖必须可调度；源码的递归类型不能被错当任务循环。
6. 执行有界纯计算或消费隔离执行回执，产生候选字节。
7. 解析制品引用、路径冲突、依赖版本和目标合法性。
8. 生成制品集合、来源映射、缺失义务和保证需求，随后交给变更/发布 owner。

构建序列不自动决定业务副作用序列。一个 API 文件和数据库模式没有同一语义版本时，即使二者单独能编译，组合发布也必须阻断。

### 制品集合

```text
ArtifactSet
  sourceSnapshotRef
  targetProfileRef
  producerBindings
  artifacts[]
    logicalArtifactId
    relativeAddress
    role / mediaType / contentDigest / byteLength
    actionKey / ruleRef / inputSelectors
    ownership / executableDependencies
  publicationGroups[]
  retainedAuthoredRegions[]
  requiredUnbound[]
  assuranceObligations[]
  remainingDeploymentBindings[]
```

同一逻辑制品与物理路径分开。发布前由目标 Host 检查大小写、Unicode、保留名、父子路径、硬链接和符号链接；固定顶层文件示例不覆盖这些检查。任何两个当前 writer 的输出路径冲突均不得通过“最后写入者获胜”解决。

集合摘要绑定成员、内容和组关系。每个制品的动作键绑定其算法和实际输入；集合来源变化可以改变集合摘要，不需要让无关制品动作键变化。该区别不意味着所有传播都必然局部：共享运行库修复与实际共同输入变化仍会扩大闭包。

### 正确复用与代价

起步实现可以采用“每规则输入切片 + 保守规则实现摘要”。只被文档规则读取的描述变化，不影响服务逻辑与数据模式的动作键；若描述参与命名或生成策略，则它也是相应规则输入。规则实现文件变化可以保守失效该规则，但这种文件级依赖不是理论最小闭包。

缓存准入另外检查生成器信任、输入证据、过期策略和当前安全要求。相同键只给出候选复用关系，不替代缓存内容读回，也不替代被撤销规则的风险裁决。更换临时输出目录、进程PID或网络请求ID不改变纯结果。

### 源码、生成、写回与部署的四个状态

`generated` 表示支持范围内的字节和引用已经形成；`build-verified` 表示精确产物在所选工具链中构建通过；`workspace-applied` 表示真实写回已读回；`deployment-authorized` 表示部署所需授权、秘密、环境、验证和恢复均满足。

候选导出模式只允许写入拥有创建权的全新目录，拒绝覆盖已有目录。异常会留下 `.sec-incomplete`，消费者不得把它当完整工程。标记移除之前必须校验成员集与摘要。该导出不是存量工作区原子事务，不声称抗断电目录发布。生产发布继续使用受控内容库与元数据提交协议。

多文件源码能生成，不等于 API 已对外监听；OpenAPI 的安全字段是合同，不是认证实现。生成工程必须列明尚未绑定的认证、通知、部署与耐久性义务。

### 生成测试与独立验收

同一模型可以生成验证义务和夹具，但独立业务预期必须来自被接受的业务合同。规则生成的代码与规则生成的期望同时出错，是共同原因失效。改变生成器中的租户查询条件时，手写跨租户测试应失败；把状态修改与审计拆成两次事务时，进程中止测试应失败。

### 权衡与重新裁决

模板直接拼字符串较轻，但必须有受限输入、转义和目标合法性检查；一开始就生成通用 AST 可能增加实现成本。有限模板后端的字段和状态应来自受限语义，模板内容也要绑定具体 revision 和信任边界。扩展复杂表达式或多语言语法时，字符串模板若不能可靠保持结构，应替换为目标 AST，不扩大字符串自由度。

多制品一次全部重生便于建立 clean 基线；增量只在动作输入确切且能与 clean 差分时启用。共享抽象需有实际重复语义、独立边界或已接受扩展义务；两个示例调用同一运行库只证明可复用路径存在，不能单独证明抽象净收益。

### 验收与证据范围

必要测试包括：重复构建；无意义顺序重排；描述性变化；实际角色或状态变化；缺失义务；输出篡改；额外可执行文件；同路径覆盖；精确快照重建；生成程序脱离编译器；完整/部分/阻塞状态不混淆。

历史机制验证及其边界见 [状态聚合生成纵向切片](../../依据/来源/设计依据与资料边界.md)。它不证明任意领域模型可自动生成完整应用。

### 输出请求 /2 的分组语义

历史`sec.output-request/2`载荷的边界见[旧输出投影](../../../examples/合同历史与范围.md#示例与检查的使用)。当前作者工具由操作规范定义，以下输出根责任不意味着必须照抄旧请求结构。outputRoots 是所选模型/目标范围内的逻辑输出根，不是任意宿主路径。每个根必须在冻结上下文中可解析；requiredClaimRefs 也须解析到合法声明，存在引用不等于声明通过。

请求中的 publicationGroups 只引用 outputRoots：每组非空、组内无重复、组间不重复归属；未显式分组的根默认为独立组。需要合组时调用者提交明确并集，不让重叠数组的顺序决定原子范围。实际产物链接后，若不同根的制品闭包共享必须共同发布的成员，编译器合并其具体发布闭包并给出见证；若超出授权或宿主原子能力，返回受影响义务，不能谎称原子。

结构 Schema 只约束形状；成员归属、根解析、目标能力、闭包共享和 Claim 适用性由后续语义层检查。/1→/2 增加显式版本并重新验证分组，不删除未知根来凑成功。不请求 publish 的编译仍可定义未来发布组，但不因此取得发布授权。
