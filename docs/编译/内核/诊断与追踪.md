# 诊断与追踪

> **阅读范围**：采用范围内的设计规范；实现状态另查未决 · [共同上下文](输入与阶段总览.md)。


## 诊断、解释与决策追踪

### 1. 目标

工程编译器必须解释“为什么得到这个设计、实现和变更”，而不仅输出结果。解释本身是从规范图、求解回执和来源生成的投影，不是人工拼接日志。

### 2. 解释图

```text
ExplainGraph = {
  question,
  answer,
  supportingFacts,
  constraints,
  decisions,
  rejectedAlternatives,
  evidence,
  unknowns,
  counterexamples,
  sourceLocations
}
```

图节点引用规范对象；自然语言只是 locale 投影。

### 3. 典型问题

系统应回答：

- 为什么这个文件受影响？
- 为什么选择库 A 而不是 B？
- 哪条约束阻止编译？
- 哪个未知导致不能冻结？
- 为什么某缓存失效？
- 为什么需要人工批准？
- 为什么这项验证必须重跑？
- 哪个输入改变会使结论反转？
- 这个生成代码对应哪个意图和设计对象？

### 4. 诊断生命周期

诊断绑定：

- 对象 revision；
- 编译阶段；
- 算法 revision；
- 作用域；
- 来源位置；
- 相关诊断；
- 可能修复；
- 陈旧条件。

输入变化后旧诊断进入 `Stale`，不能继续显示为当前错误。

### 5. 不满足解释

约束失败以图呈现：

```text
目标
→ Requirement
→ 冲突约束
→ 来源和有权 owner
→ 受影响候选
→ 可放宽项
→ 修复候选和后果
```

不能只输出求解器内部表达式。

### 6. 解析解释

实现选择显示：

- 候选闭包和完整性；
- 硬资格逐项结果；
- 被拒绝原因；
- 成本向量；
- 政策或人工决定；
- 适用范围和失效条件。

### 7. 变更解释

每个物理编辑可追到：

```text
工程意图
→ 目标声明
→ 语义对象
→ 设计 Delta
→ Target 节点
→ MutationOperation
→ 文件范围
```

格式化噪声和语义变更分开显示。

### 8. 隐私与安全

解释不自动暴露：

- 其他租户对象；
- 秘密值；
- 内部安全规则细节；
- Provider 原始敏感错误；
- 模型隐藏上下文；
- 未授权源码片段。

脱敏发生在投影层，原始证据按权限保存。

### 9. 多语言

错误码、对象 ID、路径、字段和代码保持不变；标题和说明通过 `messageKey` 派生。翻译必须保留否定、条件、数值和权限模态。

### 10. 可操作修复

`RepairCandidate` 包含精确 Delta、前提、权限、风险和验证。用户选择修复后进入正常意图和变更编译，不能由诊断 UI 直接写文件。

### 11. 验收

- 关键决定有完整解释路径；
- 解释引用真实对象而非复制文本；
- 不满足核心可理解；
- 诊断随输入局部陈旧；
- 源码映射双向可用；
- 敏感信息负向测试；
- 多入口展示同一机器事实；
- 修复候选不绕过准入；
- 解释生成确定且可缓存。
