## 原生模块直接绑定与闭合构建

### 不要求专用业务适配器

本文规定[用户定义扩展](../../作者/组合/语义扩展与领域接合.md#用户定义语言语义与编译扩展)的原生接入路径。算法已经存在于TypeScript文件时，用户提供文件、内容锁和符号绑定即可生成调用；编译器不内置算法名称，也不要求先把库重写成领域IR。

一个可选窄绑定画像是：本地闭合 TypeScript 源树、相对模块导入、命名导出和同步 Int/Bool 函数。桥接复用语言的真实类型检查器；它不等于完整 npm、FFI、泛型或异步 ABI。更复杂代码仍可用原生工具构建；窄端口不能表达只限制该绑定与保证，不禁止原工程。

### 直接供给不生成第二份应用算法

已有实现可由准确导出、类型视图、公共行为合同和Binding接入。ModuleRevision保存作者实际写出的调用与独特逻辑；SignatureView可以派生自导入；TargetProgramIR保存所选调用和必要转换。不存在一份“为使该库可被SEC管理而手写的同义主体”要求。原生应用源的可选性与目标实现可以使用原生库，是两个不同维度。

方法返回的是当前根真正需要的导入、链接、类型、转换或代码贡献。没有语义/ABI差额的入口直接调用；有差额才生成适配，且新增作用和错误继续进入检查。源调用有正确接口但行为仍未知时，不因能生成调用就获得中立替换资格。

一个黑盒供给可以在已知完整边界下正确调用，而不允许内部内联、融合、向量化或微分。通用正确调用、特定分析资格和跨目标覆盖分别记录。编译器不能因拿不到内部语义就重写全部上游，也不能伪造未知的优化性质。目标依赖类型与完整源码要求消费[交付边界](../目标/成员布局与完整产物.md#复用实现的源码与依赖交付边界)。

### 冻结输入与绑定合同

一般路径使用工程原有的语言/依赖锁、准确导出与调用合同。普通外部函数不先变成一个`requiredHostPort`，成熟包不先迁入作者`native/`目录。纯查询读取已捕获的源、声明或符号结果；安装、脚本、原生构建及工具进程分别由实际动作承担。

对于明确选择了`sec.native-bindings/1`的窄Port桥接消费者，其files与bindings继续按该版本检查：捕获成员、相对路径、SHA-256和端口引用一致，重复、遗漏、额外成员和摘要冲突拒绝。这个合同只适用于相应桥接，不是普通库使用的必经文件，更不是完整生态的唯一模型。

当前请求的输入、生成方法、目标、工具规则和真实依赖共同形成可复用键。接收外部宣称的产物时核其准确内容与生产关系；按明确的确定生成合同需要重生成比较时才做比较，不让“所有外部库必须先生成同名SEC主体”成为接纳条件。

### 解析、签名与代码生成

**普通值/函数导出走直接调用路径。** 成熟前端解析真实导出及其作用域和签名，形成ImportedModuleView。目标发射器产生恰需的导入和调用；可以直接重导出且符合公开要求时，不生成转发函数。只有必须保持独立公开名字、目标类形态、行为归一或初始化边界时，才生成必要门面。

**有明确宿主交互的port才走Host桥接。** 在所选窄ABI中构造Host类型、完整端口键和宿主对象，仍核唯一同步非泛型签名、this/Promise、表示和实际端口覆盖。该局部限制不加到普通库和全部语言；其他同步、泛型、对象、异步与FFI入口分别采用其已定义调用合同。

直接调用和Host桥接都不能仅凭checker赋值兼容取得行为保证。接口声明、边界合同、合格实现和真实权限分别解析；有限例中的唯一签名限制不能被误报成SEC不支持高阶或泛型。绑定明确的方法接收者、工厂、潜在效果、异常及寿命进入使用点解析，不通过类型断言抹去。

### 闭合工具链与静态检查的界限

虚拟目标树来自本次固定作者/导入内容、生成文件、标准库、声明包及选定解析配置。禁止从活动cwd和环境隐式补库；缺失来源产生Needs。使用成熟工具的实际模块解析与条件导出，而不是用拼接路径代替其规则。

编译检查可以含完整原生模块义务，但不会执行其顶层代码。Node内建模块的运行能力、JDK接口是否存在和第三方包的安装均由实际目标合同判断；工具版本字符串不替代捕获输入。成功只说明相应检查或生成完成，未知效果、真实运行和权限继续分开。

### 用户原生模块的设计例

一个原生模块已有乘法导出，另一个模块保存乘数。若其真实导出与接受的数值/错误合同相容，目标直接import后调用；不为这个算法添加core分支或同义SEC函数。需要完整端口注入的消费者可选择上述Host桥接，但它不是直接调用的默认形态。乘数3、输入14时的预期42用于有限符合性设计，不是已执行成绩。

### 接入完整生态的具体演进

包管理器只负责其真实求解、取得、安装和锁格式；SEC固定请求、实际解析结果、条件导出及使用点。相同依赖已锁定时直接采用。新增或冲突依赖先返回类型化解析需求，应用层在权限内取得真实结果后再生成；不得在printer内部换版本。运行安装脚本是独立动作。

未知类型的原生模块可以作为原文件保全；要向中立调用暴露强合同，需要合格声明、边界检查或精确限定。函数签名可读取不等于全部行为已可跨目标保持。必要的长期适配允许存在；没有差额和独立消费者的转发则不新增。相关完整编译数据见[供给感知主链](编译值服务.md#supply-aware-compile)。

### 原生调用的表示生命周期与失败合同

同步标量画像仅为一条直接路线。一般绑定由“语义签名＋具体传递边界＋生命周期/错误＋提供者与证据”组成，不能只扩充参数类型枚举。它消费[通用类型与资源合同](../../领域/计算基础/通用计算与任务语义.md#产品级复合类型调用与资源的具体默认设计)，不拥有第二套默认语义。

| 绑定坐标 | 必须决定的内容 | 不保持时的处理 |
|---|---|---|
| 数值和文本 | 范围、舍入、端序、编码、长度单位、缺失与空值 | 运行检查、显式有损转换或不支持；不静默截断 |
| 记录、和类型、容器 | 字段/标签稳定身份、未知保留、容器顺序、复制与循环 | 选定有版本的编解码器，不以形状相似代替兼容 |
| 调用 | 参数个数、求值顺序、接收者、重载/泛型实例、可重入性 | 锁定精确实例或写有保持合同的适配，不直接类型断言 |
| 内存与资源 | 分配方、释放方、借用期限、所有权交接点、失败时责任、线程亲和 | 复制、移动或显式共享；拒绝把进程地址当跨进程资源 |
| 回调 | 注册身份、宿主线程、捕获、可否并发/重入、注销与在途调用的结算 | 由对应拥有者保留引用，注销完成前不释放捕获 |
| 异步和流 | 冷/热启动、任务拥有者、等待、取消、缓冲与终态 | 延迟工厂或显式接管已启动任务，不凭Promise名称宣布可取消 |
| 错误 | 业务Result、异常、宿主陷阱、传输失败、未知完成 | 映射真实类别；异常不能无契约穿越不支持展开的ABI |
| 依赖和信任 | 实际工具、库、ABI版本、运行时、效果未知与当前权限 | 缺资格局部阻断，数据类型不能签发操作权限 |

同进程直接调用可避免复制，但必须保持别名、线程和生命周期。跨进程/RPC默认以拥有内容的值消息传递，资源通过有权目标签发的句柄或代理访问；消息中填一个数字不能得到文件或连接能力。零复制需要双方可验证的区域、有效期和释放协议，不能作为普遍性能默认。资源过桥可借鉴Component Model的own/borrow区分，但不强制所有后端采用Wasm。

绑定准备先检查必要端口与适配能力；数据解码/编码失败与真正开始原生执行的时间点分别记录。所有权移动何时发生由边界约定：准入前失败仍归调用方；准入后若约定已移交则由被调用方或其恢复协议承担，不能两边释放。调用发生后无法验证返回值，不意味着此前外部作用没有发生；禁止把该故障简单当可重试纯调用。

原生类型检查是有价值的证据，但不自动证明公共替换关系。例如TypeScript的赋值兼容与严格函数选项各有范围，不能用一次assignable结果代替公共函数参数逆变、结果协变和效果上界检查。原生unsafe、类型断言和错误声明继续属于真实信任边界。

多版本绑定可以并存；调用边明确实际版本，共享同一资源族时校验布局与身份兼容。升级读者不表示写者可以立即发新标签；收缩前检查旧客户端、持久数据、回滚版本和备份路径。精确兼容规则由[兼容迁移](../../演进/兼容迁移与退役.md#读写组合与迁移准入)拥有。

更复杂绑定不必统一序列化：目标原生调用、Component Model、显式C ABI和远程协议可采用不同适配，只要保留所选语义与声明。缺少该能力时保留原生工程或提出适配设计，不能借“自由”假装实现已存在。

### 验收与反转条件

需覆盖精确内容锁、额外文件、端口重复、导出缺失、相对依赖丢失、错误参数/返回、Any、泛型、重载、this、Promise、源码替换、隐式宿主声明、非法路径及类型失败零产出。正常路径须运行预先给定的Oracle。

新需求超出同步标量ABI时扩展版本和实现，不能把全项目判为不通用；类型检查接受而真实返回违反ABI时撤销该端口的运行符合性，保留已经发生的外部效果。若虚拟工具链仍读取未登记数据，撤销闭合构建资格并补输入捕获，不把污染结果放入正式缓存。


## 多语言前后端语义符合性框架

### 1. 跨语言不是语法互译

不同语言在类型、错误、并发、内存、反射、模块、数值、运行时和生态上存在无法一一对应的语义。SEC 通过 Target Profile 和 conformance contract 判断可表达性。

### 2. FrontendConformance

前端必须证明：

- source identity/span；
- parse/symbol/type/control/data/effect facts；
- dynamic/unsupported/opaque frontier；
- configuration/module resolution；
- canonical ordering；
- incremental/clean parity；
- preservation-aware edit capability。

### 3. BackendConformance

后端必须证明：

- TargetIR constructs 的完整 lowering；
- 类型和错误映射；
- behavior/effect/concurrency；
- source map；
- deterministic emission；
- runtime/dependency binding；
- round-trip reobservation；
- required verification。

### 4. 语义差距

```text
LoweringOutcome =
  exact
  | equivalent-under-profile
  | requires-runtime-support
  | requires-adapter
  | degraded-with-accepted-decision
  | unsupported
```

任何降级必须由有权 decision 接受，不能由 backend 静默选择。

### 5. 符合性语料

使用语言中立 golden semantics、语言特有边界、故障、并发、数值、模块、FFI、序列化和性能。声明跨后端符合性时，应比较能表达同一语义的目标计划及实际可观察结果，并说明前端、运行库和测试oracle的共同原因；不强迫不同语言共用同一个目标专属IR。单后端可用独立解释、变形关系或明确期望验证，不为满足数量造第二个空后端。

### 6. 验证

- exception vs result；
- nullable/optional；
- integer overflow；
- async/cancellation；
- resource lifetime；
- reflection/dynamic code；
- package/module visibility；
- deterministic collection order；
- cross-language wire/storage compatibility。


## 多语言工程转换与目标闭合

### 交付依赖模式与完成范围

依赖模式与完成程度是两个坐标。每个请求输出根分别记录，不能用“原生、混合、局部、阻断”这四个互斥标签表示整个工程。

| 坐标 | 含义与条件 |
| --- | --- |
| NativeTarget | 所选根的必需传递依赖全部可在该目标画像下实现；允许画像明示的标准运行库，不暗带原语言运行时 |
| HybridTarget | 必需依赖包含已明确接受的桥接、原运行时或外部服务，并列出其身份、效果与运行要求 |
| 未确定依赖模式 | 尚未闭合依赖，保留已知依赖与未知，不能猜成原生 |
| 完整／局部／被阻断 | 分别说明所请求根及其保持条件是否完成、是否有独立可交付子集、哪些条件阻止当前根；非请求根不参与完成汇总 |

原生输出也可以只完成一部分；混合输出可以完整满足本次请求。某个被阻断根不能让其他独立根的结果消失；若共享不变量要求共同交付，仍按相应组阻断。候选结果和已验收产物的资格另行记录，源码生成完成不提升运行证明。

打包原工程不会使它变成别的语言。局部不能转换也不意味着整个工程不能保全或导入；可继续增加规则、库映射或改写相交实现。此处是目标结果语义，不静默改变旧示例Schema的枚举。

### 降低规则

每条规则声明源构造、目标构造、适用类型、前置条件、可观察行为、错误/效果映射和排除范围。建立转换图可以复用多步规则，不为 N 种语言手写全部 N×N 翻译器。但公共层不能表达的部分仍需专门规则；不能假定 O(N) 后端数量就自动覆盖全部语义。

### 必须显式处理的差异

整数溢出与精度，浮点与 NaN，字符串与 Unicode 索引，空值，求值顺序，短路，异常和栈，闭包捕获，可变别名，GC/所有权，泛型擦除，反射，宏，FFI，线程内存模型，异步调度，取消，文件/网络、框架生命周期和数据库事务。

这些是具体构造的支持合同，不是每个简单程序都填写的检查清单。目标合格性从实际使用的构造和依赖计算。

### 从片段到工程的所需产物

后端只生成请求需要且依赖闭合的根：可为表达式、上下文区域、完整函数、模块、库或工程。函数请求不默认生成入口项目、配置、迁移与运行库；完整工程需要时才增加相应有消费者的制品。片段上下文见[单位输入](../../作者/工程源/清单模块与绑定锁.md#片段函数与工程使用同一输入合同)，源码组织见[目标生成策略](../目标/成员布局与完整产物.md)。产物不默认调用SEC服务；真实运行库或原生桥接必须列出其身份、代价和支持范围。

### 证明范围

首先保证结构合法，再做目标构建、契约测试、边界/故障/差分和特定关键转换证明。测试不能变成全上下文等价定理。编译器可以正确转换一个会无限循环的程序，无需先证明它终止。

### 理由与反证

单纯语法互转不足以保持工程；统一 VM 可保留更多行为却引入运行时，不能冒充纯原生输出；完全重新设计可能改变功能。采用多模式显式输出，使用户知道什么被真正移植。

反例：TS number 承载超范围 Python int；Java checked/unchecked 异常变成无条件成功；转换后数据库隔离改变；桥接未列原语言依赖。每种都应产生诊断或失败测试。
