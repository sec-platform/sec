# 原生能力映射与采用

本主题细化[原生与跨语言编译](../内核/原生与跨语言编译.md)的实际使用点：同一需求在Rust、TypeScript和外部C++供给中怎样保持，何时可直接复用，何时必须承认原生接口、表示、资源或保证的差额。它不是新的作者语言、独立内核或常驻平台；原语义、绑定、编译、保证与执行仍由其唯一拥有者承担。

| [对象与调用](对象与调用.md) | 子对象、共享与重复基、可见性、动态视图、成员/代理、重载、接收者与求值顺序 |

原[组合前提](../组合前提与进展闭合.md)和[有限抽象与观察策略](../有限抽象与观察策略.md)处理共同见证与可执行选择，不能由每一行单独成功推出系统合格。[原生映射与组合验收](../../运行/验收/原生映射与组合.md)保留条件案例、交叉机制和完整连续使用；[一手来源](../../依据/来源/Rust与C++映射依据.md)保留版本、适用命题及未核验范围。

设计已明确的有限路线可以实施；具体工具/驱动、目标编译与运行、ABI、并发和收益仍须相应证据。普通库/类型方案可以是最终方案，不因它没有C++同名拼写就强制升级；硬条件真实存在时，也不能用换API、额外分配、锁或隐藏原生依赖冒充无损替代。
