# 成品消费合同与发射

本篇把[成品细节](../../作者/成品/README.md)接回原resolveUse、lowerBoundUse、composeTarget与保证/执行边界，不新增编译阶段、中央Form枚举或作者工单。公共边界由[作者规范](../../作者/成品形态与公共边界.md)拥有；这里拥有方法必须消费与产出的具体内容。

## 输入与方法选择不是仅看一个名字

每个输出根消费准确候选、展开后的要求与主体、完整公开字段及默认来源、所求性质、目标语言/平台/ABI、所需完成阶段及实际环境事实。来源表中的Rule引用只定位含义；有同名函数或模板不证明合格。方案目录能列全名字，也不证明各形态已经有实现。

选定的方法需要SourceBody、ExternalExport或GenerationMethod之一，声明其全部依赖、输入域、保持前提和真实适配。结构规则与普通原生方法可以直接组合，不先打印SEC文本语言。使用公开方法无关私有实现可以不展开；对实现和保证有影响的内容仍进入准确输入。

## 三种接口及无新增公共对象

`semantics/requirements/instantiate`把defaults、uses与subject映射为原RequirementTerm与来源；不运行服务。`compiler/realization/resolve-use`在这些义务、目标和用途下得到原UseBinding，记录实际方法与缺口；不是返回一个“已支持”的bool。`compiler/target/compose`消费LoweringReceipt与真实TargetProgram贡献，区分可封存Artifact、保留进口的组件及有缺项候选。

这是现有十职责中的函数责任，不要求新增三个目录或服务。实现可以融合调用，但不能删除这些消费者的独立不变量。资格强度随用途：被测候选允许保留未证Claim，生产消费另核；缺权不变成测试模式万能通行。

## 各类方法具体产生什么

| 形态 | 方法必须取得的内容 | 具体发射/适配与成员 | 成品特有的检查 |
|---|---|---|---|
| 规格/策略包 | 公开定义闭包、解释与许可 | 作者模块、出口、完整含义和实际锁；不发空运行程序 | 无会话读入、同型不混主体、默认出处 |
| 值/资源 | 精确值、编码、原资产与消费者 | 值或准确文件、资源清单；按选择写入 | 字节/值分开、逃逸路径、缺成员 |
| 片段/修改集 | 精确外层和源版本、全部相交引用 | 合法单位或完整候选文本、EditCorrespondence | 捕获、求值顺序、错误、当前前像 |
| 库/SDK/Client | 真实行为、函数接口、进口和资源策略 | 直接重导出或必要适配，类型/JS/依赖，Client含协议编解码 | 同步性、精确整数、关闭和网络边界 |
| CLI/批程序 | 真实算法、stdio与作业合同 | 入口、编码/退出、进度/顺序槽、关闭/清理 | 部分输出、短写、日志分流、非TTY |
| Handler/Service | 请求响应、监听/健康/排空能力 | handler只交调用面；service再取得监听和生命周期 | 路由优先级、头后失败、ready、借用资源 |
| Worker/Component/Plugin | 宿主进口、消息/ABI、资源/版本 | 装载与桥接、关联与回调、结果析构、实际描述文件 | 重入、重复id、回执、释放函数仍存活 |
| Web/Desktop/Mobile/Studio | 输入/状态/动作/呈现、平台资源和权限 | 真事件与渲染、样式/消息、文件与后台适配 | IME、焦点、旧结果、草稿/保存、后台重建 |
| Family | 必需根、共享行为与成员关系 | 准确子制品和共同清单，不按目录扫描决定成员 | 局部完成、配置冲突、组合采用 |
| Query/Batch/Stream | 比较关系、快照/域、时间/重数和前沿 | 查询计划、聚合/排序、分页或检查点、sink接合 | 完整范围、未交付缓冲、Final与外部效果 |
| Migration | 前后schema、值关系、切换与围栏 | 影子准备、数据变换与检查、实际切换/恢复步骤 | 重试不二次转换、旧写关闭、逆映射条件 |
| Compiler/Analyzer/Generator | 输入文法、语义、诊断及目标 | 真读取器与检查、变换、发射和来源 | 错误模型不能自证、Pass失败候选不发布 |
| Model/Trainer/Sampler/Optimizer | shape/参数/分布/候选域与方法 | 实现、必要权重和解码、随机源/检查点/确认 | 相关性、误差、未知成本、训练非泛化 |
| GPU/Firmware/RealTime | ABI、硬件、资源/时钟及可靠界 | kernel与host桥或镜像/启动/调度与故障出口 | fence、物理安全态、WCET与部署匹配 |
| Installer/Deployment | 已封存Artifact、实际目标与操作许可 | 平台包、安装/启停/流量切换、可查回操作 | 依赖、占用、部分切换、回滚不代数据回退 |

表中的步骤由各成品详解的完整合同决定，不把一个输入标签自动扩成通用服务。没有必须成员不能写stub、TODO、空默认或假成功；独立目标有完整供给仍可正常交付。

## 目标事实不能靠源码假填

`sec.project.json.targets`引用真实可解析的目标画像，而不是任意字符串。范本是当前可读取的设计库，没有已取得生产后端；故未捏造目标Ref。这里已经确定每种产品需要怎样的画像内容：语言模式与工具版本、目标平台/ABI、公共映射、资源/加载/关闭、所需质量和能力。选定后取真实内容、构造引用与锁，再进入同一编译链。

对本例36个确定成品，当前结构检查要求每个导出的形态同时具有：完整作者根、同名语义规则、可解析规则正文、工程清单成员和至少一个目标消费入口。只有类型声明而没有任何消费入口的运行型形态不能通过这道结构门槛；静态值/资源等非运行形态仍通过明确读取函数取得内容。这个门槛只防“有名字没接口”，真正目标实现仍需各自类型、效果和运行验证。

没有目标运行环境不妨碍保存和分发完整需求定义；不允许因此报告运行程序已经可用。反过来，编译器实施者不能把每个MissingSupply都退给产品作者写算法，应按已有委派取得成熟实现或创作合格供给。目标事实是待取得材料，未写出的公开含义则是设计缺口，两者必须分开。

## 一次正常使用与可复算变化

Library根生成可调用库，不分配服务；Service根额外取得网络监听，缺Listen能力则Service未完成而Library可保留。WindowStream把windowMs从1000改5000，输入域不变，但结果窗口与检查点解释改变，不能热读旧窗口状态；需新实例或实际状态迁移。Family改Web标题不改变共同Canonical，私有规范化方法和Library根无需重算。

合格实现换成高性能核仍受全域、输入一次求值、错误顺序、联合分布和开放环境限制。同步接口没有同步核时保留原合格方法，不能为了性能变Promise。所有资源和作用由原生命周期/恢复合同执行，代码生成和实际授权不混合。

## 实施验收的闭合条件

针对每个所选根至少完成：按真实作者源展开、取得精确字段与正常输入、找到方法和目标、生成全部必需成员、建立公开入口、独立消费一次正常结果、覆盖明确失败/取消/退出、修改一项参数并核相交消费者。此为产品实施验收设计，不是本包已执行记录。

静态规范检查能检目录/引用/类型字面量/有限展开；它不能验证真实I/O、页面焦点、驱动围栏、调度界或模型分布。不得据此把本表全打为已运行；也不得用一项未完成取消其他已完整的独立成果。
