# 能力履行与接口差额

> 条件能力设计；不改变已固定的基础画像，不表示实现或目标符合性已完成。

本页补充[需求关系与能力边界](../../作者/需求关系与能力边界.md)中的相交能力；原章节继续拥有其已采用的有限语义。**当前选择：保留局部可满足性检查，防止平台化膨胀。** 只记录影响该调用/表示/导出的要求；不能为普通加法维护全系统能力证书，也不能以加权分数抵消硬条件。

这里的选择不是删除能力或承诺全部默认启用。满足真实要求的成熟库、静态展开和原生适配可以作为最终方案；额外语义只在现有路线不能保持该使用点的明确要求时激活。未提供对应解释、实现或目标条件时保留作者要求并返回具体缺项，不强迫所有项目携带设施。

输入、诊断和选择继续消费原 MethodSpec、UseBinding、Needs、Claim 与 TargetProfile。下列概念接口用于解释必要信息，不是第二套公开工具或新的持久身份域；只有所请求用途的相交义务成立才取得相应用途绑定。

### 不再用一个 supported 布尔值

一个使用点的要求按独立维度表达：

| 维度 | 要保持的内容 | 不能被什么替代 |
|---|---|---|
| 行为 | 值、外部效果、异常、析构顺序、阻塞／挂起、可观察身份 | “返回结果一样” |
| 作者接口 | SEC 中合法的调用、类型、重载、泛型与可反射信息 | 目标代码看起来相似 |
| 原生目标接口 | 外部 Rust／TS 调用者实际可用的签名与协议 | SEC 内部已经展开成功 |
| 资源 | 分配器、分配失败、区域寿命、栈／堆位置、阻塞和进展要求 | 平均速度更快 |
| 物理表示 | 大小、对齐、偏移、位布局、地址稳定、调用约定 | 可序列化成同样字节 |
| 兼容 | ABI、源语言行为、模块／库版本、运行时域 | 同名类型、同样的方法列表 |

`exact` 只在指定观察范围、输入域和目标环境内成立。不把未观察的时间、调度或地址行为顺便承诺为精确等价。实测性能必须另有输入、基线和环境；本节不虚构零成本或速度收益。

### 操作级接口

以下是规范中的概念接口，不是新增的运行服务：

```text
resolve_requirement(
    use_site,
    semantic_revision,
    concrete_or_symbolic_arguments,
    required_guarantees,
    target_profile,
    permitted_adaptations
) ->
    Bound(plan, fulfilled_guarantees, obligations, dependency_refs)
  | NeedsInstantiation(unresolved_parameters)
  | Ambiguous(candidates, conflicting_obligations)
  | Unsupported(missing_capability, affected_sites)
  | Unknown(reason, required_evidence)
  | Invalid(diagnostics)
```

候选必须先满足全部硬要求，再从合法候选中按明确偏好选择。禁止用“native＝3、emulated＝2”之类分数把 ABI、时间、字节、资金和语义抵消。`Bound` 只表示规划绑定；实现不存在、没有取得必需证据或缺依赖时不能宣称产物可交付。

目标画像至少固定后端及版本、目标 triple／JS 宿主能力、调用约定、数值模型、可用原子宽度与进展承诺、动态库与 unwind 域、允许的运行库、资源限制。只有实际相关字段参加该使用点的检查与缓存，不为每个加法附加一份全系统登记表。

### 三种 API 边界

**SEC 管理边界**允许下游 SEC 继续实例化泛型、执行反射和选择 witness；分发的语义模块保留必要合同与定义。

**原生 Rust／TS 边界**只能导出目标语言真正可以表达的 API。SEC 中的任意重载不能自动成为外部 Rust 的同名重载；可以导出唯一名字、合格 trait、闭包适配器或有限 wrappers，且必须明确这改变的是原生接口，不是 SEC 作者接口。要求外部原生调用语法完全相同时，无法表达就返回缺项。

**外部 ABI 边界**固定类型表示、传参、所有权、错误、回调、线程与卸载合同。内部 SEC 类型不能因为名称相同就直接跨该边界。

### 能力画像不是两个互不相容的语言

原已选画像的安全语义保持。布局、MMIO、foreign ABI、特殊重载等强控制局部激活；它们沿真实依赖传播，不感染无关纯函数。精确 C++ 兼容需求进入有版本的语义／ABI 扩展，而不是悄悄改变全项目默认规则。

编译器必须产生“哪个约束排除了哪个目标”的最小相关诊断。例如：`native_cpp_exception_unwind` 与 `pure_stable_rust_only` 的冲突，不应该表现成几十个无关类型错误。缺项保留原作者源及未满足要求，不生成假实现。

### 兼容 profile 必须可消费，不能是占位名称

一个 profile 至少固定身份／版本、可接受构造、名称与类型规则的责任方、求值与生命周期观察、访问语义、目标约束，以及无法映射的构造怎样被保全／拒绝。选用 profile 只是选择规则，不证明该规则已有实现。

源语言允许的可观察不确定性也属于合同：例如某种复制省略是允许而非强制，兼容模式应表达允许的行为集合，不任意发明一条“永远恰好调用一次”的历史保证。缺少正确解析／语义适配器时，不生成标为完整兼容的产物。

采用成熟源工具时，适配器必须返回实际声明／类型／布局及其工具版本和覆盖；只能查询元数据的工具不能被当成能够执行全部语义保持变换。私有元数据可见、生成代码可访问私有存储、运行期权限三者分别处理。

组合多个 profile 时先检查相交声明的含义是否一致。同名同版本展示字符串不证明两个类型能互传；在不同语义域之间使用明确的值转换／ABI 桥，不能全项目取一个“最强模式”覆盖全部规则。

## 再次修改与失效

新增硬约束、目标或导出要求时，保留原要求并重新选择相交方法；不能用当前最快候选反向重写接受条件，不重算无关输入。

## 使用点与可检验出口

这些分支保留各自的真实输入、替代路径与边界，不按条数声称更多底层能力；[比较记录](../../依据/来源/Rust与C++能力比较.md)不拥有另一套语义。

- **标准portable SIMD**：按实际数值与ISA合同复用供给；C++26特性成熟度单列，不说Rust没有SIMD。 硬边界示例：固定标准库依赖、ISA、mask异常行为或确定性归约合同，现有库/目标无法满足；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a63)。
- **语言级contracts**：保留真实安全前提与检查，是否提供通用契约语法按需求决定；不能因此宣布Gift必须有全套effect/refinement系统。 硬边界示例：必须兼容C++契约语义/诊断模式，或公共API工具必须消费标准contract实体；[具体比较与出口](../../依据/来源/Rust与C++能力比较.md#a64)。

实际组合与拒绝条件见[验收案例](../../运行/验收/跨语言控制与组合案例.md)；从作者要求到再次修改见[连续开发情景](../../../examples/连续开发/跨语言能力连续开发.md)。

## 平台、GPU、外部 SDK 与不能隐藏的供给

真实使用点选定的是一组能共同工作的语言前端、目标、构建器、库/驱动、运行时、调试与发布接口，不只是一个语言标签。芯片、GPU、系统调用或供应商 SDK 若成为硬要求，核其真实版本、目标架构、编译/链接条件、运行驱动、许可和任务实际要求的资质。当前未调查的设备保持未知，不因某语言存在目标分级就断言该设备不支持。

可采用局部原生内核、成熟桥接或进程/设备接口，前提是允许这些构建和运行成员并保留数据、同步、错误、资源和卸载合同。Rust 能启动某个 C++ 内核，不等于交付纯 Rust 的同一内核；TS 经 Wasm/native 调用也不是纯 JS 获得了原生地址或任意硬件原子。作者没有要求纯目标时，不把合法混合路线当作失败；确有纯目标硬约束时不能将 shim 藏进生成目录。

同等任务下比较成熟库、静态展开、原生接口、可选新语义四类路线；同时考虑应用作者与库维护者的修改负担、依赖审计、编译时间、代码体积、冷暖运行和后续迁移。没有同单位依据就保留成本维度和反转条件，不制造一个综合分数。真正无法满足时返回缺少的能力及可保留的独立根，而不是伪造空实现。

## 生产者、消费者、清理和外部调用者的完整接合

### 不新增一套平台

| 现有责任 | 本补充相交工作 | 不承担的工作 |
|---|---|---|
| `workspace` | 作者定义、原生片段、冻结版本、来源及更改位置 | 不凭文档内容授予外部运行权 |
| `semantics` | kind／类型、名称、投影、约束、效果、语义 profile 与访问规则 | 不执行目标 I/O，不以目标限制偷偷改作者需求 |
| `compiler` | 阶段化求值、实例化、布局与清理计划、目标选择及生成 | 不宣称未取得的工具链能力，不替目标生成成功签发部署许可 |

### 分析阶段与最小中间事实

编译流程依据依赖调度，而非要求每个模块线性通过一个巨大通用流水线：

```text
固定作者内容与目标要求
  -> 名义声明、kind、opaque 关系及必要递归分量
  -> 分阶段元求值／结构生成及依赖封存
  -> 类型、重载、投影、效果、借用与约束检查
  -> 具体实例和 witness 绑定
  -> 布局、对象状态、清理与 ABI／资源路线检查
  -> Rust／TS 目标生成及原生入口适配
  -> 所需静态检查／目标证据与准确交付状态
```

需要更早获取的目标常量必须来自已经固定的目标 profile；不能使反射依赖可变主机又假装可重复。互相依赖的声明可先建立名义身份，产生无限按值布局的环则拒绝。生成阶段循环只在明确递归／不动点协议与资源界限内求解。

`ResolvedCall`、`TypeWitness`、`ObjectState`、`Projection`、`LayoutPlan`、`CleanupPlan`、`MetaDependency`、`AbiBinding` 是应当能查询到的事实种类，不要求全部成为独立持久文件／公共 IR 层。已有结构可无损承担时复用；只有实际消费者需要时才保留。

后端消费已经绑定的语义，不能各自重新运行另一套 overload／specialization 算法。优化若改变观察范围，需要相应的保持依据；失败时回到准确的作者使用点及生成来源。

### 作者怎样使用，而不是怎样填写编译器表格

普通作者只写独特行为、引用的定义及真实强要求。对象是否需要 RTTI、函数是否单态化、字段遍历怎样展开等可推导细节不重复输入。

强控制以局部差异进入同一作者源。例如选择固定地址、某个 allocator、确定性归约或公开 ABI，并对实际相交使用点生效。高级控制撤销后，编译器重新计算合法实现，不保留失效的隐藏开关。

已有 Rust／TS／C++ 来源中的特殊语义，只有存在映射与保持依据时才能提升到中立设计。未知原生片段保全为准确来源／局部实现边界；不能先改写成“类似”的 SEC 源再声称无损。原文往返和行为保持继续是不同交付。

### 版本演进与兼容

语义 profile、公共定义与实际 ABI 都按各自身份与版本绑定。修复重载、布局、反射或清理规则可能改变旧程序结果，必须检查受影响使用点；不能以补丁版本名替代兼容性判断。

生成代码／元数据是派生物，不形成第二份手写真源；必要的原生实现源仍有自己的真实 owner。用户修改生成代码时，只能通过明确映射回源、采纳为独立实现或报告冲突，不能下次重新生成悄悄覆盖。

### 后端不能重复拥有同一个生命周期

Rust lowering 对每个资源确定唯一 cleanup owner：要么由合格的 Rust 原生 Drop／作用域机制拥有，要么由生成的状态 guard 拥有。不能同时发出手工 destructor 调用，又留下会再次 Drop 的活跃值。

部分初始化使用真实有效性状态。所有权成功转移后清除源的相应初始化／清理责任；执行销毁前先进入不可重入的 Destroying 状态，销毁后不再次调用。`MaybeUninit`、`ManuallyDrop`、raw pointer 都只在已经明确的存储与责任协议内出现，不能作为消除编译错误的通用修补。

动态子对象投影和 packed／重叠访问，只有在对应存储、对齐、有效值、寿命和借用条件已经成立时才形成 Rust 引用。运行检查只能验证它真实能观察到的事实；无法观察外部线程别名时，不能凭本地检查宣称已经证明全局独占。

### TS 类型擦除与不可信原生调用者

TypeScript 类型检查和类型注解本身不会在输出 JavaScript 中保留为运行期检查。[依据](../../依据/来源/Rust与C++能力比较.md#baseline-s30) 因此 SEC 的消费式对象、一次性 callable、资源借约与私有状态，在仅由受管代码使用时可静态消去不必要检查；公开给任意 JS 后，则必须保留合格的运行状态检查、封装句柄或数据复制边界。

不能通过 `as T` 断言，把外部对象提升为满足拥有权、纯字段访问或不变量的受信对象。外部属性可能经 getter／proxy 执行用户代码；该访问进入 foreign 效果域，允许重入／抛出与数据变化。需要纯数据时采用明确数据协议及能建立该协议的实际解码边界，不假定遍历任意对象是纯操作。

可用受管句柄及私有状态隔离内部不变量，不要求每个普通对象都使用运行时句柄表。公开入口在消费／关闭后再调、在 callback 中重入、跨 await 后使用失效借约，必须获得与 SEC 语义相符的错误或约束；不能只因为 TS 编译通过就判定安全。

这不构成对恶意同进程宿主的通用安全沙箱。真正不可信 native 模块、可直接破坏内存的宿主或进程边界要求，必须依赖相应隔离／权限供给，不能用语言访问修饰符替代。

## 验收、反例和证据边界

### 验收设计的层次

一项能力必须同时有合法例、拒绝例和组合例。检查分为语义诊断、生成结构、目标编译、运行观察以及 ABI／并发／性能专门证据；前一层通过不代替后一层。

[逐项比较](../../依据/来源/Rust与C++能力比较.md)保留每项独立验收行为，[组合验收](../../运行/验收/跨语言控制与组合案例.md)补充组合与故障注入向量。它们是可执行测试应实现的规格，**不是本设计已经运行的测试**。文档交付核验只支持实际检查过的覆盖、文件一致性、来源键及文本结构，不代替目标程序证据。

### 关键正确性义务

类型／借用层需要证明或者以明确定义的验证体系支持：合法操作不会使用未初始化／已释放值，不制造不相容独占引用，目标布局访问符合表示与 provenance 前提，效果不会越过未声明边界。

编译层需要逐变换说明保持什么观察、依赖哪些前提；C++ 兼容输入可以保留源标准允许的行为集合，不能任意收紧／放宽后称逐字等价。目标内存模型、数值模型和 unwind 域均属于证明前提。

运行层的公平性、进程退出、设备行为、网络成功和断电耐久不能只靠语言类型规则证明。需要真实宿主合同、运行记录和适用范围内的测试；不可控环境引起的未完成不能被强行转换为正常返回。

### 不采用的捷径与保留的替代方案

**不采用把全部能力塞给 unsafe。** unsafe 只能承接具体无法静态证明的前提，不能凭空得到 stable 语法、泛型或 ABI；同时保留局部 native implementation 作为诚实的受限路线。

**不采用默认把所有元编程改成 runtime 反射。** 这会改变启动成本、分配、信息暴露、部署与错误时间；只有作者接受该变化且存在实际 runtime metadata 时才是合法候选。

**不采用全项目 C++ 化或重写 rustc。** 已解析重载、特化和有限元生成可输出普通目标代码；需要原生外部 C++ 对象语义才使用精确桥接。将来新增 C++ 通用目标是独立产品决定，不由某个 ABI 用例暗中触发。

**不采用一个万能仿真运行时。** 仿真可用于明示允许的目标路线，但资源、地址、调度、原子进展和原生接口都须逐项检查。目标无法履行某项硬要求时，正确设计结果就是准确缺项，不是重写要求。

**不采用无条件全局特化与无界隐式转换。** 保留需要的开放扩展、结构式探测和局部重载，但把候选域、绑定与效果固定下来；需要精确 C++ lookup 的输入使用其兼容 profile，而不是全工程默认承受历史规则。

### 仍需实现证据的明确范围

本补充尚未给出并验证整个新语义系统的形式化健全性证明；涉及 raw projection、pin 初始化、尾部 padding、跨语言异常和并发内存模型的 lowering 需要实现级审查。未取得真实 Rust／TS 后端对本文全部规格的编译与运行结果，也未建立所有 C++ ABI／版本的兼容矩阵。

哪些路线能达到特定性能、栈空间、编译时间、代码体积和 lock-free 保证，须由精确目标及实际供给决定。本文不预测无依据的百分比，不把尚未取得的库／工具作为已经可用。

这些缺口限制的是“已实现、已验证、具体目标可交付”的声明；不阻止本补充把已识别的 64 个用例、组合规则、接口与失败结果设计出来。新的有效反例应修正对应 owner 与所有相交消费者，不只在末尾追加免责句。

## 约束传递不只沿调用图

类型与布局依赖、名称与实例化依赖、效果与清理依赖、反射观察依赖、运行寿命与外部 ABI 依赖分别维护真实边含义。它们可以引用同一声明，不合并成一个无语义万能图。

例如给 Base 增加一个字段，可能改变派生布局、成员投影、反射生成、导出 ABI 与旧对象热更新条件；却不一定改变只依赖 Base 公共行为的独立函数。依赖失效按实际观察范围传播，既不能全仓重建，也不能只刷新字段所在文件。
