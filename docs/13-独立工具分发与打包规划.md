# 独立工具分发与打包规划

> 目标：将 Spec Engineering Compiler (SEC) 编译器 CLI 从项目内置工具升级为可独立分发、全局安装并兼容 Node.js / Bun 双运行时的命令行包（`@spec-engineer/cli`），实现开发者本地及 CI/CD 环境下的快捷使用。

---

## 1. 终局形态与分发设计

独立工具将以 `@spec-engineer/cli` 的 NPM 包形式分发。

- **`sec`**：与项目名称 Spec Engineering Compiler (SEC) 保持一致，供开发者及 CI/CD 自动化流水线脚本调用。

### 1.2 运行时兼容性
- **Bun 优先**：如果系统已安装 Bun，运行时将直接通过 Bun 极速执行。
- **Node.js 兼容**：为了保证在没有安装 Bun 的受限环境（如部分标准 CI 容器）下也能运行，CLI 的编译产物应为标准 ESM (ES2022) 格式的 JavaScript 文件，并声明标准的 `dependencies`（如 `commander`, `ts-morph`, `ejs` 等）。

---

## 2. 第一版打包与发布实现 (v1.0.0 Release Implementation)

我们已经完成了所有发布相关的环境配置、自动构建脚本与隐私隔离发布工具的实现。整体采用**“极简心智，一键发布”**的工程化设计。

### 2.1 极简发布命令矩阵
开发者日常仅需关注以下三个命令：

| 命令 | 行为说明 | 使用场景 |
| :--- | :--- | :--- |
| **`bun link`** | 本地软链 CLI 到全局指令 `sec` | 开发阶段，在本地任意工作目录实时运行与联调 |
| **`bun run build`** | 打包编译 CLI 并在 `./dist` 生成生产环境 Bundle，包含官方 Registry 资源 | 准备发布或生成生产包时运行 |
| **`bun run publish`** | 自动过滤 `docs/` 和私有规则，生成干净分支推送到公开仓库 | 需要同步开源社区时运行 |

## 3. 核心机制设计

### 3.1 隐私沙盒式“双库隔离” (Google Copybara 模式)
为了杜绝开发文档（`docs/`）、AI 交互日志（`.claude/`）以及私有开发规则被意外推送到公开库，我们没有采用常规的 Git 多 Remote 合并（极易手抖导致泄漏），而是编写了专用的 **[publish-public.ts](file:///d:/Project/sec/scripts/publish-public.ts)** 脚本：
1. **沙盒提取**：在 OS 临时目录下创建一个随机独立的 Release 沙盒文件夹。
2. **白名单过滤**：仅复制必须的编译器代码与配置，**物理排除** `docs/`、`.claude/` 等所有敏感隐私路径。
3. **配置清洗（Package Sanitization）**：对沙盒内的 `package.json` 进行动态重写：
   * **命令精简**：仅保留 `sec`, `dev`, `build`, `test`, `check`, `typecheck` 等 6 个公开指令，**物理移除**全部私有演示、治理分析与发布命令。
   * **依赖精简**：**剔除重型 UI 框架依赖**（如 `next`, `react`, `react-dom`）以保持 CLI 的极致轻量化；**剔除私有开发工具依赖**（如 `gitnexus`）；并将核心编译分析引擎（`ts-morph`, `typescript`）从 `devDependencies` **提升至运行时 `dependencies`**，确保公开包能零依赖缺失地独立编译运行。
4. **历史抹平**：在沙盒中初始化全新的 Git 本地库，建立单条 clean commit。
5. **单向同步**：强制推送（Force Push）到公开源 `https://github.com/QzCrane/compliter.git`，保证公开仓库干净无污染。

### 3.2 独立可执行 Bundle 构建
脚本 **[build-release.ts](file:///d:/Project/sec/scripts/build-release.ts)** 将编译器代码编译为单个文件：
* **运行时兼容**：使用 Bun 的构建器进行代码混淆与 `.ts` 扩展名依赖解析，标记外部重型库（如 `ts-morph`, `typescript`）为 external。
* **资源随包携带**：自动将 `platform/registry/official` 与 `platform/policies/official` 打包至发布目录 `dist` 的对应相对路径中。
* **独立入口**：生成的 `dist/index.js` 自动注入 `#!/usr/bin/env node` 并赋予可执行权限（`chmod +x`），可在 Node.js 或 Bun 环境下零配置直接运行。

## 4. 开发者使用指南 (Developer Quickstart)

### 4.1 本地测试联调 (Local Development Link)
在主目录运行以下命令进行本地注册：
```bash
# 1. 执行编译，产生最新的可执行文件
bun run build

# 2. 注册本地软链
bun link
```
链接完成后，您可以在系统的任意目录下运行：
* `sec --help`
* `sec init` (可在您的其他实际测试工程中进行验证)

### 4.2 清爽推送至公开库 (Publish to Public Repo)
当您需要发布最新的编译器开源版时，直接运行：
```bash
bun run publish
```
该命令会自动将除 docs 外的所有代码发布到您的公开 GitHub 仓库。您本地的日常提交仍直接通过 `git push` 同步至私有开发仓库。
