# 独立工具分发与打包规划

> 目标：将 SpecEngineer (PJC) 编译器 CLI 从项目内置工具升级为可独立分发、全局安装并兼容 Node.js / Bun 双运行时的命令行包（`@spec-engineer/cli`），实现开发者本地及 CI/CD 环境下的快捷使用。

---

## 1. 终局形态与分发设计

独立工具将以 `@spec-engineer/cli` 的 NPM 包形式分发。

### 1.1 双指令映射
全局安装后，向操作系统注册两个可执行指令：
- **`se`**：SpecEngineer CLI 的缩写，供开发者日常开发和快速输入使用。
- **`pjc`**：与项目名称 Project Code (PJC) 保持一致，适合在 CI/CD 自动化流水线脚本中调用。

### 1.2 运行时兼容性
- **Bun 优先**：如果系统已安装 Bun，运行时将直接通过 Bun 极速执行。
- **Node.js 兼容**：为了保证在没有安装 Bun 的受限环境（如部分标准 CI 容器）下也能运行，CLI 的编译产物应为标准 ESM (ES2022) 格式的 JavaScript 文件，并声明标准的 `dependencies`（如 `commander`, `ts-morph`, `ejs` 等）。

---

## 2. 实施计划 (Execution Plan)

### Phase 1：CLI 配置重构 (CLI Packaging Configuration)
- **任务 1.1：`package.json` 属性升级**
  - 去除 `"private": true` 或添加 `"publishConfig"`。
  - 在 `package.json` 中配置 `"bin"` 字段：
    ```json
    "bin": {
      "se": "./dist/cli/index.js",
      "pjc": "./dist/cli/index.js"
    }
    ```
  - 配置 `"files"` 属性，明确打包分发时包含的必要目录（`dist/`, `platform/policies/`, `platform/registry/`）。

- **任务 1.2：CLI 名字调整**
  - 修改 `platform/cli/index.ts` 中的 `program.name('se')` 与描述，使其在打印帮助信息（`se --help`）时输出统一的品牌标识。

### Phase 2：自动构建与打包流程 (Bundle & Build Pipeline)
- **任务 2.1：TypeScript 编译配置**
  - 新建 `tsconfig.build.json` 针对发布版本，配置 `"outDir": "./dist"`。
  - 将 TS 源码编译为原生 Node.js 可直接执行的 ESM JS 代码，避免运行时编译开销。
  
- **任务 2.2：构建脚本与官方 Registry 拷贝**
  - 编写 `scripts/build-release.ts` 构建脚本：
    1. 清理存量 `dist/` 目录。
    2. 执行 `tsc -p tsconfig.build.json` 进行编译。
    3. 将只读的 `platform/registry/official/` 与 `platform/policies/official/` 资源目录拷贝至 `dist/` 对应的位置，确保分发的独立包随包携带标准能力块和策略规格。
    4. 为 `dist/cli/index.js` 添加可执行权限（`chmod +x`）。

### Phase 3：本地开发测试与验证 (Local Integration Testing)
- **任务 3.1：提供本地软链测试机制**
  - 编写 `npm run local:link` 与 `npm run local:unlink` 指令，使用 `bun link` 或 `npm link` 进行本地全局链接测试。
- **任务 3.2：独立运行验证**
  - 在全新的空目录中运行 `se init`，验证其是否能正确识别当前工作区，读取全局包内置的官方 Block 进行初始化。
