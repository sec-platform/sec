# 独立 CLI 分发与公开包规划

本文定义 SEC 从私有开发仓库构建独立 CLI 包和公开源码镜像的边界。当前仓库仍以私有开发形态为事实。

## 1. 目标形态

- 包名候选：`@spec-engineer/cli`。
- 可执行命令：`sec`。
- 标准 Node.js ESM 构建产物。
- Bun 用于仓库构建/测试加速，但公开 CLI 不要求用户必须用 Bun 执行。

## 2. 当前仓库入口

当前 `package.json` 已声明：

```text
bin.sec = ./dist/index.js
```

开发命令：

```bash
bun run sec -- <command>
bun run build
bun run publish
```

具体 script 和 dependency 列表以 `package.json` 为权威，本文不复制完整对象。

## 3. 构建边界

Release Builder 应：

1. 从 compiler/CLI 公共入口构建标准 ESM。
2. 复制运行时需要的 official registry/policy resources。
3. 保留外部 runtime dependencies 的明确依赖声明。
4. 生成 Node-compatible executable entry。
5. 验证 `sec --help` 和最小临时 Workspace 闭环。

不得：

- 依赖私有 docs 才能运行。
- 依赖本仓 `.sec/**` 缓存。
- 把 Next/React 等仅用于 reference/workbench 的依赖无条件带入核心 CLI，除非实际 runtime import graph 需要。
- 在构建时修改开发仓库 canonical source。

## 4. 公开镜像

公开镜像采用白名单提取，而不是把私有仓库直接配置第二 Remote 后人工推送。

发布脚本职责：

```text
create temp release workspace
→ copy allowlisted files
→ sanitize package metadata/scripts
→ remove private/internal material
→ build and smoke-check
→ create clean release history or release commit
→ push designated public repository
```

公开/私有边界必须由代码白名单和测试保护，不能只靠 `.gitignore`。

## 5. 隐私与许可

以下默认不进入公开包/公开镜像：

- `docs/**` 私有设计资料。
- Agent/IDE 私有配置与会话数据。
- `.sec/**`。
- 私有 Registry/Project Source。
- 仅允许开发期、许可证不适合公开产品依赖链的 Evidence Provider。

GitNexus/Graphify 等开发期 provider 不属于 SEC canonical runtime。公开包不得因为可选 Evidence Provider 缺失而无法运行核心编译链。

## 6. 发布门槛

正式发布前必须具备：

- clean install test。
- Node ESM smoke。
- `sec --help`。
- `sec init` 临时目录测试。
- 最小 resolve/compose/verify 路径。
- package surface contract test。
- resource location test。
- license/dependency audit。

## 7. 与 Semantic Core 的关系

独立分发不是当前 v0.3 主线。IR 类型、Builder 和 Projection API 应保持无 Workbench/Next 依赖，这会自然降低未来 CLI 包拆分成本。

在 Semantic Core Foundation 稳定前，只修复已有 build/publish 阻塞问题，不以发布体验扩张打断 IR 主线。
