# 独立工具分发与打包规划与执行规格

> 目标：将 SpecEngineer (PJC) 编译器 CLI 从项目内置工具升级为可独立分发、全局安装并兼容 Node.js / Bun 双运行时的命令行包（`@spec-engineer/cli`），实现开发者本地及 CI/CD 环境下的快捷使用。

---

## 1. 终局形态与分发设计

独立工具将以 `@spec-engineer/cli` 的 NPM 包形式分发。

### 1.1 双指令映射
全局安装后，向操作系统注册两个可执行指令：
- **`se`**：SpecEngineer CLI 的缩写，供开发者日常开发和快速输入使用。
- **`pjc`**：与项目名称 Project Code (PJC) 保持一致，适合在 CI/CD 自动化流水线脚本中调用。

### 1.2 运行时兼容性
- **Bun 优先**：编译器大量依赖 Bun 原生 API（如 `Glob` 等）以追求极速，因此推荐在系统安装 Bun 后使用。
- **打包规格**：使用 `Bun.build` 引擎将多文件 TS 源码深度混淆/编译为单文件 `dist/se.js`，降低启动时动态加载的 IO 延迟。

---

## 2. 核心架构与决策记录

### 2.1 为什么不采用原生的 Git 多分支/多 Remote 强推？
* **痛点**：我们的开发文档（`docs/` 目录）和 AI / Vibecoding 辅助指令是私有隐私。如果在同一个 Git 工作区分支上通过 Remote 强推到公开库，Git 的 Commit 快照本质上无法过滤掉 `docs/` 文件夹。即使在公开库的分支上做 `git rm -rf docs`，其历史 Commit 日志里也依然残留所有 docs 文件的全部历史版本，随时可以被逆向查阅，造成隐私泄露。
* **决议**：采用 **“沙盒物理清洗 + 历史扁平化发布（Squash Snapshot）”** 机制。编写自动化构建脚本 `scripts/publish-public.ts`，由其自动在操作系统 Temp 目录下建立隔离的沙盒区，物理删除 `docs/`、`.claude/` 技能缓存、`.git/` 历史后，初始化一个纯净的单 Commit 仓库强制推送。

### 2.2 本地全局链接调试与热更新
通过 `bun link` 可以建立本地符号链接映射。当您在编译器代码库修改代码后，全局执行的 `se` 命令会直接热生效，无需频繁构建打包。

---

## 3. 已实现命令与自动化操作

我们已经在 `package.json` 中配置并实现了以下发布与构建命令，力求实现最简心智操作：

### 3.1 本地全局链接调试 (链接 entrypoint 直跑 TypeScript)
在根目录下执行：
```bash
bun link
```
执行后，您可以在系统的任意目录下运行：
* `se --help`
* `se init`
* `se resolve`

### 3.2 自动化隐私分发 (发布到公开仓库)
将本地的除 `docs/` 等敏感配置外的最新编译器代码，净化并推流至公开的 Git 仓库（`https://github.com/QzCrane/compliter.git`）：
```bash
bun run publish:public
```
该命令全程自动运行，执行完毕后会自动删除本地临时沙盒，安全可靠。

### 3.3 物理打包构建 (打包发布版 `@spec-engineer/cli` NPM 包)
使用 `Bun.build` 极速进行代码混淆、单文件合并，并输出到可随时发布的 `./dist` 目录中：
```bash
bun run package
```
* **输出产物结构**：
  * `dist/se.js`：附带 `#!/usr/bin/env bun` 头部的标准可执行 JS 单文件。
  * `dist/package.json`：自动剥离了 devDependencies 与开发私有 script 的发布级 `package.json`，包名定义为 `@spec-engineer/cli`。
  * `dist/platform/registry/official/` & `dist/platform/policies/`：随包分发的官方 Block 策略配置与只读规则定义。
* **发布流程**：
  在 `./dist` 目录下运行 `npm publish` 或 `bun publish` 即可发布到 NPM 官方镜像仓库中。

---

## 4. 升级路线与后续版本规划

1. **版本配置规范化**：当 CLI 工具功能成熟后，使用 `se version <patch/minor/major>` 命令自动更新 `package.json` 版本号，并同步更新公开库。
2. **多系统Shebang兼容性优化**：对于极少数缺失 `bun` 运行时的传统容器，可选择提供编译为 Node.js 兼容版本的 bundle，或提供原生 `pkg` / `bun compile` 封装的二进制免依赖可执行包。
