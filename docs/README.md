# SEC 文档

<a id="sec-文档先选择问题再进入完整机制"></a>

先确定产品范围与系统边界，再按问题进入子系统。本文只负责导航，完整定义、字段、算法与失败条件由各主题的唯一正文维护。

## 系统层

[产品范围与约束](产品/README.md)说明要交付什么；[总体架构](架构/总体设计.md)说明系统与环境、责任协作、状态与部署；[装配与实现接合](架构/装配/README.md)进一步定位模块、接口和生命周期。系统架构不隶属于某一个编译阶段。

<a id="系统的八个主题"></a>

## 子系统与专门机制

| 主题 | 回答的问题 |
|---|---|
| [作者](作者/README.md) | 工程含义怎样表示、组合、固定选择并持续修改？ |
| [编译](编译/README.md) | 怎样解释准确输入、取得合格实现并生成完整目标产物？ |
| [开发](开发/README.md) | 人、AI和工具怎样编辑、检查、协作与继续开发？ |
| [运行](运行/README.md) | 真实作用、权限、资源、结果和恢复怎样结算？ |
| [领域](领域/README.md) | 不同计算、状态、时间、关系和数值机制怎样精确定义？ |
| [信息](信息/README.md) | 工程内容、来源、版本、查询和保留怎样管理？ |
| [演进](演进/README.md) | 怎样扩展、实施、迁移、兼容和退出？ |

这些是文档责任，不规定同数量的进程、服务或产品模块。具体模型名称、协议字面量和表示格式在相应主题内定义；不从阅读到某个例子推定整个产品必须采用它的内部结构。

## 判断、范本与维护
