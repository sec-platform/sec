## D01 产品中心是意图驱动的工程生成

**当前选择。** AI/脚本是首期客户端，准确意图可以直接成为同一作者语义；已有定义、合同和缺省让使用者只提供本次真正差异。新算法、类型或工程组合仍可由开发者在同一中立源中定义，源码库不以“大意图”作为准入门槛。支持域内可以没有原生应用作者文件，原生接入仍是自愿的完整路径。

**机制。** 应用通过[I0—I8](../作者/组合/跨软件需求合同.md#11-意图进入同一作者源的完成与缺省算法)固定任务、解析范围、合并已接受条件、推导可得信息并处理委派；已有源按固定规则编译。自然语言的AI解释是一份可比较候选，不是从话语直接得到确定语义的魔法。语义投影、Binding和产物来源由工具维护，不要求作者复制意图树、AST或查询依赖。

**作者自由与实际职责。** 使用成熟定义时，短调用承载已经写清的语义；定义不够时局部具体化或写新定义；需要新基本含义才修改相应扩展。多个实现满足同一合同可以自动选择，不构成意图不精确。尚未决定的行为、缺后端、当前授权不足和未取得运行结果分别处理。独立请求确实约束实现时保留其真实来源，不制造同义需求副本。

**最强替代与代价。** 成熟语言和现成库可以同样简短，是公平基线。SEC必须在共同合同、多产物、连续变化、目标保持或诊断上产生实际价值；它付出前端、定义、映射、分析、版本及调试成本。只运行tsc没有完成这些新增职责；只积累官方模板也没有开放自由。先做全部未来语言、治理和人类IDE又会把无关成本变成前置，当前不采用。

**失败和重开。** 若新增普通算法要求改核心业务枚举、程序需要手修生成物、公开行为被无来源默认决定、模型每次重新搜索世界库或作者多维护一份相同事实，就修相交机制。完整冷暖任务和多轮维护收益见[生成收益](../运行/验收/覆盖与收益判据.md#必要性实验与生成收益验收)，未测不能宣称更快。不能以自然语言看起来短、输出行数、图节点或文档量认证成熟生态。

**任务和来源边界。** 只设计任务交付具体规格、取舍和未决，不自行实现或运行。当前新增协议的设计、实现、采用分别记录于[主登记](../状态/前沿与登记规则.md#已知问题主登记)。

## D02 中立语义与可替换作者表示

**实现选择：** 不把新的.sec文本语言列为产品前置或自编译种子。结构化意图直接绑定现成或新创作的原生实现；可选计算表示保留其语义但不要求重写已有算法。先TS或直接成熟原生供给均可，独立热点按同合同端到端成本升级。取舍是将语言生态与ABI适配作为真实责任，而非假装一套新语法能免除它们；相同成熟库下无意图收益的任务允许纯原生路径。详见[实现供给](../架构/实现供给与替换.md)。

**当前决定。** 产品采用**意图/Block定义、类型化边界、准确组合、合格供给与同源精化**。新产品以分片JSON结构直接承载作者含义，沿现有模块/锁/Definition机制进入编译器；不以创建新的`.sec`词法为前置。已有计算语义与`.sec`文本、原生源仍为被明确选用的作者/供给表示，保留其全部正确条件但不强制使用。这个采用是设计者基于当前约束作出的决定，不冒称用户指定了每个字段、文件数量或GUI。

### 目标、方案和成本的比较口径

先固定共同要求：已有定义能简洁复用；独特算法在支持域内能正常创作；同一份已定义行为能够生成所需目标；目标特性可准确控制；文本、管脚和任务投影回到唯一作者源；源码、配置、资源与持续修改共同管理。任意原生程序的全部语义在任意目标上无损转换，不是这些有限承诺自动包含的结论。

四项多语言承诺分别评价：多语言客户端能够调用产品；不同平台实现遵守同一接口；同一份受支持算法能生成多个目标源码；任意旧程序及其平台专有观察都能互换。普通框架可以很好地实现前两项，却不能仅凭API相同取得第三项；统一二进制运行时也不自动产生指定语言的惯用源码。目标缺少硬件、权限或可表达观察时，不能通过忽略要求制造可移植。

比较完整替代路线时，所有路线都允许使用相同成熟库、生成器、宿主工具与已有上下文，并计入各自前端、适配、诊断、维护及目标成本。“在既有两前端旁增加第三条”的增量成本，只能支持不无理由新增入口，不能证明从原点选择独立语言必然优于替代。既有设计投入是迁移成本的事实，不是永久采用理由；缺少运行收益也不妨碍现在根据硬约束选择结构方案。

### 方案空间与明确处置

下表区分改变根架构的替代与可以局部复用的技术；不是全部必须实施的清单。框架、编译器、编辑器、运行时和存储并非同一比较轴，不能让一个候选仅凭名称同时取得所有能力。

| 方案族 | 真正省掉或提供什么 | 决定性代价、边界与当前处置 |
|---|---|---|
| 原生源码＋AI／语言服务 | 复用全部宿主开发方式，适合已有工程与独特单目标算法 | 仍需保证修改正确；不是相同算法跨目标保持的完整替代。作为可选原生路径保留，不成为中立缺项的必选出口 |
| 普通库、框架与注解 | 高层调用减少重复，可利用宿主类型、循环、类和调试 | 普通回调可能不透明，宿主行为不能自动中立；在单语言范围可独立最优，但不替换本产品的全部可移植目标 |
| 宏、引用、受检宿主子集或编译插件 | 复用熟悉语法并取得可分析代码，减少构造器样板 | 捕获域、绑定、阶段、作用、错误与源映射仍要定义；仅有AST不是中立语义。可作为真实替代前端，不同时建立无消费者的所有入口 |
| 分阶段程序与编译型库 | 已知参数在生成期处理，剩余计算生成普通程序；有条件消除框架运行成本 | 构造期不等于目标期；需要实际语义与终止预算。采用这种机制，复用既有定义与方法，不要求普通用户手写生成器 |
| Typed tagless-final／多解释代数 | 可借宿主类型检查某些DSL，并为同一表达式提供求值、分析和生成解释 | 类型保持不等于行为等价；编辑、持久源、身份和错误草稿仍须具体表示。允许用于内部方法，当前不把所有作者内容改为组合器树 |
| 现有多目标语言与编译器 | 直接复用语法、类型、部分标准库与多后端 | 目标集合、数值／错误差异、源码形态、内部API和维护要匹配。作为整段基础或后端的强替代供给；没有相交核对前不宣布Fable、Haxe已直接替换SEC |
| 可扩展语言工作台 | 复用语言片段、类型和编辑设施，并让高层定义逐段生成 | 工作台仍需实现领域语义，可能有IDE、模型格式与运行部署成本。采用其分责方法，不复制整套MPS或强加人类画布 |
| 完全自研独立通用语言 | 最大程度直接控制统一语义、诊断和目标策略 | 语言、工具链、标准库与生态维护最集中；不能仅因功能覆盖多而采用。现有有限语义有责任，自研范围不能无依据扩大为全部未来语言特性 |
| 图／表／投影与无代码模型 | 对连接、状态、规则和局部差异可更直接 | 这是作者表示，不提供缺失的含义；全图展开可更长。按区域使用已有结构与文本，不建设第二作者真相 |
| 模板、产品线和领域专用平台 | 在稳定领域内快速生成完整功能或变体 | 超出变化点会参数爆炸或分叉；作为有范围的定义库，必须允许在同一体系局部写新行为 |
| 约束、逻辑与求解式合成 | 在明确候选与逻辑域内从要求求实现或选择 | 不完整要求可能有多解，求解有模型／资源范围；不能代替全部一般程序。作为可选创作或解析方法，不是每次构建前置 |
| 示例／AI程序合成与修复 | 生成此前未写出的候选，减少手工草拟 | 样例不能穷尽任意行为；接受结果须保存并校验，不在普通重建时重新猜测。采用为创作机制，不作为唯一确定执行器 |
| 可执行语义与元编译框架 | 从规则复用解释、分析、验证等基础设施 | 规则仍要写对，生成质量与工具支持要核；可以减少自研解释器，不能用一份规则表证明漂亮多目标源码已经具备 |
| 统一VM、Wasm组件与多语言运行时 | 复用执行、隔离或互操作，减少每个宿主的重复实现 | 二进制兼容不是源码生成；运行依赖、跨边界拷贝与目标权利仍存在。按任务可选，不设为所有制品的必需运行层 |
| 网络服务或远端动作 | 集中实现，客户端多语言容易 | 数据披露、离线、延迟与完成未知改变合同；不是透明的语言中立替代。只在任务本来允许时使用 |
| 内容寻址程序库与双向编辑 | 降低命名漂移、定位与部分同步成本 | 不创造业务含义，也不提供任意生成代码的逆变换。复用已有身份／修订／映射，不新建程序数据库作为前置 |
| 等式饱和、自动调优与搜索 | 在合法候选空间中选实现，避免某些局部贪心 | 等式适用性、成本模型和预算先成立；不能发现未表达的要求或证明世界最优。作为实现选择的条件性方法 |

成熟例证的限定命题由[来源目录](../依据/来源/设计依据与资料边界.md)拥有：MPS/mbeddr说明语言组合及多阶段生成并非必须从所有语法开始自研；LMS/Terra说明框架可在生成期消除而非永久留在运行时；Fable/Haxe说明现有多目标编译器是完整替代类别；WIT说明跨语言接口不等于行为语言。它们不被直接采用为新依赖，也没有取得SEC任务收益或符合性证据。

### 为什么选择编译型定义体系

在原目标不降低的条件下，普通运行框架不足以单独承担独特算法的共同语义与多目标生成；固定模板不足以承担开放定义；一个统一VM不能替代所需目标源码；纯自然语言执行不能提供固定重建。将这些不足全部补进任一方案后，会重新出现程序定义、解释、转换、版本与编辑责任。因此选择直接承认这些必要责任，并复用成熟供给，而不使用“不叫语言”隐去成本。

当前产品差异集中在已有需求复用、可分析的高层关系、局部精化、全资产与持续修改。普通循环、调用、对象、内存并非产品必须重新发明的卖点。已有`.sec`合同保持为当前有限实现规格；对它能合法降低或委派的部分优先使用成熟工具。要由现有完整编译器接管一段责任，先核其输入语义、输出类型、环境、诊断和可维护接口；不要求作者先改写两份源，不增加第三条无用途作者前端。

这不是独立语言已经证明优于F#/Haxe等的裁决，也不是把产品改为某个宿主的附属库。当前架构选择已定，具体依赖只有取得相交资格才绑定；缺依据的整段替换继续作为真正的技术选型问题，而非已完成事实。有限语义的实现可以沿现有方案开展，不等待全世界工具比较结束。

### 作者抽象的当前质量裁决

**选择对象同时包括作者成果与开发操作。** 产品作者保存准确意图、Block定义及必要组合/实参；工具在其上产生局部修改、检查、实现选择和产物。动作少不能替代作者抽象，源码短也不能替代实际维护范围。现有[操作协议](../开发/需求到交付主链.md#intent-to-product)继续服务同一源，不改变该源的层次。

**原点比较。** 纯自然语言直接执行不能提供当前要求的固定重建；普通单宿主框架不足以单独承担支持域内的单源多目标源码；通用图／block能够保存关系但会给简单表达式增加定位和节点操作，类型化端口不能替不同领域的行为；强制完整文本虽然通用，却会让已覆盖任务重写无关内容。当前选择保留一份源及多种既有的精确动作，从任务事实确定最小合法动作；不是同时建设多套语言。

**为何当前采用直接结构入口。** 已有`sec.author-module/1`和Definition语义可以承担准确身份、组合与绑定；结构解码不用先实现一门新文本语法。JSON有重复键、类型和引用检查成本，机器封装可能比短文本更长，因此工具维护机械字段，普通操作只提供标签、参数和局部差异；不能将持久字节变多冒称作者负担更小。成熟文本/模型前端将来可按同含义、总成本及保持范围替换，但不无理由同时增加第三条真源。

**组合的准确地位。** 复合定义还能继续组合，是保留的机制；它既存在于普通函数和模块，也可以由管脚投影操作。SICP的组合闭包支持其可行性，不证明每个运算都应出现在全图画布。当前把Block作为封装和组合主结构，并不规定所有领域只有一种调度模型。没有合格实现的方框不是功能；把函数改称block不消除语言与库工作。内部模型也不能因为统一命名而丢失顺序、身份、借用、时基或错误。

**必要自研与无必要重复。** 必须定义含义，不等于必须自己实现其全部计算；必须有实际实现，不等于必须维护同义`.sec`主体。当前选择保持既有中立前端，但把成熟供给的直接绑定放在“重写一个缺失的SEC库”之前。通用检查、目标映射、真实差额及跨产物变更是SEC的相交责任；排序、容器、编解码、数值库、运行时和包解析在合格范围内交给成熟供给。新业务通常新增私有组合或参数，不新增核心Case；独特行为才需要真正的新算法。

**实际代价与替代。** 本方案仍支付中立前端、语义映射、必要库合同、诊断、源保全和目标适配成本。薄适配也可能引入复制、初始化、失败和依赖，不能被称为零成本；只有同名转发且无独立合同的层优先删除或改为绑定/别名。直接适配整组共同规则可以减少重复，但方法例外和跨目标缺口仍要说明。相同任务在成熟语言和同等库中更便宜时，该工程可以走原生路径，或者替换相交编译供给；这不自动撤销全产品中立目标。当前没有总成本胜出的实测依据，不能把短投影、算法范本或更多图库当成替代。

**反转条件。** 当前动作对已知源仍需额外查询；高层修改隐含改变其余要求；源与图双写；新库迫使每次改词法；整个产品缺正常目标生成；更小的成熟供给在完整合同下成立。出现这些具体证据就重开相交选择。用户提醒研究block或SDK只提供比较对象，不计为支持采用的证据。

### 当前选择已经怎样改变成品

采用成熟供给不能只停在封装准入表。成品以作者ModuleRevision与ImportedModuleView共同链接；UseBinding在实际使用点与目标下区分源主体、外部调用和生成方法；无作者body的已合格根仍可生成；目标组合器汇合真实依赖和成员。原有Host桥接仅服务明确的port消费者，不再作为普通库调用默认。完整数据和算法分别由[物理实现](../架构/装配/源绑定与解释映像.md#supply-physical-layout)和[编译主链](../编译/内核/编译值服务.md#supply-aware-compile)拥有。

这增加的是原规则需要的内部联合和接口分支，不增加作者语言或永久供给平台。删除的强制工作是镜像算法、假body和无差额Host包装；保留的成本是准确调用、边界适配、目标依赖与真实资格。现有框架直接调用同一API也可以很短；本方案仍需在多目标、精确编辑和完整资产上取得增益，不能把标准库收益算成SEC独创。

### 一份源怎样同时简洁和开放

普通作者定义仍可以是声明、参数、主体与必要合同，也可以引用已有完整合同和实际供给，不强制补写主体。使用者调用它；确需新算法时在同一支持域写普通函数；同一AI可以承担两种角色。参数、公共要求、捕获与错误不要求再抄成意图树。一个函数没有专用编译规则时，正常编译其主体；有高层优化价值时，已授权的方法按确切定义身份与条件提供特化。完整处理由[可编译库路径](../作者/组合/模块封装与复用库.md#普通库与编译型定义的共同路径)拥有。

分阶段处理只把真正固定且可安全计算的部分提前；动态值留在目标程序。类、虚表、调度器与运行框架只有目标确需时保留，不将整个开发平台生成到每个工具。特化失败、超预算或方法缺失时，能满足原要求的普通主体继续可用；普通主体不满足硬实时、布局或内存要求时，不能以有结果为由偷偷回退。

文本和管脚是同一程序的操作面；结构编码不是每次请求的必填树。修改参数保留原定义；局部特殊化建立明确的私有定义和上游基础；全库语义改变更新真实消费者。目标代码的反向修改仍受准确映射限制，不能假设所有优化都有唯一逆。

### 已选控制与自造语法的真实取舍

这项计算表示的选择不宣称没有语言责任，但也不是所有产品必须采用新文本语言的计划。当前结构需求主面与可选`.sec`计算画像分别承担自己的精确含义；选择计算画像的任务用普通定义/实参创作、用局部差异修改、用类型化控制固定必要目标，见[实际控制协议](../作者/需求关系与能力边界.md#作者实际控制什么以及唯一修改入口)。需求没有现成定义时，由开发者或获准AI写足以决定行为的普通主体；不能只留下一个高层名称，再要求编译器猜算法。已有定义覆盖的任务不重写这些主体。

自造语法能够用直接的条件、调用、资源和领域构造消除某些宿主构造器噪声，统一词法与诊断，也能避开特定宿主对引用/宏的限制。它不会免掉语言的作用域、类型、效果、阶段、控制、资源和后端保持；也不会自动得到需求复用、所有目标实现或成熟生态。嵌入式前端能复用宿主工具，但受到实际捕获范围与解释接缝约束。比较时必须同时计入两边消掉的责任与新增责任，不能将“新语法更直接”扩大为“整体一定更简单”，也不能将“有自己的词法”本身当失败。

因此当前使用直接源，不增设逐运算s.call/s.choose前端，不把目标控制另写成属性语言，不为避免新语言而强迫所有需求进入普通运行框架。第一条基线仍是现有有限语义与直接TS目标；普通主体先正确编译，专用特化按有依据的收益增加。现有编译器若通过同一输入语义、输出、诊断与成本核对，可以替换相交供给；未选替代不是每次生成的前置搜索。

特殊需求从公开参数到组合再到私有源，是表达深度的变化，不是三份同义模型。一个调用的行为例外与保持含义的优化分开；共享类型和资源可能使其影响不只一处，必须诚实展示。源与元数据共同管理不同独立决定，不要求一份程序只有一个文件，也不容许相同属性存在两个竞争写源。

### 简洁作者形式的当前选择与代价

在已选择的计算画像内采用普通函数引用、被动lambda、有限返回/参数推导和确定导入别名，继续同一计算作者源，不把这些机制抬成产品结构主面的前置，也不新增通用DSL或嵌套作者SDK。理由是这些操作直接消除重复签名与转发样板，同时能复用现有TypeStore、函数值、CST、CallableIndex和目标降低；没有省掉独特行为，也没有改变保留原生源的路径。

代价是读取器真实新增省略规则、签名补全顺序和公开函数值根；它们必须一并落实，而非只改示例。递归、身份函数、模糊名义字段和不稳定捕获采用局部显式约束，不许用Any或任意全称泛化换表面短小。计算函数的默认实参、占位参数和新流水线语法不由这份有限合同提供；已有lambda/普通调用承担其已选功能，扩展需补求值、绑定和编辑责任。结构化需求参数已经具有闭合`default`，与此不是同一个机制。

改语法必须同时保留唯一源：展开用于分析与阅读，不自动保存为更长的程序。成熟语言同样能提供函数值与推断，比较时允许它们使用这些能力；本选择只对消除已确认的重复作裁决，不由此宣称作者总成本已经优于所有宿主方案。具体规则与反例归[简洁作者合同](../领域/计算基础/紧凑表示与程序范式.md#compact-author-contract)。

### 需求的共同形状先于具体业务词与文本长度

当前进一步明确：作者抽象包含对象域、结果/结构/轨迹关系、保持帧、条件及真正的决定，不只是把函数签名写短或给业务换一个库名。既有Requirement与CompletionView承载这些相交内容；共同组合逻辑和领域叶语义分开，不新增作者语言或全世界需求原子目录。直接文件修改仍是正常方式，表/图/状态投影只有具体帮助时使用。

采用理由是同一套“映射并保持”“条件下只发布当前修订”“维护逆关系”能够跨软件复用，同时保留文件身份、命令义务和图基数等区别。更小的纯参数库足够时不强制加入完整约束树；普通编程和现成框架享有同样抽象，SEC的独立价值还须由可靠绑定、连续修改、相交编译与资产保持证明。仅增加通用节点名称不算这种价值。

不采用两种极端：为每个商业名字写一套核心机制；或把全部软件压成一个无语义的万能转换/状态图。检查方法与需求分开，防用当前方便验证的性质替换原要求；语义字段、变更规则、具体实现供给与全链消费者必须共同存在。完整合同见[跨软件意图](../作者/组合/跨软件需求合同.md#cross-software-intent-contract)。

### 成本、反例与重开条件

最低限度先筛硬要求，再比较有依据的开发投入、作者独立决定与持久内容、诊断修复、目标源码质量、冷暖构建、运行内存、依赖、长期迁移和退出。不把这些不同量纲相加成任意分数。包装层数量、关键字数、图节点数和首次短例不能代替完整任务比较。

必须攻击：相同库在成熟语言中已经同样简短；一个微小特化迫使重写整个模型；普通函数需要先注册编译插件；泛型主体被执行成任意构建脚本；生成优化改变回调失败顺序；共享表示泄漏原生目标语义；新库升级使局部派生丢掉修改；内部可重复而目标源不稳定；一个目标缺特性导致全项目失去可移植资格。

现有多目标编译器若在承诺的值域、错误／效果、目标源码、编辑与完整成本上满足要求且更小，接管相应基底或整段后端；必须按该方案自己的成本比较，不计为额外第三前端惩罚。若真实需求只有单目标且没有独立中立生成收益，普通框架可成为该目标工程更好的实现，不将平台价值强加于它。若只有新原语才能保留接受的观察，允许有范围地增加语言责任。它们改变相交选型，不自动撤销全资产、AI优先或原任务。

**明确保留的底线。** 当前方案仍包含语言与编译器；不存在仅靠换名就消失的语义责任。能简化的是重复定义、机械结构、特化样板和后续同步。任意独特信息仍须表达或明确委派，不能承诺全部程序比使用同等库的成熟语言更短，也不能将未运行的设计判断包装成总成本最优证明。

### 当前语言深度与双向维护的取舍

对于已选择的原生维护与计算校准任务，先兑现TS原生文本/成组维护和受管目标回源；新产品主线仍先闭合结构化意图及供给接合。Java按已接受范围暂缓，其他目标没有固定排位。C/Rust及其他语言是例举的供给类别，是否采用要从真实新增要求判断：已有调用、源维护、目标源码、二进制、ABI、设备或资源分别评估。没有新缺口时继续当前能力，不为了说明“语言中立”自动增加一个后端。

C能暴露原生ABI，不证明它必须是下一工作；Rust的所有权机制有价值，不证明其跨边界全部安全；某个动态语言也可能承载成熟原生数值实现。选型先筛任务和交付合同，再比较合格路线的完整成本，不按“更底层”排永久名次。条件范本保留的是接口知识，不是排程命令。

当前原生源码仍可直接维护；中立高层定义与实际已有供给不必有同义算法主体。源内容可以表达需求关系而不指定循环，普通程序保留独特行为的自由。例子使用低层语法不能据此把所有目标工程降成低层作者过程。

强逆向的当前价值包括读取现有工程、保持来源的修改回写，以及无来源时提取有依据的行为/高层候选。源原文和心理意图可能不唯一，不构成取消后两项的理由。也不能以某个局部函数的等价恢复，承诺全部二进制的原始工程已经重建。恢复算法和范围由[原生观察](../开发/原生维护/导入观察与原生资产.md#recovery-purpose)拥有。

### 有限逻辑组合为什么直接保存在结构源

当前选择给原All/Any/When/ForEach/Exists精确JSON体，复用现有引用、主体和模块，不让产品作者先手写实现算法，也不发明另一套文本关键词。只有静态、有限且有准确类型的输入进入直接条件与量化；运行、无限集合和更广关系仍由领域语义承担。这样可直接描述产品变体、共同参数和有限候选，代价是读取器必须实现词法绑定、空域、分支类型和作用域检查，不能把JSON可解析当成全部支持。

全部展开成平铺叶项会丢掉共享约束和见证位置；全部展开成析取范式可能产生巨大中间状态；只保留高层标签又无法据以实现。因此采用保留公式与作用域的有限工作表，按需要扩展，允许保守相交重算。嵌套数量不是任意规定的固定禁令，实际资源预算限制工作并返回未完成，不改掉原需求。

偏好默认在共同范围内评价，有限any/exists内禁止直接或通过use隐藏prefer。另一种方案是给每个分支独立评分，但没有跨分支统一度量时，候选可通过删掉目标获胜；故不把这种行为当作默认。需要真正的条件目标时，允许已固定产品配置决定目标，或另行给出有共同口径的评价定义。未知高优先指标不通过比较次一级被偷偷忽略；稳定选定可行者仍然允许，但优越性声明另受证据约束。

该选择没有采用Alloy、SyGuS或SemGuS作为必装引擎；相关材料只校准量词、统一合成目标和证据边界，见[有限逻辑与合成依据](../依据/来源/证明类型与编码.md#finite-logic-synthesis-sources)。若实际领域需要不能表达的主体值、动态成员或概率条件，重开其领域接口与方法，不以已有有限范本代签全能力。

### 作者成品与闭合默认的取舍

结构作者源承担独特行为和公共消费边界，不要求每个产品重写底层实现。显式default仅补闭合value参数，减少多处重复固定同一名义策略；它不同于运行函数默认、软优化偏好或隐式环境读取。保持全显式参数的旧写法合法。拒绝更强的相互依赖默认、subject默认和深合并，代价是某些关系仍需明确复合；收益是作用域、主体独立性和升级含义可直接核查。若频繁需要封装仅为计算默认，应重新比较有限依赖默认的真实成本，不直接开放任意执行。

exposes解决一个需求定义含多个同型主体时的公开边界问题。它不复制签名、不分配运行对象，也不为每个表达式建接口；目标仍消费实际合同。不开新字段而靠“取第一个subject”更短但不稳定；强制所有项目套一个Workbench根类型更整齐但改变产品。因此选择局部可选边界与画像准确映射并存。两项属于当前未发布结构编码的明确补全，不宣称所有旧读取器自动支持。

[成品范本](../../examples/成品形态/README.md)用同一关系检查不同消费条件，不用六个包装名遮住六组实现义务。全形态路由不等于所有领域都已完成，真实差额和未知继续按所属U保存。

## D03 需求与实现源分离

**选择与正向机制。** 需求规定接受的行为，设计给当前机制，源码定义具体程序，证据只支持实际对象。原任务与当前候选通过精确引用关联，可以来自同一作者文件，不重复保存函数体。编辑require/ensure、独立案例或要求源时，服务分类差异；实现编辑不自动移动要求接受关系。取得相应委派的目标变更可以一起采用，不强迫普通开发逐次人工批准。

候选自身的类型和编译保持，分别于原要求满足、实际部署和用户效果判断。[任务满足流程](../运行/保证/要求证据与裁决.md#原任务要求与候选合同的满足判定)从接受输入、结果、保持与环境逐项连接实现和方法。源不完整可以保存；生成所选根需要有实际主体或合格绑定。增加拒绝guard可以保护非法调用，但若拒绝原承诺合法的输入，就没有完成任务。

**必要区别。** 函数值通过高阶传递仍保留自身契约入口，普通函数类型不复制其全部行为；纯度不保证终止。前后条件的定义域和求值顺序要检查；互证需要合法推理规则，不因相互引用获得独立证明。后置失败不撤销既有作用。消解检查时把真实依据加入产物依赖，失效后重新判断采用资格。

**成本与更小替代。** 直接要求生成一个给定函数时，以该源为语义输入，不建立镜像需求文件或全域求解服务。有独立用户要求时保留其原来源，细节可由已有上下文推导。详细规范可以长，AI请求仍只写相关变化。保留运行检查可能更易实施；静态消解需要对应保持依据，不能单凭更短源码决定。

**反例与重开。** 收紧前置排除难输入、将后置改成恒真、删除独立验收、只验证新候选后反称原需求已满足，都要求回到接受关系和满足判定。真实任务有意改变时允许形成新要求，不为维护旧结果阻止演进。具体语言规则仍由[契约执行](../领域/计算基础/文法类型与求值.md#行为契约的执行与证明责任)和[函数值合同](../领域/计算基础/文法类型与求值.md#高阶调用中的契约不能丢失)拥有。

## D04 类型化能力端口

**选择。** 类型化端口用于有相应语义的连接分析和编辑；既有定义可经公开合同组合，产品作者直接复用Block而不展开实现。这个主结构不要求普通函数逐运算形成节点、不要求画布或每项需求先手工分块。私有算法可普通编译，满足条件时消除组合边界并保留来源；不新增运行实例或部署单元。

**正向机制。** [组合合同](../作者/组合/定义与接口.md#block-composition-contract)定义外部参数、结果、效果与保持，内部由原函数／区域或领域结构保存。调用、事件、流和资源按实际类型、激活、顺序、错误、寿命与基数解释。参数修改、一级展开、完整表达式抽取和内部值暴露使用[共同编辑](../作者/组合/结构编辑与身份保持.md#block-boundary-edit)，不另存一份可独立写入的展开图。

**实现与公开的边界。** 底层语义要由普通主体、成熟库或合格后端真正实现。调用者不必读取私有循环，但必须知道自己依赖的输入域、结果、失败和作用；摘要不够强时，工具按实际权限分析或保留缺口。复合外壳没有实现，不算功能完成。公开边界不把所有内部旋钮变成参数，新增可控制点要有消费者并保持未改使用点。

**代价和更小替代。** 已知文本直接edits更省，现有函数已有适当边界时只折叠呈现，不再次包装。结构协议只传当前变化；普通局部值不领取全局端口身份。资源管脚仍遵守move/borrow、分配者、接受点和回调注销；零复制需要别名、旧值读取与生命周期条件，不满足时采用合格复制。GUI不是AI首期前置，也不能把管脚永久降为只读装饰。

**反例与重开。** if内除法外提、两次发送合成一次、一次采样被重复、流自动广播、两个同配置会话被合并、资源重复消费、旧回调修改新代、无限结构展开，均须改相应具体合同。数据边不是权限，折叠不是无依赖，合法递归不是必然死锁。数据库同名API但隔离或失败不同仍不兼容；普通纯任务不因此承担数据库前置。领域自动抽取尚无保持规则时保留明确范围，不用“都叫block”伪造跨域同义。

**依据。** 复合过程可按同类过程使用，支持递归封装；异质actor的内部执行机制需要明确边界，支持不能将全部图边解释为同一种调度。来源见资料章的SICP与Ptolemy条目。当前不复制Ptolemy运行时或director体系，成熟具体实现仍在合格范围复用。

## D05 公共数值与目标语义

**选择。** 数值、Text、容器和相等具有自己的值域、错误、顺序和观察合同；后端及逻辑求解器不能用同名类型替换。数学Int、定宽、定点和原生数值分别适用；公共Text是Unicode标量序列，不被某个String实现的字符表限制。

**机制与代价。** 源到目标、源到证明均采用明确编码：负商余需保持截断规则；完整Text用合格标量序列模型，只有证明了受限域才可用较窄String理论。相等不能只看哈希；有限值允许物理共享，但逻辑序列化预算要考虑展开大小。多目标可能引入运行库、适配和检查成本；单目标可选显式原生画像，不能暗中缩窄公共含义。

**替代与反例。** 直接采用宿主类型最省事，却会在大整数、NaN、负零、Unicode范围、错误哨兵及别名上改变行为。不可映射时可换证明方法、限制该目标或保全原生，不阻断所有设计。新增规则或目标改变观察域时重审对应绑定，不凭任意epsilon忽略差异。具体规范见[值域](../领域/计算基础/通用计算与任务语义.md#值缺失与数值)、[逻辑编码](../运行/验收/方法与独立证据.md#契约到求解器的语义保持)与[目标映射](../编译/目标/具体降低与领域输出.md#中立语义与目标表示的逐项映射)。

## D06 多入口共享语义而非同一文本文件

**选择。** 当前文本和结构是作者输入，表格与管脚是按需投影；一个区域只有一个实际写源。新增宿主前端需先按D02改变采用决定，不是当前并行必做项。当前基础体`sec.semantic-body/1`可直接进入共同分析，既不强制先打印`.sec`，也不把JSON格式当成天然完备的程序语义。

**机制。** [基础体与编辑规范](../作者/组合/结构编辑与身份保持.md)定义局部键、绑定、类型、区域、草稿和三个精确操作；[区域迁移](../作者/工程源/清单模块与绑定锁.md#作者方式切换是一次明确的迁移)保全原内容、未知和谱系，再转移唯一写权。文本CST回写比较真实绑定与增量，不只比较打印后类型。无操作原字节保留，结构产生的源码如果没有原文补充只承诺规范输出。

**代价与边界。** 两种前端、节点和源补充需要真实适配。未知类型、原生语义、编译标注和错误节点有保全责任，支持一个基础函数体不意味着支持全部领域。缺适配时保留原源并允许已闭合局部继续，不强制转成原生，不用最后有效AST覆盖新草稿。没有真实身份映射的独立创建仅能比较相应含义，不取得共同作者谱系、权限或同字节布局。

**客户端与成本。** AI/脚本首期不增加GUI门槛；后续客户端有自己的交互验证。短ID可能增加查询往返，完整树又增加输入；按任务选择真实片段。画布坐标默认无程序作用，具有空间语义的领域另按其规则。上下文失效不换latest；图文各自保存一份或者任意整文件重印，都是需要修正的竞争作者。D33仍为历史载体别名，D41负责公共模型与前端依赖方向。

## D07 混合工程表示

**裁决。** 混合工程是可支持的画像，不是每个工程的默认义务。中立全作者、既有原生作者和受控混合均使用同一身份、要求、依赖、变更与证据规则；具体入口不会自行扩大权限。原生作者、提供者内部实现、生成的原生源码、知识未知四者不能合成一个“原生区域”。

**机制。** 每个区域一份作者源，解析结构与展开树派生。中立源可以表达全部受支持的应用行为，依赖的普通库由提供者或后端维护；原生作者只在实际已有资产或用户选择下启用。观测类型/签名不重复填报，业务要求也不被当前实现自动覆盖。多目标保持按每个区域真实语义与绑定判断。

**替代和代价。** 强制全迁写会损害存量连续性；强制混合会让每个复杂需求都被推回原生；两份源双写会漂移。选择按责任使用，但对中立生成缺项明确是语义、目标、实现还是环境不足，不默认让作者另写宿主代码。

**反例。** 无原生文件就不能创建工程；系统使用数据库驱动便宣称应用非中立；中立文件自动获得保证；原生函数永远被当黑箱；接管生成物后仍宣称旧模型无损重建。出现任一项都应修相交规则，而不是强迫所有项目采用同一比例。

## D08 保全式导入

**采用方案。** 先在真实许可范围捕获字节与覆盖，再解释内容；原资产保持不变。源只读取一次的捕获内容供解析、摘要和生成共用，避免阶段间重新读取活动路径混成不同输入。

**具体处理。** [观察协议](../开发/原生维护/导入观察与原生资产.md#从输入范围取得可用快照的正向协议)定义层选择、固定版本、弱读取/强快照、阴性回答、编码和发布。未理解文件作为不透明资产保全；无读取权、失败、未完成和精确不存在分开。统计性“未见”不能作为创建或去重的强前提，目标提交仍重新比较。

**替代和代价。** 原构建执行可以取得更多行为，但它是获准后的实际作用，不是普通导入的隐式步骤。不可变树或宿主快照更强但有能力/存储成本；弱捕获适合较小保证，必须保留其范围。已有固定输入直接复用，不为所有片段引入全仓观察。

**验收与重开。** 合法读取产生可解析内容和真实覆盖；权限错误不能变absent；读后变化不改写旧输入；捕获树不是原工作区原子切面；所有后续写回仍核对前像。发现其中任一错误就修观察或消费者，而不是删除原资产。

## D09 渐进语义提升

**决定与机制。** 在已有代码上需要高层编辑或移植时，只提升有保持规则的构造；对业务意图的推断形成候选，不作为已证语义。原生区域按任务需要逐步提升，跳过某层时仍承担该层原有的约束，不要求所有输入经过完整IR阶梯。

**取舍与反例。** 保留原代码及类型化不透明边界是更小替代，但可编辑的公共含义也较少。同名函数不能据此认定同一责任，动态外部调用不能漏掉，未知区域不能被模板覆盖。需逐语言维护规则与兼容关系；收益不足以覆盖维护成本时停止该项提升，不停止其他已成立路径。支持的回写必须经过相应映射与保持检查。

## D10 本地身份与来源对应

**选择与机制。** 稳定实体身份、可变显示名/路径、内容修订、类型合同和物理对象分别使用。默认在固定分配域内创建实体ID，移动或重命名不自动换ID；旧对象删除重建、独立复制需要新身份或明确映射。Git分支/克隆同一作者谱系可以保留语义身份，但不复制运行权限和部署控制实例。

**取舍与反例。** 外部协议确以不可变地址定义身份时采用它的合同；内部临时AST无需全局ID。身份索引与歧义处理有成本，不能按名字合并同形对象，也不能因ID相同把不同单位、版本或资源实例的类型直连。路径仍影响导入/反射时跟踪真实依赖，稳定ID不是行为永远不变的证明。

**规范与重开。** 见[身份](../作者/工程源/身份断言与采纳.md)、[类型实例](../领域/计算基础/通用计算与任务语义.md#类型与包实例的身份)与[副本分支](../作者/工程源/清单模块与绑定锁.md#副本分支与权威重建)。ABA误合并、分支误发新ID、复制控制器恢复旧权或类型锁无法闭合时重算对应边界。

**文本续用的具体选择。** 通过精确base与编辑关系保持声明身份，只持久化必要的声明映射，不复制整棵AST。外部改写有歧义时保留内容和候选映射；相似算法不能自动签发旧身份。对应的局部诊断比“全部ID写进源码”更轻，比“完全不保存映射却承诺不丢身份”更诚实。

## D11 多层 IR 而非万能图

**当前选择。** 具有独立语义、不变量与真实分析/降低消费者时采用相应表示；同进程优先共享不变结构与引用。作者区域保留唯一源。AI的任务投影只选需要的内容并借原源回写，不因显示更短增加ContextIR或第二份精简源码。

**边界与机制。** 连续、概率、单位、时间等语义在其领域保留，不能压成万能整数节点；普通整数程序又不加载这些未选画像。原生单语言工具可以直接消费自己的AST，基础CST用于原文补充。只有第二消费者而没有独立含义、变换或成本收益，不足以建立新层。[表示规范](../编译/表示/表示族与跨层保持.md#完整源与ai任务投影的分离不增加ir)定义该关系。

**替代与反例。** 全部放进一张图容易混合状态与权限；每个DTO变成IR又增加重复转换。投影省略的原文不得被压缩摘要覆盖；相同显示不代表相同语义键；把byte压缩当模型认知压缩没有消除需要理解的含义。无独立不变量的层合并，未使用阶段不物化。

投影的作用范围、往返保持与实际实现分别判断；结构可读取不等于任意表示可以无损互转。

**语义分组不等于平台分组。** 合同代号、库入口和body编码分别定位；共用一套模块、类型/效果和方法分发。对象实例、窗口和tape必须保留不同寿命，但不因此建立三个开发数据库。仅增加名称而没有新的不变量或消费者时，沿原表示和接口复用；需要新节点则使检查/降低合同可检查，不只加通用property袋。MLIR的方言是类型/操作等的组织机制，采用这个区分不要求动态插件基础设施成为首个本地实现的前置。

## D12 目标闭合与输出模式

**选择。** 输出根可以是闭合表达式、上下文区域、完整函数、模块或工作区；依赖模式、源码形式、完成度与验证阶段分别表达。一个完整满足请求的函数不因为没有项目目录而叫局部失败。临时单位和正式工程共享身份/定义/绑定，不为片段另建编译器。

**机制与代价。** [单位输入](../作者/工程源/清单模块与绑定锁.md#片段函数与工程使用同一输入合同)闭合自由引用、类型、控制出口和实际规则；[目标源码策略](../编译/目标/成员布局与完整产物.md)只产生必要结构。片段检查可能需要虚拟外层，必须标记其假设；真实插入还要核对当前宿主。更多输出形态增加边界检查，但不增加每次调用的控制设施。

**替代与反证。** 一律完整项目扩大固定成本；任意字符串加函数壳会改变return/this/捕获；按行数认定可编译没有语义依据。简单调用允许仅返回代码；有外部依赖时不能把“短”说成“自足”。当非闭合区域被报告为完整可运行，或小函数必须创建数据库时，回到输入与输出合同修改。

**产物主体。** 同一候选可以有多个目标，源类型检查不选目标也可进行；目标cases和write-output始终携带明确artifactRef。多一个引用是用来避免同一请求因缓存数量变化而换含义，不要求AI手填产物摘要。

## D13 局部源码编辑与往返

**当前方案。** 精确源基础、对应语言/CST、声明和出现映射共同定位修改。字面量和名字先改token；表达式变化选最小可保全容器；联合修改一次重建候选，再解析并检查Δ及保持范围。完整算法见[CST回写](../作者/组合/结构编辑与身份保持.md#从语义改动到文本字节的确定回写)，公共坐标与跨语言往返仍由[原转换合同](../编译/表示/编辑与受管回源.md#编辑往返的具体合同)拥有。

**为什么这样选。** 字符串替换可能捕获错误绑定且类型仍通过；完整AST重印又会丢注释与格式。需要位置补充和绑定判断，但无需每个临时节点持久化为全局ID。rename先模拟新环境；公开名、具名参数和真实反射消费者另判兼容。形参重新排位置，不重排实参原求值顺序。

**更小路径与异常。** 普通原文编辑可直接提交；结构输入可保存完整但有错误的草稿。协议无效/越权/句柄陈旧拒绝，适配不能保持则给整区域候选或回源途径，不自动接管生成文件。只支持完整函数时限定范围，后续有真实消费者再扩细，不永久禁止片段。

**反例。** 区域外移动return、捕获this改变、getter重复求值、局部改名形成捕获、来源多对一helper却只改一个上游，都不能靠精确行号解决。目标源码映射仅说明来源，不承诺任意逆向唯一。未保存缓冲、未知扩展和BOM/换行保持；格式化是显式变更。

**当前具体实现选择。** 使用原文/CST保存非语义信息，以精确生成基础、目标差异和EditCorrespondence执行写回；旧源与当前源三方合并后，再生成核相交等式、绑定和保持范围。source map只导航，不作为逆函数。可维护TS目标的常用编辑是当前交付义务；发布优化有损时显式保留来源或限制该产物的逆向范围。详细数据和I-R0—I-R8由[往返规范](../编译/表示/编辑与受管回源.md#managed-edit-roundtrip)唯一维护。

**代价与替代。** 保存必要补充占用空间，限制某些维护目标优化，写回规则需要单独实现。直接修改原作者仍是更小的正常入口；对无来源原生文件直接维护也合理。它们不能被用来取消已经承诺的受管目标常用编辑。没有独立需求时，不为任意宏、动态脚本或优化机器码建立假全逆变换。

**直接编辑与最小额外步骤。** 已有文件和缓冲是正常作者载体；源捕获、候选和固定编译是工具内部责任。普通作者修改无需generated-edit，更不逐次执行全编译；受管目标回源必须核当前相交对应，允许必要再生成但不扩大到构建/运行。原文已被外部合法保存时无需为走协议再次apply，检查失败也不删除作者工作。

**无来源恢复的更强可用性。** 原native维护之外还可以提出高层候选，并在准确机器/语言模型下验证相应行为。不能仅因目标存在多种可能源就拒绝一切行为恢复。准确重建、解释候选和新需求采用分开，多个相容候选按受委派目标选择而不谎称历史唯一；相应代价按真实恢复目标进入。

## D14 精确或保守的增量依赖

**选择与原因。** 先有正确完整计算，再按实际收益复用；正读、负读、成员、解析、规则选择和控制输入均属于可影响结果的依赖。受控完整动态读取可用，抽样追踪不能冒充完备。查询查找键、实际求值键、输出内容与证据资格分开，完整诊断可缓存，超时/OOM/取消不是语义无解。

**删除与同值。** 不变单调规则的正增量可从旧固定点传播；删除支持或改变规则默认从受影响新组件的底重新求解。A/B循环去掉唯一外部种子后，旧值互相支撑不代表新的最小解；朴素计数也会漏掉这种假支持。结果相同仍要更新本次依赖与来源，才可截断只关心值的下游传播。详见[删除固定点](../编译/查询增量与性能.md#删除递归事实与重新求固定点)。

**替代与代价。** 整程序查询或整组件重算是可用的小实现；符号级索引、删除推导和分布式缓存只有实际收益才启用。影响选择/近似的预算入语义，纯执行限额不强制破坏完整结果复用；有外部作用的失败不盲重跑。

**隔离与重审。** 同内容不等于同读取/执行/披露权。缓存不承载权威状态，关闭它只能改变纯计算成本。漏边、旧递归效果不消失、分支换来源却保留旧读集、跨租户诊断泄漏时扩大依赖/隔离或禁用相交复用。全量对照仍是其输入范围内证据。

**全工程落位。** 同文本不同项目/锁出现可共享解析而不能合并名义语义；同中立模块被两个目标使用也不因目标名字重复做前端。选择阶段键及真实负依赖比强制全局项目版本更准确，正确全量重算仍是允许的低成本实现；其具体键与反例在[工程上下文](../编译/查询增量与性能.md#project-context-invalidation)。

**变换后分析。** 采用[原generation隔离与逐项保持](../编译/内核/变换接纳与分析保持.md)。静态图没变不代表数值和资源事实没变；保持需要真实支持及传递依赖，裸地址不是跨generation身份。更小的正确路线是重算受影响分析，只有确定收益和合格保持规则时才做复杂更新，不要求为增量先建一套通用证明数据库。

资格依赖还包括实际Claim、观察、逻辑签名及确认数据是否参与过候选选择；这些变化不一定改变功能结果，但会改变可采用的保证。按[性质保持](../编译/性质保持与开放环境.md)和[探索确认](../运行/验收/覆盖与收益判据.md#adaptive-confirmation)更新相交依赖，不因此把全库基线塞进每个纯值键。


## D15 成熟工具作为机制

**当前选择。** 原生语言解析/类型、目标AST与打印、包/VCS和所需存储直接复用成熟能力。SEC自研中立语义、作者来源、跨表示与资产关系、目标保持和真实作用接合。具体角色由[宿主分配](../运行/宿主生态与技术约束.md#成熟机制的实际复用分配)拥有；不为每个外部函数批量造无收益wrapper。

**实际接合。** 纯编译值服务不持有工作区写连接，真实写入经原有租约、前像、提交和恢复边界。迁移时按精确旧接口提取共同计算，不能为新入口再建竞争编译器。TS目标adapter锁真实版本和配置，Host封闭读取；结构JSON采用具有具体树/属性事件的成熟读取器，再核重复键、Unicode与体合同。依赖声明、已安装内容与实际运行不同，不用清单代签运行。

**保持边界。** 工具只能承担其真正输入域：TS正确打印错误目标AST，仍是SEC降低错误；结构JSON返回容错树不代表合法结构；原生AST不保证保留所有注释；SQLite内部事务不包含事务外文件和消息。公共核心不依赖ts.Node、特定数据库或SDK。

**资料维护。** 每项实际供给或机制比较沿[来源R0—R7](../依据/来源/设计依据与资料边界.md#研究结论的保存复用与失效协议)取得当前适用性。旧结论稳定就复用；API、环境、用途或反例变化才复核相交原始材料。使用/维护位置覆盖全部资料，不由用户是否提醒决定。维护关系不是安装记录，自动索引也不证明语义。

**验证差额。** 按[剩余验证](../运行/保证/要求证据与裁决.md#成熟成果复用与剩余验证责任)继承精确覆盖、形式依据或明确受信采用，检查新映射、配置、组合和环境。类型检查与行为保持分别记录，独立Reviewer仅在所需保证和政策要求时启用；候选不能修改独立任务或Oracle来获得通过。

**替代与重开。** 外部工具不满足可取得性、信息保全、实际资源或许可时，可以替换相交适配或实现必要差额；无此依据不自研全部生态。API族变化仅在该边界重新映射，不能假设TS6的工厂直接等于7.x接口。普通已知绑定无需全局搜索，下载/安装/执行仍按真实权限。

## D16 设计探索与已定模型编译分离但允许规则求解

**选择。** 产品方案在相应实现前选定；用户candidateRef是内容快照；真正存在未定实现选择才比较。固定构建消费既有作者、要求、解释、布局和绑定，不每次让AI重选业务。编译可在明确预算内求解，不将所有求解排除，也不强迫普通已知符号进行全局搜索。

**成品实现。** [纯编译接口](../编译/内核/编译值服务.md#当前选定的首个编译实现方案)从固定作者内容到按根产物；明确构建/运行与观察再由应用和宿主承担。有限控制、数据并行、反馈等区域保留自己的运行含义，不要求所有输入提前特化成一张静态DAG。现有代码只有真实迁移任务时才参考其旧Block与工作区合同；它不能决定成品必须有写租约或持久事务。

**数据与变换。** 模块arena、签名、BodyAnalysis和目标区域均有写入期与封存边界。类型形状先供主体/效果分析，再按声明封存完整可调用头；分析器不等待自己参与产生的最终索引。展开引入调用、效果与依赖后补查；只给每层增加schema或checked标签不能保持含义。按有序区域生成，常量、具名实参和闭包的求值次数不由后端随意简化。

**需求到实现的闭合。** 计划记录实际基础、差异、供给前提、共同边界和残余义务，materialize按语义读集重基，而非只比较编辑位置是否重叠。需求关系与短作者表达共同保留；普通精确编辑可以直接走源变化，不为这个计划添一套强制表单。代价是需要维护真实依赖与组合检查，较小实现可先重查整个相交模块；把全部需求一律交给求解器或把所有源码再次包装，不是省事的等价替代。

**搜索与成本。** [联合规划](../编译/实现选择与设计搜索.md#带边界状态的联合搜索与合法剪枝)保留后续边界、剩余义务、实际转换和可靠成本条件。估计用于排序，不充当证明性界；合法方案可直接完成可行目标，预算结束不称无解或全局最优。小任务沿已有合格绑定，实际新选择才重开相交部分。

**稳定与演进。** [源码结构政策](../编译/目标/结构稳定与作者回源.md#跨次生成的结构稳定合同)使用明确布局基础；compareTo只作比较。基础缺失时明确canonical候选或缺项，不偷取latest。可复现、局部稳定、源兼容与ABI兼容分别检查。新运行观察在明确重新选择时进入新绑定，不暗改已有恢复意图。

**并行与结束。** 源递归不展开未来全部调用；同键查询可共享，新键无限增长另按残留/预算处理。S0—S8在真实资源下挂起父任务、保留仍在用的内存并按确定规则汇合；旧worker结果不能推进新头。远程需真实输入/工具/执行平台与发送许可；哈希正确不证明当前动作生成，竞速结果冲突不能后到覆盖。取消等待不证明计算停止。

**代价与反转。** 全LLM生成容易漂移，全手写失去确定推导，无界优化浪费资源；当前选有限且能落代码的中间方案。新增普通功能仍逼核心大改、预览启动工作区写入、展开绕过检查或按参数槽重排源求值时修相交设计。真实新语义不能表达时允许修改核心合同，不用无限兼容壳维持形式稳定。未实现和未获证据不等于当前选择未定，当前选择也不等于全体系完美。

**成品装配的当前落实。** 定义、方法、控制与目标在请求开始绑定为只读EngineImage；内部选择发生在真正有未定实现时，不让旧请求被热更新。查询只依赖实际使用方法；若搜索读取候选集合，集合成员版本也进入依赖。完整模块、数据和调用由[总架构](../架构/协作与状态边界.md)和[物理合同](../架构/装配/模块与运行实例.md)定义；旧仓库迁移只是条件附录，不再反向决定成品。

**设计收束的执行边界。** 代码准入读取已定接口、算法与验收设计；实现运行结果在代码存在后取得；真实采用再处理环境、权限与相交迁移。三者按任务分开，不要求先有部署读回才能写parser。全体问题是已知义务索引，不是首个模块的AND依赖集。新发现必需设计空白先补；尚无实测与未选领域不把已定设计重新标成未决定。唯一准入合同归[实施规范](../演进/实施/主线前沿与准入.md#验收门禁与证据计划)。

## D17 作用域内单写与多候选

**问题。** 同一份工程可以有多个合法候选和多来源观察；如果workspace、compiler、UI和执行器都能直接改变同一“当前头”，单个组件的局部正确不足以保持用户工作。把所有东西锁成一个全局事务又会使纯预览、独立目标和并行分析承担不必要成本。

**当前选择。** 作者候选由workspace封存为不可变内容，多个候选可以并存；当前采纳/保存头只有对应提交协议拥有，由execution在当前权限和前像下推进。compiler只返回分析和ArtifactSet，assurance只追加实际检查，entry只呈现。每个冲突域可以有自己的头；真正跨域原子要求通过有能力的共同提交或明确协调处理。

**机制与正常路径。** 应用固定本次接受要求与作者基础，纯fork形成新候选；需要保存时取得精确SavePlan、目标及当前许可，通过比较前像提交；冲突时保留双方内容并重新观察。生成产物和运行事实不因候选发布被修改。外置内容先固定和发布，头后提交；多文件实际中断依据原前后像处理。

**替代和代价。** 用普通文件和一个进程完全可以实现受限场景，只需真实的范围与比较；不要求每次编辑都开数据库。多写者直接覆盖看似简单，却把冲突和丢失交给最后到达者；全局锁虽然容易叙述，会牺牲独立任务和恢复。当前方案增加版本、候选映射及比较，但只在存在共享/持久责任时启用。

**边界和反例。** 单写协议不表示只能有一个用户，不表示多份观察只能保留一个来源。候选可以有语法错误，原子的是批次而非它的全部语义已经正确。真实外部文件写者不参加协议时还需目标前像和可达到的保持范围；版本目录原子切换不代表任意原始路径读者都看不到中间态。

**重新裁决。** 源相似性被用于盗认身份、两个模块绕开提交同时写头、保存源被当部署完成，或全局串行成为无必要瓶颈时，修正相交责任与协议。完整方案见[最终状态归属](../架构/装配/模块与运行实例.md#工作区内容可变头证据和作用的物理归属)。

**保留的较小与分布式替代。** 普通非交换修改采用比较与冲突域；确有保持不变量的合并代数时，允许可交换副本，不由集合并集推导全部业务无需协调。模型联邦仅在真实多上下文差异存在时采用，不是每个工程前置。

**IR变换的同一责任。** 分片可结构共享或在合格边界内私有克隆；成熟可变Pass失败后不假定输入已撤销。默认丢弃私有半成品并回到准确合格基础；只有真实可验证逆操作才用日志恢复。区域必须覆盖实际符号/使用链，不以函数文件名推断独占。不强制全工程深拷贝，也不让性能优化绕过共享读者。

## D18 纯编译与工具效果分开

**问题。** 编译可能需要尚未取得的源码、库、目标声明或外部分析；若直接把活文件、网络和执行器放进“纯读取”回调，固定输入、缓存、权限和恢复都会失去边界。反过来，把全部读取和执行都做成每个函数必须的持久事务，也会破坏轻量开发。

**当前选择。** compileFrozen只消费准确输入和已绑定方法；新需求返回有类型的ContentNeed或ToolResultNeed。application解释需求，execution执行真正获准的读取/工具动作，随后形成PreparedJob后继。已固定引用不能被新数据原地覆盖，已有源和image不偷偷换成latest。纯输入完整时直接完成，不经过数据库或工作区写流程。

**正常及失败。** 有必要输入便解析/检查/生成；缺输入给出范围与消费者；取得成功后只扩大未固定部分，未变子查询可以复用。准确不存在、拒绝、不可得和工具失败各有状态。外部工具失败不改原任务，补读没有任何进展不无限重跑。新方法或展开生成的节点重新检查，不靠旧checked标签获得资格。

**替代与代价。** 普通单次构建可以一次预先捕获所有已知输入，减少续接；动态依赖真实存在时采用按需补取。不采用核心任意I/O，因为它隐藏实际输入和权限；也不复制两个编译器分别给纯模式和工作区模式。即时运行采用按根准备＋成熟Runner，明确请求后才执行；直接解释器、独立字节码VM与自研JIT不是当前实现项。它缩小需要的输出、复用既有阶段，不取消解析与真实依赖；仍不得把preview当运行。额外的输入状态与方法合同由工具承担，不进入作者的每个小请求。

**独立边界。** 确定生成并不自动证明源满足任务；预算与取消不保证任意程序终止。进程内接口不能阻止恶意插件读全局，真正隔离由宿主承担。目标程序的作用与编译工具的作用分开，生成源码不触发其中的业务；恢复使用原意图，不能用新版本重新计算旧效果。

**重新裁决。** 同一动作键出现来自不同活树的内容、外部分析被伪称纯、预览进入写租约、恢复用新程序替换原目标，或者输入捕获把AI负担抬高时，调整取得/纯值/执行的相交接口，不再次更换产品目标。见[动态补输入](../架构/协作与状态边界.md#6-动态补输入工具调用与快照闭合)。

**输入隔离的独立条件。** 捕获时按权限裁剪会改变实际输入的，必须进入对应输入隔离范围；秘密凭证本身不放进共享查询键。库调用的次数、顺序、捕获和效果仍由原语言承担，外部声明加载也不自动允许原生顶层执行。

## D19 写回事务与恢复

**适用与选择。** 修改已有状态或相关多文件时，记录明确意图、前像、归属与恢复资料，实际写后读回；新私有目录可以采用更轻的暂存交付。缓存和索引不是恢复根。

**机制与代价。** 模型采纳、提交确认与文件/外部作用分别有状态。普通逐文件替换是可恢复过程，不承诺所有外部读者同时看到同代；强原子需求改用目标事务或版本目录等能力。日志、恢复空间和故障验证有真实成本。

**反例与重审。** 崩溃混合代际、finally删唯一备份、回滚删后继写者内容。恢复可前滚、逆变更、补偿、遏制或保留未知；第三种文件值不覆盖，终态逆向用新意图，修订不倒退。恢复用户确认的人工前像不自动等于恢复旧生成代际；需要重新核对历史清单。

**范围。** 缓冲、磁盘、索引和生成层分别协调，未知外部完成先查询。宿主已有等价原子能力时复用而非再造日志；进程中止不代证掉电或CAS/GC。协议见[持久提交与恢复](../运行/持久化提交与恢复.md)。

## D20 资源核算按模式

**选择。** 资源核算按实际运行画像区分累计消耗、可释放占用、租约、速率与外部配额。多资源阶段采用共同预留或确定顺序的可撤销获取，不让互相等待的任务各占一半资源。纯同步调用可只用局部运行预算，不建资源数据库。普通值与对象采用目标托管内存；词法名称、可达存储和外部Own责任分别决定寿命。外部资源按确定作用域、结果和真实停止清理，不依靠GC finalizer签发及时释放。

**机制。** 父子共同预算不因重试、子代理或换模型重置；归还空闲槽不退款已花费用。编译、目标运行和推理按真实范围计量。期限有时钟域，跨机器用剩余预算；业务有效期另判。等待模型/远端时不持模型提交锁，准入保留有限读回/清理容量，恢复容量不新增业务权限。[资源协议](../运行/权限与资源管理.md#多资源准入与恢复保留)拥有详细顺序。

**语言接合。** 位置捕获的内部读写不能因外层公开效果隐藏而消失；收尾在真实域内合并原出口和有序清理结果。主体失败后仍清理独立可关闭的资源，未停止子任务仍使用的缓冲继续保留。不能套Python的finally后返回、Go的具名结果重写或GC终结器来改变中立约定。

**代价与反例。** 共同预留会降低部分利用率，分段和公平队列需要调度成本；没有有限非抢占时长和负载条件就不声称等待上界。remaining混同消耗与空闲、失败拒绝无限写日志、日志耗尽无法恢复、CPU/GPU互等、为腾空间删恢复根都要求重审。

**更小替代与边界。** 按真实资源启用计量，不预建空池；负载和隔离改变才更换宿主。无限循环可编译，预算耗尽只是本次执行未完成，不是语言无解。载荷预算不冒充完整磁盘配额，进程组清理不冒充沙箱。

## D21 能力与授权分开

**选择。** 能力、安装、OS访问、任务目的和模型自述均不是授权。人和AI按真实角色和委派工作；现有政策允许的动作不要求重复弹窗。秘密读取、业务采纳、写入、结果披露、恢复分别在相应边界判定。

**机制与反例。** 绑定subject、当前actor、目标audience、目的及允许对象/动作；历史委派链用于来源，不把各级权限相加。不能把异质字段写成未定义的集合交。冻结函数只固定调用对象，不固定权限；缓存结果、恢复胶囊和旧签名不复活撤销权。共享执行不得合并不同等待者的读取许可。

**取舍。** 当前检查和误拒绝有成本，单用户可用轻量受信宿主，团队可复用已有身份服务。紧急通道有事件、范围、期限和复核，不是无限admin；用户可以定义自己的语义，不能获得他人权力或伪造事实。

**重开与归属。** [委派与目标端](../运行/权限与资源管理.md#委派的主体执行者与目标端)及幂等结果读取定义执行顺序。若撤销传播、目标能力或实际账号不满足承诺，应缩小动作或更换强制边界，不凭回调接口宣称企业IAM/即时跨节点撤权。

## D22 生成程序独立运行

**决定与机制。** 输出声明为独立程序时，仅依赖目标工具链和明确运行库；离开SEC工作目录仍应能够按发行合同构建运行。一般程序经目标AST生成，外部调用需要真实Host端口；缺少端口返回缺项，不生成空成功。后端和运行库分别发行维护。

**取舍与边界。** 当前开发时可按入口准备成可调用模块，交给成熟运行引擎，提供即时体验；发行时输出普通程序。解释与提前编译不是两门作者语言，静态检查也不要求全量发行构建。解释平台可以作为显式目标依赖，但不能无故让每次业务函数回连SEC或AI。异质前端、目标构建和实际运行分别验证支持范围；一次有限对照不能证明任意工程。

**复审。** 用户改变为解释式部署或目标运行库发生变化时重审相交合同；不因目标依赖存在就否定独立运行，也不隐去这些依赖。

## D23 验证分级与证据独立

**问题和选择。** 设计裁决、源符合、任务满足、真实作用和采用收益需要对应依据。当前优先继承可用的规范、证明、上游实现及当前工程结果，依[剩余责任协议](../运行/保证/要求证据与裁决.md#成熟成果复用与剩余验证责任)只补未被覆盖的实际义务，不以每次重跑成熟软件全集作为严格性的象征。

**方法。** 固定主体、声明和环境，划分责任并对齐前提；被证明、被测试、受信采用和未知分别记录。设计可以现在用逻辑与反例选择方案，未运行不称执行通过；设备性能、文件已写和生产权限仍需真实事实。有限案例不变成全称，旧产物不换标签给新源。

**独立性。** 候选不能改弱原任务或Oracle来自证通过。普通确定检查可以由既有合格评价规则处理，无须默认第二AI；实际政策要求独立角色或不同方法时才分离。多个代理共享错误规格并不提供独立性。Verification与Validation仍分别检查保持和任务用途，函数类型和运行效果不互相代替。

**代价与条件。** 零新增执行可以是合格复用，不能是无依据也未运行。纯预览无需证据数据库；缓存要有真实依赖；真实作用要有恢复责任；强保证才构造所需组合关系。组件很成熟也可能有新接缝；十行高风险包装比大量已验证纯逻辑需要更多局部检查，不按代码量统一减免。

**反例与重开。** 拒绝全部合法请求却称完成；上游I/O崩溃测试被扩大成文件/邮件共同原子；投影省略限制被当作限制不存在；适配版本变化仍使用旧证明；旧候选验证贴到新产物。前提变化只失效相交依据，历史事实不改写。

## D24 宿主环境与可移植边界

**决定与机制。** 文件、进程、网络、时钟和持久化能力按真实owning environment绑定，分别处理Windows、Linux、WSL、容器及目标运行时。目录名不是物理身份；平台、运行库、硬件和微架构假设只在相交保证内激活。具体端口、数据、故障和迁移由[物理画像](../架构/装配/模块与运行实例.md#物理实现画像与可逆落位方案)承担。

**取舍与反例。** 纯库或单宿主可以先完成，不预造全平台兼容矩阵。Linux参考成功不认证Windows native/WSL效果；所需能力缺失明确报告不支持。代价是平台适配和实际验证，不是阻止事先设计完整候选。新增平台或能力变化时，按真实文件/进程语义复核。

**来源。** D24、

## D25 持久化、缓存和消息

**选择与机制。** 权威状态、版本内容、意图日志、证据、索引、缓存和消息按查询/恢复义务选存储，不因名称不同就拆服务。小型本地可以同库事务共置内容与意图；跨存储外置需内容就绪、引用保护和回收协议，队列按重复、顺序与读回合同处理。

**代价与反例。** 状态模式、保留、备份和迁移有成本；清缓存改变真值、重复事件产生重复效果、旧备份复活删除数据，都说明责任混用。恢复一致数据库不等于恢复最新权威，必须核对之后的撤销、删除、业务结果与旧控制器处置。

**更小替代。** 不承诺持久恢复的纯计算不启用该层；只需一个本地事务库时不造远程消息/内容服务。事件溯源是可选方案，不必用于每个对象；选择快照也须保留其承诺的历史内容，不能只剩revision。

**重新裁决。** 真实容量、查询、分发和恢复需求改变时拆分；合法删除改变历史覆盖时明确边界，不以“永远保全”推翻保留范围。[持久规范](../运行/持久化提交与恢复.md)拥有具体步骤。

## D26 组织、法规与安全画像

**决定与机制。** 具体操作涉及某主体、法域、敏感数据或高损失危害时，启用相应约束及其更新责任。真正适用的硬义务不被成本分数抵消；适用性、地域和操作范围必须有依据。

**取舍与反例。** 纯函数不加载无关企业流程，一项地区政策未知不阻止无关的离线编译；同时不能为保持可用性删掉真实义务。只分析相交主体与危害是更小方案。地域、参与者、操作或安全假设改变时，由对应责任重审；维护与确认成本计入实际采用。

**来源。** D26、

## D27 设计研究的定位

**决定与机制。** 研究为实际工程判断服务，保存具体命题、原始定位、前提、采用或拒绝及消费者。全部来源使用[共同维护协议](../依据/来源/设计依据与资料边界.md#研究结论的保存复用与失效协议)；修改相关规则、选择工具、升级目标或出现反例时主动触发，不等用户重复点名。无法确定的理论只作待定位线索，不据此增加核心服务或阻断已明确任务。

**取舍。** 固定命题及用途未变时复用；活动API、当前安全与环境，以及新增控制/资源/编码交点，需要定向重新检查。来源目录全体的结构和归属检查可以廉价执行，但不等于每轮必须下载全部网页或所有条目又被验证一次。没有实际后台任务就不宣称全天监控，当前规则由设计执行者的启动、变更和交付步骤承担。

**代价与反例。** 不维护使用关系容易只修CUE而漏其他成熟结果；无理由全量重搜则重复成本且可能把新版本误贴到旧绑定；只保留链接会丢失采用条件；过多复制全文会造成第二规范。当前用单一来源条目、共享定位与相交消费者消除这些问题，独立限制与反例保留。作用域内的输入或记录缺失应明确取得，不能用保存记录代替实际执行。

**重开。** 相同稳定材料持续重复检索、外部变更未触发其实际消费者、拒绝备选被列成发行任务，或来源发生矛盾而旧方案仍被默认为正确时，修改维护协议及相交规则。资料字段和链接全绿不能关闭这些行为问题。

## D28 明确兼容与退役

**选择与原因。** 临时竞争双写需要退出；真实长期协议边界与历史读取可以保留。活动执行、旧数据读取、恢复材料和支持义务不按同一个“版本过期”标签一起删除。

**机制与取舍。** [读写组合](../演进/兼容迁移与退役.md#读写组合与迁移准入)逐方向检查，新旧解码成功不代表旧读改写无损。新变体、缺失/Null、字段身份、数值和未知内容进入兼容裁决。影子、回填、双读写和分批切换按义务选择；直接局部切换更小，真实状态风险才支付暂态成本。历史解释可隔离保留，不继续授予旧写入能力。

**反例与重审。** 以仓内零import证明没有旧消费者；旧工具吞未知字段；回滚器读不了新数据；等待全球consumer-zero而无法撤销危险版本；删除唯一恢复器。发现任一问题就重算方向矩阵、支持域或恢复策略，不只延长兼容期限。

**删除条件。** 相交活动消费者已迁移/排空或被真实端点拒绝，保留义务有可用安排，再删除对应临时层。没有旧消费者、持久资产或运行作用的删重文档，不跑运行退役长流程。旧open-program、目标计划、原生绑定保持各自版本，不能用语法兼容隐藏行为收紧。

## 领域表面的当前补充裁决

对象的有限语法由[对象规范](../领域/对象与控制/对象构造与分派.md#采用理由与重新裁决)拥有取舍：直接成员形式用于真实对象语义，不重新采用嵌套作者SDK；基础无对象程序不受影响。流和AD保持普通库入口，避免为每个操作再加关键字。三者共用现行装配、候选、产物与作用边界，不能把模块接口相同误作执行语义相同。

文档图的投入以独立阅读问题为单位：静态结构、数据拥有、时序、状态和算法分别呈现，完整设计不压成一张总图。图源是其所属规范的表达，渲染图册只派生呈现；新增图片数量不是架构或产品质量证明。


## D02的作者成果与记录更新取舍

真实复用使产品使用者只维护必要差异，而不是使整个软件凭空成为两行。新[作者结果](../领域/计算基础/作者表示与实现分工.md)与[完整源](../../examples/实现校准/内存编辑器计算范本.md)把高层调用、独特主体和准确宿主责任分开；成熟TS框架用同样供给也可同样简洁，不能以样例行数证明SEC净收益。

采用有限`with`不是为追求新语言特征：大型不可变记录的局部变化在原形式需要重复所有未改字段，字段增加容易遗漏。每类型setter和普通构造是保留的较小替代；当全部使用方只需一两个专有操作时并不强迫改为with。通用反射更新、任意深合并、镜像配置语言和编译期执行程序会增加更大含义/权限成本，本轮不采用。新增构造的实际解析、类型和回源成本不能被“上下文词而非关键字”掩盖。

MVU式单实例工作台适合展示纯状态和外部命令分离，但不作为所有软件唯一架构。硬实时循环、编译器IR、数据库关系与动态对象保留各自模型和真实并发/资源合同。已有流程设计仍必要，只是它不能替代源码结构的成果，二者完成条件分开。

## D02补充：需求声明是一种既有定义角色，不是第二语言

原目标要求需求抽象，普通fn及开发工具不能代替产品最终源。需求声明作为既有Definition角色保留；本次结构形式直接编码其主体、参数、需求条款与关系。候选`design/use/prefer`的语义贡献分别对应定义、实例化、硬要求和偏好；这些贡献保留，新增词法不再被认定为当前必需路线。旧计算语法不删除，也不与结构源双写。

结构化记录并非必须猜schema：外壳、体种类和精确解释已绑定时，可以明确区分需求根、普通值和运行动作。先前以“记录只能靠任意schema猜”否定结构输入的论证不成立。独立文本语言能改善某些输入简洁度，但增加词法、诊断与编辑成本；高层函数适合确定计算组合，不能不加合同就代签需求集合、非运行主体与进展。当前选择严格结构模块直接进入已有RequirementTerm，保留其他形式的真实适用范围，不把用户历史提醒当成批准文本扩展。

若真实采用表明带强schema和静态阶段的既有前端可以保持同一含义与较低总体成本，可以替换前端；不撤销用户的需求作者主面，也不因此退回让每个产品重写普通程序。库方法与目标降低可以复用成熟设施；CUE、QML、Rosette和MLIR分别只提供约束组合、声明式表达、域内合成和多级合法化的机制参照，不证明本系统已实现。
