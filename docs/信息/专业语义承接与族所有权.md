# 专业语义承接与三十二族所有权

> **阅读范围**：研究原件与现行规范之间的承接决定；不是第二份专业规范，也不表示相关能力已实现。

本页拥有**研究原件中三十二个专业族各自由哪一份现行规范承载、以什么区别为证据、哪些尚未承接**。族的定义、五面内容与逐项原文留在[只读研究数据](研究数据/README.md)，本页不复述、不改写、不并列保存第二份。

## 1. 三种对象与唯一写权

| 对象 | 实际内容 | 写权与用途 |
|---|---|---|
| 研究原件 | 三十二族五面定义、568项问题合同、1786项原文、完整模型 | 只读、逐字节固定；提供来源、反例与区别，不签发产品规则 |
| 专业语义 | 每族必须保持的独立区别、失败条件与一个区别见证 | 每族恰有一处现行位置；改族含义只改这里与原件中的依据，不复制 |
| 规范入口 | 该族在产品中的规则、接口、检查与实施责任 | 由相交主题拥有；承接位置指向它，不把阅读投影当规则 |

三种对象不能互相代签。把原件搬进正文、按族新建三十二份并列文档、或让索引里出现一个链接就声称已承接，都是失败：前者制造第二份来源，中者把分类当设计，后者用导航代替内容。反过来，某项在原件里可查询、可编码、在一个参考解释器中可运行，也不证明现行规范已采用它。

## 2. 承接的判据

一族算作已承接，须同时满足五问，缺一即降级：

1. **区别被说出。** 现行正文说出该族不得丢失的独立区别，而不是只出现同一批名词。
2. **失败条件绑定。** 违反该区别时返回什么错误、保留什么未决，有明确位置。
3. **有一个区别见证。** 至少一个反例说明"看似相同、实际不同"，且不与别族共用同一句套话。
4. **有真实消费者。** 该区别被某个检查、生成、准入或作者面实际消费，或明确标为设计约束。
5. **写权唯一。** 同一区别不在两处各自维护；别处引用本页登记的位置。

| 状态 | 含义 | 必须附带 |
|---|---|---|
| 承接 | 五问成立，证据句在承接位置的当前正文中 | 证据句 |
| 部分承接 | 主要区别成立，但该族某项独立内容无位置 | 差额 |
| 缺口 | 无现行位置承载该族区别 | 登记项与触发条件 |
| 取代 | 现行设计有意不采用该族的整项区别 | 取代理由与边界；族内单项取代记在`部分承接`的差额里 |

`缺口`不因"以后再补"而消失，必须落在一个已登记的未决项；`取代`必须说清不采用的是哪一项，不能把没做的部分写成"已融合"。

## 4. 五百六十八项合同怎样寻址

问题合同是**问题接口**，不是文档清单。每项合同有唯一所属族；族有唯一承接位置，因此一项合同的规则落点由两级寻址得到，不需要 568 行索引，也不为每项新建一节。

使用规则：

- 查询或引用一项合同时，同时固定合同号、族与承接位置；只给合同号不构成当前规范引用。
- 新增合同若不属于现有三十二族，先决定族与承接位置，再进入使用；不得先建合同后补归属。
- 族内新增合同不改变承接位置；若该合同要求族尚未承载的区别，按缺口处理，不默认为已承接。
- 合同号的命名域与仓库问题编号不同；两者不得按数字直接联结。

### 同族的其他研究输入

| 输入 | 规模 | 路由 | 不自动取得 |
|---|---:|---|---|
| 区别单元（U） | 1,786 | 每项带所属族，可与多族相交；按任一相交族的承接位置读取，多族项须分别核对各族区别 | 单元存在或可查询不证明已采用，也不合并多族的不同要求 |
| 问题合同（D） | 568 | 经所属族两级寻址 | 合同有答案类型不证明答案已实现 |
| 理论候选 | 62 | [理论依据](../依据/理论/README.md)中的论证来源，按使用它的主题声明采用范围 | 理论成立不签发产品规则或实现资格 |
| 值结构 | 60 | 作者值类型与领域类型；有消费者时才成为定义，其余保留候选 | 有原值域不证明目标表示可承载 |

四项合计说明研究原件到现行规范的完整入口：U 与 D 走族，理论与值结构走其依据或类型主题。检查器只核对族账、D 总数、位置与证据句；U 的族归属、理论采用与值结构落地仍由各主题在真实任务中判断，不因本页存在而视为完成。

## 5. 机制投影从属于本账

[机制适用性](../演进/覆盖场景/机制适用性.md)的 64 项是需求发现与接合审查的阅读投影，其"规范入口"只指出产品规则位置，不等于族承接位置。两者关系固定为：

- 投影可以指向本账的承接位置，也可以指向只承担产品规则的主题；投影新增一项时必须写明它服务哪一族。
- 投影不得成为某族区别的唯一载体；只存在于投影中的区别按缺口处理。
- 承接位置移动时，同步投影中的规范入口；投影移动不影响本账。

## 6. 缺口、取代与触发

| 项 | 内容 | 触发与关闭 |
|---|---|---|
| 缺口：MATH | 数学结构的同态、同构与商运算保持 | 当出现以代数结构为真实对象的工程需求时，在计算结构主题内建立位置并给出见证；当前不以目录占位 |
| 缺口：LOG | 逻辑画像的签名、模型类、真值与推导 | 当引入除经典一阶核心外的实际逻辑画像时建立；引用现有理论依据不足以承接 |
| 缺口：NORM 差额 | 规范履行、补救与追溯生效 | 出现真实规范履行或合规判定需求时补入原则总纲或运行责任主题 |
| 缺口：SEC 差额 | 信任根、签发链与失陷恢复 | 出现真实签发链验证需求时补入权限主题；已泄露信息不能靠删本地记录回收 |
| 族内取代：TYP 子型 | 不建立子型关系，保留名义等价与显式转换；记在该族差额中 | 改判须重开类型系统选择，不以局部兼容需要偷偷加入 |

四项差额合并登记为[U068](../状态/语义与领域.md#u068)。缺口不阻断与之无关的设计；它阻断"该族已全面融合"的声明。

## 7. 检查与变更

`python tools/documentation/check_research_inheritance.py` 核对：

1. 恰好三十二族，族集合与原件画像表一致，合同数合计 568。
2. 每个承接位置的路径在当前源内、锚点唯一可解析。
3. 每行证据句确实出现在该锚点所属章节的当前正文中；`缺口`行不得带证据句。
4. 状态属于四值词表；`部分承接`与`缺口`必须写明差额或登记项；登记项须解析到现存 U 条目。
5. `src/` 不得引用只读研究数据；研究原件的消费者只能是文档、检查器与人工查询。

变更规则：族定义变化只改原件与依据；承接位置变化同时改本账、目标正文与全部入链；删除或改名承接章节必须同批更新本账，否则检查失败；新增族先登记族、合同归属与承接位置，再使用其合同。承接是当前判断，不是永久归属：真实消费者消失、区别被并入他族或目标不再支持时，按上表改状态并保留原因。

## 8. 本轮实际改动与未改动

承接账第一次建立时，多数族的区别已在现行正文中存在，因此本轮不是重写三十二份规范，而是三件事：

- **补出三处真实缺口。** [多维组织](../信息/接入检索与派生.md#information-organization)增加分类多值与计数非总体划分；[解释与证据接纳](../运行/保证/解释与证据接纳.md#metric-observation-identity)新增指标、日志与追踪的观察身份；[测量校准与实验](../领域/仿真/测量校准与实验.md#measurement-probability-model-values)补出边际与联合不可互替。
- **把缺口变成登记。** MATH 与 LOG 不建目录占位，登记为[U068](../状态/语义与领域.md#u068)；五项部分承接逐条写明差额，不以"基本覆盖"含混通过。
- **把判断变成检查。** 族集合、合同总数、锚点、证据句、状态与缺口登记纳入`docs:doctor`，并禁止`src/`引用只读研究数据。

未改动的是：三十二族的原文、五面内容与 568 项合同本身；领域主题的现有规则；机制适用性 64 项投影的结构。它们分别属于原件、规范入口与投影，不因建立承接账而改写。反过来说，本页没有新增任何产品能力，也不表示表中"承接"已经实现或通过验证。
